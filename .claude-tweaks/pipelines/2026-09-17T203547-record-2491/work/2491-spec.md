# 2491: docs/plugin-structure.md's reconcile inventory line is now stale for archive-branches' confirm-routing (#2252/#2322)

Origin: filed by the docs-health curation row (`/claude-tweaks:wrap-up`, D1 restructural), during #2322's wrap-up.

## Current State

`docs/plugin-structure.md`'s `plugin/bin/lib/reconcile/` inventory paragraph states: "Both destructive branch checks read it screen-then-confirm: archive-branches and prune-remote screen the in-scope set in one bulk call and re-read per-branch only to confirm a destructive provisional verdict."

This is no longer accurate for `archive-branches.js`. Since #2252 (and widened by #2322), a MERGED-screened or screen-null non-cherry-equivalent branch reaches the per-branch confirm even when its provisional verdict is a non-destructive `skip` — the confirm's own squash-provenance evidence, not the provisional verdict, decides whether the branch is actually destructive. The claim stays true for `prune-remote.js`, whose provisional `skip` still short-circuits before any confirm call.

## Deliverables

- [ ] Update the sentence in `docs/plugin-structure.md`'s reconcile inventory paragraph so it states the current, differing behavior of the two checks: `prune-remote.js`'s provisional skip still short-circuits (confirm only follows a destructive provisional), while `archive-branches.js`'s confirm now also runs for a MERGED- or screen-null-screened, non-cherry-equivalent branch regardless of whether the provisional itself is destructive (`squashCandidate` routing, #2252/#2322) — the confirm's own evidence, not the provisional, has the final say for that check.

## Acceptance Criteria

- [ ] The sentence no longer claims both checks re-read per-branch "only to confirm a destructive provisional verdict" — it distinguishes the two checks' actual routing conditions, cross-referencing `docs/reconcile-checks.md`'s Merged-proof / Confirm-routing symmetry sections rather than restating their detail inline.
