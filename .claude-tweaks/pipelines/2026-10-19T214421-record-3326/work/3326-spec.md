# 3326: review: categorise-reproduction splits a reproduced finding when the two agents word it differently

Origin: reflect full (batch) from #3072,#3003

Defer-reason: tangential

**Related:** #3329

## Current State

`bin/lib/coordination.js` `categoriseReproduction` pairs a same-location candidate (path exact, line ±2) only when `sameSubstance` is not `false`. For two independently worded reports of the same issue, the substance score falls below the threshold, so a genuinely reproduced finding comes out as two `nearLocation` unconfirmed entries.

Observed three times: #3023 (lens 3b, `release.js` `merge-base --is-ancestor` missing `--end-of-options`), #3028 (lens 3f, `tests/bin-lib/compose-subject.test.js:454`, rows copied verbatim), and #3003 (lens 3c, `plugin/bin/qa-stamp.js:121` and `:132`, rows copied verbatim, both pairs split). Each time the controller fell back to the direct-verification override. Re-checked after #2955 widened the location band to ±5: the merged categoriser still returns all four #3003 entries unconfirmed, so the gap is the same-line substance test, not the band. In an unattended run where no source read happens, a reproduced medium finding routes to the Review Console's low-confidence section instead of being auto-applied under the ceiling.

## Deliverables

Make the same-substance decision robust to independent wording for same-file, same-line (±2) pairs. Options: weight shared code identifiers and backticked tokens, or treat an exact-line match plus a shared identifier as same substance.

Keep #1980's guard: two different issues at the same location must still stay split.

## Acceptance Criteria

A fixture test built from the three observed pairs (each agent's Finding text verbatim) categorises every pair as `confirmed`.

#1980's existing near-location, different-substance fixtures still come out `unconfirmed`.

## Release Note

Review reproduction pairs that report the same issue in different words are now recognized as reproduced.
