# 3922: Guard against raw markdown reads in tests (recurring Windows CRLF regressions)

Origin: wrap-up leftover from #3890

Defer-reason: tangential

## Current State

Six open `Windows regression` records (#3703, #3776, #3797, #3802, #3890, #3894) share one root cause: a `tests/*.test.js` file reads governed markdown through a raw `fs.readFileSync(path, 'utf8')` instead of `tests/helpers/read-skill.js`'s `readText`, so a Windows `core.autocrlf=true` checkout (CRLF working copy) breaks heading lookups and newline-spanning literals. CI runs on ubuntu only, so each file surfaces one at a time via the post-merge `windows-regression.yml` run and is fixed as a separate one-line record (#3890 and #3894 each fixed one). `readText` is already used by 146 test files; about 278 test files still call `fs.readFileSync` (not all on markdown). No guard exists that makes a new raw markdown read fail on Linux.

## Deliverables

- [ ] Add a `node --test` conformance scan over `tests/**/*.test.js` that fails when a file reads a `.md`/governed-doc path through a raw `fs.readFileSync` instead of `readText` (per the `bin-source-scan-conformance` / `windows-checkout-test-parity` skills' scan conventions, including a go-red self-test and a floor on matched sites).
- [ ] Route the files the scan flags through `readText`, or list a justified allowlist with reasons.

## Acceptance Criteria

- [ ] The scan goes red on a fixture test that raw-reads a markdown file and green on one using `readText` (proven by reverting).
- [ ] `npm test` is green with the scan in place, with no unexplained allowlist entries.
- [ ] The next post-merge `windows-regression.yml` run lists no test file for a raw markdown read.
