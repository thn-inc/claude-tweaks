# 2916: transcript-judge: a self-assessment watermark can claim transcript bytes the evaluation only saw after compaction

Surface: backend

## Current State

- #2730 made /feedback's self-assessment fallback write a watermark keyed on `bytesAtDispatch`. This applies on the terminal-dispatch-failure route, with `mode: "self-assessment"` (`plugin/skills/_shared/transcript-judge.md:195-211`, the "Watermark — narrower than a blanket exclusion" paragraph; the write schema is at `:226-245`).
- Self-assessment evaluates "over its own conversational context" (`transcript-judge.md:187`). The record's observed symptom: "In a long session that context may already be compacted: earlier turns survive only as a summary, not as the transcript bytes the watermark claims. A later bare /feedback then scopes its dispatch past those bytes via the offset clause and never re-judges them."
- Two readers trust the offset without checking `mode`:
  - **Offset clause.** `formatOffsetClause` (`plugin/bin/lib/transcript-judge/watermark.js:110-121`) always renders `Evaluate from byte offset {bytesAtDispatch} (line {line})`. Prompt item 5 is appended whenever `readWatermark` returns non-null (`transcript-judge.md:149-158`).
  - **Skip check.** `isTranscriptUnchanged` (`watermark.js:132-135`) returns `true` when `currentBytes <= watermark.bytesAtDispatch`, regardless of `mode`. The Skip check (`transcript-judge.md:86-120`, and `plugin/skills/feedback/session-evaluation.md:41-63`) then skips the dispatch entirely, so an unchanged transcript after a self-assessment is never re-judged at all, not just scoped.
- `reflect` opts out of the self-assessment write (`plugin/skills/reflect/SKILL.md:103`), so today only the `feedback` consumer can hold a `mode: "self-assessment"` watermark.

## Deliverables

1. Decision (approved in brainstorming, 2026-10-15): when a reader finds a `mode: "self-assessment"` watermark, it honours the watermark's dedup lists (`filedRecords`, and `dismissedSubjects`, which stays computed live) but ignores its byte offset, so the next run re-judges the transcript from the start. Rejected alternatives:
   - Scope only up to the session's last compaction boundary: this depends on an undocumented harness transcript format.
   - Keep today's full scoping (#2730 AC2): it hides never-judged bytes.
2. In `watermark.js`, `isTranscriptUnchanged(watermark, currentBytes)` returns `false` for any watermark whose `mode === 'self-assessment'`, so the Skip check never skips on one. Its header comment states why.
3. In `watermark.js`, `formatOffsetClause` accepts the watermark's `mode`. For `mode === 'self-assessment'` it renders the offset segment as `byte offset 0 (line 1)` and leaves the records and declined-subjects segments unchanged. The clause's literal wording is otherwise unchanged, and an absent `mode` behaves exactly as today.
4. In `transcript-judge.md`:
   - The self-assessment watermark paragraph (`:195-211`) states that the written `bytesAtDispatch` is kept for audit only and that readers ignore it.
   - The Skip check (`:86-120`) and prompt item 5 (`:149-168`) name the self-assessment exception.
   - Callers pass `mode` through to `formatOffsetClause`.
5. `session-evaluation.md`'s Skip check (`:41-63`) and its `mode` payload comment (`:76-79`) cite the shared exception rather than restating it.

## Release Note

Fixed /feedback so a session evaluated only by its fallback self-assessment is judged again from the start next time, instead of skipping content that was never judged.

## Technical Approach

Keep the fix in the pure helpers so prose callers inherit it. The watermark write is unchanged: it still records `bytesAtDispatch` and `mode`, so a human inspecting the file sees what happened, and pre-#2730 watermarks with no `mode` keep today's behaviour (`transcript-judge.md:206-208`'s absent-field rule). Re-judging from byte 0 duplicates no filings, because `filedRecords` still reaches the judge through the clause and `dismissedSubjects` is recomputed live (`session-evaluation.md:103`).
