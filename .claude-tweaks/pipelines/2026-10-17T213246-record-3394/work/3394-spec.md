# 3394: Review Console Approve-all drops verify-expectations issues, so carrier-commit still skips after pr-first teardown

**Related:** #3365

Origin: /claude-tweaks:build #3365 Common Step 4 (whole-branch review, declined-to-judge)

Defer-reason: pre-existing-outside-diff

## Current State

#3365 made Review Console step 11 (`plugin/skills/wrap-up/review-console.md`) always record an `issues` array via `set-verify-expectations.js --issues` on its non-Approve-all path, because wrap-up verify runs after cleanup — by then the worktree mirror holding the materialized header is gone under pr-first, and the main checkout has no `work/` until reconcile.

The Approve-all path instead runs `wrap-up-engine.js finish-console --approve-all`, whose step 1 (`plugin/bin/wrap-up-engine.js`, the `writeExpectations({ runDir, fields: { memory, upstream } })` call) writes only `memory`/`upstream`. On a pr-first Approve-all run `engine-verify.js`'s `resolvedIssueNumbers` therefore finds no header and no expectations `issues`, and the `carrier-commit` check reports `skip` instead of pass/fail — the silent skip #3365 set out to remove.

## Deliverables

1. `finish-console` accepts an optional `issues` array in its stdin payload (validated as positive integers in `validateFinishConsolePayload`) and writes it through `writeExpectations` alongside `memory`/`upstream`.

2. `review-console.md` step 11's Approve-all sentence includes `issues` in the payload, sourced exactly as the non-Approve-all path sources it (`wrap-up-pack.json`'s `inputs.records` only when `sources.records` is `headers` or `worktree-headers`, else Phase 1's record; omitted when no record resolves).

3. Tests: a `finish-console` CLI case for the new key, and the step-11 prose pin in `tests/wrap-up-record-resolution-conformance.test.js` extended to the Approve-all sentence.

## Acceptance Criteria

1. A `finish-console --approve-all` payload carrying `issues: [N]` leaves `verify-expectations.json` with `issues: [N]`, preserving every other field.

2. A payload with a non-integer `issues` entry is rejected with a validation error (exit 1), writing nothing.

3. On a fixture run dir with no header anywhere and that expectations file, `runVerify`'s `carrier-commit` row resolves `N` (pass or fail), never `skip`.

4. `npm test` passes.

## Release Note

Wrap-up verification now checks the closing keyword on runs approved with "Approve all", instead of silently skipping it.
