# 3573: Detect comment-stripper mis-parses in the windows-hide, git-status and path-guard scans

Origin: reflect light from #3536

Defer-reason: tangential

## Current State

`tests/helpers/strip-comments.js` (#3536) does not model regex literals. A quote or backtick inside a regex can pair with a later literal, and an unescaped `/*` or `//` in a character class opens a comment. Either can blank live code, and the helper's header now says so. Four inputs reproduce it, for example `const a = /'/.test(x); const b = 'p//q'; fs.realpathSync(b);` blanks `fs.realpathSync(b);`.

#3536 made the mis-parse detectable only in `tests/bin-lib/exit-code-conformance.test.js` (`guardBlankedByStripper`, 12341f5dd). The other three consumers, `tests/windows-hide-spawn-conformance.test.js`, `tests/git-status-optional-locks.test.js` and `tests/path-guard-conformance.test.js`, would still undercount silently, and an undercount is a missed violation, not a red test. No `plugin/bin` file trips this today, but nothing enforces that.

## Deliverables

- For each of the three scans, add a cheap mis-parse detector that fails the suite instead of passing silently. One option: compare the scan's raw-text match count of its own call shape with its stripped-text count, and flag any file where stripping removed a match that sits outside a real comment. Another: a shared helper that reports regions where the stripper's output diverges from a literal-blind line-comment filter.

- A planted self-test per scan, using one of the four reproducing shapes, that goes red without the detector.

## Acceptance Criteria

- Each of the three scans has a self-test that fails when its detector is removed, and passes with it.

- On the current tree every scan reports the same verdicts as before (no new violations, no detector hits).

- `npm test` passes in full.
