# 2735: flow: the auto-mode Manifesto's required FYI table render isn't mechanically enforced

Surface: infra

## Current State

`manifesto.md`'s Step 3 ("Present the Manifesto") mandates, for default `auto` mode: "render the FYI variant... show the same preview + policy-levers tables, but change the heading to `### Pipeline Config (auto)`, drop the approval call entirely, and close with a single line — `→ proceeding (no approval needed) · run with confirm to review/override`."

Across this session's two `/flow` runs, this required visible render never appeared as assistant text. Both times, the levers were computed and written directly to `config.yml` via `set-config.js`, and the pipeline proceeded straight to dispatching the build — skipping the mandated table entirely. (The later, separately-gated Multi-Spec/single-spec Review Console tables — a different, `confirm`-style render at end-of-run — DID appear correctly both times, showing the skip is specific to this one step.)

This caused no functional harm (the config was still written and read correctly downstream), but it means a user running an "auto" pipeline received zero visibility into which policy levers were actually in effect for either run — the entire point of the Manifesto being a bookend "FYI" stop.

## Deliverables

- [ ] Decide the enforcement mechanism: (a) a conformance test (in the vein of the existing skill-prose-conformance suite) that asserts an `auto`-mode `/flow` transcript contains the FYI table text, making a skip visible after the fact even if unpreventable in-band; or (b) have `set-config.js` itself print the rendered table as part of its own stdout when invoked for the Manifesto step, so the render is a mechanical side effect of the write rather than something the orchestrating model must remember to compose separately; or (c) both.
- [ ] Implement the chosen mechanism(s).

## Acceptance Criteria

1. A fresh `auto`-mode `/flow` run's own output (or a mechanical check against its transcript/logs) demonstrably includes the `### Pipeline Config (auto)` table and the `→ proceeding (no approval needed)` line — not merely a `config.yml` write with no visible render.
2. `npm test` passes.

## Technical Approach

Option (b) is the more structurally reliable fix — a prose instruction ("render this table") is exactly the kind of step an LLM orchestrator can silently skip under time/context pressure, which is precisely what happened twice in this session; moving the render into `set-config.js`'s own stdout makes it a mechanical side effect of the write call the orchestrator already makes, not a separate step to remember. Option (a) (a conformance test) can't prevent a live skip — a `node --test` suite only pins prose/fixture shape, it can't observe a real `/flow` session's actual transcript — so it's better understood as after-the-fact detection (useful for catching regressions in a fixture-driven test harness, if one exists for `/flow` runs) than a fix for the live-session problem this record's own evidence describes. Weigh both against `set-config.js`'s existing call sites (the batch write already documented in `manifesto.md`'s "Write mechanism" section) — adding a render to its stdout must not break any caller that doesn't expect extra output.

### Key Files

- `plugin/skills/flow/manifesto.md` — Step 3's FYI-variant render instruction (the mandate this record found unenforced) and the "Write mechanism" section describing `set-config.js`'s batch call
- `plugin/bin/set-config.js` — the CLI this record's fix likely extends to print the rendered table itself (Technical Approach option (b))

## Gotchas

- This is a two-run sample (both `/flow` invocations in one session skipped the render the same way) — real but small evidence; if the build phase wants stronger confirmation the skip is systemic rather than session-specific, a few more observed runs would strengthen the case, though the underlying "prose instructions are skippable" reasoning holds regardless of sample size.
- Don't let option (b)'s stdout addition break `set-config.js`'s non-Manifesto callers (the ceremony-escape single-key form, `steps-and-gates.md` case 3's recovery writes) — scope the new render to the Manifesto-specific batch call site, not every invocation of the CLI.
