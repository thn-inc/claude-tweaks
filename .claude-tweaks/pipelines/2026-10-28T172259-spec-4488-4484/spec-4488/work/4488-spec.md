# 4488: Compose review routing log lines with a CLI and refuse a --text that repeats --step

# Reflect — staged finding 1

**Category:** tangential

Origin: reflect light from #4481

Defer-reason: tangential

## Current State

`review/step3-routing.md` gives each Step 3 Routing log line as a template (`STAGED {time} — Step 3 Routing: {severity}-severity finding {category} at {file:line}. Stage path: …`) that the caller fills by hand and passes to `plugin/bin/log-decision.js` as `--text`, with `--step "Step 3 Routing"`. `log-decision.js` already writes `{step}: ` before the text, so a caller who copies the template's `Step 3 Routing:` into `--text` gets `Step 3 Routing: Step 3 Routing: …` — nothing checks for it. The severity token is also hand-ordered: #4481's review logged `high-severity security finding at …` instead of `high-severity finding security at …`, and `/claude-tweaks:release` Step 3 classifies its gate by the literal token `high-severity finding`, so that line would have read as no blocking finding. Observed in run 2026-10-27T184830-spec-4481: 13 lines carried the doubled prefix and 3 STAGED lines the mis-ordered token; they were rewritten in place by hand. Probes: `git log -S "startsWith(o.step" --oneline origin/main -- plugin/bin/log-decision.js plugin/bin/lib` and `git grep -n -i -e "repeats --step" -e "step prefix" -e "duplicated step" origin/main -- plugin/bin` both returned nothing, and no open issue matched `log-decision step prefix`.

## Deliverables

`log-decision.js` refuses (exit 2, naming both values) a `--text` or `--entries` text that begins with its own `--step` value followed by `:`.

A composer for review routing lines, `--severity`, `--category` and `--at` flags or a small `review-routing-line.js`, so `{severity}-severity finding {category} at {file:line}` is never hand-typed; `step3-routing.md` cites it in place of the free-text template.

A test that feeds the composed STAGED and KEPT-PROMPT lines through the same token match `/claude-tweaks:release` Step 3 applies and sees `review: blocking`.

## Acceptance Criteria

`node plugin/bin/log-decision.js --run <dir> --status AUTO --step "Step 3 Routing" --text "Step 3 Routing: x"` exits 2 and writes nothing.

A high finding routed through the composer produces a line containing the literal `high-severity finding`.

Each new test fails with its change reverted.

## Release Note

Review routing log lines are composed by a CLI, so the release gate always sees a staged high or critical finding.

## Technical Approach

### Key Files

- `plugin/bin/log-decision.js` — refuse a --text that repeats --step
- `plugin/skills/review/step3-routing.md` — cite the routing-line composer
