# 4484: Release disposition roster and review staging disagree on the name of a confirmed non-patch review finding

Origin: /claude-tweaks:release v6.156.3 Step 8 disposition (run 2026-10-27T161535-release-standalone)

Defer-reason: tangential

## Current State

A confirmed review finding that has no code fix (a record proposal) has no staging name that both ends of the pipeline accept:

- `review/step3-routing.md` only ever stages `staged/review-{n}.patch` (line 58). It names no `.md` shape for a confirmed finding that becomes a record.
- `plugin/bin/lib/console/resolve.js` SECTION_MAP matches `review-{n}` only through its `/\.patch$/` row, so `stage-item.js --id review-3` for a `.md` is refused `unmapped-prefix`. The nearest canonical prefix it suggests is `review-followup-` (QUEUE section), which no skill produces.
- `plugin/skills/release/disposition.md`'s Review staging roster lists `review-{n}` as `staged/review-{n}.{md,patch}` (route `confirmed`) and has no `review-followup-` row, so the one name stage-item accepts is off the disposition roster.

Hit in run `2026-10-27T161535-release-standalone` (v6.156.3): five record proposals were staged as `review-followup-1..5.md` and Step 8 disposition had to read and settle them by hand (logged as a note in that run's decisions.md).

## Deliverables

1. `review/step3-routing.md` names the staging shape for a confirmed finding routed to a record (no patch): `staged/review-followup-{n}.md`, written via `stage-item.js`, carrying the `Title:`/`Type:`/`Labels:`/`Defer-reason:` header the console's queue-write step reads.
2. `release/disposition.md`'s Review staging roster gains a `review-followup-` row (route `proposal`, counted one finding per file), and the `review-{n}` row's example narrows to `staged/review-{n}.patch` — the `.md` alternative is removed because nothing can stage it.
3. A test pins that every prefix in disposition.md's roster with a non-`not staged by review` route is either accepted by `stage-item.js` (classifies mapped) or matches the `.patch` row, so the roster and SECTION_MAP cannot drift apart again.
