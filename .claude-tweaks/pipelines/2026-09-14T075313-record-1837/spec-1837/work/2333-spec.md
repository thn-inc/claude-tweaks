# 2333: verify.js/#2026: the only new test doesn't exercise the real behavior change (empty flaky allowlist)

Surface: infra

## Current State

Found during a pre-release whole-branch review of `tests/`. #2026's change to
`plugin/bin/verify.js` (confirmed, ~line 305: `const retryHook = async (result, ctx) => { if
(!decl) return result; ...`) replaced `flakyEnabled = Boolean(decl && decl.flaky.files.length >
0)` with `if (!decl) return result`, per that change's own comment: "an empty/absent `flaky`
declaration still needs a `retryDecision.reason` recorded." `declaration.js`'s `readDeclaration`
(confirmed, ~line 126: `let flaky = { files: [], maxRetries: DEFAULT_MAX_RETRIES };`) always
defaults `flaky = { files: [], ... }`, so the empty-allowlist case is the *only* new behavior
this change introduces.

`tests/bin-lib/verify/cli.test.js:1103` (`noParseArgs`, the only new test in this range,
confirmed present) declares `flaky: { files: ['tests/flaky.test.js'] }` — a non-empty allowlist.
No test in the file exercises an empty or absent `flaky` declaration, so the actual behavior
change this record shipped is untested — it passes identically before and after the fix.

## Deliverables

Add a test that supplies an empty or absent `flaky` declaration and asserts
`retryDecision.reason` is recorded as the change's comment describes.

## Acceptance Criteria

The new test fails against a revert of #2026's `verify.js` change (proving it actually exercises
the behavior) and passes on the current code.

## Technical Approach

Add a new test case alongside the existing `noParseArgs`-based test at
`tests/bin-lib/verify/cli.test.js:1103`, using a declaration with either no `flaky` key at all,
or `flaky: { files: [] }` explicitly — following the same test fixture shape (`tmpGitRepo`,
`noParseArgs` or an equivalent args builder) the existing test already uses. Assert
`retryDecision.reason` is present in the check's recorded result even though `decl.flaky.files`
is empty, and verify-before-committing per this record's own Acceptance Criteria: temporarily
revert the `if (!decl) return result` line back to the pre-#2026
`Boolean(decl && decl.flaky.files.length > 0)` shape locally and confirm the new test actually
fails, proving it exercises the real behavior change rather than something that would pass
either way.
