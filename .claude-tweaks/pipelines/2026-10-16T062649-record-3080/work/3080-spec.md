# 3080: Gate bare shell redirection (> / >>) under worktree-always now that every Bash call reaches the hook

Surface: infra

**Related:** #2702, #2767, #2776, #3088

## Current State

Record #3074 (merged as `666d97af5`) replaced `hooks.json`'s per-pattern `if` entries with one unconditional Bash handler per tool-use event, plus a command-word prefilter in `plugin/bin/lib/hooks/bash-prefilter.js`. Every Bash call now spawns `bin/hooks.js` once per event regardless.

Bare shell redirection (`echo x > file`, `cmd >> file`) still has no gate coverage:

- `fileWriteTargets` in `plugin/bin/lib/hooks/git-command.js` returns early unless `t[0]` is in `WRITE_SHAPES`, and no branch reads a redirection target. Its header comment lists bare redirection as "Still NOT covered, and deliberately".
- The prefilter can't reach it either. `bash-prefilter.js`'s `SEPARATORS` (`/[\s;&|()<>\`{}=]+/`) splits `<`/`>` away as separators, and no command word marks a redirection, so `echo x > tracked.js` takes the skip path and the full handler never loads.
- `plugin/skills/_shared/policy-schema-coverage.md`'s "Bare shell redirection" bullet records it as declined on the measured marginal cost: full handler minus skip path, about 49 ms idle and 54 ms under contention (best-of-30, this repo's Windows box).

The old rationale (an unconditional matcher's per-call spawn cost) no longer applies, since the spawn happens anyway. The other two gaps #3074's spec named, path-qualified git and `env`-wrapped git, are now covered end to end, so redirection is the one write shape left uncovered.

## Deliverables

1. **Parser.** Add redirection-target resolution to `git-command.js`, either as a `redirectTargets(command, cwd)` sibling or as a pre-pass inside `fileWriteTargets`. It resolves `>`, `>>`, `&>`, `&>>`, `>|` and fd-prefixed `N>`/`N>>` targets per shell segment, whether the operator is spaced (`> f`) or glued (`>f`). It runs regardless of `t[0]`, so `echo`, `printf`, `cat`, a bare `> f`, and a redirect on any other command are all reached. Use the same fail-closed posture as the other write shapes: an unresolvable target (`$VAR`, a backtick or `$(…)`, process substitution `>(…)`) resolves to no target, never a guess. An fd duplication (`>&2`, `2>&1`) is not a file target.
2. **Prefilter reach.** In `shouldRunFull` (`bash-prefilter.js`), run the full handler when the command holds an unquoted output redirection whose target is not an fd duplication (`>&N`) or a `DEVNULL_LIKE` sink (`/dev/null`, `/dev/stdout`, `/dev/stderr`). `2>&1` and `> /dev/null` are the most common redirections an agent writes, so keeping them on the skip path is what keeps the added cost off most redirecting calls. Measure the skip-path cost after the change and re-record the figure in `policy-schema-coverage.md`.
3. **Gate wiring.** Feed the redirection targets into `checkWorktreeRequired`'s `writeTargetPaths` (`pre-tool-use.js`) as `exemptible: true`, so the existing exemptions apply unchanged: `.claude-tweaks/pipelines/`, a gitignored target, and `DEVNULL_LIKE`. Feed them into the pipeline-shadow guard's candidate list too (the `fileWriteTargets`/`mkdirTargets` loop near the `pipelinesDir` check), since a redirect can create a shadow run dir just as `tee` can.
4. **Coverage contract.** Add a `- Bash redirections:` line to `policy-schema-coverage.md`'s gate coverage block, with a matching `GATE_COVERAGE` field in `pre-tool-use.js`. Pin the pair in `tests/hooks-gate-coverage.test.js` the way `bashWriteShapes` is pinned. Move the "Bare shell redirection" bullet from declined to covered, and remove the "Still NOT covered" redirection line from `git-command.js`'s header comment.

## Acceptance Criteria

- `echo x > tracked-file.js`, `printf y >> tracked-file.js`, and `cat a > tracked-file.js` issued from a `worktree-always` main checkout are DENIED, with the same remediation message as `cp`/`tee`.
- `echo x > /dev/null`, `cmd 2>&1`, `cmd > ignored.log` where `ignored.log` is gitignored, and `echo x > .claude-tweaks/pipelines/<run>/x` are ALLOWED.
- `cmd 2>&1` and `cmd > /dev/null` with no other covered word take the prefilter's skip path, which the e2e `require.cache` probe in `tests/hooks-bash-prefilter.test.js` shows by loading no heavy module.
- `echo x > "$OUT"` and `echo x > $(mktemp)` resolve to no target and are ALLOWED, the same fail-closed posture as the other write shapes.
- `tests/hooks-gate-coverage.test.js` pins the new coverage line against its code twin, and the prose and the code agree.
- `perf/hooks-prefilter.test.js` still passes. `npm test` adds no failures attributable to this change against the Windows baseline.

## Release Note

The worktree-always gate now also catches file writes made by plain shell redirection (`> file`, `>> file`) from the main checkout.

## Technical Approach

`splitSegments` already gives per-segment strings with quotes respected, and it doesn't split on `>`, so a redirection stays inside its segment. Inside `forEachCommandSegment`'s handler, scan the token list (from `tokenize`, which keeps quoted spans whole) for redirection operators:

- **Standalone operator.** A token equal to `>`, `>>`, `>|`, `&>` or `&>>`, or matching `^\d+>>?$`, takes the next token as its target.
- **Glued operator.** A token like `>file`, `2>>log` or `&>out` is split at the operator.
- **Not file targets.** A token like `>&2` or `2>&1` is an fd duplication. A target starting with `(` is process substitution.

Each target goes through the existing `resolveWriteTarget(effCwd, raw)`, which already applies `isUnresolvable` and the `DEVNULL_LIKE` check, and emits `{ action: 'write', file }`. Because this scan runs before the `WRITE_SHAPES.includes(t[0])` early return (or in its own sibling), the command word doesn't matter.

For the prefilter, add a small `hasFileRedirection(command)` to `bash-prefilter.js`. It walks the raw command once with the same single-quote, double-quote and backslash state machine `splitSegments` uses, but no heavy requires. It returns true at the first unquoted `>` whose operator and target, read the same way as above, are neither an fd duplication nor a `DEVNULL_LIKE` path. `shouldRunFull` ORs it with the word scan and the assignment-plus-`$` rule. Keep the prefilter a superset of what the parser can resolve: when the prefilter can't tell (an odd quoting shape, say), it returns true and fails open to the full handler, which is the existing rule.

## Gotchas

- `2>&1`, `>&2` and `> /dev/null` are in a large share of the Bash calls agents issue. If the prefilter sends them to the full handler, the ~50 ms marginal cost lands on most calls, which is the cost this record was declined over. Keeping them on the skip path is load-bearing.
- A `>` inside quotes (`echo "a > b"`), inside a heredoc body, or inside a `[[ a > b ]]` string comparison is not a redirection. The parser must not fabricate a target from it. A heredoc body sits on its own lines after `<<EOF`, and `splitSegments` treats the newline as a segment break, so heredoc lines can show up as their own segments. Treat a target the parser can't prove as "no target", the same rule `gitTargets` follows.
- `>(…)` process substitution and `<` input redirection are not write targets.
- `noclobber`'s `>|` is still a write.
- The gate's remediation text for write shapes names the command. Check that the deny message reads sensibly when the "command" is a redirection.
- `tee` is already covered. `cmd | tee f` should keep producing exactly one target, not a duplicate.
