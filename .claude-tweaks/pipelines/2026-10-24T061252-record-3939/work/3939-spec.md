# 3939: Move the 12 pinned wall-clock budgets from tests/ to perf/

Origin: ledger resolve gate

Defer-reason: genuinely-larger

## Current State

tests/wall-clock-budget-conformance.test.js (#3491) fails any wall-clock budget under tests/ and pins the 12 that already existed on its ALLOWLIST, by comparison text, in 9 files: candidates-scale-readiness (2), dream/scan, flow/preflight, gif/palette, git-retry, health-core/premise-self-check, model-profiles/session-failures (2), wrap-up/pack, reconcile (2). Each entry carries a reason and is marked a candidate to move to perf/.

They are the flake the convention exists to prevent: tests/bin-lib/gif/palette.test.js:82 failed a full npm test run at 5235 ms against its 5 s bound under load, and passed in isolation (run 2026-10-22T061255-record-3491). docs/plugin-structure.md states that wall-clock budgets belong in perf/ (npm run test:perf), which npm test never runs.

The scan also cannot see one further budget in tests/bin-lib/wrap-up/pack.test.js (pack.durationMs < 600), because the duration comes from inside the code under test (the scan header lists this as known limit 1).

## Deliverables

- [ ] For each of the 12 pinned sites, split the test: the functional assertions stay in tests/, the timing assertion moves to a perf/*.test.js file with a header comment, keeping the same input and the same bound.

- [ ] Remove each moved site from ALLOWLIST in tests/wall-clock-budget-conformance.test.js; delete a file entry when none of its sites remain.

- [ ] Decide for tests/bin-lib/wrap-up/pack.test.js whether its pack.durationMs < 600 budget moves too.

## Acceptance Criteria

npm test passes with ALLOWLIST empty or holding only entries whose reason says why the timing is inseparable from the functional assertion.

npm run test:perf runs every moved budget and passes on an idle machine.

No moved test lost its functional assertion: each tests/ file still passes and still asserts the behaviour the budget was guarding.
