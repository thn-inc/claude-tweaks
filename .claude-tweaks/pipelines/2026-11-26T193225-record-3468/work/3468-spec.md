# 3468: A pull_request workflow run not yet created still leaves a partial rollup green at the merge gate

Verified-as-of: 6ebb484d71cc753d74ca967edfa6f45f3e41fe83

Origin: #3405 build ruling (ledger row 11)

Defer-reason: needs-human-decision

## Current State

#3405 cross-checks the workflow runs that already exist for the PR head sha (`gh run list --commit`), so a registered-but-incomplete run reads pending. A `pull_request` run GitHub has not created yet is invisible to both the rollup and the runs list, so a push-triggered run alone can still read green in that first moment. The obvious fix, requiring at least one head run with `event: pull_request` whenever the repo has PR CI (`hasPullRequestCi`), was declined during the build because it would hold path-filtered PRs (no PR workflow triggers) pending until the 15-minute park.

## Deliverables

- [ ] Choose a rule that closes the pre-creation window without parking path-filtered PRs, for example a short settle delay after the head's push, or reading the workflow definitions' path filters against the PR's changed files.
- [ ] Implement it in `classify.js`/`pr-checks.js` and Step 2.5's prose, with a test for the path-filtered case.

**Decision** (2026-11-26, maintainer, recorded by the orchestrating session; answers Deliverable 1): **a 60-second settle window.** When the repo has PR CI (`hasPrCi`) and the head commit has no `pull_request`/`pull_request_target` run yet, the PR reads `pending` until 60 seconds after the earliest workflow run GitHub created for that head sha, under any event. When no run exists at all, the head commit's committer date stands in. After the window, the absence of a PR-event run means none applies (the path-filtered case), and the existing rollup and head runs decide.

- **Evidence:** over the last 25 merged PRs (read 2026-11-26), GitHub created the `test` `pull_request` run 2 to 19 seconds after the push. In 9 of the 25, the push-only `track-issue-fixes` run had already completed 1 to 17 seconds before that, so a read in that gap saw only green. #5153's ready-run check closes this window only for workflows that skip draft PRs, and it reports `not-applicable` in this repository.
- **Cost:** a normal PR waits nothing extra. A path-filtered PR waits 60 seconds once.
- **Rejected:** matching workflow path filters against the PR's changed files. It would re-implement GitHub's branches/paths/paths-ignore/types semantics, and every divergence would be a false green or a false hold.
- **Shares `classify.js` with #3467:** build the two one after the other, never in parallel.

## Acceptance Criteria

- A PR whose `pull_request` run has not been created yet does not read green.
- A PR whose path filters match no PR workflow still reads green once its push runs complete.
