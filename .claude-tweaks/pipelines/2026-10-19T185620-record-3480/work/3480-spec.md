# 3480: Restore flaky retry for jest/vitest suites via per-dialect failure accounting

Origin: ledger resolve gate (from #3204 wrap-up)

Defer-reason: genuinely-larger

## Current State

After #3204, `unattributedFailureCount` (`plugin/bin/lib/verify/extract.js`) returns `null` for every output family other than spec/TAP, and `planRetry` (`plugin/bin/lib/verify/flaky.js`) refuses with `no-accounting-guard: {family}`. Runner-owned flaky retry therefore never fires for a jest, vitest or pytest suite; those failures route to the whole-suite re-run path in `plugin/skills/test/verification.md`.

#3204 chose refusal over an accounting check because no single cross-check fits every summary dialect: jest prints `FAIL` lines per test file while its `Tests:` totals count individual tests, and pytest collection `ERROR`s and vitest `Unhandled Errors` sit outside any `FAIL`/`FAILED` line, so a count comparison could report a log as fully accounted while a failure is not.

## Deliverables

- [ ] Add per-dialect accounting for jest (the `FAIL` file lines against `Test Suites: N failed`) and for vitest (`Test Files N failed` plus a check for an `Errors` block), so `unattributedFailureCount` returns `0` or a positive count for them instead of `null`.

- [ ] Keep pytest refusing with `no-accounting-guard: summary` unless a sound check exists: collection `ERROR`s sit outside every `FAILED` line.

- [ ] Tests with a captured log per dialect, each with an all-attributed case and an unattributed-failure case.

- [ ] Update `plugin/skills/test/verification.md` (Flake handling), `docs/journeys/run-a-deterministic-verification-check.md` Step 10, and `.claude/skills/node-test-output-evidence/SKILL.md` to match.

## Acceptance Criteria

- [ ] A jest log whose every failing file is allowlisted and fully attributed retries those files.

- [ ] A jest or vitest log carrying a failure no named file accounts for refuses with `unattributed-failures: {N}`.

- [ ] A pytest log still refuses with `no-accounting-guard: summary`.

- [ ] The prose in the three documents above names the dialects that retry and the one that does not.

## Release Note

Runner-owned flaky retry works again for jest and vitest suites whose failure output the runner can fully account for; pytest suites still fall back to a whole-suite re-run.
