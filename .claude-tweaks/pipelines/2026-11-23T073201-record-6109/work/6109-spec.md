# 6109: Add the learned-skills-auto-merge policy key and record the floor reversal in an ADR

Surface: backend
Risk-flags: none

## Current State

- Wrap-up's learned-skills PR (`plugin/bin/lib/learned-skills/land.js`, #5290) is never armed: `plugin/skills/wrap-up/learned-skills-pr.md`'s "The PR waits for a human" section says `housekeeping-auto-merge` is never read for it, and `plugin/skills/_shared/github-pr-scan.md` item 9 refuses the `<!-- wrap-up-skills-pr -->` marker by name.
- No policy key expresses "learned-skill edits may merge without a human". `housekeeping-auto-merge` (`plugin/bin/lib/policy-schema.js`) means mechanical, low-judgment cleanup and derives its unset default from `autonomy` (`true` at `trusted`/`unattended`).
- #6088 ruled (2026-11-23) that the human-review floor for the learned-skills PR is dropped: the maintainer does not read these diffs, and 36 PRs in one week piled up and conflicted. That reverses #5290's ruling and needs an ADR. The design is `docs/superpowers/specs/2026-11-23-learned-skills-auto-merge-design.md` (deleted by /specify once decomposed; this body carries what the unit needs).

## Deliverables

1. A new policy key `learned-skills-auto-merge` in `plugin/bin/lib/policy-schema.js`: type boolean, category `merge-safety`, tier `advanced` (the core tier is at its cap), schema default `false`, summary "Lets wrap-up's learned-skill update PRs merge themselves once CI is green, instead of waiting for a person." (opened with the "Not yet used" marker that the comment on the key table in `policy-schema.js` requires until a reader is wired; the `drain` sub-issue removes it when it lands)
2. Its unset default is derived beside `housekeeping-auto-merge`'s derivation in `resolvePolicyKeys`: `true` only when `autonomy` resolves `unattended` and `control-mode` does not resolve `on`; otherwise `false`. An explicit key wins in both directions (#580's rule), including an explicit `true` under `control-mode: on`. `autonomy` is read through the same source walk `deriveHousekeepingAutoMerge` uses; `control-mode` is `policyOnly`, so it is read from the policy file only.
3. A row in `plugin/skills/_shared/policy-schema.md` naming its readers (the learned-skills `drain` in `plugin/skills/wrap-up/learned-skills-pr.md` and `_shared/github-pr-scan.md` item 9 — both wired by sibling sub-issues), following the `policy-key-addition` project skill's checklist for every registration site, including any "not yet used" marker the schema conventions require until a reader lands.
4. ADR `docs/decisions/0040-learned-skills-prs-merge-without-review-once-green.md` (next free number; re-check `docs/decisions/` at build time). It records: #5290's ruling quoted ("an instruction change that merges with no review is what the floor exists to stop"); the evidence (the maintainer reports not reading these diffs; merges happen in batches minutes apart; 36 PRs in a week, median 19h open; #6083's hand fold of ten conflicting PRs); the decision (the learned-skills PR merges once CI is green under `learned-skills-auto-merge`); and the boundary (a record's own diff, the record-owned run-branch route and console-approved skill updates keep `merge-check`'s agent-instruction floor unchanged). The ADR also states: the decision takes effect only once the `drain` and PR-scan sub-issues land, and the old "waits for a human" prose stays authoritative until then; why `unattended` alone turns the default on (the setting is the maintainer's own consent to unreviewed merges, `control-mode: on` vetoes an unset default, and an explicit key always wins); that "green" means every check on the PR head completed successfully, with no checks, only skipped checks or pending checks counting as not green; and that a bad merge is undone with `git revert` of its squash commit. Other files cite the ADR by title, not by number. Add it to `docs/REGISTRY.md` if ADRs are registered there.
