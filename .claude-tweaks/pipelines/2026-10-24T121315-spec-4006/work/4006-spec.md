# 4006: Chunked per-suite stamps and the generated-path exemption are never read by the gates that should skip re-verification

Surface: infra

**Related:** #3002, #2987, #4111, #4059, #4024, #3765, #3974, #3489, #3873, #4041, #4072, #4082

## Current State

#3002 shipped `verify.js --stamp-suite`: chunked `--no-stamp` runs each write a per-check pass record (`claude-tweaks-verify-suites.json`, each entry `{ sha, dirty, at, reportPath[, generatedExempt] }`), and `verify.js --stamp-status --scope <declaration>` composes them into `verifiedHead: true` plus `suiteComposed: { declared, covered, missing, complete }` once every declared check has a record at the current clean HEAD. #2987 shipped the live generated-path exemption (`liveGeneratedExempt` in `stampStatus`, `plugin/bin/verify.js`), which keeps `verifiedHead` true while only declared `generated` files are dirty.

Both are computed only when the caller passes `--scope` (`stampStatus`, `plugin/bin/verify.js` ~line 150-270). `plugin/skills/test/stamp-composition.md` documents this as a contract ("A `--stamp-status` call with no `--scope` never looks at per-suite records at all (`suiteComposed: null`)"), and `tests/bin-lib/verify/cli.test.js` pins it (`--stamp-status with no --scope never looks at per-suite records (suiteComposed: null)`). Every gate that should stop re-running a verified suite reads bare `--stamp-status`, so neither feature ever reaches one:

- `/claude-tweaks:review` Step 1.5, both branches (`plugin/skills/review/code-mode-steps.md` ~line 74-81).
- `/claude-tweaks:test`'s Skip-if-recent artifact branch (`plugin/skills/test/verification.md` ~line 25-29).
- `/claude-tweaks:flow`'s preflight pack `stamp` probe (`plugin/bin/lib/flow/preflight.js` ~line 312) — not named in the original filing.
- `/claude-tweaks:dispatch`'s first-call stamp read (`checkFirstCallStamp`, `plugin/bin/lib/dispatch/first-call-artifact-check.js` ~line 297), which additionally requires `present: true` and an existing `reportPath`, both absent from a composed-only verdict. This read is a note, never a gate (`plugin/skills/dispatch/two-call-gate.md`, #3661): an unverified result logs a SKIP line and call 2's review Step 1.5 re-verifies anyway.

A project that chunks its suite, or whose checks regenerate declared `generated` files, still pays for the full set at every later gate — the cost #3002 and #2987 were filed to remove. `code-mode-steps.md`'s own Current-State outcome-reach check cites #3002 as its example of a record that met every criterion while these gates still read bare `--stamp-status`. #4111 (review Step 1.5 only) is a subset of this record and is absorbed into it.

**Decision (brainstormed 2026-10-24):** bare `--stamp-status` auto-discovers the conventional declaration `.claude-tweaks/verify-scope.json` at the checkout root, rather than each gate opting in with `--scope`. One fix inside `verify.js` reaches every current and future consumer; per-gate opt-in would recreate the defect class this record exists to fix (a consumer that forgets the flag silently loses the feature). The change is a widening: `match` keeps its strict single-full-stamp meaning, `suiteComposed` goes from `null` to an object only where a declaration exists, and `verifiedHead` can only become true in more cases — each still requiring every declared check to have a record at the exact current HEAD on a clean (or generated-only-dirty) tree.

## Technical Approach

All composition logic already exists in `stampStatus` behind `scopeDecl`; the change is where `scopePath` comes from. Compute `scopePath` as today when `parsed.scope` is set; otherwise, when not `foreignGitDir`, resolve the default with `resolveScopePath('.claude-tweaks/verify-scope.json', process.cwd())` and keep it only when the file exists (an existence check before `readDeclaration`, so absence stays silent rather than producing the explicit-`--scope` "no declaration at" error). Carry a `discovered` boolean so the existing `scopeError` branches stay accurate: the foreign-`--git-dir` and missing-file messages apply to an explicit `--scope` only; an unreadable discovered file reports its `readDeclaration` errors. `scopeSelfPath` already applies to any resolved path.

`checkFirstCallStamp` gains one early branch after the stamp-read-failed check: `status.verifiedHead === true && status.suiteComposed && status.suiteComposed.complete === true` returns verified. Keep the ordering of the remaining `present` → `verifiedHead` → `reportPath` checks unchanged for the single-stamp path. On a verified result `two-call-gate.md` logs nothing, as today; the returned `status` carries `suiteComposed` for audit.

No consumer call site changes: review Step 1.5, test's Skip-if-recent, flow preflight and the dispatch default stamp read all keep invoking bare `--stamp-status`.
