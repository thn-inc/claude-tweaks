# 3657: wrap-up Section D reads the detached flag as the "fourth field" of ephemeral-server.txt, which a worktree path with spaces breaks

Origin: #3021 build — whole-branch review finding (Section D positional parse)

Defer-reason: pre-existing-outside-diff

**Related:** #3656, #3664

## Current State

`ephemeral-server.txt` is written as `printf '%s %s %s detached:%s\n' "$PID" "$PORT" "$WORKTREE_ROOT" "$DETACHED"` (`_shared/dev-url-detection.md` item 4, `dispatch/task-prompt.md`). `plugin/skills/wrap-up/cleanup-procedures-execution.md` Section D step 2 (POSIX) says "When the fourth field reads `detached:yes`, also kill the process group". When the worktree root contains a space (e.g. `~/Code Workspaces/...`), the fourth whitespace field is a path fragment, never `detached:yes`, so the group kill is skipped and a detached dev command's children can outlive their leader, still holding the port.

#3021 fixed the same parse for the worktree-root field in `review/step3-routing.md`'s Fix-wave server coordination (root = everything between the port and the trailing `detached:` token); Section D and any other reader of the record were left as they were.

## Deliverables

1. Section D reads the detach flag as the trailing `detached:` token, not a positional field.
2. Audit every other reader of `ephemeral-server.txt` (`dispatch/task-prompt.md`'s liveness re-check, `wrap-up/standalone-fast-path.md`) for positional parsing and fix the same way.
3. Conformance test pinning the trailing-token rule.

## Acceptance Criteria

- With a worktree root containing spaces and `detached:yes`, Section D kills the process group.
- No reader of `ephemeral-server.txt` parses the worktree root or detach flag by whitespace position.
- `npm test` passes in full.
