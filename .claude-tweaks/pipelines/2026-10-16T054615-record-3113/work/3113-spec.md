# 3113: Byte-budget tests count CRLF bytes, so a Windows checkout masks real size regressions

Origin: /claude-tweaks:flow #3101-#3104 run 2026-10-10T190327-spec-3101-3102-3103-3104. PR #3107's CI caught what local verification missed.

Defer-reason: tangential

## Current State

`tests/release-lifecycle-byte-budget.test.js` measures `plugin/skills/wrap-up/SKILL.md` and `plugin/skills/tidy/scan-procedures.md` with `Buffer.byteLength(fs.readFileSync(...))`. That counts raw bytes, so on a Windows checkout with `core.autocrlf` the CRLF line endings inflate both counts past their caps. The test therefore always fails at base there.

`verify.js`'s baseline adjudication then counts that file as pre-existing. A real regression is invisible locally on Windows. In run 2026-10-10T190327, #3101 grew `scan-procedures.md` to 43840 B against its 42466 B cap. Local verification passed four times, and only Linux CI on PR #3107 caught it (fixed in 58625fcde).

## Deliverables

- Normalize `\r\n` to `\n` before measuring in `release-lifecycle-byte-budget.test.js`, so the count matches the LF blob CI sees.
- Sweep `tests/` for other raw-byte budget checks over skill or doc files, such as `Buffer.byteLength(fs.readFileSync(...))` or `fs.statSync(...).size` compared against a constant, and give them the same normalization. Follow the `windows-checkout-test-parity` project skill.

## Acceptance Criteria

- [ ] On a Windows CRLF checkout, `release-lifecycle-byte-budget.test.js` passes at a base whose LF blobs are under budget, and fails when a file's LF size is over budget.
- [ ] No byte-budget test under `tests/` compares a raw CRLF byte count against an LF-derived ceiling.
