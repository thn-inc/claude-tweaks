# 2626: browse: add Playwright CLI reference doc + init detection (agent-browser migration, part 2)

Surface: infra

## Current State

`agent-browser` (this plugin's current browser-automation backend) has two confirmed defects
tracked in #2537: a synthetic locator click can report success without the target's registered
handler firing (repro: icon-sized buttons inside table rows), and the screenshot pipeline can
silently return a stale/dead frame after an `os error 35` (EAGAIN) failure with no daemon-side
self-heal. Neither defect is fixable from this repo — `agent-browser`'s source isn't vendored
here.

After research (comparing Playwright CLI, Playwright MCP, Stagehand, and Browser Use against this
plugin's hard constraint — every consumer must work in both interactive sessions and hosted
Routines, which is why `mcp__claude-in-chrome__*` was already ruled out per `docs/donts.md`) and a
spike, Playwright CLI (`@playwright/cli`) was chosen as the replacement backend. The spike
confirmed: it launches genuinely headless with no display server needed, and its default `click`
fired the real handler on a built repro of the icon-button-in-table-row case (confirmed via
re-snapshotting DOM state, not just trusting the tool's own success report) — the exact failure
mode `agent-browser` has. The spike did not test the `os error 35`-equivalent screenshot-degradation
case specifically.

This is sub-project 2 of a four-part migration (1: spike, done; 2: this record; 3: migrate the
~28 consumer files onto the new backend; 4: retire `agent-browser`). Today's `agent-browser`
integration is a pure markdown convention-pin — `plugin/skills/browse/agent-browser-reference.md`
documents the abstract operation vocabulary and defers to the tool's own self-docs for anything
beyond that; there is no Node.js code layer anywhere in this pattern, and none is being introduced
here — nothing in the spike surfaced a reliability gap Playwright CLI's own `click`/`screenshot`
commands don't already cover, so there is nothing for a wrapper layer to do that the existing
doc-only pattern doesn't already handle.

## Acceptance Criteria

- `plugin/skills/browse/playwright-cli-reference.md` exists, documents the operation vocabulary
  table below in full, and explicitly states the two behavioral differences from `agent-browser`
  that a future migrating consumer must not assume away: (1) `find` here is read-only (search +
  return matching nodes) — the opposite of `agent-browser`'s bare `find`, whose action-less form
  defaults to clicking; (2) output paths (screenshots, and anything else the CLI writes to disk)
  must always be passed as absolute paths — a relative path resolves against the invoking shell's
  cwd, which is not guaranteed stable across separate tool calls.
- `step-07-browser-integration.md` detects `playwright-cli` (via `npx --no-install playwright-cli
  --version`, the tool's own documented presence check) instead of `agent-browser`, with the
  identical "optional, never blocks init" behavior preserved.
- No other file is modified — the ~28 consumer files and `agent-browser-reference.md` itself are
  untouched by this record.

## Technical Approach

Write `plugin/skills/browse/playwright-cli-reference.md` following `agent-browser-reference.md`'s
existing section shape, with this operation vocabulary translation table:

| Operation | agent-browser (today) | Playwright CLI (new) |
|---|---|---|
| Open a session at a URL | `agent-browser --session <name> open <url>` | `playwright-cli -s=<name> open <url>` |
| Navigate within a session | `agent-browser --session <name> open <url>` | `playwright-cli -s=<name> goto <url>` |
| Close a session | `agent-browser --session <name> close` | `playwright-cli -s=<name> close` |
| Close every session | `agent-browser close --all` | `playwright-cli close-all` |
| List active sessions | `agent-browser session list` | `playwright-cli list` |
| Ref-based element snapshot | `snapshot -i -c` (`@eN` refs) | `snapshot` (`eN` refs) |
| Act on a ref | `click @e3` | `click e3` |
| Locator-based find+act | `find <locator> <value> <action>` | `find "<text>"` (read-only — see caution below) |
| Fill a field | `fill @e5 "<text>"` | `fill e5 "<text>"` |
| Screenshot | `screenshot <path>` (positional) | `screenshot --filename=<path>` (flag) |
| Text-only assertion | plain `snapshot` (no refs) | `find "<text>"` or `eval` against the page |

Carry forward two cautions from `agent-browser-reference.md`, restated for the new tool, plus one
new one from the spike:
- Refs are session-scoped and regenerate on every snapshot — never store them (unchanged rule,
  unchanged mechanism).
- `find` under Playwright CLI is read-only — the opposite of `agent-browser`'s action-defaulting
  bare `find`. State this explicitly and prominently; it is the one place the translation is not a
  mechanical rename, and a future migration inheriting the old assumption would silently mutate
  pages it meant only to inspect.
- Always pass absolute output paths — confirmed during the spike that a relative path resolves
  against the invoking shell's cwd, not against any stable location.

For the installation/detection section: `npx --no-install playwright-cli --version` is the tool's
own documented presence check (falls back cleanly when not installed). No implicit daemon to
document, unlike `agent-browser` — each `open`/`attach` call is explicit.

For `step-07-browser-integration.md`: replace the `agent-browser`-specific detection command and
install hint with the Playwright CLI equivalent above; keep the "missing → surface the install
hint and continue, never block init" structure exactly as it reads today — only the tool name and
the one command change.

## Gotchas

- Do not rewrite any of the ~28 files that currently cite `agent-browser-reference.md` — that

  `agent-browser-reference.md`'s own precedent of having no test suite.
