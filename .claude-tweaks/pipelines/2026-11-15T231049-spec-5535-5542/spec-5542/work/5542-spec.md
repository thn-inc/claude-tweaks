# 5542: Remove listClaimNames and stop writing the manifest's legacy baseSha line

Surface: infra
Risk-flags: none

## Overview

Two pieces of code that their own comments describe as having no reader.

`listClaimNames` in `plugin/bin/lib/issues/claim-store.js` was kept when its one consumer moved to `listClaimEntries`, "rather than removed, since a bare rename with no remaining caller to prove it is unnecessary churn". Nothing in `plugin/` calls it.

`plugin/bin/lib/flow/manifest.js` still writes a `baseSha:` line back when it rewrites a multi-spec manifest that carries one. The key has had no reader since #3035: batch curation and boundary freshness derive the base from `git merge-base`. The comment says "parsed and preserved on rewrite, never written by manifestInit — nothing reads it".

This is part of unit 1.4 of the 2026-11-15 audit simplification design. Dropping the `baseSha` line is a small behaviour change, stated below, and is gated on a check that no live run still carries the key.

**Complexity:** Low
**Estimated tasks:** 4

## Release Note

Removed an unused claim-listing helper and stopped carrying an unread legacy key in multi-spec run manifests.

## Technical Approach

`listClaimNames` is a plain deletion; the one piece of coverage it alone held moves to `listClaimEntries`.

For `baseSha` the behaviour change is: a manifest written before #3035 loses its `baseSha` line the next time `spec-status` or `manifest-init` rewrites it. Nothing in the repository reads the key (the greps above), so no behaviour downstream changes. That, not the local gate, is what makes the removal safe for other users' manifests: the gate only checks this maintainer's live run directories, and the parser stays tolerant, so a manifest on another machine that still carries the key parses and loses the line on its next rewrite. The gate in Deliverables exists because the run directories that could carry the key are local to the maintainer's machine and are not in the repository.

- `git grep -w baseSha` matches the unrelated verify, baseline and claims values. Scope every search to `plugin/bin/lib/flow`, `plugin/skills/flow`, `docs/hooks.md` and the journey page.

- `git grep -E` with `\b` silently matches nothing on the maintainer's machine. Use `-w`, `-F` or `-P`.
