# 5324: Template the remaining per-test fixture builders: repo+worktree pairs and verify scenario repos

Verified-as-of: 8ce3275ebfcb0bda4da59264d7167625a179834e

Origin: #5297 whole-branch review: AC3.1 (60% git-process target) shortfall levers

Defer-reason: tangential

## Current State

#5297 moved the suite's reused fixture builders onto `tests/helpers/git-template.js`, which builds each fixture once per process and copies it per test with zero git processes. It also turned off auto-maintenance for the suite.

Measured on its branch, through `node tools/run-tests.js --files-from <list>` with `CT_TEST_CONCURRENCY=6` (git processes counted by `GIT_TRACE2_EVENT` file):

| Set | Before | After |
|---|---|---|
| A: tests/hooks-pre-tool-use, hooks-session-start, hooks-teardown-run, issue-branch-tracking, reconcile-archive-residue, load-delta-cli | 3,632 | 2,319 |
| B: tests/bin-lib/verify/cli-baseline, cli-flaky-preexisting, cli-scope-integration, cli-slot-queue | 2,527 | 1,940 |

The combined total is 4,259 of 6,159, or 69%. That misses #5297's 60% target.

Most of the residue is git run by the code under test, not by fixtures. In `hooks-pre-tool-use`, the hook's own `rev-parse` ran 230 times, `ls-files` 141 and `check-ignore` 36. In `cli-baseline`, most calls are verify.js's own `rev-parse HEAD`, `status`, `merge-base` and `worktree list`.

Two fixture levers remain:

- **Fixed repo-plus-linked-worktree pairs.** `tests/hooks-pre-tool-use.test.js`'s `mainAndWorktree()` (~line 49) and its other `gitRepoWithCommit()` + `linkedWorktreeOf(main)` pairs run a real `git worktree add` per test. That is 3 processes each (worktree add, plus its `branch` and `reset` children), about 190 of the file's 729 git processes. A fixed pair can come from `fromTemplateSet` with a `{ main, wtparent }` layout. Teardown-run's fixture already shows that the template rewrites a linked worktree's `gitdir` and `.git` pointers correctly.
- **Argument-keyed verify scenario builders.** `tests/bin-lib/verify/cli-helpers.js`'s `scopedRepo(rules)`, `flakyRepo(opts)` and `baselineRepo()` still init, add and commit per test. In set B's run, the commits `base` ran 26 times, `declare verify scope` 15, `pre-existing fixture` 15, `flaky fixture` 11 and `head` 12, each with its `add`.
