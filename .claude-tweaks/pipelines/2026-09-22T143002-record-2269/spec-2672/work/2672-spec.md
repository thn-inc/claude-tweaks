# 2672: visual-review/discover-mode.md: migrate stale batch/snapshot/vitals syntax to Playwright CLI

Surface: infra

## Current State
`plugin/skills/visual-review/discover-mode.md` (line ~111) still describes an `agent-browser`-era `batch` invocation bundling `open`, `snapshot -i -c`, annotated `screenshot`, and `vitals` per page:

> "For each approved candidate, open a session and walk the candidate journey via a `batch` invocation that bundles `open`, `snapshot -i -c`, annotated `screenshot`, and `vitals` per page (same shape as the worked example in `journey-mode.md`)."

This is now-broken syntax under Playwright CLI, which has no `batch` command. The 5-part playwright-cli-consumer-migration (#2645-#2649) excluded this reference because its automated check only matched lines carrying the literal string "agent-browser" — `discover-mode.md`'s line doesn't name `agent-browser` explicitly, so the migration's sweep missed it even though the syntax it describes (`batch`, `snapshot -i -c`) is exactly the pre-migration form.

Sibling records already resolved both underlying gaps that this line touches:
- **`batch`**: #2646/#2647 confirmed no Playwright CLI equivalent exists; the established replacement pattern is a sequence of individual commands against the same `-s=<name>` session (see `journey-mode.md`'s "Assemble the sequence" section, lines ~19-33, including its worked example of three sequential `open`/`snapshot`/`screenshot`/`goto` commands ending in `close`).
- **`vitals`**: #2647 confirmed no Playwright CLI equivalent exists; the established pattern is to omit the vitals capture step and note the capability gap in place (see `journey-mode.md` lines ~21-22, `page-mode.md` lines ~19-20, and `browser-review.md` line ~136).

`discover-mode.md`'s Phase 3 walk section (lines ~111-118) needs the same treatment `journey-mode.md` already received, reusing its already-established sequential-command pattern rather than inventing a new one.

## Deliverables
1. Replace `discover-mode.md`'s line ~111 `batch` invocation description with a sequence of individual `playwright-cli` commands (`open`/`goto`, `snapshot`, `screenshot`) against one named session, following the exact pattern `journey-mode.md`'s "Assemble the sequence" section already establishes (including its worked-example command block style).
2. Remove or replace the `vitals` reference in the same line and in the numbered walk steps below it (lines ~113-118, e.g. "snapshot + annotated screenshot + vitals" in step 4) per the same vitals-capability-gap note pattern `journey-mode.md`/`page-mode.md`/`browser-review.md` already use — omit the capture, add an in-place capability-gap comment/note rather than silently dropping the mention.
3. Update the numbered walk steps (lines ~113-118) that reference "the batched output" to instead describe reviewing the sequential command output, consistent with how `journey-mode.md`'s "Per-step review" section (line ~40) already frames it.

## Acceptance Criteria
- `discover-mode.md` no longer describes a `batch` invocation anywhere in its Phase 3 walk section — the section instead describes a sequence of individual `playwright-cli` commands, matching `journey-mode.md`'s established pattern.
- `discover-mode.md`'s walk steps no longer instruct the reader to capture or review `vitals` output as if it were a working capability — either the vitals mention is removed, or it is annotated the same way `journey-mode.md`/`page-mode.md`/`browser-review.md` already annotate their own vitals gaps (an in-place gap note, not a silent capability claim).
- A grep for `batch` and `snapshot -i -c` across `plugin/skills/visual-review/discover-mode.md` after the change returns no hits describing them as current, working syntax.
- The migrated section still cross-references `journey-mode.md`'s worked example (or inlines an equivalent one) so a reader isn't left to reconstruct the sequential-command pattern from scratch.
