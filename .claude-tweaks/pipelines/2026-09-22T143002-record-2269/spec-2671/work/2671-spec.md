# 2671: visual-review: redesign element-reference convention and Web Vitals replacement post-Playwright-CLI migration

Surface: infra

## Current State
The playwright-cli-consumer-migration (#2645-#2649) removed two `agent-browser` capabilities that `visual-review/*` skill files depended on, with no replacement designed:

1. **Screenshot overlay-numbering** — `playwright-cli screenshot` has no `--annotate`-style flag (confirmed during #2645's migration; `playwright-cli-reference.md`'s Screenshot row), so captured screenshots carry no bounding-box/numbered-marker overlay. `plugin/skills/visual-review/browser-review.md` (line ~29) already flags this in place: "Every instruction below that says 'reference overlay numbers' describes the pre-migration convention; until a replacement element-referencing convention is designed, reference elements by clear description ... or by the `eN` ref from the most recent `snapshot` instead." At least 18 prose mentions of "overlay number"/"annotated screenshot"/"annotated overlay" remain across six files (`SKILL.md`, `browser-review.md`, `discover-mode.md`, `journey-mode.md`, `page-mode.md`, `qa-accelerated.md`), each still describing the old overlay-number convention rather than the interim `eN`-ref fallback.
2. **Web Vitals capture** — Playwright CLI has no `vitals` command or equivalent; no built-in surface captures LCP/CLS/INP/TTFB/FCP (confirmed against the CLI's own published docs during #2647's migration; `playwright-cli-reference.md`'s Operation vocabulary table). `browser-review.md` (line ~136) already flags this: Performance findings sourced from vitals cannot currently be produced; the instruction today is to omit the Performance line from the Step 6 report header rather than fabricate values. A hand-written `eval` script against `PerformanceObserver`/the `web-vitals` library is named as a *possible* manual workaround but explicitly not prescribed.

Both gaps were flagged in place by #2647 (in-line HTML comments and prose notes marking "no equivalent found" / "capability gap") but neither was redesigned — the flags are acknowledgments, not solutions.

## Deliverables
1. Decide and document one element-reference convention to replace overlay numbers across every affected file: either (a) standardize on referencing elements by the `eN` ref from the most recent `snapshot` (already suggested as an interim fallback in `browser-review.md` line ~29), or (b) a different convention if `eN` refs prove insufficient for this skill's reporting needs (e.g. they're ephemeral and regenerate per snapshot, which may not survive into a written report the way a numbered overlay did).
2. Update every prose mention across `visual-review/SKILL.md`, `browser-review.md`, `discover-mode.md`, `journey-mode.md`, `page-mode.md`, and `qa-accelerated.md` (the ~18+ occurrences found) from "reference overlay numbers" / "annotated overlay [N]" language to the chosen replacement convention.
3. Decide whether to prescribe an `eval`/`PerformanceObserver` (or `web-vitals` library) vitals workaround as a documented, supported capture mechanism, or to formally accept that Performance findings are unavailable until Playwright CLI ships a vitals equivalent.
4. If prescribing a vitals workaround: document the exact `eval` script/invocation pattern in `playwright-cli-reference.md` and/or `browser-review.md`'s "Vitals interpretation" section, replacing the current "omit the Performance line" instruction with the new capture step.
5. If accepting unavailability: remove or rewrite the "omit the Performance line" language to read as a settled decision rather than an open gap, and note the decision's rationale (e.g. no reliable workaround, or the workaround's fidelity/complexity cost wasn't worth it).

## Acceptance Criteria
- No remaining prose in `visual-review/*.md` describes "annotated overlay [N]" or "reference overlay numbers" as the current, working convention — every such mention either uses the new convention or is clearly marked as describing pre-migration behavior for historical/comparison purposes only.
- `browser-review.md`'s "Overlay-numbering gap" note (line ~29) and its "Capability gap" vitals note (line ~136) are replaced with settled guidance (not open gap descriptions) reflecting whichever decision was made for each of the two capabilities.
- If a vitals workaround was chosen: a documented invocation exists (e.g. in `playwright-cli-reference.md` or `browser-review.md`) that a builder can copy-paste to capture at least one of LCP/CLS/INP/TTFB/FCP via `eval`.
- If vitals unavailability was accepted: the report structure (Step 6 findings table, per `browser-review.md`) no longer references an "omit Performance line" caveat as pending — it reflects the settled absence of a Performance finding category.
- A grep for `overlay \[` or `annotated overlay` across `plugin/skills/visual-review/*.md` after the change returns zero unresolved (pre-decision) hits.

## Technical Approach
Read `plugin/skills/visual-review/browser-review.md`'s two capability-gap notes (line ~29 for overlay-numbering, line ~136 for vitals) as the canonical starting point — both already state the constraint and a candidate direction. For overlay-numbering, evaluate whether `eN` refs (session-scoped, regenerate on every snapshot per `playwright-cli-reference.md`'s Cautions section) are stable enough to reference in a written report that a human reads after the session ends; if not, design an alternative (e.g. a manually-maintained numbered list derived from the snapshot text at report-write time). For vitals, evaluate the `eval`/`PerformanceObserver` workaround's practicality (browser support, whether Playwright CLI's `eval` command can run an async `PerformanceObserver` callback and return timing data) before committing to prescribing it.

## Gotchas
- `eN` refs are explicitly documented as ephemeral (regenerate on every snapshot, per `playwright-cli-reference.md`'s Cautions) — a report written after the session ends may reference a ref that no longer resolves to anything if a new snapshot was taken later in the same session. Any `eN`-based convention needs a rule for when a ref is "frozen" for reporting purposes (e.g. capture ref + description together at the moment of finding, not after the fact).
- The vitals decision is genuinely open in this record — do not treat prescribing the `eval` workaround as the obviously-correct choice without evaluating whether it's reliable and maintainable; accepting unavailability is an equally valid outcome if the workaround proves fragile.
- This record's scope spans six files with a large mention count; verify the full mention list with a fresh grep before considering the sweep complete, since new mentions may have been added to these files since this record was filed.
