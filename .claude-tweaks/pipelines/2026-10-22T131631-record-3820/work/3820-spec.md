# 3820: Let drift-only upstream-drift entries opt out of the upgrade-available finding

Origin: ledger resolve gate

Defer-reason: genuinely-larger

## Current State

Claude Code releases near daily, so `tools/upstream-drift/run.js` keeps an `upgrade-available` finding for the `claude-code` entry almost permanently (installed 2.1.302 against latest 2.1.304 at #3304 build time), and dedup reopens it after every lag. For a drift-only, floor-pinned entry the assertions carry the signal, not the version. Found in #3304's final review (I4).

**Related:** #3818

## Deliverables

Add an upgrade-class opt-out (a manifest field or an entry-level setting) that suppresses `upgrade-available` for drift-only entries.

Set it on the `claude-code` entry and cover it with a `tools/upstream-drift/tests` case.

## Acceptance Criteria

`node tools/upstream-drift/run.js due --dep claude-code` reports no `upgrade-available` finding when the installed version is behind latest.

Other entries still report `upgrade-available` as before.

## Release Note

No user-visible change.

- `tools/upstream-drift/manifest.yml` — claude-code entry
