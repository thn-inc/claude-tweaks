# 2870: resolve-run-dir mis-resolves a stale, never-closed standalone run directory as current

## Current State

During a standalone /claude-tweaks:backlog refine run (2026-10-01), `resolve-run-dir --spec-slug backlog-standalone --create` returned a pre-existing run directory, `20260911T131119-backlog-standalone` (last touched 2026-09-20, ~3 weeks stale, never closed), instead of minting a fresh one. The directory carries no `run-state.json`, so nothing marks it closeable or orphaned, which lets it be resolved as "the current run" indefinitely. The agent that hit this detected the staleness from the directory's age and missing run-state.json, declined to write into it, and hand-minted a separate directory instead rather than risk mixing new writes into stale history. The old directory is still sitting there unclosed.

## Deliverables

Make the standalone-run resolution path (`resolve-run-dir --spec-slug <slug> --create`, or whatever backs it) detect a candidate directory with no `run-state.json` and either (a) refuse to hand it back as the current run and mint fresh instead, or (b) flag it for reconcile/close-run cleanup rather than silently sitting there as a live-looking resolution target.

## Acceptance Criteria

- A `resolve-run-dir --spec-slug <slug> --create` call no longer hands back a pre-existing directory that has no `run-state.json`; it mints a fresh directory instead.
- A regression test reproduces the original symptom (a fixture directory with decisions.md content but no run-state.json) and asserts the new behavior.
- The pre-existing `20260911T131119-backlog-standalone` directory gets an explicit disposition (closed or reconciled) as part of or alongside this fix.
