# 3856: wrap-up-engine render: resolve an archived run directory like verify does

Origin: reflect light from #3672

Defer-reason: tangential

## Current State

`plugin/bin/wrap-up-engine.js` `render` reads `engine-state.json` from the exact `--run-dir` it is given (`runRender`, `fs.readFileSync(path.join(args.runDir, 'engine-state.json'))`), with no archive fallback. `verify` in the same file resolves an archived run via `resolveArchivedRunDir(args.runDir, repoRoot)` (`plugin/bin/lib/wrap-up/engine-verify.js`). #3672 moved wrap-up's phase-trace report to render after the execute step, whose cleanup item 8 archives the run directory, so `render --run-dir "$PIPELINE_RUN_DIR"` now runs against an already-archived run. #3672 worked around it in prose (`wrap-up/SKILL.md` tells the agent to pass the archive path), which depends on the agent following one sentence.

## Deliverables

- [ ] Make `wrap-up-engine.js render` resolve an archived run directory the way `verify` does, so the original `$PIPELINE_RUN_DIR` path works before and after cleanup item 8.

- [ ] Once that lands, drop the archive-path sentence from `plugin/skills/wrap-up/SKILL.md`'s phase-trace report step and its pin in `tests/wrap-up-phase4-report-order-conformance.test.js`.

## Acceptance Criteria

- `wrap-up-engine.js render --run-dir {original-path} --section trace --strict` prints the same table whether the run directory is still in place or has been moved to `.claude-tweaks/pipelines/archive/{run-id}/`.

- A test covers the archived-run render path and goes red when the fallback is removed.
