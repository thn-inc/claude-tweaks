Surface: infra

**Related:** #2401, #2402

## Current State

Split out of #1853's Deliverable 5. While building #1853 (root-privileged `npm test` failures), three of the sixteen originally-reported failures were confirmed **not** permission-related and **not reproducible on this checkout as a normal user** (20/20 across the three files, run clean):

- `tests/impeccable-plugin-contract.test.js` — pins the installed Impeccable plugin's version; fails in a sandbox whose plugin cache carries a different (or absent) version than this checkout expects.
- `tests/shaping-mode-needs-removal.test.js` — whole-file failure, cause not reproduced locally.
- `tests/tidy-needs-worklist-rule.test.js` — whole-file failure, cause not reproduced locally.

Reproduction condition: **sandbox only — passes locally.** This record does not claim to fix them; it exists to track the gap once #1853's permission-simulation skips land (so a root sandbox's `npm test` can go fully green there per #2010).

## Deliverables

- [ ] Reproduce the `tests/impeccable-plugin-contract.test.js` failure in a sandbox with a differently-versioned or absent Impeccable plugin cache; determine whether the pin should read the installed version dynamically or the sandbox's plugin-provisioning step needs a fix.
- [ ] Reproduce `tests/shaping-mode-needs-removal.test.js` and `tests/tidy-needs-worklist-rule.test.js`'s whole-file failures in the same sandbox shape; identify the actual cause (environment-dependent fixture path, missing plugin cache asset, or similar) before proposing a fix.

## Acceptance Criteria

1. Each of the three tests' sandbox failure is reproduced (not just cited) and its root cause identified.
2. A fix or an explicit environment-provisioning follow-up is proposed for each.
3. `npm test` as a normal user on this checkout stays green throughout.

Once reproduced, `tests/impeccable-plugin-contract.test.js`'s fix path likely means reading the installed plugin version dynamically (rather than a hardcoded pin) or fixing the sandbox's own plugin-provisioning step; the two whole-file failures need their actual cause identified before a fix direction can be proposed at all.
