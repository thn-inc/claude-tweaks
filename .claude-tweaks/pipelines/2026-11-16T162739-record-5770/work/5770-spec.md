# 5770: Build the learned-skills test fixtures once per process instead of once per test

**Related:** #5324, #5297

Verified-as-of: c059556fc34954c27371c25ebd65f99e79a4eb0a

## Current State

A full-suite profile on main at 8646f7c (2026-11-16, `node tools/run-tests.js --full`, git trace2 per test file) counted 59,448 git processes. The test files under `tests/bin-lib/learned-skills/` start 10,629 of them (18%):

| File | Git processes | Notes |
|---|---|---|
| `land.test.js` | 3,460 | 57 tests; 2,414 from the test process, 1,046 children of another git; diff 367, rev-parse 295, status 250, apply 220. 161 s of git time, the most of any file in the suite |
| `capture-matrix-joined-crlf.test.js` | 1,009 | diff 343, hash-object 194, apply 190, status 136 |
| `capture.test.js` | 961 | diff 241, status 149, checkout 85, apply 82 |
| `capture-matrix-joined.test.js` | 937 | diff 343, apply 190, status 136, hash-object 122 |
| the other seven `capture-matrix-*` files | the remaining 4,262 | not broken down in the profile |

- `land.test.js`: `fixture(t, { capturedTargets, autocrlf })` runs for every test. It inits a bare origin, inits a clone, commits two skill files, pushes `main`, makes a run directory and captures one patch per target (each capture is several git calls). Five tests then clone a second checkout and push from it, or force-push a foreign commit onto the run's branch, to arrange a state.
- `tests/helpers/learned-skills-capture.js`: `fixture(t, extraFiles, { autocrlf })` inits and commits per call for `capture.test.js`. The matrix files already reuse per-process scenario templates (`scenario()` over the `templates` map).
- In the matrix files most of what remains is `capture()` itself plus the helper's own read-only checks around each fault combination (`breaches`, `status`, `diffOf`, `headOf`).

`capture()` and `land()` in `plugin/bin/lib/learned-skills/` re-read tree and index state after each step that changes it. Those reads are part of their failure handling and are not repeats to remove.

`tests/helpers/git-template.js` (`fromTemplate`, `fromTemplateSet`) builds a fixture once per process and gives each caller a copy that starts no git process.

## Deliverables

1. `land.test.js`: the state `fixture()` returns (bare origin, clone, run directory with its captured patches and manifest) is built once per distinct option set through `fromTemplateSet` and copied per test. Any absolute path stored outside git's own files (manifest, patch files, `decisions.md`) is rewritten for the copy or shown not to exist.
2. `land.test.js`: a clone, push or force-push that only arranges state is folded into a template variant or replaced by a local ref update in the bare origin. Pushes, fetches and `ls-remote` calls made by `land()` itself stay real, as does `gitCalls` recording them.
3. `tests/helpers/learned-skills-capture.js`: `fixture()` comes from a template keyed by its arguments.
4. In the matrix path, a read-only git call the helper makes twice for one fault combination with nothing changed in between is made once. Product code under `plugin/bin/lib/learned-skills/` is not changed by this record.
5. If the traces show a same-question repeat inside one `capture()` or `land()` call with no state change between the two reads, the PR body lists it and it is filed with `/claude-tweaks:capture`.
6. The PR body reports git processes for every file in `tests/bin-lib/learned-skills/`, before and after.
