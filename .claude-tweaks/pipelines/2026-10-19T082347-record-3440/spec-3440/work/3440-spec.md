The run's own `verify-report` artifact shows the real picture. The issue body's excerpt does not.

- **Base commit 6a25dc724 (baseline log):** 2 failing tests, `#1929 AC4: --auto-transcript locates…` (line 113) and `#1929 whole-branch review fix 2: … (mode 000)` (line 170). Both failures predate this merge.
- **Head commit ffe20b982 (isolated log, and the isolated retry, which matches it exactly):** 7 failing tests, the same 2 plus 5 new ones from #3375: `#3375 AC3.1` (line 210), `#3375 AC3.2` (line 234), `#3375 AC4: a not-found dispatch…` (line 242), `#3375 AC4: an empty transcript…` (line 255), and `#3375: with several transcripts…` (line 313).

The issue's excerpt quotes the pre-existing `#1929 AC4` failure because `tools/windows-regression/file-issue.js`'s `excerptFor` takes the first `not ok` naming the file, not the first newly failing one.

All three causes are in the test file. The production code in `plugin/bin/phase-timing.js` and `plugin/bin/lib/timing/transcript.js` behaves correctly on Windows:

1. **The fixture home is set through `HOME` alone.** The `#1929 AC4` test (lines 121 and 126) and the `subagentRun()` helper (line 203) point the CLI at a temporary home with `env: { ...process.env, HOME: home }`. `locateTranscripts` defaults `homeDir` to `os.homedir()` (`transcript.js:41`). On Windows, `os.homedir()` reads `USERPROFILE`, not `HOME`, so the CLI searches the runner's real profile. The CI output says `tokens: transcript not found (no sess-1.jsonl under the worktree slug directory)`. This breaks `#1929 AC4` (pre-existing), `#3375 AC3.1`, and both `#3375 AC4` tests. `tests/statusline.test.js:932` already records the same Windows behavior.
2. **The golden files are read raw from a CRLF checkout.** `#3375 AC3.1` (line 214) and `#3375 AC3.2` (line 238) read `tests/fixtures/timing/subagents-golden-auto.md` and `subagents-golden-plain.md` with a bare `fs.readFileSync`. Under `core.autocrlf=true` those files carry `\r\n`, while the CLI writes `\n`. The AC3.2 diff in the CI log differs only in line endings. `.gitattributes` exempts only `tools/upstream-drift/fixtures/**`.
3. **A path is matched with a forward-slash regex.** The `#3375: with several transcripts…` test (lines 322 and 324) matches `/…sess-2\/subagents$/`. `readDispatches` names the native `fs` path, which on Windows is `…\sess-2\subagents`. CI actual: `no subagents/ directory at D:\a\_temp\ct-timing-home-EQjibG\.claude\projects\-Users-x-Code-repo--claude-worktrees-wt\sess-2\subagents`.

The pre-existing `fix 2` failure (line 170) has a different cause. It makes a file unreadable with `fs.chmodSync(…, 0o000)`, which on Windows only toggles the read-only attribute, so the read succeeds. It is skipped only under root (`skipUnderRoot`), never on win32.

## Release Note

Fix the phase-timing CLI tests so they pass on a Windows checkout.

## Technical Approach

Test-only change in one file. Each fix follows a pattern this repo already uses (`.claude/skills/windows-checkout-test-parity/SKILL.md`):

- **Home override:** `os.homedir()` resolves `USERPROFILE` on win32 and `HOME` elsewhere, so setting both keys to the fixture home makes the override effective on every platform. No production change and no new `--home` flag is needed: `locateTranscripts` already takes an injectable `homeDir`, and the CLI's use of `os.homedir()` is correct behavior.
- **CRLF goldens:** reuse `readText` from `tests/helpers/read-skill.js` (#2763's shared EOL-normalizing read). The CLI's own output is `\n`, which is the contract. The golden file's working-copy line endings are a checkout artifact, so normalize at the read.
- **Native path expectation:** the `notFound` text names an `fs` path, which is native by contract, not a display ID. So fix the expectation with `path.join`, per the skill's "Display IDs and native paths are two contracts" rule, and leave the producer alone.
- **Mode-000 test:** combine the existing `skipUnderRoot(...)` result with a `process.platform === 'win32'` reason (for example, `{ skip: (IS_ROOT && 'root ignores file permissions') || (process.platform === 'win32' && 'win32: chmod 0o000 only sets the read-only attribute') }`), matching the explicit-skip convention in `tests/helpers/root.js`.

### Key Files

- `tests/bin-lib/timing/cli.test.js`: add `USERPROFILE` to the three fixture-home env objects, read the goldens via `readText`, use a `path.join` expectation in the several-transcripts test, and add a win32 skip on the mode-000 test.
- `tests/helpers/read-skill.js`: reused as-is (`readText`), no change.
- `tests/fixtures/timing/subagents-golden-auto.md`: unchanged; now read via `readText`.
- `tests/fixtures/timing/subagents-golden-plain.md`: unchanged; now read via `readText`.

## Gotchas

- Do not "fix" this in `plugin/bin/lib/timing/transcript.js` or `plugin/bin/phase-timing.js`. Both behave correctly on Windows. A production `HOME` preference would diverge from where Claude Code itself writes transcripts on win32.
- The issue body's excerpt shows a failure that also existed at the base commit. Judge the fix by the 7-vs-2 failing-test diff in the run's `verify-report` artifact, not by the excerpt (`docs/donts.md` `[IL-160]`).
- The other root-cause fix in this file, adding a `.gitattributes` `eol=lf` rule for `tests/fixtures/timing/*.md`, was considered and rejected. It changes the checkout of every Windows clone for one suite, while `readText` is the repo's established per-read normalization.
- Interaction with #3458, which is `ready` and makes `locateTranscripts` honor `CLAUDE_CONFIG_DIR`. These fixture-home spawns copy `process.env`, so once #3458 lands, a `CLAUDE_CONFIG_DIR` set on the developer machine or runner would override the fixture home on every platform. Whichever of the two lands second must also remove `CLAUDE_CONFIG_DIR` from these env objects. Deliverable 1 does this already. If #3458 lands first and adds its own handling, keep a single removal, not two.
- `tools/windows-regression/file-issue.js`'s `excerptFor` picks the first `not ok` for an attributable file even when that test also failed at the base. This misleading excerpt is a separate defect in the filer and out of scope here.
