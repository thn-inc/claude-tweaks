The post-merge `windows-regression` workflow (run 39101872855, on `windows-latest`) found three test files newly failing after PR #3434 merged as `2a0b7f65a`. PR #3434 shipped #3370's unattended-console residue feature. The production code is correct on Windows. Every failure is a test assertion that hard-codes `/` as the path separator, for a path that the code under test builds natively with `path.join` / `path.resolve`. On Windows that path comes out as `D:\a\...\pipelines\...`. Verified against `origin/main` at `7852fd8bf`, where none of the three files has changed since `2a0b7f65a`:

- `tests/bin-lib/console/cli.test.js:382`: the `#3370` "Needs a human" test pins the trailing `paths move when the run is archived` line with ``new RegExp(`... node "/.+/bin/console-residue\\.js" --run "/.+/${path.basename(fx.runDir)}"$`)``. The producer is `plugin/bin/console-resolve.js:39`'s `needsAHumanBlock`, which prints `${pluginRoot}/bin/console-residue.js` (pluginRoot comes from `path.resolve`, so on Windows it is backslash-separated with a literal `/bin/...` tail) and `--run "${runDir}"` (native). The leading `"/` and the `/` separators in the regex never match a `D:\...` path.
- `tests/bin-lib/console/residue-cli.test.js:160`: the `MOVED` regex expects `.*/pipelines/{run} has moved to .*/pipelines/archive/{run}`. `plugin/bin/console-residue.js`'s pre-archive fallback prints `o.run` (the test builds it with `path.join`) and `archiveDir` (`path.join`), both native. `MOVED` is asserted at lines 169 and 179. Line 169 failed. Line 179's test (`--ack given the pre-archive path ...`) asserts the same regex and must be fixed too.
- `tests/bin-lib/console/residue.test.js:108`: `lines.includes(`    cat "${dir}/staged/review-13-record.md"`)`. `plugin/bin/lib/console/residue.js`'s `itemLines` builds that path with `path.join(consoleDir, 'staged', item.id)`. The same `${dir}/...` shape appears at lines 121, 129, 172 and 182 (the `spec-12/staged`, `… and 2 more — see`, `(no id)` and `see "${dir}/decisions.md"` tests). The run reported only the first failure in the file, so those lines are latent failures of the same class.

These are native filesystem paths printed as paste-ready commands, not display IDs. `windows-checkout-test-parity`'s "Display IDs and native paths are two contracts" rule therefore puts the fix on the test side: build the expected value with `path.join` / `path.resolve`, the same way the code under test does. The producers are not normalized to `/`.

Fixed three console-residue tests that failed on Windows because they expected forward-slash paths.

## Technical Approach

Test-side only, following `.claude/skills/windows-checkout-test-parity/SKILL.md`. "Display IDs and native paths are two contracts" says to build the expected value with `path.join`/`path.resolve` when the code under test joins the path. Its Anti-Patterns row says not to expect a POSIX absolute literal where the code resolves the path. Prefer exact strings built from fixture paths over loosened regexes wherever the fixture knows the real path, as `residue.test.js` and `residue-cli.test.js`'s `--ack --run "${fs.realpathSync(f.runDir)}"` pin already do. Where a regex stays necessary (a temp root or a `mainCheckoutRoot`-derived prefix the test cannot predict), replace each literal `/` separator with `[\\/]` and pass interpolated path fragments through a regex escape.

### Key Files

- `tests/bin-lib/console/cli.test.js` — line 382's `paths move when the run is archived` regex made separator-agnostic
- `tests/bin-lib/console/residue-cli.test.js` — `MOVED` regex (line 160) made separator-agnostic for both tests that assert it
- `tests/bin-lib/console/residue.test.js` — expected `cat`/`see` paths at lines 108, 121, 129, 172 and 182 built with `path.join`

## Gotchas

- Do not "fix" this by normalizing the producers to `/`. These are paths a human pastes into a shell, and native separators are correct there. `toPosix` is for display IDs only (the parity skill's Decision Framework row). The mixed `D:\...\plugin/bin/console-residue.js` that `${pluginRoot}/bin/...` produces on Windows is valid for `node` and is out of scope here.
- On macOS, `os.tmpdir()` sits behind a `/var` → `/private/var` symlink. `cli.test.js`'s fixture already `realpathSync`s its root, but `residue-cli.test.js`'s second `MOVED` test derives `mainRoot` from cwd via `mainCheckoutRoot`, so an exact-string pin there must use the same resolved form or stay a separator-agnostic regex.
- On `windows-latest`, the checkout is on `D:` and `os.tmpdir()` is on `C:` (the parity skill's real-runner section). Any expected prefix must come from the fixture's own paths, never from a hard-coded drive or root.
- This is one of several open `Windows regression:` records (#3506, #3507, #3509, #3517, #3518, #3523, #3440, #3429), each for a different commit and different files. Keep this record to the three console-residue suites and their sibling greps.
