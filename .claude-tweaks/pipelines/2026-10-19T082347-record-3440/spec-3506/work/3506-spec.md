# 3506: Windows regression: 2 test file(s) newly failing after 5cf9073d3

Surface: infra

## Current State

`.github/workflows/windows-regression.yml` flagged `tests/bin-lib/reconcile/pr-state.test.js` and `tests/bin-lib/reconcile/release-merged.test.js` after 5cf9073d3 (PR #3439, which shipped #3412). The production code is not at fault. Every failure in both files comes from how the tests fake `gh`, and the fake does not work on a Windows checkout.

The issue's two excerpts are misleading. The run's `verify-report` artifact (run 39101659988) shows that both quoted tests also fail at the base commit f49277005. They are `pr-state.test.js:35` ("merged PR wins over other PRs for the same branch") and `release-merged.test.js:242` ("Phase 1.5 resolves prState via the pool…"). The excerpt quotes only the first failure in each file, and the filer flagged the files because #3412 added new tests that fail for the same reason. Per-file counts, run in isolation:

| File | Base f49277005 | HEAD 5cf9073d3 | Newly failing (all added by #3412) |
|---|---|---|---|
| `pr-state.test.js` | 20 of 38 fail | 22 of 40 fail | lines 529 and 542 (`request closingIssuesReferences…`) |
| `release-merged.test.js` | 7 of 25 fail | 17 of 50 fail | line 381 (by-number fallback keeps the claim…), lines 938, 952, 965, 978, 993, 1004, 1017 (the `run3348Scenario` tests), and lines 1113, 1129 (the `runTwoCandidateScenario` tests) |

(Line numbers are from `origin/main` 7852fd8bf. Neither file has changed since 5cf9073d3.)

There are two causes, both Windows-only:

1. **A `#!/bin/sh` file named `gh` on PATH is never spawned.** `pr-state.js` calls `execFileSync('gh', …)` and `execFile('gh', …)` with no injection point. The tests put a script named `gh` (no extension) first on PATH: `installGhWrapper` at `pr-state.test.js:17`, plus `installArgvSpy` and `installArgvLoggingGhWrapper`, and inline `wrapperPath = path.join(wrapperDir, 'gh')` blocks in `release-merged.test.js`, including the shared `run3348Scenario` (line 869) and `runTwoCandidateScenario` (line 1035). On win32, Node looks up an extensionless command by appending `.com` and `.exe`, so the stub is skipped. Even if it were found, Windows cannot run a shell script directly. The tests then get a transport classification (`'gh-absent'`/`'network-failure'`) instead of the stub's JSON. That matches every error in the logs: `undefined !== 2`, `Cannot read properties of undefined (reading '0')`, and `{"reason":"network-failure"}` skips in `release-merged`.
2. **POSIX literal `'/tmp'` used as `repoRoot`/cwd.** `pr-state.test.js` passes `'/tmp'` 61 times. On a Windows checkout `/tmp` resolves to `{drive}:\tmp`, which does not exist. The by-number resolvers' #3029 guard (`classifyByNumberError` in `plugin/bin/lib/reconcile/pr-state.js`, around line 137) then reports `'invalid-arguments'`. So the three stub-free "gh absent -> gh-absent" tests (lines 300, 381, 489) fail with `+ 'invalid-arguments' - 'gh-absent'`.

Precedent: `tests/console-execute.test.js` (#3358) uses the same PATH-stub technique, cites `pr-state.test.js` as its source, and already skips those tests on win32 (`{ skip: process.platform === 'win32' }`, line 443 onward).

**Related:** #2767, #3412, #3416, #3429, #3440, #3491, #3505, #3507, #3509, #3517, #3518, #3523

## Deliverables

1. In `tests/bin-lib/reconcile/pr-state.test.js`, replace the POSIX literal `'/tmp'` passed as `repoRoot` with a real directory (`os.tmpdir()`, held in one module-level constant). Leave the deliberately nonexistent paths alone: `'/definitely/not/here'` and `'/tmp/definitely-not-a-repo-xyz'`.
2. In both files, skip every test that depends on a `gh` stub on PATH when running on win32, with a stated reason. Use one per-file constant, for example `const PATH_STUB_SKIP = process.platform === 'win32' && 'win32: execFileSync("gh") never spawns a #!/bin/sh stub named gh on PATH'`. This covers the tests that call `installGhWrapper` / `installArgvSpy` / `installArgvLoggingGhWrapper`, the inline wrapper blocks, and every test that runs through `run3348Scenario` or `runTwoCandidateScenario`. That includes the three `pr-state` guard tests that install a spy only to assert `gh` was never called (current lines 410, 421, 455). They pass on win32 today, but vacuously, because there the spy can never observe a call. Tests that install no stub keep running on win32: the pure `decideRelease` / `prClosesIssue` / `shouldSkipClaimRead` tests, the injected-runner `resolvePrStatesBulk` tests, the falsy-number short-circuit test, and the PATH-emptied gh-absent tests.

## Release Note

Fixed two reconciler test suites that failed only on Windows checkouts, with no change to plugin behavior.

## Technical Approach

- **Skip, not a production seam.** Rejected alternative: add an injectable runner to `pr-state.js`'s `resolvePrState*` functions (the `gh-api-module-pattern` seam), so the tests can stop faking `gh` through PATH. That would change a production module that `release-merged.js`, `archive-merged.js`, `reap-merged.js` and others depend on, purely for a test platform. The resolver logic is platform-neutral, and the POSIX run covers it. This matches #3429's ruling and the `windows-checkout-test-parity` skill: behavior only one platform can produce gets a `skip` with a stated reason. `tests/console-execute.test.js` already applies exactly this skip to the same stub technique.
- **`'/tmp'` -> `os.tmpdir()`.** This is the parity skill's "POSIX absolute literal" anti-pattern. A real directory lets the gh-absent tests reach their real ENOENT-for-gh branch on win32 instead of the #3029 nonexistent-directory branch. It also keeps the by-number stub tests honest on POSIX.
- Apply the skip per test (`test(name, { skip: PATH_STUB_SKIP }, fn)`), not by skipping the whole file. Each file has stub-free tests that should keep running on Windows.

### Key Files

- `tests/bin-lib/reconcile/pr-state.test.js`: add `os.tmpdir()` repoRoot constant replacing `'/tmp'`, and `PATH_STUB_SKIP` on the 22 stub-installing tests
- `tests/bin-lib/reconcile/release-merged.test.js`: add `PATH_STUB_SKIP` on the 17 stub-installing tests (lines 242–713 inline wrappers, 381, the `run3348Scenario` and `runTwoCandidateScenario` callers)
- `plugin/bin/lib/reconcile/pr-state.js`: read-only reference (`execFileSync('gh')` call sites, `byNumberArgsValid`, `classifyByNumberError`). No change
- `tests/console-execute.test.js`: read-only reference (existing win32 skip on the same stub technique)
