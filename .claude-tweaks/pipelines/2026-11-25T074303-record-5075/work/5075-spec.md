# 5075: A bookkeeping-only commit after a scoped build verify re-runs the whole impact-selected suite

# Reflect — staged finding 1

**Category:** tangential

Origin: reflect hindsight from #4395

Defer-reason: tangential

## Current State

A scoped re-verify classifies the delta since the stamp anchor `fullSha`, and a scoped pass does not advance that anchor (`anchorOf` in `plugin/bin/lib/verify/stamp.js` returns the `fullSha` field of the stamp, and a scoped pass writes its own base there, `plugin/bin/verify.js`). So after `/build` Common Step 5 passes scoped at S, a bookkeeping-only commit (a run-ledger row) followed by `/test` gets a delta of every file the branch changed since the merge-base, not just the ledger path.

Observed on #4395's own run: build verified 4acac2138 (scoped, impact-selected, 12794 tests), a ledger-only commit moved HEAD to 55a8e9ef8, and `/test` re-ran the same 12794 tests for 140 s before stamping HEAD `scope: scoped` (`report.json`, `scope.base` = the merge-base `ebeb43749`). The stall #4395 fixes is gone, but the `scope: none` outcome its AC1 names only happens when the prior pass was a full one.

## Deliverables

- [ ] When the prior stamp is a passing non-full pass (`scoped`, `none`, `static-only` or `tool-scoped`) at a commit that is an ancestor of HEAD, classify the delta since that pass (not since `fullSha`) so a bookkeeping-only delta resolves to `none` and re-stamps HEAD without running a suite.

- [ ] Keep `fullSha` as the base for every delta that contains a non-bookkeeping path, so the scoped set never narrows below the last full pass.

**Decision** (2026-11-25, autonomous lane authorized by the maintainer; answers the plan-review question of 2026-11-25): **Reading B.** Any clean, passing non-full stamp (`scoped`, `none`, `static-only`, `tool-scoped`) whose sha is an ancestor of HEAD may anchor the bookkeeping-only shortcut, so `none` stamps may chain. Reason: under Reading A a second bookkeeping commit (test, review and wrap-up each append ledger rows) re-runs the mapped suites, which is the cost this record removes. Chaining is safe because the shortcut only ever accepts a delta whose every path is bookkeeping (resolves to `none`), and it never changes `fullSha`.

**Family rule for related questions:** the prior stamp anchors only the bookkeeping-only classification. The stamp the shortcut writes carries the prior stamp's `fullSha` unchanged (it never advances `fullSha` to HEAD or to the prior stamp's sha). Any delta with a non-bookkeeping path is classified from `fullSha` exactly as today. A stamp that is failing, dirty, not an ancestor of HEAD, or unreadable never anchors the shortcut: fall back to today's behavior. When the shortcut fires, no suite command is spawned at all (the command set is empty), so AC1's "runs no suite" holds for `--cmd` invocations too.

## Acceptance Criteria

1. With a passing scoped stamp at S and a HEAD whose delta from S is only `docs/plans/*-ledger.md`, `verify.js --scope` runs no suite, prints `still-verified: bookkeeping-only delta`, and `--stamp-status` reports `verifiedHead: true` at HEAD.

2. With a passing scoped stamp at S and a delta from S that contains one `plugin/**` path, the scoped run selects the suites that path maps to, over the delta since `fullSha`, exactly as today.

## Release Note

A run-ledger commit after build's scoped verification no longer re-runs the impact-selected test suite: the test step re-stamps the new commit without running anything.

## Technical Approach

### Key Files

- `plugin/bin/verify.js` — let a scoped pass stamp anchor the next scoped delta
- `plugin/skills/test/verification.md` — document the scoped-anchor rule in Re-verify scoping
