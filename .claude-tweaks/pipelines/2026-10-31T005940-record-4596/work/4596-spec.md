## Deliverables

- A `plugin/bin/` CLI that runs `staleClaimInFlightPr` over `gh`, or over an agent-fetched listing file (MCP `list_pull_requests` pages normalized to `{url, body, isCrossRepository}` from `head.repo.full_name`), and, for /tidy, validates the matched PR's `### Resume` line against `pr-body.js`'s `composeResumeLine` shape — printing JSON `{match, link, resume | resolve, failure}`.
- `_shared/issue-claims.md` step 4's MCP path and `tidy/scan-procedures.md` Step 4.7 call the CLI instead of restating the rule.

## Acceptance Criteria

- Neither prose file restates the marker-match rule or the Resume-line grammar; each names the CLI.
- A test feeds the CLI a gh-shaped and an MCP-shaped listing and gets the same verdict for a matching same-repo PR, a fork PR, an inline marker mention, a 1000-entry no-match (failure), and a malformed listing (failure).
- A Resume line whose tail carries `; rm -rf ~` or a `$(…)` in its target yields `resolve`, never `resume`.
