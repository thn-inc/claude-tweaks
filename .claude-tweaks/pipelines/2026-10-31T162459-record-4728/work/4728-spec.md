## Current State

`plugin/skills/flow/context-handoff.md`'s continuation template (the Agent prompt a /flow run dispatches once its context crosses the cap) tells the child that it inherits the run's worktree, and gives it the plugin root and the async-wait discipline. It says nothing about the harness's worktree shell constraint. `plugin/skills/dispatch/task-prompt.md` item 6 does carry it for dispatch's own first and second calls, and `_shared/subagent-dispatch-core.md`'s "One plain command per Bash call" paragraph requires every worktree-isolated dispatch prompt to state it.

Run `2026-10-30T200217-spec-4588` handed off twice (`decisions.md` AUTO 21:07:12 and 13:46:23), and the continuation children ran the SDD controller, test, review and polish inside the isolated worktree. `friction-events.js` returned 40 `wd-guard-refusal` events (reason `harness-worktree-isolation`) for a five-task build: `cd …;` chains, shell variables reused in the same call, heredocs, `for` loops and `$(…)` substitutions. Several came from controller-shaped commands (`for n in 3 4 5; do bash …/task-brief …`, `cd "{worktree}"; node -e …`), not only from SDD implementers. #4243 covers the SDD implementer and reviewer dispatches, but not this continuation template.

Probe: `git grep -n -i -F -e 'shell constraint' origin/main -- plugin/skills/flow/context-handoff.md` and `git grep -n -F -e 'scratch-worktree.md' origin/main -- plugin/skills/flow/context-handoff.md` both exit 1, so neither appears in the file.
