# 5941: Set a launched agent's effort from its resolved profile

Surface: backend
Risk-flags: public-contract

## Overview

Adds a policy value under which the effort the profile resolver returns is set on the agent launch itself, through the Agent tool's `effort` parameter. Today the effort reaches an agent only as a sentence in its prompt, and a probe shows that sentence does not change the effort the agent runs at: between 8 and 19 November 2026, 60% of subagent turns on Sonnet, Opus and Fable ran at `medium` although every one of those profiles names `high`. This repository opts in and sets Standard and Capable to `medium`: the effort 60% of Sonnet, Opus and Fable subagent turns ran at in the window, and, for Capable under an Opus session at `high`, a deliberate lowering from `high` (see Gotchas).

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- Changing the shipped profile table or the default for other projects. With the value unset every launch is what it is today.
- A lower effort than `medium` for any role in the shipped table or this repository's `policy.yml`, and a retry at a higher effort after a failure. Those are the design's Phases 9 and 14. A stance (`--stance economy`) still lowers `launchEffort` one step, as it lowers `effort` today.
- Driver workers: #5942.
- Agents started by the opt-in review workflow (`plugin/workflows/review-lens-fanout.js`). They run at the harness default, measured `medium` in `docs/reference/workflow-tool-probe.md`, and whether a workflow script can set an effort is not known.
- Removing the prompt sentence (`effortLine`). It stays as it is.
- A hook that sets or checks a launch's effort.

## Release Note

Added a policy setting that makes a launched agent run at the effort its work profile names, instead of an effort that depended on which model the session was using.

## Technical Approach

The resolver already computes an effort for every launch; this record carries it to the one place where it takes effect. A second field, not a change to `effort`, keeps the prompt sentence and every reader of today's output unchanged, and lets the default reproduce today's launches exactly. The value is a switch, not a new table, because `model-profiles` rows already let a project choose each profile's effort. This repository picks `medium` because binding the table's `high` would raise most of its agents from the effort they run at now. See the design's Effort evidence and Phase 15 for the Decision Rationale.
