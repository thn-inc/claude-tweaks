# 4358: Hand off multi-spec /flow runs at the context cap — per-record resume

Origin: #4027 build (PR #4324) — context-cap handoff ruled single-spec only

Defer-reason: genuinely-larger

## Current State

Record #4027 (PR #4324) ships a per-agent context cap. At each phase boundary, `/flow` Step 4 gauges the running agent via `plugin/bin/context-gauge.js`. Past 200k tokens it writes `{run}/handoff.json` and hands the remaining steps to a fresh agent: `plugin/skills/flow/context-handoff.md`, with the dispatch continuation in `plugin/skills/dispatch/two-call-gate.md` §8.

The cap is single-spec only. A multi-spec run (`#A,#B`) never gauges, because `/flow`'s step-list resume grammar re-targets every record. A continuation would re-run records already past the boundary. Parallel-wave members never gauge either. So dispatched bundle groups, the calls with the largest contexts, get no context relief from #4027.

## Deliverables

1. A per-record resume form. `handoff.json` carries the remaining steps keyed per record, and `/flow` gains an argument that resumes each record at its own step.

2. The multi-spec sequential loop gauges at each spec/phase boundary and writes the per-record handoff.

3. The dispatch continuation accepts the per-record form. That covers `two-call-gate.md` §8, `task-prompt.md`'s continuation paragraph, and `first-call-artifact-check.js`'s `parseNextSteps`.

## Acceptance Criteria

- [ ] A multi-spec dispatched call that crosses the 200k-token cap at a phase boundary hands off. Its continuation resumes each record at that record's own step, without re-running a completed step for any record.

- [ ] The existing conformance suites pass with no added skips.

## Release Note

Long multi-record pipeline runs hand their remaining work to a fresh agent when context gets large, instead of degrading in one oversized context.

## Technical Approach

### Key Files

- `plugin/bin/lib/timing/context-gauge.js` — per-record nextSteps in handoff.json
- `plugin/skills/flow/context-handoff.md` — multi-spec handoff procedure
- `plugin/skills/flow/multi-spec.md` — gauge at spec/phase boundaries
- `plugin/skills/dispatch/two-call-gate.md` — per-record continuation
- `plugin/bin/lib/dispatch/first-call-artifact-check.js` — parse per-record NEXT_STEPS
