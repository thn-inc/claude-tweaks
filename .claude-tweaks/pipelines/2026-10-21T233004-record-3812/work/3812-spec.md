## Current State

#3595 fixed the in-run ordering: single-spec cleanup item 2 now commits and pushes the ledger deletion before item 4's `gh pr merge`, and the multi-spec Shared teardown step 0 has done the same since #3420 (`7a649060e`). Two residue ledgers landed on main after #3420 anyway, through PRs merged outside the run's own teardown:

- `docs/plans/2026-10-19-spec-3507-3509-ledger.md` via PR #3584. Run `2026-10-19T100244-record-3507` ended (`run-state.json` `lastEvent: session-end`) after spec 3509's `/test`, never reaching review, wrap-up or the consolidated console. A ledger delete that lives in the run's teardown cannot run when a human (or the fleet) merges the PR before the run reaches teardown. #3595 removed the 11 residue files on main by hand.

## Deliverables

1. Pick one mechanism that keeps a run's `docs/plans/*-ledger.md` off the integration branch when the PR merges outside the run's teardown, and record the choice. Two candidates:
   - (a) a PR check that fails a non-draft PR whose head adds a `docs/plans/*-ledger.md` the PR itself introduced;
   - (b) a reconcile/tidy convergence check that detects a merged run's ledger on the integration branch and opens a removal PR.
2. Implement it, including its registration sites (`docs/reconcile-checks.md` for (b)).
3. Test both directions: a merged-outside-teardown ledger is caught, and an in-flight draft PR's ledger is not.

## Acceptance Criteria

1. In a fixture where a PR head still carries its run's ledger, the chosen mechanism reports it, or opens the removal, before the residue can be counted by a later wrap-up.
2. A draft PR for a run still in progress, whose ledger is expected on the branch, is not flagged.
3. `npm test` passes.

## Release Note

Wrap-up ledgers no longer reach main when a run's PR is merged before the run finishes.
