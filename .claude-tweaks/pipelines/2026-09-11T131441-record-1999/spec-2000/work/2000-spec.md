# 2000: plan-audit: no control-byte check — a plan file containing a raw NUL becomes a git binary blob unnoticed

Surface: infra

## Current State
`bin/plan-audit.js` reads the whole plan file once (`fs.readFileSync(planFile, 'utf8')`), parses it, and runs four deterministic checks from `bin/lib/plan-audit/checks.js` — Check A (paths exist), Check B (scope-keyword sweep), Check C (verification-command pre-check), and the headroom check — emitting a `{checkA, checkB, checkC, headroom}` envelope and exit 1 when any `ok` is false. None of them looks at the bytes themselves. A plan that contains a raw control byte (the reporter's case: a NUL written as the literal character instead of the `\0` escape inside an inlined test fixture) parses fine, audits clean, and commits as a file git classifies as binary: `git diff` prints `Bin`, reviewers cannot read it, `grep` returns nothing for text `Read` displays, and `Edit` cannot match what it shows (this repo's own 2026-08-03 incident with `code-health/scope.js` had the same signature). The defect surfaced only at the whole-branch review, where it had to be repaired with a byte-level rewrite. The audit is the last programmatic reader of the plan before dispatch, and the one place a single-edit fix is still cheap.

## Deliverables
- [ ] `checkD(text)` in `bin/lib/plan-audit/checks.js`: scans the plan text for any code point in `U+0000`–`U+001F` or `U+007F` other than tab (`U+0009`), line feed (`U+000A`), and carriage return (`U+000D`), and returns `{ ok, findings: [{ line, column, codePoint, offset }] }` with one finding per offending byte (capped at 20, with a `truncated: true` flag beyond that); exported and added to the envelope as `checkD`, folded into the exit-code rule.
- [ ] Check D runs on the raw text before the parser on every audit invocation, and `plan-audit.js` gains a read-only `--bytes {plan-file}` verb (the `--count-tasks` shape: one JSON line `{checkD}`, exit 1 on findings, exit 2 on an unreadable file) that runs Check D alone. `build/SKILL.md` Common Step 1.5's skip clause (fewer than 3 file references and no `Scope keywords:`, or `ceremony-profile: fast-lane`) runs `--bytes` on the skip path — the gate exists to save the cost of Checks A–C, and a byte scan on a file already in memory costs nothing, while a NUL in a two-file plan is exactly as fatal as in a large one.
- [ ] `build/plan-audit.md`: a `checkD.ok === false` bullet in the result-interpretation list — a Check A-shaped unconditional stop naming each finding as `line:column U+XXXX`, never routed through the `scope-creep` policy table — and a sentence that Check D is the one check the skip gate does not cover (via `--bytes`), with the reason above; `build/SKILL.md`'s Step 1.5 skip sentence gains the `--bytes` clause.
- [ ] The one-line human summary in `plan-audit.js` gains a `Control bytes: {n}` part when findings exist.
- [ ] Tests: `tests/bin-lib/plan-audit/checks.test.js` cases — a NUL mid-line reports its line, column, and `U+0000`; a form feed and an escape byte are findings; tab/LF/CR are not; multi-byte UTF-8 text and a literal backslash-zero (`\0` as two characters) are not; the cap and `truncated` flag. `tests/bin-lib/plan-audit/cli.test.js` — a fixture plan with a NUL yields `checkD.ok === false` and exit 1 under both the full audit and `--bytes`; a clean plan reports `checkD.ok === true`; one new prose pin (beside `tests/design-wrapper-polish-anomaly-prose.test.js`'s existing match on the "Skip this step entirely when" sentence, or in its own small conformance file) asserts Step 1.5's skip sentence names `--bytes`.

## Acceptance Criteria
1. `node bin/plan-audit.js <plan-with-raw-NUL>` and `node bin/plan-audit.js --bytes <plan-with-raw-NUL>` both exit 1 with a `checkD` finding naming the line and column; `build/SKILL.md`'s skip path invokes the latter.
2. A plan whose fixture spells the byte as the two-character escape `\0` passes Check D.
3. Every existing `checks.test.js`, `cli.test.js`, and `parser.test.js` case passes unmodified; the envelope keys for A–C and headroom are unchanged.
4. `build/plan-audit.md` documents the check and the stop; `npm test` is green.

## Technical Approach
Scan code points, not bytes: `readFileSync(…, 'utf8')` has already decoded the file, so a `for (const ch of text)` walk with `codePointAt(0)` finds every control character while leaving multi-byte text alone; a byte-level scan would flag UTF-8 continuation bytes. Reporting `line:column` (1-based, computed while walking) is what makes the fix a single edit. The skip gate is prose in `build/SKILL.md`, not logic in the CLI, so exempting Check D from it means a CLI verb the skip path can call (`--bytes`, mirroring `--count-tasks`) plus one clause in that sentence; `plan-audit.md`'s "no check introduces a new skip condition of its own" line gets its explicit exception rather than leaving the reader to reconcile it.

## Gotchas
- A test fixture that *intends* a NUL must write it with the escape (`"\0"`) inside a code fence; Check D flags the raw byte only, so the legitimate spelling passes — say this in the finding text so the author knows the fix.
- Writing the CLI test fixture itself requires producing a raw NUL from Node (`Buffer.from([0x00])`), never a shell `echo` (zsh/echo escape handling varies — `printf '\0'` is the portable form if a shell is used).
- `micro-plan.md`'s fast-lane composed plan skips `plan-audit.js` entirely; that path composes the plan from the header and never inlines fixtures, so it is out of scope, but note it in `plan-audit.md`'s sentence so the exemption's edge is explicit.
- `--count-tasks` stays as is (it reports `{tasks, batched}` only); `--bytes` is its sibling, not an extension of it.

## Original request
**Summary:** A plan file that contains a raw NUL byte (a test fixture written as a literal `"\0"` character instead of the escape) is treated by git as binary — `git diff` prints `Bin` and reviewers cannot read it — and nothing in the plan audit notices.

**Kind:** Gap

**Affected component:** `bin/plan-audit.js` (invoked by `/claude-tweaks:build` Common Step 1.5)

**Use case:** A plan-writing agent inlined a NUL-byte fixture into a Markdown plan file. The plan committed as a binary blob and the defect surfaced only at review's whole-branch pass, where it had to be repaired with a byte-level rewrite. The audit already reads the whole plan file for Checks A–C; a one-line "reject control bytes other than tab/newline/CR" check (or a warning naming the byte offset) would have stopped the plan before dispatch, when the fix is a single edit.

**Definition:** Clear
