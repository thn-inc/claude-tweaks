# 3642: Migrate the five remaining path.relative containment re-derivations to the path-guard helper

Origin: build final-review follow-up from #3498

Defer-reason: pre-existing-outside-diff

**Related:** #3682

## Current State

#3498 made `plugin/bin/lib/path-guard`'s `isAncestorOrSelf` the one lexical containment implementation (`shared-primitives.js`'s `isPathContained` is now its strict/`orEqual` wrapper) and removed every `startsWith(root + path.sep)` copy under `plugin/bin`. Its final whole-branch review found five more containment checks that re-derive the answer from `path.relative` output with `rel.startsWith('..')`: `plugin/bin/hooks.js:256`, `plugin/bin/lib/hooks/pre-tool-use.js:685`, `plugin/bin/lib/visual-decide/server.js:48`, `plugin/bin/lib/wrap-up/engine-verify.js:332` and `plugin/bin/lib/skill-audit/context-cost.js:271` (line numbers as of #3498's branch). `rel.startsWith('..')` treats a child component named like `..foo` as outside the root, which is the defect `isAncestorOrSelf` was built to fix (#3417). It errs toward rejecting, so it fails closed. These five sites fell outside #3498's literal AC grep, and its `tests/path-containment-conformance.test.js` scan only matches the `startsWith(... path.sep)` idiom.

## Deliverables

- [ ] Migrate each of the five `rel.startsWith('..')` containment checks to `isPathContained` (or `isAncestorOrSelf` where equality is admitted), keeping each site's strictness and its existing suite unmodified.

- [ ] Add a characterization case per site whose behavior changes (a `..foo` child now contained), the way `tests/bin-lib/path-guard/callers-characterization.test.js` records #3417's.

- [ ] Widen `tests/path-containment-conformance.test.js`'s scan to flag a `path.relative`-derived `startsWith('..')` containment test.

## Acceptance Criteria

- [ ] `git grep -n -E "startsWith\('\.\.'" -- plugin/bin` shows no containment test outside `plugin/bin/lib/path-guard/`.

- [ ] Every migrated site's existing suite passes unmodified, and a characterization case pins each `..foo` behavior change.

- [ ] `tests/path-containment-conformance.test.js` fails on a planted `rel.startsWith('..')` containment check.

## Release Note

Internal hardening: the remaining plugin path-containment checks use the shared helper, so a folder named like `..foo` is no longer mistaken for one outside its parent.
