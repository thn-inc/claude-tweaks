# 2532: 5 test files fail outright (not skip) in a shallow-clone sandbox on an unguarded historical git-show read

Origin: ledger resolve gate (wrap-up, record #2436)
Defer-reason: pre-existing-outside-diff

## Current State

While fixing #2436's two whole-file test crashes (`tests/shaping-mode-needs-removal.test.js`,
`tests/tidy-needs-worklist-rule.test.js` — both called `execFileSync('git', ['show', {historical-sha}:{path}])`
unguarded at module-load time, crashing the whole file in a shallow/partial clone where the
historical commit is unreachable), this run's wrap-up Docs curation pass found 5 more test files
with the same unguarded `execFileSync('git', ['show', ...])` idiom:

- `tests/session-limit-degrade-conformance.test.js` (line 30, called at lines 98/104)
- `tests/needs-worklist-rule-cross-consumer.test.js` (line 26, called at lines 64/78)
- `tests/untrusted-record-content-conformance.test.js` (line 275, called via `assertGoRedAbsent`)
- `tests/demo-visual-decision-adoption.test.js` (line 29, called via `countAtPreChange`)
- `tests/demo-full-verification-pointer.test.js` (line 26, called via `countAtPreChange`)

Verified independently (not merely cited from the judge agent's report, which originally
mischaracterized these as "crash-prone" like #2436's bug): in all 5 files, every one of these
`execFileSync` calls sits *inside* a `test(..., () => {...})` callback, not at module top level.
node --test isolates a throw inside a test callback to that one test — so in a shallow clone,
each of these tests would FAIL outright (a real, misleading red in an environment where the
current code is fine), not crash the whole file the way #2436's bug did. Lower blast radius than
#2436, but the same root cause and the same false-negative-CI risk in a shallow/partial clone.

## Deliverables

- [ ] For each of the 5 files, apply the same guard pattern #2436 established: wrap the
      `execFileSync('git', ['show', ...])` read in try/catch; on failure, skip only the specific
      test(s) that depend on that read via node:test's `{ skip: reason }` option (stating the
      real underlying git error), rather than letting the assertion fail with a misleading
      "assertion failed" message that obscures the actual cause (unreachable historical commit).

## Acceptance Criteria

1. Each of the 5 files' historical git-show read is guarded the same way #2436's fix guards its
   two files.
2. A `--depth 1` shallow clone of this repo degrades each of these 5 files' affected test(s) to a
   skip with a stated reason, instead of a hard failure.
3. `npm test` as a normal user on this checkout stays green throughout (no regression to the
   full-history pass path).
