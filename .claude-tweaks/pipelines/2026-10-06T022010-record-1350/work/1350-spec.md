# 1350: Verify /specify red-team fan-out batching at next live multi-sub-issue run (#649 AC2)

Surface: backend

## Current State

Record #649 added `_shared/subagent-output-contract.md`'s fan-out single-assistant-message-rule
sentence and per-site citations (AC1, fully test-pinned in `tests/subagent-contract-clauses.test.js`,
18/18 passing). AC2 — "A `/specify` red-team over 2+ `ceremony:standard` sub-issues launches its
personas in ≤ (number of sub-issues) assistant messages, verified in the transcript by `Agent`

decomposition run's transcript.

## Deliverables

Confirm, at the next `/specify` decomposition run over 2+ `ceremony:standard` sub-issues, that
persona dispatch actually batches into ≤N assistant messages per `_shared/subagent-output-contract.md`'s
fan-out single-assistant-message rule and `red-team.md`'s per-sub-issue batching unit. Record the
observation (transcript excerpt or note) against this item, or file a defect against
`red-team.md`'s dispatch prose if it does not.

## Acceptance Criteria

A `/specify` run over 2+ `ceremony:standard` sub-issues is observed; its persona `Agent` tool_use
calls are confirmed (via transcript `tool_use` block message-id grouping) to arrive in ≤ (number of
sub-issues) assistant messages.

## Release Note

No user-visible change: verified that spec red-team reviews batch correctly across several sub-issues.

## Technical Approach

Wait for (or trigger) a `/claude-tweaks:specify` decomposition-mode run that produces 2 or more
`ceremony:standard` sub-issue records — `ceremony-check` (`assess-agent-autonomy/ceremony-check.md`)
resolves the tier per sub-issue during that run's own Step 3, so the tier isn't knowable until the
run happens. Once such a run occurs, inspect that session's stored transcript for the Step 5
red-team dispatch (`specify/red-team.md`'s Parallel dispatch section): locate the `Agent` tool_use
blocks for each dispatched persona and group them by the assistant message id each block belongs
to. Confirm the number of distinct assistant message ids covering all persona dispatches for a
given sub-issue is ≤ the number of sub-issues in that batch. Use the same read-only transcript
inspection method `transcript-payload-verification` documents for reading this session's own
locally-stored transcript, rather than instrumenting or modifying `red-team.md` itself.

If the count exceeds the bound, file a defect issue against `red-team.md`'s dispatch prose
(quoting the transcript grouping that violates the rule) instead of editing the file directly from
this record — this record's own deliverable is the observation, not the fix.
