# 2980: Move design-wrapper Layer 0 and availability onto the Impeccable engine

Surface: infra

## Overview

Move `design-wrapper`'s Layer 0 enrichment, its availability table and its native-track platform lookup off the retired `context-signals.mjs` / `resolveImpeccablePlugin` binding and onto the `impeccable-engine.js` CLI from the engine-module sub-issue. Today, for every user on Impeccable 4.2.2 or later, Layer 0 silently degrades to no signals because `context-signals.mjs` no longer exists; after this change Layer 0 runs `impeccable-engine.js run signals` and gets the same `setup`/`critique`/`git`/`devServer` shape from the engine.

Behaviour on failure stays exactly what Layer 0 promises today: any `ok: false` means no signals, and every mode completes normally. What changes is that the skip now carries a named reason with a fix, instead of a silent miss. The reasons are the six the engine module exports: `not-installed` (no Impeccable install entry at all), `upgrade-required` (an install older than 4.2.2, with no launcher), `engine-not-installed` (launcher present, engine binary not cached), `shape-mismatch`, `exec-failed` and `timeout`. If the merged engine module's exported list differs, it is authoritative over this list.

**Complexity:** Medium
**Estimated tasks:** 5
