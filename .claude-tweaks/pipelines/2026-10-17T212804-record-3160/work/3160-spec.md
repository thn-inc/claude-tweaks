# 3160: flow Manifesto's ceremony-profile fold defaults to standard for health-sweep-filed records with no ceremony:* label

Origin: reflect light mode from #3139
Defer-reason: tangential

## Current State

`flow/manifesto.md`'s Ceremony profile computation states its ceremony-profile lever is always
computed by "folding every record's materialized `ceremony:` header field" — "any record missing
the field defaults to `standard`." On this run (#3139, filed by `/claude-tweaks:docs-health`), the
GitHub issue carries no `ceremony:*` label at all (`gh issue view 3139 --json labels` confirms:
`ready, risk:low, size:low, type:task, auto:build, auto:merge, bot:in-progress, priority:low,
by:docs-health, docs-health:additive` — no `ceremony:` entry). The Manifesto ran at 19:02:37 and
wrote `config.yml`'s `ceremony-profile: standard`, before the materialize commit landed at
19:04:05 — at Manifesto time there was no materialized header yet to fold from, and no
`ceremony:*` label on the issue either, so the "missing field" fallback was the only possible
outcome. Build's own `ceremony-check` LLM judgment later determined `fast-lane` for this record
(the materialized spec's frontmatter reads `ceremony: fast-lane`, and build's own decisions.md
entries confirm `/claude-tweaks:build`'s whole-branch-review skip ran under `ceremony=fast-lane`),
but that judgment runs inside build — after the Manifesto already locked `config.yml` to
`standard` for the rest of the run. `/claude-tweaks:review` consequently ran Steps 1 (Spec
Compliance), 1.6 (Cross-Spec Promise), and 4 (Implementation Hindsight) at full `standard` depth
for a one-line docs fix that its own later ceremony judgment, and the diff itself, confirm
warranted the `fast-lane` skip of those three steps. `/claude-tweaks:wrap-up`'s own diff-derived
ceremony default (`ceremony-derivation.md`) caught and corrected this to `fast-lane` at Phase 1 of
this very wrap-up run — but only after review had already paid the full cost, since that
derivation runs in wrap-up, not before review.

This is a structural timing gap, not specific to this record: any record reaching `/flow` with no
`ceremony:*` label — every record filed by a health-sweep skill (`docs-health`, `code-health`,
etc.) rather than shaped via `/claude-tweaks:specify` (which is what actually stamps `ceremony:*`
on every record it shapes) — hits the same fallback at Manifesto time, regardless of what
`ceremony-check` will later determine during build.

## Deliverables

- Either: have `/claude-tweaks:specify` (or the health-sweep filing skills themselves) stamp a
  `ceremony:*` label on every record they file, closing the gap at the source; or have
  `flow/manifesto.md`'s ceremony-profile computation run the `assess-agent-autonomy` `ceremony-check`
  judgment itself (the same call `materialize.js`'s `--ceremony` fallback already defers to the
  caller for) when a target record carries no `ceremony:*` label, instead of defaulting straight
  to `standard`.

## Acceptance Criteria

3) — not only retroactively, post-review, via wrap-up's diff-derived narrowing.
