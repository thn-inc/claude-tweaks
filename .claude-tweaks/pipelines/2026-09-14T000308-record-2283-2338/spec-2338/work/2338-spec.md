# 2338: dev-url-detection.md: standalone cleanup bullet trusts a file that's never written in standalone mode

Surface: infra

## Current State

Found during a pre-release whole-branch review of `plugin/skills/_shared/dev-url-detection.md`.
The standalone (no run dir) cleanup bullet (confirmed, ~line 176) tells the caller to trust "the
`{pid}` currently named in `ephemeral-server.txt`", but Step 4 of the same procedure (confirmed,
~line 135) writes that file only "when a pipeline run dir exists" — the standalone case never has
a run dir, so that file is never written in the exact case this cleanup bullet is describing.

The same paragraph already names the actual standalone-safe mechanism, just as a "fallback":
"`lsof -ti tcp:{port} | xargs kill` is the fallback only when no lease exists (matching Section
D's rule in `wrap-up/cleanup-procedures-execution.md`)" — but "no lease exists" is not a fallback
condition in the standalone case; it's the *only* case, since `ephemeral-server.txt` structurally
never exists there.

## Deliverables

Fix the standalone cleanup bullet so it doesn't tell the caller to trust a file that structurally
never exists on that path — either name the actual mechanism standalone cleanup should use
(the `lsof -ti tcp:{port} | xargs kill` approach the same paragraph already names as a
"fallback"), or clarify the bullet only applies to the run-dir case.

## Acceptance Criteria

The standalone cleanup instruction and Step 4's file-write condition are consistent with each
other.

## Technical Approach

Rewrite the Standalone bullet (~line 176) to state the `lsof -ti tcp:{port} | xargs kill`
mechanism as the actual (not fallback) standalone cleanup path, since `ephemeral-server.txt`
never exists there — remove the "trust the `{pid}` currently named in `ephemeral-server.txt`"
sentence from the standalone bullet entirely (that sentence correctly describes the *pipeline*
bullet's mechanism, immediately above it) and keep the port-based `lsof`/`kill` approach as the
standalone case's real, primary mechanism rather than describing it as a fallback for a lease
that was never going to exist in this branch.

### Key Files

- `plugin/skills/_shared/dev-url-detection.md` — rewrite the Standalone cleanup bullet (~line
  176) to remove the reference to a file it never writes, and state the `lsof`-based kill as the
  actual standalone mechanism

## Gotchas

- Don't just delete the inconsistent sentence without replacing it with the correct mechanism —
  the Acceptance Criteria requires the two sections to be *consistent*, not merely non-contradictory
  by omission; a reader following the standalone path still needs an actual cleanup instruction.
- Verify the pipeline bullet (immediately above, ~line 175) isn't itself affected by this edit —
  its own `ephemeral-server.txt`-trusting description is correct for the pipeline case and should
  stay as-is.
