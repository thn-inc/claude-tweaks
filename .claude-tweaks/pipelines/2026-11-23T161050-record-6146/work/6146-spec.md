#### The event contract (shared with the hub plan)

Lines keep their existing fields (`v: 1`, `eventKey`, `repoName`, `recordNumber`, `kind`, `station`, `at`, `outcome`, `lane`, `sessionId`, `runId`, `payload`). New:

| Kind | Filed under station | `payload` |
|---|---|---|
| `planned` | the station the item is at when written (at the claim: `build`) | `{ process: 'build-a-record', processVersion: 1, list: string, stations: string[], reasonCode: string, reasonText?: string }`; `stations` is the full ordered list, including stations already passed |
| `replanned` | the station the item is at | `{ stations: string[], reasonCode: string, reasonText?: string, cause: { kind: 'outcome' \| 'decision' \| 'config', ref?: string } }` |
| `held` | the station the item is at | `{ why: 'blocked' \| 'parked' \| 'changes-requested' \| 'waiting-on-you', ref?: string }` |
| `released` | the station the item is at | `{ why: <same set> }` |
| `decided` | the station the decision was made at | `{ decision: 'authorize' \| 'accept' \| 'unblock', actor: string, via: 'panel' \| 'skill' \| 'rule', outcomeRef: string }` (`outcomeRef` is the `eventKey` of the `exited` it caused) |
| `exited` (extended) | unchanged | `outcome` is one of `passed \| sent-back \| failed \| stopped`; `payload.actor` always; `payload.reasonCode` for every outcome except `passed`; `payload.next` (a station id) for `sent-back`; `payload.reasonText?` |

`actor` is `agent`, `script`, `person` or `rule:<id>`. Reason codes are the closed list `REASON_CODES` (Task 2). A reason nothing knows is `unspecified`.

## Decisions (orchestrator, 2026-11-23, answering the plan review's three questions)

1. **Actor-less `passed` and `failed` lines are accepted unchanged until record 8/8 (#6152).** `invalidReason` applies the actor, `reasonCode` and `next` checks to an `exited` line when its outcome is `sent-back` or `stopped`, or when its payload carries an `actor` key (any outcome). A `passed` or `failed` line with no `actor` key is a pre-contract line from today's callers and is written as before. Record 8/8 removes this carve-out. This record edits none of the callers.
2. **Ship the 13 listed reason codes now.** A later record that needs a code not in the list (records 5/8, 6/8 and 7/8 write callers) may add it to `REASON_CODES` in `stations.js`, with a test, and make no other change to that file. Record 1/8 is documentation only and adds no code.
3. **A missing or unknown `reasonCode` is normalized, never dropped.** A new-vocabulary non-`passed` `exited` line whose `payload.reasonCode` is missing or not in `REASON_CODES` is written with `reasonCode: 'unspecified'`; an unknown original value is kept in `reasonText`. A `sent-back` whose `next` is missing or not a station is still dropped with a stderr reason (no edge can be drawn).

Test changes: replace `exited failed without reasonCode is dropped` with `exited failed carrying an actor but no reasonCode is written with reasonCode unspecified`; add `an unknown reasonCode is rewritten to unspecified and the original kept in reasonText`, `a passed line with no actor is written unchanged`, `a failed line with no actor and no reasonCode is written unchanged`, `a sent-back with no actor is dropped`.
