# 4265: claim-targets release-on-abort can tombstone a competing run's live claim: add a runId check

Verified-as-of: 3e3afc3a6fa361d526d7505e84e8a0b5022060d5

Origin: ledger resolve gate (wrap-up of #4183)

Defer-reason: pre-existing-outside-diff

## Current State

- `releaseClaimedThisRun` (`plugin/bin/lib/claim-targets/claim-targets.js`, around lines 206-233) reads each target's blob fresh and tombstones whatever non-absent blob it gets back. It never classifies the blob or checks that its `runId` is this run's.
- #2329 routes the unverified target through it (`stopOrSkip(..., releaseThisIssue = true)`). An unverified write is exactly the case where the blob may be a competing run's live claim (this run's write lost the race), so the abort path can tombstone another run's live claim.
- `plugin/skills/_shared/issue-claims.md`'s Post-write verification paragraph says the release fires only when the fresh read "confirms it as this run's own live claim". Code and contract disagree.
- Raised by the Task 1 implementer of #4183 and confirmed by reading the function there; the file was outside that docs-only build's diff.

## Deliverables

- [ ] In `releaseClaimedThisRun`, classify the fresh blob (`classifyClaimBlob`) and tombstone it only when it is live under this run's `runId`; otherwise leave it untouched and name it in `releaseFailed` with an error that says it is not this run's claim.
- [ ] Decide and document what the abort path reports when the fresh read shows a competing live claim (the contract is silent on that case) in `plugin/skills/_shared/issue-claims.md` and `plugin/skills/flow/claim-targets.md`.
- [ ] Add tests in the claim-targets suite for: own live claim released, competing live claim left untouched, absent blob, and unreadable blob.

## Acceptance Criteria

- A test where the fresh read returns a blob live under a different `runId` asserts no tombstone write happens and the issue appears in `releaseFailed`.
- A test where the fresh read returns this run's own live blob asserts it is tombstoned and listed in `released`.
- The all-or-abort release of the other confirmed targets is unchanged.
- `npm test` passes.

## Release Note

A run that fails to verify its own claim no longer risks releasing another session's live claim.
