# 4048: Fail closed when decideConsoleExecute runs without its ruling-text or merge-grant context

Surface: infra

**Related:** #3873, #3942, #3949, #4060

## Current State

`decideConsoleExecute` (`plugin/bin/lib/reconcile/console-execute.js`) is the exported, pure decision the reconciler's `consoleAutoResolve` path uses to decide which ticked Review Console rows an unattended session may execute. It carries two "withhold for a human" checks whose context arrives through the optional `ctx` argument, and both treat an **absent** context as "nothing to withhold":

- **Ruling gate (#3880).** The `if (ctx.rulingTexts && typeof ctx.rulingTexts === 'object')` guard skips the whole loop when the map is absent, so every `isRulingRow: true` item comes back with `rulingGateGaps: []` — floor-clearing, auto-ratified. When the map is present but an item's id is missing, the same item fails closed (`sdd-ruling-unclassified`). The two "no text for this row" cases resolve opposite ways.
- **Merge-grant gate (#1802).** The `if (hasMergeRow && typeof ctx.prBody === 'string' && ctx.memberGrants && typeof ctx.memberGrants === 'object')` guard leaves `mergeGrantGap: null` when either piece is absent — and `plugin/skills/_shared/console-execution.md` documents `null` as "every member is granted", a claim the function never checked.

Neither is a live defect: the only production caller, `consoleExecuteDetect`, always sets `ctx.rulingTexts` (via `readRulingTexts`) and always supplies `prBody` + `memberGrants` (seeded `{}`) for a candidate carrying a merge row. The risk is a future caller that omits the context and silently auto-ratifies ruling rows or auto-merges past an ungranted member, with no test going red — today both open paths are pinned as intended behaviour by `tests/console-execute.test.js` (`no ctx.rulingTexts -> rulingGateGaps [] (legacy call shape unchanged)` and `isMergeRow present but no ctx supplied (legacy call shape) -> mergeGrantGap null, unchanged`).

Decision (brainstormed on this record, 2026-10-24): close both gaps here — fail closed when a gated row is present and its context is absent — rather than keep the pre-feature "legacy call shape" convention. The review's own disposition options were apply (fail closed, flip the pinning test) or reverse (keep); this record takes apply and widens it to the merge-grant twin.

## Technical Approach

Both changes sit in `decideConsoleExecute` and keep it pure.

Ruling gate — replace the guard with a branch on the map's presence:

```js
const rulingTexts = ctx.rulingTexts && typeof ctx.rulingTexts === 'object' ? ctx.rulingTexts : null;
for (const item of items) {
  if (item.isRulingRow !== true) continue;
  const reason = sddRulingDeferralReason(rulingTexts ? rulingTexts[item.id] : null);
  if (reason) rulingGateGaps.push({ id: item.id, reason });
}
```

`sddRulingDeferralReason(null)` already returns `sdd-ruling-unclassified`, so an absent map routes through the same classifier as a missing entry — no new reason literal on this side.

Merge-grant gate — split the existing compound guard: keep `hasMergeRow` as the outer condition; when the context is incomplete, set `{ member: null, reason: 'grant-context-missing' }`; otherwise run today's `parseFixesMembers` / `evaluateMaturation` loop unchanged. `member: null` matches the existing `members-unresolved` shape, so downstream readers that already handle a null member need no change.

`consoleExecuteDetect` needs no edit: it already supplies both contexts on every path where a gated row exists.
