# 3329: Review's reproduction-pair disagreement handling should ground-truth-check a mechanically-falsifiable 'code is missing' claim

Origin: reflect full mode from #3249 (Surprises + Near-misses lenses)

Defer-reason: genuinely-larger

**Related:** #3326

## Current State

During #3249's review (14 lens agents, 7 reproduction pairs at `review-effort: high`), lens 3a's (Convention) reproduction pair disagreed: one agent (3a-A) returned no findings; the other (3a-B) returned `STATUS: BLOCKED`, citing several specific functions, exports, and parameters as "completely missing from the codebase" — with exact line-number citations drawn from the record's own materialized plan file (which shows the code to add). Every one of those claims was false: direct `grep` against the live worktree confirmed every named item already existed exactly as claimed-missing (`plugin/bin/lib/reconcile/pr-state.js:242,326`; `release-merged.js:16,360,365,385`; `archive-merged.js:320`). The agent appears to have conflated the plan document's own illustrative "add this code" listing with the code's current applied state.

The reproduction-pair mechanism (`plugin/skills/review/step3-lens-dispatch.md`) correctly flagged this as a disagreement, but its own handling treats *any* disagreement as `unconfirmed`/low-confidence, which is the right default for a genuine judgment call but is not the cheapest-available resolution for this specific claim shape: "a named function/export/parameter does not exist" is mechanically, cheaply verifiable (one `grep`/`Read`) before ever reaching a human at the Review Console. Without an explicit instruction to do that check, a differently-briefed session could plausibly have accepted the disagreement as "needs a human to judge" and left a factually-false BLOCKED claim staged as merely low-confidence, sending a human to investigate a non-existent gap.

## Deliverables

- Add one sentence to `step3-lens-dispatch.md`'s dispatch prompt template (or the CALIBRATION block) instructing lens agents not to infer code absence from a plan/spec document's own illustrative code listings — verify a "missing code" claim by reading the actual target file directly.
- Add a narrow, mechanical escape hatch to the reproduction-pair disagreement-handling procedure: when one side of a disagreement asserts code/export/parameter *absence* at a named `path:line`/symbol, the dispatching session runs one `grep`/`Read` check against the live target file before staging the finding as `unconfirmed` — a contradicted "missing" claim resolves straight to "refuted, not staged" rather than "low-confidence, staged."

## Acceptance Criteria

- [ ] A reproduction-pair disagreement where one side asserts code/export/parameter absence that a one-command `grep`/`Read` check can mechanically refute no longer reaches the Wrap-Up Review Console as a merely low-confidence item — it resolves to refuted before routing.
- [ ] The dispatch prompt template explicitly warns against inferring code state from a plan/spec document's own code listings.

## Release Note

Review's reproduction-pair handling gains a cheap ground-truth check for mechanically-falsifiable "code is missing" disagreements, reducing false BLOCKED verdicts reaching the Review Console.
