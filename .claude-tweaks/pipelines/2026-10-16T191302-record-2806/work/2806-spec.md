# 2806: Untangle verify/args.js's four-mode parseArgs coupling

Origin: ledger resolve gate

**Related:** #2779 (add `--cmd-env` to verify.js — both records edit `plugin/bin/lib/verify/args.js`; build order matters, coordinate before dispatching both)

## Current State

`plugin/bin/lib/verify/args.js`'s `parseArgs` handles four distinct CLI modes (a normal check run, `--stamp-status`, `--changed-files`, and their `--scope`/`--base`/`--integration-branch` variants) inside one function, with roughly ten cross-mode incompatibility checks (lines 79-100) enforcing which flags are illegal in which mode. A whole-branch review lens (3e, single-agent, unconfirmed) flagged this as coupling.

## Deliverables

Untangle the four modes — e.g. a discriminated result shape per mode, or separate parse paths that share only the flag-tokenizing loop — so each mode's own validation lives with that mode, not interleaved with the other three's.

## Acceptance Criteria

- Every existing cross-mode incompatibility check (the ~10 branches at lines 79-100) has an equivalent assertion in the new structure, each individually verified against the current test suite before the refactor is trusted
- `tests/bin-lib/verify/args.test.js` (or wherever this file's tests live) passes unchanged, plus any new tests the refactor's own shape needs
- No change to `verify.js`'s CLI-facing behavior (usage text, exit codes, flag names)

## Release Note

`verify/args.js`'s argument parsing restructured for clarity; no CLI-facing behavior change.
