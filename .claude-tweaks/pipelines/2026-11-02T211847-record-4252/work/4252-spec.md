# 4252: local-merge: the merge fences compose the merge commit without --keep-open, so a deferred record still gets a closing keyword

Origin: ledger resolve gate

Defer-reason: genuinely-larger

## Current State

- `compose-subject.js --keep-open` writes `Refs #n` for a kept-open record; the pr-first Step 3 fences pass it (the pre-merge `keepOpen` of `bin/closing-links.js`).
- The four local-merge fences (`_shared/local-merge-auto-finish.md`, `wrap-up/auto-merge-short-circuit.md`, `dispatch/settle-and-merge.md`, `flow/worktree-merge.md`) still pass every record to the composer without `--keep-open`, so a local-merge run that logged a deferred closure writes `Fixes #n` into its merge commit and the merge closes it.
- A local-merge run has no PR body, so the kept-open list has no pre-merge source today: the deferred-closure `decisions.md` entries (`readDeferredClosures` in `bin/lib/flow/manifest.js`) are the natural one.

## Deliverables

- [ ] Derive the kept-open list for a local-merge run from the deferred-closure decisions entries and pass it as `--keep-open` in each of the four local-merge fences.
- [ ] Extend `tests/merge-subject-composer-conformance.test.js` so each local fence is pinned to carry the flag, with a go-red control.

## Acceptance Criteria

- [ ] A local-merge run with one logged deferred closure composes a message with `Refs #n` for it and `Fixes #m` for the rest (a test over the composer call each fence documents).
- [ ] The conformance test fails when a local fence drops `--keep-open`.

## Release Note

A local-merge pipeline run no longer closes a record it deliberately left open when it merges.
