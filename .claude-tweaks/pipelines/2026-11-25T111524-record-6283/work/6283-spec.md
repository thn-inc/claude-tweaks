# 6283: Bundle a run's to-be-filed follow-up proposals that share files into one record with a per-finding checklist

Surface: infra

**Related:** #5866
**Related:** #5822
Risk-flags: public-contract
Risk-flags-unconfirmed: true

## Overview

A run's Review Console files one record per deferred finding. This record adds a console-time bundler: one gh-free CLI that runs once per console, before anything is created, over every staged record proposal of the run (every `spec-{N}/staged/` plus the parent's in a multi-spec run). Proposals in one landing class that share a Key File land as one bundle record with a per-finding checklist; everything else files as today. Fingerprint extraction becomes multi-marker so a bundle still dedups against each member's `work-fingerprint`. Every real finding stays tracked — the bundle holds all of them — so the no-implicit-deferrals rule is untouched; only the per-record ceremony cost drops.

Evidence (origin #5985): a 12-record multi-spec run filed 16 follow-ups and a follow-up run 8 more; the owner hand-consolidated 23 of the 24 into 5 bundles. Seven were `needs:definition`, one decision round each.

The bundler functions without the producers sub-issue (sibling in this decomposition: "Pass Key Files from the remaining record-proposal producers…") but bundles little until it and #5512 land, since a proposal without `### Key Files` is always a singleton.

**Complexity:** High
**Estimated tasks:** 8

## Non-Goals

- Changing which findings become records: `deferral-route.js`'s verdicts, the materiality floor, the run filing cap and its tally are unchanged (the cap counts per routed finding, before bundling).
- Bundling can't-tell filings (`plugin/bin/console-filings.js` / `plugin/bin/lib/console/finding-filing.js`, created from a session-tmp out-dir with a per-item `filed as #N` residue contract) — they keep their path.
- Bundling `parked` (trigger-gated) proposals — each carries its own wake trigger and always stays a singleton.
- Absorbing into open records: a near-duplicate screen hit (`plugin/bin/lib/issues/near-duplicate.js`) only adds a `**Related:** #N` line (#5822 is why).
- Directory-level grouping — exact shared file paths only.
- A cross-run decision round, or adding fingerprints to producers that write none today.
- The re-check of open follow-ups (the sibling re-check sub-issue, blocked by this one).
- Making producers pass `keyFiles` (the sibling producers sub-issue and #5512).

3. Two `needs:definition` proposals sharing a Key File yield one bundle whose body has an `## Open Question` section listing both members' questions and no `ready` label.

5. A file cited by 3+ of the run's own proposals but by fewer than the hub threshold of a fixture open-backlog snapshot still bundles those proposals; the same file cited by enough fixture open records to be a hub does not bridge them.

7. The bundle's labels are the highest member `risk:*`, a `size:*` no lower than the largest member's, the members' shared `type:*` (else `type:task`), and its `Defer-reason:` header is the value most members share (tie: the first member's).

10. Each bundled `ledger-record-*` member's ledger row Resolution names `staged/bundle-{n}.md` after bundling.
11. Each bundling writes one `AUTO` line to `decisions.md` naming the bundle path and its members, with `Reversibility: high`.
12. An empty proposal set exits 0, writes nothing and logs nothing; an unreadable or malformed member file is left as a singleton and named in the envelope's skipped list; an unreadable open-backlog file bundles nothing and the console logs a `SKIP` line.

## Release Note

The Review Console now files a run's follow-up findings that touch the same files as one record with a checklist per finding, instead of one record each.

## Technical Approach

**Input set:** every staged record-proposal file the console's Queue writes would create — `leftover-*`, `ledger-record-*`, `review-followup-*`, and any file with a `Title:`/`Type:`/`Labels:` header — excluding `.shadow-dup` copies, `ledger-record-sdd-ruling-*` (each writes its own ledger row once its record exists), Refused items (`wrap-up/refused-proposals.md`), `bundle-*` files and members already carrying `Bundled-into:`. Only `Keep`/`Acknowledge` ledger items and born-ready `/review` / leftover proposals can bundle; a ledger `Defer` always lands `parked`.

**Landing class (Closed rule):** a proposal's `Labels:` header decides its class — contains `parked` (and not `ready`) → `parked` (always a singleton); contains `needs:definition` (and not `ready`) → `needs:definition`; contains `ready` (and neither of the other two) → `ready`. These three are the complete set; a header combining `ready` with `parked` or `needs:definition` is contradictory (`recordPayload` refuses ready+parked) and is unrecognized. Any other header (no `Labels:` line, an unparseable one, or none of the three) is refused bundling with one envelope line naming the file and "singleton: unrecognized landing class"; it files individually as today. A plan review that finds another unlisted state applies this rule as a plan amendment, never as a `needs-human` gap.

**Hubs:** computed against the open-backlog snapshot (a path cited by at least `max(3, 10%)` open records' `### Key Files`), passed in as `hubPaths` — not against the run's own proposals, where the default would make any file cited by 3+ of one run's findings a hub, which is exactly the area signal (`grouping.js`'s thresholds were tuned on a 139-record pool). Under `work-backend: github-issues` the console passes the session record snapshot (`record-snapshot.js`'s `snapshotPath`, refreshed by `_shared/record-queue-fetch.md`'s read-fresh-or-fetch block); under `local-files` the CLI reads open records through `local-store.js`. An unreadable file, or a fresh-but-empty array, bundles nothing (`SKIP` line).

**Bundle composition:** Current State lists each member's finding; Deliverables is a checklist, one `- [ ]` item per member carrying its title, its own `Defer-reason` and its source staged path; Acceptance Criteria is the union of members' criteria grouped per member (for `needs:definition`, `openQuestion` listing every member's question); Key Files is the union. Each member's full finding text is embedded in the bundle body; its source staged path is provenance only, since the run dir is archived after the run. Labels and `Defer-reason:` per AC 7, plus the class label (`ready`, or `needs:definition` with no scoring); a `by:*` origin label only when every member shares it; never an `auto:*` or `bot:*` label; a member missing `risk:*`/`size:*` is ignored for that maximum, and the label is omitted when no member has one. `size:*` is judged from the union's deliverables and Key Files (never lower than the largest member). Each member's `Risk-flags:` slugs are unioned through `bin/risk-flags.js`, never hand-typed. Every member's `work-fingerprint` marker is carried in the trailing marker block. The near-duplicate screen runs once, on the composed bundle body; a hit against an open record adds `**Related:** #N`. The run filing cap and its tally are unchanged (they count routed findings before bundling).

**Member retirement (expand-contract):** each member is rewritten through a sanctioned writer with a `Bundled-into: staged/bundle-{n}.md` header line **and moved out of the Queue-writes set**, so an older console reading the run dir sees only the bundle as creatable. The mechanism is the builder's call (e.g. move members to a sibling `{run-dir}/bundled/` directory outside `staged/`); AC 8 is the proof.

## Build Clarifications (architecture alignment, beneficial deviations)

- Oversized-group chunking re-runs `groupByFileOverlap` (same hub set) inside each size-guard slice, so a slice never bundles members that share no file; non-overlapping members become singletons. AC 4's 10 + 2 result is unchanged.
- A bundle-eligible proposal with no valid `Defer-reason:` in its header is a singleton (named in the envelope's skipped list), since a bundle needs one and `specShapedBody` refuses an invalid value.
- The bundle's `Risk-flags:` union fails closed: any unconfirmed member, or an unclassified member beside classified ones, writes the union unconfirmed; all-`none` members write `none`.
- Crash safety: a bundle's `bundled …` AUTO line in `decisions.md` is its commit marker; the next run rolls back any uncommitted bundle. `--unbundle` logs `un-bundling` before deleting the bundle and `un-bundled (override)` after; members a human un-bundled are never re-bundled in the run, and a console-skipped bundle keeps its members in `bundled/`.
