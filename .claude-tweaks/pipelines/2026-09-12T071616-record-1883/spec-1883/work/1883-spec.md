# 1883: sweep: close-out never renders tidy's staged Approve set, only a count

Surface: infra

## Current State

`sweep/SKILL.md` Step 1 invokes `/claude-tweaks:tidy --source sweep`; tidy's Component-Skill Contract says that under that flag findings stage to the shared `staged/`, entries log to the shared `decisions.md`, and tidy suppresses its own report and `## Next Actions`, returning counts to the parent. Sweep's Step 4 then (1) invalidates the snapshot, (2) executes `backlog/attention-mode.md` Steps 1-4 as its first output block, and (3) renders its `## Next Actions` and logs a summary line. Attention's Tidy row is, by design, one line — `{count} tidy proposal(s) staged awaiting approval — run /claude-tweaks:tidy --approve` — computed from the newest `*-tidy-standalone*`/`*-sweep-standalone*` run dir's `staged/`. Nothing between these steps renders the staged items.

`tidy/step-6-auto.md` mandates the opposite for a standalone run: the Approve section is "the click surface, nothing approved unseen", rendered in a three-line-per-item shape, kept in full even when the condense rule (report over 40 lines → full report to `{run-dir}/report.md`, condensed report in chat) collapses everything else, and lint-checked by `bin/tidy-report-lint.js --surface=full|condensed` before sending. Under `--source sweep` the chat copy is suppressed and only `report.md` is written; the user is never pointed at it.

Observed on plugin 6.114.1: a sweep staged four proposals (17 remote-branch deletions, 2 claim releases, 3 registry rows, 6 run-dir archivals) and the close-out printed the bare count; the user had to ask what approval would do. Adjacent, already closed: #1822 (ordering of the `tidy --approve` line in sweep's Next Actions).

Tests: `tests/sweep-orchestrator.test.js` pins sweep's three component calls, the invalidation repeats, and failure propagation; `tests/tidy-report-rules.test.js` pins the report rules and the lint.

## Deliverables

- [ ] **Tidy persists the click surface under sweep.** `tidy/step-6-auto.md`: under `--source sweep`, in addition to `{run-dir}/report.md`, write the condensed report (or the whole report when the condense rule did not fire) to `{run-dir}/report-condensed.md`, lint-clean under `--surface=condensed` with the `Full report: {relative run-dir path}/report.md` footer; suppress only the chat send and `## Next Actions`. `tidy/SKILL.md`'s Component-Skill Contract sentence changes from "suppresses its report" to "writes it to the run dir for the parent to inline".
- [ ] **Sweep inlines it.** `sweep/SKILL.md` Step 4 gains a step between the attention render and `## Next Actions`: when `{run-dir}/staged/` is non-empty, render `{run-dir}/report-condensed.md`'s Approve section verbatim as a `## Staged for approval` block (falling back to `report.md`'s Approve section when the condensed file is absent), so every staged item appears in tidy's three-line shape with its command; when `staged/` is empty, render nothing. State that attention's Tidy row stays the one-line count (it is a cross-run summary; sweep's block is the run's own click surface), so the items render once.
- [ ] **Run the lint on what sweep sends.** Sweep's close-out runs `node "${CLAUDE_PLUGIN_ROOT}/bin/tidy-report-lint.js" --surface=condensed` over the block it is about to inline and fixes findings before sending, the same pre-send scan `step-6-auto.md` mandates.
- [ ] **Tests.** `tests/sweep-orchestrator.test.js`: Step 4 names `report-condensed.md`, the `## Staged for approval` block, the empty-`staged/` omission, and the lint call, positioned after the attention render and before `## Next Actions`. `tests/tidy-report-rules.test.js` (or a sibling): `step-6-auto.md` states the `--source sweep` persistence and `tidy/SKILL.md`'s contract sentence no longer says the report is suppressed.

## Acceptance Criteria

1. A `/claude-tweaks:sweep` run whose tidy step stages one or more items prints, after the attention block and before `## Next Actions`, a `## Staged for approval` block listing every staged item in tidy's three-line shape with its command; a run that stages nothing prints no such block.
2. `{run-dir}/report-condensed.md` exists after tidy's Step 6 under `--source sweep` and passes `tidy-report-lint.js --surface=condensed`; `report.md` is still written.
3. `tidy/SKILL.md`'s Component-Skill Contract no longer says the report is suppressed under sweep; `step-6-auto.md` names the persisted file and the parent's inline duty once.
4. `attention-mode.md`'s Tidy row is unchanged.
5. `npm test` green; the existing sweep and tidy-report tests pass with only the new assertions added.
6. This sweep run (`2026-09-09T145100-sweep-standalone`) is the worked example: its `report-condensed.md` and staged set are quoted in the PR description as the block the new step would have printed.

## Technical Approach

Persist-then-inline rather than duplicate: tidy already composes and lints the exact block; the only missing hops are writing it to the run dir under sweep and having sweep read it back. Keep attention's row a count so the items render once per close-out. The lint's condensed surface already requires the space-free `Full report:` footer, which gives the user the pointer to `report.md` the report also asked for.

- `plugin/skills/tidy/step-6-auto.md` — `--source sweep`: persist `report-condensed.md`, suppress only the chat send

## Gotchas

- The condense rule counts fences, headers, and footer toward the 40-line threshold; sweep must inline the Approve *section*, not the whole condensed report, or a large sweep close-out re-triggers the very verbosity the rule exists to cap.
- `tidy-report-lint.js`'s condensed footer regex needs a space-free path; the run-dir path under `.claude-tweaks/pipelines/` is safe, but render it relative to the repo root.
- Sweep never approves anything; the block is display only. `tidy --approve` remains the single write path.
- Under `worktree-always: true` + `pr-first`, tidy's Step 7.5 may also commit `report.md` into the housekeeping PR (#1493/#1494 and #1778); `report-condensed.md` is not in the gitignore exception list and stays uncommitted, which is fine for a chat-only artifact — say so rather than widening the exception.

## Original request

**Summary:** Under `--source sweep`, tidy's staged Approve set (the click surface) is never rendered to the user; sweep's close-out shows only "{N} tidy proposal(s) staged awaiting approval", so the user has to ask what they would be approving.

**Kind:** Defect

**Affected component:** `/claude-tweaks:sweep` (Step 4 close-out) and `/claude-tweaks:tidy`'s `--source sweep` Component-Skill Contract; `backlog/attention-mode.md`'s Tidy row

**Repro steps:**
1. In a project whose tidy scan produces findings that Stage at the `moderate` tier (e.g. merged remote branches to delete, stale issue claims to release, missing `docs/REGISTRY.md` rows, clean pipeline-run dirs to archive), run `/claude-tweaks:sweep`.
2. Tidy runs as Step 1 with `--source sweep`, stages the items under the shared run dir's `staged/`, and per its Component-Skill Contract suppresses its own report and `## Next Actions`, returning only counts to the parent.
3. Sweep's Step 4 renders `backlog/attention-mode.md`, whose Tidy row is the single line `{count} tidy proposal(s) staged awaiting approval — run /claude-tweaks:tidy --approve`.
4. Observe: nothing in the chat output names the staged items, their actions, or their exact mutations. The only place they appear is the run dir's `report.md`, which the user is never told to open.

**Expected vs. actual:**
Expected: The staged Approve set renders in full somewhere in sweep's close-out — the same three-line-per-item shape `tidy/step-6-auto.md` mandates for the Approve section ("the click surface, nothing approved unseen"; its own condense rule keeps Approve in full even when everything else collapses). Either sweep inlines tidy's Approve section before the attention render, or attention's Tidy row lists each staged item with its action and command.
Actual: A bare count. In a live run with 4 staged items (17 remote-branch deletions, 2 claim releases, 3 registry rows, 6 run-dir archivals) the user's first reaction was to ask what the four proposals were and what approving would do — exactly the "approved unseen" outcome the tidy rule exists to prevent. Adjacent but distinct from #1822, which is about the *ordering* of the `tidy --approve` line in Next Actions, not the visibility of the items behind it.
