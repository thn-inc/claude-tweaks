# 2589: shaping-mode.md, capture/SKILL.md, and refine-mode.md's shaped-body prose still name only three required sections

Surface: backend

## Current State

`plugin/skills/specify/shaping-mode.md`'s Read-back verification step,
`plugin/skills/capture/SKILL.md`'s Shaped-body branch, and
`plugin/skills/backlog/refine-mode.md`'s spec-shaped-body check (used to
build a live flag-back comment) all restate `_shared/work-record.md`'s
spec-shaped-body check in prose (per `plugin/bin/lib/compose-record/compose.js`'s
own header comment) as a three-section check (Current State, Deliverables,
Acceptance Criteria). #2580 added a fourth required section, `## Release
Note`, to the mechanical definition (`_shared/work-record.md`,
`compose-record/compose.js`'s `REQUIRED_SECTIONS`) but did not touch these
three files' own prose restatements, since none is a blocking dependency for
#2580's own Acceptance Criteria (the two mechanical gates —
`materialize-format.js`'s hard gate and `compose-record/compose.js`'s
`validateShaped` — are unaffected by what a human-facing prose checklist
says; `compose-subject.js`'s merge-time gate still catches an under-shaped
record regardless of what any of these three prose checks say).

`refine-mode.md`'s case is the same class of gap but with live behavior: its
check auto-downgrades a `ready` row to flag-back with a message listing
"missing/empty" sections — until fixed, a record missing only `## Release
Note` passes this check silently (no flag-back), and would only be caught
later, at merge time, by `compose-subject.js`'s unconditional gate.

Kept three authoring-time human checklists in sync with the four-section spec-shaped-body definition.

## Technical Approach

Each file restates the same underlying `_shared/work-record.md` definition independently in
prose (none calls a shared function for this human-facing description), so this is three
small, independent one-clause edits — no shared helper to touch, no behavioral change beyond
what each restatement names.

- `shaping-mode.md:69` says spec-shaped-body's structural minimum is "Current State,
  Deliverables, and Acceptance Criteria" and that `_shared/work-record.md`'s check
  "re-verifies exactly these three" — change to name four, including `## Release Note`.
- `capture/SKILL.md:260` detects a "shaped" body as containing `## Current State`,
  `## Deliverables`, and exactly one of `## Acceptance Criteria` / `## Open Question` — add
  `## Release Note` to the required set (`## Open Question` is capture's own alternate-AC
  form and is unaffected by this record's scope otherwise).
- `refine-mode.md:239` describes the check as verifying "`## Current State`, `## Deliverables`,
  and `## Acceptance Criteria` are present and each non-empty" — add `## Release Note` to this
  sentence. The flag-back comment template at line 244/249 already substitutes a dynamic
  `{list}`/`$MISSING_LIST` computed from whichever sections are actually missing — no template
  change needed there, only the prose describing which sections that computation checks.
