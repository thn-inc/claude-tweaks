# 6020: Make the protected-path list a policy value a project can edit

Surface: backend
Risk-flags: auth

## Overview

The protected-path list is a hardcoded array of regular expressions, `PROTECTED_PATH_RES` in `plugin/bin/lib/express/eligibility.js`, that no project can change. The express lane and the pipeline driver both refuse a record whose Key Files or diff touch it. This record makes the list a policy value: unset, the shipped list applies as today; set, the project's list replaces it, removals included, and an explicit empty list protects nothing.

The maintainer chose "fully editable" on 2026-11-21, knowing the trade-off. The express lane merges on green with no reviewer. So a project that removes, for example, `package.json` from its list lets the express lane merge a change to `package.json` with no human. The record documents that consequence in the key's prose. A factory floor (a list the factory sets that a repository cannot shrink) is Phase 11's ceiling rule and is not built here.

**Complexity:** Medium
**Estimated tasks:** 5

## Non-Goals

- `merge-sensitive-paths`, which stays a separate list with its own semantics.

## Acceptance Criteria

1. With the key unset, every eligibility and diff-bounds verdict in the existing express and driver suites is unchanged, and the equivalence test passes: for every corpus path, the glob list and today's `PROTECTED_PATH_RES` give the same answer.
2. With the key set to `["infra/**"]`, a record whose Key File is `package.json` is not refused for a protected path by `evaluateRecordEligibility` (express and driver), and a record whose Key File is `infra/main.tf` is refused with `protected path: infra/main.tf`.
3. With the key set to `[]`, no path is protected for eligibility or diff bounds, and `review.js`'s evidence-path guard still refuses an evidence path under `hooks/`.
4. `express-lane.js check` and `drive.js --check` both read the resolved key: a fixture repository whose `policy.yml` sets `protected-paths: ["infra/**"]` refuses a diff to `infra/main.tf` and does not refuse a diff to `package.json` for a protected path.
5. A malformed value (not a list of strings) resolves `invalid: true` and falls back to the shipped list, never to an empty list. An unset key, an absent `policy.yml` and an unreadable `policy.yml` all yield the shipped list, proved through the real resolver, not only the pure function.
6. Key globs are root-anchored (`globToRegExp` is `^...$`): with `["package.json"]`, `package.json` is protected and `a/package.json` is not; with `["**/package.json"]` both are. The key's prose row says so.
7. The evidence-path guard calls `isProtectedPath` through an explicit arrow (`(s) => isProtectedPath(s, union)`), not `.some(isProtectedPath)`, and `isProtectedPath` refuses a non-array list; a test shows `hooks/` still refused when a list is passed.
8. A record whose diff edits `.claude-tweaks/policy.yml` to remove `package.json` from `protected-paths` (with the main checkout still protecting it) gets the same eligibility and `check` verdict for a `package.json` change as without that edit.
9. Each adversarial spelling gets the same answer as its canonical path, against the shipped list and against `["infra/**"]`: a `.` segment (`hooks/./x.js`, `infra/./main.tf`), a `..` segment (`a/../hooks/x.js`, `x/../infra/main.tf`), backslashes (`hooks\x.js`, `infra\main.tf`), a leading `./` (`./hooks/x.js`, `./infra/main.tf`), and a trailing slash (`hooks/`, `infra/`), whose answer the test pins. Case follows the Gotcha: eligibility is case-sensitive, and the evidence guard tests three case spellings. Percent-encoding (`%2e%2e`, `%2f`) and URL schemes are out of scope: repo paths come from git and from Key Files text, and neither is URL-decoded, so `%2e%2e/hooks/x.js` is an ordinary literal path, and a test shows it is not decoded.
10. A list containing an empty-string element (`[""]`, `["infra/**", ""]`) resolves `invalid: true` and falls back to the shipped list. A well-formed glob that matches nothing (`["no/such/**"]`) is valid and protects nothing else.

## Release Note

Projects can now set which paths the express lane and the pipeline driver treat as protected, instead of a fixed built-in list.

## Technical Approach

Keep `eligibility.js` pure: the list is a parameter, never read from disk there. Convert the regexes to globs once, as a frozen constant beside the comment that explains each family, and keep the comment. Equivalence is proved by a test over a fixed corpus, not by inspection.

The fallback direction for a malformed value is the shipped list. Fail closed, as `express-driver-max-size`'s unreadable value refuses rather than widening.

### Data / API Surface

- Policy key (proposal `protected-paths`): `{ type: 'list', default: [], emptyList: true, policyOnly: true, category: 'merge-safety', tier: 'advanced' }`, with unset meaning `SHIPPED_PROTECTED_PATHS`. The exact unset-vs-default representation is settled with policy-key-addition.
- `SHIPPED_PROTECTED_PATHS`: frozen glob array exported from `eligibility.js`.
- `isProtectedPath(path, list = SHIPPED_PROTECTED_PATHS)`.
- `evaluateRecordEligibility(issue, { ..., protectedPaths })`, `evaluateDiffBounds(files, { ..., protectedPaths })`.

### Key Files

- `plugin/bin/lib/express/eligibility.js`: glob constant, `isProtectedPath` parameter, options
- `plugin/bin/lib/express/cli.js`: resolve the key and pass it
- `plugin/bin/lib/driver/steps.js`: `POLICY_KEYS` and passing the list
- `plugin/bin/lib/driver/review.js`: evidence-path guard over the union
- `plugin/bin/lib/policy-schema.js`: the key row

## Gotchas

- `globToRegExp`'s handling of `**` and of a root-level match must be checked against the corpus before writing the constant. `(^|\/)hooks\.js$` means "a file named hooks.js at any depth", which needs both `hooks.js` and `**/hooks.js` if `**/` does not match zero directories.
- `review.js` line 395 tests three case spellings of the path. Keep that when switching to the union.
- `policyOnly: true` matters: a `--run` config must never shrink the list.
- The express CLI's `gate` verb runs eligibility too. Pass the list there as well as in `check`.
- Risk proof required: this record carries kept risk flags, so one plan step must contain, per slug, a line `Proof(<slug>): <text>` with a specific proof of at least 20 characters. Lines: `Proof(auth): …`.
- Project globs match the canonical posix path with no leading `./` and are case-sensitive; the evidence guard's three case spellings still apply to the union. The key's prose row states this and the root-anchoring rule.
- `globToRegExp` renders a trailing `/**` as matching the bare parent, so `**/hooks/**` also matches a path named `hooks`; the equivalence test rules on that (a bare directory name is not a file in git) rather than assuming exactness.
- The unset sentinel must survive resolver normalization: a later change that makes unset read as `[]` would disable protection everywhere, so the resolver-level test in AC5 is load-bearing.
- `drive.js --check` reaches eligibility through `steps.js`; confirm every entry point calling `evaluateRecordEligibility` or `evaluateDiffBounds` passes the list.
- This record and the protected-path mode sibling edit the same eligibility options and prose file; the option names (`protectedPaths` beside the sibling's) are pinned once the sibling lands.
- #6019's build-time subset (`BUILD_TIME_PROTECTED`) is a fixed constant, not part of this key: it applies to a path only while the resolved list protects it. A project that removes a build-time family from its list un-protects it entirely, by choice.


## Decision Rationale

- The maintainer chose fully editable over add-only on 2026-11-21, after being shown that removals reach the express lane. The design's own wording is "a default a project can edit, with the factory able to set a floor".
- The evidence-path guard keeps the shipped list as a floor because it guards what the reviewer worker may write, not what a record may change.
- Resolved from the main checkout (maintainer, 2026-11-21), so a record cannot widen its own run by editing `policy.yml`. An empty-string glob is invalid. A never-matching glob is allowed, since the list is editable by choice.
