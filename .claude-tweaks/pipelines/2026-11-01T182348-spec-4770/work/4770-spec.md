# 4770: Tolerate a failed identity probe when closing a below-floor parent

Surface: backend

**Related:** #4801, #4800, #4798

## Current State

The below-floor parent close reads the current `gh` identity (`gh api user --jq .login`, `get_me` under MCP transport) so its already-commented dedupe can count a `## Closed below the oversight floor` comment posted by the plugin's own token under an untrusted author association. When that read fails, which happens with a token GitHub refuses on `/user` (a GitHub App installation token, for one) or a transport whose identity read fails, every twin of the procedure gives up instead of degrading:

- `plugin/bin/lib/issues/below-floor-parent-close.js` (the reconciler's Node mirror, #4599) calls `gh api user` through `call()`, so a failure throws `GhFailure` and the parent lands in `skipped` as `gh-failed`. `plugin/bin/lib/reconcile/post-merge.js` writes its post-merge marker whatever the skip reasons, so the reconciler never retries that parent.
- `plugin/skills/wrap-up/verification-brief-parent-gate.md`'s **Close the parent below the floor**, step 1, runs the same probe and says nothing about a failure, so a prose caller's behavior on a failed probe is undefined.
- `/claude-tweaks:tidy`'s backstop, the `parent-gate` scope in `plugin/skills/_shared/github-pr-scan-acceptance.md`, writes the probe's output to `$PARENTS.login` and throws `gh api user returned no login` when it is empty, which stops the whole scope: no `[parent-gate]` rows at all, not just for one parent. So the backstop the reconciler relies on fails the same way under the same token. #4801 already owns that fix (empty login degrades to trusted-only matching plus a WARNING line), with the same ruling as this record; this record does not touch that file.
- `plugin/skills/tidy/SKILL.md`'s verify line for **Closed parent below the floor** counts a close comment by trusted author or by the current `gh` identity.

Ruling (made at shaping time, 2026-11-01): a failed or empty identity probe no longer skips. The procedure proceeds with no login, so the dedupe counts trusted-author close comments only (`_shared/pr-run-comments.md`'s Trusted authors, `isTrustedComment`), and the output names the degrade. The accepted risk is one duplicate close comment, reachable only when an earlier attempt posted the comment under an untrusted association, its close call then failed, and the retry also had no readable identity. The parent still ends up closed exactly once. `isCloseMarkerComment(comment, '')` already returns false for any login match, so an empty login already means trusted-only matching in the helper.

## Deliverables

- [ ] `plugin/bin/lib/issues/below-floor-parent-close.js`: the identity probe is caught on its own. A thrown call or an empty login yields `login = ''` and never a `gh-failed` skip. When the probe failed and no trusted close comment was found, the `closed` entry for that parent carries a note naming the degrade (exact text: `identity probe failed — close marker matched against trusted authors only`), so `post-merge.js`'s summary marker shows it through its existing `notes` rendering. The probe is read at most once per call to `closeBelowFloorParents`, not once per parent.
- [ ] `plugin/skills/wrap-up/verification-brief-parent-gate.md`, **Close the parent below the floor** step 1: states that a failed or empty identity read (gh or `get_me`) proceeds with trusted-author matching only, names the degrade in the output, and does not skip the parent. The module header comment and this prose state one rule.
- [ ] `plugin/skills/tidy/SKILL.md`: the **Closed parent below the floor** verify line accepts a trusted-author close comment alone when the identity read fails.
- [ ] Tests: `tests/bin-lib/issues/below-floor-parent-close.test.js` covers a throwing probe and an empty-login probe; `tests/below-floor-parent-close-conformance.test.js` pins the new prose sentence in the parent-gate file and in tidy's verify line.

## Acceptance Criteria

- [ ] With a fake `gh` whose `api user --jq .login` call throws, a due below-floor parent with no close comment is commented once and closed; its `closed` entry carries the degrade note; `skipped` has no `gh-failed` entry for it.
- [ ] With the same throwing probe and a trusted (`MEMBER`) close comment already present, the parent is closed with no second comment and no degrade note.
- [ ] With the same throwing probe and a close comment from an untrusted association (`NONE`, the plugin-bot shape), a second close comment is posted and the parent closes: the accepted duplicate is pinned by a test, not left implicit.
- [ ] An `api user` call that returns an empty string behaves exactly like a throwing one.
- [ ] The probe call appears at most once in the fake `gh`'s call log for a run that closes two parents.
- [ ] Every existing test in both suites still passes, including the own-login dedupe case (a working probe still counts the current identity's untrusted-association comment).
- [ ] `npm test` passes on the full suite.

## Release Note

Close a below-floor parent after its last child merges even when the token cannot read the account's identity.

## Technical Approach

Probe once, lazily, in `closeBelowFloorParents`: the first parent that reaches the idempotence read calls `gh(['api', 'user', '--jq', '.login'])` inside its own try/catch, outside `call()`, so a failure never becomes `GhFailure`. Cache `{ login, probeFailed }` for the rest of the loop. Pass `login` to `isCloseMarkerComment` as today. When `probeFailed` is true and `alreadyCommented` is false, push the degrade note onto that parent's `notes` before the comment is posted.

In the prose, add one sentence to step 1 after the login read and its MCP line; keep the Trusted-authors sentence as is. Leave `plugin/skills/_shared/github-pr-scan-acceptance.md` to #4801; whichever of the two lands second checks that the scan's warning and this procedure's degrade note describe the same rule.

### Key Files

- `plugin/bin/lib/issues/below-floor-parent-close.js` — catch the identity probe on its own, cache it per call, add the degrade note
- `plugin/skills/wrap-up/verification-brief-parent-gate.md` — canonical prose: failed identity read proceeds with trusted-only matching
- `plugin/skills/tidy/SKILL.md` — verify line for a below-floor close
- `plugin/bin/lib/reconcile/post-merge.js` — read only: its `composeSummaryText` already renders `notes`; no change expected
- `tests/bin-lib/issues/below-floor-parent-close.test.js` — throwing and empty probe cases, single probe per run, accepted duplicate
- `tests/below-floor-parent-close-conformance.test.js` — pin the new prose in both skill files

## Gotchas

- The conformance suite byte-pins prose in `verification-brief-parent-gate.md` (it asserts the Trusted-authors sentence verbatim). Add the new sentence beside it rather than rewording it.
- #4800 adds a conformance test asserting the prose's skip rules and the module's are the same set. This record removes a skip cause (`gh-failed` from the probe) rather than adding a rule; if #4800 lands first, its test must still pass after this change.
- The fake `gh` in the unit test answers `api user --jq .login` from `world.login || 'plugin-bot'`, so an empty-login case needs a `throwWhen`/explicit-empty hook rather than `login: ''`.
- Out of scope: GraphQL `viewer { login }` as a second probe. A token refused on `/user` might still answer it, but nobody has checked, and adding it would be a second probe every twin must keep identical.

## Current State

`plugin/bin/lib/issues/below-floor-parent-close.js` (the Node mirror of `wrap-up/verification-brief-parent-gate.md` Step 4.0b, added by #4599) skips every parent for good when its `gh api user` identity probe fails, which is what a token that cannot read `/user` produces (a fine-grained token, an MCP-only sandbox). The probe, and the skip it causes, are copied from the canonical prose in `plugin/skills/wrap-up/verification-brief-parent-gate.md`, and `/claude-tweaks:tidy` runs the same prose, so tolerating a failed probe changes three places that must stay twins, and the already-commented dedupe the probe feeds has a duplicate-comment edge case that nobody has ruled on. Found by the #4599 review (lens 3c, tiebreak confirmed, low).
