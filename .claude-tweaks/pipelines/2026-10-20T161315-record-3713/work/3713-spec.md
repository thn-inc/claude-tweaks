# 3713: build-review-context.js: trim full-file sections from prose-heavy review bundles

Origin: reflect full from #2734

Defer-reason: tangential

## Current State

`build-review-context.js build` appends each changed file's full live content after the diff section. On #2734's xhigh review (17 changed files, about 200 changed lines, mostly skill markdown) the bundle came to 624,985 bytes while the diff itself ended at line 983. Every dispatched lens agent had to be told in its prompt to read only the diff head, and each still spent roughly 95k to 155k tokens. The full-file sections duplicate what an agent reads from the live checkout anyway. Evidence: the build result `{"bytes":624985,"files":17}`. Cost this session: twelve lens agents each paged a 625 KB bundle; how much of the roughly 1.5M subagent tokens was the bundle is unclear.

## Deliverables

- [ ] Make the bundle's per-file full-content sections opt-in, or cap them for markdown and for files above a size threshold, so a prose-heavy diff yields a bundle close to its diff size.
- [ ] Keep the `oversizeSections` and `emptySections` reporting, and keep `step3-lens-dispatch.md`'s guidance accurate about where the diff ends and what follows it.

## Acceptance Criteria

1. A review of a diff touching large shared markdown files produces a bundle whose size is within a small multiple of the diff size.
2. A lens agent can still reach any changed file's live content by reading it from the checkout.
3. `npm test` passes.

## Release Note

Review context bundles no longer carry full copies of large changed files, which cuts the tokens each lens agent spends on prose-heavy diffs.

## Technical Approach

### Key Files

- `plugin/bin/lib/review-context/build.js` — the bundle builder
- `plugin/skills/review/step3-lens-dispatch.md` — the dispatch guidance describing the bundle layout
