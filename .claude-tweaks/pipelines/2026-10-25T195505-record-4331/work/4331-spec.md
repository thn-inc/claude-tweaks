# 4331: Move close-out's update-marker parsing and validation out of prose into a tested module

Origin: reflect light from #4317

Defer-reason: tangential

## Current State

Close-out's update marker (`plugin/skills/dispatch/close-out-update.md`, Update marker section, shipped by #4317) is read and written by an agent following prose. Three of the six findings the #4317 review confirmed were deterministic parse and validation defects in that prose: a second line edited to CRLF read as "no marker" (fail-open), a `pre-update-head` taken from a comment body and pasted into `git rev-list` unchecked, and a clear decided from a single head read. Each was fixed in prose and pinned by a regex over the prose, which proves the sentence exists but not that an agent applies it.

Evidence: review lens 3b/3c reproduction pairs on #4317 (`close-out-update.md` lines 40, 46, 78 before the fix wave). Cost this session: one review fix wave plus a 19-minute re-verify.

## Deliverables

A small module under `plugin/bin/lib/` that parses a `close-out-update` marker body into `{status, updateMethod, conflictedFiles, preUpdateHead, resolutionCommits}` (trimming trailing whitespace, treating an unrecognised status line as unreadable, accepting only a 40-hex sha), serialises one, and appends an update to an existing pending marker.

`close-out-update.md` calls that module for the Read, the pending write body and the accumulation, instead of describing each rule in prose.

Unit tests for the module covering CRLF, an unrecognised second line, a non-hex `pre-update-head`, and accumulation order; the prose pins that restate those rules are dropped or reduced to the call site.

## Acceptance Criteria

Feeding the module a marker body whose second line ends in `\r` returns status `pending`; an unrecognised second line returns `unreadable`; a non-40-hex `pre-update-head` returns `unknown`.

Appending an update to a pending marker returns entries oldest first, the union of conflicted files, and the replaced `pre-update-head`.

`npm test` passes with the new unit tests and the reduced prose pins.

No user-visible change.
