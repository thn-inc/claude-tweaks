## Current State

After PR #5700 (the build of #5666) this record is down to one test that fails on Windows: `the real repoRoot default resolves the checkout top level`, at line 441 of `tests/bin-lib/skill-gate/cli.test.js` (`origin/main` at `af2bade1e`). The other two tests named in the original report pass. Both facts are read from the `windows-regression` run on that PR's branch head `95f633e0b` (run 43847349762, the whole suite, 30,232 tests). The post-merge run on `main` at `af2bade1e` (run 43851465928) was still in progress when this was written.

Line 445 asserts `assert.equal(real.realDeps.repoRoot(main, ENV), fs.realpathSync(main))`. `realDeps.repoRoot` in `plugin/bin/skill-gate.js` (line 115) returns the trimmed output of `git rev-parse --show-toplevel`. Git for Windows prints that path with forward slashes, and `fs.realpathSync` returns backslashes, so the strict comparison fails on win32 only. From the run's isolated log for this file:

```
+ 'D:/a/_temp/ct-wtd-X6v8X7'
- 'D:\\a\\_temp\\ct-wtd-X6v8X7'
```

The shipped code is not at fault. `resolveRoot` passes the value to the gate, and `plugin/bin/lib/skill-gate/index.js` (line 300) runs it through `canonicalRealpath` from `plugin/bin/lib/path-guard/index.js` before any containment comparison. The test compares a raw git path with a canonical one; the code never does.

`.claude/skills/windows-checkout-test-parity/SKILL.md` lists this failure shape: an expected `--show-toplevel` value built with `fs.realpathSync`. Its remedy is to ask git for the expected value, as `gitRevParse` does in `tests/hooks-git-exec.test.js` (#4299). That remedy does not fit this test, because the thing under test is that same git call: both sides would be one command compared with itself.

The test has a second weakness on every platform. It calls `repoRoot` with the repository root as `cwd`, so a default that returned its `cwd` argument unchanged would pass.

Nothing was run on a Windows host for this record beyond reading run 43847349762.

## Deliverables

1. **Compare through one canonical form.** The line-441 test compares `canonicalRealpath(real.realDeps.repoRoot(...))` with `canonicalRealpath(main)`, importing `canonicalRealpath` from `plugin/bin/lib/path-guard`. That is the function the gate applies to this value, so the test pins the form the code uses. It asserts first that neither side is `null`. No `process.platform` or `path.sep` branch.
2. **Call from a subdirectory.** The test creates a directory inside the fixture repo and passes it as `cwd`, so it fails for a default that returns its `cwd`.
3. **Keep a check on the raw value.** The test still asserts that `repoRoot` returns a non-empty string with no trailing newline.
4. **Windows proof.** Dispatch `windows-regression` on the fix branch and read the result from the `tests.log` in its `verify-report` artifact.
