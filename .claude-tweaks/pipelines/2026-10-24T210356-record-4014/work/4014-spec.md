# 4014: compose-subject renders the record's "Filed by" footer as part of the release note

Origin: spec #2805 review (merge)

Defer-reason: pre-existing-outside-diff

## Current State

`bin/lib/compose-subject.js` reads the subject record's release note with `extractSection(body, 'Release Note')`, which runs to the next heading. A `specShapedBody` record with no `### Key Files` ends `## Release Note` with its `_Filed by … via specShapedBody._` footer and no heading in between, so the footer becomes part of the release note.

Observed merging PR #2822 (refs #2805): `extractSection` returned the release-note sentence plus "_Filed by `ledger resolve gate`. Close to resolve; label `wontfix` to suppress future reports of this finding._", and `compose-subject.js 2805 --pr 2822` put that paragraph into the squash body after the `Release-Note:` line. It was hand-removed for that merge; every other merge composed from such a record carries it.

## Deliverables

- [ ] The release note compose-subject renders excludes a trailing `_Filed by …_` footer paragraph (stop the section at the footer line, in compose-subject's read or in a dedicated release-note extractor — not by changing `extractSection`'s heading-bounded contract for its other callers).

- [ ] A test composing a subject from a `specShapedBody` body with no Key Files asserts the footer text is absent from the output body.

## Acceptance Criteria

- `compose-subject.js` on a record whose body ends `## Release Note\n{note}\n\n_Filed by `x` via specShapedBody._` prints a body containing `Release-Note: {note}` and no `_Filed by` text.

- Existing compose-subject and merge-subject-composer conformance tests still pass.

## Release Note

Merge commits composed from agent-filed records no longer include the record's "Filed by" footer.
