# 4523: Anchor HARNESS_ISOLATION_REFUSAL_RE so quoted refusal text in command output stops logging a false event

Origin: ledger resolve gate (#3819 ledger item 3)

Defer-reason: genuinely-larger

## Current State

`HARNESS_ISOLATION_REFUSAL_RE` in `plugin/bin/lib/hooks/harness-refusal.js` has no start anchor, so a failed Bash command whose output merely quotes refusal text (a failing test fixture is the usual case) logs a false `wd-guard-refusal` event. The defect predates #3819; its widening to the agent-noun and worktree-gone signatures slightly enlarges the surface (final whole-branch review, minor 6). Anchoring at `^` is only safe if the hook's `error` always begins with the noun, which the 2026-10-28 agent probe confirmed for the agent template; the session and worktree-gone templates have not been measured.

**Related:** #4524, #4525

## Deliverables

- [ ] Measure, with a headless probe like the one #3819 used, whether `error` begins with the noun for the session and worktree-gone templates, and record the result in `tools/upstream-drift/manifest.yml`.
- [ ] Anchor the pattern at the start of `error` if all three begin with the noun; otherwise bound the match another way and say why.
- [ ] Keep `bash-prefilter.js`'s signature check consistent with the matcher.

## Acceptance Criteria

A test passes a failed-command `error` that quotes a refusal in the middle of its text and expects no `wd-guard-refusal` event.

The existing tests for the session, agent and worktree-gone refusals still pass.

`npm test` passes.
