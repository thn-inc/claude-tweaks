# 4589: Render dispatch Task prompts from a CLI instead of hand-substituting task-prompt.md

Origin: session 2026-10-30, resumed #3903 build (PR #4541, run 2026-10-30T063836-record-3903)

Defer-reason: tangential

**Related:** #4588

## Current State

`plugin/skills/dispatch/task-prompt.md` is about 48 KB. Its Step 5 instructions require the dispatching session to copy each fenced template verbatim and substitute `{issue list}`, `{minted-run-dir}`, `{plugin-root}`, `{context-pack}` (eight items, three resolved by CLIs) and `[Use: …]` by hand. One #3903 resume needed three such prompts of about 10 KB each (first call, second call, handoff continuation). Hand substitution let small drift in: context-pack items were condensed rather than copied, and `Selected at:` was written as free text. Nothing checks a dispatched prompt against the template.

## Deliverables

1. A `plugin/bin/` CLI (e.g. `dispatch-prompt.js --call first|second|continuation --run {run-dir} --issues N[,M] [--next-steps …] [--headless]`) that resolves the context pack (plugin root, policy values, profile, Selected-at), fills the template from `task-prompt.md`'s fenced blocks, and prints the finished prompt or writes it to a file.
2. `task-prompt.md`/`SKILL.md` Step 5 point the dispatching session at the CLI; the fenced blocks stay the single source the CLI reads.
3. A test that the rendered prompt contains every fixed sentence of its template and no unsubstituted `{…}` placeholder.

## Acceptance Criteria

- [ ] A dispatch firing builds each Task prompt with one CLI call and no manual placeholder substitution.
- [ ] Editing a sentence in a `task-prompt.md` fenced block changes the CLI's output with no code change.
- [ ] The test fails when a placeholder is left unsubstituted.

## Release Note

No user-visible change: dispatched build agents receive prompts generated from the template rather than hand-copied.
