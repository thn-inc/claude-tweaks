# 4251: pr-first: an armed merge never runs the closing-links post-merge reopen, so a Development-sidebar link can still close a kept-open record

Origin: ledger resolve gate

Defer-reason: genuinely-larger

## Current State

- `bin/closing-links.js --mode post-merge` (the reopen backstop) runs only from `_shared/pr-first-merge-post-merge.md` Step 4.0, which an `armed` pr-first outcome never reaches: the merge lands later, when the forge is satisfied.
- The reconciler finishes `armed` runs on merged-PR evidence but does not run the CLI. With `compose-subject.js --keep-open` the squash message and the PR body no longer name a kept-open record, so the only closing channel left is a Development-sidebar link added by hand; on an armed merge nothing reopens a record that link closes.
- Found by the final whole-branch review of the closing-link guard (ledger row of the build run); shipped with a prose note in Step 4.0 naming the gap.

## Deliverables

- [ ] Add a reconcile convergence check (registration sites per `docs/reconcile-checks.md`) that, for a merged pr-first run whose fixes span carries `Refs #n` records, runs `bin/closing-links.js --mode post-merge` once and logs the outcome.
- [ ] Drop the "armed outcome never reaches this step" caveat from `_shared/pr-first-merge-post-merge.md` Step 4.0 once the check lands.

## Acceptance Criteria

- [ ] A test drives the new check with a fake `gh` that reports a merged PR, a `Refs #n` record closed after `mergedAt`, and asserts the record is reopened and a decisions line is written.
- [ ] A run whose fixes span has no `Refs` record triggers no `gh issue` call.

## Release Note

A pr-first run that merges through auto-merge now also reopens a record it left open, even when a manual sidebar link closes it.
