# 4702: /specify near-duplicate check appends single-signal candidates to Related as noise

Origin: reflect full from /specify #4606 session

Defer-reason: tangential

## Current State

`plugin/skills/specify/shaping-mode.md`'s Near-duplicate candidate check says to "append every candidate as `#{n}` to the composed body's `**Related:**` line" (line 99 on origin/main, probed with `git grep -n -F -e 'append every candidate' origin/main -- plugin/skills/specify/shaping-mode.md` → match). `findNearDuplicates` returns score-1 hits on `body-anchor-overlap` alone, and that signal fires on a single shared incidental anchor.

Observed 2026-10-31 shaping #4606: 19 candidates came back and all 19 went onto `**Related:**`. Re-running the finder (`findNearDuplicates(#4606, open queue)`, 2026-10-31) shows the noise is shallow: 16 of the 17 score-1 hits share exactly one anchor, the bare word `main` (Windows regressions, release, policy, pr-first records). `**Related:**` feeds `/backlog refine`'s priority/Related synthesis, so noise there degrades a downstream reader.

Amended 2026-10-31 at `/flow` pre-flight: the first-filed threshold ("score ≥ `MIN_REFUSAL_SCORE` or `title-similarity`") would have dropped a real duplicate. #4701's evidence case, #3508, was the true duplicate of #4093 at score 1 with six shared Current State anchors. `isStrongNearDuplicate` (`plugin/bin/lib/issues/near-duplicate.js`, #3520) already separates the two shapes: at least 2 signals **or** at least 2 shared anchors. Against #4606 it keeps #4612, #4687 and #4229 (2 anchors) and drops the 16 one-anchor `main` hits.

## Deliverables

1. Export `isRelatedCandidate(hit)` from `plugin/bin/lib/issues/near-duplicate.js`: true when `isStrongNearDuplicate(hit)` holds or the hit's signals include `title-similarity`. Reuse `isStrongNearDuplicate`, never a second threshold.

2. `shaping-mode.md`: render every candidate in the candidate table (unchanged), but append to `**Related:**` only hits `isRelatedCandidate` accepts; below the table, name the hits left off (`Not added to Related (one shallow signal): #a, #b`) so a human can still add one by hand.

## Acceptance Criteria

- `shaping-mode.md` no longer says "append every candidate"; it names `isRelatedCandidate` for the `**Related:**` append and states its rule (2+ signals, 2+ shared anchors, or title similarity).

- `isRelatedCandidate` unit cases: score 1 with one shared anchor → false; score 1 with six shared anchors → true; title-similarity alone (score 1, no anchors) → true; score 2 → true; non-object → false. The one-anchor case fails against an `isRelatedCandidate` that returns true for every hit.

- A prose test pins the new wording and fails against the old "append every candidate" sentence.

- The candidate table still lists every finder hit.

## Release Note

Stop /specify from listing unrelated single-signal near-duplicates as Related records, while keeping deep-overlap duplicates.

## Technical Approach

Coordinate with #4701 (in flight): it changes the same paragraph's report wording and the finder's sort. This record only filters the `**Related:**` append and leaves the sort and `score` alone.
