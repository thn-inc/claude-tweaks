# 3363: flow: a freshly claimed run dir absorbs other sessions' fallback-attributed events and preflight adopts it as case 3

# Reflect — staged finding 1

**Category:** tangential
Origin: reflect light from #3337

Defer-reason: tangential

## Current State

`/claude-tweaks:flow` Step 2.8 mints the run directory (`resolve-run-dir --create`) and then immediately writes the claim-log line into its `decisions.md` (`flow/claim-targets.md`, #2492), before Step 3 writes `config.yml` or any `run-state.json` exists.

`plugin/bin/lib/hooks/context.js` `isUnadoptedMint` (line 54) excludes a mint from fallback event attribution only while it carries neither `run-state.json` nor `decisions.md`. Once the claim line lands, the mint is an unowned, newest, non-terminal run, so `post-tool-use.js`'s fallback attribution (`attribution: 'fallback'`) routes sibling sessions' events into its `events.jsonl`.

`plugin/bin/lib/flow/preflight.js:145` then computes `hasOtherContent = decisionsHasContent || nonEmpty(events.jsonl) || specMaterialized`, so a fresh mint with only foreign fallback events adopts as **case 3** (repair: backfill worktree, PR, materialize) instead of **case 2** (fresh). #3242 fixed the same misclassification for Step 1.5/1.8 `decisions.md` content; the `events.jsonl` arm is untouched.

Observed in run `2026-10-17T075913-spec-3337` (#3337): within 30 seconds of the claim, `events.jsonl` held three foreign lines — a `claude-tweaks:dispatch` `skill_invoked` and two `session-end` events from sessions `2a784df0…` and `57ef0028…`, all `"attribution":"fallback"` — and `flow-preflight.js` reported `case: 3` with backfills `worktree registration, PR-early lifecycle, materialize commit`. The orchestrator had to override the case by hand.

## Deliverables

- `isUnadoptedMint` treats a directory whose `decisions.md` classifies as `claim-log-only` (`bin/lib/log-decision/claim-log.js` `classifyDecisions`) and that has no `run-state.json` as still unadopted, so fallback attribution never targets it.
- `computeAdoption` ignores `events.jsonl` lines carrying `"attribution":"fallback"` when deciding `hasOtherContent` (only `env`/`session`-attributed events are evidence this run did anything).
- A regression test for each: a claim-log-only mint is skipped by the fallback resolver; a mint whose `events.jsonl` holds only fallback-attributed lines adopts as case 2.

## Acceptance Criteria

1. With a minted run dir holding only a Step 2.8 claim line, a hook event from a different session with no `PIPELINE_RUN_DIR` is not appended to that dir's `events.jsonl`.
2. `flow-preflight.js --run <dir>` on a dir with a claim-log-only `decisions.md` and an `events.jsonl` holding only `"attribution":"fallback"` lines reports `adoption.value.case === 2`.
3. A dir whose `events.jsonl` holds an `env`- or `session`-attributed line still reports `hasOtherContent: true`.

## Release Note

A freshly claimed `/flow` run no longer picks up other sessions' hook events, and no longer misreads them as an interrupted earlier run.
