# 3460: Detect skill reads the static closure cannot see — compare file sets, not byte totals

Origin: #3309 final whole-branch review (ledger row 36)

Defer-reason: out-of-scope

## Current State

#3309 ships `plugin/bin/skill-load-report.js` and harness-health's Skill-load check. The check files a `by:harness-health` record when a skill's measured per-invocation load exceeds its static closure from `plugin/bin/lib/skill-audit/load.js` (`overClosure = max > closure`, the spec's literal contract). On real data that comparison cannot fire, for two reasons:
- Every plugin skill's closure is transitive and runs 1.20–1.96 MB (even `claude-tweaks:capture` is 1.96 MB, out of a ~5.95 MB corpus). The largest measured max over 20 sessions plus 510 subagent transcripts is 236,519 B, a ratio of 0.01–0.13.
- harness-health invokes the CLI with only `--plugin-root "${CLAUDE_PLUGIN_ROOT}"`, so project-local `.claude/skills` always get `closure: null`. That is the only place over-closure actually showed up when the reviewer passed `.claude` explicitly (`node-test-output-evidence`, max 52,872 B against closure 15,187 B).

The spec's stated purpose is to find skills whose sessions read prose their citations never reach. `readSkillLoads` already records each invocation's `readPaths`, but the CLI discards them after summing bytes.

## Deliverables

- In `skill-load-report.js`, compare each invocation's skill-file `readPaths` against the matching entry's closure `files` (from `entryPointLoads`, normalized to the same path form). Report per skill the count and list of read files outside the closure (`outsideClosure`). Make that the filing trigger, replacing or alongside `max > closure`.
- Decide how project-local roots reach the harness-health command. One option is passing `--plugin-root .claude` when `.claude/skills/` exists. A root with no `skills/` makes the CLI exit 2 today, so the command needs a guard.
- Update harness-health's Skill-load check paragraph and its prose-pin test to match.

## Acceptance Criteria

1. A fixture invocation that reads a skill file outside its closure's `files` is reported with that path in `outsideClosure` and triggers filing. Reading only closure files does not.
2. On this repo's real transcripts, the report names at least one skill with `outsideClosure` non-empty, or the PR states why none exists.
3. A project-local skill invoked from a worktree joins its `.claude/skills` closure under the harness-health command as written.

## Release Note

Health checks now flag skills whose sessions read skill files their own instructions never point to.
