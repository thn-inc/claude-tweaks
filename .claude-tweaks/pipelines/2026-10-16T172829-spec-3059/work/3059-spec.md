# 3059: Evaluate tool.check's new ceiling field for claude-tweaks

Surface: infra

## Current State

Claude Code 2.1.290 adds a `ceiling` field to the question/verdict a mod's `tool.check` hook reads. It names the approval level an organization requires for a tool (source in the original request below).

What claude-tweaks has today:

- **No `tool.check` hooks.** claude-tweaks ships no mods, and nothing in the repo references `tool.check` or `gatingHooks` (repo-wide `git grep` returns zero live hits). Its tool-call gating is the PreToolUse hook registered in `plugin/hooks/hooks.json` and dispatched through `plugin/bin/hooks.js`. `plugin/bin/lib/hooks/pre-tool-use.js` emits `permissionDecision: 'deny'` only (line 422).
- **A separate, project-level ceiling.** claude-tweaks has its own `autonomy` policy lever, documented in `plugin/skills/_shared/autonomy-ceiling.md`. Its tiers are `supervised`, `trusted` and `unattended` (`plugin/bin/lib/issues/autonomy.js:23`). It governs which bookkeeping and record actions skills may take without a click; it gates no tool call. This is a different axis from an organization-level, per-tool approval ceiling: one is the plugin's own workflow autonomy, the other is the host's tool permissions.
- **`claude plugin validate`.** It has been run against this plugin before (archived probe notes for spec 418), but never with `--json` for gatingHooks reporting.

## Deliverables

1. A recorded decision, posted as a comment on this record. It should cover:
   - whether claude-tweaks has, or should gain, any hook that receives the `tool.check` question/verdict (today: none). If it should, whether that hook reads and respects `ceiling`;
   - whether the existing PreToolUse gates should respond to an organization-level ceiling at all, given that they only ever deny and so can never loosen an approval requirement;
   - whether the organization `ceiling` should inform claude-tweaks' own `autonomy` lever. For example: should an organization requiring approval for a tool cap the plugin's effective `autonomy` tier below `unattended`? Or do the two stay independent by design?
   - the output of one `claude plugin validate --json` run against `plugin/`, with what its gatingHooks report lists for claude-tweaks.
2. For any adoption the decision endorses, file a backlog record via `/claude-tweaks:capture` with a spec-shaped body. Otherwise, state explicitly that no change is recommended and what would change the answer.

## Acceptance Criteria

- It quotes the gatingHooks portion of a real `claude plugin validate --json` run, with the Claude Code version used.
- Every endorsed change has a filed backlog record linked from the comment. No claude-tweaks code changes land in this record.
