# 4220: Bound the total size of the /review shared context bundle

Origin: reflect full from #4028

Defer-reason: tangential

## Current State

bin/lib/review-context/build.js caps each file at 64 KB (`PER_FILE_CAP_BYTES`) but nothing bounds the bundle as a whole. On #4028's review (129 scoped files) `context.md` came to 3,153,954 bytes, 692,614 of them the diff. `review/step3-lens-dispatch.md` hands every lens agent that path, and no agent window holds about 780k tokens, so the 14 lens prompts had to tell the agents to skip the bundle and read `git diff` per path instead. `--files-from` narrows the file list but not the budget.

## Deliverables

- [ ] `buildContext` takes a total-size budget and, over it, replaces the largest sections with the existing one-line stub until the bundle fits; `oversizeSections` names every stubbed path.

- [ ] `step3-lens-dispatch.md` says what a lens agent reads when the bundle came back over budget (per-path `git diff {base}...{branch} -- {path}`), so a dispatcher need not improvise it in each prompt.

- [ ] A test builds a bundle from a fixture whose files sum above the budget.

## Acceptance Criteria

- [ ] For a diff whose files sum above the budget, the printed `bytes` is at or under the budget and `oversizeSections` lists every stubbed path.

- [ ] The new test fails when the budget logic is removed.

## Release Note

Review lens agents get a context bundle they can read on large diffs.

## Technical Approach

### Key Files

- `plugin/bin/lib/review-context/build.js` — add a total-size budget; stub the largest sections first
- `plugin/skills/review/step3-lens-dispatch.md` — name the per-path git diff fallback when the bundle is over budget
