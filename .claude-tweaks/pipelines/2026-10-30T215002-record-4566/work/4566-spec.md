# 4566: closing-tally.js has no Resolve-lane field, so a refine #N run that resolves decisions reports an all-zero tally

Defer-reason: tangential

## Current State

`plugin/bin/lib/closing-tally/closing-tally.js:13` defines `FIELDS` as priority, related, granted, flaggedBack, dependencyRepair, needsDecision, skipped and failed. `plugin/skills/backlog/refine-record.md` Step 4 resolves Resolve-lane rows (grant anyway, build it myself, keep, park, close, re-authorize). `plugin/skills/backlog/refine-closing-summary.md`'s log templates have no line for a resolved decision, and the tally has no field to count one. So a `refine #N` run whose only writes are resolves renders a tally of all zeros and lists every resolve line under `unclassified`.

Observed 2026-10-30 on `2026-10-30T043043-backlog-standalone`. Resolving #3944 and #4456 as `keep` produced `0 priority set · 0 Related updated · 0 granted · 0 flagged back · 0 dependency-repair · 0 needs-decision · 0 skipped · 0 failed`, with both resolve lines unclassified.

## Deliverables

1. Add a Resolve-lane log template to `refine-closing-summary.md`, e.g. `AUTO {time} — Backlog refine: resolved decision on #{n} as {choice}.`, and cite it from `refine-record.md` Step 4.
2. Add a `resolved` field to `closing-tally.js`'s `FIELDS`/`LABELS` that counts that template, keeping the per-record max-of-two-forms rule unchanged.
3. A test with a decisions.md holding two resolve lines.

## Acceptance Criteria

- For a decisions.md with two resolve lines, `closing-tally.js --run` reports `2 resolved` and an empty `unclassified` array.
- Every existing closing-tally test passes unchanged apart from the added field.

## Release Note

The closing tally from `/claude-tweaks:backlog refine #N` now counts resolved decisions instead of leaving them unclassified.
