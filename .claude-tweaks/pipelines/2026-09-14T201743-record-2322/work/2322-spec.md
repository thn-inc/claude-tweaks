# 2322: Archive-branches: confirm young squash-merged branches whose remote ref is gone (or document the 14-day delay)

Origin: wrap-up ledger gate for #2252 (run ledger row 24)

Defer-reason: needs-human-decision

## Current State

`plugin/bin/lib/reconcile/archive-branches.js` computes the squash-provenance proof only after the per-branch confirm, and the confirm runs only for destructive or MERGED-screened candidates. A squash-merged local branch whose remote ref was deleted by `gh pr merge --delete-branch` screens `null` (the bulk screen's deleted-ref blind spot, `pr-state.js` header), so while its tip is younger than `BRANCH_AGE_DAYS` (14) it reads `too-young` on every pass and is archived only once it ages — safe direction, delayed convergence (#2252 whole-branch re-review, out-of-scope observation; run ledger row 24).

## Deliverables

Decide whether a screen-`null`, cherry-`false` local branch should reach the per-branch confirm regardless of age (one `gh pr list --head` call per such branch per pass) or keep the age gate and accept delayed convergence.

If confirming: route `screenPr === null && !cherryEquivalent` branches to the confirm in `archiveBranches`'s loop (the `squashCandidate` routing already exists for the MERGED-screened shape) and add a fixture: young (<14d) two-commit branch, squash-merged, screen `null`, confirm MERGED with `mergeCommit` → `delete` `squash-merged`.

Document the chosen posture in `docs/reconcile-checks.md`'s Merged-proof section (the per-pass `gh` cost vs the convergence delay).

## Acceptance Criteria

A young squash-merged local branch with a deleted remote ref converges (deleted with reason `squash-merged`) on the first pass after its PR merges, or the docs state the deliberate delay and its bound (`BRANCH_AGE_DAYS`).

Every pre-existing archive-branches fixture keeps passing unchanged; the per-branch confirm count for non-candidates does not grow beyond the new routing.
