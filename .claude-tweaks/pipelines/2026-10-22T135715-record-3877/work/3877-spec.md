# 3877: Guard tidy's Arm ready PR on acceptance labeling — verify.json check before auto-merge

Origin: reflect full from #3783

Defer-reason: tangential

## Current State

`plugin/skills/tidy/actions-github-issues.md`'s `## Arm ready PR` action runs `_shared/pr-first-merge.md` Step 3 (auto-merge) on a green, non-draft PR and states that it "never touches Step 1 (Acceptance labeling)" because item 9 only selects PRs that are already green and not draft.

That reasoning covers Step 2 (Mark ready) and Step 2.5, not Step 1: being green says nothing about whether acceptance labeling (`demo:pending` / the Try it walkthrough) landed. #3783 (PR #3869) made `pr-first-merge.md` Step 1 state that labeling has not landed when the run's `verify.json` is missing or its `acceptance-labeling` row is not `pass`/`skip`, "whichever caller reached this merge", and guarded `dispatch/close-out.md` step 3, but left this third caller as it was (SDD final review Important 3, deferred by ruling 4).

A record-linked `auto:merge` PR armed here whose run skipped wrap-up's Phase 4 merges and closes its record with no demo label, the failure #3712 exposed.

## Deliverables

- `## Arm ready PR` checks acceptance labeling before running Step 3 for a record-linked PR: it resolves the run dir from the PR body's `claude-tweaks-run:` marker and reads `verify.json` (every `spec-*/verify.json` for a multi-spec parent), applying the same landed rule and live-state precheck as `dispatch/close-out.md` step 3.
- When labeling has not landed, the action stages the PR for a human (the record-linked flavor already always stages) with a reason naming the missing labeling, instead of arming it. It never runs labeling itself from a tidy sweep.
- The housekeeping-marker flavor (no linked record) is unchanged: it has no record to label.
- Consider moving the landed check into one helper that close-out, pr-first-merge Step 1 and tidy all cite (e.g. a `verify-results.js`-backed CLI printing landed/not-landed per run dir), so the three callers cannot drift.
- The "never touches Step 1" sentence is corrected to state the guard.

## Acceptance Criteria

1. A conformance test pins `## Arm ready PR` to name `verify.json`'s `acceptance-labeling` row before its Step 3 call, and fails when that sentence is removed.
2. The "never touches Step 1 … preconditions already hold" claim no longer appears in `actions-github-issues.md`.
3. A record-linked PR whose run dir has no `verify.json` (and no `demo:pending` on its `Fixes` records) is staged, not armed.
4. `npm test` passes.

## Release Note

`/tidy` no longer arms auto-merge on a record-linked PR whose acceptance labeling never landed.

## Technical Approach

### Key Files

- `plugin/skills/tidy/actions-github-issues.md` — `## Arm ready PR` checks verify.json acceptance labeling before Step 3
- `plugin/skills/_shared/pr-first-merge.md` — Step 1 caller list includes tidy's arm action
- `plugin/bin/lib/wrap-up/verify-results.js` — optional shared landed-check helper
