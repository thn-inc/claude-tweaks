## Current State

On 2026-11-16 `/claude-tweaks:dispatch #5689` stopped at selection. The queue pull excluded #5689 as `shipped` by merged PR #5700, with signals `merged-pr-mention-after-created, title-similarity`, and staged `shipped-close-5689.md`. The record was open, `ready`, carried `auto:build`, and was not shipped: PR #5700's body mentions it only in the sentence "The rest of that file stays with issue #5689", and `windows-regression` run 43847349762 still fails the record's remaining test.

`classifyShipped` in `plugin/bin/lib/issues/shipped-candidate.js` rates a qualifying mention `strong` when the title matches or the PR's files cover the record's Key Files. It does not read what the mention says. Its only downgrade is `opts.lastReleasedAt` (#4432): a claim release after the PR's merge.

#5689 was shaped to `ready` by `/claude-tweaks:specify #5689` and granted `auto:build` after PR #5700 merged (2026-11-16T10:43:57Z). The `#N` shaping form claims nothing, so no release exists. The record therefore stays excluded on every queue pull in every session, and each pull stages the Close proposal again.

The dispatch skill's `#N` rule for a record dropped by a removing exclusion is report-and-stop with no override, so the record could only be built by running `/claude-tweaks:flow #5689` outside dispatch.

Not checked: how often this shape occurs across the backlog. This is one observed case.

## Deliverables

1. A record that was shaped to `ready` or granted `auto:build` after the mentioning PR merged is rated `weak` at most, the same way a claim release after the merge is (#4432): someone saw that merge and kept the record open.

2. A record with no such event after the merge keeps today's `strong` rating.

3. The dispatch skill's shipped-candidate prose (its False-positive posture paragraph) states the new downgrade.
