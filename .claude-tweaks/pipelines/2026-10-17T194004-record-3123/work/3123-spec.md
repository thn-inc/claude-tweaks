# 3123: build / subagent-driven-development dispatch: fast-lane multi-task transcription plans still pay a review for every task plus a whole-branch review

Surface: backend

**Related:** #3115

## Current State

A `ceremony: fast-lane`, `size: low` record ran as a 4-task plan that inlined every task's full code. "SDD dispatched an implementer and a task reviewer for every task. It then ran a whole-branch review on the Capable tier and a scoped re-review of that review's one fix, about 11 agent dispatches in total." All four task reviews came back clean.

Verified on origin/main (0af440d76):

- `plugin/skills/build/dispatch.md:19` (Single-task fast-lane skip, #1926) skips the whole-branch review only when the profile is `fast-lane`, `tasks` is exactly `1`, and `batched` is `false`. "Multi-task plans and batched plans … keep the whole-branch review at every profile."
- `plugin/skills/build/plan-authoring-checks.md:19` (Batched-plan marker) defines `**Execution:** batched` only for "several same-shape edits into one dispatch (SDD's 'Batch small same-shape work')". Nothing tells an author to use it for a fast-lane transcription plan.
- `plugin/bin/lib/plan-audit/parser.js:225-232` (`countTasks`) reads the marker as the exact line `^\*\*Execution:\*\*\s*batched\s*$` in the header before the first `### Task N:`, with fenced blocks stripped, or as `[batch]` in a task title.
- The marker is descriptive: no claude-tweaks text forwards it to SDD. SDD batches on its own judgment, and its rule (installed superpowers `subagent-driven-development/SKILL.md`, "The Task Loop") covers "small, independent edit[s] of the same kind", then "Compose ONE dispatch brief … review its diff as one unit." A transcription plan whose tasks differ in shape does not obviously meet "same kind".
- `plugin/skills/build/micro-plan.md` covers only single-file fast-lane records (one implementation file or fewer), which already qualify for the single-task skip.

## Deliverables

1. Decision (approved in brainstorming, 2026-10-15): steer at plan-authoring time. `plan-authoring-checks.md`'s Batched-plan marker gains guidance that a `ceremony: fast-lane` + `size: low` plan whose tasks all inline their full code carries the batched marker. `plan-audit.js --count-tasks` already reads it. Rejected: skipping per-task reviews at dispatch, which overrides superpowers SDD's upstream per-task review loop (pinned in `tools/upstream-drift/manifest.yml`). Also rejected: doing both, which inherits that same override.
2. `build/plan-authoring-checks.md:19`: extend the Batched-plan marker paragraph. When the record header carries `ceremony: fast-lane` and `size: low` and every task inlines its complete code (pure transcription, no judgment left to the implementer), write the plan as one batch. Put `**Execution:** batched` on its own header line. Add a separate plain header line telling the executor to send every task to one implementer as a single brief and review the combined diff once, which is SDD's own batch rule. The result is one implementer, one batch review, and the whole-branch review kept as the gate.
3. Name the case the guidance excludes: a plan where any task leaves code for the implementer to write, or where a task needs its own tests or review surface, stays per-task. This matches SDD's "Reserve one-dispatch-per-task" clause.

## Gotchas

- The marker regex anchors to end of line (`\s*$`). Any text appended to `**Execution:** batched` silently flips `batched` to `false`, and under fast-lane a single-task plan then becomes eligible for the whole-branch review skip. Keep the instruction on its own line.
- The marker alone does not make SDD batch. It only sets `--count-tasks`'s `batched` flag, which keeps the whole-branch review. The dispatch saving comes from the plan header telling the executor to batch, so the guidance must require that line too.
- Do not touch `dispatch.md`'s skip condition or SDD's per-task loop. The rejected option lives there, and `tools/upstream-drift/manifest.yml` pins SDD's `## Final Review` against `dispatch.md`.
- `plan-authoring-checks.md` runs while a plan is finalized in Spec Step 3 or Design Step 3. Plans written before this change are not re-steered, so a re-run of an existing plan keeps its per-task reviews.

## Original request

build / subagent-driven-development dispatch: fast-lane multi-task transcription plans still pay a review for every task plus a whole-branch review

**Summary:** A fast-lane, low-size plan whose tasks all inline their complete code still gets a task review for every task plus a whole-branch review, because the fast-lane skip for the whole-branch review (#1926) only covers single-task plans.

**Kind:** Gap

**Affected component:** build / subagent-driven-development dispatch (`dispatch.md`, `plan-authoring-checks.md` / `micro-plan.md`)

**Use case:**
A record marked `ceremony: fast-lane` and `size: low` ran as a 4-task plan. The change was small and copied an existing pattern in the codebase. The plan inlined the full code for each task, so implementing it was pure transcription. SDD dispatched an implementer and a task reviewer for every task. It then ran a whole-branch review on the Capable tier and a scoped re-review of that review's one fix, about 11 agent dispatches in total. All four task reviews came back clean, with no Important or Critical findings. The whole-branch review found one Minor wording slip.

The fast-lane skip for the whole-branch review (#1926) applies only when the plan has exactly one task. Nothing reduces the per-task review cost for a fast-lane plan made of several transcription tasks. Nothing prompts the plan author to mark such a plan `**Execution:** batched` either. So a low-risk change pays nearly the full review ceremony.

**Definition:** Needed — there are two workable fixes and the report doesn't prefer either: (a) have `plan-authoring-checks.md` / `micro-plan.md` suggest the `**Execution:** batched` marker when the header is `ceremony: fast-lane` + `size: low` and every task inlines its complete code. SDD would then make one dispatch, reviewed once, and the batched path keeps the whole-branch review as the single gate. (b) Have `dispatch.md` skip per-task reviews, but keep the whole-branch review, for fast-lane plans whose tasks are all transcription.

**Plugin version:** 6.139.1
