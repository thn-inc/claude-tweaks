# 2827: specify shaping mode: emit a Release Note and validate the body with the gate's own checker before stamping ready

Surface: infra

## Current State

`/claude-tweaks:specify` shaping mode produces records that `/flow`'s Materialization hard gate rejects. On 2026-09-29, 110 of the 126 open `ready` records had no `## Release Note`, all carrying the `## Original request` section only shaping mode writes, and some were shaped that same day by `/sweep`'s specify drain.

- `plugin/skills/specify/shaping-mode.md`, "Edit the body into spec shape", says "Rewrite the record's body into six sections, in this literal shape". Its fenced template holds Current State, Deliverables, Acceptance Criteria, Technical Approach (with `### Key Files`), and Gotchas. There is no `## Release Note`. The requirement appears only in prose after the fence, which a shaper copying the literal template never picks up.
- The compose-then-write-once call (`plugin/skills/specify/shaping-mode-stamping.md`) writes the body and stamps `ready` with no structural check. Decomposition mode already validates via `bin/compose-record.js --require-shaped` (`record-creation-subissues.md`); shaping mode never does.
- Two structural checkers exist and disagree on edge cases. The gate's own is `shapeGate` in `plugin/bin/lib/issues/materialize-format.js`: it locates a section with `sectionText`, i.e. `body.indexOf('## {name}')`, which a `### {name}` subheading also satisfies. The other is `validateShaped` in `plugin/bin/lib/compose-record/compose.js`, which uses `splitSections` on `## ` headings. A body can pass one and fail the other.

The requirement itself arrived on 2026-09-18 (#2580/#2581, merged as #2586). It updated the gate, `_shared/work-record.md`, and `spec-template.md`, but not shaping mode's literal template.

## Deliverables

1. Add `## Release Note` in every place shaping mode lists the body's sections, directly after `## Acceptance Criteria` (the placement `spec-template.md` uses). There are three such places:
   - `shaping-mode.md`'s literal template in "Edit the body into spec shape". Add a one-line authoring note pointing at `spec-template.md`'s Release Note guidance (one plain-language, verb-first line, no record numbers, no file paths), and update the lead-in's section count from six to seven.
   - `shaping-mode-stamping.md`'s "Compose-then-write-once" final-assembly-order fence.
   - `shaping-mode-stamping.md`'s "Read-back verification" assertion. Today it reads "The five spec-shaped sections (`## Current State`, `## Deliverables`, `## Acceptance Criteria`, `## Technical Approach`, `## Gotchas`) plus `## Original request`"; it becomes six, including `## Release Note`, so the post-write read-back also verifies the section survived the write.
2. **One structural implementation, the gate's.** `plugin/bin/lib/issues/materialize-format.js` keeps `shapeGate`'s verdict semantics exactly as they are. Two additive changes:
   - It exports a per-marker placeholder list (`PLACEHOLDER_PATTERNS`: one `{ marker, re }` entry for each of the three placeholder markers `_shared/work-record.md`'s spec-shaped-body definition names, each `re` being that marker's alternative from today's combined regex) and builds `PLACEHOLDER_RE` as their union, so the combined regex is unchanged.
   - `plugin/bin/lib/compose-record/compose.js` then imports `REQUIRED_SECTIONS` (stripped of its `## ` prefix, still exported under the same name for existing importers) and `PLACEHOLDER_PATTERNS` from it instead of declaring its own copies.

   `validateShaped` decides `ok` solely from `shapeGate(body).ok`. It builds its unchanged gap strings as follows:
   - `missing section: ## {name}` / `empty section: ## {name}` for each name in `shapeGate`'s `missing` list, telling the two apart with `sectionText` (`null` means missing, `''` means empty).
   - `unresolved placeholder marker: {marker}`, one per `PLACEHOLDER_PATTERNS` entry matching the same stripped authored text, only when `shapeGate` reports `unresolved-placeholder`.

   Intended behavior change for decomposition mode's `--require-shaped` callers: placeholder detection moves from substring matching (`String.prototype.includes`, which also matched a marker embedded inside a longer word) to the gate's word-bounded regex. Section location also moves to the gate's `sectionText`. That is the point: a body can no longer pass one checker and fail the other.
3. Add a `--check <body-file>` mode to `plugin/bin/compose-record.js`. It reads a body (not a payload), runs `validateShaped`, and exits 0 on pass or 4 on failure. On failure, stderr carries exactly the `--require-shaped` path's existing format: a `compose-record.js: body is not spec-shaped:` header line, then one `  - {gap}` line per gap. `--check` is mutually exclusive with a payload argument and `--out`; combining them is exit 2. Update the file's header comment and `USAGE` string.
4. In shaping mode, run `compose-record.js --check` on the fully composed body immediately before the compose-then-write-once call. On exit 4, write nothing and stamp no labels. Report the record as `failed` on its Actions Performed row, with the Detail cell reading `pre-write shape check failed:` plus the gap list. Extend `shaping-mode-stamping.md`'s definition of `failed` with this third cause, next to the write-call and read-back failures. In a batch, continue with the next record (shaping mode's existing per-record isolation). Under `--chained` the same `failed` row is the returned output; under bare drain it is that attempt's reported outcome. Neither is ever a silent skip.
5. Add a conformance test that reads `shaping-mode.md`'s literal template fence and `shaping-mode-stamping.md`'s assembly-order fence, and asserts each contains every heading in `materialize-format.js`'s `REQUIRED_SECTIONS`.

## Release Note

Fixed record shaping so every shaped record includes the Release Note section a build requires.

## Technical Approach

Origin: design decision on #2786 (2026-09-29), decomposed under parent #2826 with two siblings: #2828, the `/tidy` in-place repair (blocked by this record, because it calls the `--check` mode added here), and #2829, the dispatch pre-claim filter.

`shapeGate` is the gate. Everything else should agree with it by construction rather than by parallel maintenance. Delegating `validateShaped` to it (rather than the reverse) keeps `/flow`'s Materialization behavior byte-identical. `materialize-format.js` only gains exports (the per-marker list whose union is its existing regex), and `shapeGate`'s return value is unchanged for every input.

The `--check` mode belongs on `compose-record.js` rather than a new CLI: the exit-4 "shape validation failed, gaps on stderr" contract already exists there, and decomposition mode already calls that CLI.

### Key Files

- `plugin/skills/specify/shaping-mode.md` — add `## Release Note` to the literal template; update the section count.
- `plugin/skills/specify/shaping-mode-stamping.md` — insert the `--check` call before compose-then-write-once, with its `failed` path; add `## Release Note` to the assembly-order fence and the read-back assertion; extend the `failed` definition.
- `plugin/bin/compose-record.js` — add the `--check <body-file>` mode, header comment, and `USAGE`.
- `plugin/bin/lib/compose-record/compose.js` — `validateShaped` delegates to `shapeGate`; imports `REQUIRED_SECTIONS`/`PLACEHOLDER_PATTERNS` instead of declaring them.
- `plugin/bin/lib/issues/materialize-format.js` — additive export of `PLACEHOLDER_PATTERNS`, with `PLACEHOLDER_RE` built as their union; `shapeGate`/`sectionText` semantics unchanged.
- `tests/bin-lib/compose-record/cli.test.js` — `--check` pass, fail (exact stderr), and misuse cases.
- `tests/bin-lib/compose-record/compose.test.js` — `###`-subheading parity case and per-marker placeholder naming.
- `tests/bin-lib/issues/materialize-format.test.js` — must pass unchanged.
- `tests/specify-shaping-template-required-sections.test.js` — new conformance test covering both fences.

## Gotchas

- Don't change `shapeGate`'s own section-location semantics here. The gate stays as it is; only `validateShaped` moves onto it. Tightening `sectionText` to line-anchored `## ` headings would change `/flow`'s gate behavior and belongs in a separate record.
- Conformance tests pin skill prose repo-wide. Run the full `npm test` before merging, not only the compose-record suites, because a prose edit to `shaping-mode.md` can trip an unrelated pin.
- Never write the literal placeholder tokens in authored prose of the new template note (paraphrase as "unresolved marker"). The shaped-body checks scan for them.
- `validateShaped`'s gap strings, and `--require-shaped`'s header-plus-indent stderr format, are consumed by `record-creation-subissues.md` callers and now by #2828's `/tidy` repair, which matches on the exact `missing section: ## Release Note` / `empty section: ## Release Note` text. Keep them byte-identical.
- Red-team (2026-09-29, Implementer+Maintainer+Skeptical Reviewer) found that `shapeGate` reports placeholders as one undifferentiated flag. Hence the additive per-marker export in Deliverable 2, rather than keeping a second placeholder implementation in `compose.js`.
