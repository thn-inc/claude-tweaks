# 2828: tidy: repair a ready record whose only spec-shape gap is a missing Release Note, in place, grants kept

Surface: infra

## Current State

On 2026-09-29, 110 of the 126 open `ready` records in this repo had no `## Release Note`, including 17 with `auto:build`. `/flow`'s Materialization hard gate (`plugin/bin/lib/issues/materialize-format.js`'s `shapeGate`) rejects every one of them, which leaves `/dispatch` no buildable candidate. The cause was `/specify` shaping mode's literal template omitting the section; #2827 fixes that producer. The defect shipped to every consumer project, so their backlogs carry the same records.

- `/backlog refine` Step 3.5 (`plugin/skills/backlog/refine-mode.md`) flags back any body that fails the spec-shaped check, removing `ready` with a comment. The next refine run, human-present or inside `/sweep`, would un-ready every affected record.
- `plugin/skills/tidy/step-1-records.md` audits open records by shape. Shape 4 ("ready record missing scoring") is a report-only sibling, and its auto-mode row is in `plugin/skills/tidy/step-6-auto.md`. No shape detects or repairs a `ready` record whose body fails the spec-shaped check.
- `/sweep` runs `/tidy` before `/backlog refine`, so a tidy repair lands before refine's flag-back can fire.

Decision (#2786, 2026-09-29): adding a one-line Release Note derived from the record's own title and Deliverables is **scope-neutral**. It changes nothing a grant was approved on, so the repair keeps every label: `ready`, `auto:build`, `auto:merge`, and every `risk:*`/`size:*`/`ceremony:*`/`type:*`/`priority:*`. Rejected alternatives: relaxing the gate (merge-time `compose-subject.js` needs the same section for the `Release-Note:` trailer); a full re-shape via `/specify` (costly, and it can change approved labels); making refine repair instead of flagging back (repair would happen only when a grant gate runs, and a grant gate would end up writing record bodies).

## Deliverables

1. **Shape 4.5 — `ready` record missing only its Release Note**, tag `[release-note]`, in `step-1-records.md` right after Shape 4. It uses the fractional-numbering convention Shapes 5.5/5.6 already follow, so Shapes 5-8 keep the numbers other files cite. Detection uses #2827's contract: write the body to a session tmp file and run `node "${CLAUDE_PLUGIN_ROOT}/bin/compose-record.js" --check {file}`. Exit 0 is conforming, so the shape does not match. Exit 4 prints stderr as a `compose-record.js: body is not spec-shaped:` header plus one `  - {gap}` line per gap; the shape matches only when there is exactly one gap line and it reads `missing section: ## Release Note` or `empty section: ## Release Note`. Any other exit code (2, 5, or a spawn failure) is reported as a scan error for that record and never treated as a match. Any other gap, alone or in addition, does not match; refine's existing flag-back owns those records. Applies under both `work-backend` drivers.
2. **Composition, agent-authored and bounded.** The line is an agent-written sentence, not a template fill:
   - **Content:** one sentence, verb-first, summarizing the record's `## Deliverables` in terms of what a release-notes reader would notice. When the Deliverables have no user-visible effect, write a plain "no user-visible change" phrasing of what improved, per `spec-template.md`'s own example ("Improved internal test coverage for the release composer").
   - **Bounds, all mechanically checked before writing (AC 4):**
     - a single line;
     - no `#\d+` token;
     - no path-shaped token (a `/` plus a file extension);
     - no backtick code span;
     - no conventional-commit prefix (`^[a-z]+(\(.+\))?!?:`).
   - **Failed bounds:** recompose once. If the second attempt also fails a bound, report a repair failure (Deliverable 3), never a weaker line.
3. **The write.**
   - Re-read the record's live body immediately before writing, per `_shared/reverify-before-write.md`. If it no longer matches Shape 4.5 (edited, re-shaped, or closed since the scan), skip it and report it as skipped.
   - Insert `## Release Note` plus the line immediately after the `## Acceptance Criteria` section (before the next `## ` heading), or fill an empty section in place. Leave every other byte of the body unchanged.
   - Re-run `--check` on the repaired body. Anything but exit 0 means no write: report a repair failure, with the record left exactly as it was (still `ready`, still failing the gate) and no label touched. It stays visible to refine's flag-back and to #2829's dispatch filter.
   - Otherwise write via `gh issue edit {n} --body-file` (github-issues) or `writeRecord` (local-files), change no label, and invalidate the session record snapshot after the batch.
4. **Tier: auto-apply with an undo snapshot** (user decision, 2026-09-29, after red-team). Add a `step-6-auto.md` row: Stage at `conservative`, Auto-apply at `moderate` (the default) and `aggressive`.
   - **The row states its own reversibility exemption.** `step-6-auto.md` otherwise stages outward GitHub body writes under the auto-mode contract's reversibility floor (the Open parent gate precedent). This repair qualifies for Auto because it is additive: exactly one section inserted, verified by the post-write diff.
   - **Undo snapshot.** It is undoable because the pre-write body is snapshotted first: to `{run-dir}/staged/tidy-release-note-{n}.original.md` when a run directory resolves (`_shared/pipeline-run-dir.md`), otherwise into tidy's report as a collapsed original-body block per repaired record.
   - **Audit trail.** When a run directory resolves, log one `AUTO` entry per repaired record per `_shared/auto-decision-log.md`, naming the snapshot path. The tidy report always lists every repaired record with its composed line, whether or not a run directory resolved, so an ad hoc run is never unaudited.
   - **Registration.** Register the shape and its `[release-note]` tag in `plugin/skills/tidy/SKILL.md`'s shape roster and in `plugin/skills/tidy/collection-routing.md`'s tag routing.
5. After merge, run `/claude-tweaks:tidy` against this repository so the backlog is repaired before the next `/backlog refine` or `/sweep` run. Record the run's repaired-record list on this issue.

## Acceptance Criteria

- [ ] A fixture body missing only `## Release Note` matches Shape 4.5. A fixture missing both `## Release Note` and `## Acceptance Criteria` does not. A fixture with an empty `## Release Note` matches. A conforming fixture does not. A `--check` exit other than 0/4 is reported as a scan error, not a match.
- [ ] After repair, the body passes `node plugin/bin/compose-record.js --check`, and a line diff against the original body shows only the inserted (or filled) Release Note section.
- [ ] The repaired record's label set is identical before and after.
- [ ] The composed line passes every Deliverable 2 bound: single line, no `#\d+`, no path-shaped token, no backtick span, no conventional-commit prefix. A line failing any bound twice produces a repair failure and no write.
- [ ] `step-6-auto.md` carries Shape 4.5's row (Stage / Auto-apply / Auto-apply), including its stated reversibility exemption. `SKILL.md` and `collection-routing.md` register `[release-note]`.
- [ ] Every auto-applied repair has a pre-write snapshot: the `staged/tidy-release-note-{n}.original.md` file when a run directory resolves, otherwise an original-body block in the tidy report. The tidy report names each repaired record and its line in both cases.
- [ ] A record edited between scan and write (fixture: live body changed after the scan) is skipped, not overwritten.
- [ ] After the post-merge run on this repo, a scan over all open `ready` records finds zero whose `--check` gaps are exactly the Release Note one, and the run's repaired list is posted on this issue.

## Release Note

Added an automatic repair that fills in a missing Release Note on ready records so they can be built again.

## Technical Approach

Origin: design decision on #2786 (2026-09-29). Parent #2826. Blocked by #2827, which adds `compose-record.js --check` and makes `validateShaped` delegate to the gate's `shapeGate`. This record uses that CLI rather than a copy of the section list, so tidy's verdict and `/flow`'s gate can never disagree.

The "exactly one gap" rule is the scope boundary. Only a missing Release Note is scope-neutral. A missing Current State or Acceptance Criteria needs real shaping judgment, which is `/specify`'s job, reached through refine's flag-back.

## Gotchas

- Run the backlog repair (Deliverable 5) promptly after merge. Every `/backlog refine` or `/sweep` run before it un-readies unrepaired records, and each un-readied record then needs `/claude-tweaks:specify` plus a human re-grant.
- `step-1-records.md` is 32,280 bytes against the 45 KB advisory `CEILING_BYTES` (`plugin/bin/lib/skill-audit/context-cost.js`), so there is about 13 KB of headroom. Re-measure with `wc -c` before adding the shape, keep the procedure tight, and cite `spec-template.md` rather than restating its rules.
- Consumer projects heal the same way: their next `/claude-tweaks:tidy` (or `/sweep`) run after upgrading repairs their Release-Note-only records. Deliverable 5's explicit run is this repo's own, not the only remediation path.
- Red-team (2026-09-29, Implementer+Skeptical Reviewer) flagged that auto-applying an outward body write departs from `step-6-auto.md`'s staging precedent. The user chose auto-apply with an undo snapshot. Staging would have let `/sweep`'s refine flag records back before anyone approved.
- `#2573` lost its `auto:merge` grant to a Materialization failure on this defect. This repair does not restore grants; a human re-issues it via `/claude-tweaks:backlog refine`.
- Retry counters are not reset by the repair (#2663 sits at 2 of 3 attempts).
- Run the full `npm test` before merging, because tidy skill prose is pinned by conformance tests.
