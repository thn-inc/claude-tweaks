# 4168: Apply reflect observation and convention findings at the Review Console instead of leaving them in Pending review

Origin: build split from #3946 (Deliverable 3 split clause)

Defer-reason: genuinely-larger

## Current State

Reflect stages `convention` and `observation` findings to `staged/reflect-{n}.md` (`plugin/skills/reflect/SKILL.md` Step 3). `classifyStagedItem` (`plugin/bin/lib/console/resolve.js`) reroutes any such file whose `**Category:**` is not `tangential` to Pending review with reason `non-tangential-category:{category}` (#2473), where nothing processes it, so every one stays `pending` and blocks archive (149 reflect items in the 2026-10-22 residue count).

#3946 was to route `observation`/`convention` items to the Skill-updates section. Its build found the Skill-updates consumer cannot apply them: `review-console.md` "On approval" step 2 applies Skills-curation proposals (`staged/wrap-up-skill-{N}.md` carrying an Update Mode patch, `skill-curation.md` 7.6), while a reflect file carries only `## Finding` and an optional `## Suggested resolution`, naming no target skill and no destination. No "On approval" step is mechanized (`console-resolve.js` computes resolutions, never executes them), and step 10 (Reflection insights), the nearest precedent, is prose. Per #3946 Deliverable 3's split clause, this record carries that consumer and the reroute behind it.

## Deliverables

- [ ] A destination line in reflect's `observation`/`convention` stage-file format (one of: edit a named skill or CLAUDE.md now, create a backlog record with a `Defer-reason:`, or record a decline), written by `plugin/skills/reflect/SKILL.md` Step 3.
- [ ] An applier CLI under `plugin/bin/` that carries a `reflect-{n}.md` file to its destination through injectable deps: the record write (gh and MCP transports, after `refused-proposals.md`'s Defer-reason check) and the decline write (`recordDecline`); an edit destination stays a prose step the console session performs.
- [ ] A new or extended "On approval" step in `plugin/skills/wrap-up/review-console.md` plus its `review-console-appendix.md` Resolution-to-step mapping row, and the console-template, interactive and multi-spec render sites (walk `.claude/skills/review-console-section-addition`'s registration table).
- [ ] `classifyStagedItem`: reflect `observation`/`convention` files route to Skill updates (stance `approve`) instead of Pending review; other non-tangential categories keep today's reroute.
- [ ] A rule for legacy reflect files that carry no destination line (the existing residue), consumed by #3950's backlog settle.

## Acceptance Criteria

1. A reflect staged file with `**Category:** observation` and one with `**Category:** convention` no longer classify to Pending review / `pending`; they resolve through the Skill-updates stance (`approve`); a `**Category:** tangential` file still classifies as Queue writes, and a file with no `**Category:**` line classifies exactly as before.
2. In a console-auto fixture holding one reflect observation and one reflect convention (each with a destination line), the consumer applies each to its destination and the run ends with zero `pending` items; the test asserts the applied effect (the record write or the decline write through the injected deps), not only the absence of `pending`.
3. A legacy reflect file with no destination line reaches a final outcome under the stated rule, with a test.
4. `npm test` passes.
