# 1892: bin/lib/reconcile archive-merged.js: split-state run dir makes archival fail with ENOTEMPTY forever and re-files the residue record

Surface: infra

## Current State

`bin/lib/reconcile/archive-merged.js`'s `archiveRunDir` no longer renames a run directory whole — #1713/#1714 made the gitignored half move entry-by-entry and the per-spec loop skip whole `spec-{n}/` renames, and `tests/bin-lib/reconcile/archive-merged.test.js` pins the `ENOTEMPTY` case. The split state this record describes still wedges, one level down. Live evidence at 2026-09-09: `.claude-tweaks/pipelines/2026-08-29T153740-spec-1296-1336/` holds only the two git-tracked headers `spec-1296/work/1296-spec.md` and `spec-1336/work/1336-spec.md`; its archive twin already holds `config.yml`, `decisions.md`, `events.jsonl`, `manifest.yml`, `run-state.json`, `staged/`, and `spec-1296/`/`spec-1336/` subtrees. `reconcile --json` reports the directory `move-failed` on every pass, and `.claude-tweaks/reconcile-cache.json`'s `residueFailures` entry for it reads `ENOTEMPTY: directory not empty, rename '…/spec-1296-1336/spec-12…'` with a count of 58 — the per-spec loop's move of `spec-{n}/work` onto a twin that already has a `work/`. The tracked headers can only leave the live path through a `git mv` plus commit, which under `worktree-always: true` is a gated write from the main checkout and lands only via a worktree PR; nothing in the sweep recognizes "archive twin complete, live path holds only tracked `work/` headers" as a distinct state.

The residue bookkeeping compounds it. `residueFailures` still carries sixteen `move-failed` entries, all `escalated: true`, for paths that no longer exist live — `2026-08-31T182808-record-1679`, `2026-08-26T054601-record-1214`, `2026-08-26T055917-record-1219` (archived, zero tracked files) among them — because `recordResidueSuccess` fires only when this sweep itself archives the directory, never when a PR or a human moves it. Escalation dedups against open records only, so once a per-path record closes (the four open instances today are #1889, #1741, #1716, #1715; #1713/#1714 already closed the same way) a later pass with a stale cache entry files a fresh one for the same path.

## Deliverables

- Make the tracked-header move idempotent against an existing archive twin: when `spec-{n}/work` (or a top-level `work/`) already exists under the archive directory, compare each tracked file's blob with the twin's copy — identical → `git rm --cached`-free path: `git mv` is unnecessary, remove the live copy through git so history stays intact (`git mv` onto the twin path when the twin copy is untracked, `git rm` when the twin already tracks it); different → return a new reason `work-twin-conflict` naming both paths, never a generic `move-failed`.
- Detect the split state before any move: archive twin exists AND `git ls-files <runDir>` lists only `work/` headers AND no gitignored entries remain → classify as `archived-pending-tracked-move` (a skip reason with its own row in `docs/reconcile-checks.md`), and under `worktree-always: true` emit the paste-ready worktree/PR command that completes the move instead of counting toward `move-failed` escalation.
- Prune `residueFailures`: on every pass, drop any `move-failed`/`structurally-stuck` entry whose live path no longer exists, and when the entry was escalated, post one resolution comment on the open record (found by the existing fingerprint marker) and close it — the path resolved by other means.
- Dedup escalation against all states: `escalateResidue` searches the marker across open **and closed** records and, on a closed match whose path is still live, comments on the closed record and reopens it rather than filing a new one.
- Close #1741 (this split-state instance) when its directory archives, and close #1889/#1716/#1715 as resolved-by-other-means once the prune lands.

## Acceptance Criteria

- A fixture run directory whose archive twin already contains `spec-1/work/1-spec.md` with identical content and whose live path holds only that tracked header archives cleanly on one pass; a differing twin copy returns `work-twin-conflict` and moves nothing — both pinned in `tests/bin-lib/reconcile/archive-merged.test.js`.
- The split-state fixture under `worktree-always: true` reports `archived-pending-tracked-move` with the completing command in `skipped[]`, and its `residueFailures` count does not increment.
- `tests/bin-lib/reconcile/cache.test.js` pins that a `residueFailures` entry whose path is absent on disk is pruned and, when escalated, triggers exactly one close call on the marker-matched record.
- `tests/bin-lib/reconcile/escalate-residue.test.js` pins that a closed marker-matched record is reopened and commented, not duplicated.
- On this checkout, `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" reconcile --json` reports no `move-failed` entry for `2026-08-29T153740-spec-1296-1336` after the tracked headers land in `archive/` via a PR, and `reconcile-cache.json` holds no `move-failed` entry for a non-existent path.
- `npm test` passes.

## Technical Approach

Keep the moves-first, close-last invariant and the `revertPlainMoves` rollback. Add the twin comparison in the `workMoves` assembly (before the per-spec loop) using `git hash-object` on both copies; the split-state predicate reads `fs.readdirSync(runDir)` minus tracked paths and the twin's existence, and sits beside `isOrphanedMint`. For pruning, iterate `residueFailures` keys in `cache.js` after `archiveMerged` returns, `fs.existsSync` each path, and delegate the record close to `escalate-residue.js`'s runner seam so tests inject it. For dedup, extend the marker lookup to `--state all` (the same `findByMarker` idiom `_shared/headless-self-report.md` uses) and add the reopen branch. Document the two new reasons and the prune step in `docs/reconcile-checks.md`.

### Key Files

- `plugin/bin/lib/reconcile/archive-merged.js` — `archiveRunDir`'s `workMoves` twin comparison, per-spec loop, new `archived-pending-tracked-move` and `work-twin-conflict` reasons
- `plugin/bin/lib/reconcile/cache.js` — `residueFailures` prune after each pass
- `plugin/bin/lib/reconcile/escalate-residue.js` — all-state marker dedup, reopen branch, resolution comment + close
- `tests/bin-lib/reconcile/archive-merged.test.js` — twin-identical, twin-conflict, split-state cases
- `tests/bin-lib/reconcile/cache.test.js` — prune + close-once case
- `tests/bin-lib/reconcile/escalate-residue.test.js` — reopen-not-duplicate case
- `docs/reconcile-checks.md` — reason vocabulary and prune step

## Gotchas

- `revertPlainMoves` must be able to undo a partial twin merge; a `git rm` of a live tracked copy is not a plain move — do it last, after every gitignored entry has moved, so a failure before it leaves history untouched.
- Reconcile runs in-process, so its `git mv`/`git rm` are not gated by the PreToolUse hook — but the resulting commit still needs to land on `main` via the sweep's own commit path, and under `pr-first` the main checkout may lag origin (the record's step 5); read `mirror.state` before deciding the split state is stale.
- The `structurally-stuck` prune interacts with #1811 (consolidated escalation for that reason); keep the prune reason-agnostic so both classes benefit without duplicating logic.
- Reopening a closed record is an outward write reconcile already performs (filing), but it is more visible; comment first, reopen second, so a failed reopen leaves an explanatory comment.

## Original request

bin/lib/reconcile archive-merged.js: split-state run dir makes archival fail with ENOTEMPTY forever and re-files the residue record

**Summary:** `archive-merged.js`'s `fs.renameSync(dir, archiveDir)` is not idempotent for a run directory whose gitignored half was already archived while its git-tracked `spec-*/work/*-spec.md` headers stayed under the live path — every later reconcile pass fails with `ENOTEMPTY`, and the auto-filed residue record is re-filed after the first one closes.

**Kind:** Defect

**Affected component:** `bin/lib/reconcile` — `archive-merged.js` (the `archive` check), plus the `move-failed` auto-file path in `bin/lib/reconcile`

**Repro steps:**
1. Finish a multi-spec `/flow` run whose per-spec `spec-{n}/work/{n}-spec.md` headers are committed (the normal `flow/materialize.md` audit-trail rule).
2. Let an archival pass move the run dir's gitignored half (`config.yml`, `decisions.md`, `events.jsonl`, `manifest.yml`, `staged/`, `spec-*/` scratch) into `.claude-tweaks/pipelines/archive/{run-id}/`, but leave the tracked headers in place under the live path — this is what happens under `worktree-always: true`, where a `git mv` from the main checkout is a gated write and the tracked half can only move through a worktree PR.
3. Run `node bin/hooks.js reconcile --json` repeatedly.
4. Observe `runs[]` reporting `reason: move-failed` with `ENOTEMPTY: directory not empty, rename '.../pipelines/{run-id}' -> '.../pipelines/archive/{run-id}'` on every pass; after 3 passes reconcile auto-files a `move-failed` record.
5. Close that record via a PR that `git mv`s the four headers into the archive path. If the main checkout has not yet fast-forwarded to that merge (its local integration branch still tracks the headers under the live path), the next passes hit the same `ENOTEMPTY` and reconcile files a second record for the same path (observed as two consecutive records in a private project).

**Expected vs. actual:**
Expected: the archive check merges into an existing archive directory — move the remaining entries individually, or detect the split state (archive dir exists AND the live dir holds only git-tracked `work/` headers) and either complete the tracked half through a worktree/PR or classify the dir as "archived pending checkout catch-up" instead of `move-failed`. A live dir left with only tracked headers should not re-trigger the auto-file after its record has already been closed by a merged PR.
Actual: permanent `move-failed` + `ENOTEMPTY` on every pass, and a duplicate auto-filed record once the first one closes.

**Related (not duplicates):** the open per-path `reconcile: move-failed stuck on …` records (#1889, #1741, #1716, #1715) are instances this defect can keep producing; #1613 covered the skip vocabulary for non-move-failed dirs, not this rename path.

**Definition:** Clear — the ask is a single behavior (merge-into-existing-archive / split-state detection), not an open design choice.
