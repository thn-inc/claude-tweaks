# 2801: Evaluate the Haiku+Opus "Advisor Pattern" for cost/quality

Surface: infra

## Current State

A named "Advisor Pattern" (a cheap/fast model executes, a stronger model advises/reviews) is reported externally to beat a mid-tier model alone at lower cost. claude-tweaks currently has no documented practice of this shape — model selection today is either a single model for the whole task, or the existing Subagent Contract's static Fast/Standard/Capable profile per dispatch, not a two-model advise/execute split within one task.

## Deliverables

Evaluate the Advisor Pattern against one representative claude-tweaks task (a build, a review, or a similarly-scoped unit of work) by running it once under the pattern (a fast/cheap model executing, a stronger model reviewing/advising) and once under the current default approach for the same task, then compare cost and output quality between the two runs.

## Acceptance Criteria

- One sample task is run both ways (Advisor Pattern vs. current default), with actual token/cost figures and a quality comparison (not just cost) reported for both.
- A recommendation is recorded: adopt the pattern for some class of claude-tweaks work (naming which), or don't, with the comparison data as the stated justification either way.
- If adopted, the recommendation states specifically which of claude-tweaks' own workflows (build, review, dispatch, etc.) it would apply to — not a blanket claim it should replace all current model selection.

## Release Note

No user-visible change: measured whether pairing a fast executing model with a stronger advising model improves cost and quality.

## Technical Approach

Pick one bounded, representative task (small enough to run twice affordably, substantial enough that quality differences would actually show) and execute it under both configurations, capturing real cost and quality data from each run rather than estimating. Compare against the Subagent Contract's existing static Fast/Standard/Capable guidance to determine whether the Advisor Pattern is complementary (a specific dispatch shape within that existing framework) or a genuinely separate mechanism.

### Key Files

- `plugin/skills/_shared/subagent-output-contract.md` — the existing model-selection guidance to compare the pattern against

## Gotchas

- A single sample task's comparison is a screening signal, not a proof — state the recommendation's confidence level accordingly rather than over-generalizing from one data point.
- Cost and quality can trade off in either direction depending on task shape — don't assume the externally-reported result (Advisor Pattern beats mid-tier alone) transfers unchanged to claude-tweaks' own task shapes without actually measuring it here, which is exactly what this record's Deliverable requires.
