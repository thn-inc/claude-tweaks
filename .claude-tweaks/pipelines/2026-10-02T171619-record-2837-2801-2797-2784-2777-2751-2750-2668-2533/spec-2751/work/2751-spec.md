# 2751: Add per-agent identity and scoped-credential hardening checks

Surface: infra

## Current State

`plugin/skills/_shared/criteria-security-hardening.md` and its generator, `plugin/bin/lib/code-health/candidates-security-hardening.js`, currently detect exactly three candidate kinds — `client-secret`, `missing-ownership-check`, `unguarded-ai-endpoint` (that file's own "Scope boundary" section names the vertical's exact three-check ownership, #2624). None of the three check for agent/tool identity separation, scoped-vs-broad tool permissions, or credential lifetime — the class of risk the filed source (an article framing prompt injection as an authorization failure, not a detection problem) argues for: assume injection succeeds, and limit what a compromised agent call can actually reach. claude-tweaks' own subagent dispatch (`plugin/skills/_shared/subagent-output-contract.md`) has no documented per-agent identity or credential-scoping check today.

## Deliverables

- A fourth candidate kind for the security-hardening generator (`candidates-security-hardening.js`) and a matching criteria section in `criteria-security-hardening.md`, following that file's existing per-check format (What to flag / What NOT to flag / a copy-paste prompt), covering: agents/tools sharing one broad-access identity or token instead of distinct, scoped identities; and delegation chains (one agent calling another, or a tool call) with no audit-log/trace of who delegated to whom.
- A one-time, hand-run application of the new check against claude-tweaks' own dispatch model (`_shared/subagent-output-contract.md`, `bin/hooks.js`'s dispatch-adjacent code) reported as a pass/fail per mitigation in this record's own PR description or a follow-up comment — this is a self-audit exercise, not a generator capability, since the generator's own scope (per its file header) is scanning *other* AI-built apps' source, not this plugin's own architecture.

## Acceptance Criteria

- `criteria-security-hardening.md` documents the new candidate kind in the same structural shape as the existing three (What to flag / What NOT to flag / one copy-paste prompt), and `candidates-security-hardening.js` emits it for a recognizable pattern (a shared/hardcoded credential or token reused across multiple call sites with no per-caller scoping, or a delegation call with no accompanying log/trace statement).
- Running `/claude-tweaks:code-health --focus=security-hardening` (or the equivalent focus-mode invocation) against a fixture containing the new pattern produces at least one finding of the new kind.
- The dispatch self-audit (Deliverable 2) is written up as a pass/fail per mitigation (identity separation, scoped permissions, credential lifetime, delegation audit) against claude-tweaks' actual subagent contract — not asserted without the write-up.

## Release Note

Added security checks for per-agent identity and narrowly scoped credentials.

## Technical Approach

Extend `candidates-security-hardening.js` with a fourth `kind` following the same generator shape the existing three use (a `{ file, kind, evidence }` candidate, a text-pattern detector, not a semantic/AST analysis — per the file's own "starting pointer, not a finding" framing). Detection signal: a credential/token variable name or literal reused verbatim across two or more distinct call sites that look like separate callers/agents (heuristic, approximate — the criteria doc's own "What NOT to flag" convention applies: false positives get filtered at judgment time, not generation time). Add the matching `## What to flag` / `## What NOT to flag` / copy-paste-prompt entries to `criteria-security-hardening.md`, keyed to this new kind, mirroring the three existing entries' structure exactly. The self-audit deliverable is separate from the generator change — it's a one-time manual application of the new criteria against this repo's own dispatch contract, reported in prose, not a new automated check running against claude-tweaks itself (the generator's stated scope is external AI-built apps, per its own header — extending it to self-scan is out of scope for this record).

### Key Files

- `plugin/bin/lib/code-health/candidates-security-hardening.js` — add the fourth candidate kind's detection logic
- `plugin/skills/_shared/criteria-security-hardening.md` — add the matching criteria section (What to flag / What NOT to flag / copy-paste prompt)
- `plugin/skills/_shared/subagent-output-contract.md` — read (not edited) as the audit target for the self-audit deliverable

**Related:** #2749 (autonomous-agent blast-radius hardening check — same security-hardening vertical, adjacent but distinct mitigation: blast-radius/scope limiting vs. this record's identity/credential-lifetime focus)

## Gotchas

- The record's two Acceptance Criteria pull in different directions: AC 1 (a generator check for *any* scanned codebase) is the vertical's normal shape; AC 2 (apply it to dispatch's own credential model) is a one-time self-audit, not a capability the generator itself gains. Treat them as two separate deliverables, not one mechanism doing both — conflating them risks either under-scoping the generator change or over-scoping it into a self-monitoring feature nobody asked for.
- Detecting "shared identity" or "delegation with no audit log" from static text alone is inherently heuristic — the existing three checks already accept this tradeoff (`missing-ownership-check` and `unguarded-ai-endpoint`'s own "What NOT to flag" sections exist for exactly this reason); expect meaningful false-positive tuning after the first real-world run, not a one-shot precise detector.
- claude-tweaks' own subagent dispatch may turn out to already satisfy some mitigations informally (e.g. `CLAUDE_CODE_SESSION_ID` scoping) — the self-audit should report what's actually true, not assume every mitigation is missing just because no formal check existed before this record.

## Original request

Add per-agent identity and scoped-credential hardening checks

- Proposes four concrete mitigations: distinct identity per agent, per-tool scoped permissions, short-lived on-demand credentials, and audit logs of delegation chains.
- claude-tweaks' current hardening guidance doesn't yet check for per-agent identity separation or credential lifetime.
Deliverables:
- A hardening checklist item (in /security-review or a new lens) verifying agents/tools use distinct identities, scoped permissions, and short-lived credentials rather than shared broad-access tokens.
- A delegation-chain audit-log requirement for any skill that lets one agent call another.
Acceptance Criteria:
- The checklist runs as part of /security-review.
- Applying it to dispatch's own agent-to-tool credential model reports pass/fail per mitigation.
