# 3536: Harden exit-code-conformance's comment stripper and share one literal-aware stripper across the source scans

Origin: reflect hindsight from #3464

Defer-reason: tangential

## Current State

`tests/bin-lib/exit-code-conformance.test.js:55` strips comments with the two-pass `src.replace(/\/\*[\s\S]*?\*\//g, '').replace(/\/\/[^\n]*/g, '')`. #3464 found and fixed exactly this defect in two other `plugin/bin` source scans (`tests/git-status-optional-locks.test.js`, `tests/windows-hide-spawn-conformance.test.js`): a `/*` inside a string literal or a `//` comment, or a `//` inside a string or regex, deletes real code. In the windows-hide scan the blind spot was hiding 4 real `windowsHide` violations.

Run against today's `plugin/bin`, the exit-code stripper over-strips 35 files (25,621 non-whitespace characters of `plugin/bin/hooks.js` alone). A probe that compared its verdicts with the literal-aware stripper's found that every file's `guardRegionFor` / `process.exit(` result is identical today. The defect is latent: a future `process.exit()` placed in an over-stripped region would pass unflagged, and a guard that gets blanked is skipped silently (`if (guard === null) continue;`, line 115).

The literal-aware stripper now exists as two byte-identical copies, at `tests/git-status-optional-locks.test.js:43` and `tests/windows-hide-spawn-conformance.test.js:43`.

## Deliverables

- Replace `tests/bin-lib/exit-code-conformance.test.js`'s `stripComments` with the literal-aware, `(?<!\\)`-guarded stripper #3464 shipped. Comments are blanked, not deleted, so line numbers stay stable.

- Move that stripper into one shared test helper that all three scans require, so a fourth copy cannot drift. Check `tests/path-guard-conformance.test.js`'s token-based stripper too, and fold it in if it is equivalent.

- Add a go-red self-test to the exit-code scan: a guard containing `process.exit(` that sits after a string holding `/*` must still be flagged.

## Acceptance Criteria

- `grep -rn "replace(/\\/\\*\[\\s\\S\]\*?\\*\\//g, '')" tests/` returns nothing.

- The new self-test fails against the old two-pass stripper and passes against the shared one.

- `npm test` passes in full, and the exit-code scan reports the same violations (none) as before.

Internal test hardening — no user-visible change.
