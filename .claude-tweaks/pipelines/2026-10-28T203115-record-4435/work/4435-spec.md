# 4435: checkResumeFreshness reads an unreadable worktree path as worktree-gone, so an interrupted run resumes

Origin: review (#4420, lens 3b, low-confidence), approved at PR #4425's Review Console

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/bin/lib/hooks/resume-freshness.js`'s `checkResumeFreshness` maps `fs.existsSync(worktree) === false` to `{ safe: true, verdict: 'worktree-gone' }`. `existsSync` also returns false on `EACCES`, `ELOOP` or `EIO`. So for an `interrupted` run, a recorded worktree path the probe cannot look at reads as gone, and the resume goes ahead.

The other resume caller, `plugin/bin/lib/flow/consolidated-pass.js`'s `parentLiveDetail`, gates the same case on path-guard's `lstatType(worktree).type === 'missing'`. That is true only for a clean `ENOENT`, so the two callers disagree on an unreadable path. #4420 left the line unchanged, because its spec kept the five pre-probe returns in their existing order.

## Deliverables

- [ ] `checkResumeFreshness` returns `worktree-gone` only when path-guard's `lstatType(worktree).type === 'missing'`. Any other unreadable result falls through to `runLiveness`, whose `error` entry `blocksResume` reads as `indeterminate`.
- [ ] The verdict-string set and the order of the five pre-probe returns stay unchanged.
- [ ] One equivalence row in the PR body: an unreadable worktree path of an `interrupted` run moves from `worktree-gone` (resume) to `indeterminate` (block).

## Acceptance Criteria

1. An `interrupted` run whose recorded worktree path is a symlink loop (`ELOOP`) gets verdict `indeterminate`, not `worktree-gone`. The test is red on the current code.
2. An `interrupted` run whose recorded worktree path does not exist still gets `worktree-gone`.
3. `tests/path-guard-conformance.test.js`'s allowlist entry for `lib/hooks/resume-freshness.js` (`existsSync: 1`) is removed, and the suite passes.
4. `npm test` passes.

## Release Note

Resuming an interrupted pipeline run no longer treats a worktree path it cannot read as deleted, so it waits instead of resuming over a possibly live run.

## Technical Approach

### Key Files

- `plugin/bin/lib/hooks/resume-freshness.js` — gate `worktree-gone` on `lstatType`
- `tests/hooks-resume-freshness.test.js` — unreadable-path and missing-path rows
