# 3766: Digest dedup trusts a materiality-fingerprint marker from any commenter

Verified-as-of: a7b41a727d09cac4d42b594b7c45fabc42aa70eb

Origin: Review Console residue audit 2026-10-20 — unconfirmed lens 3b finding from run 2026-10-17 spec-3358, bulk-acknowledged unread

## Current State

`isMaterialityDuplicate(existingTexts, entry)` (`plugin/bin/lib/health-core/materiality-digest.js:69`) collects every `<!-- materiality-fingerprint: … -->` marker from every text it is given, via `parseMaterialityFingerprints` (`:47`). `_shared/materiality-floor.md`'s Dedup section tells the routing skill to pass "every comment on the open digest issue", and `tidy/digest-sweep.md` does the same. Neither layer filters by author association, unlike the run-comment marker readers #3358 hardened through `plugin/bin/lib/issues/comment-trust.js`.

Anyone who can comment on the digest issue can therefore plant a fingerprint marker and suppress a below-floor finding: it is never appended and never counted toward the cluster-promotion threshold (≥3 entries per area). Checked on origin/main a7b41a727: no trust filter in the module, and the contract text passes raw comment bodies.

## Deliverables

- [ ] Dedup reads fingerprints only from comments whose author association is trusted, reusing `comment-trust.js`'s existing trust predicate rather than a new allowlist.
- [ ] The caller contract in `_shared/materiality-floor.md` (Dedup) and `tidy/digest-sweep.md` passes comment objects (body + `authorAssociation`), or the trusted subset, rather than raw bodies.
- [ ] Tests: an untrusted-author comment carrying a matching fingerprint does not mark the candidate a duplicate; the same marker in a trusted comment still does.

## Acceptance Criteria

- [ ] A candidate whose only matching fingerprint sits in a comment from an untrusted association (e.g. `NONE`, `CONTRIBUTOR`) is routed as new, not skipped as a duplicate.
- [ ] A matching fingerprint in an `OWNER`/`MEMBER`/`COLLABORATOR` comment still dedups exactly as today.
- [ ] The untrusted-marker test goes red when the trust filter is removed.

## Release Note

Health-sweep digests can no longer be made to skip a finding by someone posting a fake dedup marker in an issue comment.

## Technical Approach

### Key Files

- `plugin/bin/lib/health-core/materiality-digest.js` — filter fingerprint sources by trust
- `plugin/bin/lib/issues/comment-trust.js` — reuse existing trust predicate
- `plugin/skills/_shared/materiality-floor.md` — Dedup caller contract
- `plugin/skills/tidy/digest-sweep.md` — pass trusted comments only
