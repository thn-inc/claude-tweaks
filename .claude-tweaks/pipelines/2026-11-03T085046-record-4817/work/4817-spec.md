- **Decision: Reading A.** The run-marker proof covers only the non-default-base path of `closing-links.js --mode post-merge`: the marker check runs when the PR merged into a base other than the default branch, ahead of both that path's reopens and its 9b closes. Record this choice in the spec and pin it with a test asserting a default-base post-merge run still reopens for a foreign or marker-less PR body.
- **Decided (round 2), Q1: Reading A** (answers comment 6578048225). When `closing-links.js --mode post-merge` cannot read the PR's base (no `baseRefName`, or `gh repo view` fails — the `baseUnchecked` case), treat it like the default base: no run-marker proof, behaviour unchanged, and a test pins it. Rationale: an unreadable base is usually a transient `gh` failure, and an exit 4 there would be misread by the reconciler as a deterministic marker mismatch. Only a base positively known to be non-default runs the proof.
- **Decided (round 2), Q2: Reading B.** On exit 4 (run-marker mismatch), `_shared/pr-first-merge-post-merge.md` Step 4.0's closing summary names only the mismatch and the PR number, and asks for no hand close of the PR's `Fixes` records (they may belong to another run).
