# 4061: reconcile ledger-residue claims parity with tidy's orphan-ledger rule but skips the referencing-record check

Origin: /claude-tweaks:release v6.152.0 release-gate review (staged/review-5.md, run 2026-10-21T194624-release-standalone)

Defer-reason: tangential

## Current State

`plugin/bin/lib/reconcile/ledger-residue.js:118` (`classifyLedgerCandidate`), its header comment at :17, and `docs/reconcile-checks.md`'s Ledger residue section all say the check "follows tidy's orphan-ledger rule". `plugin/skills/tidy/scan-procedures.md:66` also requires checking open records that reference the ledger (a `namedTarget` path, or a filename/feature-slug substring) and closing them in the same action.

`ledger-residue.js` never checks referencing records, so a background removal PR can delete a ledger while records naming it stay open and now point at a missing file. Found by the v6.152.0 release-gate review (3e-A, verified directly against scan-procedures.md:66 and ledger-residue.js:15-26/:118-126 at d27fb609b).

## Deliverables

1. `ledger-residue` applies tidy's referencing-record check: a ledger referenced by an open record is either skipped with a named reason, or its removal PR body lists those records so they are closed in the same action.
2. If parity is deliberately not wanted, the header comment and `docs/reconcile-checks.md` stop claiming it, and say what differs and why.

## Acceptance Criteria

- A test with an open record whose body names the ledger path shows the ledger is not removed silently (skipped with the reason, or the record listed in the PR body), and goes red with the check removed.
- `docs/reconcile-checks.md` and the module header describe the same keep rule the code applies.
- `npm test` passes.

## Release Note

Background ledger cleanup no longer deletes a ledger that an open work record still references.
