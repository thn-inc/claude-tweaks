# 3124: review: lens 3f confirms a "these test cases are vacuous" finding on pair agreement alone, and the auto-applied fix deletes valid cases

Surface: backend

**Related:** #3049, #2955, #2734, #2908, #2977, #3001, #3013, #3021, #3047, #3050, #3052, #3126

## Current State

`/claude-tweaks:review` lens 3f (Test Quality, `plugin/skills/review/step3-lens-dispatch.md` § "3f: Test Quality") runs as a reproduction pair at `medium` and above. `review-coordination.js categorise-reproduction` marks a finding `confirmed` when both agents report it at the same path (line ±2), and nothing else is required (`step3-lens-dispatch.md`, Reproduction dispatch bullets).

Lens 3f has an execution-evidence rule in one direction only. Its Discrimination diagnostic says of a *new regression test*: "A green suite is not evidence here; the revert is." Nothing matches it for the opposite claim, where a finding says a test "cannot fail" or that cases "are vacuous". Such a finding can reach `confirmed` from prose alone (a comment, a fixture docstring), and a reproduction pair reading the same prose shares the same misread. The Per-Candidate Refutation Pass, which exists to catch that correlated error (`step3-debate-and-refutation.md`), runs only at `xhigh`/`max` and drops candidates below its fixed `medium` severity floor. A `low` vacuity finding at `high` therefore never gets falsified.

Step 3 Routing (`plugin/skills/review/step3-routing.md`, "Ceiling-keyed routing" table) sends a `confirmed` Low finding to AUTO at ceiling `low` or `medium`, and a Medium finding to AUTO at ceiling `medium`. Nothing in the table looks at what the fix does. A fix that deletes test cases or assertions auto-applies the same way a typo fix would.

Observed failure (6.137.0, `review-effort: high`, `review-auto-apply-ceiling: medium`): a lens 3f pair took a wrong fixture docstring at face value and reported five parametrized parity cases as "comparing two empty answers". Neither agent ran a query. Pair agreement made the finding `confirmed`, and the AUTO fix deleted all five valid cases and added a comment repeating the false premise. A later session caught it only by running the five queries.

## Deliverables

1. **Lens 3f vacuity-evidence rule** in `step3-lens-dispatch.md` § "3f: Test Quality". This is a new diagnostic bullet, the counterpart of the Discrimination diagnostic. Any finding whose substance is "this test cannot fail" or "these cases are vacuous / pass trivially" must carry execution evidence in its Evidence field: either the case run with its actual observed result shown, or the code under test mutated with the test shown staying green. A comment, docstring, fixture name, or reading of the code is not evidence for this claim.
2. **Post-categorisation downgrade** in `step3-lens-dispatch.md`'s Reproduction dispatch section, applied after `categorise-reproduction` returns. A `confirmed` lens 3f finding that makes the vacuity claim without execution evidence in either agent's Evidence field is downgraded to `unconfirmed`, whatever the pair agreed. Log it as a `STAGED` decision-log line stating that reproduction agreement was overridden for lack of execution evidence. The Direct-verification override does not lift this downgrade by reading source alone. The only way back to `confirmed` is the reviewing agent running the case itself and recording the observed result.
3. **New `unconfirmed` source** listed in `step3-routing.md`'s "`unconfirmed` findings can originate from several sources" bullets: "vacuity claim without execution evidence (lens 3f)".
4. **Test-removal fixes never AUTO** in `step3-routing.md`'s Auto-mode section. A finding whose fix deletes test cases, parametrized rows, or assertions (whole cases or assertion lines removed from a test file, net) routes STAGED at every `review-auto-apply-ceiling` value, overriding the ceiling-keyed table and the prose-exempt bump. Critical still routes KEPT-PROMPT. Log the AUTO→STAGED override with a lever note naming this rule. Mention the exception next to the ceiling table so readers of the table see it.
5. **Conformance test** `tests/review-vacuity-evidence-conformance.test.js`, which pins: the lens 3f vacuity-evidence bullet; the downgrade rule's presence in the Reproduction dispatch section; the new `unconfirmed` source bullet; and the test-removal STAGED override in `step3-routing.md`.

## Acceptance Criteria

- `step3-lens-dispatch.md` § "3f: Test Quality" contains a diagnostic requiring execution evidence (observed run result or mutation-stays-green) for any "cannot fail"/"vacuous" finding, and states that comments and docstrings do not count.
- `step3-lens-dispatch.md`'s Reproduction dispatch section states that a `confirmed` lens 3f vacuity finding with no execution evidence is downgraded to `unconfirmed` after `categorise-reproduction`, names its decision-log line, and states that Direct-verification by source reading alone does not re-confirm it.

- Replaying the observed scenario against the new text (a `low` lens 3f vacuity finding, pair-agreed from a docstring, `review-effort: high`, ceiling `medium`) ends as `unconfirmed` routed to the Review Console's Low-confidence subsection, and no test case is deleted automatically.
- `tests/review-vacuity-evidence-conformance.test.js` passes. Reverting either rule's prose turns it red (shown by reverting before commit).

## Release Note

Stop `/review` from auto-deleting test cases on a "these tests are vacuous" finding that no agent actually ran.

## Technical Approach

This is a prose-only change to two review sub-files plus one conformance test, with no code change to `review-coordination.js`. Deciding whether a finding makes a vacuity claim is a judgment over free-text finding descriptions. A keyword heuristic in `categoriseReproduction` would turn "could not parse" into a silent "does not apply" (see the repo's parse-signal-discipline skill), so the orchestrator applies the downgrade in prose, next to the existing reproduction bullets. Rule 2 (test-removal fixes never AUTO) keys on the fix's diff. The routing step already has the staged-patch diff in hand, and "removes test cases or assertions" is read from that diff, not inferred from the finding text.

Place the lens 3f bullet directly after the Discrimination diagnostic so the two evidence rules read as a pair. Place the routing override as its own bolded paragraph after the prose-exempt paragraph, in the same shape that paragraph uses: it overrides both the plain and the bumped ceiling.

### Key Files

- `plugin/skills/review/step3-lens-dispatch.md` — new lens 3f vacuity-evidence diagnostic, plus the post-`categorise-reproduction` downgrade rule in the Reproduction dispatch section
- `plugin/skills/review/step3-routing.md` — new `unconfirmed` source bullet, the test-removal-never-AUTO override paragraph, and a pointer from the ceiling-keyed table
- `plugin/skills/_shared/auto-mode-contract.md` — the `/review` Step 3 Routing row (line ~171) states severity→action with no exception; add a short qualifier naming the test-removal STAGED override, or confirm the row deliberately stays severity-only and cite why
- `tests/review-vacuity-evidence-conformance.test.js` — new conformance suite pinning both rules

## Gotchas

- `step3-lens-dispatch.md` carries a "Per-lens Calibration + Output template" block that must stay byte-identical to `_shared/criteria-review-quality.md`'s CALIBRATION block. Insert the new prose outside that block. If the change touches the calibration text, both files have to change together.
- `step3-lens-dispatch.md` feeds a composed review-dispatch bundle (`tests/review-dispatch-composition.test.js`). Run that suite after editing, because a fence or section move can break bundle parsing.
- The tier-scope table in `step3-lens-dispatch.md` (around line 39) puts lens 3f in scope at `medium` too, not only at `high`. The downgrade must apply at every tier where lens 3f produces a `confirmed` finding.
- The Refutation Pass's `medium` floor (`step3-debate-and-refutation.md`) is deliberately left alone. This record adds an evidence requirement at the source, and it does not widen refutation fan-out.
- Execution evidence must be an observed result. An agent saying "I ran it and it was empty" with no output shown is the same unverified claim in a new form, so the rule should require the actual output or command.

## Original request

review: lens 3f confirms a "these test cases are vacuous" finding on pair agreement alone, and the auto-applied fix deletes valid cases

**Summary:** At review-effort `high`, both agents of a lens 3f reproduction pair reported that five parametrized test cases "compare two empty answers". Both took the premise from a fixture docstring in the diff, which was wrong. Pair agreement made the finding `confirmed`, and Step 3 Routing auto-applied a fix that deleted the cases.

**Kind:** Gap

**Affected component:** `/claude-tweaks:review` — lens 3f in `review/step3-lens-dispatch.md` and the AUTO path in `review/step3-routing.md`

**Use case:**
A diff added a parametrized parity test (one query answered by two implementations, answers compared) and a second fixture whose docstring said every answer over the first fixture is empty. The docstring was wrong: one of the five queries returns a row over the first fixture, and the other four are empty on both implementations because each applies the same filter, which is the parity those cases exist to hold.

Both lens 3f agents read the docstring, reported the five cases as unable to catch a parity break (low severity), and neither ran a query. `categorise-reproduction` marked the finding `confirmed`. With `review-auto-apply-ceiling: medium` the fix auto-applied: it deleted the five cases and added a comment repeating the false premise. A later session caught it only because it ran the five queries before trusting the finding.

Lens 3f already has an evidence rule in one direction. Its Discrimination diagnostic says of a new regression test: "A green suite is not evidence here; the revert is." There is no matching rule for the opposite claim. A finding whose substance is "this test cannot fail" or "these cases are vacuous" can be confirmed from a comment, and a pair that shares the comment shares the misread. The per-candidate refutation pass that exists for correlated error runs at `xhigh`/`max` only, and only at severity `medium` and above, so it never sees a low finding at `high`.

Two changes would have stopped this:

1. Lens 3f: a "vacuous" or "cannot fail" finding carries execution evidence in its Evidence column: the case run with its actual answer shown, or the code under test mutated with the test shown staying green. Without it the finding is `unconfirmed` whatever the pair says.
2. Step 3 Routing: a fix that removes test cases or assertions never takes the AUTO path on pair agreement; it stages, at any ceiling.

**Definition:** Clear — both changes are small, local rule additions.

**Plugin version:** 6.137.0 when the finding was produced and applied; the reversal ran on 6.139.1.
