# 4422: Add a conformance scan banning the retired liveness probes in the four migrated callers

Surface: infra

## Current State

Sub-issues #4419, #4420 and #4421 of #3979 remove the private liveness probes from four callers:

- #4419: `adoptionRefusal` in `plugin/bin/lib/hooks/run-dir-resolve.js`. It keeps a renamed adoption-precondition helper and does not consult `runLiveness`.
- #4420: `checkResumeFreshness` in `plugin/bin/lib/hooks/resume-freshness.js` and `parentLiveDetail` in `plugin/bin/lib/flow/consolidated-pass.js`. These route through `runLiveness` and `blocksResume`. #4420 also moves `lastCommitMs` and its `git log -1` into `run-liveness/probes.js`, and deletes `checkResumeFreshness`'s own `git log -1` at line 98.
- #4421: `classifyRunDir` in `plugin/bin/lib/reconcile/archive-merged.js`. This routes through a `runVerdict` hook.

Nothing stops a later change from reintroducing a private probe in one of these files, and that is how four copies grew in the first place. A probe can return under a new name or as an inline primitive:

- `isPidAlive` is a wrapper over `process.kill(pid, 0)` (`hooks/worktree-reap.js` line 138);
- `lockVerdict` reads a `parseWorktreeList` entry's lock state;
- commit recency can be read with `--max-count=1`/`-n 1` or a `%ct`/`committerdate` format.

Today `archive-merged.js` contains no `lockVerdict`, `isPidAlive`, `process.kill` or `git log -1` anywhere. Other `lockVerdict`/`isPidAlive` consumers (`hooks/sibling-sessions.js`, `hooks/context.js`, `reconcile/background-lock.js`, `residue/probes/worktrees.js`) answer different questions (sibling sessions, lock files, residue), not run liveness, so they are out of scope.

The repo's pattern for this kind of guard is a source-scan conformance suite: the `bin-source-scan-conformance` project skill, with comment-stripped source reads through the shared stripper, a stripper-verdict check, a floor on matched sites, and go-red self-tests.

This is sub-issue D of #3979, natively blocked by #4419, #4420 and #4421.

## Deliverables

- [ ] A `node --test` conformance suite, `tests/run-liveness-callers-conformance.test.js`, scanning the whole files `run-dir-resolve.js`, `resume-freshness.js`, `consolidated-pass.js` and `archive-merged.js`.
- [ ] **Banned names** in all four files: `isDeadRunDir`, `lockVerdict`, `isPidAlive`, `lockInUse`, `lastCommitMs`.
- [ ] **Banned primitives** in all four files:
  - `process.kill(`;
  - a git commit-recency read in any call shape: an argv array or a string containing `log` together with `-1`, `-n`/`--max-count`, or a `%ct`/`%cI`/`committerdate` format;
  - a read of a worktree entry's `.locked` / `.lockReason` field.
- [ ] **Scoped rule**: `ownEventRecency` and `STALE_INTERRUPTED_TTL_MS` may appear in `archive-merged.js` only inside `classifyRunDir` (the floor), `lastOwnEventMs` (its existing wrapper) and the import and export lists, and nowhere in the other three files.
- [ ] The allowlist is documented as comments only, not matched: `runLiveness`, `blocksResume`, the `runVerdict` hook, and #4419's renamed precondition helper. Everything under `plugin/bin/lib/run-liveness/` and `plugin/bin/lib/hooks/worktree-reap.js` is out of scope by construction, because those files are not scanned.
- [ ] Go-red self-tests:
  - for each banned name and primitive form, a fixture source string that reintroduces it fails the matcher;
  - a comment-only mention does not fail it;
  - an `ownEventRecency` use moved into a new sibling helper in `archive-merged.js` fails it.
- [ ] A floor on matched sites: the suite asserts it located all four files and the `classifyRunDir`/`lastOwnEventMs` function boundaries, so a rename cannot silently empty the scan.

## Acceptance Criteria

1. The suite passes on `main` once #4419, #4420 and #4421 have landed.
2. Reintroducing `lockVerdict(` into `resume-freshness.js`, `process.kill(pid, 0)` into `consolidated-pass.js`, or `runGit(['log', '--max-count=1', '--format=%ct'])` into `archive-merged.js`, each in a scratch copy, makes the suite fail and name the file and the form. The PR body quotes the red runs.
3. A banned name that appears only in a comment does not fail the suite.
4. Renaming `classifyRunDir` in a scratch copy makes the suite fail on the site floor, not pass vacuously.
5. `npm test` passes.
