# 3810: verify.js baseline adjudication blames a branch for failures inherited from its merge-base

# Reflect — staged finding 2

**Category:** tangential

Origin: reflect hindsight from #3602

Defer-reason: tangential

## Current State

`plugin/skills/test/verification.md` (Baseline adjudication) tells every pipeline site to pass `--baseline origin/{integration-branch}` to `bin/verify.js`, so a failing suite is adjudicated against the integration branch's current tip, not against the commit this branch actually forked from.

When the integration branch moves past the branch's merge-base and fixes a test that was red at that merge-base, the branch still carries the red test (it has not merged the fix), the tip passes it, and verify.js reports the inherited failure as `ATTRIBUTABLE` — a false attribution that fails the build.

Observed on #3602 (multi-spec run 2026-10-20T124821): `tests/git-path-read-conformance.test.js` was red at merge-base 160e7c4b3 (#3651's pin vs #3302's line) and fixed on main by a25a47b92 (#3752); the first verify run reported it attributable, and only a hand re-run with `--baseline 160e7c4b3` produced the correct verdict (1 also fails at base, 0 attributable), at the cost of a second full suite run (~4.5 minutes).

## Deliverables

Adjudicate against the branch's merge-base with the integration branch (`git merge-base HEAD origin/{integration-branch}`), either by changing `verification.md`'s prescribed `--baseline` value or by having `verify.js` resolve a `--baseline` branch ref to its merge-base with HEAD.

Keep the existing exit-2 behavior for an unresolvable ref, and state in the report which commit was used as the base.

## Acceptance Criteria

Given a branch whose merge-base has a failing test that the integration branch tip has since fixed, and a run that fails only that test, verify.js reports it as also failing at base (0 attributable) and the run passes on adjudication.

Given a test that passes at the merge-base and fails on the branch, verify.js still reports it as attributable.

The report's `baselineAdjudicated.base` names the merge-base commit actually used.

## Release Note

Pipeline verification no longer blames a branch for a test that was already failing where the branch started.

## Technical Approach

### Key Files

- `plugin/skills/test/verification.md` — Baseline adjudication: prescribe the merge-base, not the moving tip
- `plugin/bin/verify.js` — resolve a --baseline branch ref to its merge-base with HEAD (or document why not)
