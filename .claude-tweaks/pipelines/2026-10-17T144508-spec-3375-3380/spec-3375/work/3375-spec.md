# 3375: Attribute agent cost to individual subagent dispatches in phase-timing and the /wrap-up run summary

Surface: backend

## Overview

Part of the "Build dispatch cost shape" decomposition (origin #3229, a feedback report from a measured 10-task subagent-driven build: about 2.5 hours of sequential agent time, roughly three-quarters of it on the most capable tier). Cost data today is per phase, not per dispatch: `phase-timing.js` derives per-phase minutes and transcript token counts and `/wrap-up` renders them, but nothing attributes cost to an individual subagent dispatch, a model tier or a role. Every other record in this decomposition claims a saving (plan review catching spec gaps early, per-task tiers, merged tasks); without per-dispatch telemetry those claims are estimates, not measurements.

This record extends the existing transcript-based timing to attribute usage to individual subagent dispatches — per dispatch: the model, the wall-clock span and the token usage — read after the fact from the session and subagent transcripts, and renders a breakdown by model tier (and by role where the dispatch description identifies it) in `/wrap-up`'s run summary. It ships first: a pre-change baseline from at least one representative multi-task `/flow` run must exist before the plan-review, per-task-tier and task-merge records change the cost shape, and the whole-branch-review decision record depends on it.

**Complexity:** Medium
**Estimated tasks:** 5-6

## Non-Goals

- Reading cost from the `SubagentStop` hook. That hook fires unreliably for Task dispatches (claude-code#27755), only in the owning session, and `bin/lib/hooks/subagent-stop.js` logs contract violations only. Do not add hook-side collection.
- Changing the existing per-phase table's numbers, columns or `timing.json` keys already consumed. The dispatch breakdown is additive.
- Pricing or dollar estimates. Tokens, tier and wall-clock only.
- Acting on the numbers (tier changes, skipping reviews). That is the other records' job.

## Release Note

Added a per-dispatch cost breakdown by model tier and role to the run summary, so a build's agent time and token use can be attributed to individual subagent dispatches.

## Technical Approach

Extend the existing after-the-fact transcript reading rather than adding a collector. The timing CLI already resolves a session's main transcript; the subagent transcripts live beside it in a `{sessionId}/subagents/` directory, so the new reader locates that directory from the same slug and session id and reuses `readUsage`'s deduping stream for each file. The meta file supplies model and description without parsing the transcript body. Role inference is a small ordered table of description patterns in `derive.js`, tested against real descriptions from the dispatch sites in `plugin/skills/build/dispatch.md`, `plugin/skills/review/step3-lens-dispatch.md` and the SDD-composed implementer and reviewer dispatches; anything that matches no pattern is `unlabelled`, which is itself useful signal.

### Data / API Surface

- `timing.json` gains `dispatches: { items: [{ agentId, description, agentType, model, tier, role, parentAgentId, spawnDepth, startTs, endTs, wallClockMs, tokens: { input, output, cacheRead, cacheCreate } }], byTier: {...}, byRole: {...} }` or `dispatches: { notFound: "<reason>" }`. Per-dispatch timestamps stay in the record so a consumer can, for example, take the dispatches after a whole-branch review's start as SDD's final stage.
- New exports from `plugin/bin/lib/timing/transcript.js` and `derive.js`; no change to the existing exports' signatures.

### Key Files

- `plugin/bin/phase-timing.js` — `dispatches` key in `timing.json`, the markdown table, the not-found line
- `plugin/bin/lib/timing/transcript.js` — subagent directory enumeration and per-dispatch usage
- `plugin/bin/lib/timing/derive.js` — tier and role aggregation
- `plugin/bin/lib/model-profiles/profiles.js` — read-only: `profileOfModel` and `PROFILES` supply the tier mapping

## Gotchas

- Read transcripts, not the hook. `plugin/bin/lib/hooks/subagent-stop.js`'s header records that `SubagentStop` fires unreliably for Task dispatches (claude-code#27755) and only in the owning session. Do not add hook-side collection as a "more accurate" alternative.
- Meta files carry the model as a family alias (`sonnet`) most of the time, but about one in eight on this machine carry `inherit` or no `model` at all (probed 2026-10-17), while transcript lines carry full ids such as `claude-sonnet-5`, `claude-opus-5-5`, `claude-haiku-4-5-20251001`. Resolve in the order the Deliverables give; `profileOfModel` throws on a non-alias, so call it only after the alias check and report `unmapped` rather than letting one odd dispatch fail the whole table. Meta key sets vary widely (several distinct shapes observed), so treat every field except the transcript's own timestamps and usage as optional.
- The multi-spec summary template that `tests/timing-prose-conformance.test.js` also covers renders the same block; find it by grepping for `phase-timing.js` under `plugin/skills/flow/` rather than assuming one file.
- The subagent directory layout above was observed on 2026-10-17 against the installed Claude Code; it is not a documented contract. Pin it in a fixture-based test and make the not-found path the behavior when the layout drifts, as `transcript.js`'s slug rule does for the main transcript (its header: "re-derive the rule from a fresh observation, do not loosen the test").
- Subagent usage lives in separate files from the main transcript, so the dispatch table does not overlap the phase table's token columns — but do not sum the two in a "grand total" row; the phase table's `Tokens` column is main-session only.
- A nested dispatch (`spawnDepth` above 1, `parentAgentId` set) is a real dispatch with its own cost; include it, and keep `parentAgentId` in the record so a later consumer can nest it.
- The final-stage cost of SDD (whole-branch review, fix wave, re-review) has no role of its own in the closed role set above because its dispatch descriptions come from SDD; the whole-branch-review decision record derives that stage from per-dispatch timestamps (the dispatches from the whole-branch review's start to the last SDD dispatch), not from a role.
- The baseline has to be taken before the plan-review, per-task-tier and task-merge records merge. If none of them has merged when this record builds, take it from the most recent representative multi-task `/flow` run available; if none is available, state that in the baseline file rather than fabricating one.
- This record shares `plugin/bin/lib/timing/transcript.js` with #3309 (ready, in progress) — build after it merges, and re-read the file first.
- Steering principle for the whole decomposition: claude-tweaks never files upstream with superpowers for this and never contradicts SDD's text. This record touches neither.
- Expand-contract: existing `timing.json` consumers (`/wrap-up`, `phase-timing.js --json`) keep working unchanged; new keys are additive.

## Revised during build (Common Step 4.5, Beneficial)

- **Elapsed:** computed from the exact millisecond union of spans (`unionMs` in `derive.js`), rounded to minutes once. Rounding each disjoint cluster with `unionMinutes` made `elapsed` exceed `agent-seconds` on short dispatches. `unionMinutes` itself is unchanged.
- **Not-found coverage:** a readable transcript with no timestamped usage rows reports `notFound: 'transcript has no usage rows'` with null numbers (no zero-fill). Symlinked `agent-*` entries are skipped, and subagents dirs are deduped by realpath, matching `locateTranscripts`' containment discipline.

## Revised during review (/claude-tweaks:review Step 3)

- **Item model fields:** a dispatch item carries `metaModel` (the meta alias), `transcriptModel` (the first `claude-` id in its transcript) and `rawModel` (the value its tier came from) in place of the single `model` the Data / API Surface names — the tier rule needs both inputs, and `unmapped` reports the raw one.
- **Not-found forms:** a `subagents/` directory that exists but cannot be listed reports `subagents/ directory not readable ({code})`; a meta file that exists but cannot be used reports `meta not readable ({code}|malformed|symlink)` rather than `meta not found`; an entry lstat cannot prove regular is never read (fail closed), and a fully symlinked dispatch is named rather than dropped.
- **Run window:** a `worktree-reaped` event is left out of the window's end, matching `derive.js`'s endOfRun rule.

## Revised during wrap-up (ledger resolve gate, fix-exhaust)

- A subagent's own `agent-{id}.jsonl` passed as `--transcript` (what `/dispatch` does) maps to the `subagents/` directory it sits in, not to a nonexistent nested one.
- A `subagents/` directory with no `agent-*` files, or a symlinked one, is `notFound`; with several transcripts, a directory that yielded nothing beside one that did is listed in `dispatches.notFoundDirs` and printed as its own not-found line.
- A meta reason is kept ahead of a transcript reason (`meta not found; transcript has no usage rows`); a usage row with no valid timestamp counts toward a dispatch that has a kept timed row; the model-family prefix must end at a hyphen or the id's end.
