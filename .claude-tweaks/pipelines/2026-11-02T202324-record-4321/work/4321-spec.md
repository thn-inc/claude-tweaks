# 4321: Test-impact selection never fires: .claude/skills/** changes and other unmatched paths force the full suite

**Related:** #4031 (parent), #4024, #4129, #4131

## Current State

#4024 shipped test-impact selection on 2026-10-24 (15:39Z), but no pipeline run has used it since. Every verify entry in `.claude-tweaks/pipelines/**/timing.json` dated after the merge: `full` 60, `scoped` 4 (journeys only), `none` 2 — **impact subset: 0**. A full `tests` run costs ~144–562 s per call (`durationMs`), so this is the largest remaining wall-time lever under #4031.

The map is not the problem: `.git/claude-tweaks-test-impact.json` (commit `71a3e0d8`, exitCode 0) is 64 commits behind origin/main, inside `maxAgeCommits: 200`, and `test-impact-map.yml` runs green on main.

**Dominant cause: unmatched paths supersede selection.** In `plugin/bin/lib/verify/scope.js` `selectScope`, any changed file matching no rule in `.claude-tweaks/verify-scope.json` sets `all = true`, and the impact suite then reports `superseded: true` and runs full. Replaying the current rules over the 59 PRs merged since #4024 (`gh pr list --state merged --search "merged:>=2026-10-24T15:39:28Z" --json files`): 37 are superseded, 20 impact-eligible, 2 have no impact paths. Superseding paths by PR count:

- 31 — `.claude/skills/**` (unmatched; project skills that wrap-up and reflect add to most PRs)
- 3 — `.release-please-manifest.json` (unmatched)
- 3 — `perf/*.test.js` (unmatched)
- 1 — `.github/workflows/**` (unmatched)
- 1 each — the deliberate full-run rules `tools/test-impact/**` and `tools/run-tests.js`

The map already traces reads under `.claude/`: it records 634 `.claude/`-prefixed paths, including `.claude/skills/**/SKILL.md` globs. An `impact: true` rule therefore lets the trace pick the tests, with selection still failing closed on any uncovered path.

**Second, unexplained cause.** The 20 impact-eligible PRs also ran full. `timing.json`'s verify entry keeps only `{mode, suitesRun, durationMs, pass, baselineAdjudicated, at}`. `report.json` keeps `scope.impact` (`fallback`, `superseded`, `selected`), but it lives at `.git/worktrees/{wt}/claude-tweaks-verify/report.json`, is overwritten on every call, and disappears when the worktree is reaped. Only 2 post-merge reports survive. The fallback reason is unrecoverable from run artifacts.

## Deliverables

1. Carry the impact outcome into the verify event that feeds `timing.json`: the suite, `fallback` reason (`mapProblem` / `selectImpactTests` `{ok:false}` reason / `no-anchor` / list problems), `superseded`, `selected` count, and the superseding paths (unmatched files plus files hitting a non-impact `suites: "*"` rule). The fields are present only when the declaration has an `impact` block.
2. Add rules to `.claude-tweaks/verify-scope.json` so the common superseding paths stop forcing a full run:
   - `.claude/**` → `impact: true, suites: "*", static: true`
   - `perf/**` → the suite set `npm run test:perf` belongs to, not `tests` (perf is excluded from `npm test`)
   - `.release-please-manifest.json` → `suites: []` unless a test reads it (check the map)
   - `.github/workflows/**` → decide it from the map's traced reads

   Keep `tools/test-impact/**` and `tools/run-tests.js` as deliberate full-run rules.
3. Once deliverable 1 has landed, re-measure across the next ≥10 pipeline runs. If impact-eligible runs still fall back, fix the dominant recorded `fallback` reason, or file it with the measured counts.

## Acceptance Criteria

- [ ] A verify run under an `impact` declaration writes the fallback reason / superseded flag / selected count into its `timing.json` verify entry. A test covers each of the three outcomes: subset, fallback with reason, and superseded with paths.
- [ ] Re-running the PR-replay over the same 59 PRs against the new rules leaves ≤ 5 superseded by unmatched paths.
- [ ] On a branch whose only change is a `.claude/skills/<x>/SKILL.md` edit, `node plugin/bin/verify.js --scope .claude-tweaks/verify-scope.json` runs an impact subset (or reports a named `fallback`), not `superseded`.
- [ ] Across ≥10 pipeline runs after merge, at least one `tests` verify entry is an impact subset. Otherwise every fallback has a recorded reason, and the dominant one is filed with counts.
