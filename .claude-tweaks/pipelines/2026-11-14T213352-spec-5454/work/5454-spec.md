# 5454: Driver: the plain path's test step judges a tree it never reads after the tests run

Origin: #5415 final whole-branch review (run 2026-11-14T153732-spec-5414-5415)

Defer-reason: genuinely-larger

## Current State

When the pipeline driver's review step is off (`reviewRequired` returns off for a `size:low` record within the Key Files bound, or policy `off`), nothing reads the worktree after `testStep`'s `verify.js` run (`plugin/bin/lib/driver/steps.js`). The commit runs before the tests, and `checkStep` and `pushStep` only compare HEAD.

Worker-authored test code the driver runs with its own rights can therefore rewrite a tracked source file without setting an index flag, and the test step passes on bytes that are never committed. CI on push runs HEAD and catches the difference later, so the harm is a wrong green verdict from the driver and a red PR, not broken code merged.

#5415 closed only the index-flag subset of this: a path newly flagged skip-worktree or assume-unchanged after a check point stops the record. Its final whole-branch review raised this plain-path gap as outside its Key Files contract.

## Deliverables

- [ ] After `testStep`'s `verify.js` call, read the tree (`git --no-optional-locks status --porcelain -z`, untracked included — the same read the review pass's tree check uses) and stop the record with status `fail` when a tracked path differs from HEAD or a new untracked file appears outside the run's own artifacts.
- [ ] The stop detail names at most a few of the changed paths (each through `neutralize`) plus their total count; a failed status read stops with a fixed detail, never git's stderr.
- [ ] `docs/driver.md` states the rule beside the index-flag rule in `## Worker rights`.
- [ ] Tests in `tests/bin-lib/driver/run.test.js` for every acceptance criterion below.

## Acceptance Criteria

1. Over a fake runner, a tracked file modified during the scoped test step stops the record at the `test` step with status `fail`, and no `check` or push runs.
2. On the Phase 1 happy path the recorded calls differ from before only by the one added status read, and the event lines are unchanged.
3. A status read that fails stops the record with status `fail` and a fixed detail.
4. A changed path holding a newline, `fixes #12` and `@someone` reaches the stop detail neutralized.

## Release Note

The pipeline driver now stops a record when its test run leaves a tracked file changed, instead of reporting green tests for bytes that are never committed.

## Plan Review Clarifications

- Decided by the user at plan review: "the run's own artifacts" means the paths the commit step also skips (`isRunArtifact`, `.claude-tweaks/pipelines/`), for tracked and untracked paths alike. A tracked file under `.claude-tweaks/pipelines/` that a test rewrites therefore passes the check, a residual left to CI on push. Reading not taken: exclude untracked pipelines paths only, so a changed tracked file there stops the record. (Finding: "The spec's artifact exclusion covers only new untracked files. The plan also applies `isRunArtifact` to tracked paths.")
- Decided by the user at plan review: a red `verify.js` run keeps its existing outcome (`stop`, reason `failing-test`) and makes no tree read. The tree check gates only a green run or a run with no verdict. Reading not taken: the tree stop outranks every verdict. (Finding: "The spec does not say whether the tree stop overrides a red verdict.")
- Build alignment (Beneficial, final-review fix wave): when the run gave no verdict (a timeout, a spawn error, or an exit other than 0 and 1) and the tree changed, the stop detail is the tree detail followed by `; ` and the run's own verdict-less detail, so the operator still sees why verify.js gave no verdict. The tree detail stays the prefix; a green run's detail is the tree detail alone. `docs/driver.md` also says that a file the commit's own git hooks write is reported the same way.
- Decided by the user at plan review: the Release Note is reworded, because "always" claimed more than the Acceptance Criteria prove (ignored files, empty directories, a change restored before the run exits, a `.gitattributes` filter and `core.fsmonitor` are not covered).
