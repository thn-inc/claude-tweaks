# 3111: Retry verify.js's isolated HEAD run once before calling a baseline-failing file attributable

Origin: reflect full (batch) from #3101-#3104, run 2026-10-10T190327-spec-3101-3102-3103-3104

Defer-reason: tangential

## Current State

`bin/verify.js`'s baseline adjudication (#3043) classifies a failing file by comparing a single-file base run against a single-file isolated HEAD run, test by test. If the isolated HEAD run fails one extra test, the file is reported `ATTRIBUTABLE` and verify exits 1, even when that extra failure is load flake that did not reproduce. In run 2026-10-10T190327 (#3104), `tests/hooks-context.test.js` was reported attributable. Its base and isolated logs both failed the known Windows path-separator test, and the isolated HEAD log also failed the cross-process `writeRunState` concurrency test. That test then passed 3 out of 3 times in isolation, and #3104's diff touches no hooks code. It cost one extra ~7-minute full verification.

## Deliverables

- When the isolated HEAD run of a baseline-failing file fails a test the base run did not, re-run that file once in isolation before reporting it `ATTRIBUTABLE`. Report it `flaky` (with the existing `CAVEAT: baseline-flaky` line) when the re-run's failing set is covered by the base run's.

## Acceptance Criteria

- [ ] A file whose isolated HEAD run fails a base-covered test plus a flaky extra test is reported `baseline-flaky` when the extra failure does not reproduce on one retry.
- [ ] A file whose extra failing test reproduces on the retry is still reported `ATTRIBUTABLE`.

## Release Note

Baseline-adjudicated verification no longer fails a build on a one-off flaky extra failure in a file that already fails at base.
