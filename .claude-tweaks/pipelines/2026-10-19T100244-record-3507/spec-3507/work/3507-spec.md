# 3507: Windows regression: 1 test file(s) newly failing after a62e27344

Surface: infra

## Current State

The post-merge Windows check (`.github/workflows/windows-regression.yml`, run 39101724698) reports one test file newly failing after commit a62e27344 (PR #3452, which added the file): `tests/manifesto-overrides-ceiling-conformance.test.js`. It passes on ubuntu CI and on any LF checkout (verified: `node --test tests/manifesto-overrides-ceiling-conformance.test.js` → 11 pass, 0 fail on macOS).

Root cause, verified against the file at `origin/main`:

- The test reads its three governed markdown inputs with raw `fs.readFileSync(..., 'utf8')` — `plugin/skills/flow/manifesto-overrides.md` and `plugin/skills/review/step3-routing.md` at lines 13-14, `plugin/skills/flow/manifesto.md` at line 95.
- `routingColumns` (line 16) does `md.split('\n')` and then ``lines.indexOf('| Severity | `none` | `low` | `medium` |')`` — an exact whole-line match. On a Windows checkout with `core.autocrlf=true` (no `.gitattributes` rule covers these files), every line keeps a trailing `\r`, so the lookup returns -1 and line 19 throws `ceiling-keyed routing table header not found in step3-routing.md`.
- The throw happens at module top level (line 67, `const cols = routingColumns(routing);`), so the whole file fails before any `test()` registers — one file-level failure, not a per-assertion one.
- Simulated: the header is found at index 44 on the LF text, -1 on the same text with `\n` replaced by `\r\n`, and 44 again after `\r\n` → `\n` normalization.

The repo already has the fix for this class: `tests/helpers/read-skill.js` exports `readText(absPath)`, an EOL-normalizing read (#2763) that about 80 test files already use for prose-conformance reads. This file, added by PR #3452, does not use it.

**Related:** #2713, #3187, #3396, #3429, #3440, #3505, #3506, #3509, #3512, #3517, #3518, #3523

## Deliverables

1. `tests/manifesto-overrides-ceiling-conformance.test.js` reads all three markdown inputs through `readText()` from `tests/helpers/read-skill.js` instead of raw `fs.readFileSync`.
2. The file's line-splitting extractors (`routingColumns`, `ceilingRow`, and the lever-7 filter in the manifesto test) split on `/\r?\n/`, so the extractor itself tolerates CRLF input, not only the read.
3. A new CRLF test case, built from the LF text with `.replace(/\n/g, '\r\n')`, asserting `routingColumns` on the CRLF text deep-equals `routingColumns` on the LF text, and that `ceilingRow` returns the same cell for each ceiling value (`none`, `low`, `medium`) on both.

## Acceptance Criteria

1. `grep -n "fs.readFileSync" tests/manifesto-overrides-ceiling-conformance.test.js` returns no matches, and the file requires `readText` from `./helpers/read-skill`.
2. `node --test tests/manifesto-overrides-ceiling-conformance.test.js` passes with 0 failures: the 11 existing tests plus the new CRLF case.
3. Go-red check: temporarily changing `routingColumns`'s split back to `split('\n')` makes the new CRLF case fail, and restoring it makes it pass again.
4. CRLF checkout check: on a scratch clone made with `git clone --config core.autocrlf=true` where `git ls-files --eol plugin/skills/review/step3-routing.md` reports `w/crlf`, the file passes with `node --test`. If `w/crlf` cannot be produced on a POSIX host, record that and rely on AC 3.
5. `npm test` passes with no new failures compared to `origin/main`.

## Technical Approach

This is a test-only change to one file, using the repo's established CRLF pattern (`windows-checkout-test-parity` project skill: "Build CRLF inputs from the LF text" and the `readText()` decision row). Replace the three raw reads with `readText(path.join(...))`. Change the three `split('\n')` sites to `split(/\r?\n/)`. Add one `test()` that builds the CRLF variant of the routing and overrides text and compares the extractor outputs. No shipped plugin file changes. The markdown inputs stay byte-identical.

Alternative rejected: a `.gitattributes` `eol=lf` rule for `*.md`. It would change checkout behavior for every Windows user of the repo, and the only current `.gitattributes` rule is a narrow fixture-hash carve-out. `readText()` is the convention #2763 and #3113 settled on.

### Key Files

- `tests/manifesto-overrides-ceiling-conformance.test.js` — use `readText()` for the three reads, split on `/\r?\n/`, add the CRLF case
- `tests/helpers/read-skill.js` — unchanged; existing `readText()` helper being consumed
- `plugin/skills/review/step3-routing.md` — unchanged; read-only input (the ceiling-keyed routing table at line 45)
- `plugin/skills/flow/manifesto-overrides.md` — unchanged; read-only input
- `plugin/skills/flow/manifesto.md` — unchanged; read-only input

## Gotchas

- Scope is this one file. Sibling "Windows regression: N test file(s) newly failing after …" records each cover their own files. The project skill also asks for a grep of `tests/` for the same `split('\n')` + exact-line-match shape. Any further instance found that no open Windows-regression record already names goes to `/claude-tweaks:capture`, not into this change.
- ubuntu CI cannot see this class of failure. The CRLF case in Deliverable 3 is the Linux-runnable pin. Without it, a later edit could reintroduce the raw read and stay green on every PR.
- The backtick-quoted cells in the header literal must stay byte-exact. Only the line terminator is the problem, so do not loosen the header match to a regex.
