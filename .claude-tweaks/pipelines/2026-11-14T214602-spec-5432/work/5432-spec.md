# 5432: Resolve policy in-process in driver/merge.js instead of spawning resolve-policy.js

Surface: backend
Risk-flags: none

Blocked by #5384

Origin: #5384 whole-branch review (declined-to-judge line: a spawner that arrived through the pre-review catch-up)

Defer-reason: genuinely-larger

## Current State

- `plugin/bin/lib/driver/merge.js:127` (`readIntegrationModel`) spawns `resolve-policy.js --run <runDir> --values integration-model` through `deps.node` with `timeout: CLI_TIMEOUT_MS`; any failure or a value other than `pr-first` is a `not-pr-first` stop.
- `plugin/bin/lib/driver/merge.js:155` (`readLever`) spawns `resolve-policy.js --run <runDir> merge-verification` the same way and parses the JSON; every failure reads as `unresolved` and runs as `wait`.
- That is the kill-timeout shape `.claude/skills/gh-api-module-pattern/SKILL.md` calls wrong: resolving `integration-model` can walk the forge-detection ladder, which carries its own bounds, so an outer `CLI_TIMEOUT_MS` can kill a slow, healthy detection.
- #5384 converted four other shipped callers (`wrap-up/facts.js`, `phase-exit/phase-exit.js`, `dispatch-prompt.js`, `release-tip-check.js`) to call `resolvePolicy` in-process through `callerDeps({ cwd, env, stderr })` exported from `plugin/bin/resolve-policy.js`, alongside `EXIT_OK`, `scalarValue` and `warningLines`. `driver/merge.js` arrived on main through #5226 after #5384's spec was written, so it was out of that record's scope.
- Tests: `tests/bin-lib/driver/merge.test.js`.

## Deliverables

1. `readIntegrationModel` and `readLever` call `resolvePolicy` from `plugin/bin/resolve-policy.js` in-process, injected through `deps` (a `deps.resolvePolicy` seam with the real core plus `callerDeps({ cwd: ctx.mainCheckout, env: deps.env, stderr })` as the default), not `deps.node(bin('resolve-policy.js'), …)`.
2. Each site keeps its current outcome vocabulary and message text: `readIntegrationModel` still returns `integration-model read failed: …` on a throw and `integration-model did not resolve pr-first (…)` otherwise; `readLever` still reads every failure as `unresolved` and runs as `wait`.
3. A result-code comparison uses the exported `EXIT_OK`, never a retyped `0`.
4. The `gh-api-module-pattern` skill bullet stops listing `driver/merge.js` as a remaining spawner.

## Acceptance Criteria

1. `node tools/count-node-procs.js` over `tests/bin-lib/driver/merge.test.js` reports 0 `resolve-policy.js` processes.
2. Tests pin, for each site, the outcome and message when the injected core returns a non-OK result and when it throws, and they match the messages before the change.
3. A test passes a non-default `env` through the seam and fails when the site ignores it.
4. The script entry of `resolve-policy.js` and its output are unchanged.
5. The full suite passes on Linux and on the Windows CI job.
