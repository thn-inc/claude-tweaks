# 3311: Decommission CEILING_BYTES, merge-size-probe, and every per-file size pin

Surface: infra

## Overview

The **decommission** step of the strangler-fig rollout tracked by parent #3305. Once #3310 (cutover) has moved every consumer to the rail, the load delta, and the size-outlier signal, the old size model has no readers left. This unit deletes it: `CEILING_BYTES` and its warning tier, the composed-bundle ceiling and its exception map, the 260/8,700-char description ceilings, the `merge-size-probe` CLI and module, `bloat.js`'s `overCeiling`/`headroom`/`ceiling` option, and every per-file byte pin in `tests/`. After this unit, `plugin/bin/lib/skill-audit/budgets.js` is the only place in `plugin/` or `tests/` that defines a skill-size number. That closes #3230's original deliverable ("remove the scattered hardcoded ceiling copies in favor of one source of truth") and ends the merge-red failure mode: no absolute cliff remains near the files that ship.

Two of the pins being removed were tighter than the global ceiling, and both rested on a misread platform limit. `SPECIFY_SUBFILE_CEILING_BYTES` (28 KB) cites #611's observation that a 34.3 KB file "truncated" in one read. That was Bash's 30,000-character output cap on a `cat`, not the Read tool, which skill prose instructs. `STUB_CEILING_BYTES` (demo 30 KB, feedback 34 KB) pins mode-split stub sizes with no platform basis. The rail replaces both.

## Technical Approach

Deletion, one comment rewrite, and the anti-scatter guard. Delete the exports first, then run the suite to get a first error list. This is **not** exhaustive: CommonJS destructuring of a deleted export yields `undefined` without throwing. `x <= undefined` and `x < undefined` evaluate `false`, so an `assert.ok(bytes <= CEILING_BYTES)` fails loudly, but a differently-shaped comparison (`bytes > CEILING_BYTES` used as a skip condition, say) silently evaluates `false` and passes. So the suite run is a first pass only. Before deleting, audit the comparison direction at each consumer listed in Current State. After deleting, the AC1 grep is the real backstop. Fix each hit by removing the size assertion, or by pointing it at `budgets.js` when the test is genuinely about the rail.

## Gotchas

- Re-merge `origin/main` immediately before the sweep and again before commit. Sibling PRs add new `<= CEILING_BYTES` assertions regularly (the habit this unit ends), and each one merged after your sweep fails at `require` time on `main`. That is exactly the merge-red shape this redesign exists to stop, so do the final re-merge plus full suite right before merge.
- The full suite runs centrally once. Never accept a dispatched agent's self-reported pass count; quote the raw `npm test` tail, redirected to a file (piping through `tail` swallows the exit status).
- A test whose title names the ceiling (e.g. `fork-worktree-isolation-conformance.test.js`'s "stays under the CEILING_BYTES ceiling") needs its title changed along with its body, or AC1's grep still matches.
- `tests/timing-prose-conformance.test.js` aliases the constant (`const CEILING = CEILING_BYTES`). Grep for the alias's uses too, not just the import.
- `git grep -c` counts lines, not occurrences, and exits 1 on zero matches. Use `git grep -n` for the AC sweeps and treat exit 1 with empty output as the pass.
