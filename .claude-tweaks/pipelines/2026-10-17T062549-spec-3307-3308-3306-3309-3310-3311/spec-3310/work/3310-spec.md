# 3310: Cut every skill-size consumer over to the rail, load delta, and size outlier

Surface: infra

## Overview

The **cutover** step of the strangler-fig rollout tracked by parent #3305. Every consumer of the old size model switches to the new one: plan-audit's headroom check moves to the rail, the harness-health bloat scan stops weighing the 50 KB soft ceiling, the PR checklist stops running `merge-size-probe`, and every live rule and instruction that cites `CEILING_BYTES`, "50 KB", "51,200 B" or the composed-bytes ceiling is rewritten to the new model. The decision itself is recorded in a new decision record that supersedes #2020's hard per-`SKILL.md` gate and the per-file ceiling half of decision 0016.

After this unit, nothing under `plugin/skills/`, `docs/` (outside history), `.claude/skills/`, or `plugin/bin/` except `context-cost.js`, `bloat.js`, and `merge-size-probe.js` themselves reads or cites the old ceiling. #3311 (decommission) then deletes those leftovers. This order is deliberate: shipped prose stops calling the `merge-size-probe` CLI one step before the CLI is deleted, so no installed plugin build ever has a skill pointing at a missing binary.

**The new model, stated once for this unit's rewrites.** A size limit blocks only where it guards a platform limit. The rail (`RAIL_BYTES`, `plugin/bin/lib/skill-audit/budgets.js`) sits at 80% of the Read tool's 25,000-token cap and binds every skill file and every composed bundle. Per-invocation cost is shown, not gated: `/review`'s skill load delta (floor/closure per entry point), and `/harness-health`'s transcript-measured load. Coherence is the corpus-relative `sizeOutlier` bloat signal. Composition over fragmentation (decision 0016) still stands: when a file grows, fence condition-specific passages with `when:` markers or compose them; never split into a "read X now" sibling that moves bytes without cutting them.
