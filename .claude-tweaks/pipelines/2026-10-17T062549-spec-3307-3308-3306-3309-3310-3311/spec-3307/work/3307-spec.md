# 3307: Add the per-invocation skill load model and show its delta in /review

Surface: infra

## Overview

Builds the per-invocation load model that replaces raw file size as the cost measure, and shows its delta in `/claude-tweaks:review` as non-blocking information. For each entry point (each `skills/*/SKILL.md` under a plugin root) the model computes:

- **floor**: the `SKILL.md`'s own measured bytes, paid on every invocation;
- **closure**: the floor plus every file reachable from it by citation, transitively, each counted once. This is the upper bound of what an invocation can load.

A PR's delta on both numbers makes splits honest. Moving a section into a sibling file that `SKILL.md` tells the reader to load immediately shows as "floor −10 KB, closure +80 B", a move rather than a cut. Under the old per-file cap the same split looked like a 10 KB win. That false credit grew the corpus from 128 to 471 skill `.md` files (2026-07-01 to 2026-10-16) while total bytes kept rising.

The delta judges only the PR's own diff against its merge-base, so two concurrent PRs can never combine to break it. It is deliberately **non-blocking**. Parent #3305 chose visibility over a gate and records this as an accepted trade-off: nothing forces a slim-down. The delta is a diagnostic shown at review time, and #3309's transcript-measured load in `/harness-health` is the backstop that makes creep visible over time. A hard delta gate was rejected because it adds a mid-flow stop `/flow` must handle in `auto` mode.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- Modeling whether a citation is conditional ("read X when Y"). The floor/closure range is honest without it; a declared load manifest and prose-conditionality parsing were both rejected (parent #3305).
- Counting citations that are not backticked `.md` tokens. Prose must backtick a file to count; #3309's transcript measure surfaces skills whose real reads exceed their closure, which is how a missed citation shows up.
- Any CI gate on load. Nothing in this unit fails a test because a load grew.
- Transcript-measured actual load (#3309, which consumes this unit's `entryPointLoads`).
- Removing anything (`CEILING_BYTES`, `merge-size-probe`, ceiling prose). #3310 and #3311 own that.

## Acceptance Criteria

1. **Citation grammar.** `extractCitations` takes every backticked token ending in `.md`. For each one it tries these rules in order, and the **first rule whose resolved path exists wins**:
   - (a) relative to the citing file's own directory;
   - (b) `{pluginRoot}/skills/_shared/{token}`, after stripping a leading `_shared/` from the token, so `` `_shared/foo.md` `` never resolves to `_shared/_shared/foo.md`;
   - (c) a token starting `${CLAUDE_PLUGIN_ROOT}/`, resolved against `pluginRoot`;
   - (d) only when the line contains "in that skill's directory" or "in the `/claude-tweaks:{name}` skill's directory": the directory of the **nearest preceding** `/claude-tweaks:{name}` token on the same line. With no such token, (d) does not apply.

   A token that resolves under no rule goes into `unresolved` as `{citingFile, line, token}` and is never counted as 0 bytes.
2. **Floor and closure.** On a fixture plugin root, `entryPointLoads` returns, per `SKILL.md`: `entry` (`{rootName}:{skill}`, e.g. `plugin:flow` or `.claude:my-skill`, so same-named skills under two roots never collide), `floor` (that file's `measuredBytes`), `closure` (the sum over the transitive citation set including the `SKILL.md`, each file once), `files` (closure members sorted lexically by repo-relative path), and `unresolved`.
3. **Cycle.** A fixture where `a.md` cites `b.md` and `b.md` cites `a.md` terminates, and each file counts once in the closure.
4. **Compose sources.** A compose call site inside a closure member adds its source files (from `findComposeCallSites`) to the closure. Those sources are themselves walked for citations, transitively, like any other member.
5. **Move-not-cut.** Fixture: a base `SKILL.md` of 20,000 B with no citations; the head moves 10,000 B into `part.md` and adds a one-line "Read `part.md` in this skill's directory" pointer. `loadDelta` reports floor ≈ −10,000 B, and a closure delta equal to the pointer line's byte length (within ±2 B for line endings).
6. **Shared-file fan-out.** A change to a `_shared/*.md` file shows a closure delta on every entry point whose closure contains it, and on no other.
7. **Added and removed entry points.** A `SKILL.md` absent at base appears with `added: true`, its deltas measured from 0. A `SKILL.md` deleted at head appears with `removed: true`, `floor: 0`, `closure: 0`, and negative deltas.
8. **Output shape per status.** With a baseline: `{ status: "ok", base: <sha>, roots: [{ pluginRoot, entries }] }`, where `entries` holds `loadDelta` rows for changed entry points only. With no baseline: `{ status: "no-baseline", base: null, roots: [{ pluginRoot, entries }] }`, where `entries` holds `entryPointLoads` rows. The CLI never prints a delta of 0 as a substitute for a missing baseline.
9. **Exit codes.** 0 on success, including a no-baseline result. 2 on a malformed invocation, including an explicit `--base <ref>` that does not resolve (`git rev-parse --verify` fails), with a message naming the ref. 3 when a `--plugin-root` has no `skills/` directory, with `corpusDir`'s message.
10. **Review 3j renders exactly one of three outcomes.**
    - The diff touches no path under any discovered plugin root's `skills/`: one line, "Skill load delta: no skill files changed — skipped".
    - The diff touches skill files but no entry point's floor or closure changed: one line, "Skill load delta: skill files changed, no entry point's load moved".
    - Otherwise: a table (entry, floor, Δfloor, closure, Δclosure, new unresolved citations).

    3j never changes the review verdict and never skips silently.
11. **Pointer budget.** The `code-mode-steps.md` addition is at most 4 lines and contains a backticked `step3-skill-load-delta.md`.
12. `npm test` passes, and running `node plugin/bin/load-delta.js --json` in this repo exits 0 and lists both `plugin` and `.claude` roots.

## Release Note

Reviews now show how a change moves each skill's always-loaded and worst-case loaded size, so a file split that only moves text no longer looks like a saving.

## Technical Approach

`load.js` is pure over an injected `readFile(path) -> string | null`, so the CLI can feed it either working-tree content or `git show` content. The CLI's base pass reads the merge-base tree, and its head pass reads the working tree. Byte measurement applies `measuredBytes`' logic to text (CRLF-normalize, then `stripMarkers`). Extract a text-level helper from `measuredBytes` rather than duplicating it, and keep `measuredBytes`' file-path signature intact for its existing callers.

`discoverPluginRoots` finds every directory `D` for which `git ls-files 'D/skills/*/SKILL.md'` is non-empty, using a single `git ls-files '*skills/*/SKILL.md'` and taking the parent of each `skills/`. This covers `plugin/` and `.claude/` here, and the equivalent layout in a consumer project, with no hardcoded root list.

### Data / API Surface

```js
// plugin/bin/lib/skill-audit/load.js
discoverPluginRoots(listFiles) -> string[]            // repo-relative roots, sorted
extractCitations(text, citingFile, pluginRoot, { exists }) ->
  { resolved: string[] /* repo-relative paths */, unresolved: Array<{citingFile, line, token}> }
entryPointLoads(pluginRoot, { readFile, listSkillMds }) ->
  Array<{ entry /* "{rootName}:{skill}" */, floor, closure, files: string[], unresolved: [...] }>
loadDelta(base, head) ->
  Array<{ entry, floor, dFloor, closure, dClosure, newUnresolved: [...], added?: true, removed?: true }>  // changed entries only
```

## Gotchas

- Follow the `gh-api-module-pattern` skill for the CLI: argv arrays only, an injectable `git` runner, and `--end-of-options` before ref arguments. In zsh, quote `"${ref}:path"`, never `"$ref:path"`.
- Use `git show <sha>:<path>`. Reading the base by checking it out would disturb a worktree session, and `git stash` is shared across worktrees.
- `git show` of a path absent at base exits non-zero. Treat that as "file did not exist at base" (0 bytes for that file), distinct from the merge-base lookup failing (`no-baseline`) and from an explicit bad `--base` (exit 2). Never let one swallowed error masquerade as another (`parse-signal-discipline`).
- Diff against `origin/{integration-branch}` or the merge-base, never a local `main` ref, which can be stale in a worktree.
- A skill reference in actionable step text must use the fully qualified `/claude-tweaks:{skill}` form.
- Add an edge for the new review sub-file to `docs/skill-graph.md` only if review's existing sub-files appear there. Check before adding.
