# 3309: Report transcript-measured skill load in /harness-health

Surface: infra

**Related:** #2933

## Overview

Adds the empirical half of the per-invocation cost measure. It reads this machine's Claude Code session transcripts (main session and subagents) to find what real sessions actually load per skill invocation, and `/claude-tweaks:harness-health` reports it every firing. The static floor/closure model from #3307 is a bound computed from citations; this unit measures where reality falls, and finds where the static model is blind. A skill whose sessions read more skill prose than its closure contains is citing files in a way #3307's citation grammar misses.

This is the visibility mechanism that parent #3305's accepted trade-off depends on. With no byte cliff, creep is stopped only by attention, and this report makes creep visible over time. The 2026-09-06 footprint audit did this by hand once: a full `/flow` session's main agent read 60–70 skill files (about 1.1 MB) plus about 0.5 MB of injected skill bodies, and subagents read another 22 MB across 40 sessions. Nothing measures that today.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- Any CI gate. Transcripts exist only on a machine that ran sessions; this is a `/harness-health` report.
- Persisting a time series. Each firing reports the window it reads. The filed records and their auto-close comments (below) are the trend trail.
- Changing `plugin/bin/lib/timing/transcript.js`'s exported `readUsage` contract, which `phase-timing.js` consumes.
- Measuring non-skill context such as CLAUDE.md or tool schemas (`harness-cost.js`'s territory, #2933).

- [ ] `plugin/bin/lib/skill-audit/transcript-load.js` (new):
  - `readSkillLoads(filePath, { fsImpl, worktree, kind: 'main' | 'subagent' })` streams one transcript and returns per-invocation rows `{ skill, injectedBytes, readBytes, readPaths: string[] }`.
  - `summarizeLoads(rows)` returns, per skill, `{ skill, invocations, median, max }` over `injectedBytes + readBytes`.
- [ ] **Attribution rules.** Each skill-path Read is attributed to the "current skill" cursor. The cursor is set by the last skill invocation (a `Skill` tool_use or a typed slash-command injection) that precedes the Read in transcript order. When one assistant turn contains several `Skill` tool_use blocks, the last one in block order sets the cursor; this is a documented limitation, not an error. A skill-path Read with no preceding invocation goes to a `(main, unattributed)` or `(subagent, unattributed)` bucket, matching the transcript's `kind`. Nothing is silently dropped. A fork-type subagent transcript is treated like any subagent transcript: its Reads attribute to its own last invocation, else to `(subagent, unattributed)`.
- [ ] **Session enumeration:** the `--sessions <n>` (default 20) most recent main transcripts in the cwd's transcript directory, by mtime, plus every subagent transcript in each one's `{sessionId}/` directory.
- [ ] `plugin/bin/skill-load-report.js` (new CLI): `--cwd <dir>` (default: process cwd), `--sessions <n>`, `--plugin-root <dir>` (repeatable; default: every root `discoverPluginRoots` finds). It outputs one JSON line: `{ status: "ok" | "no-data", transcriptDir, sessions, rows: [{ skill, invocations, median, max, closure, overClosure }] }`. `closure` is joined from `entryPointLoads` in `plugin/bin/lib/skill-audit/load.js` (#3307), matched on the skill name part of its `entry` (`{rootName}:{skill}`), and `overClosure = max > closure`. Rows are sorted by `max` descending, ties broken by `skill` ascending.
- [ ] `plugin/skills/harness-health/SKILL.md`: a "Skill-load check" paragraph next to the composed-bytes check. It runs the CLI every firing and reports the top 10 rows. It files one `by:harness-health` record (`risk:low`, `size:low`) per skill with `overClosure: true`, titled `"Skill load exceeds its static closure: {skill}"`, deduped against open `by:harness-health` records with the same title. On a firing with `status: "ok"` where a skill with an open record of that title was observed (`invocations ≥ 1`) and now has `max ≤ closure`, it comments `Back within its static closure: max {max} B ≤ closure {closure} B over {sessions} sessions` and closes the record. A `no-data` firing, or a skill not observed this firing, never closes anything. Filing and closing are both skipped under `--dry-run`.

## Acceptance Criteria

1. Task 0's recorded shapes appear in `transcript-load.js`'s header, and every fixture in `transcript-load.test.js` names which observed shape it mirrors.
2. A fixture transcript with one `Skill` invocation (injected body 10,000 B) followed by two skill-path Reads (3,000 B and 2,000 B) yields one row `{ injectedBytes: 10000, readBytes: 5000 }` with both paths.
3. Two invocations in one transcript attribute each Read to the invocation that preceded it. Two `Skill` tool_use blocks in one turn followed by a Read attribute it to the second.
4. A Read of a non-skill path (`isProcedurePath` false) contributes 0 bytes.
5. A main transcript with a skill-path Read before any invocation puts those bytes in `(main, unattributed)`. A subagent transcript with no invocation puts its bytes in `(subagent, unattributed)`.
6. With no transcript directory for the cwd (e.g. a cloud sandbox), the CLI prints `{"status":"no-data",...}` with the directory it looked in, and exits 0. It never reports zero load as if measured.
7. `overClosure` is `true` only when `max > closure`. `closure` is `null` (with `overClosure: false`) for a skill the load model does not know, e.g. another plugin's skill.
8. Rows tie on `max` sort by `skill` ascending.
9. `readUsage` and `phase-timing.js` behavior is unchanged (`tests/bin-lib/timing/transcript.test.js` passes unchanged).
10. The harness-health paragraph names the exact CLI command, the top-10 report, the filing title, the dedup rule, the auto-close condition (status `ok`, observed, `max ≤ closure`) with its comment text, and the `--dry-run` skip.
11. `npm test` passes.

## Release Note

Health checks now report how much skill text real sessions actually load per skill, including subagents, and flag skills that load more than their files account for.

## Technical Approach

Reuse `isProcedurePath` and `slugForCwd` from `timing/transcript.js` by import, not by copy. Stream line by line like `readUsage`, since transcripts reach many MB. Attribution is a single cursor per transcript, advanced in transcript (line, then block) order.

## Gotchas

- Claude Code writes one JSONL line per content block of an assistant turn, each repeating the turn's cumulative `usage` under the same `message.id`. This unit sums tool_result bytes, not usage, but attribution must still not double-count a tool_use that appears once per block.
- The transcript directory slug comes from the cwd. A worktree session's transcripts live under the worktree's slug, not the main checkout's. Enumerate from the cwd you are given, and say in the report which directory was read.
- A typed slash command leaves no `Skill` tool_use event (the skill-invocation hook sees only model-initiated calls). Task 0 must confirm how its injected body is recognizable; otherwise those invocations land in the unattributed buckets.
- ASSUMPTION — verify at build: the injected skill body is a user-role text block beginning `Base directory for this skill:` — confirm via Task 0's transcript inspection before writing any parser for it.
- ASSUMPTION — verify at build: subagent transcripts live in `~/.claude/projects/{slug}/{sessionId}/` as `.jsonl` files (the header of `timing/transcript.js` states it) — confirm via Task 0 and record the observed filename pattern.
- ASSUMPTION — verify at build: `plugin/bin/lib/skill-audit/load.js` exports `entryPointLoads` and `discoverPluginRoots` with #3307's documented shapes — confirm via `git grep -n "entryPointLoads\|discoverPluginRoots" -- plugin/bin/lib/skill-audit/load.js` once #3307 lands.
- Transcript contents are untrusted. Never echo raw excerpts into a filed record or comment. Only skill names, byte counts, and paths under a skills directory go into reports.
