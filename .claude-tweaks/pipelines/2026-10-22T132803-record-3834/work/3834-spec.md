# 3834: Stop flipLedgerRow dropping a duplicate-numbered ledger row on write-back

Origin: ledger resolve gate (#3510 final whole-branch review, I3 follow-up)

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/bin/lib/wrap-up/ledger-write.js`'s `parseLedgerTable` keys rows by item number in a `Map`, so a ledger table holding two rows with the same number collapses them on parse. `serializeLedgerTable` then writes only the survivor back. `flipLedgerRow` (used by `finish-console` and `delete-ledger`) therefore silently drops a duplicate-numbered row the next time it flips any row in that ledger. #3510's `stage-item.js --ledger` refuses to append to such a ledger (`LEDGER_UNSAFE`), but the pre-existing write-back path still loses the row.

## Deliverables

- [ ] Make `parseLedgerTable`/`serializeLedgerTable` (or `flipLedgerRow`) preserve duplicate-numbered rows, or refuse the write-back with a logged degrade instead of dropping a row.
- [ ] Add a test with a two-row `| 1 |` fixture proving no row is lost across a `flipLedgerRow` round-trip.

## Acceptance Criteria

A `flipLedgerRow` call on a ledger with two rows numbered `1` either keeps both rows byte-for-byte or fails loudly without writing; the new test fails when the fix is reverted.

## Release Note

Fix: resolving a ledger item at the Review Console can no longer silently drop a second row that shares its number.

## Technical Approach

### Key Files

- `plugin/bin/lib/wrap-up/ledger-write.js` — preserve or refuse duplicate-numbered rows on write-back
