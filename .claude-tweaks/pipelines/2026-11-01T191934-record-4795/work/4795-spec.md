# 4795: Unify the two explicit --repo host-pin mechanisms behind one seam

Origin: ledger resolve gate (wrap-up of #4505)

Defer-reason: genuinely-larger

## Current State

#4505 solves "an explicit `--repo` owns its host" twice. `pinExplicitRepoHost` (`plugin/bin/lib/repo-resolve.js`) mutates `process.env.GH_HOST` once `--repo` is parsed, and 11 CLIs wire it through `realDeps.pinGhHost` plus a `deps.pinGhHost(repoSpec)` call, rostered in `PIN_WIRED` in `tests/gh-host-seam-conformance.test.js`. `plugin/bin/lib/backlog-grant-gate/backlog-grant-gate.js` instead builds a per-call env (`nativeRunnerFor`) and never touches `process.env`.

A process-global pin forces `plugin/bin/materialize.js` to restore the environment it had before the pin (`envBeforeGhHostPin`) before running record-authored shell commands. Unifying the two touches 12 CLIs and materialize's premise-check plumbing, which is why the review deferred it as `genuinely-larger` (ledger row 16 of `docs/plans/2026-10-31-gh-host-seam-ledger.md`, review lens 3e).

## Deliverables

- [ ] Pick one mechanism (a per-call env carried by `ghOptions`, or the process-global pin) and migrate all 12 CLIs to it.

- [ ] Delete the other mechanism and the `envBeforeGhHostPin` restore if the per-call env wins.

- [ ] Update `PIN_WIRED` and the `gh-api-module-pattern` skill's explicit-`--repo` bullet to describe the one mechanism.

## Acceptance Criteria

- [ ] A CLI given an explicit `--repo` on another host sends every gh call it makes (including a call that carries no host flag) to that host, asserted through a recording runner.

- [ ] `plugin/bin/materialize.js` runs a record-authored shell command with the environment the user had, asserted by an exported `GH_HOST` surviving it.

- [ ] `grep -F "pinExplicitRepoHost" plugin/bin -r` shows at most the one mechanism the record chose, and `node --test tests/gh-host-seam-conformance.test.js` passes.

## Release Note

No user-visible change.

## Technical Approach

### Key Files

- `plugin/bin/lib/repo-resolve.js` — collapse the two host-pin mechanisms into one
- `plugin/bin/lib/backlog-grant-gate/backlog-grant-gate.js` — `nativeRunnerFor` onto the chosen mechanism
- `plugin/bin/materialize.js` — drop or keep `envBeforeGhHostPin` per the chosen mechanism
- `tests/gh-host-seam-conformance.test.js` — update the `PIN_WIRED` roster
- `.claude/skills/gh-api-module-pattern/SKILL.md` — describe the one mechanism
