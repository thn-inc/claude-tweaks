# 2933: harness-cost: measureAgentToolCost is never wired into the report, though docs say agent tools: are measured

Surface: infra

## Current State

#2741 added `plugin/bin/lib/skill-audit/harness-cost.js`. Its `measureAgentToolCost(repoRoot)` (lines 81-98) reads each `agents/{name}.md`'s `tools:` frontmatter and returns `[]` when no `agents/` directory exists. The function is exported (`:149`) and covered by `tests/bin-lib/skill-audit/harness-cost.test.js`, but nothing in production calls it. `grep -rln measureAgentToolCost plugin tests` returns only the module itself and its unit test.

`estimateHarnessCost(repoRoot)` (`:120-133`) builds its `entries` from `measureSkillToolCost` alone and returns `{ entries, totalSkills, unscopedCount }`. That function is the one consumed by `plugin/bin/harness-cost-report.js` (header comment `:18-19`: `entries` is "every skill's" record) and by `/claude-tweaks:harness-health`'s Harness cost-efficiency check (`plugin/skills/harness-health/SKILL.md:96-101`, which runs that CLI every firing).

The documentation advertises more than is reported. `docs/plugin-structure.md:23` says harness-cost.js measures each shipped skill's `allowed-tools:` count "(and each agent definition's `tools:`)". In practice `plugin/agents/qa-agent.md` (`tools: Bash`) never appears in any report. #2741's own deliverables named subagents ("so bloated skill or subagent definitions are visible"), so this is unmet scope, not a deliberate omission. The v6.134.0 release review found it (lens 3e, reproduced by both agents).

## Deliverables

1. Make `estimateHarnessCost` include agent definitions via `measureAgentToolCost`, with each entry distinguishable from skill entries (for example a `kind: 'skill' | 'agent'` field). Agent entries carry `tools`, `toolCount` and `overageRatio`. Size the agent file's bytes the same way skills are sized; shared-citation depth can be `null` or omitted for agents if it does not apply. Add an agent count to the summary alongside `totalSkills`.
2. Update `plugin/bin/harness-cost-report.js` so its output and `flagHighToolCount` handling cover agent entries. A high-tool-count agent can then be flagged the same way a skill is.
3. Update `/claude-tweaks:harness-health`'s cost-efficiency check prose (`SKILL.md:96-101`) to say agents are reported alongside skills.
4. Reconcile `docs/plugin-structure.md:23`, and the CLI line at `:128` if it describes output shape, with what is now reported.

## Acceptance Criteria

- `node plugin/bin/harness-cost-report.js --plugin-root plugin` output includes an entry for the `qa-agent` agent definition, marked as an agent rather than a skill.
- A test in `tests/bin-lib/skill-audit/harness-cost.test.js` fails if `estimateHarnessCost` stops including agent entries. Prove it goes red by removing the agent wiring.
- A fixture with no `agents/` directory still produces a valid report with zero agent entries and no error.
- `npm test` passes in full.

## Release Note

The harness cost report now includes subagent tool scopes alongside skills, as its documentation already claimed.

## Technical Approach

Concatenate `measureAgentToolCost(repoRoot)` results into `estimateHarnessCost`'s entries with a `kind` discriminator, then sort the combined list by bytes as today. Check every consumer of `entries` (the report CLI and any test fixtures pinning the JSON shape) before changing the shape. The change is additive, so existing skill-entry fields stay identical.

### Key Files

- `plugin/bin/lib/skill-audit/harness-cost.js` — `estimateHarnessCost`: include agent entries with a `kind` field and an agent summary count
- `plugin/bin/harness-cost-report.js` — report and flag agent entries; update the output-shape header comment
- `plugin/skills/harness-health/SKILL.md` — cost-efficiency check prose (96-101)
- `docs/plugin-structure.md` — reconcile lines 23 and 128 with the reported shape
- `tests/bin-lib/skill-audit/harness-cost.test.js` — agent-inclusion and no-agents-directory tests

## Gotchas

- `agents/` is a flat directory of `{name}.md` files, unlike `skills/{name}/SKILL.md`. Do not reuse `measuredBytes(path.join(dir, name, 'SKILL.md'))` for agents.
- `totalSkills` keeps meaning skills only. Add a separate agent count rather than changing its meaning, since harness-health's prose and any downstream reader treat it as a skill tally.
- `MINIMAL_BASELINE_TOOLS` was calibrated as a skill baseline. Note in the report or docs whether the same four-tool baseline is meaningful for agents (`qa-agent` declares `Bash` only) rather than implying an equivalence nobody validated.
