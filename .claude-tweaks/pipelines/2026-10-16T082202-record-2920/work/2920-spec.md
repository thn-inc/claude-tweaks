# 2920: Bookkeeping-stamps gate blocks the Write of the PR body file needed to open the PR it demands

Surface: infra

## Current State

In an `integration-model: pr-first` run, after the materialize commit and before a PR is recorded, `checkBookkeepingStampsGate` (`plugin/bin/lib/hooks/pre-tool-use.js:1566`) denies every covered file-tool write with "no PR is recorded for this run". A 6.129.0 run hit this twice: first on a plan file, which is correct because the gate exists to block implementation writes before the PR, and second on the scratch PR-body file the agent composed in a **gitignored directory inside the worktree** before calling `gh pr create --body-file`. That second denial is a deadlock: the gate demands the PR while blocking the file needed to open it.

Checked against the tree:

- The PR-body path documented in `plugin/skills/_shared/pr-early-run-lifecycle.md:315-325` is `/tmp/pr-early-body-{run-id}-{n}.md`. Since #1678 (v6.114.1), the stamps gate's file-tool branch already exempts a target that is provably not inside any git repo (`pre-tool-use.js:1636-1690`). So the documented `/tmp` path is not blocked on POSIX.
- A **gitignored path inside the worktree** has no such exemption in this gate. `isStampsGateExemptTarget` (`pre-tool-use.js`) exempts only `isPipelineBookkeeping` and `isPolicyFile` targets. The sibling worktree-required gate already exempts gitignored targets through `isUntrackedOrIgnored` (#1395, `pre-tool-use.js:278` and its call site near `:914`, which leaves a `gate-exempt-gitignored` breadcrumb). The two gates therefore disagree on the same path class. A gitignored file cannot land on the branch (no `git add -f` without an explicit commit, which the gate's own git-write branch still covers), so it cannot affect what the PR stamp protects.

## Deliverables

1. Extend `checkBookkeepingStampsGate`'s exemptions to cover a target that `isUntrackedOrIgnored(repoRoot, targetPath)` proves gitignored in its own repo. Reuse the existing helper, keep its fail-closed behavior (absolute path only; indeterminate or not-ignored stays denied), and leave the same `gate-exempt-gitignored` breadcrumb the worktree-required gate writes.
2. Add tests to `tests/hooks-bookkeeping-stamps-gate.test.js`:
   - with no PR recorded, a Write to a gitignored path inside the worktree is allowed, and a breadcrumb is written;
   - with no PR recorded, a Write to a tracked or not-ignored path is still denied;
   - a relative target path is still denied.

## Acceptance Criteria

- In a pr-first run with a materialize commit but no recorded PR, a `Write` to a gitignored file inside the run's worktree is allowed by `checkBookkeepingStampsGate`, and a `gate-exempt-gitignored` event is appended.
- In the same state, a `Write` to a tracked or not-ignored file in the worktree is still denied with the existing "no PR is recorded" message.
- The new cases in `tests/hooks-bookkeeping-stamps-gate.test.js` cover both outcomes plus the relative-path fail-closed case.
- `npm test` passes in full.

## Release Note

Fixed the pre-PR bookkeeping guard blocking writes to gitignored scratch files, which could stop an agent from writing the draft PR body.

## Technical Approach

Add the `isUntrackedOrIgnored` check to `isStampsGateExemptTarget`, or alongside its call site at the end of the file-tool branch, so it runs after the foreign-target scoping and before the stamp checks. The helper already handles absolute-path-only and git-error fail-closed cases. Match the breadcrumb shape the worktree-required gate uses so `/tidy` or an operator can audit both gates' gitignored allows the same way.

### Key Files

- `plugin/bin/lib/hooks/pre-tool-use.js` — `isStampsGateExemptTarget` / `checkBookkeepingStampsGate`: add the gitignored-target exemption with a breadcrumb
- `tests/hooks-bookkeeping-stamps-gate.test.js` — gitignored-allow, tracked-deny and relative-deny cases

## Gotchas

- This repo has a project skill for exactly this kind of change, `pre-tool-use-gate-exemptions`. Follow its discipline for adding a scoping exemption to these deny gates.
- Keep the exemption limited to file-tool writes and gitignored targets. Do not widen it to "untracked" in general: `isUntrackedOrIgnored`'s own header (#1395) explains why untracked-but-not-ignored stays gated.
- ASSUMPTION — verify at build: the 6.129.0 incident's PR-body file sat in a gitignored worktree directory rather than at the documented `/tmp` path, and nothing else (for example Windows resolving `/tmp` inside the repo) caused that denial. `pr-early-run-lifecycle.md:316-317` already notes that `Write` and `Bash` can resolve `/tmp` differently on Windows. Check this against the gate's foreign-target branch on a Windows path before closing.

## Original request

Bookkeeping-stamps gate blocks the Write of the PR body file needed to open the PR it demands

## Observation

In an `integration-model: pr-first` run, after the materialize commit lands and before a PR is recorded, `checkBookkeepingStampsGate` (`bin/lib/hooks/pre-tool-use.js`) denies every covered `Write`, with "no PR is recorded for this run — build/worktree-setup.md Step 6 … is non-skippable". That includes the `Write` of the PR body file that `_shared/pr-early-run-lifecycle.md` Step 3 tells the agent to compose before `gh pr create --body-file <file>`.

So the gate demands the draft PR while blocking the file needed to open it. Observed in plugin 6.129.0 with two denied writes: a plan file, then the scratch PR-body file in a gitignored worktree directory. The run only got unblocked by piping the body through `gh pr create --body-file -` (stdin heredoc) and then `hooks.js record-pr`.

Cost: two denied writes and one re-composition of the PR body. An agent that doesn't think of stdin may instead log the "FAILED" degrade line and continue PR-less.

## Suggested change

Either of these:

1. Exempt paths that cannot affect the branch the stamp protects: gitignored scratch dirs, `/tmp`, the run dir.
2. Have `pr-early-run-lifecycle.md` Step 3 compose the body via stdin (`gh pr create --body-file -`) by default, so the documented procedure never needs a covered write before the PR exists.
