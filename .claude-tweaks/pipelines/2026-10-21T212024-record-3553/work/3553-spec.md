# 3553: Add a hooks.js check-pass-reentry verb so the review-console re-entry check needs no node -e snippet

Origin: reflect full from #3497

Defer-reason: tangential

## Current State

`plugin/skills/flow/multispec-review-console.md`'s "Re-entry after the parent session ended" step 2 (#3497) runs the authoritative eligibility gate as a `node -e` snippet: `require('${CLAUDE_PLUGIN_ROOT}/bin/lib/flow/consolidated-pass.js').checkPassReentry(process.argv[1], { online: true, sessionId: … })`.

Its first form inlined the run-dir path into the script text. Code review on #3497 caught the quoting hazard, and the fix (b728bc6f7) passes the path as `process.argv[1]` and adds a fail-closed rule for non-JSON output.

The house pattern for a prose-side run-dir check is a `hooks.js` verb taking an anchored `--run <dir>`: `check-resume-freshness`, `check-staged-inventory` and `check-session-residue` work this way (docs/hooks.md, "An explicit `--run <dir>` must be *anchored*"). A verb gets anchoring, exit-code semantics and a JSON contract for free.

## Deliverables

- `plugin/bin/hooks.js check-pass-reentry --run <dir> [--online]` prints `checkPassReentry`'s verdict JSON. It passes the caller's `CLAUDE_CODE_SESSION_ID` as `sessionId` and runs the same `--run` anchoring as the other verbs. It exits non-zero on an unanchored run dir.
- `multispec-review-console.md`'s re-entry step 2 calls the verb instead of the `node -e` snippet. `docs/hooks.md`'s list of `--run`-accepting subcommands names it.

## Acceptance Criteria

- A test runs `hooks.js check-pass-reentry --run <fixture>` and gets the same verdict JSON as `checkPassReentry` for an eligible and an ineligible fixture. A test with an unanchored `--run` exits non-zero.
- `tests/flow-pass-reentry-conformance.test.js` pins the verb invocation in the re-entry section, and no `node -e` remains in that section.

## Release Note

The multi-spec review-console re-entry checks eligibility through a `hooks.js` verb instead of an inline script.

## Build deviations (Beneficial, /build Common Step 4.5)

- **`--run` is mandatory.** A call without `--run` exits 1 (`requires --run`) instead of falling back to a guessed run dir, following `record-worktree`'s no-guess rule (#1124).
- **Stdout carries only the verdict.** On exit 0, stdout is exactly one JSON line. Every refusal, the worktree-local-fallback notice, and any thrown error go to stderr and exit 1, so the skill's "stdout that is not that JSON is a stop" rule cannot misread a notice as a verdict.
- **Typo'd flags are caught.** The verb sits in `KNOWN_FLAGS`, so a misspelled flag such as `--onlin` prints the usage line, which is not JSON, rather than silently running offline.
- **Documented exception.** `docs/hooks.md` names `check-pass-reentry` alongside `close-run` and `resolve-console` as the verbs whose refusal exits 1.
