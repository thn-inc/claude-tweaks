# 3664: wrap-up Section D kills the recorded pid without validating it and has no branch for a port still held after the kill

Origin: reflect full mode from #3021 (review lens findings 3b/3c, both agents of each pair)

Defer-reason: tangential

**Related:** #3656, #3657

## Current State

`plugin/skills/wrap-up/cleanup-procedures-execution.md` Section D steps 2-4 stop the server `ephemeral-server.txt` names. Step 2 hands the recorded `{pid}` to `kill {pid}` (and `kill -- -{pid}` on `detached:yes`) without checking it is a positive integer, so a truncated or hand-edited record such as pid `0` or `-1` signals the caller's own process group. Step 4 says "Confirm the port is free, then delete `ephemeral-server.txt`" but defines no outcome when the port is still held after the kill (a leader-only stop under `detached:no`), so a literal reading deletes the only record of a server that is still live and wrap-up never stops it. A stale pid reused by an unrelated process is killed the same way. #3021's fix-wave coordination (`review/step3-routing.md`) now routes a mid-review stop through these same steps, so the exposure is reached up to four more times per review; that coordination guards the cases on its own side, and the root cause stays here.

## Deliverables

1. Section D validates the record before step 2 acts: fewer than four fields, a pid or port that is not a positive integer, or no trailing `detached:` token is unprovable, so log it and stop nothing.
2. Step 4 defines the port-still-held outcome: keep the record, log it, and report a cleanup failure instead of deleting the file.
3. A conformance test pins both rules and goes red against the current text.

## Acceptance Criteria

- A record whose pid is `0`, `-1`, or non-numeric makes Section D log the condition and signal nothing.
- When the port is still held after the kill, `ephemeral-server.txt` is not deleted and the cleanup report names the survivor.
- `npm test` passes in full.

## Release Note

Pipeline cleanup no longer signals a corrupted pid and no longer forgets a test server it failed to stop.
