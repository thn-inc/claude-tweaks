# 3554: Re-entry banner uses the # sigil under work-backend: local-files — share one work-backend reader

Origin: ledger resolve gate — #3497 run ledger row 14 (SDD final review M4)

Defer-reason: genuinely-larger

## Current State

`plugin/bin/lib/hooks/session-residue.js`'s `collectStaleRuns` (#3497) appends ` — consolidated pass never ran: PIPELINE_RUN_DIR="{dir}" /claude-tweaks:flow #{ids} review-console` to an eligible multi-spec run's banner line, always with the `#` sigil.

Under `work-backend: local-files` the record-reference grammar drops the sigil (`_shared/record-batch-input.md`; `plugin/skills/flow/SKILL.md`'s Input table), so the pasted command names records the backend does not resolve as written.

The banner path cannot read the backend without a third copy of the CLAUDE.md `work-backend:` parser. `WORK_BACKEND_RE` and its reader already exist twice: `plugin/bin/lib/hooks/pre-tool-use.js:77` (`readWorkBackendValue`) and `plugin/bin/lib/wrap-up/pack.js:51`. #3497's SDD final review raised this as M4, and ledger row 14 ruled it out of that record's scope.

## Deliverables

- One shared, read-only `work-backend` reader under `plugin/bin/lib/` (CLAUDE.md `work-backend:` line → value or null, never throws). `pre-tool-use.js` and `wrap-up/pack.js` migrate to it, and their local regex copies are removed.
- `collectStaleRuns` uses it: under `local-files` the re-entry suffix lists bare ids (`11,12`), and under any other or unreadable backend it keeps `#11,#12`.

## Acceptance Criteria

- A session-residue test with a `local-files` CLAUDE.md fixture shows the suffix as `/claude-tweaks:flow 11,12 review-console`. The existing `github-issues` fixture keeps `#11,#12`.
- `git grep -n 'work-backend:\s' -- plugin/bin` finds the pattern only in the new shared reader, and the existing pre-tool-use and wrap-up pack tests still pass.

## Release Note

The session-start re-entry command for an unfinished multi-spec run uses bare record ids in projects that keep records as local files.
