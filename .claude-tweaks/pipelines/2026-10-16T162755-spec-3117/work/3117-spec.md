# 3117: build / deferral-gate: the quoted surgical-changes rule and the deferral gate disagree on a pre-existing defect in an in-diff file

Surface: infra
**Related:** #2733, #2734, #2775, #2783, #2821, #2869, #2877, #2912, #2970, #3003, #3004, #3031, #3047, #3048, #3065, #3079

## Current State

Two shipped rules give an agent conflicting guidance on a pre-existing defect found in a file the build's diff touches, and neither says how they compose:

- `plugin/skills/build/SKILL.md:223` ("Scope and edit discipline") quotes the Working Approach sentence into every implementer dispatch: "a pre-existing bug you notice is a follow-up to report, not a fix to fold in, unless the task cannot work without it." The paragraph's own routing clause then sends a reported follow-up to the open-items ledger (blocking) or `/claude-tweaks:capture` (non-blocking), per Common Step 4, without naming the deferral gate.
- `plugin/skills/_shared/deferral-gate.md` "Bad reasons to skip a fix" says "if the file is in this build's diff, it is in scope", and its `Defer-reason:` vocabulary defines `pre-existing-outside-diff` as "a defect in a file this build's diff does not touch". `plugin/skills/review/step3-routing.md:105` routes the same reason the same way.

Observed in one `/flow` run (plugin 6.138.0): a review agent classified a pre-existing mismatch in two in-diff files as `pre-existing-outside-diff`, a reason reserved for files outside the diff. It then asked the parent to choose which rule governs, and the controller had to rule (it applied the gate and fixed the mismatch). Later phases of the same run deferred five similar in-diff items citing only "pre-existing", which the gate does not accept.

## Deliverables

1. `plugin/skills/build/SKILL.md` "Scope and edit discipline": add one sentence **outside** the quoted Working Approach text, stating that the quoted rule limits what an implementer changes mid-task and does not decide the reported follow-up's disposition. The follow-up is routed through `_shared/deferral-gate.md`'s fix-now test before it reaches the ledger or `/claude-tweaks:capture`.
2. `plugin/skills/_shared/deferral-gate.md` "Bad reasons to skip a fix": add a bullet saying that a reported pre-existing defect in an in-diff file goes through the fix-now test like any other finding, and that "pre-existing" alone is not a defer reason. Only `pre-existing-outside-diff` (a file the diff does not touch) can defer on pre-existence.
3. Extend the existing conformance tests to pin both new sentences: `tests/working-approach-scope-discipline.test.js` for the build paragraph and `tests/deferral-gate-conformance.test.js` for the gate bullet.

## Acceptance Criteria

- [ ] `plugin/skills/_shared/deferral-gate.md`'s Bad reasons list includes a bullet saying "pre-existing" alone is not a defer reason for a defect in an in-diff file.

## Release Note

Clarify that a pre-existing defect in a file the build touches goes through the deferral gate's fix-now test, so "pre-existing" alone no longer defers it.

## Technical Approach

Two prose additions plus the tests that pin them. The quoted Working Approach sentences in the build paragraph are pinned byte-for-byte against the init template and this repo's CLAUDE.md, so the new composition sentence goes after the quote and next to the existing routing clause ("A follow-up an implementer reports is this skill's to route..."), never inside it. The new deferral-gate bullet follows the existing "Out of scope of this plan / spec" bullet, which already states the in-diff rule.

### Key Files

- `plugin/skills/build/SKILL.md` — add the composition sentence after the quoted Working Approach text in "Scope and edit discipline"
- `plugin/skills/_shared/deferral-gate.md` — add the "pre-existing alone is not a defer reason" bullet to Bad reasons to skip a fix
- `tests/working-approach-scope-discipline.test.js` — pin the new build sentence
- `tests/deferral-gate-conformance.test.js` — pin the new gate bullet

- `tests/working-approach-scope-discipline.test.js` pins the three quoted sentences against `plugin/skills/init/claude-md-template.md` and this repo's `CLAUDE.md` (Update Mode's conformance checker). Editing inside the quote breaks byte-conformance, so the new sentence must sit outside it.
- Do not change `DEFER_REASONS` or the `pre-existing-outside-diff` definition. The defect is that the reason was misapplied, not that the vocabulary is wrong.
