# 3515: flow-preflight classifies a self-minted run dir as case 3 when a sibling session's hook events land in it first

# Ledger item #1 — record proposal

Origin: ledger Phase 2 narrowing on #3401 (row 1)

Defer-reason: genuinely-larger

## Current State

`bin/flow-preflight.js` classifies a run directory as case 3 (adopted, pre-existing) whenever its `events.jsonl` is non-empty. On run `2026-10-17T190411-spec-3401` the self-minted directory held two `gate-exempt-gitignored` events before `config.yml` existed — both attributed from a sibling session's worktree (`dispatch-record-3405`) by the hook's fallback run-dir resolver — so a fresh mint was classified as an adoption. `/flow` Step 3 recovered by hand (treated it as case 2, wrote `config.yml` from the precedence chain, appended `decisions.md`), but nothing mechanical distinguishes "events this run produced" from "events a sibling misattributed here".

Cross-run event attribution to an empty mint is the hazard `flow/claim-targets.md` already names. The fallback resolver in `bin/lib/hooks/run-dir-resolve.js` picks the most recent matching run dir when `PIPELINE_RUN_DIR` is unset in the hook's environment, which a sibling session's subagent shell routinely is. Refs #3401 (ledger row 1).

## Deliverables

`bin/flow-preflight.js` case classification treats `events.jsonl` as adoption evidence only when at least one event carries this run's own worktree or session (the `worktree`/`sessionId` fields `run-state.json` records), or when `config.yml` exists; an events file holding only foreign-attributed events classifies as case 2 and is reported as such in `preflight.json` (`eventsForeign: N`).

`bin/lib/hooks/run-dir-resolve.js`'s fallback never selects a run dir whose `run-state.json` names a different `worktree` than the hook's own resolved toplevel; when no run dir matches, it drops the event with a `sweep:`-style diagnostic to stderr instead of attributing it to the newest mint.

`tests/bin-lib/flow-preflight/*.test.js` and `tests/bin-lib/hooks/run-dir-resolve.test.js` each gain the foreign-events fixture: a freshly minted dir with two events from another worktree classifies case 2, and the resolver refuses the cross-worktree attribution.

Build note (Common Step 4.5, Beneficial deviations, auto-applied):
- **The claim-log-only-mint skip applies to every hook resolution, not just the event-attribution fallback.** That covers E1's `runDir` as well as `ownedRun`. The incident's own `gate-exempt-gitignored` line is written to the non-strict `ctx.runDir` (`pre-tool-use.js`), so a fallback-only guard never stopped it. The other-worktree guard stays strict, `ownedRun` only, so E1 still resolves a worktree-bound run from the main checkout.
- **The drop diagnostic is one stderr line per hook process, printed at the dispatcher (`hooks.js`):** `attribution: no run dir attributed — no fallback run dir matches {cwd}; skipped {list}`. It is not a per-event line, and it does not claim that events were dropped.

## Acceptance Criteria

`node plugin/bin/flow-preflight.js --run {fresh-mint-with-foreign-events}` reports `case: 2` and `eventsForeign: 2`; with one own-worktree event it reports `case: 3`.

The hook resolver test fails when the worktree guard in the fallback is removed.

`npm test` passes in full.

## Release Note

Flow: a freshly minted run directory is no longer mistaken for an adoption because a sibling session's hook events landed in it first.
