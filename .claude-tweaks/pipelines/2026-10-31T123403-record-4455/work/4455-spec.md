# 4455: Write gate models bash only, so zsh-only and variable-built redirect targets resolve nothing

**Related:** #4303

Origin: /claude-tweaks:build of #4303 (run 2026-10-25T143627-spec-4303), SDD Task 1 minors

Defer-reason: tangential

## Current State

The redirect scan in `plugin/bin/lib/hooks/git-command.js` reads `N>&word` as bash does: an fd duplication when the word is a digit, otherwise a file for N of 1. Two shapes slip through:

- **zsh:** zsh writes the file for `2>&f`, `0>&f` and `>>&f`, where bash errors or duplicates. The scanner resolves no target. Claude Code's Bash tool runs the user's shell, and on this machine that is zsh, so the gap is reachable.
- **Variable-built target:** with `V='&2'; echo x >$V`, bash creates a file named `&2`, but the scanner reads it as fd duplication and resolves no target.

## Deliverables

1. Decide whether the gate models the shell the Bash tool actually runs. Probe and document which shell that is.
2. If zsh is in scope, read zsh's `N>&file` forms as file targets.
3. Treat an unquoted `$VAR` redirect word as an unknown target, failing closed in opted-in sessions.
4. Pin both shapes.

## Acceptance Criteria

- The shell the Bash tool runs is documented, with a probe.
- Each shape is denied from a worktree of a worktree-always repo wherever that shell writes into the main checkout.
- The four scanner suites pass.

## Release Note

The worktree-always guard now covers zsh-only redirect forms and redirect targets built from a variable.
