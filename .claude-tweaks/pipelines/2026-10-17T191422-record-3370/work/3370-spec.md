# 3370: Unattended Review Console: pending and contested items vanish into the archived run, never shown to a human

Origin: /claude-tweaks:feedback self-reference stop (this repo is claude-tweaks), from the #2821 leftovers review; refs #2821

Defer-reason: genuinely-larger

## Current State

At `autonomy: unattended` with `consoleAutoResolve`, `plugin/bin/lib/console/resolve.js`'s `classifyStagedItem` routes a staged file it cannot classify to Pending review (`unmapped-prefix`, or `non-tangential-category:{c}` for a convention/observation reflect finding), and Contested findings to `keep-staged`. By design none of these is auto-applied.

The run then closes and wrap-up archives its directory to `.claude-tweaks/pipelines/archive/`. The only later surfacing, SessionStart's approvable-run notice (`plugin/bin/lib/hooks/session-residue.js` `collectApprovableStandalone`, called from `session-start.js:139`), scans only un-archived `*-(tidy|sweep)-standalone` runs. A spec or record run's pending items therefore drop out of sight for good.

Observed on #2821 (run `2026-10-16T210949-spec-2821`): `reflect-1.md` (convention), `review-13-record.md` (unmapped prefix, a non-canonical name for a record proposal) and `review-debate-deviation.md` (contested, a human decision) all went unseen. A sibling session's wrap-up found two by chance; the third surfaced only when the user asked why work was still open. That session had a live human (it asked the merge question), but the merge question did not carry the pending items.

## Deliverables

1. When an unattended console resolves with any Pending review or Contested item, carry those items into the human-facing stop the run still has (the merge-authorization ask, or the Pipeline Summary's residue section), not only `console.json`.

2. Before a run with unresolved pending or contested items is archived, either file each as a work record (the shape a Queue write takes, with its Defer-reason) or keep the run discoverable: extend the SessionStart approvable-run scan to archived pipeline runs whose `console.json` lists `pending`/`keep-staged` resolutions. The scan considers the newest 200 run names only (an unbounded read of the archive cost about 150-300 ms per SessionStart); when it cuts candidates off, the banner says so and offers `console-residue.js --ack-all`, and older residue stays reachable through `console-residue.js --run <dir>`.

3. Make an unmapped staged prefix fail loud at staging time: `stage-item.js` warns when the id matches no `SECTION_MAP` row, so a producer that invents a name finds out then, not at the console.

## Acceptance Criteria

- A fixture unattended run with one `unmapped-prefix` item and one contested item, archived after merge: the next SessionStart (or the run's own final human stop) names both items with a paste-ready command to act on them.

- `stage-item.js --id review-13-record` prints a warning naming the unmapped prefix and the nearest canonical prefixes; a canonical id prints nothing.

- No pending or contested item is ever auto-applied by this change.

- `npm test` passes, including tests for the archived-run scan and the staging-time warning.

## Release Note

Staged items an unattended run could not resolve on its own are now shown to you before the run closes, instead of disappearing into the archive.

## Architecture alignment (build, Common Step 4.5)

Beneficial deviations applied to this build-time spec (the live record body is unchanged):

- **Acknowledgement path.** Deliverable 2 names no way to dismiss surfaced residue, so a SessionStart banner would repeat forever. Built: `plugin/bin/console-residue.js --ack --run <dir>` / `--ack-all`, which writes an additive `residueAcknowledgedAt` field into `console.json`. The `--run <dir>` form prints the same block the Pipeline Summary renders. Nothing pending or contested is applied.
- **Wider discovery.** The scan also covers clean, not-yet-archived runs (the window between close and reconciler archival) and multi-spec `spec-*/console.json`, not only `archive/`.
- **Accurate staging-time wording.** The `stage-item.js` warning says the item routes to Pending review *if a wrap-up Review Console resolves this run*. Some producers (`release-held`, `dispatch-target-missing-*`) stage into run dirs that never reach `console-resolve.js`.
