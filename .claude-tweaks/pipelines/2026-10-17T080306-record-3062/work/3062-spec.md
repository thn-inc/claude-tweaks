# 3062: Feed verify.js --baseline's flaky verdicts into the flaky-allowlist hit counter

Origin: ledger resolve gate
Defer-reason: tangential

## Current State

`verify.js --baseline` (#3043) classifies a failing test file as `baseline-flaky` when it fails in the full run but passes when re-run alone at HEAD, and prints one `CAVEAT: baseline-flaky:` line. The verdict goes nowhere else:
- It is never counted into the count stamp's `flakyHits`. That is the counter #1925's allowlisted retry feeds, and it drives the five-hit `flaky-allowlist` escalation caveat.
- It never stages a proposal to add the file to `.claude-tweaks/verify-scope.json`'s `flaky.files`.

A file that keeps passing only in isolation is therefore invisible beyond each run's own CAVEAT.

Evidence: #3043's final whole-branch review follow-up I3 (ledger row 17). In the live runs, `tests/bin-lib/gif/palette.test.js`, `tests/bin-lib/hooks/reconcile-background.test.js` and `tests/bin-lib/file-lock.test.js` each landed as baseline-flaky.

## Deliverables

- [ ] Count every `baselineAdjudicated.flakyPassed` file into `flakyHits` exactly as a retried allowlisted file is counted, in the count stamp's existing shape.
- [ ] A file whose hits reach the escalation threshold without being on `flaky.files` stages a `flaky-allowlist` proposal for the Review Console. It is never applied silently.

## Acceptance Criteria

- [ ] After two adjudicated runs in which the same file is baseline-flaky, the count stamp's `flakyHits` holds that file at 2.
- [ ] At the threshold, a staged allowlist proposal names the file and its hit count, and `.claude-tweaks/verify-scope.json` is unchanged until the proposal is approved.
