**Related:** #4596, #2713, #4442, #4492, #4505, #4549, #4554, #4559

## Current State

tidy Step 4's Plan retention (`plugin/skills/tidy/scan-procedures.md`, #4465, closed) asks the model to compute, by hand, per plan: a first-add commit date (`git log --diff-filter=A --format=%cs -1 -- {plan}`, `scan-procedures.md:57` on `origin/main`), a 7-day cutoff comparison, a pre-check count against 30, a citation check only once that count reaches 30, an uncited recount, and a decline lookup — across what is by construction 30+ plans (`scan-procedures.md:50-63`).

No `plugin/bin` code computes any of it (probe: `git grep -n -i -e "plans-retention\|plan-retention\|superpowers/plans" origin/main -- plugin/bin` matches only console prefixes (`plugin/bin/lib/console/resolve.js:88`), policy-schema (`plugin/bin/lib/policy-schema.js:200`), and unrelated comments; `plugin/bin/plan-retention.js` does not exist). #4465's review returned 22 findings, 12 of them on that one paragraph (density, unstated edges, failure paths, coverage), and its conformance suite (`tests/tidy-plan-retention-conformance.test.js`) can only pin wording, not the arithmetic.

Tidy's Step 4.5 already delegates the comparable worktree/residue arithmetic to `bin/residue.js` (`scan-procedures.md:97`).

## Deliverables

- A `plugin/bin/plan-retention.js` CLI (lib under `plugin/bin/lib/plan-retention/`) that, given the resolved `superpowers-plans-retention` value and the Step 4 table's would-be-Delete list, prints JSON: each plan's route (`delete` / `keep` / `prune-ask` / `prune-archive`), its first-add date or `uncommitted`, and whether the citation check must run.
- `scan-procedures.md` Step 4's Plan retention list cites the CLI for the cutoff/threshold arithmetic and keeps only the policy meaning in prose.
- Unit tests covering the 7-day boundary, the 30 threshold, the uncommitted fail-closed path, and `ask`'s no-cutoff routing.

## Acceptance Criteria

- `node plugin/bin/plan-retention.js` on a fixture repo with 30 past-cutoff and 1 within-cutoff plan under `keep-forever` routes exactly the 30 to `prune-archive` and the 1 to `keep`.
- With 29 past-cutoff plans it routes all 29 to `keep` and reports `citationCheck: false`.
- An uncommitted plan routes to `keep` under both `keep-forever` and `ask`.
- `scan-procedures.md` Step 4 no longer spells out the `git log --diff-filter=A` date command; it cites the CLI.
- `tests/tidy-plan-retention-conformance.test.js` pins the CLI citation in place of its current `--diff-filter=A` command pin, and `npm test` passes.

## Release Note

/claude-tweaks:tidy computes plan-retention routing with a deterministic helper instead of per-plan prose arithmetic, so large plan archives route consistently.

## Technical Approach

Model the CLI on `plugin/bin/residue.js`: a `run(argv, deps)` seam with an injectable `git` runner, exit `0` on any successful (including degraded) render and `2` only on a malformed invocation. Keep the routing decision a pure function in `plugin/bin/lib/plan-retention/` (inputs: retention value, per-plan first-add date or `uncommitted`, today's date, cited set, decline state) so the 7-day boundary, the 30 threshold, and `ask`'s no-cutoff routing unit-test without a repo; the CLI wrapper does the git probing. Route semantics are the ones `scan-procedures.md:53-56` already states — `prune-after-wrapup` → `delete` unchanged, `ask` → `prune-ask` regardless of age (an uncommitted plan stays `keep`), `keep-forever` → `keep` unless 30 or more uncited past-cutoff plans and no live decline, then `prune-archive` for all of them. AC 1's fixture repo backdates commits via `GIT_COMMITTER_DATE`/`GIT_AUTHOR_DATE` in a temp repo.

## Gotchas

- `tests/tidy-plan-retention-conformance.test.js:116` byte-pins the `git -C "{REPO_ROOT}" log --diff-filter=A --format=%cs -1 -- {plan}` command and `:117` the 7-day sentence; AC 4 removes the command from prose, so update the test in the same change or the suite goes red.
- The citation check (`plan-citation-check.md`) is a model-judged step the CLI cannot perform. The "30 uncited" recount needs the citation results, so the CLI needs either a two-pass shape (first call reports `citationCheck: true` plus the past-cutoff candidates; a second call takes the cited set and recounts) or a cited-set input. Pick one at build and state it in the prose citation.
- Decline memory: today a non-null `decline` or a lookup that exits non-zero routes to `keep` (fail closed). Whether the CLI calls `bin/declined-learning.js lookup` itself or takes the decline state as input, preserve that fail-closed direction.
- The 7-day boundary's exact edge (a plan exactly 7 days old: within or past?) is not stated in today's prose; the unit test fixes it — pick one and state it in the prose so the two cannot drift.
- `%cs` is the committer date in the commit's own timezone; compare dates, not timestamps, or pin the timezone in tests so the boundary test is not flaky across CI's Node 20 runners and local machines.
- A new `plugin/bin/*.js` CLI falls under the repo's bin source-scan conformance suites (spawn options, `--no-optional-locks` on git reads, exit-code conformance) — follow the house CLI wrapper contract from the start.

## Plan Review Clarifications

- Ordering under `keep-forever`: the citation check runs once the pre-check count of past-cutoff plans reaches 30, whatever the decline state; a live or failed decline lookup only turns `prune-archive` into `keep`. This keeps today's observable output (a cited candidate still renders per `plan-citation-check.md` when a decline is live). Spec: "a pre-check count against 30, a citation check only once that count reaches 30, an uncited recount, and a decline lookup". The plan reviewer marked this needs-human; the controller resolved it to Reading A because the alternative was a reordering the plan had introduced, not a reading of the spec, and Reading A changes no Acceptance Criterion.

## Architecture Alignment (build)

- Beneficial deviation: the pure routing function (`plugin/bin/lib/plan-retention/route.js`'s `routePlans`) takes a lazy `lookupDecline` thunk rather than a precomputed decline state. The lookup then runs only when 30 or more uncited past-cutoff plans could stage an archive, and the fail-closed handling (a live entry or a throw keeps every plan) lives in one place; the CLI supplies the thunk over the in-process declined-learning store.
