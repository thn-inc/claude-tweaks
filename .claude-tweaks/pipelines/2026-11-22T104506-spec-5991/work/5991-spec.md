# 5991: Replay archived lens reviewers on any model and effort, and score each arm against the review's confirmed findings

Surface: backend
Risk-flags: none

## Overview

Teaches `tools/review-replay.js` to replay archived **lens reviewers** under chosen arms, and to score what each arm finds against what the archived review found and confirmed. This is the tier arm of the pipeline economy design's Phase 14 (`docs/superpowers/specs/2026-11-18-pipeline-economy-design.md`): how each lens performs on Haiku, Sonnet and Opus, and, using the effort key from the first sub-issue, at each effort. Today the tool replays only the tiebreak judge. The design's evidence is that the two Haiku lenses produced 443 of the 799 confirmed findings, lenses 3b and 3d return nothing over 70% of the time, and no same-lens comparison across tiers exists because each lens has one fixed tier. This record builds the mechanism that makes that comparison: the archived reviewer's own prompt, replayed against the same commits in a clean repository, under each arm. The rewrite is not free of effect: it drops the `[Effort: …]` line, empties `agent-scratch` and swaps the context bundle. So every extraction also writes a control arm at the archived reviewer's own tier and effort, and `score-reviews` reports its fidelity (recall of the archived reviewer's own rows) beside every other arm's result. An arm's numbers are read against the control, not against the archive alone.

**Complexity:** Medium
**Estimated tasks:** 7

## Non-Goals

- Task reviewers and the whole-branch reviewer. That is the third sub-issue, which reuses this record's extraction and scoring.
- Running the replay or deciding any lens's tier. That is a live run made afterwards from an interactive session.
- Rebuilding a lens prompt from today's `plugin/skills/review/step3-lens-dispatch.md`. The replay sends the prompt the archived reviewer was given, so an arm differs from the archive only in model and effort.
- Changing the tiebreak replay's commands, manifest or scoring.

## Current State

- `tools/review-replay.js` has four commands, `baseline`, `extract`, `score` and `counterfactual`, all for tiebreak judges and lens pairing. Its run seam is `run({ argv, deps })` with `deps.fs`, `deps.git`, `deps.writeTree`, `deps.log`, `deps.err` and `deps.pluginRoot`. Exit codes: 0 ok, 1 runtime failure, 2 malformed invocation, 3 not a clean result.
- `deps.writeTree(head, dest)` extracts `git archive head` without `.claude-tweaks/pipelines` (`RUN_RECORDS_DIR`, `tools/review-replay/schema.js`). The result is a plain directory with no `.git`. A lens reviewer runs `git -C <worktree> diff <base>...<head>`, so it needs a repository holding both commits.
- `tools/review-replay/replay.workflow.js` launches one agent per arm × repeat × prompt from a manifest's `arms[].prompts[]`. Each agent is told only `Replay judge {arm}|{repeat}|{name}.` and the path of its prompt file. `score` reads that identity line back (`IDENTITY_RE`).
- Archived lens reviewers: `timing.json`'s `dispatches.items` lists each with `role: "lens reviewer"`, its `agentId` and its `tier`. A probe on 2026-11-21 over this repository's run directories found 2,850 lens-reviewer dispatches, of which 2,764 still have a transcript at `~/.claude/projects/{slug}/{session}/subagents/agent-{id}.jsonl`. The prompt is the transcript's first `user` message. 2,728 of those prompts name a file in the run directory.
- What a recent lens prompt names (run `2026-11-19T154019-spec-5957`, lens 3a): `WORKTREE: {abs path to .claude/worktrees/flow-spec-5957}` with "run every git command as git -C "{that path}""; `SCOPE: git diff {40-hex base}...{40-hex head}`; the spec at `.claude-tweaks/pipelines/{run}/work/{n}-spec.md` inside the worktree; and `CONTEXT BUNDLE: {abs main checkout}/.claude-tweaks/pipelines/{run}/review-ctx/context.md`. Over all lens prompts the run-directory files named are, by count: `review-ctx/context.md` 1,966 (plus 372 under a `spec-N/` member), `work/N-spec.md` 1,559 (plus 230 under a member), and `review-ctx/agent-scratch/{lens}-{a|b}` directories, about 175 to 195 per lens.
- The archived reviewer's reply is the transcript's last assistant text. `tools/pipeline-cost-report/reviews.js` `parseLensReport` (line 140) parses it into severity rows: a `| Severity | Path:Line | Finding | Evidence |` table, a `+N more` overflow row, or `No findings`, and returns null when it cannot parse. `tools/review-replay/counterfactual.js` has `lastAssistantText` (line 74) and the `near` rule: same path, lines within 5 (line 103).
- Confirmed findings: `tools/review-replay/archive.js` `parseDecisions` (line 23) reads each lens's reproduced pairs and tiebreak verdicts from `decisions.md`; `readRun` (line 221) gives a run's recorded base and review head and excludes a run it cannot replay, with a reason from `EXCLUSION_REASONS`.
- `score.js` `transcriptCost` (line 71) totals an agent's usage, deduplicated by `message.id`.

## Deliverables

- [ ] A command `extract-reviews --runs <root> --out <dir> --role lens --arm ... [--arm ...] [--select <run,...>] [--lens <id,...>] [--max-per-lens <n>] [--min-reviews <n>] --transcripts <claude projects dir>`. `--arm` takes `extract`'s grammar, including `effort=`. The output directory must be new or empty, as `extract` requires.
- [ ] Selection: every `lens reviewer` dispatch in the selected runs whose transcript resolves, newest run first, at most `--max-per-lens` per lens when given. Each dispatch that cannot be replayed is listed in the fixture's `excluded` with a reason, never dropped. Reasons: the existing run-level ones, plus `no-transcript`, `no-sha-range` (the prompt names no `base...head` and the run records none), `commit-not-in-clone`, `run-input-gone` (a named run-directory file no longer exists), `unknown-run-input` (the prompt names a run-directory path that is not one of the three kinds below), `unrewritten-path` (after rewriting, the prompt still names an absolute path under the main checkout or any worktree) and `report-unparsed` (the archived reply does not parse, so there is nothing to score against).
- [ ] One clean repository per distinct (run, base, head), shared by that review's lens slots: `git init`, a commit of `base`'s tree, then a commit of `head`'s tree, each extracted as `writeTree` does without `.claude-tweaks/pipelines`, with a fixed author, committer and date so the shas are reproducible. The fixture records the map from each archived sha to its replay sha.
- [ ] Each slot's prompt is the archived prompt with: every archived sha (full or abbreviated, seven characters or more) replaced through the map (an abbreviation matches as a word-bounded prefix of a mapped sha; a hex token of seven or more characters that matches no mapped sha is left unchanged); the worktree path replaced by the clean repository's path; `review-ctx/context.md` copied into the repository's parent folder under the slot's name, with its shas rewritten, and its path replaced; the spec copied as the tiebreak replay already copies it (`specFileCited`; the `work/{n}-spec.md` form and the `spec-N/` member form are the same kind, and the copy sits in the clean repository's parent folder under the slot's name, which the prompt then names); each `agent-scratch` directory replaced by a new empty directory under the output directory; and any line in the resolver's `[Effort: {level} — …]` shape removed, since the arm sets effort on the launch. Nothing else in the prompt changes. The archived reply and verdicts are never written into a repository or a prompt.
- [ ] Outputs: `reviews-manifest.json` with the same `arms[].prompts[]` shape `replay.workflow.js` reads, so the workflow runs it unchanged, plus a `kind: "reviews"` key and its own validator in `tools/review-replay/schema.js`; `reviews-fixture.json` (selection, exclusions, sha maps); and `archived-reports.json` (per slot: the archived reviewer's parsed rows and the run's confirmed findings for that lens). An unmet `--min-reviews` is a shortfall: exit 3 and no arm written; exclusions alone do not change the exit code. Each slot's prompt name is `{run-id}/{lens-id}-{side}`, with `lens-id` and `side` read the way `lensIdOf` (`tools/pipeline-cost-report/reviews.js`) reads them, and `repeat` is set by `--arm` exactly as `extract` sets it.
- [ ] A command `score-reviews --out <dir> --transcripts <workflow dir> [--reference <arm>]`. It identifies each replay agent as `score` does, parses its reply with `parseLensReport`, and reports per arm and per lens: reviews scored; rows by severity per review; recall of the run's confirmed findings for that lens (a confirmed finding is a reproduced pair or a tiebreak-confirmed verdict that `parseDecisions` returns for that lens, with its path and line, and it is caught when a replay row is `near` it; one without a line is counted as `unlocated` and sits outside recall; the `a` and `b` slots of a lens in one run are each scored against the same confirmed set, and a lens's figure aggregates its slots); recall of the archived reviewer's own rows; rows not near any archived row of any lens in that run (`new`); and against `--reference`, the share of the reference arm's rows the arm also raised. Per arm: agents, tokens, minutes (as `transcriptCost`) and `recordedEffort`; with `repeat` above 1, recall is also shown per repeat beside the total.
- [ ] A slot with no reply, an unparseable reply, or an `effort-mismatch` is counted under `notJudged` by reason, never as a review that found nothing. Any `notJudged` exits 3. A reply of `No findings` is a scored review with zero rows. `recordedEffort` and `effort-mismatch` come from the first sub-issue's merged `score.js` change and are reused, not reimplemented.
- [ ] A control arm: `extract-reviews` always adds an arm named `control` that replays each slot at the archived dispatch's own tier (the profile name `timing.json` records, resolved to its model through the profile table) and the effort its transcript recorded. `score-reviews` reports, per lens, the control's recall of the archived reviewer's own rows as `fidelity`, and prints it beside every arm. A user arm named `control` is a malformed invocation (exit 2).
- [ ] The parsers are imported from `tools/pipeline-cost-report/reviews.js` and `tools/review-replay/counterfactual.js`, not copied.
- [ ] `tools/review-replay.js` header comment and `USAGE` cover both commands. A new journey, `docs/journeys/replay-archived-lens-reviews-across-tiers-{n}.md`, walks extract-reviews, the workflow and score-reviews in the same shape as the tiebreak journey.
- [ ] Tests under `tests/review-replay/` with a fixture run directory, two lens transcripts and a small git history, built in a temporary repository with an explicit committer identity.

## Acceptance Criteria

1. On the fixture, `extract-reviews --role lens` with two arms writes one clean repository per review. Inside it, `git log --format=%s` shows exactly two commits and `git diff {replay base}...{replay head} --stat` lists the same files as the archived `base...head` in the fixture history.
2. No written prompt contains the archived base or head sha, the fixture's worktree path, or the fixture's main-checkout path. Each prompt contains the replay repository's path and the replay shas.
3. A fixture lens prompt that names `.claude-tweaks/pipelines/{run}/decisions.md` is excluded as `unknown-run-input`. One that names a context bundle that has been deleted is excluded as `run-input-gone`. Neither produces a prompt file.
4. No prompt file and no file inside a clean repository contains any row text from the archived reply or any `confirmed by tiebreak` line from `decisions.md`, and no rewritten context bundle or spec copy names a path under `.claude-tweaks/pipelines` other than the rewritten ones. The test greps for each.
5. `node tools/review-replay.js score-reviews` on a fixture workflow directory, where one replay reply raises a row 3 lines from a confirmed finding and another raises nothing near it, reports that lens's confirmed recall as 1 of 1 for the first arm and 0 of 1 for the second. A row 5 lines from a confirmed finding is caught and a row 6 lines away is not (`counterfactual.js`'s `NEAR_LINES`, shared with the tiebreak scoring).
6. A replay reply that does not parse is under `notJudgedByReason["could-not-parse"]` and the command exits 3. A `No findings` reply is scored with zero rows and does not affect the exit code.
7. Running `replay.workflow.js`'s exported logic on `reviews-manifest.json` (as `tests/review-replay/workflow.test.js` does for the tiebreak manifest) launches one agent per arm × repeat × prompt with the arm's model and effort.
8. `tests/review-replay/no-plugin-reference.test.js` still passes: nothing under `plugin/` names the new files.
9. `extract-reviews` with one `--arm` writes a manifest with two arms, the given one and `control`, and the control slot for a fixture dispatch archived at tier `standard` (its `timing.json` tier, a profile name) and effort `medium` carries `"model":"sonnet"` and `"effort":"medium"`. `score-reviews` output carries `fidelity` per lens.

## Technical Approach

New modules beside the existing ones, so the tiebreak path is untouched except for CLI wiring: `tools/review-replay/reviews-extract.js` (selection, the clean-repository builder behind a `deps.writeRepo(base, head, dest)` seam, prompt rewriting) and `tools/review-replay/reviews-score.js`. Build the role handling as a small table keyed by role (how to find the dispatches, the range and the archived findings), with only `lens` filled here, so the third sub-issue adds rows rather than branches. Take the range from the prompt's `SCOPE: git diff {base}...{head}`. When there is none, use `readRun`'s recorded base and review head.

## Gotchas

- The context bundle holds the full diff, which is fine to copy. The run directory also holds `decisions.md`, `review-findings.json` and `staged/`, which carry verdicts and must never reach a replay agent. Copy only the three named kinds and exclude every other named run-directory path. Never fall back to leaving the original absolute path in the prompt, because that lets the replay agent read the live run directory.
- The archived reports file sits in the output directory, next to the clean repositories, as `archived-verdicts.json` already does for the tiebreak replay. #5632 (count judges that read outside their tree) covers this exposure for both. Do not widen it: keep archived files out of every repository.
- CI exports `GIT_AUTHOR_*`. Pass the identity and dates explicitly on every commit, in the tool and in the tests.
- The same review can be replayed by several arms. Build each repository once and point every slot of that review at it. Replay agents are read-only by prompt, so repositories are not copied per slot.
- Recall rewards an arm that behaves like the archive: the confirmed set comes from the archived tier's own output, and a `new` row is neither noise nor signal until sampled. State both in the journey and at the head of the score output.
- The replay is coupled to the archived prompt shapes. A later change to the lens prompt template appears as exclusions (`unknown-run-input`, `unrewritten-path`), never as failures. The transcript location is a platform layout this repository does not control, and a layout change reads as `no-transcript`.
- A clean repository holds two commits, so a lens that reads `git log` or `git blame` sees a different history than it did; say so when reading a result. Score output shows scored and excluded counts per lens from the fixture, so a skew toward one era of prompts is visible.
- `replay.workflow.js` does no manifest validation: `reviews-manifest.json` adds `kind: "reviews"` beside the keys the workflow reads, and only the new `schema.js` validator checks it.
- A lens prompt quotes the worktree path inside `git -C "..."` and sometimes inside backticks. Rewrite every occurrence of the path string, not just the `WORKTREE:` line, and rely on the `unrewritten-path` check to catch the rest.

## Plan Review Clarifications

- Decided by the user at plan review: confirmed recall is per slot, summed. Each slot is scored against its lens's confirmed set and the lens figure is the sum, as "the `a` and `b` slots of a lens in one run are each scored against the same confirmed set, and a lens's figure aggregates its slots" says. AC5's "1 of 1" is checked on an extraction that selects one `3a` slot (`--lens 3a --max-per-lens 1`). Not taken: a per-lens union where either side catching a finding counts once.
- Decided by the user at plan review: AC4's "no rewritten context bundle or spec copy names a path under `.claude-tweaks/pipelines` other than the rewritten ones" covers the paths that can leak: an absolute path under the main checkout or a worktree, and any path naming the archived run's own directory. A relative `.claude-tweaks/pipelines/...` mention of another run inside diff text stays as it is, so the replayed reviewer sees the archived diff unchanged. `unrewritten-path` is likewise "the prompt still names an absolute path under the main checkout or any worktree", or the archived run's own directory. Not taken: scrubbing every `.claude-tweaks/pipelines` mention, which changes the diff and excludes more slots.
- Decided by the user at plan review: the control arm is named `control` when every selected slot shares one archived (tier, effort). Otherwise there is one arm per group, named `control.{tier}.{effort}` (`none` for a profile with no effort), because `replay.workflow.js` reads model and effort per arm. `fidelity` aggregates every control arm, and a user arm named `control` or starting `control.` is a malformed invocation (exit 2). Not taken: one `control` arm carrying a per-prompt model and effort, which would change `replay.workflow.js` (a non-goal).

## Build Clarifications (architecture alignment, beneficial deviations)

- The copyable run-directory kinds also include procedure bundles (`context/{name}.md`) and the delta context bundle and scratch (`delta-ctx/context.md`, `delta-ctx/agent-scratch/{name}`), beside the three named above. A probe of 2,970 archived lens dispatches found prompts naming them, and none of them carries verdicts.
- Two exclusion reasons were added. `unlabelled-dispatch`: a lens-reviewer dispatch whose description yields no lens id or side. `no-archived-tier`: its `timing.json` tier is not a profile name. Both are listed in `excluded`, never dropped.
- Each clean repository lives at `repos/{run}--r{k}/repo` (k numbers the distinct base/head pairs within a run). A name built from archived sha prefixes would put those prefixes into every prompt.
- `score-reviews` also reports, per lens, `rowsUnlocated` (severity rows the recall parser could not place at a line) and `confirmedMissingSource` (slots whose unit's `decisions.md` could not be read, which add nothing to recall). Neither case is ever read as a review that found nothing.
