# 3392: dispatch: give the neighbour-in-flight pass an MCP-transport branch

Origin: reflect hindsight from #3278

Defer-reason: tangential

## Current State

The neighbour-in-flight pass in `plugin/skills/dispatch/queue-pull-script.md` (#3278) needs `gh` for its `bot:in-progress` pool list, its `gh repo view` slug, and its claim-blob reads. On a gh-absent firing (typically the cloud Routine sandbox running the headless bare drain, per CLAUDE.md's Stack row) the pool fetch fails, the pass prints its AUTO line and writes no exclusion. `dispatch/mcp-transport.md` records this as a documented gap. So the guard is off in the environment the unattended drain most often runs in, and overlapping records there build concurrently and resolve only at merge through `_shared/pr-first-merge.md`'s Conflict path.

## Deliverables

1. An MCP-transport branch for the neighbour-in-flight pass: list the pool through `list_issues` (label `bot:in-progress`, state open, body included), and read each neighbour's claim through `_shared/issue-claims.md`'s file-blob path.
2. The same fail-open posture as the gh branch: a failed list or read prints one AUTO line and excludes nothing.
3. `dispatch/mcp-transport.md`'s "neighbour-in-flight pool (#3278)" section rewritten from a documented gap to the mapping.

## Acceptance Criteria

- AC1: On a gh-absent firing with a live-claimed neighbour, the queue pull writes a `neighbour-in-flight` exclusion for the candidate.
- AC2: A stale `bot:in-progress` label with no live claim still never excludes, on either transport.
- AC3: A failed MCP list or claim read prints an AUTO line and writes no exclusion.

Unattended dispatch drains in gh-absent sandboxes now also hold back a record while a file-sharing neighbour is mid-build.
