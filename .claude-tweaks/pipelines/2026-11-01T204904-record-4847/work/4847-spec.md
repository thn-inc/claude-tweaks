# 4847: Let a project opt out of /init declaring claude-tweaks in its committed settings

Origin: session removing project-scope claude-tweaks installs across six repos (thn-inc/claude-tweaks PR #4841)

Defer-reason: tangential

## Current State

`/init` Step 14 (`plugin/skills/init/bootstrap/step-14-cloud-routine-parity.md`) treats `claude-tweaks@claude-tweaks-marketplace` as one of two hard requirements: its Detect section always makes it a declaration candidate, and its Apply section always adds it to the project's `.claude/settings.json#enabledPlugins` plus a `claude-tweaks-marketplace` entry under `extraKnownMarketplaces`, then writes the matching `marketplace add`/`update` lines and `PLUGIN_SPECS` entry into `scripts/claude-cloud-setup.sh`.

`/routine`'s fleet check (`plugin/skills/routine/fleet.md`, step 1) confirms the same declaration is present.

There is no way to say "this project relies on a user-scope install of claude-tweaks; don't declare it at project scope." A maintainer who removes the declaration on purpose (done 2026-11-01 across six repos, including this one in PR #4841) gets it re-added by the next `/init` run, and the fleet check reads the missing line as a fault.

## Deliverables

1. A policy key in `.claude-tweaks/policy.yml` (added per the `policy-key-addition` project skill) that turns off claude-tweaks' own project-scope declaration. Default keeps today's behavior.
2. `/init` Step 14 honors the key: when it is off, Detect drops claude-tweaks from the hard-requirement candidates, Apply neither adds nor re-adds the `enabledPlugins` and `extraKnownMarketplaces` entries, and the generated `scripts/claude-cloud-setup.sh` omits the claude-tweaks marketplace lines and `PLUGIN_SPECS` entry. `superpowers@claude-plugins-official` stays a hard requirement.
3. `/routine`'s fleet check honors the key: when it is off, a missing claude-tweaks declaration is not reported as a failure. Instead the check states that cloud firings in this project will not have claude-tweaks installed by the project declaration.

## Acceptance Criteria

- [ ] With the key unset, `/init` Step 14 and the fleet check behave exactly as today. A conformance test pins the default.
- [ ] With the key off, `/init` Step 14's documented Apply output for a project with no claude-tweaks entry leaves `.claude/settings.json` without `claude-tweaks@claude-tweaks-marketplace` or a `claude-tweaks-marketplace` marketplace entry, and the generated setup script has no `claude-tweaks-marketplace` line. A test pins this against the step's template text.
- [ ] With the key off, the fleet check's documented procedure reports the missing declaration as an informational line, not a failure, and names the cloud consequence. A test pins the wording.
- [ ] `superpowers@claude-plugins-official` is still required in both places whatever the key says.
- [ ] `npm test` passes.

## Release Note

Projects that rely on a user-scope install of claude-tweaks can now tell /init not to declare it in their committed settings, so re-running /init no longer adds it back.

## Technical Approach

### Key Files

- `plugin/skills/init/bootstrap/step-14-cloud-routine-parity.md` — Detect/Apply honor the opt-out key
- `plugin/skills/routine/fleet.md` — Fleet check reports, not fails, when opted out
- `plugin/bin/lib/policy-schema.js` — Register the new policy key

## Build Alignment Notes

Beneficial deviations from this spec, recorded at `/build` Common Step 4.5 (kept as built):

1. **The key decides, not the entry.** At `declare-claude-tweaks: false`, a claude-tweaks entry the project already carries stays in `.claude/settings.json` (Step 14's merge is non-destructive), but the generated script still leaves claude-tweaks out. To match, the fleet check prints its informational line whenever the key is `false`, whether or not a kept entry remains, and its Step 5 opt-out "OK" alternative replaces the default one. The line also says fleet routines need claude-tweaks installed in the sandbox some other way. That goes beyond the Deliverable 3 wording; it is there so the honesty check does not report full health for routines that cannot load claude-tweaks.
2. **Files beyond Key Files.**
   - `_shared/policy-schema.md`'s doc row would have breached the Read rail, so its lazy `resolveValue` section moved to `_shared/policy-schema-coverage.md`, and `init/policy-review.md`'s citation was repointed.
   - `init/SKILL.md`'s Anti-Patterns row now names the key.
   - This repo's generated `scripts/claude-cloud-setup.sh` picked up the two template comment changes.
   - This repo's `.claude-tweaks/policy.yml` sets `declare-claude-tweaks: false`, which this repo already does in practice since PR #4841.
