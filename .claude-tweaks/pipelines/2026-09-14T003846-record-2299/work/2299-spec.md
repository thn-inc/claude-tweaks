# 2299: dispatch drain-PR overlap hold (#1985) is invisible to console-resolve.js unattended auto-merge resolution

Defer-reason: genuinely-larger

## Current State

#1985 (unmerged, PR #2298) adds a "Drain-overlap hold" to `plugin/skills/dispatch/settle-and-merge.md`'s Auto-merge gate: before Authorization/Content judgment, `drain-pr-overlap.md`'s Step 6 checks whether this group's PR overlaps a still-open PR opened earlier by the same drain firing, and if so, explicitly **skips Authorization and Content judgment** and "fall[s] back to the normal Review Console for this group," logging:

```
AUTO {time} — Auto-merge gate: group [{issues}] held — overlaps drain PR #{pr} on {files}; merge order is a human call. Reversibility: n/a.
```

Separately, `plugin/bin/lib/console/resolve.js`'s `needsHumanVerdict()` (the ONLY mechanism `mergeResolution()` consults to decide `leave-open` before falling through to a plain grant check) is:

```js
function needsHumanVerdict(decisions) {
  return decisionLines(decisions).find((l) => /needs-human/i.test(l) && /merge-check|assess-agent-autonomy/i.test(l)) || null;
}
```

This regex requires BOTH `needs-human` AND (`merge-check`|`assess-agent-autonomy`) on the same `decisions.md` line — a signal that only ever comes from `assess-agent-autonomy`'s Content-judgment Layer 2 (`settle-and-merge.md`, around the `2. **Content judgment**` step). Because the drain-overlap hold explicitly *skips* Content judgment, no such verdict is ever computed or logged for a drain-held group. `mergeResolution()` therefore finds no needs-human verdict, falls through to its grant check, and if every group member carries `auto:merge` or a matured `auto:merge-pending`, returns `{resolution: 'merge', reason: 'every member carries auto:merge...'}`.

Traced (not yet reproduced live): under `autonomy: unattended`, `wrap-up/review-console.md`'s Auto-resolution short-circuit invokes exactly this `console-resolve.js` merge resolution with zero human interaction. A group held back by the #1985 drain-overlap hold would reach the Review Console, and — because the hold produces no signal `needsHumanVerdict()` recognizes — the unattended auto-resolver would compute `resolution: 'merge'` and merge it anyway, silently defeating the entire purpose of the #1985 hold for exactly the operating mode (`unattended`) most likely to run a multi-group drain unattended. This is one layer downstream of the original #1480/#1596 incident #1985 was filed to prevent.

## Deliverables

- [ ] Give `console-resolve.js`'s merge-resolution path a way to recognize a live drain-overlap hold and resolve to `leave-open` for it, analogous to the existing `needs-human` carve-out — but the semantics differ: the existing carve-out (`assess-agent-autonomy` verdict) is treated as **permanent** ("authoritative all the way down," per `settle-and-merge.md`), while `drain-pr-overlap.md`'s own Step 6 hold is explicitly **not** persisted — it re-reads the overlapping PR's current state every time it runs and self-heals once that PR merges/closes. A naive regex addition that treats any historical "held — overlaps drain PR" decisions.md line as permanent would make the unattended resolver *more* conservative than #1985's own design intends. The real fix likely needs `console-resolve.js` to re-run (or receive as an already-fresh input) the same `detectCrossPRFileOverlap` check drain-pr-overlap.md's Step 6 performs, rather than trusting a historical log line — design thought needed on where that fresh state comes from at console-resolve time (a fact-pack field? a re-invocation of the check inline in resolve.js?).
- [ ] Tests: a fixture where a group's decisions.md carries a "held — overlaps drain PR" line and the overlapping PR is still open -> `mergeResolution` returns `leave-open`; the same fixture with the overlapping PR now merged/closed -> returns `merge` (assuming grants otherwise satisfy).

## Acceptance Criteria

1. Under `autonomy: unattended`, a group held by #1985's drain-overlap hold is never auto-merged by `console-resolve.js` while the overlapping drain PR is still open, even when every member otherwise carries `auto:merge`.
2. Once the overlapping drain PR merges or closes, the same group's next Review Console evaluation resolves normally (no permanent lockout).
3. `npm test` green; existing `tests/bin-lib/console/resolve.test.js` cases unaffected.

## Technical Approach

Needs design thought (hence deferred): the cleanest shape is probably a new field in the run's fact pack (or `console.json`) that records the *live* drain-overlap state at Review-Console-render time, since the console's own render already runs after the Auto-merge gate would have logged the hold — the resolver could read that field instead of re-deriving from decisions.md text. Alternatively, a literal-but-honest log-line addition (e.g. `drain-overlap-hold: live` vs `drain-overlap-hold: resolved`) that `console-resolve.js` re-validates against current PR state before trusting.

### Key Files

- `plugin/bin/lib/console/resolve.js` — `needsHumanVerdict()`/`mergeResolution()`
- `plugin/skills/dispatch/drain-pr-overlap.md` — Step 6, the hold's own log line
- `plugin/skills/wrap-up/review-console.md` — Auto-resolution short-circuit's carve-out list
- `tests/bin-lib/console/resolve.test.js`

## Gotchas

- Do not just make the hold's log line match the existing `needs-human`+`merge-check` regex — that would be dishonest (it isn't an `assess-agent-autonomy` verdict) and would inherit the "permanent" semantics that don't fit this hold's self-healing design.
- This gap does not affect #1944/#1984/#1985's own PR #2298 (none of the three carry `auto:merge`, so this run's own merge decision never reaches `mergeResolution()`'s grant-check branch) — it only affects a *future* group that both carries `auto:merge` and gets caught by the #1985 hold in a live unattended drain.
