## Current State

- `tools/run-tests.js` is the only route that gives a test run this repo's safeguards. Its child `node --test` gets (`tools/run-tests.js:685`): git auto-maintenance off for fixture repos (`gitFixtureConfigEnv`: `maintenance.auto=false`, `gc.auto=0`, #5297); `TMPDIR`/`TMP`/`TEMP` pointed at a per-run root under `<tmpdir>/ct-test-runs/` that is removed on exit; `CT_TEST_SUITE_SLOT_HELD=1` after the runner took the machine-wide suite slot; and `--test-concurrency` at half the cores (`resolveConcurrency`, 6 on a 12-core machine; `CT_TEST_CONCURRENCY` overrides).

## Deliverables

1. **The runner takes what a direct run names.** `tools/run-tests.js` accepts explicit `*.test.js` file operands and node's own test flags, so `node tools/run-tests.js <flags> <files>` is a drop-in for `node --test <flags> <files>`:
   - File operands resolve against the caller's working directory and must land inside the runner's checkout; each must exist and end in `.test.js`. A relative path and an absolute path to the same file are equivalent. They run as an explicit subset: the `--files-from` slot lane, no impact selection, the same child environment as every other run.
   - Arguments starting with `--test-` or `--experimental-test-` pass through to the child `node --test`, in both `--flag=value` and `--flag value` forms. One exported table names the node test flags that take a value; the runner's parser and the guard's operand counter both read it.
   - `--test-concurrency=<n>` is honoured exactly as `CT_TEST_CONCURRENCY=<n>` is today (the flag wins over the variable). The runner's default concurrency and slot counts do not change.
   - File operands mixed with directory roots, with `--files-from`, `--shard`, `--record-durations` or `--full`, and any other unknown dash argument, exit 1 with one `run-tests.js:` line naming the problem. Nothing reaches `node --test` with zero files.
   - The runner's own lines stay on stderr, so a caller parsing TAP from stdout reads exactly what node's reporter wrote, and the exit code is the child's.
2. **A repo-local PreToolUse guard.** A new `tools/direct-test-run-guard.js`, registered for `Bash` in `.claude/settings.json` (maintainer-side; nothing under `plugin/` changes). It denies a Bash call, with the equivalent runner command in the reason, when the call would start a direct `node --test` that is multi-file or looped:
   - **Direct test run:** a command segment whose program is node (`node`, a path ending in `node` or `node.exe`, or `npx ... node@<version>`) with either `--test` among its options before any script operand, or a script operand ending in `.test.js` (`node tests/x.test.js`). `node script.js --test` is not one.
   - **Denied shapes:** two or more file operands; an operand holding a glob character, an unresolved `$` or backtick expansion, or a directory; no file operand at all (node then discovers and runs every test it finds); or any direct test run inside a repeating construct (`for`, `while`, `until`, `xargs`, `find -exec`, `parallel`), including through `sh -c` / `bash -c`.
   - **Allowed:** exactly one literal file operand outside a repeating construct. No warning, no added output.
   - **Script-spawned runs:** when the call runs a script file through `node`, `bash`, `sh` or `zsh`, or executes one by path, and that file sits outside the checkout's `tools/`, `plugin/`, `tests/`, `perf/`, `evals/` and `scripts/` directories, the guard reads it (at most 256 KB). It denies when a JavaScript file holds the exact string literal `--test` together with a `child_process` reference, or a shell file holds a direct test run. The reason says to spawn `tools/run-tests.js` with the same flags and files, from the checkout under test.
   - **Outside the runner's reach:** a run whose working directory or operands resolve under `evals/` (a separate Node project), or in a directory tree with no `tools/run-tests.js` above it, is allowed.
   - **Deny reason:** names the four safeguards a direct run skips, then gives the replacement on its own line. For a typed command that line is the original segment with its `node --test` head replaced by the runner, addressed by a path that resolves from the command's own working directory. It also names `--files-from <list>` as the form for a checkout older than this change, and says a single-file run outside a loop is allowed.
   - **Never breaks a session:** every path exits 0. A deny is `hookSpecificOutput.permissionDecision: "deny"` with `permissionDecisionReason` on stdout. Unparseable stdin, an unreadable script, a scanner throw or any other error allows silently. The guard starts no child process and runs no git command.
3. **Guidance stops teaching the bypass.** Every direct `node --test` command the guard would deny, in `.claude/skills/**/SKILL.md`, `docs/plugin-structure.md`, `docs/journeys/*.md`, `docs/donts.md` and `CLAUDE.md`, is rewritten to the runner form. `shell-scanner-bash-differential`'s mutant step names the runner form and says a mutation loop or script calls it once per mutant from inside the mutant's own checkout.
4. **The rule is written down.** `docs/donts.md` gains one rule (multi-file, looped or script-spawned test runs go through the runner; one clause of why). `docs/plugin-structure.md`'s `tools/` entry and the header comment of `tools/run-tests.js` document the file-operand form, and the `tools/` entry documents the guard. `docs/hooks.md` gains one sentence saying this repo-local registration exists and is not part of the plugin's dispatcher contract. `CLAUDE.md` stays at its 150-line budget: any wording change there edits an existing line.

## Release Note

Steered this repository's multi-file and looped direct test runs through its test runner, which now accepts test files and test flags as arguments; the installed plugin is unchanged.

## Technical Approach

- **A guard on the launch, not protection from inside the tests.** Three of the four safeguards belong to how a run is launched: the suite slot is taken before any test process exists, the per-run `TMPDIR` has to be set before node starts, and `--test-concurrency` is an argument to `node --test`. Only the git settings could be applied from inside a test process, and nothing makes every directly started test file load one shared helper (`tests/helpers/git-template.js` already switches maintenance off, but only around its own template build). Routing direct runs through `plugin/bin/verify.js`, #5509's other candidate, adds scope selection the caller did not ask for; `verify.js` reaches the tests through this runner anyway, so the runner is the narrower target.
- **Repo-local, not in the plugin payload.** The steer target is `tools/run-tests.js`, which is maintainer-side and never ships (ADR-0015). A gate in `plugin/bin/lib/hooks/pre-tool-use.js` could only name it through a new shipped policy key with one known consumer, so the guard is a project hook in `.claude/settings.json` running a `tools/` script. It also takes effect when it merges, without waiting for a plugin release and update.
- **Deny with a drop-in, not a warning and not a rewrite.** A warning lets the bypass run once per call and is easy to ignore. A silent `updatedInput` rewrite would put an agent into the suite-slot queue without telling it. A deny costs one round trip and is safe to apply to ambiguous shapes (globs, expansions) because the replacement accepts everything the denied command named; AC 9 pins that property.
- **Single-file runs stay direct.** They are the documented isolation re-run and the cheapest loop while iterating. They still skip the environment safeguards, bounded to one file's fixtures; a single-file run that repeats (a loop, a script) is where the measured cost came from, and that is denied.
- **The mutation route is the file-operand form, not a new mode.** A mutation loop needs to run a fixed file set, read TAP from stdout and read the exit code. Deliverable 1 gives exactly that, with every safeguard, from inside each mutant's own checkout (each checkout carries its own `tools/run-tests.js`; the slot is machine-wide). Each call queues in the subset lane like any other subset run.
- **Script scan at Bash time.** The measured offender spawned `node --test` from a scratchpad script, which no command-string check sees. Reading the script named in the Bash call covers every way the file could have been written. Tracked code directories are skipped by path, with no git call.
- **Reuse the shell scanner.** `plugin/bin/lib/hooks/git-command.js` already exports the quote-aware segment and token walkers the plugin's gates use (`forEachCommandSegment`, `forEachShellSegment`, `tokenize`, `splitSegments`), with per-segment working directory and `sh -c` handling. The guard requires them from the checkout, the way `tools/run-tests.js` requires `../plugin/bin/lib/suite-slot`, instead of carrying a second shell parser.
- **One flag table.** The set of node test flags that take a value lives once, exported from `tools/run-tests.js`; the guard's operand counter imports it, so the two cannot disagree about what is a file.

## Gotchas

- ASSUMPTION — verify at build: a project hook command can address the checkout through `$CLAUDE_PROJECT_DIR`, and that variable names a directory holding `tools/direct-test-run-guard.js` for a session working inside a linked worktree — confirm by registering the hook in a scratch project and printing the variable from a worktree session before fixing the command string.
- ASSUMPTION — verify at build: a hook `if` predicate would skip the guard's process for Bash calls that cannot match — confirm against the current Claude Code hooks reference; `plugin/bin/lib/hooks/bash-prefilter.js`'s header records that unevaluable predicates run every registration, so do not rely on it for correctness.
- Sessions read hook registrations at start. A session already running when this merges keeps running without the guard until it restarts; do not message or restart other sessions as part of this work.
- A scratch checkout older than this change has a runner without file operands; there the route is `--files-from <list>`, which the deny reason names.
- `evals/` is its own Node project with its own `node --test tests/`; the guard must not deny it (AC 7).
- `CLAUDE.md` is at exactly 150 lines today.
- The guard's own tests, and the docs conformance test, must not spawn a multi-file direct `node --test`; the real-process tests of the runner go through `tools/run-tests.js` and inherit the held slot like the existing `tests/run-tests-*.test.js` cases (`.claude/skills/suite-slot-test-env`).
