# 2882: Missing git tags for CHANGELOG entries v6.129.0-v6.132.0

Surface: infra

**Related:** #2552, #2771, #2847

## Current State

`plugin/bin/lib/residue/probes/release.js`'s `probeRelease` builds its tag set from the local repository only — `run(['git', 'tag', '-l', 'v*'])` — and reports every post-bootstrap CHANGELOG heading with no matching local tag as a `tag for CHANGELOG entry v{X}` finding carrying `remedy: 'auto'` (the finding at line ~107).

The four findings this record was filed for (v6.129.0–v6.132.0, from #2552's wrap-up residue sweep) were false positives. Verified 2026-10-15: all four tags exist on origin (`git ls-remote --tags origin` lists `v6.129.0`–`v6.132.0`, created at release on 2026-09-21) and in the main checkout's local tag set. The sweep ran in a checkout whose local tag set lagged origin, so the probe reported "missing" for tags that were published. #2847 (push those tags) was closed for the same reason.

So the defect is the probe's tag source, not the release process: a stale or shallow checkout (a fresh worktree, a cloud sandbox clone without tags) makes the probe report released versions as untagged, and labels the finding `auto`, inviting an unattended remedy against shared release history.

## Deliverables

1. `probeRelease` reads the remote tag set (`git ls-remote --tags origin 'v*'`, through the probe's existing injectable `run`) and unions it with the local `git tag -l 'v*'` list before computing missing-tag findings. A tag present on either side is not missing.
2. When the remote read fails (offline, no `origin`), the probe falls back to the local list and says so in its result (a reason string naming the fallback), rather than silently treating the local set as authoritative.
3. Missing-tag findings (`tag for CHANGELOG entry v{X}`) carry `remedy: 'record'`, not `'auto'`: creating or pushing a tag over already-released history is a human decision, not something an unattended sweep should apply.
4. Unit tests for the three cases below, using an injected `run` stub.

## Acceptance Criteria

1. With the local tag list missing `v6.130.0` and the remote list containing it, `probeRelease` reports no finding for v6.130.0.
2. With the tag absent from both lists, the probe reports one `tag for CHANGELOG entry v{X}` finding with `remedy: 'record'`.
3. With the remote read failing, the probe still runs on the local list and its result names the fallback; it does not return `ran: false`.
4. `node --test tests/bin-lib/residue/probes-observed.test.js tests/bin-lib/residue/cli.test.js` passes.

## Release Note

The residue sweep no longer reports already-published release tags as missing when the local checkout hasn't fetched them.

## Technical Approach

Add a remote-tag read beside the existing `git tag -l` call in `probeRelease`, parse `ls-remote` output (`{sha}\trefs/tags/v{X}`, plus `^{}` peeled lines for annotated tags) down to bare versions, union with the local set, and keep the existing version filter (`versionGte(v, anchor)`). Change only the missing-tag finding's `remedy`; leave the "CHANGELOG entry for v{X}" finding (line ~99) as is unless the build finds the same false-positive shape there.

### Key Files

- `plugin/bin/lib/residue/probes/release.js` — union local + remote tag sets; fallback reason; `remedy: 'record'` on missing-tag findings
- `tests/bin-lib/residue/probes-observed.test.js` — existing probe coverage; extend for the three cases (or a new sibling test file if the release probe has none there)
- `tests/bin-lib/residue/cli.test.js` — confirm the CLI output still renders the changed finding

## Gotchas

- `git ls-remote` output for an annotated tag carries a second `refs/tags/vX^{}` line; strip the `^{}` suffix before comparing, and never use an exact-ref pattern that hides the peeled line.
- A network call inside a residue probe adds latency to every wrap-up sweep; keep it to one `ls-remote` call per probe run and honor the probe's existing best-effort posture (a failure degrades, never throws).
- `/claude-tweaks:tidy` auto-applies `remedy: auto` findings for other probe kinds; moving missing-tag findings to `record` is deliberate and should be called out in the PR.
- #2771 (release-triple `docs/shipped-versions.tsv`) is very likely obsolete: `release.js` no longer reads that file and `plugin/bin/lib/release/precheck.js` documents the tsv as retired. Close it separately rather than folding it in here.
