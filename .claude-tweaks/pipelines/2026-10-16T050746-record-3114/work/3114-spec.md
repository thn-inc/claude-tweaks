# 3114: Resolve spawned test workers on close, not exit, across the remaining concurrency tests

Origin: ledger resolve gate — #3105 final whole-branch review sweep, run 2026-10-10T225734-spec-3105

Defer-reason: tangential

## Current State

#3105 found that a test which spawns a child and resolves on the child's `'exit'` event can read its stdio before the pipe drains: Node fires `'exit'` while the streams may still be open. That test's own stdout capture is fixed. Six more tests accumulate **stderr** and resolve on `'exit'`: `tests/bin-lib/declined-learning/store-concurrency.test.js:41` and `:74`, `tests/bin-lib/file-lock.test.js:151`, `tests/bin-lib/log-decision/append.test.js:207`, and `tests/hooks-context.test.js:480` and `:528`. Their pass/fail assertions read from disk, so they do not flake on the capture. However, a failing worker's rejection message can arrive with truncated stderr, which loses the diagnosis exactly when it is needed. `tests/bin-lib/hooks/sweep-shadow-claim-concurrency.test.js:72` and `tests/bin-lib/ports/registry.test.js:119` already use `'close'`. This is the third and fourth occurrence of the pattern, so a shared spawn-and-collect test helper is worth weighing.

## Deliverables

- Switch the six listed handlers from `'exit'` to `'close'` (`(code, signal)`), keeping each rejection's stderr. Alternatively, introduce one shared test helper that spawns a child and resolves on `'close'` with `{code, signal, stdout, stderr}`, and use it at all eight sites.

## Acceptance Criteria

- [ ] No test under `tests/` that collects a spawned child's stdout or stderr resolves on `'exit'`. This holds when checked by a grep for `.on('exit'` beside a stdio `'data'` accumulator, a test that waits on a `stdio: 'ignore'` SIGKILL being the documented exception.
- [ ] The six touched test files pass.
