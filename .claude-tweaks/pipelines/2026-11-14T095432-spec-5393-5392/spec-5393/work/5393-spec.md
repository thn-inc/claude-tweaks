# 5393: Reconcile residue errors cut off gh's stderr behind the echoed command

## Current State

`boundedError` (`plugin/bin/lib/reconcile/cache.js`) collapses a residue escalate/resolve failure to one line and cuts it at `RESIDUE_ERROR_MAX_CHARS` (200). Its input comes from `errorText` (`plugin/bin/lib/feedback/file-feedback.js`, re-used by `plugin/bin/lib/reconcile/escalate-residue.js`), which joins `err.message`, `err.stderr`, `err.stdout` in that order.

For an `execFileSync` failure, `err.message` begins `Command failed: <full argv>` — for `gh issue comment … --body <text>` that is the whole comment body — so the 200 characters run out before gh's stderr. The cause of the failure is lost from every surface that shows it (the background reconcile status file, the SessionStart residue line, `reconcile-cache.json`).

Observed: the #2724 escalate failure for run `2026-11-02T205944-record-3721` is recorded as `Command failed: gh issue comment 2724 --repo thn-inc/claude-tweaks --body Also stuck: \`…/2026-11-02T205944-record-3721\` Po` and has been re-shown at every session start since 2026-11-11 with no way to tell why gh refused.

## Deliverables

- The text a residue error records leads with the failing process's stderr when there is any, followed by a short form of the command (program and subcommand, never the full argv or a `--body` value), still collapsed to one line and capped at 200 characters.

- A failure with no stderr keeps today's message-based text.

- The `detail` suffix behavior from #4794 is unchanged.

## Acceptance Criteria

- [ ] A unit test feeds `boundedError` (or the function that now builds its input) an `execFileSync`-shaped error whose argv carries a 300-character `--body` and whose stderr is `HTTP 403: secondary rate limit`; the recorded text contains `HTTP 403: secondary rate limit` and is at most 200 characters before any `detail`.

- [ ] The same test with empty stderr records text beginning `Command failed:`.

- [ ] The recorded text never contains the `--body` value.

- [ ] Existing `boundedError` / residue-error tests still pass.

## Release Note

Reconcile's residue-error line now shows why a GitHub call failed instead of a cut-off echo of the command.
