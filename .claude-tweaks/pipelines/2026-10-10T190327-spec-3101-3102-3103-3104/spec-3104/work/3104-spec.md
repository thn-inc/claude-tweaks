# 3104: Dispatch #N reports a record as absent when dispatch-exclusions.json is unreadable

Origin: v6.139.2 release whole-branch review (/claude-tweaks:release Step 3, v6.139.1..7dd0242b5), staged finding review-4 — the release review stages and never applies fixes in place

Defer-reason: needs-human-decision

## Current State

`plugin/skills/dispatch/SKILL.md:178`'s fallback "no entry at all as absent from this firing's queue" cannot tell an absent entry from a corrupt or unreadable `dispatch-exclusions.json`: `plugin/bin/lib/dispatch/exclusions.js`'s `readExclusions` returns `[]` on any read/parse failure (stderr only), so a record really excluded (e.g. `not-spec-shaped`) would be reported as merely absent — the misreport class #3084 removed. Pre-existing gap; needs a corrupt file to trigger. SKILL.md is at 46002 of 46080 B, so the fix must be byte-neutral there.

## Deliverables

- Distinguish ENOENT from a read/parse failure in `readExclusions`' caller (or the queue-pull script), and route the unreadable case to a named report line in an exclusion-report sub-file, citing it from the `#N` bullet byte-neutrally.

## Acceptance Criteria

- [ ] With a corrupt `dispatch-exclusions.json`, `/claude-tweaks:dispatch #N` reports the exclusion reason as unknown because the file is unreadable, never as absent from the queue.
- [ ] `plugin/skills/dispatch/SKILL.md` stays under 46080 bytes.

## Release Note

When dispatch cannot read its exclusion list, a named record's report says so instead of claiming the record was never queued.
