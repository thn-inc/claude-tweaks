# 2949: Extend diagram-suggestion hook to /specify shaping mode and /writing-plans single-record plans

Surface: infra

**Related:** #2689

## Current State

`/claude-tweaks:specify`'s diagram suggestion (Step 2.5d, `plugin/skills/specify/decomposition-mode.md:234`) runs only in decomposition mode (design doc into sub-issue records). Its output renders in Step 9's summary under `### Diagram suggestions` (`plugin/skills/specify/decomposition-mode-closeout.md:107`). Shaping mode — a single `#N` or a comma list, which is now the primary `/specify` path — has no equivalent step in `shaping-mode.md`, `shaping-mode-stamping.md`, or `shaping-mode-readback.md`, so most shaped records never get a diagram suggestion. Found by #2689's whole-branch review.

The original request also names `/superpowers:writing-plans` single-record plans. That skill belongs to the Superpowers plugin; claude-tweaks cannot edit it, so that half is out of scope here.

## Deliverables

1. Shaping mode runs the same signal detection Step 2.5d uses, against each record's newly shaped body, and renders at most two advisory diagram suggestions for that record (each a `/claude-tweaks:visualize` recommendation).
2. The suggestions render in shaping mode's report (Actions Performed or the Next Actions area) and never block or prompt. Under bare drain and `--chained`, they are logged as `STAGED` decision-log entries, matching Step 2.5d's existing auto-mode behavior.
3. The step honors the same project gate Step 2.5d honors (CLAUDE.md `diagram-suggestions:`), so a project with suggestions disabled sees no change.
4. The signal detection lives in one place both modes cite (an extracted shared sub-file or a citation of Step 2.5d), not restated per mode.

## Acceptance Criteria

1. Shaping a record whose body describes a multi-step flow or multi-component interaction renders at least one diagram suggestion; shaping a single-file bug fix renders none.
2. A comma-list batch renders suggestions per record, capped at two each.
3. Under bare drain or `--chained`, no suggestion is printed interactively; each appears as a `STAGED` line in `decisions.md`.
4. With `diagram-suggestions:` disabled, shaping output is unchanged.
5. Step 2.5d's detection rules are stated once; `/specify`'s prose conformance tests pass.

## Release Note

`/specify` now suggests a diagram when shaping a single record, not only when decomposing a design doc.

## Technical Approach

Extract Step 2.5d's signal-detection and recommendation rules into a sub-file both modes read (or have shaping mode cite the Step 2.5d section directly), then add one step to shaping mode after the body is composed and before read-back that runs it per record. Keep the per-file lazy-load size limits in mind: shaping-mode files sit near their ceilings, so a citation is preferable to inlining.

### Key Files

- `plugin/skills/specify/decomposition-mode.md` — Step 2.5d source; becomes a citation if the rules move
- `plugin/skills/specify/shaping-mode-stamping.md` or `plugin/skills/specify/shaping-mode-readback.md` — new per-record suggestion step
- `plugin/skills/specify/next-actions.md` — where suggestions render for interactive runs
- `plugin/skills/specify/next-mode-closeout.md` — headless `STAGED` logging for bare drain

## Gotchas

- The Superpowers `/writing-plans` half of the original request is not editable from this repo; if it is still wanted, it belongs upstream via `/claude-tweaks:feedback` or the Superpowers repo, not here.
- Shaping-mode files are near the 40 KB per-file lazy-load ceiling (`tests/bin-lib/skill-audit/context-cost.test.js`); measure before adding prose.
- Advisory only: a suggestion must never become a gate or an `AskUserQuestion`.
