# 6351: Let the design skill's readers use the top model tier through one named exception in the model resolver

Surface: backend
Risk-flags: public-contract
Risk-flags-unconfirmed: true

## Overview

The new design skill runs every one of its readers on the top model tier: five readers per round for at most four rounds, plus one pre-mortem reader and one builder-check reader, 22 at most. Today the model resolver allows the top tier only at single slots, at most `frontier-run-cap` (3) per run, and silently steps a reader down to the next tier past that. This record gives the resolver one named exception for that skill, and makes a step-down visible to the caller so the skill can stop and ask instead of lowering the tier.

## Non-Goals

- The design skill itself. This record is the resolver and its contract text only.
- Raising `frontier-run-cap`, or allowing the top tier in any other fan-out.
- Allowing the top tier in a session with no human present. That rule stays.

## Prerequisites

- Decided by the maintainer on 2026-11-27, after filing: this work is dispatched now, in parallel with its siblings, and its pull request merges by itself once every gate is green. An earlier line here said it was built by hand and was not for `auto:build`; that no longer holds.

## Current State

- `plugin/bin/lib/model-profiles/profiles.js` holds the table (`frontier: { model: 'fable', effort: 'high', singletonOnly: true, degradeTo: 'capable' }`) and the gates: an `economy` stance, a `model-ceiling`, an unattended call, the run cap (`frontier-run-cap`, default 3, counted from the run's tally) and a session-failure list. A gated resolution returns the next tier with `source: degraded:{reason}`.
- `plugin/bin/resolve-profile.js` is the CLI every dispatch site calls, and reads the tally from the run folder.
- `plugin/skills/_shared/subagent-dispatch-core.md` states the rule ("Frontier is singleton-only") and lists the slots where the top tier is valid. `CLAUDE.md`'s Subagent Contract paragraph and `plugin/skills/_shared/subagent-output-contract.md` repeat it in one clause.

## Deliverables

- [ ] The resolver accepts a named exception (the caller names the design skill's reader slot) under which a top-tier resolution is valid in a fan-out and is counted against its own limit of 22 per design session, not against `frontier-run-cap`.
- [ ] Under the exception the resolver never returns a lower tier as if nothing happened: when a ceiling, an economy stance, the session-failure list or the exception's own limit would step the reader down, the output says so in a field the caller must read, with the reason, and the caller decides.
- [ ] An unattended call under the exception is refused, with the reason.
- [ ] The exception is one named entry in code, not a setting: no policy key can add a second skill to it.
- [ ] `plugin/skills/_shared/subagent-dispatch-core.md` lists the exception beside the existing slots, with its limit and the stop-and-ask rule. `CLAUDE.md` and `plugin/skills/_shared/subagent-output-contract.md` are changed only where their one clause would otherwise be false.
- [ ] Tests, sized like the resolver's existing ones.

## Acceptance Criteria

- [ ] With the exception named, resolutions 1 to 22 in one design session return the top tier with a source naming the exception; resolution 23 returns the step-down signal with reason `limit`.
- [ ] With the exception named and `model-ceiling` below the top tier, or an `economy` stance, or the top tier's model on the session-failure list, the output carries the step-down signal and its reason, and no caller can read a model from it without also reading the signal. Verify: a test per reason.
- [ ] Under the exception a step-down prints no `model` key: the output is `{"stepDown":{"reason":"..."}}` and the CLI exits non-zero, so a caller that reads only `model` gets nothing. Verify: a table-pinning test per reason. (Settled at filing from a red-team finding.)
- [ ] With the exception named and `--unattended`, the call exits non-zero.
- [ ] Without the exception named, every existing resolver test passes unchanged, and a fourth top-tier resolution in a run still degrades as today.
- [ ] A call naming any other exception exits non-zero with a message naming the one that exists.

## Release Note

The model resolver has one named exception that lets the design skill's readers use the top model tier, with a limit of its own.

## Technical Approach

Add the exception to `profiles.js` as a constant, pass it from `resolve-profile.js` as a flag, and count its use in its own tally file beside the run's existing one (the design skill's folder, since a design session has no pipeline run folder). Read every caller of `resolve()` and every test that pins the output shape before adding a field.
