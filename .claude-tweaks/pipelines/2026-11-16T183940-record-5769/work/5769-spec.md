# 5769: Cut remote-protocol git work in the prune-remote, pre-review-catchup and claims-git-cas test fixtures

**Related:** #5324, #5297

Verified-as-of: c059556fc34954c27371c25ebd65f99e79a4eb0a

## Current State

A full-suite profile on main at 8646f7c (2026-11-16, `node tools/run-tests.js --full`, git trace2 per test file) counted 59,448 git processes. Push, fetch, clone and the git processes they start are 5,995 of them (10%) but 33% of all git time: one push starts receive-pack, rev-list, pack-objects, index-pack and, without `receive.autogc = false`, a maintenance run.

Three files build their remote state from scratch in every test:

| File | Git processes | From the test process | Children of another git | Largest subcommands |
|---|---|---|---|---|
| `tests/bin-lib/reconcile/prune-remote.test.js` | 1,150 | 692 | 458 | for-each-ref 97, rev-list 80, push 74, receive-pack 74 |
| `tests/bin-lib/pre-review-catchup/cli.test.js` | 1,064 | 593 | 471 | rev-list 115, commit 97, add 96, pack-objects 86 |
| `tests/bin-lib/issues/claims-git-cas.test.js` | 661 | 332 | 329 | rev-list 68, push 45, receive-pack 45, maintenance 44 |

- `prune-remote.test.js`: `makeRepoWithOrigin()` inits a bare origin and a repo and pushes `main` per test. Each test then pushes the branches it needs (`build/merged`, `build/stale`, `build/squashed` and so on), and three tests clone a second checkout to advance or delete a branch.
- `pre-review-catchup/cli.test.js`: `fixture()` starts from the `originWithTwoClones` template (#5297), then commits, pushes and pulls again in every test to reach its own starting state.
- `claims-git-cas.test.js`: `makeBareOriginAndClone()` inits a bare origin, clones it and pushes twice (`main`, then `main:claims-registry`) per test.

`tests/helpers/git-template.js` (`fromTemplate`, `fromTemplateSet`) builds a fixture once per process and gives each caller a copy that starts no git process. It already rewrites remote urls and linked-worktree pointers in the copy.

## Deliverables

1. Each file's starting state (bare origin, clones, seed commits, the registry branch, the extra pushed and pulled commits) is built once per process through `fromTemplateSet` or `fromTemplate` and copied per test. Bare origins in these templates call `disableReceiveAutoGc`.
2. A push, clone, pull or fetch that only arranges state the test needs, and is not what the test checks, is replaced by something cheaper that leaves the same refs and objects: built into a template variant, or a local ref update where the objects are already present.
3. Remote operations that are the behaviour under test stay real: `pruneRemote`'s own fetch and delete pushes, the claims compare-and-swap push and its lease, the catch-up's fetch and merge, and the tests that need a second clone to advance a branch after the fixture was built.
4. Each new template has a spawn test in `tests/helpers-git-template.test.js`, in the style of #5297's: after a warm-up call the builder starts no git process.
5. The PR body reports git processes per file, before and after, with the split by subcommand.
