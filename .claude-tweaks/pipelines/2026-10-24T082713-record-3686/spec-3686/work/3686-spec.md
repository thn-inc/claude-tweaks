# 3686: delete-ledger and finish-console: test the unattributable arms and report inherited-only ledgers distinctly

Surface: backend

Origin: wrap-up leftover from #3566

## Current State

#3566 scoped `resolveLedgerPath` (`plugin/bin/lib/wrap-up/ledger-write.js`) to the docs/plans ledger the branch owns and added an `unattributable` outcome (no merge base, or git failed — `ledger-write.js:83`). Two CLI arms consume it, and neither has a direct test:

- `hooks.js delete-ledger` — `plugin/bin/hooks.js:1123` prints `cannot attribute docs/plans ledgers to {run} … ledger not deleted`.
- `wrap-up-engine.js finish-console` — the ledger pre-flight added by #3684 (`plugin/bin/wrap-up-engine.js:666`) fails with `cannot attribute docs/plans ledgers to this run … — nothing written`, exit 1.

`resolveLedgerPath`'s own `unattributable` outcome is unit-tested (`tests/bin-lib/wrap-up/ledger-write.test.js:130`, `:139`), but the two CLI arms are not: `git grep unattributable -- tests` finds no hit in `tests/delete-ledger-verb.test.js` or `tests/bin-lib/wrap-up/finish-console-cli.test.js`. `resolveWorktreeBase` (`plugin/bin/lib/wrap-up/pack.js:312`) has no unit test either — it is exercised only through the real-git delete-ledger tests.

Separately, `hooks.js delete-ledger` prints the same `no ledger found for {run} — not found` line both when the worktree has no docs/plans ledger at all and when it holds only ledgers inherited from the merge base, so a post-merge wrap-up that leaves its own ledger behind is indistinguishable from a clean one. Inherited-only resolving to not-found is #3566 AC1's required outcome — this is a diagnostics gap, not a defect. Since #3566 was parked, #3897 added `describeRunLedgers` (`ledger-write.js:96`), the read-side view that already splits `this-run` from `other-run` ledgers and backs the `resolve-ledger` verb; delete-ledger does not use it yet.

## Deliverables

- [ ] A CLI test for `hooks.js delete-ledger`'s `unattributable` arm: a run dir whose `run-state.json` names a non-git worktree holding a `docs/plans/*-ledger.md`, asserting the `cannot attribute` message and that the ledger file still exists afterwards
- [ ] A CLI test for `wrap-up-engine.js finish-console`'s `unattributable` pre-flight arm, with a non-empty `ledger` payload, asserting exit 1, the `cannot attribute` stderr line, and that the ledger's text is byte-identical afterwards (no row flipped)
- [ ] A unit test for `resolveWorktreeBase`: the merge base is returned when one resolves, and `null` when git or the policy read fails
- [ ] `hooks.js delete-ledger` distinguishes "no ledger at all" from "only inherited ledgers" in its not-found report, without widening `resolveLedgerPath`'s decision contract

## Acceptance Criteria

- `node --test tests/delete-ledger-verb.test.js tests/bin-lib/wrap-up/finish-console-cli.test.js tests/bin-lib/wrap-up/pack.test.js` passes, with one test named for each `unattributable` arm and one for `resolveWorktreeBase`
- Reverting the `unattributable` branch in `hooks.js` delete-ledger, or in `wrap-up-engine.js` finish-console, turns the matching new test red
- A delete-ledger run whose worktree holds only inherited `docs/plans` ledgers prints a not-found line naming those inherited ledgers (for example `only inherited ledgers found: …`), and a run with no `docs/plans` ledger at all still prints `no ledger found for {run} — not found`
- The inherited-only run still deletes nothing, and `resolveLedgerPath`'s return shape is unchanged
- `npm test` passes

## Release Note

`delete-ledger` now says when a worktree holds only inherited ledgers, instead of reporting a bare "not found".

## Technical Approach

For the inherited-only diagnostic, call `describeRunLedgers` (already exported beside `resolveLedgerPath`) in delete-ledger's not-found branch only: `report: 'none'` with a non-empty `others` list is the inherited-only case. That keeps `resolveLedgerPath`'s contract untouched — the requirement the original record stated — and reuses the same split `resolve-ledger` prints.

For the two `unattributable` CLI tests, the run dir must still be anchored under a real git repo (finish-console's `#790`/`[IL-127]` guard rejects an unanchored `--run-dir`; `finish-console-cli.test.js`'s setup already builds one). The unattributable condition comes from the worktree, not the run dir: point `run-state.json`'s `worktree` at a separate non-git temp dir that holds the ledger. For `resolveWorktreeBase`, inject `deps` (`resolvePolicy`, `git`) the same way `pack.test.js`'s `okDeps()` already fakes `resolveInputs`' deps, rather than building a real repo.

### Key Files

- `plugin/bin/hooks.js` — delete-ledger's not-found branch: inherited-only vs none

- `plugin/bin/wrap-up-engine.js` — finish-console's unattributable pre-flight arm (test target only)
- `plugin/bin/lib/wrap-up/pack.js` — `resolveWorktreeBase` (test target only)

## Gotchas

- A non-git directory as the run dir itself fails on the anchoring guard before any ledger logic runs, so a test built that way passes for the wrong reason. Only the run-state `worktree` should be non-git.
- finish-console only resolves the ledger when the payload's `ledger` array is non-empty; an empty payload never reaches the unattributable arm.
- `tests/delete-ledger-verb.test.js` may be pinned by other conformance suites; run the full suite before merging, not just the three named files.
