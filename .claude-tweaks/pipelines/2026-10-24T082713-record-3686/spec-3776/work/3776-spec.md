# 3776: Windows regression: 1 test file(s) newly failing after a34fe8bb9

Surface: infra

## Current State

The post-merge Windows check on commit a34fe8bb9 (merged PR #3750) reported `tests/auto-merge-short-circuit-dispatch-call.test.js` newly failing. The failing test is "the branch snippet, executed verbatim, answers true only for this run's own dispatch Task call", which fails with `a fenced bash block must sit inside the branch paragraph`.

Re-checked against current `main`, the failure is still live and reproduces on macOS. Running the file under a preload that makes `fs.readFileSync` return CRLF text (what a Windows `core.autocrlf=true` checkout holds) fails exactly this one test, 7 pass / 1 fail. Root cause: line 21 reads `plugin/skills/wrap-up/auto-merge-short-circuit.md` with a raw `fs.readFileSync(..., 'utf8')` into `RAW`, and the test's fence regex `/```bash\n([\s\S]*?)\n```/` is LF-anchored, so it never matches `` ```bash\r\n ``. Lines 125 and 127 hold two more raw markdown reads; they pass under CRLF today only because their regexes carry no newline anchors.

`tests/helpers/read-skill.js` exports `readText(absPath)` (#2763), the shared EOL-normalizing read for exactly this case.

**Related:** #3702, #3703, #3742, #3751, #3797, #3802, #3857, #3871, #3886, #3890, #3894

## Deliverables

1. `tests/auto-merge-short-circuit-dispatch-call.test.js` — route all three markdown reads (line 21's `RAW`, and lines 125 and 127) through `readText` from `./helpers/read-skill`.

## Acceptance Criteria

1. No raw `fs.readFileSync` of a markdown file remains in `tests/auto-merge-short-circuit-dispatch-call.test.js`. Every `.md` read goes through `readText`.
2. Under a CRLF simulation (a `--require` preload that returns `\r\n`-converted text from `fs.readFileSync` for repo files), `node --test tests/auto-merge-short-circuit-dispatch-call.test.js` passes all tests. Before the fix it reports 1 failure.
3. `node --test tests/auto-merge-short-circuit-dispatch-call.test.js` is green on Linux/macOS without the preload.
4. The next post-merge Windows check (`.github/workflows/windows-regression.yml`) no longer lists this test file.

## Release Note

Fix a Windows-only failure in the auto-merge short-circuit test caused by CRLF line endings.

## Technical Approach

Swap the reads for `readText`. The snippet the test extracts and executes with `bash -c` then carries LF line endings, which is also what bash on Windows (Git Bash) expects, so normalizing fixes both the fence match and the executed script. No assertion or regex text changes.

### Key Files

- `tests/auto-merge-short-circuit-dispatch-call.test.js` — three markdown reads routed through `readText`
- `tests/helpers/read-skill.js` — `readText` helper reused (read-only)

## Gotchas

- Do not "fix" this by making the fence regex `\r?\n`-tolerant. The extracted snippet would then still carry `\r` characters into `bash -c`, which fails on `$'\r'` command-not-found errors.
- CI runs on ubuntu only, so only the post-merge `windows-regression.yml` run proves this on Windows. AC2's CRLF simulation is the pre-merge stand-in.
