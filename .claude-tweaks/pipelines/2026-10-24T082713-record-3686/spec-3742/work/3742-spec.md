# 3742: Windows regression: 1 test file(s) newly failing after 5d4bac796

Surface: infra

## Current State

The post-merge Windows check on commit 5d4bac796 (merged PR #3735) reported `tests/bin-lib/visual-decide/cli.test.js` newly failing. The failing test is "AC1: start returns detached-running server-info (mode 0600, url has ?key=); second start refuses naming the URL", which fails with `Expected values to be strictly equal: 438 !== 384`.

Re-checked against current `main`, the failure is still live. Lines 44-45 assert `fs.statSync(infoPath).mode & 0o777 === 0o600`. `plugin/bin/lib/visual-decide/server.js:277` does write `server-info` with `{ mode: 0o600 }`, but win32 does not represent POSIX permission bits: Node reports a writable file as `0o666` (438) whatever mode was requested. The other assertions in the same test (URL carries `?key=`, a second `start` refuses and names the URL) are platform-neutral and still worth running on Windows.

The repo already gates mode-bit expectations on win32 elsewhere, e.g. `tests/skill-load-report-cli.test.js:112` (`CHMOD_DENIAL_SKIP`) and `tests/bin-lib/reconcile/reap-merged.test.js:608` ("win32 ignores directory mode bits").

**Related:** #3702, #3703, #3751, #3776, #3797, #3802, #3857, #3871, #3886, #3890, #3894

## Deliverables

1. `tests/bin-lib/visual-decide/cli.test.js` — guard only the `0o600` mode assertion (lines 44-45) behind `process.platform !== 'win32'`, with a one-line comment that win32 ignores POSIX mode bits. The rest of AC1 (`?key=` URL, second-start refusal) still runs on every platform.

## Acceptance Criteria

1. On win32, the AC1 test no longer asserts `mode & 0o777 === 0o600`. On every other platform it still does, unchanged.
2. The AC1 test's URL and second-start-refusal assertions are not skipped on win32: the whole test is not converted to a `{ skip }` test.
3. `node --test tests/bin-lib/visual-decide/cli.test.js` is green on Linux/macOS.
4. The next post-merge Windows check (`.github/workflows/windows-regression.yml`) no longer lists this test file.

## Release Note

Fix a Windows-only failure in the visual-decide CLI test, which asserted POSIX file permissions Windows cannot represent.

## Technical Approach

Wrap the two mode-bit lines in a platform condition rather than skipping the test. A whole-test `{ skip }` (the idiom the cited siblings use) would also drop the platform-neutral assertions, which are the bulk of AC1's value. No change to `server.js`: requesting `0o600` is still correct on POSIX, and harmless on win32.

### Key Files

- `tests/bin-lib/visual-decide/cli.test.js` — mode-bit assertion guarded on win32
- `plugin/bin/lib/visual-decide/server.js` — writes `server-info` with `mode: 0o600` (read-only reference, no change)

## Gotchas

- CI runs on ubuntu only, so only the post-merge `windows-regression.yml` run proves this on Windows.
- Running as root on POSIX does not change `statSync`'s reported mode for a file created with `0o600`, so no `skipUnderRoot` guard is needed here. The root caveat applies to tests that rely on permission *denial*.
