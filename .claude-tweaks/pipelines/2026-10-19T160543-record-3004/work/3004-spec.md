# 3004: build: review minors are carried into the ledger as deferred with no Defer-reason

Surface: infra

## Current State

`/claude-tweaks:build`'s default execution strategy invokes `/superpowers:subagent-driven-development` (`plugin/skills/build/build-options.md:11`, invocation instructions in `plugin/skills/build/dispatch.md:14`). SDD runs a reviewer per task and a whole-branch review at the end, and both can return Minor findings. `/build` never says what happens to those findings. No file under `plugin/skills/build/` cites `_shared/deferral-gate.md`, so the build agent improvises its ledger writes. The ledger's only build-time entry rule is Common Step 4 (`build/SKILL.md:244-252`), which covers blocked work: "Append blocked items to the open items ledger ... with phase `build/*` and status `open`".

`_shared/deferral-gate.md:27` requires a ledger entry that recommends deferral to pass the same fix-now check and name its `Defer-reason:` inline. `:39` lists "Minor / outside that scope / not load-bearing" as a bad reason, since severity is never a defer reason. `_shared/ledger-format.md:59` additionally requires `deferred` resolution text to carry origin, affected files and a revisit trigger.

In the reported run (plugin 6.136.0), the build wrote review minors as `deferred | SDD minor (deferred), triaged fine-to-defer by the whole-branch review.` or `open | —`. Six of the eleven carried rows qualified for fix-now: a number-format call, two missing unit assertions, an indentation fix, a missing e2e fixture, a live-region condition and a design-doc note. The deferral gate first ran on them at the later call's review, which cost an extra fix wave and two scoped verification runs after the build's final verification had already passed.

## Deliverables

1. In `build/dispatch.md`'s SDD invocation instruction, add a rule for review findings: every Minor (or higher) finding from a per-task reviewer or the whole-branch review is either fixed in this build, or carried to the ledger only after passing `_shared/deferral-gate.md`'s fix-now check with exactly one `Defer-reason:` from that file's vocabulary, written inline in the row's Resolution text. Severity alone ("minor", "fine to defer") is never a reason. Cite the gate file rather than restating its criteria.
2. Add the same rule to `build/SKILL.md`'s Common Step 4, next to the blocked-work ledger instruction, so the ledger-write site names the gate whatever execution strategy ran (subagent or inline).
3. Make the gap visible mechanically: when the open-items ledger carries a `build/*`-phase row whose status is `deferred` or `open` and whose Resolution text has no valid `Defer-reason:` value, the wrap-up fact pack's ledger parse reports it. Surface it at wrap-up as a non-blocking warning naming the rows, mirroring the unrecognized-status warning (`wrap-up/SKILL.md:208`, `ledger-format.md:57`, `parseLedger` in `plugin/bin/lib/wrap-up/pack.js`). Reuse `DEFER_REASONS` from `plugin/bin/lib/issues/autonomy.js` for validity.

## Acceptance Criteria

- `build/dispatch.md` and `build/SKILL.md` both cite `_shared/deferral-gate.md` at the review-finding / ledger-write instruction. A conformance test pins both citations and the "severity is never a reason" wording, and goes red against the current text.
- A unit test feeds `parseLedger` a ledger with three `build/*` rows: one `deferred` with a valid `Defer-reason:`, one `deferred` with "SDD minor (deferred)", and one `open | —`. It asserts that exactly the last two are reported as missing a defer reason.
- The wrap-up warning names the rows and never blocks. An existing wrap-up/ledger test passes unchanged.
- `npm test` passes in full.

## Release Note

Build no longer parks minor review findings in the open-items ledger without a valid defer reason. It fixes them or names why they can wait.

## Technical Approach

The prose fix is two citations of the existing gate, at the SDD invocation and at the ledger-write step. The mechanical backstop sits in the ledger parse that wrap-up already runs, reusing the closed `DEFER_REASONS` vocabulary, so a build that ignores the prose still gets caught before the end-of-run console rather than one call later at review.

### Key Files

- `plugin/skills/build/dispatch.md` — SDD invocation instruction gains the review-finding deferral rule
- `plugin/skills/build/SKILL.md` — Common Step 4 cites `_shared/deferral-gate.md` for review findings carried to the ledger
- `plugin/bin/lib/wrap-up/pack.js` — `parseLedger` reports `build/*` deferred/open rows lacking a valid `Defer-reason:`
- `plugin/bin/lib/issues/autonomy.js` — reference only: `DEFER_REASONS` source of truth
- `plugin/skills/wrap-up/SKILL.md` — surfaces the new non-blocking warning next to the out-of-enum status warning

## Gotchas

- Blocked-work rows (Common Step 4's original purpose) are `open` by design until the ledger resolve gate runs. The backstop must not flag a genuinely blocked row. Scope the check to rows that recommend deferral, or require blocked rows to name `Defer-reason: blocked-dependency` or `blocked-external` as well. Pick one and state it in the PR.
- SDD is a third-party skill (superpowers). The instruction has to travel in `/build`'s invocation text. Do not edit the upstream skill.
- `parseLedger` is at `plugin/bin/lib/wrap-up/pack.js:332`. Check that its row shape carries phase and Resolution text before extending it, and add fields rather than changing existing ones, since the Resolve Gate and the unrecognized-status warning (`wrap-up/SKILL.md:208`) already consume it.
