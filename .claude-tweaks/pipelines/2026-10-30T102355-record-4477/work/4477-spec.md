# 4477: qa-agent / stories: a story that reveals a one-time secret leaves it in snapshot, trace and screenshot artifacts

Surface: infra

**Related:** #4408

## Current State

`claude-tweaks:qa-agent` (`plugin/agents/qa-agent.md`) runs one story through `playwright-cli`. It takes an accessibility `snapshot` before every element action and every `verify` (`qa-agent.md:100-136`), writes a screenshot at every step under `SCREENSHOT_PATH` (`:22`, `:31`), and writes failure traces under `TRACES_BASE` (`:23`). The story schema (v2, `plugin/skills/stories/SKILL.md:35`) has no way to mark a value as sensitive, and nothing in the agent or `plugin/bin/qa-report.js` scrubs artifacts.

Observed on 6.145.0: one of 18 stories in a local QA run exercised a "token shown once" flow. The story prompt told the agent never to print or store the token, and the agent's own output complied. The value still landed in 4 artifact files the tooling wrote on its own: snapshot YAML, the trace, and step screenshots. A manual search found and deleted them afterwards, with 0 matches left. Prompt instructions cannot reach artifacts the tooling writes unprompted, so every "reveal a secret once" story leaves the secret behind. That covers API keys, recovery codes, one-time tokens and invite links.

## Deliverables

1. Add an optional story-level field to schema v2 that marks a story's revealed values as sensitive. The reporter proposed `secrets:`: a list of semantic locators (same locator types as steps) and/or regexes. Document it in `stories/SKILL.md`'s schema section and `story-examples.md`.
2. After a story that declares the field finishes, pass or fail, scrub every artifact the story produced. Replace matched values with a fixed marker in snapshot YAML, trace files and console logs. Delete any screenshot taken at or after the step that first revealed the value, since pixels cannot be reliably redacted by regex. The scrub runs in a `bin/` helper the qa-agent calls, so it is deterministic and testable, rather than in agent prose.
3. The QA report records the outcome per story as `{N} secret value(s) scrubbed from {M} artifact(s); {K} screenshot(s) removed`. If scrubbing fails, the story is reported as failed with the remaining artifact paths, never as clean.

## Acceptance Criteria

- A fixture run of a story with a `secrets:` regex leaves zero matches of the secret value under that story's snapshot, trace and screenshot directories (`grep -r` over them returns nothing).
- Screenshots from the reveal step onward are absent for that story. Earlier screenshots are kept.
- The QA report line names the scrubbed and removed counts.
- A story without the field produces byte-identical artifacts to today. The scrub helper is not invoked.
- A scrub failure (e.g. an unreadable trace file) marks the story failed and lists the unscrubbed paths.
- The scrub helper has unit tests over fixture snapshot YAML, a trace file, and a console log.

## Release Note

QA stories can now mark values as secret, and the QA run removes those values from its snapshots, traces and screenshots afterwards.

## Technical Approach

Two shapes were possible: scrub the artifacts after the story, or suppress artifact capture for sensitive stories. Scrubbing is chosen. Suppression would lose the evidence trail for exactly the stories most worth auditing, and the tooling writes snapshots as part of ref resolution, so they cannot simply be turned off. Resolve a locator-form secret to its value at runtime from the snapshot taken at the reveal step. The value then joins the regex list for the rest of the scrub. Keep the value only in the helper's memory, never in a file or the agent's reply.

### Key Files

- `plugin/skills/stories/SKILL.md` — schema v2: the new optional field
- `plugin/skills/stories/story-examples.md` — an example "reveal once" story
- `plugin/agents/qa-agent.md` — call the scrub helper after a story that declares the field
- `plugin/bin/qa-report.js` — the scrub outcome line
- `plugin/bin/` — new scrub helper (e.g. `qa-scrub.js`) plus `tests/` coverage

## Gotchas

- Trace files may be zip archives. The scrub must handle the container format the tooling writes, or delete the trace and say so in the report line, rather than silently skipping it.
- `playwright-cli` may write snapshots outside `SCREENSHOT_PATH`/`TRACES_BASE` (its own output directory under the cwd). Enumerate every directory the session writes to before declaring zero matches.
- Never log the secret value in `decisions.md`, the QA report, or test fixtures that look real. Fixtures use an obviously fake token.

## Original request

qa-agent / stories: a story that reveals a one-time secret leaves it in snapshot, trace and screenshot artifacts

**Summary:** A QA story that reveals a one-time secret leaves that secret in the run's snapshot, trace and screenshot artifacts. The story schema has no way to mark the value sensitive, so nothing scrubs it.

**Kind:** Gap

**Affected component:** qa-agent + /claude-tweaks:stories (story schema)

**Use case:** A QA story exercised a "token shown once" flow: issue a push token, then check that the panel shows it once. The story prompt told the agent never to print or store the value. The agent complied in its own output. But the browser tooling records every accessibility snapshot, its trace, and the step screenshots on its own. So the freshly minted token ended up in gitignored snapshot/trace files and a screenshot under the tooling's output directory. A manual search found and deleted them after the run.

Prompt instructions can't reach artifacts the tooling writes on its own. Any story whose expected behavior is "reveal a secret once" — API keys, recovery codes, one-time tokens, invite links — will leave that secret in the QA artifacts.

Proposal:
- Add an optional story-level `secrets:` field (or `redact:`): a list of locators or regexes whose matched values are sensitive.
- After each story, the qa-agent scrubs those values from snapshot YAML, traces and console logs, and deletes or redacts screenshots of the matching element.
- The run report then states "N secret values scrubbed from M artifacts", so the operator can trust the cleanup without auditing it by hand.

Evidence: one story out of 18 in a local QA run. 4 artifact files held the value. 0 matches remained after the manual cleanup.

**Definition:** Clear

## Build Alignment Notes

- Beneficial (build Common Step 4.5): trace screencast frames under `.playwright-cli/traces/resources/` are images too, so the scrub deletes those written at or after the reveal, alongside the step screenshots — they hold the same pixels. That directory is shared by parallel stories, so a sibling story's frames written after this story's reveal are deleted as well (its trace still opens, with gaps). Text artifacts are rewritten only when they hold a match, so a sibling's snapshots and logs are untouched.
- Beneficial: the reveal moment is the earliest mtime of a matching aria snapshot (`page-*.yml`), which playwright-cli writes once at the moment it is taken; logs and live traces are appended to, so their mtimes are not used. A match found only outside snapshots leaves the reveal unknown and every in-scope screenshot is deleted.
- Beneficial: the outcome line is rendered in one place (`plugin/bin/lib/qa-scrub/line.js`) and recomposed by `plugin/bin/lib/qa-report/compose.js` (the module behind `plugin/bin/qa-report.js`), so `plugin/bin/qa-report.js` itself needs no change.
