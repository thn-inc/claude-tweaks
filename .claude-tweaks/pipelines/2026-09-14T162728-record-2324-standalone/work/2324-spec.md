# 2324: Release bootstrap: explicit --release-type / --extra-file override for repos whose real manifest is not the root stack manifest

Origin: wrap-up ledger gate for #2253 (run ledger row 31)

Defer-reason: blocked-dependency

## Current State

`plugin/bin/lib/init/release-bootstrap.js`'s stack rule selects a `release-type` only when exactly one stack row matches and falls through to `simple` otherwise (#2253, by design — no precedence rule). This repo carries a root `package.json` (version 6.70.0, 51 minors behind the shipped 6.121.0), so its own bootstrap resolves `node` seeded from that stale manifest, while the design doc's Phase 3 acceptance (dropped at decomposition) and #2259's migration need `simple` with `extra-files` pointing at `plugin/.claude-plugin/plugin.json`. Probed on this checkout: `bootstrapRelease({ dryRun })` → `{ verdict: 'fresh', releaseType: 'node', version: '6.70.0' }`. Run ledger row 31; staged `build-deviation-2` in run `2026-09-11T204239-spec-2251-2252-2253-2254-2255-2256-2258`.

## Deliverables

Add an explicit override to the code twin and CLI: `--release-type <type>` and `--extra-file <path>` (JSON manifest with a top-level `version`, rendered as `{type: json, path, jsonpath: $.version}`), validated against the stack table's type vocabulary plus `simple`; when given, they replace `resolveReleaseType`'s verdict and the manifest seed reads the named file.

Step 21 prose: document the override as the escape hatch for a repo whose real manifest is not its root stack manifest, and note that #2259 uses it.

Tests: override selects `simple` + the plugin manifest on a fixture carrying a root `package.json`; an unknown `--release-type` is a usage error; the override is reflected in the rendered config and the seeded version.

## Acceptance Criteria

On a fixture with a root `package.json` (version 1.0.0) and `plugin/.claude-plugin/plugin.json` (version 6.121.0), `--release-type simple --extra-file plugin/.claude-plugin/plugin.json` produces `release-type: simple`, the matching `extra-files` entry, and manifest `6.121.0` (no `v*` tags present).

Without the override the same fixture still resolves `node` — the single-row rule is unchanged.
