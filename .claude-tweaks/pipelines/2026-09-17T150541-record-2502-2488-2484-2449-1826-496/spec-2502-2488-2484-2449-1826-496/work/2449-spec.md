Surface: infra

## Current State

`/claude-tweaks:dispatch`'s shipped-candidate exclusion (`bin/lib/issues/shipped-candidate.js`, shipped via #1984 as commit `3594fd7e0`) is meant to keep a record whose own deliverables are already present on `main` from being re-dispatched. It did not catch #1892: `/flow #1892` (run `2026-09-14T151422-record-1892`) discovered that every deliverable in #1892's spec (twin-conflict detection, `archived-pending-tracked-move` classification, `residueFailures` pruning, closed-record reopen-on-dedup) was already merged into `main` via PR #2287 two days earlier (`cde8e4e29`/`6b4685bed`/`0e11fe809`, released in v6.122.0) — yet #1892 still carried live `ready` + `auto:build` labels and was selected for this build.

PR #2287's own commit message reads `refs #1892` (a mention, not a GitHub closing keyword — the exact non-closing-mention case #1984 was built to catch via `classifyShipped`'s cross-reference-timeline signal), and PR #2287's title ("bin/lib/reconcile archive-merged.js: fix split-state ENOTEMPTY archival (refs #1892)") is a near-verbatim match of #1892's own title ("bin/lib/reconcile archive-merged.js: split-state run dir makes archival fail with ENOTEMPTY forever and re-files the residue record") — on #1984's own two-tier heuristic this should have scored `strong` (mention by a merged PR + title-token similarity above threshold) and been excluded before dispatch, staging a Close proposal instead of minting a run.
