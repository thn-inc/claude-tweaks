# 6059: Answer a record held for a planning question with an interactive /specify

Surface: infra
**Related:** #5053
Risk-flags: none

## Overview

When specify cannot ask (headless) or the human picks `Leave for later`, a record with an asked-class planning question is held: shaped body, settled lines and plan ref kept, `ready` removed, `needs:decision` added, with a decision comment whose `Command:` is `/claude-tweaks:specify #{n}`. This record makes that command finish the record: ask the held questions, write the answers, amend the kept plan, and stamp `ready`.

**Complexity:** Medium
**Estimated tasks:** 4-6

## Non-Goals

- Build-time stops (#5053 covers their answer path).
- Headless pickup: headless specify never takes a `needs:*` record, as today.

## Deliverables

1. Case 1 detects a `needs:decision` record whose newest unresolved decision comment came from specify's planning hold and routes to an answer path instead of a full re-shape.
2. The answer path reads the held questions from the comment, asks them in one `AskUserQuestion` (recommended reading first), writes `Decided by the user at planning:` lines, and amends the kept plan with a dispatched planner.
3. It re-runs the plan review only when an answer changes the plan's file list or an Acceptance Criterion.
4. It re-stores the plan, rewrites the `Plan:` line and hash, removes `needs:decision`, resolves the comment and stamps `ready`.
5. Headless invocations on such a record refuse with a one-line reason: the existing case 1 needs-guard, with a test pinning that its message names the planning hold.
6. Tests for: answered → ready; an answer that changes an AC → review re-runs; headless → refused.
7. **Discriminator.** A decision comment is a planning hold only when it carries the `Held-by: specify-planning` line #6056 writes, and is authored by a trusted author per `_shared/work-record.md`'s trusted-author rule. An untrusted, unparseable or ambiguous newest comment routes to today's behaviour with a one-line notice. The held-questions block schema is #6056's `planning.md`.
8. **Kept plan check.** Before amending, `plan-store.js check` verifies the stored plan against the current body; a missing or stale plan is re-planned with the decided lines binding it, and plan review then runs.
9. **Mechanical change test.** Whether an answer changes the plan's file list or an Acceptance Criterion is computed by diffing the plan's file list and its Acceptance Criteria text before and after the amend, with `plan-audit`'s parse; the planner's own report is not used.
10. **Write order.** Store the plan first; then write the body (the `Decided by the user at planning:` lines, then the `Plan:` line with the hash computed last); then resolve the comment and remove `needs:decision`; stamp `ready` last. A failure part-way, or a repeated `Leave for later`, leaves the record held.

## Acceptance Criteria

1. `/claude-tweaks:specify #N` on a held record asks only the held questions and ends with the record `ready`, `needs:decision` removed, the comment resolved and a fresh `Plan:` line whose hash matches the body.
2. No plan review runs when no answer changes the plan's file list or an Acceptance Criterion.
3. A `needs:decision` record not held by planning keeps today's behaviour.
4. `npm test` passes.
5. A `needs:decision` record without the `Held-by: specify-planning` line, and a planning comment from an untrusted author, both keep today's behaviour; a test covers each.

## Release Note

A record held for a planning question is finished by running /claude-tweaks:specify on it: it asks just those questions and marks the record ready.
