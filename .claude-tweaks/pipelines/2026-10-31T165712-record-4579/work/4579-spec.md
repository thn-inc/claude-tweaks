# 4579: flow materialize / specify: absence-grep acceptance criteria match the committed work/{n}-spec.md

Surface: infra

**Related:** #2713, #3190, #3721, #3875, #3975, #3976, #3986, #4275, #4452, #4492, #4496, #4573

## Current State

`/claude-tweaks:flow` commits each record's materialized spec onto the feature branch: `plugin/skills/flow/materialize.md:185` states that `.gitignore` carves the `work/` subdirectory out of the otherwise-ignored `.claude-tweaks/pipelines/` tree "so `git add`/`git commit` actually track it", at both `{run-id}/work/{n}-spec.md` and `{run-id}/spec-{N}/work/{n}-spec.md` (`plugin/bin/materialize.js:240-241`, `:627`). On main, `git ls-files -- '.claude-tweaks/pipelines/*/spec-*/work/*-spec.md'` lists 717 such files.

A materialized spec carries the record's own `## Current State` and `## Acceptance Criteria` text, so a record that removes an identifier necessarily quotes that identifier in the committed spec. An absence criterion scoped to the whole repo — `git grep -n -F "<old-name>" -- .` "prints nothing" — therefore always matches the record's own committed spec and can never pass under `/flow`. The observed cost on the filing build: one SDD ruling to exclude `.claude-tweaks/pipelines`, then one pending Review Console item for a human to approve that ruling.

The guidance that governs absence criteria says nothing about this exclusion:

- `plugin/skills/specify/spec-template.md:68` (inside `## Acceptance Criteria`) requires an absence criterion's command to be run once against a tree that still contains the target, and prefers `grep -F` — no mention of the run directory.
- `plugin/skills/specify/spec-template.md:174` (`## Delete + Tombstone Acceptance Criteria`) already handles the analogous self-defeating case for a tombstone comment by scoping the grep, which is the precedent this record follows.
- `plugin/skills/build/plan-authoring-checks.md:71` (**Absence-grep control check**) requires the control run at plan time — no mention of the run directory.
- `reflect/SKILL.md:162`, `wrap-up/leftover-routing.md` and `_shared/ledger-format.md` compose absence criteria into records with their own inline wording rather than citing `spec-template.md`, so an authoring-time rule in `spec-template.md` alone does not reach every record `/flow` builds.

Prior art for the exact pathspec: `plugin/bin/lib/release-tip/check.js:95` already defines `const RUN_DIR_PATHSPEC = ':!.claude-tweaks/pipelines';`, and `plugin/bin/lib/issues/blast-radius.js:107` already treats materialized specs as pipeline bookkeeping rather than implementation.

## Deliverables

1. **Authoring rule — `spec-template.md`.** Extend the absence-criterion paragraph in `## Acceptance Criteria` (line 68): a returns-nothing search whose scope includes the repo root (a `git grep` with no pathspec or a `.` pathspec, or a recursive `grep`/`rg` over the root) excludes the pipeline run directory — `':!.claude-tweaks/pipelines'` appended to a `git grep` pathspec, or the equivalent directory exclusion for another search tool — because `/flow` commits the materialized spec under that directory on the feature branch and the spec quotes the target. A search already scoped to named paths outside `.claude-tweaks/` needs no exclusion. The paragraph states that the control run (run once against a tree that still contains the target and seen to match) applies to the excluded form, and cites #4579.
2. **Build-time backstop — `plan-authoring-checks.md`.** Extend the **Absence-grep control check** paragraph (line 71): when a plan step or pinned acceptance criterion carries a repo-root-scoped absence search without the run-directory exclusion, the plan writes the search with `':!.claude-tweaks/pipelines'` added (or the tool's equivalent) and notes beside the control-run match that the exclusion was added per #4579. This is a plan-authoring correction, never an SDD ruling and never a Review Console item, because it keeps the record's stated intent (the target is gone from the code) and only removes the record's own bookkeeping copy from the search. This covers records composed by `reflect`, `wrap-up/leftover-routing.md` and `_shared/ledger-format.md`, which do not read `spec-template.md`.
3. **Conformance pins — `tests/absence-grep-control-check-prose.test.js`.** Add one assertion per deliverable above: the `## Acceptance Criteria` section of `spec-template.md` (the test's existing `acSection()` slice) contains the literal `:!.claude-tweaks/pipelines` and cites `#4579`; the **Absence-grep control check** paragraph (the existing paragraph slice) contains the literal `:!.claude-tweaks/pipelines` and cites `#4579`.
4. **Journey — `docs/journeys/prove-an-absence-grep-can-match-3571.md`.** Add a step after "Scope out a tombstone" describing the run-directory exclusion for a repo-root-scoped search, with the materialized-spec reason and a link back to #4579, and add the record to its Origin list.

## Release Note

Absence acceptance criteria that search the whole repo now exclude the pipeline run directory, so a `/flow` build no longer needs a Review Console ruling when its own committed spec quotes the removed name.

## Technical Approach

Prose-only change to two shipped skill sub-files plus their existing conformance suite. Follow the `## Delete + Tombstone Acceptance Criteria` precedent: scope the search to exclude a known, structurally guaranteed self-match, and keep the control-run requirement on the scoped form. Use the same pathspec literal `bin/lib/release-tip/check.js:95` already uses so the repo has one spelling. Keep each addition to one or two sentences inside the existing paragraph — no new section — since both paragraphs are already the canonical home for absence-search rules and the conformance test slices them by their existing boundaries.

- `plugin/skills/specify/spec-template.md` — extend the absence-criterion paragraph in `## Acceptance Criteria` with the run-directory exclusion rule
- `plugin/skills/build/plan-authoring-checks.md` — extend the **Absence-grep control check** paragraph with the plan-time correction for a missing exclusion

## Gotchas

- The exclusion must be added to the search, not substituted for the control run: a `git grep` whose pathspec excludes everything still exits 1 on both trees. The control run applies to the excluded form exactly as it applies to a tombstone-scoped grep.
- Do not exclude all of `.claude-tweaks/`: `.claude-tweaks/policy.yml` is real project configuration, and a renamed key living there must still be caught. Only `.claude-tweaks/pipelines` holds bookkeeping copies.
- `tests/absence-grep-control-check-prose.test.js` asserts the Absence-grep control check text appears exactly once in `plan-authoring-checks.md`, so the new sentence goes inside the existing paragraph and must not repeat that phrase.

## Original request

flow materialize / specify: absence-grep acceptance criteria match the committed work/{n}-spec.md

**Summary:** Any "search returns nothing" acceptance criterion can't pass under `/flow`. `/flow` commits the materialized spec (`.claude-tweaks/pipelines/<run>/spec-<n>/work/<n>-spec.md`) onto the feature branch, and that spec necessarily quotes the string being removed.

**Kind:** Gap

**Affected component:** `/claude-tweaks:specify` (acceptance-criteria authoring) and `/claude-tweaks:flow` materialize (`bin/materialize.js`, `work/{n}-spec.md` committed on the branch)

**Use case:** A record removes an identifier (in this case a configuration secret's name), and its acceptance criterion is that `git grep -n -F "<old-name>" -- .` (plus project-specific pathspec exclusions) prints nothing. Under `/flow` the grep always matches the committed materialized spec, whose Current State / AC text quotes the old name. The build had to make an SDD ruling to exclude `.claude-tweaks/pipelines`, and that ruling then needed human approval at the Review Console. Neither `/specify` nor `/build` adds the exclusion or warns about it; a search of main for `:!.claude-tweaks` / "materialized spec" guidance found nothing relevant.

**Suggested direction:** either `/specify` appends `':!.claude-tweaks/pipelines'` to any git-grep absence criterion it writes, or `/build` plan authoring runs such criteria with that exclusion automatically and logs it, instead of routing it through an SDD ruling. Cost observed: one SDD ruling plus one pending Review Console item per affected record.
