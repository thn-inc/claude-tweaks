# 4350: Align the shared fence rule with CommonMark indentation and info-string rules

Origin: build final whole-branch review of #4169 (Minor 1 + 2)

Defer-reason: tangential

## Current State

`fencedLineRanges` (`plugin/bin/lib/issues/record-payload.js`, added by #4169) is the fence rule `extractSection`, `sectionText` and `stripCodeSpans` share. It opens only on a column-0 run of 3+ backticks/tildes and closes only on a column-0 closer, and it accepts a backtick opener whose info string contains a backtick.

CommonMark (which GitHub renders) differs on two shapes: a closer indented 1-3 spaces closes the fence, and a line like ```` ```foo``` is the command ```` is not a fence opener at all. Under the current rule both hide every later heading, so `shapeGate` reports Deliverables / Acceptance Criteria / Release Note missing and `compose-subject.js` refuses at merge time with "carry no non-empty ## Release Note section" on a record that visibly has one. It fails safe; the #4169 whole-branch review found 0 of 1,716 real records with either shape.

Separately, `plugin/bin/lib/release-note-repair/apply.js` (`fenceInfo`, ~lines 25-26) keeps its own looser fence rule (any indentation on opener and closer), so the two can disagree; the repair post-check turns a disagreement into a refused repair, not a bad write.

## Deliverables

- [ ] `fencedLineRanges` accepts 0-3 leading spaces on opener and closer, and rejects a backtick opener whose info string contains a backtick (CommonMark 4.5)
- [ ] `release-note-repair/apply.js` uses `fencedLineRanges` (or the divergence is documented with a reason)
- [ ] the "one fence rule shared by …" comment in record-payload.js names every caller that actually shares it

## Acceptance Criteria

1. `sectionText`/`extractSection` find the record's later sections when a column-0 fence is closed by a closer indented 1-3 spaces.
2. A line starting with ```` ```foo``` is the command ```` does not open a fence: later headings are still found.
3. `npm test` passes, including the `stripCodeSpans` / `shapeGate` suites in `tests/bin-lib/issues/materialize-format.test.js`.

## Release Note

A record whose unclosed code fence hides later sections is now told to close that fence, instead of to add sections it already has; release-note repair reads fences exactly as the shape gate does.
