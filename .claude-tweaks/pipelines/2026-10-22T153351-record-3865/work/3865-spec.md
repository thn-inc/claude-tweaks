# 3865: resolve-run-dir --spec-slug matches by substring, so spec-378 adopts a spec-3784 run

Origin: reflect hindsight from #3784

Defer-reason: tangential

## Current State

`plugin/bin/lib/hooks/run-dir-resolve.js:111` picks the newest run dir whose name `includes(specSlug)`, so `resolve-run-dir --spec-slug "spec-378"` also matches a `…-spec-3784` dir (and a multi-spec `spec-3784-3790` dir). Every caller that adopts a run by record — `/claude-tweaks:wrap-up #{n}` re-entry, `resume`, and #3784's merge mode — can adopt another record's run. #3784 guards merge mode locally (its `config.yml` `spec:` must equal `{n}`); the helper itself is unchanged.

## Deliverables

- [ ] `newestMatch` in `run-dir-resolve.js` matches the spec slug as a whole name segment (the run id's trailing `-{slug}` or a delimited token), never a substring.
- [ ] A regression test where `spec-378` and `spec-3784` run dirs coexist resolves each slug to its own dir.

## Acceptance Criteria

1. `resolve-run-dir --spec-slug "spec-378"` never returns a `spec-3784` dir.
2. Every existing `run-dir-resolve` test still passes.

## Release Note

Re-entering a record's run no longer picks up a different record whose number starts with the same digits.
