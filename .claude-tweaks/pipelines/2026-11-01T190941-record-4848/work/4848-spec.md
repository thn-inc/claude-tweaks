# 4848: Digest rollover drops live entries from clustering, expiry and dedup

## Current State

`plugin/skills/tidy/digest-sweep.md:102-106` closes the digest issue at 100 comments, bootstraps a fresh one, and calls the closed issue's history the archive. It has no step that carries entries over. Cluster promotion, expiry and `isMaterialityDuplicate` all read only the open container (`_shared/materiality-floor.md`'s Dedup and Container sections), so a live entry left in the closed issue can never cluster or expire, and the same finding routes as new on its next sighting.

The rollover has never run: #1426 is the only digest issue ever created. On 2026-11-01 it held 101 comments and 711 entry lines: 633 marked, 78 live. `gh issue list --json comments` reported 100 for those 101, so that read truncates. The 100 threshold has no stated rationale.

## Deliverables

- The `Rollover digest container` procedure carries every live entry (trusted author, no trailing `→` marker) into the new container, keeping its line, fingerprint, provenance and original timestamp. Expiry's age read must survive the move.
- The procedure is ordered so a failure loses nothing: create the new issue without the `digest` label, post the carried entries, verify the count, then move the label and pin, then close the old issue. A partial run is safe to re-run and never leaves two open `digest` issues for bootstrap-race repair to merge.
- Keep the 100-comment trigger and state why: it compacts promoted and expired lines out of every sweep's read, and it matches the point where `gh issue list --json comments` truncates. The threshold read uses the true count (REST `.comments`), and any digest reader uses a paginated read.
- A helper in `plugin/bin/lib/health-core/materiality-digest.js` selects the carry-over set, sharing the trusted-author filter so a planted line is never carried.
- Rollover stays Stage at every tier.

## Acceptance Criteria

- A unit test gives the helper trusted live, marked, expired and untrusted lines, and only the trusted live lines are selected.
- A test proves a carried entry's fingerprint still makes `isMaterialityDuplicate` return true against the new container.
- A test proves a carried entry's expiry age comes from its original timestamp, not the new comment's.
- `digest-sweep.md` names the ordering, the count verification before the close, and the threshold's rationale, pinned in `tests/materiality-floor-conformance.test.js`.
