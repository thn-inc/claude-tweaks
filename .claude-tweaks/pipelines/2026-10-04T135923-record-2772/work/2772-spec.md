# 2772: Make the argument-hint mirror-surface set canonical and mechanically checked — the 'exactly two surfaces' convention was itself an undercount (third: reference-card.md Takes)

Origin: consolidated Review Console — run `2026-09-21T213441-spec-2697-2757-2758-2759`, ledger row #20 (residual scope; the reflect finding's plan-level half was already applied as a skill update at `301a7351b`)

Defer-reason: genuinely-larger

## Current State

Adding a flag to a skill requires updating every *syntactic mirror* of that skill's argument surface.
The count of those mirrors is currently carried in a plan author's head, and it has been wrong twice:

- **#679** established "a new flag has exactly two syntactic-mirror surfaces beyond the Input table"
  — the `argument-hint` frontmatter line and the Input parse line.
- **#2759** proved that convention was itself an undercount. Task 3 updated both named surfaces;
  Task 6's full-suite gate then found a **third**: `plugin/skills/help/reference-card.md`'s `Takes`
  column, byte-pinned by `tests/reference-card-argument-hint.test.js` under #564. Fixed at `613e230`.

It was caught only by luck of two coincidences: that a byte-pinning suite happened to exist for that
particular surface, and that the run's gate compared failing-file **sets** per file rather than
totals (346 failures against a 395 baseline reads as an improvement; only the per-file diff exposed
the new red file).

The plan-authoring half of the fix has shipped: `plugin/skills/build/plan-authoring-checks.md` now
carries "Derive a flag's mirror surfaces by grepping for an existing flag rather than from a
remembered count" (applied this run at `301a7351b`). That makes the next plan author less likely to
undercount. It does **not** make the enumeration canonical, and it does not make an undercount
detectable — which is the residual this record covers.

## Deliverables

- One canonical enumeration of every `argument-hint` mirror surface — a named table in
  `docs/skill-authoring.md`, or a new `plugin/skills/_shared/argument-hint-mirrors.md` — listing the
  frontmatter line, the Input parse line, and `help/reference-card.md`'s `Takes` column as permanent
  entries, with room for the next one.
- One conformance test that walks that enumeration **mechanically** for every skill, so a skill whose
  flag set disagrees across surfaces fails by construction rather than by whichever byte-pin happens
  to exist.
- Retire the "exactly two surfaces" wording wherever it still appears.

## Acceptance Criteria

Adding a flag to any skill's `argument-hint` and leaving `help/reference-card.md`'s `Takes` column
stale fails the new conformance test — proven by making that exact change and showing the test red,
then green after the mirror is updated.

The enumeration lives in exactly one file; no other file restates the list (this repo's
Cross-references convention).

Every existing skill passes the new test at the time it lands, or the exceptions are named.
