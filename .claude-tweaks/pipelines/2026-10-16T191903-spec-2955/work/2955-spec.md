# 2955: review-coordination categorise-reproduction: one finding inside a multi-line statement splits into two unconfirmed findings

Surface: infra

**Related:** #2907, #2908, #2954, #3049

## Current State

`/claude-tweaks:review` Step 3 runs reproduction pairs. Two agents run the same lens, and `bin/review-coordination.js categorise-reproduction` pairs their findings via `categoriseReproduction` (`plugin/bin/lib/coordination.js:285`). A pair is a candidate only when `sameLocation(fa, fb, LINE_TOLERANCE_REPRODUCTION)` holds (`:300`): path exact, `Math.abs(line delta) <= 2` (`:191-198`, constant `:8`). After that comes the #1980 substance check (`sameSubstance`, Jaccard ≥ `SUBSTANCE_SIMILARITY_MIN = 0.4`, `:26`, `:248-252`). The same ±2 rule is restated in prose at `plugin/skills/_shared/multi-agent-coordination.md:49` and `plugin/skills/review/step3-lens-dispatch.md:90-93`, and pinned by `tests/multi-agent-coordination.test.js:321`.

The rule fails on a finding inside one multi-line statement. In the reported run, both agents of the error-handling pair flagged the same issue, a value read inside a multi-line call argument after an external side effect. They anchored it on two different lines of that statement, 3 lines apart. `sameLocation` rejected the pair before substance was ever compared. The result was 0 confirmed and 2 unconfirmed, the real finding was routed to the Review Console's Low-confidence section instead of Step 3 Routing, and the reviewer had to confirm it by hand with the direct-verification override. Reported via `/claude-tweaks:feedback` against plugin 6.133.0.

## Deliverables

1. Add a substance-gated wider tolerance to reproduction pairing. A same-path pair whose line delta is above `LINE_TOLERANCE_REPRODUCTION` (2) but within a new, wider bound (for example 5, matching `LINE_TOLERANCE_DEBATE`) is a candidate only when its `substanceSimilarity` clears a stricter floor than `SUBSTANCE_SIMILARITY_MIN`. Today's ±2 path is unchanged, including the `null`-substance-pairs-as-match rule. An unknown (`null`) substance never qualifies for the wider band.
2. Export the new bound and the stricter floor as named constants next to the existing ones (`:8-26`, export block `:443-448`).
3. Update the prose twins (`_shared/multi-agent-coordination.md:49` and `review/step3-lens-dispatch.md:90-93`) to state the two-tier rule, so the prose and the code agree.

## Acceptance Criteria

- A test in `tests/multi-agent-coordination.test.js` passes two findings on the same path, 3 lines apart, with near-identical text and the same severity bucket. It asserts one confirmed and zero unconfirmed. Prove it goes red against the current ±2-only rule.
- A test with the same 3-line delta but substantively different text (below the stricter floor) asserts both stay unconfirmed.
- A test with a 3-line delta and one side missing its text (`null` substance) asserts both stay unconfirmed.
- The existing ±2, #1980 near-location, and #733 severity-contested tests pass unchanged.
- `tests/bin-lib/review-coordination/cli.test.js` passes unchanged.
- `npm test` passes in full.

## Release Note

Review's reproduction pairs now confirm a finding both agents reported a few lines apart within the same statement, instead of leaving it unconfirmed.

## Technical Approach

In `categoriseReproduction`'s candidate gather (`:297-302`), accept a B finding when `sameLocation(fa, fb, LINE_TOLERANCE_REPRODUCTION)` holds, or when `sameLocation(fa, fb, <wider bound>)` holds and `substanceSimilarity(fa, fb) >= <strict floor>`. Everything downstream (eligible filter, best-score selection, `reconcileSeverity`) stays unchanged. Keep `findingsMatch`'s default untouched unless a caller needs the same widening, and check its callers first.

The reporter's other option, anchoring both findings to the enclosing statement's line range, is not chosen. `coordination.js` is pure and receives only `path:line` plus text, so finding a statement range would mean reading and parsing source files inside a module that does no I/O today.

### Key Files

- `plugin/bin/lib/coordination.js` — `categoriseReproduction`: substance-gated wider tolerance band; new exported constants
- `plugin/skills/_shared/multi-agent-coordination.md` — restate the two-tier line rule (`:49`)
- `plugin/skills/review/step3-lens-dispatch.md` — restate the two-tier line rule (`:90-93`)
- `tests/multi-agent-coordination.test.js` — 3-line-apart confirm, different-substance, and null-substance cases

## Gotchas

- Choose the stricter floor with a fixture, not by intuition. Jaccard over tokenized finding text is sensitive to normalization, so check the reported pair's actual text scores above it and an unrelated same-statement pair scores below it.
- The wider band must not change the #1980 `nearLocation` behavior for pairs within ±2. That branch fires only when every same-location candidate is substantively different. Make sure a wide-band candidate that fails the strict floor is simply not a candidate, rather than being reported as `nearLocation`.
- `detectCrossLensOverlap` already uses `LINE_TOLERANCE_DEBATE` (5) for a different purpose (`:368`). If the new bound reuses that value, give it its own constant name so the two can diverge later.
