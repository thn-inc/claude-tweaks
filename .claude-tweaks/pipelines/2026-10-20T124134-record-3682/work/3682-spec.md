# 3682: Move the remaining pre-tool-use safeReal comparisons to case-canonical realpath

Origin: ledger resolve gate (wrap-up of #3495, ledger row 3)

Defer-reason: pre-existing-outside-diff

**Related:** #3642

## Current State

plugin/bin/lib/hooks/pre-tool-use.js compares paths resolved with the JS fs.realpathSync (safeReal) in several worktree-always gate decisions: the teardown gate's own-cwd containment (safeReal(target) === mainRoot and the isPathContained check, ~lines 564 and 577) and the E1 / worktree-identity checks (~lines 1746-2140). The JS form echoes the input's casing on a case-insensitive volume, so a mis-cased target or cwd can slip past those comparisons (IL-150, #3380). #3495 moved only isPolicyFile and shadowPipelineRunDir to path-guard's case-canonical .native resolvers; the remaining safeReal comparisons were left as they were, so some sites resolve one way and some the other.

## Deliverables

- [ ] Audit each remaining `safeReal` comparison in `plugin/bin/lib/hooks/pre-tool-use.js` and decide per site whether both operands can move to `canonicalRealpath()` together (a one-sided move turns an allow into a deny or the reverse)
- [ ] Migrate the sites that can, with a case-insensitive-fs regression test each (`tests/helpers/case-insensitive-fs.js`)
- [ ] Update the `lib/hooks/pre-tool-use.js` allowlist reason in `tests/path-guard-conformance.test.js` and the `pre-tool-use-gate-exemptions` skill row that says `safeReal` stays JS-form

## Acceptance Criteria

- [ ] A mis-cased cwd or target is treated the same as the correctly-cased one by the own-cwd containment and E1 checks, shown by tests on the case-insensitive fake
- [ ] `npm test` passes, including `tests/path-guard-conformance.test.js`

## Release Note

The worktree guard treats a path typed with different letter casing the same as the correctly-cased one.
