# 3192: Multispec pr-first teardown archives the run directory too early (step 7)

Defer-reason: pre-existing-outside-diff

Origin: #3088's final whole-branch review (scoped re-review step), 2026-10-15

## Current State

`plugin/skills/flow/multispec-review-console.md` step 7 ("Shared teardown") calls `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" teardown-run --run "$MULTISPEC_PARENT_DIR" --merged` unconditionally, immediately after step 6's `ExitWorktree`. `teardown-run` always archives the run directory internally (moves it to `archive/{run-id}/`) unless the `--remote-ref-only` flag (added by #3088, commit `fa6390614` on branch `worktree-dispatch-record-3088`) is passed.

Per `plugin/skills/wrap-up/cleanup-procedures.md`'s "Ordering rule, first half" (run-directory archival is item 8, always last — items 4, 6, and 7 still need to read/write files under `$RUN_DIR`), archiving the run directory this early breaks any later cleanup step in the multispec consolidated teardown/wrap-up sequence that still expects `$RUN_DIR` to resolve: ephemeral dev server teardown reading `${RUN_DIR}/ephemeral-server.txt`, issue claim release's `parked-at-shaping` restore reading `${RUN_DIR}/work/*-spec.md`, and Section B's own archival step running against a directory that has already moved.

This is the exact same defect class #3088 fixed in `plugin/skills/wrap-up/cleanup-procedures-execution.md` Section C's own step 5.5 (which used to call plain `teardown-run --merged` the same unconditional way, before #3088 added `--remote-ref-only`) — but `multispec-review-console.md` step 7 is a separate call site in a separate file that #3088's plan never touched, since #3088 was scoped to the single-spec own-worktree teardown path only. Discovered by #3088's final-review re-reviewer while verifying that fix; flagged as out-of-scope there and filed here as a follow-up rather than folded into #3088's own diff.

## Deliverables

1. Update `plugin/skills/flow/multispec-review-console.md` step 7's `teardown-run` invocation to pass `--remote-ref-only`, the same way `cleanup-procedures-execution.md`'s step 5.5 now does, so archival stays with whatever step in the multispec sequence is actually responsible for it last.
2. Confirm (or fix) where multispec's own run-directory archival actually happens relative to this step — if it is a different call site than Section B's single-spec archival, trace it and make sure the "archival always last" ordering invariant genuinely holds for the multispec path too, not just assumed by analogy to the single-spec fix.
3. Add or extend a prose-conformance test confirming step 7 uses `--remote-ref-only` — check what existing test file already pins `multispec-review-console.md` before adding a new one.

## Acceptance Criteria

- `multispec-review-console.md` step 7's `teardown-run` call includes `--remote-ref-only`.
- The run directory is still present and readable by every later multispec cleanup step that needs it, for a `pr-first` own-worktree multispec teardown.
- `npm test` passes, with no new attributable failures.

## Release Note

Multispec `pr-first` teardown no longer archives the run directory before later cleanup steps (ephemeral server teardown, issue claim release) have finished reading it.
