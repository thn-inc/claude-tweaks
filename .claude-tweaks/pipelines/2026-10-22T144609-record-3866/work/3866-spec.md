# 3866: pr-first-merge Step 4.2 logs to the run dir after reconcile archived it, recreating the dir

Origin: ledger resolve gate

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/skills/_shared/pr-first-merge-post-merge.md` Step 4.2 runs `hooks.js reconcile --checks mirror,release,archive`, whose `archive` check moves this run's dir to `.claude-tweaks/pipelines/archive/{run-id}/`, and then tells the caller to log a `decisions.md` line — the "{N} other run dir(s) need human action" line when this run's own check is clean. That line targets `$PIPELINE_RUN_DIR/decisions.md`, which no longer exists after a successful archive, so the write recreates an un-archived run dir holding one `decisions.md`. Every Step 4.2 caller is affected (`review-console.md` step 13, the auto-merge short-circuit, `wrap-up/merge-mode.md`, dispatch's auto-merge gate). Found by #3784's SDD final review (Minor 6); ruled out of #3784 scope as staged/sdd-ruling-4.md.

## Deliverables

- [ ] Step 4.2 writes any post-reconcile `decisions.md` line to the run's archived path when reconcile archived it (`_shared/timing-render.md`'s archive-path rule), or before the reconcile call — never to the moved `$PIPELINE_RUN_DIR`.
- [ ] A conformance test pins the chosen ordering in `pr-first-merge-post-merge.md`.

## Acceptance Criteria

1. After a Step 4.2 run whose reconcile archived the run dir, no directory reappears at `.claude-tweaks/pipelines/{run-id}/`.
2. The "other run dir(s) need human action" note still reaches the archived run's `decisions.md` or the closing report.

## Release Note

A merged run's directory no longer reappears under .claude-tweaks/pipelines after it has been archived.

## Technical Approach

### Key Files

- `plugin/skills/_shared/pr-first-merge-post-merge.md` — write post-reconcile log lines to the archived run path, or before reconcile
