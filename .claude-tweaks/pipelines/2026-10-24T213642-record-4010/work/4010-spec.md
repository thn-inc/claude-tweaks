# 4010: Add a lib-module-split project skill — pure-move proof and stale-location sweep

Origin: spec #2805 review (hindsight)

Defer-reason: genuinely-larger

## Current State

PR #2822 (refs #2805) split `plugin/bin/lib/issues/record.js` (high fan-in, ~100 import sites) into four sub-modules behind a re-export facade. Its review had to establish two things no project skill describes.

The proof that a split is a pure move: the export surface and every exported function's source compared base vs head, plus every base top-level declaration found verbatim in a new module. Neither the build nor its wrap-up ran it; the review did, from scratch scripts.

The blind spot: prose that states where code lives or what a file requires — code comments (`autonomy.js` "record.js requires only ./facet-shape"), pointers to non-exported internals (`record.js`'s `DEP_RE`), skill bullets, and journey `files:` frontmatter that journey-health and visual-review read. The build's docs curation updated only `docs/plugin-structure.md`; the review found 15 stale claims across 16 files (fix commit 31cf39c0e).

## Deliverables

- [ ] A project skill `.claude/skills/lib-module-split/SKILL.md` covering: when a facade is preferred over migrating call sites; the pure-move proof (export-surface + function-source identity, verbatim top-level-declaration check, require-cycle check); the stale-location sweep (grep `{file}'s {symbol}`, "in {file}", "requires only", and journey `files:` entries naming the split file — keeping references that name the still-valid public import path); and updating `docs/plugin-structure.md`.

## Acceptance Criteria

- The skill names the three proof checks and the four stale-claim shapes above, each with the command or grep that finds it.

- The skill distinguishes an import-path reference (still correct after a facade split) from a definition-location claim (stale), with one example of each from #2805.
