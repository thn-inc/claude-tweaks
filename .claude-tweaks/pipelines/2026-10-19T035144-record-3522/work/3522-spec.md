## Current State

`plugin/skills/_shared/pr-first-merge.md` Step 3 prescribes the merge call verbatim as `SUBJECT_EXPORTS=$(node "${CLAUDE_PLUGIN_ROOT}/bin/compose-subject.js" {issue-list} --tag {tag} --shell) || exit 1`, `eval "$SUBJECT_EXPORTS"`, then `gh pr merge {n} … -t "$SUBJECT_TITLE" -b "$SUBJECT_BODY"` (lines ~276-280 and ~314-318). From a worktree-isolated session the harness Bash guard refuses that shape ("runs eval inside a construct too complex to verify"), and the obvious rewrite `-t "$(cat title.txt)"` is refused too ("runs gh with a value computed at runtime"). Every pr-first merge runs from a worktree session — dispatch's second Task call, and a close-out run by a dispatching session that is itself in a worktree — so the skill's own canonical snippet is unrunnable exactly where it is meant to run. On 2026-10-18 the #3450 and #3499 merges each cost three refused Bash calls and a hand-rolled split of the composer's `--shell` output into a title literal and a `--body-file` (two `wd-guard-refusal` events in run 2026-10-17T215350-record-3417).

## Deliverables

Give `plugin/bin/compose-subject.js` a file-emitting form — e.g. `--out-dir <dir>` writing `title.txt` and `body.md` (or `--title-file`/`--body-file`) — alongside the existing `--shell` form, with the title also printed on stdout as a single line so a caller can paste it as a literal.

Rewrite `_shared/pr-first-merge.md` Step 3's two merge snippets (the `--auto` call and the immediate-merge degrade) as plain, one-command-per-line, guard-safe shapes: compose to files, then `gh pr merge {n} --repo {owner}/{repo} [--auto] --squash -t "{title literal}" --body-file {dir}/body.md` — no `eval`, no `$(…)` around `gh`.

Update every other caller of the `--shell` form (grep `compose-subject.js` across `plugin/skills/` and `plugin/bin/`) to the same shape, and extend or add the conformance test that pins Step 3's snippet so the `eval` form cannot return.

## As-built deviations (Common Step 4.5 — all Beneficial)

1. `--out-dir` also writes `message.txt` (title, blank line, body) beside `title.txt`/`body.md`, so the local-merge fences use `git merge --no-ff {branch} -F "{subject-dir}/message.txt"` with no title paste at all.
2. The stdout title line is POSIX single-quoted (`shellQuote(title)`), not raw. A title carrying `$(…)`, backticks or `'` (this record's own title has `$(…)`) stays inert when pasted verbatim as `-t {title-arg}`.
3. The four local-merge fences keep `|| exit 1` on the composer line. They are multi-line scripts run in one call from the main checkout, two of them inside an existing `if [ "$CURRENT" … ]` guard. The pr-first fences, which run from worktree sessions, are one plain command each, with stop-on-non-zero in prose.
4. `{subject-dir}` is a literal session-tmp path, resolved once via `session-tmp-resolve.js SUBJECT_DIR=merge-subject-{key}` and double-quoted in every fence, so a space in `os.tmpdir()` cannot split it.
