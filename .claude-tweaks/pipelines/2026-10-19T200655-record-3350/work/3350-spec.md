# 3350: Run config never carries the integration-model pin — pr-first PR-bookend checks silently skip

Origin: ledger resolve gate (run 2026-10-16T172750-spec-2775-2733-2677, item 4)

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/skills/_shared/integration-model.md`'s "Run-scoped stability" says a run pins `integration-model` into its own `config.yml`. Nothing writes that pin: `bin/set-config.js` refuses the key because it is not a Manifesto lever, and the Manifesto's 13-lever batch omits it.

Two readers depend on it and resolve `null` instead: `first-call-artifact-check.js` (`resolveIntegrationModel`, run-config only) and `verify-run-bookends.js` (`readConfigIntegrationModel`). Both then silently skip their pr-first PR-bookend checks. Found in run 2026-10-16T172750-spec-2775-2733-2677 (ledger item 4, refs #2775), whose pin was appended by hand.

## Deliverables

- The Manifesto writes `integration-model` into every run's `config.yml` (as resolved at run start), through the sanctioned writer, so the documented pin exists.
- `set-config.js` accepts `integration-model` (or the Manifesto writes it through the same path it uses for its levers).
- `first-call-artifact-check.js` and `verify-run-bookends.js` report an explicit degrade when the pin is absent, rather than silently skipping the PR-bookend check.

## Acceptance Criteria

- A fresh pr-first `/claude-tweaks:flow` run's `config.yml` carries `integration-model: pr-first` with no hand edit.
- With the pin present, both checks run their PR-bookend assertion (a test per reader proves it runs, not skips).
- With the pin absent, each reader prints a degrade line instead of passing silently (a test asserts the line).

## Release Note

Fixed: pr-first runs now record their integration model, so the PR-bookend checks actually run instead of silently skipping.

## Implementation notes (build, architecture alignment)

- Beneficial: when `resolve-policy.js --values integration-model` prints an empty value (an invalid `integration-model` in policy.yml), the Manifesto omits the pin pair so the 13 levers still write, and logs a `SKIP` decision. The run proceeds unpinned and both bookend readers print their degrade line. Writing `integration-model=` would have made `set-config.js` refuse the whole batch.
- Beneficial: `integration-model` is a *run pin* (`RUN_PINS` in `bin/lib/set-config/write.js`), not a Manifesto lever. It has no levers-table row and no override number. The decisions.md snapshot header lists it, so `flow/steps-and-gates.md` case-3 recovery restores the run-start value instead of re-detecting. `two-call-gate.md`, `task-prompt.md` and `claim-targets.md` log a reader's degrade line as a `SKIP` decision.
