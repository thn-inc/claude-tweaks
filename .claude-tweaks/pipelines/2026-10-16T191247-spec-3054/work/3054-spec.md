# 3054: Evaluate self-evolving skill/harness patterns for claude-tweaks

Surface: infra

## Current State

The original request says claude-tweaks "has no process for letting a skill improve itself from its own usage traces". That premise is partly wrong. Several trace-driven improvement loops already exist, and every one of them is human-gated:

- `/claude-tweaks:harness-health`'s Dream Pass (`plugin/skills/harness-health/dream-pass.md`, #2691) scans this account's own session transcripts (`plugin/bin/dream-scan.js`, `plugin/bin/lib/dream/scan.js`). It looks for tool-call failures that repeat across two or more independent sessions and stages proposals only: no code path can write to `plugin/skills/**/*.md` or CLAUDE.md.
- `/claude-tweaks:feedback`'s session evaluation (`plugin/skills/feedback/session-evaluation.md`) judges a session transcript against the maintainer objectives rubric (`plugin/skills/_shared/feedback-objectives.md`) through the shared transcript-judge harness (`plugin/skills/_shared/transcript-judge.md`). It files upstream issues after an explicit scrub and confirmation.
- `/claude-tweaks:wrap-up`'s curation engine (`plugin/skills/wrap-up/curation-engine.md`) is the per-run self-improvement judgment site. It reads the run's `decisions.md`, `events.jsonl`, ledger and commits, then proposes skill updates that surface at the Review Console for approval.
- `evals/` is a separate eval/benchmark harness ("drills") that measures skill cost and quality on fixture scenarios, with recorded baselines in `evals/BASELINES.md`.

What does not exist: an automated loop that rewrites skill text itself (SkillOpt / WikiSkill style), evolves the harness from execution traces (Darwin Godel Machine / Self-Harness style), or trains on harness-discovered behavior.

The external prompt for this record is AlphaSignal's deep dive on self-evolving agent stacks (see the original request below).

## Deliverables

1. A written recommendation, posted as a comment on this record, on whether and where self-evolving patterns fit claude-tweaks. It should cover:
   - each of the three pattern families (skill self-rewriting, harness evolution from traces, trace-trained models), mapped to the closest existing loop above, with the concrete gap each would close or a statement that the existing loop already covers it;
   - the main risk, stated explicitly: unreviewed autonomous changes to shipped skill text, which reaches every consumer through the plugin marketplace;
   - whether any candidate loop could keep the existing propose-only, human-approval posture (Dream Pass staging, Review Console approval) and still be worth building;
   - which evaluation signal a self-improvement loop would optimize against (the `evals/` drills, the feedback objectives rubric, or something new), and whether that signal is trustworthy enough to optimize against.
2. When the recommendation endorses a prototype, file it as a backlog record via `/claude-tweaks:capture` with a spec-shaped body. It should name one existing skill as the target and keep a human-review gate. Otherwise, state explicitly that no prototype is recommended.

## Acceptance Criteria

- The recommendation comment exists on this record and addresses each of the four points in Deliverable 1, citing the files above for what already exists.
- It explicitly names unreviewed autonomous skill changes as the main risk and states how any endorsed loop keeps a human-review gate.
- It states a clear verdict: no change, extend an existing loop (naming which one), or a new loop.
- Every endorsed prototype has a filed backlog record linked from the comment; no endorsed change is left as prose only.

## Technical Approach

A desk evaluation, with no code or skill edits in this record. Start from the existing loops (Dream Pass, feedback session evaluation, wrap-up curation, evals drills) and ask, for each pattern family, what it would add over extending one of them. The likely shape of a positive answer is a narrower, propose-only optimizer that drafts skill-text changes against an eval signal and stages them for human approval. An autonomous rewriter that applies changes on its own is not that shape.

### Key Files

- `plugin/skills/harness-health/dream-pass.md` — existing cross-session, propose-only transcript loop
- `plugin/skills/feedback/session-evaluation.md` — existing transcript judge against the objectives rubric
- `plugin/skills/wrap-up/curation-engine.md` — existing per-run skill-update proposal site
- `evals/BASELINES.md` — existing eval harness baselines, a candidate optimization signal

## Gotchas

- The original request's premise that claude-tweaks has no trace-driven improvement process is incorrect: the loops listed under Current State exist. The recommendation must evaluate them, not propose a parallel system blind to them.
- The original Deliverables included "prototype one low-risk self-improvement loop". This record scopes that to a filed follow-up record, endorsed by the recommendation, so that the evaluation stays agent-sized and the build gets its own spec.
- Optimizing skill text against `evals/` risks overfitting to fixture scenarios. Baselines are never edited to match observed runs (`evals/BASELINES.md`'s own rule), so any optimizer loop must not touch the corpus either.
- Any loop that edits `plugin/skills/**` changes a shipped contract. The expand-contract discipline in CLAUDE.md applies to whatever it proposes.
