# 2724: reconcile: structurally-stuck run directories

Surface: infra

## Current State

Reconcile classifies a pipeline run directory as `structurally-stuck` when it carries a skip reason of `no-worktree`, `no-branch`, `no-pr`, or `console-never-rendered-pr-closed` and has been stale past `STRUCTURALLY_STUCK_TTL_MS` (`plugin/bin/lib/reconcile/archive-merged.js`'s `classifyRunDir`). This classification is deliberately visibility-only — `trackStuckSkip` never changes what `archiveMerged` does with the directory (still just skip); it exists solely to escalate a single shared GitHub issue (this one, per `escalate-residue.js`'s #1811 Deliverable 4 — one issue for the whole reason, not one per path) so a human notices directories reconcile has decided it cannot safely resolve on its own.

This record was auto-filed naming exactly one stuck path (`.claude-tweaks/pipelines/2026-09-13T202040-record-1798`), which has since been cleaned up independently — that specific instance is stale and no longer needs action. However, a fresh `bin/hooks.js reconcile --json` run (during this shaping pass) shows the underlying condition is still live: 16 run directories currently classify under a structurally-stuck-eligible reason, several dating back to late August (`2026-08-26T191436-record-573`, `2026-08-27T*` — four more `console-never-rendered-pr-closed` entries, `2026-08-12T204800-tidy-standalone`) — weeks past any reasonable TTL. The escalation mechanism is working as designed; nobody has acted on the directories it's pointing at.

## Deliverables

- Re-enumerate the current candidate set fresh (`bin/hooks.js reconcile --json`'s `runs[]` array, filtered to `action: "skipped"` with `reason` in `no-worktree`/`no-branch`/`no-pr`/`console-never-rendered-pr-closed`) — the list in this record's Current State will have moved again by build time.
- For each candidate, confirm it's genuinely inert before touching it: no live worktree (`git worktree list`), no live local/remote branch matching its run, and — for a PR-linked run — the PR's actual state via `gh pr view` (a `console-never-rendered-pr-closed` classification specifically requires re-confirming the PR is CLOSED, never MERGED, per `archive-merged.js`'s own carve-out comment).
- Archive each confirmed-inert directory via the existing `bin/hooks.js archive-run --run <dir>` mechanism. For any directory that turns out to still hold recoverable unfinished work (a false positive in the staleness classification — e.g. a worktree that exists but reconcile's snapshot didn't see it), leave it and document why in this record's own thread rather than archiving it.

## Acceptance Criteria

- Every run directory `bin/hooks.js reconcile --json` currently classifies as `structurally-stuck`-eligible (the four reasons above) and past its TTL is either archived or left with a documented reason (posted as a comment on this issue) for why it was deliberately kept.
- A `bin/hooks.js reconcile --json` run after cleanup shows the candidate set has shrunk to zero, or only to directories newly gone stale since this pass began (with a one-line note on why those are out of scope for this pass).
- No `git worktree`/branch that is genuinely still in use gets archived — the live-check above must run before every archival, not be skipped as "probably fine."
