# 3079: build: an AC met only by a scratch check leaves no run-dir artifact for /dispatch's second call

Surface: infra

## Current State

`/claude-tweaks:build` tells every implementer, in fixed words, that "scratch checks stay scratch" (`plugin/skills/build/SKILL.md:223`, quoting CLAUDE.md's Working Approach). Nothing in build's plan guidance (`plugin/skills/build/plan-authoring-checks.md`) or its Final Verification step (`SKILL.md:266-272`, which runs `skills/test/verification.md`'s runner checks only) says what happens to the *result* of a scratch check. That matters when the check is the only evidence for an acceptance criterion. The plan is free to route that result into a conversational "build handoff" (`plugin/skills/build/handoff-template.md`).

That works in one session, but not under `/claude-tweaks:dispatch`'s two-call split. Call 1 (`build,test`) and call 2 (`review,polish,wrap-up`) are separate Task calls that share only the run directory. Review's spec-compliance check marks each criterion `met`/`partially met`/`not met` by asking whether it is "verifiable from the code and tests" (`plugin/skills/review/code-mode-steps.md:31`). It has no place to look for a scratch result call 1 produced.

Observed (original request below): an AC of "a rendered contrast audit over the main routes reports 0 failures" was met by a scratch audit in call 1. `decisions.md` mentioned "the AC2 rendered audit" with no result, counts, or log path, so call 2 had to re-run the whole audit (68 page renders plus controls).

`plugin/skills/build/SKILL.md` is 45,186 bytes against the 46,080-byte per-SKILL.md ceiling (`plugin/bin/lib/skill-audit/context-cost.js:31`, `45 * 1024`). New prose has to live in a sub-file.

## Deliverables

1. Add an "AC-evidence persistence" check to `plugin/skills/build/plan-authoring-checks.md`. When a plan task verifies an acceptance criterion only with a scratch (uncommitted) check, the plan must name that check's run-dir evidence destination, never a conversational handoff. The destination is one `decisions.md` entry written via `node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "$PIPELINE_RUN_DIR" --status AUTO --step "AC evidence"`. Its text carries:
   - the criterion it covers;
   - the exact command shape;
   - the pass/fail counts.
   When the check's output is too long for one line, the plan also writes the full log to `$PIPELINE_RUN_DIR/evidence/` and cites that path in the same entry.
2. In `plugin/skills/review/code-mode-steps.md`'s Acceptance Criteria check (check 2), add: before marking a criterion `not met` for lack of code or test evidence, read the run's `decisions.md` for an `AC evidence` entry naming it. When one exists, cite it as the criterion's evidence instead of re-executing the check. When `$PIPELINE_RUN_DIR` is unset (standalone review), behavior is unchanged.
3. Leave `plugin/skills/build/SKILL.md` unchanged. If a pointer is unavoidable, it must fit the ceiling headroom; confirm with `node plugin/bin/context-cost-report.js` or the context-cost test.

## Acceptance Criteria

- `plan-authoring-checks.md` carries a check requiring a scratch-verified AC's result to go to the run dir via `log-decision.js --step "AC evidence"`, with the criterion, command shape, and pass/fail counts in the entry text, plus a `$PIPELINE_RUN_DIR/evidence/` log for long output.
- `review/code-mode-steps.md`'s check 2 instructs reading `decisions.md` for an `AC evidence` entry and citing it rather than re-running the check. It names the unset-`$PIPELINE_RUN_DIR` standalone case as unchanged.
- `plugin/skills/build/SKILL.md` stays under the context-cost ceiling. The repo's context-cost test (`tests/bin-lib/skill-audit/context-cost.test.js`) passes.
- `npm test` passes, since conformance tests pin skill prose repo-wide.

## Release Note

Fix dispatched builds losing scratch-check results between calls: an acceptance criterion verified by an uncommitted check now leaves its result in the run directory for review to cite.

## Technical Approach

A prose-only change in two sub-files. The evidence channel reuses the existing sanctioned run-dir writer (`bin/log-decision.js`) rather than a new artifact format, so `/claude-tweaks:wrap-up`'s console and any later reader see it in the same `decisions.md` they already read. Write the `evidence/` subdirectory only for long logs, and keep its path under `$PIPELINE_RUN_DIR`, never a relative path, per `_shared/pipeline-run-dir.md`.

### Key Files

- `plugin/skills/build/plan-authoring-checks.md` — new AC-evidence persistence check
- `plugin/skills/review/code-mode-steps.md` — check 2 reads `AC evidence` entries before declaring a criterion unverified
- `plugin/skills/build/SKILL.md` — no change expected (ceiling headroom ~900 bytes)

## Gotchas

- "Scratch checks stay scratch" governs whether a check's *code* is committed, not whether its *result* is recorded. The new check must say so explicitly, so the two rules are not read as contradicting each other.
- A recorded result is evidence, not proof. Review may still re-run a check whose entry looks inconsistent with the diff, for example a stale command shape. The rule removes the forced re-run; it does not forbid one.
- Byte-pinned conformance tests cover `plugin/skills/**` prose. Run the full suite before merging, not just the targeted ones.

## Original request

build: an AC met only by a scratch check leaves no run-dir artifact for /dispatch's second call

**Summary:** An acceptance criterion met only by a scratch (uncommitted) check leaves no run-dir artifact, so /dispatch's second call cannot verify it without re-running the check.

**Kind:** Gap

**Affected component:** build (plan + test-phase exit), under /claude-tweaks:dispatch's two-call split

**Use case:**
A record's acceptance criterion read "a rendered contrast audit over the main routes reports 0 failures." The plan /build wrote said the audit "stays scratch (per the project's working approach); its result is reported in the build handoff." Under /dispatch's two-call split (`build,test`, then `review,polish,wrap-up` as a fresh Task call with no conversation), there is no conversational handoff. The first call's `decisions.md` mentioned "the AC2 rendered audit" but recorded no result, counts or log path. The second call's review has to re-derive its verdict from raw artifacts, so it had nothing to read for that criterion and had to re-run the whole audit (68 page renders plus controls).

Why was this possible? The plan routed the scratch check's result into a conversational handoff. Plans assume one session. Nothing in /build's plan or test-phase guidance says an AC verified only by an uncommitted check must persist its evidence to the run dir. CAUSAL: systemic.

Proposed fix: when an acceptance criterion's only evidence is a scratch check, /build's test-phase exit (or the plan template) should require one of two things:
- a `decisions.md` line carrying the result (pass/fail counts and the command shape), or
- the check's log written into the run dir.

The second dispatch call's review can then cite it as a raw artifact instead of re-running it or trusting a mention.

Acceptance: a dispatched two-call run whose AC is met by a scratch check leaves, in the run dir after call 1, a result line or log that call 2's review cites without re-executing the check.

**Definition:** Clear

**Plugin version:** 6.137.0

## Build deviations (Common Step 4.5)

- **Beneficial: evidence log always written when a run directory exists.** Deliverable 1 said the `$PIPELINE_RUN_DIR/evidence/` log is written only when the check's output is too long for one line. As built, the log is always written whenever a run directory exists. Separately, `plugin/skills/dispatch/task-prompt.md`'s second-call template gains one line: an `AC evidence` entry is checked against the `evidence/` log it cites, and the check is re-executed only when that log is missing or does not match. The reason: the template's CRITICAL re-derive-from-artifacts rule treats a bare `decisions.md` line as an unverified claim. A short-output entry with no log would therefore still force call 2 to re-run the check, which defeats this record's own acceptance test ("call 2's review cites without re-executing the check"). The SDD whole-branch review found this, and commit c6b5a1f16 fixed it.
- **Premise correction.** The governing size limit is `RAIL_BYTES` = 52,500 B (`plugin/bin/lib/skill-audit/budgets.js`). Current State cites a 46,080-B per-SKILL.md ceiling instead, which is stale. `plugin/skills/build/SKILL.md` (47,644 B) is unchanged either way.
