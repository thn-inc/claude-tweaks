# 5148: review: effort size proxy counts prose, plan and run-dir files, and every info finding gets a Capable tiebreak

Surface: backend
Risk-flags: none

## Current State

`/claude-tweaks:review` Step 2.5 derives `review-effort` from the record's `risk:*` × `size:*` labels, cross-checked against a diff heuristic, and takes the higher of the two (`plugin/skills/review/review-effort-derivation.md`, steps 3-4). The heuristic's record-size proxy reads Step 2's `git diff {base}...{branch} --stat` totals: **high** at 10+ files or 300+ lines, **medium** at 3-9 files or 50-299 lines (`plugin/skills/review/code-mode-steps.md`, Step 2). Nothing is excluded from those totals. A pipeline run's own committed artifacts therefore count as code size. These are the materialized spec under `.claude-tweaks/pipelines/**/work/{n}-spec.md`, the plan under `docs/superpowers/plans/**`, the run ledger `docs/plans/*-ledger.md`, and package-manager lockfiles. The result is a heuristic tier that is pushed up and overrides a low label tier.

Three measured cases from consumer runs, all reported on this record:

- plugin 6.164.0: `risk:low` × `size:low`, 10 files / 412 lines, mostly spec, plan, ledger and prose. The diff tier was `medium` over a label tier of `low`, which dispatched 8 lens agents.
- plugin 6.164.0: 13 files / 350 lines, about 245 of them flow artifacts and about 60 lines of production change in 3 files. A one-line comment-only edit to the schema file also fired the risk proxy's "schema/migration file" trigger, so high × high resolved `max`: 19 dispatches, every confirmed finding low or info.
- plugin 6.165.0: 23 files / 462 lines, about 300 of them plan (172), lockfile churn (274) and materialized spec (61). An infra/CI risk proxy of `high` resolved `max` over a label tier of `medium`, which dispatched about 35 agents for a code delta under 100 lines.

The "bookkeeping" path class is already defined in two places. One is `plugin/bin/lib/init/verify-scope-starter.js`'s `BOOKKEEPING_RULES`: `docs/plans/*-ledger.md`, `.claude-tweaks/pipelines/**`, `docs/superpowers/plans/**` and `docs/superpowers/specs/**`. The other is a project's `.claude-tweaks/verify-scope.json`, where these rules are declared as `{ "suites": [], "static": false }`, first match wins (`plugin/bin/lib/verify/scope.js`'s `selectScope`, matched with `globToRegExp` from `plugin/bin/lib/issues/blast-radius.js`). Lockfiles are already named in `plugin/bin/lib/review-context/build.js`'s `ALWAYS_STUB_BASENAMES`, which the review-context bundle stubs.

The record's Step 3.7 tiebreak half is settled and out of scope: #5540 batches tiebreak findings 8 per judge with one settle call per chunk, and #5541 moved `info` findings to the Standard tier. Resolving `info` findings as `drop` with no judge was measured and rejected (19.0% agreement).

**Related:** #5929, #5569, #5076, #5213, #5475, #5972, #4937, #6008

## Release Note

Review sizes a change by its code, not by the pipeline's own spec, plan, ledger and lockfile files, so small changes no longer get the heaviest reviews.

## Technical Approach

The core is a pure function, so tests feed it numstat text and a declaration object with no git. The CLI verb only gathers inputs. It reuses `readDeclaration` (`plugin/bin/lib/verify/declaration.js`) and the first-match `globToRegExp` loop `selectScope` uses. Do not re-implement glob matching. A rule counts as bookkeeping by its shape (`suites` an empty array, `static` false, no `impact`), not by a hard-coded path list, so a consumer's own declaration decides what counts. Thresholds stay the stated constants in `review-effort-derivation.md`: the size check lives in the module and the prose cites it.

The schema comment-only check stays in prose, as a targeted read the model already does for dependency manifests. Comment markers are `--`, `#`, `//`, `/*`, `*` and `*/` at the start of a changed line after leading whitespace. A hunk the reader cannot classify fires the trigger.

## Original request

review: effort size proxy counts prose, plan and run-dir files, and every info finding gets a Capable tiebreak

**Summary:** review-effort's diff heuristic counts prose, plan and run-dir files as size, and Step 3.7 sends every info finding through a Capable tiebreak plus two hand-written input files.

**Kind:** Gap

**Affected component:** skills/review (Step 2.5 review-effort derivation, Step 3.7 tiebreak)

**Use case:**
A small Python-script-and-docs record (labels `risk:low`, `size:low`, fast-lane ceremony) was reviewed. Step 2.5's diff heuristic read `git diff --stat` as 10 files and 412 lines, which is size `high` under its 10-files-or-300-lines rule, and combined with risk `low` resolved review-effort `medium` over the label tier `low`. Most of that "size" was a materialized spec, a plan document, a ledger and journey and architecture prose, none of which carries the code-review risk the proxy stands for. At `medium` the review dispatched 8 lens agents (4 reproduction pairs), then 13 findings (6 of them info or low and dropped as not worth acting on) each went to an independent Capable tiebreak agent. Resolving the 13 verdicts meant writing two scratch files per finding by hand (the finding JSON and the agent reply) and running `resolve-tiebreak` 13 times, i.e. 26 file writes plus 13 CLI calls, before any fix.

**Suggested fix:**
Have the size proxy in `review-effort-derivation.md` count only files that can hold executable or configuration behavior, excluding `*.md` prose, the run directory's materialized spec, plan and ledger files; or cap the upgrade from the label tier to one step when every changed non-prose file is under a small threshold. Separately, let Step 3.7 skip the independent agent for a finding the lens itself rated `info`, resolving it as `drop` with a logged line, and have `review-coordination.js` accept the reply text and entry on stdin or in one batch file so a wave of tiebreak verdicts resolves in one call instead of two writes and a call per finding.

**Definition:** Clear
