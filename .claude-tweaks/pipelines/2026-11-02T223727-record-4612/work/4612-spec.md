# 4612: Record the walkthrough automatically and keep secrets out of the packet

Surface: infra

## Overview

Fill the acceptance packet's **Recording** section automatically, and keep secrets out of it. When a story and a local base URL exist, wrap-up runs the walkthrough encoder (an animated GIF built from step screenshots) and links the result in the packet. Today `/walkthrough` does this only when a human runs it.

Agent-side checking always happens locally before merge: the agent runs its stories, including negative (break-it) stories, against a local build in the worktree, and records the walkthrough there. This is where adversarial testing is safe, and where `/stories`' Target Environment Guard (negative stories disabled on any non-localhost host) already allows it. The recording is of the happy-path feature in use.

**Exposure requirement (the main risk of this record).** Screenshots and recordings can capture tokens, e-mail addresses or customer-like data, and the packet may land in a public repository. Recordings and screenshots must be **redacted**, or — for a public repo — **stored privately and linked, never embedded**. Links must carry no token, password or session value. The mechanism is the builder's call; the invariant is that nothing secret-shaped reaches a public surface. Video is out of scope: Playwright CLI has no screencast operation (per `/walkthrough`), so GIF from step screenshots is the v1 form.

**Contract decisions this record pins:**

- **Source of frames.** The recording is built from the step screenshots the pipeline's own happy-path stories already wrote to the caller-supplied absolute `SCREENSHOT_PATH` directories (verified in `plugin/agents/qa-agent.md`: each story writes `NN_<step-name>.png` under the directory the caller passes, so the files are readable after the agent returns). No new browser run, and the recording step never starts a server. Stories marked negative (break-it) are excluded, so error screens never enter the GIF.
- **"Resolvable local base URL"** means the base URL the story run itself was given (recorded as a run fact), whose host is `localhost`, `127.0.0.1` or `::1`. `/walkthrough` deliberately never auto-detects a server (`--base` is required), and this record does not change that.
- **Storage and exposure (v1).** The GIF is stored in the run's local directory and never uploaded, in any repository visibility; the packet links the local path. A remote store is allowed later only if it enforces authenticated collaborator access, proven by an anonymous-fetch probe that fails; secret gists and Actions artifacts of a public repository do not qualify. Exposure values: `local-only` (the v1 default, and the result for any unreachable or unprobed store), `linked-private` (a remote store that passed the probe), `withheld` (a link refused by the credential rule). The packet never embeds the recording or any screenshot (no markdown image syntax, no `img` tag) in any repository visibility, and a remote link must point to a non-image landing page.
- **What redaction does and does not do.** Redaction covers every string the Recording section renders from the walkthrough (step captions, story titles, link text, failure messages), applied at one choke point, `renderRecordingSection`; it keeps the key name and replaces the whole value (`api_key=[redacted]`, `sk_live_abc` becomes `[redacted]`, so no prefix or length leaks). It does not and cannot scan pixels: the stored GIF is unredacted and local-only, and the stories must run against seed data and throwaway credentials (a Gotcha of the story step, stated in the packet contract). `captionList` stays redaction-free (a test pins that) and the standalone `/walkthrough` path is intentionally unchanged.
- **One credential-key constant.** The link rule and the redactor use the shared credential-key constant defined by the packet record (`token`, `access_token`, `password`, `passwd`, `secret`, `session`, `sessionid`, `jwt`, `auth`, `key`, `api_key`, `sig`, `signature`, `x-amz-signature`); the redactor adds value shapes (JWT, bearer, `sk_`/`ghp_`/`gho_` prefixes, e-mail addresses). A bearer-shaped path segment is a segment of 20 or more characters from `[A-Za-z0-9_-]` containing at least one digit and one letter (positive test `/a/Xk3j9f8s7d6f5g4h3j2k1/b`, negative test `/docs/token-guide`).
- **Redaction count.** A non-zero count is reported but does not change the exposure decision (exposure is already the strictest value that applies).
- **Not-recorded fact.** `{ id, kind: 'recording', status: 'not-run', reason }` with `reason` one of `no-story`, `no-local-base-url`, `no-happy-path-screenshots`, `encoder-failed`; each of the last three also appears under Couldn't test (a recording was expected but impossible); `no-story` renders plain `not recorded` only.

- Not recording dev-environment sessions (the dev smoke check is a different record and never runs negative stories).
- Not changing `/walkthrough`'s standalone interactive behavior.

## Deliverables

- [ ] Wrap-up step (in the wrap-up engine) that, when the record has a happy-path story and a resolvable local base URL (definitions above), runs `encodeWalkthrough` over the stories' existing step screenshots and records the output path as a `recording` packet fact; otherwise records the not-recorded fact with its reason.
- [ ] A redaction module (pure, `plugin/bin/lib/walkthrough/`): scans caption text and any text-bearing metadata for secret-shaped strings (bearer/JWT-shaped tokens, `key=`/`token=`/`password=`/`secret=` values, `sk_`/`ghp_`/`gho_` style prefixes, e-mail addresses) and replaces them with a fixed placeholder; reports what it redacted as a count in the packet fact (never the value).
- [ ] The exposure policy above in one function `decideExposure({ repoVisibility, storeProbe })` (single place the embed/link decision is made, a test per branch); repository visibility is read from `gh repo view --json isPrivate` and an unreadable or unexpected answer is treated as **public** (fail closed). The v1 outcome is `local-only` whatever the visibility, so visibility only matters for a future remote store.
- [ ] A conformance scan (in the style of the `bin-source-scan-conformance` skill) that fails if any module under `plugin/bin/lib/wrap-up/` or `plugin/bin/lib/walkthrough/` emits markdown image syntax or an `img` tag.
- [ ] Packet link rule: a recording link (or any test-guide link) carrying `token=`, `access_token=`, `password=`, `session=`, or a bearer-shaped path segment is refused and the section renders `recording withheld: link contained a credential-shaped value`.
- [ ] Skill prose updates in `plugin/skills/walkthrough/SKILL.md` and the packet contract describing the automatic path and the exposure rules.

## Acceptance Criteria

1. A packet for a story-backed web change whose local base URL resolves carries a Recording section with a link to the encoded GIF (test with a stubbed encoder returning a path).
2. For a repo reported public, a repo reported private, and a repo whose visibility lookup fails, the rendered packet contains no markdown image syntax or HTML `img` tag for the recording or any screenshot, only a path or link, and `decideExposure` returns `local-only` in all three; the conformance scan passes and fails when an `img` emission is planted.
2a. A story set containing one happy-path and one negative story produces a recording from the happy-path screenshots only (frame count equals the happy-path step count).
3. A caption, story title, link text or failure message containing a secret-shaped string (for example `Authorization: Bearer eyJhbGciOiJIUzI1NiJ9.e30.abc` or `api_key=sk_live_123abc`) is rendered with the whole value replaced by `[redacted]` (key names kept), the original string appearing nowhere in the Recording section; a test asserts this for at least five secret shapes plus an e-mail address, across all four text channels.
3a. `captionList` output is byte-identical to before this change (pinned by a test), and the standalone `walkthrough-encode.js` path applies no redaction.
4. A recording link carrying a credential-shaped query parameter (`token=`, `access_token=`, `password=`, `session=`) is withheld and the Recording section states why. The matcher normalizes before matching and the tests cover: uppercase key (`TOKEN=abc`), percent-encoded key (`tok%65n=abc`, `%74oken=abc`), the key in the fragment (`#token=abc`), credentials in userinfo (`https://user:pass@host/`), an uppercase scheme (`HTTPS://host/?token=abc`), a trailing-slash variant, and dot segments before the query (`https://host/a/../b?token=abc`). A benign link whose *path* merely contains the word (`https://host/docs/token-guide`) is not withheld (substring in the wrong component).
5. No story or no resolvable local base URL: the Recording section reads `not recorded` with the reason, and the same fact appears under **Couldn't test** when a recording was expected but impossible (for example the dev server would not start).
6. `walkthrough-encode.js` standalone invocation behavior is unchanged (its existing tests pass untouched).
7. `npm test` passes.

## Release Note

Added an automatic walkthrough recording to the acceptance packet, with secret-shaped text redacted and public repositories linked to a private copy instead of embedding images.

## Technical Approach

Reuse `encodeWalkthrough`; add the redaction as a pure pre-step over `captionList` output so the encoder keeps its contract. Treat redaction as best-effort defense in depth, not a guarantee: because pixel content of a screenshot cannot be scanned with a text matcher, the public-repo rule (link, never embed) is the load-bearing control, and the redaction handles the text the plugin itself writes (captions, link text, packet prose).

### Data / API Surface

- Fact: `{ id, kind: 'recording', status, url_or_path, redactions: <int>, exposure: 'local-only' | 'linked-private' | 'withheld' }`, or the not-recorded fact described above.
- Redaction placeholder: a single fixed token (`[redacted]`) so tests and consumers can assert on it.

## Gotchas

- Fail closed on visibility: an unreadable `isPrivate` answer means public. Do not default to private.
- Redaction placeholders must not be reversible and must not leak length or prefix of the secret (`[redacted]` is the only placeholder).
- Never embed, in any repository visibility; the embed/link decision lives only in `decideExposure`, and the conformance scan guards the rest.
- The stored GIF is unredacted pixels, local-only. Do not add an upload path without the authenticated-access probe in the contract above.
- Negative (break-it) stories run only against localhost; the recording step must not start a negative story against a non-local base URL (the Target Environment Guard stays; do not relax it).
- Verified during shaping: qa-agent step screenshots are written to the caller-supplied absolute `SCREENSHOT_PATH`, so wrap-up can read them after the agent returns; no dispatch-side recording step is needed.

## Plan Review Decisions

Decided by the maintainer on 2026-11-02, who accepted these readings in session. Where a decision conflicts with the text above, the decision wins.

- **Exposure rules and `--recordings`: Reading B.** The rules bind every Recording link. Legacy image URLs are refused, and the public evidence-commit route (`docs/demo-evidence/`) is retired or moved to a private store. No 40-hex exemption is added to the bearer rule.

## Build Deviations (Beneficial)

- **Redaction also runs at gather and on snapshot's stdout.** The spec names one choke point, `renderRecordingSection`. It stays, and gather also writes redacted `text`, `captions` and `failure` to the fact, so a narrator citing a recording fact cannot copy a raw value into packet prose; `fact.redactions` is the count.
- **The bearer rule reaches commands and plan lines.** The spec names links. A route with a credential-shaped path segment is written as a command with the segment replaced by `{id}`, and commands, plan lines' URL tokens and a plan's Entry point are screened.
- **An unignored destination records nothing.** Snapshot asks `git check-ignore` before writing the GIF; a path git would track gives `encoder-failed` naming it, since the file is unredacted pixels.
