## Current State

The process-efficiency design (`docs/superpowers/specs/2026-11-15-process-efficiency-design.md`, Phase 3) ends unit 3.2 with: "Done when a replay of the window's refused commands shows no read-only command refused and no write newly admitted." It also says #4990 and #4931, which teach callers to avoid refused shapes, "stay open until 3.2 lands, then are re-read: each is closed or narrowed".

How this differs from the design: the design assumed one guard that the plugin owns. Measured on 2026-11-16 over 2026-10-17 to 2026-11-16, Claude Code's own worktree-isolation guard produced 96.7% of the refusals (12,770 of 13,202) and the plugin's PreToolUse gates 3.3% (432). The plugin cannot make the harness guard accept a command. It can rewrite a command before the guard reads it (`plugin/bin/lib/hooks/guard-rewrite.js`), it can stop its own skill text from producing a refused shape, and it can decide what its own gates deny. So the design's criterion is restated here for those three, and what is left over is counted and named, not hidden.

The same measurement, with a scratch classifier, over the 3,606 read-only commands the harness refused (1,186 of them in the last 14 days of the window):

| Class | 30 days | Last 14 days | What the plugin can do |
|---|---|---|---|
| Reads another checkout: `git -C <main checkout> …`, `cd <another worktree> && git …` | 876 | 419 | Nothing in a rewrite: the guard refuses where git points. A section 7 row can name the form that works |
| `git -C <own worktree>` or `git -C .` | 496 | 285 | Rewritten by #5588, for the read subcommands it lists |
| A read chained onto an unquoted `$?` | 171 | 43 | Rewritten by #5588 |
| A backslash-escaped space | 703 | 35 | Already rewritten since v6.154.1 (`quote-escaped-space`) |
| Long chains, loops and pipes of readers | the rest | the rest | No rule: the text's meaning is known, but no single respelling is |

The classes overlap (a command can sit in two rows), so the rows do not sum to the total.

Three more facts the replay must explain:

- Of the plugin's own 314 worktree-always Bash denials in the window, 4 were read-only commands, and `gitTargets` and `fileWriteTargets` at HEAD resolve no target for any of the 4.
- After the rewriter's first release, `rewriteForGuard` at HEAD still changes 400 refused commands, 129 of them by `quote-escaped-space` and 113 of those in subagents. Either the rewritten form is refused for a second reason, or the rule never ran in that session. A backslash-space `grep -rln` probe on 2026-11-16 ran unrefused in a subagent.
- Live probes on 2026-11-16 (Claude Code 2.1.325) found read shapes section 7 does not list: `git grep -c "git-discipline" -- <file>` is refused ("names git more than once in a single command") while `"[g]it-discipline"` runs; `grep -c "Source" <file>` is refused ("runs a string through Source") while `"[S]ource"` runs, and section 7 lists only the lowercase token; `git -C "<main checkout>" rev-parse --short HEAD` is refused ("redirects git to the shared checkout via -C") while `git log origin/main --oneline -1`, run from the worktree, reads the shared refs.

## Technical Approach

The replay is a mode of the existing tool, so it shares the scan, the window flags and the fixtures. It adds no pass over the transcripts: it reads the rows the normal run already built. The standing guard against a rule that moves a write is #5588's unit test over every rule's positive cases; `writeTargetsMoved` is a one-time check on real commands.

A replay cannot ask the harness guard whether it would accept a command; the guard is closed code. `rewritten` therefore means "a rule fires and the result matches no known refused row", which is as far as text can go. The live probes in #5588 and in Deliverable 3 are the ground truth for each form, and the parked record is the check on real sessions.

The chain exclusion in AC5 is deliberate. A read-only command of four or more chained steps with loops and pipes (`cd <wt> && for f in …; do …; done; git diff … | head`) is refused as "too complex" or "names git in a form too complex". Its meaning is known, but there is no single plain respelling a rewrite could produce, and splitting it is the caller's job. The replay prints this class's count beside the others so it stays visible.
Decided 2026-11-16: a call's chain length is its number of simple commands at the top level, split at `;`, `&&`, `||`, `|` and a newline outside quotes, substitutions and heredoc bodies. A read row of length 4 or more that no earlier disposition claims is `long-chain`. AC5 shows that the replay agrees with itself; the parked record is the check on real sessions.

For the comments on #4990 and #4931, match each record's listed shapes with a committed pattern file: `mkdir -p … && playwright-cli`, a `cd "<worktree>" &&` prefix, a heredoc into `python -` or `node -`, a shell-function wrapper, `playwright-cli` with a variable or `$PWD` in `--filename`, in a `for` loop, or piped into `head`.
Decided 2026-11-16: the replay takes `--shape-patterns <file>`, a JSON list of `{ id, pattern }`, and prints `byPattern`, the number of refused rows each pattern matches. The patterns for the two records are committed as `tools/guard-refusals/caller-shape-patterns.json`, and each comment names that file at the build's commit so a reader can run the count again.

## Plan Review Clarifications

Settled by the spec's own gap rule ("Where this record leaves a choice between readings and no Decision above settles it, the build does not stop for it."); the three readings below are equal on its three tests, so each takes the one closer to the spec's sentence it cites.

- `rule-not-applied` counts a row only when every rule that changed it has a known release date and the row is dated after each of those releases; the total is a count of distinct rows. Supports: "A rule whose release date is not yet known counts no row." Not taken: counting the row under its released rule while an unreleased rule also fired.
- A row's plugin version for `rule-not-applied` is read from its own command; `byClass` counts by session version, the version any guarded row in the same transcript file names, else `unknown`. Supports: "its plugin version is `unknown` when the command names no plugin cache path" and "counting only sessions whose plugin version is that release or newer". Not taken: one per-command version for both.
- A shape counts as changed by a rule for the close/narrow/keep rule only when every refused row matching it is changed by a rule. Supports: "`close` when every shape the record lists is changed by a rule or has no refusal in the window". Not taken: any one matching row rewritten.
