# 5528: Normalize issue state and label shape in the health issue index so closed matches reopen and wontfix suppresses

Surface: infra
Risk-flags: none

**Related:** #5529 (the other Phase 0 fix from the 2026-11-15 audit simplification design; independent, no shared file)

## Overview

The four health sweeps decide what to do with a finding by looking it up in an index of already-filed GitHub issues. The index entries carry `state` and `labels` exactly as the calling session wrote them into the `--issues` file, and the two `decide()` implementations read them with different assumptions. When the file carries what `gh issue list --json state,labels` actually returns (state `CLOSED`, labels as objects), code-health skips a finding whose issue was closed instead of reopening it, and no sweep recognises a `wontfix` label.

This record normalizes both fields once, in the shared loader, so every sweep reads one shape whatever the session wrote. It is unit 0.1 of the 2026-11-15 audit simplification design: the drift is a consequence of code-health keeping a forked `decide()`, and it is fixed ahead of the later work that merges the fork.

**Complexity:** Low
**Estimated tasks:** 3

## Non-Goals

- Merging code-health's `decide()` into `health-core`'s. That is a later unit of the same design and changes more than this fix needs.
- Changing how any skill fetches issues or builds the `--issues` file. The four `gh issue list` commands and their fingerprint-parsing instructions stay as they are.
- Changing the order of the dedup decisions, the existing stderr diagnostics `loadIssueIndex` prints, or its return value for an unreadable or non-array file.
- Folding the case of label names. `wontfix` is still matched exactly; a label spelled `Wontfix` is not recognised, as today.
- Changing which closed issues reopen. A matched closed issue without a `wontfix` label reopens whatever its close reason, which is what the decision table in `plugin/bin/lib/code-health/dedup.js:17-23` documents and what the other three sweeps already do.
- Touching `plugin/bin/lib/code-health/pull-issues.js`.

## Deliverables

- [ ] `loadIssueIndex` normalizes `state` on each entry it stores: a string becomes its lowercase form; a missing or non-string value becomes the empty string `''`.
- [ ] `loadIssueIndex` normalizes `labels` on each entry it stores to an array of label-name strings: a plain string is kept, an object with a string `name` contributes that name, and any other element is dropped.
- [ ] When one or more label elements were dropped while loading a file, `loadIssueIndex` prints exactly one stderr line for that load, `[{toolName}] loadIssueIndex: ignored {n} label entries with no name`, where `{n}` is the total dropped across the file. - [ ] `plugin/bin/lib/code-health/dedup.js` compares the state case-insensitively, the same way `plugin/bin/lib/health-core/dedup.js:65` does, so a caller that builds an index without the loader gets the same answer.
- [ ] `plugin/skills/_shared/health-issue-index.md` states, next to the shape it already names, that `state` may be in either case and `labels` may be names or `gh`'s label objects, and that the loader normalizes both.

## Acceptance Criteria

1. `loadIssueIndex` on a file containing `[{"number":7,"state":"CLOSED","labels":[{"name":"wontfix"},{"name":"by:code-health"}],"fingerprint":"fp"}]` returns `{ fp: { number: 7, state: 'closed', labels: ['wontfix', 'by:code-health'] } }` and prints nothing to stderr.
2. `loadIssueIndex` on an entry whose labels are `["bug", null, {"id":1}, 42, {"name":"wontfix"}]` stores `labels: ['bug', 'wontfix']`, keeps the issue, and prints exactly one stderr line containing `ignored 3 label entries with no name`.
3. `loadIssueIndex` on an entry with no `state` key, and on one whose `state` is `5`, stores `state: ''` for each. Both `decide()` functions, given such an entry, return `action: 'skip'`.
4. `decide` from `plugin/bin/lib/code-health/dedup.js`, given an index entry `{ number: 8, state: 'CLOSED', labels: [] }` for the finding's fingerprint, returns `action: 'reopen'` with `issue: 8`. This test fails on the code as it stands.
5. `code-health.js validate-findings` run with an `--issues` file in `gh`'s raw shape reopens and suppresses correctly: a finding matching a `CLOSED` issue with no `wontfix` label produces a reopen payload and a cache entry with `status: 'regressed'`; a finding matching an issue whose labels include the object `{"name":"wontfix"}` produces no payload and a cache entry with `status: 'wontfix'`.
6. `harness-health.js validate-findings` run with an `--issues` file whose matching issue carries the object label `{"name":"wontfix"}` suppresses that finding (no payload for it).
7. The existing tests in `tests/bin-lib/health-core/issue-index.test.js`, `tests/bin-lib/health-core/dedup.test.js`, `tests/bin-lib/code-health/dedup.test.js` and `tests/bin-lib/health-core/purity.test.js` pass with no edit to their existing cases.

## Release Note

Fixed the health sweeps skipping a finding whose issue had been closed, and ignoring wontfix labels, when the issue list came straight from GitHub.

## Technical Approach

Normalize at the loader, not at each comparison. The loader is the one place all four CLIs pass through, so one change covers both `decide()` implementations and both fields. docs-health and journey-health are covered by the loader-level criteria; they get no CLI-level case of their own. The case-insensitive compare in code-health's `decide()` is kept as a second, one-line guard because that function is exported and unit-tested against hand-built indexes.

The alternative, telling each of the four skills to lowercase the state and project label names, was rejected: it would restate one rule in four skill files, and a session that skipped it would fail silently again.

The dropped-label line exists for the same reason. The index is written by hand from two transports, and only the `gh` shape has been observed. A label element in a third shape must be visible, not silently ignored. The maintainer chose this on 2026-11-15 over dropping silently.

### Data / API Surface

Index entry after this change: `{ number, state, labels }` where `state` is a lowercase string (`''` when the input had none) and `labels` is `string[]` of label names.

New stderr line, printed at most once per `loadIssueIndex` call: `[{toolName}] loadIssueIndex: ignored {n} label entries with no name`.

### Key Files

- `plugin/bin/lib/health-core/issue-index.js` — normalize `state` and `labels` in `loadIssueIndex`; the dropped-label line
- `plugin/bin/lib/code-health/dedup.js` — case-insensitive state compare
- `plugin/skills/_shared/health-issue-index.md` — one sentence on accepted input shapes
- `tests/bin-lib/health-core/issue-index.test.js` — loader normalization cases
- `tests/bin-lib/code-health/dedup.test.js` — uppercase-state reopen case
- `tests/bin-lib/code-health/cli-validate-findings.test.js` — raw-`gh`-shape end-to-end cases
- `tests/bin-lib/harness-health/cli-validate-findings.test.js` — object-label wontfix case

## Gotchas

- `tests/bin-lib/health-core/purity.test.js` asserts the dedup module does no I/O. Keep the normalization in the loader, which already reads the file.
- `loadIssueIndex`'s two existing stderr lines and its "skipping malformed issue entry" line are asserted by existing tests. Do not reword them. The new line is additive and must not print when nothing was dropped, or existing cases that assert a quiet stderr will fail.
- Prove each new test by running it against the unmodified source first. A test that passes before the fix proves nothing here, since the string-label fixtures already pass.
- `plugin/skills/_shared/health-issue-index.md` is read by all four sweeps and may be pinned by a prose-conformance suite. Run the full suite, not only the named test files, before calling the change done.
- After this lands, a code-health sweep reopens matched closed issues it used to skip. That is the fix working, not a regression; say so in the pull request.
- ASSUMPTION — verify at build: the `--issues` file a real sweep writes carries `gh`'s raw casing and label objects at least some of the time — confirm via one `--dry-run` sweep and reading the file it leaves in the session temp directory. The fix is correct for both shapes either way; this only tells you how often the bug fired.
- ASSUMPTION — verify at build: the MCP `list_issues` projection yields `state` and `labels` in a shape the loader accepts (lowercase or uppercase state; label names or objects with `name`) — confirm via one `gh`-absent sweep; the dropped-label line reports any other shape.
