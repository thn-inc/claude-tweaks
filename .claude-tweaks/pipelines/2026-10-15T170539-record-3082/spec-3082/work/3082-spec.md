# 3082: dev-url-detection: honour a declared stories/servers.yml start_command instead of only writing it

Surface: infra

**Related:** #3083

## Current State

`plugin/skills/_shared/dev-url-detection.md` is the shared procedure `/claude-tweaks:test` (QA), `/claude-tweaks:visual-review` and `/claude-tweaks:stories` use to find or start the app under test. It touches `stories/servers.yml` (or `{STORIES_DIR}/servers.yml`) in two places only:

- **Step 0 (Check Persisted Config, line 17)** reads `servers.default.url` and probes it.
- **Step 4 (Persist Result, lines 153-167)** writes the file. Item 6 (line 165): "If a start command was discovered in Step 2 (from CLAUDE.md or package.json), set `servers.default.start_command`." This is an unconditional set, so it overwrites any value already there.

Nothing reads `servers.default.start_command`. Step 2 (Check Project Configuration, line 66) discovers the dev command only from CLAUDE.md, `package.json` scripts and framework config. Step 3's "No usable server + dev command known" row (line 119) and the "Ephemeral server start" subsection (line 123) launch that discovered command. A repo-wide grep for `start_command` in `plugin/` finds only line 165.

The consequence (observed; original request below): a project whose QA stories need a specific stack, such as a production build plus a mock API started by one launcher script, can declare it in `servers.yml`, but an auto-started `next dev` runs instead and the stack-dependent stories fail. The next Step 4 can then overwrite the declared command with the discovered one.

## Deliverables

1. **Step 2 (Check Project Configuration):** add a first source, ahead of CLAUDE.md. When `servers.yml` exists and declares `servers.default.start_command`, that command is the dev command, and CLAUDE.md, `package.json` and framework config are consulted only for port hints. Record which source supplied the command (`servers.yml`, `CLAUDE.md`, or `package.json`), so Step 3 and the run's output can name it.
2. **Step 4 item 6:** change the unconditional set to set-if-absent. Write a discovered start command only when `servers.default.start_command` is missing; never overwrite an existing value.
3. **Ephemeral server start:** when the command came from `servers.yml`, run it exactly as declared, from the worktree root, still passing the lease or free-port environment (`PORT={port}` and the `bin/ports.js env` lines). The output names the declared command as the source.
4. Update the conformance tests that pin this file's prose, and add assertions for the new precedence and the set-if-absent rule. Candidates: `tests/dev-url-detection-lease-conformance.test.js`, `tests/ephemeral-server-handoff-conformance.test.js`.

## Acceptance Criteria

- `dev-url-detection.md` Step 2 names `servers.yml`'s `servers.default.start_command` as the first, highest-precedence dev-command source, ahead of CLAUDE.md and `package.json`.
- Step 4's start-command item writes `servers.default.start_command` only when the key is absent, and states that an existing value is never overwritten.
- The Ephemeral server start subsection says a `servers.yml`-declared command runs verbatim from the worktree root with the lease/free-port environment still applied.
- A conformance test asserts both the precedence wording and the set-if-absent wording, and fails against the current text.
- `npm test` passes, since conformance tests pin this file's prose repo-wide.

## Gotchas

- A declared launcher script may hard-code its own ports and ignore `PORT`. The Step 2.7 worktree-awareness check and the lease-first probe still apply to whatever port the server ends up on. If the declared command never answers on the leased port within the start timeout, report that as a start failure naming the declared command. Never fall back silently to the CLAUDE.md command.
- Existing projects may already carry a `start_command` that an earlier run wrote from discovery, not a deliberate choice. The new precedence treats it as authoritative too. That is intended (it equals the discovered command), but call it out in the PR description.
- `stories/servers.yml` is committed and shared. A declared command is project configuration, so this change makes it executable configuration; it gets no more trust than the CLAUDE.md commands section already does.

## Original request

dev-url-detection: honour a declared stories/servers.yml start_command instead of only writing it

**Component:** `skills/_shared/dev-url-detection.md` (used by `/claude-tweaks:test` QA, `/claude-tweaks:visual-review`, `/claude-tweaks:stories`)
**Kind:** gap

## What happens

`stories/servers.yml` carries a `servers.default.start_command`, but dev-url-detection only ever *writes* that key (Step 4.6: "If a start command was discovered in Step 2 (from CLAUDE.md or package.json), set `servers.default.start_command`"). It never reads it when it has to start an ephemeral server. The auto-start always uses the dev command it found in CLAUDE.md or package.json, and Step 4.6 can overwrite a start command the project chose on purpose.

## Why it matters

A project whose QA stories need a specific stack (for example, a production build plus a mock API with request-keyed fixture state, started by one launcher script) can declare it in `servers.yml`, but the declaration does nothing. An auto-started `next dev` on a free port runs instead, and stories that need the declared stack fail. Today the only workaround is to start the stack by hand and pass its URL explicitly.

## Suggested direction

When `servers.yml` declares a `start_command`, prefer it over the CLAUDE.md/package.json dev command for the ephemeral start. Never overwrite a `start_command` that is already set; record a discovered command only when the key is absent.
