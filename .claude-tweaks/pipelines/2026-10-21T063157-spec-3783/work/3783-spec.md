# 3783: Catch a skipped acceptance-labeling step before a pending-review PR merges

Origin: agent follow-up from #3712 /flow run (PR #3749)

Defer-reason: tangential

## Current State

`wrap-up/execution-and-verification.md` requires two Phase 4 steps that nothing enforces. **Acceptance labeling** (line 23) runs `verification-brief.md`'s Routing: a `demo:pending` label for a record above the oversight floor; otherwise an `oversightExempt` entry in `verify-expectations.json` and a `try-it` PR comment. **Verify execution** runs `wrap-up-engine.js verify`, whose `acceptance-labeling` check (`plugin/bin/lib/wrap-up/engine-verify.js:816`) fails exactly when that labeling is missing. `verify` only prints its table and writes no artifact, so a wrap-up that never runs it leaves no trace.

#3712's `/flow` run (PR #3749) skipped both steps. Its unattended Review Console resolved `leave-open` (no `auto:merge`), and the run reached `pending-review` with no `demo:*` label, no `oversightExempt` entry, no `try-it` comment and no `wrap-up-engine.js verify` entry in `decisions.md`. Nothing flagged it. The later human-confirmed merge only caught up because `_shared/pr-first-merge.md` Step 1 was followed by hand.

`dispatch/close-out.md` step 3, the other human-confirmed merge route for a `pending-review` PR, skips acceptance labeling explicitly. It assumes a `pending-review` PR "only exists because `/wrap-up`'s own Phase 4 execution already ran it". #3712 broke that assumption, so close-out would have merged an unlabeled record.

## Deliverables

- [ ] `wrap-up-engine.js verify` writes its per-check results to `{run-dir}/verify.json` (through the run-dir writer seam its siblings use) in addition to printing the table.
- [ ] `dispatch/close-out.md` step 3 stops assuming. It reads `verify.json`; when the file is missing or its `acceptance-labeling` row is `fail`, it runs `_shared/pr-first-merge.md` Step 1 (`verification-brief.md` from its Routing section) before the confirmation gate.
- [ ] `_shared/pr-first-merge.md` Step 1 states the same check. A missing `verify.json` or a failed `acceptance-labeling` row means labeling has not landed, whichever caller reached the merge.
- [ ] `flow/summary-template.md`'s `### Needs a human` block gains a line when the run dir holds no `verify.json` (wrap-up's Verify execution never ran), naming the paste-ready `wrap-up-engine.js verify` command.

## Acceptance Criteria

1. After `wrap-up-engine.js verify --run-dir <dir> --base <ref>`, `<dir>/verify.json` exists and carries one entry per check, `acceptance-labeling` included, with that check's result string.
2. A test drives `dispatch/close-out.md`'s step-3 rule through its code path or a conformance pin: with `verify.json` absent, acceptance labeling runs before the merge.
3. A conformance test pins `_shared/pr-first-merge.md` Step 1 and `dispatch/close-out.md` step 3 to name `verify.json`'s `acceptance-labeling` row, and fails when either sentence is removed.
4. The flow Pipeline Summary renders a `Needs a human` line for a run dir with no `verify.json`, and none when the file is present.
5. `npm test` passes.

## Release Note

A pipeline run that skips acceptance labeling is now caught before its PR merges, so a record never closes without its demo label or Try it walkthrough.

## Technical Approach

### Key Files

- `plugin/bin/lib/wrap-up/engine-verify.js` — write per-check results to verify.json
- `plugin/bin/wrap-up-engine.js` — verify verb persists its results
- `plugin/skills/dispatch/close-out.md` — step 3 reads verify.json instead of assuming labeling ran
- `plugin/skills/_shared/pr-first-merge.md` — Step 1 names the verify.json check
- `plugin/skills/flow/summary-template.md` — Needs a human line when verify.json is missing
