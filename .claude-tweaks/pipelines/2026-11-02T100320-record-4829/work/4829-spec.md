# 4829: Surface a degraded forge detection in reconcile, the express lane and the flow preflight (follow-up to #4578)

Origin: spec #4578 review (3e Architecture, tiebreak-confirmed)

Defer-reason: genuinely-larger

## Current State

Record #4578 made forge detection (`detectIntegrationModel`, `plugin/bin/lib/policy-schema.js`) honour `gh-timeout-ms`, retry once on a timeout, and report a *degraded* detection (a timeout that survives the retry) through an opt-in `onDegrade` callback, distinct from a detected `local-merge`. The callers that matter for pipeline correctness consume it (`resolve-policy.js`, the PreToolUse PR-stamp gate, `precondition.js`, the Manifesto, `phase-exit.js`). Two consumer families still treat a degraded detection as a plain `local-merge`:

- `plugin/bin/lib/reconcile/index.js` (around line 266) forwards a `timeoutMs` to `resolveIntegrationModel` but wires no `onDegrade`. After a timeout and a failed retry, `reconcile()` takes its non-`pr-first` branch (legacy reap) and records the skip as `reason: 'local-merge-model'` — the same entry a genuinely detected `local-merge` produces — so a degraded SessionStart pass cannot be told apart from a real one. Plan-review Q1 scoped #4578 to the `timeoutMs` forwarding only; the spec Release Note ("reports a degraded detection instead of silently resolving local-merge") is therefore not true on this path.

- `plugin/bin/lib/express/policy.js` (`defaultResolvePolicy`) and `plugin/bin/lib/flow/preflight.js` (`defaultDeps().resolvePolicy`) call `computeDerivedDefaults` without `onDegrade`, and their consumers read only `.value`: `express/cli.js` passes `policy['integration-model'].value` to the eligibility gate, so a degraded detection reads as "integration-model is not pr-first"; `flow/preflight.js` drops the `degraded` field when it builds the lever table. Both fail closed (express is ineligible; the preflight levers are display-only), but neither names the cause.

Verified at the review of #4578 (tiebreak verdicts: confirmed, low severity). Not a regression — before #4578 the same timeout resolved `local-merge` silently with no retry.

## Deliverables

1. `reconcile()` passes an `onDegrade` collector to `resolveIntegrationModel` and carries a degraded detection in its result (for example a distinct skip reason such as `degraded-forge-detection`, or a `degraded` field), so a degraded pass is distinguishable from a detected `local-merge`; the SessionStart consumer surfaces it the way `resolve-policy.js` does (one `degraded —` line).

2. `express/cli.js` reports a degraded `integration-model` as its own ineligibility reason instead of "not pr-first", reading the `degraded` field `computeDerivedDefaults` already writes.

3. `flow/preflight.js`'s lever entries keep the `degraded` field (or the preflight table marks the lever), so the FYI Manifesto table does not present a guess as a detected value.

4. A short statement in `plugin/skills/_shared/forge-detection.md` (Code twin paragraph) of the contract every consumer follows: handle `degraded` or consciously ignore it.

## Acceptance Criteria

With a fake `gh` that always times out, `reconcile()` reports a degraded detection (a result field or skip reason distinct from `local-merge-model`) and a detected `local-merge` (no remote) does not.

With the same fake `gh`, `express-lane.js gate` returns an ineligibility reason that names the degraded forge detection, not "integration-model is not pr-first".

With the same fake `gh`, the preflight `levers` output for `integration-model` carries the degraded marker.

Each new case goes red against the current code. `npm test` passes.

## Release Note

Reconcile, the express lane and the flow preflight now report a degraded forge detection instead of treating it as a detected local-merge.

## Technical Approach

### Key Files

- `plugin/bin/lib/reconcile/index.js` — wire onDegrade, carry the degrade in the result
- `plugin/bin/lib/express/cli.js` — name a degraded detection as its own ineligibility reason
- `plugin/bin/lib/express/policy.js` — forward onDegrade or keep the entry field for the gate
- `plugin/bin/lib/flow/preflight.js` — keep the degraded field on the integration-model lever entry
- `plugin/skills/_shared/forge-detection.md` — state the consumer contract for degraded
