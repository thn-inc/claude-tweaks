# 4738: Windows regression: 1 test file(s) newly failing after 8b610e3ec

Surface: backend

**Related:** #3982, #3995, #4725, #4764

## Current State

The post-merge Windows check failed on commit 8b610e3ec (compared against 94339d00c), after PR #4650. Baseline adjudication attributed `tests/bin-lib/dispatch/dispatch-resume-cli.test.js` as newly failing. Run: https://github.com/thn-inc/claude-tweaks/actions/runs/41209352221

All 53 attributed tests sit in this one file. The quoted ones read a run's `decisions.md` through a fake fs and get `null` back, and one reports `the fake fs saw archive/{that id}` as false, which points at the fake fs keying on forward-slash paths.

## Deliverables

1. `tests/bin-lib/dispatch/dispatch-resume-cli.test.js` passes on Windows, by fixing the product code or the test, whichever the failure turns out to be.
2. The cause is named in the PR, including whether other tests share it.

## Acceptance Criteria

1. `tests/bin-lib/dispatch/dispatch-resume-cli.test.js` passes in the Windows workflow on the fixing branch, proven by a run dispatched after the last code change.
2. The same file still passes on Linux and macOS.
3. `npm test` passes.

## Release Note

No user-facing change; this restores the Windows test suite.

## Technical Approach

Reproduce it first. Forward-slash and backslash handling is the usual cause here, and swapping `require("path")` for `path.win32` in a preload reproduces most path-string failures locally on unit tests.
