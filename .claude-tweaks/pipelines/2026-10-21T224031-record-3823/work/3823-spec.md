# 3823: Trusted-author jq in skill prose keys on authorAssociation only and fails closed on MCP transport

Origin: ledger resolve gate

Defer-reason: genuinely-larger

## Current State

The trusted-author jq filters that skill prose pastes verbatim (`trustedJqSelect()` / `untrustedJqNote()` in `plugin/bin/lib/issues/comment-trust.js`, pasted into `_shared/pr-run-comments.md`, the `tidy/digest-sweep.md` cluster-promotion read, and the other marker readers) key on `.authorAssociation`, the `gh ... --json comments` spelling only. The REST and MCP transports return `author_association` instead. A `gh`-absent run (a cloud Routine sandbox, which routes through `_shared/github-write-transport.md`) running one of those jq filters over MCP-fetched comments sees no `authorAssociation`, finds no trusted comments, and fails closed: every marker comment reads as untrusted.

The code path already handles both spellings (`commentAssociation()` reads either field), so the digest dedup in `materiality-digest.js` is unaffected; only the pasted jq in skill prose is gateway-specific. Found while building #3766 (ledger row 3, `docs/plans/2026-10-20-digest-dedup-trusted-fingerprints-ledger.md`); `_shared/pr-run-comments.md` has the same limit in its own jq.
