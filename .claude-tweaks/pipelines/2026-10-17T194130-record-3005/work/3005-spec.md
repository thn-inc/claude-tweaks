# 3005: test: QA dispatch rewrites a story's url origin but not absolute origins inside navigate steps

Surface: infra

## Current State

- `plugin/skills/test/qa-prompts.md:66-73` resolves each story's `url:` against `APP_URL` before any prompt is assembled:
  - a root-relative URL is joined to `APP_URL`
  - an absolute origin that differs from `APP_URL`'s is replaced, preserving path, query and fragment
  - an origin that already matches is kept

  The step logs once per run. This was the #2283 fix (PR #2390), which changed only `story.url`.
- Step blocks are serialized verbatim into the agent prompt: `{serialize setup block as YAML}` (`:94`), `{serialize teardown block as YAML}` (`:97`) and `{serialize story.steps as YAML}` (`:100`). The qa-agent runs a `navigate` step as `playwright-cli -s=<story-id> goto <url>` (`plugin/agents/qa-agent.md:116`), so an absolute origin inside it is followed literally.
- Observed symptom (from the record): "the agent navigates to the pinned port. With several worktrees on one machine that port can belong to another session's mock, and the story's reset call clears that session's fixture state. The orchestrator has to rewrite those values by hand in every prompt."
- The story schema does not define `navigate` or name its URL field. `plugin/skills/stories/SKILL.md:35-62` lists click/fill/assert_visible only. The one shipped example writes `- action: navigate` / `target: "https://example.com/setup-page"` (`plugin/skills/stories/story-examples.md:214-215`); the record says `value`.
- Loopback hosts are already defined once for QA: `localhost`, `127.0.0.1`, `::1`, `*.localhost` (`plugin/skills/test/qa-procedures.md:107`). The same paragraph already marks stories `SKIPPED` with a reason token (`unacknowledged-remote-target`). A worktree is detected with `repoInfo(process.cwd()).isLinkedWorktree` (`plugin/skills/_shared/dev-url-detection.md:93`).

## Deliverables

1. Decision (approved in brainstorming, 2026-10-15): in `qa-prompts.md`'s URL resolution, rewrite step-level absolute origins that equal the story's own `url:` origin to `APP_URL`'s origin, using the same path/query/fragment preservation rule as `story.url`. Any other absolute loopback origin inside a step is flagged before dispatch. It is logged once per run, and on a worktree run the story is skipped, because the secondary server's port can't be assumed there. Rejected alternatives:
   - Rewrite only: it silently mis-targets a secondary server onto the app.
   - A new schema variable for secondary origins: it needs per-worktree secondary-server resolution (#3082, still open).
2. Extend the "Resolve each story's dispatch URL" block (`qa-prompts.md:66-73`) to cover every `navigate` step's URL in `setup.steps`, `story.steps` and `teardown.steps`, using the URL from `target` or `value`. Before the step blocks are serialized:
   - **Matches the story's own origin:** rewrite the origin to `APP_URL`'s. When `story.url` is root-relative, the story's own origin is `APP_URL`'s.
   - **Other loopback origin, worktree run:** mark the story `SKIPPED` with reason `unresolved-secondary-origin`, naming the origin.
   - **Other loopback origin, primary-checkout run:** dispatch unchanged and include the origin in the flag line.
   - **Non-loopback origin:** dispatch unchanged.
3. Extend the once-per-run logging (`:73`) with one rewrite-count line for step origins and one flag line listing the distinct flagged origins and the affected story ids. These go to `log-decision.js` when a run dir is active, otherwise to the QA report.
4. Document `navigate` in `stories/SKILL.md`'s Story schema (v2): `target` is its URL field (as in the shipped example). Extend the `url:`-field paragraph (`:64`) with the step-origin rule. Also align `qa-agent.md:116`'s `<url>` with the field name.

## Release Note

Fixed QA runs so navigation steps that point at the app's own pinned address follow the resolved app URL, and stories that would reach another local server are flagged (and skipped in worktrees) instead of touching a server the run does not own.

## Technical Approach

This change is prose only and lives in the dispatcher. The resolution happens before prompt assembly, so the templates' no-sibling-file-references contract (`qa-prompts.md:7`, restated at `:75`) is untouched, and the serialized YAML simply carries the resolved URLs. Origin comparison uses `new URL(x).origin`, matching the existing `story.url` rule. Only `navigate` steps are in scope: a `fill` value that happens to be a URL is test input and must reach the form verbatim. A skipped story's dependents follow the existing dependency rule (`qa-procedures.md:89`).

### Key Files
- `plugin/skills/test/qa-prompts.md`: URL-resolution block (`:66-73`) gains the step-origin rule, skip reason and logging; adds the worked example
- `plugin/skills/stories/SKILL.md`: schema documents `navigate` + `target`; `url:` paragraph (`:64`) gains the step rule
- `plugin/agents/qa-agent.md`: navigate bullet (`:116`) names the URL field
- `tests/qa-prompts-step-origin.test.js`: new prose conformance test

## Gotchas

- Legacy-format stories (`workflow` string, `qa-prompts.md:62`, `:156`) are free text and are not parsed. State this as a coverage limit in the block rather than silently implying total coverage.
- The `navigate` field name is undocumented today (the example uses `target`, the record says `value`). Reading both fields covers existing stories. Pin `target` as canonical going forward.
- Revisit the worktree skip when #3082 (declared `servers.yml` start command) ships secondary-server resolution. A secondary-origin variable becomes possible then.
- Related: #2283 (closed) fixed `story.url`.

## Original request

test: QA dispatch rewrites a story's url origin but not absolute origins inside navigate steps

**Summary:** The QA dispatcher resolves a story's `url:` against `APP_URL`, but an absolute origin inside a `navigate` step's `value` reaches the agent verbatim, so a story that resets a mock API on a pinned port hits whatever listens on that port.

**Kind:** Defect

**Affected component:** `/claude-tweaks:test` (`qa-prompts.md`, "Resolve each story's dispatch URL against `APP_URL`")

**Repro steps:**
1. Write a story with an absolute `url:` on one port and steps that `navigate` to a second absolute origin — for example a mock API's reset endpoint on its own fixed port — before returning to the app.
2. Run QA from a worktree whose app and mock run on other ports (the ephemeral-server path).
3. The dispatcher rewrites `url:` to `APP_URL`'s origin; the `navigate` values are serialized into the agent prompt unchanged.

**Expected vs. actual:**
Expected: a story run against a relocated app does not reach servers the run does not own — either origins inside step values are rewritten the same way `url:` is (at least the ones equal to the story's own `url:` origin), a pinned origin that differs from `APP_URL`'s is flagged before dispatch, or the story schema offers a variable for a secondary origin.
Actual: the agent navigates to the pinned port. With several worktrees on one machine that port can belong to another session's mock, and the story's reset call clears that session's fixture state. The orchestrator has to rewrite those values by hand in every prompt.

Related: #2283 fixed the same hazard for a story's `url:`; step values were not part of that fix.

**Definition:** Needed — whether to rewrite origins inside step values, or to add a secondary-origin variable to the story schema.

**Plugin version:** 6.136.0
