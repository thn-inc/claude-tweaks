# 1800: pr-early-run-lifecycle and open-items ledger creation have no completion gate, unlike record-worktree's IL-131 check

Surface: infra

## Current State

The record's premise is half wrong, and the correction changes the deliverable. `checkBookkeepingStampsGate` (`plugin/bin/lib/hooks/pre-tool-use.js`) already gates PR-early lifecycle completion: once this run's materialize commit has landed and the worktree stamp is present, any covered call (Edit/Write/NotebookEdit or a Bash git write, including a push) is denied under `integration-model: pr-first` while `run-state.json` has no `pr` and `decisions.md` carries no `PR-early run lifecycle: … FAILED` degrade line (`hasLoggedPrDegrade`), with a remediation message in the same shape as the IL-131 worktree-stamp deny. Pinned by `tests/hooks-bookkeeping-stamps-gate.test.js` ("worktree stamped, pr-first, no PR recorded → deny"; "degrade already logged → allow").

The one hole is deliberate and is exactly where #903 fell through: the #989 exemption (`hasNoUpstreamYet`) lets a push that establishes the branch on `origin` for the first time through the PR-stamp branch unconditionally, because that push *is* `pr-early-run-lifecycle.md` Step 2. It does not check that Step 1 ran first. Step 1 is the `gh pr list --head {branch} --state all` reuse/reopen check that would have found the stale, still-open draft PR from the tombstoned earlier attempt at #903 before any push; but Step 1 logs to `decisions.md` only on its reopen path (`PR-early run lifecycle: reopened PR #{n} for retry`), never on its no-match or reuse-open paths, so a gate cannot tell "Step 1 ran and found nothing" from "Step 1 never ran". In dispatch run `2026-09-03T041741-record-903`, the first Task call skipped both stamps; the second call's test phase-exit push was that branch's first push, was exempted, and collided with the stale PR (non-fast-forward against unrelated history), needing a manual force-push and reconcile.

The ledger half holds as filed: `/claude-tweaks:flow` Step 1.8 creates the open-items ledger at run start (`flow/SKILL.md`), `ledger/SKILL.md`'s Create operation is "called by `/flow` Step 1 or `/build` on first item", and `review/code-mode-steps.md` merges `test/qa` ledger entries into the findings table by reading the file. A missing ledger file at review time reads as "no entries" with no note. Nothing logs a reason when Step 1.8 is skipped.

## Technical Approach

Do not add a second gate; extend the existing one's exemption predicate with a `decisions.md` regex read, the same file read `hasLoggedPrDegrade` already performs (share the read, match two patterns). Keep the exemption one-shot and unpersisted. The ledger check is prose in the review step plus a `SKIP` log line, matching `_shared/auto-decision-log.md`'s status vocabulary (a `SKIP` needs no artifact). Cross-check the prior-art dimensions the #989 and #1860 tests established (git-error upstream, inherited `origin/main` upstream, already-tracked branch) and keep each covered with the new precondition seeded.

## Gotchas

- The exemption must stay one-shot: never persist a "Step 1 ran" flag into `run-state.json`; the regex read is cheap and the file is the audit trail.
- A retried run reuses `decisions.md` across attempts; a Step 1 line from a *previous* attempt would satisfy the precondition. Match the line's branch name against the push's branch to keep it attempt-specific.
- `hasLoggedPrDegrade`'s regex is case-insensitive and unanchored; keep the new patterns equally tolerant of the `AUTO {time} —` prefix variations `log-decision.js` emits.
- The record's original Deliverable 1 asked for a check "before the first phase-exit push"; the existing gate already covers every push except the first-push exemption, so the change is a precondition on that exemption, not a new phase-exit hook.

## Current State

`/claude-tweaks:dispatch`'s two-call model splits a group's `/flow` run across two Task calls
(`build,test` then `review,polish,wrap-up`). The first call's build phase is documented to run
two required steps before or alongside the materialize commit: `pr-early-run-lifecycle.md`'s "Run
start" procedure (Callers table: `build/worktree-setup.md` Step 6, "once per run, immediately
after the materialize commit, before Spec Step 2") and `/claude-tweaks:flow` Step 1.8 ("create the
open items ledger"). Neither has a completion gate — nothing checks, before the run proceeds past
build, that either step actually ran.

`build/worktree-setup.md` Step 4.5's `record-worktree` stamp is a sibling required step in the
same phase, and it *does* have one (IL-131): a later Edit/Write inside the worktree is denied
outright with an explicit remediation command until the stamp lands. The other two steps have no
analogous check.

Reproduced live in dispatch run `2026-09-03T041741-record-903` (#903's build): the first Task
call's `decisions.md` section for `build,test` shows the Step 2.8 claim and the Manifesto adoption,
then jumps straight to `### Step 4: build (#903)` with no PR-early-lifecycle or ledger-creation log
line anywhere. The consequence surfaced two phases later, in the second Task call's own test
phase-exit push: this run's freshly-built branch collided with a stale, still-open draft PR from
an earlier, tombstoned attempt at the same record (branch name reused deterministically, no shared
commit ancestry), requiring a manual force-push-and-reconcile that an early gate would have caught
immediately after the first call's build phase, before any divergence could accumulate. Separately,
`record-worktree`'s own IL-131 gate *did* fire mid-way through this same second call (denied a
`stage-item.js` write with "this run's worktree assignment was never recorded"), confirming the
first call also skipped that stamp — but self-corrected via its existing gate, unlike the other two.

## Deliverables

- A mechanical check — plausibly alongside the existing bookkeeping-stamps gate, or as a new
  `flow`/`build` post-condition — that a run reaching its first phase-exit push (`/claude-tweaks:test`'s
  or `/claude-tweaks:review`'s) must show *some* `PR-early run lifecycle:` decision-log line
  (success, degrade-to-local-only, or an explicit `local-merge`/`current-branch` skip reason) before
  that push proceeds.
- A soft warning (not necessarily a hard gate) when a run reaches `/claude-tweaks:review` with no
  ledger file for its spec and no logged reason the creation step was skipped.
