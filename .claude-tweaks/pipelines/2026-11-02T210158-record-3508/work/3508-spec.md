# 3508: engine-verify.js: acceptance-labeling's gated/resolved parent handling disagrees with the Parent-Gate Procedure

Origin: ledger resolve gate (wrap-up of #3222, ledger item 9)

**Decision (2026-10-31, human):** the Parent-Gate Procedure (`plugin/skills/wrap-up/verification-brief-parent-gate.md`) is authoritative over #3222's Deliverable 2 for `gated`/`resolved` parents. This settles the record's earlier `needs-human-decision` deferral.

## Current State

`plugin/bin/lib/wrap-up/engine-verify.js`'s `acceptance-labeling` check evaluates `parentGateState` and the parent-path oversight floor (#3222) once a parent target resolves. A gate state of `incomplete`, or a `due` parent below the floor, skips. A `gated` or `resolved` parent still goes through the same floor check and then the `demo:pending` + Verification Brief requirement, because #3222's Deliverable 2 named `due`/`gated`/`resolved` literally:

- `engine-verify.js:904`: `if (gate === 'incomplete') {` is the only gate value that skips.
- `engine-verify.js:918-919` pushes `missing demo:pending label` unconditionally for any parent left after the floor check.
- `plugin/bin/lib/issues/acceptance.js:104-105` returns `'resolved'` for `demo:approved`/`demo:changes-requested` and `'gated'` for `demo:pending`.

`verification-brief-parent-gate.md:252` treats `gated`/`resolved` as a no-op, so the two disagree. As a result, a sub-issue reopened or wrapped up after its parent was already accepted reads `missing demo:pending label` (the label was swapped for the disposition) and BLOCKS closure. A below-floor `gated` parent's brief also goes unchecked. All references were verified at d4d40c982 (evidence carried over from duplicate #4093).

## Deliverables

- [ ] `resolved` parent: `acceptance-labeling` renders `skip` with the reason `parent #P already dispositioned`, never `missing demo:pending label`.
- [ ] `gated` parent: the Verification Brief is checked whatever the parent's risk tier, and the oversight floor never skips it.
- [ ] The oversight floor applies only to `due` parents. `incomplete` keeps today's skip.
- [ ] `verification-brief-parent-gate.md` and `engine-verify.js` state the same rule for all four gate states.
- [ ] Pin each gate state (`incomplete`, `due` above and below the floor, `gated` below the floor, `resolved`) with a test beside the existing `parentGateRow` cases in `tests/bin-lib/wrap-up/engine-verify.test.js`.

## Acceptance Criteria

- [ ] A parent carrying `demo:approved`, with every sibling closed, yields a `skip` row naming `already dispositioned`, and the check does not BLOCK.
- [ ] A parent carrying `demo:pending` with a below-floor risk tier still has its brief checked: a missing brief fails the check.
- [ ] A `due` parent below the floor still skips, and a `due` parent above the floor still requires `demo:pending` + a brief.
- [ ] Each new test fails with today's `engine-verify.js:904` condition restored.
- [ ] `npm test` passes in full.

## Release Note

Wrap-up verification no longer blocks closing a sub-issue whose parent was already accepted.

## Technical Approach

Branch on the gate state before the floor check in `acceptance-labeling`'s parent path. `resolved` returns the skip row. `gated` goes straight to the brief check. Only `due` reaches the floor. Then align the procedure file's "Evaluate the gate" text with the code, if they differ after the change.

### Key Files

- `plugin/bin/lib/wrap-up/engine-verify.js`: the `acceptance-labeling` parent path (:904-919)
- `plugin/bin/lib/issues/acceptance.js`: read only (`parentGateState`'s mapping, :104-105)
- `plugin/skills/wrap-up/verification-brief-parent-gate.md`: the authoritative rule (:252)
- `tests/bin-lib/wrap-up/engine-verify.test.js`: the gate-state pins
