# 4172: Keep a PR-rendered console with a failed finding filing out of archival until a human resolves it

Origin: build final fix-wave re-review of #3949 (out-of-scope observation)

Defer-reason: genuinely-larger

## Current State

#3949 added `--filing-failed` to `node plugin/bin/hooks.js resolve-console` (`plugin/bin/lib/reconcile/console-execute.js`): a ticked PR-console finding row whose filing failed records `filing-failed`, not `executed`, and Resolve stays unticked.

`plugin/bin/lib/reconcile/archive-merged.js` `readConsoleState` (~line 447) treats a non-empty `executedAt` alone as resolved, and PR item outcomes never feed `plugin/bin/lib/console/residue.js`'s `readRunResidue`. So once the PR console is executed, a `filing-failed` row archives with the run and survives only in the PR reply comment and `decisions.md`. `reverse-failed` already behaves this way. Related: #3946's staged review-followup-1 (a failed Queue-write execution on the live-session console keeps `apply`).

## Deliverables

- [ ] A PR console whose items include `filing-failed` (or `reverse-failed`) reads as residue: archival refuses with `console-residue` until acknowledged, and the SessionStart banner lists it.

## Acceptance Criteria

1. An executed PR console.json holding a `filing-failed` item refuses archival (archive-run verb and reconcile sweep) with a reason naming the item, and `console-residue.js --ack` clears it.
2. An executed PR console with only `executed`/`dropped` items still archives.
3. `npm test` passes.

## Release Note

A review finding whose filing failed on a PR-rendered console now blocks archival until someone handles it.

## Technical Approach

### Key Files

- `plugin/bin/lib/reconcile/archive-merged.js` — readConsoleState reads PR item outcomes
- `plugin/bin/lib/console/residue.js` — count failed PR outcomes as residue
