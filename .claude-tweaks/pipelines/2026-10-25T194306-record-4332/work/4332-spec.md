# 4332: wrap-up-engine plan diffs the main checkout instead of the worktree branch

Origin: wrap-up from #4317

Defer-reason: pre-existing-outside-diff

## Current State

`wrap-up-engine.js plan` computes its repo facts (changed files, renamed or deleted files, journey and docs gates) by calling `gatherFacts({ cwd: repoRoot, base })` with `repoRoot = resolveRepoRoot(process.cwd())`. `resolveRepoRoot` returns the parent of `git rev-parse --git-common-dir`, which for a linked worktree is the **main checkout**, so `git diff {base}...HEAD` runs against the main checkout's HEAD instead of the worktree branch the run is wrapping up. It is the right root for the telemetry path, which lives in the main checkout, but the wrong one for diff facts.

Observed on the #4317 wrap-up (a dispatched worktree run): the worklist listed 12 renames of archived run specs from other records as the "renamed or deleted" candidates, and the Journeys row's `frontmatter-overlap` candidates were five journeys unrelated to the branch, while the journey the branch had actually edited was absent. The References row opened on those renames, and the Journeys row would have judged the wrong files, had the judge trusted the worklist.

Evidence: `plan` output for run 2026-10-25T160944-record-4317 against `git diff --name-status -M {base} HEAD` in the worktree (11 files, no renames). Cost this session: the judge had to recompute scope by hand for four rows.

## Deliverables

The diff facts (`changedFiles`, `renamedDeleted`, the rename and heading checks) are read from the current worktree (`git rev-parse --show-toplevel` of the process cwd), while the telemetry path keeps using the main checkout root.

A test that builds a linked worktree whose branch differs from the main checkout's HEAD and asserts `plan` reports the worktree branch's changed files.

## Acceptance Criteria

Run from a linked worktree whose branch changed `docs/a.md`, `plan` lists `docs/a.md` in the changed files and does not list files changed only in the main checkout.

Run from the main checkout, `plan` behaves as before.

`npm test` passes with the new test.

## Release Note

Wrap-up's curation worklist now scopes itself to the branch being wrapped up when run from a linked worktree.
