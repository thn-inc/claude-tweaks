**`tests/hooks-git-exec.test.js` (1 test) is out of scope for this record.** "runGitAsync: opts.env is the spawn environment, same as runGit (#3900)" fails on the forward-slash vs backslash spelling of `rev-parse --absolute-git-dir`. #4299 (ready) covers it explicitly in its Deliverable 1, together with its `runGit` twin. **`tests/hooks-policy-exemption.test.js` (2 tests) is this record's scope.** On Windows:

- "#3900 AC1.1: git -C "<repo>" push origin --delete feature-x from a non-isolated checkout is allowed" (`tests/hooks-policy-exemption.test.js:188`) is denied by the worktree-always gate.
- "#3900 AC1.1: the -C target, not the cwd, is the repo …" (`:209`) is denied on its allowed half (`:213`).

The cause is the fixture, not the gate. Both tests splice the native temp path into the command inside double quotes (`git -C "${repo}" push …`, `:191`, `:213`), so on Windows the command reads `git -C "D:\a\_temp\…" push origin --delete feature-x`. `DELETE_ONLY_PUSH_ALLOWLIST` (`plugin/bin/lib/hooks/pre-tool-use.js:382`) admits the `-C` path through `CQ_ARG`. `CQ_ARG`'s double-quoted form, `CQ_DOUBLE` (`:324`), is a character class that excludes the double quote, `$`, the backtick and the backslash, with the comment "no $, backtick, or backslash inside". The #3900 grammar comment above the allowlist (`:370-373`) states the same exclusion on purpose. A backslashed Windows path in double quotes therefore never matches, the delete-only exemption never fires, and the push falls through to the deny. On macOS/Linux the temp path has no backslash, so the tests pass there.

Two sibling tests carry the same splice but assert a deny: `:195` (content push, splice at `:198`) and `:202` (compound, `:205`), plus the denied half of `:209` (`:215`). They pass on Windows only because the path fails to parse, not because of the shape they mean to check. They stay green but non-discriminating there.

`tests/helpers/shell-quote.js`'s `shellQuote` (from #4281) single-quotes a path for a Bash fixture while keeping every backslash, and `CQ_SINGLE` (`:323`, any run of non-quote characters between single quotes) admits it. This file already imports it (`:19`) and uses it at `:304`. A repo-wide sweep of `tests/hooks-*.test.js` for a double-quoted `"${…}"` path splice found no other site.

## Technical Approach

This is a fixture-only change following `windows-checkout-test-parity`'s row for interpolating a native path into a Bash command fixture: single-quote it through `shellQuote`. No change to `pre-tool-use.js`. The double-quoted grammar is already covered on POSIX paths by the shapes test's `'git -C "/some/worktree" …'` and `'git -C "/Users/x/Code Workspaces/repo" …'` rows (`:257`, `:260`), so moving the integration tests to single quotes loses no grammar coverage.

## Gotchas

- Do not widen `CQ_DOUBLE` to admit a backslash so the double-quoted fixture passes. The exclusion is deliberate: inside bash double quotes a backslash escapes `"`, `$`, a backtick or another backslash, so admitting it would let a crafted `-C "…\"…"` argument change the command's shape past a whole-command allowlist. A real Windows session that runs `git -C "C:\…" push origin --delete x` is denied (fail-closed) and gets the deny message's `gh api -X DELETE` fallback, while the single-quoted or forward-slash form is admitted. Changing that is a separate product decision, not this test fix.

Confirm via the `windows-regression.yml` dispatch, since Linux cannot show it.
