# 4294: Resolve escaped-blank, line-continuation and `$word\ >` redirect targets on the span-mask tokenizer

**Related:** #4212, #4210, #4247

Origin: dispatch close-out of PR #4223 (record #4212), 2026-10-25

Defer-reason: genuinely-larger

## Current State

After #4210 (PR #4235, merge `b4a2f59db`), `plugin/bin/lib/hooks/git-command.js`'s `tokenize` returns a per-character `spanKinds` mask and keeps backslashes in token values as typed; `isUnresolvable` then rejects any token still carrying a backslash. Measured on main (2026-10-25) against #4212's test expectations, three classes resolve **no** target where bash writes to a concrete path. All three are fail-open: none fabricates a target.

1. **Escaped blank in a path word:** `mkdir a\ b`, `mkdir -p /r/a\ b/c`, `cp a my\ file.js`, `cd /r/a\ b && git commit -m x` return `[]`; bash targets `/r/a b`, `/r/a b/c`, `/r/my file.js`, `/r/a b`.
2. **Backslash-newline line continuation** inside or before a word: `echo x >/ma\<newline>in/x` and `mkdir -p \<newline>/abs/dir` return `[]`; bash targets `/main/x` and `/abs/dir`.
3. **A `$` / `${…}` / backtick word, then an escaped blank, then `>`:** `echo $M\ >x`, `echo ${M}\ >x`, ``echo `d`\ >x``, `echo $M\ bar>x` return `[]`; bash redirects to `x`. `echo $M>x` staying `[]` is the documented gap and must not change.

PR #4223 (record #4212, branch `worktree-dispatch-record-4212`, tip `9a6fc75a9`) implemented all three by unescaping values in the old regex tokenizer. It was closed unmerged: it predates the span mask, conflicts with it in all four touched files, and lacks #4210's quoted-span and `(ls)>out` resolution. #4212's own acceptance criteria already pass on main.

## Deliverables

- `tokenize` yields the unescaped value for an escaped blank in a bare word and for an escaped double quote, and deletes a backslash-newline pair before word splitting, while keeping `spanKinds[i].length === tokens[i].length` (the mask must shrink with the value) and keeping every other backslash pair verbatim (Windows paths, `\'`).
- The glued-redirect scan resolves the operand after an escaped blank that follows a `$`/backtick prefix (`$M\ >x`), without accepting `$M>x`.
- `isUnresolvable` stops rejecting a token whose only backslashes were unescaped by the tokenizer.
- `docs/journeys/write-a-glued-redirect-from-the-main-checkout-4015.md` and the redirect paragraph in `plugin/skills/_shared/policy-schema-coverage.md` describe the new behavior.

## Acceptance Criteria

- Every case listed in Current State resolves the bash target named there, pinned in `tests/hooks-gate-coverage.test.js` / `tests/hooks-git-command.test.js`, each going red when the change is reverted.
- #4212's carried-over expectations hold on the new code: `echo "a\" b>c "` → none, `echo foo>x` → `x`, `echo foo\\>x` → `x`, `echo foo\>x` → none, `cd \'/wt\' && git commit` → none, `echo x > \'/abs/f\'` → none, `echo $M>x` → none, and `echo a\"b>c` → `c` (bash's actual target; #4212 had pinned it as a known miss).
- #4210's cases still resolve (`echo "hi">x` → `x`, `(ls)>out` → `out`), and the existing `fileWriteTargets` / `gitTargets` / `mkdirTargets` suites pass unchanged.
- Full `npm test` passes.
