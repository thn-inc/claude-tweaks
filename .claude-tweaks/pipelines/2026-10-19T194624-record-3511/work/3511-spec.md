# 3511: Let verify.js combine --scope with --baseline adjudication instead of refusing the pair

# Reflect — staged finding 3

**Category:** tangential

Origin: reflect full from #3401

Defer-reason: tangential

## Current State

`bin/verify.js` refuses `--scope <decl> --integration-branch <ref>` together with `--baseline <ref> --baseline-cmd <name>=…`: the baseline flag requires a declared `--cmd`, and the scoped form (map-shaped `checks.tests`) declares none, so the call exits 2 with `--baseline-cmd "tests" names no declared --cmd (declared: none)`. `test/verification.md`'s Re-verify scoping table sends `/flow`'s test phase and every re-verify site down the scoped form, while its Baseline adjudication section is reachable only from the explicit `--cmd` form.

On run `2026-10-17T190411-spec-3401` (host load average 229, three sibling runs) the scoped test-phase run failed on two timing assertions in `flaky.files`, the one allowed retry also failed, and the only way to adjudicate against the base was to abandon the scoped form and re-launch the explicit full form with `--baseline origin/main` — a second ~10-minute full run whose scope the declaration had already resolved to `full` anyway. Refs #3401.

## Deliverables

`bin/verify.js` accepts `--baseline <ref>` alongside `--scope`: when the declaration maps suites, `--baseline-cmd` may name a declared suite (`tests`, `journeys`, …) or be omitted in favour of the declaration's `retry` template for that suite, which already carries the `{file}` placeholder the baseline run needs.

`test/verification.md`'s Re-verify scoping table states that a scoped site passes `--baseline {ref}` on the same invocation, and its Baseline adjudication section names the map-form resolution rule; `flow/steps-and-gates.md`'s test-gate row cites it rather than restating it.

`tests/bin-lib/verify/cli.test.js` pins the combined invocation (scoped + baseline) parsing cleanly and a usage error only when a named `--baseline-cmd` matches neither a `--cmd` nor a declared suite.

## Acceptance Criteria

`node plugin/bin/verify.js --scope .claude-tweaks/verify-scope.json --integration-branch main --baseline origin/main --no-stamp` exits 0 or 1 on a fixture repo — never 2 — and `report.json` carries both `scope` and `baselineAdjudicated` fields.

`node --test tests/bin-lib/verify/cli.test.js` passes and the new combined-invocation test fails when the exit-2 guard is restored.

`npm test` passes in full.

## Release Note

Verification: a scoped re-verify can now adjudicate failures against the integration branch in the same run, instead of forcing a second full suite under host load.
