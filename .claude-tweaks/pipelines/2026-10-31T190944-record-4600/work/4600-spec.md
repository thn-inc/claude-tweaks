# 4600: Backstop hand-closed above-floor parents that carry no acceptance disposition

Origin: spec #4466 build (Task 1 ruling, final whole-branch review)

Defer-reason: genuinely-larger

## Current State

#4466 gave `needsBackstop` an `isParent` field (`plugin/bin/lib/issues/acceptance.js`), so tidy's `acceptance-gap` scope skips every closed decomposition parent. That scope used to flag an above-floor parent that a human closed by hand with no `demo:*` label (local-files: no `acceptance` facet).

No scope sees such a parent now. `parent-gate` (GitHub and local-files Shape 7) fetches open parents only, and `acceptance-gap` excludes parents. `_shared/github-pr-scan-acceptance.md` still says such a parent's acceptance is `/claude-tweaks:demo`'s, but nothing routes it there.

## Deliverables

- [ ] Surface a closed above-floor decomposition parent with no acceptance disposition, either as a `parent-gate` row or as a parent-aware `acceptance-gap` row, recommending `/claude-tweaks:demo #{n}`. Keep below-floor parents excluded, since #4466 closes them with a listing comment.
- [ ] Do this on both drivers.

## Acceptance Criteria

- [ ] An above-floor parent closed by hand with no `demo:*` label (or `acceptance` facet) appears in one tidy scope.
- [ ] A parent closed by #4466's below-floor close does not.

## Release Note

Tidy again flags a decomposed feature whose parent was closed by hand without a demo sign-off.

## Plan Review Decisions

Answers to the plan-review question posted on 2026-10-31 (build Common Step 1.6), decided by the maintainer:

- **Q1, recognising a parent closed by #4466: Reading B.** Exclude any closed parent carrying #4466's durable close marker (the `## Closed below the oversight floor` comment on GitHub, the body section on local-files) before applying the floor; only then compute the sub-issue risk aggregate against `risk-floor`. AC2 must hold even after the floor or a sub-issue's `risk:*` label changes.
- **Q2, a closed parent with zero discoverable sub-issues: Reading B.** Print no `[acceptance-gap]` row, matching `parentGateState`'s rule that a parent with no discoverable sub-issues never reads as due. Emit one warning line with the count of such parents, so a `work-links` mismatch stays visible without flooding the output.
- **Q3, window: Reading B.** Amend AC1 to parents closed in the last 30 days, the same window as the `acceptance-gap` scope.

## Plan Review Clarifications

- **#4466's marker is recognised exactly as #4466 recognises it.** On GitHub that is a `## Closed below the oversight floor` comment from a trusted author or from the current `gh` identity, the same test `below-floor-parent-close.js` and `wrap-up/verification-brief-parent-gate.md` apply. Supported by: "Exclude any closed parent carrying #4466's durable close marker (the `## Closed below the oversight floor` comment on GitHub, the body section on local-files) before applying the floor" and "AC2 must hold even after the floor or a sub-issue's `risk:*` label changes." Reading the marker more narrowly than #4466 would let a #4466 close posted under an untrusted association print a row after a relabel.
- **A closed parent with a sub-issue missing from the GitHub state map prints the row when its readable sub-issues already exceed the floor.** An unread sub-issue can only raise the maximum. Only when the readable ones do not exceed the floor is the parent indeterminate: it prints no row and is counted in a warning line. Supported by AC1: "An above-floor parent closed by hand with no `demo:*` label (or `acceptance` facet) appears in one tidy scope."
