# 6055: Delete a closed record's plan ref in reconcile

Surface: infra
Risk-flags: irreversible-side-effect

## Overview

Specify-time plans live on `refs/claude-tweaks/plans/{n}` on the remote. A record that closes, by merge or otherwise, no longer needs its plan, and nothing else deletes the ref. This record adds a reconcile convergence check that deletes the plan ref of every closed record.

**Complexity:** Low
**Estimated tasks:** 3-4

## Non-Goals

- Replacing a ref when a record is re-planned (the store's `write` does that).

## Prerequisites

| Spec | Title | Status |
|------|-------|--------|
| #6052 | Store a reviewed plan on refs/claude-tweaks/plans/{n} with a Plan: body line and a staleness verdict | open |

## Current State

- `plugin/bin/lib/reconcile/` holds one module per convergence check; `docs/reconcile-checks.md` lists every registration site a new check touches.
- `plugin/bin/plan-store.js` (from the plan-store record) owns the ref name.

## Deliverables

1. A reconcile check that lists `refs/claude-tweaks/plans/*` on `origin`, reads each record's state, and deletes the refs of closed records; refs of open records are left alone; an unreadable state leaves the ref.
2. Every registration site `docs/reconcile-checks.md` names.
3. Tests with a fake runner: closed → deleted, open → kept, state unreadable → kept, delete failure → reported, never thrown.
4. **Closed.** A record is closed only on a positive match: its issue `state` reads `CLOSED` (any close reason) from one aliased GraphQL batch beside `pr-state-batch.js`'s pattern. Open, a null alias, a deleted or transferred issue and a partial response all keep the ref. A record reopened after its ref was deleted is re-planned by the next specify or build (accepted).
5. **Scope of refs.** Only refs matching `^refs/claude-tweaks/plans/[0-9]+$` on `origin` are considered; the ref prefix and parser are imported from `plugin/bin/lib/plan-store/` (#6052), never re-typed. `ls-remote` failure aborts the check with a reported row.
6. **Delete.** One `git push` per ref using a lease on the observed sha (`--force-with-lease=<ref>:<sha>`), so a plan re-written between the listing and the delete survives. The check is skipped with a reported reason under `work-backend: local-files`, with no `origin`, and on the `gh`-absent MCP transport.
7. **Registration.** Background tier (it needs a remote listing), position in `DISPATCH_ORDER` and any `PREREQUISITES` entry as `docs/reconcile-checks.md` directs; under `--dry-run` it reports the planned deletions as residue and deletes nothing.

## Acceptance Criteria

1. After the check runs, no `refs/claude-tweaks/plans/{n}` remains for a closed record `n` whose state was readable and whose ref was deletable.
2. An open record's ref and an unreadable-state record's ref survive.
3. The check never breaks a session: every failure is a reported row.
4. `npm test` passes.
5. A partial batch response keeps the refs whose state is missing; a non-numeric ref suffix is never touched; `--dry-run` deletes nothing.

## Gotchas

- Read `docs/reconcile-checks.md` before starting; it names sites outside `plugin/bin/lib/reconcile/`.
- Batch the state reads (one GraphQL call), as `pr-state-batch.js` does.
- Risk proof required: this record carries kept risk flags, so one plan step must contain, per slug, a line `Proof(<slug>): <text>` with a specific proof of at least 20 characters. Lines: `Proof(irreversible-side-effect): …`.
- The `Proof(irreversible-side-effect):` step can state: closed state is read from a fresh batch immediately before the deletes, only exact-integer suffixes are deleted, each delete leases on the observed sha.
