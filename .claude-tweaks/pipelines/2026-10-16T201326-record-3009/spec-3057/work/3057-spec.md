# 3057: Compare blast-radius against Claude Code's native dangerous-rm timeout

Surface: infra

## Current State

The original request says claude-tweaks "already ships a blast-radius mod that intercepts risky commands (rm -rf, git reset --hard, etc.) and asks Proceed/Cancel". The checkout does not support that premise:

- The only blast-radius code is `plugin/bin/blast-radius.js` (with `plugin/bin/lib/blast-radius-cli.js`). It is the gather step of `assess-agent-autonomy`'s merge-check: merge-base resolution, diff numstat, and sensitive-path classification at merge time. It never intercepts a command.
- claude-tweaks ships no mods. Its tool-call interception is the PreToolUse hook (`plugin/bin/lib/hooks/pre-tool-use.js`), and it only ever emits `permissionDecision: 'deny'` (pre-tool-use.js:422). It never emits an ask prompt, so no claude-tweaks gate can leave an unattended run waiting on a Proceed/Cancel.
- None of its gates targets `rm -rf` or `git reset --hard` (no match for either in `plugin/bin/lib/hooks/`).
- Recursive deletion inside claude-tweaks' own unattended machinery runs through Node `fs.rmSync`, not a Bash `rm` command. Examples: `plugin/bin/lib/file-lock.js:115`, `plugin/bin/lib/reconcile/archive-merged.js:834`, `plugin/bin/lib/reconcile/reap-merged.js:132`. Shipped skill prose uses only single-file `rm -f` (for example `plugin/skills/_shared/headless-self-report.md:51`).

The external change: Claude Code 2.1.281+ times out a flagged dangerous `rm` prompt after two minutes in unattended, auto, or `--dangerously-skip-permissions` runs, denying the command with a rewrite hint instead of hanging (source in the original request below).
