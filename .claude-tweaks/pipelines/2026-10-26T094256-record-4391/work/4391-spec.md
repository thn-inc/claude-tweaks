# 4391: Bound the shell-scanner differential recipe so a real write shape cannot outlive its run and fill the disk

**Related:** #4303, #4281, #4149

Origin: disk-full incident found while holding /claude-tweaks:dispatch #4294, 2026-10-26

Defer-reason: tangential

## Current State

The project skill `.claude/skills/shell-scanner-bash-differential/SKILL.md` (Common Operations, "bash verdict") tells an agent to judge each command shape against real bash with `spawnSync('/bin/bash', ['-c', cmd], { cwd: scratch, env: { ...process.env, PATH: stubDir + ':' + process.env.PATH } })`. That call sets no timeout, no file-size limit and no process group. Its PATH appends the real PATH after the stubs, so any program word the stub dir lacks (`dd`, `cat`) runs for real.

Some corpus shapes never end when run for real: `dd if=/dev/zero of=…` writes until the disk is full, and `cat a f1` with stdout going into `f1` reads its own output. When the driver or the agent is stopped, `spawnSync` kills nobody (it has no timeout), or at most kills bash itself. Either way the writer is re-parented to launchd (PPID 1) and keeps writing after its scratch dir is deleted, into an unlinked file no folder listing shows.

Measured on 2026-10-26:

1. The #4303 build's oracle tree (`scratchpad/flow4303/t9-oracle-tree`) left three `gdd if=/dev/zero of=…/a.js` processes that ran 7h18m to 7h29m and wrote 154 GB, 157 GB and 152 GB (~463 GB) into deleted files, about 17 GB/hour together. The disk reached 100% with 29 GB free; the space stayed pinned after they exited, most likely by a Time Machine local snapshot taken while the files existed.
2. The #4281 review's fuzz scratch (`.claude-tweaks/pipelines/archive/2026-10-25T135603-spec-4281/review-ctx/agent-scratch/s3b/runs-*/`) left 30 orphaned `cat a f1` variants (`cat a dd of=f1 f1`, `cat a install a f1`, `cat a ln -t sub a f1`, …), each 17 hours old with 0.6 to 1.2 GB written, after that run was archived.

`tests/helpers-shell-quote.test.js`, the one committed suite that spawns `/bin/bash`, runs only `printf` and is not affected.

## Deliverables

- The skill's "bash verdict" recipe runs each shape under a hard file-size cap that every child inherits (`ulimit -f` inside the `bash -c` prefix, a few MB), so an orphaned writer is killed by `SIGXFSZ` instead of growing without bound.
- The recipe spawns bash as its own process group with a wall-clock timeout, kills the whole group (`process.kill(-pid, 'SIGKILL')`) on timeout and on driver exit, and closes stdin (`stdio: ['ignore', …]`).
- The recipe's PATH puts no real program directory after the stub dir for the words under test, so a word without a stub fails as "command not found" instead of running for real; the skill says which real tools the stub dir must link explicitly.
- An Anti-Patterns row records the 2026-10-26 incident (~463 GB from three orphaned `dd` writers, 30 orphaned `cat` loops) as the reason for the bounds.
- The skill states how to check for leftovers after a session: list PPID-1 `dd`/`cat` processes whose output file sits under a scratch or `agent-scratch` path.

## Acceptance Criteria

- Running the recipe's driver on `dd if=/dev/zero of=f1` ends within the stated timeout, leaves no process behind (`ps -ax -o ppid,command` shows no PPID-1 `dd`), and `f1` stays under the cap.
- The same check holds for `cat a f1` with stdout going into `f1`, and for a shape that backgrounds its writer (`dd if=/dev/zero of=f1 &`).
- Killing the driver mid-run with SIGTERM leaves no orphaned writer, and anything that escapes is still stopped by the file-size cap.
- The recipe text in the skill matches the driver that passed the three checks above (copied from the working script, not retyped).

## Release Note

Maintainer-only: the shell-scanner differential recipe now bounds every real-bash run, so a write shape can no longer leave a process filling the disk after the run ends.
