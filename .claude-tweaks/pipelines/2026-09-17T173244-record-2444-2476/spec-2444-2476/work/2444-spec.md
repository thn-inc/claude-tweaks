# 2444: parseRepo callers' --repo CLI flag can't target a non-github.com host

Surface: infra

## Current State

Ten call sites across `plugin/bin/` resolve an explicit `--repo` value by unconditionally
wrapping it as `` parseRepo(`github.com/${opts.repo}`) `` before parsing — so a caller-supplied
`--repo` can never target a non-github.com host, even after #2240 widened `parseRepo` itself to
return a `host` field. Only the git-remote fallback path (`parseRepo(remote)`, when `--repo` is
omitted) benefits from #2240's widening.

Confirmed live in the current tree:

- `plugin/bin/fetch-sub-issues.js:92`
- `plugin/bin/release-claim.js:138`
- `plugin/bin/file-feedback.js:112`
- `plugin/bin/apply-refine-labels.js:174`
- `plugin/bin/link-records.js:77`
- `plugin/bin/repair-claim.js:99`
- `plugin/bin/materialize.js:327`
- `plugin/bin/lib/compose-subject.js:179`
- `plugin/bin/preflight-records.js:115`
- `plugin/bin/backlog-grant-gate.js:148`

This is a distinct, still-live bug from #2443 (closed already-shipped, 2026-09-16): #2443 was
about `bin/lib/**` modules discarding a host that had already reached them; this record is about
the wrap that decides what `host` reaches them from `--repo` in the first place.

`plugin/bin/lib/number-list-cli.js:96-97` already carries the fix, landed as a review finding on
#2425: `parseRepo(opts.repo.split('/').length >= 3 ? opts.repo : \`github.com/${opts.repo}\`)` — a
3-segment `--repo` value (`host/owner/repo`, `repoSlug()`'s own GHE output shape) is passed through
unwrapped; a 2-segment `owner/repo` value still gets the `github.com/` prefix, unchanged. Its
regression tests (`tests/bin-lib/number-list-cli.test.js:166` and `:177`) are the reference
fixture shape for this record's own test coverage. `number-list-cli.js` is the shared scaffold
behind `resolve-blockers.js`/`resolve-linked-prs.js` only — the ten call sites above each hand-roll
their own `parseRepo` wrap independently and never picked up #2425's fix.

## Deliverables

- Apply `number-list-cli.js`'s exact segment-count check (`opts.repo.split('/').length >= 3 ?
  opts.repo : \`github.com/${opts.repo}\``) to each of the ten call sites listed above, replacing
  their unconditional `github.com/` wrap.
- Add one regression test per call site's existing test file, mirroring
  `tests/bin-lib/number-list-cli.test.js`'s two `#2425 review fix` cases: a host-qualified
  `--repo host/owner/repo` resolves to that host, and a bare `--repo owner/repo` still resolves to
  `github.com` unchanged.

## Acceptance Criteria

- Each of the ten named call sites' `--repo` flag accepts a host-qualified `host/owner/repo` value
  and resolves `repoSpec.host` to that host, not `github.com`.
- Each of the ten named call sites' `--repo` flag still resolves a bare `owner/repo` value to
  `host: "github.com"` — no regression on the existing, far more common case.
- Every git-remote fallback path (`--repo` omitted) is unchanged — this record touches only the
  explicit-`--repo` wrap.
- `npm test` passes.

## Technical Approach

Replace the unconditional `` `github.com/${opts.repo}` `` (or `o.repo` — two of the ten sites use
that param name) template literal at each of the ten cited line numbers with
`number-list-cli.js:96`'s conditional: pass `opts.repo` through unwrapped when it already has 3+
`/`-separated segments (already host-qualified), otherwise prefix `github.com/` exactly as today.
No change to `repo-resolve.js`'s `parseRepo` itself — the fix is entirely in how each caller
constructs the string it hands to `parseRepo`, matching #2425's precedent. Add the two-case test
pattern (`tests/bin-lib/number-list-cli.test.js:166`/`:177`) to each call site's own test file.

## Gotchas

- Don't touch `parseRepo`/`repoSlug`/`ghAvailable` in `plugin/bin/lib/repo-resolve.js` itself —
  #2240 already widened that module correctly; the bug is entirely in how the ten callers wrap
  their input before handing it to `parseRepo`.
- This is a mechanical, low-risk change (ten near-identical one-line edits plus matching tests) —
  don't let the ten-file spread inflate the ceremony; each site is independently verifiable against
  the same two test cases `number-list-cli.js` already pins.
