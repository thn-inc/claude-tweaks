# 3093: Render the adopted-branch unknown-relation stop card in code, not by hand

Origin: v6.139.1 release whole-branch review (/claude-tweaks:release Step 3, v6.139.0..48c63045a), staged finding review-3 — the release review stages and never applies fixes in place

Defer-reason: needs-human-decision

## Current State

`plugin/bin/lib/worktree/remote-branch-collision.js:142`'s `formatStopCard({ branch, remoteSha, prLookup })` has no `reason` parameter and always says the remote commit "is not in this worktree's history". `plugin/skills/build/adopted-branch-collision-check.md:57-61` requires the `unreachable`-with-`remoteSha` card (`fetch-failed`, `ancestry-check-failed`) to say the relation "could not be determined ({reason})", and the runnable command only prints `card` for `foreign` — so that card is hand-composed by the agent each time.

## Deliverables

- Add a `reason` option to `formatStopCard` that renders the unknown-relation wording.
- Have the runnable command in `adopted-branch-collision-check.md` print `card` for both stop cases (`foreign`, and `unreachable` with `remoteSha` set).
- Unit-test both card shapes.

## Acceptance Criteria

- [ ] `formatStopCard({ ..., reason: 'fetch-failed' })` names the reason and does not claim the commit is outside `HEAD`'s history.
- [ ] The command's JSON output carries `card` for an `unreachable` result with `remoteSha` set.

## Release Note

When the build cannot tell whether a same-name remote branch is yours, the stop message now says so plainly instead of being improvised.
