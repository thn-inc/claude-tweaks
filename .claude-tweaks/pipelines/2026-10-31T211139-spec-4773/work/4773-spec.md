# 4773: hooks.js archive-run ignores unknown flags such as --dry-run and archives for real

Origin: post-merge teardown of /flow run 2026-10-31T095259-spec-4549-4550-4556 (session ec124c25)

Defer-reason: tangential

## Current State

`node plugin/bin/hooks.js archive-run --run <dir> --dry-run` archives the run for real: it moves the run directory into `.claude-tweaks/pipelines/archive/` and makes a `[reconcile] archive run …` commit. The verb's usage is `archive-run [--run <dir>]`; only `reconcile` parses `--dry-run`, and every other undeclared flag is dropped the same way.

Cause: `plugin/bin/hooks.js`'s #1012 unknown-flag guard covers only the verbs listed in `KNOWN_FLAGS`. `archive-run` is not listed, so it falls to the `HELP_FLAGS`-only guard, which intercepts `--help`/`-h` and nothing else. #1012 classed `archive-run` as read-only ("No change to read-only verbs (`resolve-run-dir`, `reconcile`, `archive-run`'s own validation, etc.)"), but it moves files and commits in the main checkout.

Observed 2026-10-31 while tearing down run `2026-10-31T095259-spec-4549-4550-4556`: an earlier `--dry-run` call was refused by the console-residue gate before anything moved, which made the flag look like a working preview. The next call archived and committed (20316a43c). The outcome was the one the user had approved, so nothing was lost, but a caller expecting a preview gets a mutation.

## Deliverables

- Add `'archive-run': ['--run']` to `KNOWN_FLAGS` in `plugin/bin/hooks.js`. Any undeclared `--*` argument then prints the usage line and exits 0 before any move or commit, matching `close-run`/`teardown-run`.
- Update the `KNOWN_FLAGS` header comment, which names `archive-run` as a caller that keeps the `HELP_FLAGS`-only guard.
- Check that a `KNOWN_FLAGS` entry does not also switch `archive-run`'s `resolveRunArg` call to the `unambiguousOnly` path unintentionally (the comment says that table also feeds it). If it does, either accept that (no `--run` and an ambiguous run set then refuses instead of guessing) and say so in the PR, or keep the two concerns separate.
- Add a test in `tests/archive-run-verb.test.js`: `archive-run --run <dir> --dry-run` on an archivable fixture leaves the run directory in place, makes no commit, and prints `usage: archive-run [--run <dir>]`.

## Acceptance Criteria

- `archive-run --run <dir> --dry-run` on an archivable run prints the usage line, exits 0, and leaves the run directory and `HEAD` unchanged. The new test goes red with the `KNOWN_FLAGS` entry removed.
- `archive-run --run <dir>` with no extra flag still archives exactly as before; `tests/archive-run-verb.test.js` and `tests/hooks-archive-run-1452.test.js` pass unchanged.
- `git grep -n -F -- "archive-run" plugin/` finds no caller passing a flag other than `--run` (verified at filing: none do).

## Release Note

An unrecognized flag passed to the run-archiving command, such as `--dry-run`, now stops with a usage message instead of archiving the run anyway.
