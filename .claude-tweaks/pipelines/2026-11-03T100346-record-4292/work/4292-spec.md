# 4292: Windows: the guard-rewrite normalizer declines a native plugin root and a native cd target

Origin: #4279 — windows-regression run 40197254500 after #4205 (main d5efeed1c), folded into the #2767 class split

Defer-reason: genuinely-larger

**Related:** #4279, #4205, #4028, #2767, and the class H record from the #2767 split (it takes #4279's `hooks-pre-tool-use.test.js:1638` failure)

## Current State

On a Windows-native path, the PreToolUse `updatedInput` normalizer (`plugin/bin/lib/hooks/guard-rewrite.js`, #4205) declines two of its rules. The cause is in this file's own literal-character classes, not in `git-command.js`'s backslash rule:

- **`plugin-root-placeholder`** (line 525). Line 528 returns `null` unless `LITERAL_VALUE.test(pluginRoot)`. `LITERAL_VALUE` (line 51, `/^[A-Za-z0-9_.\/:@%+,=-][A-Za-z0-9_.\/:@%+,= -]*$/`) excludes `\`. On win32 the root is native (`DEFAULT_PLUGIN_ROOT = path.resolve(__dirname, …)`, line 44; the test's `ROOT` sits under `os.tmpdir()`), so the rule never fires.
- **`drop-redundant-cd`** (line 653). `LEADING_CD` (line 642) admits a double-quoted target only from `[^"$`\\]*`, and an unquoted one only from a class with no `\`. `` cd "D:\…\cwd" && `` never matches, so the rule returns `null`.

Both declines are safe, since the command passes through unchanged. Their effect is that on Windows the normalizer never respells these shapes, so the harness worktree-isolation refusals they exist to avoid still happen there.

The evidence in #4279: each failing assertion expects a rewrite and gets `+ null`. All 3 are in 1 file (line numbers as of d5efeed1c).

### Failing tests

- `tests/bin-lib/hooks/guard-rewrite.test.js:119` — plugin-root-placeholder substitutes the injected root and skips when the command assigns it
- `tests/bin-lib/hooks/guard-rewrite.test.js:144` — plugin-root-placeholder inlines only a file under its own bin/
- `tests/bin-lib/hooks/guard-rewrite.test.js:281` — drop-redundant-cd drops cd "<cwd>" && only when it resolves to cwd

## Deliverables

- `rewriteForGuard` takes a `pathImpl` option, defaulting to `path`, and passes it to the rules for `isAbsolute`/`sep`. It reads `lstatType`/`canonicalRealpath` through `deps`, so a `path.win32` case runs on Linux.
- `plugin-root-placeholder` inlines the root as `toPosix(pluginRoot, pathImpl.sep)`. `D:/…` passes `LITERAL_VALUE` and means the same quoted or bare. `shippedUnder` still lstat's the native join.
- `drop-redundant-cd` accepts a double-quoted target whose backslashes all precede a character other than `$`, `` ` ``, `"`, `\` or newline, so bash keeps them literally. It still requires the exact spelling of the cwd. An unquoted backslash target still declines, because bash strips those backslashes.
- In `tests/bin-lib/hooks/guard-rewrite.test.js`, the expected commands at `:119` and `:144` are built from the forward-slashed root.
