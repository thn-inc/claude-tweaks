# 2745: Upstream defect report — plan-audit Check A false positive on lone new files; `/test` web-surface full-QA rule on a non-UI diff; `node --test` bracket-path globs

Surface: infra

## Current State

Three small, related defects from the same session, bundled in one report:

1. `plan-audit.js` Check A flags a plan whose task creates a single new file in a new directory as "lone new file" — the controller had to pre-create empty directories to silence it. Spot-checked during shaping: `plugin/bin/lib/plan-audit/checks.js`'s Check A section has no visible special-case for a new-directory-plus-single-file shape, and this matches a standing workaround already known in this project ("mkdir the new module dir before auditing") — this defect still appears live, not already fixed.
2. On a record materialized with `surface: web` whose diff has no UI trigger file (a loader + route + config record), the pipeline story selection's "web surface → run the full story set" rule fires instead of reading the Layer 3 sniff first — wasting a full QA pass on a non-UI diff.
3. `node --test "<abs file>"` on Windows globs a path containing `[id]` (a Next.js dynamic-segment directory) and finds no test; the single-file invocation had to go through `tsx --test` with a quoted path as a workaround.

## Deliverables

- [ ] `plan-audit.js` Check A: count a new directory's files together, or explicitly accept a task whose only change is creating a new directory plus one file within it, rather than flagging the single file as a "lone new file" false positive.
- [ ] `/test`'s pipeline story selection: read the Layer 3 frontend-detection sniff (the same one Surface: web/mobile/desktop/backend/infra resolution already uses elsewhere) before defaulting a `surface: web` record with no UI trigger file to the full story set — a web-surface record whose actual diff carries no UI signal should not automatically run every QA story.
- [ ] `skills/test/verification.md`'s single-file test invocation: document (or escape) bracketed path segments (e.g. Next.js `[id]` dynamic-segment directories) so `node --test` globbing doesn't silently find zero tests on Windows — either a documented escaping convention or a fallback invocation path (the filer's own workaround used `tsx --test` with a quoted path).

## Acceptance Criteria

1. A plan task that creates exactly one new file inside a newly-created directory passes Check A without requiring the directory to be pre-created empty.
2. A `surface: web` record whose diff has no UI trigger file does not automatically run the full QA story set — the Layer 3 sniff's result is consulted first.
3. A single-file `node --test` invocation against a path containing a bracketed segment (`[id]`-style) finds and runs its test correctly on Windows, or `verification.md` documents the required escaping/fallback clearly enough that a controller doesn't have to rediscover the `tsx --test` workaround independently.
4. `npm test` passes.

## Release Note

Fixed plan audit false positives on new directories, full QA running on non-UI changes, and test globs with brackets.

## Technical Approach

Three independent, small fixes sharing no code path — safe to land as one record (small, related, same session's evidence) or split at build time if that reads cleaner, but nothing here requires sequencing. (1) is a Check A classification-logic fix in `plan-audit/checks.js`. (2) reuses the existing Layer 3 sniff mechanism (`design-wrapper/frontend-detection.md`'s Layer 2/3 signal, already used elsewhere per root CLAUDE.md's Auto-Mode Contract citation) rather than inventing new detection logic — call the existing sniff from the story-selection rule instead of defaulting past it. (3) is either a doc fix (state the escaping convention) or a small invocation-path change in `verification.md`'s single-file test command — prefer the doc fix first, since introducing a `tsx` dependency for this narrow case is a bigger footprint than documenting the existing workaround clearly.

## Gotchas

- Don't let (2)'s fix silently skip QA on a record that genuinely does need the full story set — the Layer 3 sniff should inform the decision, not replace human/build judgment entirely; a record with an ambiguous or borderline diff should still default toward running stories, not skipping them, per this project's general caution-toward-more-checking posture.
- (3) is Windows-specific (the filer's evidence names Windows explicitly) — verify the fix doesn't change behavior on macOS/Linux where the bracket-globbing issue may not reproduce the same way.
