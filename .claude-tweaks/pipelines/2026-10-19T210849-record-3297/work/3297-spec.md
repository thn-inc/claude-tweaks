# 3297: Post-merge reconcile reports a console-never-rendered run with pending staged items as converging later

**Related:** #3249 #3290 #3327

Origin: whole-branch review of #3249 (Finding 3)

Defer-reason: pre-existing-outside-diff

## Current State

#3249 (branch `worktree-dispatch-record-3249`) makes `archive-merged.js` archive a MERGED run with no `console.json` when its `staged/` holds nothing pending (`decideArchiveCore`'s `hasStagedPending` exception, reached from both `archiveMergedRun` and the by-number fallback). A run whose `staged/` holds real pending items still skips `console-never-rendered` by design — the #657/#1130 protection.

That remaining sub-case can never converge automatically: the fast-lane auto-merge short-circuit (`plugin/skills/wrap-up/auto-merge-short-circuit.md`) surfaces its console content only as a non-blocking PushNotification FYI and never writes `console.json`, so nothing later resolves the staged items. The #3130 incident run (`.claude-tweaks/pipelines/archive/2026-10-16T155630-record-3130/`) has exactly this shape: no `console.json`, `staged/reflect-1.md` and `staged/wrap-up-skill-1.md` pending.

`plugin/skills/_shared/pr-first-merge-post-merge.md` Step 4.2 says a reconcile failure "is logged and left for the next trigger point". #3249 amended that paragraph to name the exception, but the logged/reported skip itself still does not distinguish a transient gh/network failure (converges later) from a structural `console-never-rendered` with pending staged items (needs a human first). Plain `console-never-rendered` is also deliberately excluded from `STRUCTURALLY_STUCK_REASONS`, so it never escalates.

## Deliverables

1. Make the post-merge reconcile report distinguish "transient failure, will converge at the next trigger point" from "staged/ holds pending items, needs human action before this run can converge" — in Step 4.2's logged line and in whatever the reconcile result exposes to it (e.g. a distinct skip reason for a MERGED, console-never-rendered run with pending staged items).

2. Evaluate, and record the decision on, having the fast-lane auto-merge short-circuit write a minimal `console.json` recording that its staged items were surfaced via the PushNotification — which would let #3249's archive exception apply even when `staged/` is non-empty. If adopted, implement it with a test; if rejected, record why in the short-circuit file.

3. Decide whether that structurally-stuck sub-case should escalate via `STRUCTURALLY_STUCK_REASONS` / `trackStuckSkip` like `console-never-rendered-pr-closed` does, so it surfaces somewhere a human looks.

## Acceptance Criteria

- Step 4.2's log/report line never claims convergence is coming for a run that structurally cannot converge without human action; a test pins the distinct reason or wording.

- A transient gh/network failure is still reported as "left for the next trigger point", unchanged.

- The #657/#1130 protection holds: a run with genuinely pending staged items is never archived out of sight without either a resolved console or an explicit recorded surfacing.

## Release Note

After a fast-lane pr-first merge, a run left with unresolved staged items is reported as needing your attention instead of as cleanup that will finish on its own.
