# 3811: Hooks: match git worktree porcelain paths against native cwd on Windows (post-tool-use, context)

# Review — staged follow-up record (from #3695 lens 3a)

**Category:** tangential

## Current State

#3695 fixed teardown-run's two worktree lookups on Windows: `git worktree list --porcelain` prints `D:/a/x/feat` while a native path is `D:\a\x\feat`, so a strict `===` never matched. Review of #3695 found two more lookups in other hooks with the same strict compare of a porcelain path against the native `ctx.cwd`:

- `plugin/bin/lib/hooks/post-tool-use.js:243` — `resolveWorktreePathViaPorcelain` (`entries.findIndex((e) => e.path === cwd)`). It is the fallback that finds the worktree `EnterWorktree` just switched into, and `stampAdHocRunDir`'s widened trigger reuses it. On Windows it returns null, so neither records the worktree.
- `plugin/bin/lib/hooks/context.js:784` — `stampAdHocRunDirForDenial` (same compare). On Windows it returns null, so a gate denial in a session with no owned run dir has nowhere to land its friction event (the gap this function was written to close).

Both read `parseWorktreeList` output from `worktree-reap.js`. The realpath-normalized lookups (`isWorktreeLocked`, `resume-freshness.js`, `flow/consolidated-pass.js`, `run-integrity.js` `deriveBranch`) are unaffected. #3695's `findWorktreeEntry(entries, target, pathImpl = path)` helper lives in `teardown-run.js` and is not shared.

**Related:** #3736, #3836

## Deliverables

1. Move `findWorktreeEntry` beside `parseWorktreeList` in `plugin/bin/lib/hooks/worktree-reap.js` (keep `teardown-run.js` re-exporting or importing it), so every porcelain lookup shares one compare key.

2. Replace the strict `e.path === cwd` compares at `post-tool-use.js:243` and `context.js:784` with the shared helper, keeping each function's `{path, isMain}` / index semantics.

3. Add a `path.win32` pin per site in the existing hook test files (forward-slash porcelain vs backslash cwd).

## Acceptance Criteria

1. With `path.win32`, a porcelain entry `D:/a/x/feat` matches a cwd of `D:\a\x\feat` at both sites, and `isMain` stays true only for the first entry.

2. Each new pin fails when its site's strict `===` compare is restored.

3. `git grep -nE "\.path\s*===\s*cwd" -- plugin/bin` finds nothing.

4. `npm test` passes.

## Release Note

Fix worktree detection in claude-tweaks hooks on Windows, so a session that enters a worktree, or is denied by a gate, is recorded against the right worktree.
