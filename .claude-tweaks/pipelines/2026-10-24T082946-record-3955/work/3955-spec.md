# 3955: Derive the wrap-up ceremony diff facts in one process, not a hand-composed shell pipeline

# Reflect — staged finding 1

**Category:** tangential

Origin: reflect light from #3829

Defer-reason: tangential

## Current State

`wrap-up/ceremony-derivation.md` step 1 derives diff facts by hand-composing a shell pipeline (`git merge-base`, then `git diff --numstat -z {merge-base} | node -e "..."`). #3829 had to pre-split it into two Bash calls and tell the reader to paste a sha and the literal plugin root in, because a worktree-isolated session refuses a `$(git ...)` substitution and a runtime variable inside the `node -e` text of a git pipeline. `bin/blast-radius.js` already shows the single-process shape (merge-base, numstat parse and classification in one `node` call), but its `summary` carries no `docsFiles` or `lowSurface`, so it cannot answer step 1 as it stands.

## Deliverables

- [ ] Add a single-process diff-facts entry point (a `bin/` CLI, or a mode of `bin/blast-radius.js`) that resolves the merge-base against an `--integration-branch`, parses `git diff --numstat -z` with `parseNumstatZ`, and prints `computeDiffFacts`'s JSON

- [ ] Point `wrap-up/ceremony-derivation.md` step 1 at that one command, replacing the two-call prose and the paste-in instructions

- [ ] Update `tests/diff-facts-parse-numstat-conformance.test.js` to pin the new command instead of the pre-split composition

## Acceptance Criteria
