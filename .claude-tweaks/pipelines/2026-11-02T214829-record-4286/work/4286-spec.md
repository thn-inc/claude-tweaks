# 4286: Windows: tests pin POSIX-literal absolute fixture paths that the code resolves to D:\…

## Current State

These tests hard-code a POSIX absolute fixture path (`/repo`, `/x`, `/rd`, `/run/primary`, `/wt/explicit`, `/runs`, `/srv/content`) where the code under test runs that path through `path.resolve` or `path.join`. On win32, `path.resolve('/repo')` is `D:\repo` and `path.join('/x', 'y')` is `\x\y`. So either the expected literal no longer matches, or a fake fs or fake reader keyed on the literal is never hit. The `windows-checkout-test-parity` skill's `path.resolve` Anti-Patterns row names this class. The shapes by file:

- `tests/apply-refine-labels.test.js` (4): expects `'/repo/.claude-tweaks/pipelines/run-1'` and gets `'D:\\repo\\.claude-tweaks\\pipelines\\run-1'`.
- `tests/bin-lib/atomic-write.test.js` (2), `tests/bin-lib/json-store.test.js` (1): `startsWith('/x/store….tmp-')` against a tmp path the code builds with `path.join`.
- `tests/bin-lib/verify/impact.test.js:334`: expects `'\\repo\\.git'` (a join) where the code resolves to `'D:\\repo\\.git'`.
- `tests/bin-lib/visual-decide/server.test.js:102`: `resolveSafe` returns `'\\srv\\content\\'`, and the test expects `'/srv/content'`.
- `tests/friction-events-cli.test.js` (5): `'/wt/explicit'` and `'/run/primary'` literals, plus a fake `readEvents` keyed on `'/run/primary'` while the CLI passes the resolved key.
- `tests/hooks-context.test.js:855`: expects `'/runs/…'` where the code joins to `'\\runs\\…'`.
- `tests/revise-pr-summary-cli.test.js` (5): a fake fs keyed `'/rd/…'` that `path.join` never reaches, so no reversals are read.

20 tests in 8 files fail on Windows (line numbers as of 988cc584d).
