# 3395: Multi-spec parent console and design-wrapper still read materialized headers from the main-checkout run dir

**Related:** #3365, #3399

Origin: /claude-tweaks:build #3365 Common Step 4 (planned out-of-scope follow-up + whole-branch review)

Defer-reason: pre-existing-outside-diff

## Current State

#3365 repointed every `plugin/skills/wrap-up/*.md` reader of a run's materialized spec headers to `wrap-up-pack.json`'s `inputs.records` (`pack.js`'s `resolveRecords`: the run dir's own `work/`, then the worktree's mirror), because a worktree run's materialized spec is committed only in the worktree and reaches the main checkout by merge.

Same-class readers outside `wrap-up/` remain: `plugin/skills/flow/multispec-review-console.md` Shared teardown step 3 (claim release reads `spec-{id}/work/{id}-spec.md` "directly" from the main-checkout parent run dir to confirm the issue number) and its parked-restore paragraph (reads the same path for `parked-at-shaping`), and `plugin/skills/_shared/design-wrapper-handling.md` (`--surface` read from `$PIPELINE_RUN_DIR/work/*-spec.md`). Under pr-first these reads find nothing before merge, so the record confirmation and the parked restore silently fall back, and `--surface` is silently omitted.

## Deliverables

1. Repoint each reader to the worktree mirror (`{worktree}/.claude-tweaks/pipelines/{run-id}/spec-{id}/work/{id}-spec.md`, worktree from the parent `run-state.json`, `worktreeAtClose` for a closed run) or to the pack, keeping the run dir's own `work/` read for current-branch runs.

2. Capture `parked-at-shaping` before the shared worktree is removed in the multi-spec teardown order — the same ordering hazard #3365's Ruling R2 fixed for single-spec Section E.

3. Extend `tests/wrap-up-record-resolution-conformance.test.js`'s absence pin (or a sibling pin) to `plugin/skills/flow/multispec-*.md` and `plugin/skills/_shared/design-wrapper-handling.md`.

## Acceptance Criteria

1. No directive in `plugin/skills/flow/multispec-*.md` or `plugin/skills/_shared/design-wrapper-handling.md` reads a main-checkout `work/*-spec.md` path as its only source.

2. The multi-spec teardown reads `parked-at-shaping` before the step that removes the shared worktree.

3. A conformance pin asserts AC 1 and is proven able to go red against the pre-change text (frozen excerpt or `git show`).

4. `npm test` passes.

## Release Note

Multi-spec runs now release claims and restore parked records correctly before their branch merges, and design checks see the record's surface.
