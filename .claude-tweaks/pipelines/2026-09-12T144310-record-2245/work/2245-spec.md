# 2245: Dispatched review-fan-out agent scratch path may be unwritable under a worktree-mode /flow run

Surface: infra

## Current State

Under a `/flow` pipeline run in `worktree` mode, `{ctx-dir}` (`build-review-context.js`'s scratch dir) resolves to `$RUN_ROOT/.claude-tweaks/pipelines/{run-id}/review-ctx` — and `_shared/pipeline-run-dir.md` anchors `$RUN_ROOT` to the main checkout, never the worktree. Meanwhile a dispatched lens/refutation/gap-sweep agent isolated via `EnterWorktree` has its `Write` tool pinned to its own assigned worktree by the harness's worktree-pinning guard, which (per prior incident notes on this exact gate) refuses writes to shared main-checkout paths — including, plausibly, the `.claude-tweaks/pipelines/` tree this project's own PreToolUse hook otherwise exempts for bookkeeping writes (two independent enforcement layers that may disagree on exactly this directory). #2022 added a `SCRATCH: {ctx-dir}/agent-scratch/{agent-id}` instruction telling dispatched agents to write their probe scripts there — if the tension above is real, that Write call gets refused, and the agent's path of least resistance is writing inside its own worktree instead, which is the exact behavior #2022 exists to prevent (detection — #2022's own post-fan-out sweep — still catches it, so this degrades to "detection works, prevention doesn't," not a regression). This was raised as a Plausible/Important finding on #2022's final whole-branch review, explicitly marked "reasoned from contract + anchoring rules, not empirically dispatched" — nobody has actually dispatched a worktree-isolated agent and watched it try to write to `{ctx-dir}/agent-scratch/...` to confirm the Write refusal actually fires.

## Deliverables

- [ ] Empirically confirm or refute: dispatch a throwaway `EnterWorktree`-isolated agent during a `/flow`-piped `/claude-tweaks:review` run in worktree mode, instruct it to write a small file to its assigned `{ctx-dir}/agent-scratch/{agent-id}` path, and observe whether the Write call succeeds or is refused.
- [ ] If refused: name a worktree-local, gitignored fallback scratch path in `_shared/subagent-output-contract.md`'s Scratch rule (the one canonical location, not restated per-template) for the case where `{ctx-dir}` resolves outside the agent's own working tree, and have `step3-lens-dispatch.md`'s post-fan-out sweep exclude that fallback path too (the same way it already excludes `{ctx-dir}`).
- [ ] If confirmed writable (the pinning guard already exempts this path, or `{ctx-dir}` resolves differently than assumed here): no code change needed — close with the empirical evidence recorded, so this doesn't get re-raised speculatively again.

## Acceptance Criteria

1. The Write-refusal question has empirical evidence (a real dispatch trace), not just contract-reading inference.
2. If a fallback is needed, it's named once in the Scratch rule and excluded once in the sweep — not restated per dispatch template.
