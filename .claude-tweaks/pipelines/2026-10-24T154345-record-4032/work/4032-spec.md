# 4032: Cut hooks.js reconcile from ~63 s per call

Evidence: 14-day transcript analysis of this repo (176 main sessions, 5,599 subagent transcripts, 132 archived timing.json files, ~286k tool calls), 2026-10-24.

## Current State

497 `hooks.js reconcile` calls in main sessions over 14 days averaged 63 s each — 8.7 h of blocking. #1543 previously addressed ~2-minute runs; the per-call cost has not been profiled since.

## Deliverables

1. Per-check and per-subprocess timing in reconcile's JSON output.
2. Remove the measured hot spots: batch or parallelize `gh` calls (`gh-pool.js`), reuse cached results within a TTL (`cache.js`), skip checks whose inputs are unchanged, and move non-blocking checks to the background.
3. Update `docs/reconcile-checks.md` with the timing contract.

## Acceptance Criteria

- [ ] p50 reconcile wall time is under 10 s on this repo over 20 calls.
- [ ] Per-check timings appear in the JSON output.
- [ ] Existing reconcile fixture tests show unchanged convergence results.

## Release Note

Reconcile finishes in seconds instead of about a minute.

## Technical Approach

### Key Files

- `plugin/bin/hooks.js` — reconcile timing
- `docs/reconcile-checks.md` — timing contract

### As built (architecture alignment, /build Common Step 4.5)

These are beneficial deviations from Deliverable 2's wording; the spec now matches what was built.

- **Batching.** `gh` lookups are batched into aliased GraphQL queries (`pr-state-batch.js`, behind the per-pass resolver `pr-state-cache.js`), not only parallelized through `gh-pool.js`. Archive's prefetch fell from 5.2 s across 32 `gh` calls to 2 GraphQL calls.
- **"Skip checks whose inputs are unchanged."** The only check input that can be fingerprinted soundly is the claim blob, so `release` now skips re-reading a claim whose blob sha is unchanged. `archive-branches` and `remote-prune` depend on wall time and PR state, so their inputs never stay "unchanged".
- **The background pass has its own ceiling.** It runs under a 120 s budget (`BACKGROUND_BUDGET_MS`). That budget is needed: under the 18 s hot-path ceiling, `remote-prune`, `ledger-residue` and `reap` were skipped on every background pass. Since the CLI now defers three checks to the background pass, that starvation would have stopped them ever converging.
- **`/tidy` names all nine checks explicitly.** Its sweep needs the deferred checks to converge before it audits.
