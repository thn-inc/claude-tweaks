# 3676: Quote the runner-printed file path in the flaky-retry command

Origin: ledger resolve gate

Defer-reason: tangential

**Related:** #3674

## Current State

The flaky-retry hook substitutes each failing file path into the suite's `retry` template with `template.replace(/\{file\}/g, file)` (`plugin/bin/lib/verify/flaky.js`) and runs it under `{ shell: true }` (`plugin/bin/lib/verify/run.js`). The path comes from the runner's own output and is filtered only by `TEST_FILE_RE`, a suffix check (`plugin/bin/lib/verify/extract.js`), so a name carrying shell metacharacters passes. This predates #3480 for the spec and TAP families, which #3480 extended to the jest/vitest summary family. A real, benign form: vitest's multi-project prefix prints `FAIL  |unit| tests/a.test.ts`, which the extractor captures as the file `|unit| tests/a.test.ts`; the substituted command becomes a pipeline that exits 127, so the retry fails safe rather than clearing anything. Found by the #3480 review lens 3b (single agent, low confidence).

## Deliverables

- [ ] Quote the substituted `{file}` (or run the retry template without a shell) so a path cannot add shell syntax.

- [ ] Strip a vitest `|project|` prefix from the captured summary-family path, or refuse a path containing whitespace or shell metacharacters with a named `retryDecision.reason`.

- [ ] Tests: a path with `$(…)` and a `|unit|` prefixed vitest log, each asserting the command run and the decision.

## Acceptance Criteria

- [ ] A failing file whose printed path contains shell metacharacters never reaches the shell as syntax.

- [ ] A vitest multi-project log retries the real test file, or refuses with a named reason.

- [ ] Each new test goes red when its fix is reverted.

## Release Note

Runner-owned flaky retry no longer passes an unquoted, runner-printed file path to the shell.
