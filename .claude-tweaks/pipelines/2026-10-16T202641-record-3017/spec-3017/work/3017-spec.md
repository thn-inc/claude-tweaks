# 3017: verify.js / wrap-up-engine.js / build-review-context.js: repo-relative inputs resolve against the process cwd, not the git toplevel or --cwd

Surface: infra

## Current State

Three `bin/` CLIs resolve repo-relative inputs against `process.cwd()`. When the shell sits in a subdirectory of the checkout, they silently produce plausible-looking wrong results:

- **`bin/verify.js --scope`**: `readDeclaration(parsed.scope)` (`plugin/bin/verify.js:244`) reads the path as given. `plugin/bin/lib/verify/declaration.js:22-27` maps `ENOENT` to `{ ok: true, decl: null, missing: true }`, so a relative `--scope` that misses because of the cwd reads as "no declaration" and the run falls back to the full suite. `--cwd` (`verify.js:374`) is applied to the check commands only, never to the `--scope` path.
- **`bin/wrap-up-engine.js plan`**: `gatherFacts({ cwd: process.cwd(), ... })` (`plugin/bin/wrap-up-engine.js:194-196`) evaluates fact gates (journeys, CLAUDE.md sections) against the cwd. The same `process.cwd()` pattern recurs at `:291`, `:318`, `:468` and `:634`. `:467` already computes `resolveRepoRoot(process.cwd())` for one path.
- **`bin/build-review-context.js build`**: `plugin/bin/lib/review-context/build.js:58-73` reads each changed file as `readFile(f)` with the repo-relative name from `git diff --name-only`. From a subdirectory every read fails and every file lands in `emptySections`.

Reported run (plugin 6.136.0, cwd `<worktree>/web`): verify.js printed `Scope: full — no declaration at .claude-tweaks/verify-scope.json` and ran an unscoped 22-minute suite. `plan` reported "no journeys" although `docs/journeys/` exists at the root, and flagged a CLAUDE.md change the diff never made. build-review-context reported all 26 changed files as empty sections. An absolute `--scope` path, or running from the root, gave correct results.

## Deliverables

1. **verify.js**: resolve a relative `--scope` against the checkout root, which is `--cwd` when given, else `git rev-parse --show-toplevel` from the process cwd. An explicitly passed `--scope` path that does not exist after resolution is a usage error, exit 2 through the existing `scopeUsageExit` shape (`verify.js:236`), never "no declaration". Keep the missing-declaration fallback only for the implicit default path, if one exists.
2. **wrap-up-engine.js**: every subcommand that gathers repo facts resolves the repo root once (`resolveRepoRoot`, already used at `:467`) and passes it as `cwd` instead of `process.cwd()`. Each `process.cwd()` site listed above is either converted or annotated with why the raw cwd is correct there.
3. **build-review-context.js**: read per-file sections relative to the repo toplevel (`git rev-parse --show-toplevel`), not the cwd.
4. Each CLI's `--help` or header comment states that repo-relative inputs resolve against the checkout root.

## Acceptance Criteria

- For each of the three CLIs, a test runs it with the process cwd set to a subdirectory of a temp git repo (via `execFileSync`'s `cwd` option) and asserts the root-correct result: verify selects the declared suites, `plan` sees the root `docs/journeys/`, and `build` writes non-empty sections. Prove each test goes red against today's code.
- A test asserts `verify.js --scope does-not-exist.json` exits 2 with a message naming the resolved path.
- Running each CLI from the repo root produces byte-identical output to today. Existing suites under `tests/bin-lib/verify/`, `tests/bin-lib/wrap-up/`, `tests/bin-lib/review-context/`, `tests/wrap-up-engine-run-dir-anchoring.test.js` and `tests/wrap-up-engine-journey-crlf.test.js` pass.
- `npm test` passes in full.

## Release Note

Verification, wrap-up planning and review-context building now give correct results when run from a subfolder of your project, instead of silently running everything or seeing nothing.

## Technical Approach

Resolve the root once per invocation at the CLI boundary and thread it down as an explicit `cwd`/`root` argument. The libraries already accept one (`gatherFacts({cwd})`, `verify`'s `--cwd`). Prefer `git rev-parse --show-toplevel` over walking up for a marker file, so a linked worktree resolves to its own root, not the main checkout. Changing exit 0 to exit 2 on a missing explicit `--scope` is a deliberate behavior change: a typo'd path must stop the run rather than widen it.

### Key Files

- `plugin/bin/verify.js` — `--scope` resolution against `--cwd`/toplevel (`:235-276`); explicit-missing → exit 2
- `plugin/bin/lib/verify/declaration.js` — `readDeclaration` (`:22-27`) missing-file result, distinguishing explicit from implicit callers if needed
- `plugin/bin/wrap-up-engine.js` — `process.cwd()` sites (`:194`, `:291`, `:318`, `:468`, `:634`) → resolved repo root
- `plugin/bin/lib/review-context/build.js` — per-file `readFile(f)` (`:58-73`) relative to the toplevel
- `tests/bin-lib/verify/cli.test.js` — subdirectory-cwd and missing-explicit-scope cases
- `tests/bin-lib/wrap-up/engine-plan.test.js` — subdirectory-cwd fact-gate case
- `tests/bin-lib/review-context/build.test.js` — subdirectory-cwd section case

## Gotchas

- `/claude-tweaks:test`'s and `/claude-tweaks:flow`'s prose may pass `--scope` as a relative path today. After this change that path resolves against the root instead of the cwd, which is the intended fix, but grep the skills for `--scope` call sites and confirm none relied on cwd-relative resolution from a non-root directory.
- `wrap-up-engine.js:584` reads `readRunState(args.runDir)?.worktree || process.cwd()`. The run-state worktree is already the right root there. Do not override it with the main checkout's toplevel.
- A file deleted in the diff legitimately has no content to read. It must still land in `emptySections`, so the fix must not hide real deletions.
- Run-dir anchoring rules (`_shared/pipeline-run-dir.md`, `[IL-127]`) are about the main checkout, not the worktree toplevel. Do not conflate the two roots when threading `cwd`.
