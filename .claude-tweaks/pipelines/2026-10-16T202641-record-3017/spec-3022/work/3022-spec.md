# 3022: bin/verify.js --scope: a map-shaped verify-scope.json's per-suite commands are never run, so every selected suite must be re-typed as `--cmd`, and `--cmd-env` can attach only to those

Surface: infra

**Related:** #2806, #3017, #3063, #3066, #3113, #3129

## Current State

`.claude-tweaks/verify-scope.json` may declare `checks.tests` as a map of suite name to command. `plugin/bin/lib/verify/declaration.js:57-59` parses that map form (`isPlainObject(checks.tests)`) into per-suite commands plus `decl.suites`. The string form (`:53-56`) declares a single `tests` suite.

`plugin/bin/verify.js`'s `--scope` block never runs the map form's commands:

- The check set is always `parsed.cmds` (command-line `--cmd`s) filtered by the selection (`verify.js:308-313`). Only tool-scoped mode synthesizes a check from the declaration, and only from the string form (`decl.checks.tests.replace(/\{base\}/g, …)`, `:314-319`).
- The H2 check (`:321-338`) makes any required suite without a matching `--cmd` a usage error: `--scope: mode {mode} requires --cmd for: …`.

`plugin/bin/lib/verify/args.js` adds two more constraints:

- `:98` "at least one --cmd <name>=<command> is required", even under `--scope`.
- `:114` `--cmd-env` that "names no declared --cmd". A suite declared in `verify-scope.json` does not count.

Reported use case (plugin 6.136.0): a project declaring five suites (`tests`, `ui-static`, `ui-unit`, `ui-build`, `ui-e2e`) needed one environment variable on one suite for a full-scope re-verify. Passing one `--cmd` failed H2 for the other four. `--cmd-env` on a declared-only suite failed `:114`. The working invocation re-typed all five commands from the declaration. Two copies of each command can then drift, and the command-line copy silently wins.

## Deliverables

1. Under `--scope` with a map-form `checks.tests`, build the check set from the declaration. Each selected suite runs its declared command unless a `--cmd` with the same name overrides it. `types` and `lint` follow the same rule from `checks.types` and `checks.lint` when declared.
2. Narrow H2 so it fires only for a required name that has neither a declared command nor a `--cmd`.
3. Let `--cmd-env <suite>=KEY=VALUE` attach to a declared suite even when no `--cmd` names it. Keep the "names no check" error for names that are neither declared nor passed.
4. Relax `args.js`'s "at least one --cmd" rule when `--scope` is given and the declaration supplies checks.
5. Update the `verify.js` usage text and `plugin/skills/test/verification.md` examples that show the long `--cmd` list.

## Acceptance Criteria

- `verify.js --scope <map-form declaration>` with no `--cmd` runs exactly the suites the selection picks, using their declared commands, and writes the same pass stamp a fully spelled-out invocation writes today. A test asserts the spawned command strings.
- `--cmd <suite>=<other>` overrides that one suite's declared command, and the run report names the override.
- `--cmd-env ui-e2e=FOO=1` with no `--cmd ui-e2e` sets `FOO=1` for that suite's spawn, flaky retry included.
- A string-form or absent `checks.tests`, and any invocation without `--scope`, behaves exactly as today. `tests/bin-lib/verify/args.test.js`, `scope.test.js` and `cli.test.js` pass unchanged except where they assert the removed errors, and each such edit is named in the PR.
- `npm test` passes in full.

## Release Note

Scoped verification now runs the test commands declared in your verify-scope file, so you no longer have to repeat every command on the command line to change one.

## Technical Approach

Make the declaration the default source of commands and `--cmd` an override layer: merge `decl`'s per-suite commands with `parsed.cmds` by name (command line wins), then filter by the selection as today. H2 and the `--cmd-env` binding then check against the merged set rather than `parsed.cmds` alone. The tool-scoped string-form path is unchanged.

### Key Files

- `plugin/bin/verify.js` — `--scope` check-set build (`:308-319`) merges declared commands; H2 (`:321-338`) checks the merged set; usage text
- `plugin/bin/lib/verify/args.js` — `:98` at-least-one-`--cmd` relaxed under `--scope`; `:114` `--cmd-env` binding accepts declared suites, resolved where the declaration is available
- `plugin/bin/lib/verify/declaration.js` — map-form parse (`:57-59`); reference, exposes per-suite commands
- `plugin/skills/test/verification.md` — invocation examples
- `tests/bin-lib/verify/cli.test.js` — no-`--cmd` map-form run, override, `--cmd-env` on declared suite

## Gotchas

- #2806 (ready, in flight with `bot:in-progress` and an open PR) restructures `args.js`'s four-mode `parseArgs` with "no change to verify.js's CLI-facing behavior". This record changes that behavior in the same file. Build after #2806 merges, or rebase onto it, to avoid a conflicting parallel rewrite of `parseArgs`.
- `args.js` validates `--cmd-env` before the declaration is read. Binding to declared suites needs the check moved after declaration load (in `verify.js`) or the declared names passed in. Do not read the declaration file twice.
- A command-line override that silently shadows a declared command was the original drift risk. The run report must name every override so the shadowing is visible.
- The pass stamp's `suitesRun` must list the suites actually run, declared or overridden, so a later `--stamp-status` reads the same coverage as today's spelled-out run.
