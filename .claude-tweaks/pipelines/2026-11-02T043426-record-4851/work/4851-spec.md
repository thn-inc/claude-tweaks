# 4851: Replace commit-title word matching in the recent-commit overlap screen with a code-liveness check

## Current State

`findRecentCommitOverlap` in `plugin/bin/lib/issues/recent-commit-check.js` matches words from a new record's title against commit subjects from the last 14 days, and posts a triage comment on two or more shared words. On 2026-11-01 it commented on 12 of 14 new records: 10 matched only template words (`settle`, `digest`, `findings`, plus the area name), and 2 matched `pr-scan` and `item`. Passing files makes it worse, because the threshold drops to one word: #4809 went from 12 hits to 17.

History is equally weak. Of 82 records carrying the comment, 2 closed as not planned (#1970, #1776). How many of the 54 completed ones were already fixed is unmeasured, and #1316's own requirement of a low false-positive rate was never measured.

The comment sets no label, so a true match does not stop a build either. `_shared/health-recent-commit-check.md` still calls it a gap-closer for the #1068 failure, where a record is built after its fix has already merged.

## Deliverables

- The screen asks whether the flawed code still exists. It extracts a record's anchors (the file:line references and quoted symbols in Current State, reusing `near-duplicate.js`'s anchor extraction where it fits), and tests them at `HEAD` and against commits in the lookback window touching those files.
- A rollup record (a digest cluster) tests each entry's anchor and flags only entries whose anchor is gone.
- A confirmed match sets `needs:decision` with a proposal naming the commit and the missing anchor, so the record does not build until a human answers. A weak or unprovable result posts nothing, and a failed screen still never blocks filing.
- A record with no anchors gets no comment: no evidence means no signal.
- The open-PR screen stops matching on title words alone: it requires a shared Key File or anchor.
- A replay tool run over the 82 existing records states measured precision in the PR body.
- `health-recent-commit-check.md` and all five filing call sites describe the new behavior.

## Acceptance Criteria

- A test proves a record whose anchor still exists at `HEAD` gets no comment and no label, even when commit subjects share its title words.
- A test proves a record whose anchored line was removed by a commit in the window gets `needs:decision` naming that commit.
- A test proves a rollup flags only the entries whose anchors are gone.
- Replaying the fixture of #4807's title and Key Files produces no match.
- A test proves a git failure or an anchorless record yields no comment and no filing failure.
- The PR body quotes the replay's output over the 82 records.

## Release Note

Flag a new record only when the code it describes has really changed, and hold that record until someone confirms it.
