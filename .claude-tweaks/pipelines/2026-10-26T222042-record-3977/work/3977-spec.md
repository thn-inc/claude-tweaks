# 3977: Close dead runs in report-only mode, show only orphaned runs in the SessionStart banner, and archive a session's own ad hoc run at SessionEnd

Surface: infra

**Related:** #2724 (auto-filed structurally-stuck tracker, kept), #3898 (release runs are owned there)

## Overview

Run directories pile up because nothing closes a run whose session died. Measured 2026-10-22: 78 empty `-adhoc-standalone` directories (0 staged items and 0 decision lines in every one), and 27 stale formal runs (20 open PRs, 6 closed-unmerged, 1 merged). A session that crashes never fires SessionEnd, so its run stays `active` forever. The SessionStart "unfinished runs" banner shows 3 only because `MAX_REPORTED = 3` caps it with no overflow line, and it has no liveness filter: it listed three runs that sibling sessions were probably still driving.

This record is the report-only half of the fix. It adds a pure disposition function (run shape by liveness verdict gives close, leave, or orphan, with a reason), runs it inside reconcile in report-only mode so reconcile says what it would close and closes nothing, narrows the SessionStart banner to dead-and-orphaned runs with an overflow line, and makes a session archive its own ad hoc run at SessionEnd. Closing for real is a later record that must ship in a release after this one, so every consumer project gets a dry run on its own pile first.

The asymmetry the maintainer agreed on governs every rule here: settle findings aggressively, close runs conservatively. Closing a run a live sibling session is still driving ends that run's enforcement and event logging invisibly. A run left open by mistake costs one more banner line.

**Complexity:** Medium
**Estimated tasks:** 8

## Non-Goals

- Reconcile closes nothing in this record. No `run-state.json` is flipped to `clean` by the new rows, no staged item is dropped, no directory is archived by them. Turning that on, and `close-run --abandon`, are #3978.
- Reconcile gains no GitHub write and no skill-file write, and never carries out a staged item's outcome. It never deletes a branch, removes a worktree, or changes claim labels.
- No filing of backlog records per orphaned run, and no listing of live sibling runs "for information"; both relocate the noise.
- No change to the existing merged, `orphaned-mint`, `adhoc-superseded`, and `abandoned-interrupted` archive paths beyond the `live` skip; replacing `abandoned-interrupted`'s recency test is #3979.
- Release runs (`-release-standalone`) closing at their own end is #3898's scope; this record only covers dead ones through the standalone row.
- Not the auto-filed structurally-stuck tracker (#2724), which stays as it is.

## Deliverables

- [ ] A pure disposition function, `plugin/bin/lib/run-liveness/disposition.js` (next to the verdict module), taking run shape, liveness verdict, PR state, branch and worktree facts, and staged inventory, and returning `{ action: 'close' | 'leave' | 'orphan', reason, evidence, dropFindings }` and exporting the set of reasons that return `close` as `CLOSE_REASONS`. The ordered rules below are its contract, evaluated first match wins with a default of `leave`.
- [ ] A facts gatherer next to it (`plugin/bin/lib/run-liveness/facts.js`, injectable git and `gh` runners) that produces the inputs the function needs and maps any failed probe to the "cannot determine" value (never to a value that closes): `pr` is `merged | closed-unmerged | open | none | unknown`; `branch` is `{ localExists, remoteExists, uniqueCommits }` where `uniqueCommits` is a count against the integration branch's merge-base or `null` when it cannot be computed; `worktree` is `{ exists, dirty }` with `dirty` `null` when `git status` fails. `pr: 'unknown'` (a `gh`-absent environment, an API error, or the SessionStart fast path) and any `null` fact yield `leave` for every new row.
- [ ] The `live` skip: no archive path, existing ones included, acts on a run whose verdict is `live`. The skip is one guard at the top of the per-run loop in `archiveMerged`, which computes the verdict once per run and hands it to `classifyRunDir` as `ctx.liveness` (the classifier stays pure); a run directory with no `run-state.json` yields `unknown`. The existing merged, `orphaned-mint`, and `adhoc-superseded` paths gain only this skip and keep acting on `unknown`, each having its own evidence (a merged PR, a mint that never wrote `config.yml`, a worktree gone for 30 days). The existing `abandoned-interrupted` path also gains the skip; its own 24 hour recency test stays, and it keeps acting on `unknown`, until #3979 replaces it with the verdict.
- [ ] Reconcile evaluates the disposition for every non-clean run in REPORT-ONLY mode, behind one module constant `RUN_AUTO_CLOSE_REPORT_ONLY = true` in `plugin/bin/lib/reconcile/archive-merged.js` read at exactly one call site: it writes `would close {run} ({reason}, evidence ...)` lines to its summary and to `reconcile-cache.json` (`wouldClose`), lists the `orphan` runs in the same cache (`orphaned`, each with its PR number and reason) and in the archive check's `--json` output, reports a count of `unknown` runs in the summary (never in the banner), and closes nothing. Each pass records `reportOnlyPassAt` in `reconcile-cache.json`, the marker #3978 reads so that auto-close never acts on a checkout that has not first had a report-only pass. The summary renders wherever reconcile's summary already renders; a false positive is reported through `/claude-tweaks:feedback`.
- [ ] Banner: `collectStaleRuns` lists only runs that are `dead` and orphaned, newest run id first, keeps the 3-row cap, and adds an overflow line in the style of `CONSOLE_OVERFLOW_LINE`: `- … and {N} more orphaned run(s) (newest {MAX_REPORTED} shown): node "{root}/bin/hooks.js" reconcile --dry-run --json --checks archive`. The banner stays network-free: it reads the `orphaned` list from `reconcile-cache.json`, re-checks each entry's verdict offline with `runLiveness`, drops an entry that is no longer `dead`, and lists nothing for a run absent from the cache (nothing is listed before the first reconcile pass). Each row names its reason and a resume command, using the existing integrity-derived line text where it applies (the shipped-unclosed and consolidated-pass lines are kept as the text of rows that pass the filter). The "only the owning session should close a run" instruction text in `session-start.js` is removed.

It applies only when the `reason` on the SessionEnd input is one after which the session cannot continue (not `clear`, not `resume`) and when `staged/` is empty or holds only review findings; otherwise today's `interrupted` stamp is kept.

## Acceptance Criteria

1. A fixture run whose owner PID is alive with a matching start time (a live-PID fixture) is never listed by the banner, never reported as `would close`, and is skipped by the merged, `orphaned-mint`, `adhoc-superseded`, and `abandoned-interrupted` paths; one test per path. The first three still act on an `unknown` fixture.
2. Each numbered rule of the disposition table has a test asserting its `action` and `reason`, including the default row; a run with verdict `unknown` yields `leave` for every new row, and `pr: 'unknown'`, `uniqueCommits: null`, and `dirty: null` each yield `leave` even when every other fact says close (a `gh`-absent fixture does not close a run whose PR was never seen).
3. Fail-open variants of the disposition function (treating verdict `unknown` as `dead`, and treating `pr: 'unknown'` as `none`) are present as injected faults and the corresponding tests fail against each.
   a. A falsely `interrupted` run (status `interrupted`, owner PID alive with a matching start time, as #3845 produces) is `live`: not listed, not `would close`, and left by the `abandoned-interrupted` path.
   b. The report-only constant is read at one call site (a source-scan test finds exactly one); with the constant set, the act path is unreachable (a test calling it with the constant true observes no write).
4. A reconcile run over a fixture containing a dead ad hoc run, a dead closed-unmerged-PR run, and a dead no-PR run with nothing to resume writes three `would close` lines to the summary and to `reconcile-cache.json`, and leaves every `run-state.json`, `staged/`, and directory byte-identical (a test snapshots the tree before and after).
5. A dead formal run with an open draft PR, and one with unique commits and no PR, yield `orphan`, appear in the banner, and are not in the `would close` lines.
6. A dead run holding a non-review staged item (for example `reflect-1.md`) yields `orphan` with reason `staged items need an outcome`; a dead closed-unmerged-PR run holding only `review-unconfirmed-*` items yields a `would close` line that also lists the findings it would drop with reason `run-abandoned`, and drops none.
7. With five dead orphaned runs in `reconcile-cache.json` the banner prints the newest three rows and one overflow line naming the remaining count (2) and the listing command; with three or fewer it prints no overflow line. With only `live`, `unknown`, or would-close runs, or with no cache, the banner prints nothing about runs. A cached orphan whose verdict is now `live` is dropped.
8. Each banner row names its reason (for example `draft PR #N, session gone`, `unpushed commits on {branch}`, `staged items need an outcome`) and a resume command; the text "only the session owning a run should close it" no longer appears in `session-start.js` (a grep test pins this).
9. `session-end.js`, given a session whose own run is ad hoc and a terminal SessionEnd reason, closes the run (status `clean`, `closedBy: 'session-end'`) and archives the directory including `events.jsonl`, with the `session-end` event appended before the archive and no write afterwards (the archived directory is not recreated); given a non-terminal reason (`clear`, `resume`), or an ad hoc run holding a non-review staged item, it stamps `interrupted` exactly as before; given a formal run it still stamps `interrupted` exactly as before; given a `fallback` attribution it touches nothing.
   a. The set of terminal reasons is taken from the SessionEnd `reason` values the harness actually emits (see the Gotchas probe), and the test enumerates each.
10. `docs/reconcile-checks.md` states that the new rows are report-only in this release and that the switch is deleted by the record that enables closing.

## Release Note

Added a dry-run report of runs that could be closed automatically, trimmed the unfinished-runs banner to runs that really need attention, and made sessions archive their own scratch run when they end.

## Technical Approach

The disposition function is pure (no I/O): reconcile gathers the facts (PR state from the existing merged-proof path, branch and worktree facts, staged inventory, the verdict from `runLiveness`) and passes them in, so the table is tested without a filesystem. Report-only is one module constant read at the single call site that would act, so the enabling record is a one-line flip plus deleting the constant.

The banner reuses the same disposition: it lists exactly the runs whose action is `orphan` and whose verdict is `dead`. A `would close` run is not listed in the banner (it is reconcile's to report) and is not closed in this release.

### Data / API Surface

`disposition({ shape, verdict, pr, branch, worktree, staged })` returns `{ action, reason, evidence, dropFindings: string[] }`, where `shape` is one of `adhoc`, `standalone`, `formal`; `pr` is `merged | closed-unmerged | open | none`; `dropFindings` lists staged files that would be dropped with reason `run-abandoned`. Reconcile's summary gains a `would-close` category (`format-summary.js`'s `CATEGORIES`) and `reconcile-cache.json` gains a `wouldClose` list of `{ runDir, reason, evidence }`.

## Gotchas

- ASSUMPTION — verify at build: the resume command each banner row prints actually re-enters the run. Existing re-entry text in `collectStaleRuns` covers the shipped-unclosed and consolidated-pass cases; for `draft PR, session gone` and `unpushed commits` confirm what `/claude-tweaks:flow` adoption (`flow/preflight.js`'s `computeAdoption`) accepts before wording the command.
- ASSUMPTION — verify at build: the SessionEnd `reason` values the harness emits (for example `clear`, `resume`, and the exit reasons) and which of them leave the session running; probe it from a real hook invocation and record the raw values in the PR body before fixing the terminal set. Until verified, treat any reason other than a clearly terminal one as non-terminal.
- Reconcile must never act on `unknown`, and a probe error is `unknown`, never `dead`; do not add a shortcut that treats a missing `owner` block as dead (the legacy 72 hour route in `runLiveness` is the only legacy path to `dead`).
- The SessionEnd ad hoc close is safe only because the run is the ending session's own and ad hoc runs never resume (a resumed session mints a fresh one). Keep the `fallback`-attribution guard that `session-end.js` already has: a guessed run is never closed.
- Nested `claude -p` sessions (#3845) can fire SessionEnd against the parent's run. The ad hoc direct close must be gated on the same own-run attribution as the existing stamp, never on `ctx.runDir`.
- Report-only means no write of any kind to a run directory by the new rows: no `closedBy`, no `decisions.md` line, no archive move. The only writes are the summary and `reconcile-cache.json`.
- `reconcile` runs on a fast path at SessionStart (`FAST_CHECKS`) and a background path; the disposition needs PR state, which may require `gh`. Respect the existing gh-absent posture (`_shared/github-write-transport.md`'s MCP path and the accepted MCP gap documented in `docs/reconcile-checks.md`): without PR state a formal run is `leave`, not `close`.
- The banner currently skips ad hoc runs (`isAdHocRunDir`) so they cannot crowd out a real interrupted run; keep that skip for ad hoc and listing only `orphan` rows keeps the cap meaningful.
- File overlap with open records: `archive-merged.js` with #3975 (same file, sequential), #3945, #3740, and #3721; `session-residue.js` with #3950; `session-end.js` with #3845. Related: #2724 (the structurally-stuck tracker stays) and #3898 (release runs close at their own end there).
- Skill edges, if any, go in `docs/skill-graph.md` only; new reconcile checks follow `docs/reconcile-checks.md`'s "Adding a new check" registration list, including the `reconcile-threw` fallback duplicate in `hooks.js`.
