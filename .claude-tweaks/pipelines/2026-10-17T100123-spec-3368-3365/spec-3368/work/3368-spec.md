# 3368: auto-mode policy key: policy-schema.md says it governs standalone /build and unattended /tidy, but flow/SKILL.md lets default-off lower /flow

Surface: infra

**Related:** #3335

## Current State

The `auto-mode` policy key's behavior is consistent, but two of its descriptions are stale. `plugin/skills/flow/SKILL.md:116-119` (Step 1 mode resolution) and `plugin/skills/flow/manifesto.md:26` read the key, and `auto-mode: default-off` lowers an interactively typed `/claude-tweaks:flow` to `interactive`. `plugin/skills/_shared/auto-mode-contract.md`'s mode table, the single source of truth for modes, says the same for every skill.

The two stale descriptions:

- `plugin/skills/_shared/policy-schema.md:111`, the `auto-mode` row: its consumers column already lists `/claude-tweaks:flow`, but the default column reads "unset (`/flow` still defaults to `auto`)" (true only when the key is unset), and the meaning column reads "whether standalone `/build` and unattended `/tidy` firings default to auto mode", leaving `/flow` out.
- `plugin/bin/lib/policy-schema.js:113`, the `auto-mode` summary: "Sets whether a standalone build or an unattended cleanup run starts hands-off by default, without being asked each time." It leaves `/flow` out too.

**Decision (resolved 2026-10-17 in `/claude-tweaks:specify` brainstorming):** keep today's behavior, where `default-off` keeps lowering an interactively typed `/flow`, and correct the descriptions to match. Making `/flow` ignore the key was rejected: it would change behavior for projects relying on `default-off`, and expand-contract would require a deprecation and a removal condition. Dispatched runs are unaffected either way, because #3335 makes `/claude-tweaks:dispatch` pass `auto` explicitly, and an explicit mode argument always outranks project policy.

## Deliverables

1. Rewrite the default and meaning columns of `policy-schema.md`'s `auto-mode` row. Default: unset means each skill keeps its own default (`/flow` → `auto`, standalone skills → `interactive`). Meaning: `default-on` → `auto` and `default-off` → `interactive` for `/claude-tweaks:flow`, standalone `/claude-tweaks:build` and unattended `/claude-tweaks:tidy`, with an explicit mode argument always winning.
2. Reword the `auto-mode` `summary` in `policy-schema.js` to name the pipeline (`/flow`) alongside standalone builds and unattended cleanup, within the 140-character ceiling `tests/policy-schema-metadata.test.js` enforces.
3. Add a prose-conformance test, `tests/auto-mode-scope-conformance.test.js`, pinning the corrected scope.

## Acceptance Criteria

1. `policy-schema.md`'s `auto-mode` row no longer contains "still defaults to `auto`" or "standalone `/build` and unattended `/tidy` firings", and its meaning column names `/flow` (or `/claude-tweaks:flow`) and states that `default-off` resolves to `interactive`.
2. The `auto-mode` `summary` in `policy-schema.js` mentions the pipeline / `/flow`, no longer reads "Sets whether a standalone build or an unattended cleanup run starts hands-off by default", and stays within 140 characters.
3. The new test asserts both properties above against the live `policy-schema.md` row and the `POLICY_KEYS` entry for `auto-mode`, and goes red when the old summary text is restored (demonstrated during build).
4. `flow/SKILL.md`, `flow/manifesto.md` and `auto-mode-contract.md` are unchanged.
5. `npm test` passes, apart from failures that also fail on the `origin/main` baseline.

## Current State

The `auto-mode` policy key's documented scope disagrees with itself. `plugin/skills/_shared/policy-schema.md`'s `auto-mode` row lists its consumers as `/claude-tweaks:flow`, `/claude-tweaks:tidy` and `/claude-tweaks:build` standalone, gives the default as "unset (`/flow` still defaults to `auto`)", and describes the values as "whether standalone `/build` and unattended `/tidy` firings default to auto mode". `plugin/bin/lib/policy-schema.js`'s summary says the same. Meanwhile `plugin/skills/flow/SKILL.md:118` and `_shared/auto-mode-contract.md`'s mode table both let `auto-mode: default-off` lower `/flow` itself to `interactive`.

The gap surfaced while shaping #3335, which makes `/claude-tweaks:dispatch` pass `auto` explicitly so dispatched runs stay hands-off whatever this key says. That record deliberately left this disagreement alone.

## Deliverables

- Make the key's documented scope agree everywhere it is stated (`policy-schema.md`, `policy-schema.js`'s summary, `flow/SKILL.md` Step 1, `auto-mode-contract.md`), with a conformance pin on the agreed wording.
