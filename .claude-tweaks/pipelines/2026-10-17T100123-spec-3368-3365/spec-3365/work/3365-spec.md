# 3365: wrap-up Section C step 2: the carrier-commit glob reads the main-checkout run dir and never fires before merge

Surface: infra

**Related:** #3336 #3335 #3192 #3222

## Current State

The materialized spec (`work/{n}-spec.md`) is git-tracked in the run's worktree and "reaches the main checkout by merge" (`plugin/skills/flow/materialize.md:155`). The run dir every wrap-up reader uses is anchored in the main checkout (`_shared/pipeline-run-dir.md`), so before merge `${RUN_DIR}/work/*-spec.md` matches nothing. Observed in run `2026-10-17T075913-spec-3337`: the main-checkout run dir had no `work/`, and the worktree copy held only `work/`.

The correct resolution already exists: `plugin/bin/lib/wrap-up/pack.js`'s `resolveRecords(deps, runDir, worktree)` falls back to `worktreeMirror` (#1930 review C1). That run's `wrap-up-pack.json` resolved `inputs.records: [3337]` with `sources.records: "worktree-headers"`. Other readers still glob the main-checkout path directly:

- `plugin/bin/lib/wrap-up/engine-verify.js:374` `resolvedIssueNumbers` reads only `path.join(runDir, 'work')`, then the `verify-expectations.json` `issues` fallback. That run's `carrier-commit` check reported "skip (no resolved issue numbers found)" until `--issues 3337` was recorded by hand. A missing closing keyword therefore skips silently instead of failing.
- `plugin/skills/wrap-up/cleanup-procedures-execution.md:69` (Section C step 2, the closing-keyword carrier commit) globs `${RUN_DIR}/work/*-spec.md`, so it never stamps `Fixes #N` in a worktree run.
- Prose readers of the same glob: `review-console.md:26` and `auto-merge-short-circuit.md:10` (the auto-merge short-circuit's applicability), `wrap-up/SKILL.md:69` and `:246`, `cleanup-procedures-execution.md:418` (Section E's `parked-at-shaping` restore read), `execution-and-verification.md:29` (the current-branch `Fixes` issue set), `review-console.md:120` (step 11's "omit `issues`" condition), and `cleanup-procedures.md:7`.

**Impact, traced 2026-10-17 in a `/claude-tweaks:specify` spike.** Two `local-merge` finish paths stamp their own closing keyword through `bin/compose-subject.js`: `_shared/local-merge-auto-finish.md:118-133` and `flow/worktree-merge.md:65`. The interactive/standalone handoff to `/superpowers:finishing-a-development-branch` (Section C step 3, `local-merge`, no `config.yml`) merges with that third-party skill's plain commands, so step 2's carrier commit was its only `Fixes #N` source. A GitHub-backed project on `local-merge`, set explicitly or detected because `gh` is absent (`_shared/integration-model.md:25`), that finishes through superpowers therefore merges without closing its issue, and verify skips silently instead of failing. Under `pr-first` the PR body carries the `Fixes` lines, so step 2 is redundant there.

**Decision (resolved 2026-10-17):** repoint every reader to the one existing resolution and skip step 2 under `pr-first`. Retiring step 2 was rejected, since the superpowers handoff depends on it and is a third-party skill. Repointing without the `pr-first` skip was rejected because it adds a redundant empty commit to every run and re-enters `checkDispatchConfigGate`'s inspection in dispatched worktrees (#3336).

## Technical Approach

Reuse, don't re-derive. `pack.js` already exports `resolveRecords`, `headerRecords` and `worktreeMirror`; `engine-verify.js` should call `resolveRecords` with a minimal `deps` (`readdir`/`readFile` over `fs`) and the worktree from `run-state.json`, not copy its ladder. The prose sites cite the pack field instead of a glob. The pack is written during Phase 3 (`wrap-up-pack.json`), before Phase 4's console and cleanup read it, so every Phase 4 reader can rely on it, and the mirror-glob fallback covers a missing pack. Under `pr-first` the step 2 skip makes the carrier commit unreachable in dispatched worktrees, which keeps #3336's closed analysis true.

Observed in run `2026-10-17T075913-spec-3337`: the main-checkout run dir had no `work/`; the worktree copy had only `work/`.

Under `integration-model: pr-first` this is harmless: the draft PR body carries the `Fixes #N` lines, and `wrap-up-engine.js verify`'s `carrier-commit` check falls back to the PR body. Under `local-merge` on a GitHub-backed project, the closing keyword may never be stamped. That has not been traced through `_shared/local-merge-auto-finish.md` or `flow/worktree-merge.md`, either of which may stamp its own.
