# 4421: Route reconcile's abandoned-interrupted decision through run-liveness and report ownerlessNonClean

Surface: infra

## Current State

`classifyRunDir`'s `abandoned-interrupted` branch (`plugin/bin/lib/reconcile/archive-merged.js`, from line 1794) currently decides liveness without any probe. A run is abandoned when four things hold: its status is `interrupted`; it is not the caller's own live session; `events.jsonl` is readable; and there has been no owner-attributed event within `STALE_INTERRUPTED_TTL_MS` (line 306, defined as `ORPHAN_MINT_TTL_MS`, 24 hours). When the log is readable but holds no own event (`lastOwnMs === null`), the run counts as not recent and is abandoned on the first pass. The event probe is `ownEventRecency`, which lives in `plugin/bin/lib/run-liveness/probes.js` (line 61) and is imported by `archive-merged.js` (line 18). `isAbandonedInterrupted` (line 343) is a thin wrapper: it calls `classifyRunDir` with no `ctx` hook, and this file's tests call it directly.

`archive-merged.js` already calls `runLiveness` for the `adhoc-session-ended` kind, through `adHocSessionLiveness` (line 154), which `classifyRunDir` takes as `ctx.liveness`. That wrapper forces the worktree-path probe to `missing`, because a main-checkout worktree is always locked and always has a recent commit. Its guard, `isMainCheckoutAdHoc` (line 137), only covers **ad-hoc** dirs, because it requires `readAdHocState`. It cannot classify the pipeline runs this branch handles.

`runLiveness` reaches `dead` for an owner-block run only through the `pid` witness (owner pid gone or reused) or the `session-end` witness. It reaches `dead` for an owner-less run only through the `legacy` witness, which needs 72 hours of silence (`LEGACY_DEAD_MS`). Many shapes read `unknown` indefinitely:
- the owner is on another host;
- `owner-session-mismatch` after a resume re-stamps `sessionId`;
- the pid is alive but has no start time, and there is no SessionEnd event;
- any probe error.

The legacy route has a removal condition, recorded in #3979, but nothing reports the count it depends on. Reconcile's archive check reports through `plugin/bin/lib/reconcile/format-summary.js` and persists through `plugin/bin/lib/reconcile/cache.js` (`reconcile-cache.json`, anchored at the main checkout; `readCache` drops keys it does not know, #3132). #3973 first shipped in **v6.153.0**.

This is sub-issue C of #3979.

## Deliverables

- [ ] Task 0, in the PR body: an equivalence table for `abandoned-interrupted`. Its dimensions:
  - owner block: present or absent;
  - owner-pid detail: `gone`, `pid-reused`, `other-host`, `no-pid`, `alive-no-start-time` with or without a SessionEnd event, mismatch, or error;
  - worktree: linked-and-present, linked-and-gone, main checkout, or none;
  - own events: recent, stale, or absent;
  - own session: yes or no.

  Each row gives the old and new outcome. The table's changed rows are also persisted in `docs/reconcile-checks.md` (see the docs deliverable), not only in the PR body.
- [ ] `abandoned-interrupted` fires when the status is `interrupted`, it is not the caller's own live session (guard kept), `events.jsonl` is readable, and one of these holds:
  - **(a)** the verdict is `dead` with no `error` entry, **and** there has been no own event for the 24-hour floor (`STALE_INTERRUPTED_TTL_MS`, unchanged; maintainer ruling 2026-10-22);
  - **(b) bounded fallback** (maintainer ruling 2026-10-26): the verdict is `unknown`, **no live-probe entry (`owner-pid`, `heartbeat`, `worktree-lock`, `last-commit`) is `positive`**, and there has been no own event for `LEGACY_DEAD_MS` (72 hours).

  Without (b), owner-block runs that read `unknown` forever would never be archived, where today they are archived at 24 hours. The silence reference for both floors is `lastOwnMs`, falling back to the run-id timestamp, the same fallback `run-liveness/index.js`'s `probeOwnEvents` uses through its private `runIdMs`. Export it, or share it through `run-liveness/constants.js`'s neighbourhood, rather than copying it. A run with no own event at all is measured from its run-id timestamp, so it is no longer abandoned on its first pass.
- [ ] The verdict comes from a new injectable hook, `ctx.runVerdict(dir, now) -> { verdict, evidence }`, separate from `ctx.liveness` (the `adhoc-session-ended` verdict).
  - The default calls the real `runLiveness(dir, { now })`. For a run whose recorded worktree resolves to the main checkout, the default also forces the path probe to `missing`, the same adjustment `adHocSessionLiveness` makes.
  - `isAbandonedInterrupted` gains an optional trailing `ctx` pass-through, so its direct test callers can inject a fake.
  - The verdict is computed only after the cheap guards (status, own session, events readable, floor elapsed), because it spawns processes.
- [ ] A new predicate, `recordedWorktreeIsMainCheckout(dir, state)`, decides "recorded worktree resolves to the main checkout" for any run dir, ad-hoc or not. It reuses `canonicalRealpath`/`resolveLeaf`. `isMainCheckoutAdHoc` becomes the predicate combined with the ad-hoc check.
- [ ] Reconcile reports `ownerlessNonClean`, the number of run directories directly under the **main checkout's** `.claude-tweaks/pipelines/` (not `archive/`), counted **after** this pass's archival, whose `run-state.json`:
  - is absent; or
  - parses to a plain object with no `owner` object and a `status` that is not the literal `clean` (a missing status counts as non-clean).

  An absent file is counted because `runLiveness`'s legacy route serves those dirs too. The value is a field on the existing archive check's result, summary line and `reconcile-cache.json` (`readCache` learns the key). It is not a new check, so none of `docs/reconcile-checks.md`'s new-check registration sites apply. A skipped or errored pass leaves the field absent, never `0`.
- [ ] `reconcile-cache.json` also carries `ownerlessNonCleanZeroSince`: an ISO timestamp set when the count first reads `0`, kept while it stays `0`, and cleared when it reads above `0`.
- [ ] Docs: `docs/reconcile-checks.md` and `docs/hooks.md` record the removal condition for the 72-hour legacy route (`run-liveness/index.js`'s `legacy` witness): **remove it when `ownerlessNonCleanZeroSince` is at least 7 days old in this repository's `reconcile-cache.json`, on a plugin build newer than v6.153.0.** `docs/reconcile-checks.md` also records the bounded fallback, the 24-hour floor ruling and its revisit trigger, and the changed equivalence rows. After the route is removed, fallback (b) still classifies those owner-less `interrupted` runs as `abandoned-interrupted` at the same 72 hours, so removing it changes no archive decision. It does not drain them on its own: archival still needs the `shipped-unclosed` gate, and owner-less runs in any other status have no drain (tracked in the legacy-route removal record).

## Acceptance Criteria

1. Every `abandoned-interrupted` fixture in `tests/bin-lib/reconcile/archive-merged.test.js` keeps its decision, except rows the equivalence table lists as intentional. Existing fixtures inject a `runVerdict` fake through `ctx` or the wrapper's pass-through, so they never run real probes.
2. A run whose verdict is `live`, or `unknown` with any positive live-probe entry, is never classified `abandoned-interrupted`. A probe-error fixture with a recent own event is not abandoned.
3. An owner-block run reading `unknown` with no positive live probe, such as `other-host` or a session mismatch, is abandoned after 72 hours of silence and not sooner. An owner-block run reading `dead` is never abandoned sooner than 24 hours after its last own event.
4. An interrupted, **non-ad-hoc** pipeline run whose worktree is the main checkout and whose owner pid is gone reads `dead` through the main-checkout adjustment, and is abandoned after the 24-hour floor.
5. A run with a readable, empty-of-own-events log and a run id under 24 hours old is not abandoned.
6. `ownerlessNonClean` fixtures:
   - two owner-less non-clean runs, one absent-state run, one owner-block run, one clean owner-less run, and one archived owner-less run report **3**;
   - only owner-block runs report **0**, and `ownerlessNonCleanZeroSince` is set;
   - a later pass with a count above 0 clears `ownerlessNonCleanZeroSince`;
   - a skipped pass leaves both fields absent.
7. The summary line and `reconcile-cache.json` carry `ownerlessNonClean`. `docs/reconcile-checks.md` and `docs/hooks.md` state the removal condition exactly as the deliverable words it.
8. `npm test` passes.
