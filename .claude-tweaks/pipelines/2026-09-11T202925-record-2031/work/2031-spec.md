# 2031: ports/ensure.js reads and parses .env.local's managed region twice per call

## Current State
`plugin/bin/lib/ports/ensure.js`'s `ensure()` reads and parses `.env.local`'s managed region twice on the path that matters most: an existing lease whose bound port is not free (the common case at every subsequent session start against an already-running dev server). It reads once unconditionally as `regionBefore` (line ~70), then `isRegionCurrent()` (line 34) re-reads and re-parses the same unmodified file itself at line 90, with no write between the two reads.

## Deliverables
- [ ] Extract a `regionIsCurrent(region, base, leaseServices, policyServices)` helper that takes an already-parsed region array (the `readManagedRegion()` return value) instead of a checkout path, containing today's `isRegionCurrent` comparison logic (PORT match + `sameServices`).
- [ ] Keep `isRegionCurrent(checkoutRoot, base, leaseServices, policyServices)` exported with its current signature and behavior, reimplemented as a thin wrapper: read `.env.local`, parse it, delegate to `regionIsCurrent`.
- [ ] In `ensure()`, replace the `isRegionCurrent(checkoutRoot, base, lease.services, policyServices)` call with `regionIsCurrent(regionBefore, base, lease.services, policyServices)`, reusing the region already read into `regionBefore`.

## Acceptance Criteria
1. `ensure()` reads `.env.local` at most once per invocation for the managed-region check (verify via a spy/count on `fs.readFileSync` in a test exercising the existing-lease-not-free branch).
2. Existing `tests/bin-lib/ports/ensure.test.js` assertions pass unchanged — `isRegionCurrent`'s signature and behavior (checkout-root-in, boolean-out) are untouched, only its internals delegate.

## Technical Approach
Keeping `isRegionCurrent`'s public signature intact is required, not optional: it's exported (`module.exports`) and five assertions in `tests/bin-lib/ports/ensure.test.js` (lines 121, 181, 184, 187, 188) call it directly as `isRegionCurrent(dir, base, leaseServices, policyServices)` against a checkout path. Changing that signature to take a pre-parsed region would fail AC2. The fix instead splits the comparison logic out into a new `regionIsCurrent(region, ...)` that both `isRegionCurrent` (file-reading wrapper, for the standalone tests and any other caller) and `ensure()` (already holding `regionBefore`) can call — only `ensure()`'s internal call site changes.

### Key Files
- `plugin/bin/lib/ports/ensure.js` — `isRegionCurrent` (line 34), `regionBefore` read (line ~70), the call site at line 90 to redirect
- `tests/bin-lib/ports/ensure.test.js` — existing `isRegionCurrent` assertions that must keep passing unchanged; no new test required by the ACs beyond the read-count check in AC1, but the existing-lease-not-free branch (`stillFree` false, `isRegionCurrent`-equivalent true) should be the one exercised

## Gotchas
- `isRegionCurrent`'s own missing-file branch returns `false` before ever calling `readManagedRegion` — `regionIsCurrent` must treat a `null`/falsy `region` argument the same way (`if (!region) return false;`), matching `readManagedRegion`'s existing `if (!region) return false;` check inside the current function body.
- The two reads only both happen on one branch (existing lease AND port not free) — `!existingEntry` and `existingEntry && stillFree` never call `isRegionCurrent` at all today, so this is a hot-path optimization for the "server already running" case, not a fix that touches every call.
