# 3903: code-health: resolve 9 accumulated below-floor digest findings

Surface: infra

**Related:** #1426, #3900, #3901, #3902, #3904

## Current State

The materiality-floor digest (#1426) promoted nine below-floor findings in the `code-health` area into this record. All nine concern `/claude-tweaks:code-health` candidate generators, the deterministic pre-filters whose output an LLM judge then reads, so each is a precision or recall gap in a screen, not a user-visible defect. Each finding was filed with a trigger condition describing when it would start to matter. Verified against `origin/main` at shaping time:

**experiment-cleanup (1 item).** `normalizeBranch` in `plugin/bin/lib/code-health/candidates-experiment-cleanup.js` strips comments with literal-blind regexes (`/\/\*[\s\S]*?\*\//g` and `/\/\/[^\n]*/g`), so a branch body holding `//` inside a string loses the rest of that line. Both compared sides are mangled alike, so impact is small. The regex-aware comment stripper from #3585 exists only as a test helper (`tests/helpers/strip-comments.js`), not under `plugin/bin/lib/`. (Defer-reason at filing: pre-existing-outside-diff.)

**scale-readiness (7 items), all in `plugin/bin/lib/code-health/candidates-scale-readiness.js`** unless noted:
1. A capitalized-receiver `X.find(` matches some in-memory constant lookups with a non-function argument, and a filtered `Model.find` with no `.limit` reads as unbounded. (genuinely-larger)
2. `findMany(args)` with a non-literal argument, a spread-only `{ ...opts }`, or a computed `['take']` key reads as unbounded. (genuinely-larger)
3. A module-scope object literal holding a client in a route file (`module.exports = { db: new PrismaClient() }`) reads as `per-request-db-client`, a shape the criteria fragment's What NOT to flag already names. (genuinely-larger)
4. `unbounded-pool` matches non-DB `Pool` classes (generic-pool, undici, workerpool), because it has no DB-dependency gate. The generator already holds `ctx.deps` for its cache and monitoring checks. (needs-human-decision)
5. `window.fetch(` / `globalThis.fetch(` third-party calls on the request path are not matched, because of the dotted-receiver lookbehind. (needs-human-decision)
6. `isRouteFile` is a pure path predicate, while real route membership also needs a server/data dependency or a `"use server"` directive. This is a naming trap for a future second caller; the definition carries a comment saying so. (needs-human-decision)
7. Nuxt, h3, @trpc/server and Elysia apps with only a framework dependency read as not applicable, because `SERVER_DEPS`/`DATA_DEPS` do not name them. (needs-human-decision)

**scale-readiness criteria fragment (1 item).** `plugin/skills/_shared/criteria-scale-readiness.md`'s severity calibration leaves `unbounded-pool` off-serverless and an AI inline-slow-work call on a non-user-facing route unplaced, and its "bounded input" What NOT to flag line is in mild tension with a Severity "low" line. The judge falls back to holistic severity. (needs-human-decision)

## Deliverables

1. **Mechanical fixes, implemented with regression tests**, for the items whose fix is unambiguous:
   - experiment-cleanup: make `normalizeBranch` string-literal-aware. Promote the #3585 stripper from `tests/helpers/strip-comments.js` into `plugin/bin/lib/` and have both the test helper and the generator use it.
   - scale-readiness item 4: gate `unbounded-pool` on a declared DB dependency (`ctx.deps` against `DATA_DEPS`).
   - scale-readiness item 3: exclude the module-scope client shape already named in the fragment's What NOT to flag.
2. **Decision items surfaced, not decided unilaterally.** Items 1, 2, 5, 6 and 7 and the criteria-fragment calibration were deferred as genuinely-larger or needs-human-decision. For each, the build either implements a fix with tests or records a one-line won't-fix or keep-deferred ruling with its reason. Every needs-human-decision ruling is staged for the human at the run's Review Console, never auto-applied.
3. Each of the nine promoted digest entry lines in #1426 carries `→ #3903`.

## Release Note

Code-health's scale-readiness and experiment-cleanup screens raise fewer false candidates for non-database pools, module-scope clients and comment-like text inside strings.

## Technical Approach

Treat this as three independent slices: the stripper promotion plus `normalizeBranch`; the scale-readiness mechanical fixes (items 3 and 4); and the decision items. The decision items need no code unless a ruling chooses to fix. The `code-health-focus-vertical` and `bin-source-scan-conformance` project skills govern generator anatomy and the shared comment stripper's contract (including its stripper-verdict check), so read both before moving the stripper. Real-input fixtures matter more than synthetic ones for generator changes. Use a fixture that reproduces each false positive rather than a hand-built minimal string.

### Key Files

- `plugin/bin/lib/code-health/candidates-experiment-cleanup.js` — `normalizeBranch`
- `tests/helpers/strip-comments.js` — the #3585 stripper, to be promoted
- `plugin/bin/lib/code-health/candidates-scale-readiness.js` — `unbounded-pool` gate, module-scope client exclusion, decision items 1/2/5/6/7
- `plugin/skills/_shared/criteria-scale-readiness.md` — severity calibration (decision item)
- `tests/bin-lib/code-health/` — regression fixtures

## Gotchas

- `tests/helpers/strip-comments.js` is imported by the source-scan conformance suites. Moving it must keep every existing import path working, or the conformance suites lose their stripper silently.
- Five of the nine items were deferred as needs-human-decision. A headless build must stage those rulings rather than settle them; only the three mechanical fixes are unambiguous.
- Candidate generators are screens that the judge filters afterwards. A fix that over-narrows a pattern trades a false positive for a missed real finding, so pair every exclusion with a still-flagged positive case.
