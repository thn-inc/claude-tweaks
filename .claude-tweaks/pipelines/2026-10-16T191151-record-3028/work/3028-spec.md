# 3028: compose-subject.js: handled `issueType` rejection still echoes gh's stderr; no `--scope`; no tag for close-out's human-confirmed merge

Surface: infra

## Current State

The merge-subject composer has three separate gaps. All three were observed on a GitHub Enterprise Server host (Windows + Git Bash, gh 2.92.0):

1. **The handled `issueType` rejection is noisy.** #2561's fallback works: `isUnknownIssueTypeField` (`plugin/bin/lib/compose-subject.js:156`) detects gh's `Unknown JSON field: "issueType"` error, the call retries without the field (`compose-subject.js:233`), and it falls back to GraphQL, with exit 0 and a correct subject. But `realDeps.runner` (`compose-subject.js:206`) calls `execFileSync('gh', args, { encoding: 'utf8', timeout: GH_TIMEOUT_MS })` with no `stdio` option, so Node copies the child's stderr to the parent's in addition to capturing it. The successful compose is therefore preceded by gh's error and full field list, and reads like a failure.
2. **There is no scope support.** `composeSubject` (`plugin/bin/lib/release/subject.js`) builds the prefix as only `{type}` or `{type}!` (`subject.js:73`). Nothing anywhere produces `type(scope):`, so a project whose commit convention requires a scope can't get one.
3. **Close-out's human-confirmed merge has no tag.** Step 5 of `plugin/skills/dispatch/close-out.md` (`close-out.md:60`) reuses Step 3 of `plugin/skills/_shared/pr-first-merge.md`. That step's `{tag}` vocabulary (`pr-first-merge.md:283-289`) is `auto-merge`, `fast-lane`, and `manifesto-authorized`, and `_shared/github-pr-scan.md`'s `triage-queue` auto-merged-this-week metric counts every one of them as an auto-merge. A merge confirmed at close-out's per-PR gate is none of these. A caller was observed passing `fast-lane`, which miscounts a human decision as an auto-merge.

Two constraints affect the change. Title truncation to `SUBJECT_BUDGET = 72` (`subject.js:18`) is by design and stays unchanged, though a scope shortens the room left for the title. `tests/merge-subject-composer-conformance.test.js:25` pins `PR_FIRST_BYTE_CEILING = 31304`, and `pr-first-merge.md` is currently 30761 bytes, which leaves 543 bytes of headroom.

## Deliverables

1. **Quiet the handled rejection.** `realDeps.runner` in `plugin/bin/lib/compose-subject.js` passes `stdio: ['ignore', 'pipe', 'pipe']`. The captured `err.stderr`, which `isUnknownIssueTypeField` reads, and `err.message`, which the fatal paths print, still carry the text.
2. **`--scope <token>`.** Add an optional `--scope` flag to `compose-subject.js`, covering `parseArgs`, the USAGE/header comment, and threading the value into `composeSubject`. `composeSubject` gains an optional `scope`:
   - output is `type(scope):`, or `type(scope)!:` when breaking
   - the scope is counted inside the 72-character budget
   - a blank or omitted scope stays unscoped
   - anything that isn't a single `[A-Za-z0-9._/-]+` token is rejected with a usage error
3. **`human-approved` tag.**
   - Register the tag in Step 3's tag paragraph in `pr-first-merge.md`, which also tells callers to append `--scope {scope}` when the project convention requires one.
   - Name the tag as close-out's `{tag}` in step 5 of `dispatch/close-out.md`.
   - Document it in `_shared/github-pr-scan.md`'s `triage-queue` item 3 as deliberately excluded from the auto-merged-this-week metric. The metric's `jq` filter itself is unchanged.
4. **Tests.**
   - `tests/bin-lib/compose-subject.test.js`:
     - `--scope` parsing, including a missing value
     - scoped and breaking-scoped output
     - multi-word scope rejected
     - the runner pipes stderr
   - `tests/bin-lib/release/subject.test.js`:
     - the scope prefix stays within the budget
     - a blank scope stays unscoped
     - `a(b)` throws

## Acceptance Criteria

- On a host where `gh issue view --json issueType` is rejected, `compose-subject.js <N> --shell` prints no gh stderr and exits 0 with the GraphQL-resolved type. A genuine fatal gh failure still surfaces its error text through `err.message`.
- `compose-subject.js <N> --scope api` emits `{type}(api): {title} (#N)`. On a breaking record it emits `{type}(api)!: …`. `--scope 'two words'` exits 1 with `scope must be a single token`, and `--scope` with no value is a parse error.
- `composeSubject({..., scope: 'api'})` returns `fix(api): Fix Y (#7)` for a bug titled "Fix Y". A whitespace-only scope returns the unscoped `fix: Fix Y (#7)`. A long title with a scope stays within `SUBJECT_BUDGET`.
- `pr-first-merge.md` Step 3 lists `human-approved` and the `--scope` instruction. `dispatch/close-out.md` step 5 names `{tag}` = `human-approved`. `github-pr-scan.md` states that `[human-approved]` is excluded from the auto-merge count.
- `node --test tests/bin-lib/compose-subject.test.js tests/bin-lib/release/subject.test.js tests/pr-first-merge.test.js tests/merge-subject-composer-conformance.test.js tests/bundle-fixes-reconciliation-2015.test.js` passes. In particular, `pr-first-merge.md` stays at or under `PR_FIRST_BYTE_CEILING`.

## Release Note

Silenced a misleading error printed during merge-subject composition, added optional commit-scope support, and stopped counting human-confirmed close-out merges as auto-merges.

## Technical Approach

All three fixes are additive and local. The stdio change is a one-line fix at the single `runner` seam. Every consumer of the error text already reads the captured `err.stderr`/`err.message`, so piping loses nothing. Scope is threaded as an optional field through the CLI into the pure composer, the same way `tag` and `breaking` already flow. Validation lives in `composeSubject`, so both the CLI and any direct caller get the same rule. For the tag, the alternative was to reuse `fast-lane` or leave it untagged. Reusing `fast-lane` was rejected because it miscounts a human decision as an auto-merge. Leaving it untagged was rejected because it leaves close-out's merge outside Step 3's defined vocabulary. The original request below carries the reporter's complete diff. The reporter checked it live against the patched CLI and saw 74 of 74 passing across the touched suites.

## Gotchas

- `pr-first-merge.md` has only 543 bytes of headroom under `PR_FIRST_BYTE_CEILING`, and the reporter's patch adds about 180. Measure with `wc -c` after the edit. The ceiling is LF-measured, so a CRLF Windows checkout can exceed it locally while CI passes.
- `tests/bundle-fixes-reconciliation-2015.test.js` looks for `{issue-list}` within a 1,500-character window of Step 3. Insert the new prose so it doesn't push `{issue-list}` out of that window.
- Out of scope, noted by the reporter and not fixed here. Either one is a candidate for its own record.
  - `extractSection(body, 'Release Note')` reads up to the next h2, so a record footer after the last section leaks into the merge commit's `Release-Note:` paragraph. `release-notes.js` reads only the first line, so release notes themselves are unaffected.
  - `tidy/actions-github-issues.md`'s `## Arm ready PR` also reaches Step 3 with no defined `{tag}`. It sometimes auto-applies, so it needs its own tag decision, not `human-approved`.
- The scope regex allows `/`, so a nested scope like `ui/forms` is accepted. That is intentional per the reporter's diff. Keep `(` and `)` rejected, because they would break the Conventional-Commits prefix grammar.
