# 2802: Evaluate a jev-skill-suggestion-style skill-loading gate

Surface: infra

**Related:** #2799 (trim skill descriptions per newer-model guidance) — the more directly actionable lever for the same underlying concern (skill-listing context cost), since a plugin controls its own skill descriptions but not Claude Code's own skill-listing mechanism (see Current State).

## Current State

Claude Code lists every installed skill every session, capped at 1% of context — this is platform (harness) behavior, not something a plugin like claude-tweaks controls directly. `jev-skill-suggestion` reportedly gates that listing behind a fast classifier instead, but that would require either a harness-level feature claude-tweaks can't implement itself, or a wrapper/orchestration layer outside the plugin's own scope. What claude-tweaks *can* actually influence is the size and count of its own installed skills' descriptions — the same lever #2799 already targets.

## Deliverables

Investigate what a plugin actually has leverage over here, given Claude Code's skill-listing mechanism is platform behavior:
1. Confirm whether any plugin-level mechanism exists (today, or documented as planned) to conditionally register/hide skills from the per-session listing — if one exists, evaluate whether claude-tweaks' skill count/structure would benefit from using it.
2. If no such mechanism exists, determine whether the more direct lever — reducing description size/count (#2799's scope) and consolidating near-duplicate or rarely-triggered skills — is the actual available answer, and state that explicitly rather than pursuing an unavailable "gate" mechanism.

## Acceptance Criteria

- A concrete answer is recorded to "does Claude Code expose any plugin-level skill-listing gate today" — not assumed either way.
- If no such mechanism exists, this record's outcome explicitly redirects to #2799's already-shaped scope (description trimming) rather than treating the gate idea as still open, so the investigation lands somewhere actionable instead of dead-ending.
- If a mechanism does exist, a follow-up evaluation of whether claude-tweaks' current skill set would benefit is at least scoped (even if not fully executed in this same record).

## Release Note

No user-visible change: evaluated whether the plugin can gate which skills load per project.

## Technical Approach

Research Claude Code's actual documented plugin/skill-loading behavior first — whether any conditional-registration or lazy-listing mechanism is exposed to plugins today. This determines which of the two Deliverable branches applies; the record intentionally doesn't presuppose which.

### Key Files
