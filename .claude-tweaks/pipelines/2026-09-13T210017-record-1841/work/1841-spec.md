# 1841: wrap-up verify: acceptance-labeling check fails on every record-mode run — `gh issue view --json parent` is not a valid field in gh 2.92.0

Surface: infra

## Current State

`plugin/bin/lib/wrap-up/engine-verify.js`'s `resolveParent()` (line 392) resolves a record's decomposition parent with `gh issue view {n} --json parent`. On `gh` 2.92.0 (2026-04-28) that field is not in the command's JSON field list, the call throws `Unknown JSON field: "parent"`, and `resolveParent` returns `{ok: false}` — which the `acceptance-labeling` check folds into a `fail` row, so `wrap-up-engine.js verify` exits 3 and `/claude-tweaks:wrap-up`'s Verify step withholds the closure line (`execution-and-verification.md`'s exit-3 rule) on every record-mode run, even when the record's `demo:*` labeling is correct. On `gh` 2.96.0 (this checkout, 2026-09-09) the same command returns `{"parent": null}`, so the failure is version-dependent: any sandbox or machine still on 2.92.x hits it on every run.

Two things are wrong at once. The field choice is fragile — the plugin's other parent/sub-issue resolution (`bin/lib/issues/native-dependencies.js`, `fetchNativeSubIssues`) goes through GraphQL, which exposes `Issue.parent` on every `gh` version that can run GraphQL at all. And the failure class is misreported — every other gather failure in this file (`git status`, `git worktree list`, `git log`, `gh pr view`, lines 172–326) renders `result: 'unknown'`, which the closure line quotes without blocking, while `resolveParent`'s failure alone is rendered as `fail`, turning a tooling gap into a false labeling verdict.

## Deliverables

- Resolve the parent through GraphQL — `gh api graphql` with `repository(owner,name){ issue(number){ parent { number } } }` — through the same `deps.gh` seam the rest of the file uses, so the test double can drive it; keep the resolution in `resolveParent` (or a sibling in `native-dependencies.js` it delegates to) and drop the `--json parent` call.
- When the parent gather itself fails (GraphQL error, unparseable response), render the `acceptance-labeling` row as `result: 'unknown'` with the gather error in `detail`, matching the file's other could-not-gather rows — never `fail`. A real labeling mismatch on a successfully resolved record stays `fail`.
- Extend `tests/bin-lib/wrap-up/engine-verify.test.js`: a record whose `deps.gh` GraphQL call returns a parent redirects the labeling check to the parent; a null parent takes the non-parent path; a throwing gather renders `unknown` and does not set exit 3.

## Acceptance Criteria

- `resolveParent` no longer invokes `gh issue view … --json parent`; `grep -n "'--json', 'parent'" plugin/bin/lib/wrap-up/engine-verify.js` returns nothing.
- With a `deps.gh` double that throws `Unknown JSON field: "parent"` (or any error) on the parent lookup, `verify` renders `| acceptance-labeling | unknown | … |` and exits 0 when every other check passes; the closure line quotes the unknown row per `execution-and-verification.md`.
- With a double that returns a parent number, the check reads labels/comments from the parent record; with `parent: null`, from the record itself — both covered by tests.
- `npm test` passes.

## Technical Approach

Add a `parentOf(n)` GraphQL query beside `fetchNativeSubIssues` in `native-dependencies.js` (same `runner` seam, same `{owner, repo}` resolution) and have `resolveParent` call it via `deps.gh(['api', 'graphql', '-f', query, '-F', …])`. In the `acceptance-labeling` check (line ~463), branch on `resolved.ok`: false → return `{ result: 'unknown', detail: resolved.error }` before any label read. Keep the existing `{ok, error}` return shape so the check's other callers are untouched. Tests use the file's existing `deps` injection; no live `gh`.

### Key Files

- `plugin/bin/lib/wrap-up/engine-verify.js` — `resolveParent` (GraphQL via `deps.gh`), `acceptance-labeling` check's could-not-gather branch
- `plugin/bin/lib/issues/native-dependencies.js` — optional `parentOf` helper sharing the GraphQL runner seam
- `tests/bin-lib/wrap-up/engine-verify.test.js` — parent-redirect, null-parent, and gather-failure cases
- `plugin/skills/wrap-up/execution-and-verification.md` — only if the `unknown` row's closure-line quoting needs the acceptance-labeling case named explicitly

## Gotchas

- Do not "fix" this by pinning a minimum `gh` version: the field works on 2.96 but the plugin runs in sandboxes that install whatever `gh` the image ships; GraphQL is the version-stable path the plugin already relies on elsewhere.
- `unknown` must stay distinct from `skip` (the file's own comment at line 109); a gather failure is not a deliberately skipped check.
- The `deps.gh` double in `engine-verify.test.js` matches on argv — the GraphQL call's argv shape must be stable enough for the existing matcher style, or add one helper the tests can stub by name.
