# 5580: Design the standard-lane run graph: steps chosen per record by code, and what replaces the ceremony skip roster

Surface: infra

**Related:** #5225, #5232, #5556, #5554, #4031, #4030, #3381, #5292, #5262, #4118
Risk-flags: none

## Current State

A pipeline run takes one of four lanes, and only one of them is a program.

- **Standard lane.** `/claude-tweaks:flow` runs `build`, `test`, `review`, `polish`, `wrap-up`, with `stories` inserted when the build changed UI files (`plugin/skills/flow/steps-and-gates.md`, Allowed Steps). A model walks the steps from skill prose. `/claude-tweaks:dispatch` splits the same list into two calls, `build,test` then `review,polish,wrap-up`.
- **Fast lane.** The same steps under `ceremony-profile: fast-lane`, less the skips in `plugin/skills/_shared/ceremony-profile.md`.
- **Prose express lane.** `plugin/skills/_shared/express-lane.md`: one agent, no `/claude-tweaks:flow` frame.
- **Driver lane.** `plugin/bin/drive.js`. Its run is a fixed list of 19 step objects (`STEPS`, `plugin/bin/lib/driver/steps.js:1288`; names in `STEP_NAMES`, `plugin/bin/lib/driver/events.js:25`) that one loop in `plugin/bin/lib/driver/run.js` runs in order. A step may return `skip`. No function chooses steps from record facts: eligibility and admission (`plugin/bin/lib/express/eligibility.js`, `plugin/bin/lib/driver/admission.js`) decide whether a record enters the lane at all, and the lane's bounds are policy values (`express-driver-max-size`, `express-driver-max-key-files`, `express-driver-max-lines`).

Which steps a standard or fast-lane run takes is decided in several places, none of them one function:

- `/claude-tweaks:specify` stamps a `ceremony:*` label from `assess-agent-autonomy`'s `ceremony-check` mode, a model judgment over the record's text (`docs/decisions/0006-ceremony-tiering-owned-by-specify.md`). `plugin/bin/lib/flow/manifesto-write.js` folds it into the run's `config.yml` as `ceremony-profile`.
- `plugin/bin/lib/dispatch/ceremony-derive.js` (`computeDiffFacts`, `deriveCeremonyProfile`) narrows `standard` to `fast-lane` at wrap-up when the diff touched no implementation file. `plugin/skills/wrap-up/SKILL.md`'s Ceremony escape hatch is the only way back up.
- The roster in `ceremony-profile.md` has 10 skip rows, 11 never-skipped rows and 20 rows of mentions that are not skips. `tests/ceremony-profile-roster.test.js` pins it against every skill file. 36 files under `plugin/skills/` and 7 under `plugin/bin/` name `ceremony-profile`; 17 skill files cite the roster by file name.
- Other selectors sit outside the roster: the `stories` trigger on UI file changes and the `polish` skip on a non-frontend record (`flow/steps-and-gates.md`), the plan-writing skip in `plugin/skills/build/micro-plan.md`, review effort in `plugin/skills/review/review-effort-derivation.md`, `resolve-profile.js --diff-facts`, and `plan-audit.js --count-tasks`, which feeds the single-task skip of the whole-branch review.

The phases code recognises are `PHASES` in `plugin/bin/lib/timing/derive.js:24` (`call-1`, `call-2`, `build`, `plan`, `tasks`, `test`, `review`, `polish`, `wrap-up`, `merge`) and the 12 nested skills in `NESTED_PARENT` in the same file.

The stops no mode may silence are the "HARD-GATE / BLOCKED / STOP conditions" row of `plugin/skills/_shared/auto-mode-contract.md`. Three of them sit inside steps the roster lets the fast lane skip: `/claude-tweaks:review` Step 1 (roster tag `review-step-1`), the plan audit's hard fails (`plan-audit`) and the plan-review spec gap (`plan-review`). So a HARD-GATE today is a stop that fires when its step runs, not a promise that the step runs.

Measured on 2026-11-16 (scratch scripts over one machine's run directories and the open records; re-derive before relying on a number):

- 1,616 closed runs are named `spec-`, `record-` or `drive-`. The 100 most recent closed between 2026-11-03 and 2026-11-15: 92 standard, 3 fast-lane, 3 driver, 1 prose express, 1 with no profile. 72 of the 100 have `timing.json`, 71 with token totals; none of the 3 driver runs has one. None has `step-yield.json`, because #5556 is not built.
- Whole archive, closed runs: 995 standard (300 with `timing.json`), 394 fast-lane (94), 3 driver (0), 1 prose express (1). The 20th most recent fast-lane run closed on 2026-10-31.
- A prose express run and a driver run both write `ceremony-profile: fast-lane` to `config.yml`: `express-lane.js check` prints the value (`plugin/bin/lib/express/cli.js:352`) and both lanes write it. So `config.yml` alone does not tell the three lanes apart. Both also log an `Express lane check:` line in `decisions.md`; only a driver run directory has `driver-events.jsonl`.
- The `timing.json` files of those 100 runs also hold phases outside `PHASES`: `call-3` to `call-6`, `specify`, `visualize` and `dispatch`.
- Of 544 open `ready` records: 385 have no `ceremony:*` label, 411 have no `Surface:` line, 510 have no `Risk-flags:` line, 51 have no Key Files, 5 have no `type:*` label, 3 have no `size:*` and 3 no `risk:*`, and 6 carry `size:small`, which is not one of `low`, `medium`, `high`.
- Task count exists only once a plan exists (`plan-audit.js --count-tasks`), and changed paths only once the build has run (`computeDiffFacts`).

Design: `docs/superpowers/specs/2026-11-15-process-efficiency-design.md`, Phase 7. It extends `docs/superpowers/specs/2026-11-11-pipeline-driver-design.md`; the driver's usage page is `docs/driver.md`. This record is blocked by #5556, which writes the step yield file and `tools/step-yield-report.js`. The driver's Phase 4 (#5221) closed on 2026-11-15 and is not a blocker.

## Deliverables

1. **The design doc.** One new file, `docs/superpowers/specs/YYYY-MM-DD-standard-lane-run-graph-design.md`, dated the day it is written, with the section shape of the two designs named above: Why, Goals, Non-goals, the design itself, phases as `## Phase N` sections, Left to the builder, and Calls made in this document that were not discussed. Status line: `draft for approval`.
2. **Evidence.** Per-step cost against yield, per lane, from the step yield data over at least the 100 most recent closed runs. Every number has the command that produced it beside it.
3. **Step vocabulary.** The closed list of steps a run can take. A vocabulary step is the smallest unit the function may include or leave out on its own; anything that always runs with its parent is part of the parent.
4. **Selection function.** The function from record facts (type, size, risk, surface, changed paths, task count) to the ordered steps a run takes. It selects from the vocabulary and is code. No model writes or edits the graph, because record text is untrusted input.
5. **Assertions.** The steps no record may skip, each as an assertion inside the function, with its reason.
6. **Loops.** Where a step may run again, and the bound on each.
7. **Roster replacement.** What replaces `ceremony-profile.md`'s skip roster, and how a run in flight on the previous plugin release keeps working while both forms exist.
8. **Scope and handoff.** What the doc does not decide, and phases written so `/claude-tweaks:specify` can decompose them. This record does not run `/claude-tweaks:specify` and files no record for a phase.

**Decision rule for any further gap (author, 2026-11-16).** Where this record leaves a choice between readings and no Decision above settles it, the build does not stop for it. It takes the reading that, in this order: keeps a run on the previous plugin release working; puts the rule in code and not in skill prose; stays inside this record's Key Files. It states the choice in the PR body. A criterion that can only be observed after a merge or a release is met by filing one parked measurement record through `/claude-tweaks:capture` that carries the check and its bound.
