# 4287: Windows regression: 1 test file(s) newly failing after ff0fc67ab

## Current State

The post-merge Windows check on ff0fc67ab (run 40197844372) reports one newly failing test, which #4180 added. It is `tests/bin-lib/reconcile/reap-merged.test.js:161`, "#4180 reapMerged: a dry run reports a closed-unmerged skip without appending a worktree-reap-skipped event". The failure is `result.skipped` reasons `['network-failure']` where `['pr-closed-unmerged']` was expected.

The cause is the test's fixture, not the dry-run code. The test feeds the PR state through `installGhWrapper` (`reap-merged.test.js:32`), a `#!/bin/sh` script named `gh` prepended to PATH. On Windows, libuv resolves only `name`, `.com` and `.exe`, so the stub never spawns, the real `gh` runs on the CI runner, and the PR lookup reports `network-failure`. This is the same class #4228 fixed for the #4032 test in this file (PR #4272), by adding the file's `PATH_STUB_SKIP` constant (`reap-merged.test.js:19`) to that test.

Probed at HEAD: the #4180 test at `:161` still has no skip and still calls `installGhWrapper`. `reapMerged` already takes an injected `prStates` resolver (`plugin/bin/lib/reconcile/reap-merged.js:199`, used at `:231` in place of `resolvePrState`), and the #4032 test (`reap-merged.test.js:878`) builds one with `createPrStateResolver({ root, deps: { byBranch } })`, which spawns nothing.

The older stub-based tests in this file (`:100`, `:122`, `:140` and others) also fail on Windows. They are pre-existing failures that #4285 tracks for the shared `tests/helpers/path-stub.js` migration. #4285's failing-test list predates #4180 and does not name this test.

## Technical Approach

Mirror the subject half of the #4032 test (`reap-merged.test.js:878-905`): build the fixture, construct `createPrStateResolver({ root, deps: { byBranch: () => closedState } })`, and call `reapMerged({ cwd: root, dryRun: true, prStates })`. Injection beats the `PATH_STUB_SKIP` precedent from #4228 here, because a skip would drop the only dry-run coverage on Windows, while injection keeps it on every platform and needs no PATH change.
