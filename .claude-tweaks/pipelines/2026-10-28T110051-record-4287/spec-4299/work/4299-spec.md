# 4299: Windows regression: 1 test file(s) newly failing after 8e864ba5f

Surface: infra

**Related:** #4178, #4266, #4289, #4385, #3900, #3064, #4222, #4271, #4287, #4301, #4388, #3982, #3995

Origin: windows-regression.yml post-merge check on 8e864ba5f (PR #4266, #4178)

## Current State

The post-merge Windows check on 8e864ba5f (run 40199892803) attributes one new failure in `tests/hooks-git-exec.test.js`: "runGit: opts.env is the spawn environment — a pinned env restores -C repo discovery (#4178)" (`:335` at HEAD). The failure reads "opts.env must reach the child", with actual `D:/a/_temp/…/ct-wtd-GNAJZ6/.git` and expected `D:\a\_temp\…\ct-wtd-GNAJZ6\.git`.

The cause is the test's expectation. Git for Windows prints `rev-parse --absolute-git-dir` with forward slashes, and the test builds the expected value with `fs.realpathSync(path.join(b, '.git'))`, which is backslashed on win32. Both assertions in the test (`:339`, `:341`) have this shape. `runGit` itself is correct: the redirected and pinned answers name the right repos and differ only in separator spelling.

Probed at HEAD: the async twin "runGitAsync: opts.env is the spawn environment, same as runGit (#3900)" (`:344`, assertions `:349`, `:351`) was added after 8e864ba5f with the identical shape. #4385 reports it newly failing on Windows at 456134058. The same artifact's isolated log (`verify-logs/tests-isolated-tests+hooks-git-exec.test.js.log`) shows three other failures in this file, tests 1, 10 and 17 (`:18`, `:119`, `:273` at HEAD, the `--show-toplevel` comparisons). Those are pre-existing and owned by #4289, which names them at their 988cc584d lines `:13`, `:114` and `:264`.

## Deliverables

1. In both opts.env tests (`:335` #4178 and `:344` #3900), derive each expected git dir from git's own output rather than from `path.join`. Run `git -C <repo> rev-parse --absolute-git-dir` under `repoPinnedEnv()` in the test, which is the #4289/#4222 technique, with no `process.platform` branch.
2. Leave the three `--show-toplevel` tests to #4289.

## Acceptance Criteria

- Both opts.env tests pass under `node --test tests/hooks-git-exec.test.js` on macOS/Linux, with the same test count.
- Discrimination is kept. Each test still fails on Linux when `runGit`/`runGitAsync` ignores `opts.env`, for example by reverting the `env` pass-through in `plugin/bin/lib/hooks/git-exec.js` (`:147`, `:182`) locally, and when `repoPinnedEnv` keeps `GIT_DIR`.
- A `windows-regression.yml` dispatch on the branch shows neither opts.env test failing and no newly failing test in `hooks-git-exec.test.js` versus its base.
- `npm test` passes.

## Release Note

No user-visible change: fixes Windows-only test failures where git prints forward-slash paths.

## Technical Approach

Add one small helper in the test file, for example `gitDirOf(repo)`, that returns `fixtureGit(['-C', repo, 'rev-parse', '--absolute-git-dir'], { encoding: 'utf8', env: repoPinnedEnv() }).trim()`. `fixtureGit` returns a Buffer without `encoding` (`tests/helpers/git-fixtures.js:46-48`), and the pinned env keeps an inherited `GIT_DIR` from redirecting it. Use it for the four expected values. Git's own spelling is the correct value under the #3064 calibration, so the expectation should match it rather than normalizing both sides.

### Key Files

- `tests/hooks-git-exec.test.js` — the #4178 and #3900 opts.env tests
- `tests/helpers/git-fixtures.js` — reference only (`fixtureGit`, `gitRepo`)
- `plugin/bin/lib/hooks/git-exec.js` — reference only (`runGit`, `runGitAsync`, `repoPinnedEnv`)

## Gotchas

- #4289 (ready) edits the same file for the three `--show-toplevel` tests with the same technique. Whichever builds first should land a shared expected-value helper the other reuses, and the second rebases onto it. Never both define a helper.
- #4385's `hooks-git-exec.test.js` half (the #3900 async test) is covered by Deliverable 1 here. #4385's builder should take only its `hooks-policy-exemption.test.js` half, or close that half as fixed by this record.
- The expected-value helper must not inherit the test's foreign `GIT_DIR`. A `fixtureGit` that passes `process.env` through while the test has `GIT_DIR` set would derive the wrong repo and make the assertion pass for the wrong reason. The discrimination check in the Acceptance Criteria catches this.
- Windows proof needs a real `windows-regression.yml` dispatch after the last code change. Linux cannot show the separator difference.
