# 4303: Write gate misses writes after a conditional or pipelined cd, an assignment-prefixed cd, bundled -t/-0pi flags, a >& target, and an & in arithmetic parens

Verified-as-of: 5871d691bb6dd6a1ae363d1e3a1a7c4e1953264d

Origin: Review Console residue of #4149 (run 2026-10-24T163054-spec-4149), triaged 2026-10-25

Defer-reason: genuinely-larger

## Current State

`plugin/bin/lib/hooks/git-command.js`'s write gate (`fileWriteTargets`, `gitTargets`, both over `forEachShellSegment`) places these writes somewhere other than where bash writes them. From a worktree of a `worktree-always` repo, a write into the main checkout is therefore allowed. Each shape was run in a scratch tree against main's scanner and real bash 3.2 and 5 (M = a main-checkout dir, T/Q = other dirs, wt = the worktree):

| # | Shape | Scanner | Bash |
|---|---|---|---|
| U1 | `cd M \|\| cd T; echo x > f` | `T/f` | `M/f` |
| U1 | `cd nope && cd T; echo x > f` | `T/f` | `./f` |
| U1 | `cd M \| true; echo x > f` (a pipeline element is a subshell) | `M/f` | `./f` |
| U2 | `x=$(cd Q) cd M; echo hi \| tee f` | `./f` | `M/f` |
| U3 | `cp -rt M src`, `mv -vt M a`, `install -Dt M f` (GNU) | last positional | into `M` |
| U4 | `perl -0pi -e 's/a/b/' M/f` | nothing | `M/f` |
| U6 | `echo x >& M/f` / `echo x >&M/f` | `wt/&` / `wt/&M/f` | `M/f` |
| S49 | `x=$(true; cd M && y=$(( (1 & 3) )) && git commit -am x)` | commit in `wt` | commit in `M` |
| S50 | 15 `{ cd /tmp/aN; }` groups, `{ cd M/s0/deep; }`, then `cp a ../f.js` (sibling-layout worktree) | `wt/../f.js` | `M/s0/f.js` |

Causes:
- U1: a `cd` is applied unconditionally, ignoring `&&`/`||` and pipeline subshells.
- U2: `visitSegment`'s `cdLead` stops at the split `x=$(cd` / `Q)` tokens.
- U3: `explicitTargetDir` matches only a standalone `-t` / `--target-directory`.
- U4: `hasInPlaceFlag`'s bundled-cluster test is `/^-[A-Za-z]+$/`, so a digit hides `-i`.
- U6: the csh-style `>& file` is read as `>` with an `&…` target; `isFdDupTarget` excludes only `&digits`.
- S49 (#4149 ledger row 50): `groupEvents` treats an `&` as arithmetic only when `top()` is a `$((` frame, so a bare `(` inside `$(( ))` or `$[ ]` makes it a background.
- S50 (#4149 ledger row 51): past `CWD_SET_CAP`, `joinCwds` returns `[overflow, start]` and drops the triggering group's own cwd.

Fail-closed or test-only items from the same review:
- U14: `(( a>1 || b>2 ))` gives spurious targets `1` and `2`; `segmentSpans` cuts the arithmetic at `||` before the group walk.
- S51 (#4149 ledger row 52): ``cd M && x=`true | true & true` && echo x > f.js`` resolves `M/f.js` correctly, but no test pins the `|| span.sub` arm of the background route.
- U13: the heredoc nesting cap (`MAX_HEREDOC_NESTING`) has no test.
- U9: `{ timeout: 10000 }` on the synchronous cap tests in `tests/hooks-gate-coverage.test.js` does nothing, so a cap regression into a loop hangs `npm test` instead of failing it.

## Deliverables

- Fix U1, U2, U3, U4, U6, S49 and S50 so the scanner reports the path bash writes. Where the cwd depends on runtime success (U1), fail closed by keeping every possible cwd.
- Make `segmentSpans` arithmetic-aware, so U14 resolves no target.
- Add a pin for S51's background arm and a test for the heredoc nesting cap (U13).
- Make the U9 bound effective (an async test or an in-test step bound), or remove it.
- Pin every case in `tests/hooks-gate-coverage.test.js` with its bash 3.2 and 5 verdict in the comment, using `.claude/skills/shell-scanner-bash-differential`.
- Update `plugin/skills/_shared/policy-schema-coverage.md`'s coverage block for any shape whose verdict changes.

## Release Note

The worktree-always guard now blocks writes into the main checkout that follow a conditional or piped cd, an assignment-prefixed cd, a bundled -t or perl -0pi flag, or a >& redirect.
