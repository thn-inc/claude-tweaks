# 3136: Singleton /flow runs have no deferred-closure mechanism for the PR Fixes block (unlike bundle runs)

Origin: review light from #1350

Defer-reason: tangential

## Current State

`_shared/pr-early-run-lifecycle.md`'s "Deferred-closure decisions (#2686)" section lets a bundle
run (multi-spec, with a parent `manifest.yml`) rewrite a spec's PR `Fixes #{n}` line to
`Refs #{n} — deferred: {reason}` when that spec's own closing keyword must be withheld (e.g. its
acceptance criterion remains unmet). That file states explicitly: "A single-record run never
writes or checks this line: there is no bundle `manifest.yml` for a single-record run to rewrite
against, so the one `Fixes #{n}` line it composes here at Step 3 stays unconditional, exactly as
before."

This leaves singleton runs with no mechanism to express the same decision. Record #1350 is a
standing watch-item whose acceptance criterion depends on an external event; the
`2026-10-14T122157-record-1350` run (PR #3135) built nothing that resolves the AC and documented
"still blocked" — yet the PR's `Fixes #1350` line was composed unconditionally at run start, and
nothing in the pipeline would have corrected it before a merge, which would have wrongly
auto-closed #1350 via GitHub's closing-keyword scan despite the AC remaining unmet. (Caught and
hand-corrected to `Refs #1350` during that run's own review step, the same way the 2026-10-12
sibling attempt — PR #3127, also a singleton run — had evidently hand-corrected its own body the
same way, ad hoc, since the shipped composer's documented behavior for singleton runs is
unconditional `Fixes`.)

## Deliverables

Extend the deferred-closure mechanism (`_shared/pr-early-run-lifecycle.md` /
`_shared/pr-checklist-refresh.md`'s "Rewrite the `Fixes` block from `manifest.yml` outcomes" step)
to cover singleton runs — e.g. by reading the same
`deferred-closure: spec #{n} closing keyword withheld ({reason})` line from the run's own
top-level `decisions.md` (rather than requiring a bundle `manifest.yml`) when no manifest exists,
so a build/review/wrap-up step that determines an AC remains unmet can log that same entry shape
and have the PR-checklist refresh step rewrite that one `Fixes #{n}` line to
`Refs #{n} — deferred: {reason}` before any merge is attempted.

## Acceptance Criteria

A singleton `/flow` run whose build or review step logs a `deferred-closure` decision for its own
record has its PR's `Fixes #{n}` line rewritten to `Refs #{n} — deferred: {reason}` at the next
phase-checklist refresh, the same way a bundle run's manifest-driven rewrite already works —
verified by a test exercising `readDeferredClosures`'s (or an equivalent single-record) read path
and `composeFixesBlock`'s output for a manifest-less run.

## Release Note

No user-visible change: closes a gap where a singleton watch-item run's PR could auto-close its
own issue on merge despite the acceptance criterion remaining unmet.
