## Current State

When a retry run adopts a worktree whose branch already exists on `origin`, `build/adopted-branch-collision-check.md` asks `findPriorAttemptPr` (`plugin/bin/lib/worktree/remote-branch-collision.js:150-167`) whether the foreign remote tip is this record's own failed earlier attempt. On a match (state `prior-attempt`), the build runs `git merge --no-edit {remoteSha}` and `_shared/pr-early-run-lifecycle.md` Step 1 reopens and rebinds that PR. It never stops.

Today a PR qualifies as an earlier attempt when all of the following hold:

- it is CLOSED;
- it comes from the same repository (`isCrossRepository === false`);
- its body's first line carries the `claude-tweaks-run:` marker;
- it closes one of the run's records (`prClosesIssue === true`);
- its head is an ancestor of origin's tip.

None of those checks tells a dispatch failure tombstone apart from a PR a human closed to reject the approach. Both are closed, run-marked, same-repo PRs that close the record, and on this repo both closes come from the same OWNER account. The next retry silently adopts the rejected branch, merges any commits pushed after the close, reopens the PR, and builds on top of the work the human turned down. Review lens `3b` reported this at line 163 (run `2026-10-21T215830-record-3887`), and the tiebreak confirmed it on `e71e18563`. It still holds on `origin/main` as of 2026-10-26.

The legitimate prior-attempt shape comes from exactly one producer, `dispatch/settle-and-merge.md` Step 6 step 5. In that one settle step it:

1. posts a fresh `Attempt {N} failed: …` comment on the **issue** (`attemptFailedCommentBody`, `plugin/bin/lib/issues/retry.js`; matched by `countFailedAttempts`'s `ATTEMPT_RE`);
2. find-or-creates a `<!-- run-comment: failure -->` pointer comment on the PR;
3. runs `gh pr close`.

A human rejection close has no fresh `Attempt N failed` issue comment immediately before it.

## Deliverables

- [ ] `findPriorAttemptPr` requires failure-tombstone evidence before a PR qualifies. The record's issue must carry a trusted (`isTrustedComment`, `plugin/bin/lib/issues/comment-trust.js`) `Attempt {N} failed` comment created no more than `TOMBSTONE_CLOSE_WINDOW_MS` before the PR's `closedAt`, and not after it. A PR without that evidence stays `foreign`, so the build falls through to item 4's stop card and a human decides.
- [ ] `findPrsForBranch` fetches `closedAt` for each PR. The evidence lookup reads the record issue's comments, at most once per record per check. A failed or partial lookup yields no match: the branch stays `foreign`, which fails closed, as every other doubt in this function already does.
- [ ] `build/adopted-branch-collision-check.md`'s item 5 prose and its embedded snippet are updated to state the new condition. They keep naming dispatch's failure path as the only producer of the `prior-attempt` shape.
- [ ] Tests in `tests/bin-lib/worktree/remote-branch-collision.test.js` cover four cases:
  - a tombstone PR (attempt comment just before `closedAt`) still matches;
  - a PR with no attempt comment stays foreign;
  - a PR whose only attempt comment is older than the window stays foreign. This is the stale-marker case: an earlier failure, then a retry that reopened the PR, then a human closed it;
  - a failed issue-comment lookup stays foreign.

The adopted-branch check then reports `foreign` with the stop card.
- [ ] The tombstone shape that `dispatch/settle-and-merge.md` Step 6 step 5 leaves still returns `{ number, url }`, so a dispatch retry still adopts its own failed attempt with no stop.
- [ ] An `Attempt N failed` comment from an untrusted author (`authorAssociation` not OWNER/MEMBER/COLLABORATOR) never counts as evidence.
- [ ] Each of the four new test cases fails when the evidence check is removed from `findPriorAttemptPr`, and the suites `tests/bin-lib/worktree/remote-branch-collision.test.js`, `tests/adopted-branch-collision-snippet-fixture.test.js` and `tests/adopted-branch-collision-prose-conformance.test.js` pass.
- Plan-review decision (Reading A): when a branch carries several closed PRs, only the newest closed PR is judged. A newest PR with no in-window evidence comment makes `findPriorAttemptPr` return `null` even when an older PR on the same branch is a genuine tombstone, so rejected commits are never adopted. A fixture covers that shape: newest PR human-closed, older PR tombstoned. Plan Review Focus 4 and its test follow this reading.
- Plan-review decision, round 2 (Reading B): a same-repo non-closed PR on the branch (OPEN, draft or MERGED) that is newer than the newest closed PR blocks adoption: `findPriorAttemptPr` returns `null` (`foreign`, stop card), so live or merged work is never merged into a retry. A fixture covers each non-closed state (open, draft, merged) newer than a closed tombstone.

## Release Note

Stop a dispatch retry from adopting the branch of a pull request you closed yourself — it now stops and asks instead of building on rejected work.

## Technical Approach

Add the tombstone check inside `findPriorAttemptPr`'s loop, after the existing `prClosesIssue` and ancestry checks. Each candidate PR needs its `closedAt`, which comes from the same `gh pr list` call as long as `findPrsForBranch` asks for it. It also needs the comments of the record the PR closes. Inject an issue-comment reader alongside `git`, the way `gh` is injected today, so tests stay hermetic, and read through `gh issue view {n} --json comments` or `gh api`. Evidence is an `ATTEMPT_RE` match (export it from `retry.js` instead of copying the regex) on a comment that `isTrustedComment` accepts and whose `createdAt` falls in `[closedAt - TOMBSTONE_CLOSE_WINDOW_MS, closedAt]`.

The window value is the builder's call. Settle posts the issue comment, then the PR pointer, then closes, all in one step, so a few minutes is ample. 15 minutes is a reasonable default. Make it an exported module constant, not a policy key.

### Key Files

- `plugin/bin/lib/worktree/remote-branch-collision.js` — `findPriorAttemptPr` gains the tombstone-evidence check and an injected comment reader; `findPrsForBranch` adds `closedAt` to its `--json` fields
- `plugin/bin/lib/issues/retry.js` — export `ATTEMPT_RE` for reuse
- `plugin/bin/lib/issues/comment-trust.js` — read only (`isTrustedComment`)
- `plugin/skills/build/adopted-branch-collision-check.md` — item 5 prose and the snippet state the new condition
- `plugin/skills/dispatch/settle-and-merge.md` — read only, the producer whose Step 6 step 5 order the window relies on
- `tests/bin-lib/worktree/remote-branch-collision.test.js` — the four new cases
- `tests/adopted-branch-collision-snippet-fixture.test.js` — keep green against the updated snippet
- `tests/adopted-branch-collision-prose-conformance.test.js` — keep green against the updated item 5 prose

## Gotchas

- Post-close commits stay adoptable on a genuine tombstone (my call). The ancestry check (head is an ancestor of origin's tip, not equal to it) was a deliberate choice in #3887 (Review Focus 1). Once a human-closed PR no longer qualifies, the only commits merged are ones pushed to a dispatch-tombstoned branch, which is someone contributing to the retry, not rejected work.
- Older tombstones from before #1963 put attempt comments only on the PR, not on the issue, so they no longer qualify and stop with the `foreign` card. That is the intended fail-closed direction. Don't widen the evidence to PR comments to rescue them, because the PR's `run-comment: failure` pointer is updated in place and its timestamp is not reliable.
- With `gh` absent there is already no PR lookup (item 5 notes this; #3915 tracks an MCP-fed one), so nothing changes there.
- Author association does not tell bot and human apart on this repo, since both act as OWNER. Timing against the fresh attempt comment is the discriminator, and the trust check only stops a third party from planting one.
