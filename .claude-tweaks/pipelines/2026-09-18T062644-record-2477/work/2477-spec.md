# 2477: wrap-up verify: acceptance-labeling check doesn't recognize the Oversight-floor gate's legitimate demo:pending skip

Surface: backend

Origin: wrap-up for #2428
Defer-reason: pre-existing-outside-diff

## Current State

`bin/lib/wrap-up/engine-verify.js`'s `acceptance-labeling` check (registered around line 467)
unconditionally requires a resolved issue to carry `demo:pending` once it has a resolvable
carrier commit — `if (!labels.some((l) => l.name === 'demo:pending')) { failing.push(...'missing
demo:pending label'); }` — with no awareness of `verification-brief.md`'s Oversight-floor gate
(`#367`, `exceedsOversightFloor` in `bin/lib/issues/oversight-floor.js`). That gate deliberately
skips Steps 1-4 (no `demo:pending` bootstrap at all) whenever a record's `risk:*`/`size:*` facets
don't clear the project's `risk-floor`/`size-floor` policy — a documented, intentional "not
required" outcome, not a defect (`verification-brief.md`'s Oversight-floor gate section: "The
record closes with no `demo:*` label and no ceremony... It stays demoable later on request").

Reproduced during `/claude-tweaks:wrap-up`'s Phase 4 verify step for #2428 (`risk:medium`,
`size:medium` against a project's `risk-floor: high`/`size-floor: high` — `exceedsOversightFloor`
correctly returned `{exceeds: false}`, Steps 1-4 correctly skipped, no `demo:pending` applied).
The `acceptance-labeling` check then reported `fail — #2428: missing demo:pending label`,
forcing wrap-up to exit code 3 (`On exit code 3, do NOT emit the closure line: surface BLOCKED`)
for a record that did nothing wrong.

## Deliverables

- Give `acceptance-labeling` a way to recognize a legitimate Oversight-floor skip and render
  `skip (below oversight floor -- demo:pending not required)` instead of `fail` for that case,
  without weakening the check for a record that genuinely should carry the label but doesn't.
- Likely shape: re-run (or read a cached result of) `exceedsOversightFloor` against the same
  `risk-floor`/`size-floor` policy values `verification-brief.md` used, keyed off the resolved
  issue's own `risk:*`/`size:*` facets — mirroring the same computation, not inventing a new
  signal. Consider whether this belongs in `engine-verify.js` directly or as a new
  `verify-expectations.json` field the Oversight-floor gate writes at skip time (parallel to how
  `MULTISPEC_REVIEW_DEFER`'s `deferred` array already tells other `verify` checks about a
  legitimate skip) -- the latter avoids a second live `gh`/policy read inside `verify` and keeps
  the "why" attached to the moment the skip decision was actually made.

## Acceptance Criteria

- A record whose Oversight-floor gate resolved `exceeds: false` (no `demo:pending` applied by
  design) passes `wrap-up-engine.js verify`'s `acceptance-labeling` check with a `skip` result,
  not a `fail`.
- A record that should carry `demo:pending` (oversight floor cleared) but doesn't still fails the
  check exactly as today -- no coverage regression.
- A `node --test` case pins both branches.

## Technical Approach

Prefer the `verify-expectations.json` field approach over a second live read inside `verify`: have `verification-brief.md`'s Oversight-floor gate write a flag (e.g. `oversightFloorSkip: true`) into `verify-expectations.json` at the moment it decides to skip Steps 1-4, the same way `MULTISPEC_REVIEW_DEFER`'s `deferred` array already communicates a legitimate skip to other `verify` checks. Then `acceptance-labeling` in `engine-verify.js` reads that flag before failing on a missing `demo:pending` label — present and true means `skip (below oversight floor -- demo:pending not required)`; absent means the check runs exactly as it does today.

### Key Files

- `plugin/bin/lib/wrap-up/engine-verify.js` — the `acceptance-labeling` check (~line 467)
- `plugin/skills/wrap-up/verification-brief.md` — the Oversight-floor gate that decides the skip
- `plugin/bin/lib/issues/oversight-floor.js` — `exceedsOversightFloor`, read (not changed) by both sides
- `tests/bin-lib/wrap-up/engine-verify.test.js` — add both branches (skip vs. genuine fail) as pinned cases

## Gotchas

- Don't weaken the check itself — a record that genuinely should carry `demo:pending` but doesn't must still fail exactly as today; only the oversight-floor-skip case gets the new `skip` outcome.
