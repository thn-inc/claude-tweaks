# 3417: Shared path-guard helper — lstat type check, fail-closed leaf symlink, case-canonical realpath; route plugin/bin readers through it

## Current State

Path-guard discipline is a written rule with no mechanical home. `docs/donts.md` carries [IL-150] (resolve a leaf symlink, fail closed on an unprovable leaf) and [IL-161] (an existence check is not a type check — lstat first). IL-161's own removal condition names the fix: "a shared lstat-backed helper new filesystem-check code is required to route through". No such helper exists and no record tracks it.

Multi-spec run 2026-10-17T144508-spec-3375-3380 broke the rule three more times in two new readers, each caught only at review:

- #3375 `plugin/bin/lib/timing/transcript.js`: a symlinked `subagents/` directory was realpathed and read (ledger row 20, fixed in 759b89a29), and an lstat failure fell through to the symlink-following read path, which fails open (row 24, fixed in 4cb8e74ac).
- #3380 `plugin/bin/lib/superpowers-version.js` / `installed-plugins.js`: the home exclusion and the ancestor match compared `fs.realpathSync` output, which echoes input casing, so a mis-cased path on a case-insensitive volume slipped past the guard (row 48, fixed in 722ece0d6 by switching to `fs.realpathSync.native`).

Each reader hand-rolls its own lstat / realpath / containment logic: `transcript.js` locateTranscripts and readDispatches, `installed-plugins.js` safeRealpath, and `realTarget()` inside `plugin/bin/lib/hooks/pre-tool-use.js`. Nothing lets a new reader reuse the hardened form.

## Deliverables

- A shared module under `plugin/bin/lib/` (a flat sibling directory, per CLAUDE.md's structure note) that exposes the hardened primitives:
  - an lstat-backed type check (file / directory / symlink / missing);
  - leaf-symlink resolution that fails closed on a dangling or unreadable leaf;
  - a case-canonical realpath (`fs.realpathSync.native`);
  - an ancestor-or-self containment test built on those three.

- `transcript.js`, `installed-plugins.js` and `pre-tool-use.js`'s `realTarget()` routed through it, with no behavior change. Their existing tests stay green unmodified.

- A conformance test or lint over `plugin/bin/**/*.js` that flags a new bare `fs.realpathSync(` / `existsSync`-as-type-check call outside the shared module, with an explicit allowlist for each existing caller that is judged safe.

- [IL-150] and [IL-161] updated to point at the helper, and their removal conditions applied (retire or narrow them).

## Acceptance Criteria

- [ ] Each primitive has unit tests for the symlinked-leaf, dangling-leaf, lstat-failure and mis-cased-path inputs. Each test is shown red against a naive `fs.realpathSync` / `existsSync` stand-in.

- [ ] All three named call sites import the shared module, and `npm test` passes with their existing suites unchanged.

- [ ] The lint/conformance test fails when a fixture adds a bare `fs.realpathSync(` call in a new `plugin/bin/lib/` file, and passes on the current tree.

- [ ] `docs/donts.md`'s [IL-150]/[IL-161] lines name the helper, and `docs/incident-log.md` records which removal condition was met.
