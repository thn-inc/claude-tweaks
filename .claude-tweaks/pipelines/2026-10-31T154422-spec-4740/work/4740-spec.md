## Current State

`plugin/skills/wrap-up/cleanup-procedures-execution.md` Section C step 2 (the closing-keyword carrier commit) falls back, when `wrap-up-pack.json` is missing or carries no `inputs.closingRecords` array, to:

```bash
for f in "${MIRROR}"/work/*-spec.md; do
  [ -e "$f" ] || continue
  ...
done
```

The block runs through the Bash tool, whose shell on this repo's macOS host is zsh. Under zsh's default `NOMATCH` option an unmatched glob aborts the script with `no matches found: …/work/*-spec.md` (exit 1) before the `[ -e "$f" ] || continue` guard runs; bash loops zero times and exits 0 (reproduced with `zsh -f` during #4107's final review). The outcome — no carrier commit — is still correct, but the prose right after the block says this case "is a no-op", and an agent reading a loud exit-1 can misreport it. `tests/wrap-up-closing-records-array-fill.test.js` (added by #4107) exercises only the pack branch, so nothing pins the fallback.

## Deliverables

- [ ] Replace the fallback glob loop with a form that behaves the same in bash and zsh when nothing matches — for example a `node -e` that lists `{mirror}/work/*-spec.md` headers' `record:` values one per line, filled with the same `while IFS= read -r` loop the pack branch uses.
- [ ] Add fallback-branch cases to `tests/wrap-up-closing-records-array-fill.test.js`: no matching spec files → count=0 and exit 0 under bash and `zsh -f`; two spec files → two elements.

## Acceptance Criteria

1. With no pack file and an empty mirror `work/` directory, the extracted Section C step 2 block exits 0 with `count=0` under both bash and `zsh -f`.
2. With no pack file and two mirror spec files carrying `record: 101` / `record: 202`, the block yields two elements under both shells.
3. The pack branch's behavior and pins from #4107 are unchanged.
4. `npm test` passes.
