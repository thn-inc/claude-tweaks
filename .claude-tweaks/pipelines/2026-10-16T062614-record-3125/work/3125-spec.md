# 3125: Skill drift: node-test-output-evidence — Key Patterns

**Skill:** node-test-output-evidence | **Section:** Key Patterns | **Category:** drift | **Classification:** restructural | **Confidence:** high

Verified-as-of: f062f6938b2f1b50de9ed00c78dae26a061c196a

## Current State

Also affects: `Decision Framework`

plugin/bin/lib/verify/baseline.js lines 223-230 explicitly tolerate cancelled > 0 in the full run's accounting (`entries !== counts.fail + cancelled`), and the code comment there states "A cancelled HEAD test is then held to the usual evidence: it fails at base, or shows its own pass in isolation" — contradicting the skill's claim that a full run with a cancelled test is never adjudicated and a pass is never reached. The zero-cancelled rule the skill describes belongs to accountedFamily (used only for each isolated single-file rerun, lines 157-164 and its call sites at ~280/326/343), not the full-run extraction this subsection and Decision Framework row describe.

## Deliverables

**Current:**
```
An extracted list of failures cannot report that it missed one. `adjudicate` refuses to classify unless:

- the spec `test at` entries (`specEntryCount`) add up to the summary's `ℹ fail N`;
- every failing entry or TAP `not ok` block names a test file (`countUnmatchedFailures` returns 0);
- the summary counts parse at all, because a truncated log has none;
- `ℹ cancelled` (spec) or `# cancelled` (TAP) reads 0 in a single-file log.

The listing and `ℹ fail` do not count the same things. A cancelled test, for example one that timed out, is listed but not counted, so a full run containing one is never adjudicated. That outcome is fail-closed, and a pass is never reached. A diagnostic that says the test timed out or was cancelled (`INCONCLUSIVE_RE`) means the test did not finish, which proves nothing about whether it fails.
```

**Proposed:**
```
An extracted list of failures cannot report that it missed one. `adjudicate` refuses to classify the full run unless:

- the spec `test at` entries (`specEntryCount`) add up to the summary's `ℹ fail N` plus its `ℹ cancelled` count;
- every failing entry or TAP `not ok` block names a test file (`countUnmatchedFailures` returns 0);
- the summary counts parse at all, because a truncated log has none.

The listing and `ℹ fail` do not count the same things — a cancelled test, for example one that timed out, is listed but not counted, so the full run's entries must reconcile against `ℹ fail` plus `ℹ cancelled`, not `ℹ fail` alone. A cancelled test does not by itself block adjudication of the full run: it is held to the usual per-file evidence (it fails at base, or shows its own pass in isolation). Only that isolated single-file rerun must itself show `ℹ cancelled`/`# cancelled` at 0 (`accountedFamily`) to count as evidence — a rerun that times out or cancels proves nothing and that file stays unclassified. A diagnostic that says the test timed out or was cancelled (`INCONCLUSIVE_RE`) means the test did not finish, which proves nothing about whether it fails.
```

## Acceptance Criteria

The "Reconcile the failing list against an independent count" subsection and the Decision Framework's cancelled-count row both state that a non-zero cancelled count blocks adjudication of the full run and that "a pass is never reached" — plugin/bin/lib/verify/baseline.js's adjudicate() (lines 223-230) actually tolerates a non-zero ℹ cancelled count in the full run, requiring only that entries equal fail + cancelled, then routes the cancelled test's file through the same per-file isolated-rerun evidence as any other failure (ranCleanly/baselineInIsolation, lines ~319-356), which CAN return verdict: 'pass'. The zero-cancelled requirement (accountedFamily, cancelledCount(text, family) !== 0) applies only to each isolated single-file rerun log, not to the full run's own extraction/eligibility check. Fix both the Key Patterns subsection (oldString/newString above) and the Decision Framework row ("A non-zero cancelled count, a timeout diagnostic, or a runner-level `ℹ Error:` | Did not finish, or failed outside any test. No evidence") to the same corrected distinction: a non-zero cancelled count in the full run does not by itself mean no evidence; it only does for an isolated single-file rerun.
