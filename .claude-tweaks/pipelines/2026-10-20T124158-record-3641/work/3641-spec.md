# 3641: friction-events.js reads decisions.md local-time claim stamp as UTC, dropping every event in a non-UTC timezone

Origin: reflect full from #3498

Defer-reason: tangential

## Current State

`plugin/bin/friction-events.js` returns `[]` for a run that logged real friction, whenever the operator's timezone is ahead of UTC. `computeClaimBoundary(runDir)` reads the first `decisions.md` entry's `HH:MM:SS` and builds a `Date` from the string `{mintDay}T{HH:MM:SS}Z`, i.e. it parses that time as UTC. `plugin/bin/lib/log-decision/append.js` writes it with `getHours()/getMinutes()/getSeconds()`, i.e. in local time. `events.jsonl` timestamps are UTC (`toISOString`). On a CEST host the claim line `20:59:10` becomes `20:59:10Z`, two hours after the real claim (`18:59:10Z`), so every event the run logged before then is dropped as "pre-claim noise" (#2989).

Observed in the #3498 run (2026-10-19, CEST): `events.jsonl` held 12 `wd-guard-refusal` events (11 of them after the real claim), and `node plugin/bin/friction-events.js --run <run-dir>` printed `[]`. `/claude-tweaks:reflect`'s Friction lens treats `[]` as "consistent with a frictionless run", so the lens had no evidence to judge. The mirror case (a host behind UTC) lets pre-claim noise through instead, which is the failure #2989 fixed.

## Deliverables

- [ ] Make `computeClaimBoundary` interpret `decisions.md`'s clock time in the same zone `log-decision/append.js` wrote it in, or have `append.js` persist an unambiguous instant the reader can parse without guessing (expand-contract: keep reading the existing `HH:MM:SS` form for runs already on disk).

- [ ] Add a regression test that runs with a non-UTC `TZ` (e.g. `TZ=Europe/Copenhagen` and `TZ=America/Los_Angeles`) and asserts a post-claim event survives and a pre-claim event is dropped.

## Acceptance Criteria

- [ ] With `TZ=Europe/Copenhagen`, a run dir whose `decisions.md` first entry is stamped by `log-decision.js` and whose `events.jsonl` holds a later `wd-guard-refusal` returns that event from `friction-events.js`.

- [ ] With `TZ=America/Los_Angeles`, an event timestamped before the claim is still excluded.

- [ ] The new test fails on the pre-fix `computeClaimBoundary` (verified by reverting the fix).

## Release Note

Fixed: the reflect Friction lens no longer reports a frictionless run when the machine's timezone is ahead of UTC.
