# 3314: git-command: empty -C and omitted -C resolve to different targets on Windows

Origin: wrap-up leftover from #2767

Defer-reason: pre-existing-outside-diff

**Related:** #3315 #3317 #3318

## Current State

`plugin/bin/lib/hooks/git-command.js`'s `skipGlobalFlags` resolves a `-C` value with `path.resolve(effCwd, value)` (~:297), so `git -C '' commit` targets `path.resolve(cwd)`. With no `-C` at all, `forEachCommandSegment` passes `effCwd = cwd` through verbatim (~:239).

On POSIX the two agree for an absolute cwd. On Windows `path.resolve('/repo')` is `C:\repo` while the verbatim cwd stays `/repo`, so the worktree gate sees two different targets for what `tests/hooks-git-command.test.js` names "an empty -C value behaves like omitting -C entirely". The test now pins the resolved form (#2767, PR #3294) because that is what production returns.

## Deliverables

- [ ] Make the empty `-C` case and the omitted `-C` case produce the same target in `git-command.js`, either both resolved or both verbatim, choosing the form the worktree gate compares against.
- [ ] Pin both forms with the same expected value in `tests/hooks-git-command.test.js`, with a win32 assertion via an injected `path.win32` or an equivalent seam.

## Acceptance Criteria

For a cwd of `/repo`, `git -C '' commit` and `git commit` resolve to the identical target string on both `path.posix` and `path.win32`, asserted in `tests/hooks-git-command.test.js`.

The suite stays green.

## Release Note

Fixes the worktree guard seeing different targets for `git -C ''` and plain `git` on Windows.
