# 3816: Review Console coordination item ids collide when STAGED lines share their first 58 characters

Origin: ledger resolve gate (#3772 wrap-up)

Defer-reason: needs-human-decision

## Current State

`coordinationItems` (`plugin/bin/lib/console/resolve.js`) ids each item `decision:` + `line.slice(2, 60)`. Lines logged in the same second with the same lead-in share that id. Archived run 2026-10-17T192303-spec-3412's console.json holds three items with the identical id `decision:STAGED 23:44:20 — spec #3412 — Step 3 reproduction: Reprod`. Any per-item resolution keyed on the id cannot tell them apart. Pre-existing; found while reviewing #3772. The id is persisted in console.json, so changing its shape is a contract change that needs a migration choice (suffix vs hash, and how archived consoles read).

**Related:** #3815

## Deliverables

Choose a collision-free id scheme for coordination items and how consoles already on disk are read (expand-contract).

Implement it in `coordinationItems` with a test using three same-second lines.

## Acceptance Criteria

Three STAGED lines sharing their first 58 characters yield three distinct item ids.

A console.json written with the old id shape still reads without error.

## Release Note

Review Console items for same-second STAGED lines no longer share one id.

## Technical Approach

### Key Files

- `plugin/bin/lib/console/resolve.js` — unique ids in coordinationItems
- `tests/bin-lib/console/resolve.test.js` — cover the collision
