# 3949: Give the Review Console a final outcome for every finding and file can't-tell findings at unattended

Surface: infra

## Overview

Cut-over, part one: give every Review Console finding item a final outcome, so a finished run leaves no `pending` or `keep-staged` item behind. After the review tiebreak, the console's Low-confidence and Contested sections hold only can't-tell findings of severity medium or higher, each with a recommendation (`file` or `drop`). This record turns those sections' stance from `keep-staged` (no default, never applied) into an Approve-all default equal to the item's recommendation; adds a read-only "Dropped by tiebreak" block listing refuted high and critical drops; amends the auto-mode contract for exactly one decision (dropping a finding refuted with quoted evidence); and, at `autonomy: unattended` with `consoleAutoResolve`, files every can't-tell item of severity medium or higher as a deduplicated backlog record instead of asking (whatever its recommendation: an agent that could not tell is not licensed to drop).

New runs never produce `keep-staged`. A legacy `keep-staged` item in an existing `console.json` is still read as unresolved, permanently: that is reading old data that consumer archives still hold, not a compatibility shim.

**Complexity:** Medium
**Estimated tasks:** 7

## Non-Goals

- The tiebreak step and its dispatch (the review sub-issue) and the resolver (the resolver sub-issue); this record consumes their outcome and recommendation.
- Staged-item kinds other than review findings: mapping every prefix, the `stage-item.js` refusal and the reflect reroute belong to the staged-kinds sub-issue (which must land first, because both edit `plugin/bin/lib/console/resolve.js`).
- Removing `keep-staged` from the residue reader (`UNRESOLVED_RESOLUTIONS` stays `['pending', 'keep-staged']`).
- Settling the existing pile (the backfill sub-issue).
- Loosening the severity ceiling for applying fixes.

## Technical Approach

The Low-confidence and Contested sections already exist; their items change meaning (after the tiebreak they are can't-tell findings of severity medium or higher, each with a recommendation) and their stance changes from "defer" to "take the tiebreak's recommendation". `drop` is a console resolution (an item dismissed), `file` goes through the queue-write path that Queue-writes already use, so the unattended case reuses that path rather than adding one.

The read-only block is a render-only list fed by the refuted-drop log lines the resolver sub-issue writes (with `listInConsole`), so it needs no click and no `console.json` item.

## Gotchas

- `console.json` is a shared contract read by installed builds over consumer archives: expand-contract. Write only the new resolutions; never rewrite or reinterpret an existing `keep-staged` item as part of this record (the backfill sub-issue settles legacy data).
- A dedup key that includes the line number would mint twin records every time the code shifts; the fingerprint deliberately excludes it, at the cost that a finding reworded beyond whitespace/case normalization can still file a twin (accepted; closing a twin is the remedy).
- Work-record creation is on auto's "never silenced" list: filing rides the existing `autonomy: unattended` / `consoleAutoResolve` / queue-write capability, not a new bypass (`plugin/skills/_shared/autonomy-ceiling.md`).
- Only can't-tell findings of severity medium or higher are filed. Filing low-severity can't-tell items would relocate the noise (they go to the digest via the review step).
- The label must come from the existing `needs:*` vocabulary and must show in `/claude-tweaks:backlog attention`; do not invent a new label family. Do not add or remove any `auto:*` or `bot:*` label on any record.
- Dedup by finding fingerprint; reuse the existing helpers (`materialityFingerprint` and its marker) rather than a second hashing scheme.
- File overlap only (not a dependency): #3880 also edits `plugin/bin/lib/console/resolve.js`; #3816 (coordination item-id collisions) and #3926 (maps `wrap-up-reflect-insights`) also touch it.
