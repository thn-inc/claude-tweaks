# 3946: Route every staged-item kind to a final outcome and refuse unknown kinds at staging

Surface: infra

## Overview

Cut-over, part two: the clean-slate rule needs every staged item kind a producer writes, not just review findings, to reach a final outcome. Today `stage-item.js` only warns when an id matches no Review Console section (the item then lands in Pending review with reason `unmapped-prefix`), reflect `observation` / `convention` items are rerouted to Pending review (#2473) where nothing processes them, and `shadow-dup-*` collision copies go to Pending review too. Together with unmapped-prefix items these account for most of the existing residue that is not a review finding (2026-10-22 count: 149 reflect items and 105 unmapped-prefix `pending` plus `shadow-dup` items, out of 445 unresolved).

This record (a) switches `plugin/bin/stage-item.js`'s unknown-prefix warning to a refusal (non-zero exit, named reason) once every producer is mapped or exempt, (b) routes reflect `observation` / `convention` items to the existing Skill-updates section (Approve-all default), verifying that section's consumer can apply a `reflect-*` file (or adding the consumer), and (c) gives `shadow-dup-*` items a final outcome.

**Complexity:** Low
**Estimated tasks:** 5

## Non-Goals

- Review-finding sections (Low-confidence / Contested), the unattended filing path and the read-only drop block (the console sub-issue).
- Mapping or exempting the producers #3488 and #3926 own: this record lands after them and builds on their mapping and exemption list; it does not redo it.
- Removing the `unmapped-prefix` classification from `classifyStagedItem` (a defensive fallback stays for legacy and hand-staged files read at the console).
- Settling existing residue (the backfill sub-issue applies these outcomes to old items).

## Deliverables

Extraction rule: take the literal text of the `--id` argument; for a templated id (`reflect-{n}`, `${prefix}-${i}`) the literal head up to the first variable is the prefix; a producer whose id has no literal head (it starts with a variable) is a sweep failure to fix at the producer, not to exempt. Record the sweep as a test that fails when a new unmapped, non-exempt producer appears, shown red by a deliberately unmapped fixture producer.
- [ ] `plugin/bin/stage-item.js`: an id matching neither a `SECTION_MAP` row nor the exemption list exits non-zero with a named reason token (for example `unmapped-prefix`, pinned by a test) instead of warning; the nearest-canonical-prefix hint is kept in the refusal message. There is no `--allow-unmapped` escape hatch: the sweep covers every producer shipped here, so the refusal is reachable only by a consumer project's own or hand-written producer, which gets a loud error naming the nearest mapped prefixes. Files staged outside `stage-item.js` keep the console's defensive `unmapped-prefix` classification, which stays unresolved and blocks archive.
- [ ] Reflect items whose `**Category:**` is `observation` or `convention` (the non-tangential-category reroute; a missing category stays unaffected, and any other non-tangential category follows the same reroute as today) route to the existing Skill-updates section, whose stance is the Approve-all default. "Apply" has one meaning, taken from the existing precedent for `staged/wrap-up-reflect-insights.md` (`plugin/skills/wrap-up/review-console.md` step 10): the insight is carried to its own recommended destination (edit the named skill or CLAUDE.md now, create a backlog record, or record a decline), so the resolved item has an effect, not just a stance. Verify the skill-curation consumer can apply a `reflect-*` file that way; if it cannot, add that consumer. #2473 rerouted these items to Pending review only because the Queue-writes consumer cannot file them (no `Title:` / `Type:` / `Labels:` header), so this reroute does not undo that decision. If the consumer work proves larger than one task, split it into its own record before building and keep the reroute behind it.
- [ ] Find what produces `shadow-dup-*` reasons (`plugin/bin/lib/hooks/sweep-shadow.js` and its callers) and give each a final outcome that loses nothing: `shadow-dup-duplicate` (raw bytes identical to the anchor; a whitespace-only difference counts as divergent) is dismissed; `shadow-dup-divergent` and `shadow-dup-collision` (anchor unreadable or absent, so never auto-dismissed) go to Queue writes, so the copy's text is filed as a backlog record through the existing queue-write path instead of staying `pending`. A different final outcome is acceptable if it is final, needs no human click, and cannot lose the copy's content.
- [ ] Update `CANONICAL_PREFIXES` / `SECTION_MAP` and the resolver tests consistently.

## Release Note

Made every kind of item staged for the Review Console resolve to a final outcome, and made staging an unrecognized kind fail loudly instead of leaving residue.

## Technical Approach

The refusal is the last step, taken only after the sweep proves every real producer is mapped or exempt; otherwise a producer that was never mapped would start failing at run time, mid-pipeline. Order inside the record: sweep first, then the reflect and `shadow-dup` outcomes, then the switch from warn to refuse. The reflect reroute reuses the Skill-updates section because `reflect/SKILL.md` already says most observations belong there; the work is confirming the consumer can apply a `reflect-*` file's content.

## Gotchas

- Before switching to refusal, the sweep must prove every producer is mapped or exempt. A refusal added first would break an unmapped producer inside a live pipeline (the failure is at run time, not at test time).
- The refusal depends on #3488's exemption list and #3926's `wrap-up-reflect-insights` mapping; do not start until both have landed, and read their final shape rather than assuming it. If #3488 ships the exemption list as prose rather than one exported constant that both `stage-item.js` and the sweep test can import, extracting it into one constant is part of this record, and the Low size estimate is re-checked.
- `CANONICAL_PREFIXES` must list every alternative of every non-`.patch` `SECTION_MAP` row (`resolve.test.js` expands the regex source and fails on a miss).
- A `.shadow-dup` copy is not always a duplicate of its anchor (#2773): classification already compares text; keep that comparison and attach outcomes to its three reasons rather than collapsing them. `classifyStagedItem` depends on file content for two cases (`reflect-` by its `**Category:**` line, `shadow-dup-*` by the anchor's text); the refusal path in `stage-item.js` classifies by id alone, so the refusal must treat any id whose prefix is in `SECTION_MAP` as mapped without needing content.
- Cite functions, not line numbers: #3880, #3816, #3926 and #3488 shift lines in `resolve.js` and `stage-item.js`.
- File overlap only (not a dependency): #3880, #3816 and #3926 also touch `plugin/bin/lib/console/resolve.js`.
- ASSUMPTION — verify at build: the Skill-updates (`wrap-up-skill-`) consumer applies a free-form `reflect-{n}.md` observation (it expects skill-edit proposals today) — via reading `plugin/skills/wrap-up/review-console.md`'s skill-curation step and `plugin/skills/wrap-up/skill-curation.md`.
