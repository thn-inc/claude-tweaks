# 4251: pr-first: an armed merge never runs the closing-links post-merge reopen, so a Development-sidebar link can still close a kept-open record

Origin: ledger resolve gate

Defer-reason: genuinely-larger

**Decision (2026-11-16, record author, hub question 621; answers the plan-review question in issuecomment-6921695585).** Reading A. The reconcile `post-merge` check that #4599 added (`plugin/bin/lib/reconcile/post-merge.js`) already satisfies the original Deliverable 1, so this record builds no new check. It is rescoped to tests for that existing check, removal of the stale Step 4.0 caveat, and a documentation note. Where an Acceptance Criterion was written for a new check, read it against the existing check: the check's shipped behavior is the contract, so where it differs from a literal reading, pin the shipped behavior and say so in the PR body.

## Current State

- `bin/closing-links.js --mode post-merge` (the reopen backstop) runs in-session only from `_shared/pr-first-merge-post-merge.md` Step 4.0, which an `armed` pr-first outcome never reaches: the merge lands later, when the forge is satisfied.
- Since #4599 the reconciler's `post-merge` check (`plugin/bin/lib/reconcile/post-merge.js`) runs Step 4.0 once for every merged pr-first run with a recorded PR, with reopens bounded to 10 minutes after `mergedAt`. Its candidates are the PR's `closingIssuesReferences`, which include Development-sidebar links, plus the fixes span's `Refs` records. An armed merge that closes a kept-open record is therefore already reopened by that late run.
- `_shared/pr-first-merge-post-merge.md` Step 4.0 still carries the caveat that only a Development-sidebar link can still close a kept-open record on an armed merge, "a gap tracked in the run's ledger". That caveat is stale.
- No end-to-end test drives the `post-merge` check for the armed, kept-open case.

## Deliverables

- [ ] End-to-end tests that drive the existing `post-merge` reconcile check for the two Acceptance Criteria below.
- [ ] Remove the stale caveat from `_shared/pr-first-merge-post-merge.md` Step 4.0.
- [ ] One sentence in `docs/reconcile-checks.md` saying the `post-merge` check covers the reopen of a kept-open record after an armed merge.

## Acceptance Criteria

- [ ] A test drives the existing `post-merge` check with a fake `gh` that reports a merged PR and a `Refs #n` record closed after `mergedAt`, and asserts the record is reopened and a decisions line is written.
- [ ] A run whose fixes span has no `Refs` record triggers no `gh issue` call.

## Release Note

No behavior change: reopening a record that an auto-merged pr-first run left open already shipped. This adds tests for it and removes an outdated caveat from the merge procedure.
