# 4932: hooks.js: an unexpected exception in a VERBS command exits 0 via the entry catch

Origin: #4834 SDD final review (sdd-ruling-1, deferral ratified by the user at the Review Console)

Defer-reason: needs-human-decision

## Current State

`plugin/bin/hooks.js`'s entry point is `main(process.argv).then((code) => process.exit(code)).catch(() => process.exit(0))`. #4834 made the unknown-flag refusal immune to it (both stderr writes sit in a try/catch and the branch returns 1), but any other exception that escapes a directly invoked `VERBS` command — `resolve-run-dir`, `close-run`, `check-pass-reentry`, … — still ends as exit 0 with empty stdout, so a caller such as `RUN_ROOT=$(node … resolve-run-dir) || exit 1` proceeds as if it succeeded. This is the same silent shape #4834 removed for mistyped flags.

Two things lean on today's catch: the `record-pr` handler in `plugin/bin/hooks.js` documents relying on it, and `plugin/bin/hooks.js` holds a reviewed allowlist entry in `tests/bin-lib/exit-code-conformance.test.js`. Harness hook `EVENTS` must keep exit 0 on any failure (the never-break-a-session invariant, `docs/hooks.md`).

## Deliverables

- Split the entry catch so an unexpected exception from a `VERBS` command writes `claude-tweaks: {verb}: {message}` to stderr (via `fs.writeSync(2, …)` in a try/catch, as the #4834 refusal does) and exits non-zero, while an `EVENTS` dispatch keeps exit 0.
- Migrate the `record-pr` handler's documented reliance on the exit-0 catch.
- Update `plugin/bin/hooks.js`'s entry in `tests/bin-lib/exit-code-conformance.test.js`'s allowlist to the new contract.
- Update `docs/hooks.md`'s never-break-a-session passage and `.claude/skills/hooks-js-verb-registration/SKILL.md`'s exit-code decision to state the split.

## Acceptance Criteria

- A spawn test where a `VERBS` handler throws asserts a non-zero exit, empty stdout, and `claude-tweaks: {verb}:` on stderr.
- A spawn test where an `EVENTS` handler throws still asserts exit 0.
- `node --test tests/bin-lib/exit-code-conformance.test.js` passes with the updated allowlist entry.

## Release Note

A hooks.js command that crashes now exits non-zero with the error on stderr, instead of exiting 0 and looking like success; harness hook events still never fail a session.

## Technical Approach

### Key Files

- `plugin/bin/hooks.js` — split the entry catch for VERBS vs EVENTS; migrate record-pr
- `tests/bin-lib/exit-code-conformance.test.js` — update the hooks.js allowlist entry
- `docs/hooks.md` — state the split in the never-break-a-session passage
- `.claude/skills/hooks-js-verb-registration/SKILL.md` — exit-code decision covers unexpected exceptions
