# 5844: Give the count-node-procs real-run test its own small fixture test file

**Related:** #5374, #5771, #5297

Verified-as-of: badfd03b71f7c8f39e2188e4f36be8d3aad446c5

## Current State

`tests/count-node-procs.test.js` ends with `AC10.1: one real run prints a row for the listed test file` (lines 266-292). It writes `tests/helpers-git-template.test.js` into a list file and runs `tools/count-node-procs.js --files-from` on it. So every full suite run pays for the whole template helper test file twice.

Measured by a full `node tools/run-tests.js --full` with git trace2 per test file on main at e1c0beb1b (2026-11-17): `tests/count-node-procs.test.js` started 1,368 git processes, the same number and the same subcommand mix (commit 119, rev-list 105, add 103, init 100) as `tests/helpers-git-template.test.js`. It is the fourth largest git spender in the suite.

What the test needs from its fixture is small. `tools/count-node-procs.js` counts node processes only (a `NODE_OPTIONS` preload logs each node start and exit); it does not count git. It attributes a process to a test file only when that file is inside the checkout and its name ends in `.test.js` (`tools/count-node-procs.js:95`). The test asserts one row, the listed file name, `nodeProcs === 1`, `cliProcs` deep-equal `{}` and a numeric `wallMs`; its comment says the fixture's helpers start git, which must not be counted as node.

`tools/run-tests.js` discovers every `*.test.js` under `tests/` and `tools/upstream-drift/tests/`, and `--files-from` accepts any existing `*.test.js` file inside the checkout.

#5771 (PR #5842, one-process repo init) and #5790 (PR #5843, learned-skills git reuse) were being built by other sessions when this was filed. Neither touches the files this record edits. #5771 edits `tests/helpers-git-template.test.js`; this record does not.

## Deliverables

1. A fixture test file used only by this test. It passes on every platform CI runs, starts exactly one git process (so "a git process is not counted as a node process" stays exercised), and starts one child node process that runs a side-effect-free `plugin/bin/` CLI (so the row's `cliProcs` is non-empty and a real parent chain is attributed end to end). It starts nothing else.

2. The fixture lives where a default suite run does not discover it (outside `tests/` and `tools/upstream-drift/tests/`). If a repository check requires test files to sit under those roots, it goes under `tests/` instead and the PR body states what it costs per full run.

3. `AC10.1: one real run prints a row for the listed test file` lists the fixture instead of `tests/helpers-git-template.test.js`. It still runs the real tool through the real runner with `--files-from` and `--json`. Its row assertions are exact: one row, `file` equal to the fixture's repo-relative path, `nodeProcs` equal to the exact number of node processes the fixture starts, `cliProcs` deep-equal to the exact map, `wallMs` a number.

4. The PR body reports git processes and spawned node processes for `tests/count-node-procs.test.js` before and after.
