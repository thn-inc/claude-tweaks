# 3809: flow worktree-merge closes every run before the multi-run merge — a skip, abort or failure leaves runs closed

Origin: ledger resolve gate — #3762 ledger item 12 (whole-branch review Minor 6)

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/skills/flow/worktree-merge.md` (the `integration-model: local-merge` multi-run reconciliation merge) runs `hooks.js close-run --run "$dir"` for every non-clean run dir **before** the merge/finish sequence starts. That sequence can still stop short of a merge for a given run: a `compose-subject.js` failure, a merge conflict, or the human choosing "Skip this branch" or "Abort remaining merges". Each of those leaves the affected runs closed — worktree assignment cleared, `status: clean` — while their branches are unmerged, so their worktrees lose the teardown protection the pipeline-run assignment gives them.

#3762 fixed the same defect class on the three no-human local-merge procedures (`wrap-up/auto-merge-short-circuit.md`, `dispatch/settle-and-merge.md`, `_shared/local-merge-auto-finish.md`): every check that can fail runs before `close-run`, and any failure after it re-stamps the run with `hooks.js record-worktree --run`. This human-present path was found by #3762's whole-branch review (ledger item 12) and is outside that diff.

## Deliverables

- Close each run only for the branch about to merge, after that branch's pre-merge checks (branch guard, `compose-subject.js`, `git merge-tree --write-tree` conflict pre-check) pass — not all runs up front.
- On a branch the human skips, or every branch left when they abort the remaining merges, leave its run untouched (never closed), or re-stamp it with `hooks.js record-worktree --run` if it was already closed.
- On a merge or push failure after a run was closed, re-stamp that run the way `_shared/local-merge-auto-finish.md`'s Park branch does — run as `env -u CLAUDE_CODE_SESSION_ID … record-worktree --run`, since the reconciling session is usually not the run's owner and `record-worktree` would otherwise stamp its own session id into the run (build alignment, Beneficial).
- Extend `tests/local-merge-close-run-ordering.test.js`'s `SITES` (or a sibling suite) to pin the new order for this file.

## Acceptance Criteria

- [ ] In `plugin/skills/flow/worktree-merge.md`, no `close-run` instruction precedes a pre-merge check for the same branch (pinned by a test).
- [ ] A skipped or aborted branch's run keeps its worktree assignment and `active` status (the procedure states it; a fence or text test pins it).
- [ ] Any failure after a run was closed re-stamps it with `record-worktree --run` and logs a re-stamp that did not print `worktree recorded`.

## Release Note

Multi-run local-merge reconciliation no longer leaves a skipped, aborted or failed branch's run closed, so its worktree stays protected while it waits.

## Technical Approach

### Key Files

- `plugin/skills/flow/worktree-merge.md` — move close-run after each branch's pre-merge checks; re-stamp on skip/abort/failure
- `tests/local-merge-close-run-ordering.test.js` — pin the order for worktree-merge.md
