# 5358: Keep both PR-body delimiter forms through an MCP read-repair-write

Origin: ledger resolve gate (record #5340's build, SDD final review)
Defer-reason: pre-existing-outside-diff

## Current State

`repairPrBody` (`plugin/bin/lib/flow/pr-body.js`) counts a delimiter pair as present when only its plain-text companion (`[claude-tweaks-fixes-end]` and the like) is in the body. An MCP read strips HTML comments, so the body it hands back carries only the plain-text forms, and an MCP write-back then omits the `<!-- -->` forms. `_shared/pr-checklist-refresh.md` says "both delimiter pairs survive" the gh-absent path. Readers that match only the HTML form, such as the github-pr-scan `RUN_MARKER` check, can then miss the PR. Found by #5340's final whole-branch review; outside that diff.

## Deliverables

1. `repairPrBody` restores the HTML-comment form of every delimiter pair whose plain-text companion is present but whose `<!-- -->` form is missing, so an MCP read-repair-write keeps both forms.

## Acceptance Criteria

- [ ] A unit test feeds `repairPrBody` a body carrying only the plain-text delimiter companions (as an MCP read returns it) and asserts the repaired body carries each pair's `<!-- -->` form as well.
- [ ] That test fails against the current `repairPrBody`.
