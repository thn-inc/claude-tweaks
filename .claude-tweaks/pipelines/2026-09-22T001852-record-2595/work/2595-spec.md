# 2595: review step3 dispatch: the SCRATCH path under the main-checkout run dir is unwritable for agents in a worktree-always session (empirical reproduction of closed #2245)

Surface: infra

## Current State
`/claude-tweaks:review`'s Step 3 lens/refutation dispatch prompts (`plugin/skills/review/step3-lens-dispatch.md` line 72, `plugin/skills/review/step3-debate-and-refutation.md` lines 96 and 131) each hand every dispatched agent a line of the form `SCRATCH: {ctx-dir}/agent-scratch/{agent-id}`, citing `_shared/subagent-output-contract.md`'s Scratch rule ("any probe script or fixture the agent creates to verify its own work goes there ... and is deleted before the status word"). `{ctx-dir}` is minted by `bin/build-review-context.js` under the pipeline run directory, which is anchored under the main checkout.

`_shared/subagent-output-contract.md`'s Scratch rule already documents one related failure mode, empirically confirmed on the earlier report #2245: when the scratch directory lies outside the agent's own worktree (an `EnterWorktree`-isolated dispatch whose `{ctx-dir}` resolves to the shared main checkout — "the case a review fan-out hits on every `worktree`-mode run"), a `Write`/`Edit` tool call is refused outright by the harness's worktree-pinning guard, but the documented workaround is to create/delete the scratch file via Bash instead (`mkdir -p` + a shell redirect/heredoc, then `rm`) — the guard is scoped to the file-editing tools, not to Bash.

This record (#2595) is the empirical reproduction of #2245's *further* concern under a `worktree-always: true` project: two refutation agents dispatched during a real `/claude-tweaks:flow #N` run (2026-09-18, plugin 6.126.0) both reported the guard refusing every write to their assigned `SCRATCH:` path, and fell back to ad hoc workarounds (inline `python -c` probes; one agent created and removed its own `/tmp` directory) rather than the Bash-mediated workaround `subagent-output-contract.md` already documents. Whether those agents simply weren't instructed to use the Bash-mediated approach (the `SCRATCH:` dispatch lines in `step3-lens-dispatch.md`/`step3-debate-and-refutation.md` don't explicitly repeat the "use Bash, not Write/Edit" instruction inline) or whether `worktree-always`'s guard additionally refuses Bash-mediated writes to the same path (a stricter regime than the narrower `EnterWorktree`-isolation case the existing Scratch rule text addresses) is not yet established — this needs to be determined as part of the fix, since it changes whether the existing documented workaround already suffices or whether a genuinely different scratch location is needed.

Regardless of mechanism, the consequences observed: nothing was lost, but the "delete your scratch before your status word" contract cannot be honoured, each agent spends turns discovering the refusal before working around it, and the post-fan-out scratch sweep (`step3-lens-dispatch.md`'s own sweep, diffing `pre-dispatch-status.txt`) can never see what the agents actually did in their ad hoc fallback locations.

## Deliverables
1. Determine empirically whether a Bash-mediated write (`mkdir -p` + redirect, then `rm`) to the `SCRATCH:` path succeeds under a `worktree-always: true` project's main-checkout-anchored `{ctx-dir}`, or whether the guard refuses Bash writes there too.
2. If Bash-mediated writes already succeed: make the `SCRATCH:` dispatch lines in `step3-lens-dispatch.md` and `step3-debate-and-refutation.md` explicitly instruct the Bash-mediated create/delete pattern inline (not just by citing the Scratch rule by reference), so a dispatched agent doesn't need to discover the refusal itself before finding the workaround.
3. If Bash-mediated writes are also refused under `worktree-always`: mint `{ctx-dir}`'s `agent-scratch/` location somewhere genuinely writable under that policy — either inside the dispatching worktree's own gitignored scratch convention (the `.superpowers/` or `.claude-tweaks/scratch/` pattern SDD workspaces already use) or under the session temp root (`_shared/session-tmp-root.md`'s `sessionTmpRoot(sessionId)`, which resolves under `os.tmpdir()` and is therefore outside the repository tree and any worktree-pinning guard entirely).
4. Whichever location fixes it, `_shared/subagent-output-contract.md`'s Scratch rule is updated to state the `worktree-always` case explicitly (it currently documents only the narrower `EnterWorktree`-isolated-dispatch case from #2245), and `bin/build-review-context.js`'s `{ctx-dir}` minting reflects the corrected location.
5. The post-fan-out scratch sweep in `step3-lens-dispatch.md` looks in the corrected location, so it can actually observe what dispatched agents did there.

## Acceptance Criteria
1. Given a `worktree-always: true` project, dispatching a Step 3 lens or refutation agent and instructing it to create a probe file at its assigned `SCRATCH:` path succeeds (verified by direct reproduction — either confirming the Bash-mediated pattern now works because it's correctly instructed, or confirming the corrected location is genuinely writable).
2. Given the same setup, the dispatched agent's probe file is visible to the post-fan-out scratch sweep before the agent deletes it (i.e., the sweep's location matches wherever the agent actually wrote).
3. Given the same setup, no dispatched agent needs to fall back to an ad hoc mechanism (a self-created `/tmp` directory, an inline `python -c` probe) to honor the "verify your own work" pattern — the documented `SCRATCH:` mechanism works as instructed.
4. `_shared/subagent-output-contract.md`'s Scratch rule explicitly states the `worktree-always` case's correct mechanism/location, distinguishing it from the pre-existing `EnterWorktree`-isolated-dispatch case if the two turn out to need different handling.
5. A review run under a project WITHOUT `worktree-always` (the case #2245 already covers, presumably already working via the Bash-mediated workaround) is unaffected by this fix — verified by confirming the existing documented behavior for that case still holds.

## Technical Approach
- First, empirically test (in a `worktree-always: true` project or an equivalent simulated environment) whether `mkdir -p {ctx-dir}/agent-scratch/{agent-id} && echo test > {ctx-dir}/agent-scratch/{agent-id}/probe.txt` via Bash succeeds or is refused, to resolve the open question in Current State.
- If refused: change `bin/build-review-context.js`'s `{ctx-dir}` (or specifically the `agent-scratch/` subpath it mints) to resolve under the dispatching worktree's own gitignored scratch convention, or under `_shared/session-tmp-root.md`'s `sessionTmpRoot(sessionId)` — prefer whichever integrates more simply with the existing sweep mechanism in `step3-lens-dispatch.md`.
- If Bash-mediated writes already succeed: add the explicit Bash-mediated instruction inline to the `SCRATCH:` dispatch lines in both `step3-lens-dispatch.md` and `step3-debate-and-refutation.md`, rather than relying on the agent finding and reading `_shared/subagent-output-contract.md`'s Scratch rule on its own after hitting the refusal.
- Update `_shared/subagent-output-contract.md`'s Scratch rule prose to add the `worktree-always` case alongside its existing `EnterWorktree`-isolated-dispatch case.
- Confirm the scratch sweep in `step3-lens-dispatch.md` reads from wherever the corrected `{ctx-dir}` resolves.

## Gotchas
- Whether Bash-mediated writes are refused under `worktree-always` is the open empirical question this record itself flags — do not assume either answer without testing; the fix direction depends entirely on it (Deliverable 1/2 vs Deliverable 3).
- If the fix moves the scratch location outside `{ctx-dir}`, the post-fan-out scratch sweep (`step3-lens-dispatch.md`) must be updated in the same change — a fix that makes writes succeed but leaves the sweep looking in the old location just changes which half of the contract breaks.
- This is the second report on the same underlying class (#2245 → #2595) — if #2245 is still open or only partially addressed, cross-check before closing either, and prefer consolidating the Scratch rule's documentation into one coherent statement covering both the `EnterWorktree`-isolation case and the `worktree-always` case rather than two disconnected paragraphs.
- `session-tmp.js`'s `sessionTmpRoot` degrades to `null` when `$CLAUDE_CODE_SESSION_ID` is absent/blank (per `_shared/session-tmp-root.md`'s own degrade rule) — if that path is chosen, the dispatch prompt logic needs a defined fallback for that case too.
