# 4951: stuck-open-prs.js passes the raw origin host to gh as --hostname, skipping the #4854 host gate

Origin: /claude-tweaks:release v6.160.2 release-gate review (run 2026-11-02T060818-release-standalone)

Defer-reason: pre-existing-outside-diff

Blocked by #4933

## Current State

`plugin/bin/stuck-open-prs.js:69` builds its repo facts as `repo: () => parseRepo(remoteUrl())`, so `host` is whatever host the origin URL names. `fetchLinkedPRs` (`plugin/bin/lib/issues/linked-prs.js:47`) turns any host other than `github.com` into `--hostname {host}`, and `ghOptions` then trusts that explicit host instead of applying #4854's positive-signal gate (`*.ghe.com` or a gh `hosts.yml` key) and `normalizeHost`. With `GH_ENTERPRISE_TOKEN` set and an origin on a non-GitHub host, gh sends the token to that host: the leak #4854 closed for `GH_HOST`.

Shipped by #4849. Found by the v6.160.2 release-gate review of v6.160.1..dd6791663 (lens 3b, severity medium, confirmed by tiebreak).

Related: #4933 adds the origin-host gate to `plugin/bin/lib/repo-resolve.js` and moves every other origin-derived producer onto it; it lists `stuck-open-prs.js` as tracked here. This record moves `stuck-open-prs.js` onto that same gate, so it is built after #4933 in the same flow. #4921 changes where this same `realDeps.repo` gets its slug (`gh repo view` instead of origin); whichever lands second must keep the host gate. #4952 corrects the `gh-api-module-pattern` skill that taught the raw-host pattern.

## Decision

Same rule as #4933, decided there: an origin host with no positive GitHub signal (not `github.com`, not `*.ghe.com`, not a gh `hosts.yml` key, no exported `GH_HOST`) is **refused**, never dropped to a bare `owner/repo` or a `github.com` fallback. Dropping would send the github.com token and act on whatever same-named repo exists on github.com. The review-time draft fix (`resolveGhHost(process.cwd()) || 'github.com'`) is that rejected drop shape and is superseded.
