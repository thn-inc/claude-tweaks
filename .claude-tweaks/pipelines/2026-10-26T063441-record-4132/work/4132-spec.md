# 4132: Select tests changed between the map's commit and the base, so map-to-base drift cannot deselect a test

Origin: ledger resolve gate (#4024, ledger rows 15 and 39)
Defer-reason: genuinely-larger

## Current State

Impact selection reads a map traced at commit M and selects against the delta from the base B to HEAD. A test file that began reading a path after M (and before or at B) has no recorded read of it, so a later change to that path does not select the test. #4024 documents this as a known limit in `plugin/skills/test/impact-selection.md`, and CI's full suite on the PR gates the merge, so the gap costs a late catch rather than a missed regression. Closing it changes the selection contract: the changed-file set would have to include the test files that differ between M and HEAD, which needs the map's commit as a second diff base, and a rule for when M is not an ancestor of the base.

## Deliverables

- Extend selection so every test file that differs between the map's commit and HEAD is selected as untraced (it may read anything).
- Keep the fallback reasons unchanged for a missing, stale or non-ancestor map, and report the count of drift-selected tests in `report.json` `scope.impact`.

## Acceptance Criteria

- [ ] A test file edited after the map's commit to read `src/x.js` is selected when `src/x.js` changes, with the map's commit older than the base.
- [ ] A run with the map at the base selects exactly what it selects today.
- [ ] The known-limit paragraph in `impact-selection.md` is replaced by the new rule.

## Release Note

Test-impact selection no longer misses a test whose reads changed after the map was traced.
