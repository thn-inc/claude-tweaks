# 3488: Map or exempt every staged-id producer so stage-item.js's unmapped-prefix warning is true for each of them

Origin: ledger resolve gate (spec #3370 build, whole-branch review finding I5)

Defer-reason: genuinely-larger

## Current State

`plugin/bin/stage-item.js` (#3370) warns on stderr when the id that landed matches no `SECTION_MAP` row in `plugin/bin/lib/console/resolve.js`. Four producers stage ids no row maps: `release-held`, `upstream-draft-{N}`, `shipped-close-*` (whose call is silenced by its own `2>/dev/null`) and `dispatch-target-missing-*`. Real staged output carries more unmapped names: `review-followup-*`, `build-followup-*`, `docs-*`, `skills-*`, `wrap-up-reflect-insights`, `wrap-up-cleanup-ordering` and `reconcile-live-run-archived`. The release and dispatch run directories never reach wrap-up's `console-resolve.js`, so for them the warning ("if a wrap-up Review Console resolves this run, it routes this item to Pending review") describes a console that never runs; for the producers whose runs do reach it, an unmapped name lands in Pending review and is never auto-resolved. Files: `plugin/bin/lib/console/resolve.js`, `plugin/bin/stage-item.js`, and the producer skills under `plugin/skills/`.

## Deliverables

- [ ] Enumerate every `stage-item.js --id` producer under `plugin/skills/` and `plugin/bin/` and record, per producer, whether its run directory reaches `console-resolve.js`.
- [ ] For each producer whose run reaches the console: add a `SECTION_MAP` row (and the matching `CANONICAL_PREFIXES` entry) or rename the id to an already-mapped prefix.
- [ ] For each producer whose run never reaches it: exempt it from the warning with the reason stated beside the exemption, and drop `shipped-close-*`'s `2>/dev/null` so a real staging failure is visible.
- [ ] A test that fails when a producer's id matches neither a row nor the exemption list.

## Acceptance Criteria

1. `stage-item.js --id release-held` and `--id dispatch-target-missing-x` print no unmapped-prefix warning, and `--id review-13-record` still prints it.

2. Every id named in Current State classifies through `classifyStagedItem` without `unmapped-prefix`, or is on the exemption list with its reason.

3. `npm test` passes with no new failures relative to `main`.

## Release Note

The staging-time warning for an unmapped Review Console prefix now prints only where it is true: every producer's id either maps to a console section or is exempt with a stated reason.

## As-built notes (build Common Step 4.5)

- **Beneficial: wider producer set.** Deliverable 1's enumeration found producers that Current State does not name. Three are in-process `writeStagedItem` callers in `plugin/bin`: `premise-satisfied-` and `sibling-premise-disproof-` (materialize.js) and `dream-proposal-` (dream-scan.js). Two are named only in skill prose: `plan-citation-{n}` (wrap-up/cleanup-procedures.md) and `translation-{issue}` (flow/multi-spec.md). Each is mapped with a `pending` reason row or exempted. - **As specified: names with no producer.** `review-followup-*`, `build-followup-*`, `docs-*`, `skills-*`, `reconcile-live-run-archived`, `wrap-up-cleanup-ordering` and `wrap-up-reflect-insights` have no producer in the corpus to rename, so each gets a `SECTION_MAP` disposition (AC2).
