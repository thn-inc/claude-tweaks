# 3168: engine-verify AC1 (live git) test writes its leftover before the run dir, so it fails on macOS

**Related:** #3155, #3153, #3130

Verified-as-of: 0af440d7642a1ba30c9c0af43c24560b90d03b04

## Current State

`tests/bin-lib/wrap-up/engine-verify.test.js`'s `AC1 (live git)` test (line 767) writes the leftover plan file at line 772 and only then creates `runDir` at line 774. `plugin/bin/lib/wrap-up/engine-verify.js`'s `plans-ledger` check (line 236-249) treats an artifact older than the run dir (`entryMs < runStartMs`, line 242) as not owned by this run and returns `skip`. The test expects `fail`.

On APFS (macOS), timestamps have nanosecond resolution, so the file is strictly older than the directory and the test fails deterministically: `'skip' !== 'fail'`, detail `1 pre-existing artifact(s) found, not owned by this run: docs/superpowers/plans/2026-09-02-leftover-plan.md`. On Linux CI the two timestamps usually tie, so the test passes. Reproduced 2026-10-15 from a detached `origin/main` checkout at a path with no space (1 failure of 98).

This is a test-ordering bug; the production ownership logic (#2552) is correct.

## Deliverables

- Reorder the `AC1 (live git)` test so `runDir` is created before the leftover file is written, matching the real sequence (a run starts, then leaves residue).

- Check the other `plans-ledger` / ownership tests in the same file for the same ordering, and fix any that create the artifact before the run dir.
