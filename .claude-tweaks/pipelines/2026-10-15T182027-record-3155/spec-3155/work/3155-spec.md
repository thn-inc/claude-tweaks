# 3155: bin/verify.js baseline adjudication mangles failing-file paths in a space-containing checkout path

Surface: infra

**Related:** #3153, #3156

## Current State

`bin/verify.js`'s `--baseline` adjudication (#3043) names each failing test file from the full-run log, then compares it against a per-file isolated rerun at the baseline commit. The path extraction lives in `plugin/bin/lib/verify/extract.js`, not in `bin/verify.js` itself:

- `TAP_FRAME_RE` (line 192) captures node `--test` stack frames and `location: '...'` lines with `(?:\(|\s|')(${WIN_PATH}):\d+:\d+\)?`. `WIN_PATH` (`[A-Za-z0-9_./@~:\\-]+`) has no space character, and the leading alternation accepts any whitespace as the start of a path. So in a checkout whose absolute path contains a space, `/Users/thomasholknielsen/Code Workspaces/claude-tweaks/tests/x.test.js:1:21` matches starting after the space, as `Workspaces/claude-tweaks/tests/x.test.js`.
- `relativize()` then cannot strip the checkout prefix from the truncated string, so the file never matches a file at the base commit and is classified `attributable` instead of `baseline`/`flaky`.
- `SUMMARY_FAIL_RE` (line 195, vitest/jest/pytest summary lines) uses the `PATH` class (`[A-Za-z0-9_./@~-]+`), which also has no space, so the same truncation applies there.

This repo's own clone sits at `/Users/thomasholknielsen/Code Workspaces/claude-tweaks` (the `Code Workspaces` segment has a space). Running `/claude-tweaks:build` Common Step 5 for record #3139, `--baseline` adjudication's own `report.json` showed failing-file paths mangled this way and every one misclassified `attributable`.

## Deliverables

- Make `plugin/bin/lib/verify/extract.js`'s failing-file path capture tolerate an absolute path containing one or more spaces, by anchoring on the delimiters each log shape already carries instead of on bare whitespace: the quoted value of a TAP `location: '...'` line, the parenthesized `(path:L:C)` stack frame, and the end-of-line `at path:L:C` frame. Apply the same treatment to `SUMMARY_FAIL_RE`'s summary-line forms wherever the runner's output delimits the path unambiguously.
- Add regression cases to `tests/bin-lib/verify/extract.test.js` that feed each affected log shape with a space-containing absolute path and a matching space-containing `cwd`, and assert the relativized file comes back intact.

## Acceptance Criteria

- [ ] `extractFailingFiles` on a node `--test` TAP log whose `location:` lines and stack frames name `/tmp/a b/repo/tests/x.test.js:1:21`, called with `cwd: '/tmp/a b/repo'`, returns `['tests/x.test.js']` rather than a truncated `b/repo/...` path.
- [ ] The functions that share these regexes (`failingTestsByFile`, `fileLevelFailures`, `countUnmatchedFailures`) return the same intact relative path for that input.
- [ ] A space-free path still extracts exactly as before. Every existing `tests/bin-lib/verify/extract.test.js` case passes unchanged, including the Windows drive-letter/backslash cases and the pytest `path::name` case.
- [ ] `npm test` passes.

## Release Note

Fix `--baseline` verification misclassifying failing test files as new regressions when the checkout path contains a space.

## Technical Approach

Replace the whitespace-start alternation in `TAP_FRAME_RE` with per-shape captures: `location:\s*'(.+):\d+:\d+'` for the quoted form, `\((.+?):\d+:\d+\)` for the parenthesized frame, and `\bat\s+(.+):\d+:\d+\s*$` for the bare `at` frame. Each delimiter bounds the path, so the path class can include spaces safely. Keep `WIN_PATH`'s drive-letter and backslash handling inside those captures. For `SUMMARY_FAIL_RE`, keep the pytest `::` stop. A vitest/jest summary path is followed by ` > ` or ` (` or end of line, so allow spaces only where one of those terminators follows.

### Key Files

- `plugin/bin/lib/verify/extract.js` — path regexes `TAP_FRAME_RE`, `SUMMARY_FAIL_RE` and their consumers
- `tests/bin-lib/verify/extract.test.js` — space-containing-path regression cases

## Gotchas

- **This fix alone will not make `tests/bin-lib/verify/cli.test.js`'s 4 `--baseline` tests pass on macOS.** Verified 2026-10-15: those same 4 tests fail identically from a checkout path with no space (a detached scratch worktree of `origin/main` under `/private/tmp`). That failure has a separate root cause: `plugin/bin/lib/verify/baseline.js:59` creates the base worktree under `fs.mkdtempSync(path.join(os.tmpdir(), ...))`, which on macOS is `/var/folders/...`, while node's TAP output reports the real path `/private/var/folders/...`. `relativize()` then misses the base-dir prefix, and a file that also fails at base is classified `attributable`. Linux CI has no `/var` symlink, which is why CI is green. Track that fix separately; do not fold it into this record.
- A delimiter-anchored capture with `.+` is greedy. Use a non-greedy capture or an end-anchor so a line carrying two frames does not merge them into one path.
- `relativize()` folds backslash runs before the prefix compare. Keep the Windows behavior unchanged.

## Current State

bin/verify.js's --baseline adjudication feature (#3043) extracts each failing test's source file path from the full-run log to compare against a per-file isolated rerun at the baseline commit. In a checkout whose absolute path contains a space (this repo's own clone sits at `/Users/thomasholknielsen/Code Workspaces/claude-tweaks` — the `Code Workspaces` segment has a space), the extracted path is truncated at the space — e.g. `/Users/thomasholknielsen/Code Workspaces/claude-tweaks/.claude/worktrees/{x}/tests/bin-lib/gif/palette.test.js` becomes `Workspaces/claude-tweaks/.claude/worktrees/{x}/tests/bin-lib/gif/palette.test.js`. Every such file is then classified `attributable` (new/regression) instead of `baseline`/`flaky`, because the mangled path never resolves against the scratch base-commit worktree the adjudicator diffs against.

Observed while running `/claude-tweaks:build` Common Step 5 verification for record #3139 (a 1-line docs/REGISTRY.md fix, touching no code): a full `npm test` run in this worktree checkout reproducibly failed 5-7 tests confined to `tests/bin-lib/verify/cli.test.js`'s own #3043 baseline self-tests, `tests/bin-lib/wrap-up/engine-verify.test.js`'s live-git AC1 test, and `tests/bin-lib/gif/palette.test.js`'s timing-bound test — none of them touching record #3139's actual 2-file diff. Confirmed pre-existing/environmental rather than a regression: GitHub Actions' `test` workflow on this exact base commit (`56d5ae311`) completed with `conclusion: "success"` (`gh run list --branch main`), while the identical suite run locally in this (space-containing-path) worktree checkout reproducibly fails those same files across multiple consecutive runs, and `--baseline` adjudication's own `report.json` output shows every failing file's path already mangled this way, with every one misclassified `attributable`.

## Deliverables

Fix bin/verify.js's baseline-adjudication failing-file-path extraction (and the matching per-file isolated-rerun path resolution) to tolerate an absolute repository path containing one or more spaces — e.g. anchor on the known log-line prefix/suffix delimiters around the path, or on a trailing `:line:col`/stack-frame marker, rather than splitting on bare whitespace. Add a regression test under `tests/bin-lib/verify/` that runs the adjudicator against a fixture checkout whose directory name contains a space.

## Acceptance Criteria

A full `npm test` run inside a checkout whose absolute path contains a space, with `--baseline` adjudication enabled, correctly classifies a failing test file that also fails at the baseline commit as `baseline` (or `flaky`, as appropriate) rather than `attributable` — matching the classification the same file already gets in a checkout with no space in its path.

## Release Note

No user-visible change — fixes a verification-tooling false positive that only misfires in a checkout path containing a space.
