# 4158: test-impact tracer drops a read whose trace write fails, with no fail-closed record

**Related:** #4130, #4133

## Current State

In `tools/test-impact/tracer.js:141`, `appendFileSync` errors (EMFILE/ENOSPC) are swallowed, and `failClosed` emits through the same failing emit, so it cannot cover a failed write. A lost read leaves the test under-recorded, and `build-map` can still stamp exitCode 0, so `verify --scope` may later deselect a test that reads the changed file. Found by both lens-3c agents in the v6.153.0 release delta review. Related, not the same: #4130 (header-less trace files), #4133 (module resolution and shell parsing).

## Deliverables

1. When a trace write fails, record the failure through a channel that does not depend on that write (for example a process-exit flag that makes `trace` refuse the map, or a non-zero exit).
2. A test that injects a failing `appendFileSync` and asserts the map is refused or the test is marked unsafe.

## Acceptance Criteria

- A trace run in which any read could not be written produces no map with exitCode 0.
- The new test goes red against the current swallow.
- `npm test` passes.

## Release Note

Impact-selected test runs no longer skip a test whose file reads could not be recorded while the map was built.
