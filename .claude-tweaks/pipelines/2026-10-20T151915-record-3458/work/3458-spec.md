# 3458: phase-timing's locateTranscripts ignores CLAUDE_CONFIG_DIR and finds no transcripts under a non-default config dir

Origin: #3309 build, Task 0 premise probe (ledger row 37)

Defer-reason: out-of-scope

## Current State

`plugin/bin/lib/timing/transcript.js` `locateTranscripts({ cwd, sessionId, homeDir = os.homedir(), fsImpl })` always looks under `path.join(homeDir, '.claude', 'projects')`. `plugin/bin/phase-timing.js:159` calls it with only `{ cwd: worktree, sessionId }`.

Claude Code writes transcripts to `$CLAUDE_CONFIG_DIR/projects/` when that variable is set. `plugin/bin/dream-scan.js:66` already resolves `process.env.CLAUDE_CONFIG_DIR || path.join(os.homedir(), '.claude')`, and so does #3309's `skill-load-report.js`. On a machine running Claude Code with `CLAUDE_CONFIG_DIR=~/.claude-accounts/<slug>`, `~/.claude/projects` holds none of the sessions, so `phase-timing.js` silently finds no transcript and reports no token or procedure-byte data.

#3309 could not fix this: its spec lists `timing/transcript.js` as "not modified".

## Deliverables

- Resolve the projects root from `CLAUDE_CONFIG_DIR` (falling back to `~/.claude`) in `locateTranscripts`, or in its caller with an injectable config-dir parameter. Keep the existing `homeDir` seam working for tests.
- Update `TRANSCRIPT_SLUG_RULE`'s header note to name the config-dir resolution.

## Acceptance Criteria

1. With `CLAUDE_CONFIG_DIR` set to a temp dir holding `projects/{slug}/{sid}.jsonl`, `locateTranscripts({ cwd, sessionId })` returns that file.
2. With `CLAUDE_CONFIG_DIR` unset, behavior is unchanged (`tests/bin-lib/timing/transcript.test.js` passes).

## Release Note

Phase timing now finds session transcripts when Claude Code runs with a custom config directory.
