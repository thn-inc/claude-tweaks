# 3566: wrap-up ledger-write.js resolveLedgerPath still treats a lone docs/plans ledger as this run's

Surface: infra

Origin: build (#2887 whole-branch review)

Defer-reason: pre-existing-outside-diff

## Current State

#2887 made `ledgerProbe` (`plugin/bin/lib/wrap-up/pack.js`) attribute `docs/plans/*-ledger.md` files to a run by branch ownership: a ledger counts only when `git diff --name-only {merge-base}` or `git ls-files --others` names it. Ledgers inherited from `main` are listed as `unattributedFiles` instead.

Two sibling resolvers still use the filename heuristic #2887 retired:

- `resolveLedgerPath` in `plugin/bin/lib/wrap-up/ledger-write.js` (around `:47-56`) treats exactly one `docs/plans/*-ledger.md` candidate as this run's ledger, and returns `ambiguous` for two or more. Its callers are `hooks.js delete-ledger --run` (no `--ledger`), reached from `wrap-up/cleanup-procedures.md` row 2, and `wrap-up-engine.js finish-console`. With exactly one inherited ledger in the worktree, either can flip rows in, or delete, another run's committed ledger. With two or more inherited ledgers (this repo today: `docs/plans/` on `main` carries finished runs' ledgers), a run's own ledger becomes `ambiguous` and cannot be flipped or deleted without `--ledger`.

- Wrap-up prose re-counts "the ledger" by glob after the residue sweep (`plugin/skills/wrap-up/SKILL.md:208`, `plugin/skills/wrap-up/residue-sweep.md` around `:62-66`), through `_shared/ledger-format.md`'s resolution fallback, so an agent's own re-count can pick up inherited ledgers again.

## Deliverables

1. `resolveLedgerPath` resolves the run's `docs/plans` ledger by the same ownership rule `ledgerProbe` uses (merge-base diff plus untracked files), sharing one helper rather than re-implementing it. An inherited ledger is never returned. `ambiguous` is returned only when two or more owned candidates remain.

2. The wrap-up prose re-count after the residue sweep reads `pack.ledger` again (re-run the ledger probe), not a bare glob.

3. Tests in `tests/bin-lib/wrap-up/` for: one inherited ledger only (not found), one owned plus inherited (owned path returned), two owned (ambiguous).

## Acceptance Criteria

- In a worktree whose only `docs/plans` ledger is inherited from the merge base, `resolveLedgerPath` returns not-found, and `hooks.js delete-ledger --run` deletes nothing.

- In a worktree with one owned ledger plus inherited ledgers, `resolveLedgerPath` returns the owned ledger's path.

- `npm test` passes in full.

## Release Note

Fixed wrap-up flipping or deleting another run's ledger file when a worktree inherited one from the main branch.
