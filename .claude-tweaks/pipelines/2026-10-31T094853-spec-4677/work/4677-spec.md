# 4677: wrap-up merge mode cannot resolve a pending-review run that wrap-up already archived

## Current State

A `/claude-tweaks:flow` run under `pr-first` whose Review Console resolves the merge to leave-open (for example a record without `auto:merge`) still runs wrap-up Phase 4 in full: Section C step 3.6 runs `close-run` (status `clean`) and cleanup item 8 runs `archive-run`, moving the run dir to `.claude-tweaks/pipelines/archive/{run-id}/`. The flow summary then recommends `/claude-tweaks:wrap-up #{n} merge` to merge the parked PR.

`plugin/skills/wrap-up/merge-mode.md`'s "Resolve the run" adopts the run only through `PIPELINE_RUN_DIR` or `hooks.js resolve-run-dir --spec-slug "spec-{n}"` with no `--create`, and stops when nothing resolves. The resolver never looks under `archive/` (`plugin/bin/lib/hooks/run-dir-resolve.js`, the archive/ sibling comment) and refuses a closed run (#4151); a `PIPELINE_RUN_DIR` pointing at the archived path is rejected too. The same paragraph also states "a parked `pending-review` run stays `status: active`", which is false for exactly this path.

Observed 2026-10-31 on #4437 / PR #4662: `resolve-run-dir --spec-slug spec-4437` exited 1 ("no pipeline run directory resolved"), so the command the plugin itself recommended stops at its first step. The merge completed only by binding to the archived dir by hand; every downstream CLI the merge procedure calls (`compose-context.js`, `pr-checklist.js`, `closing-links.js`, `log-decision.js`, `teardown-run`, `release-claim.js`) accepted the archived path.

## Deliverables

- Merge mode adopts the archived run when no live run resolves: the newest `archive/*-spec-{n}` dir (same whole-segment slug match as the live resolver, #3865) whose `run-state.json` carries a `pr` object. Adoption is read-only — no re-open, no re-archive, no new run dir minted.
- The existing binding check (`config.yml` `spec:` equals `{n}`) and the Preconditions apply unchanged to an archived run; `{worktree-path}` falls back to `run-state.json`'s `worktreeAtClose` when `worktree` is null.
- Post-merge writes target the archived path (as `pr-first-merge-post-merge.md` Step 4.2 already does once reconcile archives), and Step 4.2's reconcile treats the already-archived run as a no-op.
- `merge-mode.md` drops the false "stays `status: active`" claim and says a parked run may already be archived.

## Acceptance Criteria

- A test builds a pipelines root holding only `archive/{ts}-spec-42/` (`status: clean`, a `pr` object, `config.yml` `spec: 42`) and shows merge mode's run resolution returns that archived path; the same fixture with no `pr` object, or with `spec: 43`, still stops.
- A live, non-archived match still wins over an archived one for the same slug.
- Re-running `/claude-tweaks:wrap-up #{n} merge` on a run left in the #4437 state reaches the Preconditions (PR state read) instead of stopping at resolution.
- `grep -F 'a parked `pending-review` run stays `status: active`' plugin/skills/wrap-up/merge-mode.md` returns nothing (it matches line 11 today).
- `npm test` passes.

## Release Note

`/claude-tweaks:wrap-up #N merge` can merge a PR whose pipeline run wrap-up already archived, instead of stopping with "no pipeline run directory resolved".

## Technical Approach

### Key Files

- `plugin/skills/wrap-up/merge-mode.md` — archived-run fallback in Resolve the run; drop the stays-active claim
- `plugin/bin/lib/hooks/run-dir-resolve.js` — archived-run lookup for merge mode (or a dedicated helper beside it)
