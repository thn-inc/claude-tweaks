# 3721: archive-run: commits the archive move on the current branch without reporting the commit or that it is unpushed

Surface: terminal

## Current State

`hooks.js archive-run --run <dir>` calls `archiveRunDir` (`plugin/bin/lib/reconcile/archive-merged.js`). When the run's `work/` is git-tracked, that function `git mv`s it into `.claude-tweaks/pipelines/archive/` and commits on the main checkout's current branch (`archive-merged.js:1302`, `[reconcile] archive run {runId}`, scoped to its own paths per #2241). The function returns only `{ ok: true, movedEntries }` (`archive-merged.js:1503`), so the CLI (`plugin/bin/hooks.js:1249-1252`) prints the `moved: …` lines and `claude-tweaks: archived {run-id}`. Nothing tells the caller that a commit landed, on which branch, or that it is unpushed.

Observed twice:
- In a consuming project (the original request below): the silent commit left local `master` ahead of origin, and a deploy script hard-stops on that.
- In this repo on 2026-10-21: a `/claude-tweaks:sweep` run archived 69 run dirs via `archive-run`. Four of them carried tracked `work/` and produced four unreported `[reconcile] archive run` commits on local `main` (`d48c523e0`, `6cf4efb34`, `325facfe8`, `d447003fe`). They were only noticed through a manual `git log`.

#3396 tracks the broader mechanism (unpushed reconcile archive commits on the main checkout). This record is the output gap only, which is separately fixable.

## Deliverables

1. `archiveRunDir` reports the commit it made: on success with a commit, its return value carries `commit: { sha, branch }` (short sha of the `[reconcile] archive run` commit, plus the checked-out branch name). `commit` is absent when no tracked content moved and no commit ran.
2. `hooks.js archive-run` prints one line after `archived {run-id}` whenever `commit` is present: `claude-tweaks: committed {sha} on {branch} (not pushed — {n} ahead of {upstream})`. When the branch has no upstream, the parenthetical reads `(no upstream configured)`. When the ahead-count probe fails, it reads `(push state unknown)`. The line never fails the verb.
3. The reconcile archival path that calls `archiveRunDir` surfaces the same `commit` field in its per-run result entry, so `hooks.js reconcile --json` consumers see it too.

## Acceptance Criteria

1. Archiving a fixture run with tracked `work/` returns `commit.sha` matching `git rev-parse --short HEAD` after the call, and `commit.branch` matching the checked-out branch. Archiving a fixture with no tracked content returns no `commit` field.
2. `archive-run` stdout on a tracked-work fixture contains a line matching `/^claude-tweaks: committed [0-9a-f]{7,} on \S+ \((not pushed — \d+ ahead of \S+|no upstream configured|push state unknown)\)$/m`. On an untracked-only fixture, stdout contains no `committed` line.
3. The ahead count is correct: a fixture whose branch tracks an upstream at the pre-archive commit reports `1 ahead`.
4. The reconcile `--json` run entry for an archived tracked-work run includes the `commit` object.
5. Existing `tests/archive-run-verb.test.js` cases still pass unchanged, including the `moved:`-line cases.

## Release Note

archive-run now tells you when it commits the archive move, on which branch, and whether that commit is still unpushed.

## Technical Approach

Capture the commit's sha right after the successful `commitGit` call in `archiveRunDir`, using `git rev-parse --short HEAD` plus `git symbolic-ref --quiet --short HEAD` through the same `runGit` seam, and thread it into the success return. In `hooks.js`, compute the ahead count with `git rev-list --count @{upstream}..HEAD` (anchored `-C mainRoot`), degrading to the two fallback parentheticals. Reconcile's archive call site copies the field into its result entry. Pushing, or skipping the commit on the integration branch (the request's optional alternatives), is out of scope. Those are behavior changes that belong to #3396's mechanism decision.

### Key Files

- `plugin/bin/lib/reconcile/archive-merged.js` — `archiveRunDir` returns `commit: { sha, branch }` after a successful commit; the reconcile call site (around line 1870) carries it into the run entry
- `plugin/bin/hooks.js` — `archive-run` prints the committed/ahead line
- `tests/archive-run-verb.test.js` — new stdout assertions for the committed line
- `tests/reconcile.test.js` — `archiveRunDir` return-shape assertion for `commit`

## Gotchas

- `archive-run`'s stdout is documented as informational human text that no caller parses (`hooks.js` comment above `archiveRunDir`), so adding a line is not a contract change. The `--json` run-entry field is additive.
- Resolve the ahead count from `mainRoot`, not from `process.cwd()`. A worktree cwd has a different HEAD (`[IL-127]`-style shadowing).
- An unborn or detached HEAD has no symbolic ref. Report the branch as `detached` rather than throwing.

## Original request

archive-run: commits the archive move on the current branch without reporting the commit or that it is unpushed

**Summary:** `hooks.js archive-run` commits the archive move on the main checkout's current branch, but its output never mentions the commit or that it is unpushed.

**Kind:** Gap

**Affected component:** `bin/hooks.js archive-run` → `bin/lib/reconcile/archive-merged.js` (around line 1169)

**Use case:**
After `close-run`, `hooks.js archive-run --run <dir>` was run in the main checkout, which was on the integration branch (`master`). It `git mv`'d the run's `work/*-spec.md` files into `pipelines/archive/` and committed them as `[reconcile] archive run <run-id>`. The commit is correctly scoped to its own paths (#2241). The CLI output listed only `moved: …` lines and `archived <run-id>`. It never said that a commit was made, on which branch, or that the commit was not pushed.

In this project, local `master` being ahead of `origin/master` is a hard stop for the deploy script, which refuses to run until the commit is pushed. The remote host's nightly backup also commits and pushes without pulling, so a push made later, but not deployed, can leave that backup's push rejected. The commit was only noticed by chance (`git worktree list` showed `master` at a new SHA), and it took a push plus a deploy to clear.

Repro:
1. Main checkout on the integration branch, in sync with origin.
2. `hooks.js close-run --run <run-dir>`, then `hooks.js archive-run --run <run-dir>` for a run whose `work/` holds tracked spec files.
3. `git status -sb` now shows `ahead 1`, but nothing in the archive-run output said so.

Suggested change: have `archive-run` (and the reconcile pass that calls the same code) report the commit in its output, for example `committed <short-sha> on <branch> (not pushed — <n> ahead of <upstream>)`. Optionally, offer a `--push` flag, or skip the commit when the checked-out branch is the integration branch and leave the moves staged with a note. At minimum, say that the commit exists.

Related: #3396 tracks the same symptom in this repo: unpushed `[reconcile] archive run` commits on the main checkout's local `main`. Its Deliverable 2 asks which mechanism leaves them there. This report is that mechanism seen from a consuming project, plus the output gap, which is fixable separately.
