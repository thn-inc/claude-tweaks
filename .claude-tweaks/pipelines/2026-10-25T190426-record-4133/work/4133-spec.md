# 4133: Harden the test-impact tracer's module resolution and shell-command parsing

Origin: ledger resolve gate (#4024, ledger row 22)
Defer-reason: genuinely-larger

## Current State

`tools/test-impact/tracer.js` approximates what a test reads, and `plugin/skills/test/impact-selection.md`'s Known limits name module loads and non-node children as approximated. Three gaps behind that wording were found while building #4024: the resolver ignores `require.resolve`'s `paths` option and a dependency's `package.json` `main`; a spawned command line such as `bash -o pipefail -c ...` or `env FOO=1 git ...` is not parsed as a shell command, so the script or git subcommand inside it is not recorded; and the resolver records every candidate path it probes as an existence read, which makes traces about five times larger than the files actually read. The first two can leave a read unrecorded, which CI's full suite catches before a merge; the third costs map size only, and shrinking it is unsafe unless an earlier candidate appearing still changes what `require` returns in the map's view. Each is a separate mechanism in one file with its own fixtures.

## Deliverables

- Resolve `require.resolve(request, { paths })` and a dependency's `package.json` `main` the way Node does, recording the files read and the candidates probed.
- Parse `bash -o <opt> -c`, `sh -c` and `env VAR=value cmd` wrappers when looking for the script or git subcommand a child runs.
- Measure the candidate volume per test and report whether it can shrink without losing a resolution change; shrink it only if it can.

## Acceptance Criteria

- [ ] A fixture test per mechanism fails on the current tracer and passes after.
- [ ] `tests/test-impact-tracer.test.js` stays green and the Known limits paragraph names only the approximations that remain.

## Release Note

The test-impact tracer follows more of what a test reads, so subsets miss less.
