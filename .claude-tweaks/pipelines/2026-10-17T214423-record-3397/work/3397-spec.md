## Current State

`/claude-tweaks:build`'s plan-authoring checks (`plugin/skills/build/plan-authoring-checks.md`) have no rule for deriving a "every reader of X" inventory. Record #3358's plan derived its marker-reader inventory from greps for marker literals (`<!-- `, `## Verification Brief`, named marker prefixes). It missed six readers that match on plain sentences or on prefixes the greps never named: `tidy/SKILL.md`'s parent-gate re-query, `release/bookkeeping.md`'s `Shipped in v…` check, `_shared/headless-self-report.md`'s `Resolved build:` check, the retry-marker prose callers, and `health-core/materiality-digest.js`. The whole-branch review caught four and `/claude-tweaks:review`'s lens 3b one more. That cost an extra fix wave, a re-review and two PR-body inventory rewrites.

## Deliverables

1. Add a check to `plugin/skills/build/plan-authoring-checks.md`. When a spec's deliverables say to apply something "at every reader of" a value (comments, markers, labels, files), the plan derives the inventory from the read call sites (`--json comments`, `/comments` REST paths, `issue_read`/`get_comments`, `.comments[]`, `listComments`, and so on), then classifies each hit. Greps for the value's literal text are a supplement, never the source.

2. Cite #3358's six missed readers as the motivating example, in one sentence.

## Acceptance Criteria

- `plugin/skills/build/plan-authoring-checks.md` carries a bold-paragraph check naming read-call-site derivation for reader inventories.

- A prose conformance test pins the check's key phrase, with a pre-change negative control that proves the pin can go red.

## Release Note

`/claude-tweaks:build` now tells plans to find every reader of a value from its read call sites, so a reader sweep no longer misses readers that match on plain text.
