# 4170: Re-surface a Queue-writes item whose execution failed after the unattended console resolved it apply

Origin: spec #3946 review (lens 3c, tiebreak-confirmed), refs #3946

Defer-reason: genuinely-larger

## Current State

Under `unattended`, `plugin/bin/console-resolve.js` resolves every Queue-writes item to `apply` (`SECTION_STANCES` in `plugin/bin/lib/console/resolve.js`) and writes that resolution to `{run-dir}/console.json` before `plugin/skills/wrap-up/review-console.md`'s "On approval" step 7 executes it. When execution then fails, nothing rewrites the item's recorded resolution:

- #3946's `.shadow-dup` path: a non-zero `shadow-dup-proposal.js` exit logs one Degrade-trace `SKIP` ("copy stays in staged/, not filed this run") and the item is not filed.
- Every Queue write: a failed `gh issue create` "renders in Queue writes as today" (`plugin/skills/wrap-up/refused-proposals.md`).
- #3949's can't-tell filings (folded in from #3949's review, lens 3c, tiebreak-confirmed): `plugin/bin/console-resolve.js` writes each can't-tell item `filed` (plus a `filings` summary) to `console.json` before `plugin/bin/console-filings.js` and the record creates run. A session that dies between that write and the creates leaves no record and no residue, and the needs-human re-run line `review-console.md` carries is never sent. The re-run (`console-filings.js --only`, deduplicated by fingerprint) would work, but nothing points to it.

`plugin/bin/lib/console/residue.js`'s `UNRESOLVED_RESOLUTIONS` holds only `pending` and `keep-staged`, and reconcile's `console-never-rendered-staged-pending` check (`plugin/bin/lib/reconcile/escalate-residue.js`) fires only when no console rendered, so an unfiled item is archived with the run and never shown to a human again. The `SKIP` line in `decisions.md` is its only trace.

## Deliverables

- [ ] A sanctioned way to rewrite one `console.json` item's resolution after execution (e.g. a `console-resolve.js` verb or a `console-residue.js` flag), anchored and locked like the other run-dir writers.
- [ ] `review-console.md` step 7 (shadow-dup compose failure and failed create) and `refused-proposals.md`'s failed-create line use it to record a re-surfaceable resolution (`keep-staged`) with the failure as its reason.
- [ ] A can't-tell filing reads as residue from the moment `console-resolve.js` plans it until its record exists (or is deduplicated): either `console.json` records it in a pending-filing state the residue reader counts, rewritten to `filed` after the create, or the residue reader checks `filings` against created records. *As built:* the second option, with "created records" read offline as the console dir's `decisions.md` `- AUTO … [already ]filed as #N (work-fingerprint {fp})` lines (`FILED_LINE_RE`, moved into `residue.js`) — no forge call from the residue reader, which the session-start banner runs; an unmatched planned filing reads as the derived, never-stored `filing-pending`.
- [ ] `console-residue.js`'s Needs-a-human block and the session-start residue notice list such an item with its paste-ready `cat` line.

## Acceptance Criteria

1. A console-auto fixture whose Queue-writes item fails execution ends with that item `keep-staged` in `console.json`, and `readRunResidue` reports it.
2. A shadow-dup compose failure (`shadow-dup-proposal.js` exit 2 or 3) takes the same path, and its `SKIP` line still appears.
3. An unattended console whose can't-tell filings never ran (the session stopped after `console-resolve.js`) is reported by `readRunResidue` and refuses archival, naming the re-run `console-filings.js --only` command.
4. A successful Queue write keeps `apply`, and a filed or deduplicated can't-tell item reads resolved; `npm test` passes.

## Release Note

A queued record the Review Console could not file now comes back as unreviewed residue instead of disappearing with the run.

## Technical Approach

### Key Files

- `plugin/bin/console-resolve.js` / `plugin/bin/lib/console/resolve.js` — post-execution resolution rewrite (*as built:* `console-resolve.js --set-item` over a new `plugin/bin/lib/console/item-resolution.js`, which owns `.console.lock` shared with the `console-residue.js` ack; `resolve.js` and `console-filings.js` unchanged)
- `plugin/bin/lib/console/residue.js` — residue predicate
- `plugin/skills/wrap-up/review-console.md` — step 7 failure paths
- `plugin/skills/wrap-up/refused-proposals.md` — failed-create line
- `plugin/bin/console-filings.js` — the can't-tell filing executor whose completion the rewrite records
