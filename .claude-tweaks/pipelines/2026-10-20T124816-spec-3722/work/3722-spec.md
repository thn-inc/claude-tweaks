# 3722: Adopt native re-wake for nested-dispatch children on Claude Code 2.1.302+

Origin: #3714 probe comment

Defer-reason: genuinely-larger

## Current State

#3714's live probe on Claude Code 2.1.302 showed that a dispatched agent ending its turn while a nested `Agent` child is still live is held open, then re-woken by the child's `<task-notification>`. The dispatcher is notified only once the agent stops with no live children. The harness note attached to that notification reads: "A task-notification fires each time this agent stops with no live background children of its own." In the bare-end variant the child ended at 406 and was collected at 423, with no interim result reaching the dispatcher.

The shipped rule from #3078 works differently. It keeps the turn alive with chained `sleep 20` Bash calls, at most 60 (20 minutes) per wave. That is the shape Claude Code's block message for sleeps over 20 s discourages. `_shared/subagent-dispatch-core.md`'s "Background work" paragraph also states "A dispatched agent is never re-woken once its turn ends". That claim was observed on older versions (#1965, #2271) and is false on 2.1.302.

A `Monitor` watch armed before the turn ends also re-wakes the agent. But every stop while the watch is live hands the dispatcher an interim result ending in a `STATUS:` line, 9+ for one dispatch, so a Monitor cannot serve as the bound timer as it stands.

## Deliverables

Decide and document how older Claude Code versions are handled: a minimum-version gate, a version probe, or `sleep 20` kept as the fallback path. Back the decision with a probe on at least one pre-2.1.302 version, or by citing the Claude Code changelog entry that introduced held-open subagents.

Design how the per-wave bound and the self-judge / `STATUS: BLOCKED` fallback fire when the agent is not polling, i.e. what wakes it at the bound without sending the dispatcher interim results.

Rewrite the nested-children rule in `_shared/subagent-dispatch-core.md`, `dispatch/task-prompt.md` item 7, and both fenced templates. Correct the core "Background work" paragraph's never-re-woken claim.

Confirm `plugin/bin/lib/hooks/subagent-stop.js`'s pending-dispatch handling (#3015) grades an intermediate stop with live children correctly under the new rule.

Update `tests/foreground-execution-instruction.test.js`'s SHARED_RULE and PRIMITIVE pins.

## Acceptance Criteria

A live probe, posted on this record, shows a dispatched agent following the new rule collecting a nested child's result with no wait calls on Claude Code 2.1.302.

Behavior on a pre-2.1.302 version is either verified by a probe or explicitly gated.

All four copies of the rule agree, and the agreement test goes red on a mismatched copy.

The core "Background work" paragraph no longer states the never-re-woken claim unqualified.
