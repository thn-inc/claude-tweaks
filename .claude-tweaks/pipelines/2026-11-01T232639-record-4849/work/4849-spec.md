# 4849: Granted records with a stale open PR are stuck: resume and dispatch refuse each other

**Related:** #4736

## Current State

`plugin/bin/dispatch-resume.js:490` looks for a stalled PR only at `worktree-dispatch-record-{issue}`. A PR on any other head, such as `worktree-record-3942`, reads as `no-pr`, and the refusal says to run `/claude-tweaks:dispatch #N`. Dispatch's queue pull then drops that record because it has an open linked PR (`open-pr-exclusion-report.md`), and says it is not eligible until the PR merges or closes. Neither path can act.

Observed 2026-11-01 after tidy released stale claims on #3942, #3977 and #4347, all `priority:high` with `auto:build`. Draft PRs #4444, #4445 and #4476 are all `CONFLICTING`, last touched 2026-10-26/27. `dispatch-resume.js` accepted #3977 and refused #3942 and #4347 with `no-pr`.

These records are invisible as well as stuck. `/claude-tweaks:backlog attention` has no row for a granted, unclaimed record whose open PR keeps it out of the queue, and tidy releases a claim without deciding what happens to its PR.

The same head shape also holds #3813 (PR #4641), #4477 (PR #4605) and #4467 (PR #4586). `resume.md:5` makes the fixed head deliberate, finding the PR by head instead of from the queue's exclusion file, because that file has no entry for a record the label pre-filter already dropped. A direct PR-side read keeps that property.

## Deliverables

- `dispatch-resume.js` finds the record's open PR through the same closing-reference connection the exclusion uses (`closedByPullRequestsReferences`), so any head name resolves, and keeps every existing safety check against the PR it finds. The worktree path and run binding derive from that PR rather than from the branch-name convention.
- `/claude-tweaks:backlog attention` renders a row for a record that holds `auto:build`, has no `bot:*` claim, has an open linked PR, and has no live run, with the runnable remedy for that record: `/claude-tweaks:dispatch resume #N` when eligible, otherwise the close-and-redispatch steps.
- Tidy's stale-claim release for a record with an open linked PR also states the PR's disposition, resume or close, in the finding and the approval text.
- A refusal never names a remedy that the next command refuses: the `no-pr` line only appears when no open linked PR exists.
- Every existing refusal still applies to a PR found this way, and a PR closing more than one record (such as #3984) refuses rather than resuming one member. `resume.md:5` states the new rule.

## Acceptance Criteria

- A test gives `dispatch-resume.js` a record whose open closing PR is on a non-`worktree-dispatch-record-` head, and it resolves that PR.
- A test proves a record with no open closing PR still returns `no-pr`, and a PR that only mentions the record without closing it does not resolve.
- A test proves the attention row renders for the granted, unclaimed, open-PR, no-live-run shape, and not for a record with a live run or a claim.
- `tests/` pins that the stale-claim finding names a PR disposition when an open linked PR exists.

## Release Note

Show and restart granted work stuck behind a stale open pull request, whatever its branch is called.
