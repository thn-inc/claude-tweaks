## Decisions (orchestrator, 2026-11-23)

Starting-list precedence is lane first, as written in `## Starting lists` (merged by the capture pass): *A lane of `driver` selects the list `driver`; otherwise a ceremony profile of `fast-lane` selects `fast-lane`; otherwise the list is `standard`. An absent or unknown lane with an absent profile is `standard`, and the `planned` event carries reason `default-list`.* The lane `express` was not observed and follows the same rule.
Added tests for `planOf`: `lane driver with profile fast-lane gives list driver`; `lane driver with a null profile gives driver`; `lane standard with profile fast-lane gives fast-lane`; `lane express with profile fast-lane gives fast-lane`; `lane unknown with a null profile gives standard with reasonCode default-list`.

## Decisions on the plan review (orchestrator, 2026-11-23, answering its three questions)

1. **`planned` is written at the claim with what is known then: Reading A.** A `/flow` claim usually knows neither the profile nor the lane yet, so its plan is usually `standard` with reason `default-list`; that is a true statement of what was known. The correction is a `replanned` event when the Config Manifesto or the ceremony verdict fixes the profile or lane (emission 4/8, #6148, now covers that moment). A claim that is passed a lane (the driver's claims) or whose run manifest already holds a profile selects the list at once. Write this rule in `docs/reference/station-events.md` beside `## Starting lists`.
2. **A selected list carries reason `other` with a `reasonText`: Reading A.** No vocabulary change. The `reasonText` is `lane driver`, `ceremony profile fast-lane` or `ceremony profile standard`; an explicit `standard` profile counts as selected. Only an absent lane with an absent profile carries `default-list`.
3. **The line's `lane` field stays the passed `--lane`: Reading A.** The manifest's lane only chooses the list. Every event of one claim carries the same lane. Test: `the planned line and the claim's other events carry the same lane field even when the manifest lane differs`.

The `planned` discriminator stays `planned:{runId}`, a re-claim in the same run (`alreadyOwned`) writes nothing, and a changed plan is `replanned`'s job.
