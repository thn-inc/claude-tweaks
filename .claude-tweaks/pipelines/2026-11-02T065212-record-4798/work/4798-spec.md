# 4798: Surface a partial Step 4.0b parent-close instead of recording a clean ran

Origin: /claude-tweaks:release v6.159.0 release-gate review (run 2026-10-31T203907-release-standalone)

Defer-reason: pre-existing-outside-diff

## Current State

When the reconcile post-merge pass (`plugin/bin/lib/reconcile/post-merge.js`, around line 419) leaves a parent unclosed in Step 4.0b (a `gh-failed` or `internal-error` skip, e.g. the close comment posted but the close failed), it still writes a clean `ran` entry carrying only `parentsClosed`. The skips land only in `decisions.md` prose, so `hooks.js` counts the run as `postMergeRan` and SessionStart never reports the parent left open. Found by the v6.159.0 release-gate review (lens 3c, tiebreak confirmed low).

## Deliverables

- [ ] Record Step 4.0b skips that left a parent open as a structured field on the post-merge entry.

- [ ] Have SessionStart count and surface those entries rather than treating them as a clean `ran`.

## Acceptance Criteria

A test drives Step 4.0b to a `gh-failed` skip and asserts the entry is not a clean `ran` and that the SessionStart summary names the parent.

`npm test` passes.
