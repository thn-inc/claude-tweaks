# 3044: Give build's AC-forwarding sample a sanctioned writer reachable from a worktree session

Origin: reflect full from #3040
Defer-reason: tangential

## Current State

`plugin/skills/build/dispatch.md`'s "Standing AC-forwarding verification (#496)" tells `/superpowers:subagent-driven-development` to copy the first per-task reviewer prompt verbatim to `$PIPELINE_RUN_DIR/sdd-dispatch-sample.txt`. `$PIPELINE_RUN_DIR` is anchored at the main checkout (`_shared/pipeline-run-dir.md`).

In a worktree-isolated session the harness refuses a Write/Edit to that path ("This session is isolated in the worktree … Edit the worktree copy of this file instead"). That is the same refusal family #1376 solved for `decisions.md`/`config.yml`/`staged/` with sanctioned CLI writers (`log-decision.js`, `set-config.js`, `stage-item.js`).

In run `2026-10-08T101832-record-3040` (#3040) the controller had to write the sample to the worktree's mirror of the run dir instead, and record a ruling. The verification step then read it from a path `dispatch.md` never names.

## Deliverables

- [ ] Either a sanctioned writer for the sample (e.g. `stage-item.js`-style `bin/write-run-artifact.js --run <dir> --name sdd-dispatch-sample.txt --file <src>`), or `dispatch.md` names the worktree-mirror path as the sample location under worktree isolation.
- [ ] `dispatch.md`'s verification step reads from the same path the copy step wrote to.

## Acceptance Criteria

- [ ] From a worktree-isolated session, following `dispatch.md` verbatim writes the sample without a harness refusal.
- [ ] The AC-forwarding verification reads it back and logs `AC-forwarding verified` with no controller ruling needed.

## Release Note

Builds run from an isolated worktree can now complete the dispatch-prompt sampling check without a manual workaround.
