# 4591: Ship the express lane on by default — express-lane defaults to true, a project opts out

Surface: backend

Defer-reason: tangential

**Related:** #4365, #4025, #4354

## Current State

`plugin/bin/lib/policy-schema.js:72` defines `express-lane` as `default: false`. So the express lane (#4025, `plugin/skills/_shared/express-lane.md`) runs only in a project whose `.claude-tweaks/policy.yml` sets `express-lane: true`. No project on the maintainer's machine sets it, so the lane has never run here. It shipped in #4354 on 2026-10-26.

**Decision (human-approved 2026-10-30, during #4365's brainstorm):** ship the lane on by default. A project opts out with `express-lane: false`. The maintainer expects most work to run through the scheduled bare `/claude-tweaks:dispatch` drain, which sweeps the post-merge sample reviews. The lane needs no new safety rule to be on by default, because it already:

- merges only when the record carries `auto:merge` or `/claude-tweaks:flow`'s own merge authorization passes (`express-lane.md` Procedure step 9);
- takes only `risk:low` × `size:low` × `ceremony:fast-lane` records with a `type:*` label and at most 3 Key Files;
- refuses frontend surfaces, protected paths (hooks, `skills/_shared/`, CI config, `package.json`, agent settings, the policy file) and `merge-sensitive-paths` (`plugin/bin/lib/express/eligibility.js`);
- requires `pr-first` and green PR CI;
- hands anything else back to the normal path.

This is Blocked by #4365, so that foreground express merges get their own sampled review before the lane turns on everywhere.

**Decision (Q1, malformed opt-out): Reading B, fail closed.** A lane that merges without a human must never be turned on by a typo in its opt-out. When `express-lane`'s resolved entry carries `invalid: true`, `express-lane.js gate` refuses every record with the reason `express-lane value invalid — treated as off`, and the express path does not run. The generic `policy-schema.js` fallback stays unchanged for every other key, and `resolve-policy.js --values express-lane` may still print the default. The gate is the one place that acts on it.
