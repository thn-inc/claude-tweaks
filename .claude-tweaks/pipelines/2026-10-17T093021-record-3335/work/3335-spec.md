# 3335: Dispatch Task calls under auto-mode: default-off — pass auto explicitly or refuse to dispatch

Surface: infra

**Related:** #3289 #3336 #2912 #3266 — refs #3225 (PR #3279)

## Current State

Whole-branch review Minor #8 on #3225 (PR #3279), pre-existing and amplified by `checkDispatchConfigGate`. `/claude-tweaks:flow` Step 1 resolves its mode in this order (`plugin/skills/flow/SKILL.md:116-119`): an explicit mode keyword in `$ARGUMENTS` first, then the `auto-mode` policy (`default-off` → `interactive`), then the intrinsic `auto` default. `/claude-tweaks:dispatch`'s Task-call command lines pass no mode token, so in a project with `.claude-tweaks/policy.yml` `auto-mode: default-off` every dispatched `/flow` call resolves to `interactive`. Interactive mode skips Step 3, so `config.yml` is never written, and in a run bound with `record-worktree --dispatch` every worktree commit is denied with a remedy (run Step 3) that interactive mode cannot satisfy. #2837's post-hoc check already fails these runs. A dispatched Task agent has nobody present, so `interactive` can never be honored there.

The mode-less command forms (8 in total):

- `plugin/skills/dispatch/task-prompt.md` — first-call fenced Task-scope block: singleton `/claude-tweaks:flow #{issue} build,test` (line ~111) and bundle `/claude-tweaks:flow "#{n1},#{n2},..." build,test` (line ~113); second-call fenced block: singleton `/claude-tweaks:flow #{issue}` / `review,polish,wrap-up` (lines ~237-238, wrapped across a line break) and bundle (line ~239).
- `plugin/skills/dispatch/SKILL.md` — the **Singleton group** line (~243) and **Bundle group** line (~245) restate both calls' commands.

**Decision (resolved 2026-10-17 in `/claude-tweaks:specify` brainstorming):** dispatch passes `auto` explicitly on both Task calls. Refusing to dispatch under `default-off` was rejected: it would leave `/claude-tweaks:dispatch`, and every human-granted `auto:build`, unusable in those projects. An explicit mode argument is the sanctioned override (`_shared/auto-mode-contract.md`: "an explicit mode arg always wins"; precedence CLI arg > pipeline config > project policy > skill default). `auto-mode` chooses the prompting style; the separate `autonomy` ceiling bounds what a headless run may do — under `auto` at `supervised`, a dispatched run still stops at its HARD-GATEs and still parks at `pending-review` for a human merge.

4. Add a prose-conformance test, `tests/dispatch-flow-explicit-auto-mode.test.js`, pinning that every `/claude-tweaks:flow` form in those two fenced blocks and on those two `SKILL.md` lines carries `auto` after its step list.

## Release Note

Dispatched pipeline runs now always start in hands-off mode, so they no longer get stuck behind the configuration safeguard in projects that turned off automatic mode.

## Technical Approach

Prose change plus one test. `/flow` Step 1 detects mode keywords anywhere in `$ARGUMENTS`, and `auto` is not a step name, so appending it after the step list is unambiguous. The `DISPATCH_HEADLESS=1 ` marker the dispatching session may prefix goes *before* `/claude-tweaks:flow`; the new `auto` suffix goes after the step list — the two are independent.

The test reads the live `task-prompt.md`/`SKILL.md` text — a legitimate live-corpus read under the `skill-prose-conformance-tests` project skill, since the pinned property is the shipped command text itself. Slice `task-prompt.md` at its `## First call — build,test` and `## Second call — review,polish,wrap-up` headings, take each section's first fenced block, and match `/claude-tweaks:flow` forms with whitespace-tolerant regexes (`\s+` across the second call's line break). Slice `SKILL.md` to the lines starting `**Singleton group**` and `**Bundle group**`.

### Key Files

- `plugin/skills/dispatch/task-prompt.md` — `auto` on the 4 command forms in the two fenced Task-scope blocks, plus the rationale sentence
- `plugin/skills/dispatch/SKILL.md` — `auto` on the 4 restated forms (Singleton group and Bundle group lines)
- `tests/dispatch-flow-explicit-auto-mode.test.js` — new prose-conformance pin

## Gotchas

- The second call's singleton form wraps across a line break inside the fenced block (`/claude-tweaks:flow #{issue}` then `review,polish,wrap-up`); put `auto` on the step-list line and match whitespace across the newline.
- The fenced blocks are inlined verbatim into every Task call (`SKILL.md`: "Do not paraphrase or summarize either template"); edit only the step-list tail, never the surrounding wording.
- Leave the teardown path alone: `two-call-gate.md` section 5 calls `/claude-tweaks:wrap-up {target} cleanup-only` directly, never through `/flow` (#1766) — that path is #3336's territory.
- `plugin/skills/dispatch/sequential-execution.md:58` still describes teardown as `/claude-tweaks:flow {target} wrap-up`, contradicting `two-call-gate.md`'s direct-wrap-up form — pre-existing and out of scope; report it as a follow-up rather than folding it in.
- Out of scope: `_shared/policy-schema.md`'s `auto-mode` row says the key governs standalone `/build` and unattended `/tidy` (with `/flow` still defaulting to `auto`), while `flow/SKILL.md:118` lets `default-off` lower `/flow` — this disagreement stays as is (declined during shaping) and gets its own record.
