# 5383: Run the tests of already-injectable CLIs in-process

Surface: backend
Risk-flags: none

## Overview

94 CLIs already export `run(argv, deps)`, and most of their tests call it with fakes. Thirteen test files still start a real process five or more times each, 156 processes per suite run: `review-coordination.js` 43, `digest-rollover.js` 32, and eleven smaller ones.

This record moves those thirteen files onto the in-process helper. The CLI changes are small: each covered CLI exports its `realDeps` (20 of the 94 export `realDeps` or `defaultDeps` today), and a read of a process global outside `deps` moves onto `deps`.

**Estimated tasks:** 6

- Test files that start such a CLI fewer than five times. Those calls already are the smoke tests.
- Tests that run a CLI through a skill bash fence.

## Technical Approach

Swap each file's local spawn helper for a `runCli` call returning the field names the file already asserts on. The e2e files (`diff-facts-cli-e2e`, `risk-flags-packet-e2e`, `release-local/acceptance`) keep one real-process test each as their smoke test; their remaining cases assert on output, not on the process.

Why `run(argv, deps)` and not a new `main`: see #5374's Decision Rationale.

The entry contract, set by #5374:

- The CLI exports `run(argv, deps)` and `realDeps`. `argv` is `process.argv.slice(2)`. `run` returns an integer exit code, or a Promise of one when the CLI is async.
- The script entry is the last statement of the file: `if (require.main === module) process.exitCode = run(process.argv.slice(2), realDeps);` (async: `run(…).then((code) => { process.exitCode = code; })`).
- The CLI reaches the outside world only through `deps`. Standard io keys, each present only when the CLI uses it: `stdout(text)`, `stderr(text)`, `cwd()` (returns a string), `env` (a plain object, read-only), `stdin()` (returns the whole input as a string), `homeDir()` (returns the user's home directory; real value `() => os.homedir()`). Other seams (`runner`, `now`, `mainRoot`, …) keep their names.
- Above the guarded entry, and in everything `run` calls: no `process.exitCode`, no `process.exit()`, no `process.chdir()`, no write to `process.env`.
- A relative path is resolved against `deps.cwd()`, never left to `path.resolve` or `fs`, which use the real working directory.
- Every child process is started with `cwd: deps.cwd()` and `env: deps.env`. A child started without them inherits the test runner's working directory and environment, so a `gh` or `git` stub on an injected `PATH` is skipped and the real tool runs.

## Gotchas

- `tests/bin-lib/log-decision/append.test.js` spawns several `log-decision.js` processes at once to prove the locked append. That test needs real processes; convert only the others.
- `digest-rollover.js` and `release-local.js` call `gh` through a `runner` dep; the tests stub `gh` with a script on `PATH`. In-process, either inject a fake `runner` through `deps`, or make sure the real runner passes the injected `env` to the child.
- `plugin/bin/check-artifact-overwrite.js` is called by `plugin/bin/lib/flow/artifact-overwrite-check.js`; update that caller in the same change if the deps shape changes.
- `risk-flags.js` calls `log-decision.js`'s `run` in-process and passes its `deps` through whole. The fakes must carry every key `log-decision.js` reads (`now`, `cwd`, `mainRoot`, `stdout`, `stderr`).
- The "today" counts come from one full-suite run on main @ 79cd5710d (2026-11-13) with a `NODE_OPTIONS=--require` preload that logs every node process. They are a floor: a test that spawns with a replaced `env` drops `NODE_OPTIONS`, so its children were not counted. Re-measure before starting.
- `node --test` runs each test file in its own process, so in-process state is shared only between the tests of one file.
- A CLI that relied on process exit to drop an open handle, timer or signal listener keeps the test file alive in-process. `run` closes what it opens.
- A test stays on a real process only when the process is its subject (a signal, a lock held across processes, a detached child, a closed stderr, `process.exit` timing). Use `spawnCli` for it and list it in the PR body.
- A test that fakes `gh` or `git` with a stub on `PATH`, or isolates the home directory with `HOME`, works in-process only when the CLI passes `deps.env` to every child it starts and reads the home directory through `deps.homeDir()`. Convert such a test by threading `env` to the child, or by injecting a fake `runner` through `deps`. If neither fits this record, leave the test on `spawnCli` and list it; never let it run with the stub silently skipped.
- Source-scan suites read `plugin/bin` files as text and pin their shape; `tests/bin-lib/exit-code-conformance.test.js` reads each file's last `require.main` block. Run the full suite before pushing, not only the converted files.
