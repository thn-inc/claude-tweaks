## Deliverables

1. **One composer.** A new pure module, `plugin/bin/lib/reproduction-log.js`, holds all seven forms. Each form returns `{ status, step: 'Reproduction', text, reversibility: 'high' }`, the fields `formatEntry` takes. The formatted line is byte-identical to the base commit's template with its placeholders filled.
2. **`categorise-reproduction --run`.** `categorise-reproduction <A.json> <B.json> --lens <lens> --run <dir> --only confirmed|unconfirmed` appends its lines under `## /review`, one line per finding and one line for the two sides of a coincidence, in the order of the printed result. Its JSON gains `entries`, the composed lines in the shape `log-decision.js --entries` takes, and `logged`: `true` when they were appended, or `false` with one stderr line when the append threw, which never changes the exit code. Without `--run` the output, the exit codes and the argument check are unchanged, and that form stays: a standalone review has no run directory.
3. **Two calls, in one order.** `--only confirmed` writes forms 1 and 2. `--only unconfirmed` writes forms 3 and 4, and `--hold <file>` names unconfirmed entries that get no line. The split is recomputed from the same two files on each call, so both calls see the same findings in the same order. Decided 2026-11-16: `--run` requires `--only`, and a `--run` call without it exits 2, so the one order the CLI offers is confirmed lines first and unconfirmed lines second, with no judgment about which form to use. Decided 2026-11-16: the CLI does not de-duplicate. `decisions.md` is append-only and a second line for the same finding can be legitimate (a delta review reproduces it again; a finding is staged again after a verdict, #4583), so code cannot tell a repeat from those. A call is made once per pair, and its lines go in with one write (`appendEntries`), so a call writes all of them or none.
4. **Judged lines.** A new verb, `review-coordination.js log-reproduction-judgment <judgment.json> --lens <lens> --run <dir>`, writes one of forms 5 to 7 from a one-object file: `{ kind: "absence-refuted", path, symbol, command, foundAt }`, `{ kind: "vacuity-downgraded", path, line }` or `{ kind: "vacuity-reconfirmed", path, line, command, output }`. **Closed rule:** these three kinds are the complete set. Any other kind is refused with exit 2 and one line naming the kind and the three accepted ones. A plan review that finds a fourth judged line adds its refusal case as a plan amendment, never as a `needs-human` gap. The verb formats what the session reports. It does not check that the command ran or that the output is real, which is the trust a hand-written line carries today, and its docs say so. `reversibility` is `high` for all seven forms because all seven templates say so.
5. **Prose.** The reproduction bullets in `step3-lens-dispatch.md` name the calls and no longer carry a template. They keep what the reader must do with the result: surface `severityContested` in the routing entry, add the `nearLocation` clause to a routing row, send `unconfirmed` findings to Step 3.7, run the absence check before the `--only unconfirmed` call, and hold forms 3 and 4 at `medium`. `step3-cross-lens-corroboration.md` step 4 names the same Mode 1 call with `--only unconfirmed`, plus `--hold` when the pass promoted or the absence check refuted a finding, for the lines it deferred.
6. **Tests follow the writer.** Each test listed under Current State takes its expected line from the composer, not from the prose. The step yield reader's pair-line test (#5556) generates each form from the composer and no longer reads `step3-lens-dispatch.md`.
7. **Docs.** `docs/plugin-structure.md` describes the new options and verb. `plugin/skills/release/SKILL.md:196` names the composer as the home of the form it quotes.

## Technical Approach

`categoriseReproduction` does not change. The CLI calls it, passes the result to the composer, formats each entry with `formatEntry` and appends the batch with `appendEntries` (`plugin/bin/lib/log-decision/append.js`), under one lock and with one timestamp from `deps.now()`. The run directory goes through the existing `anchorRunDir` helper, unchanged; this record adds no path rule.

The hold file is a JSON array of entries copied whole from the `unconfirmed` list the first call printed. Its typical contents are the absence claims the ground-truth check refuted and, at `medium`, the findings corroboration promoted. Decided 2026-11-16: a hold entry is the whole unconfirmed entry as printed, and it matches on `source`, `path`, `line` (absent for a finding with no line) and `text`. An entry that matches no unconfirmed finding, or more than one, exits 2. `--only` and `--hold` need `--run`, and `--hold` needs `--only unconfirmed`; AC5 lists each refusal.

The session calls with `--only confirmed` first. When the printed `unconfirmed` list is empty no second call is needed (the lens 3f vacuity check and the `severityContested`/`nearLocation` routing duties still apply to the confirmed findings). Otherwise it runs the absence check, and at `medium` waits for the corroboration pass, and then calls with `--only unconfirmed`, adding `--hold` when either took a finding out. Decided 2026-11-16: whether the absence check ran between the two calls stays a rule in the prose, pinned by AC11. Code cannot enforce it, because whether a finding asserts that code is absent is a reading of its text. A second call that is never made leaves that pair's unconfirmed findings with no line, and nothing in code detects it; a skipped hand-written line is equally silent today. On `logged: false` nothing was written: the session repeats the same call once, and if that fails too it writes the printed `entries` with `log-decision.js --entries`. A review resumed in a new session reads `## /review` for the pair's lines before it calls.

A lens 3f vacuity downgrade is logged after the reproduced line, not in place of it: the CLI writes form 1 or 2, then the session logs form 6 through the judgment verb. The step yield reader counts it that way (#5556: a downgrade relabels a finding already counted).

A finding with no numeric line gets its line with `{path}` alone in place of `{path}:{line}`, and the JSON lists it under `unlocated`. The Review Console cannot key such a line today either. `unlocated` appears only in a `--run` call's JSON, so AC2 holds. A coincidence needs two numeric lines (`sameLocation` in `coordination.js`), so form 4 never names a finding without one.

`command`, `output` and `symbol` reach the judgment verb in a file, never on the command line (`docs/skill-authoring.md`, "Untrusted text into a shell or paste command").

The new options follow this CLI's existing hand-written parsing, as `resolve-tiebreak --root` and `--run` do. Checked on 2026-11-16: #5533 lists the shared argument parser (the audit's Phase 3) as not yet specified, so no record has started on it. If one has started on `review-coordination.js` when this is built, land after it.
