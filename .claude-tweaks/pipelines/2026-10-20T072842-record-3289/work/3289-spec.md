## Current State

`/claude-tweaks:flow/SKILL.md`'s Step 3 ("Pipeline Config Manifesto") states it runs in every mode
except `interactive`, writing `config.yml` and initializing `decisions.md`'s config snapshot
header before Step 4 begins — and Step 1.8 states the open-items ledger is created unconditionally
before Step 2's pre-flight checks. On this run (dispatch bundle `2026-10-16T180901-record-2999`,
covering #2999 and #3000), a first `/flow "#2999,#3000" build,test` call completed build and test
successfully (two real commits, a draft PR opened, `TEST_PASSED=true` logged) but left no trace of
either step ever running: no `config.yml` existed anywhere under the run directory or its would-be
`spec-2999/`/`spec-3000/` subdirectories, and no open-items ledger existed at
`docs/plans/*-record-2999*-ledger.md`. `decisions.md`'s `## /flow` section began directly at
"Step 2.8: claimed #2999" with no preceding Manifesto log line. This second call (review, polish,
wrap-up) had to backfill both — writing `config.yml` via `set-config.js`, scaffolding the per-spec
subdirectories per `multispec-config-scaffold.md`, and creating the ledger via `ledger/SKILL.md`'s
Create operation — before continuing, per this call's own explicit instruction not to skip the
Manifesto write.

## Deliverables

- Investigate whether `/flow`'s Step 3 and Step 1.8 have a code path that returns without writing
  `config.yml`/creating the ledger when invoked as the first of a dispatch bundle's two planned
  calls (`build,test` then `review,polish,wrap-up`) — e.g. an early-return before Step 3 on some
  input shape, or a step-list check that (incorrectly) ties the Manifesto/ledger write to the
  presence of `review`/`wrap-up` in the resolved step list.
- Add a `node --test` assertion (or a prose self-check) that a `/flow` run reaching Step 4 for
  ANY step list always has `config.yml` and a ledger file by that point, so a future regression
  here surfaces mechanically instead of being caught by a second call's own defensive instructions.
