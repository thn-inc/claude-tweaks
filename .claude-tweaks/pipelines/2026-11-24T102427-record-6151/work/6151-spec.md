Write `held` and `released` when the hold labels (`bot:blocked`, `bot:parked`, `accept:changes-requested`) are added and removed, and stop appending blocker snapshots that did not change. #### The event contract (shared with the hub plan)

Lines keep their existing fields (`v: 1`, `eventKey`, `repoName`, `recordNumber`, `kind`, `station`, `at`, `outcome`, `lane`, `sessionId`, `runId`, `payload`). New:

| Kind | Filed under station | `payload` |
|---|---|---|
| `planned` | the station the item is at when written (at the claim: `build`) | `{ process: 'build-a-record', processVersion: 1, list: string, stations: string[], reasonCode: string, reasonText?: string }`; `stations` is the full ordered list, including stations already passed |
| `replanned` | the station the item is at | `{ stations: string[], reasonCode: string, reasonText?: string, cause: { kind: 'outcome' \| 'decision' \| 'config', ref?: string } }` |
| `held` | the station the item is at | `{ why: 'blocked' \| 'parked' \| 'changes-requested' \| 'waiting-on-you', ref?: string }` |
| `released` | the station the item is at | `{ why: <same set> }` |
| `decided` | the station the decision was made at | `{ decision: 'authorize' \| 'accept' \| 'unblock', actor: string, via: 'panel' \| 'skill' \| 'rule', outcomeRef: string }` (`outcomeRef` is the `eventKey` of the `exited` it caused) |
| `exited` (extended) | unchanged | `outcome` is one of `passed \| sent-back \| failed \| stopped`; `payload.actor` always; `payload.reasonCode` for every outcome except `passed`; `payload.next` (a station id) for `sent-back`; `payload.reasonText?` |

`actor` is `agent`, `script`, `person` or `rule:<id>`. Reason codes are the closed list `REASON_CODES` (Task 2). A reason nothing knows is `unspecified`.
