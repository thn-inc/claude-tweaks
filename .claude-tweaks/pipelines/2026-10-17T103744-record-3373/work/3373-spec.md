# 3373: wrap-up verify false-fails a leave-open (pending-review) pr-first run on run-dir-archived and worktree-removed

Surface: infra

Origin: wrap-up verify on #3335

Defer-reason: pre-existing-outside-diff

## Current State

`wrap-up-engine.js verify` (`bin/lib/wrap-up/engine-verify.js`) fails a pr-first run whose Review Console merge decision resolved to leave-open (`pending-review`). Two checks cause this. `run-dir-archived` reports `fail — original path still present`, and `worktree-removed` reports `fail — worktree still listed`. Leave-open is the designed resting state for such a run. `review-console.md`'s Auto-resolution short-circuit routes there whenever a group member lacks `auto:merge` (the ungranted-member carve-out, #1802) or a `merge-check` verdict is `needs-human`. `cleanup-procedures-execution.md` Section C then forbids removing the worktree of an unmerged PR ("A PR that hasn't merged has nothing to prove containment against"), and the reconciler archives the run directory after the human merges. Neither check reads the merge outcome, so `execution-and-verification.md`'s Verify step exits 3 and the run must report `BLOCKED` with no closure line. Observed on run `2026-10-17T093021-record-3335` (#3335, PR #3369, autonomy `unattended`, no `auto:merge` grant), which was otherwise clean. The only existing escape is `verify-expectations.json`'s `deferred` set, whose skip detail reads "deferred to parent console" — a multi-spec shape that is wrong for this case.

## Deliverables

- `engine-verify.js`'s `run-dir-archived` and `worktree-removed` checks return `skip` with a reader-facing reason such as `pending-review — teardown follows the human merge`, instead of `fail`, when this run's Review Console merge resolution is leave-open (read from `console.json`'s merge resolution, or an equivalent run-dir fact written at resolution time). Neither check reads the PR's live merge state for this.
- Do not change the merged path: once the PR has merged, both checks still require the teardown and still fail when it is missing.
- Add unit tests in the existing `engine-verify` test suite for leave-open (skip), merged with teardown done (pass), and merged without teardown (fail).

## Acceptance Criteria

1. For a run whose `console.json` records merge resolution `leave-open`, `verify` reports `run-dir-archived` and `worktree-removed` as `skip` with the pending-review reason, and exits 0 when every other check passes.
2. For a run whose merge resolution is `merge`, both checks behave exactly as today, including `fail` when the run dir or worktree remains.
3. The new tests fail against the current `engine-verify.js`, which can be shown by reverting the change.

## Release Note

Wrap-up no longer reports a false BLOCKED when a pipeline run correctly parks its pull request for a human merge.
