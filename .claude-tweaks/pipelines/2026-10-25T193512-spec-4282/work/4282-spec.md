# 4282: Windows: release bootstrap and release-local write guards follow symlinks they are meant to refuse

Origin: #2767 class split — classification of windows-regression run 40169646104 (main 6a41ebe3a)

Defer-reason: genuinely-larger

**Related:** #2767

## Current State

Two release-path write guards stop refusing symlinks on win32.

**`assertSafeWriteTarget`** (`plugin/bin/lib/init/release-bootstrap.js:456`) splits `path.dirname(rel)` on `path.sep` (lines 457-458). `rel` is `/`-separated, for example `.github/workflows/release-please.yml`. On win32, `path.dirname` keeps the `/`, and `split('\\')` leaves a single segment, `.github/workflows`. The per-segment `lstatSync` (line 463) then runs on `root\.github\workflows`. That call follows the symlinked `.github` and gets ENOENT, which counts as "doesn't exist yet" (`continue`). The intermediate symlink is never checked. `writeBootstrapFiles` then runs `mkdirSync` (line 425), which creates `workflows` inside the symlink target, outside the repo root. The realpath check after mkdir (line 426) still refuses the file write, so only the directory escapes. The test shows it: the outside directory reads back `['workflows']`.

**`writeInsideRoot`** (`plugin/bin/release-local.js:285`) realpaths the parent directory (line 290) and opens the leaf with `O_WRONLY | O_CREAT | O_TRUNC | O_NOFOLLOW` (lines 298-301). The comment at line 283 says this refuses a symlinked file at the kernel. `fs.constants.O_NOFOLLOW` is undefined on win32, so the OR silently drops it. A symlinked leaf is followed, and the file outside the root is overwritten. The test shows it: the `assert.throws` for the symlinked leaf at line 23 reports `Missing expected exception`.

2 tests in 2 files fail on Windows (line numbers as of 988cc584d).

### Failing tests

- `tests/bin-lib/init/release-bootstrap.test.js:418` — bootstrapRelease: a symlinked .github refuses to write through it; nothing lands outside root (ledger row 36)
- `tests/bin-lib/release-local/cli.test.js:18` — writeInsideRoot: refuses a symlinked leaf and a directory whose real location is outside the root; writes a plain file

## Deliverables

- In `release-bootstrap.js`, split the relative path into segments with a pure helper, `segmentsOf(rel, pathImpl = path)`. It splits on both separators and drops `.` and empty segments. `assertSafeWriteTarget` lstat's every intermediate segment through that helper.
- In `release-local.js`, `writeInsideRoot` takes `constants = fs.constants`. When `O_NOFOLLOW` is not a number, it must not drop the check. Instead it refuses a symlinked leaf with `lstatSync` before the open. After the open, it compares `fstatSync(fd)` with `lstatSync(leaf)` (`dev` and `ino`), which closes the swap window. Update the line 283 comment to match.
- Neither guard may degrade silently: a missing platform constant selects the lstat path.

## Acceptance Criteria

1. AC1: `node --test tests/bin-lib/init/release-bootstrap.test.js tests/bin-lib/release-local/cli.test.js` passes on Linux.
2. AC2: a Linux-runnable win32 pin. `segmentsOf('.github/workflows/release-please.yml', path.win32)` and `segmentsOf('.github\\workflows\\release-please.yml', path.win32)` both deep-equal `['.github', 'workflows']`.
3. AC3: a Linux-runnable no-`O_NOFOLLOW` pin. `writeInsideRoot(root, 'linked.json', 'x', { constants: { ...fs.constants, O_NOFOLLOW: undefined } })` throws `refusing to write linked.json: it is a symlink`, and the outside victim file keeps its bytes.
4. AC4: go-red. Reverting the split to `split(path.sep)` fails AC2, and removing the lstat fallback fails AC3.

## Release Note

Windows: `/claude-tweaks:init`'s release bootstrap no longer creates a directory through a symlinked `.github`, and the local release CLI no longer writes through a symlinked version file.

## Gotchas

- Creating a symlink on `windows-latest` needs Developer Mode or admin rights. The failing run did create one (the assertion was reached), so the real-symlink tests can stay as Windows ground truth beside the Linux pins.
