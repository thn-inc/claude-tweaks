# 4446: Write gate never walks the command inside a command substitution or backticks

**Related:** #4303, #4242, #4247

Origin: /claude-tweaks:build of #4303 (run 2026-10-25T143627-spec-4303), SDD Task 5 ruling and final-review rounds

Defer-reason: genuinely-larger

## Current State

`plugin/bin/lib/hooks/git-command.js`'s write gate does not walk the commands inside a `$( … )` or backtick body as their own segments. A write, mkdir or git command there resolves nothing, or resolves under the wrong cwd. Each shape below was checked against bash 3.2 and 5 from a worktree of a worktree-always repo:

- `echo $(cp a /main/f.js)` and ``echo `cp a /main/f.js` `` resolve no target. Bash writes `/main/f.js`.
- **N2:** a backtick holding a separator, followed by `&`, hides the rest of the command.
- **N3:** `((…))` as the first command in a substitution gives a spurious target.
- `echo $(( $(cd /main; cp a f.js) + 1 ))` resolves `/r/f.js`. Bash writes `/main/f.js`: the cd inside a substitution inside arithmetic is not followed.
- After a cwd-cap loss, a write inside `"$( cd …; … )"` (rr7's BVsub2/BVsub3) is allowed at every version, base included.

## Deliverables

1. Walk each substitution and backtick body as a nested command list. The body inherits the enclosing segment's cwd and gets its own cd scope, which it never leaks out, matching bash's subshell semantics.
2. Report the body's write, mkdir and git targets exactly as the top level does.
3. Pin every shape above in `tests/hooks-gate-coverage.test.js`, with its bash 3.2 and 5 verdict in the comment, per `.claude/skills/shell-scanner-bash-differential`.

## Acceptance Criteria

- Each shape above, run from a worktree of a worktree-always repo, is denied wherever bash 3.2 and 5 write into the main checkout.
- A base comparison of the #4149 routine table and the #4210 cases shows no allowed-to-denied move other than the listed ones.
- Every new rule has a mutant that turns a test red.
- The four scanner suites and `perf/heredoc-scan-linearity.test.js` pass.

## Release Note

The worktree-always guard now blocks a write into the main checkout made by a command inside $( ) or backticks.
