# 4140: release preflight pack: expose the pre-major bump flags it applied in proposedVersion

Origin: reflect hindsight from #4041

Defer-reason: tangential

## Current State

`plugin/bin/lib/release-preflight/pack.js`'s `proposedVersion` computes its bump part from `preMajor` plus `release-please-config.json`'s `bump-minor-pre-major` and `bump-patch-for-minor-pre-major` flags (`readBumpFlags`, `bin/lib/release-local/manifest.js`). It exposes only `preMajor` in its result. `/claude-tweaks:release` Step 5 (`plugin/skills/release/execute.md`, #4041) re-derives a bump part from commits that arrived after the console, so its prose must tell the agent to re-read the config file's flags by hand to fold pre-major the way the pack does.

## Deliverables

`proposedVersion.value` also carries `bumpMinorPreMajor` and `bumpPatchForMinorPreMajor` (the values `readBumpFlags` resolved).

`execute.md`'s arrived-commit fold reads those pack fields instead of the config file.

## Acceptance Criteria

A pack unit test asserts both flags appear in `proposedVersion.value` for a config that sets them and are `false` for one that does not.

The execute.md fold cites the pack fields, and the conformance suite pins that citation.

`npm test` passes.

## Release Note

The release preflight pack now reports the pre-major bump flags it applied, so later release steps fold pre-major bumps from the same source.

## Technical Approach

### Key Files

- `plugin/bin/lib/release-preflight/pack.js` — expose the resolved pre-major bump flags in proposedVersion.value
- `plugin/skills/release/execute.md` — read the flags from the pack in the arrived-commit fold
