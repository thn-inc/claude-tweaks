# 3494: windows-hide-spawn-conformance stripComments blanks live code after a /* inside a // comment

Origin: build of #3417 (shared path-guard helper), conformance-lint audit and review

Defer-reason: pre-existing-outside-diff

## Current State

`stripComments` in `tests/windows-hide-spawn-conformance.test.js` runs two regexes in sequence: block comments first, then line comments. A `/*` that appears inside a `//` comment (for example `// work/*-spec.md`) therefore opens a phantom block comment that runs to the next `*/`, blanking live code in between. Any `child_process` call in that span is invisible to the windowsHide rule, which is a silent false negative. #3417's path-guard lint found the same defect when it copied this helper. Its copy undercounted `hooks.js`, `load-delta.js`, `lib/journey-health/scope.js` and `sweep-stray-run-dirs.js`, so #3417 replaced it with a single-pass stripper in `tests/path-guard-conformance.test.js`.

## Deliverables

- Replace `stripComments` in `tests/windows-hide-spawn-conformance.test.js` with a single-pass, string-aware stripper. Reuse the one in `tests/path-guard-conformance.test.js`, or move both into a shared test helper.

- Add a scanner fixture where a `//` comment containing `/*` precedes an unhidden spawn, and assert that the spawn is flagged.

## Acceptance Criteria

- [ ] The new fixture is flagged by `unhiddenCalls`, and that fixture is shown red against the current two-regex stripper.

- [ ] The live-tree test still passes. Any newly visible unhidden call it surfaces is fixed or reported.
