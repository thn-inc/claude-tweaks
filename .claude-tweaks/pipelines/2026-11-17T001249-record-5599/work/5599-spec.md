## Current State

`/claude-tweaks:review` Step 3 dispatches its lens reviewers as Task agents, two per lens at `medium` and above (`plugin/skills/review/step3-lens-dispatch.md`). The reviewing session composes each reviewer's brief from that file, sends it twice per lens, waits, and then settles each pair with several calls. The review step is the largest single cost in the standard lane.

Measured on 2026-11-15 for the design (scratch scripts over 666 sessions and 29,557 subagent transcripts; re-derive before relying on a number):

- `/claude-tweaks:review` used 88M output tokens, 13% of all output.
- A pilot that ran a simplified lens prompt as a workflow found 0 findings where the archived review confirmed 4. The brief matters, so a port must send it unchanged.

Measured on 2026-11-16 for this record, over a sample of 40,001 subagent transcripts modified in the last 14 days in this machine's claude-tweaks project directories (the scan stopped at that count):

- 9,254 lens reviewer briefs. Size: median 6,946 bytes, 90th percentile 8,773, 99.9th percentile 13,736.
- 68 sessions dispatched lens reviewers. The median session carried 630,912 bytes of lens brief text, each brief sent twice.

What Claude Code's Workflow tool does, with what is and is not established, is in #5596's Current State. The points this record depends on: a plugin ships scripts in `workflows/`, started as `{plugin}:{meta.name}`; a script cannot read a file or require a module; `agent(prompt, { model })` takes a model alias; a run cannot be resumed from another session; a Task-dispatched agent and a pipeline-driver worker have no Workflow tool. Rows this record reads from #5596's document before any code: a start by name from a skill step; a 100,000-byte `args`; where a returned value is saved and which field of the tool result names it; a workflow agent's working directory and permission mode; a reply coming back byte for byte.

Sizes on 2026-11-16 at `026e203f3`: `CLAUDE.md` is 24,571 bytes against a 24,576-byte budget (`tests/claude-md-budget.test.js:20`) and 150 lines against a 150-line budget. `plugin/skills/_shared/policy-schema.md` is 49,189 bytes and `plugin/skills/review/step3-lens-dispatch.md` 49,090, both against the 52,500-byte read limit. `plugin/skills/review/code-mode-steps.md` is 52,358.

`plugin/hooks/hooks.json` matches `Agent` and `Task` for the PreToolUse dispatch-prompt gate (`plugin/bin/lib/hooks/pre-tool-use.js:2411`) and has no matcher for `Workflow`.

Design: `docs/superpowers/specs/2026-11-15-process-efficiency-design.md`, Phase 6. Decision 0.1 there is "limited": a change must not break a run in flight on the previous release, so this path ships beside the Task dispatch, off by default.

## Deliverables

1. **A policy key**, `review-lens-dispatch`: an enum, `task` or `workflow`, default `task`, tier `advanced`, registered per `.claude/skills/policy-key-addition`. Step 3 resolves it once, with `resolve-policy.js --values review-lens-dispatch` and `--run` when a run directory exists. An invalid value resolves to `task`. The key is not a Manifesto lever. Its row in `policy-schema.md` and a `Removal condition:` comment at the key state the condition in Deliverable 8.
2. **The script**, `plugin/workflows/review-lens-fanout.js`, `meta.name` `review-lens-fanout`. `args` is `{ lenses: [{ lens, brief, model, reviewers }] }`, `reviewers` being 1 or 2. For each lens it starts that many agents in one parallel wave over all lenses, each with `brief` as its whole prompt, `model` as its model, the label `lens {lens} A` or `lens {lens} B`, and no schema. It returns `{ started: true, lenses: [{ lens, reviewers }], reviewers: [{ lens, side, text, failed }] }`: `lenses` echoes what `args` asked for, and `reviewers` has one entry for every lens and side asked for. Each `agent` call is wrapped on its own, so one that throws, returns null or returns text that is blank after trimming gives `failed: true` and `text: null` for that reviewer and leaves the others alone. Before it starts any agent it checks `args` and returns `{ started: false, reason }` for no `args`, an empty `lenses`, a lens named twice, a missing `brief` or `model`, or a `reviewers` other than 1 or 2. It holds no prompt text, no lens rule and no model name.
3. **Step 3 prose.** A new sub-file, `plugin/skills/review/step3-workflow-dispatch.md`, read only when the key resolves `workflow`. `step3-lens-dispatch.md` gains one paragraph that names the workflow `claude-tweaks:review-lens-fanout` and points at the sub-file; that naming is the opt-in the tool requires. The sub-file says: check the tool is available; compose each lens's brief exactly as the Task path does; resolve each lens's profile with `resolve-profile.js`; make one Workflow call; settle with `review-coordination.js settle-lens-replies` (#5598), called with `--only confirmed` first and with `--only unconfirmed` after the absence check and, at `medium`, the corroboration pass, in the order #5595 fixes; handle every lens under `needsSession` by its `reason`, as the Technical Approach says; then continue Step 3 where the Task path would be after pairing (the absence check, the lens 3f vacuity check, corroboration, Steps 3.5 to 3.7).
4. **Fallback.** The review uses the Task dispatch for all lenses, and logs one `SKIP` line, when: the session has no Workflow tool; the call is refused or fails before a reviewer starts; the script returns `started: false`; the run ends with no result; or the result cannot be read. The line is `SKIP … Step 3 lens dispatch (workflow fallback): condition: {one of those five, with the tool's own message when there is one} → fallback: Task lens dispatch. Reversibility: n/a.`, written through `log-decision.js --text-file`. A standalone review puts the same sentence in its report. When the run returned but a lens is under `needsSession` with reason `reviewer-unusable`, the session dispatches the unusable reviewers again through the Task path, once, and logs one `SKIP` line naming them. With the key at `task` no line is written. What the session observes for each condition: no tool (`Workflow` is not among its tools and the deferred-tool lookup does not return it); refused or failed before a reviewer starts (the call's result is an error or a permission denial); `started: false` (the returned value says so); ended with no result (the call returned with no error and the saved file is absent or holds no `result`); unreadable (`settle-lens-replies` exits 2). Decided 2026-11-16: once the session has taken the fallback it never reads a result that arrives later, and it does not wait for a run it cannot see. In the last two conditions reviewers may already have run, so that review pays for them twice; the `SKIP` line names the condition and the parked record counts it.

## Technical Approach

The brief reaches the script through `args`, one string per lens, not through a file the agent is told to read. The pilot showed the result depends on the brief, and the contract requires the output template in the prompt itself. The cost is that the session still types each brief, once per lens where it types it twice today. Nothing in the documentation limits the size of `args`. Seven lenses at the 90th-percentile brief size are about 61 KB; at the 99.9th percentile, 96 KB. #5596 probes a 100,000-byte `args`; if that probe fails, this record stops and reports it. The session composes the brief by the same instructions on both paths, so the workflow path adds no copying step and removes one: the second copy, which the session types again today and which can differ from the first, is made by the script. No digest check is added.

Effort is not passed to `agent()`. A Task reviewer inherits the session's effort today and gets the resolver's `effortLine` as prompt text at `xhigh` and `max`; the workflow path keeps both, so the comparison measures the dispatcher and nothing else. Binding effort per agent is a change for after the measurement.

The script returns text, and `settle-lens-replies` reads it. The session gets the returned value for that call from the file Claude Code saves for the run, at the place #5596's document names. Reading it there costs no output tokens and is the reason the path is cheaper. Decided 2026-11-16: the saved run file is the only route. The session passes its path to `settle-lens-replies` as the positional argument (#5598 reads the returned value at the top level or under `result`). If #5596's document shows that no field of the tool result leads to that file, this record does not build: it stops before any code with status BLOCKED, because retyping every reply would cost more main-session output than the Task path it replaces. At run time a file that is missing, unreadable, or not `{ started: true, lenses, reviewers }` is the fifth fallback condition, and the session never looks for another run's file.

At `low` each lens has `reviewers: 1`; `settle-lens-replies` lists such a lens under `needsSession` and the session applies `step3-tier-variants.md`'s single-read rule to it. Lens 3h is not sent through the script: it is one agent with its own procedure (`ux-analysis.md`). The workflow path is used at any diff size; the "sequential in the main thread" case for a small diff is a Task-path rule. A `needsSession` lens is handled by its `reason`. `single-reviewer`: the session applies the single-read rule to the findings file the verb wrote from the workflow reviewer's reply; nothing is dispatched again and no `SKIP` line is written. `reviewer-unusable`: the session dispatches only the unusable reviewers again through the Task path, once, and then runs the per-pair steps with the usable reviewer's file.

Availability check: the session has the tool when `Workflow` is among its tools, or can be loaded through the session's deferred-tool lookup. A continuation agent, a dispatched reviewer and a pipeline-driver worker do not have it and take the fallback. A review resumed in a new session never resumes a workflow run: it treats the run as ended with no result.

The script opens with `export const meta = { name, description, whenToUse }` and then its body, as the tool's authoring reference gives it; load the `workflow-authoring` skill before writing it. To test the script, load its text, drop the `export` keyword and run the body as an async function with the five globals passed in. Put that loader in `tests/helpers/`.

This record adds no permission rule and no `allowed-tools` line. A session in which the call is refused takes the fallback.
