# 4940: Make routine self-heal, /init Step 15 and /routine create aware of declare-claude-tweaks: false

Origin: reflect full from #4847

Defer-reason: tangential

## Current State

#4847 added the `declare-claude-tweaks` policy key: at `false`, `/init` Step 14 stops adding claude-tweaks to the project's committed `.claude/settings.json` and `scripts/claude-cloud-setup.sh`, and `/routine fleet` reports the parity gap as an opt-out instead of failing. Three routine-side surfaces still ignore the key, so a routine created or fired in an opted-out project runs in a sandbox the setup script no longer installs claude-tweaks into:

- `plugin/skills/_shared/routine-template-schema.md` (the kernel self-heal, near line 67) runs `bash scripts/claude-cloud-setup.sh` on every firing where the plugin cache is empty. At `declare-claude-tweaks: false` that script no longer installs claude-tweaks, so every firing self-heals into a script that cannot help and then fails at "version unresolved" instead of naming the opt-out.

- `plugin/skills/init/bootstrap/step-15-routine-installation.md` (the Setup-script environment offer) offers to apply the script to a dedicated environment without mentioning the opt-out.

- `plugin/skills/routine/create-and-update.md` (`/routine create`) does not warn that the routine it creates will fire without claude-tweaks.

Absence probe (integration branch): `git grep -n -F -e declare-claude-tweaks origin/main -- plugin/skills/routine plugin/skills/_shared/routine-template-schema.md` returned no match at the time of filing.

## Deliverables

Make the kernel self-heal in `plugin/skills/_shared/routine-template-schema.md` opt-out aware: at `declare-claude-tweaks: false`, skip the self-heal and print one line naming the opt-out instead of the generic "version unresolved" failure.

Make `/init` Step 15's Setup-script environment offer and `/routine create` state, once, that the project opted out of declaring claude-tweaks and that a routine fired there needs claude-tweaks supplied another way, or the key set back to true.

Pin each added line with a conformance assertion in the existing `tests/declare-claude-tweaks-opt-out.test.js`, discriminating against the default (`true`) path.

## Acceptance Criteria

With `declare-claude-tweaks: false`, the kernel self-heal text in `routine-template-schema.md` names the opt-out and does not instruct running `scripts/claude-cloud-setup.sh`.

With the key unset or `true`, the self-heal text is unchanged in behavior (a test asserts the default path).

`step-15-routine-installation.md` and `routine/create-and-update.md` each carry the opt-out notice, pinned by `tests/declare-claude-tweaks-opt-out.test.js`.

`npm test` passes.

## Release Note

Projects that opted out of declaring claude-tweaks (`declare-claude-tweaks: false`) now get a clear message instead of a failing routine self-heal, and `/init` and `/routine create` tell them once that routines there need claude-tweaks supplied another way. The routine prompt kernel moves to `kernel_version: 2`, so every existing routine reports kernel-stale drift in `/claude-tweaks:routine status`; re-syncing with `/claude-tweaks:routine update` is safe, and nothing else changes for projects that keep the default.
