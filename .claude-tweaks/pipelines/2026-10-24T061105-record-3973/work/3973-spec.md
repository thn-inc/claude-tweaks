# 3973: Add a run-liveness verdict module and an owner block in run-state.json (no behavior change)

Surface: infra

## Overview

Nothing in `run-state.json` says whether the session that owns a run is still alive. `updatedAt` moves on non-owner writes (the exemption stamps in `pre-tool-use.js` write to `ctx.runDir` without an ownership check), and a worktree lock PID belongs to the worktree rather than the run and goes stale on resume. Every cleanup decision that follows in this project (closing dead runs, trimming the SessionStart banner) needs one trustworthy answer to "is this run live, dead, or can't we tell?", and today three modules each answer it their own way.

This record adds that answer and changes no behavior. It does two things. It stamps an additive `owner` block into `run-state.json` wherever ownership is already stamped. It adds a new module, `plugin/bin/lib/run-liveness/`, that turns that block plus the existing probes (worktree lock, last commit time, event recency) into a three-valued verdict from positive evidence. No caller consumes the verdict yet; later records in this project migrate callers onto it (#3977 for dead-run closing and the banner, #3979 for the duplicated definitions) and then delete the old definitions.

**Complexity:** Medium
**Estimated tasks:** 7

## Non-Goals

- No caller consumes `runLiveness` in this record: not reconcile, not the SessionStart banner, not `isDeadRunDir`, not `resume-freshness.js`. Migrating callers is a separate record in this project (#3979).
- No auto-close, no archive change, no banner change.
- `updatedAt` is not repurposed. It stays a write timestamp and nothing new reads it as a liveness signal.
- No change to the nested `claude -p` SessionEnd mis-attribution (#3845); this record only has to be correct in the presence of its false `interrupted`.
- No GitHub state changes and no new policy keys. The 10 minute and 72 hour windows are module constants, tuned only with evidence and never in the fail-open direction.

Verdict table the module implements:

| Verdict | Requires |
|---|---|
| `live` | Any one of: the owner PID is alive on this host and its start time matches `pidStartedAt`; `heartbeatAt` is within 10 minutes; a worktree lock on the run's worktree reports an in-use PID (`lockVerdict`); the last commit on the run's worktree is under 10 minutes old (the `resume-freshness.js` probe). |
| `dead` | All `live` probes negative and error-free, plus one of: the owner PID was checked on this host and is gone, or alive with a different start time; or status is `interrupted` with `lastEvent: session-end` and no owner heartbeat since. The SessionEnd route applies only to a run that has an owner block. |
| `dead` (legacy route, runs with no owner block) | No owner-attributed event in `events.jsonl` (`ownEventRecency`) for 72 hours, no in-use lock, and no commit on the worktree for 72 hours. The SessionEnd route alone is never enough for a legacy run, so a false `interrupted` from #3845 cannot kill an idle but live legacy run. |
| `unknown` | Anything else: another host, a probe that errored, a null start time with no SessionEnd, a legacy run short of the 72 hour route. |

Precedence and probe semantics (the table alone does not settle conflicting evidence):

- Every probe is consulted, in the order owner PID, heartbeat, worktree lock, last commit, owner-event recency, so the evidence list is complete and deterministic; there is no short-circuit.
- A `positive` live probe yields `live` even when another probe reported `error` (a live verdict never closes anything). Otherwise any `error` entry yields `unknown`, even when a death witness holds. Otherwise `dead` needs a death witness; with none, the verdict is `unknown`.
- "No owner heartbeat since" the SessionEnd stamp means `owner.heartbeatAt` is earlier than the `ts` of the newest `session-end` event in the run's `events.jsonl` (appended by `session-end.js`); no new run-state field is added. An unreadable `events.jsonl` is an `error`.
- The SessionEnd route is the death witness for the case the PID row cannot judge: the owner PID is alive on this host but `pidStartedAt` is `null`, or `pid` is `null`. When the PID row can judge (gone, mismatched start time, or matching start time), it decides and the SessionEnd route adds nothing.
- The worktree lock and last-commit probes return `negative` with detail `no-worktree` when the run records no worktree or the worktree is gone; absence is not an error, and a missing worktree is never itself a death witness.
- Owner-event recency: an unreadable `events.jsonl` is an `error`; a readable file with no owner-attributed events measures its age from the run id's own timestamp, so a legacy run with zero events still needs 72 hours.
- Heartbeat and PID are separate: a long hook-less stretch (a long tool call) can exceed the 10 minute heartbeat window while the PID row still reports `live`; PID-gone counts as a death witness only together with a stale heartbeat, a negative lock and a negative commit probe.

1. After `record-worktree`, `stampAdHocRunDir`, and `stampAdHocRunDirForDenial` each run against a fresh run dir, the written `run-state.json` contains `owner.sessionId`, `owner.host`, `owner.pid`, `owner.pidStartedAt` (a string, or `null` when the probe is injected to fail), and `owner.heartbeatAt`; a test per stamp site asserts every field.
2. Two hook events from the owning session 30 seconds apart leave `owner.heartbeatAt` unchanged after the second; a third event 61 seconds after the first advances it. An event attributed `fallback` never changes `owner.heartbeatAt`. A hook from a different `sessionId` never changes the owner block, and a stamp from a different session over an existing owner block leaves it unchanged.
3. A resumed session (same `sessionId`, new pid) leaves a run-state whose `owner.pid` and `owner.pidStartedAt` match the new process after its first event, written together in one `run-state.json` update, and `runLiveness` then returns `live` through the PID row. The SessionStart handler performs that re-stamp before the background reconcile pass is spawned; a test asserts the order.
4. `runLiveness` returns `live` when the owner PID is alive on this host with a start time equal to `pidStartedAt`. When the PID is gone, and every other probe is a clean negative, it returns `dead`. When the PID is alive but its start time differs from `pidStartedAt` (PID reuse), the PID row does not report `live`, and with every other probe a clean negative the verdict is `dead`.
5. Each remaining `live` probe (heartbeat under 10 minutes, in-use worktree lock, last commit under 10 minutes) alone yields `live`, tested one by one with every other probe negative.
6. A run with an owner block whose PID is alive with `pidStartedAt` `null`, status `interrupted`, `lastEvent: session-end`, and a heartbeat earlier than the newest `session-end` event yields `dead` when every `live` probe is a clean negative; the same run with a heartbeat later than that event yields `live` when it is under 10 minutes old and `unknown` otherwise, never `dead`. A run with no owner block and the same `interrupted` shape yields `unknown`, never `dead`. A run whose PID is alive with a matching start time yields `live` whatever its status.
7. A legacy run (no owner block) yields `dead` only when `ownEventRecency` is older than 72 hours, no in-use lock exists, and the last commit on the worktree is older than 72 hours; at 71 hours of event silence it yields `unknown`.
8. A probe that throws or returns an error result yields `unknown`, for each probe in turn. A different `host`, and a null `pidStartedAt` with no SessionEnd evidence, each yield `unknown`.
9. A fail-open variant of the module (probe error mapped to `dead`) is present in the test file as an injected fault and the probe-error tests fail against it; the evidence is recorded in the PR body.
10. The `CLAUDE_PID` premise result, with the raw probe output, is recorded in the PR body, and the owner block's `pid` source in the code matches it.
11. A `run-state.json` with no `owner` key is read by every existing reader without error and `runLiveness` treats it as legacy; a test pins this.
12. Every verdict carries one evidence entry per probe consulted, each with `result` of `positive`, `negative`, or `error`; a test shows that an erroring probe yields an `error` entry (not `negative`) and verdict `unknown`.
13. Precedence: a fixture with a positive heartbeat and an erroring lock probe yields `live`; a fixture with a death witness and an erroring commit probe yields `unknown`; the evidence list has one entry per probe in the stated order in both.
14. A run recording no worktree yields `negative` (`no-worktree`) from the lock and commit probes, not `error`; a legacy run with a readable, empty `events.jsonl` ages from its run id timestamp (a run id 73 hours old yields `dead` through the legacy route, one 71 hours old yields `unknown`).
15. `owner.pidSource` is `env` or `ancestry`; with neither source available `owner.pid` is `null`, and a run with a `null` pid never yields `dead` through the PID row.
16. `docs/hooks.md` names the owner block's fields (including `pidSource`), the precedence rules, and the legacy rule.

## Release Note

Added a per-run liveness record so claude-tweaks can tell a running session's run from an abandoned one, with no change to how runs behave yet.

## Technical Approach

The owner block is additive to `run-state.json`, which installed builds read over this repo's directories and every consumer project's. Readers treat a missing block as legacy and never as an error; nothing is removed or renamed.

`runLiveness` is a pure function over injected probes. Each probe returns a tagged result (positive, negative, or error) so that an error can never be conflated with a negative. The module composes per the precedence rules above: a positive `live` probe yields `live`; otherwise an `error` yields `unknown`; otherwise `dead` requires every `live` probe to be a clean negative plus a death witness; everything else is `unknown`.

### Data / API Surface

`run-state.json` gains:

```json
"owner": { "sessionId": "string", "host": "os.hostname()", "pid": 90405, "pidSource": "env | ancestry", "pidStartedAt": "string or null", "heartbeatAt": "ISO-8601" }
```

`runLiveness(runDir, { now, probes })` returns `{ verdict: 'live' | 'dead' | 'unknown', evidence: [{ probe, result: 'positive' | 'negative' | 'error', detail }] }`. The structured evidence lets a caller tell a probe error from a clean negative (a resume gate fails closed on an error but not on a clean negative). `probes` overrides any of: `pidAlive`, `pidStartTime`, `lockInUse`, `lastCommitAt`, `ownEventAt`, `hostname`.

## Gotchas

- ASSUMPTION — verify at build: hook processes receive `CLAUDE_PID` — via Task 0's probe from a real hook invocation. If they do not, walk the parent chain to the `claude` process; do not fall back to `process.ppid` unverified.
- `writeRunState` merges shallowly: writing `{ owner: { heartbeatAt } }` would erase `sessionId`, `pid`, and the rest. A heartbeat or re-stamp must read the existing `owner` and spread it into the patch.
- Never refresh the heartbeat from a `fallback`-attributed event (`isTrustedOwnedRun`): that attribution is a guess at the newest unowned run and is routinely a sibling session's directory. Refreshing it would keep a dead run looking alive.
- `ps -o lstart=` output is locale- and platform-dependent; store the raw trimmed string and compare for equality only, never parse it into a date.
- A heartbeat write is a hook-path write to a shared file: it must honor the never-break-a-session invariant in `docs/hooks.md` (swallow errors, never throw) and be throttled by reading `owner.heartbeatAt`, not by a new marker file.
- Legacy runs have no heartbeat, so "no heartbeat since the SessionEnd stamp" is always true for them; this is why the SessionEnd route requires an owner block.
- The 10 minute window and the 1 minute throttle are coupled: keep the live window at least ten times the throttle through one shared constant pair and a test asserting the ratio. The window is not a liveness guarantee for a session inside a long tool call; the PID row is the backstop for that gap.
- Residual risk, accepted by the design: on a platform where `pidStartedAt` is `null` (Windows, sandboxes), a nested `claude -p` that falsely marks the parent run `interrupted` (#3845) can make the SessionEnd route report `dead` while the parent is idle for more than 10 minutes. The next owner hook heartbeats the run back to `live`. #3845 removes the false stamp at the source.
- Host equality is `os.hostname()` string equality. A container or sandbox with its own PID namespace and the same hostname can make a live owner look gone, which is why PID-gone is a death witness only together with a stale heartbeat and negative lock and commit probes. Process liveness means the session process exists, not that it still drives this run: one long-lived process can leave several runs `live`, which only costs an extra `leave`.
- This module's table is the authority from the day it lands. The four old definitions are frozen (no edits) until #3979 migrates their callers and deletes them.
- ASSUMPTION — verify at build: SessionStart resolves a resumed session's run by `sessionId` (`ctx.ownedRun`) early enough to re-stamp before it spawns the background reconcile pass (`plugin/bin/lib/hooks/session-start.js`); if it cannot, make the re-stamp the first action of the first hook that can.
- Probe errors resolve to `unknown`, never `dead`. Every new probe wrapper needs a test where it throws.
- Windows and sandboxes: PID and start-time probes degrade to `unknown`; apply the `windows-checkout-test-parity` skill to any new path-matching test.
- Hold the in-progress neighbours in mind: #3845 (`session-end.js`), #3836/#3811/#3736 (`context.js` worktree path comparison), and #3937 (`post-tool-use.js` nested-session writes) edit nearby code.

## As-built deviations (build Common Step 4.5, Beneficial)

- Re-stamp guard: the every-event re-stamp runs only when the stored owner process is not provably alive (gone, a non-null differing start time, another host, or no stored pid); a live stored pid whose start-time probe fails counts as alive. A nested `claude -p` sharing the owner's session id therefore neither re-stamps nor heartbeats.
- Fail-closed refinements to the verdict table, each resolving to `unknown`: an owner block whose `sessionId` differs from the run's `sessionId` (`owner-session-mismatch`); a non-finite `now` (`invalid-now`); a non-string, non-null `pidStartedAt` on a live pid (`invalid-start-time`); an unreadable or non-directory worktree path (lock and commit probes `error`, via path-guard's `lstatType`); non-finite probe values. The SessionEnd witness counts only `session-end` events whose `sessionId` is the owner's.
- `probes` also accepts a `pathType` override (the worktree classification), beside the six the spec lists.
- `pidStartedAt` is read with `LC_ALL=C` and `TZ=UTC`, so the raw string is stable across processes.
- The module's suite lives at `tests/bin-lib/run-liveness/` (repo convention for `plugin/bin/lib/{module}`), not `tests/run-liveness.test.js`.
