# 3092: Derive the Bash hook prefilter word set from the guard parsers and pin it with a differential test

Origin: v6.139.1 release whole-branch review (/claude-tweaks:release Step 3, v6.139.0..48c63045a), staged finding review-2 — the release review stages and never applies fixes in place

Defer-reason: needs-human-decision

## Current State

`plugin/bin/lib/hooks/bash-prefilter.js:36` builds `PRE_TOOL_USE_WORDS` as `['git', 'env', 'mkdir', ...WRITE_SHAPES]`: only `WRITE_SHAPES` is imported, while `git`/`env`/`mkdir` are hand-typed literals that `git-command.js` recognises separately (`findGitLead`'s `lead === 'git'`, `mkdirTargets`'s `t[0] !== 'mkdir'`). A future guard keyed on another program word is silently skipped by the prefilter until someone remembers to edit this list. `tests/hooks-bash-prefilter.test.js:17` compares the literal list to itself and `tests/hooks-gate-coverage.test.js:135`'s `includes()` is true by construction. A reviewer's ~50-command differential probe found no current bypass — this is a drift risk, not a live hole.

## Deliverables

- Export one guarded-program-words constant from `plugin/bin/lib/hooks/git-command.js` beside `WRITE_SHAPES` and import it in `bash-prefilter.js` (pre and post word sets).
- Add a differential corpus test: for every command in the corpus where `gitTargets`, `fileWriteTargets`, `mkdirTargets`, or `teardownTargets` returns a target, `shouldRunFull` is true.
- Replace the self-comparing assertions in `tests/hooks-bash-prefilter.test.js` and `tests/hooks-gate-coverage.test.js`.

## Acceptance Criteria

- [ ] `bash-prefilter.js` holds no hand-typed program-word literal.
- [ ] The differential test fails when a word is removed from the exported constant and passes on the shipped code.
