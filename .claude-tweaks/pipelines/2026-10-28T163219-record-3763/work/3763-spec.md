# 3763: Quote governing project-skill rules into build plans' Global Constraints

Origin: reflect full from #3712

Defer-reason: tangential

## Current State

`/claude-tweaks:build` runs its `plan-authoring-checks.md` checks against a plan, but none of them asks whether a project skill already governs a file the plan touches. Dispatched SDD implementers and reviewers see only their task brief, so a rule that lives only in a `.claude/skills/*/SKILL.md` never reaches them unless the plan quotes it.

In #3712 this cost one review fix. The plan's Global Constraints defined "provably owned" as `isTrustedOwnedRun` plus not ad-hoc, which is weaker than `pre-tool-use-gate-exemptions`' existing rule that a deny keyed on the caller's own run must also require `classifyOwnership === 'mine'`. Five task reviews, the whole-branch review and its re-review all passed the weaker check, and /review's lens 3a caught it (fixed in 0a5d6cf24).

## Deliverables

- [ ] Add a check to `plugin/skills/build/plan-authoring-checks.md`: for each file the plan creates or modifies, find the project skills under `.claude/skills/` whose description or body names that file or its module, and quote their applicable rule bullets verbatim into the plan's Global Constraints, or say why none apply.
- [ ] Pin the new check with a conformance test, following the file's existing pinned checks.

## Acceptance Criteria

1. `plugin/skills/build/plan-authoring-checks.md` carries a check that names `.claude/skills/` and requires governing project-skill rules to be quoted into the plan's Global Constraints.
2. A test under `tests/` fails when that check's paragraph is removed from `plan-authoring-checks.md`.
3. `npm test` passes.

## Release Note

Build plans now carry any project-skill rule that governs the files they touch, so subagents implementing a task see it.

### Key Files
