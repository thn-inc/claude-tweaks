# 5375: Give hooks.js an injectable entry and run its verb tests in-process

Surface: backend
Risk-flags: none

## Overview

`plugin/bin/hooks.js` is the most-spawned CLI in the test suite: 813 processes per run, 673 of them calls to its named verbs (`record-worktree`, `ledger-row`, `archive-run`, `close-run`, …). It exports `main(argv)`, but every verb handler writes `process.stdout` directly and reads `process.cwd()` and `process.env`, so a test cannot call it in-process and see its output.

This record threads injected io through `main` and every verb handler, adds `run(argv, deps)` beside `main`, and moves the four test files that exercise the dispatcher and the heaviest verbs onto the in-process helper.

**Complexity:** High
**Estimated tasks:** 8

## Non-Goals

- The hook-event path (`pre-tool-use`, `post-tool-use`, `session-start`, …) beyond handing it the io object: the event modules under `plugin/bin/lib/hooks/` and their tests are #5377.
- The other verb test files (#5376).
- Changing any verb's output text, exit code or flag handling.
- The require-time prefilter fast path at the top of `hooks.js` and the `process.exit(code)` script entry. Both stay as they are.

## Technical Approach

`run(argv, deps)` becomes the body of today's `main`, with `argv` shifted by two. `main(argv)` stays as `(argv) => run(argv.slice(2), realDeps)` for its existing importers. How the handlers receive `deps` is the builder's choice (an extra argument to `verb.run`, or one context object built in `run`); the `VERBS` table shape that `tests/hooks-help-guard.test.js` iterates must keep `usage` and `run` on each entry.

`realDeps` for `hooks.js` needs two things the standard keys do not give: a stderr write that cannot throw (`(s) => { try { fs.writeSync(2, s); } catch {} }`, for the refusal paths), and a stdout write that can be awaited at the three flush-before-exit sites (return the Promise from `deps.stdout`, or add a second `flush` dep). Keep both behaviours byte for byte. Record the chosen shape (a Promise-returning `deps.stdout` or a second `flush` dep) in `docs/hooks.md`, so #5376 and #5377 reuse it.

Why `run(argv, deps)` and not a new `main`: see #5374's Decision Rationale.

The entry contract, set by #5374:

- The CLI exports `run(argv, deps)` and `realDeps`. `argv` is `process.argv.slice(2)`. `run` returns an integer exit code, or a Promise of one when the CLI is async.
- The script entry is the last statement of the file: `if (require.main === module) process.exitCode = run(process.argv.slice(2), realDeps);` (async: `run(…).then((code) => { process.exitCode = code; })`).
- The CLI reaches the outside world only through `deps`. Standard io keys, each present only when the CLI uses it: `stdout(text)`, `stderr(text)`, `cwd()` (returns a string), `env` (a plain object, read-only), `stdin()` (returns the whole input as a string), `homeDir()` (returns the user's home directory; real value `() => os.homedir()`). Other seams (`runner`, `now`, `mainRoot`, …) keep their names.
- Above the guarded entry, and in everything `run` calls: no `process.exitCode`, no `process.exit()`, no `process.chdir()`, no write to `process.env`.
- A relative path is resolved against `deps.cwd()`, never left to `path.resolve` or `fs`, which use the real working directory.
- Every child process is started with `cwd: deps.cwd()` and `env: deps.env`. A child started without them inherits the test runner's working directory and environment, so a `gh` or `git` stub on an injected `PATH` is skipped and the real tool runs.

## Gotchas

- Never-break-a-session: an exception on the hook-event path must still end in exit 0 through the entry's `.catch(() => process.exit(0))`, and a `VERBS` exception in exit 1 (#4932). Both are pinned by `tests/hooks-verb-exception-exit.test.js`; do not move that catch into `run`.
- The `await` in `return await verb.run(argv)` is load-bearing (comment at line 2149). Keep it when the call gains a deps argument.
- Verb handlers call lib functions that read `process.env` or `process.cwd()` themselves. A converted test that passes `env` or `cwd` and gets the runner's own value back has found one: pass the value down as a parameter. Do not patch the global in the test.
- `hookEnv()` in the converted tests spreads `process.env` and then sets `PIPELINE_RUN_DIR: ''` and `CLAUDE_CODE_SESSION_ID`. Keep that exact environment as the `env` passed to `runCli`, or a test resolves a real ambient run directory (#1130).
- #5294 (in progress, pull request #5298) changes how `hooks.js` and its libs cache git lookups across a hook process. Build this record after it has merged. About twenty other open records name `hooks.js`; rebase onto main before the final verify run and re-run the four converted files after any conflict in a verb handler.
- `hooks.js` has no `--help` at the top level and `archive-run` ignores `--dry-run`: never invoke a real verb against this checkout while testing; use the fixtures.
- The "today" counts come from one full-suite run on main @ 79cd5710d (2026-11-13) with a `NODE_OPTIONS=--require` preload that logs every node process. They are a floor: a test that spawns with a replaced `env` drops `NODE_OPTIONS`, so its children were not counted. Re-measure before starting.
- `node --test` runs each test file in its own process, so in-process state is shared only between the tests of one file.
- A CLI that relied on process exit to drop an open handle, timer or signal listener keeps the test file alive in-process. `run` closes what it opens.
- A test stays on a real process only when the process is its subject (a signal, a lock held across processes, a detached child, a closed stderr, `process.exit` timing). Use `spawnCli` for it and list it in the PR body.
- A test that fakes `gh` or `git` with a stub on `PATH`, or isolates the home directory with `HOME`, works in-process only when the CLI passes `deps.env` to every child it starts and reads the home directory through `deps.homeDir()`. Convert such a test by threading `env` to the child, or by injecting a fake `runner` through `deps`. If neither fits this record, leave the test on `spawnCli` and list it; never let it run with the stub silently skipped.
- Source-scan suites read `plugin/bin` files as text and pin their shape; `tests/bin-lib/exit-code-conformance.test.js` reads each file's last `require.main` block. Run the full suite before pushing, not only the converted files.

## Build Alignment Notes

Deviations from this spec's Technical Approach that the build kept, as improvements on its intent (Common Step 4.5, Beneficial):

- `realDeps.stderr` is a non-throwing full-write loop, not the single `(s) => { try { fs.writeSync(2, s); } catch {} }`. It converts the text to a Buffer, loops on a short write count, retries briefly on `EAGAIN`, and returns silently on any other error. `ledger-row`'s refusal was a fourth flush-before-exit site at base (`await new Promise((r) => process.stderr.write(text, r))`), beside the three stdout sites the Technical Approach names. On a non-blocking fd 2, a single `fs.writeSync` short-wrote silently (65534 of 204801 bytes observed), which broke "Keep both behaviours byte for byte". The chosen shape is a Promise-returning `deps.stdout` awaited at the three stdout flush sites, plus the full-write `deps.stderr`. It is recorded in `docs/hooks.md`'s `## In-process entry (#5375)`, as this spec asks, so #5376 and #5377 reuse it.
- `env` is threaded beyond the files the plan named. In-process tests or review showed a global read on a converted verb's path in each of these:
  - `plugin/bin/lib/reconcile/archive-merged.js`: `archiveRunDir` and `archiveCommitLine` pin git to the injected env.
  - `plugin/bin/lib/wrap-up/ledger-write.js`: `describeRunLedgers` gains `env`, beside `resolveLedgerPath`'s `cwd` (and upstream #5379's `env`).
  - `check-sibling-sessions` passes `sessionId` from `deps.env`.

  Their covering tests live in the verbs' own suites (`tests/delete-ledger-verb.test.js`, `tests/resolve-ledger-verb.test.js`, `tests/hooks-adopt-run-dir.test.js`) as well as the four converted files. None of these adds a real `hooks.js` process to the four counted files. This is the "Edits under `plugin/bin/lib` … where a converted test shows a global read" rule applied as written.
