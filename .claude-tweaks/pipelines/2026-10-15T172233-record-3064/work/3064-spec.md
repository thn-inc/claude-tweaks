# 3064: verify.js --baseline leaves its scratch worktree behind on SIGINT/SIGTERM

Origin: ledger resolve gate
Defer-reason: genuinely-larger

**Related:** #3063

## Current State

`adjudicate()` in `plugin/bin/lib/verify/baseline.js` removes its scratch worktree only in a `finally` block. A SIGINT (Ctrl-C) or SIGTERM during the base or isolated runs ends the process before that block runs. A registered `git worktree` and its `ct-verify-base-*/wt` checkout are left behind, with no stderr line naming them. `plugin/bin/verify.js` installs no signal handler. On Windows a TerminateProcess (an agent's TaskStop) cannot be caught at all, so the fix there is best-effort plus a named leftover.

Evidence: review lens 3c on #3043 (ledger row 14).

## Deliverables

- [ ] While a scratch worktree exists, `adjudicate()` registers SIGINT/SIGTERM/SIGHUP handlers that remove it (via `realGit.removeWorktree`) and then exit with the signal's conventional code. The handlers are deregistered in the `finally`.
- [ ] On an uncatchable kill, the next `verify.js --baseline` run notices a stale `ct-verify-base-*` worktree registered against this repo and names it on stderr with the `git worktree remove --force` command. It does not sweep it, because a sibling session's live scratch may look the same.

## Acceptance Criteria

- [ ] A Linux test spawns a `--baseline` run whose base command sleeps, sends SIGINT mid-run, and finds no registered scratch worktree afterwards plus an exit code of 130.
- [ ] A test seeds a stale `ct-verify-base-*` worktree registration and sees it named on stderr by the next run, and still present.

## Release Note

Interrupting a baseline verification run now cleans up its scratch worktree, and leftovers are reported on the next run.
