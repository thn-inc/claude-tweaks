# 3574: Windows regression-proof 9 prose tests that split or index raw-read markdown on '\n\n'

Origin: ledger resolve gate (wrap-up of #3523, ledger item 1)

Defer-reason: pre-existing-outside-diff

**Related:** #3587, #3565, #3579

## Current State

- #3523 fixed `tests/wrap-up-multispec-defer-still-live.test.js`, whose CRLF test double-converted an already-CRLF raw read into `\r\r\n` on a `core.autocrlf=true` Windows checkout.
- While fixing it, a repo-wide grep of `tests/` found nine other test files that apply `split('\n\n')` or `indexOf('\n\n'` to a raw `fs.readFileSync` of a tracked markdown file. On a CRLF checkout the paragraph break reads `\r\n\r\n`, so the split finds no break and the index search returns -1. They are unchanged since the shaping base `7852fd8bf`, were out of #3523's scope, and are a latent Windows-only weakness (the `windows-checkout-test-parity` skill's Anti-Patterns table names the class).
- Sites: `tests/review-vacuity-evidence-conformance.test.js:97`, `tests/working-approach-scope-discipline.test.js:88`, `tests/multi-agent-coordination.test.js:1316`, `tests/design-wrapper-review-surface-gate-prose.test.js:139`, `tests/ephemeral-server-handoff-conformance.test.js:53` and `:113`, `tests/flow-manifesto-ceremony-fallback-conformance.test.js:26`, `tests/try-it-contract-conformance.test.js:53`, `tests/skill-load-report-cli.test.js:217`, `tests/claim-mcp-projection-conformance.test.js:18`.
- Not every site necessarily fails today: some may already read through `readText()` or normalize elsewhere in the file. Verify each against its own read before changing it.

## Deliverables

- [ ] For each site that reads a tracked file raw and then searches for `'\n\n'`, route the read through `tests/helpers/read-skill.js`'s `readText()` (preferred) or LF-normalize it once before the search. Leave the extractor logic unchanged.
- [ ] For each changed test, keep (or add) a CRLF case built from the LF text, per the `windows-checkout-test-parity` skill's "Build CRLF inputs from the LF text" rule.
- [ ] Dispatch `windows-regression.yml` on the branch and quote the result for the changed files.

## Acceptance Criteria

- [ ] No test under `tests/` searches a raw read of a tracked file for `'\n\n'` (re-run the sweep grep and record the result in the PR body).
- [ ] Each changed test passes on macOS/Linux with no test skipped or removed.
- [ ] The changed files pass on `windows-latest`, proven by a `windows-regression.yml` dispatch on the branch. An in-process CRLF simulation is not a Windows run.
- [ ] `npm test` passes.
