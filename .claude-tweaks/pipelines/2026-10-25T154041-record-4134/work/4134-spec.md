# 4134: Make test-impact tracing work on Windows and keep a large impact subset inside the Windows command line

Origin: ledger resolve gate (#4024, ledger row 28)
Defer-reason: genuinely-larger

## Current State

Tracing is documented as POSIX-only in `plugin/skills/test/impact-selection.md` (Known limits): `tools/test-impact.js trace` puts the tracer's path into `NODE_OPTIONS` inside literal double quotes, and on win32 that quoting drops the path's backslashes, so the end-to-end trace test in `tests/test-impact-cli.test.js` is skipped on win32. Separately, a `--files-from` subset reaches `node --test` as an explicit file list (`tools/run-tests.js` passes root globs on win32 only for a full run, since the Windows command line cannot hold the whole list), so a large impact subset could overflow the Windows command line. CI traces on Linux, and selection reads the map on any platform, so only a developer tracing locally on Windows, or running a very large subset there, is affected.

## Deliverables

- Pass the tracer path to `NODE_OPTIONS` in a form win32 parses, and lift the end-to-end test's win32 skip.
- Bound the subset on win32 (fall back to the full run past the size the command line holds, with a named reason) or pass the subset another way.
- Remove the POSIX-only limit from the doc.

## Acceptance Criteria

- [ ] `node tools/test-impact.js trace` on a win32 checkout whose path holds a space produces a map naming the traced tests, and the Windows regression job runs the end-to-end test instead of skipping it.
- [ ] A subset larger than the win32 limit runs the full suite with a named fallback reason rather than failing to spawn.
- [ ] The Known limits section no longer lists tracing as POSIX-only.

## Release Note

Test-impact maps can be traced on Windows as well as on POSIX, and a large subset no longer overflows the Windows command line.

### Current State

`tests/test-impact-tracer.test.js` builds NODE_OPTIONS with the tracer, or a fixture preload, inside literal double quotes holding a native path:

- line 39: `` const req = `--require "${TRACER}"` ``, used by every traced run
- line 202: `` `--require "${path.join(root, 'freeze-readdir.js')}" ${env.NODE_OPTIONS}` ``

`tools/test-impact.js:145` composes the same `--require "<path.join(root, 'tools', 'test-impact', 'tracer.js')>"` shape, as #4134's Current State describes. ### Deliverables

- One helper that builds a NODE_OPTIONS `--require "<path>"` entry with the path forward-slashed (`toPosix(p, pathImpl.sep)`, `pathImpl` defaulting to `path`). It keeps the double quotes for a path that contains a space. `tools/test-impact.js:145` and `tests/test-impact-tracer.test.js:39`, `:202` and `:250` all use it.
- A Linux-runnable pin: the helper given `'D:\\a\\x y\\tracer.js'` and `path.win32` returns exactly `--require "D:/a/x y/tracer.js"`.

## Build deviations (Common Step 4.5, classified Beneficial)

- Both of `tests/test-impact-cli.test.js`'s end-to-end trace tests now run on win32.
