# 2763: Prose-conformance tests break on Windows CRLF checkouts — one shared EOL-normalizing read helper (or a .gitattributes eol policy)


Origin: ledger resolve gate

Defer-reason: genuinely-larger

## Current State

The prose-conformance suites (`tests/*-conformance*.test.js` and siblings such as `tests/feedback-watermark-prose.test.js`, `tests/demo-*.test.js`) read `plugin/skills/**/*.md` with a raw `fs.readFileSync(..., 'utf8')` and assert on literals, `startsWith(heading + '\n')`, and byte counts. This repo has `core.autocrlf=true` and no `.gitattributes`, so any file git re-checks-out on a Windows box (a revert, a `git checkout`, a fresh clone) carries CRLF in the working copy while files written by an editor or the Write tool stay LF.

Observed on #2697's run: `tests/skill-mode-split-conformance.test.js` was red at HEAD purely because a revert re-checked-out one sub-file (`plugin/skills/demo/follow-up-record.md`, `i/lf w/crlf` per `git ls-files --eol`) — fixed by normalizing `\r\n` in that test's `read()` helper. `tests/feedback-watermark-prose.test.js:190` fails on this machine today for the same reason (`'.claude-tweaks/feedback/\r'`), and the run's pre-flight sweep baseline (342 failures / 103 files, ledger #2 of run 2026-09-21T213441-spec-2697-2757-2758-2759) is dominated by CRLF/path-shaped failures of this class.

## Deliverables

One shared EOL-normalizing read helper for prose-conformance tests (e.g. `tests/helpers/read-skill.js` exporting `readText(rel)` that returns the file with `\r\n` → `\n`), adopted by every `tests/**` suite that reads `plugin/skills/**/*.md`, `docs/**/*.md`, `CLAUDE.md`, or `.gitignore` for literal assertions — replacing each suite's private `fs.readFileSync` read.

OR, if judged cleaner: a committed `.gitattributes` declaring `* text=auto eol=lf` (or `*.md text eol=lf` plus the other asserted text types) so checkouts are LF on every platform — with a one-time renormalization commit (`git add --renormalize .`) and a note in `docs/donts.md` or `CLAUDE.md`'s Commands section about the Windows baseline shrinking. Pick one; state why the other was not chosen.

## Acceptance Criteria

`node --test tests/feedback-watermark-prose.test.js` passes on a Windows checkout with `core.autocrlf=true` (its `.gitignore and step-04 intentionally diverge post-#856` test no longer fails on a trailing `\r`).

A re-checkout of any `plugin/skills/**/*.md` sub-file (e.g. `git checkout -- plugin/skills/demo/follow-up-record.md` on Windows) leaves `tests/skill-mode-split-conformance.test.js` and every other prose-conformance suite green — verified by a re-run after such a checkout on a Windows box, quoted in the wrap-up.

The Windows pre-flight baseline failure count for `node tools/run-tests.js` drops measurably versus the 342-failure baseline recorded on 2026-09-21 (quote before/after counts); failures that remain are named and are not CRLF/EOL-shaped.
