# 2877: pr-early-run-lifecycle.md's "start every row unchecked" PR-checklist rule has no mechanical enforcement

Origin: reflect full from #2749

Defer-reason: tangential

## Current State

`_shared/pr-early-run-lifecycle.md`'s Step 3 states that a run's draft PR body should start with
all five canonical phase-checklist rows (build, test, review, polish, wrap-up) unchecked,
regardless of which steps the initiating `/flow` invocation's step-list argument actually names —
"even for steps this run's step-list argument will skip." Observed on record #2749's run
(`2026-10-01T192708-record-2749`, PR #2875): the first dispatch call ran `/flow #2749 build,test`
and the PR body it created at run start carried only `- [ ] build` / `- [ ] test` — no `review`,
`polish`, or `wrap-up` rows at all — contradicting the documented contract. The second dispatch
call (`/flow #2749 review,polish,wrap-up`, this run) had to self-heal by backfilling the three
missing rows before it could flip `review` to checked (logged in this run's `decisions.md` at
21:59:13). Nothing caught the drift before that point — there is no code or test pinning this
specific composition rule, unlike, e.g., the `tests/wrap-up-registry-pin.test.js` pattern used
elsewhere in this plugin to keep a documented table and its implementation from drifting.

Evidence: record #2749's run, `decisions.md` entries at 21:58:02 (discovery) and 21:59:13
(self-heal), PR #2875's body history (`gh pr view 2875 --json body`). Cost this session: one
extra read-patch-write round trip to detect and self-heal the missing rows before the review
phase-exit checklist flip could proceed — low, but would compound across every two-call dispatch
split run until fixed.

## Deliverables

- Either: add a deterministic check (a composer function + a test pinning its output shape) that
  `pr-early-run-lifecycle.md` Step 3's PR-body composition always emits all five canonical rows
  regardless of the step-list argument passed to the composing `/flow` call, or
- Explicitly document that a two-call dispatch split (`dispatch/SKILL.md` Step 5's own sanctioned
  pattern — `/flow {target} build,test` then `/flow {target} review,polish,wrap-up`) is a
  known gap in this contract today, with the self-heal this run performed named as the interim
  mitigation every later phase's checklist-update step should apply.

## Acceptance Criteria

- A fresh two-call dispatch split run's PR body carries all five canonical phase rows
  (unchecked, in order) immediately after the first call's run-start PR creation — verified by a
  test that simulates a `build,test`-scoped first call and asserts the composed body's phases
  span contains `review`, `polish`, and `wrap-up` rows alongside `build`/`test`.

## Release Note

Hardened the PR-checklist composer so a two-call dispatch split always starts every phase row, closing a drift this record's own run hit.
