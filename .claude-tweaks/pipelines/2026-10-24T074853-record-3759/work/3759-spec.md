# 3759: ports registry test: bind-detection test collides with the machine lease pool on port 20003

Origin: reflect full from #3713

Defer-reason: tangential

## Current State

`tests/bin-lib/ports/registry.test.js` binds a real socket on `127.0.0.1:20003` (`POOL_BASE + 3`, line 59) to prove `allocate` skips a block whose port is taken. `20000+` is the machine-wide lease pool that dev servers and sibling test files also use, so under load the bind fails with `EADDRINUSE`. Evidence: on #3713's first full `npm test` run the suite reported `tests 14148, pass 14140, fail 1` with `registry.test.js` failing `EADDRINUSE 127.0.0.1:20003`; the file passed 10/10 in isolation and the second full run was green. Cost: one extra full-suite run (about 3 minutes) plus a manual isolate-and-rerun to tell load from regression. The file already routes its bookkeeping-only tests through an `alwaysFree` probe for this reason; the bind-detection tests still use the real pool range.

## Deliverables

Make the bind-detection test in `tests/bin-lib/ports/registry.test.js` independent of whether `POOL_BASE + 3` is free on the machine, for example by injecting the probe/bind seam or by choosing a free block at test time.

Keep the assertion that `allocate` moves past a block with a taken port.

## Acceptance Criteria

With another process already listening on `127.0.0.1:20003`, `node --test tests/bin-lib/ports/registry.test.js` passes.

The test still fails if `allocate` stops skipping a block with a taken port.

`npm test` passes.
