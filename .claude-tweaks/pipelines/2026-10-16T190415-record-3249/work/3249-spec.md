# 3249: Fast-lane pr-first merges never release their claim or archive their run (console-never-rendered)

**Related:** #3130, #3155, #3167, #3168, #1130, #657

Origin: dispatch firing 2026-10-16, run 2026-10-16T155630-record-3130

Defer-reason: pre-existing-outside-diff

## Current State

Under `integration-model: pr-first`, `_shared/pr-first-merge-post-merge.md` Step 4.2 hands claim release and run-dir archival to `bin/hooks.js reconcile --checks mirror,release,archive` as "convergent cleanup, not owed". The dispatched second call reports `merged` without doing either itself.

On 2026-10-16 this left the claim live, the `auto:build`/`auto:merge`/`bot:in-progress` labels in place, and the run directory unarchived after every fast-lane singleton merge in one session: #3155/#3167/#3168 (PR #3172) and #3130 (PR #3223, run `2026-10-16T155630-record-3130`). Each needed a manual `release-claim.js --reason "merged: spec N" --remove-grants` plus `hooks.js archive-run`.

Archival cause, confirmed from the code: `plugin/bin/lib/reconcile/archive-merged.js`'s `decideArchiveCore` returns `skip` with reason `console-never-rendered` when `consoleState === 'none'` (the #1130/#657 guard against archiving live runs with pending staged decisions). The fast-lane auto-merge short-circuit merges without ever rendering a Review Console, so every such run lands in that skip permanently. No later trigger point converges it, despite what the run's own log claimed (`decisions.md` line 50 of the #3130 run).

Claim-release cause, not yet verified: `plugin/bin/lib/reconcile/release-merged.js`'s `decideRelease` returns `release` for a live claim whose joined PR is `MERGED`. Yet the #3130 claim was still live after the second call's post-merge reconcile. Candidate causes: the run-state → worktree → branch → PR join failing, or the claim cache-skip (#820 D6) hiding a changed blob.

## Deliverables

- Diagnose why `releaseMerged` did not release a live claim whose PR was `MERGED` right after the merge, and fix it.

- Make a console-never-rendered, merged pr-first run converge. Either the fast-lane short-circuit writes a terminal console state (or closes the run terminal and archives via `archive-run`, like the empty-console fast path), or `decideArchiveCore` gets a narrowly scoped exception for runs whose staged items are already surfaced. Keep the #657 protection for runs with pending staged decisions.

- Keep reporting honest: a second call must not log that cleanup "will complete at the next reconcile trigger point" when the archive gate can never pass for that run.
