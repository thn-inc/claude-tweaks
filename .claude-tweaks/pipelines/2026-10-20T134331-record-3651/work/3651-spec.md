# 3651: Extend the git path-list -z sweep to numstat, ls-files, porcelain, and full-format ls-tree readers

Origin: reflect hindsight from #3470

Defer-reason: tangential

## Current State

`plugin/skills/_shared/git-path-read.md` (shipped by #3470) pins the `-z` + `--end-of-options` rule for `--name-only`/`--name-status` readers only, and its "Not covered yet" section names the readers still outside it: `--numstat`, `ls-files`, and `status --porcelain` readers, the full-format `ls-tree` readers in `plugin/bin/lib/health-core/durable-state.js` and `plugin/bin/lib/issues/claims-git-cas.js`, and the `diff -U0` patch-header parsing in `plugin/bin/lib/wrap-up/facts.js`. They carry the same `core.quotepath` hazard (a non-ASCII path prints C-quoted and matches nothing), and no backlog record tracks them.

## Deliverables

- [ ] Each reader named above reads its path list with `-z` and splits on NUL via `plugin/bin/lib/git-z.js` (add a numstat/porcelain parser there when a reader needs one).
- [ ] `tests/git-path-read-conformance.test.js` extends its pin to the argv shapes now covered, and the contract's "Not covered yet" section shrinks to whatever remains.

## Acceptance Criteria

- A fixture repo with a changed path `docs/café.md`: every reader above reports `docs/café.md`, never `"docs/caf\303\251.md"`.
- The extended conformance test goes red when `-z` is removed from any one covered reader (revert to confirm).

## Release Note

Every remaining plugin git path reader handles non-ASCII paths the same way as the --name-only/--name-status readers.

## Technical Approach

### Key Files

- `plugin/skills/_shared/git-path-read.md` — shrink the Not covered yet section
- `plugin/bin/lib/health-core/durable-state.js` — read ls-tree with -z
- `plugin/bin/lib/issues/claims-git-cas.js` — read ls-tree with -z
- `plugin/bin/lib/wrap-up/facts.js` — diff -U0 header parsing
- `tests/git-path-read-conformance.test.js` — extend the pin
