# 3000: design-craft.md Emil skill resolution: misses the .agents/skills install layout when the .claude/skills symlink is absent

Surface: infra

**Related:** #2999

## Current State

Every Emil craft-critic lookup goes through `plugin/skills/_shared/design-craft.md`'s **Emil skill resolution**. That covers `design-wrapper/critics.md:28`'s Resolution and `design-wrapper/modes/review.md` Step 3.8 (c), and `design-craft.md` is also cited from `build/design-prebuild.md`, `design-wrapper/modes/polish.md`, `pre-build.md`, `explore.md`, `flow/polish-execution.md` and `visual-review/standalone-followup.md`. The lookup order (`design-craft.md:38-43`) has two paths:

1. `{project}/.claude/skills/{name}/SKILL.md`
2. `~/.claude/skills/{name}/SKILL.md`

A name found at neither path is absent. The same file's install-layout note (`:45`) records that a real `npx skills` install puts the actual directories at `{project}/.agents/skills/{name}/SKILL.md`, and only adds per-skill symlinks at `.claude/skills/{name}`. `init/bootstrap/step-19-emil-skills.md:21` describes the same layout.

When the symlink is never created, or is lost, the skill still exists at `.agents/skills/` and the harness still lists it, but the lookup misses it. In the reported case (plugin 6.134.1) `emil-design-eng` was available to the harness with no `.claude/skills/emil-design-eng`. `review.md` Step 3.8 (c) then records `{ran: false, missed: "not installed at either path"}` (`:208-211`) and skips the critic.

`review.md:205-208` also restates the two-path list inline instead of only citing `design-craft.md`. A fix to the canonical list alone would leave that restatement stale.

## Deliverables

1. Add `{project}/.agents/skills/{name}/SKILL.md` to `design-craft.md`'s lookup order, after the `{project}/.claude/skills` path (which stays first, since it is the symlink a normal install creates and points at the same directory) and before the user-level `~/.claude/skills` path. Update the install-layout note so it says path 2 is now consulted directly, not only through the symlink.
2. Replace `review.md` Step 3.8 (c)'s inline path list (`:205-208`) with a citation of `design-craft.md`'s lookup, so the list exists in exactly one place. Reword the unavailability `missed` value and its log line from "not installed at either path" to "not installed at any lookup path" (`:209`, `:211`, and the output example at `:494`).
3. Sweep every other consumer that cites `design-craft.md`'s Emil skill resolution (list above) and confirm none restates the path list. At shaping time `git grep 'claude/skills/{name}'` found only `design-craft.md` and `review.md`.

## Acceptance Criteria

- `design-craft.md`'s lookup order lists three paths in the order above. A conformance test pins the order and the `.agents/skills` entry, and goes red against the current two-path text.
- The literal `{project}/.claude/skills/{name}/SKILL.md` appears in exactly one file under `plugin/skills/`, namely `design-craft.md`. The same conformance test asserts this with a repo-wide scan.
- No file under `plugin/` still contains "not installed at either path".
- `tests/design-wrapper-review-surface-gate-prose.test.js` passes unchanged.
- `npm test` passes in full.

## Release Note

Design reviews now find Emil craft-critic skills installed by the `skills` CLI even when the `.claude/skills` link is missing.

## Technical Approach

This is a prose-only change in the shared lookup plus one de-duplication in `review.md`, followed by a conformance test. The reporter's other option, resolving through the harness's own skill list, is not chosen. Step 3.8 has to read the skill's `SKILL.md` text to inline it into the critic dispatch, and the harness's skill list exposes names, not file paths. A file-path lookup is still required either way.

### Key Files

- `plugin/skills/_shared/design-craft.md` — Emil skill resolution: add the `.agents/skills` path and update the install note
- `plugin/skills/design-wrapper/modes/review.md` — Step 3.8 (c): cite instead of restating, and reword the `missed` value and log line (`:205-211`, `:494`)
- `tests/design-craft-emil-resolution.test.js` — new conformance test for the three-path order and the single-source restatement scan

## Gotchas

- The `missed` string in `craft_critics` is part of `review.md`'s output contract. Before rewording it, grep for consumers that match on the literal. At shaping time no `plugin/bin` code matched "either path", so the change is safe as a same-commit rename.
- Path 2 (`.agents/skills`) and path 1 (the symlink) normally resolve to the same directory. Keep path 1 first so a project that deliberately points `.claude/skills/{name}` somewhere else still wins.
- `init/bootstrap/step-19-emil-skills.md` describes the install layout but does not resolve skills. Leave it unchanged unless its wording claims the symlink is required.

## Original request

design-craft.md Emil skill resolution: misses the .agents/skills install layout when the .claude/skills symlink is absent

**Summary:** `skills/_shared/design-craft.md`'s "Emil skill resolution" and `skills/design-wrapper/critics.md`'s Resolution look for `emil-design-eng` in only two places: `{project}/.claude/skills/{name}/SKILL.md` and `~/.claude/skills/{name}/SKILL.md`. **Kind:** Gap

**Affected component:** `skills/_shared/design-craft.md` (Emil skill resolution), `skills/design-wrapper/critics.md` (Resolution), `skills/design-wrapper/modes/review.md` Step 3.8 (c)

**Use case:** A project installed the Emil skills with `npx skills@latest add emilkowalski/skills`. `.agents/skills/emil-design-eng/SKILL.md` exists and the harness lists `emil-design-eng` as an available skill, but `.claude/skills/emil-design-eng` does not exist. The review-time craft critic should still dispatch. Proposed: add `{project}/.agents/skills/{name}/SKILL.md` as a third lookup path (the install note in design-craft.md already documents it as the real location), or resolve through the harness's own skill list.
