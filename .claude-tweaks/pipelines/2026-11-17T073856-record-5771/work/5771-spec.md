# 5771: Give test fixtures a one-process repo init and remove the per-fixture git config identity calls

**Related:** #5324, #5297

Verified-as-of: c059556fc34954c27371c25ebd65f99e79a4eb0a

## Current State

A full-suite profile on main at 8646f7c (2026-11-16, `node tools/run-tests.js --full`, git trace2 per test file) counted 59,448 git processes. Fixture setup (`init`, `config`, `add`, `commit`) is 14,732 of them (25%) across 274 test files, 76 of which start 50 or more.

- `git config` alone is 3,409 processes. Nearly all are an identity pair run right after an init: `config user.name Test` 660, `config user.email test@example.com` 550, `config user.name t` 457, `config user.email t@t` 317.
- `git init` is 3,579 processes at 17–19 ms of CPU each on the measuring machine, because the default template copies the sample hooks into every new repo. With an empty template directory an init costs 13.5 ms.
- Measured on one five-process fixture (init, config, config, add, commit): writing the identity straight into `.git/config` and using an empty template directory cut it from 61 ms to 38 ms of CPU.

At c059556f, 131 files under `tests/` mention `user.name` or `user.email`: 78 under `tests/bin-lib/` (215 sites), 49 top-level test files (147 sites) and 4 helpers (10 sites). 41 files already pass the identity inline as `-c user.name=...`, which costs no extra process.

`tests/helpers/git-fixtures.js` holds the shared builders (`gitRepo`, `committedRepo`, `fixtureGit`). `tools/run-tests.js` already injects environment into its child tree (`gitFixtureConfigEnv`, `TMPDIR`), and `tests/helpers/git-template.js` sets the same kind of default for a bare `node --test` run.

Sibling records own these files, and this record leaves them alone: `tests/hooks-pre-tool-use.test.js`, `tests/hooks-pre-tool-use-forge-memo.test.js` and `tests/bin-lib/verify/cli-helpers.js` (#5324); `tests/bin-lib/reconcile/prune-remote.test.js`, `tests/bin-lib/pre-review-catchup/cli.test.js` and `tests/bin-lib/issues/claims-git-cas.test.js`; everything under `tests/bin-lib/learned-skills/` and `tests/helpers/learned-skills-capture.js`; `tests/statusline.test.js`, `tests/bin-lib/reconcile/archive-merged.test.js`, `tests/bin-lib/reconcile/archive-merged-record-guards.test.js` and `tests/bin-lib/staged-patch/stack-check.test.js`.

## Deliverables

1. A helper in `tests/helpers/git-fixtures.js` that makes a repository with one git process: it runs `git init` (optional branch, optional bare) and writes the identity into the repository's config file with `fs`, giving the same `user.name` and `user.email` values a `git config` call would. A second export writes the identity into an existing repository's config for callers that init some other way.
2. Every `git init` in a runner child uses an empty template directory, set once in `tools/run-tests.js`'s child environment, with the same default applied for a bare `node --test` run by the helper module. Tests that write into `.git/hooks/` or `.git/info/` without creating the directory keep working (ship those two empty directories in the template, or fix the callers). Tests that assert on template content (a sample hook, `description`, `info/exclude`) are found and kept green.
3. Every fixture `git config user.name` / `git config user.email` process in the test tree is replaced by the helper, except in the sibling-owned files listed in Current State and in tests where a `git config` call is itself the behaviour under test. The name and email each fixture commits with stay the same.
4. A suite test that keeps it that way: it scans the test tree for a spawned `config user.name` or `config user.email` and fails on any outside a per-file allowlist whose entries each carry a reason. The sibling-owned files start on the allowlist with their record number as the reason.
5. The PR body reports, for the touched files, total git processes and `git config` processes before and after.
