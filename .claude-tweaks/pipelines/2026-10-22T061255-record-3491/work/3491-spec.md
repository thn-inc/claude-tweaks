# 3491: Pin the no-wall-clock-budgets-in-tests/ convention with a conformance test

Origin: reflect full from #3412

Defer-reason: tangential

## Current State

`docs/plugin-structure.md:67` states that wall-clock timing budgets live in `perf/` (run by `npm run test:perf`) and never in the default `npm test` suite, because they flake under sibling-suite load. Nothing enforces that convention: #3412's build landed a `performance.now()` `< 200ms` assertion in `tests/bin-lib/reconcile/release-merged.test.js` to prove regex linearity, and it reached review before anyone noticed (open-items ledger row 23; the removal is `staged/review-1.patch` in run `2026-10-17T192303-spec-3412`). The same run hit two unrelated timing-test flakes under a load average above 200, which is the exact failure the convention exists to prevent.

Evidence: `grep -rl performance.now tests/` returns only the #3412 test file today, so the convention has held by habit alone; the repo already pins prose conventions with conformance tests (`tests/*-conformance.test.js`), so the enforcement shape exists.

Cost this session: one review finding, one staged patch, one Review Console row; no rework.

## Deliverables

A conformance test under `tests/` that scans every `tests/**/*.test.js` for a wall-clock assertion shape (`performance.now()`, `Date.now()`, or `process.hrtime` compared against a numeric budget in the same test body) and fails naming the file and line.

The test cites `docs/plugin-structure.md`'s perf/ rule in its failure message so the fix direction (move the budget to `perf/`) is on the failing line.

An allow-list mechanism for a deliberate exception, with a required one-line reason, so the gate can be bypassed visibly rather than by deleting the test.

## Acceptance Criteria

Adding a `performance.now()` budget assertion to any file under `tests/` makes `npm test` fail with the offending `file:line` and the perf/ pointer.

A budget assertion under `perf/` does not trip the test.

The existing suite passes with the test in place (zero current offenders once `staged/review-1.patch` from #3412 lands, or the one offender it names is the #3412 test and the patch is applied first).

## Release Note

Test suite: a conformance check fails any wall-clock timing budget placed under `tests/` and points at `perf/`, so timing budgets can no longer flake the default `npm test` run.
