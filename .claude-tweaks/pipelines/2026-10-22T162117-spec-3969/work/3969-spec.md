# 3969: Test suite overloads the dev machine — unbounded concurrent suites, leaked temp dirs, npx probe on every SessionStart

## Current State

- **No machine-wide concurrency control.** Every `npm test` (`tools/run-tests.js`) runs `node --test` over ~901 files at the default concurrency (`os.availableParallelism() - 1` = 11 workers on a 12-core Mac). Concurrent sessions' `verify.js` runs stack whole suites on top of each other. Measured on 2026-10-22 with two full suites live: load average 98–176 on 12 cores, 29% sys CPU with 35% idle (kernel fork/exec + filesystem contention), and a bare `node -e 0` taking 0.71s. `tests/helpers/git-fixtures.js` already documents a ~50ms test taking 41s under three concurrent suites. Prior issues #3/#104/#134/#197 only widened timeouts or allowlisted the flaking test.

- **Test temp dirs leak.** 203 of the 330 test files that call `mkdtemp` never remove what they create. `os.tmpdir()` held more than 95,000 leaked entries (`ct-wtd` 6.5k, `verify-cli-test` 3.4k, `ct-wtd-parent` 2.9k, …), most of them whole git repos. A streaming readdir of it took more than 100s, which slows every `mkdtemp` and every other tool that uses `$TMPDIR`, and it grows until reboot.

- **A shipped SessionStart probe spawns npx.** `plugin/bin/lib/deps.js` `playwrightCliMessage()` runs a synchronous `npx --no-install playwright-cli --version` inside `deps.collect()`, which `plugin/bin/lib/hooks/session-start.js` calls on every session start for every plugin user. One probe measured 1.9 CPU-seconds, and 32.7s wall-clock under load. `tests/hooks-session-start.test.js` runs the real hook in-process 63 times, paying that cost on every call.

## Deliverables

1. `tools/run-tests.js` creates a per-run temp root `ct-testrun-<pid>-XXXXXX` under `os.tmpdir()` and exports it as `TMPDIR`/`TMP`/`TEMP` to the spawned `node --test`. It removes the root on exit, including SIGINT/SIGTERM, and sweeps stale `ct-testrun-*` roots whose owning pid is dead.

2. `tools/run-tests.js` enforces a machine-wide suite slot limit: lock files under the real `os.tmpdir()`, default 1 concurrent suite, overridable with `CT_TEST_SUITE_SLOTS`. Locks left by a dead pid are reclaimed, and a waiting run prints which pid holds the slot. It also passes a default `--test-concurrency` of about half the available cores, overridable with `CT_TEST_CONCURRENCY`.

3. `plugin/bin/lib/deps.js` answers "is playwright-cli installed" with a PATH lookup and spawns no subprocess. After this change `tests/hooks-session-start.test.js` spawns no npx.

## Acceptance Criteria

- [ ] After a full `npm test`, the real `os.tmpdir()` holds no new entries whose names match a test `mkdtemp` prefix, and no `ct-testrun-*` root remains.

- [ ] With two concurrent `npm test` invocations, the second waits for the slot and prints the holder's pid. A lock file left by a dead pid is reclaimed, not waited on.

- [ ] `deps.collect()` spawns no subprocess for the playwright check: a PATH containing a `playwright-cli` executable reports it installed, and a PATH without one returns the install message.

- [ ] Unit tests cover the new `run-tests.js` helpers (temp-root lifecycle, slot acquire/reclaim, concurrency default and env override) and the `deps.js` PATH lookup, and each was proven red by reverting the change.

- [ ] The full suite is green.

## Release Note

Session start no longer launches npx to check for playwright-cli, so starting a Claude session is faster, especially on a busy machine.

## Technical Approach

### Key Files

- `tools/run-tests.js` — per-run TMPDIR root, suite slot lock, default --test-concurrency
- `plugin/bin/lib/deps.js` — replace the npx probe with a PATH lookup
- `tests/package-json-test-script.test.js` — extend for the new run-tests.js helpers (or a new sibling suite)
- `tests/hooks-session-start.test.js` — assert no npx spawn
