# 5555: Write timing.json in code when a run closes, for every run

Surface: backend

**Related:** #5535, #5013, #5466, #5376, #5377, #3978, #3977
Risk-flags: none

## Current State

`timing.json` is written only when a model step runs `plugin/bin/phase-timing.js`: the wrap-up summary, the verification brief, the flow summary and `/claude-tweaks:dispatch`'s group report (`plugin/skills/dispatch/reporting.md`). A run that closes without reaching one of those steps has no timing file, so every cost report built on the archive sees a biased sample.

Measured on 2026-11-15 over this machine's run directories (scratch scripts; re-derive before relying on a number):

- All run directories: 406 of 2,948 have `timing.json`.
- November runs named `spec-` or `record-`: 149 of 255 have it. Of the 106 without, 93 are closed (`status: clean`), 7 are active, 2 interrupted and 4 are empty directories.
- 90 of the 106 are dispatched runs (`dispatched: true` in `run-state.json`). 55 carry a `close-without-wrapup` event. 48 have a wrap-up line in `decisions.md` and still no timing file.
- For 92 of the 93 closed runs, a transcript for the recorded session id is still on disk.
- Of the 149 files that exist, 10 have no token totals.
- After a close, `run-state.json` holds the worktree path under `worktreeAtClose` and `worktree` is null (91 of the 106). `phase-timing.js --auto-transcript` reads only `worktree`, so on a closed run it falls back to the session id alone and takes the newest candidate. A dispatch session has one transcript per worktree it entered, so that candidate can belong to another run.

Every finishing run passes through `closeRunState` in `plugin/bin/lib/hooks/close-run-state.js`. It has three callers: the `close-run` verb in `plugin/bin/hooks.js`, `plugin/bin/lib/hooks/teardown-run.js`, and the reconciler's archive path in `plugin/bin/lib/reconcile/archive-merged.js`. The pipeline driver closes its runs through `hooks.js close-run` with a 120-second limit (`plugin/bin/lib/driver/merge.js`, `settle.js`).

Design: `docs/superpowers/specs/2026-11-15-process-efficiency-design.md`, Phase 5, unit 5.1 (branch `worktree-design-process-efficiency`).

## Deliverables

1. **Cause table.** The PR carries the table above, re-derived at build time, with one row per cause and its count.
2. **Timing as a function.** The computation in `phase-timing.js`'s `run` moves to a module under `plugin/bin/lib/timing/` that takes a run directory and options and returns the timing object. `phase-timing.js` calls it and its output does not change.
3. **Written when a run closes.** Each path that closes a run writes `timing.json` after the state change succeeds, in code, with no model turn. The PR lists the closing paths and the call site for each.
4. **Transcripts for a closed run.** The writer finds the run's transcript from `sessionId` and `worktreeAtClose` (or `worktree` when still set). For a dispatched run it reads the transcripts of that run's own calls and no other run's.
5. **An existing file is kept when it is better.** A `timing.json` that already has token totals is left as it is. One that is absent, or has no token totals, is written. The `budget` key is carried forward as today.
6. **A close never fails or stalls on timing.** A failure to derive or write timing is logged to the run's `decisions.md` as a `SKIP` line per `_shared/auto-decision-log.md`'s Degrade-trace rule, and the close result is unchanged. The added work stays inside one time bound: a named constant exported by the writer module, at most 60 seconds (half the driver's 120-second limit) for the whole timing step across every transcript it reads. The deadline is checked inside the transcript read loop; past it, the writer stops and logs the same `SKIP`.
7. **Docs.** `docs/hooks.md` and `docs/plugin-structure.md` say who writes `timing.json` and when.

## Technical Approach

Split `run` in `plugin/bin/phase-timing.js` at the point where it has parsed its arguments: everything from reading `events.jsonl` to building the `timing` object becomes the library function; argument parsing, the write, the budget check's output lines and the rendering stay in the CLI or move with care. The closing paths call the function in-process; they do not spawn `phase-timing.js`.

`resolveTranscripts` gains the closed-run case: `worktreeAtClose` stands in for a null `worktree`. `locateTranscripts` already takes `cwd` and `sessionId`.

For a dispatched run, the files `phase-timing.js` wrote in November name a transcript under the run's own worktree slug with the dispatching session's id, for example `…--claude-worktrees-dispatch-record-4505/{sessionId}.jsonl`. Check whether that holds for every dispatched run before relying on it; `tools/guard-refusals/transcripts.js` already attributes a subagent transcript to the run it names and is the second rule to consider.

The reconciler's archive path can run inside a session-start pass. Read `docs/hooks.md` and `docs/reconcile-checks.md` before choosing where the reconciler's write happens; `plugin/bin/lib/reconcile/background-spawn.js` is the existing way to do work off a hook's path. Decided 2026-11-15: `hooks.js close-run` and `teardown-run.js` are typed commands, not hook events; they write the whole file, token totals included, before they return, inside the time bound. The reconciler's archive path writes the phase rows from `events.jsonl` before it returns, with no transcript read, and fills the token totals in its background pass. A background pass that fails or cannot start leaves the phase rows and logs the `SKIP` line.

Do not change what `--check-budgets` does or when it runs. The closing paths never run it.

A `timing.json` "has token totals" when its `totals.tokens` object is present and the sum of its `input`, `output`, `cacheRead` and `cacheCreate` is above zero; `phase-timing.js` writes `totals.tokens` only when it ran with token derivation on. A replaced file is rewritten whole from the derivation, and `budget` is the only key carried forward, as `phase-timing.js` carries it today.

The library function returns the timing object and the transcript notes and does not run the budget check. One shared write helper, called by the CLI and by every closing path, carries `budget` forward and writes to a temporary file in the run directory and renames it, so a reader never sees a half-written file and a second closer re-reading the same run reaches the same result.

When the run's own transcripts cannot be established (neither `worktreeAtClose` nor `worktree` is set, or the session id has no transcript under that slug), the writer writes the phase rows with no token totals and logs one `SKIP` line naming the reason. It never falls back to the newest candidate for a dispatched run.

**As built (architecture alignment, /build Common Step 4.5).** The derivation lives in `plugin/bin/lib/timing/run-timing.js` and the closing-path writer in `plugin/bin/lib/timing/at-close.js` (`derive.js` is unchanged). Three refinements of the approach above:

- When a session transcript holds more than one run's calls, the at-close writer counts only the main-transcript rows inside the run's own lifetime: from the earliest of the run id's UTC timestamp, `createdAt` and the first event, through the later of `updatedAt` and the last event. A message id is placed by its first line's timestamp. This is how Deliverable 4's "no other run's" holds for two runs of one session. `phase-timing.js` does not clip, and its output is unchanged.
- The reconciler's background pass is a detached `plugin/bin/timing-at-close.js` process (`spawnTokenPass`), not `background-spawn.js`. That process takes the caller's env, and a spawn error logs the `SKIP` line.
- The shared write takes the run dir's `.timing.lock` around read-check-write, so a token pass and a closer cannot overwrite each other. A run dir that an archive moves away mid-write is followed to its archive twin, never recreated.

## Gotchas

- `plugin/bin/hooks.js` is being edited by several open records (#5376 and #5377 are in progress and move its tests in-process; #5545, #5525, #5261). Keep the change in `hooks.js` to the one call and rebase on what has landed.
- #5535 removes the `main()` shim from `phase-timing.js`. #5013, #5466, #5093 and #4259 edit `plugin/bin/lib/timing/derive.js`. Rebase on whichever has landed.
- A run on the previous release may be closed by this release's code, and the reverse. A run directory with no `worktreeAtClose` key, or with an older `run-state.json`, must close as it does today.
- A multi-record run has `spec-N` directories under one parent run directory. State in the PR which directory gets the file; `tools/efficiency-report.js` reads only the top-level one. Decided 2026-11-15: one file, in the top-level run directory, covering the whole run. The close writes nothing into a `spec-N` directory; per-record files there stay as the multi-spec summary step writes them today (#5013 owns their content).
- Decided 2026-11-15: history is not backfilled. Runs closed before this ships keep whatever `timing.json` they have; the replay in AC7 runs on copies and commits nothing into the archive. Cost reports over older runs stay a partial sample, and the Release Note says so.
- A driver run's workers are headless sessions. State in the PR what such a run's `timing.json` contains; phase rows with no token totals are acceptable there if the PR says so.
- Transcripts for a twelve-hour session are large. `readUsage` streams; keep it that way.
- Active and interrupted runs are out of scope. They get a file when they close.

## Release Note

Every pipeline run now gets a `timing.json` when it closes, including dispatched runs and runs closed without a wrap-up, so cost reports cover all runs from this release on. Runs closed earlier are not backfilled.
