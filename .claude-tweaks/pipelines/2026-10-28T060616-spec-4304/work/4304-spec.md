# 4304: Catch up with the integration branch before the whole-branch review, not only at worktree creation

Verified-as-of: 5871d691bb6dd6a1ae363d1e3a1a7c4e1953264d

Origin: Review Console residue of #4149 (run 2026-10-24T163054-spec-4149), triaged 2026-10-25

Defer-reason: genuinely-larger

## Current State

`/claude-tweaks:build` merges the integration branch into its worktree once, in `build/worktree-setup.md` step 4's post-creation catch-up (plus `/flow`'s pre-flight divergence check). After that, nothing checks for new commits on main again until review's merge-provenance step, or until a PR-first merge finds the PR `DIRTY`.

Evidence from #4149:
- #4015 landed mid-run on the same functions in `plugin/bin/lib/hooks/git-command.js` (the handler signature changed shape). It surfaced only at review Step 2, and cost a semantic-merge dispatch, a win32 follow-up and a second full suite (#4149 reflect-3).
- At merge, PR #4166 went `DIRTY` twice in one merge-mode invocation: first #4028, then #4210, which rewrote the same scanner and needed a hand semantic merge plus a three-way bash differential.

## Deliverables

- Before the SDD whole-branch review, check `origin/{integration-branch}` for commits since the merge base that touch any file this branch changed.
- When it has some, merge them into the worktree first and re-run the suite, so the review judges the combined code.
- Log the catch-up to the run's `decisions.md` in the existing catch-up log shape.
- Keep the failure posture of the existing post-creation catch-up: a merge conflict stops for resolution, and a fetch error fails open with a distinct log line.

## Acceptance Criteria

- [ ] A branch whose changed files were also changed on the integration branch after worktree creation is merged before the whole-branch review starts, and the review sees the merged tree.
- [ ] A branch with no overlapping upstream commits runs no merge, and logs the check.
- [ ] A conflicting catch-up stops for resolution rather than reviewing the stale tree.

## Release Note

Long builds now pick up overlapping changes from main before the final review, so conflicts surface during the build instead of at merge.

## Technical Approach

### Key Files

- `plugin/skills/build/worktree-setup.md` — name the pre-review catch-up beside the post-creation one
- `plugin/skills/_shared/worktree-setup.md` — reuse the Post-creation catch-up procedure for the pre-review check
  - As built (Common Step 4.5, Beneficial): the procedure lives in a new `plugin/skills/_shared/pre-review-catchup.md`, called from `plugin/skills/build/dispatch.md` through `plugin/bin/pre-review-catchup.js`. The worktree-setup bundle composed at `build/SKILL.md` Common Step 1 sits at 51,890 of 52,500 bytes, so a new section there did not fit. The new file reuses the Post-creation catch-up's failure posture (conflict stops, fetch error fails open with a distinct line, Windows long-path fix) and its `worktree branch advanced from … to …` log shape, and cites that file's integration-branch ladder rather than restating it.
