# 3695: Windows regression: 1 test file(s) newly failing after 4a67158d1

Surface: infra

**Related:** #2767, #3599, #3644, #3693, #3696, #3698, #3699, #3702, #3703

## Current State

`tests/hooks-teardown-run.test.js` fails on `windows-latest`. Its test "AC1 (#3490): a merged run with an unlocked worktree closes state, removes the worktree, deletes branch and remote ref — and never archives the run dir" (line ~58) prints `branch: skipped — no branch recorded` where it expects `branch: deleted feat-branch`. It was reported after 4a67158d1 (PR #3628) and is still failing on the latest Windows run on main (run 39414412621 at 63ce07e5a).

This is a shipped-code defect, verified against `origin/main` at `fa8286fc8`:

- `plugin/bin/lib/hooks/teardown-run.js:83` (`branchOfWorktree`) matches with `entry.path === worktreePath`. On Windows, `git worktree list --porcelain` prints `D:/a/.../feat` with forward slashes, while the stamped worktree path is native (`D:\a\...\feat`, written via `path.resolve` at `hooks.js:698`, `context.js:797` and `post-tool-use.js:337`). The strict compare never matches, `branch` falls through to null, and teardown skips both the local branch delete and the remote-ref delete.
- `teardown-run.js:257` has the same strict compare (`w.path === effectiveWorktreePath`), so the #2747 prunable-then-prune retry never fires on Windows either.
- The bug predates #3628: base aaab5285f already fails 5 tests in this file with the same line. #3628 renamed AC1 and made AC7 reach the integration-branch guard, so both counted as new.
- Its sibling `deriveBranch` (`plugin/bin/lib/hooks/run-integrity.js:84-99`) compares `realpathOrSelf` on both sides and is unaffected. `archive-merged.js:2059` and `release-merged.js:425` use `path.resolve(a) === path.resolve(b)`.

User impact on Windows: `hooks.js teardown-run --merged` leaves the merged run's local branch and remote ref behind and reports `no branch recorded`, unless `run-state.json` already carries `branch`.

## Deliverables

1. Normalize both sides of the worktree-path comparison at `teardown-run.js:83` and `:257` using the repo idiom `path.resolve(a) === path.resolve(b)`, through a `pathImpl` parameter (default `path`) so a `path.win32` pin can run on Linux.
2. Add a pin in `tests/hooks-teardown-run.test.js` (or a unit test beside it) where the porcelain output carries `D:/a/x/feat` and the stamped path is `D:\a\x\feat`: `branchOfWorktree` resolves the branch, and the prunable-retry lookup finds the entry.

## Acceptance Criteria

1. With `path.win32`, a forward-slash porcelain path and a backslash stamped path for the same worktree resolve to that worktree's branch.
2. The same win32 pin finds the prunable entry at the `:257` lookup.
3. Both pins fail when the strict `===` compares are restored.
4. `node --test tests/hooks-teardown-run.test.js` passes, and `npm test` passes.

## Release Note

Fix merged-run teardown on Windows so it deletes the run's branch and remote ref instead of reporting "no branch recorded".

## Technical Approach

Keep `path.resolve` rather than a realpath-only compare at `:257`, because the worktree may already be half-removed there and realpath would fail. Thread `pathImpl` only through the two compare sites and do not refactor `parseWorktreeList`. Do not change the test's expected strings: the existing assertions are correct, and the code under them is wrong.

### Key Files

- `plugin/bin/lib/hooks/teardown-run.js` — normalized compares at `:83` (`branchOfWorktree`) and `:257` (prunable retry), plus the `pathImpl` seam
- `tests/hooks-teardown-run.test.js` — the win32 forward-slash vs backslash pin
- `plugin/bin/lib/hooks/run-integrity.js` — `deriveBranch`'s `realpathOrSelf` precedent (read only)

## Gotchas

- `path.resolve` on win32 does not fold drive-letter case (`d:` vs `D:`). If the porcelain and stamped paths can differ in drive case, compare case-insensitively on win32. Check the CI log's casing before deciding.
- Only the post-merge `windows-regression` run confirms the other 5 pre-existing failures in this file clear. They share this root cause, but that has not been proven per test.
