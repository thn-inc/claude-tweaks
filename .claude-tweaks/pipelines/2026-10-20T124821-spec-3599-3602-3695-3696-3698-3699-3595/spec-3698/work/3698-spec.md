**Related:** #2767, #3599, #3644, #3670, #3693, #3695, #3696, #3699, #3702, #3703

## Current State

`tests/review-cross-lens-corroboration-conformance.test.js` fails on `windows-latest` with `mutation did not change the text`, in "AC1.2 go-red: stripping the At `medium` sentence from the bullet fails the same assertions" (line ~101) and in the share-a-location go-red test (line ~115). It first failed after 01a92e9c2 (PR #3662, record #3604) and is still failing on the latest Windows run on main (run 39414412621 at 63ce07e5a).

Cause, verified against `origin/main` at `fa8286fc8`:

- Line 11 reads `plugin/skills/review/step3-lens-dispatch.md` raw with `fs.readFileSync`.
- On a Windows checkout (core.autocrlf) the file is CRLF, so after `split('\n')` every line keeps a trailing `\r`.
- The go-red mutation `l.replace(/ At \`medium\`.*$/, '')` cannot match, because `.` stops at `\r` and a non-multiline `$` sits after it. The text comes back unchanged.

`.gitattributes` does not cover skill markdown, and that is intended: the test must normalize. This is a test-harness defect only.

## Deliverables

1. Replace line 11's raw `read` with the existing normalizer `readText` from `tests/helpers/read-skill.js`.
2. Add a case that feeds `crlfCheckoutRead` (same helper file) through both go-red mutations and asserts they still change the text.

## Acceptance Criteria

1. Both go-red mutations change the text when the skill is read through `crlfCheckoutRead`.
2. The new CRLF case fails when line 11 is reverted to raw `fs.readFileSync`.
3. `node --test tests/review-cross-lens-corroboration-conformance.test.js` passes, and `npm test` passes.
