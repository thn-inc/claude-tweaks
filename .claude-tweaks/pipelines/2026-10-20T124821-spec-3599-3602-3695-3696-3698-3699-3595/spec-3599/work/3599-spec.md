# 3599: Windows regression: 1 test file(s) newly failing after e91df452c

Surface: infra

**Related:** #2767, #3644, #3693, #3695, #3696, #3698, #3699, #3702, #3703

## Current State

`tests/diff-facts-parse-numstat-conformance.test.js` fails on `windows-latest`. Its test "the documented node -e composition runs and yields a diff-facts object" (line ~54) exits 1 with `Cannot find module 'D:aclaude-tweaksclaude-tweaksplugin/bin/lib/blast-radius-cli.js'`. It first failed after e91df452c (PR #3556) and is still failing on the latest Windows run on main (run 39414412621 at 63ce07e5a), where baseline adjudication classes it as pre-existing.

Cause, verified against `origin/main` at `fa8286fc8`:

- Line 13 builds a native `PLUGIN` path (`D:\a\claude-tweaks\claude-tweaks\plugin` on win32).
- Line 59 splices it into the extracted `plugin/skills/wrap-up/ceremony-derivation.md` line in place of `${CLAUDE_PLUGIN_ROOT}`, inside `node -e "...require('${CLAUDE_PLUGIN_ROOT}/bin/lib/blast-radius-cli.js')..."`.
- Inside that JS single-quoted literal, each `\a`, `\c` and `\p` is read as an escape, so the backslashes disappear.

This is a test-harness defect. The repo's settled convention (#3509, #3517, recorded in `.claude/skills/windows-checkout-test-parity/SKILL.md`) is that a test passes the plugin root with forward slashes, never that it rewrites the shipped prose. `tests/backlog-refine-foldin-no-truncation.test.js:26` and `tests/dispatch-neighbour-in-flight-mcp.test.js:74` already do this.

## Deliverables

1. On line 13 of `tests/diff-facts-parse-numstat-conformance.test.js`, build `PLUGIN` as a forward-slash path with `toPosix` from `plugin/bin/lib/shared-primitives.js` (or the inline `split(path.sep).join('/')` idiom its sibling tests use).
2. Add a Linux-runnable case proving the substituted command carries no backslash when `PLUGIN` comes from a win32-shaped root, per the windows-checkout-test-parity skill's "take the platform as a parameter" rule.

## Acceptance Criteria

1. The command line 59 substitutes contains no `\` character for a root built from `path.win32.join('D:\\a\\repo', 'plugin')`.
2. The new case fails when line 13 is reverted to the native `path.join` form.
3. `node --test tests/diff-facts-parse-numstat-conformance.test.js` passes on macOS/Linux, and `npm test` passes.

## Release Note

Fix a Windows-only test failure in the diff-facts conformance suite caused by backslashes in the plugin path.

## Technical Approach

This is a test-only change: `PLUGIN` is used only at line 59, so the swap is local. Keep `ROOT` native for the `readText` calls on line 14, since only the path spliced into the JS literal needs forward slashes.

### Key Files

- `tests/diff-facts-parse-numstat-conformance.test.js` — forward-slash `PLUGIN`, plus a win32-shaped pin
- `plugin/bin/lib/shared-primitives.js` — `toPosix` (read only)
- `plugin/skills/wrap-up/ceremony-derivation.md` — the extracted composition at line ~37 (read only, unchanged)

## Gotchas

- Do not change `ceremony-derivation.md`. More than 100 shipped `require('${CLAUDE_PLUGIN_ROOT}/...')` sites share its shape, and moving them all to an env-var read is a separate question. That question is whether Claude Code hands `CLAUDE_PLUGIN_ROOT` to a Windows session with backslashes, which nothing in the repo confirms either way. If the build finds evidence that it does, file it as its own record instead of widening this one.
- CI has no Windows job before merge, so the post-merge `windows-regression` workflow is the only ground truth. Check that run after merge.
