# 3699: Windows regression: 1 test file(s) newly failing after 8a6114ed7

Surface: infra

**Related:** #2767, #3599, #3644, #3693, #3695, #3696, #3698, #3702, #3703

## Current State

`tests/display-ci-readers-conformance.test.js` fails on `windows-latest`. Its test "AC1.1: item 9 CI filter keeps green/no-ci, drops pending, red and a failed read" (line ~87) exits non-zero with `Cannot find module 'D:a_tempct-display-ci-SeJrImcandidates.json'`. It first failed after 8a6114ed7 (PR #3640) and is still failing on the latest Windows run on main (run 39414412621 at 63ce07e5a).

Cause, verified against `origin/main` at `fa8286fc8`:

- Line 101 builds a native `candidatesFile` path.
- Line 104 substitutes it raw for `$PR_SCAN_UNARMED_CANDIDATES` in the extracted item-9 CI filter from `plugin/skills/_shared/github-pr-scan.md` (`require('$PR_SCAN_UNARMED_CANDIDATES')`, `fs.writeFileSync('$PR_SCAN_UNARMED_CANDIDATES', …)`).
- Inside those JS single-quoted literals, `\a`, `\_`, `\t` and `\c` are read as escapes, and `\t` even becomes a TAB.

This is a test-harness defect. In real use the shell fills the variable from `plugin/bin/session-tmp-resolve.js`, whose `formatPrintedPath` already prints forward slashes on win32.

`tests/sweep-backstop.test.js` substitutes the same variables with native temp paths at lines 101-103 and 180-182. It is also in the Windows failing set.

## Deliverables

1. On line 104 of `tests/display-ci-readers-conformance.test.js`, substitute `toPosix(candidatesFile)` (from `plugin/bin/lib/shared-primitives.js`). Keep the native path for the test's own `fs.writeFileSync`/`readFileSync` calls.
2. Apply the same forward-slash substitution to `tests/sweep-backstop.test.js` lines 101-103 and 180-182 (`candidatesPath`, `inputPath`).
3. Add a Linux-runnable pin per suite showing that the substituted script carries no backslash for a win32-shaped temp path.

## Acceptance Criteria

1. In both suites, a script substituted from a `path.win32`-shaped temp path contains no `\` inside the `require(...)`/`writeFileSync(...)` literals.
2. Each new pin fails when its substitution is reverted to the native path.
3. `node --test tests/display-ci-readers-conformance.test.js tests/sweep-backstop.test.js` passes on macOS/Linux, and `npm test` passes.

## Release Note

Fix Windows-only failures in the PR-scan CI-filter tests caused by backslashes in substituted temp paths.

## Technical Approach

This is a test-only change mirroring what `session-tmp-resolve.js` does in production: forward-slash the path only where it is spliced into script text. `PLUGIN_ROOT` already reaches the script through the environment (line 108) and needs no change.

### Key Files

- `tests/display-ci-readers-conformance.test.js` — forward-slash substitution plus a win32-shaped pin
- `tests/sweep-backstop.test.js` — the same substitution at both sites plus a pin
- `plugin/bin/lib/shared-primitives.js` — `toPosix` (read only)
- `plugin/bin/session-tmp-resolve.js` — `formatPrintedPath`, the production twin (read only)

## Gotchas

- `$PR_SCAN_UNARMED` is a prefix of `$PR_SCAN_UNARMED_CANDIDATES`. Keep sweep-backstop's longer-name-first substitution order.
- `sweep-backstop.test.js` may have other Windows layers behind this one. The acceptance criteria cover only the substitution, so do not claim the whole file goes green on Windows until the post-merge `windows-regression` run shows it.
