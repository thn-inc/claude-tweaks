# 1927: Multi-session drain: document the N-session shape and export CLAUDE_TWEAKS_LEASE for test-database isolation

Surface: infra
**Related:** #1793

## Overview

#1904 asked whether a single dispatching session could run groups concurrently via the `cd {worktree} &&` prefix mechanism (#447). It cannot safely: that shape breaks the one-session-one-worktree binding three hook gates depend on (`record-worktree` stamps `{worktree, sessionId}` per run; `wd-deny`/`checkWorktreeRequired` resolve the target from the session's tracked cwd, not a command's `cd`; SubagentStop and every `events.jsonl` append attribute to the session's single owned run), the worktree Bash-shape guard refuses most compound commands, and it puts N groups' outcomes in one orchestrator's context (`[IL-130]`). The supported throughput shape is N top-level sessions, each running `/claude-tweaks:dispatch` (or a bare drain) — the shape every existing invariant already assumes. Claims, the sibling-session check, fail-closed reaping, per-checkout port leases, and rate-limit backoff already prevent collision.

This unit documents that shape once, in `dispatch/sequential-execution.md`, and adds the one missing hook-point: the ports registry exports `CLAUDE_TWEAKS_LEASE` (the leased block's base port) alongside `PORT`/`{NAME}_PORT`, so a project can key its test database or schema name on a stable per-checkout token (`DATABASE_URL=…test_${CLAUDE_TWEAKS_LEASE}`) the same way it keys ports. The plugin creates no databases; it gives the project the token.

**Complexity:** Low
**Estimated tasks:** 4

## Non-Goals

- Any concurrency mechanism inside one session — explicitly rejected.
- Creating or migrating test databases.
- Changing claims, reaping, or the sibling-session check — they already hold.
- The `port-services` policy key, SessionStart lease ensure, statusline segment, or release sites — #1792/#1793 (this unit builds on the merged registry and env-file writer, and is blocked by #1792's edits to `ensure.js`).

## Technical Approach

The token is the lease base, which is already unique per checkout by the registry's construction; exporting it is one more managed line. Documentation states the recommendation once, in the dispatch skill's sequencing file, and cites the existing controls instead of restating them.

### Data / API Surface

- `.env.local` / `.env` managed region: `CLAUDE_TWEAKS_LEASE={base}` as the first line, followed by `PORT`, `{NAME}_PORT` as today.
- `ensure()`'s returned `vars` includes the lease pair; the return object gains `leaseLineAdded: boolean`.

## Gotchas

- Red-team resolution: a lease reallocation (foreign-takeover) changes the lease base — a project's already-created `test_{oldBase}` database becomes stale under the new lease. Out of scope for this unit (the plugin creates no databases); a project adopting the `DATABASE_URL` keying pattern should document its own cleanup/migration step for this case.
- Red-team resolution: #1792 remains OPEN on GitHub as of this decomposition (verified via `gh issue view 1792`) even though `plugin/bin/lib/ports/ensure.js` already exists in the tree with a header comment citing it — confirm #1792's actual merge/PR state before Task 1 rather than assuming the Prerequisites row is stale.
- Red-team resolution: "a literal test-database name" for the report-only rewrite-table row matches a small hardcoded literal list (e.g. `test_db`, `testdb`, `test.db`) appearing as a literal value in `.env`/`vitest.config.*` — false negatives (an unlisted literal) are accepted since this row is report-only.

- Merge `origin/main` before starting: #1792 edits `ensure.js` and `policy-schema.md`; a stale base makes the line numbers wrong before task 1.
- `isRegionCurrent` keys on `PORT === base` and `sameServices`; keep it exactly so. The lease line's absence is detected by a separate completeness step inside `ensure()` that rewrites the region in place with the same base — never by making `isRegionCurrent` return `false`, because its only consumer treats "not current" as a foreign takeover and reallocates to a new base (read `ensure.js`'s `registry.allocate`/`reallocate` branches before implementing).
- The managed region's EOL detection (`detectEOL`) and CRLF handling must survive the new first line; test with a CRLF fixture (`#1787` is the CRLF precedent in wrap-up).
- Never rewrite a project's database name automatically — the row is report-only; a wrong rewrite would point tests at a database that does not exist.
- `policy-schema.md` is at 38,433 bytes; one clause, not a paragraph.
- The `[IL-107]`/`[IL-43]`/`[IL-51]` citations in the new section are by tag; do not paste incident narratives (CLAUDE.md's conciseness rule).
- `refs #N` in commits.

## Decision Rationale

See the Phase 1 sub-issue's Decision Rationale for the design-wide rationale. Specific to this unit: N sessions is the shape every invariant already assumes, so nothing structural changes; the `cd {worktree} &&` shape was confirmed only on a failure path and breaks attribution, guard, and clean-room properties; parallel SDD implementers inside a build are deferred upstream (SDD forbids them; `[IL-43]`, `[IL-51]`, `[IL-108]`, and the Frontier-singleton rule depend on SDD staying sequential).
