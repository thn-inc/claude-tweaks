# 1924: init generates a starter verify-scope.json and reports drift; this repo declares its own

Surface: backend

## Overview

The scoping engine (Phase 2a) resolves `mode: full` on every project until that project declares `.claude-tweaks/verify-scope.json`. Hand-writing the declaration is the kind of setup step nobody does, so `/claude-tweaks:init` generates a starter from what it can detect — workspace packages become suites, shared packages map to every suite, the pipeline's own bookkeeping paths map to nothing — and `init --update` reports drift between the declaration's suite list and the workspace list. This unit also declares this repo's own file, which is what turns the saving on for claude-tweaks' own dispatched groups: prose under `plugin/skills/**` stays fully verified (it is under test), while ledger rows and pipeline run-dir files resolve to `none`.

**Complexity:** Medium
**Estimated tasks:** 5

## Non-Goals

- The engine or its pipeline wiring — Phases 2a/2b.
- Rewriting a project's test scripts or workspace config; the starter only reads them.
- Mapping any source path to `[]` — the starter never does; only bookkeeping paths get the no-suite rule.
- A policy lever: the declaration is a sibling file, not a `policy.yml` key, and needs none of `_shared/auto-mode-contract.md`'s "Adding a new policy lever" checklist.

## Technical Approach

Detection is mechanical (a module with fixture tests), rendering is a skill sub-file (the Step 6.5 pattern), and this repo's declaration is committed as a normal tracked file. The starter is conservative by construction: a path is either a package's own tree (its suite), shared (every suite), bookkeeping (nothing), or unmatched (full).

## Gotchas

- Red-team resolution: the yarn suite-command template is `yarn workspace {name} test` (yarn's own workspace syntax) — a third template alongside pnpm's `{tool} --filter {name} test` and npm's `npm test -w {path}`.
- Red-team resolution: a workspace package with no `test` script gets no per-package `{path}/** → [name]` rule at all — its path falls through to unmatched (full), unless the package is also "shared" (see below).
- Red-team resolution: a package that is both shared (another package depends on it) AND has its own test script keeps `suites: '*'` for its own path rule — the shared rule wins, and its own suite is implicitly included since `'*'` means every declared suite including its own.
- Red-team resolution: "shared" detection is direct `dependencies` only, by design — `devDependencies`/`peerDependencies` (build-time tooling, not runtime consumption) don't count, and detection is one hop (direct dependents), not transitive.
- Red-team resolution: distinguish npm from yarn (both use `package.json`'s `workspaces` field) via lockfile presence — `yarn.lock` present → yarn; otherwise (or `package-lock.json` present) → npm.
- Red-team resolution: `composeStarter`'s always-included bookkeeping rules are four, not three — add `docs/superpowers/specs/**` (design docs, deleted by `/specify` and read by no suite) alongside the other three, matching this repo's own hand-specified declaration and the Gotchas' generic rationale for excluding spec docs.
- Red-team resolution: writing the starter unattended in `auto` mode is a low-risk, reversible file write (the declaration can be edited or deleted trivially) — consistent with `_shared/auto-mode-contract.md`'s posture; it remains subject to the same drift-report follow-up (`init --update`) as a hand-written declaration.
- Red-team resolution: when no workspace package has a test script, `checks.tests` is omitted from the generated declaration entirely (an absent field) — `readDeclaration` already treats a missing `checks.tests` as valid per Phase 2a's schema; the starter still writes the bookkeeping-only rules.
- Red-team resolution: the "everything else unmatched → full" catch-all is guaranteed by Phase 2a's own `selectScope` engine (its fail-closed default for unmatched paths), not something `composeStarter` needs to assert separately — cited here, not restated.

- `init/SKILL.md` has ~1.7 KB of headroom under the 40 KB ceiling; measure `wc -c` before and after, and put every word of procedure in the sub-file.
- Never overwrite an existing declaration — it is project-owned and reviewed like code. `--write` is create-if-absent only.
- The starter must never map a source path to `[]`; the test in AC5's file pins that for this repo, and the module test pins it for generated output.
- `pnpm --filter {name}` filters by package *name*, not path — read `name` from each package's `package.json`.
- `.claude-tweaks/` is partly gitignored in some projects (`init/bootstrap/step-04-gitignore-suggestions.md`); the declaration must be tracked — add a `!verify-scope.json` negation suggestion to Step 4's table if the project ignores the directory.
- `docs/superpowers/specs/**` is in this repo's `[]` list because design docs are deleted by `/specify` and read by no suite; `docs/superpowers/plans/**` likewise. `docs/*.md` at the top level (e.g. `docs/skill-graph.md`) stays unmatched → full, because several conformance tests read those files.
- Intermediate commits use `refs #N`.

## Decision Rationale

See the Phase 1 sub-issue's Decision Rationale for the design-wide rationale. Specific to this unit: generated-then-edited beats hand-written for a file whose wrong content under-verifies; drift reporting (not auto-fixing) keeps the project as the owner; this repo's own declaration is the measurement vehicle for the parent's Group B target.
