# 1792: ports: port-services policy key and SessionStart lease ensure

Surface: backend

**Related:** #1441, #1100

## Overview

Turns Unit 1's registry on for a project via one policy key and makes every session in a configured checkout self-heal its lease: SessionStart allocates if missing, re-verifies the leased block against foreign binds, rewrites the env file(s), and prints the block in the session context. Without `port-services` nothing happens and no registry file is created.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- Statusline, reaper/tidy/wrap-up release (Unit 3)
- `/init` writing the key (Unit 4)
- dev-url-detection (Unit 5)
- A Manifesto/auto-mode lever — `port-services` is a project policy read by a hook, not an auto-mode behavior

- [ ] `plugin/bin/lib/ports/ensure.js` — `ensure(cwd, {home, policyServices})`: no-op `{active:false}` when the list is empty; else resolve the checkout root the same way the CLI's `--path` default does (`git rev-parse --show-toplevel` of `cwd`), pass it to Unit 1's `registry.allocate` (idempotent), then `blockFree` on every port of the lease that is not currently bound by a process whose cwd is this checkout is not knowable cross-platform, so the rule is: re-probe the block; a region is **current** iff it exists, parses, and its `PORT=`/base value equals the lease's own base for this path in the registry *and* the registry's persisted `services` array (Unit 1) matches `policyServices` for this run — anything else (region absent, unparseable, base mismatch, or a changed service list) is **stale**; if any port is bound AND the region is stale, reallocate and report `{reallocated:true, from, to}` (a changed `port-services` list is reported the same loud way as a foreign-takeover reallocation, since it also moves URLs); if bound and the region is current, assume it is this checkout's own dev server and keep the lease; always rewrite env files when the region differs.
- [ ] `session-start.js`: when `port-services` resolves non-empty, call `ensure` and push one context line: `claude-tweaks: ports {base}-{base+9} ({PORT=… API_PORT=…})`; on reallocation, prefix `claude-tweaks: ports REALLOCATED {from}→{to} — a foreign process took the old block; URLs moved:`. Any throw is caught and logged as `claude-tweaks: ports ensure failed — {message}`; the hook still exits 0.
- [ ] `docs/hooks.md`: one inform-tier bullet describing the ports line, next to the `worktree-always` verdict banner bullet.

## Acceptance Criteria

1. `tests/policy-key-naming.test.js`, `policy-schema-metadata.test.js`, `policy-schema.test.js` pass with the new row (they fail red if the `.md` row is missing).
2. SessionStart in a checkout whose policy has no `port-services` creates no `~/.claude-tweaks/ports.json` (test with an injected `home` tmp dir) and prints no ports line.
3. SessionStart with `port-services: web,api` and an empty registry prints exactly one line matching `/^claude-tweaks: ports 20000-20009 \(PORT=20000 API_PORT=20001\)$/` and writes `.env.local` with the managed region.
4. With the lease present and a test listener bound on one of its ports while `.env.local`'s region is current → lease kept, no REALLOCATED line.
5. With the lease present, a listener bound on one of its ports, and the region absent → reallocation to the next free block, REALLOCATED line printed, env file rewritten.
6. `ensure` throwing (inject a registry that throws) → the hook's output still contains every other SessionStart part and one `ports ensure failed` line; exit code 0 (garbage-stdin invariant test in `tests/hooks-dispatcher.test.js` still passes).
7. Policy value shapes accepted: `port-services: web,api,db` (comma string) and a YAML list; each entry is validated independently against `^[a-z][a-z0-9-]*$` — an invalid entry is dropped from the list and reported as one `claude-tweaks: ports — invalid service name '{name}' ignored (services must match ^[a-z][a-z0-9-]*$)` context line, while the remaining valid entries still activate port isolation (never thrown, and never zeroes the whole list for one bad entry). A list longer than the registry's `BLOCK_SIZE` (10, Unit 1) cannot fit any block — that case is reported and the *entire* list is treated as empty for the session, since there is no partial allocation to fall back to.

## Technical Approach

`session-start.js` reads the key through `policy.js`'s existing resolver (same call shape as `resolveWorktreeAlways` — add a `resolvePortServices(cwd)` beside it returning a normalized string array). `ensure.js` composes Unit 1's `registry.allocate`, `probe.blockFree`, `env-file.mergeManagedRegion` and is the only place the "stale region vs bound port" rule lives. Data surface: context line formats above are the contract `docs/hooks.md` documents.

## Gotchas

- `policy-schema.md` has ~2 KB headroom under the 40 KB ceiling — keep the row to one line.
- The SessionStart inline path must stay cheap: `ensure` does at most 10 loopback binds plus one small write; never add a network or `gh` call there.
- `session-start.js` is also edited by open #873 (this unit is Blocked by #873) and is inside #1441's scope (Related) — rebase on the integration branch before starting.
- Never make the reallocation silent: URLs move, so the line must be loud.
- #1100 (Related) adds docs to `docs/hooks.md` — expect a trivial merge.
- AC3's `20000-20009` default base comes from #1791's `POOL_BASE`/`BLOCK_SIZE` constants (`plugin/bin/lib/ports/registry.js`), not from anything defined in this unit.
- The "bound + current region ⇒ keep the lease" heuristic assumes an abandoned checkout's lease eventually gets reclaimed by something else — that's Unit 3's reap-on-worktree-removal (and Unit 1's dead-path gc for a deleted checkout); until Unit 3 ships, a lease for a since-abandoned checkout can only clear via gc, not reap.
