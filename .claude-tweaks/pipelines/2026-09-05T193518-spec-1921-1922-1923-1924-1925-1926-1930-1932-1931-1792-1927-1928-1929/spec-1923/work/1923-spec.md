# 1923: Wire scoped verification into the pipeline: re-verify sites, /test affected, QA story scoping, and multi-spec bookkeeping deltas

Surface: backend
**Related:** #1801, #1836

## Overview

With the scoping engine in place (`verify.js --scope`, the Phase 2a sub-issue), this unit wires it into every pipeline re-verification site and redefines the two diff-keyed features that today read the wrong diff. Every re-verify after build Common Step 5's full pass — the second call's auto-inserted `test`, the polish re-verify (`/claude-tweaks:test skip-qa`), the review-fix re-verify, and multi-spec's spec-N test step — runs scoped against the last full pass. Standalone `/claude-tweaks:test` stays full. `/claude-tweaks:test affected` and the QA story `affected` filter are redefined onto the shared changed-file set (`base..HEAD` ∪ working tree) instead of bare `git diff --name-only`, which is empty for every committed pipeline diff.

Closes #1801 (a ledger-row commit between specs forces a full re-run: with this unit the delta resolves to `none`, logged as `still-verified: bookkeeping-only delta`) and #1836 (pipeline QA runs every story: stories are filtered by `source_files` overlap with the run's own diff, and a non-frontend surface with zero matches skips QA explicitly).

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- The engine itself (`scope.js`, `changed-files.js`, `--scope`) — Phase 2a.
- Generating the declaration or declaring this repo's own — Phase 2c. Until a project declares one, every site here resolves `mode: full` (the engine's no-declaration branch), so this unit is behavior-neutral on undeclared projects.
- Scoping build Common Step 5 — always full.
- Flaky retry — Phase 3.
- Changing `/claude-tweaks:test`'s QA execution (agent-browser sessions, reporting) — only which stories are selected and when QA is skipped.

## Technical Approach

The runner owns execution and scope; the skills own *when* to ask for scope. Every re-verify site cites one table in `verification.md` rather than restating the rule (CLAUDE.md: each relationship stated once). The `affected` redefinition and the QA story filter both consume `--changed-files` so the three consumers of "what changed in this run" cannot disagree.

### Data / API Surface

- `verify.js --changed-files [--base <ref>] [--integration-branch <name>]` → `{base, files: [..]}`, exit 0; exit 1 with stderr when the base cannot be resolved.
- QA skip line: `QA: skipped — no affected stories ({n} stories considered, {m} changed files)`; sets `TEST_PASSED=true`.
- Decision-log lines (per `_shared/auto-decision-log.md`): `AUTO {time} — Verification scoped: {mode} — {n} changed file(s) since {base-short}: {path → rule, …}; suites: {list|none}. Reversibility: high.` and `AUTO {time} — QA scoped: {k}/{n} stories affected by {m} changed file(s){; skipped — non-frontend surface}. Reversibility: high.`

## Gotchas

- Red-team resolution: "Closes #1801" holds only once Phase 2c's declaration exists (this unit is behavior-neutral on an undeclared project, per its own Non-Goals) — read it as "unblocks the fix for #1801, verified end-to-end once Phase 2c ships this repo's own declaration."
- Red-team resolution: when a declaration exists but the stamp's `fullSha` is NOT an ancestor of HEAD (a rebase or force-push rewrote history), the re-verify sites fall back to a full run — the same fail-closed posture Phase 2a's Gotchas already state for unmatched paths.
- Red-team resolution: `--integration-branch <name>` resolves via `_shared/integration-model.md`'s existing ladder (the same resolution `blast-radius-cli.js` already uses) — both the Deliverables and Data/API Surface sections describe the identical CLI signature including this flag.
- Red-team resolution: "Standalone invocation" is any of (no `$PIPELINE_RUN_DIR`) OR (no `--source`) — either absent condition means full, the conservative (safer) reading, since full is always a superset-safe run.
- Red-team resolution: a QA story with no `source_files` field at all is always included in the run's story set regardless of surface (absence of the field is not the same as a non-matching path list) — only a story that HAS `source_files` and none of them overlap the changed-file set is eligible for the skip/frontend-exception logic.
- Red-team resolution: `source_files` entries are literal repo-relative file paths (the existing `qa-procedures.md` schema) — glob/prefix matching is out of scope for this unit.
- Red-team resolution: the three "what changed" consumers (`--scope`'s internal diff, `--changed-files`, the QA filter) share one changed-file set by construction — all three ultimately call the same `changed-files.js` module from Phase 2a, so there is no separate agreement to verify.
- Red-team resolution: AC5's bookkeeping-only-delta repro lives in `tests/bin-lib/verify/cli.test.js`, extended with the temp-project-plus-declaration scenario described in AC5.
- Red-team resolution: `work/*-spec.md` bookkeeping-only classification follows the identical rule as `docs/plans/*-ledger.md` (both map to `suites: [], static: false` in a project's declaration) — accepted without a dedicated repro beyond AC5's ledger case, since the rule mechanism is shared.
- Red-team resolution: "a matching stamp" means the same match rule Phase 1 defines for `--stamp-status` (`fullSha == sha`, `dirty == false`, `scope == 'full'`).
- Red-team resolution: the ancestor check (`fullSha` an ancestor of HEAD) is a literal `git merge-base --is-ancestor` invocation inside `changed-files.js`'s `resolveBase`, never an agent-side judgment call.

- `skip-qa` is reserved for `/flow`'s polish re-verify gate (`test/SKILL.md` line ~54, ~194); the QA story filter must not be expressed as a new `skip-qa` variant — it is a selection rule inside the existing auto-run branch.
- The frontend-surface exception is deliberate: a brand-new UI story may have no `source_files`; skipping QA there would silently drop the one check the merge precondition (CLAUDE.md's Pipeline section, #808) relies on. Never skip QA on a `web`/`mobile`/`desktop` surface with zero matches.
- The skip is never silent: it is a logged `AUTO` decision naming the changed files and story count, the same shape as the visual-review and design-gate skips.
- `TEST_PASSED=true` on a QA skip must still carry the Design CLI gate (Step 1.5) result — that gate is orthogonal to QA and still runs.
- Conformance tests pin prose repo-wide (`tests/manifesto-lever-conformance.test.js`, `tests/skill-invocation.test.js`, …); run the full suite before the PR.
- `review/code-mode-steps.md` is 33 KB; add one sentence, not a paragraph.
- Write `refs #1801` / `refs #1836` in intermediate commits; the PR description carries `Fixes #1801` and `Fixes #1836`.

## Decision Rationale

See the Phase 1 sub-issue's Decision Rationale for the design-wide rationale. Specific to this unit:

- **Bookkeeping is just a declared class**, not a special case: `docs/plans/*-ledger.md → []` is the same rule shape as any other path. #1801's option (b), moving the ledger out of the tree, is rejected as a contract change touching every ledger consumer for no additional guarantee.
- **`affected` keyed on `base..HEAD` ∪ working tree**: today's definition is empty for every committed pipeline diff, which is why #1836's run "had to fall back to a controller ruling".
- **Standalone `/test` stays full**: a human asking for the suite gets the suite.
