# 3399: wrap-up-pack carries the closing-record set and parked-at-shaping so readers stop restating Ruling R1

**Related:** #3395

Origin: reflect hindsight from #3365

Defer-reason: tangential

## Current State

#3365 repointed every `plugin/skills/wrap-up/*.md` reader of a run's materialized records at `wrap-up-pack.json`'s `inputs.records`. Because that array includes `resolveRecords`' manifest rungs (which list specs that never ran, whose PR line is `Refs`), Ruling R1 — accept the records only when `sources.records` is `headers` or `worktree-headers` — had to be restated by hand at each reader that stamps or records a closing keyword: `engine-verify.js`'s `HEADER_SOURCES`, Section C step 2's `node -e` snippet, Review Console step 11, and `execution-and-verification.md`'s current-branch `Fixes` set. The third prose site was missed until the review's error-handling lens caught it (staged as `review-1.patch`).

Section E's `parked-at-shaping` restore has the same shape: it re-reads the header from the worktree mirror at a timing-sensitive point (before cleanup item 4 removes the worktree), carried forward in prose across two files, when the pack already read that header in Phase 3.

## Deliverables

1. `pack.js` exposes a header-sources-only record field (e.g. `inputs.closingRecords`, empty whenever `sources.records` is a manifest rung) and the materialized header's `parkedAtShaping` value, with `--render` and the pack-field prose-consumer conformance test updated.

2. The four closing-keyword readers cite the new field and drop their restated `sources.records` clauses; Section E reads `parkedAtShaping` from the pack instead of the mirror.

3. `tests/wrap-up-record-resolution-conformance.test.js` pins that no `plugin/skills/wrap-up/*.md` file restates the header-source gate.

## Acceptance Criteria

1. A pack built from a manifest-only parent run dir has `inputs.records` non-empty and the new closing field empty; a header-resolved pack has both equal.

2. `grep -rn "worktree-headers" plugin/skills/wrap-up/` matches only the pack-field description, never a per-reader gate.

3. Section E's restore reads no file under a worktree path.

4. `npm test` passes.

## Release Note

Wrap-up decides which records a run may close in one place, so a closing keyword is never stamped for a record the run did not build.
