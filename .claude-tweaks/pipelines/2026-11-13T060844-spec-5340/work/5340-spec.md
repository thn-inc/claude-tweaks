# 5340: Check spec deliverables that target the PR body against the live PR body at review Step 1

Origin: reflect hindsight from #5297

Defer-reason: tangential

## Current State

A spec deliverable or acceptance criterion can target the PR body rather than a file: #5297's Deliverable 5 asked for before/after process counts and the measuring script in the PR body, and AC3.2 asked for a named shortfall there. Nothing checks that such content landed.

`/claude-tweaks:review` Step 1 checks each deliverable by searching the codebase (`plugin/skills/review/code-mode-steps.md`, Spec Compliance Check item 1), and the codebase never holds PR-body content. In #5297's run, `/build`'s Common Step 4.5 logged "PR body names them" for the builders left as-is and the AC3.1 shortfall, but PR #5299's body never carried them: its edit history shows three edits, each 1,259 characters. The gap surfaced only because a review-time read of the PR body happened to look for it.

Probe: `git grep -n -i -F -e 'PR body' origin/main -- plugin/skills/build/ plugin/skills/review/code-mode-steps.md` exited 1 (no match) on 2026-11-13.

## Deliverables

1. `/claude-tweaks:review` Step 1 (Spec Compliance Check) checks a deliverable or criterion that names the PR body (or PR description) against the run PR's live body (`gh pr view {pr} --json body`, `run-state.json`'s `pr.number`), not the codebase, and marks it `missing` when the body does not carry it.
2. A `/claude-tweaks:build` decision line that claims the PR body carries something is made true in the same step (the body is edited before the line is logged), or the line is not written.

## Acceptance Criteria

- [ ] A review of a spec whose deliverable says "the PR body reports X", against a PR body lacking X, marks that deliverable `missing` or `partial` in Step 1 (a conformance test pins the Step 1 wording).
- [ ] `grep -n -i "PR body" plugin/skills/review/code-mode-steps.md` names the PR-body check in Step 1.

## Release Note

Review now checks deliverables that belong in the PR description against the PR itself, instead of searching the code for them.

## Technical Approach

### Key Files

- `plugin/skills/review/code-mode-steps.md` — Step 1 checks PR-body deliverables against the live PR body
- `plugin/skills/build/architecture-alignment.md` — a PR-body claim is edited into the body before it is logged

## Plan Review Clarifications

- Decided by the user at plan review: a deliverable or criterion naming the PR body is marked `unverifiable` when there is no PR or the PR-body read fails (`gh` error). `unverifiable` never counts as present; Step 1 flags it as a partial gap, and it does not block. A body that was read and lacks the content stays `missing` (spec: "marks it `missing` when the body does not carry it").
