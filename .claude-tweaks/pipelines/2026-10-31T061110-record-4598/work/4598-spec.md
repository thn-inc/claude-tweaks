# 4598: Page tidy's acceptance-gap closed fetch past the 1000-result search ceiling

Origin: spec #4469 review (3e)

Defer-reason: genuinely-larger

## Current State

`_shared/github-pr-scan-acceptance.md`'s `acceptance-gap` closed-record fetch (refs #4469) is one `gh issue list --search "closed:>=$SINCE …"` call. GitHub search caps it at 1000 results whatever `--limit` says, so once the undisposed 31-day closed set reaches 1000 the scope warns and cannot be complete — raising `backlog-fetch-limit` no longer helps.

This repo recorded 971 closures in 30 days when #4469 was specified, so the ceiling is near. The failure is loud (the cap warning fires), not silent.

## Deliverables

- [ ] Split the closed-record fetch into date slices (e.g. two `closed:` ranges covering the 31-day window), each under the 1000-result ceiling, and merge them number-keyed before the client-side 30-day cutoff.
- [ ] Keep a per-slice cap warning; the scope warns only when a single slice reaches its cap.

## Acceptance Criteria

- [ ] On a repo whose undisposed 31-day closed set exceeds 1000, `acceptance-gap` returns every record with no truncation warning.
- [ ] `tests/acceptance-scan-server-filter.test.js` pins the sliced fetch and a per-slice ceiling warning, with a frozen pre-change control.

## Release Note

Tidy's acceptance-gap scan stays complete on repos that close more than 1000 undisposed issues a month.

## Technical Approach

### Key Files

- `plugin/skills/_shared/github-pr-scan-acceptance.md` — slice the closed-record fetch by date
- `tests/acceptance-scan-server-filter.test.js` — pin the sliced fetch
