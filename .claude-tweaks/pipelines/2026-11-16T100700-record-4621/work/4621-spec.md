# 4621: Upstream filing: automatic into owned repos, held for external ones

Surface: infra

## Overview

**Upstream feedback filing: automatic into owned repos, held for external ones.** Wrap-up's upstream-feedback step files feedback into another repository. Under control mode, filing is **automatic for any repo we own** and **left for the human** otherwise.

- **Owned** = repos under the current repo's owner (user or org), plus owners listed in the policy key `owned-owners`. claude-tweaks itself is owned and therefore files automatically.
- **External** repos (for example superpowers, other third-party plugins) go to the acceptance packet's **"Decisions left for you"** section and are **never filed automatically**.
- Ownership is decided **by policy, not by whichever GitHub account is logged in**, so the rule behaves identically in every environment (local, cloud, Routine). The logged-in account is never consulted.

Outside control mode, upstream filing behaves as today.

**Contract decisions this record pins:**

- **Item shape.** The step's input item is `{ targetRepo: 'owner/name', title, body }`, where `targetRepo` is the component's `owner/name` as the learning-routing step resolved it. A missing or unresolvable `targetRepo` (no `owner/name`) is external.
- **Owner resolver.** The caller derives `currentRepoOwner` once per run from the `origin` remote URL via `parseRepo` in `plugin/bin/lib/repo-resolve.js` (SSH, HTTPS, `.git` suffix and GitHub Enterprise hosts all parse there). It never reads `gh auth` state. **A non-GitHub-shaped origin or an origin whose host differs from the target's host makes the target external** (the owner string alone is not an identity across hosts); a fork's `origin` owner is the fork owner, so a fork checkout treats only the fork owner as owned (list upstream owners in `owned-owners` to extend). No `origin`: unresolvable, external.
- **Owner grammar, applied to every input.** `currentRepoOwner`, each `owned-owners` entry and the target's owner must each match `^[A-Za-z0-9](?:[A-Za-z0-9-]{0,38})$` (GitHub login charset, no dots, no underscores) with no trimming; a value that fails the grammar is external for targets (and ignored with a logged note for a bad `owned-owners` entry). The repo-name half must match `^[A-Za-z0-9._-]{1,100}$` and not be `.` or `..`. Ownership is a **literal string comparison (case-insensitive) and nothing else**: no API call, no membership check, no redirect or rename following; a transferred or renamed repo is judged by the `owner/name` as written.
- **Layering.** The owned-filing permission is a new control-mode capability in `bookkeepingPermissions(ceiling, { controlMode })` (`plugin/bin/lib/issues/autonomy.js`, the shape the carry-forward record #4620 defines) and **only grants filing for owned repos**; it does not widen anything else. Under control mode with the capability granted and the target owned, the item is filed without a prompt; **owned filing still requires control mode on**, regardless of the ceiling. For an external target, the step overrides the existing `unattended` `consoleAutoResolve` upstream-filing auto-resolution (`_shared/autonomy-ceiling.md`): under control mode an external item is **held** (carried to the packet) at every ceiling, including `unattended`.
- **Failure handling.** A filing failure (permission denied, network, rate limit, repo archived or issues disabled) is not retried silently and not dropped: the item becomes a packet "Decisions left for you" fact carrying the draft and the failure reason, and a `decisions.md` entry records the failure.
- **Exposure check.** The existing scrub gate (`plugin/skills/wrap-up/upstream-feedback.md` Step 2, which runs in every mode) runs on the body before an owned item is filed; a scrub hit (secret-shaped text, internal paths, private-repo detail) holds the item to the packet instead of filing, with the hit named. This is the exposure contract; this record adds no second scrubber.
- **Packet fact schema is owned by the packet record.** This record produces `{ kind: 'decision', origin: 'upstream', targetRepo, draftTitle, draftBody, reason: 'external' | 'filing-failed' | 'scrub-hit' | 'owner-unresolved' }`; the exact field set is whatever #4611's schema accepts (read it at build; this record conforms, not the reverse).

## Non-Goals

- Not changing the content or shape of the filed issue (the existing upstream-feedback procedure owns that).
- Not the packet's "Decisions left for you" population mechanism (the console-carry-forward record owns it); this record adds one more producer of those items.
- Not a general repo-ownership service; the predicate is used here only.
- Not mutating anything in an external repo, ever, without the human.

## Acceptance Criteria

1. `isOwnedRepo({ targetRepo: 'thn-inc/claude-tweaks', currentRepoOwner: 'thn-inc', ownedOwners: [] })` is true; `'obra/superpowers'` with the same inputs is false.
2. `ownedOwners: ['obra']` makes `'obra/superpowers'` owned; `'obra-fork/x'` stays external (exact-owner match, no prefix match).
3. Owner comparison is case-insensitive on the exact owner login, and a lookalike owner (`thn-inc-evil`, `THN-INC.evil`) is external. A malformed target repo string is external: `thn-inc` (no name), `thn-inc/`, `/claude-tweaks`, `thn-inc/../x`, `thn-inc%2Fx/y`, `HTTPS://github.com/thn-inc/x`, and a string with surrounding whitespace (no trimming that could turn a malformed value into an owned one).
4. Under control mode a feedback item for an owned repo is filed with no approval prompt and a `decisions.md` entry naming the target repo and the issue created; an item for an external repo is not filed and appears in the packet's "Decisions left for you" with the full draft.
5. The result is identical when the authenticated `gh` account is a different login (test varies the fake runner's authenticated login and asserts no change).
6. With `control-mode: off`, the upstream-feedback step behaves exactly as before (existing wrap-up tests pass untouched).
7. An unresolvable current repo owner (no `origin`, a non-GitHub-shaped origin, or an origin host different from the target's host), a malformed `owned-owners` entry (non-string, empty string, failing the grammar), or an `owned-owners` value that is not a list treats the affected targets as external (fail closed); an empty `owned-owners: []` with a resolvable current owner behaves as owner-only.
8. Under control mode at the `unattended` ceiling with `consoleAutoResolve` on, an external item is still held (not auto-filed by the existing upstream-filing auto-resolution), and an owned item at a ceiling below `unattended` is still filed with no prompt; with control mode off at `unattended` the existing behavior is unchanged.
9. A filing failure (fake runner returning permission-denied) and a scrub hit on an owned item each produce a packet decision fact with the draft and the reason, never a silent drop or a retry loop, and a `decisions.md` entry.
10. Adversarial owner inputs for every owner input (target owner, `currentRepoOwner`, `owned-owners` entries) are external or ignored: unicode lookalikes (a Cyrillic i in place of the Latin one in `thn-inc`), embedded newline or NUL, a trailing dot (`thn-inc.`), a 40-character login, underscores, a value with an embedded `/`.
11. `npm test` passes.

## Release Note

Added automatic upstream feedback filing for repositories you own, while feedback for external projects waits for you in the acceptance packet.

## Technical Approach

The decision is a pure predicate over three strings and a list; everything environment-dependent (the current repo's owner) is resolved once by a caller and passed in. External repos never see an automated write. The held draft is carried as an untrusted-free fact (it is the agent's own text), but is still rendered inert in the packet.

### Data / API Surface

- Predicate: `isOwnedRepo` as above. Inputs: `owner/name` strings and a list of owner logins.
- Packet fact: `{ kind: 'decision', origin: 'upstream', targetRepo, draftTitle, draftBody, reason }` conforming to #4611's schema.
- Item input: `{ targetRepo, title, body }`; owner resolution via `parseRepo` (`plugin/bin/lib/repo-resolve.js`).

### Key Files

- `plugin/skills/wrap-up/upstream-feedback.md` — owned/external routing
- `plugin/bin/lib/issues/autonomy.js` — control-mode filing capability next to the other bookkeeping permissions
- `plugin/bin/lib/repo-resolve.js` — `parseRepo` for the origin remote (read; reuse, do not re-parse)
- `plugin/skills/_shared/upstream-feedback-batch.md` — batch filing path to check for the same held-external rule
- `plugin/skills/_shared/autonomy-ceiling.md` — document the capability
- `plugin/bin/lib/console/resolve.js` — the console's upstream-filing slot (read; shared with the carry-forward record)
- `plugin/skills/_shared/acceptance-packet.md` — decision fact kind `upstream` (created by #4611)
- `tests/bin-lib/issues/upstream-ownership.test.js` — new; predicate tests beside `autonomy.test.js`

## Gotchas

- The whole point is not to depend on `gh auth status`: a Routine or cloud sandbox may be logged in as a different account than the maintainer.
- Exact owner match only; a prefix or `endsWith` match lets `thn-inc-evil` count as owned.
- Filing into an owned repo is still filing a public issue: the existing scrub gate runs first (see the exposure check above).
- The packet-fact schema, `unattended` auto-resolution and `console/resolve.js` are shared with #4611 and #4620; read their merged code before building.
- Overlaps the console-carry-forward record's files (`console/resolve.js`, `autonomy.js`, `autonomy-ceiling.md`); that record is a Blocked-by so the carry-forward path exists first.

## Build Deviations (Beneficial, applied at /build Common Step 4.5)

- Scrub-hit hold: the fact carries the draft by `evidenceRef` (the staged file) only, not inline in `text`; a filing-failed or external hold keeps the inline draft. A draft that failed the scrub must not reach the packet comment or a settled record; AC9's "with the draft" is met by the reference.
- Owner resolver: the origin is parsed by `repo-resolve.js`'s `originSpecOf` (the host-normalizing wrapper over the same parse), not a separate `parseRepo` call; still no re-parse and no `gh` call.
- Explicit human choice: ownership replaces the `U#` default only. An explicit uncheck (Override drill) or untick (PR console) declines an owned item, and an explicit check of a held item never files it; it stays held for the packet.
- Staged layout and audit: the `<!-- upstream-target: … -->` + `Title:` header is written only under control mode (off-mode staging byte-identical), and the post-filing `--filed` audit routes the repo the issue URL names, so it still logs after `/claude-tweaks:feedback --pre-confirmed` deletes the staged file.
