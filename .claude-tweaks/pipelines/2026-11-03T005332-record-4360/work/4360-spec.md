# 4360: Anchor the declined-learning store at the main checkout — a decline recorded from a worktree is lost on reap

Origin: build of #4168 (SDD Task 3 review, parked as pre-existing)

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/bin/lib/declined-learning/store.js` sets `STORE_PATH = path.join('.claude-tweaks', 'declined-learning', 'store.json')` (and `LOCK_PATH` alike) — a cwd-relative path. `storePath()` returns it unchanged, so every `readStore`/`writeStore`/`recordDecline`/`lookupDecline`/`listDeclined` call resolves against whatever directory the calling process runs in.

Under `integration-model: pr-first` a pipeline runs inside a worktree (`.claude/worktrees/{name}/`). `.claude-tweaks/declined-learning/` is gitignored, so a decline written there lands in the worktree's private copy and is deleted when the reconciler reaps the worktree. The next run, from the main checkout or another worktree, reads an empty store, and the declined insight re-surfaces.

Writers that hit this from a worktree: `bin/declined-learning.js record-decline` (reflect full-mode "Don't capture", /feedback) and, since #4168, `bin/reflect-apply.js`'s `decline` destination. Readers: `/feedback` session-evaluation, `reflect/SKILL.md` dismissedSubjects, `reflect/full-mode.md` lookup, and `bin/lib/reconcile/index.js` `pruneDeclines()`.

Run directories already solve the same problem through `$RUN_ROOT` anchoring (`_shared/pipeline-run-dir.md`, [IL-127]): artifacts resolve under the main checkout, never under the cwd worktree.

## Deliverables

- `store.js` resolves `STORE_PATH`/`LOCK_PATH` under the main checkout root (the same `$RUN_ROOT` resolution `_shared/pipeline-run-dir.md` uses — reuse its existing resolver, do not write a second one), so a call from any worktree of the repo reads and writes one store.
- Every existing caller keeps its current call shape; none needs to pass a root.
- A test proves a decline recorded with cwd inside a linked worktree is visible to a lookup with cwd at the main checkout.

## Acceptance Criteria

- [ ] With cwd in a linked worktree, `recordDecline` writes `{main-checkout}/.claude-tweaks/declined-learning/store.json`, and no store file appears under the worktree.
- [ ] `lookupDecline` from the main checkout finds a decline recorded from a worktree (test reverts red against the cwd-relative path).
- [ ] Outside a git repository, the store keeps today's cwd-relative behavior (degrade-open, never throws).
- [ ] `npm test` passes.

## Release Note

Declining a reflect or feedback insight from a worktree now sticks: the decline is remembered after the worktree is cleaned up, so the same insight is not proposed again.
