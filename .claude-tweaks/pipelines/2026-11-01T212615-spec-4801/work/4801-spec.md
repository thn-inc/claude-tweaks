# 4801: Keep tidy's open-parent [parent-gate] rows when the gh api user lookup fails

Origin: /claude-tweaks:release v6.159.0 release-gate review (run 2026-10-31T203907-release-standalone)

Defer-reason: pre-existing-outside-diff

## Current State

In `plugin/skills/_shared/github-pr-scan-acceptance.md`'s parent-gate fetch block, `gh api user` (around line 461) runs unguarded, line 487 throws on an empty login, and lines 504-505 make that throw end the whole scope with no `[parent-gate]` rows. Before #4600 the block read only open parents and needed no login, so an identity that cannot call `/user` (for example a GitHub App installation token) now loses every open-parent row, not just close-marker recognition. The #4600 plan (line 192, its AC1.1 empty-LOGIN control) chose a softer outcome, and `isCloseMarkerComment` in `below-floor-parent-close.js` already accepts an empty login. Related: #4770 (the same failed-probe question in the Node module). Found by the v6.159.0 release-gate review (lens 3c; tiebreak confirmed medium; evidence re-read at 0baad51).
