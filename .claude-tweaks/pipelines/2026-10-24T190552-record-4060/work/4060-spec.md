# 4060: reconcile/console-execute.js loads the wrap-up pack on every SessionStart reconcile to reach one header parser

Origin: /claude-tweaks:release v6.152.0 release-gate review (staged/review-4.md, run 2026-10-21T194624-release-standalone)

Defer-reason: tangential

## Current State

`plugin/bin/lib/reconcile/console-execute.js:37` requires `../console/resolve` only for `sddRulingDeferralReason`, a pure ~35-line header parser whose only dependency is `DEFER_REASONS`. `console/resolve.js:12` requires `../wrap-up/pack` (761 lines), which requires `../reconcile/gh-pool`. `reconcile/index.js` loads `console-execute` at module top, so every SessionStart reconcile pass (including the inline console FAST_CHECK) now loads `wrap-up/pack` too.

There is no require cycle today (`gh-pool` is a leaf), but the reconcile layer is one edge away from one, and the hook path pays the load cost for nothing. Found by the v6.152.0 release-gate review (3e reproduction pair, both agents) at d27fb609b.

## Deliverables

1. Move `sddRulingDeferralReason` into a small leaf module (its only dependency is `DEFER_REASONS`), imported by both `console/resolve.js` and `reconcile/console-execute.js`.
2. `console/resolve.js` keeps re-exporting the function if any other caller imports it from there (sweep callers first).

## Acceptance Criteria

- `node -e "require('./plugin/bin/lib/reconcile/console-execute'); console.log(Object.keys(require.cache).some(k => k.includes('wrap-up/pack')))"` prints `false`.
- A test pins that loading `plugin/bin/lib/reconcile/index.js` does not load `wrap-up/pack.js`, and goes red with the old require restored.
- `npm test` passes.

## Release Note

SessionStart reconcile no longer loads the wrap-up pack module it does not use.

## Technical Approach

### Key Files

- `plugin/bin/lib/reconcile/console-execute.js` — import the parser from the new leaf module
- `plugin/bin/lib/console/resolve.js` — import (and re-export if needed) from the leaf module
