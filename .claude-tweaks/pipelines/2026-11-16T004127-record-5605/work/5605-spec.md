## Technical Approach

The gate decides; it does not detect anew. For the wrapper it calls `evaluate()`. For `visual-review` it calls `fileMatchesFrontendPredicate` and the journey reader. Only the journeys rule is new code.

The no-surface set (Deliverable 3) is closed and small on purpose. Journeys documents every persona, developers included, so a changed CLI, hook or skill file is a surface and the skill's own three-signal check decides it. The gate takes only the diffs that check cannot fire on. The rule's basis is its first condition: test code and pipeline artifacts are nothing a persona uses. The `files:` condition is a second guard, for a journey that documents a test helper; the rule does not rely on `files:` lists being complete. A layout the set does not know (`spec/`, `e2e/`, `*_test.go`) always proceeds. Decided 2026-11-16: the set is not configurable; #5556's step yield file shows whether another project's layout is worth an entry.

The visual-review rule is Step 0.5's rule with one difference. Step 0.5 does not sniff files when the surface is declared `backend`, `infra` or `terminal`; the gate proceeds when a UI file changed whatever the surface says. So for the same changed-file list the gate never skips a load that Step 0.5 would have turned into a recommendation. AC13 pins the two surface sets against Step 0.5's text. Review Step 6 passes the gate the same list it would pass the skill.

Inputs are repository-relative paths as `git` prints them. The surface comes from the caller, read where `_shared/design-wrapper-handling.md`'s `--surface` bullet says; the gate does not look for the materialized header itself.

Follow `.claude/skills/gh-api-module-pattern` and its `cli-wrapper-contract.md` for the CLI (`run(argv, deps)`, exit codes, the run-directory anchoring guard), and write the argument parser to the contract in unit 3.1 of `docs/superpowers/specs/2026-11-15-audit-simplification-design.md` (branch `worktree-design-audit-simplification`): an unknown flag and a missing value are usage errors, `--help` exits 0. AC12 pins it. `plugin/bin/lib/cli-args.js` does not exist on 2026-11-16; if it exists when this is built, use it, and if not, that unit's migration of every `plugin/bin` CLI covers this one.

The four `evaluate()` modes read an unrecognised surface as no surface and go by the files; the gate's two own rules proceed on one. That difference is intended: `evaluate()`'s verdicts are a wire contract AC2 holds the gate to, and the gate's own rules never skip on a value they cannot read. `_shared/skill-load-gate.md` says so.

- A gate skip is never a silent skip of a required check. The gate cannot skip `visual-review` for a record whose surface is `web`, `mobile` or `desktop`. A skip is written to `decisions.md` and to the review summary, and `wrap-up/verification-brief.md` Step 2.5 still runs the visual review for an `app-route` or `rendered-page` plan. Do not change that step; AC14 pins the status string it reads.
- `design-detect.js` and its `--mode` form stay. The wrapper's own preconditions call it, and a run in flight on the previous release reads prose that calls it. The two steps that call it today move to the gate; nothing is removed.
- The reason strings in `SKIP_REASONS` are a wire contract that callers match verbatim. The gate passes them through and adds its own for the new rules; it never rewords one.
- Other steps invoke these skills and are deliberately not gated: `visual-review` invokes `design-wrapper survey` after a real browser review, `wrap-up` invokes `visual-review` as the safety net, and `/claude-tweaks:specify`, `/claude-tweaks:tidy` and `/claude-tweaks:init` invoke the wrapper by a human's choice. `_shared/skill-load-gate.md` lists them, so a later editor does not gate the safety net.
- The saving is modest and should be reported as such. The "produced nothing" counts in Current State are an upper bound on waste, taken from what a session did before its next Skill call; a load that only steered the session counts as nothing there. In the measured window the gate would have removed about 25 wrapper loads, the visual-review loads on diffs with no frontend signal (at most 98), and journeys loads on about 8% of builds. Deliverable 1's replay is the number to report, and #5556's step yield file is the place to see whether the journeys rule should widen.
- The no-surface set was measured on this repository, whose tests live under `tests/`. A project that keeps product code under a top-level `test` or `tests` directory would have its journeys load skipped for a diff confined to it. The skip is logged, and a journey that lists such a file turns it into a load.
