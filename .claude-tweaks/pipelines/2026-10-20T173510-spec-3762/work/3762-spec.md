# 3762: local-merge auto-merge closes the run before the merge can fail — reorder checks ahead of close-run

Origin: spec #3711 review (3a Convention — no implicit deferrals)

Defer-reason: genuinely-larger

## Current State

Both local-merge auto-merge procedures run `hooks.js close-run` before the merge can fail. `plugin/skills/wrap-up/auto-merge-short-circuit.md` (the human-run direct-merge path) and `plugin/skills/dispatch/settle-and-merge.md` (dispatch's local-merge fallback) both clear the run's worktree assignment first, so the merge into the main checkout is not denied as a wrong-checkout commit (E1). The composer call, the branch guard, and `git merge` run after that. When any of them fails, the run parks for a human (console fallback / `pending-review`) but is already closed: no longer E1-protected, worktree assignment cleared, so the reconciler can treat a run that still needs a human as finished. Both files record this as "One accepted residual ... Not fixed here; there is no "reopen-run" mechanic to reverse it." with no backing record (found by /review of #3711, lens 3a; refs #3711, which widened the short-circuit's fallback to cover the branch-guard abort and so made the residual reachable from a misread Task call).

## Deliverables

Move every check that can fail without touching the tree ahead of `close-run` in both procedures: the branch guard (`git branch --show-current` vs the integration branch), `compose-subject.js`, and a conflict pre-check (`git merge-tree --write-tree {integration-branch} {branch}`, exit 1 = conflict). Keep the in-call branch guard as the race backstop.

For the failures that can still happen after `close-run` (a race on the branch guard, a merge that fails for a reason `merge-tree` did not predict), restore the run's protection: either a `hooks.js reopen-run` (re-stamp `worktree`, clear the closed status) or an equivalent re-stamp via `record-worktree`, invoked from the same fallback paragraph.

Replace both "One accepted residual ... Not fixed here" sentences with the new behavior.

## Acceptance Criteria

A branch-guard mismatch or a predicted conflict aborts before `close-run` runs: `run-state.json` keeps its `worktree` field and `status` is unchanged (pinned by a test that drives the procedure's commands against a fixture repo, or a conformance test on the ordering).

A failure after `close-run` leaves the run re-protected (worktree assignment restored) before the console fallback renders.

`grep -rn 'Not fixed here; there is no' plugin/` returns no matches.

`npm test` passes in full, run centrally.

## Release Note

A local-merge auto-merge that cannot complete now leaves its run protected and assigned to its worktree, instead of closing it before the failure was known.
