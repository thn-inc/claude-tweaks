# 4599: Close below-floor parents when an armed PR merges after its session ended

Origin: spec #4466 build (final whole-branch review)

Defer-reason: genuinely-larger

## Current State

`_shared/pr-first-merge-post-merge.md`'s Step 4.0b (#4466) closes a below-floor decomposition parent once its last sub-issue's merge lands. It runs only when a session sees the merge happen: pr-first outcome `merged`, or a successful local-merge push. When the session arms an auto-merge (`armed`) and GitHub merges the PR later, typically on a repo with required checks, no session reaches Step 4.0b. Step 4.0 (closing-links) has the same gap and states "the reconciler does not run the CLI". Recovery is `/claude-tweaks:tidy`'s `parent-gate` backstop row, which stays staged at every autonomy tier. So on required-checks repos, closing a parent below the floor in practice needs a human click.

## Deliverables

- [ ] Run Step 4.0b (and Step 4.0) for a PR the run armed and GitHub merged later. The likely home is the reconciler (`bin/hooks.js reconcile`) or the next session's run-dir sweep, keyed on the run's recorded PR, and it must run exactly once.
- [ ] Keep tidy's backstop as the last resort.

## Acceptance Criteria

- [ ] A below-floor parent whose last sub-issue merges through an armed auto-merge is closed with the `## Closed below the oversight floor` comment, without a human approving a tidy row.
- [ ] The close stays idempotent with a later tidy approval: one comment, one close.
