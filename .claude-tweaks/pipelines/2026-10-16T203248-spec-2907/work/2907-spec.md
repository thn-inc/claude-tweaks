# 2907: categoriseReproduction drops a reproduced finding when the same agent reports two findings at one location

Origin: reflect full from #2628

Defer-reason: tangential

## Current State

`categoriseReproduction` (`plugin/bin/lib/coordination.js`) pairs agent A findings against agent B in A-order. When A reports two findings at the same path:line and the first has different substance from B finding, B is consumed as a `nearLocation` partner and A second finding — which does match B in substance — can no longer pair, so a genuinely reproduced finding lands `unconfirmed`. Observed on #2628 review (lens 3b, candidates-app-store-readiness.js:308: both agents reported the symlink-containment gap). Probe: A=[size-cap, symlink], B=[symlink] → 0 confirmed / 3 unconfirmed; reordering A to [symlink, size-cap] → 1 confirmed / 1 unconfirmed.

## Deliverables

Make pairing order-independent: before emitting near-location (different-substance) entries, prefer a same-substance match across all A findings at that location (e.g. pair by best substance score globally, not first-come in A order).

A regression test with the exact two-findings-one-location fixture above, asserting the symlink finding is confirmed regardless of A order.

## Acceptance Criteria

`categoriseReproduction(A,B)` and `categoriseReproduction(reversed A,B)` both return the same-substance pair as confirmed for the fixture above.

The existing #1980 different-substance near-location tests still pass.

## Release Note

Review reproduction pairing no longer drops a finding both agents reported when one agent also reported a second issue on the same line.
