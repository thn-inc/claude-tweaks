# 3989: worktree-always PreToolUse hook false-positives on numeric comparisons like "x.length > 0" inside a Bash heredoc

Defer-reason: tangential

## Current State

`plugin/bin/lib/hooks/pre-tool-use.js`'s `checkWorktreeRequired` (the `worktree-always` gate) denies a Bash call whose command text contains a `>`/`>>`/`>|`/`&>`/`&>>` redirect-shaped substring, to stop an unguarded write to the main checkout outside a worktree. The matcher appears to be purely textual: it does not distinguish a real shell redirect from a `>` that occurs inside embedded heredoc'd source (JS, in practice) passed to `node`.

Confirmed live during a `/claude-tweaks:dispatch next` Routine firing on 2026-10-23, in a non-worktree main-checkout session: `plugin/skills/dispatch/queue-pull-script.md`'s own documented grouping snippet (run via `bin/node-eval-file.js` with a heredoc) contains the literal line `if (openIds.length > 0) excludedNative.push(...)`. Running that exact documented Bash call was refused with the `worktree-always` denial message, even though the command performs no real redirect — its only file target was a `/tmp/ct-session-*` path, nowhere near the repo. Rewriting the comparison to `if (openIds.length) { ... }` (no literal `> ` text) let the identical logic run with no denial, confirming the trigger is textual, not semantic.

Because `queue-pull-script.md` is read and run verbatim by every `/claude-tweaks:dispatch` firing (and other skills following the same node-eval-file.js heredoc convention), any firing that runs in a non-worktree session and reaches this exact line hits the same false block — a Routine firing has no one to retry it by hand.

## Deliverables

- `checkWorktreeRequired`'s redirect-shaped-substring matcher gains awareness of heredoc boundaries (e.g. ignore `>`-shaped text between a `<<'EOF'`/`<<EOF`-style heredoc opener and its matching closing delimiter), or is otherwise scoped to reject only a `>` that is syntactically a shell redirect (preceded by a file-descriptor-less command boundary, not embedded inside a heredoc body).
- `plugin/skills/_shared/policy-schema-coverage.md`'s worktree-always coverage block documents the heredoc exemption explicitly, so a future matcher change doesn't silently regress it.
- A regression test in the existing `pre-tool-use` hook test suite pins a Bash command containing a heredoc with a `>`-shaped numeric comparison (e.g. `x.length > 0`) as allowed, while a real `>` redirect at the top level of the same command (outside any heredoc) is still denied.

## Acceptance Criteria

1. The exact `queue-pull-script.md` grouping snippet (containing `if (openIds.length > 0) ...`) runs without a `worktree-always` denial in a non-worktree session, when its only write target is outside the repo (e.g. under `/tmp`).
2. A Bash command with a real top-level `>` redirect into a repo file (outside any heredoc) is still denied in a non-worktree session — no regression to the gate's actual purpose.
3. `npm test` passes.

## Release Note

Internal hardening: the `worktree-always` write gate no longer mistakes a numeric comparison (`x.length > 0`) inside a heredoc-embedded script for a real shell redirect.

## Technical Approach

### Key Files

- `plugin/bin/lib/hooks/pre-tool-use.js` — `checkWorktreeRequired`'s redirect-shaped-substring matcher
- `plugin/skills/_shared/policy-schema-coverage.md` — document the heredoc exemption
- `tests/` (existing pre-tool-use hook suite) — new regression cases
