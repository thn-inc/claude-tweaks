# 3095: Exit-code conformance allowlist check reads hooks.js's prefilter guard instead of its entry point

Origin: v6.139.1 release whole-branch review (/claude-tweaks:release Step 3, v6.139.0..48c63045a), staged finding review-5 — the release review stages and never applies fixes in place

Defer-reason: needs-human-decision

## Current State

`tests/bin-lib/exit-code-conformance.test.js`'s `extractGuard` (~line 63) takes the first `require.main === module` match. Since #3074, `plugin/bin/hooks.js` has two: line 28 (the prefilter's early `process.exit(0)`) and line 1570 (the real entry point). The allowlist-staleness check for hooks.js therefore inspects the prefilter guard and would stay green if the entry guard stopped calling `process.exit`. `hooks.js:26`'s comment describing that test is inaccurate as a result.

## Deliverables

- Make `extractGuard` select the entry-point guard (the last match, or the one wrapping `main()`), or exempt the prefilter guard explicitly.
- Correct the comment at `plugin/bin/hooks.js:26`.

## Acceptance Criteria

- [ ] Converting hooks.js's entry guard to `process.exitCode` makes the staleness check fail.
