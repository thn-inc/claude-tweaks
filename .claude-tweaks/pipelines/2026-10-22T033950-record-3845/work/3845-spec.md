# 3845: A nested `claude -p` inside a pipeline session marks the parent's run interrupted at its SessionEnd

**Related:** #3056 (the build that hit this)

Origin: #3056 /prompt-audit comparison (run 2026-10-21T001740-record-3056)

Defer-reason: tangential

## Current State

During #3056's build (run `2026-10-21T001740-record-3056`), the dispatched agent ran `claude -p "/doctor prompt-audit"` twice (plus one probe) from inside its own pipeline worktree session. Each nested session ended with a SessionEnd hook event carrying the **parent's** session id (`events.jsonl`: three `session-end` lines, `sessionId` equal to the run's owner), and `plugin/bin/lib/hooks/session-end.js` stamped `run-state.json` `status: interrupted`, `lastEvent: session-end` on the parent's still-running run. The nested session's SessionStart banner then listed the live run as interrupted.

`session-end.js` stamps `interrupted` on `ctx.ownedRun` whenever its attribution is not `fallback`. Ownership resolves by session id, so a child process that runs under the parent's `CLAUDE_CODE_SESSION_ID` is indistinguishable from the owner ending. The run recovered only because the agent noticed and re-ran the idempotent `hooks.js record-worktree` restamp; an unnoticed stamp would mislead `check-resume-freshness` and the reconciler.

## Deliverables

1. Reproduce: from a session owning an active run, run a short `claude -p` and confirm the parent run's status flips to `interrupted`.
2. Fix at the source: either have the SessionEnd path distinguish a nested/child session from the owner (e.g. the hook input's own session id vs the inherited env, or a parent-pid marker), or document and enforce that nested `claude -p` runs inside a pipeline session must clear `CLAUDE_CODE_SESSION_ID` or pass `--bare`-style hook isolation — choose one and record why.
3. Add a regression test in the `tests/hooks-*` suites covering a child SessionEnd against a parent-owned active run.

## Acceptance Criteria

- A nested `claude -p` session ending inside an owning session leaves the parent run's `status` unchanged.
- A genuine owner SessionEnd still stamps `interrupted` (existing behaviour preserved).
- The new regression test fails before the fix and passes after; `npm test` passes.

## Release Note

Running a nested Claude Code command from inside a pipeline session no longer marks the running pipeline as interrupted.

## Technical Approach

### Key Files

- `plugin/bin/lib/hooks/session-end.js` — owner vs nested-session distinction
- `plugin/bin/lib/hooks/context.js` — ownedRun attribution, if the fix lands there
