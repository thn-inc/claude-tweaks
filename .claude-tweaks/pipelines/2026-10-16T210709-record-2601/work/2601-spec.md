# 2601: materialize.js writes the spec header to a worktree-relative shadow path instead of the anchored main-checkout run dir

Surface: infra

## Current State

This record was filed as a `materialize.js` bug: invoked from inside a record's worktree with `--run-dir` pointing at the anchored main-checkout run directory, the materialized spec landed at the worktree-local path `{worktree}/.claude-tweaks/pipelines/{run-id}/work/{n}-spec.md`.

That write is designed behavior, not a resolution bug. `plugin/bin/materialize.js` lines ~290–317 (#1210) deliberately rewrite a `--run-dir` that resolves to the main checkout (or another worktree) into the cwd worktree's equivalent path when cwd is inside a linked worktree, and print a stderr notice saying so. The reason is `materialize.md`'s worktree-first ordering: the spec must land on the feature branch. `_shared/pipeline-run-dir.md:67` documents `work/{n}-spec.md` as an exception that "stays inside the worktree".

The real defect is documentation drift: `plugin/skills/flow/materialize.md` still describes `--run-dir` as "the literal write-location prefix, not a run identity — the CLI writes `{--run-dir}/work/{n}-spec.md`" (line 5) and repeats "`--run-dir` is the literal write-location prefix" (line 7). Read literally, both say the main-checkout path is honored from a worktree, which is what led the reflect pass to file this as a bug.

## Deliverables

1. Correct `plugin/skills/flow/materialize.md` lines 5 and 7 to state that `--run-dir` is the write-location prefix except when cwd is inside a linked worktree and the path resolves elsewhere, in which case the CLI writes to the cwd worktree's equivalent path (#1210), citing `_shared/pipeline-run-dir.md`'s `work/{n}-spec.md` exception rather than restating it.
2. Make `materialize.js`'s usage text (and any other plugin prose describing `--run-dir` as literal) agree.
3. If an existing test already covers the #1210 rewrite, reference it in the PR; if none does, add one invoking `materialize.js` from a worktree cwd with a main-checkout `--run-dir` and asserting the worktree-local write plus the stderr notice.

## Acceptance Criteria

1. No plugin prose describes `--run-dir` as an unconditional literal write location.
2. `materialize.md` states the worktree-local rewrite and cites `_shared/pipeline-run-dir.md`'s exception.
3. A test pins the rewrite behavior, existing or new.
4. `npm test` passes.

- Add a regression test: invoke `materialize.js` with an absolute `--run-dir` from a cwd that is NOT that run dir's own ancestor (e.g., a sibling worktree), and assert the spec lands at the given absolute path, not a cwd-relative shadow of it.
