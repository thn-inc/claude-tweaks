# 2807: Evaluate replacing the hand-rolled GIF/PNG/LZW codec with an established library

Origin: ledger resolve gate

## Current State

`plugin/bin/lib/gif/lzw.js` (alongside its sibling `gif/png-decode.js` and `gif/encoder.js`) is a hand-rolled GIF/PNG/LZW codec implementation. A whole-branch review lens (3e, single-agent, unconfirmed) flagged this as a design-alternative worth considering: an established codec library might reduce the maintenance surface (this session's own `[IL-159]` cites a real LZW encoding bug in this exact file that shipped and was only caught by a from-scratch decoder in review).

## Deliverables

Evaluate whether an established library (e.g. an existing npm GIF/PNG encoder) can replace the hand-rolled `gif/lzw.js`/`png-decode.js`/`encoder.js` trio without regressing the walkthrough-encode pipeline's existing behavior (frame timing, palette quantization, budget enforcement) — a genuine build-vs-buy decision, not a mechanical fix. If the evaluation concludes hand-rolled is still the right call (e.g. for a zero-dependency constraint), record that decision and close this out; if a library is worth adopting, that's a follow-up implementation task.

## Acceptance Criteria

- A written comparison (dependency size/licensing/maintenance vs. current test coverage and behavior) exists, landing on either "keep hand-rolled" (with a stated reason) or "adopt library X" (with a migration plan)
- If adopting a library: `tests/bin-lib/walkthrough/encode.test.js` and `tests/bin-lib/gif/*.test.js` continue to pass, or are updated to match the new implementation's verified-equivalent output

## Evaluation (this build)

`docs/decisions/0019-vendored-gif-codec-over-a-runtime-dependency.md` (2026-09-22) already made
this exact build-vs-buy call, ~1 week before this record was filed — the same review lens is
re-flagging a decision already on record, citing the same LZW defect ADR-0019's own Consequences
section documents.

**Written comparison (this record's AC1):**

- **Dependency candidate:** `gifenc` (the "obvious answer" ADR-0019 names) — MIT license, ~5 KB
  before gzip, 0 transitive dependencies, stable/unmaintained (last published years ago). Favorable
  on size, licensing, and maintenance-surface-if-adoptable.
- **Why it still doesn't win:** the blocking axis was never size/license/maintenance — it's that
  the plugin ships as the `plugin/` subtree via a `git-subdir` marketplace source with no
  `plugin/package.json` and no `npm install` step anywhere in the install path (ADR-0015/ADR-0019).
  Any npm dependency, however small or well-licensed, resolves to nothing in an installed build.
  `gifenc`'s favorable profile doesn't change that.
- **Test coverage/behavior:** current hand-rolled trio (`gif/lzw.js`, `gif/png-decode.js`,
  `gif/encoder.js`, `gif/palette.js` — 393 lines) is covered by `tests/bin-lib/gif/*.test.js`
  (543 lines) plus `tests/bin-lib/walkthrough/encode.test.js`; both pass at HEAD (verified this
  build, see Final Verification below). No regression risk from this evaluation — no code changed.
- **Revisit triggers re-checked:** no `plugin/package.json` exists yet; no report of the
  quantizer's distinct-color cliff being hit by a real (non-adversarial) walkthrough; GIF is
  unchanged as the render-reach leader. None of ADR-0019's three revisit conditions has fired.

**Decision: keep hand-rolled** (stated reason: structural unavailability of any npm dependency
under the current install model, independent of that dependency's own size/license/maintenance
profile). Recorded as a "Revisited" addendum on ADR-0019 rather than a new ADR, since it reaffirms
rather than changes the existing decision. No implementation follow-up — closes #2807.
