# 1997: Retire per-file byte pins: retarget or delete the ad-hoc 40 KB assertions, rewrite donts.md's three ceiling rules to composition, plan-audit headroom check on composed bytes
Surface: backend

## Overview

Retire the ad-hoc per-file byte pins the parent design's composition mechanism makes obsolete: retarget or delete every `<= 40960`-style assertion outside `context-cost.test.js` (U3's own hard gate), rewrite `docs/donts.md`'s three ceiling rules (the `[IL-70]` extraction rule, the "draft the sub-file first" rule, and the `_shared` `wc -c` rule) to state the composition rule instead, and extend `plugin/bin/lib/plan-audit/checks.js`'s `headroomCheck` to measure composed bytes for any compose call site whose sources a plan touches — closing `[IL-140]`'s missing multi-spec pre-flight.

**Complexity:** Medium
**Estimated tasks:** 7

- Adding any new markers or compose call sites — this record is pure retirement/retargeting of tests and docs already made obsolete by U1-U9's landed work; it fences nothing new.

- Fully closing #1709 or #1881 itself with a merge/label change beyond naming them — this record closes them **by reference** in the PR description (`refs #1709, refs #1881`) and, per the parent design's instruction, closes them with a comment after this record's own PR merges; it does not silently resolve them without that comment.

## Gotchas

- Never renumber or delete an existing `[IL-nn]` entry while rewriting `donts.md`'s rules — the tag is the durable cross-reference other files cite; only the guidance text changes.
- A pin's removal condition must be recorded, not just asserted — state precisely what observable state (a specific file exceeding a specific ceiling with no compose call site protecting it) would justify reintroducing a per-file pin, per this project's "no implicit deferrals" philosophy.
- `headroomCheck`'s extension is the actual fix for `[IL-140]` (the missing multi-spec pre-flight) — verify this claim with a fixture plan spanning multiple specs that touch the same compose call site's sources, not just a single-spec fixture, since the multi-spec case is specifically what `[IL-140]` was about.
- U4 may have already made an interim adjustment to `manifesto.md`'s BUDGETS pin while landing its own markers — reconcile with that interim value rather than assuming the pin is still at its original number; read the current test file before editing, not from this record's own Current State snapshot.
- Closing #1709/#1881 happens only after this record's own PR merges (a comment, not a merge-time auto-close) — verify the record numbers are real, open records before writing `refs #N` (per this project's own convention of not reflexively writing a reference without confirming the backing issue).
