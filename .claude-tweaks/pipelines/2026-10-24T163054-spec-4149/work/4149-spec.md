# 4149: worktree-always write gate misses writes inside heredocs a non-shell or later-piped consumer runs (#3989 regression)

Verified-as-of: 1813941ecfe019b89307ea75526f2c863ffb5e1e

Origin: /claude-tweaks:release v6.153.0 release-gate review (staged/review-1.md, run 2026-10-24T152958-release-standalone)

Defer-reason: pre-existing-outside-diff

## Current State

Since #3989 (7fc7655ff), `stripHeredocBodies` in `plugin/bin/lib/hooks/git-command.js` removes a heredoc body as data unless `bodyRunsAsShell` sees a shell name on the opener line (a denylist, :554/:589) or a trailing continuation (:705). `fileWriteTargets(cmd, "/wt")` then reports no write for commands that do write into the main checkout. An executed probe at 1813941ec returned `[]` for each of these, where v6.152.0 returned the `/main/f` write:

- `make -f - <<EOF`, `at now <<EOF`, `/bin/ba[s]h <<EOF` whose body writes `> /main/f` (a non-shell or glob-named executor)
- `{ cat <<EOF … EOF\n} | sh` (the consumer is on a later line)
- a delimiter split by backslash-newline (`E\` / `OF`): bash joins the lines before matching, so the body ends early and the next line runs, while the parser keeps stripping (:681)
- `echo $[1<<3]` followed by a `3]` line: a `<<` bash never reads as a heredoc opener (:609)

Controls still caught: a `bash <<EOF` body write, `cat <<EOF > /main/g`. The same stripped text feeds `bash-prefilter.js`'s `hasFileRedirection` skip, so the gap reaches the prefilter too.

## Deliverables

1. Strip a heredoc body only when its consumer is on an allowlist of known data readers (`cat`, `tee`, `git commit -F -`, `read`, `node -`); otherwise keep the body visible to `fileWriteTargets`.
   _As built (/build Common Step 4.5, Beneficial):_ every command on the opener's logical line must be a data reader — `cat`, `tee`, `gh`, `read`, `node`, `python`, `python3`, `jq`, `wc`, or `git` with a data subcommand and no `-c`/`--config-env`/assignment — named bare or by absolute path, behind the wrappers `sudo`/`doas`/`env`/`nice`/`time`/`nohup`/`command`/`exec`; the inert neighbours `cd`, `mkdir`, `true`, `:`, `echo`, `printf` and `git add` pass; a reader a pipe feeds, or one with a substitution at or after its `<<`, fails. The canonical prose is `plugin/skills/_shared/policy-schema-coverage.md`'s heredoc paragraph.
2. Match a delimiter the way bash does when the delimiter line is joined by a backslash-newline.
3. Do not treat `<<` inside `$[ … ]` arithmetic as a heredoc opener.
4. Add each probe case above, and the two controls, to `tests/hooks-git-command.test.js`.

## Acceptance Criteria

- `fileWriteTargets` reports the `/main/f` write for the `make -f -`, `at now`, `/bin/ba[s]h`, later-pipe and backslash-joined-delimiter cases.
- A data-only `cat <<EOF` body (no redirect inside) still reports no write.
- Each new case goes red against the current `stripHeredocBodies`.
- `npm test` passes.

## Release Note

The worktree-always guard again blocks writes into the main checkout that a heredoc runs through a non-shell executor or a later pipe.

### Key Files

- `tests/hooks-git-command.test.js` — regression cases
