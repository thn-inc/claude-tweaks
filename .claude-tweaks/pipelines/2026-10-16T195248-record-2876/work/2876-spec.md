# 2876: Close this repo's own agent-trust-scope gap (no permissions.deny under autonomy: unattended)

Surface: infra

## Current State

This repo runs with `autonomy: unattended` (`.claude-tweaks/policy.yml:5`), but its committed `.claude/settings.json` has only `permissions.allow: ["Read(node_modules/**)"]` and no `permissions.deny` key. Running `scanAgentTrustScope(process.cwd())` (`plugin/bin/lib/code-health/candidates-agent-trust-scope.js`, from #2749) against this checkout returns all three candidates: `registry-access`, `network-egress` and `credential-scope`. `plugin/skills/_shared/criteria-agent-trust-scope.md`'s Severity calibration rates each one **high**, because the autonomy level is unattended and no deny key exists at all.

The three dimensions do not cost the same to close here:

- **registry-access**: no conflict. `package.json` is `"private": true`, and the plugin ships through the marketplace repo, not a package registry, so this repo's own workflows never need `npm publish`, `npm login`, `npm adduser` or `npm config set registry`.
- **credential-scope**: no conflict found. No workflow in this repo reads `.env`, `id_rsa`, `.pem`, `.aws` or `.ssh` paths.
- **network-egress**: real conflict. `/claude-tweaks:research` (`plugin/skills/research/SKILL.md`, `source-registry.md`) depends on `WebFetch`. `scripts/claude-cloud-setup.sh:129` and `plugin/skills/init/bootstrap/step-14-cloud-routine-parity.md:175` shell out to `curl -fsSL`. A blanket `WebFetch`/`curl`/`wget` deny would break those in this repo's own sessions.

## Deliverables

1. Add `permissions.deny` entries to `.claude/settings.json` for **registry-access**: the npm/yarn/pnpm publish and login family, using `Bash(...)` rule syntax that matches the generator's `REGISTRY_PATTERNS` (`candidates-agent-trust-scope.js:56-66`).
2. Add `permissions.deny` entries for **credential-scope**: `Read(...)` rules for secret-shaped paths (`.env` and `.env.*`, `id_rsa*`, `*.pem`, `.netrc`, `.aws/**`, `.ssh/**`) that match `CREDENTIAL_PATH_PATTERNS`.
3. For **network-egress**, resolve the gap without breaking `/research` or the cloud-setup `curl` call. Do one of the following:
   - (a) Add a deny rule narrow enough to leave those uses working, such as denying `wget` and pipe-to-shell `curl` shapes while keeping `WebFetch` and plain `curl -fsSL` allowed. Verify that the generator's `NETWORK_PATTERNS` count the rule as coverage.
   - (b) If no narrow rule is meaningful, record an explicit accepted-risk decision in `docs/decisions/` (the next ADR number). The decision states that unattended runs in this repo keep `WebFetch`/`curl` reach on purpose, and why.

## Acceptance Criteria

- `node -e "console.log(JSON.stringify(require('./plugin/bin/lib/code-health/candidates-agent-trust-scope.js').scanAgentTrustScope(process.cwd()).candidates.map(c=>c.kind)))"` prints neither `registry-access` nor `credential-scope`.
- `network-egress` is either absent from that output (option a), or a new `docs/decisions/*.md` ADR names the dimension, the specific uses that need it (`/research`'s `WebFetch`, the cloud-setup `curl`), and the accepted risk (option b).
- `.claude/settings.json` is still valid JSON, and `enabledPlugins`, `extraKnownMarketplaces` and the existing `allow` entry are unchanged.
- `npm test` passes in full.

## Release Note

No user-visible change: this repo's own unattended agent configuration now blocks package publishing and reads of credential files.

## Technical Approach

This is a config-only change plus, under option (b), one ADR. Write each deny rule in Claude Code's permission-rule syntax, then re-run the scan command from the acceptance criteria to confirm the generator recognizes it. A rule that is correct but invisible to the generator does not close the finding.

### Key Files

- `.claude/settings.json` — add the `permissions.deny` list
- `plugin/bin/lib/code-health/candidates-agent-trust-scope.js` — read-only: the pattern lists (`REGISTRY_PATTERNS`, `NETWORK_PATTERNS`, `CREDENTIAL_PATH_PATTERNS`) the deny rules must match
- `plugin/skills/_shared/criteria-agent-trust-scope.md` — read-only: per-dimension guidance
- `docs/decisions/` — new ADR only under network-egress option (b)

## Gotchas

- Committed `.claude/settings.json` reaches every cloud session and Routine sandbox (CLAUDE.md's Cloud parity section), so a deny that is too broad breaks those sessions too, not only local ones. In particular, never deny `WebFetch` outright while `/research` is expected to work in this repo.
- The generator reads only the committed `.claude/settings.json`, never `settings.local.json` or user-level settings. Closing the finding means the committed config carries the guardrail. It does not prove the agent's effective reach.
- Choosing between options (a) and (b) for network-egress is a judgment call about this repo's own risk posture. If the builder cannot find a narrow rule that keeps `/research` and the cloud-setup `curl` working, take option (b) instead of forcing a lossy deny.
