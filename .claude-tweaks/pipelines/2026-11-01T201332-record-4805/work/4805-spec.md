# 4805: Move the remaining parent-gate evaluators onto the shared parent-gate core

Origin: follow-up from #4603 (PR #4678) wrap-up

Defer-reason: tangential

## Current State

#4603 added `plugin/bin/parent-gate.js` and its shared core `plugin/bin/lib/issues/parent-gate.js` (paginated enumeration with `stateReason`, the self-inclusion rule, the oversight floor, cross-repo closing-reference filtering, reopen handling), and moved `plugin/skills/wrap-up/verification-brief-parent-gate.md` onto it. Two evaluators still compute the gate their own way:

- `plugin/bin/lib/wrap-up/engine-verify.js` (around lines 705-735 and 900-915) enumerates `sub_issues` with its own `gh api --paginate` call, reading no `stateReason`, and calls `parentGateState` directly. Its verdict can diverge from the CLI's on not-planned sub-issues and the oversight floor.
- `plugin/skills/demo/entry-paths.md` (around lines 254-262) composes its own sub-issue enumeration in prose instead of calling `bin/parent-gate.js`.

Ledger rows 28 and 29 of #4603's `docs/plans/2026-10-31-parent-gate-cli-ledger.md`.

## Deliverables

- [ ] `engine-verify.js` evaluates the parent gate through `lib/issues/parent-gate.js` (or `bin/parent-gate.js`), with no `sub_issues` call of its own.
- [ ] `demo/entry-paths.md` calls `bin/parent-gate.js` for enumeration instead of composing the `gh api` call.

## Acceptance Criteria

- [ ] `grep -n "sub_issues" plugin/bin/lib/wrap-up/engine-verify.js` returns nothing.
- [ ] `grep -F "issues/\$PARENT_NUM/sub_issues" plugin/skills/demo/entry-paths.md` returns nothing.
- [ ] A unit test shows engine-verify's verdict for a parent whose sub-issues are all closed not-planned matches `bin/parent-gate.js`'s verdict for the same input.

## Release Note

The wrap-up check and the demo flow now judge a decomposed feature's parent with the same tested code the close procedure uses, so all three agree on edge cases such as cancelled sub-issues.

## Technical Approach

### Key Files

- `plugin/bin/lib/wrap-up/engine-verify.js` — route the parent gate through the shared core
- `plugin/skills/demo/entry-paths.md` — call bin/parent-gate.js for enumeration
- `plugin/bin/lib/issues/parent-gate.js` — reuse
