# 3029: pr-state.js: a misordered `resolvePrStateByNumber(number, {cwd, repo})` call reads as `"network-failure"`

Surface: infra

## Current State

`resolvePrStateByNumber(repoRoot, number)` (`plugin/bin/lib/reconcile/pr-state.js:128`) takes two positional arguments. `resolveIssueStateByNumber(repoRoot, number)` (`pr-state.js:153`) has the same shape. If either is called with misordered or object-shaped arguments, for example `resolvePrStateByNumber(<prNumber>, { cwd, repo })`, `execFileSync` throws `ERR_INVALID_ARG_TYPE`. `runClassified` hands that error to `classifyExecError` (`pr-state.js:33`), which maps everything except a missing `gh` to `'network-failure'`. A programming error therefore looks exactly like a real outage. This was observed on a GitHub Enterprise Server host: the misordered call returned `'network-failure'`, and the correct `(process.cwd(), <prNumber>)` call returned `{"state":"MERGED",...}`.

The trigger is in the docs. Step 2 of `plugin/skills/dispatch/close-out.md` (`close-out.md:41`) says only "Reuse `resolvePrStateByNumber`", with no signature or return contract. It also never says that a string result is a transport failure, so a caller can read `'network-failure'` as "not DIRTY" and carry on.

Current callers:

- `plugin/bin/lib/reconcile/archive-merged.js:1687` calls `resolvePrStateByNumber(root, state.pr.number)`. `record-pr` validates that number as a positive integer at write time (`plugin/bin/hooks.js:835`), but the value is read back from an on-disk `run-state.json`.
- `archive-merged.js:744` injects `resolveIssueStateByNumber` as a default parameter.
- `plugin/skills/_shared/github-pr-scan.md:309` calls `resolvePrStateByNumber(process.env.REPO_ROOT, n)` once per PR number inside a `forEach`.

`archive-merged.js` runs inside the SessionStart reconcile pass, and its helpers are documented as never throwing (for example `archive-merged.js:440`, `:475`).

## Deliverables

1. A caller-contract guard on both by-number resolvers in `plugin/bin/lib/reconcile/pr-state.js`. When `repoRoot` is not a string, or `number` is not a positive integer (or a positive-integer string), return the distinct string `'invalid-arguments'` without calling `gh`. The existing `if (!number) return null` short-circuit stays first.
2. Document `'invalid-arguments'` alongside `'gh-absent'`/`'network-failure'` in `pr-state.js`'s return-contract comments for both functions.
3. Step 2 of `plugin/skills/dispatch/close-out.md` states the signature `resolvePrStateByNumber(repoRoot, number)`. `repoRoot` is the main checkout's path, whose `origin` gives `gh` its host and repo. The step also states the return contract: the PR state object, or one of the strings `'gh-absent'` / `'network-failure'` / `'invalid-arguments'`. It adds that any string result stops the candidate and is never read as "not DIRTY".
4. `tests/bin-lib/reconcile/pr-state.test.js` covers both resolvers:
   - a misordered call returns `'invalid-arguments'` and makes no gh call
   - an object-shaped call returns `'invalid-arguments'` and makes no gh call
   - a non-numeric number returns `'invalid-arguments'`
   - a valid call is unchanged

## Acceptance Criteria

- `resolvePrStateByNumber(4242, { cwd: '/tmp', repo: 'o/r' })` and `resolveIssueStateByNumber(4343, { cwd: '/tmp' })` both return `'invalid-arguments'` without invoking `gh`. Neither returns `'network-failure'`.
- `resolvePrStateByNumber('/tmp', 'abc')` returns `'invalid-arguments'`. `resolvePrStateByNumber('/tmp', undefined)` still returns `null`. `resolvePrStateByNumber('/tmp', '42')` passes the guard, so callers that pass JSON-parsed or string numbers keep working.
- Neither resolver throws on bad arguments, so the reconcile sweep and the `github-pr-scan.md` `forEach` loop keep running past a malformed entry.
- `close-out.md` step 2 names the positional signature and all three failure strings, and says a string result stops the candidate.
- `node --test tests/bin-lib/reconcile/pr-state.test.js tests/reconcile.test.js` passes.

## Release Note

Made the pull-request state lookup report a misused call as invalid arguments instead of a misleading network failure, and documented how dispatch close-out must call it.

## Technical Approach

The reporter offered two guard shapes and left the choice open: throw a `TypeError`, or return a distinct `'invalid-arguments'` string. This record takes the string. Both resolvers feed the SessionStart reconcile pass through `archive-merged.js`, which is documented as never throwing and falls under the hooks' never-break-a-session invariant. The value they get is read from an on-disk `run-state.json`, which can be hand-edited or corrupted after `record-pr` validated it. A throw would abort the whole sweep, and in `github-pr-scan.md:309` it would abort the `forEach` across every remaining PR. A distinct string keeps the programming error distinguishable from an outage, which was the reported problem, without adding a new failure mode. Every existing caller already handles a non-object result as "no usable state" (`archive-merged.js:1688` checks `typeof byNumber === 'object'`). The docs change makes close-out callers stop on any string.

### Key Files

- `plugin/bin/lib/reconcile/pr-state.js` — argument guard returning `'invalid-arguments'` in both by-number resolvers; return-contract comments
- `plugin/skills/dispatch/close-out.md` — step 2 signature, return contract, string-result-stops rule
- `tests/bin-lib/reconcile/pr-state.test.js` — misordered/object-shaped/non-numeric argument tests for both resolvers

## Gotchas

- Don't throw. The original request's diff throws `TypeError`. That was deliberately not adopted, for the never-throw reasons in Technical Approach.
- The guard must accept numeric strings (`String(number)` matched against a positive-integer pattern), because `github-pr-scan.md:309`'s numbers come from parsed JSON and other callers may pass strings.
- Check every consumer that branches on the string results (`'gh-absent'`/`'network-failure'`) to confirm an unknown third string falls into its non-object/failure branch rather than being misread. Grep for `resolvePrStateByNumber` and `resolveIssueStateByNumber` across `plugin/` before building. The current list is in Current State.
- On Windows, 11 other tests in `pr-state.test.js` fail because of the existing gh-wrapper shell stubs. That is unrelated and pre-existing per the reporter.

pr-state.js: a misordered `resolvePrStateByNumber(number, {cwd, repo})` call reads as `"network-failure"`

**Summary:** resolvePrStateByNumber called with misordered/object arguments returns "network-failure" instead of a caller error; close-out.md step 2 does not state the signature

**Kind:** Defect

**Affected component:** reconcile pr-state (bin/lib/reconcile/pr-state.js) + dispatch/close-out.md step 2

**Repro steps:**
1. Follow `skills/dispatch/close-out.md` step 2 ("reuse `resolvePrStateByNumber`"), which gives no signature, and call it as `resolvePrStateByNumber(<prNumber>, { cwd, repo })`.
2. Compare with `resolvePrStateByNumber(process.cwd(), <prNumber>)` from the same checkout.

**Expected vs. actual:**
Expected: a misordered call fails as a programming error; close-out documents the signature and return contract.
Actual: the misordered call returns `'network-failure'`, indistinguishable from a real outage; the correct call returns `{"state":"MERGED",...}`. (Checked on a GitHub Enterprise Server host, with and without `GH_HOST` set — the host is not the problem: `gh pr view` runs with `cwd: repoRoot`, so host/repo come from that checkout's `origin`.)

**Root cause:** the signature is positional, `resolvePrStateByNumber(repoRoot, number)` (`bin/lib/reconcile/pr-state.js:128`). With `(number, {cwd, repo})`, `repoRoot` is a number and `number` an object, so `execFileSync('gh', ['pr','view','[object Object]',...], { cwd: <number> })` throws `ERR_INVALID_ARG_TYPE`; `runClassified` (`bin/lib/shared-primitives.js:166`) passes it to `classifyExecError` (`pr-state.js:33-35`), which maps everything except `ENOENT` to `'network-failure'`. `close-out.md` step 2 (`:41-43`) says "reuse `resolvePrStateByNumber`" without the signature. Fix: (1) state the signature and return contract in `close-out.md` step 2, including that a string result is a transport failure that must stop the candidate, never read as "not DIRTY"; (2) add a caller-contract guard to both by-number resolvers so a misordered call throws `TypeError`. Existing callers are safe: `archive-merged.js:1687` passes `root` and `state.pr.number`, and `record-pr` already validates that number as a positive integer (`hooks.js:846`).
