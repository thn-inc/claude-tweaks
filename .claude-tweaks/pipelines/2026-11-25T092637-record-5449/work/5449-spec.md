When in doubt, the controller writes `behaviour`.
- [ ] **Fail-closed route function.** `plugin/bin/lib/console/sdd-ruling.js` exports `sddRulingRoute(text)`, re-exported from `console/resolve.js` like the module's other names. ## Release Note

The Review Console no longer asks you to ratify SDD rulings that only record build procedure; those are logged for audit instead.

## Technical Approach

The controller (an LLM with the ruling's context) does the classification. Code only checks the controller's label and fails closed. A keyword classifier over free-text `Ruling:` prose would misroute without anyone noticing, and a procedural ruling wrongly kept on the console only costs a click, while a behaviour-changing ruling wrongly routed to audit hides a decision from the human. So everything except a clean, explicit `Class: procedural` + `Defers: no` header stays a console row.

`Class:` is a new header key, distinct from the existing `Kind: sdd-ruling`. `readHeader` already stops at the first blank line, and the new key rides the same parse.

The audit line uses status `AUTO` because it records an applied routing that writes no staged artifact, so `STAGED` would be wrong (`_shared/auto-decision-log.md`'s Status semantics).

Use the ledger skill's documented append procedure, or an existing `hooks.js` ledger verb if one fits, and never hand-format a row that skips the ledger's format check.
