# 4673: Point /tidy's Resume open PR offer at dispatch resume when the stalled run dir is gone

**Related:** #4588

Origin: flow run 2026-10-30T200217-spec-4588 (#4588 plan review, issuecomment-6540061358 question 2)

Defer-reason: tangential

## Current State

`tidy/scan-procedures.md`'s stale-claim scan recommends "Resume open PR #{number} ({url}) — {resume}" when a stale claim's run marker sits on an open PR, where `{resume}` is the PR body's own `### Resume` line (`PIPELINE_RUN_DIR="{old run dir}" /claude-tweaks:flow ...`). When that run directory has already been archived or reaped, the pasted line points at a directory `/flow` cannot adopt. #4588 adds `/claude-tweaks:dispatch resume #N` for exactly that stalled-build case, but scoped its remedy wording to `plugin/skills/dispatch/` and left `/tidy` unchanged (issuecomment-6540061358, question 2).

## Deliverables

When the stale claim's `runId` names a run directory that is absent or archived under `.claude-tweaks/pipelines/`, `/tidy`'s Yours row recommends `/claude-tweaks:dispatch resume #N` instead of the PR body's resume line.

When the run directory still exists, the row keeps today's PR-body resume line.

## Acceptance Criteria

A stale claim on an open PR whose run directory is archived renders "Resume open PR #{number} ({url}) — `/claude-tweaks:dispatch resume #N`".

A stale claim whose run directory still exists renders the PR body's resume line, unchanged.

A test pins both branches.

Tidy now suggests the one-command dispatch resume for a stalled build whose run directory is already gone.
