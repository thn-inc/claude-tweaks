# 4786: Extend the stash guard to /dispatch Task agents and the express-lane agent

Origin: ledger resolve gate (wrap-up of #4559, ledger row 19)

Defer-reason: genuinely-larger

## Current State

The stash guard (plugin/bin/stash-guard.js snapshot, compare and restore) wraps only /build's subagent-driven-development dispatches. The /dispatch Task agents (plugin/skills/dispatch/task-prompt.md) and the express-lane agent (plugin/skills/dispatch/express-prompt.md) get the no-stash wording and the PreToolUse stash warning, but no snapshot, compare or restore, so a stash entry such an agent drops or pops from a linked worktree is not put back. The spec for #4559 scoped the guard to SDD on purpose. Found by the /review lenses for #4559 (ledger row 19).

## Deliverables

- [ ] Decide where the dispatching session takes the snapshot and runs compare around a /dispatch Task call and an express-lane agent call.
- [ ] Wire `stash-guard.js` snapshot and compare around both call sites, with the same restore-by-sha and logged-restore behavior the SDD dispatches have.
- [ ] Update the two prompt files and `docs/hooks.md` so the stated guarantee matches what is wired.

## Acceptance Criteria

- [ ] A dispatched Task agent or express-lane agent that drops a stash entry has it restored by sha when the call returns, and the restore is logged to decisions.md.
- [ ] A test in `tests/stash-guard.test.js` or `tests/dispatch-no-stash-conformance.test.js` fails when the snapshot or compare call is removed from either call site.
- [ ] `node --test tests/dispatch-no-stash-conformance.test.js tests/stash-guard.test.js` passes.

## Release Note

A stash entry dropped by a dispatched agent or the express-lane agent is now put back when that agent returns.

## Technical Approach

### Key Files

- `plugin/skills/dispatch/task-prompt.md` — wire the snapshot and compare
- `plugin/skills/dispatch/express-prompt.md` — wire the snapshot and compare
- `plugin/bin/stash-guard.js` — reuse for the dispatch call sites
