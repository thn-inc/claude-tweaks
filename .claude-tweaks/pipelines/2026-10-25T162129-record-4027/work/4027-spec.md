# 4027: Deliver each phase's procedure in the dispatch prompt instead of agents grepping skill files mid-run

Evidence: 14-day transcript analysis of this repo (176 main sessions, 5,599 subagent transcripts, 132 archived timing.json files, ~286k tool calls), 2026-10-24.

## Current State

In 14 days agents made 28.5k shell reads (`sed`/`grep -A30`/`cat`) of plugin skill files, 8.1k Reads, and 5.4k Skill loads — ~15% of tool calls and ~15% of context tokens. Most-loaded: `review/code-mode-steps.md` 398× (~35 KB each), `review/step3-lens-dispatch.md` 342×, `flow/materialize.md` 257×, `_shared/pr-early-run-lifecycle.md` 242×, `flow/manifesto.md`, `flow/claim-targets.md`.

Median procedureBytes per run rose from 79 KB (2026-09, first half, n=7) to 307 KB (2026-10, second half, n=110). Context per turn: p50 276k, p90 428k tokens. Opus latency per turn is 5.0 s under 100k context and 12.1 s above 300k. `compose-context.js` (#1988, #2019) exists, but agents still pull cited sections on demand, one turn each.

## Deliverables

1. Each dispatch call (build,test and review,polish,wrap-up) and each SDD / lens child gets a composed, condition-resolved procedure bundle (`compose-context.js`) inlined in its prompt, covering every `_shared` section the phase cites — each arrives once.
2. Pure-mechanics steps (claim, materialize, PR-early lifecycle, manifesto) move behind CLIs alongside the bookkeeping record, so their prose leaves the bundle entirely.
3. A per-agent context cap: when the accumulated context crosses a threshold (taken from the measured latency curve), the next phase starts in a fresh agent from a handoff file instead of growing one context.

## Acceptance Criteria

- [ ] Reads of plugin skill files (shell + Read) per pipeline fall by at least 80% over 10 runs.
- [ ] Median procedureBytes per run is 120 KB or less.
- [ ] Dispatch-agent context per turn p50 is 150k tokens or less.
- [ ] The existing conformance suites and the pipeline smoke test pass with no added skips.

## Release Note

Pipeline agents receive their instructions up front, cutting per-step latency and token cost.

## Technical Approach

### Key Files

- `plugin/bin/compose-context.js` — phase bundles
- `plugin/skills/dispatch/task-prompt.md` — inline bundle
- `plugin/skills/flow/SKILL.md` — drop on-demand section reads
- `plugin/skills/_shared/subagent-output-contract.md` — bundle in child prompts
