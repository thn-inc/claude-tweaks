# 4367: Match a record section heading only when it starts its own line

**Related:** #4169, #4350, #4351

## Current State

`sectionText` (`plugin/bin/lib/issues/materialize-format.js`, ~line 102) locates a section with `body.indexOf('## ' + name)` — a substring search, not a line-anchored heading match. #4169 added a fence check around it but kept the substring search.

So a heading mentioned mid-line counts as the record's own section: inline code (a Current State sentence naming the `` `## Acceptance Criteria` `` heading), a blockquote line, or prose. The match is also a prefix match, so `## Release Notes` satisfies `## Release Note`.

Probe at v6.155.1 and at the pre-#4169 tree (2837561ec), same result: `shapeGate` on a body whose only mention of Acceptance Criteria and Release Note is that inline sentence returns `{ ok: true, missing: [] }` — the shape gate passes a record that has neither section. Found by the post-release review of #4169 (staged as review-82 in the v6.155.x release run dir).

## Deliverables

- [ ] `sectionText` matches a section heading only on a line that is itself `## {name}` (line-anchored, the whole heading text, optional trailing whitespace), outside a fenced block

- [ ] `extractSection` and `sectionText` agree on what counts as a heading for the same body

- [ ] tests pin the inline-code mention, the blockquote mention and the `Release Notes` prefix case through `shapeGate`

## Acceptance Criteria

1. `shapeGate` on a body whose only Acceptance Criteria / Release Note mention is inline code in Current State reports both sections missing.

2. A body with `## Release Notes` and no `## Release Note` heading reports Release Note missing.

3. Existing real records still pass: the `shapeGate` and `sectionText` suites in `tests/bin-lib/issues/materialize-format.test.js` stay green.

4. `npm test` passes.

## Release Note

A record that only mentions a required section heading in passing no longer passes the shape gate as if it had that section.

## Technical Approach

### Key Files

- `plugin/bin/lib/issues/materialize-format.js` — sectionText matches line-anchored, whole-name headings
- `tests/bin-lib/issues/materialize-format.test.js` — inline-mention, blockquote and prefix cases
