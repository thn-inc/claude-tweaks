# 3723: Windows regression filer quotes a pre-existing failure and counts renamed tests as new

**Related:** #2767, #3644, #3693

Origin: /claude-tweaks:specify batch on 2026-10-20 (shaping #3599, #3644, #3693, #3695, #3696, #3698, #3699)

Defer-reason: tangential

## Current State

- `tools/windows-regression/file-issue.js:150` (`excerptFor`) quotes the block around the first log line that names the failing file (`normalized.findIndex(...)`), not the failures that were actually attributed as new. #3644 and #3693 both quoted "archiveMerged: a main-loop decideArchive skip (no-pr)…", which was already failing at base. The tests that were really new were #3543's AC5.1/AC5.3 (#3644) and three renamed tests (#3693).
- `plugin/bin/lib/verify/baseline.js` (~line 411) classes a failing test as attributable when no test with the same suite path failed at base. A rename of a test that already fails (cf09383fe/#3297 renamed three) therefore reads as a new failure, and the workflow files a regression issue even though base and HEAD fail the same test count. #3693 was filed only because of this.
- The cost: two records were filed for a harness limitation that was already understood, and the shaping session had to download run artifacts to find out what actually changed.

## Deliverables

1. `file-issue.js` quotes an excerpt for each test the report's baseline adjudication attributed as new (`baselineAdjudicated.attributable` / per-test identity), falling back to the first-match excerpt only when per-test attribution is unavailable, and says which case applies.
2. When every attributable failure in a file is a test whose name does not exist at base, and the file's failing count at base equals the count at HEAD, the issue body says so ("possible rename of an already-failing test") instead of presenting it as a plain regression. Detecting renames inside baseline.js is out of scope.

## Acceptance Criteria

1. Given a fixture report whose attributable test is the file's second failing test, the composed issue body quotes that test's block and not the first failure in the file.
2. Given a fixture where base and HEAD fail the same number of tests in a file and the only attributable names are absent at base, the body carries the possible-rename note.
3. Both fixtures go red when the change is reverted. `npm test` passes.

## Release Note

Windows regression issues now quote the tests that newly fail and flag likely renames of tests that were already failing.

## Technical Approach

### Key Files

- `tools/windows-regression/file-issue.js` — per-attributed-test excerpts; possible-rename note
- `plugin/bin/lib/verify/baseline.js` — read only — attribution source
