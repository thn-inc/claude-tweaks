# 4746: specify: one session-wide shaped-body temp file lets a sweep write a body onto the wrong record

Origin: reflect full from #4549/#4550/#4556 (multi-spec batch)

Defer-reason: tangential

## Current State

`plugin/skills/specify/shaping-mode-stamping.md:182` resolves `$SPECIFY_SHAPED_BODY` as `sessionTmpPath(CLAUDE_CODE_SESSION_ID, 'specify-shaped-body.md')`, one fixed filename per session, falling back to `os.tmpdir()/specify-shaped-body.md`. `shaping-mode.md:75` reuses the same path for its `--check` probe.

Every record a session shapes therefore shares one body file. Sweep run `2026-10-30T154127-sweep-standalone` wrote #4559's body onto #4549, #4549's onto #4550, and #4555's onto #4556. #4559 and #4555 kept their own correct bodies. The misfiled bodies had to be reshaped by hand on 2026-10-31.

Probe: `git grep -n -F -e 'specify-shaped-body' origin/main -- plugin` matched both lines above.

## Deliverables

Key the shaped-body temp file by record id (e.g. `specify-shaped-body-{N}.md`) at both resolve sites, so two records shaped in one session, or by sibling dispatches sharing a session id, never share a file.

Before the body write, check that the body file being written was composed for the record being written, failing loud on a mismatch rather than writing it.

A regression test that shapes two records in one session and asserts each record receives its own body.

## Acceptance Criteria

Both resolve sites name the record id in the temp filename; a conformance test pins the per-record form at each site and goes red on the fixed `specify-shaped-body.md` form.

Shaping two records back to back in one session writes each record its own body (regression test, red on the current fixed filename).

A body file whose record id does not match the target record is refused before any write, with a message naming both ids.

## Release Note

Shaping several records in one session (including sweeps) can no longer write one record's body onto another.
