# 4024: Select local tests by traced file reads instead of running the full suite for every plugin/** change

Evidence: 14-day transcript analysis of this repo (176 main sessions, 5,599 subagent transcripts, 132 archived timing.json files, ~286k tool calls), 2026-10-24.

## Current State

`.claude-tweaks/verify-scope.json` maps `plugin/skills/**`, `plugin/**`, `tests/**` and `tools/**` to `"suites": "*"`, so any skill-prose edit runs all 919 test files (~474 s on an idle machine). `tools/run-tests.js` holds one machine-wide suite slot (`CT_TEST_SUITE_SLOTS` default 1), so parallel dispatches queue behind each other.

Measured: verify.js / npm test consumed ~78 h of tool time in 14 days and ~25% of dispatch-agent wall time; full-length runs per pipeline p50 2, p90 6, max 17; 20 runs hit the 20-minute Bash timeout. #3968 (two markdown lines) paid a 476 s full run.

CI (`.github/workflows/test.yml`) already runs the full `npm test` on every `pull_request`, and this repo merges under `merge-verification: merge-when-green` — the local full run duplicates the merge gate.

A static import map is not enough: 35 test files sweep the skill corpus via readdir/glob, and 570 spawn or require `plugin/bin` code (child processes).

## Deliverables

1. A read tracer: a `--require` preload, propagated to child `node` processes via `NODE_OPTIONS`, that records every path read, required or readdir'd, attributed to the test file that caused it. One traced full-suite run emits a test-impact map (test file → read paths; directory reads stored as prefix dependencies), cached with the commit it was traced at.
2. A verify-scope rule kind that consults the map: select only test files whose recorded reads intersect the changed files (a directory read matches any changed path beneath it), plus changed test files themselves. Generic mechanism — this repo is the first consumer.
3. Fail closed: run the full suite when the map is missing, traced at a commit that is not an ancestor of HEAD or older than a staleness bound, or a changed path matches no traced read — `report.json` names the fallback reason.
4. Move this repo's `plugin/**`, `tests/**`, `tools/**` rules from `"*"` to the impact map. Explicit `full` mode stays available; CI's full suite stays the merge gate.
5. Map refresh off the hot path (post-merge on main or scheduled), never inside a build.

## Acceptance Criteria

- [ ] A diff touching only `plugin/skills/init/claude-md-template.md` and `CLAUDE.md` selects fewer than 50 test files and verify completes in under 60 s (report.json shows the selected count and duration).
- [ ] A diff touching `plugin/bin/log-decision.js` selects every test that requires or spawns it (asserted against a hand-checked list).
- [ ] A new file under `plugin/skills/` selects the corpus-sweeping tests (directory-read dependency).
- [ ] Discrimination: removing one test's recorded read from a fixture map deselects that test; restoring it reselects it.
- [ ] A missing or stale map runs the full suite and report.json names the fallback reason.
- [ ] Median verify minutes per pipeline (timing.json) falls below 1 across the next 20 runs (baseline: 4.2 fast-lane, 5.8 standard).

## Release Note

Builds run only the tests a change can affect, so most verify steps take seconds instead of about eight minutes; CI still runs the full suite before merge.

## Technical Approach

### Key Files

- `plugin/bin/verify.js` — consult the impact map in scoped selection
- `plugin/bin/lib/verify/scope.js` — impact rule kind
- `plugin/bin/lib/verify/changed-files.js` — changed paths into selection
- `.claude-tweaks/verify-scope.json` — replace "*" rules
- `tools/run-tests.js` — tracer preload + file subset
- `plugin/skills/test/verification.md` — document impact selection

### As built (architecture alignment, /build Common Step 4.5)

- **Directory reads match by status.** A directory listing matches a changed path beneath it only when that path was added or deleted, because modifying a file does not change a listing. A modified file is matched by its content readers, and a test that reads each listed file records those reads too.
- **More read kinds than "read, required or readdir'd".** The map also records existence probes (`exists`/`access`/`realpath`/`readlink`). It records content prefixes as well: the directory arguments of non-node children, and git subcommands that read content and name no path. Without these, a test that guards on a path's existence, or runs git in the repo, would be under-selected. For an added or deleted file, an existence probe or `stat` on an ancestor directory also matches.
- **A changed test file selects its readers** — meta-tests that read or list test files — as well as itself.
- **The tracer lives in `tools/test-impact/`, not `tools/run-tests.js`.** `tools/test-impact.js trace` runs `tools/run-tests.js` with the tracer preloaded through `NODE_OPTIONS`. `run-tests.js` only gains `--files-from`, the file subset `verify.js` passes.
