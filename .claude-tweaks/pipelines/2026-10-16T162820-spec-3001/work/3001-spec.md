# 3001: review/step3-lens-dispatch.md: lens agents are never told not to run the project's test suites — one ran the full Playwright e2e suite in the background during the fan-out

Surface: infra

**Related:** #2908, #2955, #2977, #3021, #3060

## Current State

`/claude-tweaks:review` Step 3 dispatches read-only lens reviewers per `plugin/skills/review/step3-lens-dispatch.md`, as reproduction pairs or single reads. `review/SKILL.md:98` lists "Running verification or QA directly in review" as an anti-pattern, because mechanical checks belong in `/claude-tweaks:test`. The dispatch contract, however, never forbids a lens agent from running the project's suites, builds or servers:

- The per-lens Calibration + Output template (`:101-145`) carries no such rule. It is byte-pinned against `_shared/criteria-review-quality.md` by `tests/code-health-misc/criteria-fragments.test.js:70-96`, so it cannot be edited freely.
- The Foreground Execution Discipline note (`:58`) implicitly allows it. It speaks of "any lens, debate, refutation, or gap-sweep agent that runs a verification command (rather than only reading/reporting)".
- The post-fan-out sweep (`:146-158`) only diffs `git status --porcelain --untracked-files=all` against the pre-dispatch listing. A stray dev server, mock server or test runner leaves no untracked file and is invisible to it.

In the reported run (plugin 6.136.0), a Fast-profile 3f Test Quality agent launched the project's full Playwright e2e suite in the background on the framework's default ports. This raced the ephemeral servers `/visual-review` starts for the same review. It produced wrong-harness failures (dev-build auth-gate failures the project documents as expected on `next dev`) and ended with "stopped with background work of its own still running" / "e2e: in-flight".

## Deliverables

1. Add an explicit rule to Step 3's dispatch prompt rules, outside the byte-identical Calibration block, alongside the Working Directory and Foreground Execution notes. The rule: lens, debate, refutation and gap-sweep agents never run the project's test suites, builds, dev servers or e2e runners. They read and report only, and mechanical verification belongs to `/claude-tweaks:test`. The rule must be part of what actually reaches each agent's prompt (the composed review-dispatch bundle), not just a maintainer-side note.
2. Reconcile the Foreground Execution Discipline note (`:58`) with the new rule, so it no longer implies running verification commands is an expected lens activity.
3. Extend the post-fan-out sweep with a report-only check for processes the fan-out left running: listeners that appeared on local TCP ports since the pre-dispatch snapshot, taken next to the existing `pre-dispatch-status.txt`. Report any new listener in the review summary's `Fan-out leftovers` section and log a `STAGED` line, mirroring the untracked-file handling. Never kill anything.

## Acceptance Criteria

- A conformance test asserts that the composed review-dispatch bundle (the text dispatched agents receive) contains the no-suites/builds/servers rule. Prove it goes red against the current text.
- `tests/code-health-misc/criteria-fragments.test.js` passes unchanged, since the Calibration block is untouched.
- `tests/review-dispatch-composition.test.js` passes, with the composed bundle still under `CEILING_BYTES` and no new `COMPOSED_STEP_EXCEPTIONS` entry.
- The sweep section documents the port-listener snapshot and diff, its report-only posture, and its `Fan-out leftovers`/`decisions.md` outputs. The conformance test pins this.
- `npm test` passes in full.

## Release Note

Code review's parallel reviewers are now told never to run your test suites or start servers, and the review reports any server they leave running.

## Technical Approach

Put the prohibition next to the existing discipline notes, in the source the composed review-dispatch bundle draws from, so it reaches agents with no per-tier duplication. For the listener check, capture a pre-dispatch snapshot (for example `lsof -nP -iTCP -sTCP:LISTEN` on macOS/Linux, with a documented skip-and-log when the command is unavailable) into `{ctx-dir}`, then diff after the fan-out. Report by port and command name only.

## Gotchas

- The Calibration + Output template is byte-identical with `_shared/criteria-review-quality.md` and pinned by a test. Do not put the new rule inside it.
- The composed review-dispatch bundle has a hard byte ceiling (`tests/review-dispatch-composition.test.js:71-78`). Measure headroom with `wc -c` before adding text, and keep the rule to one sentence.
- A listener diff can pick up unrelated processes another session started during the fan-out. Like the untracked-file sweep, it is report-only and must say it cannot attribute ownership. Never treat it as proof a lens agent misbehaved, and never kill anything.
- Refutation agents in Step 3.6 may legitimately need to read a test file. The rule forbids running suites, builds and servers, not reading code.
