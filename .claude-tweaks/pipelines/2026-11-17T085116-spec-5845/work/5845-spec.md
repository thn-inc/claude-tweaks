# 5845: Build the archive-tracked-shells test fixtures once per process

**Related:** #3975, #5772, #5768, #5718, #5771

Verified-as-of: badfd03b71f7c8f39e2188e4f36be8d3aad446c5

## Current State

`tests/archive-tracked-shells.test.js` (added 2026-11-16 by #3975, PR #5665) is the largest git spender in the suite. A full `node tools/run-tests.js --full` with git trace2 per test file on main at e1c0beb1b (2026-11-17) counted 3,528 git processes for it: 2,121 started by the test process and 1,407 by other git processes, with worktree 404, rev-list 319, commit 224 and upload-pack 208 the largest subcommands. #5768's PR showed it at 3,727 before that record removed its maintenance processes.

Its fixtures are rebuilt for every test:
- `makeFixture()` (line 32) runs `init --bare`, `clone`, `config core.autocrlf false`, `checkout -B main`, `add`, `commit` and `push -u origin main`, seven git calls plus the transport children of the clone and the push. It has 54 call sites.
- `makeLocalOnlyFixture()` (line 933) runs `init`, `config`, `add` and `commit`. It has 2 call sites.
- `addShell()` (line 52) runs `add`, `commit` and, by default, `push` for each shell. It has 78 call sites; most are `{ twin: 'absent' }` on a fresh fixture as the first step of a test, with a run id that only that test uses.

The CLI under test (`plugin/bin/archive-tracked-shells.js`) runs in-process through `runCliSync` against real git. Its own git calls (worktree add, list, remove and prune, fetch, merge, commit, push) are the behaviour under test, as are the `git worktree add` and `git worktree lock` setups of the stale, live and locked scratch-worktree tests, the fake-git interleaving tests and the merged-PR simulations.

`tests/helpers/git-template.js` (`fromTemplate`, `fromTemplateSet`) builds a fixture once per test process and hands every caller an `fs.cpSync` copy with its git metadata paths rewritten; a copy starts no git process. #5772 moved the statusline fixtures (`tests/helpers/statusline-fixtures.js`, -83%) and the archive-merged fixtures (`tests/bin-lib/reconcile/archive-merged-helpers.js`, -53%) onto it. This file does not use it.

The file sets its commit identity through the environment (`GIT_AUTHOR_*`, `GIT_COMMITTER_*`) and spawns no `git config user.name` or `user.email`. #5771 adds a suite test that fails on such a spawn.

#5771 (PR #5842, one-process repo init) and #5790 (PR #5843, learned-skills git reuse) were being built by other sessions when this was filed. #5771 edits `tests/helpers/git-template.js`, `tests/helpers/git-fixtures.js`, `tools/run-tests.js` and `tests/helpers-git-template.test.js`; this record calls the first two as they are and edits none of them. Open record #5718 (ready, not being built) will add interleaving tests to this same test file.

## Deliverables

1. `makeFixture()` and `makeLocalOnlyFixture()` return a copy of a template built once per process through `fromTemplate` / `fromTemplateSet`. The returned shape and the repository state stay what they are now: a realpath'd `base` holding `origin.git` and `main`, branch `main` with its upstream set and pushed, the repository's `.gitignore`, the `seed` commit, `core.autocrlf=false`.

2. Shell setup that is the same across tests is seeded in the template: a fixture variant keyed by the ordered list of shell options (`twin`, `clean`, `push`) returns the copy plus each shell's descriptor (`id`, `file`, `live`, `twinWork`), with the gitignored archive `run-state.json` files present in the copy. A test moves onto a variant only where every one of its assertions stays unchanged; a run-id literal in a test's setup may become the variant's id only where no assertion names that literal. `addShell()` stays for shells a test adds after its first CLI call or between steps.

3. Every git operation that is the behaviour under test stays real and per test: each git call the CLI makes, the scratch-worktree `worktree add` / `worktree lock` setups, the fake-git interleaving steps, the merged, closed and squash-merged PR simulations, and each git call an assertion reads.

4. One test in `tests/archive-tracked-shells.test.js` shows that a warm call of each templated builder and variant starts no git process: one warm-up call, then a call under `GIT_TRACE2_EVENT=<empty dir>` that leaves the directory empty, in the style of `a copy starts no git process` in `tests/helpers-git-template.test.js`. It is declared after the tests that use the builders, so it adds no template build, and it lives in this file, not in `tests/helpers-git-template.test.js`.

5. The PR body reports git processes for `tests/archive-tracked-shells.test.js` before and after, in total and for `init`, `clone`, `commit`, `push` and `worktree`.

## Acceptance Criteria

- [ ] Every test in `tests/archive-tracked-shells.test.js` before the change is present after it under the same name and passes. The number of tests is not lower. No assertion is removed or loosened and no test is skipped or merged.

- [ ] In a traced run of the file, the test process starts `git init` and `git clone` at most once per distinct template, not once per test. The PR body lists the templates.

- [ ] The warm-call test of Deliverable 4 goes red when one templated builder is put back to building per call. The PR body quotes that red output.

- [ ] A copy is independent: its `origin` remote URL is its own copied `origin.git` (asserted once), and a push in one copy leaves another copy's origin unchanged.

- [ ] The file's git process count after the change is at most 75% of its count before. If the processes that remain are the CLI's own work under test and that figure cannot be reached without replacing a real git operation under test, the PR body gives the breakdown and says so.

- [ ] Counts come from `GIT_TRACE2_EVENT=<absolute path of an empty directory>` (one file per git process) around `node tools/run-tests.js --files-from <list>`, the before count taken at the branch's merge-base with main and the after count at HEAD, back to back on the same machine with the same command and the same concurrency.

- [ ] The full suite and the Windows regression job pass after the last code change (the template copies rewrite paths in git metadata).

- [ ] No file that #5771 or #5790 is editing is changed.
