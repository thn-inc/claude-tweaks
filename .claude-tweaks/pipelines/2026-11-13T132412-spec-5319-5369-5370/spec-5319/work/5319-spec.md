# 5319: Run the impact-selected subset on a plain local npm test, and the whole suite only with --full or in CI

Surface: infra

**Related:** #5369 and #5370 (the `verify.js` and pipeline half of the same decision), #5366 (the queue-pull oracle's shim cost, which this record first carried as an optional deliverable), #5365, #5325, #5185

## Current State

A plain `npm test` on a developer machine runs every test file. `package.json` maps it to `node tools/run-tests.js`, which with no arguments collects everything under `tests/` and `tools/upstream-drift/tests/` (1,165 files at this commit) and hands it to `node --test`. The runner has no notion of what changed.

Measured on the maintainer Mac (12 cores, 33 concurrent Claude sessions) on 2026-11-13: CPU sat at 100% (about 63% user, 37% kernel) with load between 50 and 110, and two claude-tweaks test runs caused about three quarters of all process creation. Session transcripts from 9 to 13 November show that whole-suite runs also start outside `verify.js`: agents typed a plain `npm test` about 20 times in drive worktrees alone (`npm test 2>&1 | tail -40`, sometimes twice in one command), and more in flow worktrees and the main checkout. Skill prose cannot reach those runs. A headless worker runs the command it knows.

The parts needed to select by impact already exist. `.claude-tweaks/verify-scope.json` declares `impact` (#4024): a map built by a traced whole-suite run in CI on every push to main (`.github/workflows/test-impact-map.yml`) records which test files read which paths, and `verify.js --scope` narrows the `tests` suite to the files a change can affect, running `node tools/run-tests.js --files-from {list}`. Over the 60 impact-selected verify runs logged since 9 November the subset had a median of 263 files and a maximum of 591. Selection fails closed: when the map is missing, stale or does not cover a changed path, the whole suite runs (`plugin/skills/test/impact-selection.md`). CI runs the whole suite on every PR push, split across four shards (`.github/workflows/test.yml`), and the merge gate waits for it.

This record first proposed a hand-kept `heavy` list, so that a default local `npm test` would skip `tests/bin-lib/dispatch/queue-pull.test.js` (8,539 Node process starts per run, the largest spawn source measured). Selecting by impact makes that list unnecessary. The file then runs locally only when the queue-pull module, its fence or a traced dependency changed, which is the guarantee #5227 needs, and the same holds for every other file with no list to maintain. The original proposal is kept below under Original request.

Two things this record does not cover. What `verify.js` runs inside pipelines is #5369 and #5370. The cost of the queue-pull file when it does run is #5366.

## Deliverables

- [ ] **Default run.** `tools/run-tests.js` with no arguments and `CI` unset runs only the impact-selected test files for the checkout's changes since its merge-base with `origin/main`: committed, staged, unstaged and untracked. It selects with the same code `verify.js --scope` uses (`plugin/bin/lib/verify/`), never a second selector. It prints one line naming how many of how many files were selected, the base commit, and that `npm test -- --full` runs the whole suite here.
- [ ] **`--full`** runs the whole root set. So does any run with `CI` set. `--shard` and `--record-durations` keep meaning the whole set, and explicit root arguments (`perf`) and `--files-from` are unchanged.
- [ ] **Fail closed.** When selection cannot be trusted (any fallback reason in `impact-selection.md`, a changed path that a full-suite rule matches, or no merge-base), the run is the whole suite and prints the reason. An unknown never selects fewer tests.
- [ ] **Slot lanes.** A selected run takes the subset lane and a whole-suite run takes the full lane, as today.
- [ ] **Declaration.** `checks.tests.tests` in `.claude-tweaks/verify-scope.json` names the whole suite explicitly (`node tools/run-tests.js --full`), so `verify.js`'s full command and the impact tracer keep running every file.
- [ ] **Docs.** `CLAUDE.md`'s Commands block and `docs/plugin-structure.md` say what a plain `npm test` runs and how to ask for the whole suite.

## Acceptance Criteria

1. With `CI` unset, `node tools/run-tests.js` in a checkout that changed one plugin module runs only the test files the map selects for that change, and prints one line with the selected count, the total, the base commit and the `--full` hint. `tests/bin-lib/dispatch/queue-pull.test.js` is not among them unless the queue-pull module, its fence or a traced dependency changed.
2. `npm test -- --full` runs every test file. So does a plain `npm test` with `CI=true`, and `--shard i/n` slices still partition the whole set.
3. With the map missing, stale, or not covering a changed path, a plain `npm test` runs the whole suite and prints the fallback reason.
4. A clean checkout at its merge-base with `origin/main` selects nothing. The run exits 0 and its one line says that no file was selected and names `--full`, so a run of zero tests is never silent.
5. `verify.js --scope` behaves as before: it still selects and runs `queue-pull.test.js` when a traced dependency changes (#5227), and its full command still runs every file.
6. Every workflow under `.github/workflows/` that runs the suite still runs the whole suite, and a test pins that each one either sets `CI` or passes `--full`, `--shard` or `--record-durations`.
7. The choice between whole suite and subset is decided by one function of the arguments, the environment and the selection result, and is tested without spawning the suite.

## Technical Approach

`tools/run-tests.js` is maintainer tooling and already requires shipped modules (`plugin/bin/lib/suite-slot.js`), so it can call the selection code directly: resolve the changed set against the merge-base (`plugin/bin/lib/verify/changed-files.js`), load the map with `impact.js`'s `loadImpactContext` (which also runs the declared `fetch` when the map has a problem), and classify with `scope.js`'s `selectScope`, reading `.claude-tweaks/verify-scope.json` as the declaration. The selected list then takes the path `--files-from` already takes, including the Windows command-line fallback.

Suites that spawn the runner with no arguments must pin the mode (`--full`, or an explicit root), so that their result does not depend on the checkout's diff.

### Key Files

- `tools/run-tests.js` — default local run selects by impact; `--full`
- `.claude-tweaks/verify-scope.json` — `checks.tests.tests` names the whole suite explicitly
- `tests/package-json-test-script.test.js` — the default-run decision and the `--full` contract
- `tests/run-tests-shard.test.js` — shards still partition the whole set
- `tests/run-tests-isolation.test.js` — pin the mode where the runner is spawned bare
- `tests/verify-scope-declaration.test.js` — the declaration's full command and the workflow pin
- `CLAUDE.md` — Commands block
- `docs/plugin-structure.md` — test commands

## Gotchas

- GitHub Actions sets `CI=true` on every runner, and the tracer, Windows-regression and PR workflows rely on that to get the whole suite. A step that unsets it would silently run a subset, which is why acceptance criterion 6 pins it.
- `verify.js` sets `CT_TEST_SUITE_SLOT_HELD=1` for its children. That is a slot signal, not a whole-suite signal: the declared command carries `--full` itself.
- An installed plugin build only executes the declared command string, so changing `checks.tests.tests` needs no reader release.
- The map is traced in CI's environment (ubuntu, Node 20). A test whose reads differ on macOS can be under-selected locally. The PR's whole-suite CI run is what catches that, and #5370's decision document states it.
- `windows-regression.yml` passes `--cmd tests="npm test"` to `verify.js`. It runs in Actions, where `CI` is set, but naming `--full` there keeps the intent visible.
- A fresh clone with no map and no `gh` login falls back to the whole suite with the reason printed, so a first-time contributor's `npm test` still runs everything.

## Current State

`tests/bin-lib/dispatch/queue-pull.test.js` (#5227) runs `plugin/skills/dispatch/queue-pull-script.md`'s bash fence whole, beside the module, for every parity pair. That covers the AC1 matrix, the fault rows and the real-input probe, with every `gh`, `git` and `mktemp` call answered by a Node shim process. One run on 2026-11-13 at 566b73843, on a machine loaded by sibling sessions, took 470 s wall time (303 s user, 148 s system CPU) and passed 227/227.

A counting preload saw 8,539 Node process starts and 10,201 Node-side spawn calls. The largest sources were 2,398 `git` shim and 655 `gh` shim starts, 1,572 `session-tmp-resolve.js`, 1,151 `node-eval-file.js` and 499 `resolve-policy.js` runs from the fence itself, and 5,689 real `git` calls. Coreutils bash runs are not counted, so the true total is higher. A monitoring session measured the file as the largest spawn source on the machine: 949 of 3,261 spawns in a 15 s sample.

Scoped runs already gate it: `verify.js --scope` selects the file only when a file its trace touched changes (`.claude-tweaks/verify-scope.json` `impact`). A plain `npm test` (`tools/run-tests.js` with no `--files-from`) runs every file, and the runner has no tier that skips a heavy file and gives children no signal of how a file was selected. An in-file gate keyed on changed paths would duplicate the tracer with a weaker dependency set: the module and the fence reach about 20 shared modules and plugin CLIs, and a change to any of them can change the parity answer.

## Deliverables

- [ ] A `heavy` list in `.claude-tweaks/verify-scope.json`, added expand-contract per `.claude/skills/verify-scope-rule-kind`, naming `tests/bin-lib/dispatch/queue-pull.test.js`.

- [ ] `tools/run-tests.js`: a default local run (no `--files-from`, no `CI`) skips heavy files and prints one line naming them and how to include them (`--heavy`). A `--files-from` run (impact selection) and any run with `CI` set always include them.

Moved out: cutting the oracle's per-call shim cost (formerly an optional deliverable here) is #5366.

## Acceptance Criteria

1. On a default local `npm test` with no `CI`, `queue-pull.test.js` does not run, and the runner prints one line naming it and the flag that includes it.

2. `node tools/run-tests.js --files-from {list}` with the file in the list runs it, and so does any run with `CI=true` and `npm test -- --heavy`.

3. `verify.js --scope` still selects and runs the file when the queue-pull module, the fence or a traced dependency changes, as the parity guarantees of #5227 require.
