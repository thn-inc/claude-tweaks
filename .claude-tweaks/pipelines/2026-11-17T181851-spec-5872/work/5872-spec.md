# 5872: Read health-state files in one git process and skip the read when the branch does not resolve

## Current State

`plugin/bin/lib/health-core/durable-state.js` reads each health-state file with its own `git -C <root> show <ref>:<namespace>/<file>` process (`showFileAt`, ~line 178), one per file spec (3 to 5 per read round). `writeState`'s CAS loop reads at the ref name `origin/health-state` (`readFilesAtFetchedTip`) even when the combined `rev-parse` just before it (`currentRefShas`) already found that the ref does not resolve. In that case every `show` exits 128 and the read degrades to defaults, which a read at the resolved commit sha (null, so no git call at all, via `readFilesAt`'s existing falsy-ref branch) would have produced with zero processes.

Measured (mac-debugging ctprof, full `node tools/run-tests.js --full` on main c3eaa6ded, 2026-11-17, git trace2 per test file): the suite starts 55,052 git processes. About 984 of them exit 128 before git reports a subcommand, and all of those come from the three validate-findings suites: `tests/bin-lib/code-health/cli-validate-findings.test.js` 480, `tests/bin-lib/docs-health/cli-validate-findings.test.js` 292, `tests/bin-lib/journey-health/cli-validate-findings.test.js` 212. In the code-health file the 480 split into `fetch origin health-state` (105) and `show origin/health-state:code-health/{declined,runs,remembered,cursors}.json` (75 each). The fixture root is a plain tmp directory with no repo, origin, or health-state branch. The host is a 12-core Mac, CPU-bound mostly by process starts when more than about 20 Claude Code sessions are working, and this suite is the largest source of them.

Fetch count: each fetch in one invocation guards a distinct read against a remote that can move in between (readState's read, each CAS attempt, the post-push ambiguity check), so none is a duplicate that can be dropped without changing CAS semantics.

## Deliverables

1. `writeState` (and `pushState`/`writeStateLocal`, which already do) read the namespace files at the commit sha `currentRefShas` resolved rather than at the ref name, so an unresolved ref reads straight to defaults with no git process, and the read and the commit parent always describe the same commit.
2. `readFilesAt` reads every file spec in ONE `git -C <root> cat-file --batch` process (input: one `<ref>:<path>` line per spec), parsing the byte-counted output; a `missing` object, a failed process, or unparseable JSON degrades that spec (or every spec, for a failed process) to its default exactly as `showFileAt` does today.
3. The unit-test fake runners that model `git show` (`tests/bin-lib/health-core/durable-state.test.js`, `tests/bin-lib/dispatch/queue-order.test.js`, `tests/bin-lib/issues/merge-lane-breaker.test.js`) model the batch read instead, keeping every test and every assertion.
4. Before/after git process counts (GIT_TRACE2_EVENT directory, one file per process) for the three validate-findings suites and every other test file touched, reported in the PR.

## Acceptance Criteria

Every existing test in the touched files still exists and passes; none is removed, skipped, or has an assertion loosened.

readState/readStateWithMeta keep the tolerant-fetch semantics: a missing remote ref returns defaults with no stderr line, any other fetch failure returns defaults and writes the same `health-state: fetch failed, treating as empty state: ...` line.

The offline timeout handling around `plugin/bin/code-health.js:134` is unchanged (DEFAULT_RUN_TIMEOUT_MS still applies to every git call, including the batch read).

A writeState against a root whose origin/health-state does not resolve starts zero `show`/`cat-file` processes for its read.

A read round at a resolving ref starts exactly one git process for all file specs (pinned by a test that counts runner calls).

Measured git process counts for the three validate-findings suites drop versus main, with before/after numbers in the PR body.

merge-lane-breaker.js and queue-order.js (createNamespacedState consumers) behave identically: their suites pass unchanged in assertions.

## Build Alignment Notes

Beneficial deviations found at `/build` Common Step 4.5, kept as built:

- The shared contract `plugin/skills/_shared/health-state.md` now describes the batched read and writeState's read-at-resolved-commit; the Deliverables did not name it, but leaving it describing the per-file `git show` read would make the contract wrong.
- The batch read passes `maxBuffer: LARGE_MAX_BUFFER_BYTES` (64 MiB). Each old per-file `git show` ran with Node's 1 MiB default, so a state file over 1 MiB silently degraded to its default (ENOBUFS caught); it now reads. A missing file, invalid JSON, or a failed process still degrade exactly as before.
- git's own per-file `fatal: path '…' does not exist in 'origin/health-state'` stderr lines no longer appear (a missing object is a `missing` line on cat-file's stdout); the `health-state: fetch failed, treating as empty state: …` line and the missing-ref silence are unchanged.
