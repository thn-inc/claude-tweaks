# 3880: SDD deferral rulings skip the fix-now test and are auto-ratified at unattended

Origin: reflect full from #3656

Defer-reason: tangential

## Current State

`build/dispatch.md` copies every SDD `Ruling:` line into the open-items ledger and stages it as `staged/sdd-ruling-{N}.md` for ratify or reverse at the Review Console. SDD writes the bare `Ruling:` form where it decided in lieu of a human, including rulings that defer work ("pre-existing, outside the diff, routed to a follow-up record"). Nothing in that path runs `_shared/deferral-gate.md`'s fix-now test or requires a `Defer-reason:` on the staged ruling.

At `autonomy: unattended` the console's `console-resolve.js --policy console-auto` resolves an `sdd-ruling-*` item as ratify, so a deferral that failed no criterion is filed as a follow-up record instead of fixed.

Evidence: #3656's `sdd-ruling-2` (parallel-wave member servers recorded under `spec-{N}/`) deferred a one-file fix that met every fix-now criterion and fell under AC2's literal text ("no ephemeral server outlives the run"). It was caught and fixed at wrap-up only because the wrap-up agent ran the gate by hand against the ruling.

## Deliverables

1. `build/dispatch.md`'s `Ruling:` carry-forward: for a ruling whose one-liner defers work, run `_shared/deferral-gate.md`'s fix-now criteria against the record's acceptance criteria (literal text) before staging. A ruling that qualifies for fix-now is fixed in the build and not staged; one that fails carries a valid `Defer-reason:` header line in its `staged/sdd-ruling-{N}.md`.
2. `console-resolve.js`'s `console-auto` policy: an `sdd-ruling-*` item that defers work and carries no valid `Defer-reason:` resolves `pending` (needs a human) instead of ratify; `wrap-up/review-console-appendix.md`'s `sdd-ruling-*` bullet states the rule.
3. Conformance test pinning both halves.

## Acceptance Criteria

- A deferral-type SDD ruling that meets the fix-now criteria is fixed during build and does not reach the Review Console.
- A deferral-type `sdd-ruling-*` staged file always carries a valid `Defer-reason:` line.
- Under `console-auto`, a deferral-type ruling with no valid `Defer-reason:` is left pending, never auto-ratified.
- A non-deferral ruling (a settled design decision) resolves exactly as today.
- `npm test` passes in full.

## Release Note

Subagent-driven builds now fix a deferred review finding that qualifies for an immediate fix instead of handing it to the console as a follow-up.

## Build Deviations (architecture alignment, Common Step 4.5)

Classified Beneficial — kept as built:

1. **Gate timing.** Deliverable 1 put the fix-now test "before staging". The build runs it when the `Ruling:` is written, and names a fix destination for each ruling site: pre-flight → the task brief; in-loop → the next fix round; breaker or post-re-review residual → one `/build`-authorized targeted fix plus a scoped re-review. A qualifying fix therefore lands under review instead of at Finish, after the last review.
2. **Second trigger point.** Deliverable 2 named only `console-resolve.js`'s `console-auto` path. The reconciler's `consoleAutoResolve` path (`_shared/console-execution.md`, `bin/lib/reconcile/console-execute.js`) is gated too, through `rulingGateGaps`, so AC3 holds at both unattended trigger points.
3. **Deferral detection.** The spec did not say how the console tells whether a ruling defers. The staged header carries an always-written `Defers: yes|no`. A header with no `Defers:` line, more than one, or an unreadable file fails closed to `pending — sdd-ruling-unclassified`. A ruling staged before #3880 therefore waits for a human rather than being ratified.
