# 3597: backlog refine re-refuses records a human already resolved

**Related:** #1887, #1488

Defer-reason: tangential

## Current State

`plugin/skills/backlog/grant-lane-decision.md`'s Idempotence check only suppresses a fresh `needs:decision` when an *unresolved* `<!-- needs-decision: backlog-refine -->` comment exists. Once a human resolves the refusal through `/claude-tweaks:backlog refine #N` (keep, or build it myself), the next human-present `refine` run's grant-check refuses the same record for the same reason and stamps a fresh `needs:decision` and comment.

Observed 2026-10-19 (run `2026-10-19T122748-backlog-standalone`): 15 ready records already carried a human-resolved backlog-refine refusal. #3214, #3215, #3216, #3217, #3256, #3295, #3396, #3193 and #3067 were each resolved twice (2026-10-15/17 "build it myself", 2026-10-19 "keep"), so every refine run reopens a question the human already answered. That session skipped them by hand and logged a SKIP line.

## Deliverables

1. Extend the Idempotence check so a record whose latest backlog-refine decision comment is resolved (`keep` or `build it myself`), and whose body and labels have not changed since that resolution, is not re-refused. Render it as one annotation line under the Needs-decision lane (e.g. `#N — refusal resolved {choice} on {date}; not re-asked`) and write nothing.
2. A body or label change after the resolution (a re-shape, a new `risk:*`/`size:*`) re-opens the record for grant-check, as today.
3. Apply the same rule on `refine-headless.md`'s gate-4 refusal path, which reaches the identical `needs:decision` outcome.

## Acceptance Criteria

- A fixture with a resolved `keep` backlog-refine comment and an unchanged body renders the annotation and produces no `needs:decision` action.
- The same fixture with a body edit after the resolution goes through grant-check and can be stamped again.
- `npm test` passes.

## Release Note

Backlog refine no longer re-asks a grant decision you already resolved, unless the record has changed since.
