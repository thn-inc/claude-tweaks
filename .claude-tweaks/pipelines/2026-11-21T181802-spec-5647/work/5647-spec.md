# 5647: Attribute dispatched runs' subagent transcripts to timing.json token totals

Origin: reflect full from #5555

Defer-reason: tangential

## Current State

timing.json at run close (#5555) attributes token totals only from the run worktree's own-slug transcript (plugin/bin/lib/timing/at-close.js, "{configDir}/projects/{slug of the run's worktree}/{sessionId}.jsonl"). A replay over the 94 closed runs without timing.json found 92 with a worktree, 20 with an own-slug transcript, and 73 where the session transcript sits only under the main checkout slug (dispatched runs: their Task-call subagent transcripts live under that session's subagents dir). Evidence: the #5555 run dir evidence/dispatched-slug-check.txt ({"closedNoTiming":94,"withWorktree":92,"ownSlug":20,"anyHit":93,"hitButNotOwn":73}). Those 73 runs get phase rows but no token totals.

## Deliverables

Decide whether a dispatched run's own subagent transcripts may be attributed by the run id they name (the tools/guard-refusals/transcripts.js rule), and if so widen the at-close transcript resolver accordingly, with tests, updating the own-slug-only contract the #5555 spec fixed in AC9.

## Acceptance Criteria

For a dispatched run whose session transcript sits only under the main checkout slug, timing.json carries token totals attributed from the transcripts that name the run id, and a run whose transcripts name a different run id gets none.

## Plan Review Clarifications

- Decided by the user at plan review: a dispatched run's `timing.json` token totals count its own-slug transcript (when one exists) plus the dispatching and resuming sessions' depth-1 Task-call transcripts whose dispatch prompt names exactly its run id — the two are separate files, so nothing is counted twice. Readings not taken: an own-slug hit used alone, with Task calls read only when it is missing; the union only when a human resumed (`sessionId` differs from `dispatchSessionId`).

## Build Deviations

- Beneficial (Common Step 4.5): the Task-call lookup runs for a dispatched run even when `run-state.json` carries no `worktree` and no `worktreeAtClose`, or no `sessionId` — only the own-slug lookup needs those. Why: 285 of 687 dispatched Oct-Nov runs close with neither worktree field, and without this AC1.1 failed for 5 of 8 replayed October runs. Non-dispatched runs keep the early return.
