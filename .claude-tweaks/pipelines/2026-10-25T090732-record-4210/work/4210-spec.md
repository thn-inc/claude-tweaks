# 4210: Resolve a redirect glued to a word that holds a quoted span or a subshell in the worktree-always scan (echo "hi">x)

Origin: ledger resolve gate (run 2026-10-24T200414-record-4015, refs #4015)

Defer-reason: genuinely-larger

## Current State

#4015 made `plugin/bin/lib/hooks/git-command.js`'s `redirectWriteTargets` resolve a redirect glued to a preceding bare word (`echo foo>x`). The glued branch is eligible only when the whole token is unquoted, because `tokenize` carries one `singleQuoted` and one `doubleQuoted` flag per merged token. A token assembled from a quoted span plus a bare tail therefore never qualifies: `echo "hi">x`, `printf "%s\n" "$v">out.txt` and `echo foo>"x y"` all resolve no write target, and the `worktree-always` gate lets the write through.

The same branch also excludes `(` from the word before the `>` (bash arithmetic such as `((i>0))`). That drops a redirect after a one-word subshell or a process substitution: `(ls)>out`, `$(date)>x`, `diff <(a) <(b)>out`.

Both gaps fail open, the safe direction, and #4015's final whole-branch review asked for a follow-up record. `echo "hi">x` is a likely agent-written shape. The fix needs a tokenizer representation change: `tokenize` has to say which merged pieces were bare, so the glued scan can run on the bare tail without trusting a quoted `>`. That change reaches every parser that reads tokens.

## Deliverables

- [ ] Make `tokenize` record, per merged token, which spans were bare (unquoted), and run the glued-redirect scan on a bare span that holds a `>`, so `echo "hi">x`, `printf "%s\n" "$v">out.txt` and `echo foo>"x y"` resolve their targets.
- [ ] Keep every quoted `>` literal: `echo "foo>x"`, `echo 'foo>x'`, `echo foo">"x` and `node -e "x>y"` still resolve no target.
- [ ] Resolve a redirect after a balanced one-word subshell or process substitution (`(ls)>out`, `diff <(a) <(b)>out`) while `((i>0))` and `(( x>y ))` stay target-free.
- [ ] Mirror the change in `plugin/bin/lib/hooks/bash-prefilter.js`'s `hasFileRedirection` (it shares the parser), add the shapes to the differential corpus in `tests/hooks-bash-prefilter.test.js`, and update the shape list in `plugin/skills/_shared/policy-schema-coverage.md` and the gaps step of `docs/journeys/write-a-glued-redirect-from-the-main-checkout-4015.md`.

## Acceptance Criteria

`fileWriteTargets('echo "hi">x', cwd)` resolves `x`, and `'echo "foo>x"'` and `"echo 'foo>x'"` resolve nothing; `tests/hooks-gate-coverage.test.js` pins both and goes red when the change is reverted.

## Build deviations (Beneficial, Common Step 4.5)

- The per-span record is a per-character `spanKinds` mask (`b`/`e`/`s`/`d`/`x`). `tokenize`'s bare runs now stop at a quote, and double quotes are backslash-aware, so every token-reading parser sees bash's word merge (`cd foo"bar"` is `cd foobar`).
- The start-anchored scan also reads its operator on the raw token and requires a bare operator. A quoted leading `>` (`echo ">x"`, `--body "> quoted reply"`) and a `$VAR` that expands to `>x` are no longer targets. This is Deliverable 2's "every quoted `>`" read literally.
- The redirect scan tracks `"$( … )"` / `"${ … }"` / backtick nesting across every segment of a command. A `>` in that nested quoting context resolves no target, which keeps the never-fabricate posture once the new tokenizer splits inner quotes.
- An escaped character before a glued `>` (`foo\ bar>out.txt`) is accepted.
