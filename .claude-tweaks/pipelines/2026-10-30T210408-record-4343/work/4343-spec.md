# 4343: Catch the run branch up with the integration branch before build's final verification, not after it

Origin: speed analysis of the #4026 dispatch (run 2026-10-25T132807-record-4026)

Defer-reason: tangential

## Current State

`plugin/skills/build/SKILL.md` Common Step 5 (Final Verification) runs the full suite first. The build phase exit (`phase-exit.js`) then pushes and runs the Post-push merge-state check (`_shared/git-discipline.md`, "### Post-push merge-state check"). Only at that point does a DIRTY or BEHIND PR get its catch-up merge of the integration branch.

That merge changes the tree, so `/test` Step 1 (`plugin/skills/test/verification.md`, Skip-if-recent, Mismatch branch) re-runs verification. A catch-up merge is never a bookkeeping-only delta, so the suite runs a second time.

Observed 2026-10-25 on #4026 (run `2026-10-25T132807-record-4026`, PR #4277): Common Step 5 passed at `d99fc7da2` at 18:20 after 55 min. The merge-state check found PR #4277 DIRTY at 18:21, because origin/main had moved during the 4-hour build. The catch-up merge resolved 3 conflicts (`d99fc7da2` -> `622a5adf8`) at 18:27. `/test` then re-ran the full suite at `622a5adf8` until 20:01 (1h34). One of the two full runs was avoidable.

## Deliverables

- Before Common Step 5 runs its suite, build fetches the integration branch. When the run branch is behind it, build applies the existing Catch-up (`auto`) procedure from `_shared/git-discipline.md` (merge, never rebase, with the same conflict-resolution and `merge --abort` rules), so the verified tree already contains the current base.

- The pre-verification catch-up logs one `decisions.md` line naming the before and after SHAs, or a `SKIP` line when the branch is already current.

- The Post-push merge-state check stays as is. The base can still move during verification, and that residual case keeps today's behavior.

- The prose that describes the ordering (`build/SKILL.md` Common Step 5, `git-discipline.md`'s merge-state section) states the new order.

## Acceptance Criteria

- [ ] A run whose branch is behind the integration branch at Common Step 5 merges it in before the suite runs, and build's `VERIFICATION_SHA` equals the post-merge HEAD.

- [ ] When the base did not move again during verification, `/test` Step 1 takes the Match branch and runs no suite.

- [ ] A branch that is already current logs a `SKIP` and merges nothing.

- [ ] A catch-up conflict that cannot be resolved confidently follows the existing `merge --abort` path, and verification still runs on the un-merged tree.

- [ ] A conformance test pins that Common Step 5's prose places the catch-up before the verification run, and it fails against the current prose.

## Release Note

A pipeline run whose branch fell behind main during the build now merges main in before its final test run, so the full suite runs once instead of twice.

## Technical Approach

### Key Files

- `plugin/skills/build/SKILL.md` — Common Step 5 catches the branch up before running the suite
- `plugin/skills/_shared/git-discipline.md` — Post-push merge-state check section states the new order
- `plugin/skills/test/verification.md` — Skip-if-recent Match branch is the expected path after a pre-verify catch-up
- `plugin/bin/pr-merge-state.js` — reused (or a fetch-and-behind probe) for the pre-verification read
