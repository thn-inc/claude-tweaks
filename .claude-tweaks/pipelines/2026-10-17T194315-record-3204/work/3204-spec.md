# 3204: Flaky-retry's unattributedFailureCount has no accounting guard for the summary family

Origin: #3066 wrap-up Skills curation row, refs #3066

## Current State

`unattributedFailureCount` (`plugin/bin/lib/verify/extract.js`, added by #3066) returns `0`
unconditionally for every family other than `spec`/`tap`: `if (family !== 'spec' && family !== 'tap') return 0;`.
The `flaky-retry` hook in `plugin/bin/verify.js` calls `unattributedFailureCount` to decide
whether `planRetry` may retry the named, allowlisted failing files. `extractFailingFiles` *does*
extract named failing files for the `summary` family (vitest/jest/pytest-style summary-line
output) — `sniffFamily` classifies that output as `summary`, and `extractFailingFiles` has a
`summary`-family branch. So a `summary`-family log with an allowlisted failing file plus an
unattributed failure (one the summary-line extraction could not tie to a file) is retried with
no accounting guard at all — the exact class of bug #3066 closed for `spec` and `tap`.

`baseline.js`'s `adjudicate` (the function #3066's own spec cited as "the same accounting") does
not have this gap: it explicitly refuses ineligibility for `family !== 'spec' && family !== 'tap'`
("output family {family} has no failure-accounting guard") rather than silently treating it as
accounted.

## Deliverables

- [ ] Decide the correct behavior for `unattributedFailureCount` on a `summary`-family log: either
  (a) extend the accounting check to `summary` (needs a `summary`-family analog of the
  entries-vs-counts cross-check extract.js's `parseCounts('summary', ...)` already supports), or
  (b) make the flaky-retry hook refuse to retry a `summary`-family check at all (mirroring
  `adjudicate`'s "no failure-accounting guard" refusal), whichever is the more defensible default.
- [ ] A test pinning whichever behavior is chosen, exercising a `summary`-family log with an
  allowlisted failing file plus an unattributed failure.

## Acceptance Criteria

- [ ] A `summary`-family log, one allowlisted failing file + one failure the summary-line
  extraction could not tie to a file, no longer silently retries and clears the check.
