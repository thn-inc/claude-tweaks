# 2860: Document the multi-spec rule for the PR verdict run-comment — one shared marker per PR

Origin: reflect full (multi-spec batch) from #2633/#2664

## Current State

`_shared/pr-run-comments.md` finds and updates each run-comment kind by a first-line marker (`<!-- run-comment: verdict -->`), one comment per kind per PR. A `/flow` multi-spec run shares one PR across N specs, and each spec's `/review` Step 7 posts a verdict. The documented find-and-update would make spec N's verdict silently overwrite specs 1..N-1's, and the file has no multi-spec rule.

Run 2026-09-30T190052-spec-2633-2664 ruled ad hoc: it kept one cumulative comment with a per-spec section that each spec's review updates in place (`decisions.md`, spec-2633 Step 7).

## Deliverables

1. `_shared/pr-run-comments.md` states the multi-spec rule: one cumulative `verdict` comment per shared PR, with one `### #{n}` section per spec, and each spec's review replacing only its own section.
2. `review/code-mode-steps.md` Step 7 cites it.
3. Add a conformance test pinning the rule's presence.

## Acceptance Criteria

- `pr-run-comments.md` names the multi-spec cumulative-section rule, and Step 7 cites it.
- A conformance test fails when the rule text is removed.
