# 3376: Re-pin superpowers to 7.0.0 and pin the upstream text the dispatch cost-shape changes lean on

Surface: backend

## Overview

Part of the "Build dispatch cost shape" decomposition (origin #3229). The plan-review, per-task-tier and task-merge records lean on specific upstream superpowers text — SDD's pre-flight scan sentence, its Model Selection tier lines, its "Batch small same-shape work" rule and writing-plans' "The implementer writes the body." — and the drift manifest pins none of those lines. Two of them do not exist at all in the version the manifest pins today (6.2.0): "Batch small same-shape work" first appears in 6.3.0 and writing-plans' "writes the body" first appears in 7.0.0 (checked against the local caches 2026-10-17). The manifest's superpowers entry reads only the cached copy whose version equals `pinned`, so adding the new assertions against 6.2.0 would fail immediately, and the version-notice record would never warn a project on 6.3.0.

This record re-pins the superpowers entry to 7.0.0 through the `upstream-repin` project skill — re-verifying every existing superpowers assertion against 7.0.0, one of which is already known to fail there — and then adds one assertion per upstream line the dispatch-cost-shape records depend on, each tied to the claude-tweaks file that relies on it.

**Complexity:** Low-Medium
**Estimated tasks:** 3-4

## Non-Goals

- Changing any claude-tweaks skill prose. Assertions are added; the files they cite are edited by the records that depend on them.
- Pinning other dependencies (Impeccable, code-simplifier).
- Making the version notice for projects on older superpowers; that is a separate record that depends on this one.
- Filing anything upstream with superpowers.
- Certifying that `/build`'s SDD-driving behavior is verified against a major release. The pin means "the literals claude-tweaks acts on exist in 7.0.0", not "behavior verified"; the diff step below is a bounded read, not a behavioral test suite.

## Technical Approach

Follow `.claude/skills/upstream-repin/SKILL.md` step by step; do not improvise a pin edit. The new assertions are the only net-new content, plus the one retarget forced by 7.0.0's brainstorming rewrite. If a dependent record is reshaped or never lands, move the assertion's `file:` to wherever the reliance ended up, or drop the assertion with the record.

## Gotchas

- Tooling under `tools/` is maintainer-side and never ships (`docs/decisions/0015-plugin-payload-boundary-is-the-plugin-subtree.md`); nothing under `plugin/bin/` may import from it. The shipped version-notice record cannot read this manifest and needs its own source for its floor version.
- The superpowers entry's checks run against only the cache copy whose version equals `pinned`, with an exact version match. Re-pin first, then add assertions; the reverse order fails on the lines that do not exist in 6.2.0. A drift run where the 7.0.0 cache is missing reports `skipped`, which verifies nothing — do not read "no breach" as "all literals verified".
- Every literal is matched with `content.includes` on raw bytes. A string that wraps across lines never matches: use the single-line fragments in Current State, and check any further literal with `grep -cF` against the cache before putting it in the manifest.
- The Model Selection text of SDD is byte-identical between 6.3.0 and 7.0.0 (checked 2026-10-17), but verify each existing assertion yourself against 7.0.0 rather than trusting that — the brainstorming assertion proved otherwise.
- Read the pinned version from the installed artifact (`plugin.json`), never from release notes or the marketplace catalog (`[IL-89]`, cited in the manifest header).
- Do not loosen a `must-match` until it matches anything; if a line moved, point the claim at the surviving upstream line or drop the assertion together with the local claim it backed.
- The pin is a verification baseline, not a minimum-version requirement. The exact superpowers version the cost-shape records need differs per line (see Current State's introduction versions); the version-notice record owns what floor it enforces. If a pinned line disappears in a later release, the dependent records must be revisited, not only the assertion retargeted.
- A same-version re-publish replacing bytes under an existing cache directory goes unseen by this tool (the entry's own documented accepted risk) — not in scope here.
- Steering principle for the whole decomposition: claude-tweaks never files upstream with superpowers and never contradicts SDD's text; these assertions exist so that if upstream changes the text the records lean on, drift reports it.
