# 3679: Harden and cover the staged-patch stacked check — 14 follow-ups from #3290's final review

Origin: ledger resolve gate (wrap-up of #3290)

Defer-reason: genuinely-larger

## Current State

#3290 shipped the staged-patch stacked check (`plugin/bin/lib/staged-patch/stack-check.js`, `plugin/bin/check-staged-stack.js`, the console wiring in `plugin/bin/console-resolve.js` and `plugin/bin/lib/console/resolve.js`). Its whole-branch review passed and the build's final review ruled fifteen minor findings ok-to-defer. Together they span six or more files, so no single fix-now pass covers them. They fall in four groups. Robustness: `headerSources` scans the whole patch including the free-text preamble, so a `rename from ../x` preamble line skips the patch and CRLF leaves `\r` in the source name; `isUnsafe` splits on `/` only; `rederive` gives the generic 'not a file in the worktree' reason for a file an earlier patch created; `git merge-file` exit 255 (a git error) is reported as 'conflict in {path}'; the STAGED conflict line names only the first conflict that involves the target. Portability: `defaultGit`'s `GIT_CONFIG_GLOBAL=os.devNull` is unverified on a Windows checkout and needs git 2.32 or newer. Coverage: no committed rename, new-file, deleted-file or binary patch case; untested `rederive` branches (already-satisfied, unsafe or not-in-patches guards, multi-file partial conflict, rename or delete refusal, numstat or summary failure) and untested CLI `rederiveReason` branches; the console's `checkPatchStack` wiring and its throw fail-closed branch have no test; the order-agreement test mirrors `readSnapshot`'s filter and sort instead of calling it; the `cli.test.js` shadow-refusal test asserts a vacuous `existsSync`. Contract pins and docs: `tests/staged-patch-contract.test.js` pins token presence only, not the re-run-once bound or the re-anchor condition, and its go-red control trips only the heading assertion; the `docs/plugin-structure.md` CLI line does not say exit 2 still prints the JSON line. Each item's detail and trigger is in the #3290 run ledger, `docs/plans/2026-10-19-staged-patch-stacked-check-ledger.md`, rows 1-15.

## Deliverables

Scan `headerSources` from the first `diff --git` line only and strip a trailing `\r` from a source name

Make `isUnsafe` reject a `..` segment split on `\` as well as `/`

Give `rederive` a specific refusal reason when the target file is created by an earlier staged patch

Report a `git merge-file` exit above 1 as a git error, not as 'conflict in {path}'

Name every conflict that involves the target in the stacked-check STAGED line, not only the first

Verify `GIT_CONFIG_GLOBAL=os.devNull` on a Windows runner and document or replace the git 2.32 requirement

Add committed `stack-check` cases for rename, new-file, deleted-file and binary patches

Add `rederive` branch tests: already-satisfied, unsafe path, target not in patches, multi-file partial conflict, rename or delete refusal, numstat or summary failure; make the same-anchor rederive test assert the reason, not only `/conflict/`

Add CLI tests for the `rederiveReason` branches: rederive refusal, rederive throw, `--rederive-out` with a non-conflicting target, `conflictsWith` equal to the target

Replace the vacuous shadow-refusal assertion in `tests/bin-lib/staged-patch/cli.test.js` with one that fails when the shadow is written

Test `plugin/bin/console-resolve.js`'s `checkPatchStack` wiring and its throw fail-closed branch

Make the stack-check order-agreement test call `readSnapshot` instead of mirroring its filter and sort

Make `tests/staged-patch-contract.test.js` go red on each assertion it claims, and pin the re-run-once bound and the re-anchor condition

State in `docs/plugin-structure.md` that exit 2 for an unapplicable target still prints the JSON line
