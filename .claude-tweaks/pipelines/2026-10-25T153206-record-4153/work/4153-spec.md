## Architecture Notes (build, Common Step 4.5)

- **Beneficial deviation — the shared probe lives in a leaf module, not `run-liveness/index.js`.** `index.js` transitively requires `hooks/context.js` (through `hooks/run-integrity.js` and `run-liveness/probes.js`), so `context.js` requiring `index.js` would form a cycle and hand one side a partial `module.exports`. `probeOwnerPid` (with `MAX_PID`, `errorMessage`, `call`) moved verbatim into `plugin/bin/lib/run-liveness/owner-pid-probe.js`, which requires nothing; `index.js` and `context.js` both import it. A test pins the requires-nothing property.
- **Deliverable 2 path taken:** the removal condition was recorded (not the reader migration); the migration is tracked by #4318.
- **Two intended behaviour corrections in `refreshOwnerBlock`'s takeover decision** that follow from one judge: a non-string stored `pidStartedAt` now keeps the block (`invalid-start-time`, was read as pid reuse), and a stored pid of 0 / negative / above int32 now allows takeover (`no-pid`, was decided by `isPidAlive`).
