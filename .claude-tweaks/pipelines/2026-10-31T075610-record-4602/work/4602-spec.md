# 4602: Give the below-floor parent close an MCP transport path for gh-absent sandboxes

Origin: spec #4466 review (lenses 3b/3c, tiebreak-confirmed)

Defer-reason: genuinely-larger

## Current State

#4466's below-floor parent close (`plugin/skills/wrap-up/verification-brief-parent-gate.md`'s **Close the parent below the floor**, run post-merge by `_shared/pr-first-merge-post-merge.md` Step 4.0b) only issues `gh` calls: `gh api .../sub_issues`, `gh issue view --json state,comments`, `gh issue comment`, `gh issue close`, and `gh repo view` for the default-branch gate. None of them has a `_shared/github-write-transport.md` MCP mapping.

In a gh-absent sandbox (a cloud Routine with only the `github` MCP server, which detects `local-merge`), `_shared/local-merge-auto-finish.md` runs Step 4.0b and every parent is skipped and reported. Tidy's `parent-gate` backstop can't recover it there either, because `_shared/github-pr-scan-acceptance.md` skips the whole scope when `gh` is unreachable. The parent closes only on a later gh-present tidy run.

`plugin/skills/dispatch/settle-and-merge.md`'s #205 paragraph says every `gh` call the Parent-Gate Procedure makes is one of three standard shapes (`issue_read`, `add_issue_comment`, `issue_write`). The close call and the sub-issue read added since then make that claim stale.

## Deliverables

- [ ] Map the parent close (`gh issue close --reason …` → `issue_write` with state and state reason), the native sub-issue enumeration, and the default-branch read to their MCP equivalents in `_shared/github-write-transport.md`, and cite that mapping from the close section and Step 4.0b.
- [ ] Correct `settle-and-merge.md`'s #205 paragraph so it lists the calls the Parent-Gate Procedure actually makes.

## Acceptance Criteria

- [ ] A gh-absent run that has the GitHub MCP server closes a due below-floor parent through Step 4.0b, posting the same listing comment.
- [ ] Every `gh` call in the Parent-Gate Procedure has an MCP mapping row, or an explicit statement that it fails open.

## Release Note

Cloud Routines without the `gh` CLI now close a decomposed feature's parent once its last low-risk sub-issue merges, the same as local sessions.

### Key Files

- `plugin/skills/_shared/pr-first-merge-post-merge.md` — Step 4.0b
- `plugin/skills/dispatch/settle-and-merge.md` — the #205 blanket-mapping paragraph
