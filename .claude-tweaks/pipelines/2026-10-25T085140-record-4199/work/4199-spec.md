# 4199: pr-first: rewriting Fixes #N to Refs #N before merge does not stop GitHub closing #N — the closing link from the PR's creation persists

Verified-as-of: d36f5f6a54367f74e589527555a81ab403ba3058

Origin: merge of PR #4144 (#3997, #2724)

Defer-reason: tangential

## Current State

- `_shared/pr-checklist-refresh.md`'s pre-merge "Rewrite the `Fixes` block from outcomes" step (#2686, #3136) turns a deferred-closure spec's `Fixes #N` line into `Refs #N — deferred: {reason}` so the merge leaves that record open.
- It does not hold on GitHub. PR #4144 was created with `Fixes #2724` in its body, and the body was rewritten to `Refs #2724 — deferred: …` before merge. At merge `gh pr view 4144 --json closingIssuesReferences` still listed `[2724, 3997]`, and GitHub closed #2724 two seconds after the squash merge (closed event 2026-10-24T18:52:34Z, no commit id). The merge commit message carried only `Fixes #3997`. #2724 was reopened by hand.
- So every bundle run whose PR is born with all `Fixes` lines (`_shared/pr-early-run-lifecycle.md` Step 3) and later defers one closure closes that record anyway.

## Deliverables

1. Before any pr-first merge, read `closingIssuesReferences` and compare it with the issue list the merge is meant to close. When a deferred or not-run record is still linked, unlink it, or reopen it immediately after the merge, and log either outcome. Find the mechanism that actually removes a closing link (body edit timing, the PR Development sidebar, or the GraphQL API) by probing on a throwaway PR first.
2. Alternatively, have `_shared/pr-early-run-lifecycle.md` open a bundle PR with `Refs` lines and add `Fixes` only at the pre-merge refresh, if probing shows GitHub links only at creation.
3. A test of the chosen check against a fake `gh` that returns a stale closing reference.

## Acceptance Criteria

- A bundle run that logs a deferred closure for #N merges without closing #N, verified on a probe PR.
- When the forge still links #N at merge time, the merge step either unlinks it first or reopens it right after, and `decisions.md` records which.
- The new test fails against the pre-change procedure.

## Release Note

A multi-record pipeline run no longer closes a record it deliberately left open when its PR merges.
