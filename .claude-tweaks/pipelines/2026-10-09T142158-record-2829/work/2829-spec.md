# 2829: dispatch queue pull: exclude non-spec-shaped candidates as not-spec-shaped before claiming

Surface: infra

**Related:** #2775

## Current State

`plugin/skills/dispatch/queue-pull-script.md` builds each run's `dispatch-groups.json` and writes `dispatch-exclusions.json` entries (via `plugin/bin/lib/dispatch/exclusions.js`) under the reasons `blocked`, `oversized`, `open-pr`, `target-missing`, and `shipped`. It already holds every candidate's body, but never checks that body's spec shape.

A candidate whose body fails `/flow`'s Materialization hard gate (`shapeGate` in `plugin/bin/lib/issues/materialize-format.js`) is therefore claimed and handed to `/flow`, where it fails. The failure counts against `dispatch-retry-ceiling`, and a `correctness`-classified failure makes Settle revoke `auto:merge`. Evidence from the 2026-09-29 human-typed drain (run `2026-09-29T105522-dispatch-standalone`, reported on #2786): #2663 used attempt 2 of 3, and #2573 used attempt 1 and lost its `auto:merge` grant, both failing at the gate for a missing `## Release Note`. The drain was halted because every remaining group would have failed the same way. A deterministic content defect visible in the cached body was only discovered after a claim.

## Deliverables

1. In the queue-pull script, run `shapeGate` (`require`d from `plugin/bin/lib/issues/materialize-format.js`, never a new copy of the section list) on every otherwise-eligible candidate's cached body, after the existing exclusion passes and before groups are finalized.
   - **Absent, null, or empty body:** `shapeGate` already treats a non-string body as empty, so the candidate is excluded with all four sections missing. That fails closed, which is correct: such a record cannot pass Materialization either.
   - **Pass cannot run at all** (the `require` fails): print a `Warning: not-spec-shaped pass skipped — {error}` line and continue without it. This follows the script's existing degrade-with-warning pattern; `/flow`'s gate remains the backstop.
2. Append each failing candidate to `dispatch-exclusions.json` as `reason: 'not-spec-shaped'`, `detail: { missing: [...] }`, using `shapeGate`'s `missing` array verbatim (section names plus `unresolved-placeholder` when present), through `plugin/bin/lib/dispatch/exclusions.js`'s existing `appendExclusion`. That module has no reason enum: its header states that a new reason is one `appendExclusion` call site plus one report line, so it needs no change.
3. **Remove excluded candidates from `dispatch-groups.json` per member.** Follow the `target-missing` precedent (`g.filter((c) => !groupIsExcluded([c], …))`): a file-overlap group keeps its conforming members and drops only the non-conforming ones, and a group left empty is dropped. Excluded candidates are never claimed, never count against the retry ceiling, and never reach Settle.
4. **No direct-`#N` bypass.** This follows the `open-pr`/`target-missing`/`shipped` precedent, not `oversized`'s. `oversized` lets a human who names a record accept a size risk. A spec-shape failure is not a risk anyone can accept: `/flow`'s Materialization gate would stop the named record anyway, after a claim and a spent retry. A direct `/claude-tweaks:dispatch #{n}` on a non-conforming record therefore excludes it and renders the report.
5. Add a `not-spec-shaped` exclusion report as its own file, following `blocked-exclusion-report.md`/`open-pr-exclusion-report.md`, named `plugin/skills/dispatch/not-spec-shaped-exclusion-report.md`. It lists each excluded record, its missing sections, and one remedy line: `/claude-tweaks:tidy` when the only gap is the Release Note (#2828's Shape 4.5 repairs it in place), `/claude-tweaks:specify #{n}` otherwise. `plugin/skills/dispatch/SKILL.md` gets only a one-line pointer next to the existing report pointers.
6. Update the reason list at the top of `queue-pull-script.md` with the new reason, stating its no-bypass posture the way the `oversized` entry states its bypass.

## Acceptance Criteria

- [ ] With a queue fixture containing one conforming and one non-conforming (`## Release Note` missing) eligible candidate, the queue pull writes exactly one `not-spec-shaped` exclusion, with `detail.missing` equal to `["Release Note"]`, and `dispatch-groups.json` contains only the conforming candidate.
- [ ] A candidate with an unresolved placeholder in authored prose is excluded with `unresolved-placeholder` in `detail.missing`. The same marker inside `## Original request` or a code span is not excluded (`shapeGate`'s existing exemptions).
- [ ] A file-overlap group with one conforming and one non-conforming member keeps the conforming member in `dispatch-groups.json` and excludes only the other. A group whose every member is non-conforming disappears.
- [ ] A direct `#N` invocation naming a non-conforming record excludes it with `not-spec-shaped`, the same as a drain.
- [ ] A candidate with an empty body is excluded with all four sections in `detail.missing`.
- [ ] The exclusion report renders each excluded record number, its missing sections, and the correct remedy line for the two cases.
- [ ] `plugin/bin/lib/dispatch/exclusions.js` is unchanged, and `tests/bin-lib/dispatch/exclusions.test.js` still passes.
- [ ] `plugin/skills/dispatch/SKILL.md` grows by at most one pointer line.

## Release Note

Dispatch now skips records that are not fully shaped instead of claiming them and failing mid-build.

## Technical Approach

Origin: design decision on #2786 (2026-09-29). Parent #2826. The filter itself `require`s `shapeGate` directly, so it needs nothing from #2827 (the shaping-mode fix). It is blocked by #2828 (the `/tidy` repair) because the exclusion report's remedy line points at #2828's Shape 4.5; shipping first would point users at a repair that doesn't exist yet.

Filtering at queue pull turns a deterministic, body-visible defect into a free exclusion instead of a costly `/flow` failure. The gate itself in `/flow` stays as it is, as the backstop for anything that changes between queue pull and materialization.

### Key Files

- `plugin/skills/dispatch/queue-pull-script.md` — the `shapeGate` pass, the exclusion append, and the reason list.
- `plugin/bin/lib/dispatch/exclusions.js` — consumed via `appendExclusion`, not modified.
- `plugin/skills/dispatch/not-spec-shaped-exclusion-report.md` — new report file.
- `plugin/skills/dispatch/SKILL.md` — one pointer line only.
- `plugin/bin/lib/issues/materialize-format.js` — read only (`shapeGate`).
- `tests/bin-lib/dispatch/` — a queue-pull fixture test for the `not-spec-shaped` pass.
