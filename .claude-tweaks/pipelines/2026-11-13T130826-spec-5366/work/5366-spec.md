# 5366: Write the queue-pull parity oracle's gh, git and mktemp shims as sh scripts, so a shimmed call stops costing a node start

**Related:** #5319 (its optional third deliverable moves here), #5227 (built the oracle), #5230 (edits the same oracle file)

## Current State

`tests/bin-lib/dispatch/queue-pull-oracle.js` (#5227) runs `plugin/skills/dispatch/queue-pull-script.md`'s bash fence in a sandbox whose `<root>/bin` holds PATH shims. `writeShims` (`queue-pull-oracle.js:275`) writes `gh`, `git` and `mktemp` as `#!<node>` scripts that `require()` the module and call `shimMain(kind)` (`:886`), so every shimmed call is a node start (about 35 ms on the maintainer Mac) plus, for `git`, a second process: `gitShim` runs the real git through `spawnSync` (`:859`) and waits for it. `bin/node` is a `#!/bin/bash` script (`nodeShim`, `:296`) that logs two CLIs' argv and then execs the real node.

Measured on 2026-11-13 (maintainer Mac, 12 cores, 0% idle, about 37% kernel time): in a 30 s capture, session flow-5230 running `tests/bin-lib/dispatch/queue-pull.test.js` spawned 583 of 1,180 new processes machine-wide, along the chain `node --test -> bash queue-pull-N.sh -> bash -> node -> node -> git`. A counting preload on an earlier run (#5319's Current State) saw 8,539 node starts, of which 2,398 were git-shim and 655 were gh-shim starts; that run took 470 s of wall time (303 s user, 148 s system). Start costs measured on that Mac: node about 35 ms, bash about 13 ms, `/bin/sh` about 9 ms, git about 13 ms.

The shims log to `<root>/logs/gh-argv.jsonl` and `git-argv.jsonl` (`shimLog`, `:793`). Their readers are `collectResult` (`:557`, which feeds `r.ghArgv`/`r.gitArgv` to about 20 assertions in `queue-pull.test.js` reading `tag`, `argv`, `why` and `cwd`), plus four direct reads in the shim go-red tests (`queue-pull.test.js:172`, `:203`, `:236`, `:2787`). No reader uses the `status` field of a `delegated` git entry. Exact-argv gh matching is a plain equality check (`ghAnswer`, `queue-pull-fixtures.js:68`). Graphql matching (a regex on the query plus alias extraction) and `effect` entries (which need the plugin's `sessionTmpRoot`) are the parts that need node.

#5319 (ready) skips this suite from a default local `npm test`, and lists a cheaper shim as an optional extra. #5230 (`bot:in-progress`, PR #5323) edits `queue-pull-oracle.js` (the `MCP_MD` constant and the exports line) and `queue-pull.test.js` (around lines 54, 2521, 2776 and the end of the file). It does not touch the shim functions.

## Deliverables

- [ ] `git` shim as a POSIX `sh` script generated by `writeShims`. It does every check `gitShim` does today, in the same order with the same exit codes and stderr text: refuse on exported `GIT_DIR`/`GIT_WORK_TREE`; parse the leading global options as `gitSubArgv` does (an unknown option is refused before a bad `-c` key); allow only the `core.quotepath` `-c` key, compared case-insensitively; resolve the cwd and each `-C` (chained, as git does) physically and refuse anything outside the sandbox root or unresolvable; answer the table's `gitFail` prefixes with exit 128 and `remote get-url origin` with the canned URL. Otherwise it logs and `exec`s the real git, so a delegated call is one process, not two. Table data (root, real git path, fail prefixes, remote URL) is written into the generated script with `shQuote`, never spliced in unquoted. `setScenario` rewrites the script.
- [ ] `mktemp` shim as a POSIX `sh` script with `mktempShim`'s exact contract: no arguments, `TMPDIR` and `QP_TMPNAME_COUNTER_FILE` required, the counter validated as a non-negative integer, `<TMPDIR>/tmp.qp<8-digit n+1>` created exclusively with mode 0600, the same refusal texts and exit 97.
- [ ] `gh` shim as a POSIX `sh` script that answers every exact-argv table entry without `effect` from precomputed answer files (stdout and stderr byte-exact, `status` as the exit code, tag `ok` or `injected`). Every other call, meaning `api graphql`, entries with `effect`, and any miss, `exec`s a node shim that runs today's `ghShim`, so `ghAnswer` stays the one matcher for those and an unmatched call still exits 97 with `gh-shim: no canned response for: …` and logs `UNHANDLED`. `setScenario` regenerates the answers. The header comment of `queue-pull-fixtures.js` ("the one matcher the PATH shim and fakeRun share") is updated to say which part the sh shim answers.
- [ ] One shim log format that every writer uses and one reader for it. A shell cannot JSON-escape an argv cheaply, so the sh shims (and the node gh fallback) append NUL-separated, count-prefixed records. The JSONL readers move to an exported `readShimLog(logs, kind)` that returns today's objects (`{ tag, argv }` for gh; `{ tag, why?, cwd, argv }` for git) and throws on a malformed or truncated record. `collectResult` and the four direct reads in `queue-pull.test.js` call it. The log files get a non-`.jsonl` name. The `delegated` entry drops `status` (it has no reader; logging it would cost a process per call).
- [ ] `bin/node` (`nodeShim`) moves from `#!/bin/bash` to `#!/bin/sh` if its body is POSIX, which it appears to be.
- [ ] Go-red coverage for the new shims in `queue-pull.test.js`. The three existing shim tests (lines about 142-243) keep passing unchanged except for the log reader. Added: a parity check that for every exact-argv entry of every scenario the sh gh shim's stdout, stderr, exit and tag equal what `ghAnswer` gives; one argv that is a near miss of an exact entry (same words, one argument changed) answered by the node fallback as `UNHANDLED`; a `-C` into a symlink that points outside the sandbox, refused; a mktemp counter-file and refusal check. Each new test is proven by a mutant: break the matching rule in the generated script and watch the test fail.
- [ ] A before/after measurement of `node --test tests/bin-lib/dispatch/queue-pull.test.js` on the same machine, run back to back, quoted in the PR body: node process starts (a counting `--require` preload added to `NODE_OPTIONS`, which `runEnv` already passes through to every sandbox child), shim invocations by kind (from the shim logs), wall time, and user+sys CPU (`/usr/bin/time`). The measurement scripts stay in scratch; they are not committed.

## As-built deviations (build Common Step 4.5, all Beneficial)

- **gh answers are inline in `bin/gh`, not precomputed answer files.** Each exact, effect-free entry is a `case` arm that prints its `shQuote`d stdout and stderr. At the fixture maximum (9.7 KB per answer) a separate file buys nothing measurable and adds a file read per call. An `effect` entry shadows every later entry with the same argv, so those calls stay on the node fallback (`<shimDir>/gh-fallback`), and `ghAnswer` stays their only matcher.
- **`bin/gh` refuses a missing `QP_LOG_DIR` first**, before any answer, so a call can never answer without logging.
- **The git shim refuses more than the node shim did.** On top of the listed checks it refuses `GIT_CONFIG_COUNT`/`GIT_CONFIG_PARAMETERS` (a `-c` allow-list bypass), `GIT_COMMON_DIR`/`GIT_OBJECT_DIRECTORY`/`GIT_ALTERNATE_OBJECT_DIRECTORIES`, a `GIT_INDEX_FILE` outside the sandbox (absolute values normalized lexically, relative values with a `..` segment refused), an unresolvable cwd, and a failed log write. The shim contains *where* git acts, not which programs git may run; `withEscapeGuard` remains the backstop.
- **A `-C` into a file or an unsearchable directory is refused** (exit 97, `unresolvable directory`), where the node shim delegated and git exited 128. Refusing fails closed, and no fence path does this.
- **mktemp adds fail-loud refusals** (`file exists`, `cannot create`, `cannot write counter`, a counter longer than 15 digits) on inputs where the node shim crashed.
