# 3019: design-wrapper pre-build: always-load reference list names files Impeccable 4.5 no longer ships

Surface: infra

## Current State

`plugin/skills/design-wrapper/modes/pre-build.md:32-36` selects which Impeccable reference files a frontend pre-build loads:

- **Always load:** `typography.md`, `color-and-contrast.md`, `spatial-design.md`, `motion-design.md`, `interaction-design.md`, `new-work.md` (`:34`)
- **Conditional:** `responsive-design.md` on breakpoint/mobile/viewport mentions (`:35`), and `ux-writing.md` on copy/microcopy/empty-state mentions (`:36`)

Against the installed Impeccable 4.5.2 (`~/.claude/plugins/cache/impeccable/impeccable/4.5.2/skills/impeccable/reference/`, the latest cached build), only `new-work.md` exists. The other five always-load files and both conditional files are gone, so every frontend pre-build reports up to seven misses and builds its brief from `new-work.md` alone. The reporter saw the same on 4.5.0 (plugin 6.136.0).

Impeccable 4.5 states its own load order in its `SKILL.md`. Line 20 says to load the request's playbook, which is `reference/new-work.md` for a new surface. Line 21 says to read `reference/craft-floor.md` "immediately before any UI edit… It carries the quality floor, the absolute bans, and the reflexes no detector catches." Line 41 points at `reference/operate.md` for deeper Operate/Read guidance. Responsive and copy concerns now live under command playbooks (`adapt.md`, `clarify.md`, `typeset.md`, `layout.md`) rather than standalone topic files.

`tools/upstream-drift/manifest.yml` pins `skills/impeccable/reference/new-work.md` and `document.md` (`:85-87`, `:121-149`), but none of the pre-build always-load names. The drift checker therefore never flagged the five removals.

## Deliverables

1. Replace `pre-build.md`'s always-load set with Impeccable 4.5's own load order: `new-work.md` plus `craft-floor.md`. Add `operate.md` when the record's surface is an Operate or Read surface (dashboard, settings, admin, docs). Cite Impeccable's `SKILL.md` steps 2-3 as the reason, rather than restating its content.
2. Replace the two conditional rules with their 4.5 equivalents (`adapt.md` for responsive/breakpoint mentions, `clarify.md` for copy/microcopy mentions), or drop them, with the reason recorded in `pre-build.md`, when no 4.5 file carries that guidance.
3. Pin every reference file `pre-build.md` names in `tools/upstream-drift/manifest.yml`, so a future Impeccable release that removes or renames one turns the drift check red instead of failing silently at pre-build time.
4. Keep the `missed` reporting (`pre-build.md` Output to caller) unchanged. A missing file is still reported, never silently skipped.

## Acceptance Criteria

- Every reference file name in `pre-build.md`'s selection rules exists in the installed Impeccable 4.5.x `skills/impeccable/reference/` directory. A test or the upstream-drift check asserts this against the manifest's pinned paths.
- `tools/upstream-drift/manifest.yml` lists each of those paths, and its own suite (`tools/upstream-drift/tests/`) passes.
- The terminal-track always-load set (`pre-build.md:27-30`) is unchanged, and `tests/terminal-track.test.js` passes.
- `npm test` passes in full.

## Release Note

Design pre-build loads Impeccable's current craft guidance again, instead of reporting missing reference files and building the brief without it.

## Technical Approach

A prose update to one selection list, backed by drift pins so the next rename is caught mechanically. Deriving the list dynamically from the installed directory was considered and not chosen. A directory listing cannot tell a craft reference from a command playbook, so Impeccable's own documented load order (its `SKILL.md`) is the better source. The manifest pin keeps that choice honest across upgrades.

### Key Files

- `plugin/skills/design-wrapper/modes/pre-build.md` — reference selection rules (`:32-36`)
- `tools/upstream-drift/manifest.yml` — pin each named reference path alongside the existing `new-work.md`/`document.md` pins (`:85-87`)

## Gotchas

- `pre-build.md:38` explains why `new-work.md` stays in the always-load set (its "Decide what is already true" step). Keep that paragraph accurate after the list changes.
- Older Impeccable installs (3.x, 4.0-4.4) carried the old topic files. The new list will report misses there. That is acceptable, since Layer 0's version pin (#2980) governs the supported range, but confirm the pinned minimum is 4.5 or later before dropping the old names.
- `operate.md` is mode-specific guidance. Loading it for every surface would push Operate conventions onto Persuade (landing) surfaces, which Impeccable's `SKILL.md:41` explicitly separates.
