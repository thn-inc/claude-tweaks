## Technical Approach

Three independent items; each is either fixed or dropped with a one-line reason recorded on this record.

1. **Witness rationale.** The death-witness conjunctions live in `gatherEvidence` (`plugin/bin/lib/run-liveness/index.js`, the `witnesses.push('pid' | 'session-end' | 'legacy')` block, currently lines 159-173 — the `:193` citation in Deliverables predates later edits). Add a comment above the `session-end` and `legacy` conjunctions stating why each clause is required (what false-dead verdict each clause prevents), and extend the `LEGACY_DEAD_MS` comment in `constants.js` with why 72h was chosen. Source the rationale from the git history of these lines (`git log -L` on the block) and the records that introduced them (#3973 and its follow-ups) — do not invent a rationale; if none is recoverable, say so in the comment and in the drop/fix note here.
2. **Discarded resume-path probes.** `checkResumeFreshness` (`plugin/bin/lib/hooks/resume-freshness.js`) and `parentLiveDetail` (`plugin/bin/lib/flow/consolidated-pass.js`) call `runLiveness` and then read only the `worktree-lock` and `last-commit` entries through `resumeEntries`/`blocksResume`. Either pass probe overrides that short-circuit the owner-pid, heartbeat, and owner-events probes on these two call sites (via the existing `probes` injection seam), or drop this item with the reason that the cost is bounded and the full evidence array is worth keeping for diagnostics. The `blocksResume` maintainer ruling (owner probes stay informational) must not change either way.
3. **Repeated events.jsonl parses.** `ownEventAt` (`plugin/bin/lib/run-liveness/probes.js`) calls `ownEventRecency` (one `readEventLines`) and then `readEventLines` again for the session-end scan. Fold both scans into a single `readEventLines` pass inside `ownEventAt`, preserving the `readable`/throw semantics and the fallback-attribution and `ownerSessionId` filters exactly. The third parse (`classifyRunDir` in `plugin/bin/lib/reconcile/archive-merged.js` calling `ownEventRecency` before `runVerdict`) may stay — note it in the fix note if it is left as is.

Then append `→ #4560` to each promoted entry line in digest #1426.
