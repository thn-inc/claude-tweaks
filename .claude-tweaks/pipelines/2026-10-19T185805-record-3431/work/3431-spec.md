# 3431: Fix wrap-up-engine plan reading repo facts from the main checkout inside a linked worktree

Verified-as-of: b548e8336d813d90c90bd91d9161eb5d89005766

Origin: reflect light from #3389

Defer-reason: tangential

## Current State

`plugin/bin/wrap-up-engine.js plan` gathers its repo facts (changed files, renamed/deleted paths, journey frontmatter overlap, CLAUDE.md budget) through `resolveRepoRoot()`, which runs `git rev-parse --git-common-dir` and takes its dirname. From a linked worktree that is the MAIN checkout, not the worktree the run is building in, so `git diff {base}...HEAD` runs against the main checkout's HEAD. Observed on run 2026-10-17T183731-record-3389 (worktree `dispatch-record-3389`, a 6-file diff touching `plugin/bin/lib/console/resolve.js`): `gatherFacts` with `cwd` = the worktree returns 6 changed files including `resolve.js`; with `cwd` = the common-dir root it returns 0, and `plan` printed the journeys row with `candidates: []` even though `docs/journeys/resolve-the-unattended-console-in-one-process-1932.md` lists `resolve.js` in its `files:` frontmatter.

The common-dir resolution is deliberate for telemetry (`resolveTelemetryPath` anchors `.claude-tweaks/wrap-up-outcomes.tsv` to the main checkout) and was reused for facts by #3017 to fix the subdirectory-cwd case. The facts read needs the worktree top-level instead. `runVerifyVerb` (around line 517) also calls `resolveRepoRoot`; its `--base` diff has the same exposure. Gates that fall out of the wrong diff (CLAUDE.md Commands renamed, renamed/deleted references, journey overlap) can silently close in worktree runs, which is every `/flow` run.

## Deliverables

- [ ] Resolve a second root for repo facts: `git rev-parse --show-toplevel` from the invocation cwd (the worktree top-level inside a linked worktree, the checkout root otherwise, the subdirectory case still handled). Keep `resolveRepoRoot` (common-dir) only for the telemetry path.

- [ ] Use the top-level for `gatherFacts` and `buildJourneyFrontmatter` in `runPlan`, and audit `runVerifyVerb`'s use for the same exposure.

- [ ] Add a regression test under `tests/` that builds a linked worktree fixture with a changed file named in a journey's `files:` frontmatter and asserts `plan`'s journeys row carries that journey as a candidate (it must fail against the common-dir resolution).

## Acceptance Criteria

- `wrap-up-engine.js plan` run from a linked worktree reports the worktree branch's own changed files, so a journey whose `files:` overlaps the diff appears in the journeys row's `scope.candidates`.

- Telemetry still lands in the main checkout's `.claude-tweaks/wrap-up-outcomes.tsv`.

- The new test goes red when `runPlan` is pointed back at the common-dir root.

## Release Note

Wrap-up's curation plan now reads the branch diff from the worktree it runs in, so journey, reference and CLAUDE.md gates no longer close on an empty diff in worktree runs.
