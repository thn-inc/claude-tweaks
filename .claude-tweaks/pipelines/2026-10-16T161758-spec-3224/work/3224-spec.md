# 3224: Dispatch: run the first /flow call on the Capable profile (+ context-pack item 3 investigation)

Surface: infra

## Overview

`/claude-tweaks:dispatch` runs each group as two Task calls — call 1 is `/claude-tweaks:flow #N build,test`, call 2 is `review,polish,wrap-up`. Across two sessions on 6.140.0, first calls on the template's Standard profile (Sonnet) deviated from `/flow` in 6 of 10 cases; on Capable (Opus), 0 of 3 did (#3212's maintainer decision, 2026-10-16). This unit moves the first call's resolved model from Standard to Capable, states the known ceiling-clamp caveat so the change is never silently inert, adds a per-group resolved-model log instruction, and investigates whether a different part of the same template (context-pack item 3) is itself part of the cause.

**Complexity:** Low
**Estimated tasks:** 4

## Non-Goals

- Changing the second call's (`review,polish,wrap-up`) profile — no second-call deviation has been observed, and the design decision (#3212) scopes the profile change to the first call only.
- Building the dispatcher-bound run / commit gate (a separate sub-issue of this same decomposition).
- Building the `checkFirstCallArtifacts` repair classification or the two-call-gate repair branch (a separate sub-issue of this same decomposition).
- Changing `/flow`'s own Manifesto computation — out of scope per the design doc; a `/flow`-internal root cause, if the investigation below finds one, is filed separately.

## Technical Approach

Neither edit changes `/flow`'s own behavior or the SECOND call. The investigation deliverable is evidence-gathering plus, conditionally, a third text edit to the same file's context-pack item 3 — its outcome (reword vs. negative finding) is recorded either way, so this unit cannot complete silently.

## Gotchas

- #3212's own evidence: Sonnet first calls deviated in 6 of 10 cases across two sessions; Opus 0 of 3. Two stopped-but-complete builds (#3138, #3126) merged clean after a hand review — cite this, don't re-derive a new sample. This is a small, opportunistic sample, not a controlled experiment — state that plainly rather than treating the ratio as proven causation, and leave a trigger to re-measure the deviation rate after a further batch of dispatch firings runs on Capable.
- A `model-ceiling: standard` project policy clamps `Capable` back to `sonnet` (`profiles.js`'s `resolve()` function, lines 122-124, `source: 'ceiling'`) — the template's caveat must say this explicitly; do not assume `Capable` always resolves to Opus.
- `profiles.js:155-180`'s diff-facts cap only fires when the caller passes `--diff-facts`; dispatch's first-call invocation does not pass it, so no caveat is needed for that cap specifically.
- This unit never weighs the cost/latency delta of running every first call on Capable (Opus) instead of Standard (Sonnet) against the measured reliability gain — state in the PR description that the added spend is accepted as the cost of fewer stranded builds; no monitoring deliverable is added here, since the design doc scopes this decomposition to the fix itself, not an ongoing cost dashboard.
- "The firing's `decisions.md`" means the run directory this dispatch invocation is actually operating within — the same `$GROUP_RUN_DIR`/run-dir resolution dispatch Step 5 already uses (`_shared/pipeline-run-dir.md`), not a separate or global log.
- `ASSUMPTION — verify at build: the deviating runs' transcripts (#3070, #3062, #3111, #3129, #3126, #3138) are still retrievable (via session-transcript lookup or stored run artifacts) — via checking each session's transcript path before concluding the investigation item either way; a transcript that has already rotated out means a negative finding by unavailability, not by content, and the PR description must say which case applies.`
- `plugin/skills/dispatch/SKILL.md` is already 46,054 bytes, over the 45 KB advisory ceiling — none of this unit's new text goes there; all of it belongs in `task-prompt.md`.
