# 3153: verify.js --baseline adjudicator: nested-subprocess TAP output fabricates attributable failing files

Surface: infra

**Related:** #3156, #3164, #3179, #3189, #3066, #3129

## Current State

`plugin/bin/verify.js --baseline origin/main --baseline-cmd tests="node --test {file}"`, run against a clean, unrelated diff (the #3136 build touched only `plugin/bin/lib/flow/manifest.js`, two `_shared/*.md` files and three test files), returned `verdict: "fail"` with 7 "attributable" entries — none of them new failures:

1. `tests/bin-lib/verify/cli.test.js` and `tests/bin-lib/wrap-up/engine-verify.test.js` fail identically on a clean `origin/main` checkout (confirmed in a detached scratch worktree: 4/86 and 1/98 failing), yet the adjudicator classified both `attributable` rather than `baseline`. Both files' fixtures involve real subprocess/mtime timing, so the *specific* failing sub-test differs between the base and HEAD isolation runs and the strict by-test-identity comparison never matches.
2. The other 5 entries are fabricated: `/private/var/folders/.../verify-cli-test-*/tests/env.test.js`-shaped paths. `cli.test.js` spawns `verify.js` as a subprocess against temp-sandbox fixtures it `mkdtemp`s per run; their nested TAP output (`not ok 1 - env`, …) leaks into the outer log, and the failing-file extraction in `plugin/bin/lib/verify/extract.js` picks those temp paths up as if they were repo test files. A fresh temp path can never match anything at base, so these read `attributable` regardless of whether `cli.test.js`'s real assertions regressed.

Effect: the baseline-adjudication pass stamp cannot clear for this suite at all, so every `/build`/`/test` run against this repo hits the same false `fail` and falls back to the hand-run by-file diff (`test/verification.md`'s "Isolating pre-existing failures by file").

## Deliverables

- [ ] The baseline adjudicator's failing-file extraction (`plugin/bin/lib/verify/extract.js`, consumed by `plugin/bin/lib/verify/baseline.js`) never reports a path from a nested TAP document that a test itself spawned — either by scoping extraction to the outermost TAP document (indentation-nested `not ok` lines are not top-level failing files), or, at minimum, by dropping extracted paths that do not exist in the checkout under test.
- [ ] The nondeterminism in `tests/bin-lib/wrap-up/engine-verify.test.js`'s `AC1 (live git)` test (plans-ledger ownership classification depends on mtime/birthtime ordering between a just-written file and a just-created temp dir; a tie under load flips `fail` to `skip`) and in `tests/bin-lib/verify/cli.test.js`'s `--baseline` scenario tests is either fixed, or each file is recorded as a known-flaky entry in `.claude-tweaks/verify-scope.json`'s `flaky.files` with the reason.
- [ ] A unit test in `tests/bin-lib/verify/extract.test.js` feeds an outer TAP log containing an indented nested `not ok` block with a temp-dir path and asserts that path is not extracted as a failing file.

## Acceptance Criteria

- [ ] Running `bin/verify.js --baseline origin/main --baseline-cmd tests="node --test {file}"` against a diff that does not touch `cli.test.js` or `engine-verify.test.js` reports neither file (nor any temp-dir path) as `attributable`, and `report.json.baselineAdjudicated.verdict` is `"pass"`.
- [ ] The new `extract.test.js` case fails against the pre-change extraction and passes after it.
- [ ] No path absent from the checkout ever appears in an adjudicator `attributable` entry.

## Release Note

Baseline test adjudication no longer reports phantom failures from test fixtures that spawn their own test runs.

## Technical Approach

Fix the extraction first: it is the deterministic half. In `extract.js`, distinguish top-level TAP lines from indentation-nested subtest/subprocess output when collecting failing files, and add an existence filter on extracted paths relative to the checkout as a backstop. Then address the two flaky files: prefer a real fix to the mtime-ordering race in `engine-verify.test.js` (an explicit ordering or injected clock), and fall back to a documented `flaky.files` entry only where the race cannot be removed cleanly.

### Key Files

- `plugin/bin/lib/verify/extract.js` — failing-file extraction ignores nested TAP documents / non-existent paths
- `plugin/bin/lib/verify/baseline.js` — consumer of the extraction; confirm adjudication reads the filtered set
- `tests/bin-lib/verify/extract.test.js` — new nested-TAP regression case
- `tests/bin-lib/wrap-up/engine-verify.test.js` — fix or allowlist the AC1 mtime race
- `tests/bin-lib/verify/cli.test.js` — fix or allowlist the `--baseline` scenario flakiness
- `.claude-tweaks/verify-scope.json` — `flaky.files` entries, only if a race is allowlisted rather than fixed

## Gotchas

- Several sibling captures from the same session describe overlapping symptoms of this adjudicator (#3156, #3164, #3179, and the ready #3189 for space-containing paths). Check them before building so one change does not leave the others half-fixed or duplicated.
- `node --test` nests subtest output by indentation; a naive "ignore indented lines" rule would also drop legitimate nested subtest failures inside a real repo test file. The rule must separate a spawned child process's TAP stream from the outer file's own nested subtests.
