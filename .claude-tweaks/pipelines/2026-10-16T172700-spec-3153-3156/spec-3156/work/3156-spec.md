# 3156: verify.js --baseline adjudication silently misattributes in nested-worktree sessions

Surface: infra

**Related:** #3189, #3153

## Current State

`plugin/bin/lib/verify/baseline.js`'s `--baseline` adjudication (#3043) is supposed to classify each failing test file against a scratch checkout of the baseline ref as `baseline` / `flaky` / `attributable`. Observed during `#3110`'s `/claude-tweaks:flow review` re-verify step (worktree `.claude/worktrees/dispatch-record-3110`, repo at `/Users/thomasholknielsen/Code Workspaces/claude-tweaks` — note the space in the path):

```
node plugin/bin/verify.js --run "$PIPELINE_RUN_DIR" --cmd tests="npm test" \
  --cmd-env tests=CT_HOOKS_GIT_TIMEOUT_MS=60000 \
  --baseline origin/main --baseline-cmd tests="node --test {file}"
```

returned `verdict: "fail"` with `baselineIsolated: {}` (empty) for all 9 failing files, including files byte-identical between `origin/main` and `HEAD` — meaning the scratch-worktree base-vs-HEAD comparison never actually ran/produced evidence for any file, and every one fell through to the `attributable` catch-all (`report.json`'s own `baselineAdjudicated.attributable` lists all 9 failing files, `baselineFailing: []`, `flakyPassed: []`). The runner's own stdout also printed truncated `ATTRIBUTABLE:` paths missing the `/Users/thomasholknielsen/Code ` prefix (e.g. `Workspaces/claude-tweaks/.claude/worktrees/dispatch-record-3110/tests/bin-lib/gif/palette.test.js`), suggesting a naive path-prefix-strip that doesn't account for a space in the repo path.

This defeats the whole purpose of #3043 precisely in the `/flow`/`/dispatch` worktree sessions it was built for: a failing run inside a worktree checkout can never get credit for a pre-existing/environment-sensitive failure, because the adjudicator silently produces no comparison evidence instead of either comparing correctly or reporting `Baseline: not adjudicated — {reason}` (the documented fail path in `skills/test/verification.md`'s Baseline adjudication section).

## Deliverables

- Reproduce with a minimal fixture: (a) a `tmpGitRepo()`-style fixture nested inside an already-existing worktree session, and (b) a repo path containing a space, to isolate which of the two suspected causes (nested-worktree creation silently failing, or space-in-path handling) is responsible — possibly both.
- Fix `plugin/bin/lib/verify/baseline.js`'s scratch-worktree setup and/or path handling so it either produces real per-file evidence or explicitly reports `Baseline: not adjudicated — {reason}` per `skills/test/verification.md`'s documented fail-path vocabulary — it must never silently fall through to `attributable` with an empty `baselineIsolated`.
- Add a regression test in `tests/bin-lib/verify/` covering the reproduced scenario(s).

## Acceptance Criteria

- [ ] `--baseline` run from inside an already-nested worktree, on a repo path containing a space, against a file byte-identical to the baseline ref, classifies that file as `baseline` (or reports a named `not adjudicated` reason) — never silently `attributable` with empty `baselineIsolated`.
- [ ] A new test in `tests/bin-lib/verify/` pins this.

## Release Note

No user-visible change yet — this is an internal CI/test-tooling correctness fix for dispatch/flow worktree sessions.

## Technical Approach

Reproduce first with two fixtures (a nested-worktree session; a repo path containing a space) to pin which cause empties baselineIsolated. Then fix the scratch-worktree setup or path handling in baseline.js, and make an empty isolation result fail closed with a named not-adjudicated reason instead of falling through to attributable.

### Key Files

- `plugin/bin/lib/verify/baseline.js` — scratch-worktree setup, path handling, fail-closed on empty isolation
- `plugin/bin/lib/verify/extract.js` — failing-file path extraction (space truncation, shared with #3189)
- `tests/bin-lib/verify/baseline.test.js` — regression fixtures for the reproduced scenario(s)
