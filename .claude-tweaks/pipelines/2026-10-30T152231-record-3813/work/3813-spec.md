## Technical Approach

The root cause is the merge's position, not any one action, so the fix moves the merge rather than chasing each residue item into the console. Adding console steps for reference repairs, genre conventions, and cleanup items 1/3/5 would fix today's inventory, but every future execution-step action would reopen the gap. With one finish point after the last tree writer, new actions are covered by default.

Suggested shape (the builder may choose another that meets the constraints): console steps 1-12 unchanged; step 13 becomes "item 2 + push" only (or folds into the execution step); the execution step runs its tree-changing work, commits, and pushes; then a single Branch finish step runs `_shared/pr-first-merge.md` (or leave-open), then cleanup items 4, 6, 7, 8. When the execution step is skipped, the Branch finish step still runs straight after the console.
