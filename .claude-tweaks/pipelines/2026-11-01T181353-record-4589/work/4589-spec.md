# 4589: Render dispatch Task prompts from a CLI instead of hand-substituting task-prompt.md

Origin: session 2026-10-30, resumed #3903 build (PR #4541, run 2026-10-30T063836-record-3903)

Defer-reason: tangential

**Related:** #4588

## Current State

`plugin/skills/dispatch/task-prompt.md` is about 48 KB. Its Step 5 instructions require the dispatching session to copy each fenced template verbatim and substitute `{issue list}`, `{minted-run-dir}`, `{plugin-root}`, `{context-pack}` (eight items, three resolved by CLIs) and `[Use: …]` by hand. One #3903 resume needed three such prompts of about 10 KB each (first call, second call, handoff continuation). Hand substitution let small drift in: context-pack items were condensed rather than copied, and `Selected at:` was written as free text. Nothing checks a dispatched prompt against the template.

## Deliverables

1. A `plugin/bin/` CLI (e.g. `dispatch-prompt.js --call first|second|continuation --run {run-dir} --issues N[,M] [--next-steps …] [--headless]`) that resolves the context pack (plugin root, policy values, profile, Selected-at), fills the template from `task-prompt.md`'s fenced blocks, and prints the finished prompt or writes it to a file.
2. `task-prompt.md`/`SKILL.md` Step 5 point the dispatching session at the CLI; the fenced blocks stay the single source the CLI reads.
3. A test that the rendered prompt contains every fixed sentence of its template and no unsubstituted `{…}` placeholder.

## Acceptance Criteria

- [ ] A dispatch firing builds each of `task-prompt.md`'s first, second and continuation prompts with one CLI call and no manual placeholder substitution. The express-lane prompt is out of scope (#4735).
- [ ] A non-zero `dispatch-prompt.js` exit blocks the group: it takes `two-call-gate.md`'s terminal path, and the prompt is never filled by hand.
- [ ] Editing a sentence in a `task-prompt.md` fenced block changes the CLI's output with no code change.
- [ ] The test fails when a placeholder is left unsubstituted.
- [ ] A `Task()` prompt that differs from the CLI's rendered file, or is missing its marker, is denied before the agent starts.

## Decisions

Decided 2026-10-31 on the plan-review questions (issuecomment-6521814313):

1. **CLI failure:** reading A. A non-zero `dispatch-prompt.js` exit blocks the group through `two-call-gate.md`'s terminal path; there is no hand-substitution fallback, since that would reintroduce what AC1 removes.
2. **Express-lane prompt:** reading B. AC1 covers `task-prompt.md`'s first, second and continuation prompts only; `express-prompt.md` is a follow-up (#4735), since `express-lane` resolves `false` in this repo.

Decided 2026-11-01 on the plan-review question (issuecomment-6555127850):

3. **Prompt fidelity:** reading B. Each dispatched first, second and continuation `Task()` prompt must equal the file `dispatch-prompt.js` rendered, byte for byte. A PreToolUse hook on the `Agent` tool compares the prompt against the rendered file, or a hash the CLI writes, and denies a mismatch. It also denies a prompt from the bound dispatch session that names the group's run directory but lacks the CLI's marker. A denied call is resent from the file unchanged and is never edited by hand. Before relying on it, the plan verifies that PreToolUse fires for `Agent` calls with `tool_input.prompt`, and whether older Claude Code versions name the tool `Task`.

No user-visible change: dispatched build agents receive prompts generated from the template rather than hand-copied.
