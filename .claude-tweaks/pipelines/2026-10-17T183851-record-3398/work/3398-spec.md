# 3398: review lens anchor rule: weak-assertion findings split across test and production lines, defeating reproduction pairing

Origin: reflect full from #3351

Defer-reason: tangential

## Current State

`plugin/skills/review/step3-lens-dispatch.md` tells every lens agent where to anchor a test-related finding. A coverage gap ("a missing test, a weak test, a missing assertion, or insufficient case coverage") anchors at the production line. A test-quality defect ("refactor-coupled, non-discriminating, or polluting shared state") anchors at the test line. The same rule is restated in lens 3f's bullet list.

The two categories overlap. An assertion too loose to catch the regression it was written for is both "a weak test / missing assertion" and "non-discriminating". The two agents of a reproduction pair can each pick a different category for one finding and anchor it on different files. `categorise-reproduction` then pairs on `path` exactly, so the shared finding drops to `unconfirmed` on both sides.

Observed in #3351's review (run 2026-10-17T095806-spec-3351). Lens 3f agent A anchored the AC6.1 regex gap at `tests/multispec-preflight-failure-conformance.test.js:22`, and agent B anchored it at `plugin/skills/flow/multispec-preflight-failure.md:9`. The same split happened on the AC3.1 waves gap (test:652 vs `plugin/bin/preflight-records.js:236`). Both were real, and both carried mutation-run evidence on each side. Only the reviewer's manual direct-verification override kept them from being staged as low-confidence noise. At an unattended run with no override, two genuine medium findings would have bypassed Step 3 Routing.

## Deliverables

- Make the anchor rule unambiguous for the overlap case: one rule for "an existing test whose assertions cannot catch the regression", naming a single anchor (the production line the test should pin), and remove "non-discriminating" from the test-line list or redefine it so it cannot also describe a weak assertion.
- Apply the same wording to lens 3f's bullet in the same file, so the two restatements agree.

## Acceptance Criteria

- [ ] `step3-lens-dispatch.md`'s anchor rule classifies every test-related finding into exactly one anchor; no listed term appears in both the production-line and test-line lists, and "an assertion too weak to catch its regression" names one anchor.
- [ ] A conformance test pins the rule: the production-line list and the test-line list share no term, and the dispatch-prompt instruction text and lens 3f's bullet state the same anchor for that case.

## Release Note

Review lens agents now anchor a weak or non-discriminating test finding at one agreed location, so a real test-quality finding both agents report is no longer dropped to low-confidence.
