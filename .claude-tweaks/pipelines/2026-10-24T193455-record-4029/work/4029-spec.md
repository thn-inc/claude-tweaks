# 4029: Track turn classes, context size and ceremony share per run, and flag budget regressions

Evidence: 14-day transcript analysis of this repo (176 main sessions, 5,599 subagent transcripts, 132 archived timing.json files, ~286k tool calls), 2026-10-24.

## Current State

timing.json records minutes, tokens, procedureBytes and toolRoundTrips per phase, but not what the turns were spent on, the context size per turn, the model mix, or any budget. Median procedureBytes grew ~4× in six weeks without anything noticing, and this analysis needed ad hoc scripts over 10 GB of transcripts.

## Deliverables

1. `phase-timing.js` adds per-phase turn-class counts (productive edit/read/explore, procedure read, bookkeeping, orientation, verify, guard refusal), context-per-turn p50/p90, model mix, and subagent count.
2. Per-ceremony-profile budgets in policy (round trips, procedureBytes, verify minutes), checked at wrap-up; a breach stages a finding for the Review Console.
3. A `tools/` cross-run report giving weekly medians from the archive.

## Acceptance Criteria

- [ ] timing.json for a fixture run carries the class breakdown, matching a hand count of that fixture.
- [ ] A budget-breach fixture produces a staged item.
- [ ] The cross-run report reproduces this analysis's headline medians (79 min, 407 round trips) on the current archive.

## Release Note

Each run reports where its turns went, and the Review Console flags runs that blow their efficiency budget.

## Build notes — architecture alignment (Beneficial, kept as built)

1. **Two extra turn classes.** The class set adds `dispatch` (Agent/Task calls, which is also the subagent count) and `other` (everything unclassified). Classes count tool calls, not round trips, so with these two buckets every call lands somewhere and a batched user row counts each of its calls.
2. **Six flat policy keys.** The budgets are six flat `-ceiling` integers rather than one nested block: `{fast-lane|standard}-run-{round-trip|procedure-kb|verify-minutes}-ceiling`. This follows the flat policy-key naming rule, and `0` disables a budget. Defaults are the archive p90, rounded up.
3. **Check behind a flag.** The wrap-up check is `phase-timing.js --check-budgets`, which wrap-up Phase 3 runs before the Review Console.
4. **One record per profile.** A breach stages a Queue-writes record proposal with a stable per-profile title and the work-fingerprint `efficiency-budget:{profile}`. When an open record already carries that fingerprint, nothing is staged and an AUTO line names it. This keeps p90 ceilings, which by design breach about 1 run in 5, from filing one record per run.
5. **Degraded checks still log.** A degraded check writes its own SKIP line: an unstaged breach, or metrics left unmeasured.
6. **Multi-spec stages once.** A multi-spec run stages one item in the parent run dir.
7. **The report reads the archive in place.** It reads `{archive}/{run-id}/timing.json` only. The AC3 medians (79 / 407) reproduce on the analysis's 143-run archive; on today's 146 runs they read 78 / 403.
