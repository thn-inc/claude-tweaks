# 3333: wrap-up: spec-qualify the brief PR run comment under multi-spec

Origin: ledger resolve gate

Defer-reason: genuinely-larger

## Current State

Under pr-first, `wrap-up/verification-brief.md` Step 4 posts each above-floor record's Verification Brief to the run's PR as the `brief` run comment (`<!-- run-comment: brief -->`, `_shared/pr-run-comments.md`). The marker is not spec-qualified. In a multi-spec `/claude-tweaks:flow` bundle, every spec shares one PR, so the second above-floor spec's brief finds and overwrites the first one's. `verdict` and, since #2821, `try-it` already take a `:{spec}` suffix under multi-spec.

Two readers depend on the unqualified marker. `bin/lib/wrap-up/engine-verify.js`'s acceptance-labeling check reads the `brief` comment to confirm it posted. `/claude-tweaks:demo`'s PR run-comment lookup (`demo/entry-paths.md`, added by #2821) reads it back as the record's brief, so in a bundle it can show a sibling spec's brief. Raised by #2821's whole-branch review (I3); refs #2821.

## Deliverables

1. Post the brief as `<!-- run-comment: brief:{spec} -->` when `$MULTISPEC_PARENT_DIR` is set (`verification-brief.md` Step 4), mirroring the `verdict:{spec}` rule, and add the multi-spec form to `_shared/pr-run-comments.md`'s kinds.

2. Make `engine-verify.js` and `demo/entry-paths.md`'s PR lookup read `brief:{n}` first, then fall back to plain `brief`, so single-spec runs and briefs posted before this change still resolve.

## Acceptance Criteria

- In a two-spec bundle with both specs above the floor, the PR carries two brief comments, one per spec, and neither overwrites the other.

- `/claude-tweaks:demo #N` on a bundled spec renders that spec's own brief.

- A single-spec run still posts and reads the unqualified `brief` marker.

- `npm test` passes, including a test for the `brief:{spec}` marker and the fallback read.

## Release Note

Multi-spec runs no longer overwrite one spec's Verification Brief with another's on the shared PR.
