# 3892: Route sweep-shadow's run-dir containment check through isPathContained

Origin: /review of #3642 (lens 3a, direct-verified by the reviewing agent)

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/bin/lib/hooks/sweep-shadow.js:113-119` decides whether `runDir` sits under the run root with a retyped `runDir.startsWith(rootWithSep)` (`rootWithSep` is `root + path.sep`) and then slices `rel` off by `rootWithSep.length`. That is the hand-rolled idiom `docs/donts.md` [IL-161] bans in favor of `shared-primitives.js`'s `isPathContained`. It is strict and correct on POSIX, but it lacks the win32 casing and drive semantics `isAncestorOrSelf` provides. #3498's conformance scan (`tests/path-containment-conformance.test.js`, `HAND_ROLLED`) only matches a `startsWith(...)` whose argument carries `path.sep` on the same line, so the copy built through the `rootWithSep` variable escapes it. #3642's diff does not touch this file.

## Deliverables

- [ ] Replace the `startsWith(rootWithSep)` guard with `isPathContained(runDir, root)`, deriving `rel` with `path.relative(root, runDir)`.
- [ ] Widen `HAND_ROLLED` in `tests/path-containment-conformance.test.js` (or add a sibling scan) so a `startsWith(<variable built from path.sep>)` containment test is flagged.

## Acceptance Criteria

- [ ] `tests/bin-lib/hooks/sweep-shadow.test.js` passes unmodified.
- [ ] The widened scan fails when the old `rootWithSep` guard is restored.

## Release Note

Internal hardening: the shadow-sweep run-dir check uses the shared path-containment helper.
