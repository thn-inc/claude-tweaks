# 2757: Activity report: /claude-tweaks:activity, a period-scoped what-shipped markdown report with citation-validated narration

Surface: infra

**Related:** #2758 — the feature-walkthrough record from the same djoef-adoption design pass; shares the five docs registration files

## Overview

Add `/claude-tweaks:activity`, a period-scoped "what shipped" report: merged PRs, closed issues, commits, issues raised, reviews given, and what is still in flight, narrated for a human reader and rendered to markdown. Nothing in the plugin answers "what did I ship over the last two weeks" today: `/claude-tweaks:help` Section 2 is *state now*, and `flow/summary-template.md` is *this one run*. Neither aggregates over a period, and neither narrates. The gap matters at exactly the moments a maintainer needs prose rather than state: a retro, a standup, release notes.

The capability is adopted from the `djoef` plugin's `activity-report` skill; the implementation is not (djoef's is Danish-first, GitHub-Enterprise-bound HTML). The one mechanism taken wholesale is the **anti-fabrication rule**: gathering and rendering are two separate programs, the skill writes narration *between* them, and the renderer validates every citation against the gathered facts and drops any that is not present, with a warning. A hallucinated issue number is therefore structurally unpublishable, not merely discouraged. The renderer never trusts the narrative; it trusts `facts.json`, which only `gh` wrote.

**Complexity:** Medium
**Estimated tasks:** 8 (Task 0, gather module, gather CLI, render module, render CLI, skill, registration, tests)

## Non-Goals

- Reporting *how the harness performed* (per-phase timings, token cost, auto-decisions, gate trips). That overlaps `/claude-tweaks:feedback`'s session judge and `_shared/feedback-objectives.md`; two rubrics answering one question is the outcome to avoid. Revisit only if those are retired or merged.
- HTML output. Markdown pastes into a PR comment, a Slack message, or an email, diffs cleanly, and matches the existing `report.md` convention QA runs already use.
- A `since-last` period preset. It needs per-user state outside the repo, and the weekly cadence that would justify it is assumed, not observed. Revisit once explicit periods have been used enough to show the pattern.
- Embedding demo or walkthrough artifacts into the report. The walkthrough skill (see **Related**) produces shareable artifacts; wiring them into this report is a later, deliberate integration.
- Cross-organization aggregation of "everything you touched". The current repo plus explicitly named repos covers the motivating case.
- Multi-host scope. Every `--repo` entry must live on the host `gh` is authenticated to by default (github.com); one actor login is resolved once for the whole run, and a host-qualified name (`ghe.example.com/owner/name`) exits 1. A `gh` authenticated to the wrong account for one named repo surfaces as that repo's per-query `failures[]` entries, not as exit 2.
- Issues the actor closed during triage without being author or assignee. GitHub exposes the closer only through the timeline API; `closed_issues` is defined as "closed in the window, with the actor as author or assignee", and the report footer says so.
- Per-review timestamps. `reviews_given` is a proxy (PRs the actor reviewed whose last update falls in the window); exact review times would cost one `pulls/{n}/reviews` call per PR and are out of scope. The proxy semantics are stated in `gather.js`'s header and the report footer.
- An MCP transport. The gather is `gh`-only, and `gh` absent means stop with the CLI's own message relayed verbatim.

## Technical Approach

Three components with a hard boundary between them, following this repo's deterministic-in-`bin/`, judgment-in-the-skill split:

| Component | Responsibility |
|---|---|
| `activity-gather.js` (+ `lib/activity/gather.js`) | All `gh` calls. Writes `facts.json`. No narration, no judgment. |
| `skills/activity/SKILL.md` | Reads `facts.json`, writes `narratives.json`: the prose, with citations. |
| `activity-render.js` (+ `lib/activity/render.js`) | Validates citations against facts, renders markdown, warns on drops. |

**Queries** (one runner call each, each try/caught independently; `{from}`/`{to}` are ISO dates; `{login}` is the actor; run once per repo in scope):

| facts key | `gh` argv |
|---|---|
| `merged_prs` | `pr list --repo {slug} --state merged --search "author:{login} merged:{from}..{to}" --limit 200 --json number,title,url,mergedAt,additions,deletions,labels` |
| `closed_issues` | `issue list --repo {slug} --state closed --search "closed:{from}..{to}" --limit 200 --json number,title,url,closedAt,labels,author,assignees` then client-side keep where author or an assignee is `{login}`, tagged `role` (`author` wins when both apply) |
| `issues_raised` | `issue list --repo {slug} --state all --search "author:{login} created:{from}..{to}" --limit 200 --json number,title,url,createdAt,state` |
| `commits` | `api repos/{slug}/commits?since={from}T00:00:00Z&until={to}T23:59:59Z&author={login}&per_page=100 --paginate --slurp` (fields: `sha`, `commit.message` first line as `subject`, `commit.author.date`, `html_url`) |
| `reviews_given` | `search prs --repo {slug} --reviewed-by {login} --updated {from}..{to} --limit 200 --json number,title,url,updatedAt,author` then client-side drop PRs authored by `{login}`. Proxy semantics: `--updated` filters on the PR's last update, not the review's own timestamp, so a review on a PR untouched since falls out and an old review on a recently-updated PR falls in; stated in the header and footer |
| `in_flight` | `pr list --repo {slug} --state open --search "author:{login}" --limit 100 --json number,title,url,isDraft,updatedAt` |

`--search`/`search prs` ride GitHub's search index, which lags fresh writes by minutes; that is acceptable for a period report and is stated in `gather.js`'s header and the report footer. Every `gh` call passes an explicit `timeout` (`GH_TIMEOUT_MS = 15000`, wider than the 5 s single-call convention because `--paginate` on commits is a multi-page call; state the reason in a comment beside it).

**Register** changes tone and detail, never facts: `retro` (default) is terse and technical for the person who did the work; `standup` names mechanisms for teammates who know the codebase, refs on everything; `manager` is plain business language with no commit-speak. The default is `retro` rather than djoef's `manager` because the primary reader is the maintainer themselves.

### Data / API Surface

`facts.json` (written by `activity-gather.js`):

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-09-21T10:00:00Z",
  "actor": "login",
  "period": { "from": "2026-09-14", "to": "2026-09-21", "preset": "7d" },
  "repos": ["owner/name"],
  "merged_prs": [{ "repo": "owner/name", "number": 1, "title": "", "url": "", "mergedAt": "", "additions": 0, "deletions": 0, "labels": [] }],
  "closed_issues": [{ "repo": "owner/name", "number": 1, "title": "", "url": "", "closedAt": "", "labels": [], "role": "author|assignee" }],
  "issues_raised": [{ "repo": "owner/name", "number": 1, "title": "", "url": "", "createdAt": "", "state": "OPEN|CLOSED" }],
  "commits": [{ "repo": "owner/name", "sha": "40hex", "subject": "", "date": "", "url": "" }],
  "reviews_given": [{ "repo": "owner/name", "number": 1, "title": "", "url": "", "updatedAt": "" }],
  "in_flight": [{ "repo": "owner/name", "number": 1, "title": "", "url": "", "isDraft": false, "updatedAt": "" }],
  "failures": [{ "query": "merged_prs", "repo": "owner/name", "error": "verbatim gh stderr" }]
}
```

`narratives.json` (written by the skill):

```json
{
  "schemaVersion": 1,
  "register": "retro|standup|manager",
  "sections": [
    { "heading": "Shipped", "items": [{ "text": "…", "refs": ["owner/name#123", "owner/name@abc1234"] }] },
    { "heading": "Reviewed", "items": [] },
    { "heading": "In flight", "items": [] }
  ]
}
```

Citable ref grammar: `{owner/name}#{N}` resolves against the union of `number` over `merged_prs`, `closed_issues`, `issues_raised`, `reviews_given`, `in_flight` for that repo; `{owner/name}@{sha7+}` (at least 7 hex characters) resolves by prefix against `commits[].sha` and must match exactly one commit. Anything else is dropped with the warning. Rendered markdown: `# Activity — {from} to {to} ({register})`, one `## {heading}` per non-empty section with `- {text} ({ref links})` bullets (a ref renders as a markdown link to the fact's `url`), a `## Partial gather` section listing `failures[]` verbatim when non-empty, and a footer with counts plus the three standing caveats (search-index lag; `reviews_given` is an updated-in-window proxy; commits are matched by linked GitHub login, with an explicit note when `commits[]` is empty while other actor arrays are not).

## Gotchas

- `gh search prs --reviewed-by` and `--search "merged:…"` both hit the search index, which lags fresh writes; do not "fix" a missing just-merged PR by switching to whole-repo `--state all` list scans, which would blow the 200-row cap on a busy repo. State the lag in the report footer instead.
- `gh api … --paginate` without `--slurp` emits one JSON array per page back to back; use `--paginate --slurp` (gh 2.40 or newer) and pin the exact argv in the fake-runner test.
- `closed_issues` cannot be filtered to the actor server-side in a way that includes assignees; fetch by `closed:` window and filter client-side, tagging `role` (`author` takes precedence when the actor is both).
- Task 0's live probe is what decides the pinned argv. If the installed `gh` rejects `search prs --updated` as a range, the documented fallback is `search prs --reviewed-by {login} --repo {slug} --limit 200 --json number,title,url,updatedAt,author` followed by a client-side `updatedAt` window filter; if `--repo` scoping on `search prs` is rejected, use the `repo:{slug}` qualifier as a positional query term. Record whichever form landed.
- The renderer must never read `narratives[].text` to *find* refs; refs come only from `refs[]`. A `#123` typed inside `text` is prose, not a citation, and is left as-is. Say this in `render.js`'s header.
- Keep gather and render as two binaries. Collapsing them "for convenience" removes the property that makes citation validation meaningful, since the narrative and the facts would share a program.
- `tests/bin-lib/exit-code-conformance.test.js` fails on any `process.exit(` inside the `require.main === module` guard; set `process.exitCode`.
- Temp files resolve per `_shared/session-tmp-root.md` (`activity-facts.json`, `activity-narratives.json`, `activity-report.md`), never a literal `/tmp/` path.
- `tests/skill-catalog-completeness.test.js` reads the four registration surfaces by directory name; a frontmatter typo cannot hide the skill from it, and forgetting any one of the four fails the suite.
- `tests/bin-lib/skill-audit/anti-patterns.test.js` keeps a live-corpus row-count ledger in its comments for `## Anti-Patterns` tables; if the new SKILL.md ships such a table, update the count and its comment ledger in the same commit.
- Write `narratives.json` with the Write tool, never `echo` (zsh mangles `\n`).
- The save-location question runs even inside a pipeline: the report is user-facing output, not a decision `auto` mode may silence; nothing is committed on the user's behalf in any mode.
- The five docs registration files are also edited by the sibling walkthrough record (see **Related**); expect a trivial merge on them if both build concurrently.

## Decision Rationale

- **"What shipped" over "how the harness performed".** Harness data is genuinely differentiated, but it overlaps `/claude-tweaks:feedback`'s session judge and `_shared/feedback-objectives.md`. "What shipped" has no existing owner at all.
- **Markdown over djoef's HTML.** Travels further for this audience; needs no renderer, no styling decisions, no browser.
- **Two CLIs, not one.** Putting narrative and facts in one program is precisely what makes citation validation meaningless. The separation is the safety property, not a layering preference.
- **Default register `retro`.** The primary reader is the maintainer; `manager` exists for when it is not.
- **Default write location outside `.claude-tweaks/artifacts/`.** That tree is disposable by declaration; a kept report must not live where `/tidy` prunes.
- **Re-gathering is never an edit.** A different period or repo set is a new run; an edit re-runs narration and render only.
