# 2697: /demo and /feedback SKILL.md files load their full body regardless of which entry-path branch is taken

Surface: infra

## Current State

Unlike other multi-mode skills already split by issue #89 (`/routine`, `/specify`, `/tidy`, `/dispatch`), `/demo` and `/feedback` still load their entire `SKILL.md` body (every mode's full procedure, the complete Anti-Patterns table, batch/`--pre-confirmed` handling, etc.) on every invocation, even when the resolved entry path (e.g. a bare `/feedback` invocation) only ever executes a small fraction of that content. Measured: 2 full-skill-body loads in one session (demo, feedback) where the executed path used well under half of each file's content — meaningful context spent on unused procedure text (batch semantics, `--pre-confirmed`, `explore`/`live` modes) on invocations that never touched those branches.

## Deliverables

- Split `skills/demo/SKILL.md`'s mutually-exclusive mode bodies into sub-files, following #89's established pattern (`/routine`, `/specify`, `/tidy`, `/dispatch`) — load only the matched mode's sub-file at invocation time.
- Split `skills/feedback/SKILL.md`'s mutually-exclusive mode bodies the same way.

## Acceptance Criteria

- A bare `/feedback` invocation no longer loads batch/`--pre-confirmed`/other-mode procedure text it structurally cannot execute.
- A `/demo` invocation loads only its resolved mode's procedure (not `explore`/`live`/every other mode's full body when only one applies).
- Every existing `/demo` and `/feedback` behavior is unchanged — this is a load-time restructuring, not a behavior change; every mode still works identically once its sub-file is loaded.

## Technical Approach

Follow #89's precedent directly rather than inventing a new split convention: identify each skill's mutually-exclusive entry paths (the same way `/routine`/`/specify`/`/tidy`/`/dispatch` already did), extract each mode's full procedure into its own sub-file in that skill's directory, and reduce `SKILL.md` to a routing stub (Input parsing, mode dispatch table, cross-mode shared content like the Anti-Patterns table if genuinely shared) that reads only the matched sub-file. Compare against one of the already-split skills (e.g. `/tidy`'s `SKILL.md` + its mode sub-files) as the structural template.

### Key Files

- `plugin/skills/demo/SKILL.md` — split into mode-specific sub-files
- `plugin/skills/feedback/SKILL.md` — split into mode-specific sub-files
- `plugin/skills/tidy/SKILL.md` (or another already-split skill) — reference template for the split structure

## Gotchas

- Preserve every existing behavior exactly — this is a pure load-time restructuring. Verify each mode's full procedure text lands intact in its own sub-file with nothing dropped or altered in the split.
- Watch for content genuinely shared across modes (a common Anti-Patterns table, a shared Component-Skill Contract section) — that shouldn't be duplicated per sub-file or lost; decide per #89's own precedent whether shared content stays in the routing `SKILL.md` or gets its own cited fragment.
