# 2759: Feedback: draft-only --upstream <owner/name> path for third-party learnings, routing the learning-routing third-party rule instead of stopping

Surface: infra

## Overview

Give `/claude-tweaks:feedback` a **draft-only terminal path** for learnings owned by a third-party dependency (superpowers, agent-browser, an MCP server, another plugin), selected by a new `--upstream <owner/name>` argument, and change `_shared/learning-routing.md`'s third-party rule from "report it, name the owner, and stop" to "hand it to the draft path". Today the routing contract terminates without serving the learning: `/claude-tweaks:capture` files against the wrong owner, `/claude-tweaks:intake`'s `upstream` verdict resolves only to `/claude-tweaks:feedback`, which refuses any target but claude-tweaks, and the D4 memory fallback preserves the user's workaround without ever reporting the defect. The learning dies in the session. A live example: agent-browser exposes no screencast or frame-capture operation, the blocking constraint on any demo-recording capability, and there is no path to its maintainer today.

**Draft-only preserves the invariant instead of negotiating with it.** The skill still *files* only at `thomasholknielsen/claude-tweaks`. It additionally *drafts* for elsewhere: the existing gather, classify, dedup (retargeted, advisory), draft, and the unchanged scrub hard gate run, then the scrubbed draft is persisted to disk and the human is handed a shell-safe `gh issue create` command plus a web fallback. Nothing is published, so the confirm gate that guards publishing has nothing to guard and is skipped; the scrub gate emphatically stays, because a draft pasted by a human leaks a credential exactly as well as one filed by a CLI. Judgment a skill cannot make (honor their issue template, recognize a Discussion is the right venue, judge whether an existing thread is really the same bug) stays with the human.

**Purely additive.** An invocation without `--upstream` is byte-identically routed to today's behavior; there is no dual-running period and no old branch to remove.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- Filing, commenting, or any other write against a third-party repository. Permanently: this is the design's central invariant, not a phase-one limitation.
- Cross-session queueing of unfiled drafts. Persistence is per-run; a drafted-but-never-filed report is not tracked for later, and `/claude-tweaks:tidy`'s backstop scan (which enumerates `upstream-unfiled-*.md` only) is not extended. Stated plainly: the persisted file is a courtesy that outlives the session, with no mechanism that resurfaces it; a follow-up record may extend tidy's backstop if that proves to matter in practice.
- Non-GitHub targets. `--upstream` names a GitHub-hosted repository. A dependency with no resolvable GitHub repository (an MCP server distributed some other way, a plugin with no public tracker) takes the unresolved-target branch below: the draft is still produced and persisted, and the hand-off renders with an `<owner/name>` placeholder for the human to fill in.
- Reading a target repository's `CONTRIBUTING.md` or issue templates to pre-shape the draft. That is what the human step is for.
- A policy allowlist of permitted targets. An allowlist bounds what automation may publish; this path publishes nothing.
- Reading targets from `tools/upstream-drift/manifest.yml`. Maintainer-only tooling outside `plugin/`, and incomplete (no `agent-browser` entry).
- A sibling skill. It would duplicate the Capable-model scrub dispatch and the fingerprint dedup; the one skill that already owns them is extended instead.
- The `feedback/SKILL.md` byte-ceiling restructuring itself. That is #2697's scope; this record lands after it.

## Technical Approach

The draft path reuses the expensive machinery unchanged and replaces only what publishing needed:

| Step | On the draft path |
|---|---|
| 1 Gather | Reused: summary, affected component (theirs), repro or use case |
| 2 Classify kind | Reused: `defect`/`gap` still shapes their triage |
| 3 Self-reference check | Replaced by `upstream-draft.md`'s self-target guard on `--upstream`'s value (the guard's only home); on a self-target hit control returns to `SKILL.md` Step 3 |
| 4 Dedup | Reused, retargeted to `--upstream`, read-only, advisory |
| 5 Draft | Reused with the adapted template (claude-tweaks-internal fields dropped) |
| 6 Scrub | Reused, unchanged hard gate |
| 7 Confirm | Not applicable: nothing is published; the human is the filer |
| 8 File | Never runs; `bin/file-feedback.js` is not invoked |
| 9 Report | Replaced: persisted path, paste-ready command, web fallback |

**Where the value comes from.** The routing contract already instructs the classifier to name the owner; that identified owner is what `/intake` and `/reflect` pass as `--upstream`. The explicit flag serves direct invocation.

**Naming constraint on persistence.** `upstream-draft-{N}.md` stays outside the `staged/wrap-up-upstream-*.md` glob both consoles scan, so a stop-and-resume never re-enumerates a hand-off draft as a fresh filing proposal (the same constraint Step 8's `upstream-unfiled-{N}.md` fallback already observes). It is also outside tidy's `upstream-unfiled-*` backstop glob by design (Non-Goals).

**Shell safety of the hand-off.** `gh` has no `--title-file`, so the title must be inlined; single-quoting with `'\''` escaping is the one form under which backticks and `$(...)` are inert in every POSIX shell. The body goes via `--body-file`. This hazard is real precisely because a human runs the command in their own shell.

### Data / API Surface

`--upstream <value>` on `/claude-tweaks:feedback`'s `$ARGUMENTS`. Resolvable forms (normalized to lower-case `owner/name`): `owner/name`, `github.com/owner/name`, `https://github.com/owner/name`, `git@github.com:owner/name`, each optionally suffixed `.git` and/or `/`. Any other non-empty value is an unresolved target (see the `upstream-draft.md` deliverable), never an error; an empty value (`--upstream` with nothing after it) exits with `"'--upstream' needs a value: an owner/name slug, a GitHub URL, or the dependency's name"`.

Persisted draft file (`staged/upstream-draft-{N}.md` or the scratch path), the scrubbed body only, opening with a comment line `<!-- upstream-draft: {owner/name or "unresolved (value)"} | {kind} | drafted {ISO date} -->` so a later reader can tell target and kind without the session.

Hand-off block:

```
gh issue create --repo {owner/name} --title '{title with ' escaped as '\''}' --body-file {absolute path}

Web: https://github.com/{owner}/{name}/issues/new  (paste the body from {absolute path})
```

Intake verdict: `upstream:<owner/name>` → `Skill(skill: "claude-tweaks:feedback", args: "<text> --upstream <owner/name>")`.

## Decision Rationale

- **Draft-only over auto-filing with a stricter gate.** Auto-filing imports a genuine consent and reputation problem (issues under the user's identity at projects with conventions the skill cannot read) to save one paste.
- **Extend `/feedback` over a sibling skill.** A sibling duplicates two hard-gated subsystems; the honest version would first extract them into `_shared/`, which is more work than extending the owner.
- **No allowlist, no manifest read.** An allowlist bounds publishing and this path publishes nothing; the manifest is maintainer-only, outside `plugin/`, and incomplete.
- **Skip Step 7, keep Step 6.** Step 7 guards an irreversible publish that does not happen here; Step 6 guards leakage, which a human paste can cause exactly as well as a CLI.
- **Persist the draft.** The main objection to draft-only is that the learning dies at the paste step instead of the stop step; a file on disk outlives the session whether or not the command is ever run.
- **Contract edit and consumer sweep land together.** A routing rule naming a path `/feedback` does not yet implement would be a worse intermediate state than either endpoint, which is why this is one work unit.
