# 3479: wrap-up-pack.js residue probe runs within 0.5s of its 30s timeout in a many-worktree checkout

Origin: wrap-up reflect (friction) from run 2026-10-17T200218-record-2977

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/bin/lib/wrap-up/pack.js` runs the residue probe (`bin/residue.js --scope blast-radius --no-suite --json`) under `EXEC_OPTS.timeout = 30000` (line 31). On 2026-10-17, in this repo with 68 registered worktrees (`git worktree list`), the probe reported `ok: false, error: "Command failed: node .../residue.js ..."` at `durationMs: 30032` during `wrap-up-pack.js` for run `2026-10-17T200218-record-2977`. Running the identical command by hand afterwards succeeded and took 29440 ms, so the probe has about 0.5 s of headroom and flips to a timeout under any extra machine load. A failed probe renders the residue sweep as `unknown`, and the operator re-runs `residue.js` by hand to get the findings.

## Deliverables

- [ ] Give the residue probe in `pack.js` a timeout with real headroom (or its own per-probe value), or make `residue.js --scope blast-radius` cheaper in a many-worktree checkout, so a normal run finishes well inside the limit.

- [ ] Make the failure legible: when the probe times out, the pack error names the timeout instead of the generic `Command failed` text.

## Acceptance Criteria

- A pack run in a checkout with the same worktree count completes the residue probe with `ok: true` and a measured duration under half the timeout.

- A forced timeout in `tests/` (injected `deps.execFile` that never resolves or rejects with a kill signal) produces an error whose text names the timeout.

- `node --test` passes for the wrap-up pack suites.

## Release Note

Fixed the wrap-up fact pack timing out on its residue probe in repositories with many worktrees.
