# 4131: Record a test-impact map's dirty-tree provenance and clean up an interrupted trace's temp dir

Origin: ledger resolve gate (#4024, ledger row 27)
Defer-reason: genuinely-larger

## Current State

`node tools/test-impact.js trace --allow-dirty` writes a map whose `commit` is HEAD even though the traced tree held uncommitted changes, so the map cannot be told apart from a clean one; CI never passes `--allow-dirty`, but a developer's local map can come from one. Separately, a `trace` interrupted by a signal leaves its `ct-test-impact-trace-*` temp dir behind, because the cleanup is a `finally` block that a signal exit does not reach. The first needs a new map field, which is a codec change (`encodeImpactMap`/`parseImpactMap`) with an expand-contract rule for maps written by older tools; the second needs signal handlers around the spawned suite.

## Deliverables

- Add an optional `dirty` boolean to the map (written by `trace`, absent in older maps) and have `verify.js` report it in `scope.impact` and treat a dirty map per an explicit rule stated in `impact-selection.md`.
- Remove the trace temp dir on SIGINT and SIGTERM.

## Acceptance Criteria

- [ ] A map traced with `--allow-dirty` parses with `dirty: true` and a map from a clean tree parses with it false or absent; an older reader still parses both.
- [ ] A test sends SIGINT to a running `trace` and finds no temp dir left.
- [ ] `impact-selection.md` states how a dirty map is treated.

## Release Note

Test-impact maps record whether they were traced from a clean tree, and an interrupted trace cleans up after itself.

## Technical Approach

### Key Files

- `plugin/bin/lib/verify/impact.js` — the map codec
- `tools/test-impact.js` — `trace`, which would set the field and handle signals
- `plugin/skills/test/impact-selection.md` — the map format and its treatment
