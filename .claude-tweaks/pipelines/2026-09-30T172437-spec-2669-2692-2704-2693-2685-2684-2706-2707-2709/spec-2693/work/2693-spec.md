# 2693: Add a pre-launch checklist lens for AI/vibe-coded sites

Surface: infra

**Related:** #2624, #2692

## Current State

No standing pre-launch checklist exists across `/review`, `/code-health`, or `/build` for AI-generated sites. A documented 20-item pre-publish checklist covers custom 404, meta title/description per page, OG image, favicon, robots.txt, sitemap.xml, alt text, mobile breakpoints, form/loading states, thank-you page, privacy policy, terms, cookie banner, analytics, real contact info, and compressed images.

## Deliverables

- Turn the 20-item list into a policy-row set for `/code-health` or a final `/review` pass before a site ships.
- Group items by cheap-to-automate (sitemap.xml, robots.txt, alt text, image compression) vs. needs-human-judgment (privacy policy, terms).

## Acceptance Criteria

- Running the lens against a sample site reports pass/fail for all 20 items.

## Release Note

Added a pre-launch code-health check for AI-built sites covering commonly missed launch items such as sitemaps, meta tags, and legal pages.

## Technical Approach

Follow the precedent #2624 set for the sibling pre-launch security checklist: a `/claude-tweaks:code-health` focus vertical (`focus=prelaunch`) made of a candidate generator, a criterion entry, a criterion fragment, and the focus-mode registration rows. The generator emits candidates only for the mechanically detectable items (sitemap.xml, robots.txt, favicon, custom 404, per-page meta title/description, OG image, `alt` attributes, image sizes over a compression threshold); the fragment lists every one of the 20 items and marks the rest (privacy policy, terms, cookie banner, analytics, real contact info, mobile breakpoints, form/loading states, thank-you page) as needs-manual-check, so the report separates "verified" from "a human should confirm".

### Key Files

- `plugin/bin/lib/code-health/candidates-prelaunch.js` — new focus generator: file/markup-presence candidates for the automatable items, with a Coverage block header like `candidates-security-hardening.js`
- `plugin/bin/lib/code-health/focus-generators.js` — register the `prelaunch` focus
- `plugin/bin/lib/code-health/criteria.js` — `prelaunch` criterion entry pointing at its fragment
- `plugin/skills/_shared/criteria-prelaunch.md` — new criterion fragment: all 20 items, split into automatable vs. needs-manual-check, with severity calibration
- `plugin/skills/code-health/focus-mode.md` — Criterion-pinning table row and Coverage-section pointer for `prelaunch` (both required whenever `FOCUS_GENERATORS` gains a key)
- `tests/bin-lib/code-health/candidates-prelaunch.test.js` — generator tests, mirroring `candidates-security-hardening.test.js`

## Gotchas

- Keep the automatable/manual split explicit in the output — a report that conflates "verified automatically" with "a human should confirm" overstates what the check did.
- Items needing a live render (mobile breakpoints, form/loading states) are needs-manual-check in the fragment, not generator candidates — the acceptance criterion's pass/fail for all 20 items allows a "needs manual check" outcome.
- The generator's Coverage block must state its reach honestly (IL-110): presence of a file or tag, not its quality.
- focus-mode.md makes a registry key without a Criterion-pinning row a fail-loud stop — land both in the same change.
