# 2685: Evaluate adopting an Intent.MD-style pre-build intent file

Surface: infra

## Current State

Anthropic has described a file convention, intent.MD, that precedes and guides a feature's development lifecycle — a single file with sections like Author, Status, and Problem that an agent reads before starting a build. claude-tweaks currently starts build work from an issue/spec record (via `/specify`) with no equivalent lightweight, structured intent-capture step ahead of that.

## Deliverables

- Assess whether an intent.MD-style file would improve the current spec/build flow (e.g. as a precursor to `/claude-tweaks:specify`), and if so, propose its field structure and where it's read from.

## Acceptance Criteria

- A written adopt/discard decision, with reasoning either way.

## Release Note

Recorded a decision on whether to adopt an Intent.MD-style pre-build intent file (no user-visible change).

## Technical Approach

This is an evaluation record, not a build record — the deliverable IS the written decision, recorded as an ADR under `docs/decisions/` (a rejected option is a valid ADR outcome). Compare intent.MD's stated purpose (Author/Status/Problem fields read before a build starts) against what `/claude-tweaks:capture` and `/claude-tweaks:specify`'s shaping-mode body sections (`## Current State`, `## Deliverables`, `## Acceptance Criteria`) already capture, to judge whether intent.MD adds net-new value or duplicates a step this repo already has. Read the source article's description of intent.MD's actual field set and workflow position before judging overlap. The compared skill files are read, not edited, so they are not Key Files.

### Key Files

- `docs/decisions/0020-intent-file-evaluation.md` — new: the written adopt/discard decision (take the next free number under `docs/decisions/` at build time)

## Gotchas

- The Acceptance Criteria only require a written decision, not an implementation either way — if the decision is "adopt," a follow-up record should be filed for the actual implementation rather than folding both into this one.
- Judge genuinely, not performatively — this repo's existing `/capture` → `/specify` flow may already cover intent.MD's value; a reflexive "adopt everything Anthropic describes" isn't the goal here.
