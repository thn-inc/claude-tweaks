# 2704: worktree-setup.md's catch-up log obligation has no home when no run directory exists

Surface: infra

## Current State

`_shared/worktree-setup.md`'s "Post-creation catch-up" section states: "When either merge actually advances the worktree's branch ... the calling procedure appends an entry to the run's `decisions.md` under its own heading." This assumes a pipeline run directory (and its `decisions.md`) already exists at the point the catch-up merge runs. But `specify/SKILL.md`'s own `needs:definition` redirect path explicitly states "brainstorming completes before any pipeline run directory exists" — and the ordinary interactive `/claude-tweaks:specify #N` entry point more generally has no `PIPELINE_RUN_DIR` at the point its own worktree is created and the catch-up procedure runs (a plain `/specify` invocation is not itself a `/flow`/`/dispatch`-orchestrated pipeline run). When this catch-up's merge genuinely advances the worktree branch (a real fast-forward pulling in upstream commits, not a no-op) under one of these no-run-dir call sites, the log obligation `worktree-setup.md` prescribes has nowhere to be written — the advance happens, but its audit trail is silently dropped.

## Deliverables

- Add an explicit no-run-dir branch to `_shared/worktree-setup.md`'s Post-creation catch-up "Log the correction when it changes anything" subsection: when no `$PIPELINE_RUN_DIR` resolves, either (a) write the advance to a standalone per-session log under `.claude-tweaks/` (a new, minimal mechanism), or (b) state explicitly that the calling skill must report the advance in its own Step 9/completion summary instead, and name which callers this applies to.
- Update `specify/SKILL.md` (or wherever it cites `worktree-setup.md`'s catch-up section for its own worktree-creation call site) to point at whichever branch is chosen, so the obligation has a stated home rather than being silently unsatisfiable for this call site.

## Acceptance Criteria

- `_shared/worktree-setup.md`'s Post-creation catch-up section states what happens to its own logging obligation when no pipeline run directory exists, rather than assuming one always does.
- A `/claude-tweaks:specify #N` invocation whose worktree-creation catch-up merge genuinely advances the branch reports that advance somewhere the user or a later auditor can find it (the skill's own summary, or a standalone log) — not silently.

## Release Note

Worktree setup now states where its catch-up correction is recorded when no pipeline run is active.

## Technical Approach

Decide between the two named branches in the Deliverables before implementing: a new minimal per-session standalone log (more mechanism, more durable) versus pushing the obligation onto each no-run-dir caller's own completion summary (less mechanism, relies on each caller remembering to report it). Given this repo's general preference for durable audit trails over caller-remembered reporting (per CLAUDE.md's auto-decision-log conventions elsewhere), lean toward option (a) unless the no-run-dir call sites are few enough that option (b) is reliably enforceable — enumerate every no-run-dir caller of `worktree-setup.md`'s catch-up section before choosing, since the choice should cover all of them, not just `/specify`.

### Key Files

- `plugin/skills/_shared/worktree-setup.md` — the Post-creation catch-up section's logging obligation
- `plugin/skills/specify/SKILL.md` — the citing call site to update once the branch is chosen
