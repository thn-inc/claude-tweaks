# 3457: Extend the load model citation grammar with plugin-root- and skills-dir-relative tokens

Origin: ledger resolve gate (#3307 wrap-up, ledger row 20)

Defer-reason: needs-human-decision

## Current State

`plugin/bin/lib/skill-audit/load.js` `extractCitations` resolves backticked `.md` tokens by rules (a) citing-file-relative, (b) `_shared/`, (c) `${CLAUDE_PLUGIN_ROOT}/`, (d) "in that skill's directory" (#3307 AC1). It does not resolve plugin-root-relative tokens such as `skills/build/SKILL.md` (191 occurrences reachable from `flow`) or skills-dir-relative tokens such as `wrap-up/x.md`.

On `plugin:flow` that leaves 982 unique unresolved (citing file, token) pairs, so the closure undercounts what an invocation can load. Unresolved tokens are never counted as 0 bytes, but their bytes are missing from closure.

## Deliverables

- A rule (e) in `extractCitations`: a token starting `skills/` resolves against `{pluginRoot}/`, and a token `{skill}/{file}.md` whose first segment names an existing skill directory resolves against `{pluginRoot}/skills/`.
- Rule order stays first-existing-wins; the new rule runs after (a)–(d).
- `load.test.js` cases for both token shapes, plus a case showing a same-named relative sibling still wins via rule (a).

## Acceptance Criteria

- `extractCitations` resolves `skills/build/SKILL.md` and `wrap-up/cleanup-procedures.md` from a fixture SKILL.md to their real paths.
- On this repo, `plugin:flow`'s unresolved-pair count drops from 982 to the count that genuinely names nothing (stated in the PR).
- No previously resolved token changes its resolved path (diff of resolved sets before/after shows additions only).

## Release Note

Skill load closures now count files cited by plugin-root- or skills-directory-relative paths, so the worst-case load figure stops undercounting.
