# 3587: Windows: specify-ceremony-tally-prose.test.js reads the skill without CRLF normalization and passes a backslash plugin root to its fences

Surface: infra

Origin: /claude-tweaks:build for #3509 (run 2026-10-19T100244-record-3507), spec Gotcha

Defer-reason: tangential

**Related:** #3574, #3565

## Current State

`tests/specify-ceremony-tally-prose.test.js` already fails at base on a Windows checkout, and was adjudicated as baseline in the #3509 windows-regression run. Two defects, verified at base `f3f8a16eb`:

- Line 13 reads `plugin/skills/specify/record-creation-subissues.md` with raw `fs.readFileSync(..., 'utf8')` and no CRLF normalization. On a `core.autocrlf=true` checkout, `fenceAfter` (line 77) searches for a bare-`\n` bash fence and finds none. The module-load failure is `extraction pattern is out of sync: no bash fence after **Fresh manifest for this invocation.**`.
- Line 74 defines `PLUGIN_ROOT = path.join(REPO_ROOT, 'plugin')`. Line 104 passes it unnormalized as `CLAUDE_PLUGIN_ROOT` to the init, accumulate and tally fences. Those fences interpolate it into a JS single-quoted string inside `node -e "..."`, so a win32 path like `D:\a\...` is read as JS escapes. This is the same defect #3509 fixes in `tests/specify-crossref-manifest-resolve.test.js`. Fixing the CRLF read alone would expose it.

The open umbrella baseline record #2767 does not name this file.

## Deliverables

1. Read the skill through `readText()` from `tests/helpers/read-skill.js` instead of the raw read at line 13.
2. Pass `CLAUDE_PLUGIN_ROOT` to the fences with forward slashes (`PLUGIN_ROOT.split(path.sep).join('/')`). Add a one-line comment naming the JS-string-literal reason, following #3509 and `tests/dispatch-not-spec-shaped-exclusion-fixture.test.js:67-69`.

### Key Files

- `tests/specify-ceremony-tally-prose.test.js`: the CRLF-safe read and the forward-slash env value
- `tests/helpers/read-skill.js`: unchanged; supplies `readText()`
