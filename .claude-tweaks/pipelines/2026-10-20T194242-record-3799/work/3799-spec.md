# 3799: verify.js --cwd into another checkout writes the invoking checkout's pass stamp

Verified-as-of: 44b59b5eaa651505e44c599c20875c6542d0012f

Origin: found during #3757's merge (PR #3775) while checking its Try it walkthrough

Defer-reason: tangential

## Current State

`--cwd` (#2376, landed in #2411) moves where each `--cmd` check spawns, and also roots `--scope` and the baseline toplevel. It does not move the git reads. `resolveGitDir()` (`plugin/bin/verify.js:237`) and both `gitInfo()` snapshots (`verify.js:262` start, `verify.js:650` end, #3757) still read `process.cwd()`.

So running `node plugin/bin/verify.js --cwd <another repo or worktree> --cmd ...` from checkout A runs the checks in checkout B, then:
- writes A's pass stamp, `report.json` and count stamp under A's git dir;
- credits A's HEAD with a full pass (`scope: full`, `match: true`, `verifiedHead: true`) for checks that never ran against A;
- leaves #3757's moved-tree guard watching A's HEAD rather than B's.

This was observed on 2026-10-20 during #3757's merge. A walkthrough check ran with `--cwd` pointing into a scratch repo. It replaced the worktree's real 14,305-test stamp with a one-check run, and a real full run was needed to restore it.

The intended use, `--cwd` pointing at a subdirectory of the *same* checkout (a monorepo package), keys correctly today and must keep working.

## Deliverables

- A check run whose `--cwd` resolves to a different git dir than the invoking checkout's (`git -C <cwd> rev-parse --absolute-git-dir` vs `resolveGitDir()`) is refused before any check runs. It exits 2, and the message names both git dirs and says to run `verify.js` from inside the target checkout.
- A `--cwd` inside the invoking checkout behaves exactly as today.
- `verify.js`'s usage text and `docs/plugin-structure.md`'s verify line state the rule.

## Acceptance Criteria

- [ ] A `tests/bin-lib/verify/cli.test.js` case runs `verify.js` from repo A with `--cwd` pointing at a separate repo B. It asserts exit 2, no check spawned, and no pass stamp or `report.json` written under A's git dir. The case fails on the current code and passes with the fix.
- [ ] A `--cwd` pointing at a subdirectory of the invoking checkout still runs and stamps. The existing `args.test.js` `--cwd` cases (#2376) and `baseline.test.js`'s "a --cwd subdir offsets both the base cwd and the cat-file path" case pass unchanged.
- [ ] `verify.js --help` usage text and `docs/plugin-structure.md`'s verify CLI line both say `--cwd` must stay inside the invoking checkout.

## Release Note

Pointing `verify.js --cwd` at a different repository is now refused, instead of quietly recording a pass for the checkout you ran it from.

## Technical Approach

### Key Files

- `plugin/bin/verify.js` — refuse a --cwd whose git dir differs from the invoking checkout's, before any check runs
- `plugin/bin/lib/verify/args.js` — usage text states the same-checkout rule for --cwd
- `tests/bin-lib/verify/cli.test.js` — cross-repo --cwd refusal test
- `docs/plugin-structure.md` — verify CLI line states the rule
