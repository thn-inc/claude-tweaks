# 4679: Review Console: unattended filing ignores the tiebreak's drop recommendation and files verification questions as needs:definition

**Related:** #3944 (parent design: "settle findings aggressively", "moving the nag instead of removing it" named as a rejected shape), #3949 (shipped the file-everything unattended rule), #4620 (control mode carries undecidable console items into the acceptance packet — overlapping destination), #1426 (digest container)

Origin: /claude-tweaks:backlog attention triage, 2026-10-31 — 50 Review Console can't-tell records in the needs:definition queue

Defer-reason: tangential

## Current State

With no human present, the Review Console files **every** can't-tell finding of severity medium or higher as a `needs:definition` backlog record, ignoring the tiebreak's own `file`/`drop` recommendation:

- `plugin/bin/lib/console/resolve.js` `resolveAll` maps every `tiebreak` item to `resolution: 'filed'` (`UNATTENDED_FILED_REASON`: "an agent that could not tell is not licensed to drop"). Only the human-present Approve-all path honours the recommendation (`approveAllDefault`: `drop` → `dropped`).
- `plugin/bin/lib/console/finding-filing.js` `composeFindingProposal` files the can't-tell shape with an `## Open Question` ("Does this finding hold at `path:line`?") and `Labels: needs:definition`, `Defer-reason: needs-human-decision`.
- The same rule is stated in `plugin/skills/_shared/autonomy-ceiling.md` (`consoleAutoResolve` row) and `plugin/skills/_shared/console-execution.md:186`.
- `_shared/materiality-floor.md`'s "Tiebreak can't-tell value" already routes **low/info** can't-tell findings to the digest (`tiebreak-cant-tell`); medium+ never reaches it.

**Measured cost (2026-10-31).** The `needs:definition` queue held 53 records; 50 were these console filings (filed 2026-10-24 by the console backfill). 41 carried `Recommendation: drop` and were closed by hand on that basis. The other 9 (`file` or confirmed) were each settled in under a minute by one Standard-profile agent reading the code at `main`, with quoted evidence — 8 held, 1 was gone. None needed brainstorming, yet `needs:definition` routes each into `/claude-tweaks:specify`'s brainstorm redirect, and that redirect rejects batch form, so 50 records meant 50 interactive sessions.

It carries no `needs:definition` label, and its `Defer-reason` fits a verification task, not `needs-human-decision`.
- [ ] Update the restated rule in `_shared/autonomy-ceiling.md`, `_shared/console-execution.md`, and `_shared/materiality-floor.md` (the digest value now also covers medium+ `drop`). Record the reversal of #3949's "not licensed to drop" ruling, with the measurement above as its evidence.

**Decision (plan review Q1, 2026-11-16).** Reading B. Add a new closed-vocabulary value, `needs-verification`, to `DEFER_REASONS` and to `plugin/skills/_shared/deferral-gate.md`: the finding is unverified and the filed task is the bounded check that settles it. It clears the floor, because the task is concrete work a builder can run, not a judgement a human owes. Expand-contract applies: every reader of `DEFER_REASONS` accepts the new value in this change, no existing value changes meaning, and a build on the previous release that meets the value treats it as it treats any non-member today (it denies), which is the safe side.
