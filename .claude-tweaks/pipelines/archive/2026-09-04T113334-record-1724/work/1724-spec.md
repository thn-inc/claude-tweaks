# 1724: PR #1723 (closed #626) shipped the wrong fix — GraphQL owner/repo variables need -f, not -F

Surface: backend

## Current State

PR #1723 (merged, closed #626) swapped `plugin/skills/_shared/github-pr-scan.md`'s and `plugin/skills/demo/entry-paths.md`'s `gh api graphql -f owner='{owner}' -f repo='{repo}'` to `-F owner={owner} -F repo={repo}`, on the theory that `-f` never substitutes gh's `{owner}`/`{repo}` placeholder and only `-F` does. It also added `tests/gh-graphql-owner-repo-placeholder-pin.test.js`, pinning `-F` as the required flag repo-wide.

This contradicts the repo's own canonical `.claude/skills/gh-api-module-pattern/SKILL.md` (unchanged by #626, predating it — last touched at `7495dfba`), which is explicit about exactly this shape:

> "gh api graphql is where two of these rows collide: a String! variable needs -f, and -f never expands {owner}/{repo}, so the placeholder mechanism is simply unavailable to a GraphQL variable. Resolve the slug locally instead ... and pass it as -f owner=…/-f name=…."

And its own value-mechanism table: "An already-resolved string bound to a GraphQL `String!` variable → `-f` → `-F` type-coerces an all-numeric name (`2048`) to an Int and GraphQL rejects it (#610)."

`entry-paths.md`'s pre-#626 text already said this correctly, citing the same skill by name, before #626 overwrote it. Three other live call sites elsewhere in the codebase — `plugin/skills/specify/shaping-mode-stamping.md`, `plugin/skills/backlog/refine-record.md`, `plugin/skills/_shared/pr-run-comments.md` — all use the identical `-f id="{value}"` shape for a GraphQL variable, confirming `{value}` here is prose notation for "the agent's already-resolved value" (the same convention as `gh pr view {number}` throughout this codebase), not a gh runtime template. `repository:null` was never a `-f`-vs-`-F` problem — the pre-#626 code was correct.

`main` currently ships the regression (verified live on `main` at the time this issue was filed).
