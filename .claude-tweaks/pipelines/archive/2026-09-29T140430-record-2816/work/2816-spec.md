# 2816: archive-run refuses git-mv-failed on the empty untracked work/ a materialize-gate stop leaves behind, and leaves a partial archive twin

Defer-reason: pre-existing-outside-diff

## Current State

`/flow`'s Step 1 materialize hard gate stops a run before any spec is written, but the run directory already holds an empty `work/` directory (mkdir'd for the header that never lands). `bin/lib/reconcile/archive-merged.js`'s `archiveRunDir` treats any existing `work/` as a git-tracked subtree and runs `git mv work archive/{run}/work` unconditionally; on an empty, untracked directory that `git mv` fails, the whole archival is refused with `git-mv-failed`, and because `writeRunState(archiveDir, { status: 'archiving' })` ran before the move, `.claude-tweaks/pipelines/archive/{run}/run-state.json` is left behind as a partial twin while the source directory stays in place.

Observed live on 2026-09-29 during a human-typed `/claude-tweaks:dispatch --budget all` drain, run `2026-09-29T105914-record-2663`: `hooks.js archive-run` printed `archival refused — git-mv-failed`, the archive dir held only `run-state.json` (status `archiving`), and the source still held `context/`, `decisions.md`, `events.jsonl`, `run-state.json` (status `clean`), `wrap-up-pack.json`, and the empty `work/`. Manual recovery was `rmdir work/` then a second `archive-run`, which succeeded. The same shape recurs on every shape-gate stop, which today is every record in the `auto:build` queue (#2786), so the reconciler's archive sweep will keep skipping these directories as `git-mv-failed` indefinitely. Related: #2724 (manual cleanup of structurally-stuck run dirs), #953 (closed; the untracked-but-non-empty `work/` variant).

## Deliverables

- In `archiveRunDir` (`plugin/bin/lib/reconcile/archive-merged.js`), before queuing `work/` (top-level and per-`spec-{N}/`) into `workMoves`, detect an empty directory that `git ls-files` reports as untracked and treat it as absent: `rmdirSync` it and continue with the plain moves, never `git mv` it. A non-empty untracked `work/` keeps today's behaviour (refuse) — that is #953's distinct case.
- On any refusal path that runs after `writeRunState(archiveDir, { status: 'archiving' })`, remove the partial archive twin (`archiveDir` and its `run-state.json`) when nothing else has been moved into it yet, so a refused archival leaves the filesystem exactly as it found it.
- Unit tests in `tests/bin-lib/reconcile/` (sized like the neighbouring archive-merged tests): (a) an empty untracked `work/` archives cleanly with `work` absent from `movedEntries` and no `git mv` invoked; (b) a non-empty untracked `work/` still refuses; (c) a refusal leaves no `archive/{run}/run-state.json` behind.

### Key Files

- `plugin/bin/lib/reconcile/archive-merged.js` — `archiveRunDir` (`topWork` / per-spec `specWork` queuing, `writeRunState` marker, refusal returns)
- `plugin/bin/hooks.js` — `archive-run` verb (prints the refusal; no partial-twin cleanup today)
- `tests/bin-lib/reconcile/*.test.js` — existing archive-merged coverage the new cases sit beside

## Acceptance Criteria

- `node plugin/bin/hooks.js archive-run --run <dir>` on a closed run whose only `work/` content is an empty untracked directory exits 0, prints `archived {run}`, moves every other entry, and leaves no `work/` at either path.
- A refused archival (any `ok: false` reason reached after the `archiving` marker is written, with nothing yet moved) leaves no `.claude-tweaks/pipelines/archive/{run}/` directory behind.
- The non-empty untracked `work/` case still returns `git-mv-failed` (no behaviour change for #953's shape), pinned by a test.
- `npm test` passes with the three new cases red-before/green-after (verified by reverting the fix once).
