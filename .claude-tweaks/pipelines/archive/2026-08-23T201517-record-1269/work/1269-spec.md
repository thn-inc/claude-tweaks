# 1269: Reconcile decisions.md STAGED lines against staged/'s actual file inventory on resume

Origin: ledger resolve gate (spec #991 wrap-up, /reflect full-mode Near-misses lens)

## Current State

`decisions.md`'s `STAGED` entries name a `staged/{name}` destination for the proposal they
describe, but `log-decision.js` (which writes the `decisions.md` line) and `stage-item.js` (which
writes the actual `staged/{name}` file) are two independent calls with no atomicity between them.
A session crash between the two leaves `decisions.md` claiming a staged proposal exists when the
file was never written. Observed directly on this run: review's Step 3 lens dispatch logged a
`STAGED` line for `staged/review-defer-1.md` at 08:22:19, but the session crashed at 08:27:05-07
before the file was written — the next wrap-up run had to manually re-derive the missing proposal
from `decisions.md`'s prose. `check-resume-freshness` only checks whether a live process still
holds the run's worktree; it does not cross-check `decisions.md`'s `STAGED ... Stage path:
staged/{name}` line count against `staged/`'s actual file inventory.

## Deliverables

- Add a reconciliation check (in or alongside `check-resume-freshness`, or at the Review Console's
  "Read inputs" step) that parses every `STAGED ... Stage path: staged/{name}` line in
  `decisions.md` and verifies the named file exists under `staged/`.
- On a mismatch, surface it explicitly to whatever resumes the run (a log line, a console section)
  rather than relying on a human or agent to notice and manually re-derive the missing proposal.

## Acceptance Criteria

A `decisions.md` carrying a `STAGED` line whose named `staged/{name}` file does not exist is
flagged by the reconciliation check rather than silently passing through resume/console-read —
verified by a regression test that stages a `decisions.md` STAGED line with no corresponding
`staged/` file and asserts the check reports the mismatch.
