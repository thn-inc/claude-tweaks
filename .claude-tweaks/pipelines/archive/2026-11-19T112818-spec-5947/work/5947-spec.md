# 5947: Refresh the test-impact map when drift makes it stop paying for itself

## Current State

`verify.js` scoped runs select tests through the test-impact map (`<git-common-dir>/claude-tweaks-test-impact.json`, shared by all worktrees). `plugin/bin/lib/verify/impact.js`'s `mapProblem` only reports a problem — and `loadImpactContext` only runs `impact.fetch` — once the map is more than `impact.maxAgeCommits` (200, `.claude-tweaks/verify-scope.json`) commits behind HEAD. CI rebuilds the map on every push to main (~10 min), so the local one is routinely 50-200 commits old.

Until it crosses 200, every test file that differs between the map commit and HEAD is re-selected as `driftTests` (`selectImpactTests`). Measured 2026-11-19 (Mac load 37 on 12 cores): eight scoped runs selected 323-636 files, 245-405 of them drift (~75%), map age 50-76 commits, wall 218-279 s each. Example: a 9-file change selected 540 of ~1,325 test files, 405 drift. Counterfactual: `node tools/test-impact.js fetch --out <scratch>` took 2.8 s wall / 0.27 CPU-s and selection with the fresh map picked 113 files (-79%, ~950 core-s saved per run). Drift saturates near 405, so waiting for 200 gives long near-full-run stretches then a sawtooth.

## Deliverables

1. In `loadImpactContext`, when the map is otherwise usable but drift-selected files exceed a threshold (about 50, a named constant in impact.js), run the declared `impact.fetch` once, reload the map, and recompute drift. The 200-commit limit stays as the backstop.
2. At most one proactive attempt per stale map per ~10 minutes (CI cadence), recorded by a marker file beside the map in the shared git common dir, so a failing or no-op fetch is never retried on every run (never slower than today on the failure path).
3. Failure behaviour unchanged: a fetch that exits non-zero, times out, or yields no usable ancestor map leaves the previous map and its drift selection in force; the fetch stays REST (`gh run list/download`), never GraphQL.
4. Report the fetch in the existing `fetch` field of the impact context so the verify report shows it ran.
5. Tests under `tests/bin-lib/verify/impact.test.js`, run via `tools/run-tests.js` (not bare `node --test`).

## Acceptance Criteria

- A map with drift above the threshold triggers exactly one `runFetch` call; the reloaded map's drift is what selection uses.
- A map with drift at or below the threshold triggers no fetch.
- A second load within the attempt window (marker present) triggers no fetch; an expired marker allows one.
- A failing fetch (non-zero exit, timeout) falls back to the original map and drift, with no second attempt in the window.
- The existing stale (>maxAgeCommits) path is unchanged, and still fetches regardless of the marker.
- The PR description reports before/after selected-file counts for a real change.

## Release Note

Scoped test runs refresh the test-impact map as soon as it stops paying for itself, so a typical change re-runs far fewer test files.

## Technical Approach

### Key Files

- `plugin/bin/lib/verify/impact.js` — proactive drift-triggered refresh in loadImpactContext
- `tests/bin-lib/verify/impact.test.js` — tests for the new trigger, marker window and fetch failure
- `docs/plugin-structure.md` — document the trigger if the impact map is described there
