# 2027: session-start.js never surfaces ports/ensure.js's envWriteError — a failed .env.local write is silent

Surface: infra

## Current State

`plugin/bin/lib/ports/ensure.js`'s `ensure()` resolves `{ active, base, ports, vars, reallocated, envWriteError, leaseLineAdded }`; `envWriteError` carries the message of a failed registry env-file write or of the fallback `.env.local` lease-line write (commit 2856593e6, review lens 3c of #1927). `plugin/bin/lib/ports/cli.js` (the `ports.js` CLI) reads it and prints `ports.js: could not write env file(s) ({error}) — lease recorded in the registry regardless…` to stderr. `plugin/bin/lib/hooks/session-start.js`, the hook-side caller, renders its ports banner from `result.active`, `base`, `ports`, `vars`, and `reallocated` only (the block around its `portsEnsure.ensure(ctx.cwd, { policyServices: services })` call), so a session whose `.env.local` is unwritable gets a normal `claude-tweaks: ports {range} ({vars})` line and no sign that the lease line did not persist. The `ensure()` throw path is already caught and rendered (`ports ensure failed — …`); the non-throwing partial failure is the silent one.

Tests: `tests/hooks-session-start.test.js` pins the ports banner (#1792 AC2/AC3/AC6: no policy → no call; policy → one line; throw → caught); `tests/bin-lib/ports/ensure.test.js` and `cli.test.js` cover `envWriteError` on the library and CLI sides.

## Deliverables

- [ ] `session-start.js`: after the ports line, when `result.active` and `result.envWriteError` is a non-empty string, push one more part — `claude-tweaks: ports — env file write failed ({envWriteError}); the lease is recorded in the registry, re-run `node "${CLAUDE_PLUGIN_ROOT}/bin/ports.js" env` after fixing the file` — the same wording family the CLI uses, so the two surfaces agree. Never a throw; the existing ports line still renders first.
- [ ] `tests/hooks-session-start.test.js`: one case with `ensure()` stubbed to return an active result carrying `envWriteError`, asserting both the ports line and the warning line render in order; the #1792 cases unchanged (no `envWriteError` → no extra line).

## Acceptance Criteria

1. With `port-services` policy set and `.env.local` unwritable, the session-start banner shows the ports line followed by the env-file-write warning naming the error.
2. With a writable env file, the banner is byte-identical to today; the #1792 AC2/AC3/AC6 cases pass unchanged.
3. The hook never throws on this path (the existing never-break-a-session posture holds).
4. `npm test` green.

## Technical Approach

Read the field the library already computes and render it in the caller that already renders the rest of the result; mirror the CLI's wording so a user who sees both recognizes the same condition. No change to `ensure.js`.

### Key Files

- `plugin/bin/lib/hooks/session-start.js` — ports banner: warning line on `envWriteError`
- `tests/hooks-session-start.test.js` — new case beside the #1792 cases

## Gotchas

- `envWriteError` is set on the `active: true` branch only; guard on `active` first so an inactive result never renders the warning.
- The banner is a list of `parts` joined into `additionalContext`; add a part, do not replace the ports line.
- The CLI's stderr message is the wording source; keep the hook's line one sentence so the banner cap on parts is respected.
