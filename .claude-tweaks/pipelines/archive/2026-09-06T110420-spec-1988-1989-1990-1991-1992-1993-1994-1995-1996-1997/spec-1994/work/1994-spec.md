# 1994: Pipeline-step call sites: review/code-mode-steps.md and test/verification.md compose their shared-contract reads into one bundle per step
Surface: backend

## Overview

Give the two most-read pipeline-step files by subagents — `plugin/skills/review/code-mode-steps.md` (56 reads) and `plugin/skills/test/verification.md` (43 reads) — a compose call site that folds the `_shared` contracts each cites unconditionally today into one bundle per step, rather than fencing the step files themselves (which are mostly step-specific procedure, not branch-dependent prose). `code-mode-steps.md` composes `review-code` from `subagent-output-contract.md`, `pipeline-run-dir.md`, and `auto-decision-log.md`; `verification.md` composes `test-verify` from `pipeline-run-dir.md` and `pr-early-run-lifecycle.md`. `when:` markers are added to the two step files themselves only where they carry pr-first/local-merge or auto/interactive branches (`code-mode-steps.md` has both).

**Complexity:** Medium
**Estimated tasks:** 5

## Non-Goals

- Fencing `subagent-output-contract.md`, `pipeline-run-dir.md`, `auto-decision-log.md`, or `pr-early-run-lifecycle.md` themselves beyond what U2/U4 already fenced — this record composes from the already-fenced (or soon-to-be-fenced by U4) sources, it does not add new fences to them.
- Changing `/test`'s or `/review`'s standalone (no run directory) behavior — both commands run standalone today and must keep working; this record states the standalone case explicitly at each call site rather than silently assuming a run directory always exists.
- Migrating `review/step3-lens-dispatch.md` or `dispatch/task-prompt.md` — those are the sibling U8 record.
