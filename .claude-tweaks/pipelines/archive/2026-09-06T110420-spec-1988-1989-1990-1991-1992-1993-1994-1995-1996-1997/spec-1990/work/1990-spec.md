# 1990: Per-step composed-bytes measurement in context-cost.js: hard gate on composed bytes per compose call site, per-file 40 KB test on marker-stripped bytes as a warning

Surface: backend

## Overview

Extend `plugin/bin/lib/skill-audit/context-cost.js` so the hard byte gate moves from "no single file exceeds 40 KB" to "no compose call site's composed bytes exceed the ceiling under any condition combination it actually branches on" — the number a reader actually pays, per the parent design (#1987). The existing per-file 40 KB assertions become warnings, measured on marker-stripped bytes read from the git blob (fixing the CRLF-inflation bug tracked separately as #1880) rather than the working tree.

**Complexity:** Medium
**Estimated tasks:** 5

- Fixing #1880 itself as a standalone record — this record's CRLF-safe measurement approach is the fix, folded in here rather than filed separately, since it's required for this record's own correctness.

## Deliverables

- [ ] `findComposeCallSites(repoRoot)` — scans `plugin/skills/**/*.md` for lines matching the literal, single-line `compose-context.js … --step {name} {files}` call form (the call sites U2/U4/U5/U6/U7 produce are all single-line by construction) and returns an array of `{step, file, sources}` (the skill file the call site lives in, the step name, and the resolved list of source file paths, resolved relative to the repo root — the same root every other path in this module already resolves against). A call site wrapped across multiple lines is a known, accepted gap for this record — not handled — since every call site this decomposition itself produces is single-line; note this limitation in the function's own comment so a future multi-line call site doesn't silently go unmeasured.
- [ ] `measureComposed(repoRoot, callSite)` — composes the named sources via U1's exported `compose(sources, conditions)`, under every combination of the condition values the sources actually branch on (determined by scanning the sources for `when:` keys using U1's own marker-parsing logic, never a second regex, against the closed six-key vocabulary U1's `resolve-conditions.js` exports — not the full six-key cross-product blindly), and returns bytes per combination.
- [ ] `measureSkills`/`measureSubFiles` switch from raw working-tree byte counts to marker-stripped bytes (via U1's exported `stripMarkers(text)`), measured from the git blob — `git show HEAD:{path}` for any path git currently tracks, whether or not it has uncommitted local edits (a tracked-but-locally-edited file is measured from the *working tree*, not stale `HEAD` content — only a genuinely untracked new file has no git-blob source at all and falls back to a plain working-tree read) — so a CRLF checkout no longer inflates the count (#1880).
- [ ] The existing "no SKILL.md exceeds 40 KB" and "no sub-file exceeds 40 KB" assertions in `tests/bin-lib/skill-audit/context-cost.test.js` become `console.warn` reports under a new function, `overCeilingWarnings` (matching the existing `nearCeiling`-style naming convention in this module) — no longer a hard test failure.
- [ ] New hard-gate test: "no compose call site's composed bytes exceed `CEILING_BYTES` under any condition combination" — this is the test that now fails the suite. Whether any real call site is known to already violate this today is not asserted either way; the test is authored and proven against a synthetic fixture (AC 2) regardless of the real corpus's current state.
- [ ] `composedBytesReport(repoRoot)` — the informational payload/headroom log gains a per-call-site composed-bytes table this function produces (one row per call site, one column per condition combination it branches on); `overCeilingWarnings` and `composedBytesReport` are separate functions with separate concerns (warnings vs. the informational table), not folded into one.
- [ ] `plugin/skills/_shared/harness-health-analysis.md` gains one evidence pre-check row that runs this measurement and cites the module by name — it does not restate the numbers inline (the module and `/claude-tweaks:harness-health`'s own rendering are the source of truth for the actual figures).
- [ ] Keep `bloat.js`'s `CEILING_BYTES` import working unchanged — verify with a passing `bloat.js` test run, not just a code read.

## Technical Approach

`measureComposed` should not blindly cross-product all six condition keys for a call site whose sources only ever branch on two of them (e.g., `integration-model` and `transport` for the `merge` bundle) — inspect the sources' actual `when:` key usage first (reusing U1's marker-parsing logic, not a separate regex) and only combinate the keys that appear.

## Gotchas

- `bloat.js` imports `CEILING_BYTES` from `context-cost.js` — do not rename or remove that export while restructuring the module; add the new functions alongside it.
- `plan-audit/checks.js`'s `headroomCheck` also imports `CEILING_BYTES` — do not retarget that check in this record; it's explicitly U10's job, done later once the composed-bytes measurement this record ships has stabilized.
- Measure from the git blob (`git show HEAD:{path}`), not the working tree, specifically to close #1880 (CRLF inflation) as a side effect — a working-tree read on a CRLF checkout silently overcounts every file's bytes by roughly one byte per line.
- This record is blocked by U1 alone in the dependency graph, but its Draft AC references U2's `merge` call site as the first real fixture — sequence the work so U2 has actually landed before writing the "AC 1" verification, or use a synthetic fixture call site in the interim and re-verify against the real one once U2 merges.
- Related, not rebuilt here: #1929 is the empirical (transcript-side) measurement channel — this record is the static (source-side) one; don't conflate the two or attempt to satisfy #1929's deliverables from this record's work.
- Reusing the same `CEILING_BYTES` (40 KB) for both a single file's budget and a composed multi-source bundle's budget is deliberate, not an oversight — the parent design (#1987) states the hard gate should move to "composed bytes per step, 40 KB, the number a reader actually pays," i.e. the same ceiling number applied to the unit that now actually matters (a composed bundle), not a new, separately-tuned number.
- Before switching `measureSkills`/`measureSubFiles` to git-blob-sourced bytes, grep every caller of those two functions (not just `bloat.js`'s `CEILING_BYTES` import) — `/claude-tweaks:harness-health`'s own reporting code may call them directly and could be surprised by the semantics change (uncommitted edits no longer moving the reported byte count until git-tracked, per the clarification above).

## Build deviations (architecture alignment, /build Common Step 4.5)

Four deviations from the Deliverables above shipped. Three are classified **Update the spec** (the spec was wrong or self-contradictory; the build is correct) and are staged for the consolidated Review Console as `spec-1990/staged/build-deviation-{1..3}.md` — each carries the proposed amendment text; the code stays as built either way. One is **Beneficial** and applied as-built.

1. **Per-file bytes are CRLF-normalized working-tree reads, not git-blob reads** (staged, build-deviation-1). Normalization closes #1880 identically (the blob under autocrlf is the LF form), with zero git spawns, no stale-HEAD split for edited files, no git dependency, and a CRLF/LF twin proof that runs on an untracked fixture (AC4).
2. **The hard gate carries a per-step exception for the merge site** (staged, build-deviation-2). The only real call site measures 55,995 / 57,476 / 57,274 / 58,755 B across its four combinations and 58,761 B for the both-branches read — over the ceiling under every one — so "hard gate over the real corpus", "not asserted either way", and "`npm test` passes" could not all hold. `COMPOSED_STEP_EXCEPTIONS = { merge: 59 * 1024 }` is a provisional ceiling within 1,655 B of the measured maximum; a stale-exception test fails on a shrink under 40 KB or on more than 4 KiB of slack. The restructuring is a follow-up record filed at wrap-up.
3. **Repo-relative sources are rejected, not resolved** (staged, build-deviation-3). #1989 established the install-safe `${CLAUDE_PLUGIN_ROOT}/…` form; a bare repo-relative source, an unknown flag, or a missing step is an `unparsed` row that fails the gate, while a placeholder-bearing line is documentation and is skipped.
4. **One `unresolved` row per call site** (Beneficial, applied). Beyond "every combination of the condition values the sources branch on", the row with every used key pinned to `unresolved` is what a standalone run (no `config.yml`) reads — both branches — and is the true maximum the gate must see.

Also as built: AC1's log shows five rows per merge site (four combinations plus `unresolved`); Deliverable 4's warnings also cover a third pre-existing hard assertion (`tightest.free >= 0`) the record did not name; `harness-health-analysis.md`'s check 10 carries a runnable snippet and the dimension-9 row cites checks 9 and 10.
