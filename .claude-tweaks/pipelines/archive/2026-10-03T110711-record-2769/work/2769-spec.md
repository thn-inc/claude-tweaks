# 2769: GIF quantizer is distinct-colour-bound, not pixel-bound: 482s / 1.3 GB on a high-entropy walkthrough, and the shipped perf test only covers the fast band

Origin: consolidated Review Console — run `2026-09-21T213441-spec-2697-2757-2758-2759`, ledger row #17 (`deferred`; the row promised a staged Queue-write proposal that was never written — filed here at the console instead)

Defer-reason: genuinely-larger

## Current State

`plugin/bin/lib/gif/palette.js` was rewritten during #2758's fix wave (`41dc8424f`) to fix an
earlier pathology (224 s / 900 MB RSS on one real walkthrough) using distinct-colour dedup plus a
cached nearest-index lookup. The re-review then measured what the rewrite actually made it bound by:
**distinct colour count, not pixel count.**

| Input | quantize | RSS |
|---|---|---|
| real 1280x720 UI screenshots (the shipped fixtures) | 58 ms | — |
| adversarial 8-frame 1280x720 gradient + noise, 259,895 distinct colours | **482,135 ms** | **1,336 MB** |

That adversarial figure is worse than the original bug it replaced. UI screenshots sit in the fast
band (low thousands to tens of thousands of distinct colours), so `/claude-tweaks:walkthrough` over
an ordinary app is fine; a walkthrough over a photo-, map-, or video-heavy page falls off the cliff.

The shipped perf regression test does not bound this case: it runs at 400x300 against a <5000 ms
budget and measures 730 ms — entirely inside the fast band, so it can never go red for the failure
mode above.

## Deliverables

A colour-count-bounded quantizer path — sampling, pre-bucketing, or an explicit distinct-colour cap
that degrades quality instead of time — so wall-clock and RSS stay bounded regardless of input
entropy. Plus a perf test that actually exercises the slow band (a high-distinct-colour fixture), not
only the fast one.

## Acceptance Criteria

The adversarial case above (8 frames, 1280x720, ~260k distinct colours) completes within a stated
wall-clock and RSS budget — quote the measured numbers before and after.

A committed perf test covers the high-distinct-colour band and is proven to go red against the
pre-fix quantizer.

The real-screenshot fast band does not regress (still ~tens of ms at 1280x720).
