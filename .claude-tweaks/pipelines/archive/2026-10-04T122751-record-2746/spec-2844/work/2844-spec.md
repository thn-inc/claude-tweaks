# 2844: PR-early lifecycle's Step 1.6 remote-only stale-branch check didn't prevent a same-name push collision on worktree-dispatch-next

## Current State

`_shared/pr-early-run-lifecycle.md` documents that `build/worktree-setup.md` Step 1.6 ("Remote-only stale branch check") exists specifically so a same-name branch left on `origin` by a prior, unrelated run is caught and stopped for a decision *before* `EnterWorktree` creates the new worktree and before Step 2's push can be rejected non-fast-forward. On run `2026-09-30T102540-record-2625` (#2625, dispatch group, worktree branch `worktree-dispatch-next`), the first (`build,test`) call's own `decisions.md` entry records that Step 2's push nonetheless failed non-fast-forward twice, against a genuinely unrelated stale branch left by a different old run (commit `c19a97b7a`, re #2266, ~61 commits behind current main) — exactly the shape Step 1.6 is supposed to close. The run proceeded local-only with `prExempt: true` stamped in `run-state.json` rather than stopping for the documented decision, and the second call had to resolve it manually (rename + push to a disambiguated branch name).

## Deliverables

Fix the gap so a genuinely unrelated same-name remote branch is caught before worktree creation, consistent with the documented contract, rather than surfacing only as a failed push two steps later.
