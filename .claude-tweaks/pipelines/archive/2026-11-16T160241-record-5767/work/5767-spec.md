# 5767: guard-rewrite.test.js: print the shell stubs' argv from sh instead of starting node per call

**Related:** #5324, #5373

Verified-as-of: c059556fc34954c27371c25ebd65f99e79a4eb0a

## Current State

`tests/bin-lib/hooks/guard-rewrite.test.js` checks that each command rewrite behaves the same under bash and zsh. It puts three stub executables first on `PATH` (`ls`, `node` and `git`, written at lines 773–778 at c059556f) and compares what the original and the rewritten command print.

Each stub ends by starting a full node process to print its arguments:

- `ls` and the `node` stub's fallback: `exec "<node>" -e 'console.log(JSON.stringify(process.argv.slice(1)))' -- "$@"`
- `git`: honours leading `-C <dir>` with `cd`, then `exec "<node>" -e 'console.log(JSON.stringify([process.env.PWD, ...process.argv.slice(1)]))' -- "$@"`

A bare node start costs about 34 ms of CPU on the measuring machine (12 cores, load 50–110). A 45-second process sample on 2026-11-16 saw about 335 node starts from the `git` stub of one run of this file.

The `node` stub's `-e|-p|--eval|--print` branch hands off to the real node on purpose: the `node-eval-separator` rule is tested against real `process.argv`. Only the print-the-arguments path is waste.

## Deliverables

1. The `ls` stub, the `git` stub and the `node` stub's fallback branch print their output with shell builtins only: no node and no other child process per call.
2. The printed text is byte-identical to today's JSON for every input the suite sends, so every existing assertion is unchanged. That includes arguments holding a space, a double quote, a backslash, a newline or a non-ASCII character.
3. The `node` stub still execs the real node for `-e`, `-p`, `--eval` and `--print`.
4. The stubs run under the interpreter their shebang names on macOS and on the ubuntu CI image.
5. The PR body reports, for this file, node processes started by the stubs and git processes, before and after. The stubs run with a reduced environment (`PATH`, `HOME`, `A`), so a `NODE_OPTIONS` preload does not reach them: count stub node starts with a scratch wrapper around the node path, not committed.

## Acceptance Criteria

- [ ] A run of the file starts no node process from the `ls` stub, the `git` stub or the `node` stub's fallback branch. The PR body shows the before and after counts.
- [ ] The stubs' output for a fixed argument list holding a space, a double quote, a backslash, a newline and a non-ASCII character equals `JSON.stringify` of the same list, checked by a test in the file.
- [ ] The equivalence tests still fail when they should: with the rewrite temporarily broken so that it drops an argument, joins two arguments, or drops a `-C <dir>` that changes the directory, the file goes red. The PR body quotes the red output for each of the three.
- [ ] The file reports the same number of tests as before, all passing under bash and zsh; no test is deleted, skipped or loosened.
- [ ] The full suite and the Windows regression job pass.
