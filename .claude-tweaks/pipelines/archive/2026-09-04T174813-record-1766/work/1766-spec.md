# 1766: dispatch's cleanup-only teardown call reproduces the materialize hard-gate it exists to escape

## Current State

`dispatch/two-call-gate.md` §5 and `dispatch/task-prompt.md` document the teardown path for a `/claude-tweaks:dispatch`-orchestrated first-call HARD-GATE failure as `PIPELINE_RUN_DIR="{run-dir}" CLAIM_RUN_ID="{RUN_ID}" /claude-tweaks:flow {target} wrap-up cleanup-only`. But `flow/SKILL.md` Step 1.5 and `flow/steps-and-gates.md`'s "Record-reference input" section state that a record reference is resolved and shape-gated via `materialize.md`'s Resolution + Materialization hard gate unconditionally, before Step 2's other checks -- with no `cleanup-only` exception. When the first Task call's own HARD-GATE failure was itself the materialize shape-gate (record not spec-shaped -- Deliverables/Acceptance Criteria missing or a placeholder present), the documented teardown call re-runs Step 1.5 against the same still-unshaped record and reproduces the identical STOP, never reaching wrap-up's cleanup route at all.

Observed live during a `/claude-tweaks:dispatch next` Routine firing: record #1633 failed `materialize.js`'s shape gate for the 3rd consecutive time (retry ceiling reached, `bot:blocked` applied, `auto:build` removed by the first call's own Settle procedure). Invoking the documented `/claude-tweaks:flow #1633 wrap-up cleanup-only` teardown call would have hit the exact same "Record #1633 is not spec-shaped" STOP before ever reaching Step 5's wrap-up execution. Worked around by invoking `/claude-tweaks:wrap-up #1633 cleanup-only` directly instead -- `wrap-up/SKILL.md`'s own Flags section documents `cleanup-only` as "never typed standalone in practice, but parsed the same way regardless of caller," which structurally supports this, but the documented dispatch-side procedure itself does not name this workaround.

## Deliverables

- [ ] Either: give `/flow`'s Step 1.5 materialize gate a `cleanup-only`-aware exception (skip re-resolution/re-gating when `cleanup-only` is set and the failure being torn down is the materialize gate itself), or update `dispatch/two-call-gate.md` §5's documented teardown call to invoke `/claude-tweaks:wrap-up {target} cleanup-only` directly rather than routing through `/claude-tweaks:flow`, at least for this failure mode.
- [ ] Confirm which of dispatch's other first-call HARD-GATE shapes (besides the materialize gate) would hit the same problem, and cover them by the same fix.

## Acceptance Criteria

- A `/claude-tweaks:dispatch`-orchestrated first-call materialize-gate failure's teardown call reaches `wrap-up/cleanup-procedures.md`'s worktree/claim/run-dir cleanup without re-triggering the same materialize gate.
- `tests/dispatch-firing-exclusion.test.js` or an equivalent test covers this teardown path for a materialize-gate-originated failure specifically, not just a build/test-originated one.
