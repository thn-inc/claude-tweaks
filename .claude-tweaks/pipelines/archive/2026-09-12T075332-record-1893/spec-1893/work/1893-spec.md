# 1893: review/review-effort-derivation.md: `build-review-context.js mint` prints a JSON line, but the prose reads as if it prints a bare directory path

Surface: infra

## Current State

`plugin/bin/build-review-context.js` documents itself as printing "a one-line JSON result on stdout (`{dir}` for mint; `{dir, contextPath, bytes, files, …}` for build)" and its `mint` branch writes `JSON.stringify({ dir }) + '\n'`. `plugin/skills/review/review-effort-derivation.md` Step 2 (the `github-issues` branch) says the command "prints `{dir}` once and the same `{ctx-dir}` is reused by Step 3's `build --dir {ctx-dir}` call", then uses `{ctx-dir}` as a bare path in `gh issue view {n} --json labels > {ctx-dir}/record-{n}.json` and in the `node -e` facet read. `step3-lens-dispatch.md`'s dispatch block spells out `build`'s JSON result fields but inherits the same `{ctx-dir}` placeholder for `--dir`. The placeholder notation `{dir}` is the CLI comment's shorthand for "a JSON object with a `dir` field", and the skill prose reuses it as if it were the path itself.

Observed on plugin 6.114.1: a review run set `CTX=$(node … mint --run "$PIPELINE_RUN_DIR")`, got `{"dir":"…/review-ctx"}`, and the documented redirect failed with `no such file or directory: {"dir":"…"}/record-{n}.json` while `build --dir '{"dir":"…"}'` created a nested directory literally named `{"dir":"` under the worktree, surfacing later as untracked junk at commit time.

Tests: `tests/bin-lib/review-context/exit-code.test.js` and `build.test.js` pin the CLI's exit codes and build output, including "mint with no --run exits 0 and prints a JSON line with a dir key"; no test pins the prose's use of that output.

## Deliverables

- [ ] **Plain-path output mode on `mint`.** `build-review-context.js mint --print-dir` prints the bare directory path followed by a newline and nothing else (the JSON line stays the default, so every existing consumer of `mint` is untouched). The usage line and the header comment name both shapes.
- [ ] **Prose names the shape and uses the flag.** `review-effort-derivation.md` Step 2: state that `mint` prints `{"dir": …}` by default, and switch the Step 2 command to `CTX_DIR=$(node "${CLAUDE_PLUGIN_ROOT}/bin/build-review-context.js" mint --print-dir --run "$PIPELINE_RUN_DIR")` so the redirect and the facet read take a path; show the `node -e` `.dir` extraction once as the fallback for a build that predates the flag. `step3-lens-dispatch.md`: the `--dir {ctx-dir}` reuse sentence says `{ctx-dir}` is the path printed by `mint --print-dir` (or the `.dir` field of the default JSON), so the placeholder is defined where it is first used.
- [ ] **Tests.** `exit-code.test.js` or a sibling: `mint --print-dir` prints exactly the path and a newline; `mint` without the flag still prints the JSON line; `--print-dir` on `build` is rejected with the usage error (the flag is `mint`-only). A prose pin asserting `review-effort-derivation.md` names the JSON shape and the `--print-dir` form, and that no `{ctx-dir}` placeholder is used before it is defined.
- [ ] `docs/plugin-structure.md`'s command-reference line for `build-review-context.js` gains the flag.

## Acceptance Criteria

1. `node bin/build-review-context.js mint --print-dir --run {run}` prints `{run}/review-ctx` (or the resolved scratch path) and nothing else; without `--print-dir` the output is unchanged JSON.
2. Following `review-effort-derivation.md` Step 2 literally with the new command produces a working redirect into `{ctx-dir}/record-{n}.json` and a `build --dir` call that creates no stray directory; demonstrated once in the PR description on a fixture run.
3. `step3-lens-dispatch.md` defines `{ctx-dir}` at first use.
4. `npm test` green; the existing review-context tests pass unchanged.

## Technical Approach

Add the smallest CLI affordance that makes the documented one-liner correct, and make the prose stop implying a shape the CLI never had. Keep JSON as the default so `build`'s and `mint`'s output conventions stay consistent for programmatic callers; `--print-dir` is the shell-substitution convenience, named in the prose that uses it.

## Gotchas

- `build-review-context.js` had a compute-then-exit truncation fix (`cc302658d`); keep the `deps.stdout` write path and do not add a `process.exit` after the plain print.
- The prose's `node -e` facet read takes the path as `process.argv[1]`; with the flag it receives the same path it did in the author's intent, so no change to that snippet beyond the variable name.
- A review run on a build older than this change still gets the JSON line; that is why the `.dir` extraction stays documented as the fallback rather than deleted.
