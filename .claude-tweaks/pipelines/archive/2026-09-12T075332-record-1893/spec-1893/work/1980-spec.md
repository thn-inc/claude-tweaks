# 1980: coordination.js: categoriseReproduction's location-only match can silently merge two distinct findings

Surface: infra

## Current State

`categoriseReproduction(agentAFindings, agentBFindings)` in `plugin/bin/lib/coordination.js` walks agent A's findings and, for each, takes the first unmatched agent-B finding for which `sameLocation` holds (same `path`, `|line difference| <= LINE_TOLERANCE_REPRODUCTION`, 2); the pair becomes one `confirmed` entry via `reconcileSeverity` (lower severity wins, `severityContested: true` when buckets straddle, #733); everything unmatched lands in `unconfirmed` with `source: 'A'|'B'`. No field other than `path`/`line` is consulted: `normalizeFinding` normalizes `path`/`line`/`severity` only, and the finding text (`text` in the test fixtures, the `Finding` column in the lens agents' Template A output that `review-coordination.js categorise-reproduction` reads from JSON) is never compared. Two unrelated findings within two lines are therefore merged and the B-side one vanishes from both arrays. `findingsMatch` (a sibling used elsewhere) still requires equal severity buckets, so the two matchers disagree about what "match" means.

`tests/multi-agent-coordination.test.js` pins the #733 straddle case (same location, same `text`, straddled buckets → confirmed, contested), the ±2 / ±3 line tolerance, and "genuine location disagreement" across different paths; no case has same location with different substance. `review/step3-lens-dispatch.md` consumes the CLI's `confirmed`/`unconfirmed` arrays when merging lens findings into the routing table.

## Deliverables

- [ ] **Normalize substance.** `normalizeFinding` gains a `text` field taken from the first present of `text`, `finding`, `Finding`, `summary`, `Summary` (string, trimmed); absent → `null`.
- [ ] **Location plus substance decides a pair.** A new `sameSubstance(na, nb)` returns `true` when both texts are non-null and their token Jaccard (lowercased words, stop words and punctuation stripped, `path:line` fragments removed) is at or above `SUBSTANCE_SIMILARITY_MIN = 0.4`, or when one text is a prefix/suffix of the other after normalization; `null` when either text is missing (unknown, not false). `categoriseReproduction` pairs a B finding with an A finding when `sameLocation` holds and `sameSubstance` is `true` or `null`; a same-location pair whose `sameSubstance` is `false` is **not** paired: both findings go to `unconfirmed` with an extra `nearLocation: { source, path, line }` field naming the other, so a consumer can see the coincidence. The #733 behavior is unchanged for pairs that agree on substance (the straddle test's fixtures share `text`).
- [ ] **Prefer the best B candidate.** When several unmatched B findings share A's location, pick the one with the highest substance similarity rather than the first in array order, so a same-substance pair is never lost to an earlier unrelated neighbour.
- [ ] **Consumers surface the coincidence.** `review/step3-lens-dispatch.md`'s reproduction rules (the three bullets after the `categorise-reproduction` command: same bucket → confirmed, straddled bucket → confirmed contested, one side only → unconfirmed) gain a fourth: same location, different substance → both unconfirmed, each carrying `nearLocation`, logged as `STAGED … — Reproduction: lens "{lens}" findings {path}:{lineA} / {path}:{lineB} share a location but not substance; both staged`. An `unconfirmed` entry carrying `nearLocation` renders one extra clause in its routing-table row ("same location as {source} finding at {path}:{line}, different substance") so the reviewer sees both; `docs/plugin-structure.md`'s `review-coordination.js` line notes the field. `findingsMatch` is aligned to call `sameSubstance` too, keeping its severity-bucket requirement (its own callers pin that).
- [ ] **Tests.** `tests/multi-agent-coordination.test.js`: same location, different substance (a low nit at line 100 vs a critical bug at line 101) → two `unconfirmed` entries, each with `nearLocation`, nothing dropped; same location, same substance, straddled buckets → the #733 case unchanged; same location, one side missing `text` → paired (unknown substance never discards); three B findings at one location where the second matches A's text → that one is paired and the other two stay unconfirmed; the existing tolerance and disagreement tests pass unchanged. A prose pin for the lens-dispatch clause.

## Technical Approach

Add substance as a second signal rather than replacing location, and make "unknown substance" behave like today so agents that omit the text column lose nothing. Never discard: the only new outcome is "two unconfirmed entries that point at each other", which the reviewer can still merge by hand. The tokenizer can be the one `#1944`'s near-duplicate module introduces if that lands first; otherwise keep it local to `coordination.js` and pin it with fixtures (similarity scores are normalization-sensitive).

## Gotchas

- `sameLocation` deliberately returns `false` for unlocated findings (the `undefined !== undefined` trap in its comment); `sameSubstance` must return `null`, not `false`, for missing text, or unlocated-and-untexted pairs change behavior.
- Keep `LINE_TOLERANCE_REPRODUCTION` at 2; the fix is a second signal, not a tighter window.
- `reconcileSeverity` spreads `fa` into the confirmed entry; the `nearLocation` field must only ever be set on `unconfirmed` entries, never leak into `confirmed`.
- The lens agents' JSON column is `Finding`; a fixture using `text` and a fixture using `Finding` must both parse, pinned by a test.

## Original request

## Current State
`categoriseReproduction` in `plugin/bin/lib/coordination.js` matches a reproduction pair on `sameLocation` alone (location within `LINE_TOLERANCE_REPRODUCTION`, 2 lines) — it no longer requires matching severity buckets (that requirement was deliberately dropped by #733, to stop a same-substance pair straddling a severity-bucket boundary from being wrongly treated as unconfirmed). But `sameLocation` alone is also the ONLY signal used to decide two findings are "the same issue" — there is no substance/text check. Two agents reporting genuinely UNRELATED findings within 2 lines of each other (e.g. an unrelated critical bug at line 101 when agent A already reported a low-severity nit at line 100) are merged via `reconcileSeverity`, and the second, distinct finding is silently discarded — it appears in neither `confirmed` nor `unconfirmed`.

`tests/multi-agent-coordination.test.js`'s "genuine location disagreement" test only exercises different paths, never a same-location-different-substance pair, so this gap is untested.

## Deliverables
A design that keeps #733's fix (a same-substance pair straddling a severity bucket must still be reproduced) while no longer silently discarding a same-location pair that is NOT the same underlying issue — e.g. requiring some text/summary similarity signal alongside location proximity before treating two findings as a reproduction pair, or surfacing an ambiguous same-location pair distinctly rather than always collapsing it into one `confirmed` entry.

## Acceptance Criteria
- [ ] A new test pins that two same-location, substantively-different findings from agent A and agent B are NOT silently discarded — both surface somewhere in the output.
- [ ] The existing #733 regression test (severity-bucket straddle on the SAME substance is still reproduced) continues to pass unchanged.
- [ ] Full `npm test` passes.

Defer-reason: genuinely-larger — requires a design decision on how to distinguish "same issue" from "same location" without reintroducing #733's false-negative; found by the pre-v6.117.0 whole-branch review.
