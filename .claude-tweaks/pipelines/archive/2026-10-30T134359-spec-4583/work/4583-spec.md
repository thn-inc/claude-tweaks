# 4583: Review Console: a contested-pair partner re-staged after its own earlier verdict never inherits the pair's later verdict

Origin: wrap-up leftover routing from #4563

Defer-reason: tangential

## Current State

#4563 made a settled `review-contested-*` file pass its verdict to every finding in its `## Positions` section (`plugin/bin/lib/console/resolve.js` `tiebreakModel`), but only for a partner key with no `settledByKey` entry at all. A partner whose key already carries a verdict logged *before* the partner's own (re-)STAGED line therefore never inherits: the earlier verdict does not satisfy `settledAfter` for the later STAGED line, and the inheritance guard skips the key, so the line stays keep-staged. Rare and fail-safe (never dropped). Deferred from #4563 (ledger row 4).

## Deliverables

Make inheritance skip a partner key only when an existing verdict for it is logged after that partner's own latest STAGED line; otherwise let the pair's verdict settle it.

## Acceptance Criteria

A partner key with a verdict logged before its own re-STAGED line, followed by a contested pair verdict naming it in Positions, produces no keep-staged item for the partner.

A partner whose own verdict is logged after its STAGED line still keeps that verdict over the inherited one (existing #4563 tests stay green).

## Release Note

A re-flagged review finding that a later contested-pair verdict covers is now settled at the Review Console.

### Key Files
