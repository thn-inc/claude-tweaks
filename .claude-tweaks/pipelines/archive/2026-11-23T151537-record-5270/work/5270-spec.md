# 5270: Pick flow's context-handoff branch from the caller, not the run's dispatched flag

Origin: reflect full from #4589

Defer-reason: tangential

## Current State

`plugin/skills/flow/context-handoff.md` picks its branch from the run, not from the caller: "Then take the branch that matches the run, by the same `dispatched` read Step 4 used to build `--next-steps`" (line 33; probe `git grep -n -F -e "by the same \`dispatched\` read" origin/main -- plugin/skills/flow/context-handoff.md` matched on origin/main at 01a50fabe). A run whose `run-state.json` carries `dispatched: true` always takes the Dispatched call branch: stop before the next step and report `OUTCOME: handoff` / `NEXT_STEPS:` for a dispatcher to continue.

On #4589 (run 2026-11-01T190716-record-4589) the dispatched run was orphaned and a human resumed it with a typed `PIPELINE_RUN_DIR=… /claude-tweaks:flow "#4589" build`. After the test gate the gauge printed `over: true` (200,622 of 200,000 tokens) with a handoff path; the `dispatched` read printed `dispatched`, so the session stopped and rendered an `OUTCOME: handoff` block addressed to a dispatcher that did not exist. The human then had to paste the resume line, and the resumed session (still over the cap) hand-split the remainder: review and polish went to a fresh Agent, wrap-up ran in the session because its Review Console needs the human. Neither step is what the file prescribes for this caller.

## Deliverables

1. `context-handoff.md` (and `SKILL.md` Step 4 item 4 where it cites the branch) select the Dispatched call branch only when this agent is itself a dispatcher-launched Task call, not whenever the run is dispatch-bound. A dispatched call's prompt already starts with the `[dispatch-prompt: {run-id} {call}]` marker (#4589, `plugin/bin/lib/dispatch/task-prompt.js`), which is a candidate signal; a session with no such prompt (a human-typed or Routine-typed `/flow`) takes the Top-level run branch.
2. On the Top-level branch for a dispatch-bound run, `--next-steps` and the handed-off steps exclude `wrap-up`, as for any top-level run, so the Review Console stays in the human's session.

## Acceptance Criteria

- [ ] A human-typed `/claude-tweaks:flow` resume of a `dispatched: true` run that crosses the context cap hands its remaining non-wrap-up steps to one fresh Agent and runs `wrap-up` itself; it never renders `OUTCOME: handoff`.
- [ ] A `/claude-tweaks:dispatch` Task call (prompt starting with the dispatch-prompt marker) that crosses the cap still stops and reports `OUTCOME: handoff` / `NEXT_STEPS:` exactly as today.
- [ ] A prose test pins both branch conditions in `context-handoff.md`.

## Release Note

A human resuming a dispatched pipeline run no longer gets stranded with a dispatcher-only handoff block when the session crosses its context cap.
