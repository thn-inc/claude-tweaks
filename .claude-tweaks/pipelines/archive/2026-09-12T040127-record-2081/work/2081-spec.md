# 2081: set-config.js: support writing multiple config.yml levers in one invocation

Filed by wrap-up reflect (light mode, record #1971's run, refs #1971).

## Current State

`bin/set-config.js` writes exactly one `config.yml` lever per invocation (`--key <lever> --value
<value>`). The documented recovery path for an inherited run directory that reached `/flow`'s Step
3 with no `config.yml` yet (`flow/steps-and-gates.md`'s "Adopting an inherited run directory", case
3) requires computing and writing all 13 canonical Manifesto levers before the pipeline can
proceed. Record #1971's own wrap-up run hit exactly that case and needed 13 sequential
`set-config.js` invocations to backfill the Manifesto.

Evidence: run `2026-09-08T115203-record-1971`'s own Step 3 recovery — 13 separate
`node bin/set-config.js --run ... --key ... --value ...` Bash calls to write `mode`,
`scope-creep`, `overlap`, `design-intent`, `leftover-default`, `auto-fix-threshold`,
`review-auto-apply-ceiling`, `tidy-aggressiveness`, `ceremony-profile`, `model-stance`,
`merge-verification`, `design-critique`, `merge-authorization`.

## Deliverables

- [ ] `bin/set-config.js` accepts a batch form (e.g. repeated `--key X --value Y` pairs, or a
      `--from-json <file>` of `{lever: value}` pairs) that validates and writes every pair in one
      invocation, using the same per-lever validation (`validateLever`) it already runs today.
- [ ] The single-pair form (`--key <lever> --value <value>`) keeps working unchanged — this is
      additive, not a breaking CLI change.
- [ ] `flow/steps-and-gates.md`'s case 3 recovery procedure references the batch form once it
      exists.

## Acceptance Criteria

- A caller can write all 13 canonical Manifesto levers via one `set-config.js` invocation instead
  of 13.
- Existing single-key callers (the Ceremony escape hatch, `flow/manifesto.md`'s per-lever writes)
  are unaffected.
