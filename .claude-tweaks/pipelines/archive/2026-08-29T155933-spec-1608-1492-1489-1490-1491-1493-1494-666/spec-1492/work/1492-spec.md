# 1492: Dispatch: bare invocation drains the queue with --budget (next deprecated, interactive pick retired)

Surface: backend

## Overview

Changes `/claude-tweaks:dispatch`'s bare invocation from an interactive batch pick
(`AskUserQuestion` over the authorized queue, grouped by file overlap) to the same headless drain
shape Phase 4 gives `specify`: repeat `next`'s select-and-dispatch loop over ranked authorized
groups until `--budget <n|all>` groups are dispatched or none remain. `next` becomes a deprecated
alias for `--budget 1`; `--batch-size` folds into `--budget` as a second deprecated alias. A human
who wants to choose specific work now names it directly (`#N,#M`) or pastes `overview`'s Dispatch
line, rather than answering an interactive prompt bare invocation used to trigger.

## Non-Goals

- Does not change per-group dispatch mechanics — claim semantics, sequential execution, the
  Auto-merge gate, Settle — any of it. This record only changes *how a group is selected* for
  bare/`next`-shaped invocations; `#N`/`#N,#M,...` (explicit) are unaffected.
- Does not add `--budget` to `/claude-tweaks:sweep` — Phase 7's orchestrator explicitly never
  invokes `/dispatch` at all (self-authorization: dispatch claims and builds).
- Does not change `overview` mode's Dispatch stage rendering beyond removing the word `next` from
  its paste line — the stage's own logic (funnel buckets, batch composition) is unaffected.

## Prerequisites

None internal to this design — independent of Phases 1-3 and 6-7 per the parent design doc's own
dependency graph. `#762`'s shared grammar file (if it has landed via the Phase 4 record) is where
`--budget` should be defined for consistency, but this record does not block on it — it can define
`--budget` locally the same way Phase 4 does if #762 hasn't landed yet, and a later pass folds
both into one grammar file.

## Deliverables

- [ ] `dispatch/SKILL.md` Input table: bare `$ARGUMENTS` (no argument) resolves to the headless
      drain, unconditionally — an interactive (human-present) bare invocation drains immediately
      with no confirmation prompt, identically to a headless firing; there is no separate
      dry-run/confirm affordance. `next`'s select-and-dispatch procedure repeats over ranked
      authorized groups until `--budget <n|all>` groups have been dispatched or the ranked set is
      empty. **Each iteration re-fetches the authorized queue fresh** — a dispatched group's
      records leave it by construction (they're claimed), and a group that fails Settle is also
      removed from/marked ineligible in the same re-fetch (its records carry `bot:blocked` or an
      equivalent settle-failure marker per `sequential-execution.md`'s existing per-group outcome
      handling) — so a Settle-failed group is never re-selected on the next iteration; it still
      counts as one attempted budget unit (AC2) but the loop moves on rather than looping on it.
      Default budget is the existing `dispatch-batch-size` key's value — no new policy key, unlike
      Phase 4's `specify-budget`, since `dispatch-batch-size` already exists. This is a semantic
      narrowing of that key, not merely a reuse: it previously capped a human-picked menu's size
      (browsing volume); it now caps unattended dispatch volume directly — a project that set it
      high for convenient browsing now auto-dispatches that many groups with zero confirmation.

      isn't mistaken for a leftover default.

## Acceptance Criteria

1. Given three authorized file-overlap groups and `--budget 2`, a bare `dispatch --budget 2`
   firing dispatches the top two by priority-then-age ordering and exits reporting the third as
   remaining/not dispatched this run — no `AskUserQuestion` fires.
2. `--budget all` against a five-group authorized queue drains all five sequentially in one
   firing, subject to the existing per-group settle/claim semantics (a group that fails Settle
   still counts as attempted, per Phase 4's "budget counts attempts" convention carried over
   here).
3. `dispatch next` (typed directly) behaves identically to `dispatch --budget 1` — one deprecation
   notice, exactly one group dispatched, unchanged zero-eligible-groups posture.
4. `dispatch --batch-size 3` (typed directly) behaves identically to `dispatch --budget 3` — one
   deprecation notice naming `--batch-size` as the deprecated spelling.
5. A bare `dispatch` invocation with a human present and no `--budget` flag never presents an
   `AskUserQuestion` — it drains up to `dispatch-batch-size` groups directly, matching `next`'s
   existing headless-safe posture now applied to the default bare form too.
6. `overview` mode's Dispatch stage paste line and `refine`'s Next Actions dispatch line render no
   reference to `next`.

## Technical Approach

Identical shape to Phase 4: the loop body is `next`'s existing select-and-dispatch procedure,
completely unchanged in its per-group mechanics (claim, sequential execution, settle). Only the
driver changes — from "call it once" (today's `next`) or "ask a human to pick a batch"
(today's bare) to "call it up to `--budget` times, re-querying the authorized queue before each
call." Reuse `sequential-execution.md`'s existing loop; do not write a second dispatch loop.

## Gotchas

- **This record and Phase 4 are independent but should share one `--budget` vocabulary.** If both
  land in the same window, make sure the flag's semantics (`n` = attempt count, `all` = drain to
  empty) read identically in both records' prose — a reader hitting `specify --budget all` and
  `dispatch --budget all` should not have to check two different definitions.
- **`--batch-size` is now a two-hop deprecated alias** (`--concurrent` → `--batch-size` →
  `--budget`). Do not collapse this into a single alias entry — `deprecated-aliases.md`'s existing
  `--concurrent` row keeps its own removal condition untouched; add a new row for `--batch-size`
  rather than editing the existing one to point past it.
- **Retiring the interactive bare pick is a genuine behavior change for any human relying on it.**
  Say so plainly in this record's own summary/PR description — a human who types bare `dispatch`
  today expecting a menu will instead see groups dispatched immediately. This is the design's
  explicit intent (named directly in the parent design doc's Target Shape table), not an
  accidental regression, but it should not be discovered as a surprise in review.
- **`dispatch/SKILL.md` is at 40,777 bytes** — 183 bytes under the 40,960-byte ceiling. Check
  headroom before adding the drain-mode prose; removing Step 3's interactive-pick text frees real
  space, but verify the net change stays under the ceiling rather than assuming the removal
  covers the addition.
