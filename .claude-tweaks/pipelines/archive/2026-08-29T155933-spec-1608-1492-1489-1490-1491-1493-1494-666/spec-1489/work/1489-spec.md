# 1489: Backlog attention: single human list, refine #N resolver, and --reset-breaker

Surface: backend

## Overview

Makes `/claude-tweaks:backlog attention` the one human-facing list that reads every `needs:*`
marker (the Definition family this record's dependency introduces), plus two non-record rows —
a merge-lane circuit-breaker banner and a tidy-residue row — and gives it a resolver:
`/claude-tweaks:backlog refine #N`, which reads a record's unresolved decision comment and
applies the human's choice in one batch table. This is the authority #825 partially addressed
(removal of `needs:definition`) generalized to the whole `needs:*` family, and it retires the
"human has to remember which command surfaces which marker" friction the design doc's Problem
section names.

## Non-Goals

- Does not fold `backlog grant` into `refine`'s headless posture — that's Phase 3. This record's
  `refine #N` form is scoped to resolving decision comments; the presence-switched headless lane
  selection is a separate, later change to the same file.
- Does not add the tidy-side marker writes the tidy row surfaces — Phase 6 writes those; this
  record only renders the row when `staged/` is non-empty, using whatever run directories already
  exist.
- Does not change `overview` mode — explicitly out of scope per the design doc's Non-goals.

   `Proposed:` line quoted and `/claude-tweaks:backlog refine #{n}` as the launcher.
2. Running `/claude-tweaks:backlog refine #{n}` on such a record and choosing "build it myself"
   leaves the record with no `needs:*` label, exactly one comment carrying a `**Resolved:**` line,
   and no `auto:*` label added; a subsequent headless `refine` worklist fetch (once Phase 3 lands)
   would include this record, since it no longer carries `needs:*`.
3. With the merge-lane breaker tripped, `attention`'s rendered output's first row is the banner,
   before the ranked table; `/claude-tweaks:backlog refine --reset-breaker` asks exactly one
   `AskUserQuestion` and, on Reset, writes exactly one `decisions.md`-shaped log line and no other
   record mutation.
4. With a `*-tidy-standalone*` run directory whose `staged/` holds 3 files, `attention` renders
   one tidy row naming the count 3 and the `tidy --approve` launcher; with `staged/` empty or
   absent, no row renders.
5. `attention`'s empty-state message and the existing Anti-Patterns table (no third-type
   truncation, no separate row per matched type) both still hold — verified against
   `tests/backlog-overview-foldin-no-truncation.test.js`'s sibling convention for a new or
   extended attention-specific test.

## Technical Approach

`refine #N`'s per-record batch table reuses `refine-lanes.md`'s existing lane-rendering shape
(one table, `AskUserQuestion` for apply-all-vs-override) rather than inventing a new interaction
pattern — the difference is scope (one named record instead of the whole queue) and the choice
set (grant/build-myself/park/keep/close/re-authorize instead of priority/grant/flag-back). Do not
duplicate `merge-lane-reset.md`'s question text for `--reset-breaker` — call that file's existing
procedure directly.

### Data / API Surface

- `readBreakerState(cwd)` — existing (`bin/lib/issues/merge-lane-breaker.js`); no signature
  change.
- Comment parse: read every comment on the record matching `^<!-- needs-decision: (\S+) -->`,
  take the last one with no `**Resolved:**` line anywhere in its body as the live proposal; if the
  comment also matches `^<!-- backlog-refine-human-only -->` (PR #1440's own marker, pre-dating
  this record's generalization), treat it as an unmigrated `needs:decision` proposal for
  `backlog-refine` with `{unit}` defaulted to the literal string `backlog-refine` (the old marker
  carries no capture group) — the record itself may still lack the `needs:decision` *label*, so
  `#N`'s own targeted fetch (by number, not by label) is what makes it reachable regardless; this
  fallback is a **temporary compatibility shim with a removal condition**: delete it once no open
  record in the repo carries the old `<!-- backlog-refine-human-only -->` marker (checked via `gh
  search issues` or a one-off audit script at the next minor release after this record ships).

## Gotchas

- **This record depends on the Phase 1 record's label and comment shape existing first** — do not
  start this record's `attention`/`refine #N` work before that record's `needs:decision` label and
  `<!-- needs-decision: {unit} -->` comment format are live; this record's tests would have nothing
  real to fetch against otherwise.
- **PR #1440's comment-only marker predates the label.** If #1440 (or the Phase 1 record's own
  generalization of it) has not yet re-labeled every record #1440 touched, `refine #N`'s comment
  parser should still recognize the old `<!-- backlog-refine-human-only -->` marker as a live
  proposal (see Data / API Surface) rather than silently ignoring pre-migration records. This
  fallback covers `refine #N` (targeted by number) only — `attention`'s own Step 1 fetch discovers
  records by the `needs:*` label, so a pre-migration record with the old comment-only marker and
  no label stays invisible to `attention`'s list until it's re-labeled. Accept this as a transient
  gap bounded by how quickly #1440-era records get re-labeled, not something this record needs to
  separately fix.
- **The breaker banner degrades silently, on purpose** — `merge-lane-reset.md`'s own posture for
  a `readBreakerState` failure is "can't confirm, skip the question, proceed as untripped"; the
  banner row must fail the same way (omit, never render a false-positive tripped state) rather
  than surfacing a raw error to the human running `attention`.
- **`attention-mode.md` is 11,122 bytes** — well under the 40,960-byte ceiling; there's headroom
  for this record's additions without needing to split the file.
