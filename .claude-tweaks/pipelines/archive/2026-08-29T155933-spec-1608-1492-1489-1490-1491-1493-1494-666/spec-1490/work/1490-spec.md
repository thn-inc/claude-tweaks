# 1490: Retire backlog grant mode into refine's presence-switched headless posture

Surface: backend

## Overview

Retires `/claude-tweaks:backlog grant` as a separate mode by folding its exact behavior into
`refine`'s **headless posture** — a presence switch, mirroring `/claude-tweaks:dispatch`'s own
human-present-vs-Routine-fired distinction. The two modes already call the same
`bin/backlog-grant-gate.js` / `grant-gate.js` chain; the only thing that ever justified two modes
was `refine`'s human-only contract, which existed only because its grant half needed a human. Once
the labeling lanes (Priority/Related/Flag-back/mechanical dependency repair) run with the
identical zero-click semantics `refineAutoApply` already exercises today at
`autonomy: unattended` — that precedent is about the *labels being applied without a confirm
click*, not about *no human being present in the session*; this record extends it to a genuinely
new posture (a Routine or `/sweep` firing with nobody present at all), stated as an explicit,
accepted risk rather than a settled one. What makes the extension safe is that nothing about
*what* gets authorized changes — the grant half runs in the same headless firing without anyone
gaining a new authorization path: the two policy keys
(`autonomy: unattended` + `grant-origination-enabled`) and `grant-gate.js`'s gate chain are
unchanged.

## Non-Goals

- Does not change `grant-gate.js`'s gate chain, the two-key opt-in, `fleet-daily-grant-cap`, the
  veto window, or the merge-lane breaker's trip conditions — explicit non-goal in the parent
  design doc.
- Does not build `/claude-tweaks:sweep` — that's Phase 7, and it's what will actually *invoke*
  `refine`'s headless posture outside a scheduled Routine.
- Does not change the Re-authorize lane, `--reset-breaker`, or the `#N` form (Phase 2) — those
  stay human-present-only exactly as designed there.

## Acceptance Criteria

1. A headless `refine` firing (no human present) at `autonomy: supervised` applies
   priority/Related label changes and originates no `auto:*` label — identical to today's
   `refineAutoApply` behavior for the non-grant lanes, now reachable with nobody present.
2. A headless `refine` firing at `autonomy: unattended` + `grant-origination-enabled: true`
   grants exactly the set `backlog grant` would have granted against the same candidate pool. The
   `<!-- grant-mode-audit: -->` comment format is (and was already, in `grant-mode.md`) a pure
   function of the candidate record's own state plus the gate chain's verdict — never of the
   invocation context (no session id, timestamp-of-invocation, or run id embedded) — so
   "byte-identical" here means exactly that: the same record, the same gate verdict, the same
   comment, regardless of whether `refine`'s headless posture or the old `grant-mode.md` produced
   it. Verified by re-pointing (not rewriting) `tests/grant-mode-inprogress-pin.test.js` and the
   `bin-lib/backlog-grant-gate/` suite against the new call path, with identical
   `fleet-daily-grant-cap` accounting.
3. `evals/scenarios/backlog-refine-permission-matrix-compliance.yaml` still passes unmodified —
   the local-files stop and the never-self-grant rule hold identically under the new Preflight
   paragraph.
4. `grep -rn "backlog grant" plugin docs README.md` returns only `deprecated-aliases.md`'s own
   entry and its removal-condition text — no other file names the retired mode.
5. `backlog grant` (typed directly) still originates the exact grant set it would have before this
   record, emits exactly one deprecation-notice line, and `grant-mode.md` no longer exists on
   disk.
6. `routine/fleet.md` row 10's provisioned Routine, unchanged in schedule, now runs the labeling
   lanes even when the two-key threshold isn't met — verified by a firing at `supervised` producing
   a non-empty `decisions.md` (priority/Related activity) rather than the single
   "ceiling gate not satisfied — nothing to do" line it produces today.

## Technical Approach

This is a **move-and-generalize**, not a rewrite: `grant-mode.md`'s Steps 0-5 are already correct
and already tested. The task is (a) relocate that content under a presence-gated branch of
`refine-mode.md`'s flow, (b) wire the presence switch itself, and (c) sweep every reference. Do
not re-derive the ceiling gate, the breaker sweep, the gate chain, the audit-comment format, or
the cap-tracking logic from first principles — copy them verbatim from `grant-mode.md` and adjust
only what genuinely differs (the entry point, and the fact that the labeling lanes now run
alongside the grant lane in the same firing rather than being a separate mode's exclusive job).
