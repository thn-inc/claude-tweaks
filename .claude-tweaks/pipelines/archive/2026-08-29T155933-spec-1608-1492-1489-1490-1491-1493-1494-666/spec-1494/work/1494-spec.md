# 1494: Add /claude-tweaks:sweep orchestrator and parent-invocation contracts on tidy/specify/refine

Surface: backend

## Overview

Adds `/claude-tweaks:sweep`, a thin orchestrator that runs `/claude-tweaks:tidy` (auto mode),
`/claude-tweaks:specify` (bare, drain), and `/claude-tweaks:backlog refine` (headless posture) in
that order under one run directory and one `decisions.md`, closing out with `attention`'s render
and a recommended `/claude-tweaks:dispatch` line. This is the "run everything cheap and frequent
that doesn't need a human, in one command" the whole design exists to deliver — everything before
this record made the three units individually safe to run headlessly; this record is what
actually chains them. It never claims, builds, or merges, which is exactly what makes it a legal
parent of a grant-writing unit (`refine`'s headless posture) under this codebase's
self-authorization rule.

## Non-Goals

- Does not include the four health-sweep skills (code-health/docs-health/journey-health/
  harness-health) — those are an audit, not hygiene; a human triggers them deliberately.
- Does not invoke `/claude-tweaks:dispatch` — dispatch claims and builds, and a skill that claims
  or builds may never headlessly parent a grant-writing unit (the reasoning this whole design's
  Phase 3 record exists to protect). `sweep`'s close-out recommends the dispatch command; it never
  runs it.
- Does not ship a `routine-template.yml` — the cloud fleet keeps its own composition (rows 9-12 of
  `fleet.md`'s table); `sweep` is the on-demand, single-session form of a similar idea, not a
  fleet replacement.
- Does not change `overview` mode, or any of the three units' own individual argument grammars
  beyond the parent-signal contract this record adds to each.

## Current State

- No skill in this plugin composes tidy, specify, and backlog refine into one invocation today —
  the only existing composition is the cloud fleet's independently-scheduled rows (`fleet.md`'s
  composition table, rows 9, 10, 12), which run on different cadences and share no run directory.
- `tidy/SKILL.md`'s Component-Skill Contract states: "If a future parent skill ever wraps `/tidy`
  ... the parent must update this contract; until then, treat parent invocation as not
  applicable." No parent contract exists yet.
- `specify/SKILL.md`'s bare-drain form (Phase 4) and `backlog/refine-mode.md`'s headless posture
  (Phase 3) both render their own `## Next Actions`/report blocks even when invoked headlessly by
  a Routine — there is no notion of "invoked as a component step by a sibling skill" distinct from
  "invoked directly by a human or a Routine."
- `_shared/record-queue-fetch.md`'s session-scoped record snapshot has a documented invalidation
  rule (any create/edit/close call invalidates it) but no consumer today relies on that
  invalidation happening *between* two skills reading the queue in the same session — every
  existing single-skill invocation reads the snapshot once per session naturally.
- `docs/skill-graph.md` has no `## sweep` section; `help/reference-card.md`,
  `README.md`'s artifact-lifecycle diagram, and `docs/plugin-structure.md`'s skill table don't
  list it.
- `evals/` has no scenario asserting a skill never invokes `/flow`, `/build`, or `/dispatch`.

## Acceptance Criteria

1. Given a queue with one stale record (tidy-eligible for Delete/Defer), one unshaped-but-eligible
   record, and one scored-and-shaped-but-ungranted record (grant-eligible under the active
   ceiling), a single `/claude-tweaks:sweep` invocation ends with: the stale record disposed or
   marked per tidy's active aggressiveness tier, the unshaped record either `ready` or
   `needs:definition`, the grantable record carrying `auto:build`, exactly one run directory,
   exactly one `decisions.md`, zero `AskUserQuestion` calls anywhere in the run, and a rendered
   close-out whose first block is `attention`'s render and whose Next Actions recommends
   `/claude-tweaks:dispatch`.
2. A test that stubs `record-snapshot.js`'s snapshot file between steps proves the invalidation
   fires — `specify`'s drain step observes the record state tidy's step left behind, not a
   pre-tidy snapshot; same proof between `specify`'s step and `refine`'s step.
3. The new eval scenario passes: no input combination to `sweep` results in an invocation of
   `flow`, `build`, or `dispatch`.
4. `tidy`, `specify` (drain mode), and `backlog refine` (headless posture), each invoked directly
   by a human or a Routine (not via `sweep`), render their own `## Next Actions`/report exactly as
   before this record — the parent-contract suppression fires only when `$PIPELINE_RUN_DIR` was
   set by `sweep` specifically, never as a side effect of any other headless posture.
5. `docs/skill-graph.md`'s `## sweep` section and the three children's reciprocal rows exist;
   `help/reference-card.md`, `README.md`, and `docs/plugin-structure.md` each list `sweep`.

## Technical Approach

`sweep` is deliberately thin — a sequencer, not a reimplementation of any of the three units' own
logic. Each step is a direct invocation of the existing skill under a shared `$PIPELINE_RUN_DIR`,
the same composition pattern `/claude-tweaks:flow` already uses for build/test/review/polish/
wrap-up, scaled down to three steps with no HARD-GATE stops (none of the three units has one that
applies outside its own internal logic). The close-out's call into `attention` is a direct
invocation of that mode's existing render, not a re-derivation of its fetch/merge/rank logic.

### Data / API Surface

- No new label, no new policy key beyond forwarding `--budget`/`--scope` to existing consumers.
- Run directory shape: `{ISO}-sweep-standalone/` with `decisions.md`, mirroring every other
  standalone-auto run directory's contract (`_shared/pipeline-run-dir.md`).
- Parent-signal detection in the three children: an explicit `--source sweep` flag, forwarded by
  `sweep` on every call — the same `--source <caller>` mechanism #1490 introduces for `refine`'s
  presence switch, and the concrete realization of what `tidy`'s Component-Skill Contract already
  anticipated in the abstract ("a future parent skill ever wraps `/tidy`").

## Gotchas

- **This record cannot build before Phases 3, 4, and 6 all exist** — `sweep`'s three steps call
  capabilities (headless `refine`, drain `specify`, tidy's residue markers) that don't exist
  without them. Confirm all three are merged, not just filed, before starting.
- **The "no `AskUserQuestion` anywhere" acceptance criterion is the load-bearing one.** If any of
  the three units' headless postures have a code path that still surfaces a question (a gate this
  design doc's earlier phases missed), `sweep` will hang on a firing with nobody present to answer
  it — this is exactly the failure mode the design's Problem section names for a bare `next`-form
  Routine firing today, and `sweep` must not reintroduce it at the orchestration layer.
- **Don't restate `attention`'s render logic inline.** `sweep`'s close-out calling `attention`
  directly (rather than re-deriving its fetch/merge/rank steps) is what keeps the two surfaces
  from drifting apart — any future change to `attention`'s row types or ranking should need no
  corresponding edit in `sweep`.
- **The eval scenario is the actual enforcement of the self-authorization invariant** — the prose
  Non-Goal ("does not invoke dispatch") is not enough on its own; write the eval so a future edit
  that adds a `dispatch` call to `sweep` fails CI, not just a doc review.
