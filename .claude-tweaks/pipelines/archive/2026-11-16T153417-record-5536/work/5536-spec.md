# 5536: Remove dead code from the four health CLIs

Surface: infra
Risk-flags: none

## Overview

The four health CLIs (`code-health.js`, `docs-health.js`, `harness-health.js`, `journey-health.js`) and `lib/code-health/` carry code that no skill, hook or CLI reaches: four `main()` shims whose only callers are 15 lines of one test file, a `pull-issues` subcommand no skill has invoked since 2026-07-10, a frozen v1 issue payload "kept only so its own test file can assert this historical shape", the v1 branch of the fingerprint function, one flag alias that occurs once in the repository, and one option no caller passes.

This is unit 1.3 of the 2026-11-15 audit simplification design. `pull-issues` is removed outright rather than through a deprecation cycle: no shipped prose has invoked it since July, so no installed build can hold prose that calls it.

**Complexity:** Medium
**Estimated tasks:** 7

- Merging code-health's `decide()` into `health-core`, or sharing the `run()` wiring (#5440). Both belong to Phase 4 of the same design.
- `toIssuePayload` in `docs-health.js`, `harness-health.js`, `journey-health.js` and `health-core/validate-findings-dispatch.js`. That name is live there; only the v1 function in `lib/code-health/issue-payload.js` goes.
- The unused `listSlices` import at `code-health.js:16`.

## Release Note

Removed unused commands, flags and legacy code paths from the health sweep tools.

## Technical Approach

Delete in dependency order: callers first (the test's `main` calls, the dispatch branch), then the functions, then the modules. The legacy marker reader is the one thing kept, because closed and open issues filed before the v2 payload still carry the old marker (for all three health skills) and dedup must keep matching them. No new guard is added to `fingerprint`: `validate-finding.js:43`, which requires `criterion`, is the guard, and a call without `criterion` is a caller bug. The CLI is internal to the health skills; its only documented caller, the skill prose, was removed on 2026-07-10.
