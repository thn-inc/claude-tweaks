# 5967: Read transcript usage through one shared max-per-message.id reader

# Reflect — staged finding 1

**Category:** tangential

Origin: reflect hindsight from #5914

Defer-reason: tangential

## Current State

Three modules each implement the transcript usage rule "take the maximum of each usage field per `message.id`": `plugin/bin/lib/timing/transcript.js` (`readUsage`, ~line 233), `tools/review-replay/score.js` (lines 81-87) and `tools/pipeline-cost-report/spend.js` (~line 133, added by #5914).

#5914 could not reuse `readUsage` because it returns neither `message.id` nor the `cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens` split, and its spec forbade any `plugin/` change.

Probe: `git grep -n -F -e 'ephemeral_5m' 'origin/main' -- 'plugin/bin/lib/timing/transcript.js' 'tools/review-replay/score.js'` matched nothing (2026-11-19).

When Claude Code changes the transcript usage shape, the three readers can drift apart and the spend, review-replay and timing figures stop agreeing.

## Deliverables

- [ ] `readUsage` (or a sibling export in `plugin/bin/lib/timing/transcript.js`) additively exposes each row's `message.id` and the 5-minute / 1-hour cache-write split, with no change to the fields its current callers read
- [ ] `tools/pipeline-cost-report/spend.js` and `tools/review-replay/score.js` read usage through it via a `pluginRoot` dep, and their own max-per-`message.id` code is removed

## Acceptance Criteria

1. `grep -n "Math.max(p.output" tools/review-replay/score.js` and the per-`message.id` max loop in `tools/pipeline-cost-report/spend.js` return nothing
2. The existing `tests/pipeline-cost-report/*.test.js`, `tests/review-replay/*.test.js` and timing transcript tests pass unchanged, AC1 of #5914 (one `message.id` on three lines counted once at the max) included

## Release Note

Transcript usage is read by one shared reader, so the cost report, review replay and timing figures agree.
