# 2028: console-resolve.js's readMembers fallback misses multi-spec parent run dirs (manifest.yml, spec-*/work/)

Surface: infra

## Current State
`plugin/bin/lib/console/resolve.js`'s `readMembers` (the `unattended` Review Console resolver behind `bin/console-resolve.js`, #1932) takes the member list from `wrap-up-pack.json`'s `inputs.records` when a pack exists, else scans `{runDir}/work/*-spec.md` headers only. `plugin/bin/lib/wrap-up/pack.js`'s `resolveRecords` is the producer of that same list and climbs a three-rung ladder: the run dir's own `work/` headers, the worktree's mirror of the run dir (`worktreeMirror`), then a parent multi-spec run's `manifest.yml` ids plus every `spec-*/work/` header (`source: 'manifest'`). `resolveRecords` and `headerRecords` are module-private — `pack.js` exports only `gatherPack`, `resolveInputs`, `wrapProbe`, `parseLedger`, `PROBE_NAMES` — so `readMembers` carries a hand-copied first rung and nothing else.

Consequence: against a multi-spec parent run dir (headers under `spec-{a}/work/`, `spec-{b}/work/`) at any point where `wrap-up-pack.json` is absent or unparseable, `readMembers` returns `[]`, `readSnapshot` skips `readGrants`, and `resolveAll` resolves the merge half to `leave-open` with reason `members-unresolved` even when every member carries `auto:merge`. The single-spec fallback (`{runDir}/work/`) works today and must keep working byte-for-byte.

Both modules read through the same `deps` shape (`readFile`, `readdir` — `console-resolve.js` wires `fs.readFileSync`/`fs.readdirSync` with a catch-to-`[]` readdir, identical to `pack.js`'s default deps), so the ladder can be shared rather than copied a second time.

## Deliverables
- [ ] `plugin/bin/lib/wrap-up/pack.js` exports `resolveRecords` (and `headerRecords`) alongside the existing exports; no behavior change inside `pack.js`.
- [ ] `readMembers` in `plugin/bin/lib/console/resolve.js` replaces its inline `work/` scan with a call to `resolveRecords(deps, runDir, worktree)` and returns its `records`, keeping the pack-first branch (`inputs.records` wins whenever it is non-empty) unchanged.
- [ ] The worktree argument for the second rung comes from `{runDir}/run-state.json`'s `worktree` string when present (read via the existing `readJson`), else `null` — and `worktreeMirror` in `pack.js` returns `null` for a non-string worktree instead of throwing from `path.join`, so the console path with no run-state file degrades to rungs one and three.
- [ ] Regression tests in `tests/bin-lib/console/resolve.test.js` using its existing `fixture` helper (extend it with `manifest`/`specHeaders` options): (a) a multi-spec parent run dir with no `wrap-up-pack.json`, `manifest.yml` listing two spec ids and headers under `spec-*/work/`, resolves `members` to those ids and no longer yields `members-unresolved`; (b) the existing single-spec header case and the pack-wins case stay green unchanged.
- [ ] One export-shape assertion in `tests/bin-lib/wrap-up/pack.test.js` (or its conformance sibling) that `resolveRecords` is exported and still reports `source: 'manifest'` for the parent-run fixture, so the shared ladder cannot silently regress to private again.

## Acceptance Criteria
1. With no `wrap-up-pack.json` and members only under `spec-*/work/` (plus `manifest.yml` ids), `readSnapshot(...).members` equals the sorted unique union `resolveRecords` reports for the same run dir.
2. With no pack and headers under `{runDir}/work/` only, `members` is byte-identical to today's output (same order, same de-duplication, `record:` frontmatter still wins over the filename).
3. With a non-empty `inputs.records` in the pack, `members` is taken from the pack and the ladder is never consulted.
4. `resolve.js` contains no second copy of the header-scanning regex after the change; `pack.js`'s `resolveRecords` is the only implementation of the ladder.
5. `readMembers` never throws on a run dir with no `run-state.json` or a `run-state.json` without a `worktree` string.
6. `npm test` is green.

## Technical Approach
Export, don't copy: the drift exists because the first rung was transcribed into `resolve.js`; adding the third rung by transcription would leave the second rung (worktree mirror, #1930 review C1) missing and set up the next drift. `resolveRecords` already returns `{ records, source }`; `readMembers` keeps its pack-first branch and delegates the fallback:

```js
const state = readJson(deps, path.join(runDir, 'run-state.json'));
const worktree = state && typeof state.worktree === 'string' ? state.worktree : null;
return resolveRecords(deps, runDir, worktree).records;
```

`pack.js` requires `../flow/manifest` for `parseManifestYaml` already; `resolve.js` requiring `../wrap-up/pack` is a one-way dependency (pack.js does not import the console module), so no cycle.

### Key Files
- `plugin/bin/lib/console/resolve.js` — `readMembers` (fallback scan to replace), `readJson`/`readText` helpers, `readSnapshot` (the `members.length` guard around `readGrants`).
- `plugin/bin/lib/wrap-up/pack.js` — `headerRecords`, `worktreeMirror`, `resolveRecords`, `module.exports` line.
- `plugin/bin/console-resolve.js` — `resolverDeps` wiring (`readFile`, `readdir`); no change expected.
- `tests/bin-lib/console/resolve.test.js` — fixture helper writes `wrap-up-pack.json` and `work/{n}-spec.md`; extend for `manifest.yml` + `spec-*/work/`.
- `tests/bin-lib/wrap-up/pack.test.js` — the `resolveInputs (c)` parent multi-spec case (#1930 review C1) is the ladder's existing coverage; add the export assertion beside it.

## Gotchas
- `worktreeMirror(runDir, null)` throws today (`path.join` on `null`), but only `resolveRecords` calls it and today's sole caller always passes a string; the null-guard is what makes the console path safe, so it is part of this change, not an optional nicety.
- `readMembers` deliberately ignores the pack when `inputs.records` is empty (`fromPack.length` check) — keep that: an empty pack list falls through to the ladder, as before.
- `pack.js`'s `readText` and `resolve.js`'s `readText` are byte-identical helpers; do not try to share them — the deps object is what is shared, and each module's helper stays with it.
- `manifest.yml` is parsed with `parseManifestYaml` from `bin/lib/flow/manifest.js`; the fixture needs a `multispec.specs[].id` shape, not a flat list.
