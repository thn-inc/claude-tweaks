# 5830: A per-run config or an arbitrary --run directory can switch off the human-acceptance park gate

Verified-as-of: 3f9d5d0fa2125c54e3ba50716655f46e2f66d4b7

Origin: /claude-tweaks:release v6.172.0 release-gate review (run 2026-11-16T184554-release-standalone)

Defer-reason: pre-existing-outside-diff

## Current State

Two findings by lens 3b (security), each confirmed independently by a fresh tiebreak agent. Together they leave the human-in-control switch (#4608) reachable from a per-run file.

1. **`control-mode` can be set per run.** `plugin/bin/lib/policy-schema.js:191` declares `control-mode` without `policyOnly`, so the resolver applies a run's `config.yml` on top of `policy.yml` for it (the overlay is skipped only for `policyOnly` rows, `policy-schema.js:702`). `accept-park.js` `parked --run` (line 362) then prints `not-parked` and exits 5 before reading any labels, and `plugin/bin/lib/driver/merge.js` (`acceptPark`, line 1039) proceeds to `decide`. A record already parked for local acceptance can then merge with no human accept. The comment in `accept-park.js` accepts that result only for control mode turned off project-wide, not for a per-run override. The tiebreak judge notes two limits on the original finding: `autonomy` (line 189) and `auto-merge-max-lines` are not `policyOnly` either, so "every other key is" overstated it, and a run config is written by the run's own agent, which keeps the exposure low.
2. **`--run` is not checked to be a pipeline run directory.** `resolveTarget` (`plugin/bin/lib/log-decision/append.js:88-111`) checks only that the directory exists and that its nearest git root is the main checkout. `plugin/bin/queue-pull.js:200` and `accept-park.js` `anchoredRun` (line 226) both use it, so a path such as `plugin/` passes. AUTO lines then go into a `decisions.md` in a non-run directory, and in `accept-park.js` a `config.yml` in that arbitrary directory feeds the control-mode overlay (`readPolicySources`, line 297). Only the caller's own mistake triggers this.

## Deliverables

- Decide whether `control-mode` belongs to the keys a run config may not loosen (the convention at `policy-schema.js:91`), and mark it `policyOnly` if so; record the decision in the schema if not.
- Make the shared run-directory guard require that the directory sits under `.claude-tweaks/pipelines/`, so every consumer (`queue-pull.js`, `accept-park.js`, the log writers) gets the check from one place.

## Acceptance Criteria

- A test sets `control-mode: off` in a run `config.yml` and asserts `accept-park.js parked --run` still reads the project-level value (or the documented decision holds).
- A test passes a directory outside `.claude-tweaks/pipelines/` (for example `plugin/`) as `--run` to `queue-pull.js` and to `accept-park.js` and asserts each refuses it.
- Existing run-directory resolution tests still pass.

## Release Note

A per-run config can no longer switch off the human-acceptance park gate, and the park and queue-pull commands now refuse a --run directory that is not a pipeline run directory.

## Technical Approach

Put the pipelines-path check in the shared `resolveTarget` guard rather than in each CLI. Check `_shared/pipeline-run-dir.md` first, because other callers rely on its current anchoring rules.
