# 5863: Queue pull: an origin HEAD branch of `(unknown)` excludes every named target as target-missing

Origin: ledger resolve gate

Defer-reason: genuinely-larger

## Current State

With no `integration-branch` policy key, the queue pull reads the integration branch from the `HEAD branch:` line of `git remote show origin` (`plugin/bin/lib/dispatch/queue-pull.js`, the reader below the `git remote show origin` comment; fence line 382 of `plugin/skills/dispatch/queue-pull-script.md`). When the command succeeds but the remote HEAD is not set, git prints `HEAD branch: (unknown)`. The branch is then `(unknown)`, the ref is `origin/(unknown)`, and the target-missing pass finds every named target absent at that ref: each record naming a file is excluded as `target-missing` and gets a staged Close proposal.

#5305 fixed the neighbouring case only: an empty branch (a failed `git remote show origin`) now skips the pass with one `Warning: target-missing pass skipped — …` line. Its Plan Review Clarification kept `(unknown)` out of scope. Found by #5305's final build review (refs #5305).

## Deliverables

- [ ] A branch value that does not name a resolvable `origin/` ref (`(unknown)` included) takes the same skip-with-Warning path as the empty branch, in the module and, while it still exists, the fence.

- [ ] A test (in-process, plus a parity row while the fence exists) that feeds `HEAD branch: (unknown)`.

## Acceptance Criteria

1. With `git remote show origin` printing `HEAD branch: (unknown)` and no `integration-branch` key, the pull prints the target-missing skip Warning, excludes no record as `target-missing`, and stages no Close proposal.

2. That test fails with the fix reverted.
