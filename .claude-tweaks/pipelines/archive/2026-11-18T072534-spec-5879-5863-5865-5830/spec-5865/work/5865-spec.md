# 5865: Queue pull (files transport): a dependency the agent cannot read is left out of the dep-freshness file with no message

Origin: ledger resolve gate

Defer-reason: needs-human-decision

## Current State

`plugin/skills/dispatch/mcp-transport.md`'s `--dep-freshness` bullet says of the agent-written `dispatch-dep-freshness.json`: "a number `issue_read` cannot read is left out". The queue pull's cache write-back (`runWriteBack` in `plugin/bin/lib/dispatch/queue-pull.js`) then persists a dependency-freshness signal that is missing that dependency, and a later pull can hit the queue-order cache without the dependency ever being re-checked. Blocking is already fail-closed for the same dependency: the `--verified-open-deps` file lists a dependency whose `issue_read` fails as open (#5311), and #5408 counts an omitted number as open unless the freshness file shows it closed. Only the cache write-back and the missing Warning remain.

#5310 fixed the gh transport's dependency-freshness search (one Warning per failed search, no cache write-back after a failed write-back search, via `state.depFreshFailed`). Its plan review settled that record as gh-only, so the files transport still drops an unreadable dependency silently (refs #5310).

**Decision (maintainer, 2026-11-18): fail closed.** The agent writes an explicit entry for a dependency it cannot read, and the pull treats that dependency as open, warns once, and persists no queue-order cache.

## Deliverables

- [ ] `mcp-transport.md`'s `--dep-freshness` bullet: for a number `issue_read` cannot read, the agent writes an entry `{"number": N, "state": "unreadable"}` instead of leaving the number out.
- [ ] `plugin/bin/lib/dispatch/queue-pull.js`, files transport: an `unreadable` entry in the dependency-freshness data sets `state.depFreshFailed`, prints one Warning naming each such number, and is never counted as closed (the #5408 `closedDependencyNumbers` rule already ignores a non-`closed` state; a test pins that).
- [ ] A pull that sets `state.depFreshFailed` writes no queue-order cache, as on the gh transport.

## Acceptance Criteria

- A files-transport pull whose `--dep-freshness` file holds `{"number": 8000, "state": "unreadable"}` prints exactly one Warning naming #8000, writes no queue-order cache file, and does not count #8000 as closed (a record that depends on #8000 stays excluded as blocked when #8000 is also absent from the verified-open-deps file).
- The same pull with #8000 shown `closed` writes the cache and prints no such Warning.
- A file with an `unreadable` entry for one dependency and `closed` entries for the others writes no cache; the others are still counted closed.
- The new tests were shown to fail against the unfixed module (revert the change and see them red).
- `mcp-transport.md` states the `unreadable` entry shape, and `plugin/skills/dispatch/SKILL.md` stays at or below `RAIL_BYTES`.

## Release Note

A gh-absent `/claude-tweaks:dispatch` queue pull no longer caches a queue order computed without a dependency it could not read.
