# 3900: hooks: resolve 3 accumulated below-floor digest findings

Surface: infra

**Related:** #1426, #3901, #3902, #3903, #3904

## Current State

The materiality-floor digest (#1426) promoted three below-floor findings in the `hooks` area into this record. Each was verified against `origin/main` at shaping time:

1. **Delete-only push exemption rejects the `git -C` form.** `DELETE_ONLY_PUSH_ALLOWLIST` in `plugin/bin/lib/hooks/pre-tool-use.js` (the #658 grammar, used by `isDeleteOnlyPush` at the push-exemption check) is anchored `^\s*git\s+push\s+…`, so it admits exactly `git push <remote> --delete <branch>` (or `:branch`). The `git -C <path> push <remote> --delete <branch>` form, which worktree sessions use as standard, is denied. The gate message's `gh api -X DELETE` fallback is the only retry path. (Digest provenance: `2026-08-24T183516-tidy-followups-standalone`.)
2. **The git-discipline guard matches git-like phrases inside prose arguments.** A plain non-git command, a `bin/log-decision.js` call, was denied because its `--text` string contained the substring `git show` inside a sentence. The guard pattern-matches command text rather than parsing the actual command being invoked. (Digest provenance: `2026-09-13T230428-record-2271`.)
3. **`runGit` trims stdout, which corrupts `-z` output.** `plugin/bin/lib/hooks/git-exec.js` returns `stdout.trim()`, so a NUL-separated (`-z`) reader built on it loses leading whitespace on its first path. Four `-z` readers call `runGit` today: `pre-tool-use.js` (`diff --cached --name-status -z`), `worktree-reap.js` (`diff --name-only -z`), `reconcile/archive-merged.js` (`ls-files -z`, the `archiveRunDir` guard) and `sweep-stray-run-dirs.js` (`ls-files -z`, `hasTrackedWork`). No live reader is hit yet, because every affected path so far starts with a non-space character. (Digest provenance: `2026-10-20T134331-record-3651`.)

## Deliverables

1. The delete-only push exemption admits `git -C <path> push <remote> --delete <branch>` (and the `:branch` refspec form) with the same strictness as the bare form, still denying anything with extra arguments, chaining, or a non-delete push.
2. The git-discipline guard no longer denies a command solely because a quoted argument's prose contains a git-like phrase. A genuine git invocation is still caught.
3. `-z` readers receive untrimmed stdout from `runGit`, or an equivalent no-trim path, so a leading-whitespace first path survives. Callers that rely on today's trimming keep it.
4. Each item is fixed, or explicitly ruled won't-fix with a one-line reason in the closing PR.
5. Each of the three promoted digest entry lines in #1426 carries `→ #3900`.

## Release Note

Worktree sessions can delete remote branches with `git -C`, the worktree guard no longer trips on git-like words inside command text, and git path lists keep leading spaces.

## Technical Approach

1. Extend `DELETE_ONLY_PUSH_ALLOWLIST` with an optional `-C <quoted-or-bare-path>` group between `git` and `push`, reusing the existing `CQ_ARG` token grammar so path quoting follows the same rules. Keep the default-deny-by-construction shape: the whole command must match.
2. Locate the matcher that flagged `git show` in the log-decision `--text` argument. The `pre-tool-use-gate-exemptions` project skill documents how this file's gates parse commands. Make it ignore content inside quoted arguments of a non-git leading command, so it judges the invoked program rather than the raw string.
3. Add an opt-out from trimming to `runGit`/`runGitAsync` (for example `opts.raw` or `opts.noTrim`), or a sibling helper, and switch the four `-z` callers to it. Prefer the additive option over flipping the default, since many callers parse trimmed output.

### Key Files

- `plugin/bin/lib/hooks/pre-tool-use.js` — `DELETE_ONLY_PUSH_ALLOWLIST`/`isDeleteOnlyPush`; the git-phrase matcher; its own `-z` `runGit` call
- `plugin/bin/lib/hooks/git-exec.js` — `runGit`/`runGitAsync` trimming
- `plugin/bin/lib/hooks/worktree-reap.js` — `-z` caller
- `plugin/bin/lib/reconcile/archive-merged.js` — `-z` caller (`archiveRunDir` guard)

- `tests/` — the existing `pre-tool-use` and `git-exec` suites gain the regression tests
