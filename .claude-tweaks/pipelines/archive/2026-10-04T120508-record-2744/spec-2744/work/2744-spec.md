## Original request

Upstream defect report — `verify.js --changed-files` returns an empty set when the runner stamp sits at HEAD; `impeccable-cli` pin 3.6.0 vs installed 4.1.0

Component: `bin/verify.js` (`--changed-files`), `skills/test/SKILL.md` pipeline story selection, `skills/design-wrapper/impeccable-cli.md` (pin)
Kind: defect (two related)
Version: claude-tweaks 6.126.0

## Symptom

(1) After Common Step 5 stamped verification at HEAD, `/test`'s pipeline story selection calls `verify.js --changed-files --integration-branch develop`; the runner uses the stamp's own sha as the base, so the changed set is `[]` and the selection rule reads "zero matches → web surface → run the full story set" — the opposite of what the diff warrants. The record's own range (plan commit..HEAD) intersected `source_files` for 4 of 15 stories; the controller had to compute that by hand.
(2) `impeccable-cli.md` pins the CLI at 3.6.0 and states an off-pin CLI fails the contract test, while `npx impeccable --version` resolves 4.1.0 on this machine; `detect --json` still returned the documented array shape, so the gate ran, but a stale pin turns every run into a documented contract breach.

## Expected

(1) `--changed-files` should fall back to the record's materialized range (or `merge-base(integration-branch)..HEAD`) whenever the stamp sha equals HEAD, instead of returning an empty set; the story-selection rule should treat an empty set from that cause as "unknown", not "none". (2) Bump or widen the `impeccable-cli` pin (4.1.x parses identically for `detect --json`).
