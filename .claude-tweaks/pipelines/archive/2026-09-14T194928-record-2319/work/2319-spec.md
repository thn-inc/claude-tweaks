# 2319: compose-subject CLI hardening: distinct exit code for an uncomposable record, timeout headroom, firstSentence abbreviations

Origin: ledger resolve gate

Defer-reason: needs-human-decision

## Current State

Three review minors on `plugin/bin/lib/compose-subject.js` from #2251 review, each needing a maintainer call rather than a mechanical fix: (1) exit code 1 covers both a malformed invocation and an uncomposable record (no resolvable Type, `breaking` with no `## Breaking Change` section) — a distinct code would let a merge site park a shaping defect instead of treating it as a bad call, but the Split-1/2 vocabulary (`resolve-blockers.js`, `fetch-sub-issues.js`) reserves 1/2/3 and a new code must be documented per gh-api-module-pattern; (2) `GH_TIMEOUT_MS = 5000` is the single-call convention but a slow `gh issue view` at merge time becomes exit 3 — widening needs a stated reason beside it; (3) `firstSentence` cuts at the first `.` followed by whitespace, so an Overview opening with `e.g. ` or `v6.34. ` truncates early.

## Deliverables

Decide and document: a fourth exit code (e.g. 4 = uncomposable record) in the module header and USAGE, with the six merge-site fences branching on it, or an explicit note that 1 stays overloaded.

Decide the timeout: keep 5000 with a comment, or widen with a stated reason per gh-api-module-pattern.

Decide `firstSentence` handling for abbreviations and version numbers, or document the heuristic as accepted.

Tests for each decision that changes behavior.

## Acceptance Criteria

Each of the three items has either a behavior change with a pinning test or a header comment recording the decision.

`tests/bin-lib/compose-subject.test.js` and `tests/merge-subject-composer-conformance.test.js` pass.
