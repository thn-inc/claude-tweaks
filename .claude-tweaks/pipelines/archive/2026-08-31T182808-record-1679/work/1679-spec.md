# 1679: reconcile: dedup remaining hand-duplicated sync/async primitive pairs (ghApi/ghApiAsync, resolvePrState/resolvePrStateAsync)

Defer-reason: pre-existing-outside-diff

## Current State

#1652 (this session, in progress) deduped two hand-duplicated sync/async primitive wrapper pairs — `runGit`/`runGitAsync` (`plugin/bin/lib/hooks/git-exec.js`) and `ghHealthCheck`/`ghHealthCheckAsync` (`plugin/bin/lib/reconcile/preflight.js`) — by extracting a shared `runClassified`/`runClassifiedAsync` try/execute/catch scaffold into `plugin/bin/lib/shared-primitives.js`, with each pair's own `buildSuccess`/`buildFailure` shaping functions defined once and reused by both twins.

#1652's own final whole-branch review (opus, 2026-08-29) independently found two more pairs following the exact same shape, in files #1652's diff never touches:
- `ghApi` / `ghApiAsync` — `plugin/bin/lib/reconcile/release-merged.js:87` and `:138`. Retyped try/catch, retyped { stdout, failure } shaping, retyped `classifyGhExecError(e)` in both.
- `resolvePrState` / `resolvePrStateAsync` — `plugin/bin/lib/reconcile/pr-state.js:73` and `:102`. Retyped try/catch -> `classifyExecError`, plus a second retyped `JSON.parse` -> 'network-failure' fallback in each.

Note: `resolvePrStateAsync` has a deliberate, documented asymmetry from `resolvePrState` (no opts/preferOpen parameter) — this pair is not a pure mechanical dedup the way the first two were; the fix needs to preserve that asymmetry, not flatten it away.

The reviewer also suggested (as a nice-to-have, not required) a derived key-parity test — Object.keys() parity between a sync/async twin's success and failure results, computed from the two live results rather than a hard-coded literal list — added once for each pair this record touches, to convert AC clause 3's one identified residual (a maintainer widening buildSuccess's signature could update one twin's call site and leave the other silently passing undefined, since nothing currently compares the two twins' shapes to each other) into a red test rather than a silent gap.

## Deliverables

Extend the `runClassified`/`runClassifiedAsync` + per-pair `buildSuccess`/`buildFailure` pattern (already shipped by #1652 in `git-exec.js` and `preflight.js`) to:
1. `ghApi`/`ghApiAsync` in `plugin/bin/lib/reconcile/release-merged.js`.
2. `resolvePrState`/`resolvePrStateAsync` in `plugin/bin/lib/reconcile/pr-state.js` — preserving `resolvePrState`'s extra opts/preferOpen parameter that `resolvePrStateAsync` deliberately omits.

Optionally, add one derived Object.keys() parity test per pair (covering all four pairs now unified under the scaffold, not just these two) as the reviewer's suggested hardening for AC clause 3's residual.

## Acceptance Criteria

No behavioral change to any existing caller. Existing test suites for `release-merged.js` and `pr-state.js` (and any other suite exercising these two pairs) still pass. Same structural guarantee #1652 established: a future fix to one twin's contract cannot land without the shared code path enforcing it also applies to the other — for these two pairs too.
