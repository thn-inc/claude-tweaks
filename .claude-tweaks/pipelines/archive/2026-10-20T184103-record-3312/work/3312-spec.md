# 3312: Let agent-trust-scope judges honor an accepted-risk ADR instead of re-reporting the dimension

Verified-as-of: 6832e7565b3668045d1e0c0c0aba56a730b1508b

Origin: reflect full from #2876

Defer-reason: tangential

## Current State

`plugin/skills/_shared/criteria-agent-trust-scope.md`'s "What NOT to flag" section has no exception for a dimension the project has formally accepted in an ADR, and `plugin/bin/lib/code-health/candidates-agent-trust-scope.js` cannot see one.

This repo accepts `network-egress` under `docs/decisions/0022-unattended-runs-keep-network-egress.md` (#2876): `/claude-tweaks:research` needs `WebFetch`, and a narrow deny rule would only silence the finding. So every `/claude-tweaks:code-health focus=agent-trust-scope` sweep, and every `/claude-tweaks:review` Step 6.65 pass on a diff touching `.claude/settings.json`, re-reports `network-egress` at medium severity. A judge then re-derives "accepted risk" by hand each time, or a sweep files a duplicate issue for a decided question. Observed on #2876's own review: Step 6.65 returned `["network-egress"]`, and the judge had to cite ADR 0022 manually.

## Deliverables

- Add a "What NOT to flag" bullet to `plugin/skills/_shared/criteria-agent-trust-scope.md` covering a dimension that a committed `docs/decisions/*.md` ADR with `**Status:** accepted` names by the generator's exact kind literal (`registry-access` / `network-egress` / `credential-scope`) as an accepted risk. The judge reports it as an informational "accepted risk — ADR NNNN" line, never as a finding and never as a filed issue.
- Update `plugin/skills/review/focus-criterion-passes.md` Step 6.65's result-handling table with the matching row: an accepted-risk candidate renders as a footer note naming the ADR, not as an Agent Trust Scope finding.
- Keep the guard tight. A dimension that is only mentioned in an ADR, or an ADR whose status is not `accepted` (superseded, proposed), still reports.

## Acceptance Criteria

- With ADR 0022 accepted, a `/claude-tweaks:code-health focus=agent-trust-scope` sweep of this repo files no `network-egress` issue, and its output names ADR 0022 as the reason.
- With ADR 0022's status changed to anything other than `accepted` (fixture or temp copy), the same sweep reports `network-egress` again.
- An ADR that mentions `network-egress` without accepting it does not suppress the finding.

## Release Note

Agent-trust-scope sweeps and reviews stop re-reporting a dimension your project has formally accepted in an ADR, and show it as an accepted risk instead.

## As built (architecture alignment, /build Common Step 4.5)

Beyond the two listed Deliverables, the build added four things, all classified **Beneficial**:

- `plugin/skills/code-health/SKILL.md` Step 10 lists each candidate set aside under a fragment's accepted-risk rule as `accepted risk — ADR NNNN ({kind})`. Without that slot, AC1's "its output names ADR 0022" relied on an agent carrying one sentence from Step 5 to Step 10 (final whole-branch review, Important).
- The fragment's standalone copy-paste prompt mirrors the exception, so a standalone run does not re-report the dimension.
- `plugin/skills/review/review-summary-template.md` carries the matching footer note, so Step 6.65's row has a rendering target.
- The ADR location honors a repo's `doc-convention-adr` home (`_shared/decision-records.md`), with `docs/decisions/` as the default.
