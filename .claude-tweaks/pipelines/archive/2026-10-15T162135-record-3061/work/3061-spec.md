# 3061: Worktree Bash guard refuses a plain `powershell -File script.ps1` invocation

Origin: reflect full from #3043
Defer-reason: tangential

## Current State

The PreToolUse worktree Bash guard refuses any command that launches `powershell`, even an unadorned `powershell -NoProfile -ExecutionPolicy Bypass -File <script>.ps1` run from the worktree. It replies that the command "runs powershell in a plain command; what it reads or is handed as shell text cannot be shown not to run git". The same script runs fine when wrapped in `node wrapper.js`, which spawns powershell itself, so the refusal adds a hop without adding safety.

Evidence: #3043's Common Step 5, while checking for orphaned `npm test` processes after a TaskStop. Two refusals, and then a Node wrapper (`scratch/node-procs.js`).

Cost this session: two retries and a throwaway wrapper.

## Deliverables

- [ ] Treat `powershell -File <path>` (no `-Command`, no inline script text) the way `bash script.sh` is treated: a plain script invocation the guard inspects by path, not as opaque shell text.
- [ ] Keep refusing `powershell -Command …` and `-EncodedCommand`, whose text can hide a git call.

## Acceptance Criteria

- [ ] A guard test shows `powershell -NoProfile -File C:/x/probe.ps1` allowed in a worktree session.
- [ ] A guard test shows `powershell -Command "git push"` and `powershell -EncodedCommand …` still refused.
