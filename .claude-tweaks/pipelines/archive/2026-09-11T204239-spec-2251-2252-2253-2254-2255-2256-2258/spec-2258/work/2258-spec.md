# 2258: The release train Routine

Surface: infra

## Overview

Once `/claude-tweaks:release --train` exists (unit 6), a project that wants unattended minor/patch releases needs a scheduled Routine to invoke it, exactly the same way `/claude-tweaks:specify` already has one. This unit mirrors that existing routine's fleet-slottable shape rather than inventing a new pattern, and registers `release` as an instantiable skill in `/claude-tweaks:routine`.

**Complexity:** Low
**Estimated tasks:** 3

## Non-Goals

- Any `--train` logic itself, or the `autonomy` ceiling's semantics — both are unit 6's deliverables; this unit only schedules the invocation.
- A new scheduling mechanism — this unit reuses the existing Routine infrastructure (`/claude-tweaks:routine-kickoff`, the fleet-slottable template shape) unchanged.

## Current State

- `plugin/skills/specify/routine-template.yml`: the existing fleet-slottable routine template this unit's own template mirrors in shape (schedule cadence, `/claude-tweaks:routine-kickoff` invocation prefix, fleet-slot metadata).
- `plugin/skills/routine/SKILL.md`: the skill that instantiates a named template into a live scheduled routine — today's instantiable list does not include `release`.
- `plugin/skills/_shared/autonomy-ceiling.md`: already gained a `train` row for the `/claude-tweaks:release` skill itself in unit 6; this unit needs a routine-specific statement of what the train Routine's *unattended firing* may do, distinct from a human typing `--train` interactively.

## Deliverables

- [ ] `plugin/skills/release/routine-template.yml` — new; mirrors `plugin/skills/specify/routine-template.yml`'s fleet-slottable shape exactly (same schedule-cadence structure, same fleet-slot metadata keys). Daily cadence; invokes `/claude-tweaks:routine-kickoff` then `/claude-tweaks:release --train`.
- [ ] `plugin/skills/routine/SKILL.md`: register `release` as an instantiable skill, alongside the existing entries.
- [ ] `plugin/skills/_shared/autonomy-ceiling.md`: a row stating what the train Routine may do when it fires at `unattended` (merge the release PR under pr-first, or tag locally under local-merge — one clause covering both, since the row cites unit 6's own per-engine `execute.md` dispatch rather than re-deriving separate per-engine behavior; minor and patch bumps only) and what it never does (a major bump, a `review: blocking` verdict, a hook failure) — distinct from unit 6's own `train` row for the skill in general; this row is specific to the unattended Routine-firing context.

## Acceptance Criteria

1. `plugin/skills/release/routine-template.yml` instantiated against this repo produces a working schedule (validated the same way `specify/routine-template.yml`'s instantiation is validated today).
2. That schedule's firing on a main branch with unreleased `fix:` commits and no blocking review finding ends in a tag being created. **Test method:** since a Routine's cron trigger is not itself something a build-time test waits on, this AC is proven by invoking the template's own payload command directly — `/claude-tweaks:release --train` against a fixture repo with `release-train: true` and `autonomy: unattended` set — the identical invocation the schedule performs when it fires; the schedule/cron wiring itself is validated separately (AC1) as a syntactic/structural check, not by waiting for a real cron tick.
3. The same fixture repo, but with an unreleased `breaking`-labelled record instead, invoked the same direct way, ends in `HELD` with no tag created — proving the train's major-bump refusal (unit 6's own logic — this unit adds no refusal logic of its own) reaches the Routine-firing invocation path, not only a human-typed `--train` path. Both AC2 and AC3's pass/fail outcomes are exactly as reliable as unit 6's own `--train` classification logic, since this unit invokes that logic verbatim rather than reimplementing any part of it.
4. `/claude-tweaks:routine` lists `release` among its instantiable skills, and instantiating it does not require any manual edit beyond what `specify`'s existing instantiation flow requires.

## Technical Approach

Mirroring `specify/routine-template.yml`'s shape exactly (rather than designing a new template structure) keeps every fleet-slottable routine in this repo interchangeable from the scheduler's own point of view — the scheduler's fleet-slot logic doesn't need to special-case a second template shape. This mirroring is about **template structure only** (schedule-cadence fields, fleet-slot metadata keys, the `/claude-tweaks:routine-kickoff`-then-target-skill invocation shape) — `specify/routine-template.yml` itself has no refusal/HELD branch to mirror, and neither does this unit's template: the template is a thin, unconditional wrapper that always invokes `/claude-tweaks:release --train` and lets that skill's own Step 4/`--train` logic (unit 6) decide proceed-vs-HELD-vs-refused. The "no blocking review finding" precondition in AC2 is likewise entirely unit 6's own Step 3 check, read by `--train`, not a separate condition this unit's template evaluates. The daily cadence is a default, not a hard requirement enforced by this unit's own code; a project can reconfigure the schedule after instantiation the same way it can for any other routine template.

## Gotchas

- This unit is `Blocked by` unit 6 — `--train` must exist and be invocable before a Routine can be built to fire it unattended; building the template first would leave it pointing at a skill flag that doesn't exist yet.
- Do not conflate this unit's Routine-firing row in `autonomy-ceiling.md` with unit 6's own skill-level `train` row — they answer related but distinct questions (what may an unattended *scheduled firing* do, vs. what may `--train` do when invoked at all) and both need their own explicit statement per the design doc's Phase 7 text.
- `/claude-tweaks:routine-kickoff` already runs the stale-docs guard, plugin-list dump, and reconcile before invoking the target skill — this unit's template does not duplicate any of that; it only adds the `/claude-tweaks:release --train` invocation after the existing kickoff prefix.
