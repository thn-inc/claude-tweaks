# 2256: The `/claude-tweaks:release` skill

Surface: infra

## Overview

This is the consumer-facing deliverable the whole design exists to produce: `/claude-tweaks:release`, a skill that **drives** a release rather than implementing one. It reads unit 5's preflight fact pack, runs the whole-branch review before any bump (the same gate `docs/releasing.md` already requires and `[IL-97]` exists to prevent regressing), renders one console table, executes the merge/tag through whichever engine `integration-model` selects (release-please for pr-first, unit 4's `bin/release-local.js` for local-merge), verifies the result actually landed, and closes out the shipped records' bookkeeping.

**Complexity:** High
**Estimated tasks:** 8

## Non-Goals

- Implementing either engine — release-please is a third-party GitHub Action; `bin/release-local.js` is unit 4. This skill only drives them.
- Registry publishing or deployment — a project's own `release: published` workflow hook (pr-first) or `release-hook` policy command (local-merge) owns that, never this skill (design doc stance 6).
- A new autonomy lever for `--train` — it reads the existing `autonomy` ceiling rather than introducing a parallel gate (design doc stance 9).

## Acceptance Criteria

1. Fixture repo, pr-first, with an open release-please PR: `--dry-run` prints the console with the correct shipped-record set and proposed version, and merges nothing (no `gh pr merge` call made).
2. local-merge fixture: a live (non-dry-run) run produces the tag and the `shipped: v{version}` lines on the shipped local records, and the rendered summary names the released version.
3. `--train` with a `breaking`-labelled record having reached the integration branch since the last tag writes `release-held.md` to the run directory and merges nothing — `HELD` appears in the run's summary.
4. `--train` invoked when `release-train` is `false` or `autonomy` does not resolve `unattended` logs `train: refused — autonomy {value}` and behaves exactly as an on-demand (non-train) invocation — it does not silently proceed as if `--train` had been accepted.
5. Step 3's whole-branch review runs and completes (or blocks) before Step 4's console renders on every invocation — there is no code path that reaches the console without the review step having run.
6. A missing `release: published` workflow run, a workflow run present but concluded as a failure (pr-first), or a nonzero `release-hook` exit (local-merge) at Step 6 are all reported as a named partial state with a recovery command — never rendered as a clean, successful release.
7. This unit's own conformance test fails on a fixture skill-prose file that references `/claude-tweaks:release` in actionable instruction text using the bare `/release` form instead of the fully-qualified one.
8. `--train --as {version}` on a fixture whose commits alone would justify only a minor bump, but whose `--as` value is a major version bump over `lastTag`, writes `release-held.md` and merges nothing — proving the major-bump gate reads the effective (post-override) version, not only the commit-derived proposed one.
9. A `--train` run whose Step 5 merge/tag succeeds but whose Step 6 Verify then finds a failed hook run reports `PARTIAL` (not `HELD`, not clean success) in the run summary, with the same named recovery command Step 6 always produces for that failure.

## Technical Approach

The whole-branch review running *before* the bump on every path, including `--train`, is non-negotiable per the design doc's stance 8 and `[IL-97]` — a v6.48.0 → v6.48.1 incident where a Critical finding surfaced twenty minutes after a release it should have blocked is the reason `docs/releasing.md`'s procedure exists at all; an unattended train that skipped this step would reintroduce that failure at higher frequency, not lower it. The HARD-GATE list (`review: blocking`, a major bump) is deliberately short and fixed — these are the only two conditions `--train` cannot silently proceed past, matching `_shared/auto-mode-contract.md`'s general HARD-GATE exemption discipline used elsewhere in this repo's auto-mode pipelines.

`--as {version}`'s bounded poll (waiting for release-please to re-render the PR after a `Release-As:` push) is explicitly allowed to time out into a reported `partial: override pushed, PR not re-rendered` state rather than looping indefinitely — an unbounded poll would make the skill hang on a slow or stuck release-please run.

- **The review base is `{base}`** — `lastTag.value.tag`, or the root commit of `origin/{branch}` when no `v*` tag exists; `/claude-tweaks:review` gained a `base:{ref}` scope token for it (rulings 1, 9).
- **Catalog surfaces land here** — help/reference-card.md, help/context-flow.md and docs/getting-started.md rows, because `tests/skill-catalog-completeness.test.js` fails the moment the skill directory exists; /help's diagrams and README stay #2257's (ruling 2).
- **HARD-GATEs are registered**, not new mid-flow stops — `review: blocking` and a major bump on the effective version sit in `_shared/auto-mode-contract.md`'s registry (ruling 3); the run directory resolves per `_shared/pipeline-run-dir.md` and `release-held.md` is staged through `stage-item.js` (ruling 4).
- **Local records gain a `shipped:` facet** (`local-store.js`: `closeRecord(file, { shipped })`, `markShipped(file, version)`), serialized after `closed-at:` (ruling 5).
- **Bounded polls are 15 × 20 s everywhere** — the `Release-As:` re-render, the tag, the GitHub Release, the hook run (rulings 6, 7); the hook run is filtered by the tag's commit sha, read from the `ls-remote` output.
- **The shipped set** is the deduplicated `(#N)` suffixes of `unreleased.value.commits[].subject`; unattributed commits are listed, never dropped (ruling 8). The train refusal reads `release-train` and `autonomy` through `resolve-policy.js` (ruling 10).
- **Five summary outcomes** — `released | dry-run | HELD | PARTIAL | failed`; `failed` is a Step 5 attempt that landed nothing with no gate fired (ruling 13; staged as build-deviation-1 for the record's wording).
- **Gating version vs shipped version** — Step 4 gates on `--as` or `proposedVersion`; Steps 6–7 verify and book the engine's own version, reconciled once; under `--as` a mismatch is `failed` (ruling 14).
- **The release PR's own checks gate the merge** per `_shared/pr-first-merge.md` Step 2.5 and the `merge-verification` lever; the release never arms `--auto` (ruling 15).
- **Engine exit `1` splits on its stderr prefix** (nothing written → `failed`; `partial:` → `PARTIAL`); `--dry-run` under local-merge passes through to the engine and renders its output; the engine runs with `--root "$RUN_ROOT"` (ruling 16).
- **`--as` is pr-first only** — refused right after Step 1 under local-merge, logged `SKIP` (ruling 17; ledger row 90).
- **The description-corpus ceiling** rose 7,900 → 8,200 for the 36th skill (ruling 11); the reference-form test scans the sub-files whole, exempting only the preamble and Anti-Patterns (rulings 12, 18).
