# 2068: verify-cleanup.js's renderCleanupTable doesn't escape pipe characters, unlike engine-verify.js's sanitizeCell

## Current State
`plugin/bin/lib/smoke-test/verify-cleanup.js`'s `renderCleanupTable` (line 40) interpolates `row.artifact` directly into a markdown table row with no pipe-character escaping: `` `| ${row.artifact} | ${row.claimed ? 'yes' : 'no'} | ${row.verifiedAbsent ? 'yes' : 'no'} |` `` (line 41). `plugin/bin/lib/wrap-up/engine-verify.js` has a `sanitizeCell` function (line 640, `String(text).replace(/\s+/g, ' ').replace(/\|/g, '\\|').trim()`) built for the identical purpose and already used by that file's own `renderVerifyTable` — but `sanitizeCell` is a private function, not currently in `engine-verify.js`'s `module.exports` (line 656, which lists `runVerify`, `renderVerifyTable`, `resolveArchivedRunDir`, `registerCheck`, `defaultGit`, `defaultGh`, `resolveParent`, `resolvePrNumber` — no `sanitizeCell`). An artifact string containing a literal `|` (e.g. a branch/PR-title-derived description) splits the generated row into extra columns, breaking the Step 6 report table's rendering.

## Deliverables
- [ ] Add `sanitizeCell` to `engine-verify.js`'s `module.exports` (it already exists as a private function; this just makes it importable).
- [ ] In `verify-cleanup.js`, `require('../wrap-up/engine-verify')` and call `sanitizeCell(row.artifact)` before interpolating it into `renderCleanupTable`'s row string.

## Acceptance Criteria
1. A test with an artifact string containing a literal `|` renders a well-formed 3-column table row (verify via `renderCleanupTable`'s output split on `|` producing exactly the expected column count for that row).
2. `engine-verify.js`'s own existing tests and usages of `sanitizeCell`/`renderVerifyTable` are unaffected by adding it to `module.exports` (a pure additive export, no signature change).

## Technical Approach
Reuse rather than duplicate: `sanitizeCell` already does exactly what's needed (pipe-escaping plus whitespace collapsing, consistent with how `renderVerifyTable` already sanitizes its own cells), so exporting it and importing it in `verify-cleanup.js` is a two-file, additive-only change — no new escaping logic to write or independently verify.

### Key Files
- `plugin/bin/lib/smoke-test/verify-cleanup.js` — `renderCleanupTable` (line 40)
- `plugin/bin/lib/wrap-up/engine-verify.js` — `sanitizeCell` (line 640), `module.exports` (line 656)
