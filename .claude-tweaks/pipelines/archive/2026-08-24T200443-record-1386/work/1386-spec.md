# 1386: _shared/trust-table.md hardcodes bare /tmp/ paths that don't survive per-call isolation

**Related:** #1384

## Current State

_shared/trust-table.md's canonical Fetch snippets (the work-links: native sub-issue enumeration and the git-log dump sections) hardcode literal paths under bare /tmp/ — /tmp/trust-table-parent-issues.json, /tmp/trust-table-sub-issues.json, /tmp/trust-table-sub-issues-batch.json, /tmp/trust-table-git-log.txt, /tmp/trust-table-records.json. This harness's Bash tool runs each call in a fresh per-process environment where a bare /tmp write from one call is not guaranteed visible to a later call in the same session. Following the skill's snippets verbatim in a live run (2026-08-24) required rewriting every one of these paths to a session-scoped scratchpad path before executing, since the literal /tmp/ paths as written are not reliably portable across the calls the same procedure issues.

## Deliverables

- Replace every hardcoded /tmp/trust-table-* path (and any sibling _shared snippet file with the same pattern) with a variable resolved once at the top of the procedure — ideally reusing the same sessionTmpPath / session-scratchpad convention bin/lib/session-tmp.js already provides elsewhere in this plugin — documented as "the session scratchpad, never bare /tmp".

## Acceptance Criteria

- _shared/trust-table.md's Fetch section snippets contain no literal /tmp/* path; every intermediate file path is resolved via a session-scoped helper.
- A fresh session following the updated snippets verbatim (no ad-hoc path substitution) completes the Fetch section without any file being unexpectedly empty or missing due to per-call /tmp isolation.
