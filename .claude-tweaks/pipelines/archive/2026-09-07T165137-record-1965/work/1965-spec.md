# 1965: Dispatched /flow Task agents yield their turn waiting on a background test run or child agent and are never re-woken

Defer-reason: tangential

Origin: /claude-tweaks:dispatch --budget all drain, run 2026-09-05T090744-dispatch-standalone (14 groups attempted)

## Current State

Three of the 28 Task calls this firing (1442 build, 1442 review, 1821 build) ended their turn with "Waiting for the background test run / fix-round / simplify subagent" and no status line. A Task agent that yields expecting a completion notification is never re-woken inside the Task; the dispatching session had to detect the missing status line and resume each via SendMessage. two-call-gate.md treats a missing report as a failed first call, so without manual intervention these would have counted as build-test failures. task-prompt.md's templates say nothing about foreground execution.

## Deliverables

- [ ] Add one paragraph to both task-prompt.md templates: run `npm test` and every long command in the foreground redirected to a file; never background it; never end the turn waiting on a background process or child agent.
- [ ] Add the same instruction to build/dispatch.md's implementer/reviewer prompts, which are the grandchildren that actually launched the background runs.
- [ ] Pin with a conformance test that both dispatch templates contain the foreground instruction.

## Acceptance Criteria

1. Both task-prompt.md templates carry the foreground-only instruction verbatim.
2. A dispatch firing over 5 groups on the updated templates produces zero missing-status-line stops (verify at the next live drain and record in this issue).
