# 1179: consoleAutoResolve default-merge must not override a merge-check needs-human verdict

Surface: infra

## Current State

`flow/multispec-review-console.md` and `wrap-up/review-console.md`'s Auto-resolution short-circuit (`consoleAutoResolve`, granted at `autonomy: unattended` per `_shared/autonomy-ceiling.md`) state that "the merge half of the terminal decision defaults to merge," with no stated exception for a prior `needs-human` verdict from `assess-agent-autonomy merge-check` (`dispatch/settle-and-merge.md`'s Auto-merge gate Layer 2). Followed literally, an unattended run would merge diffs the more specific, more conservative gate explicitly routed to a human — observed live in run `2026-08-20T194024-record-642` (PR #1156), where merge-check returned `needs-human` for all 5 bundle members on the agent-instruction-file floor while `consoleAutoResolve` would have completed the merge anyway. The executing agent held the merge (KEPT-PROMPT, decisions.md 22:42:45) and a human later ruled: **merge-check's `needs-human` verdict is authoritative and must not be overridden by `consoleAutoResolve`'s default-merge.**

## Deliverables

1. In `wrap-up/review-console.md`'s Auto-resolution short-circuit and `flow/multispec-review-console.md`'s Auto-resolution short-circuit: add an explicit carve-out — when a `merge-check` verdict of `needs-human` exists for the run (any member, for a bundle), the merge half of the terminal decision resolves to "leave PR open / pending-review," not merge; every non-merge item still auto-resolves as today.
2. Cross-reference the carve-out from `dispatch/settle-and-merge.md`'s Auto-merge gate (one sentence stating the verdict survives into the console short-circuit) so the precedence is stated where the verdict is produced as well as where it would be overridden.
3. A conformance test pinning the carve-out prose in both console files (live-corpus scan with go-red proof, per the `skill-prose-conformance-tests` convention).

## Acceptance Criteria

- [ ] Both short-circuit sections name the `needs-human` carve-out explicitly; neither says "defaults to merge" without the exception.
- [ ] `dispatch/settle-and-merge.md` states that a `needs-human` merge-check verdict is not overridden by `consoleAutoResolve`.
- [ ] Conformance test fails when the carve-out sentence is removed from either console file.

## Gotchas

- Human ruling on precedence already made (2026-08-21, this issue's origin run): merge-check wins. The build task is pinning it in prose + tests, not re-litigating the design.
- The single-spec (`wrap-up/review-console.md`) and multi-spec (`flow/multispec-review-console.md`) short-circuits must stay consistent — the multi-spec file explicitly mirrors the single-spec one.

## Technical Approach

Add the carve-out to both console short-circuit sections (single-spec and multi-spec) as an explicit precedence rule ahead of the default-merge behavior, cross-reference it from the merge-check gate that produces the verdict, and pin both with a live-corpus conformance test per the skill-prose-conformance-tests convention.
