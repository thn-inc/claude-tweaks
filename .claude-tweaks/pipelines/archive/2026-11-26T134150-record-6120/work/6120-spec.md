# 6120: Run drive.js --budget as a Dispatch script job in this repository and measure the main-session share

Surface: backend
Risk-flags: none

## Overview

Phase 13's done-when is measured, not just built. This record runs `drive.js --budget` as a Dispatch script job in this repository, with dispatch's session drain leaving driver records to it, and measures whether the main session's share of cost for driver records goes to zero. It also documents the launch line a script job needs, since a script job runs outside any Claude session and has no `CLAUDE_PLUGIN_ROOT`.

## Non-Goals

- Dispatch-side code. The job is created through Dispatch's existing script-job type (a `command`, no model).
- Changing a default. `express-driver-runner` stays `session` by default. This repository opts in, per the design's 20-run rule.

## Prerequisites

- Phase 7's #6019 and #6020 (under parent #6017) and Phase 8's #5571 merged: the blockers on this record. #6021 was removed as a blocker on 2026-11-26 on the maintainer's go: its guard 1 verdict is already worse and its trial values were reverted (#6229), so its guard 3 read cannot change the admission this trial runs under. Caveat: this trial's PRs merge inside #6021's guard 3 window (read on or after 2026-12-08).
- This phase's other three sub-issues merged and released, and the release installed: the drain-overlap hold, the worker stop and the session drain's exclusion.

## Current State

- No script job runs the driver. The 12 November driver runs were started by hand, and dispatch routes driver records from a model session (`plugin/skills/dispatch/driver-route.md`).
- `docs/driver.md` says a launcher must leave stdin a pipe or set `CC_HUB_RUN`, so that the driver never reads a job runner as a person at a terminal. It gives no launch line.
- The installed plugin's path changes with every version (`~/.claude/plugins/cache/claude-tweaks-marketplace/claude-tweaks/{version}/`). `plugin/bin/lib/installed-plugins.js` reads `~/.claude/plugins/installed_plugins.json`.

## Technical Approach

Create the job with Dispatch's `create_job` (`type: script`, `command`, the repository's id, a schedule). Keep the budget small at first (for example 3 per firing) so a defect costs a few records, not the queue. Read results from the summary line and the cost report, not from model transcripts: the point is that no model session walked the queue.

Order: confirm the version `installed_plugins.json` reports on the job host carries `express-driver-runner`, then merge the policy change, then enable the job. The Dispatch repository id comes from `list_repos`. The host is the machine that runs the Dispatch runner and holds the subscription login, with `CLAUDE_CONFIG_DIR` set in the job's environment. A first schedule such as hourly with `--budget 3` is a starting point, not a requirement. A record the job could take is one the cost report's funnel counts as admitted. The closing comment is posted when the trial window ends. Guard 3 is read 14 days after the last merge and posted as an addendum comment, and the record closes after that addendum. Guard baselines are the design's `### Quality guards` section, with guard 2 handled as the design's Phase 7 trial does.

## Gotchas

- #5259 (open): workers get only `ENV_ALLOW` (`PATH`, `HOME`, `USER`, `TMPDIR`, `LANG`, `CLAUDE_CONFIG_DIR`), so a job host that authenticates through environment variables launches every worker unauthenticated. Run the job on a host with a subscription login reachable through `CLAUDE_CONFIG_DIR`. With the worker stop merged, a wrong host ends the run `worker-stop` rather than escalating records.
- A job runner that gives `drive.js` a terminal on stdin and sets none of the session variables reads as a person, so naming would count as `typed`. `CC_HUB_RUN=1` prevents that. Keep it in the launch line.
- The policy change lands in committed config, which installed builds read. Merge it only once the release carrying `express-driver-runner` is installed, or an older build reads an unknown key.
