# 5269: Keep the verb in driver commit titles: strip a closing keyword only before an issue reference

Origin: #5218 SDD ruling 31, reversed by the user

Defer-reason: needs-human-decision

## Current State

`neutralize` in `plugin/bin/lib/driver/events.js` (#5218) removes every closing keyword (`close`, `closes`, `closed`, `fix`, `fixes`, `fixed`, `resolve`, `resolves`, `resolved`, any case) from worker-controlled text, and separately removes every issue reference. `normalizeTitle` runs the worker's title through it before the title becomes a commit message, so a title `Fix the loop` becomes `the loop`.

That was #5218's acceptance criterion 3, recorded as its SDD ruling 31; the user reversed the ruling on 2026-11-12. A closing keyword only closes an issue when a reference follows it, and every reference is already removed, so a keyword with no reference after it can close nothing.

`neutralize` also cleans the worker's summary for the PR body and the text on event lines, so the same rule applies there.

## Deliverables

- [ ] `neutralize` removes a closing keyword only when an issue reference follows it, optionally after a colon and whitespace: `#N`, `owner/name#N` or a GitHub issue or pull request URL. It keeps removing every such reference, with or without a keyword before it.

- [ ] The tests in `tests/bin-lib/driver/run.test.js` that asserted a bare keyword's removal are updated to the new rule; the rest are unchanged.

## Acceptance Criteria

1. `normalizeTitle('Fix the loop')` returns `Fix the loop`, and `normalizeTitle('Resolves the race in the sink')` returns `Resolves the race in the sink`.

2. `normalizeTitle('Add the loop. Resolves #9.\nsecond line')` returns `Add the loop`, and `normalizeTitle('Closes #4')` returns an empty string. `Fixes: #12`, `fixes owner/repo#3` and `Closes https://github.com/o/r/issues/5` each lose both the keyword and the reference.

3. For every closing keyword in any case and every reference shape in criterion 2, no output of `neutralize` contains the keyword followed, after an optional colon and whitespace, by `#` and a digit, by `/` then `#` and a digit, or by `github.com/`.

4. The commit-step test that feeds a title containing a closing keyword followed by a reference (`AC3.4, AC3.5` in `tests/bin-lib/driver/run.test.js`) still passes.

## Release Note

Commit titles written by the pipeline driver keep their leading verb, such as Fix or Resolve.

## Technical Approach

### Key Files

- `plugin/bin/lib/driver/events.js` — remove a closing keyword only before an issue reference
- `tests/bin-lib/driver/run.test.js` — update the normalizer tests to the new rule

## As Built (architecture alignment, Beneficial deviations)

- The keyword decision reads the whitespace-delimited token after the keyword: the keyword goes when that token carries `#<digit>` or `/issues|pull/<digit>` (a superset of "a reference follows" that does not depend on modelling every autolink form; staged for ratification as `sdd-ruling-8`). A keyword that is a whole path segment stays, so the URL around it is still removed.
- Reference removal repeats to a fixed point (in-loop removals leave a space), so a removal cannot splice a new reference, keyword or `<!--` together; the comment opener is escaped after the loop.
- `URL_REF`'s left boundary is letters-only (`(?<![A-Za-z])`, as cmark-gfm rewinds a scheme), so `_https://…` and `1https://…` issue URLs are removed too.
- Every pattern is linear on uncapped worker text (`QUALIFIED_REF` start condition, `(?:\s*:)?\s*`, forward-only pointers), pinned in `perf/driver-neutralize-linearity.test.js`. Open: a keyword chain before a `www.`/bare `github.com` URL still peels one keyword per loop pass (staged as `sdd-ruling-10`).
