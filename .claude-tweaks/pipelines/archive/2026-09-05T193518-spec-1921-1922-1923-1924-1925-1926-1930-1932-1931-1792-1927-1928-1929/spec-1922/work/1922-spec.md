# 1922: verify.js diff-aware scoping engine: verify-scope.json, changed-files.js, scope.js, and a scope-labelled stamp anchored to the last full pass

Surface: backend

## Overview

After the runner-written stamp lands (Phase 1 sub-issue), every re-verification after the run's first full pass still runs the full set whenever HEAD moved — a ledger row, a materialized `work/*-spec.md`, a review-fix commit all cost ~5–6 min of suite. The stamp is a SHA-equality test, not a diff test, and no file-type heuristic can safely decide what a changed path exercises: in this repo `plugin/skills/**/*.md` is under test (`[IL-120]`, `[IL-140]`), in another project `docs/**` is read by nothing. Only the project can say.

This unit builds the pure scoping engine: a project-declared `.claude-tweaks/verify-scope.json` (rules mapping path globs to suites and static checks, plus an optional `flaky` section Phase 3 consumes), a shared changed-file-set module, a pure `scope.js` rule that turns declaration + changed files + current stamp into `{mode, suites, static, base, unmatched}`, and `verify.js --scope` which applies it, runs only the selected checks, and writes a stamp whose `scope` names exactly what ran, anchored to the last full pass's SHA. Nothing in the pipeline calls `--scope` yet — the wiring is the next sub-issue — so this unit changes no run's behavior on its own; it makes the mechanism exist and be unit-tested.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- Wiring scoped runs into `/claude-tweaks:test`, `/flow`, multi-spec, or the QA story filter — the pipeline-wiring sub-issue (Phase 2b).
- Generating the declaration in `/claude-tweaks:init` or declaring this repo's own — Phase 2c.
- Flaky retry execution — Phase 3 (this unit only parses and validates the `flaky` section so the schema is complete).
- Scoping build Common Step 5, the run's first pass — always full, by design.
- Reading `.claude-tweaks/policy.yml` from the runner — the declaration is an explicit `--scope <path>` input the caller names.

## Acceptance Criteria

1. `selectScope` with `decl: null` returns `{mode: 'full', suites: '*', static: true, unmatched: []}` regardless of files (today's behavior, byte-for-byte).
2. Given the example declaration below and `files: ['docs/plans/x-ledger.md']`, `selectScope` returns `mode: 'none'`; with `['docs/guide.md']` → `mode: 'static-only'` (rule `static: false`… see schema: `docs/**/*.md` has `static: false`, so `none`); with `['apps/api/src/a.ts']` → `mode: 'scoped', suites: ['api'], static: true`; with `['packages/shared/x.ts']` → `mode: 'full'`; with `['unknown/path.txt']` → `mode: 'full', unmatched: ['unknown/path.txt']`; with `['apps/api/src/a.ts', 'docs/plans/x-ledger.md']` → `mode: 'scoped', suites: ['api']` (union, bookkeeping adds nothing).
3. `resolveBase` returns the stamp's `fullSha` when present and an ancestor of HEAD; returns the integration-branch merge-base when no stamp exists; throws `ChangedFilesError` when neither resolves — verified with a fake `execImpl` in all three cases.
4. In a temp git repo with a declaration mapping `src/**` → `["unit"]` and `docs/**` → `[]` (`static: false`): run 1 (`--scope`, no stamp) writes `scope: "full"`; after committing `docs/a.md`, run 2 writes `scope: "none"`, `fullSha` unchanged, `suitesRun: []`, exits 0, and the `unit` command was not spawned (assert via a command that touches a marker file); after committing `src/a.js`, run 3 writes `scope: "scoped"`, `suitesRun: ["unit"]`, `base === fullSha` of run 1.
5. `--scope` with a `--cmd` name that is not `types`, `lint`, or a declared suite exits 2 with a usage error naming the offending name.
6. A declaration with an unknown suite in `rules[].suites` fails `readDeclaration` with an error naming the rule index and the suite; the CLI exits 2 and writes no stamp.
7. `verify.js` without `--scope` behaves exactly as before this unit (the existing `cli.test.js` cases pass unmodified).
8. `npm test` passes with no new failures relative to `main`.

## Technical Approach

### The mechanical rule (`scope.js`)

1. No declaration → `mode: full` (unchanged behavior).
2. `base`/`files` per `changed-files.js` (base = stamp `fullSha` when present, else merge-base).
3. Classify each file by the **first** matching rule (`globToRegExp`, repo-relative, forward slashes). Unmatched → `{suites: "*", static: true}` and listed in `unmatched`.
4. `suites` = union over files; any `"*"` ⇒ every declared suite. `static` = any file with `static: true` or unmatched.
5. `mode` = `full` if every suite selected and `static`; `static-only` if `suites` empty and `static`; `none` if `suites` empty and not `static`; else `scoped`.
6. `none` runs nothing but still stamps — the decision is on record and a later consumer sees that only declared no-suite paths moved since the last full pass.

Anchoring invariant: scope selection always diffs against `fullSha`, never the last scoped `sha`, so scoped runs never chain into unbounded drift; the set "verified only by scoped runs" is exactly `fullSha..HEAD`.

### Data / API Surface

`.claude-tweaks/verify-scope.json` (tracked, project-owned):

```json
{
  "checks": {
    "types": "pnpm typecheck",
    "lint": "pnpm lint",
    "tests": { "api": "pnpm --filter api test", "web": "pnpm --filter web test" }
  },
  "retry": { "api": "pnpm --filter api test -- {file}", "web": "pnpm --filter web test -- {file}" },
  "rules": [
    { "match": "apps/api/**",           "suites": ["api"], "static": true  },
    { "match": "apps/web/**",           "suites": ["web"], "static": true  },
    { "match": "packages/shared/**",    "suites": "*",     "static": true  },
    { "match": "docs/**/*.md",          "suites": [],      "static": false },
    { "match": "docs/plans/*-ledger.md","suites": [],      "static": false },
    { "match": ".claude-tweaks/pipelines/**", "suites": [], "static": false }
  ],
  "flaky": { "files": ["apps/api/test/mailer.test.ts"], "maxRetries": 1 }
}
```

- `checks.tests`: a string (single suite named `tests`) or a map of suite name → command. A string containing `{base}` selects tool-scoped mode.
- `checks.types`/`checks.lint`: optional strings. `retry`: optional map, suite → per-file command template with `{file}` (Phase 3 uses it; validated here). `flaky`: optional; `maxRetries` default 1, ceiling 2.
- `rules[]`: evaluated per changed file, first match wins; `suites` is `"*"`, `[]`, or an array of declared suite names; `static` gates `types`+`lint`.

Stamp additions (fields already reserved by Phase 1): `scope`, `base`, `changedFiles`, `suitesRun`; plus `mode: "tool-scoped"` inside a `scopeDetail` object when applicable. `report.json` gains `scope: {mode, suites, static, base, unmatched, changedFiles}`.

`changed-files.js` exports `changedFiles`, `resolveBase`, `ChangedFilesError`. `scope.js` exports `selectScope`. `declaration.js` exports `readDeclaration`.

## Gotchas

- Red-team resolution: AC2's `['docs/guide.md']` example was self-contradictory (asserted `static-only` then corrected itself to `none` in the same sentence) — the correct expected value is `mode: 'none'` only (per the mechanical rule: `suites: []` + `static: false` is `none`, never `static-only`); `scope.test.js` must also cover the genuinely untested `static-only` branch (`suites: []` with `static: true`) with its own fixture rule, since no rule in the example declaration exercises it.
- Red-team resolution: tool-scoped mode's field location is `scope` itself (the same top-level enum field every other mode uses) taking the value `'tool-scoped'` — there is no separate `scopeDetail` object; the reserved `scope` enum is therefore `full | scoped | static-only | none | tool-scoped`, and the anchoring invariant ("any scope other than full ⇒ base === fullSha") already covers it with no special case.
- Red-team resolution: tool-scoped mode is the one exception to "verify.js never reads commands from the declaration itself" (Option A) — the runner substitutes the resolved `{base}` into `checks.tests`'s template and executes that one command directly; every other check (`types`, `lint`, and any non-tool-scoped `tests` suite) still comes from the caller's `--cmd` flags.
- Red-team resolution: tool-scoped runs never advance `fullSha` (only `mode: 'full'` may) — consistent with the anchoring invariant; add a test asserting a tool-scoped run's stamp carries the prior `fullSha` unchanged.
- Red-team resolution: when `checks.tests` is a plain string (not the `{base}` tool-scoped form and not a suite map), `verify.js` treats `tests` as an implicitly declared suite name for the `--cmd` usage-error check and for any rule referencing `suites: ['tests']`.
- Red-team resolution: every one of `checks.{types,lint,tests}`'s command strings is name/shape-validation only in this unit (so `/init` and the caller share one declared source) — actual execution always comes from the caller's `--cmd` flags, except tool-scoped mode's `{base}` substitution (see above).
- Red-team resolution: `changed-files.js`'s working-tree set includes untracked (`??`) entries from `git status --porcelain`, not only renames/deletions.
- Red-team resolution: the "Option A" phrasing in this file just states the rule directly (no separate Option B was ever proposed) — read it as "the caller resolves commands", not as a choice between named alternatives.
- Red-team resolution: Windows path-separator normalization (asserted above) is accepted here without its own dedicated test in this unit — `changed-files.js`'s repo-relative, forward-slash convention is the contract; a normalization regression would surface via `scope.test.js`'s existing path-matching assertions on any contributor's Windows CI run.

- Integration-branch resolution must follow `_shared/integration-branch.md`'s ladder exactly as `blast-radius-cli.js` does; an unresolvable base is a thrown error, never an empty diff (`[IL-131]`'s shape — an empty diff clears every threshold).
- The declaration is repo-relative with forward slashes; normalize `git diff` output on Windows (#1837's reporter came from a Windows host).
- First match wins, so rule order matters — document that in the schema note and test it (a `docs/**/*.md` rule before `docs/plans/*-ledger.md` shadows the second; both map to `[]` in the example so the shadow is harmless there, but the test must show the ordering rule).
- `mode: none` must still exit 0 and write a stamp; a consumer reading "no stamp" would fall open to a full run and the saving disappears.
- Do not let a scoped run write `fullSha = sha`; only `mode: full` may advance `fullSha`. Test it explicitly (AC4's run 3 checks `base === fullSha` of run 1).
- `run.js`'s fail-fast ordering applies to the filtered set unchanged: `types`/`lint` still gate `tests`-family checks when both are selected.
- Under `--scope`, suite names in `checks.tests` map become the `--cmd` names the caller passes (`--cmd api="..."`); `verify.js` never reads commands from the declaration itself — Option A: the caller resolves commands. (The declaration's `checks` block exists so `/init` and the caller share one source; the runner validates that names agree.)
- `plugin/bin/lib/verify/` is a flat sibling directory (CLAUDE.md's `plugin/bin/lib/{name}/` convention) — no nested `_shared/`.
- Intermediate commits use `refs #N`.

## Decision Rationale

See the Phase 1 sub-issue's Decision Rationale for the design-wide rationale (runner-owned artifact, expand-contract, guarantee statement). Specific to this unit:

- **JSON declaration, not `policy.yml`.** `policy.yml` is read by a flat-line parser that cannot express a map; adding a YAML dependency for one file is not worth it.
- **Reuse `blast-radius.js`'s glob.** The design left the matcher choice open; the repo already has a tested segment-aware matcher and zero npm deps — a second matcher would drift.
- **Fail-closed on unmatched paths.** `[IL-120]` (a markdown edit tripped a size-ceiling test in an unrelated suite) — only declared paths get cheaper.
- **Anchor to `fullSha`.** Without it, scoped runs chain and the unverified set grows unbounded.
- **Rejected:** scoping the first pass (deferred as a possible `verify-first-pass` lever once Phase 6 numbers exist); extension-based downgrade (`[IL-120]`, `[IL-140]`).
