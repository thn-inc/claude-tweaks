# 1928: Per-phase timing telemetry: verify event, persisted spec-status phases, phase-timing.js, Timing tables, and the contract-violation fallback fix

Surface: backend
**Related:** #1480

## Overview

Nothing records phase durations. `events.jsonl` has `skill_invoked` and `commit` events with timestamps but no verify event, no step boundary, no PR event; `spec-status --phase` accepts a phase and drops it (`bin/lib/flow/manifest.js` uses it only for the banner string). #1904's numbers were reconstructed by hand. Every other phase of the parent design names this as its measurement source, and it has no dependency on them beyond the stamp's scope fields, so it can ship early.

This unit adds the two mechanical sources that bound every phase — a `verify` event written by the runner itself when `--run` is passed, and a persisted `phases[]` array in `manifest.yml` — and a pure derivation, `bin/phase-timing.js --run <dir>`, that turns `events.jsonl` + `manifest.yml` into `{run-dir}/timing.json` and a markdown table using the boundary table below. The table lands in `/flow`'s Pipeline Summary, `/wrap-up`'s summary, the run's PR comment under `pr-first`, and one line per group in dispatch's report. It also fixes the `contract-violation` noise: `subagent-stop.js` falls back to the parent session's `transcript_path` when `agent_transcript_path` is absent, so it grades the orchestrator's own narration as a subagent reply (2,471 events in the corpus, most of this shape).

**Complexity:** Medium
**Estimated tasks:** 7

## Non-Goals

- Token accounting, procedure-bytes-loaded, tool round-trips, guard-denial counts — the Phase 6b sub-issue.
- A `phase` event skills must emit at every boundary — rejected (agent-invoked bookkeeping is forgotten under load).
- Attributing a human-typed `/claude-tweaks:build` — `skill_invoked` records model-initiated calls only; such phases show as `unattributed`, stated in the output.
- Changing what `contract-violation` checks — only removing the parent-transcript fallback.

## Technical Approach

Two mechanical sources plus one persisted field bound every phase; the derivation is pure over files so it is unit-testable on a frozen fixture and can be re-run on any archived run dir.

### Phase boundary table

| Phase | Start | End |
|---|---|---|
| `call-1` / `call-2` | 1st / 2nd `skill_invoked` `claude-tweaks:flow` | next call's start, or `session-end` / `close-run` |
| `build` | `skill_invoked` `claude-tweaks:build` | next top-level `claude-tweaks:*` skill event |
| `plan` (in build) | `skill_invoked` `superpowers:writing-plans` | `skill_invoked` `superpowers:subagent-driven-development` |
| `tasks` (in build) | SDD start | first `verify` event of the call |
| `test` / `review` / `wrap-up` | their `skill_invoked` | next top-level `claude-tweaks:*` event; nested skills attribute to the enclosing phase via the parent map |
| `polish` | last `skill_invoked` `claude-tweaks:design-wrapper` between review's start and wrap-up's start (review's own Step 6.5 invocation precedes polish's) | `skill_invoked` `claude-tweaks:wrap-up`; no such event ⇒ 0 min |
| `verify` (sub-rows) | each `verify` event | — |
| `merge` | `commit` event with `action: push` after wrap-up start | `run-state.json` `pr` resolution / `close-run` |

### Data / API Surface

- `verify` event: `{type: 'verify', ts, mode, suitesRun, durationMs, pass, sha, flakyRetried, reportPath}`.
- `manifest.yml` spec entry: `phases: [{phase, status, at}]` (append-only), `phase` (latest).
- `timing.json`: `{runDir, generatedAt, phases: [{phase, start, end, minutes, source, verify: [...]}], totals: {minutes, verifyRuns, verifyModes}}`.
- `phase-timing.js --run <dir> [--json] [--markdown]` → exit 0; 2 on malformed invocation.

## Gotchas

- Red-team resolution: polish's start boundary disambiguates from review's own Step 6.5 `design-wrapper` call by searching strictly AFTER review's own `design-wrapper` invocation (not merely after review's `skill_invoked` start) for the LAST `claude-tweaks:design-wrapper` event before wrap-up's start; when no such later event exists, polish is 0 min with `start`/`end` both equal to wrap-up's start and `source: 'unattributed'`.
- Red-team resolution: `build`'s own minutes are its span MINUS the `plan`+`tasks` sub-spans (nesting, not overlap) — `timing.json`'s `totals.minutes` sums each phase's own exclusive duration exactly once, never double-counting a nested phase's time in both its own bucket and its parent's.
- Red-team resolution: the nested-skill parent map is NOT exhaustive by design — an un-mapped `claude-tweaks:*` `skill_invoked` event is treated as a new top-level phase boundary (the safe, conservative default: an unrecognized skill gets its own attributed span rather than silently nesting into an unrelated phase). `derive.js` carries a comment stating that a maintainer adding a new nested-skill call site inside review/wrap-up/etc. should add it to this map to avoid a spurious top-level phase.
- Red-team resolution: `derivePhases` always attempts to populate the canonical ten-phase list (`call-1`, `call-2`, `build`, `plan`, `tasks`, `test`, `review`, `polish`, `wrap-up`, `merge` — the same set AC3 names) regardless of what events exist; when even `call-1` can't be inferred (no `skill_invoked` events at all), every phase renders `unattributed` rather than being omitted.
- Red-team resolution: under `local-merge` (no PR), the `merge` phase ends at the ff-merge `commit` event (`action: 'merge'`) or `close-run`, per `_shared/integration-model.md`'s no-forge fallback — not PR resolution, which applies only under `pr-first`.
- Red-team resolution: under `pr-first`, "PR resolution" (the `merge` phase's end condition) means `run-state.json`'s `pr.mergedAt` field becoming non-null (or the PR's `state` transitioning to `MERGED`).
- Red-team resolution: AC3's #1535-derived reference numbers (25/24/8/12/15 min) apply to whichever fixture is actually checked into `tests/fixtures/timing/` — if a substitute archived run is used instead (per this record's own fallback for a missing #1535 archive), the AC's expected numbers are re-baselined to that fixture's own measured durations, not literally #1535's.
- Red-team resolution: a re-entered phase (e.g. `build` re-invoked after a review-requested-changes loop) produces additional entries in the already-append-only `phases[]` array — `derivePhases` sums ALL spans attributed to a given phase name across the run into that phase's total minutes, consistent with `manifest.js`'s append-only `phases[]` design; no separate re-entry mechanism is needed.
- Red-team resolution: #1480 is a soft-coordinate on this unit's `subagent-stop.js` edit, not a hard gate — the fallback-removal fix can be authored independently of #1480 landing and reconciled via merge conflict if #1480 lands first ("regardless of what comment #1898 added", per this unit's own Gotchas). Phase 2a is the true hard blocker (the `scope`/`fullSha` fields the `verify` event needs).
- Red-team resolution: "malformed invocation" (exit 2) covers a missing `--run` flag, a `--run` argument pointing at a nonexistent directory, or an unreadable `events.jsonl` (permission error) — an individual malformed JSON *line* inside an otherwise-readable `events.jsonl` is skipped per-row, never fatal.
- Red-team resolution: `stage-item.js`'s `resolveTarget` takes a bare path/dir argument and returns `{ok, resolved|reason}` — confirmed generic enough for `verify.js`'s `--run` flag to reuse directly; read its exact signature before Task 1 rather than assuming.

- Merge `origin/main` first and read `subagent-stop.js` as #1898 left it; the fallback removal is the fix regardless of what comment #1898 added. `**Related:** #1480`.
- `dispatch/SKILL.md` is 40,677 bytes — within ~280 bytes of the ceiling. One line, and trim an equal number of bytes first.

## Decision Rationale

See the Phase 1 sub-issue's Decision Rationale for the design-wide rationale. Specific to this unit: mechanical sources (the runner's own event, a persisted status transition) over agent-emitted `phase` events, because bookkeeping an agent must remember is forgotten under load; polish's boundary derived from the last design-wrapper invocation because review's own Step 6.5 call always precedes polish's; the `contract-violation` fallback removed rather than filtered because grading a parent transcript is never right.
