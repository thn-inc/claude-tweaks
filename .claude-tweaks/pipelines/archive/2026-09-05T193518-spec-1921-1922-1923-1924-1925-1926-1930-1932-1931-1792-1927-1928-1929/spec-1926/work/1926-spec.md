# 1926: Fast lane that sheds cost: ceremony-profile skip roster, skip SDD whole-branch review for single-task fast-lane plans, skip polish under fast-lane

Surface: backend
**Related:** #1886, #1765, #1911, #1912

## Overview

`ceremony:fast-lane` today trims spec-compliance, cross-spec promise, hindsight, architecture alignment, plan audit, and reflect depth — none of which is where the minutes go. #1904's docs-only Group B still paid ~13 min for SDD's whole-branch review plus fix wave and re-review, and a polish pass. This unit makes the fast lane shed real cost with two new skips, each provably safe or escape-hatched: (1) SDD's final whole-branch review (and its fix wave / re-review) is skipped when `ceremony-profile: fast-lane` **and** the plan has exactly one task — the task review's diff *is* the whole branch, and every cross-task incident in the `[IL-02]/[IL-04]/[IL-10]/[IL-97]/[IL-101]` cluster needs two or more tasks; (2) the `polish` step is skipped under `fast-lane` — polish is refinement, not correctness, and on a fast-lane record it can modify code and trigger a re-verify. It also creates `_shared/ceremony-profile.md`, the single roster of every skip each profile makes and every step no profile may skip, with a test that pins every skip named in a skill to the roster. The two-call split is explicitly kept.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- Collapsing the two Task calls — rejected (Decision Rationale).
- New header fields or labels: `ceremony:` on the record and `ceremony-profile` in `config.yml` already carry the tier.
- Skipping `/claude-tweaks:review` Steps 2, 3, 5, or Step 6's rendered-UI check; build Common Step 5; reflect's Near-misses/Fresh-start/Friction lenses; the escape hatch; `[IL-116]`'s cleanup floor; any HARD-GATE.
- Propagating a fast mode into superpowers' brainstorming/writing-plans (#1886), micro-plans (#1911), model tiering by diff facts (#1912), fast-lane bundling (#1910) — separate records.
- Changing the review-effort derivation (`review/review-effort-derivation.md`).

## Technical Approach

The roster is the contract; consumers cite it. The single-task condition reads the plan file (authoritative, already parsed by plan-audit) rather than SDD's progress ledger — the design's open question, resolved here. Both new skips are `SKIP` decision-log entries so the Review Console and Phase 6's timing see them.

- `bin/plan-audit.js --count-tasks <plan-path>` → `{tasks: n, batched: boolean}` on stdout, exit 0; exit 2 on a missing/unreadable plan.
- Decision-log literals: `SKIP {time} — Whole-branch review skipped: fast-lane, single-task plan (task review covers the whole branch). Reversibility: n/a.` and `SKIP {time} — polish skipped: fast-lane. Reversibility: n/a.`

## Gotchas

- Red-team resolution: `--count-tasks`'s canonical output shape is `{tasks: n, batched: boolean}` (the Technical Approach/Data-API-Surface version); the Deliverables bullet is aligned to the same shape, and AC2's fixture assertions include the `batched` field.
- Red-team resolution: soften "provably safe" — the safety argument is "no recorded counterexample among the `[IL-02]/[IL-04]/[IL-10]/[IL-97]/[IL-101]` incidents, all of which required 2+ tasks", an empirical observation from this codebase's incident history, not a structural proof.
- Red-team resolution: the Phase 1 blocking prerequisite is #1921 (`build/dispatch.md` reviewer seam — reviewer does not run the suite).
- Red-team resolution: worked example for the roster-citation trim boundary — before: a citing file restates "`ceremony:fast-lane` skips architecture alignment (see `build/architecture-alignment.md`)"; after: "fast-lane skip: see `_shared/ceremony-profile.md`'s roster" — the condition (which tier, what's skipped) moves to the roster; the citing file keeps only a pointer.
- Red-team resolution: the roster-conformance match is single-line, case-insensitive substring match for both `fast-lane` and `skip` on that line; "a step" is identified by requiring the step name to also appear, verbatim, as a Step column value in the roster's Skips table.
- Red-team resolution: a plan that is readable but has zero parseable tasks is also `exit 2` (treated as malformed), consistent with `plan-audit.js`'s existing Check A parser behavior.
- Red-team resolution: a Step 6.5 design finding on a polish-skipped fast-lane record is handled like any other review finding — it can still require follow-up work on the current build via the ordinary review-fix loop; the escape hatch's "next run runs standard" effect is additional, not a substitute for addressing an existing finding.

- Three touched SKILL.md files are at or within 1 KB of the 40 KB ceiling (`flow/SKILL.md` 40,138; `wrap-up/SKILL.md` 40,708; `dispatch/SKILL.md` 40,677 — do not touch dispatch). Measure `wc -c` first; move bytes into sub-files before adding a sentence (`[IL-140]`, `hard-ceiling-headroom-check`).
- The whole-branch review instruction lives in the invocation text `build/dispatch.md` composes; the third-party SDD skill file is never edited. Phase 1 pinned SDD's whole-branch review step literal in `tools/upstream-drift/manifest.yml` — reuse that assertion; do not add a second.
- "Exactly one task" must be read from the plan file, never inferred from the diff or from SDD's own narration (`[IL-07]` echo shape).
- `[IL-145]` is the precedent for a fast-lane skip letting a defect through; the escape hatch is the control. Do not weaken it; document that the new skips fall under "next run runs standard".
- The Frontier-singleton rule (`_shared/subagent-output-contract.md`) depends on SDD staying sequential — nothing here changes SDD's task loop.
- `tests/manifesto-lever-conformance.test.js` pins `ceremony-profile` lever prose; run the full suite.
- `**Related:** #1886, #1765, #1911, #1912` (adjacent records, not dependencies); `refs #N` in commits.
- "The whole branch" for the skip's guarantee means the task's own diff plus the two prose commits the pipeline itself lands on the branch before build — `materialize.md`'s `work/{n}-spec.md` and the committed plan file — which no review reads for correctness and which the skip does not change. Run-dir files (`config.yml`, `decisions.md`, `staged/`) live under the main checkout's `.claude-tweaks/pipelines/`, outside the branch entirely. Staged-patch applications happen in `/claude-tweaks:review` Step 3, after this skip and inside the lens review's own scope, so they are reviewed by the judgment that applies them. Batched-dispatch plans are excluded from the skip outright (`batched: true`) rather than argued equivalent — a batch bundles work items reviewed together, and the single-task equivalence claim does not obviously hold for it.

## Decision Rationale

See the Phase 1 sub-issue's Decision Rationale for the design-wide rationale. Specific to this unit:

- **Keep two calls.** Collapsing them for fast-lane records saves only the second call's preflight (~5 of ~15 overhead minutes) and loses the clean-room review — the same agent that built the change would review it with its framing intact (`[IL-07]`, `[IL-130]`). Fast-lane records already have spec-compliance and hindsight off, so the independent lens review is the last judgment standing; it is the wrong place to remove independence.
- **Single-task condition from the plan file**, not SDD's progress ledger: the plan is authoritative and already parsed.
- **Polish skipped, not shortened**: polish is Impeccable refinement (polish/clarify/harden); `/review` Step 6.5's read-only design judgment still runs, so a design finding still reaches the escape hatch.
- **A roster file** because today the skip list is reconstructed from five files and `[IL-93]`-style drift (five restatements, all stale) is the known failure shape.
