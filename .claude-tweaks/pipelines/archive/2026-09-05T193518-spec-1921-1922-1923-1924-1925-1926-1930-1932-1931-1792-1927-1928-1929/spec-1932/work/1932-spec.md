# 1932: Reflect depth from diff facts on every auto-mode firing, and console-resolve.js for batched unattended console auto-resolution

Surface: backend
**Related:** #1854

## Overview

Two fixed-cost tails remain after the wrap-up and preflight packs. First, reflect ran in full mode for 12 minutes on record #1535's `size:low` single-module fix because `wrap-up/ceremony-derivation.md`'s diff-derived downgrade is gated to `DISPATCH_HEADLESS=1` — the gate exists because a present human "could adjust the Manifesto's `ceremony-profile` lever", but in `auto` mode the Manifesto is a read-only FYI table and nobody adjusts it. This unit applies the derivation whenever the run's mode is `auto` (headless or human-present) and skips it only under `confirm`/`hybrid`, where the lever was actually a question. Second, at `autonomy: unattended` with `consoleAutoResolve`, the Review Console resolves each staged item in its own turn (render, log, write). `bin/console-resolve.js --run <dir> --policy console-auto` applies the contract's stance to every staged item in one process, writes one decisions block with one line per item, writes `console.json` (which the auto-resolve path never wrote — #1854, so `archive-merged.js` never archived an unattended run's directory), and prints the table the console renders once. `supervised`/`trusted` are unchanged.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- Changing the derivation's own rules (never upgrades; the escape hatch still runs after it) or reflect's lenses.
- Changing what `consoleAutoResolve` resolves each item *to* — the stances in `review-console.md`'s Auto-resolution short-circuit (Approve-all defaults, merge-half rules, the `needs-human` and ungranted-member carve-outs, `U#` filed) are applied verbatim.
- Any interactive console change.
- Adding a subcommand to `bin/stage-item.js` — its documented contract is a single write verb with fixed exit codes; the resolver is a sibling CLI.

## Technical Approach

The derivation change is a gate swap in prose (the rules are untouched). The resolver is a pure classification-and-stance module over the run dir's files plus a thin CLI that owns the three writes (decisions block, `console.json`, stdout table); side effects that need a model or an external call (memory writes, upstream filings, the merge itself) stay in the skill and consume the resolver's output.

### Data / API Surface

**Staged-item → console-section mapping (`classifyStagedItem`).** Keyed on the staged file's id prefix (the `--id <kind>-<n>` `stage-item.js` wrote) and, for the two coordination sections, on `decisions.md` entries. Initial table — verify each row against `review-console.md` and `console-template.md` at plan time and pin one test per section; **an unrecognized prefix maps to Pending review with `reason: unmapped-prefix` and is never auto-approved** (fail-safe, so a new producer cannot silently pass the console):

| Prefix / source | Section |
|---|---|
| `review-{n}.patch`, `test-fix-{n}.patch`, `deepen-collapse-{n}.patch`, any other `*.patch` (`_shared/staged-patch.md`) | Pending review (code-fix proposals; `git apply --check` gates) |
| `review-contested-{N}.md` + `decisions.md` coordination entries (`review-coordination.js`) | Contested findings / Low-confidence findings |
| `polish-suggestion-{n}.md`, `visual-review-*.md`, `design-decision-*.md` | Pending review (advisory design findings) |

| `wrap-up-memory-{N}.md` | `M#` memory updates |
| `wrap-up-upstream-{N}.md` | `U#` upstream feedback |

**Grant state (AC3).** `resolveAll({runDir, policy, deps})` takes an injected `deps.readGrants(numbers) → {number: [labels]}`; the CLI supplies a `gh issue view --json labels`-backed reader for every group member named by the run's materialized header(s); tests inject a fake. When the reader fails (`gh` absent, API error) the merge half resolves to `leave-open` with `reason: grants-unreadable` — never to merge. The module stays dependency-free and file-pure except through `deps`.

- `{run-dir}/console.json` (auto path): `{resolved: true, mode: 'auto-resolve', at, ceiling: 'unattended', items: [{id, section, resolution, reason}], merge: {resolution, reason}}`.
- Decisions block: `AUTO {HH:MM:SS} — Console auto-resolved {n} item(s) at unattended (console-resolve.js). Reversibility: per item.` then one line per item: `AUTO {HH:MM:SS} — Console item {id} ({section}): {resolution} — {reason}. Reversibility: {high|medium|n/a}.`
- CLI: `console-resolve.js --run <dir> --policy console-auto [--dry-run] [--json]` → exit 0/2/3/4.
- Module exports: `resolveAll`, `classifyStagedItem`, `SECTION_STANCES` (the table the prose cites).

## Gotchas

- Red-team resolution: `console.json`'s canonical shape includes `ceiling` (the Data/API Surface version: `{resolved: true, mode: 'auto-resolve', at, ceiling, items, merge}`) — the Deliverable's inline spec is aligned to match, since `archive-merged.js`/AC6 need the `ceiling` field.
- Red-team resolution: the canonical decisions-block header literal is the Data/API Surface version: `AUTO {HH:MM:SS} — Console auto-resolved {n} item(s) at unattended (console-resolve.js). Reversibility: per item.`
- Red-team resolution: In an unattended run, `review-console.md`'s short-circuit falls through per exit code — exit 4 (ceiling not granted) renders the ordinary interactive console (a human/lower-autonomy path, unaffected); exit 2/3 (malformed/not-anchored) is treated as a HARD-GATE failure — the wrap-up run stops and reports the CLI error rather than attempting "Present a real stop" (which has no answerer in unattended mode), consistent with this codebase's existing fail-loud-on-malformed-input convention.
- Red-team resolution: exit code 2 covers a malformed `--policy` value (anything other than `console-auto`) or a `--run` argument that isn't a directory.
- Red-team resolution: confirmed via reading `plugin/bin/lib/reconcile/archive-merged.js` — `readConsoleState` already returns `'resolved'` whenever `parsed.resolved === true`, with no check on a `mode` field; the proposed auto-resolve shape already passes unmodified. This deliverable becomes: add ONLY a regression test (`tests/bin-lib/reconcile/archive-merged.test.js`) confirming this — no code change to `archive-merged.js` itself is needed.
- Red-team resolution: add a test asserting `console-resolve.js`'s full run (module + CLI) makes zero `gh pr merge`/`git merge` invocations (spy on every `execFileSync` call across a fixture run) — pinning the "merge is computed but not executed" boundary the Gotchas already state in prose.
- Red-team resolution: the justification for widening the ceremony-derivation gate rests on a structural fact, not an unverified behavioral claim — `flow/manifesto.md`'s auto-mode FYI variant never calls `AskUserQuestion`, so there is no UI surface for adjusting `ceremony-profile` in `auto` mode at all (not merely an assumption that humans don't use one).
- Red-team resolution: `resolveAll` reads all inputs (`decisions.md`, every `staged/` item, member grant/label state) into memory as one snapshot BEFORE computing any item's resolution — no item's classification or stance can depend on another item's resolution within the same run, by construction (a single read pass, then a pure map over the snapshot).
- Red-team resolution: the Overview's mode list is aligned with the Deliverable's — the ceremony-derivation gate skips under `confirm`/`hybrid`/`interactive` (all three), and when no `config.yml` exists.
- Red-team resolution: AC1 is extended with explicit sub-cases for `mode: hybrid`, `mode: interactive`, and the missing-`config.yml` path (each writing nothing), alongside the existing `mode: confirm` case.
- Red-team resolution: the `tests/flow-claim-preflight.test.js` Key Files entry is dropped — confirmed (by reading the test) that it pins `DISPATCH_HEADLESS` against `task-prompt.md`/`claim-targets.md` only, never `ceremony-derivation.md`, so no re-scoping is needed.

- The resolver must re-check `consoleAutoResolve` itself (exit 4 otherwise) — a CLI that resolves a console at `supervised` would silence a stop the auto-mode contract lists as never silenced.
- The merge half is computed, never executed, by the CLI: `gh pr merge` stays in the skill's existing path (`_shared/pr-first-merge.md`), after acceptance labeling (`verification-brief.md`'s ordering is load-bearing).
- `needs-human` and ungranted-member carve-outs must be honoured exactly as `review-console.md` states them; copy the wording into `SECTION_STANCES` comments and pin with tests.
- Staged patches: `git apply --check` at resolution time; stale → re-derive from `Invariant:`, never apply blind (`_shared/staged-patch.md`).
- `console.json` must be readable by `archive-merged.js`'s `readConsoleState` — read that function before choosing field names; #1854's fix is this write.
- `tests/flow-claim-preflight.test.js` pins `DISPATCH_HEADLESS` somewhere; find which file it reads before removing the literal from `ceremony-derivation.md`.
- Under `--dry-run` nothing is written — including `console.json`.
- `**Related:** #1854` (superseded by this unit's `console.json` write; the PR carries `Fixes #1854`); `refs #N` in intermediate commits.

## Decision Rationale

See the Phase 1 sub-issue's Decision Rationale for the design-wide rationale. Specific to this unit: the headless gate protected a lever nobody adjusts in `auto` mode, so the gate is the mode, not the presence of a human; batching the console at `unattended` changes no decision, only the number of turns; a sibling CLI rather than a `stage-item.js` verb because that CLI's exit-code contract is documented and pinned.
