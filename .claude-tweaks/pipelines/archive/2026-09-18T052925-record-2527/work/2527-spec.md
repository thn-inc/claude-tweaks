# 2527: /test's Skip-if-recent verify branch may not reliably skip a same-sha re-verify after /build

Origin: reflect full from #2492
Defer-reason: tangential

## Current State

`plugin/skills/test/verification.md`'s Skip-if-recent procedure says a `/test` step running in the
same `/flow` conversation as `/build` should skip full type/lint/test verification when the
in-conversation `VERIFICATION_SHA` context matches `git rev-parse HEAD`. During record #2492's own
build->test dispatch, `events.jsonl` shows build's own final verify completing at 18:37:12Z on sha
`b8b874f4911c0a16b62c44e4f9ac284f718b1577` (`mode: full`), followed by `/test`'s own verify at
18:41:39Z on the identical sha, also `mode: full` — a second ~140s full-suite run against a tree
that had not changed since build's own passing verify. The skip condition is a soft,
natural-language check with no mechanical enforcement, unlike `checkBookkeepingStampsGate`'s
worktree/PR stamps — the same enforcement-gap shape #2492 itself named for the Step 2.8 claim
write (`plugin/skills/flow/claim-targets.md`'s "Known gap" note), just for a different step. Not
confirmed whether the in-conversation signal was actually unavailable to `/test` or was available
and not consulted — the evidence is the duplicate-sha verify pair from this run's own
`events.jsonl`, not a traced root cause inside `/test`'s own execution.

## Deliverables

- [ ] Reproduce a `/flow #{n} build,test` (or `build,test,review,...`) run and confirm, from the
      conversation itself, whether the `VERIFICATION_PASSED`/`VERIFICATION_SHA` signal `/build`'s
      Common Step 5 sets is actually read by `/test`'s Step 1 before it decides to run the full
      suite again
- [ ] If the signal is available but not consulted, fix `/test`'s Step 1 to honor it (or document
      why re-verification is intentional there) and add a regression test/assertion pinning the
      skip
- [ ] If the signal genuinely cannot reach `/test` in this dispatch shape (e.g. a subagent
      boundary that doesn't carry natural-language context the way `flow/SKILL.md` assumes),
      document that limitation in `verification.md` rather than leaving the skip described as
      unconditional

## Acceptance Criteria

- [ ] A `/flow #{n} build,test` run on an unchanged tree either (a) demonstrably skips `/test`'s
      full verification per the Skip-if-recent branch, confirmed by absence of a second full-suite
      `verify` event at the same sha in `events.jsonl`, or (b) the skip condition's actual
      unavailability in this dispatch shape is named and documented, not silently assumed to work
