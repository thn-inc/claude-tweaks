# 1432: Conformance lint for docs/skill-graph.md table structure — unescaped pipes and column counts

Surface: backend

Origin: reflect hindsight from #1274
Defer-reason: tangential

## Current State

`docs/skill-graph.md` is the single source of truth for every skill relationship (CLAUDE.md Cross-references), yet nothing validates its table structure mechanically. `tests/skill-catalog-completeness.test.js` and `tests/skill-conventions.test.js` check section presence and Relationship-section absence only. #1274's build shipped an unescaped `|` inside a code span in a two-column row (`^CEREMONY: (fast-lane|standard)$`), which GFM parses as a phantom third cell — silently truncating the row's load-bearing clause from the rendered table. Every task-level review passed; only the whole-scope reviewer's manual GFM cell-count check caught it (finding Important 1, fixed in `4a80c44f`). The same defect class can land in any of the file's ~400 rows at any time, and the existing suites are structurally blind to it.

## Deliverables

- [ ] A `node --test` suite (e.g. `tests/skill-graph-table-structure.test.js`) that, for every table in `docs/skill-graph.md`, counts unescaped pipes per row (a pipe not preceded by `\`) and asserts each data row's cell count equals its header's — naming file:line for every offender.
- [ ] A go-red proof per the `skill-prose-conformance-tests` skill: a hand-built minimal pair (a valid row; the same row with one unescaped pipe inside a code span) run through the counting helper, so the helper itself is proven discriminating.
- [ ] Consider extending the sweep to the other `docs/*.md` files whose tables are load-bearing (`docs/plugin-structure.md`) — or state why skill-graph.md alone is the right scope.

## Acceptance Criteria

1. The new suite fails on a planted unescaped pipe inside a code span in a two-column skill-graph row (proven via the synthetic minimal pair, not tree mutation) and passes on the live file.
2. `npm test` picks the suite up with no registration (the recursive glob) and passes.
