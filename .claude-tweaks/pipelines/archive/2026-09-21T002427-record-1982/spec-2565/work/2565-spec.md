# #2565 — reconcile: archive check tests the main checkout's HEAD, so merged runs stay `local-behind-merge`

Materialized from GitHub issue #2565 (labels: bug, ready, size:medium, type:bug, auto:build, priority:high, risk:medium, ceremony:standard, shaped:headless).

## Deliverables

1. `localHasMerge` tests the merge commit's ancestry against the local integration-branch ref (`refs/heads/{integration-branch}`) — or `origin/{integration-branch}` after a fetch when stale — instead of `HEAD`.
2. `mirrorFastForward` gains a path that updates a non-checked-out local integration branch via `git fetch origin {integration}:{integration}` (git refuses loudly when it wouldn't fast-forward — same safety as `--ff-only`), instead of unconditionally skipping with `wrong-branch`.
3. The existing `wrong-branch` skip path is preserved as fallback only when the fetch-based update isn't viable (e.g. no local integration branch ref exists yet).

## Acceptance Criteria

1. With `integration-branch: develop` checked out under another name in the main checkout, and a merged run's commit present on `origin/develop`, `reconcile --checks mirror,release,archive` updates the local `develop` ref via fetch, without needing it checked out.
2. `localHasMerge` reports the merge commit present once the local ref is updated, using that ref (or `origin/develop`), not `HEAD`.
3. The merged run's reconcile status advances past `local-behind-merge` without manual intervention.
4. When the main checkout IS on the integration branch, behavior is unchanged.
5. When the local integration ref would NOT fast-forward from origin (genuine divergence), the fetch-based update fails loudly rather than silently rewriting history.
6. The `wrong-branch` skip reason still fires for the residual case the fetch fix doesn't cover.

- `plugin/bin/lib/reconcile/classify.js` — `classifyMirror` — confirm its ref-to-ref comparison already handles the non-checked-out case; only the write step needs the fix.
