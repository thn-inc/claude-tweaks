# #2568 — console-execution: no way to resolve a pending-review console answered in chat instead of via PR checkboxes

Materialized from GitHub issue #2568 (labels: enhancement, ready, size:medium, type:feature, auto:build, priority:medium, risk:medium, ceremony:standard, shaped:headless).

## Deliverables

1. A new `hooks.js resolve-console --run {run-dir} --approve {ids} --decline {ids}` subcommand that performs the three coupled writes described in `console-execution.md`'s "Write order after execution" section, in the documented order: (1) post a reply comment (`<!-- console-item: executed -->`) summarizing per-item outcomes, (2) edit the console comment's first line to add `<!-- claude-tweaks-console-resolved -->`, (3) write `console.json.executedAt` and `console.json.resolved: true` together in one write.
2. The new verb reuses `console-execute.js`'s existing parsing/decision helpers (`readConsoleJson`, `isResolveTicked`, `parseItemTicks`, `decideConsoleExecute`) rather than re-deriving console state independently.
3. `console-execution.md`'s "Live-session accelerator" section is updated to name this verb as the concrete mechanism behind "perform the same Write order".
4. Registration in `hooks.js`'s `USAGE`/`KNOWN_FLAGS` tables following the `record-worktree` pattern: `--run` is required (no implicit "newest non-terminal run" fallback), `--help`/unknown-flag interception wired the same way as every other mutating verb.

## Acceptance Criteria

- `resolve-console --run {run-dir} --approve 1,2,3 --decline 4,5,6` posts exactly one reply comment, before editing the console comment's first line, before writing `console.json.executedAt`/`resolved: true` in one write — exact call order verified by a unit test with an injected fake runner.
- Omitting `--run` exits non-zero with a usage message and performs zero writes.
- Running against an already-`resolved: true` console, or one with a live (non-stale) `executingAt` claim, no-ops and reports that state.
- An unknown id in `--approve`/`--decline` exits non-zero naming the unknown id(s), zero writes.
- A declined id logs "declined, no reason given"; no execution procedure runs for it.
- A declined `isMergeRow: true` item does not tick Resolve if any other item remains unticked.
- `npm test` passes in full, including a new suite exercising write-order and idempotence via a fake runner.
- `console-execution.md`'s "Live-session accelerator" names the new verb explicitly.

## Key Files

- `plugin/bin/hooks.js` — add `resolve-console` case to `main(argv)` dispatch (near `record-worktree`); register in `USAGE`/`KNOWN_FLAGS`.
- `plugin/bin/lib/reconcile/console-execute.js` — add the write-performing function composing existing read-only helpers with the new three-step write sequence.
- `plugin/skills/_shared/console-execution.md` — update "Chat answers first" bullet.
- `tests/bin-lib/reconcile/` — new test coverage.
