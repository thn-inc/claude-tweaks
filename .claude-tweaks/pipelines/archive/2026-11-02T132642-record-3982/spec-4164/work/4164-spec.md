# 4164: Tiebreak resolver rejects correct evidence for skill-relative Locations and backtick-bearing quotes

Surface: infra

**Related:** #3986, #4198, #4244, #4292, #4294, #4345

Origin: #3950 acceptance run and final whole-branch review (PR #3992) — parked observation, ruled out of #3950's scope
Defer-reason: tangential

## Current State

`resolveTiebreak` (`plugin/bin/lib/tiebreak.js:261`) settles each tiebreak judge's reply for `/claude-tweaks:review` Step 3.7 (`plugin/skills/review/step3-tiebreak.md`) and the refutation pass. The `resolve-tiebreak` verb of `plugin/bin/review-coordination.js` (`:205-232`) feeds it a `readFile` confined to `--root`. Before accepting a confirmed or refuted verdict, `evidenceProblem` (`tiebreak.js:230-246`) checks three things, in this order:

- `evidence.path !== finding.path` returns `'evidence-path-mismatch'`.
- The cited line must sit within ±5 of the finding's line (`LINE_TOLERANCE_REPRODUCTION_WIDE`, `plugin/bin/lib/coordination.js:17`).
- The whitespace-squashed quote must appear in the ±5-line window of `readFile(finding.path)`.

A rejected verdict falls back to can't-tell handling, which files or digests a finding the judge actually settled.

**Case 1, skill-relative Location (still reproduces).** On current main, a finding with path `wrap-up/x.md`, given a correct reply citing `plugin/skills/wrap-up/x.md:10` with the verbatim line, resolves `digest` with reason `evidence-path-mismatch` (probed against `tiebreak.js` at HEAD). Even with the path equality relaxed, `readFile(finding.path)` would resolve `wrap-up/x.md` against `--root` and fail, so the read would also need the canonical path.

**Case 2, backtick-bearing quote (already resolved; premise corrected).** The filed request says a quote whose source line contains backticks fails. On current main it does not. `stripWrapper` (`tiebreak.js:81-94`, landed in #3817) strips a Markdown code span of any equal backtick run, padding included. The check is a substring match against the squashed window, not a whole-line equality. Probed on HEAD, a single-backtick wrap of ``Run `foo` then `bar` now`` and of `` `a` and `b` `` both resolve `confirmed`. `tests/bin-lib/tiebreak.test.js:334` ("a code span of any backtick run…") already pins the backtick-led form.

## Deliverables

1. `evidenceProblem` accepts a skill-relative finding path when `'plugin/skills/' + finding.path === evidence.path`, and reads the file through that canonical path. A finding path that already starts with `plugin/` is compared exactly as today.
2. A test for case 1 goes red on the current resolver and green after the change.
3. A regression test for case 2's template-literal shape: a single-backtick wrap of a source line that itself contains backticks resolves to the judge's verdict. This pins today's correct behavior so a future parser change cannot reintroduce the report.

## Acceptance Criteria

1. Finding `{ path: 'wrap-up/x.md', line: 10 }` with reply Evidence `plugin/skills/wrap-up/x.md:10` plus the verbatim line, and a reader that serves only `plugin/skills/wrap-up/x.md`, resolves `confirmed`. The same test resolves `evidence-path-mismatch` with the change reverted.
2. Finding `wrap-up/x.md` with Evidence `plugin/skills/review/x.md:10` still resolves `evidence-path-mismatch`. So does Evidence `plugin/bin/x.md:10`.
3. A finding with full path `plugin/skills/wrap-up/x.md` behaves exactly as before. The existing `tests/bin-lib/tiebreak.test.js` cases pass unchanged.
4. The case-2 regression test resolves `confirmed` for Evidence `` `Run `foo` then `bar` now` `` against that source line.
5. `npm test` passes.

## Release Note

Review tiebreak verdicts are no longer discarded when a finding's location is written relative to its skill.

## Technical Approach

Normalize once, at the top of `evidenceProblem`. Compute the canonical finding path: the path as given when it starts with `plugin/`, else `plugin/skills/{path}` only when `evidence.path` equals that. Use it for both the equality check and the `readFile` call. Keep `--root` confinement in `review-coordination.js` unchanged, since the canonical path is still repo-relative. Do not widen the rule to other prefixes (`plugin/bin/`, `tests/`). The skill-relative shape is the only legacy form observed.

### Key Files

- `plugin/bin/lib/tiebreak.js` — `evidenceProblem` path canonicalisation and read path
- `tests/bin-lib/tiebreak.test.js` — case-1 go-red test, mismatch guards, case-2 regression pin
- `plugin/bin/review-coordination.js` — reference only: the `--root`-confined `readFile` the canonical path must still pass

## Gotchas

- The logged `where` string (`tiebreak.js:270`) and the refuted drop line use `finding.path`. Leave them showing the finding's own Location so the decisions.md trail still matches the reported finding.
- `findingId` hashes `finding.path` (`tiebreak.js:55`). Do not canonicalise the finding object itself, or tiebreak ids and `checkRunTiebreakCoverage` matching would shift for existing runs.
- The step3-tiebreak.md template already tells judges to cite "the Location path exactly as given". For a legacy skill-relative Location, a judge citing the full path is right in substance, which is why the resolver, not the template, absorbs the difference.

## Current State

`resolve-tiebreak` (the resolver `/claude-tweaks:review` Step 3.7 `step3-tiebreak.md` and the refutation pass feed each judge's reply through) checks a confirmed or refuted verdict's `Evidence:` line: the cited path must be the finding's Location path, the line within 5 of it, and the quote the whole source line verbatim. Two cases fail that check although the judge's evidence is correct:

1. A legacy Location written skill-relative (`wrap-up/x.md`) never matches a correct full-path Evidence line (`plugin/skills/wrap-up/x.md`), so a correct verdict is discarded.
2. An Evidence quote whose source line contains a backtick fails the verbatim comparison, because the reply template wraps the quote in backticks.

A discarded verdict falls back to can't-tell handling, which files or digests a finding the judge actually settled.

## Deliverables

- The path check accepts a skill-relative Location when the Evidence path is the same file under `plugin/skills/`.
- The quote check handles a source line containing backticks — either the template's quote delimiter changes, or the parser takes the outermost delimiters.

## Acceptance Criteria

- A resolver test with Location `wrap-up/x.md:10` and Evidence `plugin/skills/wrap-up/x.md:10` plus a verbatim quote resolves to the judge's verdict; the same test fails against the current resolver.
- A resolver test whose quoted source line contains a backtick resolves to the judge's verdict; it fails against the current resolver.
- A mismatched path (another file) is still rejected.

## Release Note

Review tiebreak verdicts are no longer discarded when a finding's location is written relative to its skill or the quoted line contains a backtick.
