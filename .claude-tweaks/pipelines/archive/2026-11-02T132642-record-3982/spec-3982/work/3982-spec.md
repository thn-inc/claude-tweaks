**Related:** #2767, #3702, #3703, #3742, #3751, #3776, #3953, #3983, #3993, #3995

## Current State

The post-merge Windows check on commit c31b0e07c (merged PR #3919) reported `tests/reconcile.test.js` newly failing. The failing test is "archiveRunDir: the git mv of work/ is committed, not left staged (no uncommitted rename after archival)" (line 485), with:

```
+ '.claude-tweaks/pipelines/archive/2026-08-14T120000-spec-999/work/999-spec.md'
- '.claude-tweaks\\pipelines\\archive\\2026-08-14T120000-spec-999\\work\\999-spec.md'
```

Root cause, read from current `main` (d02483933): the assertion at line 501 compares `git ls-files -- {archivedWorkRel}` output, which git always prints with `/` separators, against `path.join(archivedWorkRel, '999-spec.md')`, which is `\`-separated on Windows. The production code (`archiveRunDir` in `plugin/bin/lib/reconcile/archive-merged.js`) behaves correctly: the archived file is committed at the right path. Only the test's expected value is platform-joined. This is the path-separator class #2767 tracks, not a CRLF read. Line 501 is the only `ls-files`-vs-`path.join` comparison in the file.

`plugin/bin/lib/shared-primitives.js` exports `toPosix(p)`, the house helper for converting a platform path to git's `/` form.

## Deliverables

1. `tests/reconcile.test.js`: build line 501's expected value in git's separator form, `toPosix(path.join(archivedWorkRel, '999-spec.md'))` using `shared-primitives`' `toPosix`, so the comparison holds on every platform.

## Acceptance Criteria

1. The `archiveRunDir: the git mv of work/ is committed…` test's `ls-files` assertion compares against a `/`-separated expected path on every platform.
2. Under a `path.sep` simulation where the expected value is built with `path.win32.join` (or the assertion is exercised with `toPosix(p, '\\')` on a backslash-joined input), the assertion still matches git's output. This is demonstrated in the PR or by a small unit check.
3. `node --test tests/reconcile.test.js` is green on Linux/macOS.
4. The next post-merge Windows check (`.github/workflows/windows-regression.yml`) no longer lists this test file.

## Release Note

Fix a Windows-only failure in the reconcile archival test caused by path separators.

## Technical Approach

Import `toPosix` from `../plugin/bin/lib/shared-primitives` and wrap the expected path. The `git status --porcelain -- {archivedWorkRel} {oldWorkRel}` assertion two lines above passes platform paths as pathspecs, which Git for Windows accepts, and compares against `''`, so it needs no change. No production code changes.

### Key Files

- `tests/reconcile.test.js` — line 501's expected path converted with `toPosix`
- `plugin/bin/lib/shared-primitives.js` — `toPosix` reused (read-only)

## Gotchas

- Do not change the expectation to a hardcoded `/`-joined string literal built from `runId`. Converting the already-computed relative path keeps the test tied to the same `archiveDir` derivation as the code under test.
- CI runs on ubuntu only, so only the post-merge `windows-regression.yml` run proves this on Windows.
