# 1875: pr-early-run-lifecycle.md's fixed-per-issue temp path can silently serve a stale draft on retry

# Reflect — staged finding (queue write 1)

**Category:** tangential

Origin: reflect full mode from #1687
Defer-reason: tangential

## Current State

`pr-early-run-lifecycle.md`'s Step 3 template composes the draft PR body to a fixed path keyed only by issue number: `/tmp/pr-early-body-{n}.md`. When a run against the same issue is retried after a prior attempt reached this same step (e.g. a failed build, released claim, fresh run-id), the fresh authoring step can write its content somewhere the later `gh pr create --body-file` invocation never reads (observed on Windows: the `Write` tool and the `Bash` tool resolve `/tmp` to different real paths — see the companion memory entry), leaving the prior attempt's stale file in place at the fixed path. `gh pr create` then silently opens the PR with the wrong run-id marker, Resume line, and phase checklist.

## Deliverables

- [ ] Scope the temp path by run-id, not just issue number (e.g. `/tmp/pr-early-body-{run-id}-{n}.md`), in `pr-early-run-lifecycle.md`'s Step 3 template and its citing call sites.
- [ ] Consider a cheap sanity check — re-read the composed file's first line back before invoking `gh pr create`/`gh pr edit`, confirming it names this run's own `run-id` — as a second line of defense against a divergent-tmp-path class of bug on any OS.

## Acceptance Criteria

1. A retried run against the same issue number never opens or edits a PR carrying a different run's `claude-tweaks-run` marker.
2. `npm test` passes.
