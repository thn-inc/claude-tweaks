# 1703: capture: exempt --source intake from the deferral check and name intake as a parent

Surface: backend

**Related:** #1423

## Overview

`/claude-tweaks:capture` treats every `--source` value as a deferral signal: the Shaped-body branch's deferral check (precedence item 2) and the `--defer-reason=` Input-table row both say a filing with *any* `--source` must carry a valid `--defer-reason=` or stop and file nothing. That rule exists for producers filing exhaust from a build (`--source build`, `--source reflect`, the health sweeps' triage captures). The upcoming `/claude-tweaks:intake` skill (#1704) is a different caller: it delegates a human's own braindump fragments to `/capture` — human intent, never exhaust (the same distinction `_shared/materiality-floor.md` already draws for human-typed `/capture` input) — and it needs `--source intake` purely as the parent signal that suppresses `/capture`'s `## Next Actions` block mid-report. Without an exemption, intake would either have to invent a `Defer-reason:` (a lie) or let `/capture` render Next Actions inside intake's own report.

This unit adds `--source intake` as a **named exemption** to the deferral check — expand-only — and adds intake to `/capture`'s parent list. Every other `--source` value keeps today's semantics unchanged.

**Complexity:** Low
**Estimated tasks:** 3

## Non-Goals

- Loosening the "any `--source`" rule for any value other than `intake` — `build`, `reflect`, and the health-sweep sources stay deferrals.
- Changing the headless absorb bar (`capture/routing.md`) — every intake→capture call carries an explicit `--route=` (#1704's Data / API Surface: `--route=keep` on the batch call, `--route=absorb:N` on each absorb call), and `routing.md`'s bar says "explicit `--route` wins", so the bar never fires for intake and needs no text.
- Creating the intake skill itself — #1704, the sibling sub-issue under this parent.
- Touching `_shared/deferral-gate.md` — its line 10 reads "`skills/capture/SKILL.md` (Shaped-body branch — `--defer-reason=` validation and the deferral check)" in its owner list, and a regex search of that file for `--source` finds no other mention (verified 2026-08-30), so there is no second copy of the "any `--source`" rule to caveat; the exemption lives at the one owner.
- Verifying invoker identity — see Gotchas: `--source` is a prose-trusted flag for every value it accepts today, and this unit inherits that model rather than changing it.

## Gotchas

- **Trust boundary (red-team, Skeptical Reviewer).** The exemption keys on the literal flag value `--source intake`; nothing verifies the caller is `/claude-tweaks:intake`. This is the existing trust model for the whole `--source` family — `--source build` and `--source reflect` are equally unverified — and the gate this flag bypasses (deferral reason) protects *exhaust bookkeeping*, not a destructive action; the filing itself is still a plain backlog stub a human reviewed in intake's table. State this in the CSC paragraph (Deliverable 3b) rather than leaving it implicit; do not build an identity check — there is no code path to put one in.
- The literal token `source` inside a Bash `grep` pattern trips the worktree session's command guard ("runs a string through source") — search this file with `node -e` and a regex instead of `grep "--source"`.
- `#1423` (`bot:in-progress`) also edits `plugin/skills/capture/SKILL.md` (a blocked-by edge for Current-State narration) — expect a merge on that file; the two edits touch different sections (Input table / Shaped-body branch / CSC here; the Entry Format guidance there).
- `capture/routing.md`'s headless bar names `--source` as a trigger; do **not** add intake text there — every intake→capture call carries an explicit `--route=` (#1704's Data / API Surface) and the bar's own rule says explicit `--route` wins. Adding a second exemption site would be the drift this unit's single-statement rule exists to avoid.
- There is no behavioral test to write: the deferral check is prose applied by the model at invocation time, with no `bin/` function behind it. The prose pins in the new test block are the entire enforceable surface — the same enforcement model every other `capture/SKILL.md` rule already has.
- Keep the added prose short: the file has ~4.3 KB of headroom and a sibling in-progress edit; a 40 KB overrun fails `tests/bin-lib/skill-audit/context-cost.test.js`.
- Per `docs/skill-authoring.md`, a skill reference inside actionable text must be the fully-qualified `/claude-tweaks:intake` form; the bare `/intake` form belongs only in `docs/skill-graph.md`'s table cells.

## Decision Rationale

Why a named exemption rather than dropping the "any `--source`" rule: the rule protects the deferral gate for every producer that files exhaust (`_shared/deferral-gate.md`'s hard gate — a deferral with no reason is the predictable failure mode). Intake is the one caller whose `--source` carries human intent, and `_shared/materiality-floor.md` already draws that same human-input line. Naming the single exempt value keeps the gate intact for everyone else and makes the exemption greppable. Why not `--pre-confirmed`-style plumbing or a new flag: a new flag would need its own Input-table row, parse rule, and test for a one-caller need; reusing the existing parent-signal flag with one named value is the smallest correct change. See the parent record (#1702) Decision Rationale for the intake design as a whole.
