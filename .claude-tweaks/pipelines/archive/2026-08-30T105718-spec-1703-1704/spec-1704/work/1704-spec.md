# 1704: Add /claude-tweaks:intake — the braindump gatekeeper (skill, catalog registration, conformance tests)

Surface: backend

**Related:** #1494, #1492

## Overview

Add `/claude-tweaks:intake`, the braindump gatekeeper: a human-only skill that takes a mixed dump of text (a paste, or `--file <path>`), splits it into fragments, judges each fragment against *this* repo, assigns one verdict from a closed ordered set, renders one batch table plus one `AskUserQuestion`, runs at most one nudge round, and delegates every write to the writers that already exist — `/claude-tweaks:capture` (`--batch --route=keep --source intake` for `file`, `--route=absorb:N --source intake` per absorb), `/claude-tweaks:feedback "<text>"` for `upstream`, and `_shared/learning-routing.md`'s "Memory write procedure (D4)" for `remember`. The report ends with an Actions Performed table, a Dropped section (nothing silent), a paste-ready Carry-over block of `not-here` fragments, and fully-qualified Next Actions. This unit also registers the skill in every catalog surface the repo's conformance tests enforce, adds the skill's own conformance test, and ships a graded fixture so the behavioral check is repeatable.

**Complexity:** Medium
**Estimated tasks:** 8 — (1) SKILL.md scaffold + Steps 1–3; (2) Steps 4–7, Decisions, Anti-Patterns, Next Actions; (3) the two fixture files; (4) `docs/skill-graph.md` + `docs/plugin-structure.md`; (5) the three `/help` surfaces; (6) `README.md` + `docs/getting-started.md`; (7) `tests/skill-conventions.test.js` edit; (8) `tests/intake-conformance.test.js` + the dogfood run. The Deliverables checkboxes below group into these eight.

## Non-Goals

- Extraction of any kind — intake never fetches a URL, reads a video, or calls a user-config skill; a URL-only fragment is a `nudge` ("what's in this?").
- An `auto`/headless mode, a `/flow` step, a Routine template, or a `--yes` flag — recorded as a decision inside the SKILL.md, not an omission.
- A new `_shared/*.md` contract, new labels, policy keys, hooks, or `bin/` code.
- Cross-repo routing — one repo per run; `not-here` fragments are returned as text.
- A tiered "inspiration/reference" shelf — the gate is strict: `file`/`absorb` or a visible non-filing verdict.
- The `/capture` `--source intake` exemption — #1703, which this unit depends on.
- Editing `docs/skill-graph.md`'s `## capture` section — #1703 owns that row; this unit adds the `## intake` section.
- Automated grading of a dump's verdicts — the graded fixture is compared by a human at dogfood time; no test asserts model judgment.

## Technical Approach

One new SKILL.md written to the repo's authoring conventions; the judgment lives in prose the model applies, not in code. Every write delegates to an existing skill via the `Skill` tool with fully-qualified names. Registration is one edit per catalog surface, each shaped like the existing `/capture` entry beside it. The conformance test reads the live SKILL.md (a legitimate live-corpus pin per the `skill-prose-conformance-tests` skill: it enforces a documented convention against future edits) and is proven discriminating by reverting. Behavioral correctness is covered by the graded fixture pair, compared by a human — the plugin has no harness for asserting model judgment, and this record does not invent one.

## Gotchas

- The `Skill` tool requires the fully-qualified `/claude-tweaks:{skill}` form inside step bodies and Next Actions; a bare `/capture` there fails with "Unknown skill" at invocation time (CLAUDE.md Cross-references). Bare forms are allowed only in descriptive prose and `docs/skill-graph.md` cells.
- Copy the interaction-style directive from `capture/SKILL.md` verbatim — `tests/skill-conventions.test.js` compares it byte-for-byte.
- `tests/skill-catalog-completeness.test.js`'s `mentionsSkill` matches `claude-tweaks:intake` or `` `/intake` `` followed by a non-name character; a plain "intake" in prose does not count.
- `/capture`'s batch mode with `--route=keep` renders no routing prompt (`batch-mode.md` Routing section) — do not add an intake-side "keep" prompt on top; the intake table is the one decision.
- `/capture`'s Component-Skill Contract suppresses its `## Next Actions` when `--source` is passed; if #1703 has not merged, `/capture` instead stops on a missing `--defer-reason=` — that stop is the signal the prerequisite is unmerged, not a bug in this unit. The native blocked-by edge keeps a headless dispatch from reaching that state at all.
- Do not restate any skill edge inside the SKILL.md (no Relationship table since v6.34.0) — edges go in `docs/skill-graph.md` once.
- `README.md` and `plugin/skills/help/context-flow.md` diagrams are cross-checked by the maintainer convention in CLAUDE.md, not by a test — edit both in the same commit.
- Judging Definition and Type guessing are `/capture`'s per-entry job; intake passes neither `--type=` nor `--needs-definition` unless the fragment states it outright.
- The self-reference collapse fails toward *self*: an unreadable, missing, or unclassifiable `origin` sets `$SELF_REPO` to `true`, so an uncertain identity can never file a `/feedback` issue. The cost of that direction is one learning landing as a `file` stub instead of an upstream issue; the cost of the other direction is the plugin filing issues against itself from its own repo.
- The nudge round and the empty-input prompt are free-text prompts, not `AskUserQuestion` calls — the convention allows one `AskUserQuestion` per decision, and the run's one decision is the table.
- `#1494` (`bot:in-progress`, adds `/claude-tweaks:sweep`) and `#1490` both edit `docs/skill-graph.md`; `#1492` edits `reference-card.md` — expect additive merges on those hub files; none of their edits touch intake's sections.
- In a worktree session, `grep` patterns containing the token `source` are refused by the command guard — use `node -e` with a regex for any search touching `--source`.

## Decision Rationale

See the parent record (#1702) Decision Rationale — strict gate, no `auto` mode, extraction in user config, one repo per run, name `intake`, writers reused rather than reimplemented, `/feedback`'s confirm gate kept. This unit adds three local decisions: (1) the fixtures live under `tests/fixtures/` rather than `evals/` because they are dogfood input plus a human-graded expectation, not an eval scenario with a scored assertion; (2) failure semantics are best-effort per fragment, because the alternative — aborting the run on one failed absorb — would strand every later fragment's already-approved verdict behind a fault in an unrelated record; (3) the self-reference collapse resolves uncertainty toward self (no external filing), the same fail-safe direction `_shared/materiality-floor.md` takes when an axis cannot be judged.
