# 2022: Dispatched review agents leave probe files in the worktree; no mandated scratch location or post-fan-out untracked-file sweep

Surface: infra

## Current State
`/claude-tweaks:review` dispatches up to a dozen agents per run — reproduction-pair lens agents (`step3-lens-dispatch.md`, 3a–3f), cross-lens debate judges and per-candidate refutation agents (`step3-debate-and-refutation.md`, Step 3.5), and the gap-sweep critic (Step 3.6) — each with "fresh read access to the actual current file content" and no instruction about where to put anything they write. The main thread already has a per-review scratch directory: `build-review-context.js mint` produces `{ctx-dir}` (`{run}/review-ctx` under a pipeline run, a unique system-temp directory otherwise), and every file the *skill* writes (`lens-*.json`, `findings-by-lens.json`) lives there. The dispatch prompts hand agents the bundle path inside it but never say "write your probe scripts here"; an agent that wants to execute a snippet drops `zz-*.mts` or `__bench_*.mjs` in the worktree root or beside the module under review. The only untracked-file check in the skill is the post-dispatch diff audit in `step3-routing.md`, which runs `git status --porcelain` after *fix* agents return, not after the lens/refutation/gap-sweep fan-out. Observed cost on a 12-agent `xhigh` review: a false architecture finding ("throwaway debug script committed in the module directory" — an untracked sibling-agent leftover), `tsc` errors for a later implementer from a reviewer's stray file, and four manual `rm` sweeps. Nothing was committed only because every commit used explicit paths. (The record names `curation-engine.md` as the sweep site; that file belongs to `/wrap-up`'s curation registry, and the review-side collection points are the ones above.)

## Deliverables
- [ ] One "Scratch rule" paragraph in `_shared/subagent-output-contract.md`'s input-discipline section, stated once and cited by every dispatch template that hands an agent write access: any file an agent creates to verify its work (probe script, benchmark, fixture) goes under the scratch directory the prompt names, never under the repository tree; the agent deletes what it created before its status word; a dispatch prompt that gives an agent write access must name a scratch path.
- [ ] The three review dispatch templates (`step3-lens-dispatch.md`'s per-lens Calibration/Output template's *outer* prompt, not the byte-identical Calibration block; `step3-debate-and-refutation.md`'s refutation and gap-sweep templates) gain a `SCRATCH: {ctx-dir}/agent-scratch/{agent-id}` line, minted per dispatch under the existing `{ctx-dir}`, and cite the contract's Scratch rule. Debate judges write nothing and get no line.
- [ ] A post-fan-out untracked-file sweep in `step3-lens-dispatch.md`, run once after every reproduction pair (and, at `high`+, after Step 3.5/3.6) has returned and before Step 3 Routing: `git status --porcelain --untracked-files=all` diffed against the same listing captured before the first dispatch; any new untracked path outside `{ctx-dir}` is reported by name, logged as `STAGED {time} — Review fan-out left {n} untracked file(s): {paths}. Not deleted. Reversibility: n/a.`, and excluded from the findings a reviewer sees (a finding whose only evidence is one of those paths is downgraded to `unconfirmed` with that reason). Deletion is not automatic here: the sweep names files, the controller decides — the `sweep-shadow` analogy the record draws is a move, not a delete, and a reviewer's leftover could be a sibling implementer's in-flight file.
- [ ] `step3-routing.md`'s existing post-dispatch diff audit gains one sentence pointing at the fan-out sweep as its sibling, so the two untracked checks are visibly one rule applied twice.
- [ ] Tests: `tests/multi-agent-coordination.test.js` (which pins `step3-lens-dispatch.md`) keeps its byte-identical-block assertion unchanged and gains pins for the `SCRATCH:` line in each of the three templates and the fan-out sweep's `STAGED` line shape; `tests/subagent-contract-clauses.test.js` pins the contract's Scratch rule heading.

## Acceptance Criteria
1. Every review dispatch template that grants write access names a scratch path under `{ctx-dir}` and cites the contract rule; the Calibration/Output block stays byte-identical (its existing pin proves it).
2. After the fan-out, a new untracked file outside `{ctx-dir}` is named in the review output and `decisions.md`, and cannot become the sole evidence of a `confirmed` finding.
3. No agent-created file is deleted by the skill; the sweep reports, the controller decides.
4. `npm test` is green, including the unchanged byte-identical-template pin.

## Technical Approach
Use the scratch directory that already exists rather than inventing a second one: `{ctx-dir}` is per-review, per-run unique, avoids the `tmp/` path segment the permissions deny-glob matches (refs #1213), and is already the home of the skill's own scratch files, so an agent-scratch subdirectory under it needs no new minting or cleanup path (`/wrap-up` archives the run dir with it). Put the rule in the contract, not in each template: the record's own repro spans three templates, and the next fan-out site (`/design-wrapper`'s craft critics, `/docs-health`'s per-target dispatch) would otherwise re-derive it. Report-don't-delete for the sweep because a reviewer cannot distinguish its own agents' leftovers from a concurrent implementer's untracked work in the same worktree.

## Gotchas
- The per-lens Calibration + Output block must stay byte-identical across all tiers (the cross-lens reproduction logic depends on it); the `SCRATCH:` line goes in the outer prompt beside the scope and `Path:Line` instructions, exactly where `step3-lens-dispatch.md` already places per-dispatch text.
- `--untracked-files=all` matters: the default `git status --porcelain` collapses a new directory to one line and would hide a probe script inside a freshly created folder.
- `{ctx-dir}` under a pipeline run is committed with the run dir's archive by `/wrap-up`; keep agent scratch small or add `agent-scratch/` to the run dir's ignore rules — `_shared/auto-mode-contract.md`'s "Pipeline run directory" section owns the layout and gitignore treatment; check it before choosing.
- Agents under `EnterWorktree`-based isolation cannot chain commands (contract's Shell constraint); the cleanup instruction must be one plain `rm` per file, not a `find … -delete`.

## Original request
**Summary:** Lens, refutation and gap-sweep agents dispatched during `/review` write probe scripts wherever is convenient inside the worktree, including inside the module under review, with no mandated scratch location and no controller sweep to catch what's left behind.

**Kind:** Gap

**Affected component:** `/review` lens, refutation and gap-sweep dispatch templates; `curation-engine.md` post-fan-out sweep

**Use case:** A multi-agent review run (lens agents 3b-3f, refutation agents, the gap-sweep agent) needs to run probe scripts to verify findings, without leaving stray untracked files that pollute the worktree for later steps or other agents.

**Repro steps:**
1. Run a review with several dispatched lens/refutation/gap-sweep agents (observed on a 12-agent `xhigh` review).
2. Let one or more agents write ad hoc probe scripts (e.g. `zz-*.mts`, `__bench_*.mjs`) directly in the worktree root or inside the module under review.
3. Let the fan-out complete without an explicit cleanup step.

**Expected vs. actual:**
Expected: probe scripts either never touch the tracked worktree, or are swept up automatically before the fan-out's results are trusted.
Actual: in one run this produced a false architecture finding ("throwaway debug script committed in the module directory" — it was actually untracked, left by a sibling agent), tsc errors for a later implementer caused by a reviewer's stray file, and four manual `rm` sweeps by the controller. Nothing was actually committed only because every commit used explicit paths rather than `git add -A`.

**Suggestion:** (1) the per-lens / refutation / gap-sweep dispatch templates name a scratch location outside the repo (`os.tmpdir()`-based, or the run dir's own scratch subdirectory) and require cleanup before the status word; (2) the controller's post-fan-out sweep runs `git status --porcelain` and reports or deletes untracked files that appeared during the fan-out, the same way `sweep-shadow` handles stray staged files.
