# 1470: worktree-setup.md's stale-same-name-branch check misses a remote-only collision

## Current State

`worktree-setup.md`'s Step 1.5 stale-same-name-branch check (#767) and `_shared/pr-early-run-lifecycle.md`'s Step 1 PR-list check both key off the branch/worktree name derived deterministically from the record/spec-slug, but the local-collision check (`git branch --list "{name}"`) only inspects local git refs. It never probes whether origin already carries a same-named branch left behind by a prior attempt that ran on a different machine or sandbox.

Hit live on record #1317's dispatch run (run dir `2026-08-26T043405-record-1317`, worktree `dispatch-record-1317`): a fresh local branch `worktree-dispatch-record-1317` was created cleanly — no local collision detected, since nothing by that name existed in this checkout's local refs. But origin already carried a same-named branch from an abandoned prior attempt (run `2026-08-25T063911-record-1317`, on a cloud sandbox, PR #1440 still open in draft, single materialize commit only — predating a materialize-path refactor: the old commit wrote `work/{n}-spec.md` at the repo root instead of under `.claude-tweaks/pipelines/{run}/work/`).

Build's phase-exit push (`_shared/git-discipline.md`) then failed non-fast-forward against this stale remote history. The documented degrade path applied correctly (log the failure, proceed local-only, no PR) — but the run now has no PR at all under an `integration-model: pr-first` project, and every later phase's own phase-exit push hits the identical rejection until a human resolves the branch-name collision (force-push, delete the stale remote branch, or rename this run's branch) — none of which an agent is authorized to do unilaterally.

## Deliverables

Extend the collision check — `worktree-setup.md`'s Step 1.5, or `pr-early-run-lifecycle.md`'s Step 1 PR-list check, whichever is the smaller change — to also probe the remote (`git ls-remote origin {name}`, or the existing `gh pr list --head {name}` call already run by pr-early-run-lifecycle.md Step 1, which would have surfaced PR #1440 if checked before worktree creation instead of only after the push failed). Route a remote-only collision through the same human-visible handling the local case already gets: surface the existing branch/PR and offer reuse-vs-recreate, rather than silently creating a divergent local branch that only discovers the collision via a failed push several steps later.

## Acceptance Criteria

A fresh worktree/branch creation whose deterministic name collides with a remote-only stale branch (no local ref, no attached local worktree) is detected and surfaced before the first phase-exit push attempt, not discovered only via a failed `git push`.

`npm test` passes.
