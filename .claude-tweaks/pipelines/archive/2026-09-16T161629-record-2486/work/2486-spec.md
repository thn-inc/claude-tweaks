# 2486: verify.js --changed-files --integration-branch silently returns a degenerate empty result inside a worktree

Origin: reflect full mode from #2324 (wrap-up)

Defer-reason: pre-existing-outside-diff

## Current State

During record #2324's `/test` phase, `node bin/verify.js --changed-files --integration-branch main` was run from a worktree checkout to check for frontend/UI files in the diff. It returned `{base: <current worktree HEAD>, files: []}` — a base identical to HEAD, with an empty changed-file list — silently (exit 0), even though the worktree branch was well ahead of `main`. The result looked plausible enough (valid JSON, no error) that it could easily be trusted at face value; it was caught only by an independent cross-check via `git diff --name-only` against the known-good merge-base. `/claude-tweaks:review`'s own Step 2 documents the underlying hazard generally ("never trust a bare local branch name for `{base}` — a long-lived worktree's local tracking branch routinely drifts behind its remote"), but this specific CLI's `--changed-files --integration-branch` handling doesn't appear to apply that `origin/{base}` resolution rule, and returns no signal when its resolved base ends up suspiciously identical to HEAD.

## Deliverables

Read `bin/verify.js`'s `--changed-files --integration-branch <ref>` implementation and confirm whether it resolves `<ref>` via `origin/<ref>` (per review's own documented hazard) or a bare local branch name when invoked from inside a worktree.

If it resolves a bare local branch: fix it to resolve via `origin/<ref>` first, matching the rule `/claude-tweaks:review`'s Step 2 already documents for hand-written git commands.

Regardless of the root cause found: add a guard that surfaces a warning (or a distinct result field) when the resolved `base` equals `HEAD` in a context where the caller's own worktree branch is known to be ahead of `main` — so a caller doesn't have to independently cross-check via `git diff` to catch a silently degenerate result.

## Acceptance Criteria

A regression test reproducing this repo's own #2324-review scenario (a worktree branch ahead of `origin/main`, `--changed-files --integration-branch main` invoked from inside the worktree) resolves a non-empty `files` list matching the branch's real diff, not an empty list.

`node --test tests/bin-lib/verify*.test.js` (or wherever the existing suite for this CLI lives) passes with the new regression test included.
