# 2660: specShapedBody() composer omits the required Release Note section

Surface: infra
Defer-reason: pre-existing-outside-diff

## Current State

`bin/lib/issues/record.js`'s `specShapedBody()` composer (lines 667-711) emits only three
sections — `## Current State`, `## Deliverables`, and `## Acceptance Criteria` (or
`## Open Question`) — with no `## Release Note`. This is the shared body composer for every
"born-ready" producer named in `_shared/work-record.md`'s Born-ready rule: all four
health-sweep skills (`bin/lib/{code-health,docs-health,harness-health,journey-health}/issue-payload.js`
and `harness-health/filing.md`/`code-health/filing.md`'s own callers) plus `/wrap-up`,
`/reflect`, and `/review`'s `side-effect:*` trust-class producers.

`_shared/work-record.md` line 276 states the canonical spec-shaped-body contract requires four
sections including `## Release Note`, and `bin/lib/compose-record/compose.js`'s own
`REQUIRED_SECTIONS` (line 11) already lists all four — but `specShapedBody` was never updated
to match when the four-section contract shipped (#2580/#2581). Every record `specShapedBody`
files is therefore missing a required section from day one.

Confirmed live on issue #2587 (filed by `/claude-tweaks:docs-health` via
`bin/lib/docs-health/issue-payload.js`'s `specShapedBody` call): its body had no
`## Release Note` section. `bin/compose-subject.js` hard-refused to compose this record's merge
commit subject/body (`compose-subject.js: record(s) #2587 carry no non-empty "## Release Note"
section`), blocking the pr-first Auto-merge short-circuit until the section was manually
appended to the live issue body as a one-off unblock. `materialize-format.js`'s own
`REQUIRED_SECTIONS` gate (three sections, tracked separately in #2603) does not catch this
either, so a `specShapedBody`-composed record currently passes both filing and `/flow`'s
materialize-time hard gate silently, and is only caught at merge time by
`compose-subject.js` — the latest and most expensive point to discover it.

## Deliverables

- [ ] Add an optional `releaseNote` parameter to `specShapedBody()` (`bin/lib/issues/record.js`)
      that renders a `## Release Note` section (following the existing Acceptance
      Criteria/Open Question block), mirroring `compose-record/compose.js`'s own Release Note
      handling
- [ ] Update every `specShapedBody` call site to pass a `releaseNote` — the four health-sweep
      `issue-payload.js` files, and any `/wrap-up`/`/reflect`/`/review` side-effect producer
      that calls it directly — each with a plain-language, verb-first sentence appropriate to
      that producer's finding category (per `spec-template.md`'s Release Note guidance:
      "no user-visible change" phrased plainly is an acceptable value, never omitted)
- [ ] Decide, and document in `_shared/work-record.md`'s Born-ready rule, whether
      `releaseNote` becomes a required (not optional) parameter on `specShapedBody` — an
      omitted Release Note should fail loud at filing time (matching `currentState`/
      `deliverables`/`filedBy`'s existing required-parameter behavior), not silently produce
      an invalid body that only fails much later at merge
- [ ] Check `tests/bin-lib/issues/record.test.js` (or wherever `specShapedBody` is unit-tested)
      for fixtures asserting the current three-section shape and update them
- [ ] Cross-check against #2603 (`materialize-format.js`'s `REQUIRED_SECTIONS` gap) — that
      record's own fix (adding `## Release Note` to the materialize-time gate) does not by
      itself repair the health-sweep skills' bodies; this record's fix is the upstream
      producer-side half, #2603 is the downstream gate-side half, and both are needed to close
      the full gap end-to-end

## Acceptance Criteria

1. `specShapedBody()` accepts a `releaseNote` parameter and renders a `## Release Note`
   section when provided
2. Every current `specShapedBody` call site (health-sweep skills' `issue-payload.js` files,
   `/wrap-up`/`/reflect`/`/review` side-effect producers) passes a non-empty `releaseNote`
3. A record freshly filed by any of the above producers, when passed to
   `bin/compose-subject.js --tag {tag}`, composes successfully — no `"carry no non-empty
   ## Release Note section"` refusal
4. Unit tests cover both the new parameter's presence and (if made required per Deliverable 3)
   its absence failing loud

## Release Note

Fixed a gap where health-sweep and wrap-up/reflect/review auto-filed records were missing a
required section, silently blocking their own auto-merge until caught manually at merge time.

## Technical Approach

Mirror `compose-record/compose.js`'s existing Release Note handling — that composer already
requires and renders the section (`REQUIRED_SECTIONS`, line 11); `specShapedBody` is the sibling
composer for the born-ready path and should carry the identical contract, per
`_shared/work-record.md`'s already-stated four-section rule (line 276).

### Key Files

- `plugin/bin/lib/issues/record.js` — `specShapedBody()`, lines 667-711
- `plugin/bin/lib/code-health/issue-payload.js` — health-sweep call site
- `plugin/bin/lib/docs-health/issue-payload.js` — health-sweep call site
- `plugin/bin/lib/harness-health/issue-payload.js` (or equivalent) — health-sweep call site
- `plugin/bin/lib/journey-health/issue-payload.js` (or equivalent) — health-sweep call site
- `plugin/skills/_shared/work-record.md` — Born-ready rule prose (line ~294-297 currently
  describes only three sections)

## Gotchas

- Grep every `specShapedBody(` call site fresh at build time — this record's own body was
  composed by reading the function's live source, not an exhaustive call-site grep; the four
  health-sweep files are confirmed, the `/wrap-up`/`/reflect`/`/review` side-effect call sites
  (`_shared/work-record.md` line 310-312) need their own grep to enumerate exactly
- Related-but-distinct from #2603 (`materialize-format.js`'s gate-side gap) — do not conflate
  or close one as a duplicate of the other; both fixes are needed

(`/claude-tweaks:flow #2587 review,polish,wrap-up`)._
