# 2268: Migrate status-line instruction: test, docs-health, tidy, research family

Surface: backend

## Overview

Part of the 5-unit status-line migration decomposition (parent #2264, keystone #2265). This unit
covers the test, docs-health, tidy, and research skill families — 5 files, 5 instances of the old
first-line-position instruction, each a pure mechanical text replacement.

**Complexity:** Low
**Estimated tasks:** 3

## Non-Goals

- Editing the canonical contract file itself, or `subagent-stop.js`'s detection logic — that is
  #2265, which this unit is `Blocked by`.
- Editing any file outside the 5 listed below — those belong to WU2, WU3, or WU5 in this same
  decomposition.
- Changing the four status words themselves or the Template A/B/C content that follows the status
  line.

## Acceptance Criteria

1. All 5 instances across the 5 files above read the new trailing-`STATUS:`-line instruction; none
   still asserts "first line" as the required position. The underlying assertion — the reply's
   last non-empty line reads exactly `STATUS: {WORD}` — is identical in substance across all 5;
   only surface grammar differs per file to fit each file's existing sentence structure (e.g.
   `methodology.md`'s "one of ... as the last non-empty line" vs. `qa-prompts.md`'s "Status line
   (required): the last non-empty line ... must read exactly").
2. `plugin/skills/tidy/scan-execution.md`'s instruction reflects the reversed order for Template A
   agents (findings table first, trailing status line last) rather than merely relabeling the old
   "status line, then table" order.
3. `grep -rn "first line\|FIRST line\|line 1 of your reply" plugin/skills/test/qa-prompts.md
   plugin/skills/docs-health/SKILL.md plugin/skills/tidy/scan-execution.md
   plugin/skills/research/reference/methodology.md plugin/skills/research/source-registry.md`
   returns no match against any of the edited status-line instructions.
4. A positive check confirms the new text actually landed, not merely that the old text is gone:
   `grep -l "STATUS:" plugin/skills/test/qa-prompts.md plugin/skills/docs-health/SKILL.md
   plugin/skills/tidy/scan-execution.md plugin/skills/research/reference/methodology.md
   plugin/skills/research/source-registry.md` lists all 5 files.
5. Before editing each file, `grep -n` for the exact old phrase quoted in Current State above
   confirms the instruction's current line number rather than trusting the approximate `~N` given
   there — line numbers drift as neighboring content changes between when this record was
   authored and when it's built.
6. `npm test` passes with no regressions.

## Technical Approach

`plugin/skills/_shared/subagent-output-contract.md`. One deliverable in this batch
(`tidy/scan-execution.md`) additionally needs its stated ordering reversed (table before status
line, not status line before table) since it is a Template A dispatch site and the design doc's
Decision section specifies that order reversal explicitly for Template A agents.

- `tidy/scan-execution.md`'s edit is not a pure text swap like the other 4 files in this batch — it

  otherwise places it).

  alone") is a define-in-prose format, not one of Template A/B/C — its own file documents this
  under the Subagent Contract's "Not every consumer uses A/B/C" allowance; the replacement keeps
  that same allowance, just relocates the position.
- This unit is `Blocked by` #2265 — the exact replacement wording must match the canonical text
  #2265 lands, not a guess at what it will say. The strings quoted in Deliverables above are this
  record's best-effort snapshot at authoring time; re-read #2265's actual landed text in
  `subagent-output-contract.md` before applying any edit here and defer to it if the two differ.
- This unit never touches `subagent-stop.js`'s detection logic (owned by #2265) — it relies
  entirely on #2265 having shipped position-agnostic parsing before this unit's edits go live,
  which the `Blocked by` dependency (native GitHub issue-dependency edge, not a body-text line)
  already enforces at dispatch/queue time.
