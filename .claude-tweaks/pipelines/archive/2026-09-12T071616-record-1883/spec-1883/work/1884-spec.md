# 1884: backlog attention: no per-group batch launcher lines, unlike tidy's Yours grouping

Surface: infra

## Current State
`backlog/attention-mode.md` Step 4 renders one launcher per row in the Recommended-action column and closes with a single `Pick up next: #{n} …` line. Nothing groups the rows by the command the human will run, so a 19-row table (the reporter's case: 10 `needs:decision`, 7 `shaped:headless (no grant)`, 2 `needs:definition`) offers 19 per-row commands plus one pick, when three commands would cover it: `/claude-tweaks:backlog refine #a,#b,…` for the decision rows (`backlog/SKILL.md`'s `argument-hint` accepts `[#N[,#M...]]` and `refine-record.md`'s per-record resolver takes the list), bare `/claude-tweaks:backlog refine` once for the headless-shaped rows (the Grant lane is ref-less, per the render text's own "never `refine #{n}`" rule for that type), and one `/claude-tweaks:specify #{n}` line per `needs:definition` row (`specify/SKILL.md`'s batch branch fails the whole invocation on a `needs:definition` element by design). `tidy/step-6-auto.md`'s "Yours grouping (by the command the human runs)" already states the rule that produces exactly this — group by the leading command key, read the target skill's `argument-hint` at render time, close a batchable group with one batch line, a single-ref group with a paste block, a ref-less group with one line — so attention mode is the inconsistent surface.

`sweep/SKILL.md`'s `## Next Actions` inherits the gap: it surfaces `tidy --approve`, `dispatch`, and `backlog attention`, with the needs-you launcher slot carrying only the single top pick, so a sweep that ends with a full attention table hands the human one record's command.

## Technical Approach
Reuse, not a second grouping rule: the Yours grouping section is the one place the command-key derivation, group order, and batchable/single-ref/ref-less split live, and it already reads `argument-hint` at render time so a skill gaining a batch form shortens both renders with no edit. Attention's block cites that section and adds only the two attention-specific facts (the Grant lane is ref-less; `needs:definition` is never batched). Sweep copies the rendered lines rather than re-grouping, keeping its Step 4 free of attention's row logic as its own text requires ("any future change to attention's row types or ranking must need no edit in this file").

## Original request
**Summary:** `backlog attention` renders one launcher per row and a single "Pick up next" line; it never emits a batch command per launcher group, even though `refine #N[,#M...]` and bare `refine` cover most rows in one call, and tidy's own Yours section already implements exactly that grouping rule.

**Kind:** Gap

**Affected component:** `backlog/attention-mode.md` (Step 4 Render); `/claude-tweaks:sweep`'s Next Actions precedence (surfaces only the top pick)

**Use case:** After a `/claude-tweaks:sweep` run in a private project, the attention table held 19 rows: 10 `needs:decision`, 7 `shaped:headless (no grant)`, 2 `needs:definition`. The user asked for "a simple command to go with all the recommended actions in the table". The answer is three commands, but nothing renders them: `/claude-tweaks:backlog refine #a,#b,...` (the per-record resolver accepts a comma list — `backlog/refine-record.md`) covers all 10 decision rows; bare `/claude-tweaks:backlog refine` (one Grant lane with one batch-confirm) covers all 7 headless-shaped rows; the 2 `needs:definition` rows must stay one-per-command because specify's batch form rejects `needs:definition` elements by design. `tidy/step-6-auto.md`'s Yours grouping rule already does this — group rows by the launcher's command key, read the target skill's `argument-hint` to decide batch line vs paste block — so attention mode is the inconsistent surface. Proposed: reuse that grouping rule in attention's Step 4 render (a batch line under each launcher group; `needs:definition` and `solution:unjustified` explicitly render as paste blocks, one line per record), and let sweep's Next Actions carry the group batch lines rather than only the single "Pick up next" launcher.
