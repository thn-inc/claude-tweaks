# 3675: Review lens dispatch tells agents to use a shell shape the worktree-isolation guard refuses

Origin: reflect full from #3480

Defer-reason: tangential

## Current State

`plugin/skills/review/step3-lens-dispatch.md` (Scratch path, per dispatch) instructs each lens agent to create its probe file "via Bash (`mkdir -p` + a redirect/heredoc, then `rm`)". In a worktree-isolated session the harness refuses compound commands, variable assignments chained with `;`/`&&`, and heredocs by shape (`_shared/scratch-worktree.md` section 7). On #3480 the 8 medium-tier lens agents produced about 14 `wd-guard-refusal` friction events in under three minutes (`mkdir -p …; D=…`, `W=…; for f in …`, `cat > … <<EOF`), each a wasted turn, while the same run's operator hit the guard another 13 times. The dispatch already inlines the Working Directory Discipline; it does not carry the one-plain-command-per-Bash-call rule.

## Deliverables

- [ ] Reword the Scratch path instruction in `step3-lens-dispatch.md` so a lens agent creates and removes its probe with one plain command per Bash call (no variable assignments, no `&&`/`;` chains, no heredoc) or with `Write` where the path is inside its worktree, and cite `_shared/scratch-worktree.md` section 7.

- [ ] Add the one-plain-command rule to the dispatch contract bundle (`_shared/subagent-dispatch-core.md`) beside the Working Directory Discipline so every dispatch site inherits it.

- [ ] Update the conformance test that pins the Scratch path wording, if any.

## Acceptance Criteria

- [ ] `step3-lens-dispatch.md` no longer recommends a heredoc or a chained command for the agent scratch file.

- [ ] The dispatch contract names the one-plain-command rule once and the lens dispatch cites it.

- [ ] Any prose conformance test pinning the old wording is updated and goes red against the old text.
