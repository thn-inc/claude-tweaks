# 2227: reconcile: archiveOrphanedMint fs-renames a git-tracked work/ spec with no git mv or commit, leaving main's working tree dirty

**Related:** #1732 (archive-merged.js lifecycle-mechanism consolidation — this is a narrower, standalone fix that could be absorbed there), #1604 (the branch whose comment documents the missing guard), #593 (the git-aware `archiveRunDir` guard this reuses).

## Current State

`archiveOrphanedMint` (`plugin/bin/lib/reconcile/archive-merged.js`) archives any run dir that has no `config.yml` and is older than `ORPHAN_MINT_TTL_MS` (24h) with a bare per-entry `fs.renameSync` plus `fs.rmdirSync` — no git awareness at all. Its own comment at the `isAdHocStandaloneSuperseded` branch already admits this ("archiveOrphanedMint is a bare fs.renameSync with no tracked-entry guard") and routes ad-hoc-standalone dirs to `archiveRunDir` for exactly that reason. An ordinary record run dir that ends up state-less with a git-tracked spec is not routed around it.

That shape is real and recurring: `.claude-tweaks/pipelines/2026-09-05T155335-record-1594/` (observed 2026-09-10) holds only the git-tracked `work/1594-spec.md`. Record #1594 shipped via PR #1908 (merged); its `run-state.json`/`decisions.md`/`config.yml` lived only in the worktree copy, so the main checkout never got them. Both `close-run` and `archive-run` refuse the dir by design — `archive-run`'s message says "a state-less dir is reconcile's archiveOrphanedMint's job, not this verb's" — so this path is the *only* owner of the dir.

When the TTL elapses, `archiveMerged` reaches the `isOrphanedMint` branch (no `config.yml`, not ad-hoc-standalone, mtime > 24h) and fs-renames the tracked spec into `archive/{run}/work/`. The main checkout is left with an unstaged ` D` on the spec and an untracked `?? archive/{run}/` that nothing ever commits. `iterRunDirsWithState`'s #593 archive-twin check cannot compensate: it reads a terminal `run-state.json` on the twin, and this dir never had one on either side. `archiveRunDir` (the git-aware path: batched `git mv` + one `[reconcile] archive run` commit, `tracked-entry` refusal for anything else) does not require `run-state.json` and is what this dir shape actually needs.

## Deliverables

- In `archiveMerged`'s orphaned-mint branch (or inside `archiveOrphanedMint` itself), detect git-tracked content under the dir before moving anything — `git -C root ls-files -- {dir}` non-empty is the signal `archiveRunDir` already uses for its own `tracked-entry` check — and route such a dir through `archiveRunDir` (git mv + commit) instead of the fs-only move. The fs-only path stays for genuinely untracked orphaned mints.
- The routed result flows through the same `trackArchiveResult` / `skipped` reporting as the existing paths, so a refused git-aware archival (any of `archiveRunDir`'s own `{ ok: false, reason }` outcomes) is a visible skip reason — never a silent fs move of tracked content and never a silent no-op.
- Update the `isAdHocStandaloneSuperseded` branch comment that today documents the missing guard, so it no longer describes a gap that has been closed.
- Tests in `tests/bin-lib/reconcile/archive-merged.test.js`: (a) a state-less run dir past the TTL whose `work/{n}-spec.md` is git-tracked is archived via a commit, leaving `git status --porcelain -- .claude-tweaks/pipelines` empty; (b) a state-less run dir with no tracked entries still takes the fs path with no commit; (c) an `archiveRunDir` refusal on the routed dir appears in `skipped` with its reason.

## Acceptance Criteria

- Given a run dir with no `config.yml`, mtime older than `ORPHAN_MINT_TTL_MS`, and a git-tracked `work/{n}-spec.md`, one `archiveMerged` pass moves it to `archive/{run}/` **and** `git status --porcelain -- .claude-tweaks/pipelines` is empty afterward — the move is a committed rename, not a working-tree edit.
- Given the same dir with no tracked entries, `archiveMerged` behaves exactly as today: fs move, no commit, `archived` contains the dir.
- When `archiveRunDir` refuses the routed dir, `skipped` carries `{ runDir, reason }` with `archiveRunDir`'s own reason string, and the dir is left in place unmodified.
- Test (a) fails against the unpatched `archiveOrphanedMint` (verified by reverting the fix), so it discriminates.
- `npm test` passes.
