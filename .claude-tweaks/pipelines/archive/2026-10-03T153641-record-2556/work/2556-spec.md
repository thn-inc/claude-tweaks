## Current State

#1826 (this record's parent) fixed the two specific silent-degrade gaps its own diagnosis confirmed: the Manifesto's `config.yml` write logged no absolute path (#1810's occurrence), and no conditional skip on that write path logged a `SKIP` entry, and `steps-and-gates.md`'s case 3 recomputed levers fresh from the precedence chain instead of preferring `decisions.md`'s own snapshot header, and its prose assumed interruption rather than also covering a completed-but-config-missing first call.

What #1826 explicitly called for but this pass did not build: a genuine end-to-end regression test simulating a `/flow` two-call dispatch handoff (`build,test` then `review,polish,wrap-up` sharing one `PIPELINE_RUN_DIR`) against a real fixture repo — bare git remote for the push/PR half, `gh` mocked at the injectable-runner seam — asserting the anchored run directory's actual `config.yml`/`decisions.md`/`run-state.json` contents after call 1, and a companion fixture where the claim step is skipped and a build commit must never happen.

Investigation during #1826 found `tests/dispatch-flow-rundir-handoff.test.js` (the file #1826's own Gotchas assumed already had this fixture machinery) is entirely prose-conformance-based — it regex-matches skill `.md` files, with no bare-repo/mocked-`gh` runtime simulation anywhere in the suite. The underlying units this test would exercise are each already well-covered in isolation (`plugin/bin/lib/flow/preflight.js`'s `computeAdoption` case 3 logic — `tests/bin-lib/flow/preflight.test.js`; `bin/claim-targets.js`'s contest/all-or-abort handling — `tests/bin-lib/claim-targets/claim-targets.test.js`, including the exact "second target live → first released, exit 3" shape AC5 wants), but nothing ties them together end-to-end the way `/flow`'s own Step 1→2.8→3→4 sequence actually runs.

## Deliverables

- Build a fixture-repo harness (bare `origin` remote, a temp worktree-like checkout, `gh` faked at the same injectable-runner seam `tests/bin-lib/claim-targets/claim-targets.test.js` already uses) that runs the real sequence: `bin/materialize.js` → `bin/claim-targets.js` → `bin/set-config.js` (the Manifesto's batch write) → `bin/hooks.js record-worktree` → the PR-early push+draft-PR procedure (mocked `gh pr create`/`gh pr list`).
- Assert the anchored run directory's `config.yml`, `decisions.md`, and `run-state.json` (with `worktree` and `pr` fields) all exist and carry correct content after this simulated "call 1."
- A companion fixture where the claim step (`bin/claim-targets.js`) exits non-zero (contested) — assert the harness never reaches the materialize/commit step for that case.
- A companion fixture reproducing the shadow-write hypothesis: a `config.yml` written under `<worktree>/.claude-tweaks/pipelines/{run}/` instead of the anchored `$RUN_ROOT` path — assert this is detected (or made structurally impossible by the harness's own path construction).

## Acceptance Criteria
