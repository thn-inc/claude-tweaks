# 1906: blast-radius.js should exclude pipeline-artifact paths from implLines/implFiles counting

Origin: reflect light from #1535
Defer-reason: tangential

## Current State

`bin/blast-radius.js`'s `summary.implLines`/`summary.implFiles` count every non-test file in the diff as implementation, with no carve-out for this pipeline's own generated process artifacts: a materialized spec (`{run-dir}/work/{n}-spec.md`) and a `superpowers:writing-plans` implementation plan doc (`docs/superpowers/plans/*.md`). On #1535 — a genuinely 1-line production fix in `plugin/bin/build-review-context.js` plus a 21-line test — the tool reported `implLines: 152`, `implFiles: 3` against a configured guideline of `auto-merge-max-lines: 40`/`auto-merge-max-files: 2`, purely because the 39-line spec and 111-line plan doc were counted alongside the actual code change.

`merge-check.md`'s Step 2 explicitly asks the judge to weigh `implLines`/`implFiles` against the guideline "once the diff is judged to carry behavior change" — but the tool hands over a number that conflates pipeline bookkeeping with real implementation risk, forcing every merge-check invocation on a record with a materialized header to manually discount the spec/plan doc's line count before the comparison means anything. That manual discount is easy to get wrong or skip under time pressure, and skipping it would make a genuinely tiny, low-risk fix look artificially large enough to lean `needs-human`.

## Deliverables

- In `plugin/bin/lib/issues/blast-radius.js` (or wherever `summary` is computed), exclude paths matching `${RUN_DIR}/work/*-spec.md` (the materialized-header convention, `flow/materialize.md`) and `docs/superpowers/plans/*.md` (the `superpowers:writing-plans` convention) from `implLines`/`implFiles`/the file classification that feeds them — the same way test files are already split out into `testLines`/`testFiles`.
- Confirm `merge-check.md`'s Step 2 prose still reads correctly once the counts it consumes no longer include pipeline artifacts (no prose change expected, since the judge already treats the numbers as inputs, not ground truth).

## Acceptance Criteria

1. `node bin/blast-radius.js --integration-branch <ref>` run against a diff containing only a materialized spec + plan doc (no real code) reports `implLines: 0`, `implFiles: 0`.
2. Existing `blast-radius`/`merge-check` tests continue to pass with the narrower classification.

Surfaced during #1535's own wrap-up (Reflect, light mode, Fresh-start lens) — evidence is that run's own `blast-radius.js` output: `{"summary":{"implLines":152,"implFiles":3,"testLines":21,"testFiles":1}}` for a 1-line production change.
