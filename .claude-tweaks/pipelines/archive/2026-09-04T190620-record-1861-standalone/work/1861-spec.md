# 1861: run-integrity.js's checkRunIntegrity misses bareIntegrationName normalization (#1688 follow-up)

## Current State

\`resolveIntegrationBranch\`'s policy-configured path can return either a bare branch name or an \`origin/{name}\`-prefixed one (\`preferRemoteTrackingRef\`, added by #1688). #1688 normalized four call sites that assume a bare name back through the new \`bareIntegrationName\` helper: \`post-tool-use.js\`, \`teardown-run.js\`, \`reconcile/index.js\`, and one more — but missed \`plugin/bin/lib/hooks/run-integrity.js:231\`'s \`checkRunIntegrity\`, which still calls \`resolveIntegrationBranch(root, cache)\` raw and compares the result directly against \`evidence.branch\` (always bare, from \`deriveBranch\`/\`fallbackBranch\`) in \`mergedEvidence\`'s self-ancestor guard (\`if (branch === integration) return null;\`, line 164).

Found by the whole-branch review gating the next release (CLAUDE.md's Releasing section / IL-97 precedent) — confirmed via independent verification, not yet fixed.

## Deliverables

- Wrap \`run-integrity.js\`'s \`resolveIntegrationBranch(root, cache)\` call with \`bareIntegrationName\`, importing it from \`./worktree-reap\` (same pattern as \`reconcile/index.js\`: \`bareIntegrationName(resolveIntegrationBranch(root, opts.cache))\`).
- Extend \`tests/run-integrity.test.js\` to cover a policy-configured \`integration-branch\` where \`refs/remotes/origin/{name}\` actually exists (today's suite sets \`integration-branch: trunk\` but never creates that ref, so this path is untested).

## Acceptance Criteria

- A worktree standing on the integration branch itself, under a policy-configured \`integration-branch\` that resolves to \`origin/{name}\`, correctly trips \`mergedEvidence\`'s self-ancestor guard (returns \`null\`, not a spurious 'ancestor').
- \`node --test tests/run-integrity.test.js\` passes with the new case.

## Failure scenario this fixes

A project sets \`integration-branch: main\` in policy.yml and already has \`refs/remotes/origin/main\` fetched. \`resolveIntegrationBranch\` returns \`origin/main\`. The self-ancestor guard compares this against the worktree's bare checked-out branch name (\`main\`), which never matches, so the guard silently fails to fire; \`git merge-base --is-ancestor main origin/main\` can spuriously report 'ancestor', producing a false 'shipped-unclosed' verdict consumed by \`session-start.js\` and \`archive-merged.js\`'s archival sweep.
