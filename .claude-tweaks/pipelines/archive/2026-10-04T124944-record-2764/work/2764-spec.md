# 2764: No sanctioned writer CLI covers spec-*/verify-expectations.json from a worktree-isolated wrap-up session


Origin: ledger resolve gate

Defer-reason: blocked-dependency

## Current State

`wrap-up/review-console.md`'s Multi-spec defer protocol step 4 instructs writing `{run-dir}/verify-expectations.json` (`{"version":1,"memory":[],"upstream":[],"deferred":[...]}`) into the pipeline run directory. The three sanctioned run-dir writers documented in `gh-api-module-pattern/cli-wrapper-contract.md` — `log-decision.js` (`decisions.md`), `stage-item.js` (`staged/`), `set-config.js` (`config.yml`) — cover exactly three filenames; none covers this one. A direct `Write` to the main-checkout run-dir path from a worktree-isolated per-spec session is refused by the PreToolUse worktree-isolation gate.

Observed twice in the same multi-spec run (2026-09-21T213441-spec-2697-2757-2758-2759): `spec-2758`'s wrap-up hit this gap and logged it as ledger #19 of `docs/plans/2026-09-21-spec-2697-2757-2758-2759-ledger.md`, flagging it for "the run's final wrap-up, which can write it once outside worktree isolation, or a backlog record proposing a fourth sanctioned writer CLI for this file class." `spec-2759`'s wrap-up (the run's actual final spec) re-confirmed the same gap still applies — it is also still a worktree-isolated session, so it cannot write the file either. The bounded consequence (per `review-console.md`): a per-spec `verify` run renders `memory-updates`/`upstream-feedback` as `unknown (expectations file missing)` instead of `skip (nothing recorded)` — accepted, does not block the consolidated Review Console, which reads `decisions.md`/`staged/` directly.

## Deliverables

A fourth sanctioned run-dir writer CLI (or an added mode on an existing one) covering `verify-expectations.json`, following the same `run(argv, deps)` seam, exit-code vocabulary, and run-dir anchoring guard as `log-decision.js`/`stage-item.js`/`set-config.js` (`gh-api-module-pattern`'s CLI wrapper contract).

## Acceptance Criteria

A worktree-isolated `/claude-tweaks:wrap-up` session can write `spec-{n}/verify-expectations.json` (or update it) via the new/extended sanctioned CLI without tripping the PreToolUse worktree-isolation gate — verified by a regression test exercising the CLI from a simulated worktree-isolated context.

`review-console.md`'s per-spec `verify` step no longer needs the `unknown (expectations file missing)` fallback once the file is actually written — the memory-updates/upstream-feedback probe reads `skip (nothing recorded)` normally.
