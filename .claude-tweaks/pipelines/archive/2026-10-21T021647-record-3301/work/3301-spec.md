# 3301: friction-events: worktree-isolation refusals of Write/Edit calls are never logged (only Bash refusals are)

Origin: reflect hindsight from #2783

Defer-reason: tangential

## Current State

#2783 added `plugin/bin/lib/hooks/post-tool-use-failure.js`, registered in `plugin/hooks/hooks.json` with matcher `Bash` only. It records Claude Code's worktree-isolation refusal of a **Bash** command as a `wd-guard-refusal` event (`HARNESS_ISOLATION_REFUSAL_RE` = "This session is isolated in the worktree … Refusing to run it").

The same harness guard also refuses **Write/Edit** calls aimed at a shared-checkout path, with different wording: "This session is isolated in the worktree <path>. Edit the worktree copy of this file instead of the shared-checkout path." That refusal fired during #2783's own review (a Write to `.claude-tweaks/pipelines/<run>/review-ctx/pre-dispatch-status.txt`). Neither the Bash matcher nor the regex captures it, so `/claude-tweaks:reflect`'s Friction Lens never sees this class of isolation friction.

Not yet measured: whether a Write/Edit isolation refusal fires `PostToolUseFailure` at all, and if it does, what the payload's `error` field holds. #2783's probe measured the Bash refusal only.

## Deliverables

1. Probe empirically (headless `claude -p`, as #2783 did for Bash) whether the harness fires `PostToolUseFailure` for a Write/Edit isolation refusal, and record the payload shape (`tool_name`, `error`).

2. If it fires, widen the `hooks.json` matcher to Write|Edit and teach `post-tool-use-failure.js` the Write/Edit refusal wording. Log `wd-guard-refusal` with `tool: <Write|Edit>`, `reason: harness-worktree-isolation` and the target `file_path` (not file content), via the same `resolveDenialRunDir`. `bash-prefilter.js` needs no change: it already passes every non-Bash payload through (its `tool_name !== 'Bash'` early return).

3. If it does not fire, document that limit in `plugin/skills/reflect/full-mode.md`'s Friction Lens section, beside the existing ad-hoc-session Known-limitation clause.

## Acceptance Criteria

- A Write or Edit refused by the worktree-isolation guard appears in `node plugin/bin/friction-events.js --run <dir>` output as a `wd-guard-refusal` event naming the tool, OR `reflect/full-mode.md` states explicitly that this refusal class is not observable.

- An ordinary Write/Edit failure (e.g. a stale-read rejection) is not logged as a guard refusal.

- `npm test` passes.

## Release Note

Friction logging now also covers worktree-isolation refusals of file edits, not just shell commands.
