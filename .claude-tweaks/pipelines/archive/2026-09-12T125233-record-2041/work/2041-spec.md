# 2041: friction-events.js's contract-violation detector over-reports on a multi-turn async-wait dispatch

Origin: `/claude-tweaks:reflect` (full mode, via `/claude-tweaks:wrap-up` on record #1963)

Defer-reason: tangential

**Related:** #2036 — same subagent-stop contract-violation misattribution cluster

## Current State

`bin/lib/hooks/subagent-stop.js`'s `contract-violation` detection fired 4 times during record
#1963's review phase, each time flagging an intermediate turn where the dispatched agent (that
run's own review/polish/wrap-up call, running as a Task-dispatched subagent) ended a turn with
plain status narration ("Still waiting on the N lens-review agents...") while waiting on
background Agent-tool notifications — the documented async-wait pattern (end the turn with a
status message and no tool call, per `_shared/subagent-output-contract.md`'s async dispatch
guidance). None of these were the dispatch's actual final reply; the OUTPUT FORMAT
status-word-first rule governs the final reply, not every intermediate turn a long-running
dispatch produces while polling background work. `reflect/full-mode.md`'s own Friction lens
documentation already names this exact failure mode ("the detector cannot tell which agent
replied... over-reports") but the mechanism itself has no way to distinguish "this is the final
deliverable reply" from "this is legitimate mid-flight narration during an async wait."

## Deliverables

- Investigate whether `subagent-stop.js`'s contract-violation check can be scoped to only the
  dispatch's terminal reply (the one actually consumed by the caller) rather than every turn a
  long-running Task agent produces, OR document more prominently that a multi-turn async-wait
  dispatch will predictably accumulate false-positive `contract-violation` events that
  Friction-lens readers must filter by hand.

## Acceptance Criteria

- A dispatched agent using the documented async-wait pattern (status-only intermediate turns, no
  tool call) across multiple background-agent waits no longer logs a `contract-violation` event
  for those intermediate turns, only for an actual malformed final reply.
