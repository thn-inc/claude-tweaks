# 1806: Several skill files sit within ~150 bytes of the 40KB content-cost ceiling on main

Origin: Found while merging PR #1803 (port-isolation) into main — a pre-existing condition on main, unrelated to that PR's own content.

Defer-reason: pre-existing-outside-diff

## Current State

A recent merge (PR #1803, port-isolation feature) discovered that several plugin skill files are already sitting within ~150 bytes of the 40 KB per-invocation content-cost ceiling enforced by `tests/bin-lib/skill-audit/context-cost.test.js` — on `origin/main` alone, before that PR ever touched them:

- `plugin/skills/tidy/SKILL.md` — 40956 B (ceiling 40960 B)
- `plugin/skills/tidy/scan-procedures.md` — 40853 B
- `plugin/skills/tidy/step-6-auto.md` — 40926 B
- `plugin/skills/journey-health/SKILL.md` — 40798 B
- `plugin/skills/specify/SKILL.md` — 40948 B

The suite already has a 90-100%-of-ceiling WARN band (`context-cost.test.js`'s "warns (without failing) on any file in the 90-100% ceiling band" test), so every one of these files has presumably been silently warning for some time — but nothing turns that warning into an action a human or CI actually has to respond to. The result: an unrelated PR landing its own small, individually-harmless additions (a 3-line stub, one table row) was enough to tip several of these files over the hard ceiling simultaneously, purely from the combination, with neither branch's own diff alone appearing to cross the line.

## Deliverables

- [ ] Either (a) a dedicated trim pass bringing `tidy/SKILL.md`, `tidy/scan-procedures.md`, `tidy/step-6-auto.md`, `journey-health/SKILL.md`, and `specify/SKILL.md` back down to a healthy margin below the 40 KB ceiling (extracting a section to a lazy-loaded sub-file per the ceiling test's own remediation hint, or trimming redundant prose), or (b) a stronger surfacing mechanism for the existing 90-100% warn band — e.g. failing CI (not just warning) once a file crosses 95%, or a scheduled harness-health sweep check — so the band stops being silently ignorable. Pick whichever fits this project's actual maintenance cadence better; both are legitimate fixes for the same underlying gap.
- [ ] If (a) is chosen for any file, verify the corresponding prose-conformance tests (pinned section/line assertions elsewhere in the suite) still pass — several of these files are conformance-tested outside `context-cost.test.js` itself.

## Acceptance Criteria

1. None of the five named files sits above 90% of `CEILING_BYTES` (`plugin/bin/lib/skill-audit/context-cost.js`) on `main`.
2. `tests/bin-lib/skill-audit/context-cost.test.js`'s "no SKILL.md exceeds the 40 KB per-invocation ceiling" and "no lazy-loaded sub-file exceeds the ceiling either" tests pass with a comfortable margin, not just barely.
3. Whatever mechanism is chosen (trim vs. stronger warning) is documented in the relevant test file or a doc so a future contributor understands why the margin exists.
