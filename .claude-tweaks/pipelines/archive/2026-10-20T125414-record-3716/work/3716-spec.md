# 3716: Verify Premise-check argv quoting on Windows for anchors containing double quotes or backslashes

Origin: ledger resolve gate

Defer-reason: blocked-external

## Current State

The Premise-check runner now spawns a PATH-resolved sh on win32 (posixShell, #3563), and windows-latest proved the four target files pass. What that run does not exercise is Node-to-MSYS argv quoting for a Premise-check command whose anchor contains a double quote or a backslash. buildPremiseCheck (plugin/bin/lib/harness-health/issue-payload.js) single-quotes operands, but a command containing those characters is passed through execFileSync to sh.exe on Windows, where MSYS argv parsing can mangle it. A mangled command that exits non-zero reads as resolved, so materialize.js reports satisfiedAtBase:true and stages a close proposal for a Windows build whose premise still holds. No test in the suite covers an anchor with a double quote or a backslash on Windows, and the POSIX simulation cannot show it. Files: plugin/bin/lib/health-core/premise-self-check.js, plugin/bin/lib/harness-health/issue-payload.js, tests/bin-lib/health-core/premise-self-check.test.js.

## Deliverables

Add real-shell tests to tests/bin-lib/health-core/premise-self-check.test.js that compose a Premise-check command (via buildPremiseCheck) for anchors containing a double quote, a backslash, and a single quote, and assert defaultRunner reads each as unresolved when the anchor is absent from the target file and as resolved when present

Dispatch windows-regression.yml on the branch and read the per-file result for the new tests from the run log, as AC2 of #3563 did

If any case fails on Windows, fix the quoting at the composition site (buildPremiseCheck) or the spawn site, and keep the tests

## Acceptance Criteria

The new tests pass on macOS/Linux and in a windows-latest run of windows-regression.yml, quoting the per-file log result rather than the run verdict (#3568)

A Premise-check command whose anchor contains a double quote or a backslash reads unresolved when the anchor is absent and resolved when it is present, on both platforms

## Release Note

Fixed premise checks on Windows misreading findings whose proposed text contains quotes or backslashes, so already-done work is detected correctly and open work is not auto-closed.
