# 1308: pre-tool-use.js teardownTargets: env-prefixed git worktree remove bypasses the teardown gate

Defer-reason: genuinely-larger
Surface: infra

## Current State

`plugin/bin/lib/hooks/pre-tool-use.js`'s `teardownTargets()` (line ~325) checks `toks[0] !== 'git'` directly on each parsed shell command segment to find a `git worktree remove` target for the pre-tool-use teardown gate. A command like `env git worktree remove <path>` (or `nice`/`nohup`/`time`-prefixed equivalents) has `toks[0] === 'env'`, not `'git'`, so the segment is silently skipped — `teardownTargets` returns no target for it, and the raw worktree removal proceeds completely ungated, bypassing the safety check the gate exists to enforce.

Found in the same pre-release whole-branch review (range e90376a4..b517ee68) that produced #1174, which named this as a related-but-separate defect and explicitly deferred it per that record's own Deliverables/Gotchas ("decide whether the teardownTargets env-prefix gap is fixed here or split out; if split, file it").

## Deliverables

- Normalize a leading command-wrapper prefix (`env`, and any other wrapper this codebase already treats specially elsewhere — check the "#590 lead-normalization work" this gap is named as the same family as) before `teardownTargets`' `toks[0] !== 'git'` check, so `env git worktree remove <path>` resolves the same target a bare `git worktree remove <path>` would.
- A regression test: `env git worktree remove <path>` (and the bare form, for a non-regression check) both produce the same teardown target from `teardownTargets()`.

## Acceptance Criteria

- `teardownTargets()` returns a target for `env git worktree remove <path>` identical to what it returns for the bare `git worktree remove <path>` form.
- Every existing `teardownTargets`/pre-tool-use teardown-gate test still passes.
- `npm test` passes.

## Technical Approach

Read `#590`'s lead-normalization work first (its module/function, and how it strips or normalizes a leading wrapper command) to reuse the same normalization rather than inventing a second copy of that logic. Apply it to the token array `forEachCommandSegment` hands to the `toks[0] !== 'git'` check inside `teardownTargets()`.

### Key Files

- `plugin/bin/lib/hooks/pre-tool-use.js` — `teardownTargets()`, the `toks[0] !== 'git'` check (~line 325)
- Whatever module #590's lead-normalization work landed in — the reusable normalization logic

## Gotchas

- Don't expand the compound-command surface this parser accepts beyond adding wrapper-prefix normalization — `teardownTargets`' own header comment states it deliberately does not extend the compound-command surface #174 tracks; stay narrow.
- Ambiguity resolves to allow (never fabricate a target) — the existing "any other flags, multiple positionals, or parse doubt skip that segment" rule stays in force; this fix only removes the leading-wrapper blind spot, it doesn't loosen anything else.
