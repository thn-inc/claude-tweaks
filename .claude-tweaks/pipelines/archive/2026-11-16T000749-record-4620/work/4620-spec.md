# 4620: Control mode: carry undecidable console items into the packet, leave no residue

Surface: infra

## Overview

**The autonomous middle, console half.** Under control mode nothing between intent and acceptance asks the human anything. The Wrap-Up Review Console stops being a stop: everything it can resolve by policy it resolves and logs (the existing `consoleAutoResolve` machinery, granted at the `unattended` autonomy ceiling); anything it genuinely cannot — a contested finding, an unconfirmed bug flagged by review, a `needs-human-decision` SDD ruling — is **carried into the acceptance packet's "Decisions left for you" section** instead of a separate console.

**Bookkeeping never accumulates.** At run end, ledger residue, reflection insights, and archived-run residue are each **resolved**, or **filed as a backlog record** (spec-shaped, with a `Defer-reason:` from `_shared/deferral-gate.md` when an agent holds the context), never left pending. "Pending for a human" is not a terminal state in control mode. **Memory writes are fully automatic**, logged so a bad one is traceable and revertable; no approval prompt.

Existing HARD-GATEs (the canonical list is `_shared/auto-mode-contract.md`'s exemption list; the design cites test failure, spec compliance, plan validation and an unresolvable merge conflict among them) still stop the run; a stop in control mode is a failure to report, not a question to answer. Anti-goal: re-creating the residue pile under a new name. Evidence the model has outlived involvement: dozens of open ledger residues, unreviewed console items and leftover worktrees accumulate because the plugin keeps asking for attention the human has stopped giving.

**Outside control mode all of this is unchanged** (designer's call: the stop-removing behaviors exist only under control mode).

**Contract decisions this record pins:**

- **Ceiling composition.** Control mode is a new input to the bookkeeping permissions: `bookkeepingPermissions(ceiling, { controlMode })` returns the `unattended` capability set when control mode is on. Precedence for the effective ceiling: CLI arg > an explicit `autonomy` value in pipeline config or `policy.yml` > the control-mode implication > the `supervised` default. So `control-mode: on` with no `autonomy` key yields `unattended` capabilities; `control-mode: on` with an explicit `autonomy: supervised` yields `supervised` (the explicit lever wins, and the status scan says so). The grant is the maintainer's own: `control-mode: on` in `policy.yml` is a committed, human-made edit (the init setup path writes it only after the user answers), exactly like setting `autonomy: unattended` today; no other actor can raise the ceiling. The control-mode-switch record composes the full implied set; this record supplies only the console-and-residue effect.
- **Sink for carried decisions.** The console resolver appends facts to `{runDir}/packet-facts/decisions.json` (a working file; the packet record's gather reads it, and the schema's single owner is `_shared/acceptance-packet.md`). This record's code constants for the fact (`kind: 'decision'`, `origin` values `console | review | upstream`, `id`, `summary`, `evidenceRef`) are pinned equal to that schema table by a prose-code twin test. `id` is `decision:{origin}:{slug}` where `slug` is the staged item's id; `evidenceRef` is a fact id or a repo-relative path. Mapping: contested-finding and unconfirmed-bug rows (review-sourced) have `origin: 'review'`; `needs-human-decision` SDD rulings and other console rows have `origin: 'console'`; external-repo upstream items (the upstream-filing record) have `origin: 'upstream'`. No new console section is added; the route replaces the interactive render for these rows only under control mode.
- **Boundary with #3944 and #4587.** The agent tiebreak of #3944 (when it ships) runs first and settles what it can; only findings it cannot settle, and contested pairs, are carried. #4587's contract, restated: the unattended console holds `needs-human-decision` SDD rulings for a human instead of auto-applying them; this record carries those held rulings into the packet.
- **Terminal states for residue.** A ledger residue row, reflection insight or archived-run residue ends `resolved`, `filed` (a spec-shaped backlog record passing the deferral gate), or `digested` (below the materiality floor, `_shared/materiality-floor.md`; a digest entry counts as terminal by design). An item that is none of these is carried into the packet as a decision fact; if even that fails, the run reports a failure card naming the item, never a silent drop. Filing authorization: the existing `unattended` record-filing bookkeeping capability (verify the capability name in `_shared/autonomy-ceiling.md` "What it authorizes"). A filing failure or a gate rejection carries the draft into the packet. Sources and hooks: ledger residue through `wrap-up/residue-sweep.md` and the ledger resolve gate, reflection insights through `reflect`'s Defer/Capture routing, archived-run residue through the existing `plugin/bin/lib/reconcile/` checks (name each exact module at build from `docs/reconcile-checks.md`); the residue predicates are "row status is open", "insight not yet routed" and "archived run has open items".
- **Unanswered packet decisions.** A carried decision is the packet's open item for the human. When a verdict of `approved` arrives while decisions are still listed, the verdict handler calls this record's pure `settleOpenDecisions(packetFacts)` which files each still-open decision as a spec-shaped backlog record (so nothing is silently ratified by an accept). A packet never blocks a merge on its decisions.
- **Memory writes.** Scope: the memory files the Review Console's memory approvals cover today, and nothing else. Each automatic write logs to `decisions.md` the path, the prior content hash (`none` on create) and a unified diff old-to-new (capped at 20 KB; a larger write stores the prior content in the run's `staged/` directory), so a bad write is reverted by applying the reverse diff. The existing console memory-approval section is auto-resolved under control mode, not removed.
- **HARD-GATEs.** The canonical list is `_shared/auto-mode-contract.md`'s HARD-GATE exemption list; this record cites it rather than restating. The design also names an unresolvable merge conflict; if the contract does not list it, add it there as part of this record. A gate stop is reported with the existing generic failure card (`flow/manifesto.md`'s failure card), asserted per gate in tests.
- **AC5 baseline.** "Unchanged outside control mode" means the existing console, resolve and wrap-up test suites pass unmodified when built from current `main` (including #3942's and #4587's landed changes).

## Acceptance Criteria

1. With `control-mode: on` and a run that produced one policy-resolvable item and one contested finding, the run ends with the first resolved and logged, the second present in the packet's "Decisions left for you" section, and **no console prompt** rendered.
2. A control-mode run ends with zero pending console items outside the packet, zero unresolved ledger residue rows, and zero unfiled reflection insights; each was resolved or filed (assert against fixtures).
3. A filed residue record is spec-shaped and carries a `Defer-reason:` accepted by the deferral gate (a record failing the gate's shape check fails the test).
4. A memory write under control mode produces a `decisions.md` entry naming the path, the prior content hash (`none` for a create) and the old-to-new unified diff; applying the reverse diff restores the prior content (round-trip test); no approval prompt is emitted; a write outside the memory scope is refused.
4a. A residue item that is not resolvable, not fileable (gate rejection or filing failure) and not below the floor appears as a decision fact in the packet; a forced failure of that carry produces a failure card naming the item. A below-floor item lands in the digest and counts as terminal.
4b. `settleOpenDecisions` files one spec-shaped backlog record per still-open decision when called with an approved packet, and files nothing when none are open; an unanswered decision never blocks a merge.
4c. Ceiling precedence: `control-mode: on` alone gives `unattended` capabilities; with an explicit `autonomy: supervised` the capabilities are `supervised`'s; with `autonomy: trusted` they are `trusted`'s; `control-mode: off` is unchanged.
5. With `control-mode: off`, console behavior is unchanged: the pre-existing console, resolve and wrap-up test suites pass unmodified when built from current `main`.
6. Every HARD-GATE on `_shared/auto-mode-contract.md`'s exemption list still stops the run under control mode and is reported with the generic failure card, not a question (one fixture per gate).
7. A `needs-human-decision` ruling is held in the packet (not auto-applied), matching #4587's unattended behavior.
8. `npm test` passes.

## Release Note

Made the end-of-run review console optional in control mode, resolving what policy can and carrying anything that needs you into the acceptance packet.

## Technical Approach

Reuse `consoleAutoResolve` for the resolvable class; add one new terminal route for the unresolvable class (packet section) instead of the interactive render. Residue convergence runs at run end through the existing reconcile/ledger machinery; do not add a new sweep. Control mode implies the `unattended` bookkeeping capabilities through the ceiling-composition rule in the contract decisions above (the `autonomy` ceiling remains the mechanism; an explicit `autonomy` value beats the implication).

### Data / API Surface

- Fact: `{ id, kind: 'decision', origin: 'console' | 'upstream' | 'review', summary, evidenceRef, suggestedResolution }` appended to the packet's decisions list.
- Filed records follow `_shared/deferral-gate.md` and `_shared/materiality-floor.md` (below-floor items go to the digest, not the backlog).
