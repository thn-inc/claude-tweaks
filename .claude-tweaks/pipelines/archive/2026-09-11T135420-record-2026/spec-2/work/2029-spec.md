# 2029: flaky.js's allowlist match is exact-string only — doesn't reuse verify-scope.json's own glob engine

Surface: infra

## Current State
`bin/lib/verify/flaky.js`'s `planRetry` builds `new Set(flaky.files)` and treats a failing file as allowlisted only when `listed.has(file)` — exact string equality against the declaration's `flaky.files` entries. The same `verify-scope.json` file's `rules[].match` entries are globs, compiled by `bin/lib/issues/blast-radius.js`'s `globToRegExp` (memoized, `**` spans segments, `*` stays segment-bound, every other character escaped) and applied in `scope.js`. So one schema carries two matching semantics: a project can write `tests/**` in a rule but must enumerate `tests/flaky/a.test.js`, `tests/flaky/b.test.js`, … in the allowlist and edit the list every time a flaky file is added. `declaration.js` validates `flaky.files` only as "an array of path strings", and `test/verification.md`'s Flake handling paragraph documents the entries as "exact repo-relative paths" that "must match the failing-file paths exactly as the suite's own output prints them".

## Deliverables
- [ ] `planRetry` matches each failing file against `flaky.files` with `globToRegExp(entry).test(file)` (any entry matching allowlists the file), keeping the `unlisted: [...]` reason and the fail-safe on any unmatched file; an entry with no glob metacharacter compiles to an anchored literal, so existing exact-path lists behave byte-for-byte as today.
- [ ] `declaration.js`'s `flaky.files` validation message reads "an array of path or glob strings"; no schema change.
- [ ] `test/verification.md`'s Flake handling paragraph: "exact repo-relative paths" becomes "repo-relative paths or globs (the same `**`/`*` forms `rules[].match` accepts)", and the sentence that entries must match the suite's printed paths keeps its warning about package-relative output — a glob is matched against the same printed path.
- [ ] Tests in `tests/bin-lib/verify/flaky.test.js`: a `tests/flaky/**` entry allowlists a new file under that directory; an exact entry still matches only itself; `tests/*.test.js` does not match a nested file (segment-bound `*`); an entry that matches nothing leaves the unlisted reason naming the file. `tests/bin-lib/verify/declaration.test.js` gets the message text update if it pins the old wording.

## Acceptance Criteria
1. Existing exact-path `flaky.files` entries produce the same `planRetry` decisions as before (the existing flaky cases pass unmodified).
2. A glob entry allowlists every failing file it matches, with `**` and `*` behaving exactly as they do for `rules[].match`.
3. A failing file matched by no entry still blocks the retry with `unlisted:` naming it.
4. The `flakyHits` counter and the `flaky-allowlist` escalation CAVEAT stay keyed by the concrete file path, never by the glob; `npm test` is green.

## Technical Approach
Reuse the engine the file already shares a schema with: `scope.js` imports `globToRegExp` from `bin/lib/issues/blast-radius.js`; `flaky.js` imports the same function and replaces the `Set` lookup with a `some(entry => globToRegExp(entry).test(file))` pass. The regex builder escapes every non-glob character, so backward compatibility for exact paths is a property of the compiler, not a special case. The retry command template still substitutes the concrete file, so nothing downstream sees a glob.

### Key Files
- `plugin/bin/lib/verify/flaky.js` — `planRetry` (the `listed` Set and `unlisted` filter).
- `plugin/bin/lib/issues/blast-radius.js` — `globToRegExp` (read-only, imported).
- `plugin/bin/lib/verify/declaration.js` — `flaky.files` validation message.
- `plugin/skills/test/verification.md` — Flake handling paragraph.
- `tests/bin-lib/verify/flaky.test.js`, `tests/bin-lib/verify/declaration.test.js`.

## Gotchas
- `globToRegExp` has no `?` wildcard (it escapes `?`); say "the same forms `rules[].match` accepts" rather than promising full glob syntax.
- The escalation counter is what tells a maintainer which concrete file keeps flaking; a glob allowlist must not blur that, so the per-file `flakyHits` key is unchanged and the `flaky-allowlist` CAVEAT still names the file.
- `/claude-tweaks:wrap-up`'s leftover routing files an escalation as a backlog record per file; a glob entry does not change that shape.
