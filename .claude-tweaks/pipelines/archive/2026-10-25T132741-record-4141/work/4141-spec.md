# 4141: resolve-policy --values: warn on stderr when a requested key's value is invalid

Origin: reflect full from #4041

Defer-reason: tangential

## Current State

`plugin/bin/resolve-policy.js --values` prints one scalar per requested key. For a key whose configured value fails schema validation, the resolver returns `{ value: <schema default>, invalid: true }`, and `--values` prints that default with exit 0 and nothing on stderr. The `invalid` flag is lost. #4041's review found `release-tip-moves: abc` silently read as `2` this way (`tests/release-reviewed-tip-conformance.test.js` "the --values form prints the default with exit 0 and no sign of the invalid value"), and fixed only that one read site by switching it to the JSON form. 61 files under `plugin/skills` and `plugin/bin` still call `--values`, so a typo in any policy key they read degrades to the default with no trace.

## Deliverables

`resolve-policy.js --values` writes one stderr line per requested key whose entry carries `invalid: true`, naming the key, the rejected value, and the default it fell back to. Stdout and the exit code stay unchanged, so no existing caller breaks.

## Acceptance Criteria

A `tests/` case runs the real `resolve-policy.js --values` against a run config holding an invalid value. It asserts stdout is the default, exit is 0, and stderr names the key and the word `invalid`.

A case with only valid keys asserts stderr is empty.

`npm test` passes.

## Release Note

An invalid value in `.claude-tweaks/policy.yml` or a run config now produces a warning when a skill reads it, instead of silently falling back to the default.

## Technical Approach

### Key Files

- `plugin/bin/resolve-policy.js` — warn on stderr for each invalid key in --values mode
