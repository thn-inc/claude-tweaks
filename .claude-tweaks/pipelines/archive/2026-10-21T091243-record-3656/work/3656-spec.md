# 3656: flow multi-spec: ephemeral-server.txt is written per spec, so later specs' review fix waves and the consolidated teardown miss the shared server

Origin: #3021 build — whole-branch review finding (multi-spec record location)

Defer-reason: pre-existing-outside-diff

**Related:** #3657, #3664

## Current State

In a multi-spec `/claude-tweaks:flow` run each spec's `PIPELINE_RUN_DIR` is `{parent}/spec-{N}/` (`plugin/skills/flow/multi-spec.md`). `_shared/dev-url-detection.md`'s Ephemeral server start writes `{run-dir}/ephemeral-server.txt`, so the record lands in whichever spec first started the server; later specs reuse that server by port probe without a record of their own.

- `review/step3-routing.md`'s Fix-wave server coordination (#3021) reads `{run-dir}/ephemeral-server.txt`; from the second spec on it finds no file and skips the stop, so that spec's fix-wave re-verify can rebuild the app under the still-live shared server — the #3021 defect, for every spec after the first.
- `flow/multispec-review-console.md` step 1 and `flow/multispec-console-template.md` row 15 tear down `{parent-run-dir}/ephemeral-server.txt`, a path nothing writes, so the shared server is likely left running at the end of a multi-spec run.

## Deliverables

1. Pick one record location for a multi-spec run (the parent run dir, via `MULTISPEC_PARENT_DIR`) and make every writer (`dev-url-detection.md` item 4, `dispatch/task-prompt.md`'s detached-start record) and reader (`review/step3-routing.md`'s coordination, `wrap-up/cleanup-procedures-execution.md` Section D, `flow/multispec-review-console.md` step 1) resolve it.
2. Conformance test pinning that a multi-spec run's writer and readers name the same path.

## Acceptance Criteria

- In a multi-spec run, a later spec's review fix wave stops the server an earlier spec started.
- The consolidated teardown kills the recorded shared server; no ephemeral server outlives the run.
- Single-spec runs behave exactly as today.
- `npm test` passes in full.

## Release Note

Multi-spec pipeline runs now stop and clean up their shared test server correctly instead of leaving it running or rebuilding under it.
