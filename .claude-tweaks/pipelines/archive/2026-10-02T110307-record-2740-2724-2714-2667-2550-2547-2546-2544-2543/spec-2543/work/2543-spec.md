# 2543: friction logging: gate denials incurred in the main checkout before any run dir exists are never logged

Surface: infra

## Current State
`worktree-always: true` projects can incur a `wd-deny`/`gate-denial` in the main checkout (not a worktree) before any pipeline run dir has been minted for the session — for example a `git push origin develop` blocked by the integration-branch push gate. `bin/lib/hooks/post-tool-use.js`'s `stampAdHocRunDir` (the mechanism introduced by #500/#1333 to give a denial somewhere to land when no run dir exists yet) only fires when an `EnterWorktree` call just happened or `cwd` resolves to a worktree. In the main-checkout case, neither condition holds, so `appendEvent` is called with no run dir and the event is dropped. A later standalone `/claude-tweaks:wrap-up` creates a `{ts}-<topic>-standalone` run dir and its Friction lens reads `[]` from `bin/friction-events.js` for that run, even though the operator experienced a real denial earlier in the session. `reflect/full-mode.md`'s Friction lens vocabulary states every denial is written to the log, which is not true for this case. Confirmed still present in plugin version 6.126.0; #2351 (closed) may already address part of this and needs to be checked against the repro below before this is treated as still-open.

## Deliverables
1. Confirm whether #2351 already covers the main-checkout-before-any-run-dir case; if it does, close this record noting which release carries the fix instead of proceeding with 2-4 below.
2. If not covered, extend the ad-hoc run-dir stamping (or add a session-scoped events file that `bin/friction-events.js` unions in) so a gate denial incurred in the main checkout, before any run dir is owned by the session, is retrievable by a later `friction-events.js --run` call for a run dir created afterward in the same session.
3. Add a test beside `tests/reflect-friction-lens-vocab.test.js` covering the main-checkout-denial-before-run-dir scenario.
4. Update `reflect/full-mode.md`'s Friction lens section to state the coverage limit explicitly, so an empty array is not read as a clean run when the session was never in a worktree at denial time.

## Acceptance Criteria
- Given a `worktree-always: true` project, a session that never enters a worktree, and a gate denial (e.g. a blocked `git push origin develop`) that occurs before any pipeline run dir exists, a subsequent `node bin/friction-events.js --run <run-dir-created-later-in-the-same-session>` call returns that denial event (not `[]`), OR the record is closed with the specific plugin version/PR that already fixed this, cited from #2351.
- A new automated test beside `tests/reflect-friction-lens-vocab.test.js` reproduces the main-checkout-before-run-dir scenario and fails on the current `stampAdHocRunDir` behavior (only fires post-`EnterWorktree` or when `cwd` resolves to a worktree), then passes after the fix.
- `reflect/full-mode.md`'s Friction lens section names the coverage limit (or states it is now fully covered, if the fix closes the gap entirely) so a reader does not read an empty array as an all-clear when the session ran entirely in the main checkout.
- No regression to existing worktree-scoped ad-hoc stamping behavior (`tests/reflect-friction-lens-vocab.test.js` and any existing `stampAdHocRunDir` tests continue passing).

## Release Note

Logged guard denials that happen in the main checkout before a run directory exists.

## Technical Approach
Two viable directions, either satisfies the acceptance criteria above:
1. Widen `stampAdHocRunDir` in `bin/lib/hooks/post-tool-use.js` to also fire on the first denial in a session with no run dir owned yet, regardless of whether `cwd` resolves to a worktree or an `EnterWorktree` call just happened.
2. Add a session-scoped events file (keyed by `CLAUDE_CODE_SESSION_ID`, not by run dir) that `bin/friction-events.js` unions into its results whenever a `--run` is queried, so a main-checkout denial recorded under the session key is still visible once a run dir is later created in the same session.

Start by checking #2351's diff to see whether it already implements one of these; if it does, this becomes a confirm-and-close task rather than a build task.

### Key Files
- `plugin/bin/lib/hooks/post-tool-use.js` — `stampAdHocRunDir` function; widen its firing condition or add the session-scoped fallback write
- `plugin/bin/friction-events.js` — event read path; union in the session-scoped events file if that approach is chosen
- `plugin/skills/reflect/full-mode.md` — Friction lens section; state the coverage limit or its resolution
- `tests/reflect-friction-lens-vocab.test.js` — sibling test file; add the new main-checkout-before-run-dir scenario here

## Gotchas
- Confirm against #2351 first — this may already be fixed and this record may just need a close-with-citation rather than new code.
- A session-scoped events file introduces a second on-disk log distinct from the run-dir-scoped one; make sure `friction-events.js`'s union doesn't double-count an event that later also gets a real run-dir-scoped entry once the session enters a worktree.

## Original request

friction logging: gate denials incurred in the main checkout before any run dir exists are never logged

**Summary:** A `wd-deny`/`gate-denial` fired against a session working in the main checkout (not a worktree) with no run dir yet has nowhere to land, so a later standalone `/claude-tweaks:wrap-up`'s Friction lens reads `[]` from `friction-events.js` for a run whose operator did experience a denial.

**Kind:** Defect

**Affected component:** friction logging — `bin/lib/hooks/post-tool-use.js` (`stampAdHocRunDir`) and `bin/friction-events.js`; `reflect/full-mode.md`'s Friction lens

**Repro steps:**
1. `worktree-always: true` project. Session works in the main checkout with no pipeline run dir owned.
2. Trigger a gate denial there (e.g. `git push origin develop`, see the sibling report on the integration-branch push gap).
3. Later in the same session, run `/claude-tweaks:wrap-up` (standalone). Phase 1 creates `{ts}-<topic>-standalone`.
4. `node bin/friction-events.js --run <that run dir>`.

**Expected vs. actual:**
Expected: the denial from step 2 is retrievable — either the ad-hoc stamp (`stampAdHocRunDir`, #500/#1333) fires on the first denial in a session with no run dir regardless of cwd, or main-checkout denials are recorded to a session-scoped events file that `friction-events.js` also unions in.
Actual: `[]`. `stampAdHocRunDir` only fires when an `EnterWorktree` call just happened or `cwd` resolves to a worktree; in the main checkout neither holds, so `appendEvent` had no run dir, and the Friction lens knew about the denial only from the conversation, not from the log the vocabulary block says every denial is written to.

Proposed fix: extend the ad-hoc stamp (or a session-scoped events file unioned by `friction-events.js`) to cover main-checkout denials, add a test beside `tests/reflect-friction-lens-vocab.test.js`, and state the coverage limit in `reflect/full-mode.md`'s Friction lens so an empty array is not read as a clean run when the session was never in a worktree. Possibly already addressed by #2351 (closed) — if so, this is a request to confirm which plugin version carries the fix, since 6.126.0 still shows the behaviour.
