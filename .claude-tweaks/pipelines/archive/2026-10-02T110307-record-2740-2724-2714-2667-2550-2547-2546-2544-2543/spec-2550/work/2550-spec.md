# 2550: wrap-up summary-template: mandated-verbatim Timing and State blocks render empty or contradict the verdict beside them on a standalone run

Surface: terminal

## Current State
The wrap-up closure report (`skills/wrap-up/summary-template.md`) mandates verbatim inclusion of two generated blocks — a Timing table from `phase-timing.js --markdown` and a State block from `wrap-up-state.js` via `wrap-up-pack.js` — plus a closure Verdict line derived from the verify contract. On a standalone `/claude-tweaks:wrap-up` run (typed directly, not via `/flow`) on conversation-based work whose curation commits land in a fresh worktree, three problems compound: (1) the Timing table renders 12 rows all reading `0 | unattributed | 0/0 | 0.0 | 0` because no phase events were recorded outside a `/flow` run, producing a table with zero information content; (2) the State block is captured once at Phase 3, before the curation commits exist, so it reads "0 commits, UNPUSHED" immediately next to a "Final measured state: PR merged" line that contradicts it; (3) the Verdict opens "Everything shipped" but is immediately followed by "BLOCKED per the verify contract" because verify's structural fails (outside the scope of this run) are surfaced as a hard block rather than a non-applicable note.

## Deliverables
1. `phase-timing.js --markdown` (or its caller in `summary-template.md`) collapses the Timing table to a single summary line — e.g. "no phase events; N tool round-trips, {in}/{out} tokens" — whenever every phase row would render `unattributed`/zero.
2. `wrap-up-state.js` (via `wrap-up-pack.js`) captures State after Phase 4 execution completes (post-curation-commit) on a standalone run — or, if a fresh capture isn't feasible at render time, the rendered block is explicitly labelled as a Phase 3 snapshot and a delta line is appended noting what changed since.
3. The closure Verdict line in `summary-template.md` reports verify's structural fails that are outside the current run's scope as "not applicable" rows rather than forcing an overall BLOCKED verdict that contradicts an "Everything shipped" opening line.

## Acceptance Criteria
1. Running `/claude-tweaks:wrap-up` standalone on work with no recorded phase events renders a single-line Timing summary, not a 12-row all-zero table.
2. Running `/claude-tweaks:wrap-up` standalone on work whose curation commits land after the Phase 3 snapshot renders a State block that either reflects post-commit state or is explicitly labelled as a pre-commit snapshot with a stated delta — it never juxtaposes "0 commits, UNPUSHED" directly against "Final measured state: PR merged" with no reconciling text.
3. When verify's only fails are structural checks outside the current run's scope, the rendered Verdict does not read "BLOCKED" beneath an "Everything shipped" opening line — out-of-scope fails render as "not applicable" instead.
4. Existing `/flow`-driven wrap-up runs (which do have phase timing events) are unaffected — the collapse in AC1 triggers only when all phase rows are `unattributed`/zero.

## Release Note

Stopped the wrap-up summary from showing empty or contradictory timing and state blocks on standalone runs.

## Technical Approach
Modify the rendering logic in `summary-template.md`'s Timing and State block instructions to add the conditional collapse (AC1) and snapshot-labelling (AC2) behavior. Adjust `phase-timing.js`'s markdown output (or the template's consumption of it) to detect the all-zero case. Adjust `wrap-up-state.js`/`wrap-up-pack.js` to support a post-Phase-4 recapture, or to emit a snapshot timestamp usable for delta-labelling. Adjust the closure-Verdict composition rule to treat out-of-scope verify structural fails as "not applicable" rather than "BLOCKED".

### Key Files
- `plugin/skills/wrap-up/summary-template.md` — Timing/State block rendering instructions, closure Verdict composition rule
- `plugin/bin/phase-timing.js` — markdown timing output; needs an all-zero/unattributed detection path
- `plugin/bin/wrap-up-state.js` — state snapshot capture; needs post-Phase-4 recapture or snapshot-timestamp support
- `plugin/bin/wrap-up-pack.js` — orchestrates state capture into the wrap-up pack consumed by the template

## Gotchas
This is a display/reporting-only change — no data model or contract fields are removed. The main risk is scope: the fix must not alter `/flow`-driven wrap-up runs, which do have real phase timing data and a Phase 4 state capture already in the normal flow. Verify the all-zero detection is specific to the standalone-run case and doesn't accidentally collapse a real (but small) timing table.
