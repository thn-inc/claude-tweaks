# 2544: wrap-up/reflect/feedback: steps prescribed as JS module calls have no CLI verb, forcing scratch glue scripts

Surface: infra

## Current State
Several steps that `/claude-tweaks:wrap-up`, `/claude-tweaks:reflect`, and `/claude-tweaks:feedback` prescribe are only reachable today as JS module APIs, or have no verb at all:
- `bin/lib/declined-learning/store.js`'s `listDeclined`/`lookupDecline`/`recordDecline`, prescribed by `reflect/full-mode.md`, have no CLI wrapper.
- `bin/wrap-up-pack.js` has no way to print a single probe's value (`residue`, `state`, `blastRadius`) — only a full dump.
- `bin/wrap-up-engine.js record` accepts one stdin payload per invocation, with no batch form.
- The Wrap-Up Review Console's own outcome writes (`verify-expectations.json`, decline log lines, ledger row status flips) have no dedicated verb — a caller has to hand-assemble them.
- Ledger deletion (wrap-up cleanup item 2) has no verb at all.

In a live standalone `/claude-tweaks:wrap-up` run on a private project, this forced nine ad-hoc scratch glue scripts in a temp directory to execute what the skill text prescribes as steps, including a 3-attempt retry loop (a `node -e` module call printed nothing under Git Bash until the call was moved into a file) and two shape-guessing crashes reading `wrap-up-pack.json` (its `residue.value.results` field is a list, not a dict, which was not discoverable without trial and error). A `worktree-always` project's gate cannot inspect ad-hoc scratch scripts the way it can inspect a sanctioned CLI invocation (see the related report on the complexity verifier, referenced below), so this also degrades auditability, not just convenience.

## Deliverables
1. `bin/declined-learning.js lookup --source <source>` — reads a description from stdin, prints the computed fingerprint plus any prior decline record for it.
2. `bin/declined-learning.js record-decline --source <source>` — reads a description (and reason) from stdin, writes a decline record via `recordDecline`.
3. `bin/wrap-up-pack.js --print <residue|state|blastRadius>` — prints just the named probe's value from the pack, instead of requiring a full JSON dump plus manual field extraction.
4. `bin/wrap-up-engine.js record --batch <file>` — accepts a file of multiple record payloads in one invocation instead of one stdin payload per call.
5. `bin/wrap-up-engine.js finish-console --run <dir> --approve-all` — writes `verify-expectations.json`, logs the terminal decision plus each M#/U# outcome, and flips the corresponding ledger row statuses, replacing the current hand-assembly of those three outcome writes.
6. `bin/hooks.js delete-ledger --run <dir>` — deletes the run's ledger file, giving wrap-up cleanup item 2 a verb.

## Acceptance Criteria
- `bin/declined-learning.js lookup --source reflect` (given a description on stdin) prints a fingerprint and any prior decline record, with no scratch script required, and returns a non-zero exit code on a malformed/missing description rather than silently printing nothing.
- `bin/declined-learning.js record-decline --source reflect` writes a decline record retrievable by a subsequent `lookup` call against the same fingerprint.
- `bin/wrap-up-pack.js --print residue`, `--print state`, and `--print blastRadius` each print only that probe's value (matching the shape already returned inside the full pack's corresponding field) and exit non-zero if the named probe is absent from the pack.
- `bin/wrap-up-engine.js record --batch <file>` records every entry in the batch file in one invocation, verified by re-reading the resulting records and confirming a count match against the batch file's entry count.
- `bin/wrap-up-engine.js finish-console --run <dir> --approve-all` produces a `verify-expectations.json` at the expected path, appends the terminal decision and every M#/U# outcome to the decision log, and updates every corresponding ledger row's status — verified by re-reading all three artifacts after the call.
- `bin/hooks.js delete-ledger --run <dir>` removes the run's ledger file and exits 0; running it again on an already-deleted ledger exits with a clear "not found" status rather than a crash.
- None of the six new verbs requires a scratch `node -e` script or a temp-directory glue file to invoke from a skill's prescribed step text.

## Release Note

Added command-line tools for steps that previously needed throwaway scripts.

## Technical Approach
Add one CLI subcommand (or a small new CLI file, matching this repo's existing `bin/*.js` conventions per `gh-api-module-pattern` and the CLI-wrapper-contract conventions already used by `stage-item.js`/`compose-context.js`/`set-config.js`) per Deliverable above, each thinly wrapping the existing JS module function it fronts — no new business logic, just a stdin/argv-to-function-call adapter with the CLI's standard exit-code vocabulary. `wrap-up-pack.js --print <probe>` and `wrap-up-engine.js record --batch` extend existing CLIs with new flags rather than adding new files. `finish-console` and `delete-ledger` are new subcommands on `wrap-up-engine.js`/`hooks.js` respectively.

### Key Files
- `plugin/bin/declined-learning.js` — new CLI file (or new subcommands on an existing declined-learning entry point if one already exists) wrapping `lookupDecline`/`recordDecline` from `bin/lib/declined-learning/store.js`
- `plugin/bin/lib/declined-learning/store.js` — existing module providing `listDeclined`/`lookupDecline`/`recordDecline`; no changes expected beyond exposing what the new CLI wraps
- `plugin/bin/wrap-up-pack.js` — add `--print <residue|state|blastRadius>` flag
- `plugin/bin/wrap-up-engine.js` — add `record --batch <file>` flag and a new `finish-console --run <dir> --approve-all` subcommand
- `plugin/bin/hooks.js` — add a `delete-ledger --run <dir>` subcommand
- `plugin/skills/reflect/full-mode.md` — update prescribed steps to cite the new `declined-learning.js` verbs instead of the raw module calls
- `plugin/skills/wrap-up/**` (console/cleanup sub-files) — update prescribed steps to cite the new `wrap-up-pack.js --print`, `wrap-up-engine.js record --batch`/`finish-console`, and `hooks.js delete-ledger` verbs

## Gotchas
- `wrap-up-pack.js`'s `residue.value.results` field is a list, not a dict — the `--print` flag's implementation and its documentation must reflect the actual shape, not the shape a caller might guess.
- `finish-console --approve-all` batches three distinct outcome writes (`verify-expectations.json`, decision-log entries, ledger row flips) atomically from the caller's perspective — decide and document what happens if one of the three writes fails partway through, so a partial console finish isn't silently reported as complete.
- Related records #2564 and #2568 may overlap with parts of this gap — check their scope before duplicating work on the same verbs.
- Git Bash's `node -e` behavior (module output not flushing to stdout until run from a file) is an environment quirk observed during the triggering session, not necessarily reproducible on every platform — don't over-fit the new CLIs' output-flushing behavior to that one observation without confirming it's a real cross-platform issue.
