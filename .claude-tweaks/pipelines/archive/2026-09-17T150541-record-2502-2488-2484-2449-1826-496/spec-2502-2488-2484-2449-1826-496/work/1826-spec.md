## Current State

The resuming call's `/claude-tweaks:review` Step 5 code-simplifier dispatch was BLOCKED by the bookkeeping-stamps PreToolUse gate until the session ran `_shared/pr-early-run-lifecycle.md` by hand mid-review.
- Run `2026-09-04T122916-record-976` (#1832, absorbed here): the group's first `build,test` call recorded in its own `decisions.md` that it "executed directly against the group's shared worktree without invoking the full `/claude-tweaks:flow` skill machinery (Manifesto/materialize/claim steps)" — so `/flow` Step 2.8's claim-targets never ran, an earlier firing's live claim on 4 of the 6 records was never seen, and the call re-implemented work PR #1799 had already merged. Same shape as the two runs above, with the claim step as the third artifact that vanished.
- Run `2026-09-04T181649-record-1484` (#1858, absorbed here): the directory carried `decisions.md`/`events.jsonl`/`run-state.json` but no `config.yml`, `decisions.md` had no Manifesto entry and no `PR-early run lifecycle` entries, the branch had no upstream, and `run-state.json` had no `pr` field — both mandatory procedures silently absent with zero trace.
- A private-project run on plugin 6.114.0/6.114.1 (#1810, absorbed here): the first `build,test` call completed normally and its own `decisions.md` records the Manifesto writing `config.yml`, yet the second call ~80 minutes later found `decisions.md`, `events.jsonl`, `run-state.json` (with `worktree` and `pr`) and a committed `work/{n}-spec.md` but no `config.yml`; it landed in case 3, whose prose describes an interrupted first call, and recovery backfilled `config.yml` via `set-config.js` from `decisions.md`'s "Pipeline config snapshot" header. The cause could not be established because the Manifesto's write logs no path.

What the current code says should happen: `bin/lib/flow/preflight.js` classifies an adopted directory into case 1 (has `config.yml` → adopt as-is), case 2 (no `config.yml`, otherwise empty → adopt then initialize as fresh, the minted-but-unadopted shape dispatch creates), or case 3 (no `config.yml` but other content → explicit backfill of `config.yml`, `record-worktree`, and the PR-early push/open). The record-703 run is case 2 for the first call — so either that call's `/flow` never reached the Manifesto and `build/worktree-setup.md` Step 6, or its writes landed somewhere other than the anchored directory (a worktree-local shadow is exactly `[IL-127]`'s shape, and `checkPipelineShadowGuard` only denies *creating* a new run directory in a worktree, not writes into a pre-existing shadow). The record-1484 run is case 3 for the second call, and #1858's hypothesis — an adopt-inherited-run-dir guard treating a pre-existing directory as "already handled" — would explain both artifacts vanishing together. Neither run's first call left a `SKIP` line, so the degrade-trace rule (`_shared/auto-decision-log.md`) was not honored on whichever path skipped.
