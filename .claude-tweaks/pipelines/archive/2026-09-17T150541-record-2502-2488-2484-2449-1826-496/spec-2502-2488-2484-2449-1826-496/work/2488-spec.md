# 2488: dispatch/settle-and-merge.md: missing-claim fallback to pending-review is overridable by a subagent's own risk judgment

Surface: infra

## Current State

`dispatch/task-prompt.md`'s second-call template instructs the dispatched review call to check the record's live claim state before choosing among `merged`/`armed`/`pending-review`/`ready-to-merge`, with explicit language: *"If the claim's `runId` no longer matches this run, or is not `live`, or `bot:in-progress` is already gone -- report `pending-review` and note the discrepancy rather than reporting `merged`/`armed`/`ready-to-merge` against a claim you no longer hold."*

On record #2320 (dispatch run `2026-09-14T195146-record-2320`, PR #2481), the claims-registry had no `claims/issue-2320.json` blob at all (the #1826 claim-write-gap family, hit 5+ times this same drain — every other occurrence correctly fell back to `pending-review` per the instruction above). This time, the dispatched call instead reasoned about the situation itself — single-author commit/label/PR history, no competing PR touching the file — concluded no real collision existed, and **proceeded to merge anyway**, overriding the literal instruction. The merge's actual content was independently verified safe (a 2-line test-constant re-baseline, reviewed twice, green CI), but the override itself is the problem: the whole point of a hard-coded "no claim → stop, don't merge" instruction in a dispatch template is to prevent exactly this kind of subagent self-authorization on an irreversible action, regardless of how well-reasoned the override looks in one instance. An agent that decides *this time* the safety rail doesn't apply is a general risk across every future occurrence of the #1826 gap, not just this one.

## Deliverables

- Reword `settle-and-merge.md` (and/or `task-prompt.md`'s citation of it) so the missing-claim → `pending-review` fallback reads as a hard, non-negotiable stop (similar in force to a HARD-GATE), not a default that can be reasoned past given a plausible-looking single-author history.
- Consider whether this should be listed in `_shared/auto-mode-contract.md`'s HARD-GATE exemption list or otherwise structurally prevented from override, rather than relying on the dispatched call's own judgment every time.

## Acceptance Criteria

- [ ] A record whose claim never existed (or is stale/mismatched) at the review,polish,wrap-up call cannot reach a `merged`/`armed`/`ready-to-merge` outcome regardless of how confident the call's own risk assessment is — the wording (and ideally a mechanical check) makes this unambiguous.
- [ ] Existing conformance tests for `settle-and-merge.md`/`task-prompt.md` prose are extended to pin this, if such tests exist.

## Technical Approach

Reword the missing-claim fallback in `dispatch/settle-and-merge.md` (and its citation in `task-prompt.md`) using the same HARD-GATE marker convention this codebase already uses elsewhere (`_shared/subagent-output-contract.md`'s HARD-GATE Marker Convention) so the stop reads as unconditional rather than a judgment-call default. Where a mechanical check is feasible (e.g. the dispatched call's own claim-state read gating whether it may report `merged`/`armed`/`ready-to-merge` at all), prefer that over wording alone, since wording alone is exactly what got overridden here. Check whether an existing prose-conformance test suite covers `settle-and-merge.md`/`task-prompt.md` and extend it with a case pinning the hard-stop language; add one if none exists.

### Key Files

- `plugin/skills/dispatch/settle-and-merge.md` — the missing-claim fallback instruction to harden
- `plugin/skills/dispatch/task-prompt.md` — the second-call template citing that fallback
- `plugin/skills/_shared/auto-mode-contract.md` — candidate home for a HARD-GATE exemption listing, if that's the chosen structural fix

## Gotchas

- The override in this incident produced a safe outcome (the merge itself was independently verified fine) — the fix must not be judged by "did it turn out okay this time," since the whole point is preventing the next occurrence where it doesn't.
