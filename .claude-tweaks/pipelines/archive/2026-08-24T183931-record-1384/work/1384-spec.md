# 1384: Grant mode has no consolidated CLI or cheap early short-circuit

**Related:** #1385, #1386, #1387

## Current State

skills/backlog/grant-mode.md's headless grant sweep has no single `bin/` CLI — a human or agent must hand-run ~40 Bash/`node -e` steps (ceiling gate, merge-lane breaker sweep on watched.json, ready-label fetch, sub-issue enumeration, git-log parse, trustRows() build, then evaluateGrantGate per candidate) to reach gates 1-3's pure conclusion. overview-mode.md's machineGrantOutlook computes the identical Phase-1 (gates 1-3) verdict cheaply in one pass as part of its own funnel render. Observed in a live run (2026-08-24): the manual grant sweep spent an entire multi-minute session (~40 commands, full trust-table rebuild) to conclude 0 of 11 eligible candidates were grantable — a conclusion overview had already surfaced via its "N refused — trust: N" line for the same backlog state.

## Deliverables

- A bin/backlog-grant-gate.js (or similar) CLI that runs grant-mode.md's Step 0 (ceiling gate) through Step 2 Phase A (gates 1-3, pure) as one invocation, reusing evaluateGrantGate/trustRows/machineGrantOutlook directly instead of requiring an agent to hand-compose the equivalent Bash pipeline.
- An early-exit check in grant-mode.md's procedure (or in the CLI above) that consults a fresh machineGrantOutlook result before running the full per-candidate loop, and short-circuits with the refusal breakdown when zero candidates have needsGrantCheck: true.

## Acceptance Criteria

- A headless (or hand-run) /claude-tweaks:backlog grant invocation on a backlog where no trust class reads clean completes without re-deriving the full trust table via ad-hoc shell composition.
- The CLI's output (or the skill's own early-exit report) states the same refusal breakdown overview's machineGrantOutlook already computes, with no discrepancy between the two surfaces for the same backlog state.
