# 1259: Bookkeeping-stamps gate: record-worktree-branch foreign-session guard is near-unreachable

**Related:** #1258

Origin: whole-branch review of #991 (bookkeeping-stamps gate)

Defer-reason: genuinely-larger

## Current State

`checkBookkeepingStampsGate`'s (`plugin/bin/lib/hooks/pre-tool-use.js`) foreign-session guard (`isForeignSessionCall`) mirrors E1's own owner-vs-caller comparison: `ctx.runState.sessionId` (owner) vs `ctx.input.session_id` (caller), warning instead of denying only when both are known and differ. But ownership (`sessionId`) is stamped by `record-worktree` itself and by `post-tool-use.js`'s ad-hoc-run stamping — both write `sessionId` and `worktree` together. So on the gate's own `record-worktree` deny branch (fired precisely when `runState.worktree` is UNSET), `owner` is almost always empty — not provably foreign — so the guard rarely engages exactly where it matters most: the deny that hands the agent a `record-worktree --run <dir> <path>` remediation command risking corruption of a sibling session's `run-state.json`. The guard is fully effective on the PR-stamp branch (where `worktree` is already set, so `sessionId` is too). Separately, `ctx.ownedRun` is already threaded into the hook dispatcher (`plugin/bin/hooks.js`) and is unused by this gate — a stronger signal than the current `runState.sessionId`/`input.session_id` comparison.

## Deliverables

- Investigate using `ctx.ownedRun` (already resolved and threaded into the PreToolUse hook dispatch) to strengthen the `record-worktree` branch's foreign-session guard, so it can distinguish "this run is genuinely unowned, proceed" from "this run belongs to a live sibling session that just hasn't stamped ownership onto it yet" — the case the current `sessionId`-comparison guard structurally cannot see.
- Preserve the existing PR-stamp branch's guard unchanged (already fully effective there) and the ambiguity-resolves-to-allow posture throughout.

## Acceptance Criteria

- A regression test reproduces the specific gap: a live sibling session's run genuinely lacks a `worktree` stamp yet (record-worktree hasn't run for it yet), and the gate's deny-remediation message does not risk instructing an unrelated agent to stamp that sibling's run state.
- The PR-stamp branch's existing foreign-session tests continue to pass unchanged.
