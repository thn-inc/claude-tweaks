# 2436: npm test: 3 sandbox-only failures split out of #1853 (Impeccable pin, 2 whole-file)

Surface: infra

**Related:** #2401, #2402

## Current State

Split out of #1853's Deliverable 5. While building #1853 (root-privileged `npm test` failures), three of the sixteen originally-reported failures were confirmed **not** permission-related and **not reproducible on this checkout as a normal user** (20/20 across the three files, run clean):

- `tests/impeccable-plugin-contract.test.js` — pins the installed Impeccable plugin's version; fails in a sandbox whose plugin cache carries a different (or absent) version than this checkout expects.
- `tests/shaping-mode-needs-removal.test.js` — whole-file failure, cause not reproduced locally.
- `tests/tidy-needs-worklist-rule.test.js` — whole-file failure, cause not reproduced locally.

Reproduction condition: **sandbox only — passes locally.** This record does not claim to fix them; it exists to track the gap once #1853's permission-simulation skips land (so a root sandbox's `npm test` can go fully green there per #2010).

## Deliverables

- [ ] Reproduce the `tests/impeccable-plugin-contract.test.js` failure in a sandbox with a differently-versioned or absent Impeccable plugin cache; determine whether the pin should read the installed version dynamically or the sandbox's plugin-provisioning step needs a fix.
- [ ] Reproduce `tests/shaping-mode-needs-removal.test.js` and `tests/tidy-needs-worklist-rule.test.js`'s whole-file failures in the same sandbox shape; identify the actual cause (environment-dependent fixture path, missing plugin cache asset, or similar) before proposing a fix.

## Acceptance Criteria

1. Each of the three tests' sandbox failure is reproduced (not just cited) and its root cause identified.
2. A fix or an explicit environment-provisioning follow-up is proposed for each.
3. `npm test` as a normal user on this checkout stays green throughout.

## Blocked / Future Work

- **`tests/impeccable-plugin-contract.test.js` — blocked, environment-provisioning follow-up
  proposed, not code-fixed.** Root cause (identified by reading `checkVersion` in
  `tools/upstream-drift/checks.js` and the test's own comments): the "installed plugin matches
  the pinned version" assertion SKIPS when the plugin is absent, but FAILS ('breach') when a
  *present-but-different* version is installed — this is the drift detector's intended job, not a
  bug. Reproducing the failure requires an actual sandbox whose plugin cache carries a different
  version of `impeccable-plugin` than `tools/upstream-drift/manifest.yml`'s pin; the test file's
  own comments explicitly forbid mutating the real `~/.claude/plugins/cache` to simulate this, so
  it could not be reproduced from this checkout. Proposed fix: none — this is working as
  designed. Proposed follow-up: whatever provisions the sandbox's plugin cache (the root-privileged
  `npm test` environment referenced in #1853) must install exactly the pinned version, not a
  different or absent one. Tracked as an open ledger item (`docs/plans/2026-09-17-record-2436-ledger.md`)
  for `/wrap-up` to route (backlog record vs. accept-and-close).
- **`tests/shaping-mode-needs-removal.test.js` and `tests/tidy-needs-worklist-rule.test.js` —
  reproduced and fixed.** Both perform a top-level (module-load-time) `execFileSync('git', ['show',
  'd111b14742e935487e64a7afa7949cd24e71b8d8', ...])` to read a historical "go-red control" fixture.
  Reproduced empirically: a `--depth 1` shallow clone of this repo does not have that commit's tree
  reachable (`fatal: path '...' exists on disk, but not in '{sha}'`), and since the read had no
  try/catch, the exception crashes the whole file at `require()` time — a whole-file `node --test`
  failure, exactly the reported symptom. Fixed: the git-show read is now guarded in try/catch; on
  failure only the one go-red-control test that needs it is skipped (with a stated reason) instead
  of crashing the file. Verified: unchanged pass behavior in a full-history checkout (10/10 across
  the two fixed files, 20/20 across all three); a `--depth 1` clone now degrades to a skip instead
  of a whole-file crash.

## Technical Approach

Needs an actual sandbox (root-privileged, or a plugin cache provisioned with a different/absent Impeccable version) to reproduce — not reproducible from this checkout alone. Once reproduced, `tests/impeccable-plugin-contract.test.js`'s fix path likely means reading the installed plugin version dynamically (rather than a hardcoded pin) or fixing the sandbox's own plugin-provisioning step; the two whole-file failures need their actual cause identified before a fix direction can be proposed at all.
