# 2728: Sequential skill re-invocation re-injects the whole SKILL.md verbatim even when the harness states it's already loaded

Surface: infra

Origin: by:feedback (self-referential session evaluation, /claude-tweaks:feedback bare invocation)

**Related:** #2722

## Current State

When the same skill is invoked twice in one session, the harness itself annotates the second invocation as a re-invocation ("the skill instructions were previously loaded") — but the full `SKILL.md` body is still injected a second time, byte-identical to the first. In a session on 2026-09-20/21, `/claude-tweaks:backlog` and `/claude-tweaks:feedback` were each invoked twice; each second invocation carried the harness's own "previously loaded" annotation immediately followed by a full re-injection of that skill's `SKILL.md` (over 26KB and 35KB respectively). Separately, a reference doc citation in `_shared/pipeline-run-dir.md` names "the `resolve-run-dir` CLI" (confirmed: line 3's introductory sentence) without spelling its actual invocation form (`node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" resolve-run-dir`, confirmed present only later, at line 14's "Resolving it" section) — which led to guessing a nonexistent `bin/resolve-run-dir.js` path; recovering required reading that file's full ~24KB body to find the one line documenting the real invocation.

## Deliverables

- On a harness-flagged re-invocation of a skill already resident in context, consider whether the citing convention (or the harness's own skill-loading behavior, if within this plugin's control) can inject only the frontmatter/args block rather than the full body a second time.
- In `_shared/pipeline-run-dir.md` (and any other `_shared` doc that names a CLI by an informal label), spell the exact invocation form at first mention, not just in a "Resolving it" subsection a reader may not reach before guessing.

## Acceptance Criteria

- A second same-session invocation of a skill the harness has already flagged as previously-loaded does not re-inject that skill's full body content.
- `_shared/pipeline-run-dir.md`'s first mention of `resolve-run-dir` names its real invocation form (`node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" resolve-run-dir`), so a reader does not need to reach the "Resolving it" section to avoid guessing a standalone script path.

## Release Note

Reduced the context cost of invoking a skill that is already loaded.

## Technical Approach

The two deliverables have very different scope. The doc-citation fix (second deliverable, second AC) is small and mechanical: edit `_shared/pipeline-run-dir.md`'s line 3 introductory sentence to name the actual invocation form (`node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" resolve-run-dir`) inline, rather than only "the `resolve-run-dir` CLI reference" — the same fix applies to any other `_shared` doc found to name a CLI informally at first mention without its invocation form. The first deliverable (skill re-injection) is a harness-behavior question, not necessarily something this plugin's own skill files can fix directly — if the harness's re-injection is structural (outside plugin control), the resolution may be "document the constraint and accept it" rather than a code change; if there IS a citing-convention lever within this plugin's control (e.g. a skill noting "if already loaded this session, skip to section X" rather than relying on the harness alone), evaluate that instead. Treat the first AC as satisfied by either a real behavior change or an explicit, justified determination that none is possible within this plugin's control.

### Key Files

- `plugin/skills/_shared/pipeline-run-dir.md` — line 3's informal `resolve-run-dir` mention, to be updated with the real invocation form
- Other `_shared/*.md` files — sweep for the same "names a CLI informally at first mention" pattern while addressing this record, per the Deliverables' own "and any other `_shared` doc" scope

## Gotchas

- The first deliverable is explicitly hedged ("if within this plugin's control") — a build that concludes the harness's re-injection behavior isn't something this plugin's skill files can influence should document that conclusion and its reasoning, not force an ineffective workaround just to show activity on the AC.
- Don't conflate this record's doc-citation fix with #2722's broader lazy-load/context-overhead work (Related) — this record's second deliverable is narrowly about naming an invocation form at first mention, not about splitting or restructuring the file's sections.
