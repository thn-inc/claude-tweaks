# 2722: backlog refine: several large _shared reference docs load in full when only a fraction of their branches apply to a given invocation

Surface: infra

Origin: by:feedback (self-referential session evaluation, /claude-tweaks:feedback bare invocation)

**Related:** #2728

## Current State

Executing `/claude-tweaks:backlog refine` end to end (both its `#N`-filtered and whole-queue forms) in a single session on 2026-09-20 required reading several large `_shared`/skill reference files in full — `refine-lanes.md` (457 lines, confirmed: Resolve, Re-authorize, Grant, Flag-back, Needs-decision, Priority, Dependency-repair, and Needs-you lane templates), `_shared/worktree-setup.md` (296 lines, confirmed: Pre-creation reconcile, Post-creation catch-up, Pre-flight divergence check, and several Windows-specific and headless-ride-along subsections), and `_shared/pipeline-run-dir.md` (288 lines, confirmed: the full Anchoring section including the CLI-argument-boundary guard family, most of which applies to callers other than a standalone `/backlog refine` run). In the narrower `#N`-filtered invocation, only the Priority lane's own rendering rules and the plain worktree fetch+merge ever executed — the Resolve/Grant/Flag-back/Needs-decision templates, the Windows long-path recovery procedure, and the CLI-argument-boundary guard descriptions were all read but never exercised.

## Deliverables

- Where a lazy-loaded sub-file already documents multiple mutually-exclusive branches (as `refine-lanes.md` does per-lane), consider whether a citing skill step can name which branch(es) apply to the resolved invocation shape *before* the read, so a reader can skip straight to the relevant section rather than reading start-to-finish.
- For `_shared/worktree-setup.md` and `_shared/pipeline-run-dir.md` specifically, evaluate whether the Windows-specific recovery procedures and the CLI-argument-boundary guard family (relevant mainly to `bin/*.js` authors, not to a skill-following session) could split into their own sub-files, following the same lazy-load discipline already applied elsewhere in this plugin.

## Acceptance Criteria

- A `/claude-tweaks:backlog refine #N` invocation touching only the Priority lane no longer requires reading Resolve/Grant/Flag-back/Needs-decision lane templates in full to reach the one section it needs.
- Total bytes read from `_shared/worktree-setup.md` and `_shared/pipeline-run-dir.md` during an ordinary worktree-creation catch-up drop measurably versus today's full-file reads, without losing any content a citing skill still needs.

## Release Note

Reduced how much reference material backlog refine loads when only part of it applies.

## Technical Approach

Both deliverables are evaluation tasks first, not a locked-in split — this record's own Acceptance Criteria are measurable outcomes (reduced reads for the common case), not a specific file-split mechanism, so the actual resolution should be judged against those outcomes rather than assumed up front. For `refine-lanes.md`: the citing step in `refine-mode.md` already knows, per invocation shape (`#N`-filtered vs. whole-queue), which lanes it will actually reach — the fix is likely a scoping note at the citation point ("this invocation only reaches the Priority lane section below") rather than restructuring the lane file itself, since the lanes genuinely are mutually exclusive per-record but the file as a whole still needs all of them documented somewhere. For `_shared/worktree-setup.md`/`_shared/pipeline-run-dir.md`: this is the kind of cross-referenced `_shared` file split the `shared-contract-extraction` skill exists to guide — read it before extracting anything, since a shared contract file has multiple citers whose own cross-references must keep resolving after any split.

### Key Files

- `plugin/skills/backlog/refine-lanes.md` — the 457-line lane-template file; candidate for a citation-site scoping note rather than a structural split
- `plugin/skills/backlog/refine-mode.md` — the citing step that already knows which lane(s) a given invocation shape reaches
- `plugin/skills/_shared/worktree-setup.md` — candidate for splitting out the Windows-specific recovery procedure into its own lazily-loaded sub-file
- `plugin/skills/_shared/pipeline-run-dir.md` — candidate for splitting out the CLI-argument-boundary guard family (relevant to `bin/*.js` authors, not most skill-following sessions) into its own sub-file

## Gotchas

- Any actual file split must follow the `shared-contract-extraction` skill's consumer-list derivation and citation-sweep discipline — a `_shared` file with multiple citers is exactly the shape that skill exists to migrate safely; splitting ad hoc risks stranding a citation that expected the content inline.
- The Deliverables are deliberately non-committal ("consider," "evaluate") — a build should treat "we evaluated and decided a split isn't worth it, here's why" as a legitimate resolution too, provided the Acceptance Criteria's measured-reduction goal is still met by some other means (e.g. the citation-scoping note alone, without any file split, may already satisfy the `refine-lanes.md` AC).
