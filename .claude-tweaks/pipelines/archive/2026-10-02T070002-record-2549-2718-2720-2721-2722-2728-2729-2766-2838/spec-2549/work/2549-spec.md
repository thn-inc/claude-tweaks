# 2549: log-decision.js: --section "/reflect" is MSYS-path-mangled into "## C:/Program Files/Git/reflect" under Git Bash

Surface: terminal

## Current State

`plugin/bin/log-decision.js` parses `--section` via a plain positional grab (`parseArgs`, `bin/log-decision.js:16-29`: `else if (a === '--section') o.section = next();`) with no validation or normalization of the resulting string. `plugin/bin/lib/log-decision/append.js:116-134`'s `appendEntry` uses that raw value directly to build the `decisions.md` heading (`const heading = \`## ${section}\`;`, line 134).

Under Git Bash (MSYS) on Windows with `MSYS_NO_PATHCONV` unset, MSYS's automatic path-conversion rewrites any argument that looks like a Unix absolute path (a leading `/`) into a Windows path before Node ever sees it — `--section "/reflect"` arrives at `log-decision.js` as `--section "C:/Program Files/Git/reflect"`, and the resulting heading written to `decisions.md` reads `## C:/Program Files/Git/reflect` instead of `## /reflect`. The record's own report observed this corrupting both a `/reflect` and a `/wrap-up` section header in one session, repaired by hand; 3 of the observed session's 4 `log-decision.js` call sites had separately worked around it by exporting `MSYS_NO_PATHCONV=1` first, and 1 had not.

`plugin/skills/_shared/auto-decision-log.md` is the canonical, single-source-of-truth doc for this CLI's signature (line 61: `` `bin/log-decision.js --run <run-dir> --status <STATUS> ... [--section "/<skill>"]` ``) and its invocation templates (lines 162, 189: `--section "/{skill-name}"`). At least a dozen skill files across the repo cite `--section "/{skill}"` literally (confirmed via grep: `wrap-up/cleanup-procedures-execution.md`, `backlog/refine-lanes.md`, `backlog/refine-record.md`, `dispatch/settle-and-merge.md`, `release/bookkeeping.md`, `release/SKILL.md`, `release/execute.md`, `_shared/local-merge-auto-finish.md`, `_shared/git-discipline.md`, `_shared/pr-early-run-lifecycle.md`, `build/micro-plan.md`, `build/dispatch.md`, `build/design-prebuild.md`, `build/architecture-alignment.md`, and others) — every one of these is a live Windows-Git-Bash exposure today, and none of the surveyed skill text mentions `MSYS_NO_PATHCONV`.

## Deliverables

1. In `bin/log-decision.js`'s argument handling (or a normalization step in `bin/lib/log-decision/append.js` before the heading is built), detect and reverse the MSYS path-mangling pattern: a `--section` value matching `^[A-Za-z]:/.*?/Git/(.+)$` is normalized back to `/$1` before use.
2. Accept a bare `--section reflect` (no leading slash) as equivalent to `--section /reflect`, adding the slash internally — this gives every future call site an option that MSYS's path-conversion cannot mangle in the first place, since it never resembles an absolute path.
3. Add one Windows-invocation note to `plugin/skills/_shared/auto-decision-log.md` (its own canonical-source-of-truth status makes it the right single home, per this file's own citation convention — no new file needed) documenting the `MSYS_NO_PATHCONV=1` workaround and/or the no-leading-slash form, that every `log-decision.js`-citing skill can link to rather than restating.
4. Existing call sites are not required to change their `--section "/{skill}"` form (the CLI-side fix in Deliverable 1 protects them even if mangled), but this deliverable does not preclude migrating call sites to the slash-free form later as a separate, lower-priority cleanup.

## Acceptance Criteria

- `node bin/log-decision.js --run <dir> --status AUTO --section "C:/Program Files/Git/reflect" --text "x"` writes a `## /reflect` heading to `decisions.md`, not `## C:/Program Files/Git/reflect` — verified by a unit test simulating the MSYS-mangled input string directly (no actual Windows/Git-Bash environment needed to test the string-normalization logic).
- `node bin/log-decision.js --run <dir> --status AUTO --section "reflect" --text "x"` (no leading slash) writes the same `## /reflect` heading, verified by a unit test.
- `node bin/log-decision.js --run <dir> --status AUTO --section "/reflect" --text "x"` (the normal, unmangled case) continues to write `## /reflect` exactly as before — no regression on the common case, verified by re-running (or confirming still-passing) any existing test covering this path.
- A `--section` value that does not match the MSYS-mangled pattern and does not start with `/` is still treated as the slash-free form (Deliverable 2) rather than being rejected or double-slashed — verified by a unit test on a plain `--section wrap-up` style value.
- `plugin/skills/_shared/auto-decision-log.md` documents the `MSYS_NO_PATHCONV=1` workaround (or the no-slash calling form) in a location every existing `--section "/{skill}"`-citing skill can reference.
- `npm test` passes in full after the change.

## Release Note

Fixed decision log headings being mangled into Windows paths under Git Bash.

## Technical Approach

Add a small normalization function in `bin/lib/log-decision/append.js` (or `bin/log-decision.js`'s `parseArgs`, whichever this repo's existing convention for CLI-argument normalization favors — check `gh-api-module-pattern`'s CLI wrapper contract for where similar normalization already lives in sibling CLIs) that: first checks the MSYS-mangled pattern `^[A-Za-z]:/.*?/Git/(.+)$` and rewrites to `/$1` if matched; otherwise, if the value doesn't already start with `/`, prepends `/`. Apply this normalization once, before `appendEntry` builds the heading, so both the CLI's own direct callers and any future caller benefit without needing to know about the MSYS quirk.

Add the Windows-invocation note to `_shared/auto-decision-log.md`'s existing structure — likely near the "Append protocol" section (`auto-decision-log.md:170`) or alongside the CLI signature itself (line 61), whichever reads more naturally as the note a skill author encountering the `--section "/<skill>"` citation would actually see. State the two mitigations plainly: export `MSYS_NO_PATHCONV=1` before invoking, or omit the leading slash and let the CLI add it.

### Key Files

- `plugin/bin/log-decision.js` — `parseArgs` (lines 16-29): confirm whether normalization belongs here or in `append.js`.
- `plugin/bin/lib/log-decision/append.js` — `appendEntry` (lines 116-134): apply the normalization to `section` before building the heading (line 134).
- `plugin/skills/_shared/auto-decision-log.md` — add the Windows-invocation note (near line 61's CLI signature or line 170's Append protocol section).
- Any `tests/` file covering `bin/log-decision.js` or `bin/lib/log-decision/append.js` — add the new normalization test cases (MSYS-mangled input, slash-free input, already-correct input).

## Gotchas

- The MSYS-mangling regex (`^[A-Za-z]:/.*?/Git/(.+)$`) is specific to Git for Windows' typical install path shape (`C:/Program Files/Git/...`); a non-default Git for Windows install location, or a different MSYS-based shell, could mangle the path differently and not match this exact pattern. The slash-free calling form (Deliverable 2) is the more robust long-term fix since it sidesteps MSYS path-conversion entirely rather than trying to reverse every possible mangled shape; document this as the recommended form going forward even though the regex fix is still needed to repair existing call sites' literal `"/skill"` citations.
- Only `log-decision.js`'s `--section` flag is addressed here — the record's own "Affected component" line also names "every skill that cites a CLI with slash-prefixed arguments on Windows" as a broader category; other CLIs with similar leading-slash arguments are out of scope for this record unless a specific instance is identified — don't scope-creep this fix into an audit of every CLI flag in the plugin.
- The fix must not double-prepend a slash on a value that already starts with `/` (the normal case) — the normalization order (check MSYS-mangled pattern first, then check for missing leading slash) must handle "already correct" as a no-op, not accidentally produce `//reflect`.
