# 2729: backlog refine's closing-summary tally is hand-composed and can disagree with its own decisions.md audit trail

Surface: backend

## Current State

`refine-closing-summary.md` documents that the closing tally line is derived by "counting these lines by type" from the run's own `decisions.md` log. In a session on 2026-09-20, a whole-queue `/claude-tweaks:backlog refine` run's rendered closing summary stated "40 priority set (19 this run + this batch) · 3 Related updated · ... · 3 collision-reconciled · 0 failed" — but the run's own `decisions.md` contains exactly 19 `refine #N` priority-set entries, and the surrounding table in the same message lists exactly 19 records. The "40" figure conflated the count of labels resolved by this run's writes with the size of a different, 40-record population (the grant-check candidates, none of which this run actually wrote a priority label to — those already carried one from a concurrent actor). `collision-reconciled` is also not one of `refine-closing-summary.md`'s enumerated tally fields — confirmed absent from the current skill prose (`grep -rn "collision-reconciled" plugin/` returns no hits). Separately, a later closing message for that same skill stated "writing the watermark" as an action about to be taken, when the only subsequent action was deleting scratch files — the session-evaluation self-assessment path never writes a watermark by design, so the claim was never going to be backed by an actual write.

## Deliverables

- Add a small mechanical helper (a `hooks.js` subcommand, or extend `bin/log-decision.js`'s sibling tooling) that derives a refine run's closing tally directly from its own `decisions.md` entries by type, so the rendered summary cannot state a count its own audit trail doesn't support.
- Constrain the closing summary's tally vocabulary to `refine-closing-summary.md`'s enumerated fields only (or document `collision-reconciled` there if it's a legitimate addition worth keeping).
- Where a skill step is about to state a specific action in its closing text ("writing the watermark," "closing the run"), require that the action actually execute (or the claim be omitted) before that sentence renders — particularly relevant for the self-assessment degradation path, which by design skips several actions a dispatched-judge path would take.

## Acceptance Criteria

- A `/claude-tweaks:backlog refine` closing tally, run against a fixture `decisions.md`, matches a mechanical count of that file's own entries by type.
- No closing-summary tally field appears outside `refine-closing-summary.md`'s documented vocabulary without that file being updated first.

## Release Note

Made backlog refine's closing tally come from its own decision log so the two can never disagree.

## Technical Approach

Add a small CLI helper — a new `hooks.js` subcommand, or a function alongside `bin/log-decision.js`'s existing `decisions.md` write path — that reads a run's `decisions.md`, classifies each line against the exact per-type templates `refine-closing-summary.md` already documents (`AUTO … set priority:…`, `AUTO … updated **Related:**…`, `AUTO … granted auto:build…`, `AUTO … flagged back…`, `AUTO … repaired dependency…`, `AUTO … stamped needs:decision…`, `AUTO … skipped …`, `FAILED …`), and prints the per-type counts in the documented tally-line format. `refine-mode.md`'s Step 5 (the closing-summary render `refine-closing-summary.md` specifies) then shells out to this helper to produce the tally line, rather than composing it from memory — turning the file's existing "no second bookkeeping channel" intent from a prose convention into an actual mechanical check. Constrain the per-type vocabulary to exactly the eight fields `refine-closing-summary.md` already documents (`priority set`, `Related updated`, `granted`, `flagged back`, `dependency-repair`, `needs-decision`, `skipped`, `failed`) — the helper's own classifier is the enforcement point: a line matching none of the eight templates should surface as a visible warning in the helper's own output rather than being silently dropped or letting the caller invent an unlisted field name. Separately, at each closing-text call site that states a specific about-to-happen action ("writing the watermark," "closing the run"), require the corresponding write call's own exit code to confirm success before that sentence renders, or omit the sentence when it didn't run.

### Key Files

- `plugin/skills/backlog/refine-closing-summary.md` — documents the tally vocabulary and the "counts these lines by type" convention; needs a pointer to the new mechanical helper once it exists
- `plugin/bin/log-decision.js` — candidate location for the new tally-derivation function, since it already owns the `decisions.md` write path this helper reads
- `plugin/skills/backlog/refine-mode.md` — Step 5's closing-summary render is the call site that needs to shell out to the new helper instead of hand-composing the tally

## Gotchas

- The fixture-based acceptance test needs a `decisions.md` fixture covering every one of the eight documented line types plus at least one malformed/unclassified line, to prove the helper's classifier doesn't silently drop or miscount lines it doesn't recognize.
- `collision-reconciled` (the extra field seen in the cited incident) does not appear anywhere in this repo's current skill prose (verified by grep) — this fix either needs to retire that phrase entirely from future renders, or document it in `refine-closing-summary.md` if a maintainer decides it's a legitimate addition; the Deliverables above leave that as an open documentation choice, not a foregone one.
