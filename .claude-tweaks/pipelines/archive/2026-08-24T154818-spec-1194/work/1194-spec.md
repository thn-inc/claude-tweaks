# 1194: demo: cli-surface Observation plan for a decomposed sub-issue skips end-to-end manual verification guidance

Surface: backend

## Overview

For a sub-issue that is one slice of a decomposed feature whose user-facing behavior only exists once later siblings ship (the repro: an early backend/data-layer slice of a webhook-driven pipeline), `/claude-tweaks:demo #N` renders an Observation plan that is correct for the slice — `Surface: cli`, `Entry point: {the record's scoped test command}` — and silent about the fact that it is a slice: nothing says end-to-end verification is not yet possible, which sibling records gate it, or what the eventual check looks like.

The cause is structural, not a missing sentence. `wrap-up/verification-brief.md`'s Routing sends every parent-linked sub-issue to the Parent-Gate Procedure in place of Steps 1-4, so a decomposed sub-issue never gets a wrap-up brief or `demo:pending` — its parent gets one gate once every sibling has closed. `/demo #N` on an early slice therefore always resolves through `demo/entry-paths.md`'s `#N`-branch fallbacks (closing-commit reconstruction, or `#N`-scoped session-recall), and neither composer knows the record is a sub-issue of anything. The "end-to-end verification lands on the parent" concept already exists (the parent brief's inline walkthrough, `parentGateState`'s `incomplete`/`due`, `needsBackstop` skipping `hasParent` records); what is missing is a forward pointer from the sub-issue's own plan to it.

This record adds that pointer as an optional `Full verification:` block on the Observation plan schema, composed by `/demo`'s two `#N`-branch composers from live parent/sibling state at demo time. The parent brief and wrap-up's Routing are untouched.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- A parentless Step 2.6 collapse (at most 2 units, `Blocked by` edges, no parent). Those records already get their own wrap-up brief and the dependency is one visible body line; pointing a blocker at its dependents would need a reverse `blockedBy` lookup and a different target. Revisit only if it bites.
- Any change to `wrap-up/verification-brief.md`'s Routing, to Step 2's plan authoring, or to the parent brief's inline walkthrough (`verification-brief-parent-gate.md`).
- Widening `/demo` to the parent's scope when `#N` is a sub-issue, or any change to its one-item-at-a-time contract. The parent has no brief until its gate is `due`, the end-to-end check cannot run while siblings are unshipped, and a verdict on the parent would have nowhere to land.
- A `Blocked-by:` line in the Observation plan. `Blocked by #N` is the parsed dependency-edge vocabulary (`record.js`'s `DEP_RE`, `_shared/work-record.md`'s Decomposition rules); the same words in a plan would read as an edge.
- Any change to `verificationSurface` (`bin/lib/issues/acceptance.js`) — it stays the floor classifier for the reconstruction path, unmodified.
- Multi-level decomposition. The block names the record's **immediate** parent only and lists that parent's direct sub-issues; a parent that is itself a sub-issue of a grandparent is not walked upward. `/specify` produces one level (`_shared/work-record.md`'s Decomposition rules — sub-issues link to one parent; tasks never become records), so this is the only shape the system creates.

## Technical Approach

The Observation plan gains one optional block that only a parent-linked sub-issue's plan carries. Every input it needs is already resolvable at demo time, and sibling open/closed state is live then — fresher than anything wrap-up could have written at build time, which is why the block is composed by `/demo` rather than posted by wrap-up. The two composers that can ever see a parent-linked record are both in `demo/entry-paths.md`'s `#N` branch; the label-backed `demo:pending` path is unreachable for such a record by Routing, and the no-argument session-recall path has no record to resolve a parent from.

### Data / API Surface

Schema addition (`plugin/skills/_shared/observation-plan.md`):

```markdown
- Full verification: {present only on a parent-linked sub-issue}
  - Parent: #P {parent title}
  - Pending: #X {title} (open), #Y {title} (open)
  - Then: {one line — what a human triggers and observes once every sibling ships}
```

`Pending:` alternative form when no sibling is open: `none — every sibling closed; parent gate {due|gated|resolved}`.

Helper (`bin/lib/issues/record.js`):

```js
// candidate sub-issue numbers -> one batched, aliased GraphQL query requesting each
// issue's native parent (work-links: native), read from the sub-issue's own side.
function buildNativeParentQuery(numbers) {
  if (!Array.isArray(numbers) || numbers.length === 0) return null;
  const fields = numbers
    .map((n) => `i${n}: issue(number:${n}){ number parent{ number title state } }`)
    .join('\n      ');
  return `query($owner:String!,$repo:String!){\n  repository(owner:$owner,name:$repo){\n      ${fields}\n  }\n}`;
}
```

`/demo` runs it as `gh api graphql -F owner='{owner}' -F repo='{repo}' -f query="$(node -e "…buildNativeParentQuery([N])…")"` — `-F` for the resolved owner/repo values, `-f` for the query string (the repo's `gh-api-module-pattern` skill states the `-f`/`-F` split).

## Gotchas

- The GraphQL field name for a sub-issue's parent (`parent`) was probed live on this repo at shaping time — see Current State for the exact request and both responses (a real parent, and `null` on a parentless record). The helper's header comment records that shape; no re-probe is needed, but if GitHub renames the field the helper's own test is the tripwire, not a prose claim.
- `gh api graphql` value mechanics: `-F` substitutes typed/resolved values (`owner`, `repo`, `n`), `-f` passes a raw string (the query). Do not put `{owner}`/`{repo}` placeholders inside `-f` values — they are only substituted on REST paths.
- `deriveSlug`/fingerprint discipline is irrelevant here (no new record is created), but the body carries this record's own `work-fingerprint` so a resumed `/specify` run resolves it — do not strip the marker.
- Never write the literal placeholder tokens the spec-shaped-body check greps for into skill prose; paraphrase ("an unresolved marker").
- The block is a *pointer*, not a walkthrough: `Then:` is one line. The parent brief's Compose part 2 (in `verification-brief-parent-gate.md`) remains the only place a full end-to-end walkthrough is authored.
- `Pending:` excludes the record in hand — a reconstruction runs on a closed record, but a session-recall entry may run on one still open; either way the record being demoed is never listed as pending against itself.
- Fail open *visibly*: `/demo` has no run directory and no `decisions.md`, so a silent omission is indistinguishable from "no parent". The one-line trace above the verdict is the only signal — the same reason `_shared/design-contract.md`'s malformed case takes that shape.
- Byte-budget: `plugin/skills/demo/SKILL.md` is ~30 KB and `entry-paths.md` ~14 KB against the 40 KB per-skill-file ceiling (`tests/bin-lib/skill-audit/context-cost.test.js`). Keep the SKILL.md addition to a few lines; the sub-procedure's bulk belongs in `entry-paths.md`.
- Physical file overlap (from `/specify`'s implicit-dependency detection, sections disjoint, no `Blocked by` wired): `record.js` is also touched by open #1309 and #1224 (append the helper next to `buildNativeSubIssuesQuery`; do not reorder exports); `demo/SKILL.md` by #807 (Step 4), #806 (Prepare/Validate), #762 (Input grammar), #1208 (Show's browser path); `docs/skill-graph.md` by #1187. Merge-conflict risk is line-local; re-read those files at build start.
- Prose-conformance suites in this repo read live skill text — an assertion must be proved red by reverting the prose it pins, not by asserting on a fixture that mirrors it (`skill-prose-conformance-tests` skill; IL-80).

## Decision Rationale

Approach A (schema block, composed at demo time) was chosen over two alternatives named in the origin record and the brainstorm: **B — widen `/demo` to the parent's scope** when `#N` is a sub-issue with open siblings, rejected because the parent has no brief until its gate is `due`, the end-to-end check cannot run while siblings are unshipped, and it breaks both `/demo`'s one-item contract and the one-gate-per-parent invariant — the human would get a walkthrough they cannot execute and a verdict with nowhere to land; **C — wrap-up posts a label-free sub-issue brief carrying the pointer**, rejected because sibling state goes stale the moment it is posted, `/demo`'s `#N` lookup keys on `demo:pending` so the brief would not be found without a second contract change, and it reintroduces the per-sub-issue ceremony the Routing rule exists to avoid. The block is named `Full verification`, not `Blocked-by:`, because `Blocked by #N` is already parsed dependency-edge vocabulary. Scope is parent-linked sub-issues only; the parentless collapse case is a stated non-goal, not an oversight.
