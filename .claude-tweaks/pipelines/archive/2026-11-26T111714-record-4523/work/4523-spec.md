# 4523: Anchor HARNESS_ISOLATION_REFUSAL_RE so quoted refusal text in command output stops logging a false event

Origin: ledger resolve gate (#3819 ledger item 3)

Defer-reason: genuinely-larger

## Current State

`HARNESS_ISOLATION_REFUSAL_RE` in `plugin/bin/lib/hooks/harness-refusal.js` has no start anchor, so a failed Bash command whose output merely quotes refusal text (a failing test fixture is the usual case) logs a false `wd-guard-refusal` event. The defect predates #3819; its widening to the agent-noun and worktree-gone signatures slightly enlarges the surface (final whole-branch review, minor 6). Anchoring at `^` is only safe if the hook's `error` always begins with the noun, which the 2026-10-28 agent probe confirmed for the agent template; the session and worktree-gone templates have not been measured.

**Related:** #4524, #4525

## Deliverables

- [ ] Measure, with a headless probe like the one #3819 used, whether `error` begins with the noun for the session and worktree-gone templates, and record the result in `tools/upstream-drift/manifest.yml`.
- [ ] Anchor the pattern at the start of `error` if all three begin with the noun; otherwise bound the match another way and say why.
- [ ] Keep `bash-prefilter.js`'s signature check consistent with the matcher.

## Acceptance Criteria

A test passes a failed-command `error` that quotes a refusal in the middle of its text and expects no `wd-guard-refusal` event.

The existing tests for the session, agent and worktree-gone refusals still pass.

`npm test` passes.

## Decisions

**Decision** — plan-review Question 1 (2026-11-26, maintainer-authorized autonomous lane): Reading B. Anchor `HARNESS_ISOLATION_REFUSAL_RE` at the start of `error` (`^`, without the `m` flag). Three things count as enough evidence for the two templates a headless probe cannot provoke: each is a noun-first template literal in the binary, the probe measured that the shared shell-error wrapper adds no prefix on the worktree-gone path, and the probe measured both reachable templates as noun-first on Claude Code 2.1.325. Record that inference and the measured version in the `claude-code` comment of `tools/upstream-drift/manifest.yml`, so a later template change shows up as drift. Rejected: Reading A's line-start anchor (`^` with `m`). The `error` field carries the failed command's own output, so a line of output that begins with the refusal text would still match, and that is the false positive this record exists to remove. Provoking the hub-only template interactively first is not worth it here: if an untriggered template ever gained a prefix, the cost is an under-counted friction metric, not a broken session, and the drift comment covers that risk.

**Decision** — the plan's Tasks 1 and 2 carry `**Review risk:** high`, because they change a protected hook path (`harness-refusal.js`, `bash-prefilter.js`).

**Decision** — Task 2 also updates the Bash prefilter bullet at `docs/hooks.md:25` so it describes the anchored signature check.
