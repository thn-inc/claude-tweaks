# 5957: Keep the station-event log from dirtying a project's main checkout

Origin: v6.175.0 release-gate review (run 2026-11-19T124921-release-standalone) (3e)

Defer-reason: genuinely-larger

## Current State

Since #5902, station-event producers append to `.claude-tweaks/station-events.jsonl`, behind a sibling `station-events.jsonl.lock`, in the main checkout of whatever project runs the plugin (`plugin/bin/lib/station-events/emit.js:123-125`).

This repo ignores both paths in its own `.gitignore`. A consumer project is protected only by `/init`'s `step-04-gitignore-suggestions.md` row, which reaches it only when someone re-runs `/claude-tweaks:init`. Nothing in code ignores or relocates the file at runtime.

Until then the file is untracked in that checkout. `plugin/bin/lib/reconcile/classify.js:36` runs `git status --porcelain`, which counts untracked files, so mirror reads the checkout as dirty, its fast-forward never runs, and archiving on the integration branch stalls at `local-behind-merge`. That is the failure #4387 recorded for `reconcile-cache.json`, which has the same init-row-only protection.

Found by the v6.175.0 release-gate whole-branch review (lens 3e; confirmed by tiebreak a5e9ec784c19 at high). refs #5902

## Deliverables

Make the station-event log unable to dirty a project's main checkout without a manual `/init` re-run: write it (and its lock) under the git common dir, as the test-impact refresh marker does, or ensure-ignore it at write time. Pick one and record why in `docs/reference/station-events.md`.

If the path moves, migrate every reader (`driver-mirror.js`, `docs/reference/station-events.md`, the `/init` step-04 row) by expand-contract, so a run in flight on the previous release still finds its log.

A test that appends a station event in a fixture repo with no station-events ignore rule and asserts `git status --porcelain` stays empty.

## Acceptance Criteria

In a fixture repo whose `.gitignore` has no station-events entry, `appendStationEvent` leaves `git status --porcelain` empty.

Every reader of the station-event log finds it at its new home, or at both homes during the expand phase.

reconcile's mirror classifies a checkout as clean after producers have run in it.

## Release Note

Station events no longer leave an untracked file in a project's main checkout, so archiving no longer stalls in a project that has not re-run /claude-tweaks:init.

## Plan Review Clarifications

Decided by the user at plan review: keep only the untracked case in scope (Reading A). `info/exclude` hides an untracked file only, so a log already tracked in a project's index would still dirty its checkout. None can exist: #5902's emitters are unreleased (`git tag --contains abcfed6e06` prints nothing), and each append writes the exclude entry before its first line. The acceptance criteria stand as written, and `docs/reference/station-events.md` records the tracked-file limit and why it cannot arise.
