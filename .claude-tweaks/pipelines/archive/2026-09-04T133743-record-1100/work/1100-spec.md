- `docs/incident-log.md` — the `[IL-nn]` post-mortem home; the spec-315 stomp (2026-08-19/20) has no entry. `docs/donts.md` — the rule list; CLAUDE.md's Don'ts section explains the rule+tag format.

- [ ] **Checkpoint (first task, blocking):** re-derive the ownership contract's specifics — the predicate's exact verdict names and count, the resolution order, the message wording — from the **merged code** of #1012 and #1099 (`git log`/diff of their landed commits), not from this record's paraphrase. Where the shipped shape differs from the enumerations below, the shipped shape wins and this record's wording is corrected in the same pass.
- [ ] `docs/hooks.md`: an "Ownership" section — the composite identity contract (`{ sessionId, worktree }` vs `{ CLAUDE_CODE_SESSION_ID, cwd }`), the `classifyOwnership` verdicts as shipped, the unambiguous-only implicit resolution order for mutating verbs, the explicit-`--run` override semantics, and the measured fact, which MUST include this exact sentence (AC1 checks for it literally): *`CLAUDE_CODE_SESSION_ID` is shared across all subagents of a session (observed 2026-08-20 via the #965 probe, recorded in parent #1096 — scope: Task-tool subagents of an interactive session; re-verify before extending the claim to cloud Routines or headless runs, and re-verify if harness session handling changes); it identifies the session, never the agent; no ownership decision may treat its equality as sufficient.*
- [ ] `docs/incident-log.md`: an entry for the spec-315 stomp — which build it bit (the 2026-08-19/20 10-record parallel dispatch; spec-315's run-state overwritten three times by three sibling worktrees via `close-run --help` fall-through), how it was caught (each offending agent's own events.jsonl/PR-state vigilance, not a guard), what it cost (manual restoration; enforcement disarmed while `worktree:null` stood) — and the corresponding one-clause rule + tag in `docs/donts.md`. The IL number comes from the log's own sequence at write time.
- [ ] Redirect `classifyOwnership`'s closing doc-comment pointer in `plugin/bin/lib/hooks/context.js` (currently `.claude-tweaks/pipelines/2026-08-20T185022-spec-1098/work/1098-spec.md`, which wrap-up archived to `.claude-tweaks/pipelines/archive/2026-08-20T185022-spec-1098/work/1098-spec.md`) at the new docs/hooks.md Ownership section, keeping one line naming the archived originating spec — staged rationale from #1098's wrap-up: the run-dir path dies on archival while the comment calls it authoritative; nothing else in this record's scope covers a code-side back-reference.
- [ ] Sweep the "always pass `--run`" prose — **in-repo prose only**: `plugin/skills/_shared/pipeline-run-dir.md` and any other skill prose stating the discipline as convention now cites the structural refusal (verbs refuse ambiguous implicit resolution) rather than restating the rule. Grep for `--run` across `plugin/skills/**/*.md` and `docs/**` and update each carrier that asserts the old prose-only posture. (The operator's personal memory store carries similar phrasing but is outside the repo and outside this record's scope — no repo deliverable references it.)

1. `docs/hooks.md`'s new section contains the italic contract sentence from the Deliverables bullet above **literally** (checkable with a plain `grep -F` for its first clause) — that sentence is what makes re-introducing a sessionId-only ownership check contradict the docs.

Tombstone-style exclusion per `plugin/skills/specify/spec-template.md`'s "Delete + Tombstone Acceptance Criteria" section. Write `docs/hooks.md`'s section against the shipped implementations (read the merged code of both blockers first, not the design's wording — the parent's Decision Rationale is the intent record; the code is the behavior record). Keep the donts.md line to rule + one why-clause per that file's format. The prose sweep is a targeted grep-driven edit, not a rewrite: each carrier keeps its own context and gains a one-line citation of the structural guarantee.
