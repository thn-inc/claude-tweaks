## Proposed title

`/test`: migrate qa-prompts.md and qa-procedures.md's live agent-browser auth invocations to playwright-cli session-state

## Current State

`#2681` (this run) migrated the QA-story-authoring path — `plugin/agents/qa-agent.md`, `plugin/skills/stories/auth-resolution.md`, `SKILL.md`, `refine.md`, `story-examples.md` — from `agent-browser`'s credential-vault auth model to `playwright-cli`'s `state-load`/`state-save` session-state persistence.

The `/test qa` orchestrator's own live invocations were outside #2681's declared scope and were NOT migrated:

- `plugin/skills/test/qa-prompts.md` — Phase 3 prompt template (~lines 96-97, ~152): still instructs `agent-browser --session {story.id} auth login <vault-name>`.
- `plugin/skills/test/qa-procedures.md` — Phase 2.5 pre-flight (~lines 99-112): still runs `agent-browser auth list`, tells a story author to run `agent-browser auth save <vault-name> --url <login-url> --username <username> --password <password>` for a missing vault, and instructs `agent-browser --session <story-id> auth login <vault-name>`.
- `plugin/skills/_shared/dev-url-detection.md` (line 28): still references credentials being "saved via `agent-browser auth save`".

Confirmed via `grep -rn agent-browser plugin/skills/test/qa-prompts.md plugin/skills/test/qa-procedures.md plugin/skills/_shared/dev-url-detection.md` against this run's worktree.

This means #2682's stated premise ("once #2670 and #2681 ship, nothing in the plugin calls agent-browser anymore") does not actually hold yet — the `/test qa` production pipeline still depends on agent-browser's auth commands for its own pre-flight and prompt template, independent of the qa-agent.md/stories path #2681 fixed.

## Deliverables

- [ ] Update `plugin/skills/test/qa-prompts.md`'s Phase 3 prompt template to invoke the same `playwright-cli state-load <file>` + `goto <url>` sequence #2681 established in `qa-agent.md`, instead of `agent-browser auth login`.
- [ ] Update `plugin/skills/test/qa-procedures.md`'s Phase 2.5 pre-flight to check for `.claude-tweaks/auth-state/<vault-name>.json` (per #2681's `auth-resolution.md` convention) instead of running `agent-browser auth list`; update the missing-vault warning message to print the new capture procedure instead of `agent-browser auth save`.
- [ ] Update `plugin/skills/_shared/dev-url-detection.md` line 28's credential-storage description to reference the captured session-state file instead of `agent-browser auth save`.
- [ ] Re-run `grep -rn agent-browser plugin/skills/test/ plugin/skills/_shared/dev-url-detection.md` and confirm clean.

## Acceptance Criteria

1. `grep -rn agent-browser plugin/skills/test/qa-prompts.md plugin/skills/test/qa-procedures.md plugin/skills/_shared/dev-url-detection.md` returns no match.
2. `/test qa`'s Phase 2.5 pre-flight and Phase 3 prompt template both resolve auth via a captured `.claude-tweaks/auth-state/<vault-name>.json` file, consistent with #2681's `auth-resolution.md` convention.
3. A manual QA run exercising an auth-gated story through the actual `/test qa` orchestrator (not just `qa-agent.md` directly) passes with no `agent-browser` process ever starting.

## Release Note

Moved QA story authentication to the new browser backend's saved sessions.

## Related

## Technical Approach

Follow #2681's already-established `auth-resolution.md` convention directly rather than inventing a new pattern — the Deliverables checklist above already names the exact three files and their line ranges. Apply the same `playwright-cli state-load <file>` + `goto <url>` sequence #2681 used in `qa-agent.md` to `qa-prompts.md`'s Phase 3 prompt template, and the same `.claude-tweaks/auth-state/<vault-name>.json` check to `qa-procedures.md`'s Phase 2.5 pre-flight, replacing the `agent-browser auth list`/`auth save`/`auth login` invocations named above.

## Gotchas

- Acceptance Criterion 3 requires a manual QA run through the actual `/test qa` orchestrator (not just `qa-agent.md` directly) — don't treat the grep-clean check (AC1) alone as sufficient verification.
- This record's premise is a precondition for #2682 (a related record) — landing this fixes #2682's stated premise gap, so sequencing may matter if #2682 is also in flight.
