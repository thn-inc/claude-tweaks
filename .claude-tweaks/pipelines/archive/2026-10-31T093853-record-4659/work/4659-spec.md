# 4659: Route claim-targets.md tombstone Resume-line parse through the shared parser

Origin: reflect full from #4596

Defer-reason: tangential

## Current State

`plugin/skills/flow/claim-targets.md` (the tombstone-PR path, lines ~263-294) still carries a prose copy of the PR body's `### Resume` line grammar: it tells the agent to read the `### Resume` section, find the exact command line `PIPELINE_RUN_DIR="{run-dir}" /claude-tweaks:flow ...`, and validate the marker by eye.

Record #4596 moved the same grammar into code: `plugin/bin/lib/flow/pr-body.js` exports `resumeLineUnder(body)` (last `### Resume` heading) and `parseResumeLine(line, runId)` (allowlisted dir and target classes, a string `runId` guard, no `..` dir segment), and `plugin/bin/stale-claim-pr.js` prints `resume` only for a line `parseResumeLine` accepts. The tombstone path in `claim-targets.md` is the last prose restatement, so the two can drift (the #4596 review found `RESUME_LINE_RE`'s original denylist passing `!` and C0 control characters, which the prose copy would also accept).

Found by the #4596 whole-branch review; out of that record's two named prose files.

## Deliverables

Route the tombstone-PR `### Resume` read in `plugin/skills/flow/claim-targets.md` through `pr-body.js`'s `resumeLineUnder`/`parseResumeLine` (a small CLI or an existing one such as `stale-claim-pr.js --resume`), so the prose no longer restates the grammar.

Extend the existing conformance test that pins `claim-targets.md` as the only prose copy (`tests/issue-claims-stale-open-pr-conformance.test.js`) so it pins the removal.
