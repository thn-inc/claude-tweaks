# 3130: visual-decide stop exits 0 without writing server-stopped marker when target PID is a zombie

Defer-reason: pre-existing-outside-diff

**Related:** #3027, #3071

## Current State

plugin/bin/lib/visual-decide/cli.js's pidAlive() signals the target PID with kill(pid, 0) to decide liveness. The test kills the server's PID with SIGKILL, waits 300ms, then calls stop. In this sandbox (PID 1 is a Firecracker process_api init, not a standard reaper), the killed child becomes a zombie whose PID still answers kill(pid,0) successfully for longer than 300ms, so pidAlive reports "alive" even though the process is dead. cmdStop then takes the live-process branch: sends SIGTERM (a no-op on a zombie), waits up to 3000ms via waitFor for the server-stopped marker or !pidAlive, times out, and still exits 0 printing "stopped" — but the server-stopped marker file (written only by the server's own SIGTERM handler) never gets created, since the zombie can't run code. Net effect: stop exits 0 with "stopped" but no marker file, violating the stale-PID-tolerance contract the test name describes.

## Deliverables

Either (a) treat a waitFor timeout in cmdStop as cause to also write the server-stopped marker defensively (matching the dead-pid branch's own behavior at cli.js:190-197), or (b) make pidAlive zombie-aware (e.g. checking /proc/{pid}/stat state Z on Linux) so it correctly reports a zombie as not-meaningfully-alive for this CLI's purposes. Re-run the test 3x in this same sandbox type to confirm no regression.

## Acceptance Criteria

- node --test tests/bin-lib/visual-decide/cli.test.js passes reliably (3/3 consecutive runs) in a container without a reaping init (PID 1 not a standard init/tini).
- No change to the already-passing EPERM/ESRCH pidAlive semantics documented at cli.js:48-52.
- Existing stop/status test coverage for the non-zombie dead-PID path (ESRCH) still passes unchanged.

## Release Note

No user-visible change — internal test/CLI reliability fix for the visual-decide stop command in containers without a reaping init.
