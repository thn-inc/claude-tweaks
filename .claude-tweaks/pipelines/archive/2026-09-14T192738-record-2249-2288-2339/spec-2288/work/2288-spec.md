# 2288: browse: agent-browser has no documented color-scheme emulation

Surface: infra

## Current State

`agent-browser` is a third-party tool this plugin depends on optionally (CLAUDE.md's Dependencies
table) — it is not part of this repo's own codebase; `plugin/skills/browse/agent-browser-reference.md`
documents its usage but does not own its implementation. That reference file's documented operation
vocabulary (open, snapshot, find, click, fill, screenshot, vitals, trace, etc.) has no
color-scheme/emulation flag.

Verifying a light-mode-only CSS change in a project whose theming is driven solely by
`prefers-color-scheme` media queries (no in-app toggle) required building a standalone HTML
fixture with the target CSS rules copied in and the desired scheme's token values inlined, opened
via `file://`, instead of driving the live app in the actual scheme under test — a real but
indirect substitute.

Because `agent-browser` is external, this record's scope is bounded by what this repo can
actually change: whether the tool already supports color-scheme emulation through some mechanism
not yet documented here, and if not, formalizing the documented workaround so a future verifier
doesn't have to rediscover it.

## Deliverables

- Investigate whether the installed `agent-browser` version already supports color-scheme
  emulation via an undocumented flag, environment variable, or underlying CDP passthrough (e.g.
  `Emulation.setEmulatedMedia`) — check its own `--help` output and any bundled documentation
  first.
- If a mechanism already exists: document it in `agent-browser-reference.md`'s operation
  vocabulary, with a usage example.
- If no mechanism exists: document the standalone-HTML-fixture workaround (build a minimal
  fixture with the target CSS and the desired scheme's token values inlined, open via `file://`)
  as the recommended pattern in `agent-browser-reference.md`, so a future verifier facing the same
  gap has a documented path instead of reinventing it — and, separately, file feedback against
  `agent-browser` itself (outside this repo) requesting the capability, since this repo cannot add
  a feature to a tool it doesn't own.

## Acceptance Criteria

- `agent-browser-reference.md` documents either (a) a working color-scheme emulation flag/option,
  verified against the actually-installed tool version, or (b) the standalone-fixture workaround
  pattern, clearly labeled as a workaround rather than a native capability.
- Whichever path is documented is validated by actually using it to verify a light-mode-only (or
  dark-mode-only) CSS change against a real project with `prefers-color-scheme`-only theming —
  not merely described in the abstract.
- If no native mechanism exists, upstream feedback is filed against `agent-browser` (outside this
  repo's own issue tracker) requesting the capability, and that filing is referenced from this
  record's closing comment.

## Technical Approach

Run `agent-browser --help` (and any subcommand-specific help, e.g. `agent-browser open --help`)
against the actually-installed version to check for an existing but undocumented emulation
option before assuming none exists — third-party tools frequently expose CDP-passthrough flags
that aren't surfaced in every doc surface. If nothing surfaces, formalize the fixture-based
workaround already used as a real substitute: a minimal standalone HTML file with the target
CSS rules and the desired scheme's computed token values inlined, opened via `agent-browser open
file://<path>`. Document whichever path is real in `agent-browser-reference.md`'s existing
operation-vocabulary section, in the same format as its other documented operations.

### Key Files

## Gotchas
