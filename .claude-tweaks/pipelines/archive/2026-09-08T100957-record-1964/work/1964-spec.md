# 1964: queue-pull-script.md: backtick-quoted next inside a double-quoted node -e string is command-substituted by bash

Defer-reason: tangential

Origin: /claude-tweaks:dispatch --budget all drain, run 2026-09-05T090744-dispatch-standalone (14 groups attempted)

## Current State

dispatch/queue-pull-script.md's size-guard block is a `node -e "..."` double-quoted string containing a JS comment with `next` in markdown backticks. Bash performs command substitution on the backticks, printing `next: command not found` to stderr on every run (observed on all 15 queue pulls this firing). Harmless to the output, but it is noise a headless firing logs every time and a latent hazard if any other backtick token in that block ever names a real command.

## Deliverables

- [ ] Remove backticks from the JS comments inside the double-quoted node -e blocks in queue-pull-script.md (and sweep next-ranking.md and settle-and-merge.md for the same shape).
- [ ] Add a conformance test that greps every `node -e "` block in plugin/skills/**/*.md for a backtick and fails on a hit.

## Acceptance Criteria

1. Running the queue-pull script verbatim produces no `command not found` line on stderr.
2. The new conformance test goes red when a backtick is reintroduced inside a double-quoted node -e block.
