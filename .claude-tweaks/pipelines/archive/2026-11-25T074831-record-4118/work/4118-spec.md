## Current State

`/claude-tweaks:capture`'s Shaped-body branch step 3 files a spec-shaped body as `ready` with `risk:*`/`size:*` labels. It deliberately never passes `ceremony` to `recordPayload` (`plugin/skills/capture/SKILL.md` ~line 305: "this branch never passes those"), because `/claude-tweaks:specify` is the sole owner of `ceremony:*`. So every born-ready capture reaches `/claude-tweaks:flow` unlabelled. `flow/manifesto.md`'s Ceremony profile computation then runs one inline `assess-agent-autonomy ceremony-check` per such record, and `materialize.md` falls back the same way when no Manifesto verdict exists.

This is the common case: release-gate, wrap-up and health-sweep findings filed through `/capture --source …` all take this branch. On 2026-10-24, #4012, #4041 and #4060-#4072 were all filed this way. In `/flow #3898,#4012,#4041` (run 2026-10-24T103516-spec-3898-4012-4041) both fallback calls were wasted. #3898 already carried `ceremony:standard`, so the run-wide AND fold was `standard` before either judgment ran. A per-record verdict only changes behaviour where `build/micro-plan.md`'s gate reads `ceremony: fast-lane` with `size: low`, and #4041 is `size:medium`. The inline call is also where the pipeline stalled (the sibling record on return-to-caller).

## Deliverables

1. Born-ready captures carry a `ceremony:*` label. Either the Shaped-body branch judges it through the canonical `_shared/ceremony-check-invocation.md` pattern and stamps it, which updates `_shared/work-record.md`'s permission matrix so `/capture` co-owns `ceremony:*` on that branch only, or the decision to keep `/specify` as sole owner is recorded with its reason and deliverable 2 alone carries the fix.
2. `flow/manifesto.md`'s Ceremony profile computation skips the per-record judgment when its verdict cannot change anything: the run-wide fold is already `standard` from a labelled record, **and** the record is not `size:low` (the only case `build/micro-plan.md` reads a per-record `fast-lane`). It passes `--ceremony standard` to materialize for those records and logs the skip with its reason.
