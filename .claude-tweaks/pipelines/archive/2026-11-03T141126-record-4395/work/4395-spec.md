# 4395: Leave a verification stamp on /test's bookkeeping-only skip so review Step 1.5 passes after the ledger commit

Origin: reflect full from #4288

Defer-reason: tangential

## Current State

Two pipeline gates read the same bookkeeping-only delta and reach opposite answers.
- `/claude-tweaks:test`'s Skip-if-recent (`plugin/skills/test/verification.md`) sees `VERIFICATION_SHA` ≠ HEAD. It classifies every changed path against `.claude-tweaks/verify-scope.json`, and when all of them are bookkeeping-only (`suites: []`) it skips verification and writes no stamp.
- `/claude-tweaks:review` Step 1.5 (`plugin/skills/review/code-mode-steps.md`) then reads `verify.js --stamp-status`. It gets `verifiedHead: false`, because the full-pass stamp names the pre-ledger-commit SHA. Its gate row says "re-trigger `/claude-tweaks:test`, re-check", but the re-triggered `/test` takes the same bookkeeping-only skip and still writes no stamp, so the gate names no terminal outcome.
- A `/flow` run reaches this state whenever a bookkeeping-only commit lands between `/build` Common Step 5's full verify and `/test` (for example, run-ledger rows recording AC results, which only exist after verify). #4288's run hit it: build verified 65fd6e5, a ledger-only commit moved HEAD to 81a3dc6, and the review got past the gate only by hand-running a scoped `verify.js --scope .claude-tweaks/verify-scope.json --integration-branch origin/main` (`scope: none`, `still-verified: bookkeeping-only delta`), which wrote a `none` stamp verifying HEAD.

## Deliverables

- [ ] Make `/claude-tweaks:test`'s bookkeeping-only Skip-if-recent branch run the scoped `verify.js` invocation the Re-verify scoping table already gives the multi-spec spec-N step (`none` on a bookkeeping-only delta), so the skip leaves a stamp that verifies HEAD instead of writing nothing.
- [ ] Give `/claude-tweaks:review` Step 1.5's `verifiedHead: false` row a terminal outcome: after one re-trigger, a still-unverified stamp either stops the review with a named cause or passes on a recorded bookkeeping-only classification. It must never loop.

## Acceptance Criteria

1. In a `/flow` run whose only change after build's full verify is the run ledger commit, `/claude-tweaks:test` exits Skip-if-recent with `verify.js --stamp-status` reporting `verifiedHead: true` (`scope: none`) at the new HEAD.
2. `/claude-tweaks:review` Step 1.5 then passes its test gate with no hand-run `verify.js` and no second `/test` re-trigger.
3. A delta with any non-bookkeeping path still runs the scoped or full re-verify exactly as today.

## Release Note

A pipeline run no longer stalls at the review test gate after build commits its own ledger: the test step's bookkeeping-only skip now leaves a verification stamp for the new commit.
