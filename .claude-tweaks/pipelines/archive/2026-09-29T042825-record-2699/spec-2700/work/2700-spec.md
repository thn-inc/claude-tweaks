# specify: decomposition-mode.md loads unused closeout context before the delegate decision

Surface: infra

## Current State

`specify/decomposition-mode.md` documents that its mechanical range (Steps 3-9) can be delegated
to a subagent via `mechanical-handoff.md`, and that the delegate "loads only
`decomposition-mode-closeout.md`" — never the interactive file. In practice, a caller working
through decomposition mode in the main thread reads the closeout range's own sub-files before
reaching the point where it decides to delegate — that reading is substantially wasted, since
the delegated subagent is separately instructed to read the same files itself.

## Deliverables

- In `decomposition-mode.md`, move the delegate-or-continue decision point to occur before any
  instruction that would cause a caller to open the closeout sub-files — state explicitly, near
  Step 2.5d's handoff to Step 3, that a caller planning to delegate needs only
  `collapse-decision.md` plus `mechanical-handoff.md`'s own required-inputs table.
- Confirm `mechanical-handoff.md`'s required-inputs table is sufficient on its own for a caller
  to compose a complete dispatch prompt without consulting the closeout files directly.

## Acceptance Criteria

- A caller that decides to delegate before reaching Step 3 can compose a complete, correct
  dispatch prompt using only `decomposition-mode.md`'s own text, `collapse-decision.md`, and
  `mechanical-handoff.md`.
- `decomposition-mode.md`'s prose states this non-consumption explicitly.
