# specify: mechanical-handoff has no return channel for staged red-team findings

Surface: infra

## Current State

`specify/decomposition-mode-closeout.md` Steps 3-9 can be delegated to a subagent per
`mechanical-handoff.md`'s canonical dispatch prompt. When Step 5's multi-persona red-team writes
a decision-worthy finding (one whose resolution would change a sub-issue's
Deliverables/Acceptance-Criteria scope), that finding is staged for the Review Console with
`ready` cleared — but a plain interactive `/specify` invocation has no `PIPELINE_RUN_DIR` and no
Review Console to stage into. The delegated subagent correctly declined to resolve two such
findings unilaterally and left them as inline `<!-- ambiguity: -->` markers with `ready` cleared,
reporting them in its Step 9 summary for the caller to resolve. The caller then had no mechanized
way to apply the resolution.

## Deliverables

- Extend `mechanical-handoff.md`'s OUTPUT FORMAT (and `decomposition-mode-closeout.md`'s Step 9
  template) with a structured `### Staged for caller` section — one row per decision-worthy
  finding left unresolved, naming: the record, the exact flagged sentence/marker text, and the
  suggested resolution the red-team persona proposed.
- Add a small `bin/` CLI (or extend an existing record-editing helper) that takes a record
  reference, a marker-matching string, and a resolution string, and mechanically replaces the
  `<!-- ambiguity: ... -->` marker with the resolution text, then restores `ready` if no other
  markers remain in the body.
- Wire `decomposition-mode-closeout.md`'s own text to point a delegating caller at this new CLI.

## Acceptance Criteria

- A delegated Steps-3-9 run that leaves N decision-worthy findings staged returns a
  `### Staged for caller` section the caller can act on with N CLI calls.
- The new CLI correctly clears a marker and restores `ready` only when zero
  `<!-- ambiguity: -->` markers and no `## Open Questions` section remain in the body afterward.
