# 5917: Launch every driver worker with an explicit model

Surface: backend
Risk-flags: public-contract

## Overview

Every headless worker the pipeline driver launches gets an explicit model, chosen per role by policy and resolved through the plugin's work-profile table. Today no driver launch names a model, so the implementer, the reviewer and both judgment workers run on whatever the account's default is: Opus in the three runs of 2026-11-12, and Fable for an account whose default is Fable. The plugin's own rule is that no dispatch inherits the session model by omission. See #5914 for the Decision Rationale.

**Complexity:** Medium
**Estimated tasks:** 6

- Choosing the implementer's profile from the record's size (the design's Phase 9).
- Changing what any role is allowed to do, or its ceilings.
- The dispatch walker's profile: #4030, the design's Phase 4.

## Acceptance Criteria

1. With the key unset, the argument list composed for an implementer launch contains `--model` followed by the model `standard` resolves to, and the reviewer's contains the model `capable` resolves to.
2. With the key setting `implementer: fast` in `.claude-tweaks/policy.yml`, the implementer's argument list names the model `fast` resolves to; the same value in a run's `config.yml` changes nothing.
3. With `model-ceiling: standard` in policy, the reviewer launches on the model `standard` resolves to.
4. A role value of `frontier` resolves to the `capable` model, because every driver launch is headless.
5. A launch for a role absent from the resolved map exits before spawning, and the driver's final line reports the stop with the role's name.
6. Adding a fifth entry to `ROLES` without a default profile makes a test fail.
7. After a driver run, every `worker` step line in `driver-events.jsonl` has a `model` field equal to the model that launch was given.
8. The module header of `worker.js` records a dated live probe for each distinct default model after this change.

## Release Note

Made every pipeline driver worker launch on a model set by policy instead of the account's default.

## Technical Approach

One resolution point, `launchTracked`, keyed on the role every caller already passes, so no call site grows its own model logic. Resolution reuses `profiles.js` so a project's `model-profiles` rows and `model-ceiling` apply to driver workers exactly as they do to dispatched agents. The reviewer defaults to Capable because the whole-branch review, the nearest existing equivalent, finds a Critical or Important issue in 70% of runs and its tier has not been compared; the judgment workers default to Standard because code floors already decide the unsafe cases before they launch. The Capable default is provisional: the 70% rate shows the review is worth running, not that it needs Capable, so a tier comparison belongs to a follow-up record once the first record's report has a baseline.
