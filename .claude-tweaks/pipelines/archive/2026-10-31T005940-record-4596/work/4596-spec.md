## Build Deviations (Beneficial — architecture alignment, Common Step 4.5)

- B1: the CLI's exit vocabulary goes beyond the spec's JSON shape: exit 0 prints a verdict for every outcome, failure included; 1 = malformed invocation; 2 = only gh absent with no --listing (the caller's cue to fetch the MCP listing); 3 = owner/repo unresolved; a non-github.com repo host prints a failure verdict, never a clean no-match.
- B2: the Resume-line check is stricter than composeResumeLine's literal shape: the dir and target fields are ASCII allowlists (no !, no control characters), the run dir must end in /{runId}, and the line under the last ### Resume heading is read (SDD rulings, staged/sdd-ruling-2..5).
- B3: normalizePrListing rejects any element that is not a PR (no string url, no head/repo on an MCP entry, a non-string-or-null body, a non-boolean isCrossRepository) as a failure, never a clean no-match (staged/sdd-ruling-1).
- B4: staleClaimInFlightPr (claim-targets' gh path) also runs normalizePrListing, so both callers share one path.
- B5: /tidy's gh path lists open PRs once per stale claim (the CLI fetches per call) rather than once per tidy run; the MCP path still lists once per run.
