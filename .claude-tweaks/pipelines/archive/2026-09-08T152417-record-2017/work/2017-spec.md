## Current State

`plugin/bin/lib/compose-context/resolve-conditions.js`'s `transport` probe (`execFileSync('gh', ['--version'], …)` in a try/catch) is the sixth near-verbatim copy of the `gh`-availability check in `plugin/bin` — `release-claim.js`, `lib/feedback/file-feedback.js`, `link-records.js`, `materialize.js`, and `lib/repo-resolve.js` each carry their own, with drifting option objects (`stdio: 'ignore'` vs `stdio: 'pipe'` + `timeout`). None share a helper, so a rule applied to one (a timeout bound, an env override for sandboxes) silently misses the rest — the drift shape `gh-api-module-pattern`'s "sibling default runners" bullet records for git/gh runner pairs. `grep -rn "'--version'" plugin/bin` lists the six sites. Raised by #1988's whole-branch review and its Task 2 reviewer independently; staged at #1988's hindsight reflect as a convention finding whose resolution is a follow-up record, which the consolidated console cannot file without this header.

## Deliverables

- One `ghAvailable(deps)` helper — injectable runner, one bounded options object (`stdio: 'ignore'`, a timeout) — in `plugin/bin/lib/repo-resolve.js` or a new `plugin/bin/lib/gh-available.js`.
- Migrate the six call sites to it; delete the local copies.
- A fake-runner test pinning the helper's shape (available / absent / throwing runner), and a grep-backed test that `'--version'` appears in `plugin/bin` only inside the helper.

## Acceptance Criteria

- Every migrated CLI's existing tests stay green with the helper injected.
