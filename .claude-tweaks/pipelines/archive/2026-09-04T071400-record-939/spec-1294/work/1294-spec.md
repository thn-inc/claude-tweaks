# 1294: console-execution.md's reconciler-side consoleAutoResolve executor can override a merge-check needs-human verdict

Surface: infra

## Current State

#1179 added the Needs-human carve-out to both console files' Auto-resolution short-circuits and cross-referenced it from `dispatch/settle-and-merge.md`'s Auto-merge gate. But `_shared/autonomy-ceiling.md` names a second sanctioned caller of `consoleAutoResolve`: `_shared/console-execution.md`'s reconciler-side executor, which auto-ticks and executes a PR-posted console when the ceiling is raised after render time. That file's "consoleAutoResolve wiring" section treats every console item as floor-clearing ("no narrower per-item test today") and routes execution through `review-console.md`'s "On approval" steps 1-6 — including the branch-finish/merge row — while containing zero occurrences of "merge-check" or "needs-human". Reachable scenario (traced during #1179's review): `settle-and-merge.md`'s gate fails a layer at an attended tier, so the console renders unticked on the PR without the short-circuit (and hence the carve-out) ever evaluating; nothing persists the `needs-human` verdict (`console.json`, `decisions.md` entry schema, PR label); the ceiling is later raised to `unattended`; the reconciler auto-ticks the merge box, and `_shared/pr-first-merge.md` performs no independent needs-human check. This defeats exactly the precedence rule #1179 pinned (human ruling 2026-08-21: merge-check's needs-human verdict is authoritative), via an adjacent file #1179's spec did not scope. Refs #1179.

## Deliverables

1. Persist the merge-check `needs-human` verdict at console render/post time in a place the reconciler-side executor reads (e.g. a `mergeCheckVerdict` field in `console.json` written by `_shared/console-on-pr.md`'s post procedure — mechanism choice is part of this record's design work; interaction with #347's planned per-item floor predicate must be considered, since `console-execution.md` explicitly forbids pre-implementing that predicate).
2. In `_shared/console-execution.md`'s "consoleAutoResolve wiring": mirror the #1179 carve-out — when a persisted `needs-human` verdict exists for the run, the merge/branch-finish row is not floor-clearing; Resolve stays unticked for a human; every non-merge item still auto-resolves.
3. Extend the #1179 conformance suite (`tests/console-autoresolve-needs-human-carveout.test.js`) or add a sibling suite to pin the executor-side carve-out with go-red proof, and cover the persistence mechanism with a unit test.

## Acceptance Criteria

- A console posted for a run with a `needs-human` merge-check verdict cannot have its merge/branch-finish row auto-ticked by the reconciler-side executor at any later ceiling.
- The verdict survives session end (persisted artifact readable by a foreign session — not conversation state).
- Conformance/unit tests fail when the executor-side carve-out prose or the persistence write is removed.

## Technical Approach

Persist the merge-check `needs-human` verdict at console render/post time in a location the reconciler-side executor can read independent of session state (e.g. a `mergeCheckVerdict` field in `console.json`), then have `_shared/console-execution.md`'s `consoleAutoResolve` wiring check that persisted verdict before treating the merge/branch-finish row as floor-clearing — mirroring the carve-out #1179 already added to the render-time short-circuit. Coordinate with #347's planned per-item floor predicate rather than pre-implementing it. Extend or add a conformance suite with go-red proof for the executor-side carve-out and a unit test for the persistence write.

### Key Files

- `plugin/skills/_shared/console-execution.md` — the `consoleAutoResolve` wiring needing the carve-out
- `plugin/skills/_shared/console-on-pr.md` — the post procedure that would write the persisted verdict
- `plugin/skills/wrap-up/review-console.md` — "On approval" steps 1-6, including the branch-finish/merge row
- `tests/console-autoresolve-needs-human-carveout.test.js` — the existing #1179 conformance suite to extend or sibling

## Gotchas

- #347 (autonomy-tiered console resolution) plans a real per-item floor predicate for this same loop; coordinate rather than pre-implement or conflict.
- `console-execution.md`'s `ctx.ownedRun` exemption means the executor may run with no access to the original session — the verdict must be in the run dir or on the PR, never assumed from context.
