# 2686: PR-early run lifecycle: dual-marker Fixes-#N block doesn't reconcile per-spec deferred-closure decisions

Surface: infra

## Current State

`_shared/pr-early-run-lifecycle.md`'s dual-marker PR body convention (the `[claude-tweaks-fixes-start]...[claude-tweaks-fixes-end]` block, per-record `Fixes #{n}` lines composed around line 195/259-267) lists a `Fixes #{n}` line for every spec in a multi-spec run unconditionally. When a spec deliberately omits the closing keyword from its own commit — because a decision was already logged (e.g. to `decisions.md`) to leave that spec's issue open until a later manual step completes — the shared PR-level block still lists it. GitHub auto-closes on the coarser PR-body signal regardless of the finer per-commit one, contradicting the logged decision. Observed cost: one issue was incorrectly auto-closed, requiring manual reopen, an explanatory comment, and a follow-up PR to properly re-close once the deferred work actually finished.

## Deliverables

- Before composing the dual-marker `Fixes #{n}` block, check whether any spec in the run has a logged decision to withhold its own closing keyword (e.g. a `decisions.md` entry recording a deliberate deferred-closure decision for that spec).
- Omit any such spec's `Fixes #{n}` line from the shared PR-body block, so the PR-level marker never contradicts a more specific per-spec decision already on record.

## Acceptance Criteria

- A multi-spec run where one spec has a logged deferred-closure decision produces a dual-marker block that omits that spec's `Fixes #{n}` line.
- Merging that PR does NOT auto-close the deferred spec's issue.
- Every other spec in the run (with no such decision) still gets its `Fixes #{n}` line as before — this fix narrows the block, it never widens or otherwise changes it.

## Release Note

Fixed multi-record pull requests closing a record that was deliberately left open.

## Technical Approach

Locate the block-composition step in `_shared/pr-early-run-lifecycle.md` (the "One `Fixes #{n}` line per record" section, and the dual-marker template around line 195) and add a check, before emitting each record's line, against that run's own decision log for a deferred-closure marker naming that spec. The check reuses whatever mechanism already records a deliberate withhold-closing-keyword decision (per the bug report, a `decisions.md` entry) — no new log format should be invented if one already captures this decision shape; if none does today, this fix needs to also define what that entry looks like so a later run can be checked against it reliably.

### Key Files

- `plugin/skills/_shared/pr-early-run-lifecycle.md` — the dual-marker block composition logic (Fixes-start/Fixes-end template, per-record line emission)

## Gotchas

- This fix must not change single-spec runs at all (they get one line, unconditionally, today) — scope the check to the multi-spec bundle path only, where a per-spec deferred-closure decision is possible.
- If no existing log entry shape unambiguously records "this spec's closing keyword was deliberately withheld," this fix needs to define one before the check above can be reliable — verify a matching entry shape exists (or add it) rather than guessing at a decisions.md grep pattern.
