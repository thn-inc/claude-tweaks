# 1276: Encode the declined structural-isolation rationale for framing-check's inline invocation

Surface: backend

**Related:** #1442, #1491

## Overview

#1276 asked whether dispatching `framing-check`'s untrusted-content judgment as a Task-agent call (instead of inline via the `Skill` tool) would provide a meaningfully stronger structural boundary against prompt injection. Brainstormed 2026-08-29; the decision is **no structural isolation** — keep `framing-check` inline at all three call sites, and encode the security rationale durably in the prose a future auditor reads, so the question is answered where it would be re-raised rather than only in this closed issue.

The evaluation found a Task-agent boundary buys ~nothing here: the caller (`/specify`) doesn't merely hold the record body — shaping itself reasons over that untrusted content inline, in turns with full tool access, on every path; isolating only the judgment step contains nothing, because the shaping exposure is identical either way. A fresh subagent context is no structural barrier to persuasion regardless of which model profile runs it (the wrapped content is judged by an LLM in both shapes), and the verdict's blast radius is a non-gating label. Against that, the cost is one Task dispatch per record per call site plus re-plumbing inline-gathered context (the `## Gotchas` evidence weighting) into every dispatch prompt.

## Decision Rationale

Three threat lenses were weighed for Task-agent dispatch, none improved by it: (1) injection reaching the orchestrator's tools — no gain, and not merely because the content is *present*: `/specify` actively reasons over the untrusted body inline (fetching, shaping, rewriting it) in turns with full tool access on every path, so moving only the judgment step into a contained subagent leaves the identical mid-turn exposure in place during shaping; (2) manipulating the verdict — no gain, an LLM judges the same wrapped content in either shape and a fresh context erects no structural barrier to persuasion, whatever model profile runs it; (3) verdict-channel confusion — marginal, since the body sits in the parent's context from its own fetch, "read the verdict only from the callee's rendered output" remains a prose discipline either way. Cost is real: framing-check runs per record, every run, at three call sites. Blast radius bounds residual risk for `framing-check` specifically: a hijacked verdict can only flip `solution:unjustified`, which gates nothing (#471) — no `auto:*` grant, no merge, no label-driven automation; the decision carries a revisit clause should that ever change. This blast-radius ground was evaluated for `framing-check` only — `grant-check`'s verdict carries real authority (headless `auto:*` grants), so only the two structural grounds are claimed for it, and a grant-check-specific evaluation is deliberately out of scope (Non-Goals). Alternatives rejected: full Task-agent dispatch at all three sites (cost without gain); isolating only headless sites (#1275 deliberately retired headless-scoped wrapping after it misfired once); an adversarial spike first — declined as an accepted risk, stated plainly: persuasion-resistance parity between the two shapes is argued structurally above, not empirically measured, and this record does not claim otherwise.
