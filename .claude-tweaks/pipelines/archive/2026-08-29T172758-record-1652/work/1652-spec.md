# 1652: reconcile: dedup hand-duplicated sync/async primitive pairs (runGit/Async, sharedFetch/Async, ghHealthCheck/Async)

Defer-reason: genuinely-larger

## Current State

runGit/runGitAsync (`plugin/bin/lib/hooks/git-exec.js`), sharedFetch/sharedFetchAsync, and ghHealthCheck/ghHealthCheckAsync (`plugin/bin/lib/reconcile/preflight.js`) are three separate hand-duplicated sync/async twin pairs, built purely to enable one narrow `Promise.all` path in `reconcile/index.js`'s FAST_CHECKS shape. Each pair already shares its classification/timeout helpers (`classify()`, `resolveTimeout()`, `FAILURE` constants) — only the ~10-line wrapper itself is duplicated per pair, and a fix to one twin's contract must be manually mirrored to the other. This has already happened once: a whole-branch pre-release review (pre-v6.110.0) found `runGit`'s `stderr` field had been added without updating `runGitAsync` to match, despite a header comment claiming "identical return shape" — fixed directly as part of that review, but the underlying duplication that let it happen remains.

## Deliverables

Either collapse the FAST_CHECKS dispatch to be async-native (removing the need for sync twins entirely), or extract the shared wrapper shape so only the sync-vs-async execution call differs between each pair.

## Acceptance Criteria

No behavioral change to any existing caller. Existing test suites for `git-exec.js`, `preflight.js`, and `reconcile/index.js`'s FAST_CHECKS all still pass. A future fix to one twin's contract cannot land without the shared code path enforcing it also applies to the other.
