# 6110: Let a resumed learned-skills land recognise edits a merged PR already shipped

Surface: backend
Risk-flags: none
**Related:** #5663

## Current State

- `plugin/bin/lib/learned-skills/land.js` reads the run branch's PRs only when `git ls-remote` still finds `refs/heads/learned-skills/{run-id}` (the `if (line) { … listPrs() … }` block in step 1, "The base"). With no remote branch it builds fresh commits on the integration tip and opens a new PR.
- When the branch exists and its PR is `MERGED`, `land` sets `orphanReason` ("the earlier learned-skills PR #N was merged, so … is not reused as a base") and stages every captured entry.
- Sibling sub-issues make the learned-skills PR merge itself once green and delete its branch on merge (`--delete-branch`). A run that dies after that merge but before its manifest write would then, on resume, either open a second PR with the same edits (branch gone) or stage edits that already shipped (branch present, PR merged).

## Deliverables

1. `land` looks up the run branch's PRs by head-branch name whether or not the remote branch exists (`gh pr list --head learned-skills/{run-id} --state all`, through the same `listPrs` seam, or through `listPrsForHead` if #5663 has landed by build time). A failed lookup or commit read fails closed: every remaining captured entry is staged with a reason naming the failed read, and `land` never builds fresh commits or a new PR on that path. The commit read pages to completion. When several PRs share the head name, the commits of every `MERGED` one count.
2. When a `MERGED` PR exists for the run branch, each still-`captured` entry whose commit is among that PR's commits is recorded `landed` against that PR (commit and PR URL set, its AUTO log line written once). A commit matches an entry when its trailers carry this run's id and the entry's id, and its diff's `git patch-id --stable` equals the entry's patch file's — the same verification `land` already applies to commits on an existing branch. Read the merged PR's commits through `gh` (`gh pr view {n} --json commits` or `gh api repos/{owner}/{repo}/pulls/{n}/commits`); the branch may be deleted, so never read them from `origin/learned-skills/{run-id}`. The patch-id comparison needs the commits' objects locally, so `land` first runs `git fetch origin refs/pull/{n}/head` (GitHub keeps that ref after a merge and a branch delete); a fetch that fails is a failed read under the rule above.
3. Entries not on the merged PR, including ones captured after it merged, are staged with a reason naming the merged PR, as today; that staging is intended.
4. The header comment's Resume paragraph in `land.js` and `plugin/skills/wrap-up/learned-skills-pr.md`'s description of a resumed `land` say the new rule.

## Acceptance Criteria

- A test in `tests/bin-lib/learned-skills/land.test.js` with no remote branch and a `MERGED` PR whose commits carry the run's trailers and matching patch-ids records every entry `landed` against that PR, creates no new branch or PR, and stages nothing.
- A test with the same merged PR missing one entry's commit lands the present entries and stages only the missing one, its reason naming the merged PR.
- A test with no remote branch and no PR at all keeps today's behaviour (fresh commits, new PR).
- Each new test was seen failing with the new lookup reverted.
- `npm test -- --full` passes.

## Release Note

Fix a resumed wrap-up so it recognises learned-skill edits whose PR already merged, instead of opening a duplicate PR or staging them again.

## Technical Approach

Hoist the `listPrs()` call out of the `if (line)` block so it runs for every land; keep the existing branch-present paths (open PR reused, closed PR stages, no PR means the branch is this run's own). Add the merged-PR reconciliation before `orphanReason` stages anything. Reuse the existing trailer and patch-id verification helpers rather than writing a second matcher.

### Key Files

- `plugin/bin/lib/learned-skills/land.js` — PR lookup independent of the remote branch; merged-PR reconciliation; header comment
- `plugin/skills/wrap-up/learned-skills-pr.md` — resumed-land description
- `tests/bin-lib/learned-skills/land.test.js` — new resume cases

## Gotchas

- The sibling sub-issue that merges the learned-skills PR in the same wrap-up widens the merge-then-crash window, but the rule here is safe whichever lands first: a PR merged by a human in the old flow hits the identical case.

- #5663 replaces head-branch PR lookups with one fork-excluding helper and touches `land.js`; whichever lands second rebases onto the other.
- `--state all` with `--head` matches by head ref name, so a deleted branch's PR is still found; verify with a fake runner that the argv carries no `--repo`-less fork ambiguity (#5663's concern).
