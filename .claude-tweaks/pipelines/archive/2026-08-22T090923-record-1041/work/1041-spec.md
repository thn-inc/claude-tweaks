## Current State

plugin/skills/specify/next-mode.md (around lines 210-239) feeds the body/title of a GitHub issue selected by /specify next's headless selection logic directly into the framing-check step, with no sanitization or untrusted-boundary treatment of that content. Since /specify next is designed to fire headlessly (e.g. via a scheduled Routine, with no human reviewing the selected issue first), and GitHub issue bodies/titles can be authored by anyone with issue-creation access to the repo, this is a prompt-injection-adjacent surface: an issue body crafted to look like framing-check instructions could influence the headless shaping outcome with no human in the loop to notice.

## Deliverables

- Decide and apply an appropriate untrusted-content boundary — e.g. explicitly wrapping/labeling the issue body as untrusted data in the framing-check prompt (matching how other skills in this plugin already handle untrusted external content, if such a convention exists — check plugin/skills/_shared/ for one before inventing a new pattern), or another mitigation appropriate to the actual mechanism found.
- Add a test or explicit note covering the mitigation, matching this codebase's existing test conventions for next-mode.md / framing-check.
