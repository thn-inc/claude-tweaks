# 3557: specify/build: a spec-mandated decision line must still follow the auto-decision-log status vocabulary

Surface: infra

**Related:** #3079, #3284, #3289, #3295, #3297, #3363, #3377, #3378, #3442, #3483, #3496, #3503, #3510, #3515, #3577

## Current State

Spec #3520's Deliverable 5 told `/dispatch` to log a decision line with the word `STAGED`. That line was copied from a warning #1985 had already added to `plugin/skills/dispatch/drain-pr-overlap.md`. Neither line writes a `staged/` artifact, so both violated the Status semantics in `plugin/skills/_shared/auto-decision-log.md:139-156`, where `STAGED` requires a proposal written to the run's `staged/` directory and `STAGED`/`SKIP` are disjoint by the presence of a staged artifact. An informational "dispatched anyway" warning is `AUTO`.

The SDD final whole-branch review flagged it as Minor 4. The controller ruled to keep the line because the spec mandated that exact text. Review lens 3a then reproduced the finding, and commit `ccca47271` on PR #3530 changed all three lines to `AUTO`. That cost #3520 one wrong ruling and one review-fix commit.

Two gaps let it through, and both were verified on the current tree:

- `/claude-tweaks:specify` has no check that a literal `decisions.md` line mandated by a spec uses a status word consistent with `_shared/auto-decision-log.md`'s Status semantics. Its two composition paths, `plugin/skills/specify/shaping-mode.md` (shaping) and `plugin/skills/specify/record-creation-subissues.md` (decomposition), carry no such check today.
- `/claude-tweaks:build`'s SDD invocation instruction (`plugin/skills/build/dispatch.md`) never says that a project contract outranks spec-mandated literal text. A ruling can therefore keep a contract violation because the spec spelled it out.

## Deliverables

1. `/claude-tweaks:specify`: when a composed spec mandates a literal `decisions.md` line, check its status word against `_shared/auto-decision-log.md`'s Status semantics before the record is written or stamped `ready`. A `STAGED` line must name the `staged/` artifact it writes. A line that writes no artifact must use `AUTO`, or `SKIP` for a degrade trace. Add this check in both composition paths: shaping (`shaping-mode.md`) and decomposition (`record-creation-subissues.md`). On a mismatch, rewrite the line to the contract-conformant status before writing; never stop mid-flow to ask.
2. `/claude-tweaks:build`: in `plugin/skills/build/dispatch.md`'s SDD invocation instruction, state that spec-mandated literal text does not override a project contract (`_shared/*.md`). When the two conflict, the ruling conforms to the contract and records the change as an update-the-spec deviation (`build-deviation-*`). The spec's text is never kept on the grounds that the spec spelled it out.
3. Two conformance tests, one per instruction, each pinning the instruction's presence in its file.

## Acceptance Criteria

1. A conformance test fails when the literal-decision-line status-word check is removed from `plugin/skills/specify/shaping-mode.md` or from `plugin/skills/specify/record-creation-subissues.md`.
2. A conformance test fails when the "contract beats spec-mandated literal text" instruction is removed from `plugin/skills/build/dispatch.md`.
3. Neither change adds a new mid-flow stop in `auto` mode. The specify check rewrites rather than prompts, and the build instruction directs a ruling rather than a question.
4. Both new tests pass on the changed tree, and each fails when its instruction is reverted (proved by temporarily reverting the instruction).

## Release Note

Spec shaping now corrects a mandated decision-log line whose status word breaks the decision-log contract, and builds now side with the project contract over conflicting spec wording.

- Add the build instruction to `build/dispatch.md`'s SDD invocation instruction, beside the existing ruling-related directives (the SDD `Ruling:` carry-forward paragraph). Reuse the existing `build-deviation-*` staged-item convention.
- The tests follow the existing prose-conformance pattern (`tests/build-*.test.js`, `tests/specify-*.test.js`), reading the live skill text.
