# 2282: friction-events: the worktree-isolation guard's refusals are not a logged friction event kind, so the Friction lens cannot see them

Surface: infra

## Current State

The PreToolUse worktree-isolation guard (`bin/lib/hooks/pre-tool-use.js`'s `checkWorktreeRequired`
and its supporting compound-Bash-shape detection) refuses Bash commands it cannot prove are
non-git (runtime-computed paths, heredocs mentioning commits, compound commands) when
`worktree-always: true`. `bin/friction-events.js` recognizes five event kinds (comment at line
~26: `wd-deny`, `gate-denial`, `bookkeeping-stamp-deny`, and others) but this specific refusal
class is not one of them — confirmed still true: no `wd-guard-refusal`-shaped kind exists in
either `friction-events.js` or `pre-tool-use.js` as of this shaping pass. `checkWorktreeRequired`
does call `appendEvent(..., 'gate-denial', ...)` at one point in its own logic, but that call is
scoped to a resolved "owned run" context (per the surrounding comment: "an owned run dir records
nothing here" for the foreign-owned case) — it is not a general log-every-refusal call, which is
consistent with the reporter's direct empirical observation below.

A real run (worktree-always: true, plugin 6.118.0) over one build → test → review → wrap-up cycle
had roughly eight commands refused by this guard — a `sed -n` reading a run-dir path from a shell
variable, a `for` loop over `gh issue list --json` calls, and heredocs mentioning commit hashes —
each rewritten by hand into a plain command or moved to the Write tool. At wrap-up,
`/claude-tweaks:reflect`'s Friction lens ran `friction-events.js --run <run-dir>` and saw 1
`bookkeeping-stamp-deny` and 13 `contract-violation` events, and zero `wd-deny`/`gate-denial` —
the eight guard refusals left no trace, so the lens reported the run as proportionate when the
guard refusals were the operator's most frequent actual stop. The refusal mechanism itself is
already tracked separately (#1798); this record is only about its observability.

## Deliverables

- Log each worktree-isolation guard refusal (the "cannot prove non-git" compound/heredoc/
  runtime-path case, distinct from `checkWorktreeRequired`'s own narrower `gate-denial` path) as
  a new friction event kind — e.g. `wd-guard-refusal` — carrying the refused command's executable
  and the refusal reason.
- Add the new kind to `bin/friction-events.js`'s recognized-kinds list and its aggregation logic.
- Add the new kind to `skills/reflect/full-mode.md`'s Friction lens vocabulary block, so the
  pinned vocabulary test (`tests/reflect-friction-lens-vocab.test.js`) covers it.

## Acceptance Criteria

- A worktree-isolation guard refusal of the "cannot prove non-git" shape (a compound command, a
  heredoc mentioning a commit, or a runtime-computed path) appends a `wd-guard-refusal` event
  (or equivalent new kind) to the active run's `events.jsonl`, distinct from `gate-denial` and
  `wd-deny`.
- `friction-events.js --run <dir>` reports the new kind's count in its aggregate output.
- `reflect/full-mode.md`'s Friction lens vocabulary block names the new kind, and
  `node --test tests/reflect-friction-lens-vocab.test.js` passes.
- Replaying this record's own described run (8 guard refusals, 1 `bookkeeping-stamp-deny`, 13
  `contract-violation`) with the fix applied would show 8 `wd-guard-refusal` events, making the
  Friction lens's proportionality judgment reflect the operator's actual experience.
- `npm test` passes.

## Technical Approach

Locate every return point in `checkWorktreeRequired` (and any sibling function in
`pre-tool-use.js` handling the same "cannot prove non-git, fails closed" compound-Bash refusal
class — per that file's own comment at ~line 135, "Fails CLOSED, deliberately: anything this
cannot prove sits under the repo's [isolation boundary]") that produces a deny decision for this
specific refusal shape, as opposed to the already-logged `gate-denial`/`wd-deny` paths. Add an
`appendEvent(runDir, 'wd-guard-refusal', { command: command.slice(0, 200), reason })` call at
each such point, following the exact pattern the existing `gate-denial` call
(`appendEvent(ownedRun.dir, 'gate-denial', { tool: toolName, path: targetPath, ...testTag },
ownedRun.attribution)`) already uses — including its run-dir resolution and any test-tag
handling needed to avoid the test suite's own exercise of this gate polluting a real run's
friction counts (mirroring `friction-events.js`'s existing `gate-denial`+`test===true` skip at
line ~93). Then wire the new kind through `friction-events.js`'s aggregation and
`reflect/full-mode.md`'s vocabulary block the same way the existing five kinds are already wired.

### Key Files

- `plugin/bin/lib/hooks/pre-tool-use.js` — add the `wd-guard-refusal` event append at the
  compound/heredoc/runtime-path refusal point(s) in `checkWorktreeRequired`
- `plugin/bin/friction-events.js` — recognize and aggregate the new kind (mirror the existing
  `gate-denial` test-tag skip if the same test-pollution risk applies)
- `plugin/skills/reflect/full-mode.md` — Friction lens vocabulary block, new kind name
- `tests/reflect-friction-lens-vocab.test.js` — cover the new kind name

## Gotchas

- Do not conflate this new kind with the existing `gate-denial` event `checkWorktreeRequired`
  already logs for its own narrower, owned-run-scoped case — they're different refusal shapes;
  changing `gate-denial`'s existing meaning would break whatever currently reads it.
- Mirror the test-pollution guard the existing `gate-denial` kind already has
  (`friction-events.js`'s `parsed.test === true` skip) if this guard's own test suite exercises
  the same refusal path — otherwise this repo's own hook tests would inflate a real run's
  friction count.
- This record is scoped to observability only — the refusal mechanism's own correctness (whether
  it should refuse a given command at all) is #1798's territory, not this record's.
