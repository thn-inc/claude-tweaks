# 2002: Bring the composed merge bundle under the 40 KB composed-bytes ceiling and remove its COMPOSED_STEP_EXCEPTIONS entry

Surface: backend

**Related:** #1987, #2019

## Overview

Bring the composed `merge` bundle (`_shared/pr-first-merge.md` + `_shared/pr-early-run-lifecycle.md`, read by `/wrap-up`'s two pr-first merge sites via `bin/compose-context.js`) under the 40 KB composed-bytes ceiling `plugin/bin/lib/skill-audit/context-cost.js` now enforces per compose call site, and remove the `merge` entry from `COMPOSED_STEP_EXCEPTIONS`.

## Current State

- #1989 fenced the two sources' branch-specific prose with `when:` markers without rewriting a sentence. Under `integration-model=pr-first` + `transport=gh` the composed bundle measures 55,995 B (raw sources 58,612 B): additive fencing of prose that already exists saved 4.5%, because almost all of both files is genuinely pr-first-and-gh procedure.
- #1990 added the composed-bytes hard gate. The `merge` step is the only real call site and is over the ceiling under every combination — 55,995 B (pr-first+gh), 57,476 (pr-first+mcp), 57,274 (local-merge+gh), 58,755 (local-merge+mcp), 58,761 (both branches, the standalone-run read) — so the gate carries `COMPOSED_STEP_EXCEPTIONS = { merge: 59 * 1024 }` — a provisional per-step ceiling 1,655 B above the measured maximum, pinned to at most 4 KiB of slack by the stale-exception test, that fails on any growth, with a stale-exception test that fails the moment the step fits under `CEILING_BYTES`. Parent #1987's Cross-Spec Promise F4 records the byte figures.
- Both `/wrap-up` merge sites fall back to reading the two sources directly when the compose command is unavailable, so the both-branches read (58,612 B) is what a standalone run pays today.

## Deliverables

- [ ] Measure which sections of the two sources a merge-time reader actually needs at the moment of `gh pr merge` (the Step 2.5 gate, Step 3's merge attempt and its degrade chain, the post-merge handoff) versus what is run-start or phase-checklist procedure already executed by then (`pr-early-run-lifecycle.md`'s Steps 1-4 open the draft PR at run start) — a per-section reader-need table, cited from the sites that read each section.
- [ ] Narrow the `merge` call site's source list or split `pr-early-run-lifecycle.md` along the reader-need boundary (a lazily-read sub-file for the run-start half, per `docs/skill-authoring.md`'s composition-over-fragmentation rule: a split is legitimate only when some reads never need the other half), so that every `integration-model` × `transport` combination composes under `CEILING_BYTES`; byte-identity of the moved prose proven (`stripMarkers` vs `git show origin/main`).
- [ ] Remove `merge` from `COMPOSED_STEP_EXCEPTIONS`; the stale-exception test and the hard gate both pass on the real corpus with no exception.
- [ ] Update `docs/skill-graph.md`'s `_shared/pr-first-merge.md` row and the `#1989` journey step (`docs/journeys/compose-a-per-run-context-bundle-1988.md` step 6) to the new source list; flip promise F4 on #1987 to satisfied.

## Acceptance Criteria

1. `node --test tests/bin-lib/skill-audit/context-cost.test.js` passes with `COMPOSED_STEP_EXCEPTIONS` empty.
2. The informational composed-bytes table shows every `merge` combination at or under 40,960 B.
3. Every citer of a moved section still resolves (grep for the section headings and anchors across `plugin/skills/**` and `docs/**`).
4. `npm test` passes.

## Non-Goals

- Raising `CEILING_BYTES` — the parent design fixes it at the number a reader pays per step.
- Rewriting the merge procedure's semantics; only where prose lives and which sources the call site names change.

## Technical Approach

Measure before moving: the reader-need table is the deliverable that decides between the two mechanisms, and it is built from the two call sites that read the bundle (`wrap-up/auto-merge-short-circuit.md`'s composed read and the Review Console's merge path), not from the sources' own headings. Prefer narrowing the call site's source list when the run-start half is never needed at merge time; split `pr-early-run-lifecycle.md` only if some merge-time reads need part of it, and then move prose byte-identically (`stripMarkers` output compared against `git show origin/main:{path}`) so the `when:` fencing from #1989 keeps its meaning. Remove the exception last, so the stale-exception test flips from "exception too generous" to "no exception needed" in the same commit that makes it true.

### Key Files

- `plugin/bin/lib/skill-audit/context-cost.js` — remove the `merge` entry from `COMPOSED_STEP_EXCEPTIONS`
- `plugin/skills/wrap-up/auto-merge-short-circuit.md` — the `merge` compose call site: its `compose-context.js --step merge {sources}` argv is the source list to narrow or repoint (the composer takes sources from argv; `context-cost.js` measures call sites found in skill prose)
- `plugin/skills/_shared/pr-early-run-lifecycle.md` — run-start half split out only if the reader-need table justifies it
- `plugin/skills/_shared/pr-first-merge.md` — citations to any moved section
- `plugin/skills/wrap-up/review-console.md` — the second merge-path reader and its direct-read fallback
- `docs/skill-graph.md`, `docs/journeys/compose-a-per-run-context-bundle-1988.md` — source-list rows and journey step 6
- `tests/bin-lib/skill-audit/context-cost.test.js` — passes with an empty exception map

## Gotchas

- Sources today: `pr-first-merge.md` 30,404 B and `pr-early-run-lifecycle.md` 30,181 B; the ceiling is 40,960 B composed, so narrowing alone works only if the merge-time reader needs strictly less than about two thirds of the pair.
- The direct-read fallback (compose command unavailable) must land under the ceiling too, or a standalone run keeps paying the both-branches read; the AC's "every combination" includes it.
- #1987 is closed; flipping promise F4 is an edit to that record's body, not a reopen.
- #2019 (open) proposes section-scoped review/test bundles after this restructuring; do not pre-empt its scope here.
