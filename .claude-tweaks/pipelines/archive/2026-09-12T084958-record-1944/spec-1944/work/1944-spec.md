# 1944: Detect near-duplicate open records before build (specify/dispatch time)

Surface: infra

## Current State

Nothing in the plugin compares a record being shaped or dispatched against the rest of the open queue for near-duplication. The closest surfaces each solve a different problem: `/claude-tweaks:specify`'s decomposition mode runs an Overlap Analysis of a *design doc* against open records (a prose judgment, `decomposition-mode.md`); `/claude-tweaks:dispatch`'s queue pull groups eligible records whose `### Key Files` overlap (`groupByFileOverlap`, `bin/lib/issues/grouping.js`) so they build together rather than collide, and since #1224 excludes any record with an open linked PR; the health sweeps dedup their own filings by fingerprint (`bin/lib/health-core/dedup`). Shaping mode's single-record path (`specify/shaping-mode.md`) and the headless drain (`specify/next-mode-shape.md`) have no step that looks at sibling records at all; the drain's refusal grounds ("already implemented", "duplicate of open record") exist only as the shaper's own judgment.

Observed: #1821 and #1224 were shaped independently, built in parallel branches, and #1224's review-passed PR #1852 surfaced only during #1821's review, after both builds. In this sweep's own headless drain (run `2026-09-09T145100-sweep-standalone`), the shaper refused and absorbed nine records by hand for the same reason (#1812–#1817, #1832, #1858, #1810 among them), each found by grepping titles and Key Files against the queue — the check the plugin does not perform.

`grouping.js` already exports `extractKeyFiles` (a record body → Key Files list) and the overlap logic dispatch uses; the session-scoped record snapshot (`_shared/record-queue-fetch.md`) already holds every open record's title and body during a specify run.

## Deliverables

- [ ] **A candidate finder, not a verdict.** `plugin/bin/lib/issues/near-duplicate.js` exporting `findNearDuplicates(subject, records, opts)` → `[{ number, title, score, signals }]`, where `signals` names which of three tests fired: (1) Key Files overlap — two or more shared paths from `extractKeyFiles`, or one shared path when either list has at most two entries; (2) title similarity — Jaccard over lowercased word tokens after stripping stop words, numbers, and `#refs`, at or above 0.5; (3) body-anchor overlap — the same named symbol or file path appearing in both `## Current State` sections. Records carrying `parent-issue`, `parked`, or the subject's own number are excluded. Pure function, no I/O; thresholds are `opts` with the defaults above.
- [ ] **Shaping mode consults it.** `specify/shaping-mode.md`'s sanity-check paragraph gains a step before composition: run the finder over the session snapshot; when candidates exist, render a three-column table (record, score, signals) in the shaping output, append each candidate to the body's `**Related:**` line, and, when a candidate is `ready` with an open linked PR or `bot:in-progress`, stop shaping and route the record to the existing `needs:decision` path with a proposed Absorb naming the candidate (the same refusal shape this sweep used by hand). `next-mode-shape.md` cites the same step for the headless drain.
- [ ] **Dispatch warns on cross-group candidates.** `dispatch/queue-pull-script.md`: after grouping, run the finder pairwise across records in *different* groups and log one `AUTO … — near-duplicate candidates across groups: #A / #B ({signals})` line per pair; no selection change (grouping already co-builds same-Key-Files records, and #1224 already excludes open-PR duplicates), so the warning is the dispatcher's cue, not a gate.
- [ ] **Tests.** `tests/bin-lib/issues/near-duplicate.test.js`: each signal fires alone; thresholds honoured; exclusions honoured; a fixture built from #1821/#1224's titles and Key Files returns each as the other's candidate; unrelated records return nothing. Prose pins for the shaping step, the drain citation, and the dispatch log line, sized like `tests/specify-decomposition-crossref-prose.test.js`.

## Acceptance Criteria

1. `findNearDuplicates(#1821-shaped, [#1224-shaped, …])` returns #1224 with `signals` including Key Files overlap and title similarity; the same call with unrelated fixtures returns `[]`.
2. `/claude-tweaks:specify #N` on a record whose Key Files and title match an open `ready` record renders the candidate table and appends the candidate to `**Related:**`; when that candidate has an open linked PR, shaping stops with a `needs:decision` Absorb proposal instead of writing `ready`.
3. The headless drain performs the same check and counts the refusal as `failed` (deliberate refusal) with the candidate named in the log line.
4. `dispatch`'s queue pull logs the cross-group candidate line and selects exactly what it selected before the change for the same queue.
5. `npm test` green; `tests/bin-lib/issues/grouping.test.js` (or its sibling) unchanged.
6. Re-running the #1821/#1224 sequence in a fixture queue stops the second shaping at the candidate table; quoted in the PR description.

## Technical Approach

Keep the finder a pure, cheap screen: the shaper still judges (a candidate is not a verdict), and only the one unambiguous case (candidate already has an open PR or is in progress) refuses automatically, mirroring the refusal grounds this sweep applied by hand. Reuse `extractKeyFiles` and the snapshot so no new fetch is added to specify or dispatch. Title similarity is normalization-sensitive; pin the tokenizer with fixtures rather than tuning thresholds in prose.

### Key Files

- `plugin/bin/lib/issues/near-duplicate.js` — new: `findNearDuplicates` with the three signals and exclusions
- `plugin/bin/lib/issues/grouping.js` — reuse `extractKeyFiles`; no behavior change
- `plugin/skills/specify/shaping-mode.md` — candidate step before composition; `**Related:**` append; refusal route
- `plugin/skills/specify/next-mode-shape.md` — cite the step for the drain
- `plugin/skills/dispatch/queue-pull-script.md` — cross-group candidate log line
- `tests/bin-lib/issues/near-duplicate.test.js`; a prose-pin test sibling of `tests/specify-decomposition-crossref-prose.test.js`

## Gotchas

- Stop-word and token normalization decide everything (memory: similarity scores are normalization-sensitive); ship the tokenizer with fixtures, and treat a score as a screen, never a merge decision.
- The snapshot may be stale within a session (`record-snapshot-ttl`); invalidate per `_shared/record-queue-fetch.md` before the check in the drain, which already invalidates between records.
- Reconcile-filed residue records share titles by construction (`reconcile: structurally-stuck on …`); exclude records whose title starts with `reconcile:` (the auto-filed residue carries no origin label, only `bug`) from title similarity, or the drain would flag every one against every other.
- `docs/plugin-structure.md` lists `bin/lib/issues/` modules; add the new module's line.
