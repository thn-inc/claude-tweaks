# 2701: Multiple skills re-ask decisions already resolved by prior input or policy

Surface: terminal

## Current State

Across at least three call sites, a stop asks the user to confirm something a prior input or a resolved project policy had already decided, rather than proceeding or presenting it as a read-only FYI:

1. **A pasted Next Actions-style list with an explicit `(recommended)` marker on one line** is not treated as an implicit selection — the consuming skill still asks "which of these should I run?" with that same line pre-marked Recommended, even though the marker's whole purpose (per `docs/skill-authoring.md`'s Skill handoffs convention — recommended-first, paste-ready commands) is to let a human paste the line they want without further ceremony.
2. **`superpowers:brainstorming`'s scope-assessment step**, when a design's framing could go two ways (e.g. "should we also weigh approach X"), asks a stop specifically to gate *whether to consider* an approach, immediately followed by a second stop asking *which approach to choose* — the first is subsumed by the second and could be folded into one question with the alternative as one of the offered options.
3. **`_shared/pr-first-merge.md`'s (or the calling skill's) merge-path question** ("push + open a PR" vs "merge locally") is asked even when `.claude-tweaks/policy.yml`'s `integration-model: pr-first` has already resolved which applies — CLAUDE.md states this resolution should never be re-derived ad hoc ("Never re-derive which one applies ad hoc — read the resolution, once, per that file"), which by extension means it should not be re-asked as an open choice either once resolved.

Measured on one session: 8 `AskUserQuestion` stops (9 questions) across 5 substantive user turns; 9 of 9 resolved to the pre-marked Recommended option; of the 8 stops, 3 fell into the pattern above.

## Deliverables

- Wherever a skill renders a `## Next Actions`-style block with a `(recommended)`/`(Recommended)` marker and later re-consumes that same text as raw input (e.g. via a paste), treat the marked line as the default selection when the paste is unambiguous, rather than re-asking which option to run.
- In `superpowers:brainstorming`'s scope-assessment guidance (or the calling skill's own framing step, if this repo layers one on top), fold a "should we also weigh approach X" gate into the immediately-following "which approach" question, offering X as one of the presented options instead of gating access to it with a separate prior stop.
- In whichever skill/shared file renders the merge-path question after `_shared/pr-first-merge.md`'s (or `_shared/integration-model.md`'s) resolution is already known, replace the question with a one-line FYI ("Integration model: pr-first — pushing and opening a PR") and proceed, reserving an actual question for the case where no policy value resolves.

## Acceptance Criteria

- A paste containing a single `(recommended)`/`(Recommended)`-marked line is not re-confirmed via a fresh `AskUserQuestion` when the paste is otherwise unambiguous (no competing marked line, no additional free text implying a different choice).
- Brainstorming's scope-assessment and approach-choice questions collapse into one `AskUserQuestion` call when they would otherwise be sequential and the first is fully subsumed by the second.
- A merge-path decision governed by a resolved `integration-model` policy value renders as a read-only FYI line, not an `AskUserQuestion`, in the default case.

## Release Note

Stopped skills from re-asking decisions that earlier input or project policy already answered.

## Technical Approach

Three independent, separately-verifiable fixes sharing one root cause (a stop re-asks a decision that upstream input or policy already made):

1. **Next Actions paste recognition** — wherever a skill's entry point parses free-text input that could be a pasted Next Actions block (the shape `docs/skill-authoring.md`'s Skill handoffs convention defines), detect a single `(recommended)`/`(Recommended)`-marked line with no competing marker and treat it as the selection, skipping the re-confirmation `AskUserQuestion` for that ambiguity-free case only.
2. **Brainstorming scope-assessment merge** — locate the two sequential stops (a "should we consider X" gate immediately followed by "which approach") in `superpowers:brainstorming`'s scope-assessment guidance, and merge them into one `AskUserQuestion` call whose options include X directly, removing the prior gating question.
3. **Merge-path FYI** — locate the merge-path `AskUserQuestion` in `_shared/pr-first-merge.md` (or its caller) and gate it on whether `integration-model` already resolved to a definite value (`_shared/integration-model.md`'s resolution); when it has, render a one-line FYI and proceed instead of asking.

Each fix should be independently testable against a captured session transcript exhibiting the pattern (the Original request cites concrete evidence for all three), and none should suppress the underlying question when the resolving input is genuinely ambiguous or absent.

### Key Files

- `plugin/skills/_shared/pr-first-merge.md` — the merge-path question, gated on `integration-model` resolution
- `plugin/skills/superpowers:brainstorming` (or this repo's own framing layer on top of it, if any) — the scope-assessment / approach-choice stop merge
- `plugin/docs/skill-authoring.md` — the `(recommended)` marker convention this fix relies on for paste recognition

## Gotchas

- Fix 1 (Next Actions paste recognition) must stay narrow: only collapse the question when the paste is genuinely unambiguous (one marked line, no competing signal in the free text) — a paste with additional context implying a different choice should still ask.
- Fix 2 (brainstorming merge) touches `superpowers:brainstorming`, an upstream dependency this plugin does not own — verify whether the scope-assessment step lives in superpowers itself or in a claude-tweaks layer on top before deciding where the fix lands; an upstream-only fix may need to be filed against that plugin instead of implemented here.
- Fix 3 (merge-path FYI) must still ask when `integration-model` resolves to nothing (an unresolved/ambiguous case) — the FYI-only path applies exclusively when CLAUDE.md's own resolution note says the value is already known.
