# 3056: Run /prompt-audit against claude-tweaks' own CLAUDE.md and skills

Surface: infra

## Current State

Claude Code 2.1.283+ ships a built-in `/prompt-audit` command. It reads CLAUDE.md files, skills, agents, and custom commands, and flags instructions written for older models, stale paths, and contradictory rules (source in the original request below).

What claude-tweaks already has in this space:

- `/claude-tweaks:harness-health` (`plugin/skills/harness-health/SKILL.md`) audits `.claude/skills/*.md`, `.claude/rules/*.md` and CLAUDE.md against the codebase, a template, and best practice, one target per firing. It then files `by:harness-health` issues. Its stated scope is the project's own `.claude/` tree (this repo has 17 files under `.claude/skills/`), not the 39 shipped `plugin/skills/*/SKILL.md` files. Its target discovery reads only `<root>/.claude/skills` (`plugin/bin/lib/harness-health/scope.js:198`).
- `docs/skill-authoring.md`'s "Model-version prompting notes" section (line 215) is a manual checklist to re-run whenever a new Claude model ships. It covers model-version deltas and a verification/self-check instruction audit against `docs/reference/claude-quality-levers.md`. That is the "instructions written for older models" concern, done by hand.

So the open question has two parts: what `/prompt-audit` catches that neither harness-health nor the manual model-version checklist catches, and whether it reaches the shipped `plugin/skills/` library at all.

## Deliverables

1. Run `/prompt-audit` once against this repo's CLAUDE.md, `.claude/skills/`, `plugin/skills/`, and `plugin/agents/`, and keep its raw output.
2. A comparison, posted as a comment on this record, that sorts each finding into one of three buckets:
   - already covered by harness-health (name the harness-health check);
   - already covered by the model-version prompting checklist in `docs/skill-authoring.md`;
   - genuinely new.
3. For each genuinely new finding, take exactly one of two routes:
   - a backlog record via `/claude-tweaks:capture` with a spec-shaped body, either fixing the flagged instruction or extending harness-health or the checklist to catch that class;
   - a stated reason, in the comment, why it is not worth acting on.

## Acceptance Criteria

- `/prompt-audit` has been run once over the targets in Deliverable 1. The comment states the Claude Code version used and the target set actually covered.
- Every finding in the run's output appears in the comparison comment under exactly one of the three buckets.
- Every genuinely new finding has either a linked filed backlog record or a stated reason for no action; none is left unrouted.
- The comment states whether `/prompt-audit` reached the `plugin/skills/` library, since harness-health does not.

## Release Note

No user-facing change. This produces an internal comparison of Claude Code's `/prompt-audit` against claude-tweaks' own harness-health audit.

## Technical Approach

Run `/prompt-audit` from an interactive session at the repo root. Then work through its findings against two references: harness-health's analysis criteria (`plugin/skills/_shared/harness-health-analysis.md`, the shared judge procedure) and the model-version checklist. Fixes to individual skills are not made in this record; they are filed as follow-ups so each lands with its own conformance-test run.

### Key Files

- `plugin/skills/harness-health/SKILL.md` — the existing audit whose coverage is compared
- `plugin/skills/_shared/harness-health-analysis.md` — harness-health's shared judge procedure
- `docs/skill-authoring.md` — the manual model-version prompting checklist (line 215)
- `docs/reference/claude-quality-levers.md` — the levers that checklist audits against

## Gotchas

- ASSUMPTION — verify at build: `/prompt-audit` can be run on demand in this environment and accepts the `plugin/` subtree as a target. It is a built-in slash command, so a headless agent may not be able to invoke it the same way. Confirm before relying on an unattended run.
- Fixing a flagged skill instruction here would touch shipped prose that conformance tests pin repo-wide (`tests/` byte-pins skill text). That is why fixes go to follow-up records, each with its own full-suite run.
- harness-health's own scope is `.claude/` by design. A finding that it misses on `plugin/skills/` is a scope question, not automatically a harness-health defect.
