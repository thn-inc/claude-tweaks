# 4486: Write gate assumes a case arm always runs, so a cd in an unmatched arm hides a write

Origin: ledger resolve gate

Defer-reason: genuinely-larger

## Current State

`plugin/bin/lib/hooks/git-command.js`'s cd walk assumes a `case` arm always runs, so a `cd` in an arm reaches the commands after `esac` even when no pattern matches. `case $x in a) cd /wt;; esac; echo x > f` resolves only `/wt/f`; bash 3.2 and 5 write `./f` when `$x` is not `a`. Pre-existing; #4481 (ledger row 1, SDD Task 1 review) recorded it, and `plugin/skills/_shared/policy-schema-coverage.md` lists it as a known gap ("a case arm whose pattern does not match").

**Related:** #4487, #4489

## Deliverables

After a `case` whose arms carry no catch-all `*)` pattern, carry the cwd before the case as well as each arm's cwd into the commands after `esac`, failing closed.

Pin `case $x in a) cd /wt;; esac; echo x > f` (both `/wt/f` and `./f`) and the catch-all form `case $x in a) cd /wt;; *) cd /q;; esac; echo x > f` (no `./f`), with bash 3.2/5 verdicts.

## Acceptance Criteria

`fileWriteTargets('case $x in a) cd /wt;; esac; echo x > f', '/r')` includes `/r/f` and `/wt/f`.

Each new test fails with the change reverted; the hook suites pass; the known-gaps clause is removed from policy-schema-coverage.md.

## Release Note

The worktree write gate no longer assumes a `case` arm runs when no pattern may match.

## Technical Approach

### Key Files

- `plugin/bin/lib/hooks/git-command.js` — join the pre-case cwd after a case with no catch-all
- `tests/hooks-gate-coverage.test.js` — pin both shapes
- `plugin/skills/_shared/policy-schema-coverage.md` — drop the known-gap clause
