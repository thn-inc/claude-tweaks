# 1425: subagent-stop.js contract-violation events stamp a foreign session's run dir — ownedRun scoping missing at this call site

**Related:** #1431

Origin: reflect full (conversation wrap-up, tidy-followups)

Defer-reason: tangential

## Current State

`bin/lib/hooks/subagent-stop.js:50` appends its `contract-violation` event to `ctx.runDir` — the session-agnostic newest-non-terminal resolution — with none of the `ownedRun` scoping `pre-tool-use.js`'s gate-denial breadcrumb received in the [IL-96] fix (see that file's comment at the gate-denial call site). With parallel sessions active, a sibling session's Task-agent stop stamps whichever run dir is newest. Observed live 2026-08-24: a fresh standalone wrap-up run dir (`2026-08-24T183516-tidy-followups-standalone`) received a `contract-violation` event ("**Verdict: FINDINGS** (2 prose fixes; code is correct)" — a review-agent verdict from one of three concurrently active sibling dispatch pipelines) 10 seconds after creation, before the owning session had dispatched any Task agent. Double harm: the foreign run's friction-lens input is polluted, and the sibling run that actually experienced the violation records nothing.

## Deliverables

- `subagent-stop.js` scopes its `appendEvent` to the calling session's own run (`ctx.ownedRun`, same pattern and rationale as pre-tool-use.js's gate-denial breadcrumb: [IL-96]), degrading to a silent no-op when the session owns no run — never to the unfiltered `ctx.runDir`.

- A `tests/` hooks case pins the scoping: a SubagentStop payload arriving while `ctx.ownedRun` names run A and `ctx.runDir` names run B writes the event to A only (and to nowhere when `ownedRun` is unset).

## Acceptance Criteria

- With two run dirs present (owned + newer foreign), the contract-violation event lands only in the owned run's events.jsonl.

- With no owned run, no event is written and the hook still returns cleanly (never-break-a-session invariant).

- Existing subagent-stop tests pass unchanged.
