# 5914: Report pipeline spend, the driver admission funnel and filed records from transcripts

Surface: backend
Risk-flags: none

## Overview

A maintainer-side report, `tools/pipeline-cost-report.js`, that measures what the pipeline costs and how much work it files, from session transcripts, run directories and the forge. It reproduces the spend, driver-funnel and filed-record tables in `docs/superpowers/specs/2026-11-18-pipeline-economy-design.md`'s `## Evidence`, so every later phase of that design can state its effect as a before-and-after reading of one command. Those tables were produced once by scratch scripts that no longer exist in the repository.

**Complexity:** Medium
**Estimated tasks:** 6

## Non-Goals

- The quality-guard measures (whole-branch review results, first-pass rate, post-merge bug records): a separate record adds them to the same tool.
- Any change under `plugin/`. The tool only reads.
- Real invoices. Dollars are list-price equivalents of recorded token usage.
- Replacing `tools/efficiency-report.js`, which reports medians from `timing.json` and stays as it is.

## Deliverables

- [ ] `tools/pipeline-cost-report.js` with `--since <YYYY-MM-DD>`, `--until <YYYY-MM-DD>`, `--projects <dir>`, `--pipelines <dir>`, `--match <substring>`, `--section spend|funnel|records|all`, `--repo <owner/name>` (default: resolved from `origin`), `--simulate <reason[,reason...]>` (repeatable) and `--json`. The window includes `--until`, is in UTC, and a message belongs to it by its own timestamp. `--match` filters transcripts by a substring of the session's working-directory path. `--projects` roots are deduplicated by real path.
- [ ] Section `spend`: list-price dollars by session type, by model family, by main session or subagent, by prompt-size bucket, and cache-write dollars by cause (ordinary growth, model switch, compaction, an hour or more since the last model call, session start).
- [ ] Section `spend` also prints merged pull requests in the window and dollars per merged pull request, total and for build sessions (`flow` and `dispatch`).
- [ ] Section `funnel`: `drive.js --check` over every open record labelled `ready` and `auto:build`, the count admitted, the count per refusal reason, and, for each `--simulate` set (default: one set per distinct refusal reason, taken alone), the count that would be admitted if those reasons stopped refusing. The section is a point-in-time reading stamped with its run date and the plugin version. A `--check` that fails, times out, or prints no `admitted` and `reasons` fields counts under `unreadable`.

The long-prompt multiplier applies to every price column. - [ ] `docs/superpowers/specs/2026-11-18-pipeline-economy-baseline.md`: the tool's output for 2026-11-08 to 2026-11-18, committed, with a header stating the run date, the window rule, and the design's headline figures ($18,851, 164 merged pull requests, 317 of 586 records filed as deferrals, 207 closed) beside the measured ones.
- [ ] Tests for each section over fixture transcripts and fixture `--check` verdicts.

## Acceptance Criteria

1. On a fixture transcript holding one `message.id` on three lines with rising `output_tokens`, the `spend` section counts that message once, at the highest value of each usage field.
2. On a fixture with one Haiku request whose prompt is 120,000 tokens and one whose prompt is 80,000, the first is priced at five times the per-token rate of the second.
3. A fixture session whose first invoked claude-tweaks skill (a `Skill` call or a typed `/dispatch` line, whichever comes first in the transcript) is `claude-tweaks:dispatch` is reported under `dispatch`; a session that invoked no claude-tweaks skill is reported under `no skill invoked`; subagent spend is attributed to its parent session's type, and a subagent whose parent transcript is missing is reported under `unattributed`.
4. A turn that writes more than half its prompt and more than 40,000 tokens to cache is classed as a re-write, and its cause is `model switch` when the previous model call in that transcript used another model family.
5. With fixture verdicts, `funnel` prints the admitted count, one row per distinct refusal reason, and for a named set of reasons the count of records whose every reason is in that set.
6. `records` counts a created record as deferred only when its body holds a line matching `Defer-reason:`, and prints one row per reason word.
7. `--json` prints one JSON object holding the same figures as the Markdown output for every section.
8. A transcript or run directory that disappears or cannot be parsed during the scan is counted in a printed `unreadable` figure, and the run exits 0.
9. No file under `plugin/` changes, and no file under `plugin/` references `tools/pipeline-cost-report`.

## Release Note

Added a maintainer report of what the pipeline costs per session type, model and merged pull request, and how much follow-up work it files.

## Technical Approach

One CLI over three readers, each a module with an injected `deps` (file system, `gh` runner, clock) so tests run on fixtures. Session type is the first claude-tweaks skill a main session invoked, read from a typed `<command-name>` in a user line or a `Skill` tool call. Prompt size per request is uncached input plus cache read plus cache write.

### Data / API Surface

- Price table, dollars per million tokens as `[input, output, cache read, 5-minute cache write, 1-hour cache write]`: Fable `[8, 40, 0.2, 10, 16]`, Opus `[4, 20, 0.2, 5, 8]`, Sonnet `[2, 10, 0.1, 2.5, 4]`, Haiku `[0.1, 0.5, 0.01, 0.125, 0.2]` times five when the request's prompt exceeds 100,000 tokens. Dated 2026-11-03.
- Cache-write cause, first match wins: `session start` (the first model call of a transcript), `model switch`, `compaction`, `idle` (an hour or more since the previous model call), else `ordinary growth`. A write below the re-write threshold is `ordinary growth`.
- Prompt-size buckets in thousands of tokens: under 50, 50-100, 100-150, 150-200, 200-300, 300-400, 400-500, 500-700, over 700.
- `--json` shape: `{ window, spend: { total, bySessionType, byModel, byBucket, cacheWrites, perMergedPr }, funnel: { checked, admitted, reasons, simulations }, records: { created, closed, open, deferred, byReason }, unreadable }`.

## Decision Rationale

Absorbed from `docs/superpowers/specs/2026-11-18-pipeline-economy-design.md`.

- The pipeline cost $18,851 at list prices over 8 to 18 November 2026 for 164 merged pull requests. Main sessions were 41% of it, and 81% of main-session spend fell on turns over 200k tokens. The driver lane built three records for under a dollar each and admits 11% of authorized records.
- Runs filed 317 of the 586 records created in the window as deferrals; 207 records were closed.
- The design's tiers are: quick wins (this report, the driver worker's test runs, explicit driver models, limits on work a run may file), fast follows (wider driver admission, routing, implementer tier from the record, lens selection, a factory policy layer), and longer term (the plan made with the spec, the driver as the drain, review replay).
- Every new behaviour ships as a policy value whose default reproduces today. This repository opts in first, and a default changes only after 20 runs with the value on show the quality guards no worse.
- Rejected: re-tiering models alone, which caps near 1.7 times cheaper; and removing reviews, since the whole-branch review finds a Critical or Important issue in 70% of runs after every task review has passed.

## As-Built Deviations (Common Step 4.5, classified Beneficial)

1. Default spend scope: with no `--match`, transcripts are limited to the main checkout and its worktrees, and a `Match:` line (and `window.match` in JSON) names the scope; `--all-projects` widens it to every project. The spec set no default, and the unscoped default mixed every project on the machine (4.3× inflation of the per-merged-PR figure on 2026-11-18).
2. `--repo` is refused for `--section funnel|all` when it names a repository other than the current checkout's, since `drive.js --check` always reads the checkout's own repository.
3. `--json` carries the spec's shape plus `priceTableDate`, `spend.unpriced`, `spend.byAgent` and `runs`; nothing in the specified shape is renamed or dropped.
4. Usage is read from the raw transcript lines rather than through `readUsage` — the ASSUMPTION gotcha was reversed at build (readUsage exposes neither the 5-minute/1-hour cache-write split nor `message.id`); the maximum-per-`message.id` rule is implemented in `tools/pipeline-cost-report/spend.js`.
5. Key Files additions: `tools/pipeline-cost-report/runs.js` (pipeline run-directory listing shared by the sections) and `tests/pipeline-cost-report/cli.test.js` (CLI flag and rendering tests).
6. The default `--repo` is resolved with `gh repo view` (gh's own default remote) rather than read from `origin` as the Deliverables line states.
