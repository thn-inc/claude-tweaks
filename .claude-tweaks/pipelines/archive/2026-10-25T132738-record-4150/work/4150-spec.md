# 4150: refreshOwnerBlock resolves the owner pid (up to 8 ps spawns) before checking the heartbeat throttle

Verified-as-of: 1813941ecfe019b89307ea75526f2c863ffb5e1e

Origin: /claude-tweaks:release v6.153.0 release-gate review (staged/review-2.md, run 2026-10-24T152958-release-standalone)

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/bin/hooks.js:1830` calls `refreshOwnerBlock` on every non-session-start hook event. In `plugin/bin/lib/hooks/context.js:877` it runs `resolveOwnerPid(env)` before the `HEARTBEAT_THROTTLE_MS` check (~:896-899). Without `CLAUDE_PID`, `resolveOwnerPid` falls back to `ancestorClaudePid` (`run-liveness/process-probe.js:45-63`): up to `MAX_ANCESTOR_HOPS = 8` synchronous `ps` calls with a 2 s timeout each, on every PreToolUse/PostToolUse. When the walk finds nothing, `owner.pid` stays null and the failing walk repeats on every event.

## Deliverables

1. On the heartbeat branch, check the throttle window before any pid probe that cannot change the outcome.
2. Or cache the resolved owner pid (including a negative result) per process.
3. Test in `tests/hooks-context.test.js` that a call inside the throttle window spawns no `ps`.

## Acceptance Criteria

- Inside the throttle window, `refreshOwnerBlock` makes no process-probe call (asserted with an injected probe).
- Outside the window, the owner block is still restamped.
- The new test goes red against the current ordering.
- `npm test` passes.

## Release Note

Hook events no longer pay for a process-tree walk on every tool call while the run owner's heartbeat is fresh.

## Technical Approach

### Key Files

- `plugin/bin/lib/hooks/context.js` — throttle before pid resolution
- `tests/hooks-context.test.js` — no-probe-inside-window case
