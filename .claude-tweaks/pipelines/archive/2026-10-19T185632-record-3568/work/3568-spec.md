# 3568: windows-regression: baseline workflow_dispatch runs against the integration branch, not HEAD^1

Origin: reflect light from #3518

Defer-reason: tangential

## Current State

`.github/workflows/windows-regression.yml`'s "Resolve the comparison base" step uses `github.event.before` and falls back to `HEAD^1` when that is empty, which is always the case for `workflow_dispatch`. A dispatch on a feature branch therefore baselines against the branch's previous commit. When the fix under test already sits in that previous commit, the run reports `pass (baseline-adjudicated ...)` from comparing a tree against a tree that already contains the fix, so the adjudication line says nothing about whether the tests pass. Observed on run 39214305973 (record #3518, base `60a8ef7` already carrying the test fix): the green verdict was only meaningful because the per-test `ok` lines in the run's `tests.log` could be read directly.

## Deliverables

- [ ] Make a `workflow_dispatch` run resolve its comparison base to the merge-base with the integration branch (or accept an explicit `base` input defaulting to it), instead of `HEAD^1`
- [ ] Log the resolved base and its source in the step output, as the step already does, so a reader can tell a merge-base run from a `HEAD^1` one

## Acceptance Criteria

- [ ] A `workflow_dispatch` run on a branch whose earlier commit already fixes a failing test is adjudicated against the integration-branch tip, not the previous branch commit, so the fixed test no longer reads as passing at base
- [ ] A `push` run still baselines against `github.event.before`, unchanged
