# 2007: Route the multi-spec Review Console's short-circuit through console-resolve.js

Surface: backend

## Overview

`flow/multispec-review-console.md`'s "Auto-resolution short-circuit" section still carries a hand-rolled per-item resolution procedure (render every section as `AUTO-RESOLVED`, resolve every item per its stated default, log one decisions line per item, write no `console.json`) — the same shape `wrap-up/review-console.md`'s single-spec short-circuit had before #1932 replaced it with one `console-resolve.js --run … --policy console-auto` call. The two consoles' unattended paths have drifted structurally since, and the multi-spec path's missing `console.json` write leaves an unattended multi-spec run un-archived by `archive-merged.js`'s `readConsoleState` — the same problem #1854 fixed for the single-spec path.

**Design resolved before shaping (the record's own open Deliverables choice):** `console-resolve.js`'s CLI (`plugin/bin/console-resolve.js` ~line 45, 109-110) accepts exactly one `--run <dir>` per invocation, and `bin/lib/console/resolve.js`'s `readSnapshot`/`readMembers` (~lines 101-144) read a single flat run dir's own `work/`, `staged/`, `decisions.md`, `engine-state.json` directly — there is no parent-manifest-aware mode and none should be added here (that would duplicate the multi-spec file's own existing manifest-reading logic in a second place). Since each `spec-{N}/` subdirectory already has exactly that single-run-dir shape, and the multi-spec console's own Step 2 (unchanged by this spec) already reads the parent run dir's own `decisions.md`/`staged/` as a separate unit from each spec's, the correct call pattern is: **once per `spec-{N}/` directory, plus once more over the parent run dir itself** — never a single call over the whole tree.

**Complexity:** Medium
**Estimated tasks:** 3-4

## Non-Goals

- Adding parent-manifest-awareness to `bin/lib/console/resolve.js` itself (a `readMembers`/`readSnapshot` mode that walks `spec-*/` subdirectories in one call) — rejected above; would duplicate logic the multi-spec skill file already owns.
- Changing the single-spec `wrap-up/review-console.md` short-circuit (#1932's already-shipped call) in any way.
- Changing the bundle-level branch-finish/merge decision's own carve-out logic (needs-human, ungranted-member — both already documented in the file's existing "Auto-resolution short-circuit" prose) — see Gotchas below for why each `console-resolve.js` call's own per-spec `merge.resolution` field must NOT be wired into that bundle-level decision.

## Technical Approach

Mirror `wrap-up/review-console.md`'s already-shipped one-call pattern (#1932), extended to N+1 calls (one per spec dir, one for the parent) rather than one call over a hypothetical parent-aware mode — because `console-resolve.js`'s `--run` is single-directory by construction, adding parent-awareness to the resolver itself would duplicate logic the multi-spec skill file already owns for reading per-spec directories (Step 1's manifest read). Failure isolation across the fan-out reuses the file's own existing precedent from Step 3's engine call rather than inventing a new pattern.

## Gotchas

- Do not add a parent-manifest-aware mode to `bin/lib/console/resolve.js` — rejected in Non-Goals; the multi-spec skill file already owns manifest-reading, and duplicating it in the resolver creates two places that can drift.
- The bundle-level merge decision is genuinely NOT the same computation as any single spec's `console-resolve.js` call — each call only sees its own spec dir's grants/verdicts, never the bundle's other members. Wiring a per-call `merge.resolution` into the bundle decision would silently break the existing needs-human/ungranted-member carve-outs, which are computed across ALL members. This is the one correctness risk in this spec that the original record's Deliverables didn't call out at all — flagged explicitly so the implementer doesn't introduce it.
- Mirror Step 3's existing per-spec failure-isolation precedent (Current State above) for the fan-out — don't let one malformed spec dir abort the whole console.
