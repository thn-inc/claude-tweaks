# 1903: Add conformance test banning process.exit() inside require.main guards in plugin/bin/**/*.js

## Current State

Three separate records have now each closed the identical `process.exit(run(...))` compute-then-exit stdout-truncation idiom in a different `plugin/bin/*.js` file: #1176, #1313, and #1535. Each was found by a manual `process.exit(` grep sweep over `plugin/bin/*.js` — and each sweep missed at least one file the previous sweep had already missed, since the violation this record (#1535) fixed was only discovered as a byproduct of #1313's own final whole-branch review. The contract this idiom violates is already documented — `plugin/skills/gh-api-module-pattern/SKILL.md`'s CLI wrapper contract section states the `require.main === module` guard must set `process.exitCode = run(...)`, never call `process.exit()` directly, because the latter can truncate a pending stdout write for a piped consumer — but nothing enforces it mechanically. A fourth recurrence is only a matter of time without a mechanical check.

#1535's final whole-branch review (opus, high effort) verified two existing exceptions to the rule are safe and should be allowlisted rather than flagged: `plugin/bin/hooks.js:1273` (`main(process.argv).then((code) => process.exit(code)).catch(() => process.exit(0));` — all of this file's own stdout goes through `fs.writeSync(1, ...)`, a synchronous call with nothing pending to flush) and `plugin/bin/lib/statusline-wrapper-source.js` (a wrapper that deliberately hard-stops on the child process's own exit code — the hard stop is the intended behavior, not a bug).

## Deliverables

- Add a `node --test` conformance test (e.g. `tests/bin-lib/exit-code-conformance.test.js`) that walks `plugin/bin/**/*.js`, finds each `require.main === module` (or equivalent) entry-point guard, and fails if that guard calls `process.exit(...)` directly instead of assigning `process.exitCode = ...`.
- Allowlist exactly two entries, both re-verified against the current file content at implementation time (not just copied from this record): `plugin/bin/hooks.js` and `plugin/bin/lib/statusline-wrapper-source.js`.
- Confirm the test fails (red) against a synthetic fixture carrying the violating idiom before wiring it against the real `plugin/bin/**/*.js` tree, per this repo's TDD convention.

## Acceptance Criteria

1. The new conformance test passes against the current `plugin/bin/**/*.js` tree with exactly the two allowlisted exceptions above and no others.
2. Reverting either #1313's or #1535's fix (reintroducing `process.exit(run(...))` in the affected file) makes the new test fail.
3. `npm test` passes in full.
