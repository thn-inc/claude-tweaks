# 2773: console/resolve.js SECTION_MAP: the curation engine's own wrap-up-claude-md-/wrap-up-adr- staged prefixes are unmapped (silently never applied at unattended), and .shadow-dup is reported as a duplicate even when divergent

Origin: consolidated Review Console — run `2026-09-21T213441-spec-2697-2757-2758-2759`; found while executing `flow/multispec-review-console.md`'s Auto-resolution short-circuit against this run's five run directories

Defer-reason: tangential

## Current State

Two defects in `plugin/bin/lib/console/resolve.js`'s `SECTION_MAP`, both observed live on this run's
parent run directory.

### 1. The curation engine's own staged prefixes are not in `SECTION_MAP`

`bin/wrap-up-engine.js`'s `claude-md` and `decision-records` registry rows stage their findings as
`staged/wrap-up-claude-md-{n}.md` and `staged/wrap-up-adr-{n}.md`. Neither prefix appears in
`SECTION_MAP`, so `classifyStagedItem` falls through to its catch-all and the resolver reported:

```
| 5 | Pending review | wrap-up-adr-1.md       | AUTO-RESOLVED: pending | unmapped-prefix |
| 6 | Pending review | wrap-up-claude-md-1.md | AUTO-RESOLVED: pending | unmapped-prefix |
| 7 | Pending review | wrap-up-claude-md-2.md | AUTO-RESOLVED: pending | unmapped-prefix |
```

All three belong in **Configuration updates** — `ENGINE_ROW_SECTIONS` already maps `claude-md` and
`decision-records` to `SECTIONS.CONFIG`, and the console's own "On approval" step 5 says config
updates (CLAUDE.md, rules, ADRs) apply under Approve-all. The engine-row path only emits rows whose
`action` is `applied`, so a `staged` engine finding reaches the console **only** through the
staged-file path — which is exactly the path that does not recognize it.

Consequence: at `unattended`, a `consoleAutoResolve` run silently leaves every engine-staged
CLAUDE.md/Don'ts/ADR proposal unapplied and merges anyway. The `unmapped-prefix` fallback is
fail-safe by design ("a new producer can never slip past the console"), and it did its job here — but
these are not new producers, they are the engine's own, and the mismatch means the curation engine's
`claude-md` and `decision-records` rows are effectively inert under auto-resolution. This run had to
apply all three by hand against the skill's own prose.

### 2. A `.shadow-dup` is not always a duplicate

`SECTION_MAP`'s first row classifies any `*.shadow-dup` as `shadow-dup-collision` with the comment
"is a duplicate of some other staged file, not a proposal of its own." That is a guess, and on this
run it was wrong for 2 of 7: `spec-2758/staged/build-deviation-1.md.shadow-dup` and
`build-deviation-2.md.shadow-dup` hold **different findings** from their anchored namesakes — real
proposals recovered from a clobbering write (see the `stage-item.js` id-allocation record). The other
5 (all in `spec-2757/`) were byte-identical, as the comment assumes.

Resolving to `pending` is the right *stance* either way, so nothing was lost here. The defect is the
stated **reason**: it tells a reader the file is redundant when it may be the only surviving copy of a
finding. `hooks.js sweep-shadow` already computes duplicate-vs-divergence; the resolver throws that
away and re-guesses.

## Deliverables

- Add `wrap-up-claude-md-` and `wrap-up-adr-` to `SECTION_MAP`, both routing to `SECTIONS.CONFIG`.
  Audit every staged prefix the engine and the skill corpus can actually write against the table, and
  add a test that fails when a producer writes a prefix the table does not know.
- Make the `.shadow-dup` row's reason honest: compare against the anchored file (or read
  `sweep-shadow`'s own verdict) and report `shadow-dup-duplicate` vs `shadow-dup-divergent`. A
  divergent copy must read as a real proposal awaiting a human, not as a redundant copy.

## Acceptance Criteria

A run directory containing `wrap-up-claude-md-1.md` and `wrap-up-adr-1.md` resolves them under
Configuration updates with an `approve` resolution, not `pending — unmapped-prefix`. Pinned by a test.

A test walks the producer set (engine row ids plus the skill corpus's staged filenames) against
`SECTION_MAP` and fails on any prefix with no row — so the next producer added cannot reintroduce
this.

Given one byte-identical and one divergent `.shadow-dup` beside their anchors, the resolver reports
two distinguishable reasons.
