# 2004: report.js writeReportAtomic is exported and tested but never called — wire it into verify.js or remove it

Surface: backend

## Overview

`plugin/bin/lib/verify/report.js` exports `writeReportAtomic`, tested but never called: `verify.js` and `stamp.js` both write JSON through `plugin/bin/lib/verify/atomic-write.js`'s `writeJsonAtomic` instead — a plain, non-pid-suffixed `.tmp`-then-rename.

**Design resolved before shaping (the record's own Open Question):** read both modules directly. `writeReportAtomic` isn't a standalone mechanism — it thinly wraps `plugin/bin/lib/atomic-write.js`'s `writeFileAtomic`, which is this codebase's own **dominant, already-adopted** atomic-write convention: a pid-suffixed tmp file (`{path}.tmp-{pid}`), the shared primitive behind four other consolidated call sites since #1653 (`json-store.js`, `log-decision/append.js`, `flow/manifest.js`, `hooks/context.js`). What `verify.js`/`stamp.js` use instead — `lib/verify/atomic-write.js`'s `writeJsonAtomic` — is a narrower, separately-extracted primitive (plain `.tmp`, no pid suffix) from an earlier, unrelated consolidation (#892/#881, deduplicating a 4-line pattern between `report.js` and `count-stamp.js`, not a collision-safety concern). Checked every caller of `lib/verify/atomic-write.js`: exactly two, both inside the verify subsystem this spec touches (`verify.js` lines 370 and 392, `stamp.js` line 55) — migrating both retires the narrower module entirely, not just marks the dead export used.

**Keep and wire, not delete.** The pid-suffixed convention is more defensive and already the codebase's dominant pattern — reusing it here is more consistent than keeping a second, narrower atomic-write primitive alive for no reason once nothing requires its distinct behavior. This project has real precedent for concurrent-session collisions inside a shared checkout (index.lock races between sibling sessions are a documented, recurring operational fact here), so the more defensive shape costs nothing and buys real margin even though `verification.md`'s foreground rule makes same-session collisions unlikely today.

## Technical Approach

Two call sites migrate to the codebase's existing dominant atomic-write primitive rather than inventing a third variant; the now-fully-redundant narrower module is deleted outright rather than left as an unused-but-harmless leftover, since "one writer" (the record's own stated goal) is best satisfied by removing the alternative entirely, not merely by routing traffic away from it. The legacy bare-SHA twin write in `stamp.js` is left untouched (Non-Goals) since it's independently transitional and unrelated to this spec's collision-safety concern.
