# 3378: Forward per-task implementer and review tiers for marked plan tasks

Surface: backend

## Overview

Part of the "Build dispatch cost shape" decomposition (origin #3229). In the measured 10-task build only one of nine implementers and none of the thirteen re-reviews ran on the cheapest tier, while the three top-tier task reviews all caught real defects (a crash on a JSON column write, a lost undo control, a race with no guard). SDD's Model Selection already says transcription implementers and single-file mechanical fixes take the cheapest tier and scoped re-reviews of small fix diffs take a cheap-to-mid tier, but it leaves the call to the controller on every dispatch. Under `/build`, `dispatch.md` makes it worse: the spec header's `size:` maps every implementer in the spec to one profile (low to Fast, medium to Standard, high to Capable), so a mechanical task in a `size: medium` spec never reaches Fast, and `dispatch.md` pins no tier for task reviews or re-reviews at all.

This record makes that call deterministic for `/build` runs. The plan author tags each task at authoring time with two optional markers — an implementer role (`transcription`, `integration` or `judgment`, SDD's own complexity signals decided once at plan time) and a review risk (`high` for concurrency, decision logic or rendering-heavy UI), and `dispatch.md`'s SDD invocation forwards tiers only for tasks that carry a marker. A plan with no markers gets exactly today's forwarded text.

**Complexity:** Medium
**Estimated tasks:** 6-8

## Non-Goals

- Skipping any per-task review or any re-review. The "controller verifies a no-code fix round with no re-review" idea contradicts SDD's text ("The fix was small, skip the re-review" is in its rationalization table) and is not done here; a small fix still gets a re-review, only on a cheaper tier.
- Overlapping task N's review with task N+1's implementation. SDD's loop is sequential; not done here.
- Changing behavior for plans without markers, or changing `dispatch.md`'s `size:` mapping and `profile=` semantics for untagged tasks. The `profile=frontier` guard is untouched.
- Rewriting writing-plans' code-density rules (upstream 7.0.0 already has them).
- Merging adjacent tasks (a separate record in this decomposition).

## Release Note

Added optional per-task role and review-risk markers to build plans so mechanical tasks run on cheaper model tiers while high-risk tasks keep a top-tier review.

## Technical Approach

Decide the role and risk once, at plan time, where the author has the full task text, and make the dispatch rule a pure function of the markers. The parser extracts markers per task block; `dispatch.md` runs the plan-audit marker mode once and writes the tier instructions into the same SDD invocation it already composes. Per-task tier instructions are forwarded as choices within SDD's own Model Selection rules (the same way `dispatch.md` already forwards the AC excerpt and the final-review model), never as an override of SDD's loop.

### Data / API Surface

- Plan-audit marker output: `--task-markers {plan}` prints `{"markers": boolean, "tasks": [{ "index": n, "title": "...", "role": "transcription"|"integration"|"judgment"|null, "risk": "high"|null }]}`; findings for unknown values come from the audit checks.
- Tier table (the contract this record adds to `dispatch.md`): implementer role to profile, review risk plus role presence to profile, re-review diff class to profile; all resolved by `resolve-profile.js <profile>`.

## Gotchas

- Steering principle for the whole decomposition: claude-tweaks never files upstream with superpowers and never contradicts SDD's text. Forward instructions that choose within SDD's Model Selection rules; do not tell SDD to skip a review or re-review.
- Expand-contract: every marker is optional and absence reproduces today's behavior byte-for-byte. Plans written before this ships are not re-steered.
- The batched-plan header regex is end-anchored (`^\*\*Execution:\*\*\s*batched\s*$`, multiline, on the header with fenced code blocks stripped) and `[batch]` is matched case-insensitively in task titles. A per-task marker line must not satisfy either, and a marker written inside a fenced example in a plan header must not be read as a real one. Test both directions.
- Anti-goal: a concurrency, decision-logic or rendering-heavy task's review dropping below Capable. Those top-tier reviews are what caught the defects in the measured build. `profile=fast` must never lower a `high` review.
- Anti-goal: a plan without the new markers behaving differently from today. Pin the unmarked case with a test, not a promise.
- With writing-plans 7.0.0 ("The implementer writes the body" — a body appears only for an algorithm the signature and tests do not determine), most mid-size tasks are signature-plus-tests, not complete code. SDD's rule is that the cheapest tier is for tasks whose plan text contains the complete code (transcription plus testing) and that a mid-tier model is the floor for implementers working from prose descriptions, so the authoring guidance must say a signature-only task is `integration`, not `transcription`.
- "Comment-only, or test-file-only with no assertion line added or removed" for the Fast re-review tier is judged from the fix diff by the controller; when unsure, Standard. A test-file fix that corrects an assertion is exactly where a re-review must run a discrimination check, so it is Standard. The re-review is never skipped.
- A marker overrides the `size:` mapping for its task, both ways: in a `size: high` spec an `integration` task runs Standard, in a `size: low` spec a `judgment` task runs Capable. That is intended (the author has the full task text); state it in the authoring guidance so it is not a surprise.
- The missing-`high` guard lives in the plan review, which runs in Spec Mode only and is skipped for `fast-lane` and trivial plans. A design-mode or skipped build that carries markers has no such guard; that gap is accepted.
- Forwarded tiers are keyed by task index and title because SDD addresses tasks by its own identity; both are forwarded so a renumbered plan (the adjacent-task-merge guidance lowers the task count) cannot silently misaddress a tier. The plan must be final before `--task-markers` runs.
- Profile resolution is `bin/resolve-profile.js`, which also applies the model ceiling, stance and session-failure avoidance; never hardcode a model name and never bypass it for Fast.
