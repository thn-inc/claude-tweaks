# 3772: Review Console keeps an unconfirmed finding pending after the same run confirmed it, and lists staged items whose files are gone

**Related:** #3488

Verified-as-of: a7b41a727d09cac4d42b594b7c45fabc42aa70eb

Origin: Review Console residue audit 2026-10-20 — 323 bulk-acknowledged items across 126 runs, read and classified after the fact

Defer-reason: tangential

## Current State

On 2026-10-20 a `console-residue.js --ack-all` acknowledged 323 unreviewed items across 126 runs. Reading them afterwards showed that two console behaviors inflate the residue count with items no human needs to see.

1. **Superseded STAGED lines.** `coordinationItems` (`plugin/bin/lib/console/resolve.js`, around `:398-413`) emits a `keep-staged` Low-confidence (or Contested) item for every `- STAGED` decisions.md line matching `low-confidence|not directly verified|unconfirmed`. It never checks whether a later `- AUTO` line in the same `decisions.md` elevated that same finding ("… finding {path}:{line} elevated via direct-verification override … Confirmed"). Example: run `2026-10-17T192303-spec-3412`'s decisions.md, lines 50-68. Each STAGED reproduction line there is followed within a second by its AUTO elevation, and every one still counted as "no human has reviewed". The same pattern appeared in runs for #3365, #3386, #3431 and #3520.
2. **Missing staged files.** Seven pending items named staged files that no longer exist in their run dir, so the residue line had nothing to `cat`: `docs-1.md`, `docs-2.md` and `skills-1.md` (spec-3376-3386), `wrap-up-docs-1.md` and `-2.md` (record-3258), `doc-update-1.md` (record-3278), `wrap-up-docs-1.md` (record-1909).

Unmapped staged-id prefixes, the third source of mis-sectioned residue, are already #3488 and out of scope here.

## Deliverables

- [ ] `coordinationItems` skips a STAGED line when a later AUTO line in the same `decisions.md` elevates or confirms the same finding, matching on lens + `path:line`. The AUTO line already carries the finding's own outcome.
- [ ] A console item whose staged file is absent gets a distinct resolution (e.g. `missing`). It is excluded from the unreviewed count, and the residue banner names it in one line instead of listing it as pending with no pointer.
- [ ] Tests for both, built from a decisions.md excerpt shaped like spec-3412's (STAGED then AUTO elevation for the same `path:line`) and a console item whose staged file is deleted.

## Acceptance Criteria

- [ ] A STAGED low-confidence line followed by an AUTO "elevated via direct-verification override" line for the same lens and `path:line` produces no Low-confidence item.
- [ ] A STAGED line with no later elevation still produces its `keep-staged` item exactly as today.
- [ ] A pending item whose staged file does not exist is not counted by `console-residue.js` or the SessionStart residue banner as "no human has reviewed".
- [ ] Each new test goes red with its fix reverted.

## Release Note

The end-of-run Review Console and the session-start reminder no longer list review findings the run already confirmed, or staged items whose files are gone, as waiting for a human.

## Technical Approach

### Key Files

- `plugin/bin/lib/console/resolve.js` — coordinationItems supersession + missing-file resolution
- `plugin/bin/lib/console/residue.js` — exclude missing items from the unreviewed set
- `plugin/bin/lib/hooks/session-residue.js` — banner wording for missing items
