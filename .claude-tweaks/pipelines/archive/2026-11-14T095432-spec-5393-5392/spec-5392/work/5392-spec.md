# 5392: Hooks fail open for the whole session when node is not on the session's PATH

Surface: infra
Risk-flags: none

## Current State

**Related:** #3975, #4492, #4494, #4686, #5377, #4318, #4892, #5062, #3822, #3875, #4576, #4846, #4971, #5375, #3813, #3873, #4128, #4217, #4310, #4345, #4353, #4362, #4365, #4442, #4456, #4558, #4591, #4672, #4685, #4737, #4829, #4910, #4989, #5050, #5059, #5100, #5160, #5231, #5266, #5294, #5376, #5387, #5405, #5412, #3788, #4499, #5007

Every registration in `plugin/hooks/hooks.json` (20 entries across SessionStart, UserPromptSubmit, SessionEnd, PreCompact, PreToolUse, PostToolUse, PostToolUseFailure, SubagentStop) is `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" <event>`. When the PATH the Claude Code process started with has no `node`, `/bin/sh` exits 127 before `hooks.js` runs. Claude Code treats that as non-blocking and shows only `Failed with non-blocking status code: exit 127 … the hook's stderr is left out`; the transcript's `hook_non_blocking_error` attachment carries `/bin/sh: node: command not found`. Every gate (the `worktree-always` deny, the write gate, E1, the Review Console ask gate, the bookkeeping-stamp and dispatch-config gates) and every hook-written run artifact (`events.jsonl`, run-state writes) is silently off for the session's whole lifetime, and nothing tells the model or the user.

Observed 2026-11-13: the `/flow` session for spec-5319-5369-5370 (PR #5371) logged 525 such errors (217 PreToolUse:Bash, 22 PreToolUse:Edit, 20 PreToolUse:Write, 8 PreToolUse:Agent, 214 PostToolUse:Bash, plus SessionStart and UserPromptSubmit) and ran its whole build ungated. Three more sessions launched in the same minute were in the same state. Node was installed on that machine; only the session's PATH missed it (an nvm setup whose PATH prepend fires only when `~/.nvm/alias/default` names a literal version directory). Interactive-shell-only node resolution (nvm/fnm/asdf lazy-load stubs are shell functions `/bin/sh` never sees) is common, so this is not a one-machine problem.

Constraints already in the code:

- `docs/hooks.md`'s never-break-a-session invariant: every hook path exits 0, and a deny is expressed as `hookSpecificOutput.permissionDecision: 'deny'` in stdout JSON, never via the exit code. A shell launcher can emit that JSON without node.
- `resolveWorktreeAlways` (`plugin/bin/lib/policy.js`) reads `.claude-tweaks/policy.yml` through `parseFlatLines` (`plugin/bin/lib/policy-schema.js`): a column-0 `worktree-always: <value>` line, value cut at the first `#` and trimmed, the last occurrence winning, ON only when the value is exactly `true`; the deprecated `worktree.always` key is read through `RENAMED_KEYS` when the canonical key is absent. `pre-tool-use.js` reads that file from the main checkout (`wtDetect.mainCheckoutRoot` in `plugin/bin/lib/hooks/worktree-detect.js`), never from the linked worktree's own copy, because many projects gitignore `policy.yml` and a worktree then has none (#4492, #4494).
- `~/.claude-tweaks/` is the existing home-level state directory (`plugin/bin/lib/ports/registry.js` keeps `ports.json` there).
- `tests/hooks-dispatcher.test.js` pins the registration command strings with regexes such as `/bin\/hooks\.js" pre-tool-use$/`.

Decided during `/claude-tweaks:specify` (2026-11-14, maintainer-approved): find node before giving up, including a node path saved by the last session whose hooks ran; when none is found, warn every session and, in projects whose policy sets `worktree-always: true`, deny write-capable tool calls until restart. Projects without that policy are warned only, never blocked (the plugin is often enabled user-wide, and blocking Bash in unrelated projects would break those sessions).

**Decision (plan review Q1, 2026-11-14, maintainer):** the no-node `pre-tool-use` deny covers only Bash, Edit, Write and NotebookEdit. The launcher matches `tool_name` in the stdin it already drains against fixed patterns (no input is interpolated into output), and prints nothing for AskUserQuestion, Agent, Task and ExitWorktree, so the model can still ask the user or leave the worktree. Agent and Task need no deny of their own: the subagents they spawn hit the same no-node hook.

**Decision (plan review Q2, 2026-11-14, maintainer):** the no-node branch resolves the main checkout from the hook process's own cwd and never parses `cwd` out of the stdin JSON, since escaped quotes or backslashes in a path would break a shell pattern on a path that must never break. The plan's live probe records whether the process cwd and the payload `cwd` diverge, and `docs/hooks.md` documents the result. The accepted risk: after a `cd` into a different repository, the shell reads that repository's policy, while the SessionStart/UserPromptSubmit warning still fires.

**Decision (Windows, 2026-11-14, maintainer):** accept that a Windows install without Git Bash, where Claude Code falls back to PowerShell and there is no `sh`, loses every claude-tweaks hook. Git Bash becomes a stated Windows requirement in README's Dependencies table and `docs/hooks.md`.

## Deliverables

- A POSIX `sh` launcher, `plugin/bin/hooks.sh`, through which every `hooks.json` registration runs as `sh "${CLAUDE_PLUGIN_ROOT}/bin/hooks.sh" <event>`, with each registration's event verb unchanged.
- Node resolution in the launcher, first hit wins: `command -v node`; the path stored in `$HOME/.claude-tweaks/node-path` when it names an executable file; the nvm default alias when it names a literal version directory under `$NVM_DIR` (default `$HOME/.nvm`); Volta's `$HOME/.volta/bin/node`; `/opt/homebrew/bin/node`; `/usr/local/bin/node`; fnm's default alias. On a hit it `exec`s that node on `hooks.js <event>`, stdin passed through, so stdout, stderr and exit status are exactly `hooks.js`'s.
- `session-start` (when node runs) saves `process.execPath` to `$HOME/.claude-tweaks/node-path` only when the stored value differs. Best-effort: a failed write never changes the hook's stdout or exit status.
- The launcher's no-node branch, which always drains stdin and exits 0:
  - `session-start` and `user-prompt-submit`: print one `hookSpecificOutput` JSON object whose `additionalContext` says claude-tweaks hooks cannot run in this session because no `node` was found, that every claude-tweaks guard is off, that the user must be told and repository edits should stop, and that the fix is to restart Claude Code from a shell where `node` resolves.
  - `pre-tool-use`: when the main checkout's `.claude-tweaks/policy.yml` turns `worktree-always` on and the payload's `tool_name` is Bash, Edit, Write or NotebookEdit, print a deny. The main checkout is the same root `wtDetect.mainCheckoutRoot` gives the node gate: from a linked worktree, its main checkout. Fall back to the hook's cwd when it can't be resolved. The deny carries `permissionDecision: "deny"` and a reason naming the restart fix. No worktree-isolation check: it denies inside a linked worktree too, on purpose. Otherwise print nothing (allow).
  - Every other event: print nothing.
- The shell policy check agrees with `resolveWorktreeAlways` on every input, pinned by a differential test (below).
- `docs/hooks.md` documents the launcher, the saved node path, and the no-node behavior beside the never-break-a-session invariant, including how Claude Code runs hook commands on Windows (with the source cited) and what that means for `sh`.

## Release Note

claude-tweaks hooks now find node even when it's missing from the session's PATH, and when it can't be found they warn the session, and block edits in worktree-always projects, instead of silently switching every guard off.

## Technical Approach

`plugin/bin/hooks.sh` is a small POSIX script (dash on Ubuntu, bash 3.2 on macOS: no bashisms). It resolves its own directory from `$0`, tries the candidates in order, and `exec`s the first hit on `hooks.js "$@"`. The no-node branch prints fixed JSON literals (no interpolation of any input), so no escaping is needed. The `pre-tool-use` policy check reads the policy file with `grep`/`sed` written to mirror `parseFlatLines` (column-0 key, value cut at the first `#`, trimmed, CR stripped, last occurrence wins, `worktree.always` consulted only when the canonical key is absent). The differential test is the guard against drift between the two (`docs/incident-log.md` `[IL-133]`: an announcement that disagreed with enforcement).

The well-known-location list must be overridable by tests, because CI runners have node in `/usr/local/bin` and toolcache paths. Use a single environment variable that replaces the list, documented as a test seam.

The saved-path write goes in `session-start.js` (one read per session, not per tool call), using the same `~/.claude-tweaks/` directory as `ports/registry.js`.

### Key Files

- `plugin/bin/hooks.sh` — new — node-resolving launcher and the no-node branch
- `plugin/hooks/hooks.json` — modify — route all 20 registrations through `hooks.sh`
- `plugin/bin/lib/hooks/session-start.js` — modify — save `process.execPath` to `~/.claude-tweaks/node-path` when it differs

- `docs/hooks.md` — modify — document the launcher, saved path, no-node behavior, Windows

## Gotchas

- Windows is the anti-goal case: `hooks.json` is shared by every platform, so if Claude Code on Windows does not run hook commands through a shell that has `sh`, this change kills every hook there. Establish how it runs them, from the Claude Code docs or a measurement, before building. If `sh` is not available, stop and bring options back instead of shipping.
- The no-node branch must read stdin to EOF before exiting, so the harness never hits a broken pipe while writing the payload.
- `exec` replaces the shell, so no extra process lingers. The cost per hook call is one `sh` startup plus the `command -v` probe; every Bash tool call runs two hooks, so measure it with `npm run test:perf`.
- Resolving the main checkout in shell: `git rev-parse --path-format=absolute --git-common-dir` needs git 2.31+. Alternatively, mirror `mainCheckoutRoot`'s fs walk (a `.git` file's `gitdir:` line, then that directory's `commondir`). Either must agree with `mainCheckoutRoot` on the test fixtures. `git` may also be missing or slow; fall back to the cwd rather than failing. Claude Code runs hook processes in the session's cwd; confirm that rather than parsing `cwd` out of the stdin JSON in shell.
- An nvm default alias such as `lts/*`, `node` or a partial version like `22` names no literal directory. Skip it rather than guessing a version; the saved path covers this machine's case.
- Tests that strip node from PATH must also empty the well-known list and point `$HOME` at a temp dir, or they will find the runner's own node and pass for the wrong reason.

## Open Question

When no node can be found, should PreToolUse for write-capable tools (Bash, Edit, Write, NotebookEdit) deny through the same `hookSpecificOutput` JSON the node gates use (fail closed), or only warn via SessionStart/UserPromptSubmit context and let the session run ungated? Deny matches what the gates exist to enforce and stays inside the exit-0 invariant, but a session whose Bash is denied cannot easily diagnose itself. Warn-only keeps the session usable but repeats the 2026-11-13 ungated build with a louder label. Middle option, recommended: deny write tools only when the project's `.claude-tweaks/policy.yml` sets worktree-always (readable without node), and warn everywhere else.

## Plan Review Clarifications

- Settled by plan review after an answered round: "Nothing decides what happens when a node is found but can't run `hooks.js`" (an asdf/mise shim with no version set, a Node older than 18). Chose first hit wins as the Deliverables state ("On a hit it `exec`s that node"): the hit is not probed, no later rung is tried, and `docs/hooks.md` states that an unrunnable hit fails as before (non-blocking error, guards off). Not taken: a version probe before `exec` with fall-through to the next rung, which changes the Deliverables' exec-on-hit contract and adds a spawn per hook.
- Settled by plan review after an answered round: "the existing 'skip path cost above bare Node < 60ms' ceiling then no longer measures `sh`" once the perf control is rebased onto `sh`. Chose to keep the perf control as bare `node -e ''`, so the existing ratio and 60ms ceiling include the launcher, which keeps "`npm run test:perf`'s hook budget still passes with the launcher in the path" as written. Not taken: a rebased `sh` control plus a separate launcher-share assertion with a restated budget of about 60ms for `hooks.js` plus 60ms for `sh`, which would loosen that criterion.
- Build deviation (Beneficial, /build Common Step 4.5): `session-start`'s `run(ctx)` passes `ctx.nodePathHome` to `saveNodePath({ home })`; unset, the home stays `process.env.HOME || os.homedir()`. It is a test seam only — every in-process test caller passes a temp home so the suite never writes the developer's real `~/.claude-tweaks/node-path`; production behavior is unchanged.
- Build deviation (Beneficial, /build Common Step 4.5): `plugin/skills/_shared/policy-deprecations.md`'s `worktree.always` removal record now names `bin/hooks.sh`'s `policy_verdict` (pinned by `hooks.sh AC9`) as a second reader, so removing the alias also removes the launcher's `worktree.always:` branch.
- Settled by plan review after an answered round: "On win32 the writer and the reader of the saved path can point at different homes" (Node's `os.homedir()` is `USERPROFILE`; the launcher reads `$HOME`). Chose that `session-start` writes under `process.env.HOME || os.homedir()`, matching the Deliverables' "`$HOME/.claude-tweaks/node-path`" and the launcher's reader on every platform. Not taken: keep `os.homedir()` and accept that the saved-path rung misses on a win32 setup whose `HOME` differs.
