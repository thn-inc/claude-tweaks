# 1592: assess-agent-autonomy merge-check: resolve stale local branch names against origin before blast-radius

## Current State

`assess-agent-autonomy/merge-check.md` Step 1 resolves `INTEGRATION_BRANCH` per `_shared/integration-branch.md`, which (inside a worktree) correctly falls back to the bare GitHub-default branch name, e.g. `"main"`, and passes that bare name straight to `blast-radius.js --integration-branch`.

`review/code-mode-steps.md` Step 2 already carries an explicit guard against exactly this class of hazard for its own `{base}` resolution: "never trust a bare local branch name for `{base}`... resolve it via `git fetch origin {base}` then use `origin/{base}`." `merge-check.md`'s Step 1 has no equivalent instruction before invoking `blast-radius.js`.

Observed live during a `/claude-tweaks:review` merge-check for record #897: the shared checkout's local `main` ref was stale (`b3962148`, well behind `origin/main` at `0efccfdf2`). `blast-radius.js --integration-branch main` resolved the merge base against the stale local ref and reported a wildly inflated blast radius (`implLines=1071`, `implFiles=35`, covering ~38 unrelated commits) instead of the record's actual 6-file/127-line diff. `blast-radius.js --integration-branch origin/main` gave the correct numbers. Caught only because the numbers looked implausible for the record's known scope — a less obviously-wrong stale-branch read could silently produce a false `needs-human` (or worse, a false `auto-merge`) verdict.

## Deliverables

- [ ] Either (a) `merge-check.md`'s Step 1 applies the same fetch-and-prefer-origin discipline `review/code-mode-steps.md` Step 2 already states before calling `blast-radius.js`, or (b) `blast-radius.js` itself resolves `--integration-branch {name}` against `origin/{name}` when that ref exists, falling back to the bare local ref only if it doesn't — the second option fixes every caller (`assess-agent-autonomy`, `residue.js` already defaults to `origin/main` per its own doc note, so this would make the two consistent) at once rather than just this one call site.

## Acceptance Criteria

1. A shared checkout with a stale local `main` (behind `origin/main`) produces the same blast-radius numbers whether `--integration-branch main` or `--integration-branch origin/main` is passed.
2. A test pins the stale-local-branch scenario (fixture repo with local `main` behind a remote-tracking `origin/main`) and asserts the resolved merge base matches `origin/main`'s, not the stale local ref's.
