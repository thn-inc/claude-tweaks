# 1270: Hook-event-simulating tests inherit ambient PIPELINE_RUN_DIR, contaminating the real run's events.jsonl

**Related:** #1242

Origin: ledger resolve gate (spec #991 wrap-up, /reflect full-mode Friction lens)

## Current State

This run's `events.jsonl` carries `gate-denial`/`wd-foreign-session`/`close-without-wrapup`
entries at 08:10:23-24 and 08:27:06-07 pointing at synthetic test-fixture paths
(`ct-disp-repo-*`, `ct-wtd-parent-*`), timestamped exactly at this run's own `npm test`
invocations. This matches this same run's `/claude-tweaks:test` decisions.md entry, which
independently attributed transient failures in `hooks-dispatcher.test.js`/`pr-state.test.js` to
"ambient PIPELINE_RUN_DIR ... leaking" into those tests — the same root cause from two angles: a
hook-event-simulating test spawns a child process that inherits the real ambient
`PIPELINE_RUN_DIR` from the shell, so its synthetic events land in the real run's `events.jsonl`
instead of an isolated fixture location.

## Deliverables

- Have hook-event-simulating tests (`hooks-dispatcher.test.js`, `pr-state.test.js`, and any other
  test spawning `bin/hooks.js` as a child process) explicitly unset or override
  `PIPELINE_RUN_DIR` in the spawned child's environment.
- Audit for other spawn sites in `tests/` with the same pattern (any `execFileSync`/`spawnSync`
  call into `bin/hooks.js` that doesn't already control its child env).

## Acceptance Criteria

Running the full suite with `PIPELINE_RUN_DIR` set in the parent shell's environment produces no
synthetic `ct-disp-repo-*`/`ct-wtd-parent-*` (or similar test-fixture-path) entries in the real
run directory's `events.jsonl` — verified by a regression test that sets `PIPELINE_RUN_DIR` before
running the affected test file(s) and asserts the real run dir's `events.jsonl` is untouched.
