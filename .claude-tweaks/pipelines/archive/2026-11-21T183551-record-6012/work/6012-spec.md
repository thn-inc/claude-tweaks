# 6012: Show in the cost report whether admitted records ever reached the driver

Surface: backend
Risk-flags: none

## Overview

Between 12 and 21 November 2026 the driver took no record, while `drive.js --check` admitted 15 of 142 build-authorized records. Finding the cause took a manual scan of run directories and transcripts. The three driver runs on 12 November were started by hand: their run directories are `drive-{N}`, minted by `drive.js` itself. Dispatch's driver route (#5232) first shipped in v6.171.0, which was never installed; the plugin cache went from 6.170.0 to 6.172.0 on 17 November. All 18 dispatch sessions from 15 November 23:06 to 17 November 07:27 ran v6.170.0, which has no route. No dispatch firing ran after that. Not one run directory holds a `Driver route (skipped)` line. `tools/pipeline-cost-report.js --section funnel` reports only the point-in-time admission verdict, so it showed "15 admitted" and nothing about whether any of them could have been driven.

This record adds driver activity over the window to the funnel section: how many driver runs there were, split into dispatch-routed and standalone, and when the last one ran; how many dispatch firings ran, how many of them reached the driver route, and which plugin versions they ran; and one line flagging records that were admitted while nothing routed any.

**Complexity:** Medium
**Estimated tasks:** 4

- Alerting or scheduling. The report is run by hand, as today.
- Changing the admission verdicts or the existing funnel rows.

- Route evidence in a dispatch transcript: a Bash `tool_use` whose command runs `drive.js` with `--check`, or a `log-decision.js` call with `--step "Driver route (skipped)"`. The session's plugin version is on the SessionStart hook's `claude-tweaks v{X.Y.Z} @` line.

## Deliverables

- [ ] The funnel section gains `driverRuns` over the report window: `total`, `dispatchRouted`, `standalone`, `last` (date of the latest), counted from run directories (top level and `archive/`) holding `driver-events.jsonl`. A directory whose name ends `-drive-{N}` (the name `drive.js` mints for itself) counts as `standalone`. Any other directory counts as `dispatchRouted` only when its `manifest.json` carries `lane: driver`, the fill the route makes at adoption (`driver-route.md`'s `refused` row); one with neither counts as `standalone`, so the flag below errs toward speaking.
- [ ] The funnel section gains `dispatchFirings` over the window: `total` (sessions whose first claude-tweaks skill is `claude-tweaks:dispatch`), `reachedRoute` (those holding route evidence as defined in Current State), and `byPluginVersion` (count per version read from the session's `claude-tweaks v{X.Y.Z} @` line, `unknown` when absent). A session is in the window when its first timestamped message falls in it. `reachedRoute` is strict: the session ran `drive.js --check` or logged the `Driver route (skipped)` line. A firing on a build with no route reads as not reached, and `byPluginVersion` tells the reader why.
- [ ] When `admitted > 0` and `driverRuns.dispatchRouted === 0`, the Markdown output prints one line: `Admitted records were not driven: {dispatchFirings.total} dispatch firings in the window, {dispatchFirings.reachedRoute} reached the driver route.`
- [ ] `--json` carries `driverRuns` and `dispatchFirings` with the same figures.

## Release Note

The maintainer cost report now shows whether admitted records ever reached the pipeline driver, not only how many were admitted.

## Technical Approach

Reuse the existing readers rather than adding scanners: `listRuns` for the run directories, `scanTranscript` (extended to record route evidence and the plugin version line in the same pass) for sessions. Window membership follows the report's existing rule: a run directory by its name's date, a session by its messages' own timestamps.

### Data / API Surface

- `collectFunnel` result gains `driverRuns: { total, dispatchRouted, standalone, last }` and `dispatchFirings: { total, reachedRoute, byPluginVersion }`.

### Key Files

- `tools/pipeline-cost-report/funnel.js` — collects `driverRuns` and `dispatchFirings`
- `tools/pipeline-cost-report/spend.js` — `scanTranscript` records route evidence and the plugin version line
- `tools/pipeline-cost-report.js` — renders the two rows and the flag line
- `tests/pipeline-cost-report/funnel.test.js` — ACs 1-6

## Gotchas

- Transcripts for this project sit in several account roots that are the same store: deduplicate roots by real path, as `--projects` already does.
- A subagent transcript is not a dispatch firing. Count only main-session transcripts; skill invocations inside `/subagents/` do not count.
- Mentions of `drive.js --check` in prose, such as a skill file read into the transcript, are not route evidence. Count only a Bash `tool_use` input.
- The plugin version is read from the `claude-tweaks v{X.Y.Z} @` text the SessionStart hook injects. It sits inside the transcript's hook-context text, not in a dedicated field (a 6.175.0 session shows it), so match the pattern over the raw text of a session's first records; a session with no match is `unknown`.
- The flag line speaks only when no dispatch-routed run is in the window. One old routed run silences it, which is intended: the line reports that nothing was routed, not that routing is rare.
- #5971 and #5970 edit the same report files. Merge order between them is free, but each rebase must keep the other's change.
