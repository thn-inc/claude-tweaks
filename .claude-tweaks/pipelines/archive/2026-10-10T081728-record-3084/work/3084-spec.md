# 3084: Dispatch #N and #N,#M forms misreport a not-spec-shaped record as having an open PR

Origin: v6.139.0 release whole-branch review (/claude-tweaks:release Step 3, v6.138.0..cef435b77), staged finding review-9 — the release review stages and never applies fixes in place

Defer-reason: needs-human-decision

## Current State

`plugin/skills/dispatch/SKILL.md:178` (the `#N` selection form) explains a record absent from `dispatch-groups.json` by reading only `reason: 'open-pr'` entries from `dispatch-exclusions.json`. Since #2829 (#3073), the queue pull also drops records with `reason: 'not-spec-shaped'` (`queue-pull-script.md`). A user naming such a record with `#N` gets the open-PR explanation (or none, if no `open-pr` entry exists). The `#N[,#M...]` form's `notFound` reporting (`SKILL.md:180`) likewise lists only the open-PR reason. Spec #2829's AC4 (named-target behavior) has no test for the `#N` form.

## Deliverables

- `SKILL.md`'s `#N` bullet reads every exclusion reason that removes a record from `dispatch-groups.json` (at least `open-pr` and `not-spec-shaped`) and reports the matching one by name; for `not-spec-shaped` it renders the same line and remedy as `not-spec-shaped-exclusion-report.md`.
- The `#N[,#M...]` bullet's `notFound` reason list names `not-spec-shaped` too.
- A fixture test pins the `#N` form's not-spec-shaped report (alongside `tests/dispatch-not-spec-shaped-exclusion-fixture.test.js`).

## Acceptance Criteria

- Naming a not-spec-shaped record via `#N` reports `not spec-shaped (missing: …)` with its remedy, never `already has an open PR`.
- Naming it inside an `#N,#M` list reports the same reason in `notFound`, and the rest of the list proceeds.
- The new test fails on today's `SKILL.md` text and passes after the change.

## Release Note

Naming a record that is not spec-shaped in `/claude-tweaks:dispatch #N` now says so and tells you how to fix it, instead of wrongly claiming it already has an open PR.
