# 2314: Re-pin impeccable-cli from 3.6.0 to the installed 4.1.0

**Related:** #2321

## Current State

tools/upstream-drift/manifest.yml and plugin/skills/design-wrapper/impeccable-cli.md pin the Impeccable CLI at 3.6.0, but 4.1.0 is what is actually installed. Running the upstream-drift skill against impeccable-cli finds a version breach, plus one assertions-drift finding: the contract file cli/engine/cli/main.mjs, which two documented assertions point at ("findings JSON is written to stdout, not stderr"; "a clean scan prints an empty JSON array rather than nothing"), no longer exists at 4.1.0 — the CLI internals were reorganized, not just patched. The two existing fixture replays (warning.html, clean.html) still pass against the installed 4.1.0 binary, so the externally-visible CLI contract may be unchanged even though the internal file moved. Not a release blocker: tests/impeccable-cli-contract.test.js skips entirely when impeccable is not installed, so CI never runs it — this only surfaces on a machine with impeccable installed globally.

## Deliverables

Locate where the assertion-relevant source now lives in 4.1.0 (or confirm it is no longer checkable that way) and update the two assertions in impeccable-cli.md accordingly.

Run the full upstream-drift capability JUDGE, diffing cli-v3.6.0 to the latest tag, to catch any other drift or new capability.

Re-record fixtures if CLI behavior actually changed.

Move both the manifest pin (tools/upstream-drift/manifest.yml) and the <!-- upstream-pin: impeccable-cli@... --> comment in impeccable-cli.md together, per that file own warning against two independent pins drifting.

## Acceptance Criteria

node --test tests/impeccable-cli-contract.test.js passes against the installed version with no skip.

The upstream-drift deterministic checks for impeccable-cli report status: ok on both the version and assertions checks.

impeccable-cli.md pin comment and the manifest pinned value agree.
