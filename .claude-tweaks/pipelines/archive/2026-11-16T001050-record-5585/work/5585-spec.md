## Current State

It says contract changes follow expand-contract, that a deprecated behavior gets a removal condition, and it ends: "Prefer stability over novelty in shipped skill contracts — adopt new conventions in new skills first, then migrate existing ones deliberately, with the incident log recording what each migration cost."

Decision 0.1 of `docs/superpowers/specs/2026-11-15-process-efficiency-design.md` (answered by the maintainer on 2026-11-15) sets a limited stance: redesign is free and no shim stays without a removal condition, but a change must not break a run in flight on the previous release, because live sessions run mixed plugin versions. `project-maturity` stays `established` (`.claude-tweaks/policy.yml` line 13). The paragraph's last sentence says the opposite of "redesign is free".
Decided 2026-11-16: the paragraph keeps the maintainer's words, "the previous release". They name the nearest case, not a horizon. How long an old form stays is set by the removal condition recorded with each change, and that condition does not hold while a run that reads the old form can still be in flight. A run in flight is a pipeline run that a session on an earlier plugin version has started and not closed.
