# 5930: Decide a deferred item's route in code

Surface: backend
Risk-flags: none

## Overview

A read-only CLI, `plugin/bin/deferral-route.js`, that decides in code where a deferred item goes: filed as a record, or appended to the digest. Today that decision is prose a model follows at about eight sites, and no code applies it. This record builds the decision as one function that reproduces today's rule exactly, so later records of this decomposition can change the rule in one place and measure it. Runs filed 317 of the 586 records created between 8 and 18 November 2026 as deferrals; `docs/superpowers/specs/2026-11-18-pipeline-economy-design.md` (Phase 6) sets out to cut that.

**Complexity:** Medium
**Estimated tasks:** 7

## Non-Goals

- Changing where anything goes. With default policy the verdict equals what `plugin/skills/_shared/materiality-floor.md` says today.
- Making any skill call the CLI. #5931 moves the routing sites onto it.
- Deciding whether to fix. The deferral gate's fix-now test runs first and is untouched.
- Creating a record or posting a digest comment. The CLI prints a verdict and writes nothing.
- Making the three-axis judgement consistent across sites. The axes stay the calling skill's judgement, because the floor is defined on how the record would be scored at filing time.

- [ ] **Closed rule:** the verdicts are exactly `file`, `digest` and `refused`. `refused` covers a `--defer-reason` outside `DEFER_REASONS`, a missing reason, both or neither of `--agent-raised` and `--human`, a `--severity` that is present but not exactly one of `critical`, `high`, `medium`, `low`, `info`, a flag given without its value, a repeated flag, and an unknown flag; it prints one line naming the input and its remedy. A severity typo such as `High` is refused rather than read as not high, because reading it as not high would digest an item that may be critical. ## Acceptance Criteria

1. `--defer-reason pre-existing-outside-diff --size low --priority low --risk low --agent-raised` prints verdict `digest`, rule `floor`.
2. The same call with `--risk medium` prints `file`, rule `not-low`; with `--priority` omitted it also prints `file`, rule `not-low`.
3. `--defer-reason tangential` with all three axes low and `--agent-raised` prints `file`, rule `tangential`.
4. All three axes low with `--severity high` prints `file`, rule `severity`; `--severity critical` the same; `--severity medium` prints `digest`.
5. `--human` prints `file`, rule `human`, whatever the other flags.
6. `--defer-reason not-a-reason` exits non-zero with verdict `refused` and a line naming the value and the accepted list.
7. The exhaustive test produces no combination whose verdict is outside `file`, `digest` and `refused`.
8. Running the CLI creates, changes or deletes no file, and it makes no `gh` call.
9. `--severity High` (and `--severity urgent`) exits 2 with verdict `refused` and a line naming the value and the accepted list; `--severity` omitted does not.
10. `--defer-reason tangential --severity high --agent-raised` with all axes low prints `file`, rule `severity`; the same call with `--defer-reason not-a-reason` prints `refused`; `--human` with a bad reason also prints `refused`.

## Release Note

Added a command that decides in code whether a deferred finding becomes a record or a digest entry, matching today's rule.

## Technical Approach

One pure function with its inputs passed in, so the rule has a single code home that tests can enumerate. The three axes stay the caller's judgement: the floor is defined on how a record would be scored at filing time, which only the filing skill can say. The CLI follows the `run(argv, deps)` seam and exit-code vocabulary the repository's other `plugin/bin` CLIs use. The flags are caller-declared and the CLI cannot verify them: a caller derives `--agent-raised` or `--human` from `plugin/bin/lib/issues/provenance.js`'s rule and passes `--human` whenever the origin is unsure, because `--human` files. Once the sites call the command, `route.js` is the authority and `materiality-floor.md` its explanation, pinned equal by the test above. The sites cite the floor and do not restate it: the existing assertion at `tests/materiality-floor-conformance.test.js` line 192 fails when any of the eleven adopter files restates the three-axis rule, so a site's wording cannot drift from the prose unnoticed.

### Data / API Surface

- Function: `routeDeferral({ deferReason, severity, size, priority, risk, agentRaised }) -> { verdict: 'file'|'digest'|'refused', rule: string, reason?: string }`.
- CLI output: one line of JSON on stdout with the keys `verdict`, `rule`, `reason` (`refused` only) and `input` (the inputs as given, absent ones as `null`). Exit 0 for `file` and `digest`; 2 for `refused`, whose JSON is also on stdout.
  - `{"verdict":"digest","rule":"floor","input":{"deferReason":"pre-existing-outside-diff","severity":null,"size":"low","priority":"low","risk":"low","agentRaised":true}}`
  - `{"verdict":"refused","rule":"refused","reason":"--severity \"High\" is not one of: critical, high, medium, low, info","input":{"deferReason":"genuinely-larger","severity":"High","size":null,"priority":null,"risk":null,"agentRaised":true}}`
- Contract: the output keys, the `verdict` and `rule` vocabularies and the exit codes only grow. A later input is an additive flag whose default reproduces today's verdict, so a session on an older release is never broken by a newer one.

## Decision Rationale

Absorbed from `docs/superpowers/specs/2026-11-18-pipeline-economy-design.md`, Phase 6.

- Between 8 and 18 November 2026, 586 records were created and 207 closed. 317 of the new ones carried a `Defer-reason:`; the reasons named were `pre-existing-outside-diff` 135, `tangential` 80, `needs-human-decision` 71, `genuinely-larger` 56.
- The plugin already has a fix-now rule, a digest and a 90-day expiry. Two rules send agent-noticed work to new records anyway: `tangential` always files, and `pre-existing-outside-diff` files unless all three axes are low.
- The digest batches: three entries in one area become one proposed record. Since 8 November, 16 such records bundled 111 findings.
- No code decides the route today and no single function sees every filing, so the rule cannot be changed or measured in one place. This decomposition therefore builds the code gate first (this record), moves the routing sites onto it, and only then adds the policy value that sends more to the digest, an evidence check and a per-run cap.
- Every new behaviour is a policy value whose default reproduces today. This repository opts in first.
- Rejected: fixing outside-the-diff findings inside the run, which grows a diff beyond its record; and dropping them outright, which loses the 90-day window in which a repeated finding can still be promoted.
