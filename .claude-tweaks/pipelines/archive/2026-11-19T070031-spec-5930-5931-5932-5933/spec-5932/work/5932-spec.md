# 5932: Send chosen agent-raised deferral reasons to the digest by policy

Surface: backend
Risk-flags: public-contract

## Overview

Adds a policy value naming the deferral reasons that always go to the digest when an agent raised the item, and sets it in this repository to the two reasons behind most run-filed records: a problem outside the run's diff, and an idea the run had. Today an idea always becomes a record and an outside-the-diff problem becomes one unless it is small on every axis; together those two reasons were named 215 times on the records filed between 8 and 18 November 2026. Human-typed capture is unaffected, and high or critical findings keep filing. See #5930 for the Decision Rationale.

**Complexity:** Medium
**Estimated tasks:** 5

## Non-Goals

- Changing the default for other projects. With the value unset every verdict is what it is today.
- The evidence check and the per-run cap: #5933.
- The digest's own lifecycle. Cluster promotion at three entries and expiry at 90 days stay as they are.
- Fixing an outside-the-diff finding inside the run. It is logged, not fixed.

## Release Note

Added a policy setting that sends chosen kinds of agent-noticed follow-up work to the digest instead of filing each as a new record.

## Technical Approach

One more clause in the routing function, ahead of the three-axis floor and behind the two protections that must not move: human input and high severity. The value is a list of reasons, not a switch, so a project chooses which kinds of noticed work it wants as records. In effect about seven digest entries become one proposed record, and an entry nobody promotes expires. `policy-reason` deliberately ignores all three axes, risk included: the protections against a risky item being digested are human input and severity. A single item in an area that never reaches three entries expires after 90 days unfiled; that is accepted, since the policy trades per-item records for the digest.

### Data / API Surface

- Policy key `deferral-digest-reasons` (name final): `type: 'list'`, `element: 'defer-reason'` (new, validated against `DEFER_REASONS`), `default: []`. Resolved through run config, then repository policy, then default. In `policy.yml` the value is one flat comma-separated line, like every `list` row (`isValidValue` splits on commas, `policy-schema.js` line 506), and one bad element makes the whole value invalid.
- `routeDeferral` gains `digestReasons: string[]`; a new `rule` value `policy-reason`.
