# 5931: Move the deferral routing sites onto the route command

Surface: backend
Risk-flags: public-contract

## Overview

Every place where a run decides between filing a deferred item and sending it to the digest asks `plugin/bin/deferral-route.js` for the verdict, in place of applying the materiality floor from prose. The verdict itself does not change. After this record the floor has one code home that every routing site uses, so a policy value can change the rule for all of them and a count of verdicts means something. See #5930 for the Decision Rationale.

**Complexity:** Medium
**Estimated tasks:** 8

## Non-Goals

- `/claude-tweaks:capture`. It applies the hard gate only, and every agent deferral reaches it already routed by one of the six sites.
- Changing any verdict. A site that filed before still files.
- The fix-now test, the `Defer-reason:` vocabulary and the hard gate in `plugin/skills/_shared/deferral-gate.md`.
- The console's can't-tell digest and ledger narrowing, which follow their own rules today and are left as they are.
- The filings made outside runs: `plugin/bin/ci-health.js`, `plugin/bin/lib/reconcile/escalate-residue.js` and `plugin/bin/lib/feedback/file-feedback.js`.
- The five health sweeps' floor step (`plugin/skills/code-health/filing.md`, `plugin/skills/docs-health/SKILL.md`, `plugin/skills/harness-health/filing.md`, `plugin/skills/journey-health/SKILL.md`, `plugin/skills/ci-health/SKILL.md`). Their findings carry no `Defer-reason:`, which the command refuses, so they keep citing the floor in prose.
- Creating the record or posting the digest comment through the CLI. Each site keeps its own write.

## Release Note

Moved the choice between filing a deferred finding and adding it to the digest from skill prose into one command that every pipeline step calls.

## Technical Approach

The rule's text stays in `plugin/skills/_shared/materiality-floor.md` as the explanation; the command is how a site applies it. Each site keeps judging the three axes, because only it knows how the record would be scored, and hands the verdict to the path it already has. Nothing here is expand-contract: a run in flight on the previous release reads the old prose and reaches the same verdict. Equivalence rests on #5930's exhaustive test, which pins the command to the floor's prose; after this record no site keeps a rule of its own, so the command is the authority and the prose its explanation. `bin/deferral-route.js` and the skill edits ship in one plugin release under one plugin root, so a skill that calls the command finds it. Later changes to the command are additive, each new input a flag whose default reproduces today's verdict.

### Data / API Surface

- Command form, cited by every adopter: `node "{plugin root}/bin/deferral-route.js" --defer-reason {value} [--severity {value}] --size {value} --priority {value} --risk {value} (--agent-raised | --human)`.
- Verdict handling: `file` → the site's filing path; `digest` → the site's digest path; `refused` → report and leave open.
- Inputs and output, all from #5930: axis values `low`, `medium`, `high`; severities `critical`, `high`, `medium`, `low`, `info`; one JSON line on stdout with `verdict` and `rule`; exit 0 for `file` and `digest`, 2 for `refused`.
