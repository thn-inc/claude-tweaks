# 1388: overview-mode.md Step 1's fold-in script truncates its own input file

**Related:** #1389

## Current State

skills/backlog/overview-mode.md Step 1's fold-in script (the mergeUnsyncedRecords call) reads its own output path (backlog-overview-faceted.json, referenced as $ST_BACKLOG_OVERVIEW_FACETED in both the github object read and the shell redirection > target) in the same shell command that overwrites it. Since shell redirection (>) truncates the target file before the command's own node -e process opens it for reading, require('$ST_BACKLOG_OVERVIEW_FACETED') inside that same command can read a truncated or empty file rather than the content written by the prior step. A user manually running this procedure by hand (2026-08-24) hit exactly this failure and had to route the read through a separate temp file to work around it.

## Deliverables

- Fix overview-mode.md Step 1's fold-in script so the read and the write target different paths (read from the pre-fold-in faceted file, write the merged result to a distinct path, then move/rename into place, or write to a temp path and mv over the original after the node process exits) — never read-and-redirect-write the same path in one shell command.

## Acceptance Criteria

- Running overview-mode.md Step 1's fold-in script verbatim in a fresh shell never truncates backlog-overview-faceted.json before its own content is read.
- A regression test (or a documented manual repro step) confirms the merged output includes both the GitHub-sourced and unsynced-sourced records after this fix.
