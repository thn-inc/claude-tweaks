# 1535: Fix compute-then-exit truncation risk in build-review-context.js

Defer-reason: pre-existing-outside-diff

## Current State

While performing #1313's final whole-branch review (fix compute-then-exit truncation risk in `plugin/bin/release.js` and `plugin/bin/review-coordination.js` — itself a follow-up to #1176's earlier sweep), the reviewer found that #1313's own sweep enumeration was incomplete. `plugin/bin/build-review-context.js:76` carries the identical idiom:

```js
process.exit(run(process.argv.slice(2)));
```

`run()`'s `build`/`mint` branches end with `deps.stdout(JSON.stringify(result) + '\n'); return 0;` — the same shape #1176/#1313 already fixed elsewhere: a stdout write immediately before returning an integer that then feeds `process.exit()`, which can truncate the write for a piped consumer.

The enumeration was verified exact by the #1313 final reviewer: `process.exit(` appears in exactly three `plugin/bin/*.js` files — `build-review-context.js:76` (this idiom, unfixed), `hooks.js:779` (correctly excluded — uses synchronous `fs.writeSync(1, ...)` with no async flush to lose), and `wrap-up-engine.js:361` (a comment, not a call, not in scope). A GitHub search (`gh issue list --search "build-review-context process.exit"` and `--search "truncation exit in:title"`, both `--state all`) found no existing record for this file.

This matters more than the other two instances: `build-review-context.js` is what `/claude-tweaks:review` Step 3 shells out to for its context bundle, and skill prose parses its stdout JSON line.

## Deliverables

- In `plugin/bin/build-review-context.js`, change `process.exit(run(process.argv.slice(2)));` to `process.exitCode = run(process.argv.slice(2));`. The call sits inside an existing `try` block whose `catch` already sets `process.exitCode = 1` — that fallback is unaffected, since `process.exit()` never threw there anyway.
- Read `main()`/`run()` in full first, per #1176's own safety rule, to confirm no code after the changed line assumes an immediate hard-stop (the same check #1313 performed for its two files).

## Acceptance Criteria

1. The file exits with the same status code as before for a representative success and failure case.
2. `npm test` passes in full.
