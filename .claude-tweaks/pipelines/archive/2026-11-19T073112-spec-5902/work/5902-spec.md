Needed by the factory floor design (dispatch PR #1894, a draft awaiting approval: `docs/superpowers/specs/2026-11-18-factory-floor-design.md`, "The ledger: station events", "Station visits", "The dependency graph", Phase 0 and Phase 2). Nothing emits station events today: `git grep -il station -- plugin` matches only `plugin/bin/lib/issues/author-association.js` and `plugin/bin/lib/issues/provenance.js`, both unrelated. What exists, checked against the checkout at `main`:

## Deliverables

1. **An emitter module**, `plugin/bin/lib/station-events/emit.js`, exporting `appendStationEvent(event, deps)`. It appends one JSON line to `{main checkout}/.claude-tweaks/station-events.jsonl` (the main checkout, not a linked worktree, so parallel sessions share one file), under `file-lock.js`. It never throws and never changes a caller's outcome: a failed append is dropped with one stderr line, the same posture the claim's label and log side already has. No network call, no hub dependency, no policy key in this version.
2. **The line format** (version 1), one object per line, field names taken from the design's `station_events` so dispatch maps them without translation: `v` (1), `eventKey` (unique and deterministic, so a retry or a re-read does not double count), `repoName` (`owner/name`), `recordNumber`, `kind` (`entered | started | exited | session_bound | blockers`), `station`, `at` (ISO-8601 UTC), `outcome` (on `exited`: `passed | failed | returned | skipped | abandoned`), `lane` (`standard | express | driver | unknown`), `sessionId`, `runId`, `payload` (object). `kind: blockers` is an addition to the design's four kinds and carries the blocker snapshot (deliverable 5). `station` uses the names in the design's registry table, held in one table module in this directory so a correction after the Phase 0 fixtures is a one-file change. The format is documented in `docs/reference/station-events.md`.
3. **`session_bound`**, written when a claim lands: `plugin/bin/lib/claim-targets/claim-targets.js` emits one event per claimed record with `sessionId` (from `deps.sessionId`) and `runId`, so a `--budget` drain that claims several records in one session writes several events, one per record. For a driver run, `plugin/bin/lib/driver/steps.js` and `worker.js` copy the worker result's `session_id` into the `worker` step's event extras and emit `session_bound` for that record with it.
4. **Transition events from the code that already makes the transition**, each carrying `lane` when the call site knows it (`driver` from `plugin/bin/lib/driver/`, `express` from `plugin/bin/express-lane.js` call paths, `standard` from the claim in a `/flow` run, else `unknown`):
   - the claim write and `bot:in-progress` add (`claim-targets.js`), and the release and tombstone (`release-claim.js`, with the release reason as the outcome);
   - label grants and removals applied by `apply-refine-labels.js` (`auto:build` and the stage labels it moves);
   - `accept:*` changes in `accept-park.js` and `accept-entry.js`;
   - PR creation in `pr-early-open.js`, and the driver's step starts and ends (`worker`, `test`, `review`, `pr`, `ci`, `merge`, plus the `merge-*` sub-steps that mark a PR ready, merge it or park it), emitted from `run.js` beside the existing `sink.emit` calls.
5. **The blocker snapshot.** `fetchNativeDependencies` accepts an optional `onSnapshot` callback (default none); `resolve-blockers.js` and `preflight-records.js` pass one that appends one `kind: blockers` event per record, with `payload` holding `blockedBy`, `openBlockerIds`, `crossRepoBlockers` and `fetchedAt`. No extra GitHub call.
6. **Tests** beside the neighbouring suites: the emitter (line shape, deterministic `eventKey`, lock, swallowed failure, worktree resolves to the main checkout), `tests/resolve-blockers-cli.test.js` (snapshot event, unchanged stdout and exit codes), the claim path, and `tests/bin-lib/driver/run.test.js` (a driver run's events mirror its step lines).
7. **Housekeeping.** Add `.claude-tweaks/station-events.jsonl` to `.gitignore` and to `step-04-gitignore-suggestions.md`; add a short "Station events" section to `docs/driver.md` pointing at the reference page.

## Acceptance Criteria

- After `claim-targets.js` claims record N, the file holds a `session_bound` event whose `recordNumber` is N and whose `sessionId` equals `CLAUDE_CODE_SESSION_ID`; claiming records 1, 2 and 3 in one session writes three such events with the same `sessionId`.
- A driver run's `driver-events.jsonl` and the station-event file agree: every `worker`, `test`, `review`, `pr`, `ci` and `merge` step that has a line in the first has a started and an exited event in the second, with the same record and run id, and the `session_bound` event names the worker's `session_id`.
- `resolve-blockers.js 12,13` emits two `kind: blockers` events and prints the same stdout and exit code as before; a record with a blocker in another repository carries it in `payload.crossRepoBlockers`.
- Every event passes a line-format check: valid JSON, a known `kind`, `at` in UTC, a deterministic `eventKey`; emitting the same transition twice yields one `eventKey`.
- Run from a linked worktree, the event lands in the main checkout's `.claude-tweaks/station-events.jsonl`.
- With the file unwritable (read-only directory), the claim, the release, `resolve-blockers.js` and a driver run still finish with their unchanged results and exit codes.
- No event is written by a skill prose step; `git grep -n "station-events" -- plugin/skills` matches no instruction to log.
- The full test suite and lint pass.

## Release Note

Record each claimed record's session, its station transitions and its blocker snapshot to a local station-event file that the dispatch factory floor reads.

## Technical Approach

One small module owns the line format, the station table and the append; call sites hand it facts they already hold (record number, run id, session id, label name, step name, outcome). Appends use the existing `file-lock.js` directory lock and one `write` per line, so parallel sessions in different worktrees interleave whole lines. The path is resolved to the main checkout with `mainCheckoutRoot` (`plugin/bin/lib/hooks/worktree-detect.js`). Lane is passed in by the caller, never inferred; `unknown` is a valid value.

The driver is the model for timing: `run.js` already emits one event per step result, so the station event is emitted from the same point from the same `ctx`, rather than a second pass over `driver-events.jsonl`. Where the driver's step names are mapped to stations (`worker` to `build`, `ci` to `merge`, and so on) the mapping lives in the station table, not in `run.js`.

Transitions that skill prose performs today (`ready` added by `/specify`, a standard-lane `gh pr merge`) get no event in this record. Asking prose to log would break the design's rule; moving those writes into code is a separate decision, and the design's reconciler covers them in the meantime.

## Gotchas

- **Event names are not settled.** The station, label, skill and driver-step names above are a reading of this repository and of the design's registry table. Confirm every one against captured fixtures (design Phase 0: a real `driver-events.jsonl` from a merged and an escalated run, the label set from `plugin/skills/_shared/label-bootstrap.md`, a real timeline) before the table module pins them. The table is one file so a correction is cheap.
- ASSUMPTION — verify at build: `CLAUDE_CODE_SESSION_ID` as seen by `claim-targets.js` is the same id dispatch stores in `sessions` for a hub-run headless session — confirm via a Phase 0 fixture pairing a claim blob's `sessionId` with the matching `sessions` row.
- ASSUMPTION — verify at build: `kind: blockers` is accepted by dispatch. The design lists four kinds; this record adds a fifth, so the dispatch design (PR #1894) needs the same addition before the two sides agree.
- ASSUMPTION — verify at build: the file is only readable by dispatch on an embedded instance, as the design says; a server instance reads it through a command's output lines, which this record does not provide.
- Coverage gap by design: `ready` added by `/specify` and a standard-lane `gh pr merge` have no code emitter, so the floor sees them only through reconciliation.
- A bare drain claims through `claim-targets.js` once per record, so `session_bound` per claim covers `--budget` drains and bundles; work that never claims (a standalone `/specify` or `/build` with no run) writes no `session_bound`.
- The `.gitignore` entry is load-bearing, not cosmetic: an untracked state file in the main checkout makes reconcile's and mirror's `git status --porcelain` dirty check read it as dirty (the precedent in `step-04-gitignore-suggestions.md` for `wrap-up-outcomes.tsv` and `reconcile-cache.json`), so land the ignore line in the same change as the first write.
- No rotation or compaction in this version: dispatch tracks its own read offset, and the file grows by a few lines per record. Add rotation only after the reader exists.
- Driver stdout and `driver-events.jsonl` stay unchanged and are not a contract (`docs/driver.md`); the station file is the contract.
- This record is large for one build. If it is too big for one pass, the natural split is the emitter, claim and `session_bound`, blockers and driver first, then the label, accept and PR transitions.
- Risk proof required: this record carries kept risk flags, so one plan step must contain, per slug, a line `Proof(<slug>): <text>` with a specific proof of at least 20 characters. Lines: `Proof(public-contract): …`.
