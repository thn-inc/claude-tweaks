# 1571: dispatch: persist queue ranking as a git-ref cache to skip re-triage on unchanged queues

Surface: infra

## Overview

Every dispatch firing re-triages the entire authorized queue from scratch via dispatch/queue-pull-script.md: fetch every auto:build issue, verify dependencies, query the native blocker graph, run the file-overlap union-find, and rank — a ~65s, almost entirely deterministic pipeline. This adds a persisted cache in front of that pipeline: a queue-order namespace holding the last-computed ranked/grouped queue plus a freshness stamp, checked on read before falling back to today's full pull.

## Prerequisites

#1466 (claims-git-cas.js duplicates durable-state.js's generic CAS primitive) — CLOSED. Resolution: durable-state.js was NOT extended with branch parameterization/raw-blob support (judged not worth the risk to createDurableState's byte-identical-behavior guarantee). This work therefore consolidates on createNamespacedState exactly as it exists today — a JSON namespace on the shared health-state branch — rather than a standalone queue-order git ref.

## Deliverables

- A queue-order namespace (JSON blob: computedAt, runId, freshnessSignal.issues, groups, excluded).
- dispatch/queue-pull-script.md's procedure gains a cache-check prefix and a write-back suffix.
- Branch bootstrap handled by createNamespacedState itself (existing behavior).

## Acceptance Criteria

1. An exact freshness-signal match uses the persisted groups/excluded directly, zero calls to the per-dependency verification loop or native blocker query.
2. A freshness mismatch runs today's full pull unchanged, then persists a new blob.
3. A dependency issue flipping OPEN->CLOSED is classified as a mismatch.
4. A missing/unreadable blob or failed freshness fetch runs today's full pull exactly as if the cache didn't exist.
5. Two racing writes: exactly one lands (CAS); the loser's own in-memory groups/excluded stay valid for its own firing.
6. A test suite for the freshness-signal comparison and blob compose/parse passes.

## Investigation Findings

**Prerequisite resolution confirmed first**: `gh issue view 1466` → CLOSED. Read `durable-state.js`'s own header comment (already present, predating this record): "NOT extended to also absorb bin/lib/issues/claims-git-cas.js's claims-registry CAS engine (#1466) ... judged not worth that risk." This settles the ambiguity the record's own Prerequisites section flagged — the design proceeds on `createNamespacedState` exactly as it exists (a JSON namespace on the shared `health-state` branch), not a standalone `queue-order` git ref, per the Technical Approach's own explicit fallback ("or the primitive #1466 lands on if consolidation changes its shape").

**Implemented:**

1. `plugin/bin/lib/dispatch/queue-order.js` (new): `readOrder`/`writeOrder` (thin wrappers over `createNamespacedState('queue-order', ...)`), `buildFreshnessSignal` (normalizes/dedups `{number, updatedAt, state}` triples), `signalsMatch` (exact set+field comparison — covers exact match, an auto:build issue's `updatedAt` change, an issue added/removed from the set, and a dependency's `state` flipping OPEN→CLOSED, per AC6's four required cases), `composeOrderBlob` (states the blob's field list once, matching `claims.js`'s `claimPayload`/`releasePayload` precedent).
2. `tests/bin-lib/dispatch/queue-order.test.js` (new, 14 tests): all four `signalsMatch` cases from AC6, `buildFreshnessSignal`'s dedup/normalization, `composeOrderBlob`, and `readOrder`/`writeOrder` wiring (real fake-git-runner pattern mirroring `merge-lane-breaker.test.js`, including a genuine write failure returning `{ok:false}` without throwing).
3. `plugin/skills/dispatch/queue-pull-script.md`: added a cache-check prefix (reads the persisted blob; computes the current freshness signal via the existing `DISPATCH_QUEUE_RAW` call — now also fetching `updatedAt,state`, satisfying AC1's "merged call structure" allowance — plus one targeted `gh issue list --search` call for the persisted blob's dependency-only numbers; on a match, writes `DISPATCH_GROUPS`/`DISPATCH_BLOCKED_EXCLUDED` from the persisted blob and locally recomputes `DISPATCH_OVERSIZED_EXCLUDED` via `partitionGroupsBySizeGuard` — a pure function, no network call, satisfying AC1's "zero calls" requirement for the size-guard file too even though the record's own blob schema doesn't persist it directly); wrapped the existing full-pull pipeline in `if [ "$CACHE_HIT" != "1" ]; then ... fi` (AC2/AC4 — unchanged behavior on a miss, blob-absent, or freshness-fetch failure, since `CACHE_HIT` degrades to `'0'` on any of those); added a write-back suffix inside that same block, persisting a freshly composed blob after a full pull (AC2), using the union of `parseDependencies` output across the pull's own `DISPATCH_ELIGIBLE_PRE_DEP` set as the recorded-dependency list for the new freshness signal.

**Verified during implementation, not just assumed:**
- Confirmed empirically (not just from the design's own prose) that a naive `sed 's/[0-9]*/#&/g'` risks a zero-width-match edge case; switched both occurrences to `sed 's/[0-9][0-9]*/#&/g'` (one-or-more digits) to remove the ambiguity entirely rather than rely on this sed implementation's specific empty-match-adjacency behavior.
- `bash -n` on the extracted fenced script confirms valid bash syntax after every edit.
