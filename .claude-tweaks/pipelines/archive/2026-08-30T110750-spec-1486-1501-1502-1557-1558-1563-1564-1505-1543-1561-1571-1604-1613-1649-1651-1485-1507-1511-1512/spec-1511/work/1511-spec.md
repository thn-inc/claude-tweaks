# session-tmp-root-migration.test.js's LITERAL_TMP_RE can't span a {placeholder} token

## Current State

`tests/session-tmp-root-migration.test.js:73`'s `LITERAL_TMP_RE` uses a `[a-z0-9-]*` character class that can't span a `{placeholder}` token (e.g. `{issue}`, `{n}`) — a literal like `/tmp/backlog-needs-decision-{issue}.md` breaks the match at `{` and never re-synchronizes to the extension, so it goes undetected in any `MIGRATED_FILES` entry.

## Deliverables

- Extend `LITERAL_TMP_RE` to also match a `{...}`-containing bare `/tmp/` literal.
- Confirm no currently-migrated file has this exact blind spot (the two known instances in `refine-lanes.md` were already fixed manually during #1488's review).

## Acceptance Criteria

- A file containing a bare `/tmp/some-thing-{placeholder}.md` literal fails the migration test (fixture/regression case proving this).
- The existing assertions still pass unmodified in intent (no false positives on `$VAR`-based or `ct-`-prefixed paths).
- Full `npm test` green.

## Investigation Findings

**Widened `LITERAL_TMP_RE`** (`tests/session-tmp-root-migration.test.js`): each hyphen-joined segment now accepts `(?:[a-z0-9-]|\{[a-zA-Z0-9]+\})*` instead of a plain `[a-z0-9-]*`, so a `{placeholder}` token no longer breaks the match. The required literal `-` between segments, the `(?!ct-)` exclusion, and the required leading `[a-z]` are all unchanged — only widens what a segment's own characters can be, not which paths qualify as candidates.

**Regression fixture added** (proving AC1 without polluting the real `MIGRATED_FILES` corpus with a deliberate violation): a new test writes each of 3 literal strings — `/tmp/backlog-needs-decision-{issue}.md`, `/tmp/backlog-refine-flagback-{issue}.md` (the two originally-discovered shapes), and a generic `/tmp/some-thing-{placeholder}.md` — into a temp fixture file, then runs the exact same `text.match(LITERAL_TMP_RE)` mechanism the real loop uses, asserting each is caught. A second new test pins the negative controls the Gotchas required: a `ct-`-prefixed path, a `$VAR`-based session-scoped path, and ordinary prose with no `/tmp` literal all still correctly evaluate to no match after the widening.

**Confirmed the two motivating instances are already fixed** — `grep -n "backlog-needs-decision\|backlog-refine-flagback" plugin/skills/backlog/refine-lanes.md` returns nothing; per this record's own Gotchas, they were not re-fixed here (out of scope, already resolved during #1488's review).

**No other MIGRATED_FILES entry regresses** — the existing `'no migrated file retains a literal unscoped /tmp/{prefix}-*.{ext} path'` test still passes against the current, wider corpus (38 entries today, up from the 26 the record cites — grown by #923's later sweep, not a discrepancy) with the widened regex, confirming no other file carries this exact blind spot.

**Test results.** `tests/session-tmp-root-migration.test.js`: 6/6 pass (4 pre-existing + 2 new). Full `npm test` run — see this record's commit history for the final pass/fail counts.
