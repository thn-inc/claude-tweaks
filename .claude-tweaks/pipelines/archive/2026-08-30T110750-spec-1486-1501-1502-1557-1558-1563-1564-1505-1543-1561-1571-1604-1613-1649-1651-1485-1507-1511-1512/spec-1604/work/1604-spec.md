# 1604: Ad-hoc-standalone run dirs never get an eventual-cleanup path (#1117 follow-up)

Surface: backend

## Current State

#1117 permanently exempted `-adhoc-standalone` run dirs from isOrphanedMint's 24h mtime sweep, but never implemented the "swept once genuinely superseded" half of its own chosen design. Traced: decideArchive never archives these dirs (no console.json ever written into one), and even a merged PR can't help since archive-before-reap sequencing means the worktree registration can be gone before archive gets a chance. Net effect: a genuinely-ended ad-hoc session is now permanently un-archivable and perpetually renags SessionStart.

Separately, isAdHocStandaloneMint was a pure basename-suffix match with no corroborating check.

## Deliverables

Needs a design decision among: (1) a secondary long TTL keyed on worktree absence, (2) wrap-up's reflect pass explicitly archiving, (3) both. Also: corroborate isAdHocStandaloneMint with a run-state.json/worktree check, update docs/hooks.md and reflect/full-mode.md's #1117 prose, add regression coverage.

## Acceptance Criteria

- An ad-hoc-standalone run dir whose worktree has been removed/reaped is eventually archived.
- probePipelineRuns (or equivalent) can surface/resolve a stuck ad-hoc dir.
- SessionStart's nag does not fire indefinitely for a genuinely-superseded ad-hoc dir.
- A still-live ad-hoc dir is NOT swept prematurely.
- npm test passes, including new coverage.
- docs/hooks.md and reflect/full-mode.md accurately document the complete lifecycle answer.

## Key Files

- plugin/bin/lib/reconcile/archive-merged.js — isAdHocStandaloneMint, decideArchive
- plugin/bin/lib/reconcile/index.js — DISPATCH_ORDER
- plugin/bin/lib/residue/probes/pipeline-runs.js — probePipelineRuns

- plugin/skills/reflect/full-mode.md and docs/hooks.md — #1117 prose

## Gotchas

- Must not regress #1117's own fix — a still-live ad-hoc session must never be swept.
- isAdHocStandaloneMint's corroboration fix is a prerequisite, not optional polish.
- archive-before-reap sequencing is why a PR merging in the same pass can already lose its worktree registration.

## Investigation Findings

**Decision made** (record itself flagged `Defer-reason: needs-human-decision` — ruling made here per the batch's lighter-ceremony/rulings-not-stalls posture): Deliverables option 1 (a secondary long TTL keyed on worktree absence). Option 2 alone (wrap-up's reflect pass explicitly archiving) would still leave a gap for any ad-hoc session that never runs wrap-up at all — the exact realistic path the record's own "Net effect" paragraph names as common (an ordinary ad-hoc session that eventually gets formalized and merged, or simply abandoned). Option 1 is a complete backstop regardless of whether wrap-up ever consumed the dir.

**Implemented in `plugin/bin/lib/reconcile/archive-merged.js`:**

1. **Corroboration fix (prerequisite, per Gotchas):** `isAdHocStandaloneMint` now requires the `-adhoc-standalone` suffix AND a real `run-state.json` carrying a non-empty `worktree` field (via `readRunState`) — a malformed/mkdir-only dir sharing the suffix no longer gets exempted from `isOrphanedMint`'s ordinary mtime sweep, closing the leak the record's Gotchas identified.
2. **`isAdHocStandaloneSuperseded(dir, state, worktrees, now)`** (new): true only when the dir is a genuine ad-hoc mint (via the corroborated `isAdHocStandaloneMint`), its recorded `state.worktree` no longer resolves in a fresh `git worktree list --porcelain`, AND `ADHOC_SUPERSEDED_TTL_MS` (30 days — two orders of magnitude longer than `ORPHAN_MINT_TTL_MS`, since a torn-down worktree is unambiguous "session over" evidence, unlike a bare mtime heuristic on a never-adopted mint) has elapsed since the dir was last touched. A still-live worktree (registered, regardless of age) always returns false — #1117's own invariant, unchanged.
3. Wired into `archiveMerged`'s main loop, positioned ahead of the `no-worktree`/`no-branch` skip that would otherwise catch a superseded ad-hoc dir permanently. On a hit, reuses `archiveOrphanedMint` (a plain directory move — ad-hoc dirs never have a tracked `work/` subdirectory needing the git-mv treatment, since they're informal dev-session artifacts, not formal spec builds).

**AC2/AC3 satisfied transitively, no separate code needed:** confirmed via `context.js`'s own comment ("Other siblings under pipelines/ — notably archive/...") that `iterRunDirsWithState` (which both `probePipelineRuns` and `session-start.js`'s nag iterate) deliberately excludes `archive/`. Once a superseded ad-hoc dir is physically moved there, both the nag and the backstop stop seeing it — no changes needed to `pipeline-runs.js` or `session-start.js` themselves.

**Docs updated:** `docs/hooks.md` and `plugin/skills/reflect/full-mode.md` — both files' `#1117` prose was already accurate (not overstated, as the record's Deliverables assumed — likely already corrected by the same reviewing session that filed this record) and already cited `#1604` as the tracked gap. Updated each file's closing sentence from "tracked as a known gap in #1604" to describe the now-implemented `isAdHocStandaloneSuperseded` mechanism and its 30-day TTL, preserving the explicit note that a still-live dir is never swept regardless of age.

**Regression tests added/updated** (`tests/reconcile.test.js`):
- Updated the two existing `#1117` tests that broke under the new corroboration requirement (`isOrphanedMint: false for a genuine adhoc-standalone mint...` now writes a real `run-state.json`; `isAdHocStandaloneMint: matches only the suffix` rewritten as `...requires the suffix AND a corroborating run-state.json worktree field`, covering: genuine match, wrong suffix, suffix-as-substring, suffix-with-no-run-state-at-all, suffix-with-run-state-but-no-worktree-field).
- New `isAdHocStandaloneSuperseded` unit tests: still-live worktree (false, any age), worktree gone but younger than TTL (false), worktree gone and TTL elapsed (true), non-ad-hoc dir even past TTL (false).
- New `archiveMerged` integration tests: a superseded ad-hoc dir is physically moved to `archive/` (AC1); a still-live one is never swept regardless of age (#1117 regression guard, AC4).

**Bug caught and fixed during test-writing, not just assumed correct:** an initial attempt at the "TTL elapsed" test backdated the dir's mtime via `mintEmptyRunDir`'s `ageMs` option BEFORE calling `writeRunState` — but `writeRunState` writes a file into the directory, which resets the directory's own mtime back to "now," silently undoing the backdating. Fixed by introducing a `mintAdHocDir` test helper that writes run-state first, then backdates via `fs.utimesSync` afterward. Separately, the "still-live worktree" tests initially failed with the *opposite* symptom (a live worktree read as gone) due to a real macOS quirk: `os.tmpdir()` returns a `/var/...` path that's a symlink to `/private/var/...`, and `git worktree list --porcelain` always reports the resolved form — `path.resolve()` alone doesn't resolve symlinks, so an un-realpath'd `wtDir` never matched. Fixed by `fs.realpathSync(os.tmpdir())` before constructing the worktree path, matching this same test file's own pre-existing `bareRepoRoot()` convention (which already does this for the same reason). Confirmed this is a test-fixture artifact, not a production bug — real `run-state.json` worktree paths are written under the actual repo root (`.claude/worktrees/{name}`), never under a symlinked system tmpdir.
