# 1543: reconcile runs twice per dispatch firing at ~2min each, tripping the harness command timeout both times

Surface: infra

## Current State

hooks.js reconcile runs twice per dispatch firing, ~2 minutes each, and both runs exceed the harness's default ~2-minute command timeout — so every invocation gets auto-backgrounded and the session pays extra choreography (poll loops, blocking TaskOutput waits) on top of the runtime itself. In a headless next firing (Dispatch hub run #9, 2026-08-26), Step 2's reconcile ran ~2m03s then required a poll-and-collect sequence; the post-merge reconcile (_shared/pr-first-merge.md) ran ~2m04s and needed the same sequence again. An earlier firing the same day (run #6) actually died at this point — the model scheduled a wakeup to wait for the backgrounded reconcile and its one-shot turn ended, stranding the firing mid-flight.

## Deliverables

One or more of the following, scoped during implementation against what the profiling reveals:

- Profile where the ~2 minutes goes; if it's dominated by fetch + full-sweep passes, add a --scope option usable at the dispatch call sites to narrow the pass.
- Have dispatch/SKILL.md Step 2 and _shared/pr-first-merge.md's post-merge call mandate an explicit, generous timeout on the reconcile invocation so it stays foreground instead of auto-backgrounding.
- Reconsider whether the post-merge reconcile needs to run inline in the firing at all, versus being left to the next firing's own Step 2 reconcile.

## Acceptance Criteria

- A headless dispatch firing's total reconcile time either completes within the harness's default command timeout without auto-backgrounding, or is demonstrably reduced from the ~4-minutes-of-43 baseline above.
- The near-death failure mode observed in run #6 cannot recur for a foreground-timeout-compliant reconcile call.
- Whichever deliverable option is implemented is reflected in dispatch/SKILL.md Step 2 and/or _shared/pr-first-merge.md's post-merge reconcile invocation text.

## Key Files

- plugin/bin/hooks.js — reconcile subcommand entry point
- plugin/bin/lib/reconcile/index.js — ALL_CHECKS sweep composition; likely locus of a --scope option
- plugin/skills/dispatch/SKILL.md — Step 2 reconcile invocation
- plugin/skills/_shared/pr-first-merge.md — post-merge reconcile invocation

## Gotchas

- The three deliverable options are separable and were offered as suggestions, not a single prescribed fix.
- A --scope narrowing must not silently skip checks a full sweep would have caught — any scoped call site needs to still hit every check class the full reconcile would run over, or note explicitly which class it intentionally excludes.

## Investigation Findings

Read `plugin/bin/lib/reconcile/index.js` end to end. Findings:

- A `checks`-scoping seam already exists at the library level (`opts.checks`, `ALL_CHECKS = ['mirror', 'red-tip', 'reap', 'release', 'archive', 'archive-branches', 'remote-prune', 'console']`), already used internally (`reconcile-summary`'s own `checks: ['mirror']` call) — but `bin/hooks.js`'s `reconcile` CLI command had no flag exposing it to external callers (dispatch/SKILL.md, pr-first-merge-post-merge.md).
- `pr-first-merge-post-merge.md`'s own Step 4.2 prose already describes needing exactly 3 of the 8 checks: "Fast-forwards the mirror ... releases the claim, and archives the run dir" — i.e. `mirror`, `release`, `archive`. Confirmed via `reconcile()`'s dispatch-order comments that `release`/`archive` depend only on `mirror` having refreshed the ref first (not on `red-tip`/`console`), and must run before `reap` (which physically removes worktrees those two derive branch state from) — `archive-branches`/`remote-prove`/`red-tip`/`console`/`reap` are all safely excludable for this specific call site.
- `remote-prune`'s inclusion in the default `ALL_CHECKS` set is what forces `shared-fetch.js`'s full `--prune all-refs` fetch instead of the cheaper single-integration-ref fetch a `mirror`-only (or `mirror`+non-remote-prune) request uses (confirmed via existing test names in `tests/reconcile.test.js`, e.g. "sharedFetch: a mirror-only pass fetches the single integration ref, never --prune all-refs") — a strong, evidence-backed candidate for where the ~2 minutes goes on this call site specifically, without needing new live profiling instrumentation.
- `dispatch/SKILL.md`'s Step 2 call, by contrast, reads `console.ready` and describes "converging the main checkout toward origin" for the queue pull — its actual check dependencies are less clearly bounded from static reading alone, and the record's own Gotcha explicitly warns against narrowing without profiling. Left unscoped (full `ALL_CHECKS`) rather than guessed at.

**Fix implemented** (combining Deliverable options (a) and (b), scoped per the above):

1. `plugin/bin/hooks.js`'s `reconcile` command: added a `--checks <c1,c2,...>` flag, comma-split and forwarded as `opts.checks` (empty/missing value safely falls back to `reconcile()`'s own existing ALL_CHECKS default — no new validation needed).
2. `plugin/skills/_shared/pr-first-merge-post-merge.md`'s Step 4.2: scoped to `--checks mirror,release,archive` (backed by that step's own pre-existing prose) and added an explicit 150000ms+ timeout mandate.
3. `plugin/skills/dispatch/SKILL.md`'s Step 2: added the same explicit timeout mandate, left unscoped (no `--checks`) per the reasoning above — this satisfies AC1's first branch ("completes within [an explicit] timeout without auto-backgrounding") directly, regardless of actual runtime, and AC2 (no more scheduled-wakeup-against-a-backgrounded-reconcile hazard, since an explicit generous timeout means it never gets backgrounded in the first place).

**Regression tests added** (`tests/reconcile.test.js`): two CLI-acceptance tests for the new `--checks` flag (accepted with a value; falls back safely on an empty value), matching this file's own established convention for CLI-level flag tests (a no-remote fixture, proving acceptance/no-crash — deeper behavioral coverage of the underlying `opts.checks` seam is already extensive at the library level, e.g. "reconcile(): checks: [\"mirror\"] alone never calls the GitHub-health preflight at all"). `tests/reconcile.test.js` runs 94/94 green.

AC3 is satisfied: both call sites' invocation text now reflects the fix. Not implemented: Deliverable option (c) (removing the post-merge reconcile call entirely) — scoping + an explicit timeout already resolves the observed hazard without needing to also change when the call happens.
