# 1563: classifyOwnership: owner-absent worktree-bound run classifies foreign at pre-tool-use E-checks regardless of caller identity

Surface: backend

## Current State

#1099's review found that classifyOwnership's worktree-binding branch (context.js:297-308, from #1098) returns 'foreign' purely from a worktree-path mismatch, never checking whether either side's session id is present. Combined with record-worktree legitimately omitting sessionId when CLAUDE_CODE_SESSION_ID is unset (hooks.js:260), an unowned but worktree-bound run would classify 'foreign' (allow + warn) at both of #1099's enforcement sites (checkTeardownGate, runInner's commit path in pre-tool-use.js) whenever the caller is provably standing in a different live worktree, regardless of caller session id.

Before #1099, both sites used raw owner && caller && owner !== caller equality: with owner falsy, the condition is always false, so both gates unconditionally denied a teardown/commit against an unowned-but-bound, non-terminal run.

## Deliverables

- Decide, deliberately, whether an owner-absent worktree-bound run should classify 'foreign' or 'indeterminate' (fail toward deny) when the caller has no session id, no matching session id, or an owner-absent run generally.
- If the decision is to deny: adjust classifyOwnership's binding branch or add a narrower guard at the two pre-tool-use.js call sites.
- If the decision is to keep 'foreign': update #1099's site comments and #1098's own spec/contract documentation, and add the missing regression test (owner-absent + caller-in-different-live-worktree) at both enforcement gates.

## Acceptance Criteria

1. A named regression test exists at both checkTeardownGate and runInner's commit path covering: run recorded with no sessionId, caller in a genuinely different live worktree, with and without a caller session id, asserting whichever outcome is correct.
2. plugin/bin/lib/hooks/pre-tool-use.js's inline comments at both sites accurately describe the actual behavior for this sub-case.
3. Full npm test green.
