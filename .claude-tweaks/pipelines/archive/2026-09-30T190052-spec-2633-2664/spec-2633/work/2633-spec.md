# 2633: Self-validate a health-skill Premise-check command at filing time (dry-run, drop if not exit 0)

Surface: infra

**Related:** #2621, #2545

## Current State

`buildPremiseCheck` landed with #2621 (closed 2026-09-23) in `plugin/bin/lib/harness-health/issue-payload.js:66`, called from `toIssuePayload` at line 129. It composes one of two commands:

- additive intent: `! grep -qF -- {anchor} {path}`
- removal intent: `! test -r {path} || grep -qF -- {anchor} {path}`

Exit 0 means the finding is still unresolved. Any non-zero exit means resolved, and `plugin/bin/materialize.js` (5 s `PREMISE_CHECK_TIMEOUT_MS`) auto-closes the record at build time.

Nothing runs the composed command when the finding is filed. #2621's whole-branch review (M2, deferred) flagged the gap: a short, generic anchor that already appears elsewhere in the target file makes the command read "resolved" on its very first evaluation, auto-closing a finding whose work was never done. The reviewer's fix: run the command once at filing time and drop the `Premise-check:` line when it doesn't currently read "unresolved", rather than guessing at a length or specificity floor.

Scope as of 2026-09-30: only harness-health composes a `Premise-check:` line. `plugin/bin/lib/{code,docs,journey}-health/issue-payload.js` have no equivalent, and no open record tracks porting one. The original request's "fold into the already-specced port" therefore has no port to fold into, so this record covers harness-health and places the helper where a later port can reuse it.

## Deliverables

1. A shared helper in `plugin/bin/lib/health-core/` (e.g. `premise-self-check.js`). It runs a composed `Premise-check:` command once via `sh -c` from the repo root, with a bounded timeout matching materialize's 5 s, and returns whether the command exited 0. The command runner is injectable for tests.
2. Harness-health filing wires it in: after `buildPremiseCheck` returns a command, run the helper. If it doesn't exit 0 (non-zero exit, timeout, or spawn error), omit `premiseCheck` from the `specShapedBody` call so the filed finding carries no `Premise-check:` line. Place the call where it can take an injected runner, either `toIssuePayload` with a defaulted parameter or the `cmdValidateFindings` call path in `plugin/bin/harness-health.js`, so `toIssuePayload`'s existing unit tests don't start spawning shells.
3. Tests for the helper and the filing-time drop.

## Acceptance Criteria

- A finding whose composed command exits non-zero at filing time is filed with no `Premise-check:` line.
- A finding whose composed command exits 0 at filing time is filed with a `Premise-check:` line byte-identical to what `buildPremiseCheck` produces today.
- A timeout or spawn error while self-checking omits the line (fail toward "no auto-close"), never keeps it.
- Helper unit tests cover exit 0, non-zero, and timeout via a fake runner. One real-shell test composes an additive check against a temp file that already contains the anchor and confirms it is dropped.
- `MAX_PREMISE_ANCHOR_LENGTH` and the anchor-eligibility rules in `buildPremiseCheck` are unchanged; no length or specificity floor is added.
- `npm test` passes.

## Release Note

Stopped health sweeps from filing findings that close themselves before the work is done, by dropping any premise check that already reads as resolved at filing time.

## Technical Approach

Keep `buildPremiseCheck` pure: it composes, and the new helper executes. Put the helper in `health-core` rather than `harness-health`, because the other three health skills would need exactly this step if they ever gain a `Premise-check:` composer. Use `execFileSync('sh', ['-c', command], { cwd: root, timeout, stdio: 'ignore' })` inside an injectable runner, catching the thrown error to read `status` (non-zero) versus `signal`/`ETIMEDOUT` (timeout); both map to "drop".

### Key Files

- `plugin/bin/lib/health-core/premise-self-check.js` — new helper: run once, bounded timeout, injectable runner
- `plugin/bin/lib/harness-health/issue-payload.js` — call the helper after `buildPremiseCheck`; omit `premiseCheck` when it doesn't exit 0
- `plugin/bin/harness-health.js` — `cmdValidateFindings`, if the runner is threaded from the CLI call path rather than defaulted inside `toIssuePayload`
- `tests/bin-lib/health-core/premise-self-check.test.js` — new helper tests
- `tests/bin-lib/harness-health/issue-payload.test.js` — filing-time keep/drop cases

## Gotchas

- The self-check runs in the sweep's checkout, and materialize runs the same command later in a build checkout. The command bakes in an absolute path, so it checks exactly what it will check later only when both run on the same machine. On a different machine the missing-file fail-safes still read "unresolved", which keeps the line (the safe direction).
- Don't add a specificity heuristic. The reviewer explicitly rejected it, and the dry run is the whole fix.
- A future port to code/docs/journey-health is out of scope here and has no record yet. File one with `/claude-tweaks:capture` if that composer is ever wanted.
