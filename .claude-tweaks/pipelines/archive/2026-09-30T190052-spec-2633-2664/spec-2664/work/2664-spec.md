## Current State

`hasMaterializeCommit` (`plugin/bin/lib/hooks/pre-tool-use.js:1075`) was fixed for its multi-spec per-spec runDir blind spot by #2571 (PR #2662), with regression tests in `tests/hooks-bookkeeping-stamps-gate.test.js`. That record's Deliverables 3/4 were blocked because `check-pr-bookkeeping.js` did not exist yet.

The blocker has cleared: #2472 closed on 2026-09-20 via PR #2570, and on `origin/main` today:

- `plugin/bin/check-pr-bookkeeping.js` and `plugin/bin/lib/pr-bookkeeping/precondition.js` exist.
- `precondition.js:49` calls `hasMaterializeCommit(worktreeRoot, runDir)` (the fixed shared helper), and `precondition.js:29` reads `readRunState(runDir)` for the `worktree`/`pr` fields.
- `tests/bin-lib/pr-bookkeeping/cli.test.js` and `precondition.test.js` exist, but every fixture uses a single-spec top-level run dir (`…-spec-1`). None constructs the multi-spec per-spec shape (`{parent-run-id}/spec-{N}/`).

Separately, #2571's Deliverable 2 is still unanswered: where a multi-spec run's `run-state.json` lives. `readRunState(runDir)` reads from the per-spec `$PIPELINE_RUN_DIR`. `build/worktree-setup.md` Step 4.5 (`record-worktree --run "$RUN_DIR"`) is not skipped under `MULTISPEC_SHARED_WORKTREE=1` and re-resolves `$RUN_DIR` fresh per call. If `record-worktree` writes to the parent dir while `precondition.js` reads the per-spec one, the precondition misses the recorded worktree/PR: the same wrong-directory shape #2571 fixed for the materialize check.

## Deliverables

1. A regression test under `tests/bin-lib/pr-bookkeeping/` that builds a temp git repo with a multi-spec per-spec run dir (`{parent-run-id}/spec-{N}/`) and a committed `spec-{N}/work/{N}-spec.md`. It runs `checkPrBookkeepingPrecondition` (and the `check-pr-bookkeeping.js` CLI) against the per-spec run dir and asserts the materialize commit is recognized, with no false `not-materialized-yet`.
2. A traced answer to where a multi-spec run's `run-state.json` is written (parent only, or per spec), derived from the `record-worktree`/`record-pr` write path in `plugin/bin/lib/hooks/`. Record the answer as a comment next to `precondition.js`'s `readRunState(runDir)` call, citing the file and function that decide the write location.
3. If the trace shows `precondition.js` reads a different directory than the writers use, extend the test from Deliverable 1 to reproduce the miss and fix `precondition.js`'s run-state lookup in the same change.
