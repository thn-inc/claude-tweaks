# 1796: escalate-residue: removal-failed escalation body names the plugin's own path as the fix site and omits the worktree's dirty-file list

Surface: infra

## Current State

`residueBody` (`plugin/bin/lib/reconcile/escalate-residue.js`) composes every reconcile escalation issue — `removal-failed`, `structurally-stuck`, `move-failed` — from `{reason, targetPath, count, firstFailedAt, lastError}` and ends with the literal line ``Filed automatically by `bin/lib/reconcile` — see #644.``. In a consumer project that line reads as a repo-relative path and a local issue number: neither exists there, and `/claude-tweaks:specify`'s shaping sanity check has no way to know the path belongs to the plugin. Three consumer records were shaped with `bin/lib/reconcile/` as their Key File and each failed a headless build on "named location does not exist" before being closed as upstream.

For `removal-failed`, `reap-merged.js`'s failure branch (`if (rm.failure)`) forwards only `rm.stderr || rm.failure` as `lastError` (#1341) into `trackReapResidue` → `cache.js`'s `trackResidue`/`recordResidueFailure` (which persists `{count, firstFailedAt, lastError, escalated}` per `reason:path`) → `escalateResidue`. Git's refusal text ("contains modified or untracked files, use --force to delete it") says the worktree is dirty but not *with what*; the reader cannot tell a leftover untracked ledger from real uncommitted work without shelling into the host. `bin/lib/residue/probes/worktrees.js`'s `defaultIsDirty` already runs `git -C {path} status --porcelain` (10 s timeout, `null` on read failure), but reduces the output to a boolean and is not called from the reaper.

Tests: `tests/bin-lib/reconcile/escalate-residue.test.js` (six cases; "residueBody: embeds the path, reason, and the fingerprint marker"), `reap-merged.test.js`, `cache.test.js`. Related, distinct: #1424 (tidy path: never classify a dirty worktree as deletable), #1341 (the human handoff this body implements), #1811 and #1892 (this sweep's consolidated `structurally-stuck`/`move-failed` records for this repo's own residue; both keep `bin/lib/reconcile/` as a correct Key File *here*).

## Deliverables

- [ ] **Attribution line that survives a consumer repo.** Replace the closing line in `residueBody` with one that names the code owner and the record's purpose for all three reasons: filed by the claude-tweaks plugin's reconcile pass; the logic lives in the plugin source (`bin/lib/reconcile/` of `thomasholknielsen/claude-tweaks`, not a path in this repository); a fix to the reconcile logic belongs upstream (`thomasholknielsen/claude-tweaks#644` as the tracking reference, fully qualified); this record is the human handoff for the path named above. Keep the fingerprint marker and its basis unchanged so existing dedup keeps matching.
- [ ] **Carry the dirty-file list on `removal-failed`.** In `reap-merged.js`'s failure branch, read `git -C {real} status --porcelain` (extract `worktrees.js`'s porcelain read into a small exported helper that returns the raw lines or `null`, and have `defaultIsDirty` call it, so there is one implementation) and pass `dirtyFiles` (array of porcelain lines, capped at 50 with a `… and N more` tail line) through `trackReapResidue` → `trackResidue` → `recordResidueFailure` (persist `dirtyFiles` next to `lastError`, refreshed on every failure, dropped with the streak on success) → `escalateResidue` → `residueBody`, which renders a `**Dirty files (\`git status --porcelain\` at the last failed pass):**` fenced block. When the read returned `null`, render `could not read — git status failed` in that block rather than omitting it (a check that did not run must not look like a clean worktree).
- [ ] **Disposition hint, no behavior change to the reaper.** Below the block, one line: only `??` (untracked) entries that are plainly disposable make `git worktree remove --force {path}` safe; any modified tracked entry means inspect first. The reaper itself never gains `--force` (the original request's explicit non-goal).
- [ ] **Tests.** `escalate-residue.test.js`: attribution line names the plugin and the qualified upstream ref, no bare `bin/lib/reconcile` path; `dirtyFiles` block rendered, capped, and the `null` case rendered as unreadable; non-`removal-failed` reasons render no block. `reap-merged.test.js`: on `rm.failure` the porcelain read runs against the worktree path and its lines reach the injected `escalate`. `cache.test.js`: `dirtyFiles` persisted and replaced per failure, cleared on success. `tests/bin-lib/residue/*`: `defaultIsDirty` still returns `true`/`false`/`null` through the shared helper.
- [ ] Update `docs/reconcile-checks.md` if it quotes the body's closing line or the cache entry shape (grep first; edit only the quoted text).

## Acceptance Criteria

1. `residueBody({reason: 'structurally-stuck', …}).body` contains the plugin attribution with `thomasholknielsen/claude-tweaks#644` and does not contain the bare line ``Filed automatically by `bin/lib/reconcile` ``; the fingerprint marker is byte-identical to today's for the same `(reason, path)`.
2. `residueBody({reason: 'removal-failed', dirtyFiles: ['?? docs/plans/x-ledger.md']}).body` contains a fenced block with that line and the disposition hint; with `dirtyFiles: null` it contains the unreadable sentence; with 60 lines it renders 50 plus a `… and 10 more` tail.
3. In `reap-merged.test.js`, a failed `git worktree remove` results in exactly one `status --porcelain` invocation against the worktree path and the lines appear on the escalation call's arguments; a successful removal performs no status read.
4. `cache.json`'s `residueFailures[reason:path]` entry carries `dirtyFiles` after a failure and the entry is deleted on success, pinned in `cache.test.js`.
5. `npm test` green; every pre-existing case in the three reconcile test files and in `tests/bin-lib/residue/` passes unchanged.
6. A record filed by this code in a consumer repo, shaped by `/claude-tweaks:specify`, would not name `bin/lib/reconcile/` as a Key File — demonstrated in the PR description by quoting the new body text and stating which sentence carries the upstream pointer.

## Technical Approach

Additive: a new optional `dirtyFiles` field on the cache entry and the escalation call, `null`/absent for the two other reasons, so no existing consumer changes shape. One porcelain reader shared between the residue probe and the reaper, with the same 10 s timeout and `null`-on-failure contract. The attribution rewrite is text only; keep the marker line last so `tidy-residue-markers` style consumers that locate the fingerprint keep working. Cap the list in the reaper, not in the body composer, so the cache never stores an unbounded array.

### Key Files

- `plugin/bin/lib/reconcile/escalate-residue.js` — attribution line; `dirtyFiles` block + hint in `residueBody`; pass-through in `escalateResidue`
- `plugin/bin/lib/reconcile/reap-merged.js` — porcelain read on `rm.failure`; `dirtyFiles` into `trackReapResidue`
- `plugin/bin/lib/reconcile/cache.js` — persist `dirtyFiles` in `recordResidueFailure`; forward it in `trackResidue`'s `escalate` call
- `plugin/bin/lib/residue/probes/worktrees.js` — export the porcelain reader `defaultIsDirty` now delegates to
- `tests/bin-lib/reconcile/escalate-residue.test.js`, `reap-merged.test.js`, `cache.test.js` — new cases
- `docs/reconcile-checks.md` — only if it quotes the closing line or the cache entry shape

## Gotchas

- The reconcile pass runs in the background on every session (`reconcile-background.lock`); a status read on a dirty worktree is one more spawn per failed reap — bounded by the 10 s timeout and only on the failure branch, so acceptable, but do not add it to the success path.
- Porcelain lines can contain paths with spaces and renames (`R  old -> new`); store them verbatim, never split.
- Do not change the fingerprint basis: an attribution change must not re-file already-escalated paths.
- Records this code already filed in this repo (the `structurally-stuck`/`move-failed` instances absorbed into #1811 and #1892 by this sweep) keep their old body text; nothing here rewrites filed issues.

## Original request

**Summary:** A `removal-failed` escalation issue filed by `bin/lib/reconcile/escalate-residue.js` reads, in the consumer project, as an in-repo bug ("Filed automatically by `bin/lib/reconcile` — see #644") and carries git's stderr but not the dirty worktree's `git status --porcelain` output — so a human cannot tell a disposable untracked ledger from real uncommitted work without visiting the host, and a downstream `/specify` shapes the record with `bin/lib/reconcile/` as its Key File even though that directory does not exist in the consumer repo.

**Kind:** Defect

**Affected component:** `bin/lib/reconcile/escalate-residue.js` (`residueBody`), with `bin/lib/reconcile/reap-merged.js`'s `removal-failed` tracking as the producer

**Repro steps:**
1. In a consumer project (not claude-tweaks itself), let a merged-PR worktree accumulate one untracked file (e.g. a leftover `docs/plans/*-ledger.md`) so `git worktree remove` refuses with `contains modified or untracked files, use --force to delete it`.
2. Let reconcile's reap pass hit `removal-failed` on that path three times so `cache.js`'s escalation latch trips and `escalateResidue` files the issue.
3. Read the filed issue body, then run `/claude-tweaks:specify #N` on it.

**Expected vs. actual:**
Expected: the body says the removal logic lives in the claude-tweaks plugin (a fix, if any, belongs upstream — and a maintainer reading the consumer's issue should not be pointed at a repo-relative `bin/lib/reconcile/`), and it lists the worktree's porcelain lines so the reader can decide between "disposable residue — `git worktree remove --force` is safe" and "real uncommitted work — inspect first" without shelling into the host. `bin/lib/residue/probes/worktrees.js` already has `isDirty(worktreePath)` running `git status --porcelain`; `residueBody` only needs the porcelain text, not just the boolean.
Actual: the body's fix-site line reads as a consumer-repo path (three reconcile-filed records were shaped by `/specify` with `bin/lib/reconcile/` as Key File and each failed a headless build on "named location does not exist" before being closed as unreproducible/upstream), and the body's only diagnostic is git's one-line stderr. This is the escalation-path half of what claude-tweaks #1424 fixed for the `/tidy` path (never classify a dirty worktree as deletable, never offer bare `--force`) and the human handoff #1341 designed — the handoff works, it just does not carry the one fact the human needs. Not a request to add `--force` to the reaper.
