# 2540: specify Step 2.5b-ii: variant exploration (explore/live) is mandatory ceremony with no policy off-switch; explore always skips on current Impeccable

Surface: infra

## Current State

`/claude-tweaks:specify`'s Step 2.5b-ii variant exploration (layout tournament → single-scaffold `live`) is mandatory ceremony on every frontend decomposition, `explore` always skips on a current Impeccable install, and the `live` fallback is far heavier than the change it is offered for. Concretely, on a decomposition whose one frontend phase was a copy-and-ticks change inside an already-shipped fieldset (a third window axis on an existing slider component): (1) `explore --scope layout` skipped because `impeccable-plugin.md` pins `impeccable-plugin@4.0.2` while the cache held 4.1.1 and 4.3.1 — the tournament can never run for anyone on a current Impeccable release, yet the offer is still presented as "Recommended" before the availability check runs; (2) the fallback `live` path then required writing a throwaway scaffold, starting an ephemeral static server, and booting Impeccable's live helper, which injected a `<script src="http://localhost:8400/live.js?token=...">` tag into BOTH tracked scaffold files under `docs/plans/` (not just the new one), plus a background `live-poll` loop and a human in a browser — for a change whose whole visual delta was two slider captions, a floor sentence, and two tick labels; (3) `_shared/policy-schema.md` has no key governing Step 2.5b-ii, so the only way to avoid both prompts is to answer "Skip" every time.

## Deliverables

- [ ] Add a policy key (`design-variant-exploration: off|offer`, default `off`) to `_shared/policy-schema.md` that skips Step 2.5b-ii entirely when set to `off`, so projects that only want `shape`/`critique`/`audit` never see the tournament or scaffold-live offers
- [ ] Run the exact-pin availability check in `design-wrapper`'s `explore` mode BEFORE offering it in `specify/design-pre-steps.md` Step 2.5b-ii, and omit the option (or mark it unavailable, naming the installed vs. pinned versions) when it cannot run, instead of recommending it
- [ ] Scope `live-inject` (`design-wrapper`'s `live` mode) to the scaffold the session was booted with (`--target`), not every page file it can find under the scaffold directory

## Acceptance Criteria

- [ ] With `design-variant-exploration: off` (the new default), Step 2.5b-ii's tournament and scaffold-live offers never fire during decomposition
- [ ] With the policy at `offer`, `explore` is only presented as an option when the exact-pin availability check already passed — an unavailable pin shows as unavailable (naming the versions), never as "Recommended"
- [ ] `live-inject` only modifies the scaffold file the session was booted against, never other tracked files under the scaffold directory
- [ ] `npm test` passes, including new coverage for the policy key and the reordered availability check

## Technical Approach

Add `design-variant-exploration` to `_shared/policy-schema.md`'s schema (default `off`) and gate `specify/design-pre-steps.md`'s Step 2.5b-ii on it before any tournament/live offer is rendered. In `design-wrapper`'s `explore` mode, move the exact-pin `resolveImpeccablePlugin` availability check ahead of the option-presentation logic so an off-pin install is surfaced as unavailable (with both installed and pinned versions named) rather than as a recommended-but-silently-skipping option. In `live` mode, scope the live-inject step to the `--target` scaffold path explicitly rather than scanning the whole scaffold directory for injectable page files.

### Key Files

- `plugin/skills/_shared/policy-schema.md` — add the `design-variant-exploration` key
- `plugin/skills/specify/design-pre-steps.md` — gate Step 2.5b-ii on the new policy key
- `plugin/skills/design-wrapper/modes/explore.md` (and its availability-check call site) — reorder the exact-pin check ahead of option presentation
- `plugin/skills/design-wrapper/modes/live.md` — scope `live-inject` to `--target` only

## Gotchas

- The policy default (`off`) is a behavior change for existing projects that never explicitly opted into variant exploration — confirm this matches what most installs already effectively get today (the tournament already always skips on a current Impeccable pin per the observed evidence, so `off` mostly formalizes existing behavior rather than removing a working feature).
- Reordering the availability check must not silently swallow a *different* kind of `explore` failure (a transport/exec error) as "unavailable" — keep the two failure classes distinguishable in the rendered message.
