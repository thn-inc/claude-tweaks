# 4344: Extract the PR-stamp release rule so the push gate and phase-exit.js call one predicate

Origin: review lens 3e (architecture), both reproduction agents, refs #4026
Defer-reason: genuinely-larger

## Current State

`plugin/bin/lib/phase-exit/phase-exit.js` `prPushReleased` re-applies the PR-stamp release rule of `checkBookkeepingStampsGate` (`plugin/bin/lib/hooks/pre-tool-use.js`, the `if (!runState.pr)` branch) by composing the gate's exported predicates (`hasLoggedPrDegrade`, `hasLoggedPrEarlyStep1`, `hasNoUpstreamYet`) plus an inline `status`/`prExempt`/`hasPr` test. The gate's branch itself is inline and interleaves model resolution, the #989 first-publish exemption and the `prExempt` memo write, so nothing ties the two copies together: a new release condition added to the gate does not reach the push phase-exit.js makes, and no test compares them. #4026's review added a cross-reference comment at the gate; that is a pointer, not a pin. Refs #4026.

## Deliverables

1. A pure predicate in `pre-tool-use.js` (or a lib it requires) that answers "may a pr-first push go ahead with no recorded PR" from `{runState, runDir, branch, model, hasNoUpstream}`; the gate and `prPushReleased` both call it.
2. The gate keeps its stamp-outcome and `prExempt` memo side effects around the predicate call.

## Acceptance Criteria

- [ ] A table-driven test runs the gate and `prPushReleased` over the same scenarios (recorded PR, `prExempt`, FAILED degrade line, first publish with and without its Step 1 line, closed run, per-spec parent) and asserts the same allow/deny.
- [ ] `tests/hooks-bookkeeping-stamps-gate.test.js` passes unchanged.
