# 2067: crossReferenceKeyFiles: sibling-title substring match lacks word boundaries, and re-parses/re-greps per outer unit

## Current State
In `plugin/bin/lib/issues/decomposition-crossref.js`'s `crossReferenceKeyFiles` (line 57), sibling-title matching uses a plain lowercased substring test (`line.toLowerCase().includes(titleLower)`, line 72) with no word-boundary check — a short/generic sibling title can appear as a substring inside an unrelated longer word or phrase in another unit's Gotchas/Prerequisites text, wrongly attaching that unit's grep hits to the wrong sibling's Key Files list. Separately, `extractSection(other.body, 'Gotchas'/'Prerequisites')` (line 68) is recomputed inside the inner `for (const other of list)` loop on every outer `unit` iteration, even though each `other`'s section text doesn't depend on the outer unit — O(N^2) re-parsing for a decomposition batch of N sub-issues — and the injected `grep(ident)` subprocess call (line ~76) has no memoization across outer units sharing the same identifier, real avoidable subprocess-spawn cost that scales with batch size.

## Deliverables
- [ ] Add a word-boundary check to the sibling-title substring match, reusing the existing `escapeRegExp` helper (`plugin/bin/lib/shared-primitives.js`) to build a `\b{escaped title}\b` regex rather than writing a new escaper — the title is user-authored text and may itself contain regex metacharacters.
- [ ] Hoist the `extractSection(other.body, 'Gotchas')` / `extractSection(other.body, 'Prerequisites')` computation for each `other` outside the outer `unit` loop (compute once per `other`, into a map keyed by `other`, not once per unit×other pair).
- [ ] Memoize `grep(ident)` results (a `Map<string, string[]>`) across outer units within one `crossReferenceKeyFiles` call, so the same identifier is grepped at most once per batch regardless of how many units reference it.

## Acceptance Criteria
1. A test with a short generic sibling title (e.g. "Fix") that also appears as a substring of an unrelated word in another unit's Gotchas text does not wrongly cross-reference.
2. A test confirms `extractSection` is called at most once per distinct `other` unit within one batch (not once per unit×other pair) — e.g. via a call-counting wrapper or spy on a batch of 3+ units.
3. A test confirms the injected `grep` is called at most once per distinct identifier within one batch, even when multiple units' Gotchas reference the same identifier.
4. All six existing tests in `tests/bin-lib/issues/decomposition-crossref.test.js` pass unchanged.

## Technical Approach
Reuse `escapeRegExp` from `plugin/bin/lib/shared-primitives.js` (already used the same way in `claim-store.js:415` to build a safe dynamic regex from untrusted text) rather than introducing a second escaping implementation. For the two performance fixes, restructure the double loop so the `other`-keyed work (section extraction) happens once per `other` before the outer `unit` loop runs, and thread a shared `Map` for grep memoization through the whole `crossReferenceKeyFiles` call.
