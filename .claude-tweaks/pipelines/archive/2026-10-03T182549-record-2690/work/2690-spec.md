# 2690: Assess native /design skill vs. Impeccable in design-wrapper

Surface: infra

## Current State

`design-wrapper` currently routes all design-quality work through Impeccable's commands. Anthropic (via the official ClaudeDevs account) announced a native `/design` skill (research preview) with an artboard workflow built on artifacts.

## Deliverables

- Try the native `/design` skill on a sample UI task and compare output/workflow against Impeccable's.
- Decide whether `design-wrapper` should route to native `/design` for artboard-style exploration and keep Impeccable for its deeper critique/audit passes, or stay Impeccable-only.

## Acceptance Criteria

- A short comparison note (strengths/gaps of each) checked into the `design-wrapper` skill or its docs.

## Release Note

No user-visible change: compared Claude Code's native design skill with Impeccable for design work.

## Technical Approach

Run the native `/design` skill against one real or representative UI task, capturing its output and workflow shape. Compare against `design-wrapper`'s existing Impeccable-routed passes (`skills/design-wrapper/modes/`) on the same task where feasible. Write the comparison as a short note covering: what each is good at, where they overlap, and whether a routing split (native `/design` for artboard exploration, Impeccable for critique/audit) is worth implementing versus staying Impeccable-only.

### Key Files

- `plugin/skills/design-wrapper/` — where a routing decision would land if adopted
- `plugin/skills/design-wrapper/modes/` — the existing Impeccable-routed passes to compare against

## Gotchas

- Native `/design` is explicitly a research preview — note its maturity/stability in the comparison, since a routing decision based on a preview feature may need revisiting as it matures.
- This is a comparison-and-decide record, not a commitment to change `design-wrapper`'s routing — if the decision is "stay Impeccable-only," that's a valid, complete outcome.
