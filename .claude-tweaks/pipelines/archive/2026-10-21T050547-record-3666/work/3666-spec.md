# 3666: Resumed /build with a valid plan skips Common Steps 1.5-1.7 unconditionally

Origin: wrap-up leftover from #3377

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/skills/build/SKILL.md` Spec Step 2 says "If the plan is still valid and work remains, skip to Common Step 2" (line 84, and again at line 151). Common Steps 1.5 (plan audit), 1.6 (plan review, added by #3377) and 1.7 (design pre-build) sit between Spec Step 3 and Common Step 2, so a resumed build whose plan is still valid never runs any of them. Found at #3377's final review; it predates that record, which only added the 1.6 instance of it.

## Deliverables

- [ ] Decide, per skipped step, whether a resumed build with a valid plan should run it (plan audit and design pre-build are idempotent re-checks; the plan review is a once-per-plan gate that a resume has probably already passed).
- [ ] Make the Spec Step 2 resume branch state which of Common Steps 1.5-1.7 it runs, skips, or conditionally re-runs (for example when the spec or plan changed since the last run), instead of jumping to Common Step 2 unconditionally.
- [ ] Pin the chosen behaviour in the build conformance suite.

## Acceptance Criteria

1. The Spec Step 2 resume branch names Common Steps 1.5, 1.6 and 1.7 and what a resumed build does with each.
2. A conformance test fails if the resume branch goes back to an unconditional skip to Common Step 2.
3. npm test passes.

## Release Note

A resumed build with a still-valid plan now says which pre-execution checks it re-runs, so a plan or spec that changed between runs is audited again.

## Technical Approach

### Key Files

- `plugin/skills/build/SKILL.md` — Spec Step 2 resume branch (lines ~84 and ~151)
- `plugin/skills/build/plan-review.md` — state whether a resumed build re-runs the plan review
