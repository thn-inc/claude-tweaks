# 1213: review: build-review-context.js scratch dir collides with a common tmp/ deny rule

Origin: Discovered during #316's /flow review (Step 3 lens dispatch)

Defer-reason: tangential

## Current State

plugin/bin/build-review-context.js nests its scratch directory at {run-dir}/tmp/review-ctx/ (per _shared/pipeline-run-dir.md), and /claude-tweaks:review's Step 3 lens dispatch (step3-lens-dispatch.md) hands every dispatched lens agent this path to read.

A user carrying "Read(**/tmp/**)" in ~/.claude/settings.json's permissions.deny (a broad, defensible glob meant to block system-/tmp reads) also blocks reads of this nested project-relative path, since the glob matches any tmp/ path segment, not only the leading system one.

Observed live during #316's review: two independently-dispatched lens agents (3b Security, 3c Error Handling) both hit Read/Bash denial on {run-dir}/tmp/review-ctx/context.md and reported it plainly. One agent self-recovered by reconstructing the diff via direct git diff origin/main...{branch} commands; the other returned BLOCKED and had to be re-dispatched with explicit file paths instead of the bundle.

## Deliverables

- [ ] Rename build-review-context.js's scratch subdirectory away from a literal tmp path segment (e.g. {run-dir}/review-ctx/ directly, or {run-dir}/scratch/review-ctx/), OR document this collision in the lens-dispatch prompt with a mandatory git-diff fallback so a BLOCKED agent doesn't stall the review.

- [ ] Sweep other bin/*.js scratch-dir conventions for the same tmp/ segment pattern, since this is a naming convention, not a one-off in this file.

## Acceptance Criteria

1. A lens agent dispatched under an environment with Read(**/tmp/**) denied can complete its review without hitting a permission BLOCKED state on the context bundle path.

2. No other bin/*.js scratch directory nests a literal tmp/ path segment under a project-relative run directory.
