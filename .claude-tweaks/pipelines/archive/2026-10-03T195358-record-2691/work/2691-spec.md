# 2691: Add a cross-session self-healing pass (a /dream-style skill)

Surface: infra

## Current State

claude-tweaks' `harness-health`, `reflect`, and `wrap-up` skills each look at recent work, but none mines the full session corpus for mistakes repeating across sessions. A described "/dream" skill pattern: a nightly pass over every stored session that finds patterns no single session could see, proposes (never applies) a fix, and requires a two-session evidence bar with quoted turns before touching always-loaded context.

## Deliverables

- Prototype a corpus-wide pass (in `harness-health`, or a new scheduled routine) that surfaces repeated cross-session failures as dated proposals.
- Carry over the read-only/propose-only safety model and the two-session evidence bar before anything lands in CLAUDE.md or a skill.

## Acceptance Criteria

- Run against this account's own session history and produce at least one real proposal with quoted evidence.
- Proposals are reviewable and rejectable, never auto-applied.

## Release Note

Added a cross-session pass that proposes fixes for failures that keep repeating across sessions.

## Technical Approach

Prototype as a new pass rather than folding into an existing skill initially, given the distinct evidence-bar requirement (two independent sessions, quoted turns) that `harness-health`/`reflect`/`wrap-up` don't currently carry. Scope the prototype to a bounded session-history window first (not the full corpus unbounded) to keep the pass tractable, and enforce the read-only/propose-only model structurally — the pass writes proposals to a staged location for human review, never edits CLAUDE.md or a skill file directly, mirroring this repo's existing staged-proposal pattern (`_shared/staged-patch.md`).

### Key Files

- `plugin/skills/harness-health/` — natural home if folded in, or the reference pattern for a new sibling routine
- `plugin/skills/_shared/staged-patch.md` — the existing staged-proposal pattern to reuse for propose-only output

## Gotchas

- The two-session evidence bar is load-bearing — a single-session anomaly should never produce a proposal; verify the prototype actually enforces this rather than treating it as documentation-only guidance.
- This scans real session transcripts, which may contain sensitive content — confirm what's in scope for the corpus scan (this account's own sessions only, per the Acceptance Criteria) and don't widen it without an explicit decision.
