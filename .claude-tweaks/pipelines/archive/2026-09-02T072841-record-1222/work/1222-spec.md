# 1222: wrap-up verify verb: plans-ledger/design-caches structurally blind to worktree-local leftovers under default pr-first mode

Origin: record #900's wrap-up verify verb (plugin/bin/lib/wrap-up/engine-verify.js), whole-branch re-review finding #3, 2026-08-21.
Defer-reason: genuinely-larger

## Current State

`plans-ledger` and `design-caches` (plugin/bin/lib/wrap-up/engine-verify.js) resolve their scan directories against `repoRoot` (the main checkout, via `git rev-parse --git-common-dir`), reused from `run-dir-archived`'s need for `.claude-tweaks/pipelines/` (which genuinely only exists in the main checkout, gitignored, never in a worktree). But `docs/superpowers/plans/`, `docs/plans/`, and `.superpowers/sdd/` are ordinary tracked-repo paths that exist independently in every checkout, and an execution-plan or SDD-ledger file created during a `worktree`/`pr-first` run (this project's default integration model) lives as untracked content in the WORKTREE's own working tree — invisible from the main checkout's working tree even though both share one git object store. Verified live: this very run's own leftover plan file and SDD ledger directory (created in the worktree) were both invisible to a verify run pointed at the main checkout's copy of the run directory, while an unrelated prior session's leftover `.superpowers/sdd/` content in the main checkout was flagged instead.

## Deliverables

- [ ] Thread a separate `cwd` parameter through `runVerify`'s check-argument object (distinct from `repoRoot`, which must stay the main checkout for `run-dir-archived`'s pipeline-directory lookups), defaulting to `process.cwd()` in production (`wrap-up-engine.js`'s `runVerifyVerb`).
- [ ] Switch `plans-ledger`/`design-caches` to read `cwd` instead of `repoRoot`.
- [ ] Rework the test suite's isolation convention for these two checks (currently `makeCleanRepoRoot()`, deliberately isolating `repoRoot` from this worktree's own live/churning content) to pass an isolated `cwd` fixture at every `runVerify()` call site in `tests/bin-lib/wrap-up/engine-verify.test.js` that doesn't already isolate `repoRoot` — otherwise every test in the suite implicitly depends on this worktree's live, churning `.superpowers/sdd/`/`docs/superpowers/plans/` state.

## Acceptance Criteria

1. A `plans-ledger`/`design-caches` leftover created in a worktree is caught by a verify run invoked from that same worktree, matching how the CLI is actually invoked in production under the default `worktree`/`pr-first` mode.
2. The existing `npm test` suite stays fully green and no longer depends on this worktree's own live filesystem state for any `plans-ledger`/`design-caches` assertion.
3. `run-dir-archived`'s existing `repoRoot`-based (main-checkout) resolution is unchanged — this fix must not regress that check, which genuinely needs the main checkout.
