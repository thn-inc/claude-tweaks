# 3577: first-call-artifact-check.js does not verify the canonical Step 2.8 claim line the dispatcher's own gate depends on

Origin: reflect hindsight from #2912
Defer-reason: tangential

## Current State

#2912 added a `claim-log` bookend to `plugin/bin/verify-run-bookends.js` (canonical `Step 2.8: claimed #{n}` line in `decisions.md`) and required it of the first call on every transport. That check is a self-run step inside call 1 — the same agent whose bypass of `/claude-tweaks:flow` produced the missing-line incident (#2765) is the one told to run it. The dispatching session's own mechanical backstop, `plugin/bin/lib/dispatch/first-call-artifact-check.js` (`checkFirstCallArtifacts`, `dispatch/two-call-gate.md` section 2), checks run-state, config.yml, the live claim blob, the PR and the materialized spec, but never reads `decisions.md`. The two checkers also overlap (worktree, PR, claim and materialize are verified in both) and share the `integration-model` read gap #3350 owns; a single shared reader behind both is the larger version of this follow-up and is out of scope here. A first call that skips the self-check and reports `DONE`/`build-test-ok` therefore reaches call 2 with a non-canonical or missing claim line, and the stamps gate in `pre-tool-use.js` denies call 2's first push.

## Deliverables

1. `checkFirstCallArtifacts` reads each member's `decisions.md` claim line through `hasCanonicalClaimLogFor` (`plugin/bin/lib/log-decision/claim-log.js`) and returns `{ ok: false, reason, message }` naming the missing member when the canonical line is absent.
2. `dispatch/two-call-gate.md` section 2 lists the new check beside the others.
3. A regression test in the first-call-artifact-check suite fails when the line is absent and passes when it is present.

## Acceptance Criteria

- `checkFirstCallArtifacts` returns `ok: false` for a run directory whose `decisions.md` lacks `Step 2.8: claimed #{n}` for a member, and `ok: true` once the line is written.
- The `integration-model` read gap stays with #3350 and is not touched here.
