# 2612: tidy standalone-auto: report-condensed.md and staged/ can silently drift, leaving --approve nothing to resume from

Surface: infra

## Current State

`/claude-tweaks:tidy`'s standalone-auto Approve report (`report-condensed.md`) is agent-composed prose, written independently from the `staged/*.md` files it describes — nothing in the skill's own procedure cross-checks that the two agree before a run is considered complete. Observed directly this session: a prior standalone tidy run's `report-condensed.md` listed 14 Approve items (title, finding, proposed command, full text) while `staged/` on disk held zero files — `/claude-tweaks:tidy --approve` on that run had nothing to resume from. The 14 files had to be hand-reconstructed from the report's own text, matching the exact template a prior run's staged files used, before `--approve` could execute anything.

Root-cause chain (confirmed): no script generates `report-condensed.md` — `plugin/skills/tidy/step-6-auto.md` and `SKILL.md` are the only hits for the filename, both skill prose, not a `bin/*.js` renderer. The report and the staged files are two independent writes from the same tidy pass, with no shared source of truth and no later verification that both landed.

## Deliverables

- Standardize each `staged/*.md` proposal item with a machine-readable sidecar written alongside it at staging time: `staged/{name}.json` — an array of `{tag, record, title, action, command}` objects, one per proposal item in that file.
- Add `plugin/bin/render-tidy-report.js` — reads every `staged/*.json` sidecar under a run dir and renders the Approve section's exact three-line-per-item shape (number + tag + record + title, then the staged action, then the exact command).
- `step-6-auto.md`'s Step 6 stops hand-composing the Approve section as independent prose — it invokes the renderer and uses its output verbatim for both `report.md`/`report-condensed.md`.
- `approve-mode.md`'s "Re-entering the Approve rendering" step reuses the same renderer instead of its own re-composition instructions, so a later `--approve` run reads the identical rendering path a fresh run would.
- Update `plugin/bin/tidy-report-lint.js`: drop the Approve-section format checks the renderer now guarantees by construction (or repoint them at the renderer's own output), so the lint and the renderer never enforce the same rule two different ways.

## Acceptance Criteria

- A tidy standalone-auto run whose `report-condensed.md` Approve section and `staged/` directory could previously disagree can no longer diverge — the Approve section is generated by iterating `staged/*.json`, so it cannot describe an item that isn't on disk, and cannot omit one that is (inverse drift closed by construction, not by a separate check).
- `npm test` passes, including new coverage in `tests/bin/render-tidy-report.test.js`: (1) the renderer produces the exact expected Approve-section text from a fixture `staged/` directory holding multiple `.json` sidecars; (2) a staged item added to the fixture after an initial render is present on the next render, proving the report can never trail `staged/`'s actual contents.
- `node "${CLAUDE_PLUGIN_ROOT}/bin/tidy-report-lint.js" --surface=condensed` still passes against a renderer-produced report.

## Technical Approach

Render-from-staged (chosen over a post-write parity assertion, which would only detect drift after the fact rather than making it structurally impossible): `staged/*.json` becomes the single source of truth for the Approve section's content. `step-6-auto.md`'s Step 6/7 write each staged item's `.json` sidecar at the same point it already writes the item's human-readable `.md` file — both describe the same proposal, but only the `.json` is ever read back to render the Approve section. `render-tidy-report.js` takes a run dir, globs `staged/*.json`, flattens every file's item array in file-then-item order, and renders the fixed three-line-per-item template — this becomes the one place that template is implemented, replacing today's duplicated agent-prose composition.

### Key Files

- `plugin/bin/render-tidy-report.js` — new renderer; reads `staged/*.json`, renders the Approve section
- `plugin/skills/tidy/step-6-auto.md` — Step 6/7 staging + report-composition instructions
- `plugin/skills/tidy/approve-mode.md` — "Re-entering the Approve rendering" step
- `plugin/bin/tidy-report-lint.js` — Approve-section format checks, now redundant with the renderer
- `tests/bin/render-tidy-report.test.js` — new test coverage

## Gotchas

- The `.json` sidecar and the `.md` file describe the same proposal from two writes; nothing enforces they stay in sync with each other (only that the Approve section stays in sync with the `.json` side) — a future divergence between a staged item's human-readable prose and its machine-readable fields is a smaller, cosmetic version of the bug this record fixes, not eliminated by this design. Worth a one-line note in `step-6-auto.md` calling this out explicitly so it isn't rediscovered the same way #2612 itself was.
- `tidy-report-lint.js`'s existing Approve-section checks need to be reconciled with the renderer rather than left running in parallel — two independent enforcers of the same format is the same class of drift risk this record is fixing, at one remove.

## Breaking Change

None — this is an internal tooling/format change to `/claude-tweaks:tidy`'s own run-directory contents. No public flag, CLI verb, exported function, or `_shared/*.md` convention that external consumers rely on is removed or renamed; `staged/*.json` is new, additive content alongside the existing `staged/*.md` files.
