# 1446: reconcile: move-failed stuck on /Users/thomasholknielsen/Code Workspaces/claude-tweaks/.claude-tweaks/pipelines/2026-08-20T211123-record-1011

Surface: backend

**Related:** #1447

## Current State

Reconcile's merged-PR archival sweep (`archive-merged.js`) treats every filesystem move/mkdir
failure as an opaque `move-failed` result — every `catch` block that produces this reason
discards the underlying `Error` object entirely (`catch { ... }`, no binding). When the same run
directory fails 3 consecutive reconcile passes, `trackArchiveResult` escalates by filing a GitHub
issue via `escalateResidue`, but never supplies a `lastError`. `escalateResidue`/`residueBody`
(`escalate-residue.js`) and `recordResidueFailure` (`cache.js`) already accept and render a
`lastError` field in the issue body's "**Last error:**" line — the plumbing exists — but nothing
upstream ever populates it, so it's dead code today. #1446 is a live instance of the resulting
problem: reconcile failed `move-failed` for 3 consecutive passes on one run directory, and the
automatically-filed issue names only the path and the generic reason, giving a human nothing to
diagnose without reproducing the failure by hand on the affected machine.

The sibling check for worktree removal residue, `reap-merged.js`'s `trackReapResidue`, already
does this correctly: it accepts `lastError` from its caller and threads it straight into both
`recordResidueFailure` and `escalate(...)` (`reap-merged.js:74-86`). `archive-merged.js`'s
`move-failed` path is the one residue class that never adopted this.

## Deliverables

- Every catch block in `archive-merged.js` that returns `{ reason: 'move-failed' }` or
  `{ reason: 'move-failed-partial-revert' }` captures the underlying error (bind it in the
  `catch` clause) and includes it in the returned result, e.g.
  `{ ok: false, reason: '...', lastError: err.message }`. Sites: `archiveOrphanedMint`'s
  combined mkdir+rename try block, `archiveRunDir`'s top-level plain-move loop, its spec-dir
  archive-dir mkdir, and its spec-dir plain-move loop.
- `trackArchiveResult` forwards `result.lastError` into both `recordResidueFailure`'s options
  (`{ lastError: result.lastError }`) and the `escalate(...)` call's payload — mirroring
  `reap-merged.js`'s `trackReapResidue`.
- No change to any other failure reason (`mkdir-failed`, `git-mv-failed`, `commit-failed`,
  `ls-files-failed`, `readdir-failed`, `tracked-entry`, `close-failed`) — only `move-failed`/
  `move-failed-partial-revert` are tracked/escalated today, and widening the tracked set is out
  of scope here.

## Acceptance Criteria

- A test drives `archiveRunDir`/`archiveOrphanedMint` through a plain-move (or mkdir) failure
  (e.g. by making the destination path unwritable, or by injecting a failing `fs` call) and
  asserts the returned result carries a non-empty `lastError` string containing the underlying
  error's message.
- A test asserts that when `trackArchiveResult` escalates at the failure threshold, the
  `escalate` call it makes includes a `lastError` matching the failing result's `lastError`
  (extending the existing `trackArchiveResult` escalation tests in
  `tests/bin-lib/reconcile/archive-merged.test.js`).
- A test asserts `recordResidueFailure`'s cache entry for the (`move-failed`, path) key carries
  the supplied `lastError` after `trackArchiveResult` runs (`cache.test.js` already covers
  `recordResidueFailure`'s own `lastError` storage in isolation — this closes the missing
  caller-side wiring test).
- `npm test` passes in full (no regressions in `tests/bin-lib/reconcile/*`).
- A freshly-escalated `move-failed` issue body (via `residueBody`) renders a non-empty
  "**Last error:**" line — confirmed by the updated/added tests above, not a new manual repro.

## Technical Approach

Mirror `reap-merged.js`'s already-correct pattern (`trackReapResidue`, lines ~74-86) onto
`archive-merged.js`'s `move-failed` path:

1. In each of the four catch sites listed under Deliverables, change `catch {` to `catch (err) {`
   and add `lastError: err.message` (or `err && err.message`) to the returned
   `{ ok: false, reason, ... }` object.
2. In `trackArchiveResult`, change:
   ```js
   const streak = recordResidueFailure(root, 'move-failed', dir);
   ```
   to
   ```js
   const streak = recordResidueFailure(root, 'move-failed', dir, { lastError: result.lastError });
   ```
   and add `lastError: result.lastError` to the `escalate({...})` call's payload —
   `recordResidueFailure` (`cache.js`) already accepts and persists a `lastError` option; no
   change needed there. `escalateResidue`/`residueBody` (`escalate-residue.js`) already accept
   and render `lastError`; no change needed there either.
3. Do not touch `mkdir-failed`, `git-mv-failed`, `commit-failed`, `ls-files-failed`,
   `readdir-failed`, `tracked-entry`, or `close-failed` — `trackArchiveResult`'s own header
   comment (`archive-merged.js` ~line 452) states only `move-failed` is tracked, and broadening
   that is a separate decision this record doesn't make.

## Gotchas

- `archive-merged.js`'s catch blocks are deliberately bare (`catch { ... }`) elsewhere for
  genuinely best-effort operations (e.g. `revertWorkMoves`/`revertPlainMoves`'s own best-effort
  reverts, and the late-write-guard straggler sweep) — only the four sites that produce the
  tracked `move-failed`/`move-failed-partial-revert` reason need an error binding; don't add
  error capture to every catch block in the file, since most exist specifically to swallow
  errors silently by design.
- `err.message` on a Node `fs` error (e.g. `EACCES`, `ENOENT`, `ENOTEMPTY`) already includes the
  path and errno code in a human-readable form — no need to separately format `err.code`/
  `err.path`; just forward `err.message` as-is, matching `reap-merged.js`'s own convention of
  passing through whatever string its caller already had.
- This fix is diagnostic, not curative: it does not retroactively add a `lastError` to the
  already-filed #1446, and it does not by itself unstick the specific run directory named there
  (`.../pipelines/2026-08-20T211123-record-1011` on the reporting machine, outside this sandbox's
  reach) — that stuck path still needs a human to look at it once this ships and it re-escalates
  (or is manually cleared). The deliverable here is making the *next* occurrence of this class of
  failure diagnosable without a repro.
