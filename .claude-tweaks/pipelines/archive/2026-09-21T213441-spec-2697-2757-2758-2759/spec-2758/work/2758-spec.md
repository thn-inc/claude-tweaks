# 2758: Feature walkthrough: /claude-tweaks:walkthrough, a shareable animated GIF plus caption list from an executed story via a vendored encoder

Surface: infra

**Related:** #2757 — the activity-report record from the same djoef-adoption design pass; shares the five docs registration files

## Overview

Add `/claude-tweaks:walkthrough`: execute an existing schema-v2 user story through Playwright CLI, capture one screenshot frame per step, and encode an animated GIF plus an ordered caption list that a second person can open, attach to a PR, or commit into a docs directory. Today the capture already happens (the `qa-agent` and `/claude-tweaks:visual-review` both screenshot every step) but every frame lands under `.claude-tweaks/artifacts/`, which is declared disposable tooling residue on a 30-day `/claude-tweaks:tidy` cleanup. The frames exist and are thrown away; what is missing is an encoder and a place to put the result.

The capability is adopted from the `djoef` plugin's `feature-demo` skill; the implementation is explicitly not. djoef records video through the `playwright` npm library with four npm dependencies self-installed on first use. This plugin ships **zero runtime dependencies** — no `plugin/package.json`, nothing ever runs `npm install` for a marketplace-installed plugin — and browser automation is an externally-installed CLI tool (currently Playwright CLI, `CHANGELOG.md` v6.128.0/#2645-#2649; an interim tool, agent-browser, was replaced by it — this record's build base already ships Playwright CLI), never a bundled npm dependency of this plugin itself. The decision is therefore to **vendor a minimal GIF encoder** (LZW compression plus palette quantization, plus the PNG decoder the design doc left implicit, since Playwright CLI screenshots are PNG) under `plugin/bin/lib/gif/`, tested under `node --test` like any other module.

The name avoids `/claude-tweaks:demo`, which already exists and means human acceptance sign-off on a built thing.

**Complexity:** High
**Estimated tasks:** 10 (Task 0, PNG decoder, palette + LZW, GIF writer, walkthrough encode module + CLI, story selection module, stories schema field, skill, registration, tests). This exceeds the standard 8-task target deliberately: the four codec modules are each under ~100 lines and share one test harness, and the user chose one record over a codec/skill split.

## Non-Goals

- Burned-in captions. Rasterizing text into frames needs an image library (native dependency, ruled out) or a vendored text rasterizer (more code than the encoder itself); injecting a caption banner into the page needs arbitrary JS evaluation, which Playwright CLI's documented operation set does not expose. Captions are an ordered markdown list beside the GIF.
- True motion capture (cursor travel, scroll, CSS transitions). Playwright CLI exposes no screencast or frame-capture operation (`tracing-stop` produces a trace file, not a playable recording, and offers no output-path control). This is stepwise animation: each state with its caption. Should Playwright CLI gain a screencast operation, only the frame source changes.
- A second story schema (`demo.yml`). The stories v2 schema already has semantic locators and the same CSS/id ban; the only addition is one optional per-step field.
- APNG output. Node's `zlib` would make the encoder a quarter the size with truecolor frames, but APNG support in chat clients is inconsistent while GIF renders everywhere a PR body does. Revisit if destinations narrow.
- Embedding walkthroughs into the activity report (see **Related**). A later, deliberate integration once both exist independently.
- Any consuming app's in-product help or news surfaces.
- Authoring a story when none matches. `/claude-tweaks:stories` owns story authoring; this skill offers to invoke it and stops.

## Technical Approach

**Pipeline:** story YAML → Playwright CLI session (one `snapshot` + ref-based action per step, then `screenshot --filename=<path>`) → N PNG frames in the session temp dir → `walkthrough-encode.js` (decode → downscale → global median-cut palette → LZW → GIF89a) → `{name}.gif` + `{name}.md` caption list at the user-chosen location.

**Stepwise animation, not motion.** One frame per step, captured after the step's action settles (the ref-based action command returns after the action completes; add a `wait` per `playwright-cli-reference.md`'s operation vocabulary only when a step declares one). Frames hold 2 s by default, the last 4 s so the loop does not snap away from the result.

**Decoder scope from Task 0.** Implement exactly the PNG color types the baseline covers: 0, 2, and 6, 8-bit, non-interlaced. Task 0's live probe observed color type 2 (RGB, 8-bit, non-interlaced) — already inside the baseline, so no widening. Supporting types 0 and 6 alongside the observed type 2 costs one branch each in the unfilter loop; anything else throws `PngDecodeError` so a future Playwright CLI change fails loudly at the first frame.

**Budget.** `--budget-mb` defaults to 8. The check runs on the encoded buffer before any write; over budget returns the lever list in order: fewer steps, then lower `--width`. Frame delay does not change size and is not offered as a lever.

**Story selection for `#N`.** Fetch the record (`gh issue view N --json body`), read its `### Key Files` via `extractKeyFiles` (`plugin/bin/lib/issues/grouping.js`), collect any `docs/journeys/{name}.md` names the body cites, and call `select.js`'s `selectStories` over the parsed `stories/*.yaml` files. Zero matches: offer `/claude-tweaks:stories` and stop. More than one: one `AskUserQuestion` listing them by `id` and `matchedBy`.

**Frame dimensions.** All frames must be identical in size (one logical screen, one global palette). The skill guarantees this by setting the viewport explicitly at session open; the encoder enforces it with `FrameMismatchError` rather than padding or cropping, so a viewport change mid-run fails loudly instead of producing a torn animation.

## Gotchas

- Playwright CLI screenshots are PNG; the design doc's "vendor a GIF encoder" silently assumed frames arrive as raw pixels. The PNG decoder is a real deliverable (roughly 120 lines with `zlib.inflateSync`). Types 0/2/6 are the baseline; Task 0 can only widen it, never narrow it, so a later editor touching the type-0 or type-2 branch has a fixture telling them what breaks.
- `find … <action>` returning means the command completed, not that the page is visually settled. The `--settle-ms` wait covers ordinary transitions; a story whose step triggers a slow async render needs an explicit `wait` step for the walkthrough even when QA never needed one, and the skill says so.
- The LZW table must reset at 4096 codes and the code size must grow from `minCodeSize + 1` up to 12 bits exactly as decoders expect; an off-by-one here produces a GIF that some viewers open and others reject. The test-file reference decoder is what makes AC 3 trustworthy; do not assert only on byte counts.
- Use one global color table for the whole animation, not a local table per frame: per-frame palettes make cross-frame flicker on identical backgrounds and cost 768 bytes per frame.
- `screenshot --filename=<path>` paths must be space-free (pinned Playwright CLI limitation, `playwright-cli-reference.md`); the session temp dir naming above has none.
- Every story-supplied string spliced into a `playwright-cli` command argument (a locator's `name`/`text`/`label`/`placeholder`, or a `fill`/`press` value) must be shell-escaped per `qa-agent.md` Section 4's escaping rule before interpolation — the same discipline `qa-agent.md` already applies at runtime.
- Never use `backend=chrome` here; `browse/SKILL.md` restricts that escape hatch to human ad-hoc use and explicitly forbids it for `qa-agent`, `/stories`, `/visual-review`, `/review`, and `/flow` (`CLAUDE.md`'s Don'ts) — this skill is the same kind of pipeline-adjacent consumer and stays `playwright-cli`-only, which also keeps it portable to hosted Routines.
- `stories/SKILL.md` has about 10 KB of headroom under the 45 KB advisory ceiling and is also touched by open record #2283 (absolute-origin rewriting); keep the schema addition to the field line plus one sentence, and re-measure with `wc -c`.
- `qa-agent.md` maps step keys explicitly; because it never enumerates unknown keys, `caption` is already ignored at runtime. The one-sentence note makes that a stated contract rather than an accident, so a future "reject unknown keys" hardening cannot silently break walkthrough stories.
- `tests/bin-lib/skill-audit/anti-patterns.test.js` keeps a live-corpus row-count ledger for `## Anti-Patterns` tables; adding one on the new SKILL.md means updating that count and its comment ledger.
- The reference-card argument column must be byte-equal to the frontmatter `argument-hint` (`tests/reference-card-argument-hint.test.js`).
- Do not auto-detect the dev server. A walkthrough recorded against the wrong environment is silently wrong rather than obviously broken, which is why `--base` is required.
- The five docs registration files are also edited by the sibling activity-report record (see **Related**); expect a trivial merge on them if both build concurrently.

## Decision Rationale

- **Vendored encoder over Playwright/gifenc.** Playwright reverses a deliberate removal on record and would make a marketplace plugin install a browser engine; any npm dependency breaks the zero-dependency property a cache-installed plugin relies on. A vendored ~300-line encoder plus ~120-line PNG decoder is code this repo can test and own.
- **GIF over APNG.** Reach: GIF renders in PR bodies, chat clients, and docs tooling; APNG is inconsistent in chat clients.
- **Reuse stories v2 over a `demo.yml` schema.** The two are near-identical; a second authoring format for the same concept is the duplication `shared-contract-extraction` exists to prevent. One optional field is expand-only: no existing story changes meaning.
- **Captions beside, not burned in.** Both burn-in routes need capabilities the plugin cannot take (an image library or arbitrary JS evaluation); a GIF plus caption list degrades well when the GIF does not render.
- **Output outside `.claude-tweaks/artifacts/`.** A walkthrough exists to be kept; writing it into a tree `/tidy` prunes after 30 days would defeat it. Nothing is committed on the user's behalf.
- **Stepwise animation accepted as a limitation, not deferred.** The communicated content is *what happens when you do this*, which survives the loss of interpolation.
