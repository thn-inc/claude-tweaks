# 1705: docs/skill-graph.md's stated-once convention has no mechanical enforcement

Surface: infra

## Current State

docs/skill-graph.md states its "stated once, under the alphabetically-first citing skill" convention in its own "How to read this" preamble and is followed by every existing multi-caller `_shared/*.md` row (`causal-depth.md`, `pr-early-run-lifecycle.md`, `session-tmp-root.md`, and others) — confirmed by grep, none carry a reciprocal row in another citing skill's section. Nothing mechanical enforces it: `tests/skill-graph-table-structure.test.js` checks pipe and cell counts only, never cross-reference completeness or reciprocal-row duplication.

Record #1423's own build (commit fc2160ba2) violated the convention once — the new `_shared/dependency-narration-check.md` row under `capture` closed with "see the specify section," a pointer to content the convention says should not exist — and that record's own review compounded it on the first fix attempt (commit 07e1c545a) by adding the missing section instead of removing the false pointer, before a second, deliberate read caught and corrected both (commit 0bb704229). Nothing mechanical would have caught either the original defect or the first wrong fix; only a second careful read of the file's own stated convention did.

A follow-up commit on #1423 (606ffad76) added `tests/dependency-narration-check-conformance.test.js`, which pins the single-instance case (the new `_shared/dependency-narration-check.md` row lives once, under `capture`, never restated under `specify`) — but it does not generalize: it names that one contract file explicitly and would not catch the same mistake recurring against any other `_shared/*.md` row.

## Deliverables

Either:
- Add a conformance check (to `tests/skill-graph-table-structure.test.js` or a new sibling test) that generically flags any `_shared/*.md` target appearing under more than one skill section in `docs/skill-graph.md`, unless both rows are explicitly marked as a deliberate reciprocal pair (the `challenge`/`specify` pair is the one known legitimate exception — a skill-to-skill edge with deliberately different framing in each direction, not a shared `_shared/*.md` contract row) — and/or flags a "see the {section} section" pointer phrase with no matching content in that section; or
- Strengthen `docs/skill-graph.md`'s own "How to read this" preamble with a one-line warning against adding a reciprocal row for a `_shared/*.md` file already owned elsewhere, as the cheaper (non-mechanical) alternative.

## Acceptance Criteria

- A red-proof commit reintroducing the exact defect pattern from fc2160ba2/07e1c545a (a `_shared/*.md` row restated, or a "see the {section} section" pointer with no matching content) fails the new/updated test before the fix and passes after.
- Existing precedent files (`causal-depth.md`, `pr-early-run-lifecycle.md`, `session-tmp-root.md`, and the `challenge`/`specify` reciprocal pair) all still pass — the check must not false-positive on the one known legitimate exception.
- `npm test` stays green (6826+ tests) after the change.

Cost this session (#1423): one wrong commit (07e1c545a) written, pushed, and then corrected by a second commit (0bb704229), plus two extra full `npm test` runs of 6826 tests each to re-verify.

## Technical Approach

Add the generic reciprocal-row/pointer-phrase check to tests/skill-graph-table-structure.test.js (or a new sibling test file) as a mechanical scan: parse docs/skill-graph.md's per-skill sections, build a map of every cited _shared/*.md filename to the skill section(s) that cite it, and flag any target with more than one citing section, unless both rows carry an explicit reciprocal-pair marker (seed the exception list with the known challenge/specify pair). Separately, grep every section body for the literal phrase "see the {section} section" and confirm a heading matching {section} actually exists in the target section, flagging when it doesn't. Model the reciprocal-pair exception list as an explicit, editable array in the test file itself, not inferred heuristically, so a legitimate future exception is a one-line addition rather than a parser special case. Choose between the two Deliverables alternatives (mechanical check vs. preamble warning) during implementation and note which was chosen.

### Key Files

- tests/skill-graph-table-structure.test.js - extend with the generic reciprocal-row and dangling-pointer checks, or add a new sibling suite
- docs/skill-graph.md - target of the new checks; only edited if the cheaper preamble-warning alternative is chosen instead

## Gotchas

- The two Deliverables alternatives are not both required - pick one and note which was chosen in the PR description; the mechanical check is stronger, the preamble warning is cheaper.
- The reciprocal-pair exception list must include challenge/specify from day one, or the new check false-positives immediately.
- A _shared/*.md filename can legitimately appear in running prose without being a table-row citation (a narrative cross-reference) - key the check off the table-row citation shape specifically, not any mention of the filename, to avoid a third false-positive class.
