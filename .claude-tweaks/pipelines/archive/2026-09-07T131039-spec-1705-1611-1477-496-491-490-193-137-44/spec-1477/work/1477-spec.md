# 1477: wrap-up verify: converge engine-verify.js's process.cwd() sites onto threaded cwd param

Surface: backend

## Current State

`plugin/bin/lib/wrap-up/engine-verify.js`'s checks are wrap-up's closure-gate verifications (deterministic `git`/`gh` reads via an injectable `deps.git`/`deps.gh` seam). #1222 (now closed — the underlying PR #1476 itself closed unmerged, but the `cwd`-threading work landed via a different path, confirmed live below) threaded a distinct `cwd` parameter — the invoking checkout, e.g. a linked worktree under this project's default `worktree`/`pr-first` mode — through `runVerify` and into the `plans-ledger`/`design-caches` checks, replacing those two checks' prior hard-coded `process.cwd()`/`repoRoot` mix. `run-dir-archived` deliberately keeps resolving against `repoRoot` alone (pinned by its own #1222 regression test) since it does `.claude-tweaks/pipelines/` lookups that must stay anchored to the main checkout regardless of which checkout invoked `verify`.

Eleven other `deps.git`/`deps.gh` call sites in the same file still pass the literal `process.cwd()` instead of the now-available `cwd` parameter: `worktree-removed` (1), `carrier-commit` (2: `git log`, `gh pr view`), `reference-repairs` (2: `git log`, `git diff-tree`), the `ghAvailable(deps)` helper (1), the `resolveParent(n, deps)` helper (1, exported), `acceptance-labeling` (3: two `gh issue view` calls plus one `gh pr view` call, plus reaching `ghAvailable`/`resolveParent`), and `upstream-feedback` (1, reached via `ghAvailable`). Several of these — `carrier-commit`'s `git log`, `reference-repairs`' `git log`/`diff-tree` — mean exactly the "invoking checkout" concept `cwd` now denotes: they read commit history on the run's own branch, which under `worktree`/`pr-first` mode lives in the linked worktree, not the main checkout. Because these call sites hard-code `process.cwd()` rather than accepting an injected path, none of them can be pointed at a fixture directory in a test the way `plans-ledger`/`design-caches` now can — every test exercising them is at the mercy of whatever directory the test runner's own process happens to be invoked from.

#1222 has since closed (2026-09-02) and the `cwd` parameter now exists on `master` — confirmed live: `plans-ledger`/`design-caches` (lines ~166/198 of `engine-verify.js`) already destructure and use `cwd`. This record is no longer blocked; the eleven call sites below are unconverted and buildable now (re-confirmed by grep: exactly eleven literal `process.cwd()` occurrences remain at the sites this record names, plus the two untouched `runVerify` fallback lines noted in Gotchas).

## Deliverables

- Replace the literal `process.cwd()` argument at all eleven remaining call sites in `plugin/bin/lib/wrap-up/engine-verify.js` with the already-threaded `cwd` parameter.
- Widen the two helper functions the eleven sites route through — `ghAvailable(deps)` and the exported `resolveParent(n, deps)` — to accept `cwd` as an explicit parameter, and update every call site of each helper to pass it.
- Extend `tests/bin-lib/wrap-up/engine-verify.test.js` with call-capture assertions (the `{args, cwd}` fake-runner pattern `plans-ledger`'s own tests already use) proving each converted check runs against the injected `cwd`, not the live `process.cwd()`.

## Acceptance Criteria

- Zero occurrences of the literal `process.cwd()` remain inside `worktree-removed`, `carrier-commit`, `reference-repairs`, `ghAvailable`, `resolveParent`, `acceptance-labeling`, and `upstream-feedback` in `plugin/bin/lib/wrap-up/engine-verify.js` — `grep -n "process.cwd()" plugin/bin/lib/wrap-up/engine-verify.js` returns only `runVerify`'s own `repoRoot || process.cwd()` fallback line (deliberately untouched — see Gotchas).
- Each of the seven converted checks/helpers has at least one test asserting the fake `deps.git`/`deps.gh` call it makes receives the injected `cwd` value, not the test process's real working directory — following the existing `statusCall.cwd, repoRoot` assertion pattern `plans-ledger`'s tests use post-#1222.
- Production behavior is unchanged: `wrap-up-engine.js`'s `runVerifyVerb` already supplies `cwd: process.cwd()` explicitly (from #1222's CLI change), so every converted check resolves to the identical directory it resolved to before this change.
- `run-dir-archived` is untouched by this change — its existing `repoRoot`-only regression test (record #1222 AC3) still passes unmodified.
- `npm test` passes.

## Technical Approach

Mechanical parameter-threading, one file plus its test file. For each of the seven check functions currently destructuring `({ ..., deps })` from the object `runVerify` passes them, add `cwd` to the destructure and swap every `process.cwd()` argument inside that function for `cwd`:

- `worktree-removed`: swap `deps.git(['worktree', 'list', '--porcelain'], process.cwd())`.
- `carrier-commit`: swap both `deps.git(['log', ...], process.cwd())` and `deps.gh(['pr', 'view', ...], process.cwd())`.
- `reference-repairs`: swap both `deps.git(['log', '--grep=Initiative-Fix:', ...], process.cwd())` and `deps.git(['diff-tree', ...], process.cwd())`.
- `acceptance-labeling`: swap its own three `deps.gh(...)` calls, and pass `cwd` into its `ghAvailable(deps)` and `resolveParent(n, deps)` calls.
- `upstream-feedback`: swap its own `deps.gh(...)` call, and pass `cwd` into its `ghAvailable(deps)` call.

For the two shared helpers, widen the signature and thread `cwd` through to their own `deps.gh(...)` call:
- `ghAvailable(deps)` → `ghAvailable(deps, cwd)`, used by `acceptance-labeling` and `upstream-feedback`.
- `resolveParent(n, deps)` → `resolveParent(n, deps, cwd)` (exported from the module — no other file currently imports or calls it directly per a repo-wide grep, so this is a safe signature widening, not a breaking change).

`run-dir-archived` is explicitly out of scope — it must keep resolving against `repoRoot`, never `cwd`, per its own #1222 regression test (`run-dir-archived check keeps resolving against repoRoot even when cwd differs and is dirty`).

For tests, mirror the `{args, cwd}`-capturing fake-runner pattern already used for `plans-ledger`/`design-caches` (`tests/bin-lib/wrap-up/engine-verify.test.js`): pass two distinct directories as `repoRoot` and `cwd` in `runVerify(...)` and assert each converted check's captured call carries `cwd`, not `repoRoot` or the real `process.cwd()`.

### Key Files

- `plugin/bin/lib/wrap-up/engine-verify.js` — convert the eleven remaining `process.cwd()` call sites (across `worktree-removed`, `carrier-commit`, `reference-repairs`, `ghAvailable`, `resolveParent`, `acceptance-labeling`, `upstream-feedback`) to the threaded `cwd` parameter; widen `ghAvailable`/`resolveParent` signatures and their callers
- `tests/bin-lib/wrap-up/engine-verify.test.js` — add `cwd`-capture assertions for each converted check/helper

- `run-dir-archived` must NOT be converted to `cwd` — it is deliberately pinned to `repoRoot` (main checkout only) because it resolves `.claude-tweaks/pipelines/archive/` paths, which live in the main checkout regardless of which worktree invoked `verify`. #1222 already added a regression test guarding this; don't weaken or remove it.
