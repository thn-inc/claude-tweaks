## Original request

worktree guard: refuses non-git commands whose arguments are runtime variables, and gh graphql calls

**Summary:** Under `worktree-always`, the worktree-isolation guard denies plain non-git commands (`sed`, `gh api graphql`, `node` loops) whenever an argument is a runtime-computed variable or the command text is "too complex to verify", even though none of them can invoke git.

**Kind:** Defect

**Affected component:** worktree isolation guard (`bin/lib/hooks/pre-tool-use.js`, the wd-deny / "cannot be shown not to be git" branch)

**Repro steps:**
1. In a worktree-isolated session (`worktree-always: ON`), run a Bash call that sets a variable and uses it in a non-git command in the same line: `F="/tmp/notes.md"; sed -n '4,60p' "$F"`.
2. Run `gh api graphql --hostname <ghe-host> -f query='mutation($id:ID!,$body:String!){updateIssueComment(input:{id:$id,body:$body}){issueComment{id}}}' -f id=... -F body=@file.md`.
3. Run a loop with no git in it: `for d in a b c; do node "<plugin>/bin/friction-events.js" --run "$P/$d"; done`.

**Expected vs. actual:**
Expected: all three are allowed — the executable is `sed`/`gh`/`node`, the text contains no `git` token, and nothing in them can target another checkout.
Actual: each is refused: "this command runs sed with a value computed at runtime (the variable F) in a plain command, so what it runs cannot be shown not to be git. Refusing to run it"; "runs gh with the text query=mutation(...) inside a construct too complex to verify, so what it runs cannot be shown not to be git"; the loop is refused as a compound construct. The only way through is to move each into a script file and run that — one extra round-trip per denial (about six this run; a multi-spec wrap-up reads many long procedure files with `sed -n` ranges, which is exactly where it bites).

**Definition:** Clear

**Plugin version:** 6.126.0
