## Original request

Upstream defect report — worktree guard refuses in-worktree compound commands and matches `eval` as a substring

Component: `bin/lib/hooks/pre-tool-use.js` (the worktree-isolation guard on Bash)
Kind: defect
Version: claude-tweaks 6.126.0, Windows 11, Git Bash

## Symptom

On a worktree-isolated session the guard refused at least fifteen Bash commands whose every path was inside the worktree, with "this command is too complex to verify that it stays inside the worktree": (1) `A="…literal…"; node … --files "$A"` (a shell variable holding a literal), (2) `cd "<worktree>" && python - <<'EOF' … EOF` heredocs feeding python, (3) `git -C "<worktree>" diff … > "<worktree>/file.diff" && printf … >> "<worktree>/progress.md"`, (4) `bash "<script>" "<plan>" 1 && bash "<script>" "<plan>" 2 …` chains of plain calls, and (5) any command containing the substring `eval` — a QA subagent's `agent-browser --session x eval "document.activeElement…"` was blocked although `eval` was an argument to a third-party CLI, not the shell builtin. Each refusal cost a re-issue as separate plain commands or a script file; two subagents hit the same wall independently.

## Expected

Allow a compound command when every path literal (after variable substitution of literals assigned in the same command) resolves under the worktree, allow heredocs whose only consumer is a non-git interpreter, and match `eval` as a shell builtin token (word-boundary, command position), not as a substring of an argument.

## Evidence

Run 2026-09-20T195550-spec-497-498-499 (multi-spec, auto): the refusals appear in the session transcript around the review-package + ledger append chain, the design-detect file-list loop and the QA report heredoc; the qa-agent's note is in spec-499/decisions.md ("a worktree-isolation guard in this environment blocks any Bash command containing the literal substring eval"). Cost: roughly twenty re-issued commands (~15 min) and one subagent workaround.
