# 2688: bin/wrap-up-engine.js: render fails silently when the plan/record sequence was skipped

Surface: infra

## Current State

`wrap-up-engine.js render --section console` fails with no diagnostic output when the run's `record` step was never invoked after `plan` — a caller who performs per-row judgment out-of-band (e.g. via separate `stage-item.js`/`log-decision.js` calls instead of feeding a structured payload back into the engine) gets no indication of what precondition is missing. Observed twice in one session: `--strict` exits 2 with completely empty stdout/stderr; without `--strict` it exits 0 with empty output. Either way there is no actionable signal, and the caller has to infer from source reading that a `record` call was expected and never made — cost roughly 10 extra tool calls reading procedure files and hand-composing the Review Console content instead of one working render call.

## Deliverables

- `render --section console` detects a missing/empty engine-state (no prior `record` call for this run-dir) and fails loud with a specific, actionable message — e.g. "no engine-state.json found for this run-dir — run `record` first."
- This applies under both `--strict` and non-strict invocation: neither mode should produce silent empty output.

## Acceptance Criteria

- Running `render --section console --strict` against a run-dir with a `plan` output but no `record` call exits non-zero with a non-empty, actionable error message naming the missing precondition.
- Running the same command without `--strict` also produces the actionable message (not silent exit 0 with empty output).
- Running `render --section console` against a run-dir that DID complete `record` is unaffected — this fix only changes the missing-precondition path.

## Release Note

Made the wrap-up engine fail with a clear message when its console is rendered before any results were recorded.

## Technical Approach

Locate `render`'s entry point in `plugin/bin/wrap-up-engine.js` (the `--section console` handler) and its read of the run-dir's engine-state file. Add a precondition check before rendering: if the expected engine-state artifact (written by the `record` step) is absent or empty, exit with a clear error naming the missing precondition and the remedy (`run record first`), on both `--strict` and non-strict paths — today the two paths differ only in exit code, both leaving stdout/stderr empty, so the fix should apply the same message to both rather than only fixing one.

### Key Files

- `plugin/bin/wrap-up-engine.js` — `render --section console` handler and its engine-state read

## Gotchas

- Don't conflate "missing engine-state" with "engine-state present but empty" — both need actionable messages, but a caller reading the error should be able to tell whether `record` was never run at all versus ran but produced nothing.
- Keep the fix scoped to detecting and reporting the missing precondition — do not add a fallback that silently synthesizes a Review Console from a `plan`-only run-dir, which would mask the same problem this fix exists to surface.
