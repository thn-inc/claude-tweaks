# 1579: dispatch: detect concurrently-authorized records with overlapping unmerged root-cause fixes

# Reflect — staged finding 2

**Category:** tangential

Origin: reflect light from #1410
Defer-reason: tangential

## Current State

Record #1410 and record #1402 (PR #1577, parked/unmerged) both diagnose the exact same root
cause in `plugin/bin/lib/hooks/context.js`'s `resolveRun` fallback branches — a missing
worktree-binding check. #1402's build ran first but its PR never merged; #1410 was later
authorized and dispatched, and its own build necessarily re-implemented the identical fix from
scratch (it had no way to build on top of #1402's unmerged branch). Direct diff comparison during
#1410's review confirmed the two PRs' functional code is byte-identical in `context.js`, differing
only in explanatory-comment wording — a trivial, but real, merge conflict on second-merge (also
touching one `docs/hooks.md` line both PRs edit differently). Nothing detected this duplication
before dispatch authorized and ran #1410's build; it only surfaced because this review call
happened to cross-reference the two PRs by hand at the operator's explicit request.

## Deliverables

- `/claude-tweaks:dispatch` (or `/claude-tweaks:backlog refine`, wherever authorization happens)
  gains a check that flags — at authorization or dispatch time, not discovered post-hoc in review —
  when two `ready`/`auto:build` records name overlapping file regions or an unmerged sibling PR
  already claims to fix the same root cause, so a human can choose to serialize them (block #1410
  on #1402's merge) rather than pay for two independent builds of the same fix.

## Acceptance Criteria

- AC1: A concrete detection signal is proposed (file-overlap on unmerged PR diffs, a shared
  root-cause reference in each record's body, or similar) and evaluated for false-positive rate.
- AC2: The chosen signal is wired into dispatch's authorization or claim path, with a documented
  fallback for "unclear," never a hard block on ambiguous evidence.
