# 3070: Batch verify --baseline's per-file base probes into O(1) git calls

Origin: v6.138.0 release review (lens 3d performance), refs #3043
Defer-reason: genuinely-larger

## Current State

Before any rerun starts, `adjudicate` (`plugin/bin/lib/verify/baseline.js:256-257`) calls `git.fileExistsAt` (`git cat-file -e`) and `git.sameAtBase` per failing file. `sameAtBase` (lines 52-57) adds `rev-parse --show-toplevel`, `rev-parse sha:file` and `hash-object`, and the toplevel lookup repeats a root `adjudicate` already holds from `git.repoRoot()`. That is up to four serial `execFileSync` spawns per file. On this Windows box's ~98-file baseline, the spawn cost alone is seconds of dead time. This is unmeasured.

Evidence: v6.138.0 release whole-branch review, staged `review-8.md`. Reproduced by both 3d agents.

## Deliverables

- [ ] Existence and sameness for all failing files resolved in a constant number of git calls (e.g. one `cat-file --batch-check` plus one `hash-object --stdin-paths`), with the repo root passed in rather than re-resolved.

## Acceptance Criteria

- [ ] An adjudication over N failing files makes a number of pre-run git spawns that does not grow with N (asserted through the injected git seam).
- [ ] Verdicts on the existing baseline test fixtures are unchanged.
