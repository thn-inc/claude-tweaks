# 4548: build: dispatch rules forbid git stash but not image-name process kills — a subagent killed every node process on the machine

Surface: infra

## Current State

Dispatched agents share more than a worktree. They share the machine's process table with every sibling session. The plugin already guards one shared resource. `_shared/subagent-dispatch-core.md` (the "Never run `git stash` in any form" paragraph) states the rule, and it is forwarded verbatim into `build/dispatch.md`'s SDD implementer instruction, both Task() calls in `dispatch/task-prompt.md`, `dispatch/express-prompt.md`, and `flow/multispec-parallel-waves.md`'s wave-member prompt. It is also backed by a warn-tier hook (`pre-tool-use.js`'s `checkGitStashWarn`, documented in `docs/hooks.md`) and pinned by `tests/dispatch-no-stash-conformance.test.js`.

No equivalent rule exists for processes. A grep of `plugin/skills` for `taskkill`, `pkill`, and `killall` finds no prohibition anywhere. In one observed incident, an implementer on a plan with a runtime-verification task accidentally started a background build. It stopped the build with `taskkill /F /IM node.exe`, which killed every node process on the machine. That included dev servers and tooling of several concurrent Claude sessions in sibling worktrees of the same repo. The implementer surfaced it only afterwards as a concern. Runtime checks that start servers (`/claude-tweaks:visual-review`, `/claude-tweaks:stories`, Task-0-style verification tasks) are routine, so agents will keep needing to stop processes they started.

The plugin's own ephemeral-server teardowns are already PID- or port-scoped rather than image-name kills. Three of them still over-match, though:

- `_shared/dev-url-detection.md`'s Standalone cleanup bullet (POSIX branch) runs `lsof -ti tcp:{port} | xargs kill`.
- `journey-health/deep-tier.md` step 4 ("Clean up") runs the same command.
- `wrap-up/cleanup-procedures-execution.md` Section D names that same command as its no-lease stale-PID fallback.

`lsof -i tcp:{port}` matches every process holding a TCP socket whose local *or remote* port is `{port}`. That includes clients connected to the dev server, such as the Playwright browser driving the check or another session's browser tab. The same file's own worktree-awareness probe (`dev-url-detection.md`, the no-lease branch) already scopes its lookup correctly with `lsof -nP -iTCP:{PORT} -sTCP:LISTEN -t`. The win32 branches already use `taskkill /PID {pid} /T /F` against a recorded PID, which is correct.

## Deliverables

1. **Canonical rule.** In `plugin/skills/_shared/subagent-dispatch-core.md`, directly after the no-`git stash` paragraph, add a paragraph forbidding image- or name-based process kills: `taskkill /IM`, `pkill`, `killall`, `Stop-Process -Name`. State why: the process table is shared machine-wide with sibling sessions and worktrees. Name the sanctioned alternative: kill only a PID you captured when you started the process, or the PID of the listener on a port you own (`lsof -nP -iTCP:{port} -sTCP:LISTEN -t` on POSIX; `taskkill /PID {pid} /T /F` on win32). If neither PID can be identified, leave the process running and report it rather than reaching for a broader kill.
2. **Forwarded into every dispatch prompt that forwards the no-stash rule.** Agents only see their prompt, so add a short sentence beside each existing no-stash instruction:
   - `plugin/skills/build/dispatch.md`'s SDD per-task implementer instruction. Cite the core file, as the no-stash forwarding does.
   - Both Task() calls in `plugin/skills/dispatch/task-prompt.md`, inlined.
   - `plugin/skills/dispatch/express-prompt.md`, inlined.
   - `plugin/skills/flow/multispec-parallel-waves.md`'s wave-member prompt, inlined.
3. **Listener-scoped teardowns.** Replace `lsof -ti tcp:{port} | xargs kill` with a listener-only form (`lsof -nP -iTCP:{port} -sTCP:LISTEN -t | xargs kill`, or the recorded PID where one exists) at three sites: `plugin/skills/_shared/dev-url-detection.md`'s Standalone cleanup bullet, `plugin/skills/journey-health/deep-tier.md` step 4, and `plugin/skills/wrap-up/cleanup-procedures-execution.md` Section D's no-lease fallback mention.
4. **Warn-tier hook gate.** Add `checkProcessKillWarn` to `plugin/bin/lib/hooks/pre-tool-use.js`, mirroring `checkGitStashWarn`'s posture: a warn-only `systemMessage`, never a deny. It fires on a Bash segment invoking `pkill`, `killall`, `taskkill` with an `/IM` argument (case-insensitive, any `/IM` position), or `Stop-Process`/`kill` with `-Name`/`-ProcessName`. The message names the shared-process-table hazard and the PID-scoped alternative. It is run-independent and location-independent, unlike the stash gate's linked-worktree condition, because the hazard is machine-wide. Add the trigger words to `plugin/bin/lib/hooks/bash-prefilter.js`'s `PRE_TOOL_USE_WORDS` so the prefilter does not skip these commands before the gate loads. Document the gate in `docs/hooks.md` beside the git-stash gate bullet.
5. **Tests.** Add a prose conformance test alongside `tests/dispatch-no-stash-conformance.test.js`, using the same per-call region split, pinning the new rule in every Deliverable 2 site and the canonical file. Add a test that no `plugin/skills/**/*.md` file contains the unscoped `lsof -ti tcp:` kill form. Add `tests/hooks-pre-tool-use.test.js` cases for the gate's positive shapes, its negatives (`kill {pid}`, `taskkill /PID 123 /T /F`, `lsof … -sTCP:LISTEN`), and a prefilter case proving a bare `pkill node` reaches the handler.

## Release Note

Stop dispatched agents from killing processes by name, which could take down other sessions' dev servers, and scope dev-server teardown to the server's own listening process.

## Technical Approach

Follow the no-stash rule's existing three-layer shape (prose rule, forwarded prompt text, warn hook) rather than inventing a new mechanism. The canonical paragraph lives in `subagent-dispatch-core.md`. `build/dispatch.md` cites it, as its no-stash forwarding already does. The three literal prompt templates inline a short sentence, because dispatched agents never see sibling files.

The hook gate reuses the segment walk `checkGitStashWarn` already gets from the shared `resolvedGitSegments` pass, or the equivalent per-segment token list, and appends to the same `warnings` array. It must never throw. It obeys the never-break-a-session invariant in `docs/hooks.md`: a parse failure means no warning, never a deny.

The teardown edits are one-token-class changes at each site. Add `-nP -iTCP:{port} -sTCP:LISTEN` so only the listening server process matches. Where the site already holds a recorded PID, prefer that.

## Gotchas

- **Prefilter skip.** Without the `PRE_TOOL_USE_WORDS` addition, `bin/hooks.js` exits before `pre-tool-use.js` ever loads for a plain `pkill node`. The gate would then be dead code that unit tests calling the gate function directly still pass. Test through the prefilter too.
- **`taskkill` flag case.** Windows flags are case-insensitive and position-free (`/im`, `/IM`, after `/F` or before it). Match `/IM` as a token, case-insensitively.
- **Keep `kill -- -{pid}` working.** The POSIX process-group kill in Section D is PID-scoped (negative PID = the group *this pipeline* started) and must not warn.
- **Byte-pinned prose.** `tests/dispatch-no-stash-conformance.test.js` and the region-split anchors (`## First call` / `## Second call` / "None of Templates A/B/C") read `task-prompt.md` directly. Insert the new sentence without moving those anchors, and run the full suite, since other conformance tests pin this prose.
- **Related #4559** (Fast-tier implementer ignored the no-stash rule). It is evidence that prose alone is not always obeyed by the cheapest tier, which is why this record pairs the prose with a hook warning rather than relying on the prompt text.
- **Scope note.** The record asked to apply the rule "wherever the plugin's own procedures start ephemeral servers." On inspection those teardowns were already PID- or port-scoped. The residual defect is the client-matching `lsof -ti tcp:{port}` form, so Deliverable 3 narrows to that rather than rewriting the teardown procedures.

## Original request

build: dispatch rules forbid git stash but not image-name process kills — a subagent killed every node process on the machine

**Summary:** `/claude-tweaks:build`'s dispatch instruction protects shared cross-session state by forbidding `git stash`, but has no matching rule for processes. An implementer that stopped a stray build with `taskkill /F /IM node.exe` killed every node process on the machine, including other concurrent sessions' dev servers.

**Kind:** Gap

**Affected component:** build (`skills/build/dispatch.md`, the SDD invocation's forbidden-operation rules)

**Use case:** A record's plan included a runtime verification task: build and start the app, then run Playwright against it. The implementer accidentally started a background build and stopped it with an image-name kill (`taskkill /F /IM node.exe`). On that machine, several Claude sessions were active in sibling worktrees of the same repo, and the kill took their node processes down too. The implementer reported it afterwards as a concern.

The plugin already reasons this way about git. The no-stash rule says "the stash stack is shared repo-wide across every worktree, so it can pop or clobber a sibling worktree's in-flight work". Processes are the same kind of shared resource. `/claude-tweaks:visual-review` and Task-0-style runtime checks start servers routinely, so subagents will keep needing to stop them.

**Proposed:** Next to the forwarded no-`git stash` rule in `dispatch.md`, add: "never kill processes by image or name (`taskkill /IM`, `pkill node`, `killall`); find the PID of the process you started (by port or by the PID you captured at start) and kill only that PID". Apply the same rule wherever the plugin's own procedures start ephemeral servers (e.g. the `dev-url-detection.md` ephemeral dev server teardown).

**Definition:** Clear
