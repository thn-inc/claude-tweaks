# 2770: stage-item.js's per-writer filename counter silently overwrote two staged Review Console proposals — allocate ids per run dir and never clobber

Origin: consolidated Review Console — run `2026-09-21T213441-spec-2697-2757-2758-2759`, ledger row #31

Defer-reason: genuinely-larger

## Current State

**`bin/stage-item.js` silently destroyed two staged Review Console proposals in this run.** The
filename counter that allocates `build-deviation-{n}` restarts **per writer**, not per run
directory, so a later writer in the same `spec-{N}/staged/` reuses `build-deviation-1` /
`build-deviation-2` and overwrites whatever an earlier writer had already put there.

Concretely, in `spec-2758/staged/`:

| Written | File | Content |
|---|---|---|
| 07:59:24 | `build-deviation-1.md` | agent-browser -> playwright-cli tooling premise correction |
| 07:59:24 | `build-deviation-2.md` | inline Interaction-style directive (forbidden since #1909) |
| 11:13 | `build-deviation-1.md` | skill-graph reverse-edge deviation — **overwrote the 07:59 file** |
| 11:13 | `build-deviation-2.md` | AC7 no-running-app deviation — **overwrote the 07:59 file** |

`spec-2758/decisions.md` records all four `STAGED` lines under those two names, so the audit trail
said four proposals existed while the directory held two. The consolidated Review Console reads
`staged/` — it would have rendered **3** items for #2758 instead of the real **5**, and the two lost
findings would never have reached a human.

They survived only because a worktree shadow copy existed; `hooks.js sweep-shadow` recovered them
non-destructively as `build-deviation-1.md.shadow-dup` / `build-deviation-2.md.shadow-dup`. That is
luck, not a mechanism — the same sweep found 7 collisions across the run, 5 of them (all in
`spec-2757/`) byte-identical and harmless, and exactly these 2 divergent.

This is silent data loss in a sanctioned run-directory writer whose entire job is to make a proposal
durable until a human sees it.

## Deliverables

- Allocate staged-item ids against the **target run directory's existing contents**, not against
  per-writer state: read `staged/` and pick the next free `{kind}-{n}`.
- Make a collision impossible to lose silently regardless: refuse to overwrite an existing
  `staged/{name}` (non-zero exit with the existing path named), or write to the next free suffix and
  report the adjusted name on stdout. Never a blind clobber.
- Audit the other sanctioned run-dir writers (`log-decision.js`, `set-config.js`) for the same
  per-writer-state assumption.

## Acceptance Criteria

Two `stage-item.js` invocations from different processes, staging the same `--id` kind into the same
run directory, produce **two** files; neither is lost. Pinned by a regression test that fails against
the current allocator.

An attempted overwrite of an existing `staged/{name}` is a reported outcome (non-zero exit, or a
renamed write echoed on stdout), never a silent success.

`hooks.js sweep-shadow`'s collision report distinguishes duplicate from divergence, as it did here —
keep that, but it must stop being the only thing standing between a proposal and the void.
