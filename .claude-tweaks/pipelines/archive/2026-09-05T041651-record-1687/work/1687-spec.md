# 1687: reconcile-background: the archive sweep's ownership gate has no session id to check against

Surface: backend

## Current State

`archive-merged.js`'s `isAbandonedInterrupted` (added by #1673) refuses to auto-close a run owned by the calling session:

```js
if (owner && sessionId && owner === sessionId) return false; // our own live run
```

`sessionId` reaches it from two places, and in the one that matters it is always `null`:

- `plugin/bin/lib/hooks/session-start.js` now threads `ctx.input.session_id` into its inline `reconcile({...})` call (#1673). But that call passes `checks: FAST_CHECKS`, and `FAST_CHECKS = ['mirror', 'red-tip', 'console']` — **`archive` is not in it**. The gate is never reached from there.
- The archive check runs only from the detached `reconcile-background` child (`BACKGROUND_CHECKS = ['release', 'archive', 'archive-branches', 'remote-prune', 'reap']`), spawned from `session-start.js` with `stdio: 'ignore'` and no stdin. It has no hook payload, so no `session_id`.
- `archiveMerged`'s remaining fallback is `process.env.CLAUDE_CODE_SESSION_ID`, which `plugin/bin/hooks.js`'s own comment documents as "not reliably present" for a hook-spawned process.

Net effect: in production the ownership gate is a no-op, and the substantive protection is the other two gates alone — the 24h staleness window over non-fallback events, and `checkRunIntegrity` returning `shipped-unclosed`.

## Deliverables

- [ ] The `reconcile-background` child receives a session id — most likely via its spawn environment, set from `ctx.input.session_id` at the spawn site in `session-start.js`.
- [ ] `hooks.js`'s `reconcile-background` subcommand reads it and threads it into `reconcile({ ..., sessionId })`.
- [ ] A test proving the gate actually engages on that path: a run owned by the spawning session is not auto-closed even when the staleness and evidence gates both pass.

## Acceptance Criteria

1. A run whose `run-state.json` records the same session id as the session that spawned the background pass is never auto-closed by `archiveMerged`, on the real `reconcile-background` path (not merely in a unit test that passes `sessionId` directly).
2. With no session id resolvable, behavior is unchanged from today — the other two gates still govern, and nothing fails closed in a way that disables the sweep.
3. `npm test` passes.

## Gotchas

Threading a value into a detached child process's environment is a change to the fast/background split's own contract (`#820`), not to the auto-close criterion #1673 added. This is a missing belt-and-braces guard, not an open hole: the auto-close still requires a run to be `interrupted`, to have had no self-attributed event for 24h, and to carry `shipped-unclosed` evidence.
