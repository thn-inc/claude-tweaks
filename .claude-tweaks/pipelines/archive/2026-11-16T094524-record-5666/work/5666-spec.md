## Current State

The post-merge Windows check at `0905c172d` (PR #5628, the build of #3974) reports three test files newly failing, one test in each. There are two causes.

**Cause 1: the null device given to git as a config file.** Two tests build a git environment with `GIT_CONFIG_GLOBAL: os.devNull`:

- `tests/bin-lib/flow/preflight.test.js` line 795, in the test `AC3.1 specOnBranch on a real repo branch whose last commit git-mv'd the header`
- `tests/verify-run-bookends.test.js` line 520, in the test `AC3.1 isSpecCommitted on a real repo whose last commit git-mv'd the header to the archive path`

On win32 `os.devNull` is `\\.\nul`, and Git for Windows refuses it on every call: `fatal: unable to access '\\.\nul': Invalid argument`. Both tests fail at their first `git init`. `.claude/skills/windows-checkout-test-parity/SKILL.md` lists this mistake, first seen in #3696, and gives the fix: the literal `/dev/null`, which Git for Windows maps to `nul`. Other test files already pass the literal, for example `tests/helpers/git-fixtures.js` line 131 and `tests/statusline.test.js` line 1162.

A third line holds the same value: `tests/bin-lib/skill-gate/cli.test.js` line 23, added by PR #5617. #5689 reports that file's three Windows failures, two of them with the same `\\.\nul` message. These three lines are the only uses of `os.devNull` under `tests/` and `tools/` on `origin/main` at `ad1553186` (`git grep -n -F "os.devNull" origin/main -- tests tools`). Two merges in one night added the three, and nothing in the test suite stops a fourth.

**Cause 2: a POSIX string expected from the host's path module.** `tests/run-header.test.js` line 63, the test `archivedRunDir: run dir and per-spec child dir under pipelines`, calls `archivedRunDir('/m/.claude-tweaks/pipelines/…')` with the default path module and expects a `/`-separated string. `archivedRunDir` in `plugin/bin/lib/run-header.js` builds its result with `pathImpl.join`, and the module header says the filesystem-facing functions return native paths. On win32 the result is `\m\.claude-tweaks\pipelines\archive\…`. The code does what it documents; the expected value in the test depends on the host. The same file's win32 case, at line 82, passes `path.win32` and pins backslashes.

The causes are read from the failure text and the sources. Nothing was run on a Windows host for this record, so it is not known whether each test passes once it gets past the line that fails today.

2. **`tests/run-header.test.js`.** The line-63 test passes `path.posix` as the second argument of both `archivedRunDir` calls, so it pins the POSIX strings on every host, the way the win32 case pins backslashes.
3. **A check that stops the next one.** A new suite, `tests/git-config-null-device-conformance.test.js`, reads every `.js` file under `tests/` and `tools/` and fails, naming file and line, where `GIT_CONFIG_GLOBAL` or `GIT_CONFIG_SYSTEM` is given the value `os.devNull`. It covers the object-literal form (`GIT_CONFIG_GLOBAL: os.devNull`) and the assignment form (`process.env.GIT_CONFIG_GLOBAL = os.devNull`). It has a self-test on planted text and a floor on the number of files it read. A header comment states what it cannot see: a destructured `devNull`, or a value held in a variable.

## Technical Approach

Three one-line test edits and one new scan suite. The scan is a line-level match over test sources, not a parser: the two variable names followed by `:` or `=` and `os.devNull`. `tests/raw-markdown-read-conformance.test.js` is an existing scan over test sources and shows the house shape (a recursive walk, a file floor, a self-test on planted text). The new suite holds its planted offenders as text, so it must not report itself: build the planted strings so the scan's own source does not match, or skip its own file by name and say so in the header comment.

## Gotchas

- Do not change `archivedRunDir` to return `/`-separated paths. The filesystem-facing functions in `plugin/bin/lib/run-header.js` return native paths by design, and the win32 tests in `tests/run-header.test.js` pin that.
- Other tests in `tests/run-header.test.js` also call the default path module with POSIX inputs. They compare against `path.join` or expect `null`, and the Windows run did not report them. Leave them as they are.
- `os.devNull` is fine as a file to read or as a stdio target. Git for Windows rejects it only as a config path, so the scan matches the two config variables and not every `os.devNull`.
- Shipped code is outside this record. `plugin/bin/lib/staged-patch/stack-check.js`'s `gitEnv` already chooses `/dev/null` on win32, and the scan does not read `plugin/`.
- #5689 is open and unshaped. Its file overlaps this record's in one line (Deliverable 4). If #5689's fix merged first, AC2 already holds for that file and Deliverable 4 is a no-op.
- `tools/run-tests.js` finds test files by walking `tests/`, so the new suite needs no registration.
