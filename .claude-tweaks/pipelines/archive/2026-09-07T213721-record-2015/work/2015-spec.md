# 2015: Reconcile a bundle PR's Fixes lines with manifest outcomes before the merge — a not-run or failed spec must never close on merge

Defer-reason: pre-existing-outside-diff
Origin: reflect full (batch) from /flow #1988-#1997 consolidated close (parent run 2026-09-06T110420)

## Current State

`_shared/pr-early-run-lifecycle.md` ("One `Fixes #{n}` line per record") writes one `Fixes #{m}` per `manifest.yml` `specs[].id` into the bundle PR body at run start, before any spec has run — draft-safe by design. Nothing later reconciles those lines with what the run actually built: `hooks.js spec-status` writing `not-run` or `failed` does not touch the PR body, the "Pre-merge title/description refresh" section refreshes only the title and the phase checklist, and `flow/multispec-review-console.md`'s Shared teardown step 2 tells `_shared/pr-first-merge.md` Step 3 to put every `specs[].id` into the merge commit's `Fixes` lines. In the #1988–#1997 run, #1996 was ruled `not-run` (its go/no-go reads post-release data) and the PR body still carried `Fixes #1996` until the controller re-read the body at close-out and replaced it by hand; the merge-commit `Fixes` list had to be narrowed by hand the same way. A headless dispatch firing has no such re-read — the merge would have closed a record that never built, and the never-started claim release would then have posted on a closed issue.

## Deliverables

- In `_shared/pr-early-run-lifecycle.md`'s pre-merge refresh: rewrite the body's `Fixes` block from `manifest.yml` — one `Fixes #{m}` per spec with `status: complete`, and one `Refs #{m} — not run/failed: {reason}` line per spec with any other status — as an unconditional `AUTO` step alongside the title/checklist refresh.
- In `flow/multispec-review-console.md` Shared teardown step 2 and `_shared/pr-first-merge.md` Step 3: define `{issue-list}` for a bundle as the manifest's `complete` specs, never the full `specs[].id` list; the not-run/failed set is released with `never-started:`/`abandoned:` reasons in step 3 exactly as today.
- A conformance test pinning both prose sites, plus a fixture on whatever helper composes the `Fixes` block (a manifest with one `not-run` entry yields no `Fixes` line for it and one `Refs` line).

## Acceptance Criteria

- A multi-spec run with one `not-run` spec merges with `Fixes` lines only for the complete specs; the not-run record stays open after the merge and its claim releases as `never-started`.
- The pre-merge refresh log line names the rewritten `Fixes` block.
- `npm test` green apart from the tracked baseline (#1900).
