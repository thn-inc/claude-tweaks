# 2030: timing/derive.js's NESTED_PARENT roster has no corpus-scanning conformance test

Surface: infra

## Current State
`plugin/bin/lib/timing/derive.js` attributes a `skill_invoked` event to a phase by name: a `claude-tweaks:*` skill that is one of the ten `PHASES` opens that phase, a skill listed in `NESTED_PARENT` (`simplify`, `reflect`, `visual-review`, `capture`, `design-wrapper`, `challenge`, `assess-agent-autonomy`, `ledger`, `journeys`, all mapped to `'enclosing'`) attributes to the phase that is already open, and — by the file's own comment — "an un-mapped `claude-tweaks:*` skill_invoked event opens a new top-level phase named after the skill", so that "a maintainer adding a new nested-skill call site inside review/wrap-up/build must add its name here, or every run will grow a spurious top-level phase." Nothing enforces that sentence. The only test touching the roster is `tests/bin-lib/timing/derive.test.js`'s `NESTED_PARENT.journeys === 'enclosing'` pin. The sibling roster for ceremony skip tags is pinned by `tests/ceremony-profile-roster.test.js`, which walks `plugin/skills/**` and asserts every fast-lane skip mention in the corpus carries a rostered tag — the shape this record asks for.

## Deliverables
- [ ] `tests/timing-nested-parent-roster.test.js`: walks the phase-skill directories (`build`, `test`, `review`, `design-wrapper`, `wrap-up`, `flow`, and their `_shared/` contracts) and collects every `/claude-tweaks:{name}` invocation that appears *outside* a `## Next Actions` block (Next Actions lines are human launchers, not nested Skill-tool calls) and outside fenced code blocks that render commands for a human; each collected `{name}` must be a `PHASES` member, a `NESTED_PARENT` key, or on a small, commented allowlist of skills that are named descriptively but never invoked from a phase (e.g. `specify` cited as the upstream, `sweep` as the orchestrator). The assertion message names the file, line, and skill so the fix is one roster entry.
- [ ] A second assertion in the same file: every `NESTED_PARENT` key is invoked somewhere in that scan, so a stale entry (a nested skill that no phase skill calls any more) is reported rather than carried forever.
- [ ] A comment on `NESTED_PARENT` pointing at the test by name, replacing the "must add its name here" sentence's implicit trust with the explicit pin.
- [ ] The existing `derive.test.js` pin stays; `npm test` picks the new file up via the recursive glob (no registration).

## Acceptance Criteria
1. Deleting any current `NESTED_PARENT` key makes the new test fail naming a real call site in the corpus (each of the nine keys is exercised).
2. Adding a `/claude-tweaks:{new}` invocation inside a phase skill's step body without a roster entry makes the test fail with file, line, and skill name; adding the entry makes it pass.
3. A `/claude-tweaks:{name}` under a `## Next Actions` heading or inside a human-facing fenced command block does not trip the test.
4. The test passes on the current corpus; `npm test` is green.

## Technical Approach
Scan the corpus the way the ceremony roster test does (walk `plugin/skills`, read each file, regex per line) rather than parsing `docs/skill-graph.md`: the graph rows are prose and describe every relationship kind, while the timing roster cares only about what a phase skill *invokes* mid-phase, which is exactly what the phase directories' step bodies say. The `## Next Actions` exclusion is the load-bearing heuristic — every phase skill ends with a launcher block naming skills it does not invoke — so the scanner tracks the current `##` heading while walking lines. The stale-key assertion is the half the ceremony test lacks and the cheap half to add, since the scan already produces the invoked set.

### Key Files
- `plugin/bin/lib/timing/derive.js` — `PHASES`, `NESTED_PARENT`, `isTopLevel`, the roster comment.
- `tests/ceremony-profile-roster.test.js` — the corpus-walk template (`walk`, per-line regex, heading tracking).
- `tests/bin-lib/timing/derive.test.js` — existing pin (unchanged).
- `plugin/skills/{build,test,review,design-wrapper,wrap-up,flow}/**` and `plugin/skills/_shared/**` — the scanned corpus.

## Gotchas
- `skill_invoked` events exist only for model-initiated Skill calls, so a skill a phase names only in prose ("see `/claude-tweaks:specify`") never produces an event; that is why the scan needs an allowlist for descriptive mentions and why the allowlist must stay short and commented — a growing allowlist is the roster problem moved.
- `PHASES` names (`test`, `review`, `polish`, `wrap-up`) are themselves skills invoked by `/flow`; they are top-level by design and must be excluded from the nested check, not added to `NESTED_PARENT`.
- `design-wrapper` is invoked as the `polish` phase by `/flow` (top-level there) and as a nested call from `/review` (Step 3.8 craft critics); `NESTED_PARENT` maps it to `'enclosing'` and `derive.js` resolves the polish phase separately — the test asserts roster membership only, never phase semantics.
- Keep the scan to the phase directories; `backlog`, `tidy`, and `sweep` invoke many skills but never run inside a timed pipeline phase.
