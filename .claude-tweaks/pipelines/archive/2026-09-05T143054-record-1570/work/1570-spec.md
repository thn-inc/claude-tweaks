# 1570: /claude-tweaks:review's flow-context full-mode default isn't self-enforcing

Origin: reflect light from #1143
Defer-reason: tangential

## Current State

`skills/review/SKILL.md`'s Overview states: "When invoked by `/claude-tweaks:flow`, review runs in **full** mode by default (code + visual)." But the Input resolution section's actual mode-selection rules (1-8) are purely token-based — the literal word `full` appearing in `$ARGUMENTS` is the only thing that selects full mode. There is no rule that checks `$PIPELINE_RUN_DIR` (or any other flow-context signal) and defaults to full mode when no explicit mode token is present. A flow executor who invokes `/claude-tweaks:review {spec}` without typing `full` explicitly silently gets **code** mode instead — no warning, no divergence from the documented default surfaced anywhere. This run (#1143's own flow continuation) hit exactly this gap: `/claude-tweaks:review #1143` was invoked without the `full` token, resolving to code mode per the skill's own Input resolution rule 1. No actual harm occurred this run (the record's `surface: backend`, so visual review would have been skipped by Step 6's own detection regardless of mode) — but on a frontend record, the same omission would silently skip the browser visual-review pass in a context where the skill's own documentation promises it always runs.

## Deliverables

- [ ] Add a rule to `skills/review/SKILL.md`'s Input resolution (or its own note) that defaults to full mode when `$PIPELINE_RUN_DIR` is set (or an equivalent flow-context signal is present) and no explicit mode token (`full`/`visual`/`journey:`/`discover`) appears in `$ARGUMENTS` — making the documented "flow invokes review in full mode by default" promise self-enforcing rather than dependent on the flow executor remembering to type `full`.
- [ ] Audit `skills/flow/SKILL.md`'s own Step 4 invocation prose for the same gap — it also just says "Flow invokes `/claude-tweaks:review` in full mode by default" without specifying the mechanism that makes this true.

## Acceptance Criteria

1. `/claude-tweaks:review {spec}` invoked with `$PIPELINE_RUN_DIR` set and no explicit mode token resolves to full mode (verifiable by reading the updated Input resolution rule).
2. `/claude-tweaks:review {spec}` invoked standalone (no `$PIPELINE_RUN_DIR`) and no explicit mode token still resolves to code mode, unchanged — the fix must not alter standalone behavior.
3. An explicit mode token (`full`/`visual`/`journey:`/`discover`) still always wins over the flow-context default, in either context.
