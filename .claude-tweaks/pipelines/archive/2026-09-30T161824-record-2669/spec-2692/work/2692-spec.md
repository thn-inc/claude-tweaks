# 2692: Add a lightweight perf-audit lens (images, unused loads, measure-first)

Surface: infra

**Related:** #2693

## Current State

claude-tweaks has no standing performance-audit lens — `/code-health` and `/review` don't check image format, unused resource loading, or a measured baseline. A 3-minute speed-audit checklist (image format conversion, unused-resource flagging, PageSpeed Insights baseline before changing anything) exists as an established, low-cost pattern worth codifying as a lens.

## Deliverables

- Add a perf-audit lens/policy row (image-format check, unused-resource flag, PageSpeed Insights baseline) to `/code-health` or `/review`.
- Keep it a fast, free check — no new paid tooling.

## Acceptance Criteria

- Running the lens against a sample app reports pass/fail for at least the three checks above (image format, unused resources, PageSpeed Insights baseline).

## Release Note

Code and visual reviews now flag oversized or legacy-format images and unused loaded resources, and recommend measuring page speed before optimizing.

## Technical Approach

Two homes, split by what each can observe. The static checks — a legacy-format or oversized image added to the diff, and a script/stylesheet/font loaded but unused — join `/claude-tweaks:review`'s lens 3d (Performance) in `plugin/skills/review/step3-lens-dispatch.md` as question bullets. The measure-first rule — record a baseline with a free tool (Lighthouse CLI, or the PageSpeed Insights API's free tier) before changing anything for performance — joins `/claude-tweaks:visual-review`'s `page-mode.md` Step 4 Performance subsection, which already owns runtime vitals. No new paid dependency.

### Key Files

- `plugin/skills/review/step3-lens-dispatch.md` — lens 3d (Performance) gains the image-format/oversized-asset and unused-loaded-resource bullets
- `plugin/skills/visual-review/page-mode.md` — Step 4's Performance subsection gains the measure-first baseline (free Lighthouse CLI or PageSpeed Insights) before any performance fix

## Gotchas

- "No new paid tooling" is an explicit constraint — Lighthouse CLI and the PageSpeed Insights API free tier both stay within it; name the tool in the text.
- This is a lightweight addition, not a full performance-audit subsystem — scope the three named checks only.
- page-mode's Performance subsection says vitals are unavailable from its own browser session; the measure-first rule is guidance to run a baseline, not a claim that the walk measures it.
