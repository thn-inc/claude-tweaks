# 2648: browse: migrate demo/* and test/* to Playwright CLI syntax (agent-browser migration, part 3d)

Surface: infra

## Overview

`plugin/skills/demo/legacy-brief-compatibility.md`, `demo/SKILL.md`, `plugin/skills/test/
qa-procedures.md`, and `test/qa-prompts.md` each name or construct `agent-browser` — the demo
skill's two files in prose only (naming the tool while describing opening/closing a session, no
literal constructed command strings), the test skill's two files with real command construction
(`--version`, `auth list`/`auth save`/`auth login`, `open`, `trace start`/`trace stop`, `set
viewport`, `close`). This record translates every one to Playwright CLI per
`plugin/skills/browse/playwright-cli-reference.md`'s Operation vocabulary table — a straight
prose name-swap in the two demo files, and the same gap-resolution work parts 3a/3b/3c of this
migration already established (`auth`, `trace`, `set viewport` have no table row) in the two test
files. (This record uses "part 3a/3b/3c" — the sibling sub-project labels — consistently
throughout, not "unit N"; the two are the same records, just named once here to avoid the
dual-numbering confusion a red-team pass on this record flagged.) This is sub-project 3d of a
five-part consumer migration
(`docs/superpowers/specs/2026-09-20-playwright-cli-consumer-migration-design.md`, now absorbed
into this and its four sibling records) — sub-projects 1 (spike) and 2 (reference doc + init
detection, #2626/#2627) have already shipped.

**Complexity:** Medium
**Estimated tasks:** 5

## Technical Approach

Two of these four files (`legacy-brief-compatibility.md`, `demo/SKILL.md`) need only a prose
tool-name swap — neither constructs a literal `agent-browser` command string, they only name the
tool while describing opening/closing a browser session conceptually. Swap `agent-browser` →
`playwright-cli` in both, unchanged otherwise.

The other two (`qa-procedures.md`, `qa-prompts.md`) construct real commands and hit the same four
gaps (`auth`, `trace`, `doctor`, `set viewport`) parts 3a/3b/3c of this migration already identified
against `playwright-cli-reference.md`'s Operation vocabulary table — part 3a is #2645, 3b is #2646,
3c is #2647 (named here for a durable cross-reference, since the design doc tying all five parts
together is deleted once this decomposition closes). **Build this record after (or alongside, if
concurrent) the sub-issues that first resolve each gap** — the `auth` gap is first hit by the
`stories/*` sub-issue (#2646), `trace` by both `qa-agent.md` (#2645) and `stories/*` (#2646), and
`doctor`/`set viewport` by `visual-review/*` (#2647). Reuse whatever row each of those sub-issues
added to `playwright-cli-reference.md`'s Operation vocabulary table (or whatever "no equivalent"
finding they recorded as a negative-result row in that same table, per #2647's convention) rather
than independently re-deriving the same answer — a second, divergent resolution for the same
underlying `agent-browser` command across sibling records in the same migration would itself be a
defect (Step 6 Self-Review's Internal consistency check, `specify/decomposition-mode-closeout.md`).
Check the table directly (`grep` for the command name) rather than trusting build order or
re-fetching #2645/#2646/#2647's issue bodies — the table is the durable artifact, those issues may
already be closed by the time this record builds. If a gap genuinely has no row yet (no sibling has
resolved it), fall back to the same bundled-self-docs check those records describe
(`node_modules/playwright-core/lib/tools/skills/playwright-cli/SKILL.md` plus its `references/`
sub-docs), and if that path is unreadable (this repo's own permission settings can structurally
deny `Read`/`Bash` access under `node_modules/**` — confirmed during this decomposition's own
red-team review), fall back further to `npx --no-install playwright-cli --help <subcommand>` or
Playwright CLI's own published documentation — rather than blocking on build order. When a gap
resolves to "no equivalent," mark every affected call site in these two files with the literal
comment `<!-- playwright-cli: no equivalent found for agent-browser {command} — see issue Gotchas
-->` immediately above the untranslated line.

`qa-procedures.md`'s `agent-browser --version` presence check is a separate, already-resolvable
case: `_shared/browser-detection.md`'s Detect section documents `npx --no-install playwright-cli
--version` as Playwright CLI's own presence check, and the install/detect-plumbing sub-issue (part
3e) is independently wiring this exact same command into `plugin/bin/lib/deps.js`'s detection
code — translate to that command directly, no gap-resolution needed.

`qa-prompts.md` carries the highest execution risk in this group: its `agent-browser` mentions sit
inside literal dispatch-prompt template text that gets interpolated with `{story.id}`/`{story.url}`
placeholders and handed verbatim to a dispatched qa-agent subagent (the same subagent this
migration's part 3a record, `qa-agent.md`, is separately migrating). A translation that leaves the
template syntactically broken — mismatched quoting, a stray placeholder, an incomplete substitution
— breaks every QA dispatch that reads this template, not just this file's own prose. Manually walk
through one concrete substitution after translating (see Acceptance Criteria) rather than trusting
the diff by inspection alone.
