# 2646: browse: migrate stories/* to Playwright CLI syntax, drop React-introspection (agent-browser migration, part 3b)

Surface: infra

## Overview

The `stories` skill (story generation for QA — `/claude-tweaks:stories`) constructs `agent-browser`
CLI commands across six files: `auth-resolution.md`, `refine.md`, `SKILL.md`,
`source-analysis.md`, `source-aware-design.md`, and `story-examples.md`. This record translates
every one to Playwright CLI syntax per `plugin/skills/browse/playwright-cli-reference.md`'s
Operation vocabulary table, and additionally removes the React runtime-introspection capability
that `source-analysis.md` and `source-aware-design.md` document — `agent-browser`'s `react tree`
and `react inspect @eN` commands have no Playwright CLI equivalent, and the decision (made before
this record, in the design doc this decomposition absorbs) is to drop the feature rather than
research a replacement. This is sub-project 3b of a five-part consumer migration
(`docs/superpowers/specs/2026-09-20-playwright-cli-consumer-migration-design.md`, now absorbed
into this and its four sibling records) — sub-projects 1 (spike) and 2 (reference doc + init
detection, #2626/#2627) have already shipped.

**Complexity:** Medium
**Estimated tasks:** 6

## Release Note

## Technical Approach

Mechanical lookup-and-substitute against `playwright-cli-reference.md`'s Operation vocabulary
table for every translatable command — no new design per command, matching the same approach
every sibling record in this five-part migration uses. Two rules apply on top of the raw
substitution, restated here so this record is self-contained after the design doc is deleted:

- **Session flag position.** `agent-browser --session <name> <verb>` puts `--session` before the
  verb; Playwright CLI's `-s=<name>` keeps that same before-the-verb ordering
  (`playwright-cli -s=<name> <verb>`).
- **`find` is not a mechanical rename.** Playwright CLI's `find "<text>"` is read-only and
  text-only — the opposite of `agent-browser`'s action-defaulting, locator-flexible `find`. A call
  using a role/testid/css locator, or one whose `<action>` clicks/fills, must be re-derived as
  `snapshot` (obtain a ref) followed by a separate `click <ref>`/`fill <ref> "<text>"` — this
  applies to `refine.md`'s runtime `find` call, `SKILL.md`'s `find` call,
  `source-aware-design.md`'s locator-staleness `find <type> <args>` call, and
  `story-examples.md` line 3's schema-v2 runtime-execution sentence (it describes the identical
  one-command find-and-act model as `SKILL.md` line 56 — rewrite it to describe the two-step
  snapshot-then-click/fill flow, not a re-worded single `find` call).

**The `auth`, `batch`, and `trace` gaps.** `playwright-cli-reference.md`'s Operation vocabulary
table documents no `auth` subcommand, no `batch` subcommand, and no `trace` subcommand — none of
the three is a row in the table shipped by sub-project 2. Per the reference doc's own Authority
section ("On any command error, or before using a command or flag this file does not list, consult
the bundled self-docs — never guess flags from memory"), check Playwright CLI's own bundled
self-documentation (`node_modules/playwright-core/lib/tools/skills/playwright-cli/SKILL.md` plus
its `references/` sub-docs) for the actual command names covering credential/vault management (used
by `auth-resolution.md`'s `auth list`/`auth save`, `refine.md`'s `auth login`, `SKILL.md`'s `auth
save`/`auth login`, and `story-examples.md`'s `auth login` example), multi-operation batching (used
by `SKILL.md`'s `batch --session <name>` bundling of `open + snapshot + screenshot`), and tracing
(used by `refine.md`'s `trace start`/`trace stop <path>` failure-recording calls). **If that path
is unreadable** (this repo's own permission settings can structurally deny `Read`/`Bash` access
under `node_modules/**` — confirmed during this decomposition's own red-team review), fall back to
`npx --no-install playwright-cli --help <subcommand>` or Playwright CLI's own published
documentation site; only treat a gap as genuinely unresolved once both the bundled docs and this
fallback have been tried. **Before writing any new row**, grep `playwright-cli-reference.md`'s
Operation vocabulary table for an existing row first — this same trio of gaps is independently hit
by parts 3a (`trace`) and 3c (`batch`, `trace`) of this migration, so a sibling record may have
already landed a row; reuse it rather than adding a second, potentially divergent one. If a genuine
equivalent exists and no row exists yet, translate to it and add the missing row to
`playwright-cli-reference.md`'s Operation vocabulary table (a documentation debt this record
incurs by finding the gap, not a scope expansion — the table is the shared resource every sibling
record in this migration reads). If genuinely no equivalent exists, note the gap explicitly in
this record's own Gotchas and mark every affected call site with the literal comment
`<!-- playwright-cli: no equivalent found for agent-browser {command} — see issue Gotchas -->`
(substituting the actual command, e.g. `auth login`) immediately above the untranslated line,
rather than inventing syntax or silently deleting the step — never guess a Playwright CLI
subcommand name from `agent-browser`'s own vocabulary. Per the reference doc's absolute-path
caution, any `trace stop` path argument found to have a real equivalent must be made absolute in
the migrated form, matching every sibling record's treatment of screenshot/trace paths.

**React-introspection removal.** `source-analysis.md`'s `## React introspection (opt-in)` section
(lines 218-243) documents `agent-browser --session <name> react tree` (component hierarchy) and
`agent-browser --session <name> react inspect @eN` (props/state/file-path for one element) —
neither has a Playwright CLI equivalent. Remove the section entirely (not just its command lines —
the surrounding explanatory prose describes a capability that no longer exists) and replace it
with one sentence: "React component-tree inspection was available under `agent-browser` and has no
Playwright CLI equivalent as of this migration." `source-aware-design.md` line 38 cross-references
the same capability in one clause of a longer sentence ("...and the React runtime introspection
workflow (`agent-browser react tree` + `react inspect`), read `source-analysis.md` in this skill's
directory") — trim that clause, keep the rest of the sentence (the pointer to
`source-analysis.md` for extraction patterns/SourceContract schema remains valid), and add the
same one-sentence capability-loss note nearby.
