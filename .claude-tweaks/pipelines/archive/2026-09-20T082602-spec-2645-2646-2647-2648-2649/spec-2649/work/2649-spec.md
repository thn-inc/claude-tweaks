# 2649: browse: migrate install/detect plumbing to Playwright CLI (agent-browser migration, part 3e)

Surface: infra

## Overview

The install/detect plumbing group covers four files with no `agent-browser` command construction
of their own — a conventions skill's prose (`browse/SKILL.md`), a plugin manifest keyword
(`plugin.json`), the actual JS detection code (`bin/lib/deps.js`), and a cloud-sandbox setup-script
generator (`step-14-cloud-routine-parity.md`). `deps.js` is the one real technical change in this
group — its detection helper cannot be mechanically renamed, because the correct Playwright CLI
presence check (`npx --no-install playwright-cli --version`) is structurally different from the
bare `${cmd} --version` pattern its shared `has()` helper assumes. This is sub-project 3e of a
five-part consumer migration
(`docs/superpowers/specs/2026-09-20-playwright-cli-consumer-migration-design.md`, now absorbed
into this and its four sibling records) — sub-projects 1 (spike) and 2 (reference doc + init
detection, #2626/#2627) have already shipped.

**Complexity:** Medium
**Estimated tasks:** 5

  `demo/*`+`test/*` are each their own sibling record (part 3a/3b/3c/3d).

- Full migration of `step-14-cloud-routine-parity.md`'s Chrome-for-Testing cloud-sandbox

  own browser-binary provisioning that have not been confirmed to apply, or apply the same way, to
  Playwright CLI — see Gotchas for why this needs its own investigation rather than a mechanical
  rename here.

## Technical Approach

**`browse/SKILL.md` — prose swap, with two judgment calls beyond a bare rename.** Fifteen hits,
none of them a literal constructed command string — this file describes conventions, not command
syntax, so every hit is a tool-name or capability-name reference inside prose. Two hits need more
than search-and-replace:

- The Requirements paragraph's daemon-on-port-4848 claim and `agent-browser doctor` recovery
  reference (line 30) describe `agent-browser`'s specific architecture — Playwright CLI has no
  persistent daemon (`_shared/browser-detection.md`'s Session/process lifecycle section). Reuse
  #2647's (`visual-review/*`) resolution of this exact same claim/gap rather than re-deriving it
  independently — that sub-issue already establishes both the accurate daemon-model replacement
  text and whatever `doctor`-equivalent finding its own bundled-self-docs check produces. Check
  `plugin/skills/visual-review/browser-review.md`'s own migrated Prerequisites section directly for
  the exact replacement text (or `playwright-cli-reference.md`'s Operation vocabulary table for a
  `doctor` row, if #2647 added one) rather than #2647's issue body, which may already be closed by
  the time this record builds. **If neither exists yet** (this record builds before #2647), derive
  the daemon-model replacement text independently from `_shared/browser-detection.md`'s
  Session/process lifecycle section (quoted in Current State above) — that much is self-contained
  in this record already — and, for `doctor` specifically, fall back to Playwright CLI's bundled
  self-docs (`node_modules/playwright-core/lib/tools/skills/playwright-cli/SKILL.md`, or
  `npx --no-install playwright-cli --help` if that path is permission-denied, as confirmed to
  happen in this harness during this decomposition's own red-team review) rather than blocking on
  build order. If `doctor` resolves to "no equivalent," mark the line with the literal comment
  `<!-- playwright-cli: no equivalent found for agent-browser doctor — see issue Gotchas -->`.
- Lines 9, 48, and 101 name `agent-browser-reference.md` as "the single source of truth" for
  concrete command syntax. That claim was true when this file was `agent-browser`-only; it is no
  longer true once this file names `playwright-cli` as its backend, since `agent-browser-
  reference.md` documents the retired tool's syntax, not the current one. `playwright-cli-
  reference.md` (shipped in #2626/#2627) is the file that actually serves that role today — repoint
  both pointers at it. This does not touch `agent-browser-reference.md` itself (still untouched,
  per Non-Goals and the design doc's own scoping); it only changes where `browse/SKILL.md` tells
  its own readers to look.

**`plugin.json` — correcting a design-doc misdescription.** The design doc this decomposition
absorbs describes line 19 as a dependency declaration. Reading the actual file shows this is
inaccurate: `plugin.json` has no `dependencies` field at all, in any shape — line 19 is a plain
string inside the `keywords` array, used for plugin-marketplace discoverability/search, not
functional dependency resolution. The fix is therefore a one-line array-entry value swap, not an
edit to a declared-dependency shape (there is no such shape in this file to preserve or match).

**`deps.js` — a real technical change, not a rename.** The current `agentBrowserMessage()` (line
60) delegates presence-detection to the shared `has(cmd)` helper (line 5), which always shells out
to the literal `${cmd} --version` — this pattern cannot express `npx --no-install playwright-cli
--version`, the actual documented detection command (`_shared/browser-detection.md`'s Detect
section, and `playwright-cli-reference.md`'s own Installation/detection section). A naive
`has('playwright-cli')` call would only detect a global install and miss the local/npx-resolved
case the rest of the plugin already treats as the real detection contract — silently under-
detecting Playwright CLI in the common case where it's installed via `npx` rather than globally.
The migrated function therefore needs its own inline `execSync` call, not a call through `has()`,
mirroring `has()`'s own try/catch-false shape (line 5's pattern: `try { execSync(...); return
true; } catch { return false; }`) so the rest of `collect()`'s control flow is unaffected by the
change. `has()` itself is untouched — other callers (`detectPackageManager()`,
`detectVersionManager()`'s siblings, the `node`/`git` checks in `collect()`) keep using it exactly
as today; nothing about this change alters `has()`'s own contract or its other call sites.

**`step-14-cloud-routine-parity.md` — deliberately narrow.** This file's other 9 `agent-browser`
references describe a Chrome-for-Testing browser-binary provisioning workflow specific to
`agent-browser`'s own cache-directory layout (`~/.agent-browser/browsers/`) and installation
mechanics (`agent-browser install --with-deps` not working unmodified in a cloud sandbox, worked
around by a bespoke download step). Whether Playwright CLI needs the identical workaround, a
different one, or none at all (many Playwright-family tools manage their own browser binaries via
a different provisioning path than what's documented here) is an open question this record does
not resolve — it requires its own investigation against a real cloud sandbox, not a mechanical
rename. Changing only the literal install line keeps the setup script's stated behavior accurate
for what this record actually verifies, without asserting anything about the unverified remainder.
