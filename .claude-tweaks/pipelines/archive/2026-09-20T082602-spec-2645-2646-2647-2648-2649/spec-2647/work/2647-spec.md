# 2647: browse: migrate visual-review/* to Playwright CLI syntax (agent-browser migration, part 3c)

Surface: infra

## Overview

`/claude-tweaks:visual-review` constructs `agent-browser` CLI commands across five files:
`browser-review.md` (shared prerequisites/procedures), `journey-mode.md`, `page-mode.md`,
`qa-accelerated.md`, and `reconnaissance.md`. This record translates every one to Playwright CLI
syntax per `plugin/skills/browse/playwright-cli-reference.md`'s Operation vocabulary table. Most
of this group's commands — `batch`, `doctor`, `trace start`/`stop`, `vitals`, and `set viewport` —
have **no row** in that table, so this record's real work is resolving each of those gaps against
the CLI's own bundled self-docs before translating, not a pure lookup-and-substitute. This is
sub-project 3c of a five-part consumer migration
(`docs/superpowers/specs/2026-09-20-playwright-cli-consumer-migration-design.md`, now absorbed into
this and its four sibling records) — sub-projects 1 (spike) and 2 (reference doc + init detection,
#2626/#2627) have already shipped.

**Complexity:** Medium
**Estimated tasks:** 7

## Technical Approach

Mechanical lookup-and-substitute against `playwright-cli-reference.md`'s Operation vocabulary
table wherever a row exists (`open`, `snapshot`, `screenshot`, `close`) — no new design for those,
matching every sibling record in this five-part migration. The real work here is the five commands
with no table row at all:

- **`doctor`.** `agent-browser doctor` (referenced in `browser-review.md`'s crash-recovery note)
  has no row in the Operation vocabulary table. Per the reference doc's own Authority section ("On
  any command error, or before using a command or flag this file does not list, consult the
  bundled self-docs — never guess flags from memory"), check Playwright CLI's own bundled
  self-documentation (`node_modules/playwright-core/lib/tools/skills/playwright-cli/SKILL.md` plus
  its `references/` sub-docs) for an equivalent diagnostic command before assuming none exists.
  **If that path is unreadable** (this repo's own permission settings can structurally deny
  `Read`/`Bash` access under `node_modules/**` — confirmed during this decomposition's own
  red-team review), fall back to `npx --no-install playwright-cli --help` (check for a diagnostic
  subcommand in its output) or Playwright CLI's own published documentation site. If genuinely none
  exists after both, note the gap in this record's own Gotchas — and in the reference table itself
  (see below) — rather than inventing a workaround.
- **`batch`, `trace`, `vitals`, `set viewport`.** None of these four has a table row either. Apply
  the identical resolution procedure as `doctor` (bundled self-docs, then the `npx --help`
  fallback). **Before writing any new row**, grep `playwright-cli-reference.md`'s Operation
  vocabulary table for an existing row first — `trace` is independently hit by parts 3a and 3b of
  this migration, and `batch` by part 3b too; a sibling record may have already landed a row for
  either. If a genuine equivalent exists and no row exists yet, translate to it and add the missing
  row (a documentation debt this record incurs by finding the gap, not a scope expansion). If
  genuinely no equivalent exists: (1) document the gap in this record's own Gotchas, (2) mark every
  affected call site in the five files with the literal comment `<!-- playwright-cli: no
  equivalent found for agent-browser {command} — see issue Gotchas -->` immediately above the
  untranslated line, and (3) add a negative-result row to `playwright-cli-reference.md`'s Operation
  vocabulary table itself (`| {command} | agent-browser {command} | *(investigated during
  #2645-#2649's migration — no Playwright CLI equivalent found)* |`) so a future reader can tell
  "checked, confirmed absent" from "never checked" — this record's own Gotchas section is deleted
  along with the closing issue eventually, but the reference table is permanent. `vitals` in
  particular is load-bearing for this skill — `browser-review.md`'s own Important Notes calls Web
  Vitals "a first-class finding category, never skip the `vitals` op" — so a confirmed
  no-equivalent finding here is a real capability gap worth flagging prominently, not a minor
  translation note.

**The daemon-model claim.** `browser-review.md`'s Prerequisites section states "The daemon
auto-starts on port 4848 with the first command" — this is specific to `agent-browser`'s
architecture and is factually wrong for Playwright CLI, which has no persistent background daemon
(`_shared/browser-detection.md`'s Session/process lifecycle section: "each `open`/`attach` call
starts or reuses a named browser process directly, and `list`/`close-all`/`kill-all` operate on
that set of processes this CLI invocation tree manages, not on a daemon"). Replace the sentence
with an accurate one rather than deleting it silently — a reader debugging a stuck session needs to
know there's no daemon to restart. This is in scope for this record (not a separate content
change) because it sits in the same Prerequisites section, adjacent to the commands this record is
already translating, and leaving it stale would make the migrated file internally inconsistent —
prose describing a daemon architecture right above commands that no longer use one.
