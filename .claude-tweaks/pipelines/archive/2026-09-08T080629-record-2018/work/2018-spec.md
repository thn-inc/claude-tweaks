## Current State

`plugin/skills/_shared/issue-claims.md` documents a `gh`-absent (MCP) path for every claim step except two, and #1992's `transport` fencing makes the composed `claims` bundle a cloud Routine reads the *only* instruction it sees:

1. **The mirror comment has no MCP form.** `## The mirror`'s code block ends in `gh issue comment "$ISSUE" --body-file /tmp/claim-${ISSUE}.md` and nothing beside it says what an MCP run does instead — even though `_shared/github-write-transport.md`'s CRUD table already maps `Comment` → `add_issue_comment`. The block stays unconditional in the bundle precisely because removing it would delete the only guidance.
2. **"The lock" step 2 gives an MCP reader a wrong action.** Step 2 says the file from step 1 "holds the **wrapper object** `{content, sha}` from the `gh api` call's `-q` filter" and pipes it through `jq -r '.content'` — but step 1's surviving MCP bullet writes "the tool's returned content to a file", which is already the content. The same wrapper-object phrase recurs under "Authoritative: read the blob" ("never the raw `{content, sha}` wrapper object a fresh `gh api` read produces"). Under `transport=mcp` the `gh` sentence that gave the phrase its antecedent is stripped, so the instruction reads as a step to perform on content that has no wrapper.

Both passages predate #1992 (the raw file said the same); #1992 left them untouched because its acceptance proves `stripMarkers(file) === origin/main` byte identity (`[IL-144]`), which any content change breaks.
