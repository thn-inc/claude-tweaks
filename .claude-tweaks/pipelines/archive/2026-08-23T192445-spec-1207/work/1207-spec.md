# 1207: compare-shell: tweak levers for token-level adjustment without a full reroll

Surface: web
Design-intent: none

## Current State

- `plugin/skills/design-wrapper/compare-shell/template.html` — the compare-shell's focus view renders a fixed verdict bar (Pick / Reroll / Steer / Exit); a `MODE` flag (`"live"` vs `"durable"`) gates whether those controls are interactive — durable pages never attach live-only listeners at all (`MODE !== 'live' return`, template.html:190, and the comment at template.html:288-289). No token-level tweak controls exist today.
- `plugin/skills/_shared/visual-decision.md` — documents exactly four event shapes (`pick`, `reroll`, `steer`, `exit`) as the canonical vocabulary every consumer relies on; there is no fifth shape.
- `plugin/skills/design-wrapper/compare-shell/seed-compare.mjs` — seeds `decision.html` for both `live` and `durable` modes today; has no path for baking a chosen tweaked token set into the durable output.
- The parent decomposition's Decision Rationale (#1201) explicitly deferred per-token tweak controls (nudging a single color or spacing value without a full reroll) out of the initial compare-shell build (#1203).

## Deliverables

- [ ] A tweak-levers panel in the compare-shell focus view (`template.html`) — sliders/steppers for a small, fixed set of design tokens (exact set left open until build time; likely candidates: primary hue, spacing scale, corner radius)
- [ ] A fifth event shape added to `_shared/visual-decision.md`'s vocabulary (e.g. `{"type":"tweak","token":"...","value":"...","ts":<epoch-ms>}`), with the conformance suite extended to pin it
- [ ] `seed-compare.mjs` durable-mode support for baking a tweaked token set into the recorded `decision.html`

## Acceptance Criteria

1. The tweak panel renders only in live mode — durable mode stays inert, matching the existing verdict-bar disable pattern (`MODE !== 'live'`, template.html:190)
2. A `tweak` event round-trips through `/events` and is reflected in the live page without a full reroll
3. `npm test` passes with the extended conformance suite pinning the new event shape

## Technical Approach

Extend `_shared/visual-decision.md`'s "Exactly four event shapes" section to five, adding `tweak` alongside `pick`/`reroll`/`steer`/`exit`, in the same one-JSON-object-per-line JSONL convention the other four already use. Wire the new panel into `template.html` behind the existing `MODE` gate so the tweak controls follow the identical disable/no-listener pattern the verdict bar already uses in durable mode, rather than inventing a second mechanism. `seed-compare.mjs`'s durable-mode path needs a way to bake an already-chosen tweaked token set into the static `decision.html` output, rather than requiring the token set to route through a live round every time.

**As-built (Beneficial deviations, applied per Architecture Alignment Check):** the whole-branch review found that a bare `--tweak-{token}` CSS custom property with no consumer satisfies AC1 but not AC2 — nothing visibly changes on lever movement. The panel therefore also carries a live numeric readout per lever and a small preview swatch driven by the same `var(--tweak-*)` properties (commit `86329b06`), which is what actually makes the tweak "reflected in the live page." The review also found the vocabulary migration was incomplete — `visual-decision.md`'s Turn loop/Precedence sections and `explore.md`'s Verdict branches still described a four-shape world with no handling for `tweak` on resume — fixed by treating `tweak` as never a verdict (resume acts on the last non-`tweak` event; a tweak-only events file resolves the same as an empty one) (commit `728a579b`). A slider drag posting one `tweak` event per `input` tick was coalesced to `input` for visual feedback + `change` for the actual `/events` POST, so a drag no longer floods the events file (commit `d07e4b55`). Durable mode also replays baked `outcome.tweaks` into the sliders/readout/swatch rather than leaving them at their markup defaults while the recorded value sits invisible in `meta.dataset.tweaks` (commit `d07e4b55`). Restyling the judged candidate's own iframe content (as opposed to the shell's own preview) was ruled out of scope — the iframe is deliberately sandboxed without `allow-same-origin`, and reaching into it would need a materially larger, opt-in cross-frame protocol; filed as follow-up #1336.
