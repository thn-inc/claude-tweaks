# 1337: friction-events.js: aggregate volume signal is polluted by test-fixture gate-denial events

Surface: backend

## Current State

This #357 wrap-up run's Friction lens pulled `bin/friction-events.js --run {run-dir}` and got 136
`gate-denial` events. Every single one traces to a synthetic temp-directory fixture path
(`/private/var/folders/.../T/ct-disp-repo-*/a.txt`) — none are a real operator action denied
during that run. These are almost certainly produced by the test suite's own exercise of the
pre-tool-use hook's deny logic against synthetic repos (`npm test` running hook-behavior tests),
not by anything the build/review/wrap-up session did. `friction-events.js` has no way to
distinguish "a real session action the hook denied" from "a unit test asserting the hook denies
a synthetic fixture" — both append through the same `appendEvent(...)` call site
(`bin/lib/hooks/pre-tool-use.js`), which resolves `ownedRun.dir` from the calling process's own
session/env attribution (`ctxLib.resolveRun`) regardless of whether the call originated from a
real tool invocation or a `node --test` assertion running in-process against a synthetic fixture.

## Deliverables

A way for `friction-events.js` (or the underlying `appendEvent` call in
`bin/lib/hooks/pre-tool-use.js`) to exclude denial events generated by the test suite's own
exercise of the hook — e.g. an explicit test-mode flag/env var the hook checks before logging,
or a path-shape heuristic recognizing the test harness's own tmpdir fixture convention.

## Acceptance Criteria

- Running the full `npm test` suite no longer inflates a subsequently-queried run's
  `gate-denial` count in `friction-events.js`'s output.
- A real operator wd-deny/gate-denial during an actual session still logs and is still returned.
- The Friction lens's "Aggregate volume" judgment (`reflect/full-mode.md`) can trust the count it
  reads without needing to manually classify every event's path, as the #357 wrap-up run had to.

## Technical Approach

Two candidate mechanisms, per the Deliverables — pick one at implementation time rather than
stacking both:

1. **Test-mode signal at the write site.** `pre-tool-use.js`'s `appendEvent(ownedRun.dir,
   'gate-denial', ...)` call (currently ~line 655) checks an explicit marker — an env var the
   test harness sets before invoking the hook module in-process (e.g. something in the same
   family as existing test-only env conventions) — and skips the `appendEvent` call, or tags the
   written event with a `test: true` field `friction-events.js` filters on read. This keeps the
   write side authoritative about provenance instead of guessing from the path after the fact.
2. **Path-shape heuristic at the read site.** `friction-events.js`'s `readEvents` (or its
   aggregation step) recognizes the test harness's own tmpdir fixture convention (the
   `ct-disp-repo-*` prefix under the OS tmpdir) and drops matching `gate-denial` events before
   counting. Cheaper to land (no hook-side change) but brittle — it hard-codes a fixture naming
   convention that lives in the test suite, not in the hook, and would silently stop working if
   the fixture prefix ever changes.

Whichever is chosen, the fix must not change behavior for a real wd-deny/gate-denial produced by
an actual operator action — Acceptance Criteria's second bullet is the regression guard for that.

### Key Files

- `bin/lib/hooks/pre-tool-use.js` — the `appendEvent(ownedRun.dir, 'gate-denial', ...)` call site; candidate home for a write-side test-mode gate
- `bin/lib/hooks/context.js` — `appendEvent`'s implementation (writes `runDir/events.jsonl`); candidate home for a shared test-mode gate if it should apply to more than just `gate-denial`
- `bin/friction-events.js` — `readEvents`/aggregation; candidate home for a read-side path-shape filter instead
- `tests/` — the `node --test` hook-behavior suites that exercise `pre-tool-use.js`'s deny logic against synthetic repos; whichever mechanism is chosen, these tests are what must set the signal (or keep producing the fixture path pattern) the fix relies on

## Gotchas

- Fix touches `bin/lib/hooks/pre-tool-use.js` and/or `bin/friction-events.js`, neither of which
  was in #357's own diff.
- Needs-human-decision undertone: the "right" signal to gate on (env var vs path heuristic vs a
  dedicated test-mode logger seam) is a design call, not a purely mechanical fix.
