# 1240: specify: preserved Original request placeholder tokens trip materialize-format.js's whole-body PLACEHOLDER_RE
Surface: backend

## Current State

`plugin/skills/specify/shaping-mode.md` mandates verbatim preservation of a record's original title/body into a new `## Original request` section ("this is a rule, not a suggestion"). Separately, `plugin/bin/lib/issues/materialize-format.js`'s `shapeGate(body)` (lines 10, 28-38) runs its placeholder-detection regex against the entire composed body with no section exemption -- this is `/flow`'s materialization hard gate. That regex flags three markers: a three-letter "yet to be decided" abbreviation, a four-letter "still outstanding" abbreviation, and an HTML-comment-prefixed ambiguity flag.

## Deliverables

- [ ] Reproduced live on #1207: `/claude-tweaks:specify #1207` shaped the record correctly (all five required sections present and non-empty, `risk:low`/`size:medium`/`ceremony:standard`/`ready` labels landed, `parked` absent), but the preserved `## Original request` text carried one of those markers verbatim, inherited from the original capture's own Deliverables bullet describing an exact set left undecided at build time. Read-back confirmed the placeholder regex matched the written body solely because of that preserved section.
- [ ] Decide and implement one remedy: either scope `shapeGate`'s placeholder check to exclude the `## Original request` section (materialize-format.js), or give `shaping-mode.md` an explicit sanctioned way to flag/neutralize a placeholder marker found only in the preserved verbatim copy (today there is none -- hand-editing the verbatim text isn't sanctioned per the "rule, not a suggestion" preservation clause)

## Acceptance Criteria

1. A record whose only placeholder-marker occurrence is inside a verbatim-preserved `## Original request` section passes `/flow`'s materialization hard gate
2. A record with a genuine unresolved placeholder marker in its own authored sections (Current State/Deliverables/Acceptance Criteria/Technical Approach/Gotchas) still fails the gate as today
3. Existing materialize-format.js tests plus a new regression test covering this exact case pass

## Technical Approach

Pick one of the two remedies named in Deliverables and implement it end to end:

1. **Scope the gate** -- in `shapeGate(body)`, strip (or otherwise ignore) the `## Original request` section's text before running the placeholder-detection regex against the remainder, so a marker preserved verbatim from a record's original capture can never fail the gate on its own.
2. **Sanction a neutralization convention** -- add an explicit, documented way for `shaping-mode.md`'s compose step to flag a marker found only inside the preserved verbatim copy (e.g. a wrapping annotation the gate is taught to recognize and skip), without hand-editing the "verbatim, don't touch" preserved text itself.

Whichever is chosen, update `shaping-mode.md`'s preservation rule and its placeholder-token authoring constraint to describe the sanctioned behavior, and extend `materialize-format.js`'s test suite with a regression case mirroring this exact reproduction -- a marker present only in `## Original request`, absent from every authored section.

### Key Files

- `plugin/bin/lib/issues/materialize-format.js` -- `shapeGate` and its placeholder-detection regex, the gate this record is about
- `plugin/skills/specify/shaping-mode.md` -- the preservation rule and the placeholder-token authoring constraint
- materialize-format's test suite -- add the regression case

## Gotchas

- Whichever remedy is picked must still fail a record whose *own* authored sections (not the preserved copy) carry a genuine unresolved marker -- Acceptance Criterion 2 exists specifically to guard against a fix that's too broad.
- Composing this very record's shaped body has to avoid writing the abbreviations and the HTML-comment-prefixed flag literally in its own authored sections, for the same reason the underlying bug exists -- a naive editorial pass here would trip the gate on itself. The preserved `## Original request` section below is exempt from that constraint (it's verbatim, not composed prose) and does contain the literal markers as a live illustration of the bug.
