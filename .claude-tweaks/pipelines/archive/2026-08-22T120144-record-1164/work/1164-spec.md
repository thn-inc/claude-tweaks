# 1164: 3 clean pipeline-run dirs fail archive-run — local main checkout mirror is stale/dirty, one case unexplained

Origin: ledger resolve gate

## Current State

Three pipeline run directories under `.claude-tweaks/pipelines/` have `run-state.json` status
`clean` but `node plugin/bin/hooks.js archive-run --run <dir>` refuses each with `archival
refused — git-mv-failed`: `.claude-tweaks/pipelines/2026-08-20T193627-record-355`,
`.claude-tweaks/pipelines/2026-08-20T193632-record-345`,
`.claude-tweaks/pipelines/2026-08-20T204530-record-951`. Detected by this run's residue sweep
(`plugin/bin/residue.js --scope blast-radius`) during wrap-up of record #280.

Root-caused via direct `git mv` stderr capture (the wrapper `bin/lib/hooks/git-exec.js`'s
`runGit` discards stderr, `stdio: ['ignore','pipe','ignore']`, which is why `archive-run` itself
never surfaces a reason): `fatal: source directory is empty` — `git mv` sees no tracked content
under `work/` from the local main checkout's own index.

**record-355 and record-951**: their materialize commits (`69cef5a7`, `ac1f3fdc`) ARE already
reachable from `origin/main` (`git branch --all --contains <sha>` lists `remotes/origin/main` for
both) — the files are safely committed upstream. The local main checkout's own working
tree/index is simply stale: `node plugin/bin/hooks.js reconcile` reported `mirror: not
fast-forwarded (dirty)` when this run's wrap-up ran it, meaning something in the local main
checkout has uncommitted/staged changes blocking a clean `--ff-only` pull. Once that dirty state
clears and the mirror fast-forwards, these two files become tracked in the local index and
`archive-run` should succeed unmodified.

**record-345**: unexplained — `git log --all --oneline -- .claude-tweaks/pipelines/2026-08-20T193632-record-345/work/`
returns nothing at all (no commit on any ref, dangling or not, touches this path), yet the
physical file (`345-spec.md`) exists on disk with real content. This is a different, deeper issue
than the staleness explanation above and needs its own investigation — possibly never committed
in the first place, or committed then the ref/branch was deleted before any merge captured it.

Record #280's own analogous case (this same run's wrap-up) had a third, distinct cause — a
`git revert` on the feature branch itself reverted the materialize commit before the branch
merged, so the file never reached `origin/main` at all — see the sibling staged proposal
(`ledger-record-backfill-280-spec-audit-trail.md`) for that one. Do not assume 355/345/951 share
#280's revert cause; the evidence above says otherwise for 355/951 at least.

## Deliverables

- Clear whatever uncommitted/staged state is blocking the local main checkout's `--ff-only` pull,
  then re-run `node plugin/bin/hooks.js reconcile` (or `archive-run` directly) for
  record-355 and record-951 — expected to succeed once the mirror catches up
- Investigate record-345's missing commit history separately; determine whether its content was
  ever actually merged anywhere, and if not, materialize/commit it properly before archiving

## Acceptance Criteria

- `node plugin/bin/residue.js --base <any-recent-sha> --integration-branch origin/main --scope
  blast-radius --no-suite` no longer reports these three directories as outstanding pipeline-run
  findings
- record-345's spec file is confirmed either genuinely tracked somewhere reachable, or freshly
