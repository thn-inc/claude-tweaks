# 5990: Let a review-replay arm set its effort, and refuse to score a replay agent that ran at another

Surface: backend
Risk-flags: none

## Overview

Adds an `effort` key to a review-replay arm, so an arm can run its replay agents at an effort other than the one its profile names, and makes `score` prove that each replay agent actually ran at the effort its arm asked for. This is the effort arm of the pipeline economy design's Phase 14 (`docs/superpowers/specs/2026-11-18-pipeline-economy-design.md`): the replay has to show what a review finds at `low`, `medium` and `high` before a review is given one fixed effort. The arm key alone is not enough. The design's evidence shows that an effort named only in a prompt sentence does not reach the agent, and that a launch with no effort runs at the session's effort or at `medium`. So a slot that ran at the wrong effort must count as not judged, not as an answer from the arm.

**Complexity:** Low
**Estimated tasks:** 4

## Non-Goals

- Replaying lens, task or whole-branch reviewers. That is the second and third sub-issues of this phase. This record changes only the existing tiebreak replay's arm grammar and its `score`.
- Choosing an effort for any review. The live replay run decides that.
- A `model=` arm key. An arm's model still comes from its profile (`fast`, `standard`, `capable`, `frontier`).
- Changing `plugin/bin/lib/model-profiles/profiles.js` or any policy value.

## Prerequisites

None.

## Current State

- `tools/review-replay/extract.js` `parseArm` (line 28) accepts the keys `name`, `chunk`, `profile` and `repeat` (`ARM_KEYS_ACCEPTED`, line 19). `writeOutputs` writes each manifest arm with `model: PROFILES[a.profile].model, effort: PROFILES[a.profile].effort` (line 230). The shipped profile table gives `fast` no effort and the other three `high`.
- `tools/review-replay/schema.js` already lists `effort` in `ARM_KEYS` (line 26), and `tools/review-replay/replay.workflow.js` passes `effort` to `agent()` when it is not `null` (`tests/review-replay/workflow.test.js` lines 51 and 61 pin both cases).
- Whether a Workflow script's `agent()` effort reaches the agent has not been measured. The design's Phase 15 lists the review workflow's agents as running at the harness default, measured `medium`.
- A subagent transcript records the effort of each assistant turn as top-level `effort` and `perTurnEffort` fields on the `type: "assistant"` entry (seen 2026-11-21 on a Claude Code 2.1.x transcript: 264 assistant entries, each `"effort":"high"` and `"perTurnEffort":"high"`).
- `tools/review-replay/score.js` identifies each judge from its transcript's identity line (`agentIdentity`, line 63), totals its cost (`transcriptCost`, line 71), and counts a finding it cannot settle under `notJudged` by reason (line 246). Any `notJudged` makes it exit 3 (line 284). It never reads the recorded effort.

## Deliverables

- [ ] `--arm` accepts `effort=<level>`, where `<level>` is one of `low`, `medium`, `high`, `xhigh` and `max` (the Agent tool's values). Any other value is a malformed invocation (exit 2) naming the value. With `effort` given, the manifest arm's `effort` is that value; without it, the profile's effort as today.
- [ ] `score` reads the effort each identified replay agent's assistant turns recorded. Per arm it reports `recordedEffort`: a count of agents by the effort they recorded, with `mixed` for an agent whose turns disagree and `unrecorded` for one whose turns carry none.
- [ ] When an arm's manifest `effort` is not `null`, every finding of a slot whose agent recorded anything other than that effort on every turn is counted under `notJudged` with reason `effort-mismatch`, so `score` exits 3. When the arm's effort is `null`, there is no check and `recordedEffort` is still reported.
- [ ] `tools/review-replay.js`'s header comment and `USAGE` show the new key. The journey `docs/journeys/replay-archived-reviews-to-measure-a-tiebreak-change-5557.md` gains the key in step 2 and `effort-mismatch` in step 4's notJudged reasons.
- [ ] Tests in `tests/review-replay/extract.test.js` and `tests/review-replay/score.test.js`, with transcript fixtures whose assistant entries carry `effort`.

## Acceptance Criteria

1. `node tools/review-replay.js extract ... --arm name=lo,chunk=1,profile=capable,repeat=1,effort=low` writes a manifest whose arm `lo` has `"model":"opus"` and `"effort":"low"`.
2. `--arm name=x,profile=capable,effort=fast` exits 2, and stderr names `fast`.
3. An arm without `effort=` writes the same manifest arm as before this change, byte for byte (the profile's model and effort).
4. In `score`, a slot of an arm with `effort: "low"` whose transcript's assistant entries all carry `"effort":"medium"` puts each of its findings under `notJudgedByReason["effort-mismatch"]` and makes the command exit 3. The same slot with entries carrying `"effort":"low"` is scored.
5. A slot whose agent recorded no effort on any turn, in an arm with a non-null effort, is `effort-mismatch`, and that arm's `recordedEffort` shows it as `unrecorded`.
6. Reverting the score change makes the test for criterion 4 fail. The pull request quotes that red run.

## Release Note

Maintainer tooling only, nothing ships: the review replay can run an arm at a chosen effort and refuses to score a replay agent that did not run at it.

## Technical Approach

Extend `parseArm` with one key validated against a local five-value list. In `score`, read the effort per assistant entry in the same pass that `transcriptCost` makes over the parsed lines, and check it per slot before settling, beside the existing `no-reply` and `chunk-split` reasons.

### Key Files

- `tools/review-replay/extract.js` — accept and validate `effort=`; write it into the manifest arm
- `tools/review-replay/score.js` — read recorded effort per agent; `recordedEffort` per arm; `effort-mismatch` notJudged reason
- `tools/review-replay.js` — header comment and `USAGE`
- `tests/review-replay/extract.test.js` — arm parsing and manifest cases
- `tests/review-replay/score.test.js` — mismatch, match, unrecorded cases
- `docs/journeys/replay-archived-reviews-to-measure-a-tiebreak-change-5557.md` — steps 2 and 4

## Gotchas

- `score.js` is also changed by #5632 (judges that read outside their tree), #5704 (Standard-tier escalation) and #5967 (shared usage reader). Keep the change local to the slot-settling loop and the per-arm summary so the merges stay mechanical.
- A turn's `effort` and `perTurnEffort` have been equal in every transcript seen. Read `effort`. If a fixture or real transcript shows them differing, report both and do not pick one silently.
- The prompt's `[Effort: …]` sentence is not how effort reaches the agent. Do not add one to the judge prompts.
- If the live run shows that `agent()`'s effort does not reach the agent, every non-default arm ends `effort-mismatch` and `score` exits 3. That is the intended outcome: it tells the live run the key is inert. `recordedEffort` reports `unrecorded` apart from a mismatch, so a change in the transcript format shows as `unrecorded`, not as a wrong effort.
- Read every `type: "assistant"` entry in the agent's own transcript; one without an `effort` field makes the slot `unrecorded`, and any entry that differs from the arm's effort makes it `effort-mismatch`, because a slot must have run at one effort throughout. A transcript `agentIdentity` cannot identify is handled as `score` handles it today.
- `effort=` is accepted on every profile, including `fast`, whose own effort is `null`: the arm's effort then applies and is checked. The recorded string is compared with the arm's value as written (`low`, `medium`, `high`, `xhigh`, `max`).
