# 2792: New skill idea: detect prose tables pinned to a code twin with no conformance test

Origin: ledger resolve gate

## Current State

Two review lenses independently flagged a project skill pinning a prose-canonical table to a code twin during the #2251-2258 multi-spec build — a pattern where a skill's markdown prose restates a table that also exists as executable code (an enum, a switch, a lookup table), and the two can drift apart with no test catching it (the same class as `record.js`'s `TYPE_LABELS` needing to stay in sync with `subject.js`'s `TYPE_PREFIX`, which this repo already pins via an explicit conformance test). No project skill currently names this pattern as something to check for during review.

## Deliverables

A new project skill (working name `prose-code-twin-pin`) that a reviewer or skill-author can invoke to find prose-restated tables with a code twin, and check whether a conformance test pins them equal — modeled on this repo's own existing pinning-test convention (e.g. `tests/deferral-gate-conformance.test.js`, `tests/bin-lib/compose-subject.test.js`'s "Type vocabulary has one source of truth" test).

## Acceptance Criteria

- A new skill exists under `plugin/skills/` (or `.claude/skills/` per this repo's own dogfooding convention) describing the prose-code-twin-pin pattern and when to check for it
- The skill names at least the two known instances from #2251-2258 as worked examples
- `/claude-tweaks:harness-health` or `/claude-tweaks:review`'s skill-gap detection can surface a candidate instance of this pattern

## Release Note

New project skill: `prose-code-twin-pin`, for finding prose tables that restate executable code without a conformance test pinning them equal.
