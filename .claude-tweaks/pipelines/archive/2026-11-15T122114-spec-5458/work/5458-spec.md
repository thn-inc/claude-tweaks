# 5458: Driver: the push guard misses a same-commit branch switch

Origin: SDD ruling ratified at Review Console (#5414 final whole-branch review, run 2026-11-14T153732-spec-5414-5415; maintainer chose the push-guard option)

Defer-reason: needs-human-decision

## Current State

#5414 made the pipeline driver read HEAD on both sides of every worker launch (`plugin/bin/lib/driver/steps.js`, `runImplementer`) and stop the record when HEAD moved or became unreadable. That check compares commits only. A worker that switches to another branch, or detaches HEAD, at the same commit passes it. So does the push guard (`pushStep`, `steps.js:863-897`): it checks that `rev-parse HEAD` equals the commit `check` verified, then pushes `refs/heads/{branch}`.

In that case a later fix-round commit lands on whatever HEAD now points at, not on `{branch}`, and the push sends `{branch}` without it. The PR then misses the fix commit until CI or a reviewer notices. The worker's rights already block `git switch` and `git checkout`, so this is defense in depth against escaped worker code. `docs/driver.md` `## Worker rights` states the limit today ("A branch switch is caught only when it changes the commit HEAD points at").

The maintainer chose the narrower fix at the run's Review Console: one more read in the push guard rather than a `symbolic-ref` read around every launch. Launch-side detection would need two more calls per launch and an amendment to #5414's AC7 call-count pin.

## Deliverables

- [ ] In `pushStep`, after the existing HEAD comparison and before `git push`, read `refs/heads/{branch}` (`git rev-parse --verify --end-of-options refs/heads/{branch}`) and stop the record with status `stop` (pre-push) when it is not the commit `check` verified. The stop names the branch and both shas, and every value goes through `neutralize`. A read that fails stops with a fixed detail, never git's stderr.
- [ ] `docs/driver.md` `## Worker rights`: replace the same-commit-switch limit with the push guard's branch check.
- [ ] Tests in `tests/bin-lib/driver/run.test.js` for every acceptance criterion below.

## Acceptance Criteria

1. Over a fake runner, a run where `refs/heads/{branch}` reads a different sha than `check`'s head (HEAD itself at the checked sha) stops at the `push` step and runs no `git push`.
2. A `refs/heads/{branch}` read that fails stops at the `push` step with a fixed detail and runs no `git push`.
3. On the Phase 1 happy path the recorded calls differ from before only by the one added `refs/heads/{branch}` read, immediately before the push, and the event lines are unchanged.
4. `grep -F "A branch switch is caught only when it changes the commit HEAD points at" docs/driver.md` matches before the change and returns nothing after it, and `## Worker rights` names the push guard's branch check.

## Release Note

The pipeline driver now refuses to push when its branch no longer points at the commit it checked, so a branch switch during a worker run cannot ship a branch without its latest commit.
