# 3674: Fail closed on a jest log that does not end with the runner's trailer

Origin: reflect full from #3480

Defer-reason: tangential

**Related:** #3676

## Current State

After #3480, `summaryUnattributedCount` (`plugin/bin/lib/verify/extract.js`) accounts a jest or vitest log by enumerating failure channels: `UNATTRIBUTED_LINE_RES` plus the vitest banners. That list was incomplete three times in one build: the spec named three shapes, the SDD final review added obsolete snapshots, global hooks and bail, and the review phase added the `Unhandled Rejection` and `Source Errors` banners, each found only by reading runner source or capturing a real log. Any channel not yet enumerated reads as fully accounted (a false 0), the unsafe direction for a flaky retry or a preExisting waiver.

## Deliverables

- [ ] Add a positive-recognition guard for jest: a log whose last non-empty line is not the runner's normal `Ran all test suites…` trailer is unattributed, since a crash after or instead of the summary leaves a stack or other text there.

- [ ] Decide, with a captured vitest log per case, whether vitest has an equally stable closing marker; if it has none, record that and keep its enumerated list.

- [ ] Keep every existing fixture row in `DIALECT_ROWS` green and add one captured log of an unenumerated post-summary crash for jest that only the trailer guard refuses.

- [ ] Update the three prose sites (`plugin/skills/test/verification.md` Flake handling, `docs/journeys/run-a-deterministic-verification-check.md` Step 10, `.claude/skills/node-test-output-evidence/SKILL.md`) to name the guard.

## Acceptance Criteria

- [ ] A jest log whose final line is not the `Ran all test suites` trailer refuses with `unattributed-failures: {N}` even when no enumerated channel matches.

- [ ] A fully attributed jest log (`jest-attributed.txt`) still retries.

- [ ] The new guard's test goes red when the guard is removed.
