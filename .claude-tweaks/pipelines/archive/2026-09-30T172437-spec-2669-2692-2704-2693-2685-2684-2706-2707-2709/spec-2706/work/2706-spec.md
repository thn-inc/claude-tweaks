# 2706: Add a notification-badge design checklist to the UI review lens

Surface: infra

**Related:** #2707, #2709

## Current State

The Impeccable/design-review lens has no explicit rules for count badges vs. status dots (when to combine, when they collide). No guidance distinguishes "something changed" (dot) from "how much" (number), or governs badge color semantics (red = act now, green = online). No rule flags a badge that lingers after the user has already viewed the item, or a count that resets to zero instead of ticking down.

## Deliverables

- A policy row (or lens check) for badge/dot usage: one signal per element, color tied to meaning, clears on view.
- A check for "badge everything" anti-patterns that dilute color meaning.
- Reference the source technique inline so the check has a rationale, not just a rule.

## Acceptance Criteria

- Running the design-review lens on a UI with a badge flags a dual dot+counter on the same element.
- The check explains why (noise / trained-to-ignore) rather than just failing silently.

## Release Note

The UX heuristics lens now flags confusing notification badges: doubled dot-and-count signals, colors without meaning, and badges that never clear.

## Technical Approach

Add the badge/dot rules as rows in `/claude-tweaks:visual-review`'s UX heuristics lens (`plugin/skills/visual-review/ux-heuristics-lens.md`, the plugin-owned UI checklist that page mode Step 4 applies and `/claude-tweaks:review` uses for UI-affecting diffs), in its existing Heuristic | What it flags | Example violation shape. `design-wrapper/modes/` is not the home: it routes to Impeccable and to project-local critics and owns no checklist of its own. Rows: one signal per element (flag a status dot and a count badge on the same element), color tied to meaning (flag badge colors that do not map to a stated convention, and "badge everything" dilution), and clears on view (flag a badge that lingers after the item was viewed, or a count that resets instead of ticking down). Each row's "What it flags" carries the one-line rationale (noise; users trained to ignore), per the Acceptance Criteria.

### Key Files

- `plugin/skills/visual-review/ux-heuristics-lens.md` — new checklist rows for badge/dot usage

## Gotchas

- #2707 and #2709 edit the same file (`ux-heuristics-lens.md`); Key Files overlap lets `/flow`/`/dispatch` group them. Landing them together avoids three rounds of churn on one table.
- Keep the rationale text genuinely explanatory (why dual-signal badges create noise), not a restated rule — the Acceptance Criteria require it.
- The lens header describes its rows as manual-inspection prompts, not hard rules; the new rows follow that framing.
