# 2684: Audit CLAUDE.md files against Anthropic's own <200-line context-engineering guidance

Surface: infra

## Current State

Anthropic's own context-engineering guidance says Claude Code's own system prompt was cut by over 80% for Opus 5/Fable 5 with no measurable eval loss, and targets CLAUDE.md files at roughly under 200 lines. An independent audit of a real 388-skill repository found its CLAUDE.md at 829 lines / 110KB — 4x over that target, with one section alone consuming 86,630 characters. A separate piece from the same author on writing a good global CLAUDE.md argues each rule should name a specific past failure rather than state vague preferences (e.g. "write clean code"). claude-tweaks generates and maintains CLAUDE.md content across projects with no check against this size or authoring guidance. Notably, this repo's own CLAUDE.md already practices a related discipline manually — its `## Don'ts` section states "Full rule list now lives in docs/donts.md (moved out of this always-loaded file to fit the 150-line budget)" — so a lint/audit check would formalize and enforce a budget this repo already tries to hold ad hoc.

Update (shaping, 2026-09-30): the line-count half already exists. harness-health's check 4 (`plugin/skills/harness-health/judge-procedure.md`, "Tiered line-budget check") puts CLAUDE.md in the always-loaded tier and compares it against `harness-health-always-loaded-budget`, default 150 (`_shared/policy-schema.md`). Missing: a single-runaway-section signal, and the specific-failure authoring principle in `init`'s CLAUDE.md template. The record is rescoped to that delta.

## Deliverables

1. Add a runaway-section signal to harness-health's tiered line-budget check (check 4) in `plugin/skills/harness-health/judge-procedure.md` and `plugin/skills/_shared/harness-health-analysis.md`: flag a CLAUDE.md whose largest `##` section exceeds a stated share of the file's lines, even when the file is under budget.
2. Add the "each rule names a specific past failure, not a vague preference" principle, citing Anthropic's context-engineering guidance, to `plugin/skills/init/claude-md-template.md`'s authoring guidance.

## Acceptance Criteria

1. Check 4 in both `judge-procedure.md` and `_shared/harness-health-analysis.md` describes the runaway-section signal, its threshold, and how the section share is computed (heading-bounded line counts).
2. The signal reports as a `template-conformance` finding framed as a flag for review, never a hard failure.
3. The `harness-health-always-loaded-budget` default (150) is unchanged.
4. `plugin/skills/init/claude-md-template.md` states the specific-past-failure principle and cites its source.
5. `npm test` passes.

## Release Note

Harness health now flags a CLAUDE.md dominated by one runaway section, and generated CLAUDE.md guidance asks each rule to name a specific past failure.

## Technical Approach

harness-health check 4 already classifies CLAUDE.md into the always-loaded tier and compares `wc -l` against `harness-health-always-loaded-budget` (default 150, stricter than the 200-line guidance). Extend that check with a second mechanical signal: scan `##` heading boundaries and flag when the largest section exceeds a stated share of the file (e.g. 40% of its lines), even when the total is under budget — reported as the same `template-conformance` finding, a flag for review, never a gate. Mirror the change in `_shared/harness-health-analysis.md`'s check 4 so the two stay identical. Separately, add the specific-failure principle to `plugin/skills/init/claude-md-template.md`, the origin template dimensions 7 and 8 already read for `claude-md` targets.

- `plugin/skills/harness-health/judge-procedure.md` — check 4 (tiered line-budget) gains the runaway-section signal
- `plugin/skills/_shared/harness-health-analysis.md` — the same check 4 in the shared analysis procedure, kept in step
