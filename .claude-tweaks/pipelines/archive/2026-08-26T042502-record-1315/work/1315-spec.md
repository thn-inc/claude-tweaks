# 1315: Veto-window-hours resolver-failure hazard: empty policy value bypasses the 24h fallback

## Current State

`#309`'s veto-window maturation logic (`bin/lib/issues/grant-maturation.js`'s `evaluateMaturation`) has two call sites — `plugin/skills/dispatch/settle-and-merge.md`'s Auto-merge gate Phase 1, and `plugin/skills/wrap-up/auto-merge-short-circuit.md`'s Authorization layer (added in a #309 fix-wave follow-up) — that both compute the veto window the same way:

```bash
GRANT_VETO_WINDOW_HOURS=$(node bin/resolve-policy.js --values grant-veto-window-hours)
...
vetoWindowHours: Number('$GRANT_VETO_WINDOW_HOURS'),
```

`grant-maturation.js` has a belt-and-braces fallback to a 24h default when `vetoWindowHours` is invalid (`NaN`), but `Number('')` evaluates to `0` — a finite, non-`NaN` number — so if the policy resolver ever returns an empty string (e.g. a transient resolution failure), the fallback never engages and every `auto:merge-pending` grant matures instantly with zero veto window. This defeats the entire point of #309: giving a human a real window to veto a machine-originated merge grant.

Discovered during #309's fix-wave scoped re-review as a pre-existing hazard, now duplicated across two sites rather than one after the follow-up fix. Out of scope for that review's own findings list — flagged for its own scoped fix.

## Deliverables

- Validate the resolver's output at both call sites before passing it to `evaluateMaturation` (treat empty/non-numeric as invalid rather than trusting `Number()`'s permissive empty-string coercion), OR harden `grant-maturation.js`'s `evaluateMaturation` itself to treat `vetoWindowHours <= 0` (or non-finite) as invalid input equivalent to `NaN`, triggering the same 24h fallback.
- A regression test proving an empty-string (or non-numeric) policy value does not zero out the veto window and does not bypass the fallback.
- Both call sites covered by the fix — not just one.

## Acceptance Criteria

- A test exists asserting `evaluateMaturation` (or the calling site's own guard) does not treat an empty-string-derived `0` as a valid, sub-24h veto window — the belt-and-braces fallback still engages.
- Both `settle-and-merge.md`'s Auto-merge gate and `auto-merge-short-circuit.md`'s Authorization layer are covered by the fix (a single-site fix leaves the sibling site vulnerable).
- No change to the intentional, already-correct behavior when the resolver returns a real numeric string.
