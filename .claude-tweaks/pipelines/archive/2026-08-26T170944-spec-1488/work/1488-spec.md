# 1488: Sweep residue: needs:decision marker, comment template, and the needs:* worklist rule (absorbs #1317)

Surface: backend

## Overview

Introduces `needs:decision` — one label, one comment shape — as the tracker-side residue channel
for any headless unit's "I can't decide this alone" outcome. Today that outcome is expressed
three incompatible ways: `needs:definition`/`solution:unjustified` (labels a list reads),
`backlog refine`'s comment-only human-only marker (#1317/PR #1440, ships no label), and tidy's
report rows (invisible after a headless firing). This absorbs #1317 by generalizing its marker
into a label plus a documented comment template, adds the worklist rule every headless unit must
respect, and closes the standing gap where a content-level "not an autonomous-build candidate"
verdict gets expressed as "not shaped" and strips `ready` — looping the record between `ready`
and backlog forever.

## Non-Goals

- Does not change `grant-gate.js`'s gate 1-3 refusal behavior (origin, trust, ceiling, cap) —
  those stay silent by design; only the gate-4 content refusal gets a marker.
- Does not build `attention`'s rendering of this marker, `refine #N`'s resolution UI, or the
  headless `refine` posture — those are Phase 2 and Phase 3.
- Does not touch `needs:definition`'s own filing-time semantics (`/capture`/`/feedback`'s content
  judgment) — only its removal authority and its place in the shared worklist rule.

## Acceptance Criteria

1. A scored (`risk:*` + `size:*` present), spec-shaped record refused by `grant-check` (headless
   or interactive path) ends the run carrying `ready` + `needs:decision` + exactly one unresolved
   decision comment naming `/claude-tweaks:backlog refine #{n}`; running the same refusing path a
   second time against the same record writes no second comment and applies no label change — the
   idempotence check fires.
2. A record genuinely missing `risk:*` or `size:*`, or failing the spec-shape check, still lands
   in Flag-back exactly as before this record — `needs:decision` is never stamped in that branch.
3. `grant-gate.js`'s candidate fetch, `next-mode.md`'s eligibility query, and every `tidy`
   record-scoped shape each exclude a record carrying any `needs:*`-prefixed label — pinned by a
   conformance test (skill-prose-conformance-tests convention) reading the live `EXCLUDE` set
   construction and the `grant-gate.js` filter predicate, each with a go-red control proving the
   assertion can actually fail.
4. Shaping mode (`/specify` on a record reference) removes every `needs:*` label the record
   carries when it resolves that record's open question — verified against #763's own historical
   scenario: #763 entered shaping carrying `needs:definition`, had its stated open question
   resolved via an in-shaping `AskUserQuestion`, and was stamped `ready` + full scoring while
   `needs:definition` remained on the final label set (the exact bug this AC closes). Re-running
   that same shaping sequence today must land with zero `needs:*` labels remaining.
5. `#1317` is closed by this record with a comment naming it as the absorbing record — not built
   as a separate change. `#825` is closed the same way.
6. `gh label list` shows `needs:decision` with the stated description, and
   `claude-tweaks:bootstrapped-v6` replaces `claude-tweaks:bootstrapped-v5` as the bootstrap
   marker after this record's first bootstrap run.

## Technical Approach

The comment-marker + idempotence-check shape already exists and is proven correct — PR #1440
(open against #1317) shipped a comment-only version of exactly this outcome. This record's job is
narrower than reinventing it: promote that comment convention to a real label (so the worklist
rule has something mechanical to filter on) and generalize its `{unit}` tag so `backlog-grant` and
(later, Phase 6) `tidy` can write the identical shape. Do not re-derive the comment template from
scratch — read `backlog/human-only-outcome.md` (PR #1440) for the exact idempotence-check bash
snippet and marker-comment mechanics, and adapt rather than rewrite them.

### Data / API Surface

- New label: `needs:decision` (repo-wide GitHub label, `gh label create`).
- Comment marker format: `<!-- needs-decision: {unit} -->` as the comment's first line,
  unconditionally — `{unit}` is one of `backlog-refine`, `backlog-grant`, `tidy` (only the first
  two are wired by this record; `tidy` is Phase 6's job, but the format must already support it).
- Resolution line format: `**Resolved:** {choice} — {date}` prepended to the existing comment body
  in the same edit that removes the label.

## Gotchas

- **PR #1440 may land before or after this record builds.** #1440 (open, targets #1317) ships a
  comment-only marker with no label. If it merges first, this record's diff against
  `refine-mode.md`/`refine-lanes.md`/`grant-gate.js` becomes a generalize-and-add-label pass over
  already-shipped code, not a from-scratch addition — read the merged diff before writing this
  record's changes, and do not duplicate the idempotence-check logic PR #1440 already wrote.
  Either way, this record's own Acceptance Criteria (the label existing, the worklist rule) still
  need to land — PR #1440 alone does not satisfy them.
- **`EXCLUDE` in `next-mode.md` is a `Set`, not an array-of-prefixes check** — converting the
  `needs:definition` entry to a prefix rule means changing the *shape* of the exclusion check
  (from `.has(label)` to `.some(l => l.startsWith(...))` for that one case), not just the set's
  contents; the other four literals in the set stay exact-match.
- **`refine-mode.md` is at 40,933 bytes against the 40,960-byte ceiling** — 27 bytes of headroom.
  This record's edits to it must net-shrink or hold flat; if the Grant-lane fix alone doesn't fit,
  extract the branch into a new sub-file (e.g. `backlog/grant-lane-decision.md`, cited from
  `refine-mode.md` Step 3 the way `record-creation.md` is cited from `specify/SKILL.md`) rather
  than inlining more prose into `refine-mode.md` itself. Check the file's current size before
  writing a single line into it.
- **`grant-mode.md`'s gate-4 marker names `/claude-tweaks:backlog refine #{n}` as its `Command:`,
  not a command on `grant-mode` itself** — deliberate convergence, not an oversight: both origins
  (interactive Grant-lane refusal and headless gate-4 refusal) resolve through the same front
  door regardless of which gate produced the marker, so a human resolving a record never needs to
  know which path flagged it. This holds before and after Phase 3 folds `grant-mode` into
  `refine` — the `Command:` value doesn't change when that fold happens.
- **Never write the worklist rule twice.** State it once in `_shared/work-record.md` and have
  `grant-gate.js`'s code comment, `next-mode.md`'s prose, and `tidy/step-1-records.md`'s prose
  each cite it by name — this codebase's `_shared/` convention exists precisely to prevent the
  three-copies drift this design doc's own Problem section complains about.
- **`bootstrapped-v5` already exists on this repo** — bumping to `v6` means the next label
  bootstrap anywhere in the plugin re-runs the full check-then-create loop once, then re-stamps.
  That's expected, not a bug to guard against.
- **No automated resolver exists yet for a record this record stamps `needs:decision`.**
  `refine #N` (Phase 2) is what applies a human's choice and writes the `**Resolved:**` line
  going forward; until it ships, a human clears a stamped record manually: `gh issue edit #{n}
  --remove-label needs:decision` plus a comment appending `**Resolved:** {choice} — {date}` to the
  live decision comment, following the resolution rule by hand. This is expected during the window
  between this record and Phase 2, not a defect in either.
- **Check `_shared/work-record.md`'s own byte headroom before writing into it**, the same way the
  `refine-mode.md` check above applies — this record adds a label-taxonomy row, the comment
  template, new permission-matrix cells, and the worklist-rule statement to that file; measure
  `wc -c` first.
