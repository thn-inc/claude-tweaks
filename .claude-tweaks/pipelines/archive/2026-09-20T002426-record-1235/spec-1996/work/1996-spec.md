# 1996: Subagent skill-tree read gate: pre-tool-use denies a subagent's Read of plugin/skills/_shared when the step's composed bundle exists — go/no-go on U8's measurement

Surface: backend

## Overview

Add a new deny gate in `plugin/bin/lib/hooks/pre-tool-use.js` that denies a subagent's `Read` (or a Bash `cat`/`sed`/`head` invocation) of a `plugin/skills/_shared/**/*.md` path when the current run's `{run}/context/` directory already holds a composed bundle for the specific step currently in progress (the per-step condition governs everywhere in this record — Deliverables/AC below use "current run" loosely in a couple of places; read every such instance as "for the current step," since a run can have multiple steps and multiple bundles, and the gate must key off the one the current tool call's step actually needs, not merely "some bundle exists somewhere in this run") — enforcement for the boundary U8 established by convention alone. The first deliverable is explicitly a go/no-go check against U8 (#1995)'s own before/after measurement (reported in #1995's own last Deliverable and PR description): if U8 already achieved the ≥10× subagent-read reduction it targets, this record closes as not-needed, with the numbers quoted in the closing comment, rather than shipping an enforcement gate nothing further requires. That close is a snapshot judgment against U8's measured sessions, not a permanent guarantee — a later regression in subagent behavior that reintroduces heavy `_shared/` reads is a new record, evaluated fresh against then-current numbers, not an automatic reopening of this one.

**Complexity:** Low
**Estimated tasks:** 4

- Fixing #1894, #1501, or #1441 — all three also edit `pre-tool-use.js`; this record's gate is additive and must not collide with any of them, but resolving those records is out of scope here.

## Gotchas

- Read U8's numbers before writing any code — this record's very first deliverable can end the record entirely; do not start on the gate implementation until that read has actually happened and the decision is recorded.
- Every unprovable answer in this file fails CLOSED, and a conclusive exemption must never be gated on an unrelated inconclusive one (`[IL-149]`) — `wtDetect.repoInfo()`/`mainCheckoutRoot()` returning `indeterminate: true` or `null` is a different fact from a definitive negative, never read as "not applicable."
- Resolve the leaf symlink before deciding, mirroring `realTarget()` (`[IL-150]`) — a path-based decision made on the raw literal target can be defeated by a symlink whose target resolves outside the intended scope; never call a path-answering function on a literal path without checking for a leaf symlink first.
- A Bash-shaped exemption (or, here, a Bash-shaped deny condition) must match the ENTIRE command string against a grammar — no partial match on a flag or filename lets a differently-shaped command slip past. Prove the staged set with `git diff --name-status`, never `--name-only`, when verifying the fix's own diff.
