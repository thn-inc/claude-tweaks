# 2526: Mechanically enforce flow Step 2.8's claim write (follow-up from #2492)

Surface: infra

## Current State

#2492 confirmed that `/claude-tweaks:flow`'s Step 2.8 claim step (`bin/claim-targets.js`, or its MCP equivalent) has no mechanical backstop: a `/flow #2322 build,test` dispatch completed a full build+test pass with no `claims/issue-2322.json` blob ever written on `claims-registry`, and none of `flow/claim-targets.md`'s documented skip-guard conditions applied to that dispatch shape — the call was simply never made. `bin/claim-targets.js`'s own write path is not the gap (`tests/bin-lib/claim-targets/claim-targets.test.js` already covers create-only/conditional/contested/transient/unverified-write-back cases in depth, including the write-then-verify race #2073 closed). #2492 closed the doc-only half of this (claim-targets.md now mandates a `decisions.md` log line — `AUTO ... Step 2.8: claimed #{n}` — on every successful claim, both transports), but nothing yet enforces that the claim step actually ran before a build proceeds. This mirrors a failure class the codebase has already solved once: `bin/lib/hooks/pre-tool-use.js`'s `checkBookkeepingStampsGate` denies the next covered write until `record-worktree` and (under `integration-model: pr-first`) the PR-early draft-PR open have landed — added after IL-131 (a build agent skipping mandatory bookkeeping) recurred on #893. The claim step has no equivalent gate.

## Deliverables

- [ ] Extend `checkBookkeepingStampsGate` (or add a sibling gate using the same materialize-commit-sentinel + `runState`-cached-exemption pattern) to require, once this run's materialize commit has landed and `work-backend: github-issues`, that `decisions.md` carries the `Step 2.8: claimed #{n}` log line (mirroring the existing `hasLoggedPrDegrade` PR-stamp check) before allowing the next covered write — denying with a remediation message that names the missing claim, the same shape the worktree/PR denials already use.
- [ ] Thread a `claimExempt`-style cache field into `run-state.json` (mirroring `prExempt`) so this new check pays its cost once per run, not on every covered call.
- [ ] Add unit tests for the new check sized like the existing `checkBookkeepingStampsGate` coverage (the PR-stamp branch's own test file is the pattern to follow) — cover: claim logged → allow; claim missing after materialize → deny; `work-backend: local-files` → exempt (no claim infra); foreign-owned run → warn, not deny (matching the existing foreign-session downgrade).
- [ ] Update `docs/hooks.md`'s bookkeeping-stamps gate section and `flow/claim-targets.md`'s "Known gap" note (added by #2492) to point at the shipped mechanism instead of describing it as an open gap.

## Acceptance Criteria

- [ ] A `/flow #{n} build,test` dispatch whose Step 2.8 claim step is skipped (no `Step 2.8: claimed #{n}` line in `decisions.md`) is denied at its next covered write by the mechanical gate, with a remediation message — not silently allowed to proceed to a full build with no claim on record.
- [ ] `work-backend: local-files` runs, and runs where the claim log line is present, are unaffected (no new false-deny).
- [ ] `npm test` passes, including the new gate tests.

## Technical Approach

Mirror `checkBookkeepingStampsGate`'s existing PR-stamp branch shape (`plugin/bin/lib/hooks/pre-tool-use.js`): once the run's materialize commit is detected as landed and `work-backend: github-issues`, grep this run's `decisions.md` for a `Step 2.8: claimed #{n}` line before allowing the next covered write; deny with a remediation message naming the missing claim when absent. Cache the outcome per run in `run-state.json` (a new `claimExempt` field, mirroring the existing `prExempt` field) so the check reads `decisions.md` at most once per run rather than on every covered call. `work-backend: local-files` exempts unconditionally (no claim infra exists on that driver). A foreign-owned run (this session isn't the run's own owner) downgrades to a warning, matching the existing foreign-session posture the PR-stamp branch already uses — never a hard deny on state this session didn't create.

### Key Files

- `plugin/bin/lib/hooks/pre-tool-use.js` — add the new claim-stamp branch to `checkBookkeepingStampsGate`
- `plugin/bin/lib/hooks/context.js` — read/cache `run-state.json`'s new `claimExempt` field alongside `prExempt`
- `tests/hooks-bookkeeping-stamps-gate.test.js` — new test cases for the claim-stamp branch
- `docs/hooks.md` — update the bookkeeping-stamps gate section to document the new branch
- `plugin/skills/flow/claim-targets.md` — replace the "Known gap" note with a pointer at the shipped gate

## Gotchas

- The gate must key off `work-backend: github-issues` specifically — `local-files` has no claims infrastructure at all, so an unconditional gate would false-deny every local-files run.
- A foreign-owned run (this session isn't the run's own owner) must warn, not deny, mirroring the existing PR-stamp branch's foreign-session downgrade — the gate must not block a session that isn't responsible for the missing claim.
- Cache the check's outcome in `run-state.json` once landed, so a long multi-write build doesn't re-grep `decisions.md` on every covered call.
