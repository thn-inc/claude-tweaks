# 5589: Give the adopted-branch collision check a CLI so worktree setup stops sending a refused heredoc

Surface: backend

**Related:** #3915, #4627, #4058, #4283, #4243
Risk-flags: none

## Current State

`/claude-tweaks:build`'s worktree setup checks whether the branch it is about to adopt already exists on the remote with someone else's commits. The check is `plugin/bin/lib/worktree/remote-branch-collision.js` (`classifyRemoteBranch`, `findPrsForBranch`, `findPriorAttemptPr`, `formatStopCard`). It changes no file in the working tree and no ref: it runs `git ls-remote`, fetches the remote tip into the object store, checks ancestry and runs `gh pr list`. It returns one of the states `absent`, `mine`, `foreign` or `unreachable`.

The module has no CLI. `plugin/skills/build/adopted-branch-collision-check.md` (8,993 bytes) tells the agent to run it as a 14-line script in a heredoc fed to `bin/node-eval-file.js`:

```
node "${CLAUDE_PLUGIN_ROOT}/bin/node-eval-file.js" "{branch}" "{repo}" "{records}" <<NODE_EVAL_EOF
const m = require('${CLAUDE_PLUGIN_ROOT}/bin/lib/worktree/remote-branch-collision.js');
…
NODE_EVAL_EOF
```

The run is inside a linked worktree, where Claude Code's worktree-isolation guard judges every Bash call. Measured on 2026-11-16 with `tools/guard-refusals.js` over 2026-10-17 to 2026-11-16: the guard refused this command 346 times ("this command is too complex to verify that it stays inside the worktree"), 81 of them since 2026-11-02, the latest on 2026-11-15 from plugin 6.168.0. Of the 849 refusals in that window that trace to exactly one skill fence, 347 trace to this one, more than to any other. Each refusal costs the model turn that sent it and a retry in another form, and the file itself warns that a hand-rolled retry "silently no-ops on Windows Git Bash … which would read as a clean result".

The guard is harness code and the plugin cannot change what it accepts. A single `node <literal script path> <literal arguments>` call is a form it accepts (`plugin/skills/_shared/scratch-worktree.md` section 7).

Design: `docs/superpowers/specs/2026-11-15-process-efficiency-design.md`, Phase 3. How this differs from the design: the design planned to make "the guard's scanner" admit read-only shapes. The guard that refuses this command is not the plugin's, so the fix is to stop the skill text from producing the shape.

Tests that read this fence today: `tests/adopted-branch-collision-snippet-fixture.test.js`, `tests/adopted-branch-collision-prose-conformance.test.js` and `tests/node-eval-file-heredoc-syntax.test.js`. The module's own tests are in `tests/bin-lib/worktree/remote-branch-collision.test.js`.

## Deliverables

1. **A CLI**, `plugin/bin/remote-branch-collision.js`: `--branch <name>` (required), `--repo <owner/name>` (optional) and `--records <n[,m…]>` (optional). It parses its flags, calls one new exported function of the module, `checkAdoptedBranch({ branch, repo, records, git, gh })`, which holds the logic of the fence's script, and prints the result as one JSON line: `{ state, reason, remoteSha }`, plus `pr` when the state becomes `prior-attempt`, or `card` when a stop card is composed.
   Decided 2026-11-16: an empty `--repo ""` or `--records ""` means the flag was not given (`null` and `[]`), because the fence passes every placeholder even when its value is empty. An empty `--branch ""` is passed to the module, which answers `unreachable` with reason `invalid-branch-name` as it does today, and the CLI exits 0. Two differences from the old script are deliberate: an empty records value gives `[]` where the script's `split(',').map(Number)` gave `[0]`, and a records item that is not a positive integer exits 2 where the script dropped it silently. `pr` is printed as the module returns it.
2. **Exit codes.** 0 when a JSON line was printed, whatever the state. 2 for a malformed call (no `--branch`, an unknown flag, a `--records` item that is not a positive integer, a flag with no value, a repeated flag, a positional argument), with a usage line on stderr and nothing on stdout. An exception from the module prints `claude-tweaks: remote-branch-collision: {message}` on stderr and exits 1 with nothing on stdout, so "no output" still means "not a result", as the skill text already says.
3. **The fence becomes one plain command**: `node "${CLAUDE_PLUGIN_ROOT}/bin/remote-branch-collision.js" --branch "{branch}" --repo "{repo}" --records "{records}"`. The sentence that explains why the script is inline ("the module has no CLI of its own, and a hand-rolled multi-line `node -e` silently no-ops on Windows Git Bash") is replaced by one that names the CLI. The rules that follow the fence (re-run once on no output, what each state means) keep their meaning.
   Decided 2026-11-16: the re-run rule gains one clause: exit 2 is a malformed call, which is corrected and not re-run. A missing script file (`node` exits 1 with nothing on stdout) falls under the existing no-output rule, as the old fence's failures did.
4. **Tests.** A CLI suite with the module's `git` and `gh` injected: one case per state (`absent`, `mine`, `foreign` with a stop card, `foreign` turned `prior-attempt`, `unreachable` with and without a `remoteSha`), and one per exit code. The module's own suite gains the cases for `checkAdoptedBranch`. The snippet-fixture and prose-conformance tests are updated to the new fence, and the heredoc-syntax test loses the half of one case that reads it.
   The case at line 187 of `tests/node-eval-file-heredoc-syntax.test.js` (on 2026-11-16) checks two things: the header of `plugin/bin/node-eval-file.js`, and this skill file's fence, which it finds by `<<NODE_EVAL_EOF`. The second half goes with the fence; the header half and the file's other cases stay.
5. **Docs.** `docs/plugin-structure.md` lists the CLI. `docs/journeys/retry-a-record-whose-first-attempt-left-a-branch-3887.md` is updated where it describes how the check is run.

## Technical Approach

Write the CLI to `.claude/skills/gh-api-module-pattern`'s CLI wrapper contract: `run(argv, deps)` returns the exit code, `deps` is `{ git, gh, log, err }`, and the file ends with the `require.main === module` guard. The module's functions already take `git` and `gh` as parameters, so the CLI passes its injected runners through.

Move the fence's logic into `checkAdoptedBranch` line for line, including its two-sided condition (`r.state === 'foreign' || (r.state === 'unreachable' && r.remoteSha)`), the `reason` passed to the stop card, and the `prior` lookup only for `foreign`. Only the records parsing changes, as Deliverable 1 says.
Decided 2026-11-16: the composition moves into the module as one exported function, `checkAdoptedBranch({ branch, repo, records, git, gh })`, and the CLI only parses, calls it and prints. #3915 and #4627 change this check, and a function is where they can reach it. AC1 compares against literals written in the test, not against a second copy of the logic.

Keep `plugin/bin/node-eval-file.js`: other fences use it (`tests/node-eval-file-heredoc-syntax.test.js` reads 22 references).

## Gotchas

- Decision 0.1 of the design: sessions run mixed plugin versions. A session reads its own version's skill text and runs its own version's `bin/`, so the new fence and the new CLI always arrive together. Nothing is removed that an older session calls.
- The CLI name must not collide with a shipped or proposed one (`plugin/skills/_shared/issue-claims.md`, Deliverable-name collisions). On 2026-11-16 the only `remote-branch-collision.js` in the tree is the module under `plugin/bin/lib/worktree/`.
- The audit simplification design moves every `plugin/bin` CLI onto one argument parser (its Phase 3). Check at build time whether that phase has reached `plugin/bin`: if the shared parser exists, use it; if not, parse by hand like the neighbouring CLIs and leave the migration to that phase.
- #3915 (an MCP-fed PR lookup for the same check when `gh` is absent), #4627 (continue an open PR named by a `Continue-pr:` line) and #4058 (a confirmed review finding in the module) touch the module or this skill file. Rebase on whichever has landed, and keep whatever branch the fence gained in the meantime.
- #4283 is about skill snippets that splice `${CLAUDE_PLUGIN_ROOT}` into a JavaScript string literal, which breaks on a Windows path. This fence is one of them, and the CLI removes it. Say so in the PR; do not edit #4283.
- The exact property that makes the guard refuse the old command (the unquoted heredoc delimiter, the body's size or its text) was not isolated. #5590 probes it and writes the section 7 row. This record does not need the answer.
  Known from the 346 refused commands (scratch count, 2026-11-16): none names `CLAUDE_PLUGIN_ROOT`, because the agent had already pasted a literal path; 345 have an unquoted delimiter; 19 start with a `cd`; no script body holds a `$`; 343 were sent by subagents. So the variable is not the cause.
- `.claude/skills/skill-prose-conformance-tests` covers the two prose tests; `.claude/skills/windows-checkout-test-parity` applies to any path the CLI test asserts.
- `docs/plugin-structure.md` is also edited by #5587 and #5590. Rebase on whichever has landed.

## Build Alignment (Beneficial deviations, /build Common Step 4.5)

- The CLI's `deps` are `{ git, gh, cwd, env, stdout, stderr, pinGhHost, checkAdoptedBranch }`, not `{ git, gh, log, err }`: the CLI entry contract (`.claude/skills/gh-api-module-pattern/cli-wrapper-contract.md`, #5374) names the io keys `stdout`/`stderr`, requires `realDeps`, and requires every child process to get `cwd: deps.cwd()` and `env: deps.env`; `tests/helpers/run-cli.js` injects exactly those keys.
- `--help`/`-h` prints the usage on stdout and exits 0 (the repo-wide CLI convention); it is not a JSON line, so it is the one exit-0 case without one.
- An explicit `--repo` is parsed (`parseRepo`, as `bin/link-records.js` does) and its host pinned through `pinExplicitRepoHost` for the gh calls (`tests/gh-host-seam-conformance.test.js`'s `PIN_WIRED` roster); an unparseable value is not pinned and still reaches the module as given.

## Release Note

Fixed the branch-collision check at the start of a build so it runs as one plain command and is no longer refused and retried in a worktree session.
