# 1228: dispatch: groupByFileOverlap's union-find chains records into a false giant bundle via broad directory-level Key Files tokens

Origin: discovered during headless /claude-tweaks:dispatch next firing on 2026-08-21 (record #703's own dispatch)

Defer-reason: pre-existing-outside-diff

## Current State

`groupByFileOverlap` (plugin/bin/lib/issues/grouping.js) unions candidate records transitively (union-find) on any shared `keyFiles` entry, with no check that the shared token names a specific file. In a headless `/claude-tweaks:dispatch next` firing on 2026-08-21 (record #703's own dispatch), after excluding #257 (already had an open unmerged PR #869 for it — the exact gap #1224 tracks), the next-ranked candidate was a 52-record group. Diagnosis: bare directory-level tokens extracted from issue bodies (e.g. "tests/", "plugin/bin/lib/hooks/", "plugin/skills/specify/", "plugin/skills/test/") act as super-connectors — "tests/" alone appeared in 15 of the 52 records' extracted key files, enough on its own to chain unrelated records into one component. Dispatch's own SKILL.md frames a "bundle" as a small genuinely-overlapping cluster (its own examples show size 2); the design does not anticipate or handle a 50+ record group. Worked around live by filtering out any candidate group with 20+ members before re-ranking (not a code fix, lives nowhere in the repo) — after which the largest group observed was size 2.

## Deliverables

- Harden `extractKeyFiles`/`groupByFileOverlap` in `plugin/bin/lib/issues/grouping.js` so a bare directory-level or otherwise overly generic token cannot act as a transitive-union hub across unrelated records — e.g. only union on a token that resolves to a single concrete file path (reject/ignore directory-shaped tokens, or require an extension), or reject tokens matching a stoplist ("tests/", other bare directory names).
- Add a size guard: cap or flag any resulting group above a sane size (e.g. >5-10) rather than silently allowing dispatch to select and dispatch it as one build/test/review/wrap-up run.
- Add regression coverage in `tests/` reproducing the hairball shape (multiple records sharing only a directory-level key-file token) and asserting they no longer collapse into one group.

## Acceptance Criteria

- `groupByFileOverlap` no longer merges records whose only shared "overlap" is a bare directory-level token.
- A synthetic fixture with N records sharing only a directory-level token produces N (or near-N) singleton/small groups, not one N-member group.
- `/claude-tweaks:dispatch`'s Step 3 selection (or its own tests) demonstrates it will never auto-select a group above the configured size guard without at least surfacing it rather than dispatching silently.
