# 2963: Stop browse's argument-hint leaking YAML backslash escapes into the reference card

Origin: Review Console — run `2026-10-04T135923-record-2772` (PR #2962), ledger row 3

Defer-reason: pre-existing-outside-diff

**Related:** #2964

## Current State

`plugin/skills/browse/SKILL.md`'s `argument-hint` is a double-quoted YAML string containing `set device \"<name>\"`. `docs/skill-authoring.md` says a hint containing a literal `"` is written single-quoted; this one is not.

`plugin/bin/lib/skill-audit/argument-hint.js`'s `extractArgumentHint` strips the surrounding quotes but does not unescape, so it returns the hint with literal backslashes. `plugin/skills/help/reference-card.md`'s `Takes` cell for `/claude-tweaks:browse` therefore carries `set device \"<name>\"`, backslashes included, and `/claude-tweaks:help` renders them to the user.

`tests/argument-hint-mirrors.test.js` passes because both surfaces are byte-identical after extraction — the walker compares mirrors, it does not validate the canonical value.

## Deliverables

- Rewrite `browse`'s `argument-hint` single-quoted with a plain `"<name>"`, per the existing convention, and update the reference card's `Takes` cell to match.

- Add a check that fails when any skill's `argument-hint` is double-quoted and contains a backslash escape, in `tests/argument-hint-input.test.js` or beside it.

## Acceptance Criteria

The reference card's `Takes` cell for `/claude-tweaks:browse` contains no backslash other than the `\|` pipe escapes.

Re-introducing a `\"` escape in any skill's double-quoted `argument-hint` fails the new check.

`npm test` passes.

## Release Note

Fixed stray backslashes in the browse command's argument summary in the help reference card.
