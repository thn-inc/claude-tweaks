# Staged: Close (GitHub) — #1771's worktree-slot-reuse evidence has a benign cause (tracked pipeline headers and merge commits on main)

**Finding:** `[gh-issue]` #1771 (open, `Defer-reason: scope`, follow-up to #1520) infers worktree-slot reuse from two observations inside a dispatch worktree: 100+ `.claude-tweaks/pipelines/*/work/{n}-spec.md` directories for unrelated records, and a `git log` chain of `[resume-merge]` / `Merge origin/main into worktree-…` commits. Both are inherited from `main`, not evidence of reuse: on this checkout `git ls-files .claude-tweaks/pipelines` lists 837 tracked files across 522 run directories (798 of them `work/{n}-spec.md` headers, committed by materialize and archived under `archive/`), and the `[resume-merge]` commits are on `main` itself (`git log main --grep=resume-merge` → 5). A worktree branched from `main` sees all of it on day one. The one file the hypothesis depends on, `run-state.json`, is gitignored and therefore absent in a fresh worktree — a stale same-path binding can only exist when the same physical directory is re-entered, which dispatch's per-record naming (`.claude/worktrees/dispatch-record-{n}`) makes possible only for a re-dispatch of the *same* record whose earlier worktree was never reaped. `classifyOwnership` today fails open to `indeterminate` (never `foreign`) on that shape, and #1520 (closed 2026-09-04) plus commit `f352f8623` already classify same-session sibling worktrees as foreign. The record's own Deliverable 3 asks for exactly this outcome: close as not-a-bug with the explanation.

**Proposed:** Close #1771 as not planned (ruled out), with the finding above as the closing comment. The narrow residual (same-record re-dispatch into an un-reaped worktree carrying an old `run-state.json`) is named in the comment so a maintainer can capture it separately if they consider it worth a status-aware binding check.

**Why staged:** closing a `github-issues` record is an outward-facing write, Stage at every tier; the record's AC also allows "a documented finding" only, so the close is the recorded decision.
