## Current State

`materialize.js`'s worktree write mode and the `pre-tool-use.js` shadow-guard carve-out (#959, commit 73478c8b5) fixed the writer going forward, but 26 root-level `work/{n}-spec.md` files remain committed at the repo root (not under any `.claude-tweaks/pipelines/{run-id}/work/` run dir) as of 2026-08-27 — pre-dating the fix, and at least one (`work/1124-spec.md`, committed 2026-08-27) landed *after* the fix shipped, via a direct commit on the integration branch outside any worktree/materialize.js invocation (root cause not yet diagnosed — likely a hand-authored write bypassing the documented CLI, not a defect in the CLI itself). #1142's own 2026-08-25 "Absorbed" addendum named this sweep as follow-up work once the writer was fixed; #1142 verified the writer fix but did not do the sweep (out of scope for that build — touching 26 files risked colliding with ~69 concurrent sibling records in the same drain).

## Deliverables

- [ ] For each of the 26 (check current count — more may have landed since) root-level `work/{n}-spec.md` files, determine its originating run dir under `.claude-tweaks/pipelines/` (live or `archive/`) and move the file there (`work/{n}-spec.md` if live, `archive/{run-dir}/work/{n}-spec.md` if archived); when no matching run dir can be found (already reaped/archived elsewhere), leave a decision trail for what happened to it rather than silently deleting.
- [ ] Add a pin test (e.g. under `tests/`) asserting the repo-root `work/` directory contains no `{n}-spec.md` files going forward — catches a regression of this same class, whatever its root cause turns out to be.
- [ ] Separately diagnose why `work/1124-spec.md` landed at the repo root on 2026-08-27, *after* #959's fix shipped (2026-08-21) — confirm whether this was a hand-authored bypass of `materialize.js`/the worktree-first flow, or a genuine residual gap the pin test above would also need to guard against structurally (not just via test coverage).

## Acceptance Criteria

1. Repo-root `work/` directory contains zero `{n}-spec.md` files (pinned by the new test).
2. Every one of the swept files' content is preserved somewhere traceable (its run dir's `work/`, or `archive/{run-dir}/work/`) — no silent deletion.
3. The 2026-08-27 `work/1124-spec.md` root-landing is explained; if it points to a code gap (not a one-off hand-authored write), that gap gets its own follow-up.
4. `npm test` passes.
