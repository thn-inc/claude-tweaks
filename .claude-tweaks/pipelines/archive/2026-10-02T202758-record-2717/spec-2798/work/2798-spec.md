# 2798: Verify claude-tweaks setups aren't silently switched off by AGENTS.md

Surface: infra

## Current State

Claude Code reads `AGENTS.md` only when `CLAUDE.md` is missing, so file ordering can silently determine which instructions actually govern a session. Neither `/claude-tweaks:init` nor `/claude-tweaks:harness-health` currently checks for this — a project could have both files present with `AGENTS.md` silently winning (or a stale `AGENTS.md` shadowing an intentionally-maintained `CLAUDE.md`), and nothing in the plugin would surface it. Confirmed: neither `plugin/skills/init/SKILL.md` nor `plugin/skills/harness-health/SKILL.md` currently mentions `AGENTS.md` at all.

## Deliverables

Have `/claude-tweaks:init` and/or `/claude-tweaks:harness-health` detect when both `CLAUDE.md` and `AGENTS.md` are present in a project root and warn — naming which file Claude Code actually reads in that configuration, so a maintainer isn't silently governed by the wrong file.

## Acceptance Criteria

- Running `/claude-tweaks:init` (re-run/drift-detection mode) or `/claude-tweaks:harness-health` against a project with both `CLAUDE.md` and `AGENTS.md` present produces an explicit warning naming the precedence (`AGENTS.md` is ignored while `CLAUDE.md` exists) and pointing at both files.
- A project with only `CLAUDE.md` (the common case) triggers no such warning — the check is presence-of-both-gated, not a general nag.
- The warning text itself states the actual Claude Code precedence rule (CLAUDE.md wins when both exist) so a reader doesn't have to look it up elsewhere.

## Release Note

Added a warning when a project has both CLAUDE.md and AGENTS.md, naming which one Claude Code actually reads.

## Technical Approach

Add a file-presence check (`fs.existsSync` for both `CLAUDE.md` and `AGENTS.md` at the project root) to whichever of `/claude-tweaks:init`'s drift-detection pass or `/claude-tweaks:harness-health`'s workflow is the better fit — `harness-health` is likely the more natural home since it already exists to detect harness/config drift, but confirm against each skill's current scope before choosing. Render the warning inline with that skill's existing finding format, not as a new separate mechanism.

### Key Files

- `plugin/skills/harness-health/SKILL.md` — likely home for the new detection check (confirm against `init/SKILL.md`'s own scope first)
- `plugin/skills/init/SKILL.md` — alternate/complementary home, particularly for the drift-detection re-run path

## Gotchas

- Don't over-warn: a project intentionally maintaining both files for some other tool's benefit (not Claude Code) with `CLAUDE.md` correctly taking precedence is not itself a problem — the warning's job is surfacing the *ambiguity risk*, not asserting both-files-present is always wrong. Keep the tone informational, not an error.
- Confirm the actual current Claude Code precedence rule (CLAUDE.md wins when present, AGENTS.md read only when CLAUDE.md is absent) against current platform behavior before hardcoding it in the warning text — platform behavior can change across Claude Code versions.
