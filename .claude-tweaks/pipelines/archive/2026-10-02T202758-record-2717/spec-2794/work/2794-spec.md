# 2794: Reconcile harness-health with Claude Code's built-in prompt-audit

Surface: infra

## Current State

Claude Code v2.1.283 shipped a built-in `/doctor` prompt-audit that overlaps with `/claude-tweaks:harness-health`'s own drift checks (`plugin/skills/harness-health/SKILL.md`'s Workflow section documents this skill's checks). Whether the overlap is redundant, complementary, or covers genuinely different ground has not been investigated — this record exists to make that determination and act on it, not to assume the answer either way.

## Deliverables

Investigate what Claude Code's built-in `/doctor` prompt-audit actually checks (via its own documentation/help output) and compare it against `harness-health/SKILL.md`'s documented checks. Decide one of two outcomes and implement it:
1. If the built-in audit genuinely subsumes part of harness-health's scope, have harness-health invoke or defer to it for that overlapping portion rather than duplicating the check.
2. If the overlap is only superficial (different depth, different trigger conditions, or different failure modes caught), explicitly document in `harness-health/SKILL.md` why the two checks stay separate, so a future reader doesn't re-raise the same "isn't this redundant now?" question without the answer already being on record.

## Acceptance Criteria

- `harness-health/SKILL.md` (or a linked doc) states explicitly, after this investigation, either how it now calls/defers to the built-in `/doctor` audit for the overlapping portion, or why it deliberately does not.
- The decision is grounded in an actual comparison of what each check covers, not an assumption — cite the specific check(s) on each side that were compared.

## Release Note

Aligned the harness health check with Claude Code's built-in prompt audit so the two no longer overlap.

## Technical Approach

Run or inspect Claude Code's built-in `/doctor` command (via `--help`, its own output, or release notes for v2.1.283) to determine its actual check coverage. Cross-reference against `harness-health/SKILL.md`'s Workflow section (checks currently documented there) to find genuine overlap versus superficial similarity. The decision itself (defer vs. document-separation) follows directly from what that comparison finds — this record's Deliverables intentionally don't presuppose which outcome is correct.

### Key Files

- `plugin/skills/harness-health/SKILL.md` — the Workflow section documenting current checks; the target for either the defer-call or the explicit separation-rationale

## Gotchas

- Don't assume redundancy or non-redundancy without actually running/inspecting the built-in `/doctor` audit first — the capture that filed this record only noted the overlap exists, not which way it resolves.
- If harness-health ends up deferring part of its scope to a built-in Claude Code command, confirm that command is stable/versioned enough to depend on (Claude Code version drift is a real risk for a plugin-level dependency on harness-internal tooling) before wiring it in as a hard dependency.
