# 2675: Scope whether claude-tweaks needs a creative/image-workflow plugin

Surface: infra

## Current State
`claude-tweaks`'s own skill set (`plugin/skills/`) covers the code lifecycle (`capture`/`specify`/`build`/`test`/`review`/`wrap-up` and their supporting skills) plus repo-hygiene and research skills (`code-health`, `docs-health`, `research`, etc.) — none address creative or image-generation workflows. Note: `concierge` (cited in the original request as an existing text-based content-routing precedent) is actually a separate personal skill under the `claude-user-config` plugin, not part of `claude-tweaks` itself — there is no in-repo precedent for a non-code-lifecycle content-routing skill inside `claude-tweaks` proper; `concierge` is evidence a sibling plugin pattern exists, not that `claude-tweaks` already does this.

Generative-image models are shipping rapidly (e.g. the cited ChatGPT Images 2.5 launch), and at least one enrolled project (`memenu-app`) has a real, standing need for image workflows — this is the concrete demand signal motivating the scoping question, not a speculative future need.

No decision has been recorded on whether `claude-tweaks` (or a sibling plugin) should own image/creative-workflow tooling.

## Deliverables
1. Survey enrolled repos (starting with `memenu-app`, plus any others with git history mentioning image generation, creative asset pipelines, or similar) for concrete, standing image-workflow needs — not hypothetical future demand.
2. For each identified need, note what it actually requires: model selection guidance, prompting conventions, workflow integration into an existing lifecycle step, or something else.
3. Compare against `claude-tweaks`'s existing scope (code lifecycle) and `claude-user-config`'s existing scope (personal/cross-project skills like `concierge`) to judge which, if either, is the natural home — or whether this belongs in project-local skills instead.
4. Record a decision: build a dedicated plugin, extend an existing skill/plugin, or defer — with the rationale that drove the choice (demand strength, scope fit, maintenance cost).

## Acceptance Criteria
- At least one enrolled repo beyond `memenu-app` was checked for image-workflow demand signals (even if the finding is "no such need"), so the survey isn't scoped to a single anecdote.
- The recorded decision explicitly picks one of: dedicated plugin, extend an existing skill/plugin (name which one), or defer — no decision that avoids naming one of these three.
- The rationale cites the specific demand evidence found (or its absence) and the scope-fit reasoning (why claude-tweaks vs. claude-user-config vs. project-local, or why none of the above yet).
- The decision is recorded somewhere durable and discoverable (e.g. a comment on this record, a decision note in the relevant plugin's docs, or a follow-up work record if the decision is "build") — not left only in this record's closing comment with no forward pointer.
