# 2985: Re-pin Impeccable to the engine, re-record fixtures, rewrite contract tests, add a retirement sweep

Surface: infra

## Overview

Close the Impeccable engine migration: point the upstream pin, the drift manifest, the recorded fixtures and the contract test at the engine, and add a conformance test that fails if anything reintroduces the retired scripts. This is also the sub-issue that stops `npm test` from depending on which old Impeccable versions happen to sit in a machine's plugin cache. Today the three `tests/impeccable-plugin-contract.test.js` failures that #2840, #2867, #2880 and #2531 each re-diagnosed pass only because an orphaned 4.0.2 cache directory survives on the maintainer machine.

The pin's meaning changes: `impeccable-plugin@…` becomes "last verified version", read only by the drift tooling and the tests, never by runtime gating (runtime gates on output shape, per the engine module). A second pin, `impeccable-engine@…`, records the engine `VERSION` of that same install.

## Technical Approach

The contract test splits into two layers: fixture-driven shape tests that need no install and run everywhere, and live-engine tests gated on `impeccable-engine.js resolve`. Version drift becomes a drift-tool report, not a test failure. The sweep test is a plain `git ls-files` plus whitespace-collapsed substring scan with an exact-path exemption list.
