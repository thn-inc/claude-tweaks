# 3442: friction-events.js reads decisions.md local times as UTC and drops every event east of UTC

Origin: reflect full from #3404

Defer-reason: tangential

## Current State

`plugin/bin/friction-events.js`'s `computeClaimBoundary` (#2989) reads the first `decisions.md` entry's `HH:MM:SS` and builds `new Date(`${mintDay}T${hh}:${mm}:${ss}Z`)` — it interprets the time as UTC.

`plugin/bin/lib/log-decision/append.js`'s `hms()` writes that time with `getHours()/getMinutes()/getSeconds()` — local time. `events.jsonl` timestamps are ISO UTC.

On any machine east of UTC the computed claim boundary lands hours after the run's real events, so `readEvents` drops every event as "pre-claim noise". Observed on #3404's run (UTC+2): `events.jsonl` held 5 `wd-guard-refusal` events, yet `node bin/friction-events.js --run <run-dir>` printed `[]`, so `/reflect`'s Friction lens saw a frictionless run.

## Deliverables

- [ ] Make `computeClaimBoundary` read the `decisions.md` time as local time, matching `hms()`, so the boundary is the same instant the entry was written.

- [ ] Add a regression test that runs the boundary computation under a non-UTC `TZ` (for example `Europe/Copenhagen`) and asserts events after the first claim entry survive while earlier unrelated events are still dropped.

## Acceptance Criteria

- Under `TZ=Europe/Copenhagen`, a run dir whose `decisions.md` first entry reads `20:39:18` and whose `events.jsonl` holds events at `2026-10-17T18:40:00Z` returns those events from `friction-events.js`.

- The existing #2989 tests (pre-claim events still dropped) pass unchanged, and a new test fails with the old `Z` construction (revert to confirm).

## Release Note

Fixes the Friction lens silently reporting a frictionless run for operators east of UTC.
