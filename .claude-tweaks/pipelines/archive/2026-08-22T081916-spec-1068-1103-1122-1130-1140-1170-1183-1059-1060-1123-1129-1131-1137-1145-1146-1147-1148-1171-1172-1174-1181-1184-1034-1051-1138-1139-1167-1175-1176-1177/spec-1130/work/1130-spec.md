# 1130: Pipeline run state polluted by foreign writes + archived before console answered

Surface: backend

## Current State

While resuming record #657's parked pipeline run (`2026-08-20T065316-record-657`) for final
Review Console approval, two related anomalies turned up in that run's own state files:

1. **The run directory was already under `.claude-tweaks/pipelines/archive/`** before its Review
   Console had been resolved and before its PR (#1025) had merged — `cleanup-procedures-execution.md`
   Section B's archival step is documented as the *last* cleanup action, gated on the console
   having been answered and the branch outcome being known. Evidence it moved early: the
   git-tracked `work/657-spec.md` (committed on the feature branch per `materialize.md`'s
   contract — "reaches the main checkout by merge") was still sitting in the **worktree's own**
   `.claude-tweaks/pipelines/2026-08-20T065316-record-657/work/` copy, never `git mv`'d into the
   archive path — exactly what you'd see if a reconcile pass moved the gitignored half
   (`decisions.md`/`run-state.json`/`events.jsonl`/`staged/`) to `archive/` on its own, ahead of
   Section B's full procedure, before the PR that would bring `work/` to the main checkout even
   existed as a merged commit.

2. **`run-state.json` and `events.jsonl` carried what looks like `node --test` fixture data**,
   not this run's own real state:
   - `run-state.json`'s `pr` field read `{"number": 7, "url": "https://github.com/o/r/pull/7"}"`
     — this run's real PR is #1025 on `thomasholknielsen/claude-tweaks`; `o/r` is a classic
     placeholder owner/repo pair, and `run-state.json` also carried `"worktree": null, "status":
     "clean"` at a point in the run's real timeline (07:26 UTC) that predates its actual PR
     handoff (07:36 UTC per `decisions.md`).
   - `events.jsonl` carried four entries at 07:26:25–07:26:27Z that don't belong to this run at
     all: a `wd-foreign-session` event naming `caller: "bystander"`, `owner: "owner"`, and paths
     under `/private/var/…/T/ct-wtd-parent-DvqiNQ/wt` / `/private/var/…/T/ct-disp-o3teYc`; and
     three `gate-denial` events against files at `/private/var/…/T/ct-disp-repo-{8t7nWx,
     MjEJbx,fZKeRs,oZQWDF}/a.txt`. These path shapes (`ct-wtd-parent-*`, `ct-disp-*`, a bare
     `a.txt`) match temp-fixture directories a hooks-dispatcher test suite would create, not
     anything this run's own session did.

Both anomalies land right at a `pre-compact`/`session-end` boundary in this run's own
`events.jsonl` (07:26:21Z), suggesting whatever process runs after a session-end/compaction —
plausibly a reconcile pass or `session-start.js`'s resolver — is capable of (a) sweeping a run to
`archive/` too early, and (b) somehow attributing another process's (very possibly a concurrently
running `npm test` suite's) writes to this run's `run-state.json`/`events.jsonl`. This is the
same class of bug already known for `record-worktree` called without an explicit `--run` (which
has corrupted sibling sessions' `run-state.json` files before), but the exact write path here
does not match that known cause — the polluting content looks like test-suite fixture data, not
another real session's state.

## Deliverables

- [ ] Determine what wrote the `{number: 7, url: .../o/r/pull/7}` PR object and the
      `wd-foreign-session`/`gate-denial` events into this run's `run-state.json`/`events.jsonl` —
      check whether a `node --test` suite (hooks-dispatcher tests are the strongest match for the
      `ct-disp-*`/`ct-wtd-parent-*` path shapes) resolves "current run" to a real run directory
      under some condition instead of a fully isolated temp fixture, or whether a hook resolver
      (`bin/lib/hooks/context.js`'s `resolveRun`) can misattribute a foreign/bystander session's
      writes to an unrelated run when multiple sessions/test runs are concurrently active.
- [ ] Determine why this run's directory was moved to `archive/` before its Review Console was
      answered and before its PR merged — trace which reconcile/archive code path did the partial
      move (gitignored half only, `work/` left behind in the worktree) and fix it to either not
      archive until Section B's real preconditions hold, or to archive atomically.
- [ ] Add regression coverage: a live pipeline run directory must never receive events/state
      writes attributable to an unrelated bystander session or a test fixture, and must never be
      archived ahead of its console being resolved.

## Acceptance Criteria

- A concurrent `npm test` run (or a bystander session) cannot cause writes to appear in an
  unrelated, real pipeline run's `run-state.json`/`events.jsonl`.
- `cleanup-procedures-execution.md` Section B's archival step only fires once its stated
  preconditions hold (console answered, branch outcome known) — a new/updated test demonstrates
  this for the two-call dispatch handoff shape specifically, since that's where this instance
  surfaced.

## Technical Approach

Two independent investigations, both starting from `bin/lib/hooks/context.js`'s `resolveRun` and
the reconcile archival call path (`bin/lib/reconcile/archive-merged.js`): (1) trace whether the
hooks-dispatcher test suite's temp-fixture isolation (`ct-disp-*`/`ct-wtd-parent-*` naming) can
under any condition resolve to a real run directory instead of its own isolated fixture root —
grep the test suite for `resolveRun`/`CLAUDE_CODE_SESSION_ID` handling and compare against how a
live session resolves the same; (2) trace the reconcile pass that performs the gitignored-half
archival move to find where it fires ahead of Section B's stated preconditions (console answered,
branch outcome known) — likely a race between a `pre-compact`/`session-end` hook trigger and the
full cleanup-procedures-execution sequence. Both fixes land as either a stricter isolation
guarantee (test suite) or an explicit precondition check (reconcile archival), not a shared
mechanism — treat them as two deliverables, not one root cause, unless the trace reveals
otherwise.

### Key Files

- `plugin/bin/lib/hooks/context.js` — `resolveRun`, the run-directory resolution logic to audit for cross-session/test-fixture bleed
- `plugin/bin/lib/reconcile/archive-merged.js` — the reconcile archival pass to trace for premature-archive timing
- `plugin/skills/_shared/cleanup-procedures-execution.md` — Section B's stated archival preconditions
- `tests/bin-lib/hooks/` — the hooks-dispatcher test suite whose fixture path shapes (`ct-disp-*`, `ct-wtd-parent-*`) matched the polluting events

## Gotchas

- This resembles the known `record-worktree`-without-`--run` corruption class, but the write path doesn't match — don't assume the existing fix for that class covers this one; verify independently.
- The `pr` field was already repaired in place (`record-pr --run <dir> 1025 https://github.com/thomasholknielsen/claude-tweaks/pull/1025`) so #657's own merge/cleanup could proceed safely — this record is about the unaddressed root cause, not a live-data recovery task.
- Defer-reason: genuinely-larger — tracing the actual write path (likely inside the hooks dispatcher or a test suite's fixture isolation) is a real investigation, out of scope for #657's own diff.
