# 1137: specify: no auto-continue from an approved brainstorming design doc into decomposition

Surface: infra

## Current State

After `/superpowers:brainstorming` completes and its design doc is approved, the lifecycle always stops and waits for a manual `/claude-tweaks:specify` invocation — there is no opt-in way to auto-proceed into decomposition. A user brainstorms a feature through to an approved, committed design doc, then has to come back and type `/claude-tweaks:specify <doc>` themselves before decomposition starts. That pause carries no decision: the design was already approved section by section and the written doc reviewed, so the extra "go ahead" is pure ceremony.

Precedent for auto-chaining already exists inside `/claude-tweaks:specify` itself — Resolve-the-input case 4 (bare topic) invokes `/superpowers:brainstorming` and continues straight into decomposition without stopping, and the `needs:definition` redirect does the same. The missing piece is the symmetric path: when a session starts in `/superpowers:brainstorming` (or `/specify` is expected to follow a design doc), an opt-in — e.g. a policy key or a documented handoff convention — that proceeds from design-doc approval directly into decomposition, still honoring `/specify`'s own downstream gates.

## Deliverables

- An opt-in mechanism (a project policy key, resolved the same way other pipeline policy is resolved per `_shared/pipeline-run-dir.md`/policy conventions, or a documented handoff convention at `/superpowers:brainstorming`'s own completion point) that, when enabled, proceeds from an approved design doc directly into `/claude-tweaks:specify`'s decomposition mode without a manual re-invocation.
- The mechanism must still honor every one of `/specify`'s existing downstream gates (Step 2.5 design pre-steps, the granularity contract, red-team, record creation) — this is auto-*continuation*, not a bypass of any existing check.
- Documentation of the new opt-in at the brainstorming → specify handoff point in `/claude-tweaks:specify`'s own docs.

## Acceptance Criteria

- With the opt-in enabled, a `/superpowers:brainstorming` session that ends with an approved, committed design doc proceeds into `/claude-tweaks:specify` decomposition mode without a separate manual invocation.
- With the opt-in disabled (the default, unless a project has explicitly turned it on), today's behavior is unchanged — the lifecycle stops after brainstorming as it does now.
- Every existing `/specify` decomposition-mode gate (design pre-steps, granularity contract, red-team) still runs on the auto-continued path exactly as it would on a manually-invoked one.

## Technical Approach

Mirror the existing auto-chain precedent: Resolve-the-input case 4 (bare topic → brainstorming → decomposition, no stop) and the `needs:definition` redirect both already invoke `/superpowers:brainstorming` and continue straight into decomposition mode without a manual re-invocation in between. The new piece is the reverse direction — a session that *starts* in `/superpowers:brainstorming` (not via `/specify`'s own bare-topic path) needs a way to signal, at design-doc approval, that decomposition should follow automatically. The cleanest mechanism is likely a policy key (checked the same way other pipeline policy is resolved) that `/superpowers:brainstorming`'s completion step reads before deciding whether to stop or hand off directly into `/claude-tweaks:specify`'s decomposition mode — since `/superpowers:brainstorming` is an unchanged superpowers skill per this project's CLAUDE.md, the handoff point may need to live in a claude-tweaks-side wrapper or convention rather than editing the superpowers skill itself.

### Key Files

- `plugin/skills/specify/SKILL.md` — the Resolve-the-input case-4 and `needs:definition` precedent this mirrors
- Project policy resolution (wherever `resolve-policy.js`-style keys are read) — the new opt-in's home
- CLAUDE.md's superpowers-overrides section — documents that `/superpowers:brainstorming` is otherwise unchanged; the new opt-in must respect that boundary

## Gotchas

- `/superpowers:brainstorming` is explicitly documented as unchanged/upstream in this project's CLAUDE.md ("Superpowers overrides" section) — the opt-in mechanism should live on the claude-tweaks side (a wrapper, a policy check at the handoff point) rather than modifying the superpowers skill itself.
- Don't let "auto-continue" become "auto-skip" — every one of `/specify`'s existing gates must still run; this deliverable adds a lifecycle shortcut, not a lighter-weight decomposition path.
