# 1172: residue branches probe runs ref-mutating git remote prune on report-only and blast-radius runs

Defer-reason: pre-existing-outside-diff
Surface: backend

## Current State

`plugin/bin/lib/residue/probes/branches.js` runs `git remote prune <remote>` unconditionally on every residue invocation — a local-ref-mutating, up-to-15s network call executed even on report-only `residue.js --json` runs and under /wrap-up's `--scope blast-radius`, where every branch finding (all scope 'observed') is guaranteed to be filtered out afterward. Pruned remote-tracking refs have no reflog, so a read-only inspection can destroy the evidence another session is investigating (a just-deleted upstream branch), and every wrap-up pays the network round-trip for findings the scope filter drops.

## Deliverables

- Gate the prune on the probe's results actually being consumed (skip under blast-radius scope, and/or a read-only flag threaded from residue.js), or move the prune to the fix-now application path where the 422-avoidance rationale actually applies.
- Tests covering: no prune call under blast-radius scope / report-only invocation; prune still runs (with the existing 15s bound and degrade tag) where a deletion could be applied.

## Acceptance Criteria

- `residue.js --json` performs zero ref-mutating git calls.
- The existing unpruned-read degrade behavior is preserved on the path that keeps the prune.

## Technical Approach

Thread a read-only/scope signal from `residue.js` down into `branches.js`'s probe function — the cleanest source is the same `--scope` argument `residue.js` already accepts (report-only and `blast-radius` both already distinguish themselves at the CLI layer). Gate the `git remote prune <remote>` call on that signal: skip it entirely for `--scope blast-radius` and any report-only invocation, and only run it on the path where a branch finding could actually be applied as a fix (per the record's alternative: move the prune to the fix-now application path instead of the probe's gather step). Preserve the existing 15s bound and degrade-tag behavior on whichever path keeps the prune.

### Key Files

- `plugin/bin/lib/residue/probes/branches.js` — the unconditional `git remote prune` call
- `plugin/bin/residue.js` — the `--scope`/report-only signal to thread through

## Gotchas

- Pruned remote-tracking refs have no reflog — this isn't just a performance issue, it's a one-way data-loss risk for whatever evidence another concurrent session might be relying on. Treat "skip the prune" as the safe default and "run the prune" as the case that needs explicit justification, not the reverse.
- Preserve the existing unpruned-read degrade behavior exactly on the path that keeps the prune — don't let the gating change also weaken what happens when a prune legitimately can't run (network failure, etc.).
