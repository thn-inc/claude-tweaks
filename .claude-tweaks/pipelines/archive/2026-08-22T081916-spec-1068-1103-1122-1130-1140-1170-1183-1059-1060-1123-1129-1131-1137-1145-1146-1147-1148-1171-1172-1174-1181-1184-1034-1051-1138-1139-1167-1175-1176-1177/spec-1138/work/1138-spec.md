# 1138: Empty-string --run/--run-dir routes a blank path through all six run-dir CLIs

Surface: backend
Defer-reason: genuinely-larger

## Current State

All six run-dir-accepting `plugin/bin` CLIs (`hooks.js` subcommands, `wrap-up-engine.js`, `materialize.js`, `apply-refine-labels.js`, `resolve-profile.js`, `resolve-policy.js`) accept an empty-string `--run`/`--run-dir` value — the shape an unset `$PIPELINE_RUN_DIR` expands to in shell — and route it through their guards as a blank path. For the resolver CLIs (post-#1065) a blank from a linked-worktree cwd resolves to cwd and rejects with a malformed message (`--run  resolves outside the main checkout` — double space, no path); pre-#1065 `resolve-profile.js --run-dir ""` silently appended a relative `frontier-tally.log` into cwd. Found by #1065's whole-branch review (Minor #8).

## Deliverables

- [ ] A `value.trim() === ''` → `"{flag} requires a value"` parse-time rejection in each of the six CLIs' run-dir argument handling, before any guard or I/O
- [ ] One test per CLI pinning the empty-string rejection (message + exit code matching each CLI's documented invocation-failure contract)

## Acceptance Criteria

1. `--run ""` / `--run-dir ""` (and whitespace-only values) exit with each CLI's invocation-failure code and a "requires a value" message naming the flag, in all six CLIs
2. No blank-path value ever reaches a guard, `statSync`, or tally path composition
3. `npm test` passes in full

## Technical Approach

Same one-line pattern applied identically across all six CLIs: at each CLI's `--run`/`--run-dir` argument-parsing point (`resolveRunArg` in `hooks.js`; the equivalent parsing in the other five), add a `value.trim() === ''` check that exits with `"{flag} requires a value"` and each CLI's own documented invocation-failure exit code — before the value reaches any guard (`isAnchoredUnderRoot`, worktree containment checks), `statSync`, or path composition (the pre-#1065 `resolve-profile.js` silent-relative-append case). Each CLI already has its own invocation-failure contract (exit code + message shape) for other malformed-argument cases — match that contract rather than inventing a new one.

### Key Files

- `plugin/bin/hooks.js` — `resolveRunArg`
- `plugin/bin/wrap-up-engine.js`, `plugin/bin/materialize.js`, `plugin/bin/apply-refine-labels.js` — `--run`/`--run-dir` parsing
- `plugin/bin/resolve-profile.js`, `plugin/bin/resolve-policy.js` — `requireValue` / `--run` parsing

## Gotchas

- Match each CLI's own existing invocation-failure exit code and message shape rather than picking one convention and applying it everywhere — the six CLIs may not share an identical contract for other malformed-argument cases, and the AC requires matching "each CLI's documented invocation-failure contract" specifically.
- The double-space malformed message (`--run  resolves outside the main checkout`) is itself evidence the empty value is currently reaching string-interpolation *after* a guard already ran — verify the fix's check point is early enough to prevent that message from ever appearing again, not just add a second check downstream of it.
