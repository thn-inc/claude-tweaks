# 1146: init gitignore migration: offer .claude-tweaks/artifacts/ to already-split projects

Defer-reason: genuinely-larger
Surface: backend

## Current State

`plugin/skills/init/bootstrap/step-04-gitignore-suggestions.md`'s migration table (added by #1077) triggers its artifacts row only on a bare root-level `screenshots/` line. A project that already migrated to the split `.claude-tweaks` entries and has no bare `screenshots/` line falls through to the final "Already has the split entries → No-op" row — so re-running `/claude-tweaks:init` never offers the `.claude-tweaks/artifacts/` line, and QA screenshots/traces land untracked (or get committed) indefinitely. This repo's own `.gitignore` was the live example until #1077's fix wave added the line by hand. Found by #1077's final whole-branch review; run ledger `docs/plans/2026-08-20-qa-artifact-retention-ledger.md` row 2.

## Deliverables

1. A migration-table trigger (either a new row before the no-op row, or an artifacts-line presence check folded into the no-op row's condition) that fires when the split entries are present but no `.claude-tweaks/artifacts/` line exists, offering to add it.
2. The re-run behavior paragraph above the table mentions the artifacts-line check alongside the existing blanket-line and pipelines-subline migration checks.

## Acceptance Criteria

- A gitignore fixture with the full split entries and no artifacts line matches a Migrate row, not the no-op row.
- A gitignore already carrying `.claude-tweaks/artifacts/` still resolves to no-op.
- The table's other rows are unchanged.

## Technical Approach

Prose-only edit to the migration table and its surrounding explanation, following the file's established row format ("Backup `.gitignore` before write" included).

### Key Files

- `plugin/skills/init/bootstrap/step-04-gitignore-suggestions.md` — migration-table trigger + re-run behavior paragraph

## Gotchas

- Keep the per-level `pipelines/` pattern and its migration rows byte-identical — only the artifacts condition is in scope.
