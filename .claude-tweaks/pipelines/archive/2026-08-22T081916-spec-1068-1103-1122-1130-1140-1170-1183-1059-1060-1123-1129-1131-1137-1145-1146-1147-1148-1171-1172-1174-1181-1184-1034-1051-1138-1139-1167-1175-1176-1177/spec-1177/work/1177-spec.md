# 1177: Review-sweep cleanup batch: parseRepo x8, anchoring-guard copy-paste, mint-rollback coupling, artifacts double-walk, IL-40 literals

Surface: backend
Defer-reason: pre-existing-outside-diff
Origin: pre-release whole-branch review (range e90376a4..b517ee68) — confirmed cleanup findings below the review's severity cap, batched as one hygiene record by human decision.

## Current State

Five confirmed cleanup findings, none behavior-breaking on their own, re-verified against the current tree at shaping time:

1. **`parseRepo` duplication** — 6 files each define their own `function parseRepo`, alongside the canonical export in `plugin/bin/lib/repo-resolve.js`: `plugin/bin/release-claim.js`, `plugin/bin/claims.js`, `plugin/bin/file-feedback.js`, `plugin/bin/link-records.js`, `plugin/bin/preflight-records.js`, and `plugin/bin/materialize.js`. (`plugin/bin/fetch-sub-issues.js` and `plugin/bin/resolve-blockers.js` already import the canonical version and only re-export it — those two were fixed after this record was originally filed, so the current duplicate count is 6, not the 8 originally reported.)
2. **Anchoring-guard copy-paste** — `plugin/bin/resolve-profile.js` (~line 103-113) and `plugin/bin/resolve-policy.js` (~line 95-105) each call `wtDetect.checkRunDirAnchoredOrOutside` and then duplicate the same `foreign-checkout`-vs-other-failure branching into `wtDetect.unanchoredRunDirShadowMessage`/`unanchoredRunDirNoRepoMessage` (#1065/#1079) — the shared branching belongs in one helper.
3. **Mint-rollback layout coupling** — `plugin/bin/lib/hooks/post-tool-use.js` (~line 421-423) hardcodes the run-dir's internal layout (`staged/` subdir, `decisions.md` file) inline when rolling back a failed mint, instead of delegating to a run-dir module helper that already owns that layout.
4. **Artifacts probe double-walk** — `plugin/bin/lib/residue/probes/artifacts.js`'s `probeArtifacts` calls `legacyShapeMatches` (walks `base` for the shape check) and separately `newestFileMtimeMs`/`ageBasisMs` (walks the same tree again for the age basis) — two `fs.readdirSync` passes where one loop could compute both.
5. **IL-40 cardinality literals** — at least one wrap-up prose site restates a list's size as a literal count instead of describing it by reference: `plugin/skills/wrap-up/SKILL.md:225` ("Cleanup enumerates 8 items, in canonical order: ..."). The origin review flagged a second site; it was not independently re-confirmed during this shaping pass — locate it at build time via `docs/donts.md`'s cardinality-rule pattern (a numeric literal modifying a list-size noun near an enumerated list).

## Deliverables

- One consolidation pass per item, each with the existing suites kept green.
- Item 1 migrates the 6 files above to import `parseRepo` from `plugin/bin/lib/repo-resolve.js` instead of defining their own copy.
- Item 5 fixes both flagged prose sites (the confirmed one plus the second, located per the note above), replacing the literal count with a by-reference description.

## Acceptance Criteria

- `grep -rn "function parseRepo" plugin/bin | wc -l` returns 1.
- No duplicated anchoring-guard block across `resolve-profile.js`/`resolve-policy.js`.
- Wrap-up prose carries no literal count for either flagged list.

## Technical Approach

1. **`parseRepo`** — delete the local `function parseRepo` in each of the 6 files listed above and replace it with `const { parseRepo } = require('./lib/repo-resolve')` (or the correct relative path per file — `materialize.js` sits directly under `plugin/bin/`, the other five are also direct siblings of `lib/`). Where a file's own `module.exports` re-exports `parseRepo` (the pattern `fetch-sub-issues.js`/`resolve-blockers.js` already use), keep that export line pointing at the imported binding.
2. **Anchoring guard** — extract the `checkRunDirAnchoredOrOutside` call plus the `foreign-checkout`-vs-other `fail(...)` branching shared by `resolve-profile.js`/`resolve-policy.js` into one helper (e.g. in `plugin/bin/lib/`, alongside `repo-resolve.js`), parameterized on the flag name each caller uses in its own message text (`--run-dir` vs. `--run`). Call the helper from both sites.
3. **Mint rollback** — move the `staged`/`decisions.md`/directory-removal sequence out of `post-tool-use.js` and into the run-dir module that already owns that layout (wherever `writeRunState`/`readRunState` live), exposing something like `rollbackMint(path)`. Call that from `post-tool-use.js` instead of hardcoding the paths inline.
4. **Artifacts probe** — merge `legacyShapeMatches`'s walk and the age-basis walk (`newestFileMtimeMs`/`ageBasisMs`) into a single `fs.readdirSync` pass that computes the shape match and tracks the newest mtime in the same loop.
5. **IL-40 literals** — replace `plugin/skills/wrap-up/SKILL.md:225`'s "Cleanup enumerates 8 items" with a by-reference description (e.g. "the cleanup items below, in canonical order"), then locate and fix the second flagged site the same way.
