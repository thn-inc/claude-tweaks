# 1175: findRunsByWorktreePath: excludeDir resolve-vs-realpath mismatch double-emits the primary run's events

Defer-reason: pre-existing-outside-diff
Surface: backend

## Current State

`plugin/bin/lib/hooks/context.js` `findRunsByWorktreePath` (~line 310) compares `excludeDir` with `path.resolve()` on both sides, while the iterated run dirs and the target are realpath-canonicalized. `friction-events.js` passes `path.resolve(opts.run)` (never realpath'd) as excludeDir, so on macOS a `/tmp`-spelled run dir (real path `/private/tmp`) or any symlinked repo parent makes the exclusion never match — the primary run also matches worktreeMatches and every primary event is re-emitted tagged `_source: 'adhoc'`, double-counting evidence in the reflect Friction Lens.

## Deliverables

- Canonicalize `excludeDir` with the same realpath-with-fallback treatment the target gets before comparing.
- A test with a symlinked run-dir spelling proving the primary run is excluded.

## Acceptance Criteria

- A `/tmp`-spelled `--run` on macOS excludes the primary run's events from the ad-hoc scan.

## Technical Approach

Apply the same realpath-with-fallback treatment `findRunsByWorktreePath` already applies to the iterated run dirs and target to `excludeDir` as well, before the comparison — either canonicalize at the `friction-events.js` call site (`path.resolve(opts.run)` → realpath-with-fallback) or inside `findRunsByWorktreePath` itself, matching whichever pattern the existing target/iterated-dir canonicalization already uses.

### Key Files

- `plugin/bin/lib/hooks/context.js` — `findRunsByWorktreePath`, ~line 310
- `plugin/bin/lib/hooks/friction-events.js` — the `path.resolve(opts.run)` call site passing the uncanonicalized `excludeDir`

## Gotchas

- The fix must use the same realpath-with-fallback treatment already applied elsewhere in this function, not a plain `fs.realpathSync` — a bare realpath call would throw on a path that doesn't exist yet, which the existing fallback presumably already guards against.
- The bug is macOS-specific in its most common trigger (`/tmp` → `/private/tmp`) but the underlying comparison mismatch also affects any symlinked repo parent on any platform — write the test to cover the general symlink case, not just the `/tmp` special case.
