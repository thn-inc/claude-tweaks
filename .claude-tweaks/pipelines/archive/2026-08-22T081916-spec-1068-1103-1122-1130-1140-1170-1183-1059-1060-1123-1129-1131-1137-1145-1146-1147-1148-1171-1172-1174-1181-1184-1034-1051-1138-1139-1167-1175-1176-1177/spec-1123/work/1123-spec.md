# 1123: curation-engine.md dispatch prompts should inline staged-patch.md's diff format

Surface: infra

## Current State

`wrap-up/curation-engine.md` section 4's dispatch instructions (both the fan-out and singleton branches) tell the dispatcher to inline "the row's worklist entry, the judge file's full text, the literal payload JSON template, and the `stagePath` self-verification instruction" into each curation-row dispatch prompt — but never mentions `_shared/staged-patch.md`'s own artifact format (the `Target:`/`Invariant:`/`Finding:`/`Staged-at:` preamble followed by a literal `diff --git` block). During record #701's wrap-up, all three curation-row dispatches (Skills, Docs, Journeys) that staged findings produced well-reasoned, correctly-scoped proposals, but two of the three (Docs' two findings) came back as description-only "before/after" text blocks with no `diff --git` section, forcing the console's apply step straight to the slower re-derivation path (`staged-patch.md`'s "Console apply with description fallback" step 2/3) instead of the fast `git apply` path — even though every one of those findings was a trivial single-clause insertion that a real unified diff would have applied cleanly.

## Deliverables

- Add `_shared/staged-patch.md`'s artifact format (the preamble shape + the requirement that a literal `diff --git` block follow it whenever the finding is a concrete file edit) to `curation-engine.md` section 4's dispatch-prompt contract, alongside the existing `stagePath` self-verification instruction — so every dispatched curation-row judge (Skills/Docs/Journeys, and any future row) produces a proper unified diff by default rather than free-text before/after blocks.

## Acceptance Criteria

- `curation-engine.md` section 4 documents the staged-patch preamble+diff format as part of what every dispatch prompt inlines.
- A future run's Docs/Journeys/Skills curation-row dispatch, staging a single-clause additive finding, produces a file that passes `git apply --check` on the fast path rather than falling through to re-derivation.

## Technical Approach

Prose-only edit to `curation-engine.md` section 4's dispatch instructions: add the `_shared/staged-patch.md` artifact format (preamble fields + literal `diff --git` block requirement) as an explicit inlined element, in the same list as the existing "worklist entry / judge file text / payload JSON template / `stagePath` self-verification" elements. No code changes — this is a dispatch-prompt contract gap, not a runtime defect.

### Key Files

- `plugin/skills/wrap-up/curation-engine.md` — section 4, the dispatch-prompt contract to extend
- `plugin/skills/_shared/staged-patch.md` — the artifact format being added by reference

## Gotchas

- Verify the fix actually closes the gap by checking a future wrap-up's staged findings for `diff --git` blocks rather than assuming the documentation change alone suffices — a judge could still produce free text if the inlined instruction isn't clear enough about the block being literal, required output.
