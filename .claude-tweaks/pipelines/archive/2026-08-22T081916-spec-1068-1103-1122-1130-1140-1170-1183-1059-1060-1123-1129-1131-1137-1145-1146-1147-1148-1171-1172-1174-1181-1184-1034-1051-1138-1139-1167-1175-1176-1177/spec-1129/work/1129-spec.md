# 1129: Two-call dispatch handoff never writes config.yml to the run directory

Surface: backend

## Current State

Record #657's own pipeline run (`2026-08-20T065316-record-657`, dispatched as a two-call handoff:
`build,test` then `review,polish,wrap-up`) never wrote `config.yml` to its run directory, despite
`decisions.md` carrying a full Manifesto snapshot ("mode: auto, steps: build,test" plus the
computed-levers log line). `/claude-tweaks:reflect` flagged this as a friction observation
(`staged/reflect-1.md`) during that run's own wrap-up. Confirmed empirically when resuming the
same run for final Review Console approval: the run directory (now at
`.claude-tweaks/pipelines/archive/2026-08-20T065316-record-657/`) contains `decisions.md`,
`run-state.json`, `events.jsonl`, `staged/`, `engine-state.json`, and `console.json` — but no
`config.yml`, at any point in the run's lifecycle.

`flow/steps-and-gates.md`'s "Adopting an inherited run directory" documents a case-2 branch for
exactly this shape (mint-but-empty directory, adopted then "initialized in place... write
`config.yml` and initialize `decisions.md`"), which per the contract should leave `config.yml`
present. Whatever code path this two-call dispatch handoff actually exercises did not do that —
wrap-up's Phase 1 ceremony-profile read had to fall back to `decisions.md`'s prose snapshot
rather than reading the file the contract says should exist.

## Deliverables

- [ ] Trace which code path `/claude-tweaks:dispatch`'s two-call handoff (`build,test` then
      `review,polish,wrap-up`, sharing one `PIPELINE_RUN_DIR`) actually takes through
      `flow/steps-and-gates.md`'s four adoption cases, and confirm whether `config.yml` is
      written on that path at all.
- [ ] If it is not: fix the gap so a two-call dispatch handoff run always ends up with a real
      `config.yml`, matching the documented case-2 contract.
- [ ] Add a regression test (or extend an existing one) covering the two-call handoff's
      `config.yml` presence.

## Acceptance Criteria

- A fresh two-call dispatch handoff run (build,test then review,polish,wrap-up sharing one
  `PIPELINE_RUN_DIR`) leaves `config.yml` present in its run directory at every phase, matching
  `flow/steps-and-gates.md`'s documented case-2 contract.
- A new/updated test fails on the current (pre-fix) behavior and passes after the fix.

## Technical Approach

Start by tracing `/claude-tweaks:dispatch`'s two-call handoff through `flow/steps-and-gates.md`'s
four run-directory adoption cases (mint-fresh, mint-but-empty/case-2, already-initialized,
inherited-with-config) to determine which case actually fires for this handoff shape — the most
likely gap is that the second call (`review,polish,wrap-up`) adopts a directory the first call
already touched, but under a case that assumes `config.yml` already exists when it doesn't (the
first call may itself skip the case-2 write under some condition specific to the dispatch handoff
path vs. a single-call `/flow` run). Once the exact gap is identified, the fix is either making
the first call's adoption path always write `config.yml`, or making the second call's adoption
path detect the missing file and backfill it per case-2.

### Key Files

- `plugin/skills/flow/steps-and-gates.md` — the four run-directory adoption cases, case-2 in particular
- `plugin/skills/dispatch/SKILL.md` — the two-call handoff's own dispatch logic
- `tests/` — new/extended regression coverage for the two-call handoff's `config.yml` presence

## Gotchas

- This run was a *resumed* pipeline run adopting a run directory a prior call had already minted and used for build+test — the gap may be specific to that resumption shape rather than every two-call dispatch handoff; verify against a fresh (non-resumed) two-call handoff too before concluding the fix covers the general case.
- Defer-reason: genuinely-larger — tracing the dispatch two-call handoff's exact code path and fixing/regression-testing it is out of scope for #657's own diff and its resume dispatch.
