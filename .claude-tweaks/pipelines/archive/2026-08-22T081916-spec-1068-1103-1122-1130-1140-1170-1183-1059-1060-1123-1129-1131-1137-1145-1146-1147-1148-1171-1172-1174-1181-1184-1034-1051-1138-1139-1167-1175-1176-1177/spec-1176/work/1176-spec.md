# 1176: merge-size-probe fail() uses write-then-process.exit — diagnostic can truncate on piped stderr

Surface: backend

## Current State

`plugin/bin/merge-size-probe.js`'s `fail()` (~line 26-29) calls `process.stderr.write(...)` immediately followed by `process.exit(1)` in the same function — the write-then-exit truncation pattern: when stderr is a pipe (a pipeline caller capturing output), the process can exit before the piped write flushes, so a failing probe (unresolvable `--head` ref, merge conflict) can exit 1 with empty/truncated stderr, leaving the calling step with a probe failure and no reason. Three other `plugin/bin/*.js` files already use the safer convention — `process.exitCode = 1` set on the way out, with the function returning normally instead of calling `process.exit()` directly: `plugin/bin/verify.js:88`, `plugin/bin/sweep-stray-run-dirs.js:186`, and `plugin/bin/visual-decide.js:12`. Every call site of `merge-size-probe.js`'s `fail()` already does `return fail(...)`, so swapping `fail()`'s own body to set `process.exitCode` and return, rather than calling `process.exit()`, is a drop-in change — `main()`'s existing `return` after each call already stops execution at the right point.

## Deliverables

- In `plugin/bin/merge-size-probe.js`, change `fail()` to set `process.exitCode = 1` and `return` instead of calling `process.exit(1)` after the `process.stderr.write(...)` call, matching the convention in `verify.js`/`sweep-stray-run-dirs.js`/`visual-decide.js`.
- Sweep `plugin/bin/*.js` for other functions that write to `process.stderr`/`process.stdout` and call `process.exit()` in the same function immediately after the write (not every `process.exit(1)` call qualifies — only ones directly preceded by a stream write in the same function, which is the specific truncation-on-pipe risk). Apply the same `process.exitCode` + return fix to each one found.

## Acceptance Criteria

- A failing probe invocation (e.g. `merge-size-probe.js --head nonexistent-ref`) with stderr piped to a consumer (e.g. `... 2>&1 | cat`) delivers the full diagnostic message, not a truncated or empty one.
- `merge-size-probe.js` still exits with status 1 on failure and status 0 on success — only the write-then-exit mechanism changes, not the exit code contract documented in the file's own header comment.
- Every other `plugin/bin/*.js` write-then-exit instance found by the sweep is fixed the same way, or the sweep's findings (including "none found") are stated in the PR/commit description.

## Technical Approach

Change `fail()` in `plugin/bin/merge-size-probe.js`:

```js
function fail(msg) {
  const firstLine = String(msg).split('\n')[0];
  process.stderr.write(`merge-size-probe: ${firstLine}\n`);
  process.exit(1);
}
```

to end with `process.exitCode = 1;` followed by `return;` instead of `process.exit(1)`. No other change is needed in this file: `main()`'s three call sites already read `return fail(...)`, so `fail()` returning `undefined` unwinds `main()` at the same point `process.exit()` used to terminate the process outright.

Then grep `plugin/bin/*.js` for `process.exit(` calls and inspect each one's enclosing function for an immediately-preceding `process.stderr.write`/`process.stdout.write` (or `console.error`/`console.log`, which share the same async-flush-on-pipe risk on some platforms) in the same statement block — not every `process.exit(1)` in `bin/` is this pattern; several already follow `process.exitCode = ...` assignment or exit without a preceding write. Fix each true match the same way.

### Key Files

- `plugin/bin/merge-size-probe.js` — `fail()` swaps `process.exit(1)` for `process.exitCode = 1` + `return`
- `plugin/bin/*.js` — sweep target for the same write-then-exit pattern; exact file list determined by the sweep itself

## Gotchas

- Not every `process.exit(1)` call in `plugin/bin/` is this bug — the sweep must confirm an immediately-preceding stream write in the same function before treating a hit as an instance of this pattern; a `process.exit(1)` with no preceding write, or one already gated behind `process.exitCode`, is not in scope.
- `merge-size-probe.js`'s top-level `main(process.argv)` call has no wrapping try/catch — an uncaught `computeMergeSizeOverflow` error that isn't a `MergeSizeProbeError` already propagates as a thrown exception today; this change doesn't touch that path and shouldn't need to.
