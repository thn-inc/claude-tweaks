Surface: infra

## Current State

`plugin/bin/resolve-blockers.js` — built per its own header to replace hand-rolled `gh api graphql` under the scratch-worktree one-plain-command shell constraint (#538) — is referenced by zero skill files. `plugin/skills/wrap-up/unblocked-records.md` (~line 52) still instructs the hand-rolled `gh api graphql -f query="$(cat /tmp/...)"` pattern, so a worktree-isolated session needing the work-links:native blocked-by check still hits the compound-command refusal the CLI was built to bypass, while the shipped CLI sits unreachable. (Related pre-existing gap noticed in the same review: `teardownTargets` in pre-tool-use.js checks `toks[0] !== 'git'` directly, so `env git worktree remove` bypasses the teardown gate — same family as the #590 lead-normalization work.)

## Deliverables

- Wire `resolve-blockers.js` into the skill prose that needs it (wrap-up/unblocked-records.md at minimum; sweep for other hand-rolled blocked-by GraphQL sites).
- Register the CLI in docs/plugin-structure.md's bin listing if not already there.
- Decide whether the teardownTargets env-prefix gap is fixed here or split out; if split, file it.

## Acceptance Criteria

- No skill instruction text teaches the hand-rolled blocked-by GraphQL pattern where the CLI covers it.
- A worktree-isolated session can complete the blocked-by check with single plain commands.

Replace `wrap-up/unblocked-records.md`'s ~line 52 hand-rolled `gh api graphql -f query="$(cat /tmp/...)"` instruction with an invocation of `resolve-blockers.js`, matching whatever CLI interface the script already exposes (check its own header/usage). Grep `plugin/skills/**/*.md` for the same `gh api graphql` blocked-by pattern to find any other sites needing the same swap. Register the CLI in `docs/plugin-structure.md`'s bin listing per the project's existing convention for shipped `plugin/bin/*.js` CLIs.
