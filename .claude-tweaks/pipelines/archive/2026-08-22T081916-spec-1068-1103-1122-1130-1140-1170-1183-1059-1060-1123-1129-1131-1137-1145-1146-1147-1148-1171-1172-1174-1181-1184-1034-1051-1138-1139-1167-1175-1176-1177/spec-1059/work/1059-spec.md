# 1059: Reconsider tests/** in review-auto-apply-prose-exempt's exempt glob set

Surface: infra

## Current State

#660's final whole-branch review flagged that the `review-auto-apply-prose-exempt` exempt glob set (`skills/**/*.md`, `docs/**/*.md`, `tests/**`) includes `tests/**` — executable code in this repo and in every consumer project — while the record's own evidentiary basis (4 findings, all `skills/**/*.md`) and its own Gotchas caution against generalizing beyond the observed carve-out's exact scope. `tests/**` was nonetheless explicitly enumerated in #660's own Deliverables/AC, so it shipped as specced rather than being narrowed unilaterally by the build.

## Deliverables

- Gather evidence for (or against) auto-applying prose-exempt bumps to `tests/**` fixes specifically — search for prior findings, incidents, or reasoning that justified including executable test code in a glob set originally evidenced only by prose findings.
- Decide whether to narrow the exempt glob set to the two prose-only globs (`skills/**/*.md`, `docs/**/*.md`) or keep `tests/**` with documented justification, and implement whichever the evidence supports.

## Acceptance Criteria

- A recorded decision on `tests/**`'s inclusion in `review-auto-apply-prose-exempt`'s exempt glob set, backed by evidence gathered per the Deliverables above.
- If narrowed: the glob set change lands with `npm test` passing.
- If kept: the justification is documented at the glob set's definition site.

## Technical Approach

Start from #660's own body and its final whole-branch review comment for the original reasoning behind including `tests/**`. Grep the codebase for prior auto-apply incidents involving test-file changes to see whether the carve-out has empirical grounding beyond the prose-only evidentiary basis #660 itself cites. The decision is binary (narrow vs. keep-with-justification) and the implementation for either branch is a small, localized glob-set edit.
