# 1676: Resolve the curation-engine.md dispatch contract vs. project-skill git-mutation conflict

Surface: backend

Origin: ledger resolve gate

Defer-reason: genuinely-larger

## Current State

During record #1276's wrap-up Phase 2 (ROUTE), the Skills-row curation judge followed `.claude/skills/skill-prose-conformance-tests/SKILL.md`'s own "Record the audit" step, which invokes `harness-health.js validate-findings`. That step pushed a commit (`dad090519`) to the remote `health-state` tracking branch — a git mutation. The judge's dispatch prompt, composed per `plugin/skills/wrap-up/curation-engine.md` section 4, explicitly forbids any git mutation ("never run git add, git commit, or any other git mutation"), on the grounds that the controller alone commits, serially, after auditing each finding. The judge grepped the dispatcher for `git`/`spawnSync` beforehand and found nothing — the durable-state write lives on a path that grep missed (inside `harness-health.js`'s own audit-recording mechanism, invoked as a documented step of the project skill it was applying, not as a git command the judge composed itself).

Blast radius was contained: the push landed only on `health-state` (2 files, cursor/run bookkeeping — never the feature branch, never `main`), recorded zero findings, and left the worktree HEAD and working tree exactly as the judge's own edits left them. But the underlying gap is real: `curation-engine.md`'s dispatch contract has no carve-out for a project skill's own legitimate, sanctioned bookkeeping writes to a dedicated tracking branch, so a judge following a project skill's documented procedure can violate the contract without realizing it — the contract and the project skill disagree, and nothing in either file resolves the disagreement.

## Deliverables

- [ ] Decide the resolution direction: either (a) `curation-engine.md`'s dispatch-prompt git-mutation prohibition gets an explicit carve-out for a project skill's own sanctioned bookkeeping branch writes (name the pattern — a push to a branch distinct from the worktree's own feature branch and from the integration branch, or an explicit allowlist), or (b) `.claude/skills/skill-prose-conformance-tests/SKILL.md`'s "Record the audit" step gains a precondition that skips the write when invoked from a context whose contract forbids git mutation (e.g. a documented env var or a passed flag the dispatch prompt sets).
- [ ] Implement the chosen direction.
- [ ] Add a conformance test or explicit inline note documenting the resolved contract, so a future dispatch-contract change doesn't silently reintroduce the conflict.

## Acceptance Criteria

1. A Skills-row (or any other curation-engine.md fan-out/singleton) judge dispatch, run against a project whose applicable skill file includes a git-mutating audit-recording step, either completes the write safely under a stated, narrow exception, or the write is skipped with the skip logged — never an unnoticed, unauthorized push.
2. `npm test` passes.
