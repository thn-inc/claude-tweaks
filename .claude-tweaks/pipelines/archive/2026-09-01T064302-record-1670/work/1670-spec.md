# 1670: Migrate verify/report.js and model-profiles/session-failures.js onto writeFileAtomic

Defer-reason: genuinely-larger

## Current State

`plugin/bin/lib/verify/report.js`'s `writeReportAtomic()` (lines 55-59) hand-rolls a tmp-write-then-rename atomic write with a **non-pid-suffixed** tmp path (`${jsonPath}.tmp`) and no cleanup-on-failure — two concurrent `verify.js` processes writing the same `jsonPath` collide on that shared tmp filename, a real latent bug. `plugin/bin/lib/model-profiles/session-failures.js`'s `recordFailure()` (~lines 116-118) hand-rolls the same pattern with a pid-suffixed tmp path but likewise no cleanup-on-failure. Neither was migrated by #1653 (which extracted `plugin/bin/lib/atomic-write.js`'s `writeFileAtomic(filePath, content, deps)` from four other copies) because #1653's spec, filed from a pre-release review's findings #6-#8, named only those four sites — #1653's own final whole-branch review found these two afterward by grepping the repo for the `renameSync` pattern directly. `writeReportAtomic`'s current signature takes an `fsImpl` object rather than named deps (`tests/bin-lib/verify/report.test.js:79-85` asserts against that shape).

## Deliverables

Migrate both `writeReportAtomic` and `recordFailure` onto `writeFileAtomic`, giving `writeReportAtomic` a pid-suffixed tmp path in the process — a genuine behavior fix (fixes the concurrent-collision bug), not just a refactor, so it needs its own test. Reshape `writeReportAtomic`'s `fsImpl`-object signature to the injectable-deps convention the other four consumers use.

## Acceptance Criteria

Both consumers call `writeFileAtomic` instead of hand-rolling tmp-write-rename. `writeReportAtomic`'s tmp path is pid-suffixed, with a test proving two different-pid writers no longer collide on the tmp filename. Existing test suites for both consumers pass (reshaped for `report.test.js` given its signature change, not just re-run unmodified). No new runtime dependency.
