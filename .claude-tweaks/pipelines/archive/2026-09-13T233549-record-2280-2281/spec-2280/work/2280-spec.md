# 2280: review/step3-routing.md: the auto-mode routing table is keyed to ceiling low; the ceiling=medium rule is one prose line an agent can miss

Surface: infra

## Current State

`plugin/skills/review/step3-routing.md`'s auto-mode routing table (line ~40) is headed
"Default action under `review-auto-apply-ceiling: low`", with the `medium` and `none` ceiling
behavior stated only as plain prose sentences below the table (lines 47-48: "When
`review-auto-apply-ceiling: medium`: auto-apply Low AND Medium; stage High"). Worse,
`skills/review/code-mode-steps.md` Step 6.7 (line ~310) cites the routing rule directly in its
own text as a fixed mapping — "severity-based auto routing when a pipeline run directory exists
(low → AUTO, medium → STAGED, high → STAGED, critical → KEPT-PROMPT)" — with no mention of the
ceiling at all, baking in the `low`-ceiling behavior as if it were universal.

A live run confirmed the failure mode: under a resolved `review-auto-apply-ceiling: medium`,
Step 6.5 produced medium-severity Design Quality findings, and Step 6.7 staged all four of them
(`STAGED … Stage path: staged/review-{n}.patch`) instead of auto-applying them, then
self-corrected four minutes later with a "routing correction" log line. The same agent, in the
same run, had applied medium-severity *code* findings correctly at Step 3 earlier — because
Step 3's own prose names the resolved ceiling explicitly, while Step 6.7's text does not.

## Deliverables

- Make `step3-routing.md`'s table ceiling-keyed — one column per ceiling value (`none` / `low` /
  `medium`) with the action in each cell, replacing the current single `low`-only table plus
  separate prose sentences for `medium`/`none` — so a reader (or an agent following it) sees all
  three ceilings' behavior in one place with no risk of reading only the table header and missing
  the prose below it.
- Fix `code-mode-steps.md` Step 6.7's own citation (line ~310) to name the resolved ceiling
  explicitly, the way Step 3's own prose already does, instead of hardcoding the `low`-ceiling
  mapping (`low → AUTO, medium → STAGED, high → STAGED, critical → KEPT-PROMPT`) as if it applied
  under every ceiling.

## Acceptance Criteria

- `step3-routing.md`'s routing table has a column (or an equivalent unambiguous per-ceiling
  layout) for `none`, `low`, and `medium`, each showing that ceiling's actual per-severity action
  — no ceiling's behavior is stated only as prose below a table headed with a different ceiling.
- `code-mode-steps.md` Step 6.7's routing citation names the resolved ceiling variable (mirroring
  how Step 3's own prose already does) rather than a hardcoded `low`-ceiling mapping.
- Re-reading Step 6.7 in isolation (without also reading `step3-routing.md`'s prose sentences
  below the table) is now sufficient to route a medium-severity finding correctly under a
  `medium` ceiling — the exact gap the live-run repro demonstrated.
- No change to the actual routing *behavior* for any ceiling value — this is a documentation
  clarity fix; the underlying `_shared/auto-mode-contract.md` severity-routing floors are
  unchanged.

## Technical Approach

In `plugin/skills/review/step3-routing.md`, restructure the table at line ~40 (currently 4 rows ×
3 columns: Severity / Default action under `review-auto-apply-ceiling: low` / Log entry) into a
ceiling-keyed form — either add two more Default-action columns (`review-auto-apply-ceiling:
medium`, `review-auto-apply-ceiling: none`) to the same table, or split into three small
ceiling-headed tables in sequence — whichever keeps the file's existing lazy-load size discipline
(`docs/skill-authoring.md`'s byte-ceiling conventions this repo already enforces on skill files).
Fold lines 47-48's current prose content into whichever layout is chosen rather than leaving it
duplicated alongside the new table. Then in `code-mode-steps.md` at line ~310, replace the
hardcoded `(low → AUTO, medium → STAGED, high → STAGED, critical → KEPT-PROMPT)` parenthetical
with language naming the resolved `review-auto-apply-ceiling` variable and pointing at
`step3-routing.md`'s table, mirroring how this same file's Step 3 prose (which does not exhibit
this bug) already names the ceiling.
