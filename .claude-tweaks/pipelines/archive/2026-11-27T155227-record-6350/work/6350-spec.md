# 6350: Ask only design-level, hard-to-undo and contradiction questions at plan review here (`planning-decisions: asked-classes`)

Surface: backend
Risk-flags: none

## Overview

On 2026-11-26, 12 of 15 dispatched builds in this repository stopped at plan review to ask the maintainer a question. v6 already has a setting, built as Phase 12 of the pipeline-economy design (#6051) and never switched on here, that limits which questions are asked. This record switches it on. It is the first thing built from the factory v7 design, agreed by the maintainer on 2026-11-27.

## Non-Goals

- `plan-at-specify`. It is scored on past records first, in a separate record.
- Any change under `plugin/`. The setting exists; nothing is built.
- The same line in other repositories. Each repository's own record covers it.

## Prerequisites

- Decided by the maintainer on 2026-11-27, after filing: this work is dispatched now, in parallel with its siblings, and its pull request merges by itself once every gate is green. An earlier line here said it was built by hand and was not for `auto:build`; that no longer holds.
- `.claude-tweaks/policy.yml` is a guarded file: the maintainer grants the change. Agreed on 2026-11-27.

## Current State

- `planning-decisions` resolves to `ask-all`, the default: plan review asks about every gap it cannot settle from the record.
- With `asked-classes` (`plugin/skills/_shared/planning-decisions.md`, `plugin/skills/build/plan-review-asked-classes.md`), plan review asks only three kinds of question: design-level, hard to undo (a flagged risk category), or a contradiction. Every other question is settled by a written rule and listed, and the acceptance packet shows each such call.

## Deliverables

- [ ] `.claude-tweaks/policy.yml` sets `planning-decisions: asked-classes`.
- [ ] Two weeks after the merge, a comment on this record's parent gives the share of builds that stopped at plan review in those two weeks, against 12 of 15.

## Acceptance Criteria

- [ ] On the integration branch, `node plugin/bin/resolve-policy.js --values planning-decisions` prints `asked-classes`, with no warning on stderr.
- [ ] The first dispatched build after the merge that reaches plan review with a gap outside the three classes records a settled planning call and does not stop. Verify: that run's `decisions.md`, quoted in a comment on this record.
- [ ] The two-week count is posted on the parent.

## Release Note

No user-visible change.

## Technical Approach

One line in the settings file. It is undone by removing the line. Read `plugin/skills/_shared/planning-decisions.md` once before the change to confirm the value's spelling and that nothing else must be set with it.

### Key Files

- `.claude-tweaks/policy.yml`
- `plugin/skills/_shared/planning-decisions.md` (read only)
- `plugin/skills/build/plan-review-asked-classes.md` (read only)

## Gotchas

- The installed plugin reads this repository's committed settings with its own code, so the change takes effect at merge, for every session whose installed release carries #6051. Name that release in the pull request.
- A run already past plan review when the line merges is not affected.
- The 12 of 15 figure is one day of dispatched builds and the stops were not classified by question class beforehand, so the two-week count is a before/after comparison, not proof that the setting caused the drop. Count "stopped at plan review" as a build whose `decisions.md` records a plan-review stop awaiting the maintainer, and say that source in the comment.
- If no dispatched build reaches plan review with a gap outside the three classes within the two weeks, say so in the second acceptance comment instead of waiting; the setting stays on.
- Releases that do not carry #6051 ignore the key or warn; name the first release that carries it (the tag containing the #6051 merge) in the pull request and note in it whether an older release warns on the unknown value.
