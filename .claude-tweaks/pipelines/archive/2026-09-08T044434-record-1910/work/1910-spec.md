# 1910: Fast-lane bundling: dispatch packs up to three non-overlapping fast-lane records into one multi-spec run to share preflight and wrap-up

Origin: brainstorm on #1904 (docs/superpowers/specs/2026-09-05-pipeline-ceremony-cost-design.md, "Filed separately")
Defer-reason: tangential

## Current State

Every dispatched group pays a fixed tail regardless of diff size: the second call's preflight (run-dir adoption, freshness probe, Manifesto render, change analysis) and wrap-up plus reflect — measured at ~24 min and ~27 min respectively on record #1535, a `size:low` single-module fix on this repo. `dispatch/queue-pull-script.md` groups records only by file overlap (union-find over `### Key Files`), so three unrelated `ceremony:fast-lane` records become three groups and pay that tail three times. `/flow`'s multi-spec mode already runs several specs in one run with one parent run dir, one wrap-up (batch-scope curation via `flow/multispec-batch-curation.md`), and per-spec test gates; `[IL-109]` records the risk of long multi-record runs — a record's stated facts expire while it waits its turn — which bounds how large such a bundle may be.

## Deliverables

- [ ] A bundling rule in `dispatch/next-ranking.md` / `queue-pull-script.md`: after file-overlap grouping, merge up to three singleton groups whose every member carries `ceremony:fast-lane`, disjoint Key Files, and the same `auto:merge` state into one multi-spec group, oldest-first; never merge a group that already has two or more members, and never merge across `priority:*` bands.
- [ ] A `dispatch-fastlane-bundle-cap` policy key (default `3`, `0` disables) following `_shared/policy-key-naming.md`, with its `_shared/policy-schema.md` row.
- [ ] The bundle dispatches through the existing multi-record `/flow "#a,#b,#c" build,test` form; the multi-spec pre-flight verify sweep and per-spec freshness re-check (`[IL-109]`'s mitigation, `flow/multispec-freshness.md`) apply unchanged.
- [ ] The dispatch Reporting section names the bundle and its members.

## Acceptance Criteria

- [ ] Three eligible fast-lane singletons dispatch as one group; a `standard` record or an overlapping Key File keeps them separate (unit test on the grouping function with the orthogonal-category case present).
- [ ] A bundle's wall-clock, from Phase 6 telemetry (`timing.json`), is below the sum of three singleton runs by at least one preflight plus one wrap-up tail.
- [ ] `dispatch-fastlane-bundle-cap: 0` reproduces today's grouping byte-for-byte.
