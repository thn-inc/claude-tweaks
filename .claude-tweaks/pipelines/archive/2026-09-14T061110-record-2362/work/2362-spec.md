# 2362: EnterWorktree bypasses record-worktree, breaking teardown-run/archive-run's worktree lookup

Origin: /claude-tweaks:feedback session-evaluation (self-assessment, degraded from a failed Frontier judge dispatch), self-referential run (this repo's own origin is thomasholknielsen/claude-tweaks) — routed to a normal backlog record per Step 3 rather than filed as upstream feedback.

## Current State

Worktrees created via the harness-native `EnterWorktree` tool (rather than `plugin/skills/dispatch/`'s own `record-worktree` CLI) never get their worktree/branch association written into that run's `run-state.json`. Downstream, `teardown-run`/`archive-run` (`plugin/bin/hooks.js`) can't find the association and report "no worktree recorded" instead of tearing the worktree down automatically. In one session this recurred across 7 separate worktrees, each requiring a manual `git merge-base --is-ancestor` proof + `git worktree remove --force` + `git branch -D` + `gh api -X DELETE .../refs/heads/{branch}` sequence in place of one CLI call — roughly 14 extra manual commands that a working association would have made unnecessary. A related recovery-quality symptom from the same gap: a prior session's main checkout was found 256 commits behind `origin/main` while still holding uncommitted archival bookkeeping from an earlier `/tidy` run — state left behind with no automatic reconciliation path, blocking a later session's own `archive-run` calls until manually resolved via a scratch-worktree PR.

Related, narrower observation from the same evaluation: the ledger's canonical Create location (`docs/plans/YYYY-MM-DD-{feature}-ledger.md`, per `_shared/ledger-format.md`) requires a worktree write under `worktree-always`, but `residue-sweep.md` explicitly expects a standalone (no-worktree) wrap-up run to be able to create one "so the ledger's own resolve gate has something to enforce on a standalone run." In practice a standalone run has no lightweight path to satisfy this — creating a ledger file for a single non-blocking item means a full worktree-commit-push-PR-merge cycle for a file that gets deleted moments later once resolved.

## Deliverables

1. Either make `EnterWorktree` call `record-worktree` itself when the harness detects a claude-tweaks-managed repo, or make `teardown-run`/`archive-run` fall back to `git worktree list`/branch-name matching when `run-state.json` carries no worktree field.
2. Let a standalone, no-worktree wrap-up log ledger items to a location that doesn't require a worktree write — e.g. `.claude-tweaks/pipelines/{run-id}/` (already commit-exempt under `worktree-always` and already the run's own audit-trail home) instead of `docs/plans/`.

## Acceptance Criteria

- A worktree entered via `EnterWorktree` during a dispatch/wrap-up run is torn down by `teardown-run`/`archive-run` without a "no worktree recorded" failure and without any manual `git worktree remove`/`git branch -D`/`gh api DELETE` fallback.
- A standalone wrap-up run with at least one ledger item can create, resolve, and delete its ledger without needing a worktree, a commit, or a PR.
