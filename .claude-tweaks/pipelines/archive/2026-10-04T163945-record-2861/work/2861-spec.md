# 2861: flow-preflight misclassifies a claim-log-only decisions.md as an adopted run (case 3)

Origin: reflect full (multi-spec batch) from #2633/#2664

Defer-reason: tangential

## Current State

At the start of run 2026-09-30T190052-spec-2633-2664, `flow-preflight` classified the freshly minted run dir as adoption **case 3** (an adopted, already-running run), not case 2 (a fresh mint).

The cause was the issue-claim step, which had already appended its claim-log lines to `decisions.md`. The preflight treated a non-empty `decisions.md` as evidence of a prior run. The executor ruled case 2 by hand and logged the ruling.

A case-3 misclassification would have triggered the case-3 adoption-recovery backfill (`flow/steps-and-gates.md`) on a run that had nothing to recover.

## Deliverables

1. The preflight's case classification ignores `decisions.md` entries written by the claim step, recognized by their claim-log section or line shape, when deciding fresh vs adopted.
2. Add a regression test with a run dir whose `decisions.md` holds only claim-log lines.

## Acceptance Criteria

- A run dir with only claim-log lines in `decisions.md` classifies as case 2.
- A run dir with any non-claim decision entry still classifies as it does today.

## Release Note

Freshly started /flow runs are no longer mistaken for resumed ones after claiming their records.
