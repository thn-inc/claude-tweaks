# 1387: overview's machineGrantOutlook and grant-mode's candidate filter disagree on refusal counts

**Related:** #1384

## Current State

overview-mode.md's bare-mode funnel computes the specified bucket's machine-grant outlook via machineGrantOutlook, which runs evaluateGrantGate's gates 1-3 on every specified (ready, ungranted) record with no pre-filter — including human-filed records (facets.origin === null). Since gate 2 (trust) is evaluated before gate 3 (origin), a human-filed record whose class trust also fails lands in the same refused.trust bucket as an agent-filed record that could theoretically be granted once trust clears. skills/backlog/grant-mode.md's own Step 1 candidate fetch, by contrast, pre-filters out human-filed records before running the gate chain at all (a documented "cheap pre-pass on the same gate-3 condition"). The result: overview reports "N refused — trust: N" while grant-mode's own eligible candidate count for the identical backlog state is smaller (in a live run on 2026-08-24: overview reported 38 refused-on-trust, while grant mode's own eligible set was 11 — the other 27 were human-filed records that would separately fail gate 3, but never individually get attributed to it because gate 2 short-circuits first). This forced the user to ask "what actually happened" and required a multi-step reverse-engineering pass to reconcile the two numbers.

## Deliverables

- Either have overview's machineGrantOutlook apply the same origin pre-filter grant-mode's Step 1 already applies (so refused counts decompose consistently across both surfaces), or annotate the specified funnel line's refusal breakdown to separately call out how many of the refused records are structurally ineligible (human-filed) versus trust-blocked, so a reader does not have to reverse-engineer the two code paths to understand the discrepancy.

## Acceptance Criteria

- For the same backlog state, overview's reported refusal counts and /claude-tweaks:backlog grant's own candidate-set size are either equal, or overview's report explicitly states how many of its refused records are excluded from grant-mode's candidate set and why.
