# 3493: plan-audit Check A accepts a regular file as a Create/Test bullet's parent directory

Origin: build of #3417 (shared path-guard helper), conformance-lint audit and review

Defer-reason: pre-existing-outside-diff

## Current State

Check A in `plugin/bin/lib/plan-audit/checks.js` treats `fs.existsSync` as proof that a Create/Test bullet's parent is a directory. Three sites do this: the nearest-existing-ancestor loop (line 46), and `existsSync(parentAbs)` / `existsSync(grandparentAbs)` (lines 62 and 74). A plan that creates a file under a path that is currently a regular file therefore passes the audit and fails only at write time. `tests/path-guard-conformance.test.js` (#3417) allowlists this file with an `UNSAFE —` reason. #3417 forbade fixing call sites, so the gap stayed open.

## Deliverables

- Route the three parent checks through `plugin/bin/lib/path-guard`'s `lstatType()`, requiring `type === 'directory'` for a parent.

- Add a Check A regression test where the bullet's parent path is a regular file, shown red against the current code.

- Update the `lib/plan-audit/checks.js` entry in `tests/path-guard-conformance.test.js`: drop the `UNSAFE —` prefix and adjust the token count.

## Acceptance Criteria

- [ ] A plan whose Create bullet names a file under a path that is a regular file is reported in `checkA.missing`.

- [ ] The `lib/plan-audit/checks.js` allowlist entry no longer carries `UNSAFE —`, and `npm test` passes.

## Release Note

plan-audit no longer accepts a regular file as the parent directory of a planned new file.
