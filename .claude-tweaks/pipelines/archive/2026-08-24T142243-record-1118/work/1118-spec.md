# residue.js --scope blast-radius doesn't filter branch/pipeline-run findings by run identity

## Current State

`plugin/skills/wrap-up/residue-sweep.md` documents `--scope blast-radius` as narrowing
`bin/residue.js`'s findings to "this run's own blast radius (a branch this run's worktree left
behind, a PR from this run's own head branch, a missing release-triple entry)" — explicitly
contrasted with `--scope repo`, which keeps "another session's live worktree" and is called out as
noise this preamble must avoid.

`plugin/bin/lib/residue/probes/branches.js`'s `probeBranches()` does not implement that filter: it
lists every remote branch merged into the integration branch (excluding only this run's own
`scope.headBranch`) and tags each `scope: 'blast-radius'` unconditionally (line 46). The
pipeline-run probe behaves the same way for un-archived `run-state.json: status: clean` directories
— it doesn't check whether the run belongs to the invoking session.

Observed live during record #706's wrap-up in a 30+-concurrent-session repo: a `--scope
blast-radius --integration-branch origin/main` invocation for record #706's own run returned 8
findings that are not #706's own blast radius at all — merged-not-deleted branches
`origin/worktree-record-736`, `origin/worktree-record-768`, and 6 un-archived `.claude-tweaks/pipelines/`
run directories for records 538, 663, 671, 768, 667, 736 (none is #706). `bin/lib/residue/scope-filter.js`'s
own comment confirms the intended contract: `blast-radius` narrows to findings whose own `scope`
field is `'blast-radius'`, "dropping `observed` findings (a sibling worktree, another run's PR)" —
but nothing upstream of the filter ever tags a sibling-session finding as `observed` instead of
`blast-radius`, so the filter has nothing to drop.

## Deliverables

- `probeBranches()` (and the equivalent pipeline-run probe) tag a finding `scope: 'observed'`
  rather than `'blast-radius'` when the branch/run-dir cannot be attributed to the invoking run's
  own worktree/session — e.g. a branch name that doesn't match this run's own worktree naming
  convention, or a pipeline-run directory whose `spec:`/`created:` fields don't match this run's
  own identity.
- `--scope blast-radius` then genuinely returns only this run's own leftovers, matching what
  `residue-sweep.md` already documents as the contract.

## Acceptance Criteria

- Running `bin/residue.js --scope blast-radius` from one run's worktree, with at least one other
  concurrent session's merged-but-undeleted branch or clean-but-unarchived pipeline-run directory
  present, does not include that other session's finding in the output.
- `--scope repo` is unaffected — it continues to surface every finding regardless of attribution,
  as `/claude-tweaks:tidy`'s repo-wide sweep requires.
- Existing `tests/bin-lib/residue/*.test.js` continue to pass; a new test pins the attribution
  filter using two fixture branches / run-dirs, one attributable to the invoking run and one not.
