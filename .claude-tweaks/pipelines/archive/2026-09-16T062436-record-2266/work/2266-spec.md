# 2266: Migrate status-line instruction: design-wrapper + dispatch + specify family

Surface: backend

## Overview

Part of the 5-unit status-line migration decomposition (parent #2264, keystone #2265). Once #2265
lands the new canonical trailing-`STATUS:`-line convention in
`plugin/skills/_shared/subagent-output-contract.md`, every dispatch site that carries its own
inline copy of the old first-line-position instruction must be updated to match. This unit covers
the design-wrapper, dispatch, and specify skill families — 5 files, 6 instances of the old
instruction text.

**Complexity:** Low
**Estimated tasks:** 3

## Non-Goals

- Editing the canonical contract file itself, or `subagent-stop.js`'s detection logic — that is
  #2265, which this unit is `Blocked by`.
- Editing any file outside the design-wrapper/dispatch/specify families listed below — those are
  WU3 (review family), WU4 (research + misc batch A), or WU5 (misc batch B) in this same
  decomposition.
- Changing the four status words themselves or the Template A/B/C content that follows the status
  line — this unit only relocates the instruction's stated position, from first line to trailing
  line.

## Current State

Each file below currently instructs its dispatched agent to put the status word as the literal
first line of its reply, "nothing before it, not even a lead-in sentence" (or an equivalent
position-asserting phrasing):

- `plugin/skills/design-wrapper/modes/explore.md` (~99): `Status line (required): first line of
  your reply is one of DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED.`
- `plugin/skills/design-wrapper/modes/review.md` (~222): `Status line (required): First line of
  your reply must be one of: DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED.`
- `plugin/skills/dispatch/task-prompt.md` (~110 and ~199, two separate instances): `Status line
  (required): First line of your reply must be one of: DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT /
  BLOCKED.`
- `plugin/skills/specify/mechanical-handoff.md` (~62-63): `Status line (required): First line of
  your reply must be one of: DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED.` — one
  instruction spanning two lines (a single instance, not two separate ones — unlike
  `task-prompt.md` below, which genuinely has two). Note: this is the very file defining the
  dispatch-prompt template used to launch mechanical-range subagent runs (the same template family
  this task's own dispatch was launched under).
- `plugin/skills/specify/red-team.md` (~30): `> Status line (required): First line of your reply
  must be one of: DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED.` (inside a Form B
  blockquote).

## Acceptance Criteria

1. All 6 instances across the 5 files above read the new trailing-`STATUS:`-line instruction; none
   still asserts "first line" as the required position.
2. `grep -rln "Status line (required): first line\|Status line (required): First line" plugin/skills/design-wrapper/modes/explore.md
   plugin/skills/design-wrapper/modes/review.md plugin/skills/dispatch/task-prompt.md
   plugin/skills/specify/mechanical-handoff.md plugin/skills/specify/red-team.md` returns no
   match — anchored to the literal retired instruction phrase, not the bare substring "first
   line," so the check cannot pass on an ambiguous partial match against unrelated prose.
3. A positive check confirms the new text actually landed correctly, not merely that the old text
   is gone: `grep -c "STATUS: DONE" plugin/skills/design-wrapper/modes/explore.md
   plugin/skills/design-wrapper/modes/review.md plugin/skills/dispatch/task-prompt.md
   plugin/skills/specify/mechanical-handoff.md plugin/skills/specify/red-team.md` returns at least
   1 for each file (2 for `task-prompt.md`, which has two instances).
4. `npm test` passes with no regressions.

## Technical Approach

Mechanical text replacement only — no logic change. Each file's existing instruction is replaced
with the canonical trailing-line phrasing #2265 establishes in
`plugin/skills/_shared/subagent-output-contract.md`: the reply's last non-empty line must read
exactly `STATUS: {WORD}`. Preserve each file's own surrounding formatting (blockquote prefixes,
list indentation, code-fence context) — only the instruction's asserted position and wording
change, not its placement within the file or the file's other structure.

## Gotchas

- `mechanical-handoff.md` defines the dispatch-prompt template used to hand off decomposition-mode
  Steps 3-9 to a subagent (exactly the template family this migration's own originating dispatch
  used) — get its wording exactly right, since a malformed instruction there self-propagates into
  every future mechanical-handoff dispatch.
- `task-prompt.md` has two separate instances at different line numbers — both must be found and
  edited; a grep for the exact old phrase before editing (not just a line-number lookup) confirms
  neither was missed if line numbers have drifted since this record was written.
- `red-team.md`'s instance is inside a `>` Form B blockquote — the replacement text must stay
  inside the blockquote (each line still prefixed with `>`), not be pasted below it.
- This unit is `Blocked by` #2265 — do not start until the canonical contract text in
  `subagent-output-contract.md` has actually landed, since the replacement wording here must match
  it verbatim, not a guess at what it will say. The exact replacement strings quoted in
  Deliverables above reflect the wording decided at this spec's authoring time — re-read #2265's
  actual landed text in `subagent-output-contract.md` before applying any edit here and use that
  literal wording if it differs in any way from what's quoted above; #2265 is the source of truth,
  this record's quoted text is a best-effort snapshot of it.
- `mechanical-handoff.md`'s dispatch-prompt template self-propagates into every future
  mechanical-handoff dispatch (see Key Files note above) — a wrong edit here is discovered only
  when a later dispatch under this template misbehaves, not at review time. No standalone smoke
  test is required for this unit (that would duplicate #2265's own hook-detection test coverage),
  but the AC3 positive-content grep above catches a malformed or missing replacement before it
  ships.
