# 5557: Turn the review replay scratch scripts into one tested tool

Surface: infra

**Related:** #5540, #5541, #5122, #5214
Risk-flags: none

## Current State

The review and tiebreak numbers behind `docs/superpowers/specs/2026-11-15-process-efficiency-design.md` came from scratch scripts, now in `tools/replay-scratch/` on branch `worktree-design-process-efficiency`: `baseline.js`, `counterfactual.js`, `prep-tiebreak.js`, `tiebreak-replay.workflow.js` and `score-tiebreak.js` (331 lines together), plus `review-yield.js`, which the step yield record replaces. They have no tests and assume one machine's layout.

Two open records need the tiebreak replay as their proof: #5540 (at least 20 archived reviews, at least 100 findings per arm) and #5541 (at least 60 `low` and 30 `info` findings per arm, agreement per verdict class).

Known limits of the scratch version:

- A finding is matched to its archived verdict by lens, path and line.
- `prep-tiebreak.js` leaves `.claude-tweaks/` out of the extracted tree, so a claim about a spec file cannot be judged.
- The judge prompt is written inside the workflow script. It is a copy of Step 3.7's rules, not read from `plugin/skills/review/step3-tiebreak.md`.
- The arms (one judge per chunk, one judge per finding) and the judge's model are fixed in the script.

The judges run as agents of a Workflow script, started from a Claude Code session. That is kept: an agent started that way costs what a review's own tiebreak agent costs, so the replay's token totals can be compared with the archive's. `tools/driver-merge-check-eval.js` is the nearest existing tool: it builds fixtures from archived run directories, replays them, and never counts a failed launch as a judged result.

Design: Phase 5, unit 5.3.

## Deliverables

1. **`tools/review-replay.js`** with these subcommands, each replacing a scratch script:
   - `baseline`: per archived run, the review's recorded verdicts, lens and tiebreak agent cost, and the commit the review examined.
   - `counterfactual`: from each lens reviewer's own findings table in its transcript, what one reviewer alone would have raised, against the confirmed set.
   - `extract`: for a chosen set of runs, writes the reviewed tree, one prompt file per judge call per arm, an arm manifest, and, in a separate file the judges are never given, the archived verdicts. Options select runs by count and by severity quota; the quota counts each finding's severity in the run's `review-findings.json`. `extract` reports the totals left after exclusions against the requested count and quotas, and exits non-zero when it cannot meet them (exit codes follow `tools/driver-merge-check-eval.js`).
   - `score`: reads the workflow run's results, settles each reply, and compares each arm's verdicts with the archived ones and with a named reference arm, in total, per archived verdict class and per severity. It totals agents and tokens per arm.
2. **Arms are data.** An arm names its chunk size (1 is one judge per finding), its model profile and its repeat count. On the command line an arm is `--arm name=<id>,chunk=<n>,profile=<profile>,repeat=<n>`; the manifest records each arm's fields, and a repeat's replies are keyed by arm, repeat number and prompt file name. #5540's and #5541's arms are expressed with options, not a code change.
3. **The production prompt and settle.** `extract` builds each prompt from `plugin/skills/review/step3-tiebreak.md` as that file is at run time. `score` settles replies with `plugin/bin/lib/tiebreak.js`. The replay exercises what a review runs. "As that file is at run time" means the file in the checkout the tool runs in; `extract` finds the template fence by its heading and fails loudly when it is not found. Each placeholder is filled from the archived run: `Location`, the claim and any positions from `review-findings.json`; `Diff scope` from the commit the review examined (Deliverable 6) and the base the run recorded (a run with none is excluded with a reason); the two bracketed discipline lines from the review-dispatch bundle's own text; the `SCRATCH` and `[Use: ...]` lines are dropped, the model coming from the arm. Repo-relative paths in a prompt are rewritten to absolute paths under the extracted tree, so a judge reads the reviewed tree.
4. **A thin workflow script**, `tools/review-replay/replay.workflow.js`. It takes the arm manifest as `args`, starts one agent per prompt file with the arm's model (taken from the manifest in `args`), and returns each reply with its prompt file's name. It holds no prompt text and no rules.
5. **Failed judges are not results.** A judge that returns nothing, or a reply with no valid verdict for a finding, is counted under `notJudged` for that finding and arm, never toward agreement.
6. **The reviewed tree.** `extract` records the commit each review examined and writes the tree at that commit, including the run's spec file where the archive has it. A run whose commit is not in the local clone is excluded with a reason.
7. **Stable finding identity.** A fixture finding carries the id from the run's `review-findings.json`. A run without that file is matched by lens, path and line, and the output counts how many findings used the fallback. The output also counts archived verdicts with no matching finding id and findings with no archived verdict.
8. **Tests** in `tests/review-replay/`, sized like `tests/guard-refusals/` and `tests/efficiency-report.test.js`, with fixtures under `tests/fixtures/review-replay/`.
9. **Cleanup and docs.** `tools/replay-scratch/` is deleted except `review-yield.js`, which #5556 deletes; whichever of the two records lands last removes the then-empty directory. `docs/plugin-structure.md` gains the tool's line and commands. #5540 and #5541 each get a comment naming the commands for their arms.

## Technical Approach

Follow `tools/driver-merge-check-eval.js` for the seam (`run({ argv, deps })` with injected `git`, `fs` and writers), the exit codes and the fixture discipline.

A workflow script cannot read files or require a module, so everything a judge needs is in its prompt file, and the script only hands each file to an agent. `score` reads the run's results from the workflow's transcript directory, as `score-tiebreak.js` does today; take the directory as an argument.

Chunk order follows the order of the run's `review-findings.json`. Do not group by lens or by file.

Agreement is the judge's verdict equal to the archived verdict, in total, per archived verdict class and per severity (the finding's severity in `review-findings.json`). Read `tools/replay-scratch/score-tiebreak.js` first and match its rule; the PR says where the new rule differs. The reference arm is named by `--reference`, default the first arm in the manifest. `baseline` reads agent cost from the source `baseline.js` reads today, and the PR names the field.

Until #5540 lands, the chunk handling lives in one adapter function marked `remove when #5540 has landed and tiebreak.js exports a chunk splitter`. Its prompt headers each finding with its id and the reply repeats the id as a line-anchored header, the form #5540 specifies. A test fails once `tiebreak.js` exports a chunk splitter, so the adapter cannot outlive its removal condition.

Modules go under `tools/review-replay/`; the CLI is `tools/review-replay.js`.

## Gotchas

- `tools/` does not ship (`docs/decisions/0015-*`). Nothing under `plugin/` may require this tool.
- AC8 starts a workflow with about 70 agents. This record is the maintainer's approval to run that one workflow for AC8. A session that cannot start a workflow stops there and reports; it does not replace the run with a different launcher.
- `tools/replay-scratch/` is on branch `worktree-design-process-efficiency` until that branch merges. If it is not on `main` when this is built, read the scripts from the branch and skip the deletion.
- #5122 (escaped backticks read as an unverified quote) lowers agreement in any replay. Report `cant-tell` counts beside agreement.
- #5540 changes `plugin/bin/lib/tiebreak.js` to settle a chunk in one call, and changes the Step 3.7 prompt to a list of findings. Until it lands, `extract` builds a chunk prompt by repeating the one-finding block under one set of rules, and `score` splits a reply by finding id before the one-finding settle. Once it lands, use its splitter.
- Fixtures committed under `tests/fixtures/` are written by hand or reduced until they hold nothing but what a test asserts. The archive holds record bodies and review text; none of it is copied in.
- `tests/review-tiebreak-step-conformance.test.js` has failed on Windows before (#4828). A test that reads `step3-tiebreak.md` follows `.claude/skills/windows-checkout-test-parity`.
