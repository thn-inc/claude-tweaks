# 1678: bookkeeping-stamps gate may deny session-scratchpad writes outside its documented scope

Origin: wrap-up Upstream feedback row from #1321

Defer-reason: tangential
**Related:** #1664

## Current State

The bookkeeping-stamps gate (`docs/hooks.md`) denies any Write under a pipeline run's scope until both `record-worktree` and PR-open have landed, and names the exact remediation in its denial. During #1321's wrap-up run, a `Write` targeting the *session scratchpad* (outside both the worktree and the run directory the gate exists to protect) was denied by the same rule while a PR body was being composed. The run recovered cleanly — `gh pr create --body '...'` inline, no temp file needed — so this was not blocking, but the gate's path-matching appears to reach beyond its own stated scope (the run directory) into unrelated scratch paths.

## Deliverables

- Confirm whether the bookkeeping-stamps gate's path-matching is meant to cover the session scratchpad, or only the pipeline run directory / worktree it documents.
- If out of scope: narrow the gate's matcher so a scratchpad write is never denied by this rule.
- If in scope: update `docs/hooks.md` to state that explicitly, so the denial message's remediation advice covers the scratchpad case too.

## Acceptance Criteria

A `Write` to a path under the session scratchpad directory succeeds regardless of `record-worktree`/PR-open bookkeeping-stamp state, verified by a regression test in the hooks gate suite; or `docs/hooks.md` explicitly documents the scratchpad as in-scope and the denial message names the correct remediation for that case.
