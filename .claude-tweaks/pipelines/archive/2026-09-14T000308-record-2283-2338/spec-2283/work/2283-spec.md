# 2283: test/qa: stories that embed an absolute origin are not rewritten to the resolved APP_URL, so a worktree QA run targets the main checkout's server

Surface: infra

## Current State

`_shared/dev-url-detection.md` resolves (or starts) a per-worktree dev server and sets
`APP_URL = http://localhost:{port}` (an ephemeral, worktree-isolated port — see its Step 2.7
Worktree Awareness gate). `skills/test/qa-prompts.md`'s Phase 3 dispatch template fills
`{story.url}` verbatim into each dispatched qa-agent's prompt (lines ~76 and ~139: `**URL:**
{story.url}`) — there is no rewrite step anywhere between resolving `APP_URL` and composing that
prompt. A story file that pins an absolute origin (`http://127.0.0.1:<port>/...`) therefore
drives whatever server is actually listening on that literal port — the main checkout's server on
the live database — even when `dev-url-detection.md` correctly resolved a different, isolated
`APP_URL` for this worktree run. This is exactly the wrong-code/wrong-data failure Step 2.7's
worktree-awareness gate exists to prevent, except it happens one layer downstream, after
`APP_URL` has already been correctly resolved.

Confirmed on a real run (plugin 6.118.0): four story files pinned absolute origins, two used
root-relative paths; every dispatched qa-agent for the four absolute-origin stories would have
navigated to the wrong server. The operator manually rewrote the origin in every dispatched
prompt by hand (~20 minutes of pre-flight) because the plugin has no documented convention for
whether story `url:` values should be absolute or `APP_URL`-relative, and no rewrite mechanism
either way.

## Deliverables

- At dispatch (`qa-prompts.md`'s Phase 3 template construction, wherever `{story.url}` is
  currently substituted verbatim), when a story's `url` carries an absolute origin
  (scheme+host+port) that differs from the resolved `APP_URL`'s origin, substitute `APP_URL`'s
  origin for the story's own origin, preserving the story's path/query/fragment unchanged.
- Log the rewrite once per run (not once per story) when at least one story needed it — naming
  the original and resolved origins — so a QA report makes clear the substitution happened.
- Document in `stories/SKILL.md` that a story's `url:` field should be a root-relative path
  joined to the resolved `APP_URL` at dispatch time — the convention this record's fix
  establishes — and that an absolute origin, if present, gets its origin rewritten to `APP_URL`'s
  rather than followed literally.

## Acceptance Criteria

- A story with `url: http://127.0.0.1:9999/dashboard` dispatched under a resolved
  `APP_URL = http://localhost:54321` navigates to `http://localhost:54321/dashboard`, not the
  literal `9999` port.
- A story with a root-relative `url: /dashboard` is joined to `APP_URL` unchanged (no regression
  to the already-working case the record's own use case confirms works today).
- The rewrite is logged exactly once per QA run when triggered, not once per affected story.
- `stories/SKILL.md` documents the `url:` field convention (root-relative preferred; an absolute
  origin gets rewritten, not followed literally) where the story schema is otherwise documented.

## Technical Approach

Add the rewrite as a small pure function (parse the story's `url`, and when it carries a
scheme+host+port that differs from the resolved `APP_URL`'s own scheme+host+port, replace just
the origin, keeping path/query/fragment intact — a root-relative `url` needs no parsing branch at
all, since `new URL(story.url, APP_URL).toString()` already does the right thing for both shapes)
applied once, at the point in `qa-prompts.md`'s Phase 3 (or wherever the per-story dispatch prompt
is actually assembled, likely just before the `{story.url}` substitution at lines ~76/139) where
`APP_URL` is already in scope. Log the rewrite via this test pipeline's existing decision-log
convention if a run directory is active, otherwise to the QA report directly
(`qa-reporting.md`'s existing output conventions).

### Key Files

- `plugin/skills/test/qa-prompts.md` — apply the origin rewrite before substituting `{story.url}`
  into the Phase 3 dispatch template (~lines 76, 139)
- `plugin/skills/stories/SKILL.md` — document the `url:` field convention
- `plugin/skills/_shared/dev-url-detection.md` — read-only reference: this is where `APP_URL` is
  resolved; not modified by this record

## Gotchas

- Do not silently swallow a story whose origin points at a genuinely different host on purpose
  (e.g. a story deliberately testing an external service, not the app under test) — the rewrite
  should only ever touch the origin, and if a project genuinely needs a story to hit a different
  host, that's outside this record's scope; flag it as a known limitation rather than trying to
  distinguish intent here.
- The log-once-per-run rule (not per-story) matters for QA report readability on a large story
  suite — don't regress it to log every rewritten story individually.
