# 2552: wrap-up-engine verify: run-dir-archived, reference-repairs and plans-ledger fail for reasons outside the run, forcing a BLOCKED closure

Surface: infra

## Current State
`bin/wrap-up-engine.js verify` (backed by `bin/lib/wrap-up/engine-verify.js`) runs nine checks and forces a `BLOCKED` closure per `skills/wrap-up/execution-and-verification.md`'s exit-3 rule whenever any check fails. Three of those checks — `run-dir-archived`, `reference-repairs`, and `plans-ledger` — currently fail on runs that are actually fine, because each check's assumptions don't hold under this plugin's own configuration:

1. `run-dir-archived` decides pass/fail by checking whether the *original* pipeline path is gone. When invoked with `--run-dir` already pointed at the post-archival path (`pipelines/archive/<name>`), it reports "original path still present" (misreading the archive path as the original); before archival happens, it reports "not archived" — there's no invocation shape that reports a genuine pass.
2. `reference-repairs` reads the file set of the single merged commit on `main` to confirm each `Initiative-Fix:` repair landed. Under `integration-model: pr-first`, the mandated merge strategy is a squash merge, which folds N one-file `Initiative-Fix:` commits into one multi-file commit — so a check written for a fast-forward/merge-commit history sees a shape it never expected and fails even though every fix landed.
3. `plans-ledger` scans for gitignored `.superpowers/sdd/*-archive` directories and attributes anything it finds to the current run, regardless of whether that artifact's timestamp predates the run's start or the run ever referenced it. On a shared checkout with other sessions' leftover archive directories, this hands the operator a false "must run `/claude-tweaks:tidy`" instruction for artifacts unrelated to their run.

The observed cost on one real run: verify exited 3 on both attempts, forcing a BLOCKED closure narrative built entirely from checks the run could not have passed, plus a manual follow-up handed to the user for residue that wasn't the run's.

## Deliverables
1. `run-dir-archived`: pass when `pipelines/archive/<name>` exists and the pre-archival `pipelines/<name>` path does not — regardless of which of the two paths `--run-dir` was invoked with.
2. `reference-repairs`: under `integration-model: pr-first`, verify each `Initiative-Fix:` repair by inspecting the source PR's commit list (or the run's staged patch files) instead of assuming a 1:1 mapping between source commits and the post-merge commit on `main`.
3. `plans-ledger`: scope residue detection to artifacts this run actually referenced (or, failing that, to tracked files only) rather than every gitignored `.superpowers/sdd/*-archive` directory found in the working tree. Directories that predate the run's start and that the run never touched are reported as informational "found, not owned" rather than counted as a fail.
4. `skills/wrap-up/execution-and-verification.md`'s exit-3 handling distinguishes a genuine failing row from a structural/not-applicable row (e.g. an informational "found, not owned" residue report) before forcing the BLOCKED closure line — a run whose only non-passing rows are structural/informational is allowed to close normally.

## Acceptance Criteria
1. Given a run pointed at its post-archival path (`pipelines/archive/<name>`), `run-dir-archived` reports pass, not "original path still present".
2. Given the same run invoked before archival (still at `pipelines/<name>`), `run-dir-archived` reports "not archived" (its existing not-yet-archived signal), and after archival with `--run-dir` at either the pre- or post-archival path, it reports pass — i.e. there exists an invocation shape post-archival that passes.
3. Given a `pr-first` run whose PR squash-merges N one-file `Initiative-Fix:` commits into a single multi-file commit on `main`, `reference-repairs` reports pass, verified against the PR's commit list or staged patch files rather than the squash commit's file set.
4. Given a working tree containing a gitignored `.superpowers/sdd/*-archive` directory dated before the run's start and never referenced by the run, `plans-ledger` reports it as informational "found, not owned" and does not count it toward the check's fail state.
5. Given a run where the only non-passing rows are the informational/structural cases covered by ACs 1-4, `wrap-up-engine.js verify` exits 0 (or its existing non-blocking success code), not exit 3, and the wrap-up skill's closure narrative does not force `BLOCKED`.
6. A run with a genuine, unrelated verify failure (e.g. an actual missing `Initiative-Fix:` repair) still exits 3 and still forces `BLOCKED` — the fix narrows false positives without masking real ones.

## Release Note

Fixed wrap-up verification failing on archived runs and ledger checks for reasons outside the run.

## Technical Approach
- `run-dir-archived`: detect archival state from the pair of candidate paths (`pipelines/<name>` and `pipelines/archive/<name>`) rather than from which single path `--run-dir` was given, so the check's pass condition ("archive path exists AND original path does not") holds under either invocation shape.
- `reference-repairs`: branch on `integration-model` — when `pr-first`, resolve the repair commit list via `gh pr view <pr> --json commits` (or by reading the run's staged patch files, if commit history isn't reliably available) instead of diffing the single post-merge commit on `main`.
- `plans-ledger`: cross-reference found `.superpowers/sdd/*-archive` directories against the run's own recorded run-dir start time and/or referenced-artifact list before attributing them to the run; anything outside that scope becomes an informational line, not a fail.
- `execution-and-verification.md`: introduce a row-classification step (real fail vs. structural/informational) ahead of the existing "any fail → BLOCKED" rule, so BLOCKED is reserved for rows that are genuine failures.

### Key Files
- `plugin/bin/wrap-up-engine.js` — `verify` subcommand entry point; no logic change expected beyond what the lib functions below already handle, but confirm the exit-code mapping still distinguishes real fails from informational rows.
- `plugin/bin/lib/wrap-up/engine-verify.js` — home of the `run-dir-archived`, `reference-repairs`, and `plans-ledger` checks; fix each per the Technical Approach above.
- `plugin/skills/wrap-up/execution-and-verification.md` — update the exit-3 → BLOCKED rule to gate on genuine fails only, per Deliverable 4.

## Gotchas
- The `reference-repairs` fix must not silently accept a squash-merged commit that dropped a repair — the check still needs to fail when a repair genuinely didn't land; the fix changes *how* landed-ness is verified under `pr-first`, not what counts as landed.
- `plans-ledger`'s "found, not owned" reclassification must not become a blanket pass for all gitignored residue — an artifact the run itself created (even if gitignored) should still be attributed to that run and cleaned up normally.
- Distinguishing "structural/not-applicable" from "real fail" in `execution-and-verification.md` needs an explicit, auditable classification per row (not an implicit heuristic) so a future genuine regression in one of these three checks doesn't get silently reclassified as informational.
- Related record #2565 may share root cause or fix surface with one or more of these three checks — cross-check before landing to avoid duplicate or conflicting fixes.
