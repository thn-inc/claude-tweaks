# 1376: wrap-up/review: ceremony-escape-hatch config.yml downgrade cannot be persisted from a worktree session

## Current State

`bin/stage-item.js` and `bin/log-decision.js` give a worktree-isolated session a sanctioned way to write `decisions.md` entries and `staged/*` proposals into a pipeline run directory that Edit/Write itself refuses from that session (documented worktree-pinning behavior — CLAUDE.md's Hooks section: run-state is written only through `hooks.js` verbs, and the run dir generally is refused to worktree Edit/Write). No equivalent exists for `config.yml`. `/claude-tweaks:review`'s ceremony escape hatch (`review/code-mode-steps.md`'s "Ceremony-Aware Step Selection") and `/claude-tweaks:wrap-up`'s own copy of the same hatch (`wrap-up/SKILL.md` Phase 1 "Ceremony escape hatch") both instruct downgrading `config.yml`'s `ceremony-profile` from `fast-lane` to `standard` "in place" when a review finding fires — but a worktree-isolated session (the normal `/claude-tweaks:flow`/`/claude-tweaks:dispatch` execution shape) has no CLI to actually perform that write. The decision can be logged (`log-decision.js`) but the lever itself cannot be persisted, so a downstream skill in the same run that re-reads `config.yml` still sees `fast-lane`.

Reproduced: 2026-08-24, run `2026-08-24T122139-record-835-834` (records #834/#835) — `/claude-tweaks:wrap-up`'s ceremony escape hatch fired (review's summary carried findings), the downgrade decision was logged via `log-decision.js`, but `config.yml` itself could not be updated from the worktree session — no writer CLI exists for that file, unlike `decisions.md` and `staged/`.

## Deliverables

- A `bin/set-config.js` (or equivalent) CLI mirroring `stage-item.js`'s/`log-decision.js`'s shape: `--run <run-dir> --key <lever> --value <value>`, anchored-under-`$RUN_ROOT` guard, writes the named lever into `config.yml` idempotently (parse YAML, set key, write back), refuses a key not in `_shared/policy-schema.md`'s lever enum.
- Wire the two documented "downgrade in place" ceremony-escape-hatch call sites (`review/code-mode-steps.md`, `wrap-up/SKILL.md` Phase 1) to actually invoke it, replacing the current prose-only "downgrade `config.yml`'s `ceremony-profile` to `standard` in place" instruction that a worktree session cannot follow literally.

## Acceptance Criteria

- A worktree-isolated pipeline session can downgrade a `config.yml` lever (e.g. `ceremony-profile`) without an Edit/Write refusal, and a downstream step in the same run that reads the file via `resolve-policy.js --run` observes the new value.
- `npm test` green; a new `tests/bin/set-config.test.js` (or equivalent) pins the anchoring guard and the lever-enum refusal.

## Technical Approach

Follow `bin/stage-item.js`'s existing shape (`bin/lib/stage-item/write.js`'s `resolveTarget` anchoring check is directly reusable) rather than inventing a new anchoring convention.

### Key Files

- `plugin/bin/stage-item.js`, `plugin/bin/log-decision.js` — the existing sanctioned-write precedent to mirror
- `plugin/skills/_shared/policy-schema.md` — the lever enum a new writer must validate against
- `plugin/skills/review/code-mode-steps.md`, `plugin/skills/wrap-up/SKILL.md` — the two "downgrade in place" call sites to wire up
