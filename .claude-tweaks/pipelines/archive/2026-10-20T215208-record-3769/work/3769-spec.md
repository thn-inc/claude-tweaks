# 3769: Teardown gate's assigned-run deny can miss a mis-cased worktree path on a case-insensitive volume

Verified-as-of: a7b41a727d09cac4d42b594b7c45fabc42aa70eb

Origin: Review Console residue audit 2026-10-20 — unconfirmed finding from run 2026-10 record-3682 (its ledger row 10, ruled out of scope), bulk-acknowledged unread

Defer-reason: tangential

## Current State

The teardown gate's assigned-run deny (`plugin/bin/lib/hooks/pre-tool-use.js:608`) finds the run holding a `git worktree remove` target through `ctxLib.findRunByWorktreePath`. That function (`plugin/bin/lib/hooks/context.js:562`) canonicalizes the target with plain `fs.realpathSync`. On a case-insensitive volume (macOS APFS default), the JS `realpathSync` keeps the input's letter case rather than the on-disk case. A differently-cased path to an assigned worktree that is not the session's own cwd may therefore fail to match its run and not be denied.

A second, test-only inconsistency: `shadowPipelineRunDir` (`pre-tool-use.js:689`) calls `canonicalRealpath(repoRoot)` without `{ fsImpl }`, so a fake-volume test resolves its operands on different filesystems.

The reviewer's claim is unconfirmed: the first deliverable reproduces it before any fix. Checked on origin/main a7b41a727: both call sites are unchanged.

## Deliverables

- [ ] Reproduce first: a test on a simulated case-insensitive volume showing a mis-cased removal target for an assigned worktree is (or is not) denied today. If it is denied, close this record with that evidence.
- [ ] If reproduced: resolve the target in `findRunByWorktreePath` with the case-canonicalizing resolver the gate already uses elsewhere (`canonicalRealpath`, per the project's `pre-tool-use-gate-exemptions` skill), not plain `fs.realpathSync`.
- [ ] Pass `{ fsImpl }` through at `pre-tool-use.js:689`.
