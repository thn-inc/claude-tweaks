# 1653: Consolidate the fourth hand-rolled atomic-write copy in log-decision/append.js onto a shared primitive

Defer-reason: genuinely-larger

## Current State

`plugin/bin/lib/log-decision/append.js`'s `appendEntry()` hand-rolls a tmp-file-plus-rename atomic write, independently reimplementing the same pattern `plugin/bin/lib/json-store.js`'s `writeJsonFile`, `plugin/bin/lib/flow/manifest.js`, and `plugin/bin/lib/hooks/context.js`'s `writeRunState` each already have their own copies of. Four independent copies exist with no shared primitive enforced anywhere — `json-store.js`'s `writeJsonFile` is JSON-specific (hardcodes `JSON.stringify`), so a genuine consolidation needs a lower-level shared `writeFileAtomic(filePath, content)` that all four wrap. `log-decision/append.js`'s own version is currently the most complete (it cleans up the tmp file on a failed rename); `json-store.js`'s currently lacks that cleanup.

## Deliverables

Extract a shared `writeFileAtomic(filePath, content)` primitive (likely into `json-store.js` or a new `atomic-write.js`), and migrate all four call sites (`json-store.js`'s `writeJsonFile`, `log-decision/append.js`'s `appendEntry`, `flow/manifest.js`'s writer, `hooks/context.js`'s `writeRunState`) onto it, preserving each site's existing failure-cleanup semantics — the union of what all four currently do, not a regression to the weakest one.

## Acceptance Criteria

No behavioral change to `run-state.json`, `manifest.yml`, or `decisions.md` writes. A future fix to the atomic-write pattern (e.g. an EXDEV cross-device rename fallback) lands once, not four times. Existing test suites for all four consumers pass unchanged.
