# 2984: Adapt the finish-reviewer dispatch to Impeccable 4.2.2+'s input packet and return shape

Surface: infra

## Overview

Bring `design-wrapper` `review` mode's Step 3.7 dispatch of `impeccable-finish-reviewer` in line with the agent's 4.2.2+ contract. Since Impeccable 4.2.2 the agent expects a much larger input packet and returns a `disposition:` first line plus exactly five sections. Step 3.7 still passes the old inputs and normalizes the old return, and it checks agent availability with the retired `resolveImpeccablePlugin`.

The agent stays exempt from this repo's subagent output contract — its definition ships outside `plugin/agents/` — so all adaptation happens at the caller's boundary: build the packet, check availability at the agent level, normalize the return, and never report an unavailable, failed, empty or unparseable run as a clean result.

The parent design also planned to adapt an `impeccable-asset-producer` caller. That half is dropped: on main nothing in the wrapper dispatches `impeccable-asset-producer` (its only mention is the comparison note `third-party-design-skill-comparisons.md:86`), so there is no caller to change.

**Complexity:** Medium
**Estimated tasks:** 4

## Non-Goals

- Where the direction contract text comes from (the direction-contract sub-issue).
- Adding an `impeccable-asset-producer` dispatch.
- Re-prompting the agent for format, inlining Template A, or asking it for a status line — the third-party exemption forbids all three.

- [ ] Availability: take the plugin root from `impeccable-engine.js resolve`'s `pluginRoot` and keep the agent-file existence check (`{pluginRoot}/agents/impeccable-finish-reviewer.md`); an `ok: false` resolve or a missing agent file keeps today's skip-and-log behaviour.

- [ ] Normalization: parse the first non-empty line as `disposition: <word>` against the four-word vocabulary. Skip the optional one-line missing-inputs note upstream places above the sections, then split the five named sections (or the single `recapture` section). Mappings:

  - `fix` → one medium-severity finding per `material_fixes` line.
  - `rebuild` → one high-severity finding carrying the first material fix. The rest are moot, because upstream's rebuild directive tells the builder to stop ordering repairs.
  - `recapture` → one medium-severity finding naming the missing or invalid captures.

  Each of these is reported as "finish review unparseable", never as a clean pass: an unknown disposition word, a missing section, an empty reply, and `fix` with an empty `material_fixes`.
- [ ] Update the comparison note `third-party-design-skill-comparisons.md`'s present-tense description of how the wrapper uses the two agents, only where it now misstates the return shape.
