# 3671: log-decision.js: read entry text from a file so interpolated file names need no shell escaping

Origin: reflect full from #3483

Defer-reason: tangential

## Current State

Prose in two places tells an agent to escape `"`, `$`, backtick and `\` in git-supplied text (file names, error messages) before it goes into the double-quoted `--text` argument of `bin/log-decision.js`: `flow/steps-and-gates.md` (adoption path, #3014) and `wrap-up/execution-and-verification.md` (leave-open mergeability re-check, #3483). #3483's own review found the second site had omitted it. The rule lives only in prose beside each command, so every new call site that interpolates a file name has to remember it, and an agent that forgets it composes a shell-injectable command.

## Deliverables

- [ ] Add a way for `bin/log-decision.js` to read the entry text without it passing through shell quoting (a `--text-file <path>` flag, or `--text -` reading stdin), keeping `--text` unchanged (expand step).

- [ ] Migrate the call sites that interpolate git- or user-supplied text (the two named above) to the new form and drop their escape sentences, keeping their conformance pins pointed at the new wording.

- [ ] Add the new flag to `log-decision.js` USAGE, `docs/plugin-structure.md`, and `_shared/auto-decision-log.md`.

## Acceptance Criteria

- `log-decision.js --run <dir> --status AUTO --text-file <file>` writes the same entry `--text "<contents>"` would, including for contents with `"`, `$(...)` and backticks (a unit test covers each).

- Neither named call site carries an escape instruction; both name the file-based form.

- `--text` still works unchanged for every existing caller.

## Release Note

No user-visible change.

## Technical Approach

### Key Files

- `plugin/bin/log-decision.js` — add --text-file
- `plugin/skills/wrap-up/execution-and-verification.md` — migrate the leave-open log call
- `plugin/skills/flow/steps-and-gates.md` — migrate the adoption-path log call
