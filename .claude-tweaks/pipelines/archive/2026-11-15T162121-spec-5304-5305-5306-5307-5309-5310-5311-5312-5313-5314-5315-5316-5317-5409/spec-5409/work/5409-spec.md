# 5409: Stop dispatch's queue pull, or clear its stale file, when a step error leaves an earlier pull's session file in place

Origin: spec #5230 review (3c)

Defer-reason: pre-existing-outside-diff

**Related:** #5314

## Current State

refs #5230. `plugin/bin/lib/dispatch/queue-pull.js` catches a throw inside a step, prints `queue-pull: <step>: <message>` and continues wherever the retained `queue-pull-script.md` fence continues (the module header's R6 rule). The session-tmp file paths are the same on every pull of a session, so on a drain re-pull a step that fails before writing its file leaves the previous iteration's file on disk, a later pass (for example the blocked pass) reads it as this pull's, and the pull exits 0. `plugin/skills/dispatch/SKILL.md` Step 2 treats exit 0 as a clean pull. The behavior predates #5230 (the fence has it), and #5230's Non-Goals kept module behavior changes out of the cutover. The #5230 review tiebreak confirmed it at low.

## Deliverables

- For every step whose output file a later pass reads, remove the file in the step's catch (or stop the pull with exit 4) so no later pass reads an earlier pull's data.
- Mirror the change into the retained `queue-pull-script.md` while it still exists, or land this after #5231 removes it.
- Add a fixture that fails one such step on a second pull in the same session.

## Acceptance Criteria

1. A second pull in one session whose eligible-pre-dep step throws does not leave the first pull's file for a later pass: the later pass reads no data or the pull exits 4.
2. The fixture fails with the fix reverted.
3. `npm test` passes.

**Decision** (plan review, 2026-11-17): Reading B — #5314 already fixed the eligible-pre-dep step named in acceptance criterion 1, and its existing test keeps covering that case. This record's own fix is the session files a failed step can still leave from an earlier pull (`dispatch-named-targets.json`, `dispatch-shipped-probe-prs.json`, `dispatch-shipped-releases.json`, `dispatch-crosspr-overlap.json`, `dispatch-near-dup-pairs.json`). Acceptance criterion 2's fixture is a new test that fails one of those steps (the cross-PR overlap step) on a second pull in the same session and goes red when this record's own change is reverted.

## Release Note

Dispatch no longer reuses a previous queue pull's data when a step of the current pull fails.
