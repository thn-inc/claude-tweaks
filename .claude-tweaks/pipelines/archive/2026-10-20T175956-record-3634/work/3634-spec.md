# 3634: Resolve the remaining bare-name citations in the skill load model

Origin: ledger resolve gate (wrap-up of #3457, ledger row 5)

Defer-reason: needs-human-decision

## Current State

After rule (e) (#3457), the load model's citation grammar still leaves 469 unresolved (citing file, token) pairs inside plugin:flow's base-closure files. 110 are placeholders or globs, 95 are paths outside the plugin (docs/, CLAUDE.md), 3 are `skills/` tokens whose target file is missing, and 261 are bare names or sub-paths. Some of those 261 name real files that are cited relative to a skill other than the citing one (for example `modes/review.md` for design-wrapper, or `reference/*.md`), so the closure still undercounts what an invocation can load. Resolving them needs a design choice: a further grammar rule in `extractCitations`, or fixing the citation form in the skill prose.

## Deliverables

- [ ] Classify the 261 remaining bare-name and sub-path pairs on plugin:flow: which name a real file, which name nothing
- [ ] For each real-file class, either extend `extractCitations` with a further rule or change the citation form in the skill prose, whichever the classification supports
- [ ] Add `load.test.js` cases for any new rule, including a case showing the first-existing-wins order is unchanged

## Acceptance Criteria

- On plugin:flow, every remaining unresolved token is a placeholder or glob, a path outside the plugin, or a token that genuinely names nothing; the per-class counts are stated in the PR.
- A diff of resolved sets before and after shows additions only: no previously resolved token changes its resolved path.

## Release Note

Skill load closures now count files cited by bare name or sub-path, so the worst-case load figure stops undercounting.

### Key Files

- `plugin/bin/lib/skill-audit/load.js` — extend extractCitations if the classification supports a further rule
- `tests/bin-lib/skill-audit/load.test.js` — cases for any new rule
