# 2726: capture: Shaped-body branch never states `bin/compose-record.js`'s payload fields

Surface: infra

## Current State

`plugin/skills/capture/SKILL.md`'s Backend Selection step 2 shows only the stub payload shape for `bin/compose-record.js` (`{title, body, type, origin}`). The Shaped-body branch (line ~268) tells the caller to file via `recordPayload({ …, origin: 'capture', risk, size, ready: true, deferReason })` — eliding the base fields with `…` rather than restating them — and separately compose the body via `specShapedBody(...)`. Verified against `plugin/bin/lib/issues/record.js`'s actual `recordPayload` signature: `{ title, body, type, origin, risk, size, ceremony, solutionUnjustified, ready, parked, priority, fingerprint, effort, framing, deferReason }`. Nowhere in `capture/SKILL.md` does the full accepted field list appear in one place for the Shaped-body branch — a caller has to cross-reference the Shaped-body branch's elliptical `{…, ...}` call against Backend Selection's stub example and `record.js`'s source to reconstruct the complete payload, which is exactly the reverse-engineering cost the filer measured (five source reads before one shaped capture could be filed).

## Deliverables

- Add a Shaped-body-branch-specific payload example to `capture/SKILL.md`, spelled out in full (not elliptical), showing every field the Shaped-body branch actually passes: `title`, `body` (the `specShapedBody`-composed text), `type`, `origin: 'capture'`, `risk`, `size`, `ready: true`, `deferReason` — placed near the existing Backend Selection stub example or inline at the Shaped-body branch's own `recordPayload({…})` reference, whichever reads more naturally in context.
- Keep the stub-payload example (`{title, body, type, origin}`) for the non-shaped (stub) branch as-is — this record only fills the gap for the Shaped-body branch's own field list, not a rewrite of the existing stub documentation.

## Acceptance Criteria

- `capture/SKILL.md` states the Shaped-body branch's full `recordPayload` field list in one place, matching `record.js`'s actual accepted keys for the fields the branch uses (`title`, `body`, `type`, `origin`, `risk`, `size`, `ready`, `deferReason`) — not an elliptical `{…}` reference requiring a source read to complete.
- The existing stub-payload example and Backend Selection's own prose are unchanged except for this addition — this is a documentation fill-in, not a restructuring.
