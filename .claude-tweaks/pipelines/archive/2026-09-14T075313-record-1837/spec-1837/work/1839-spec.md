# 1839: materialize-format.js: PLACEHOLDER_RE flags a TODO inside a fenced code block that quotes the deliverable text itself

Surface: infra

## Current State

Three checkers implement `_shared/work-record.md`'s spec-shaped-body rule "no unresolved placeholder markers (the two deferral tokens and the ambiguity HTML-comment marker) outside the verbatim `## Original request` section", and none of them distinguishes a marker in authored prose from one inside quoted code:

- `shapeGate` (`plugin/bin/lib/issues/materialize-format.js`): `PLACEHOLDER_RE = /\bTBD\b|\bTODO\b|<!--\s*ambiguity:/` tested against everything before `## Original request` (#1240). This is `/flow`'s materialization hard gate; a hit exits `materialize.js` with `unresolved-placeholder` and Settling points at `/claude-tweaks:specify`.
- `validateShaped` (`plugin/bin/lib/compose-record/compose.js`): a substring loop over `PLACEHOLDER_MARKERS` with the same section exemption, used at compose time.
- The prose rule itself (`_shared/work-record.md`, the spec-shaped-body list), re-run by `/claude-tweaks:backlog refine`'s Step 3.5 body-shape auto-downgrade and the grant gate; `specify/shaping-mode.md` therefore tells shapers never to *mention* the tokens, even in prose.

Harness-health drift records quote the current and proposed CLAUDE.md text verbatim in fenced blocks under `## Deliverables` by construction. When the quoted bullet is the "No implicit deferrals" philosophy line (which ends "…leave a T-O-D-O comment without a corresponding record"), every such record fails the gate although nothing in it is unresolved: observed on plugin 6.114.1, `materialize.js` exit 1 `unresolved-placeholder`, worked around by a logged hand materialization. The same shape recurs for any CLAUDE.md section whose template wording contains the word, and for any record that quotes code or prose containing it.

Tests: `tests/bin-lib/issues/materialize-format.test.js` (`shapeGate` cases including the #1240 exemption and "a genuine marker in an authored section still fails"); `tests/bin-lib/compose-record/` for `validateShaped`.

## Deliverables

- [ ] **One helper, two checkers.** Add `stripCodeSpans(text)` to `plugin/bin/lib/issues/materialize-format.js` (exported): removes fenced blocks (```` ``` ```` and `~~~`, any info string, unclosed fence runs to end of text) and inline code spans (backtick runs of any length, per CommonMark) from the authored text before `PLACEHOLDER_RE` is applied. `validateShaped` in `compose.js` imports and applies the same helper before its marker loop. A bare marker in authored prose still fails in both.
- [ ] **Prose rule and shaping guidance.** `_shared/work-record.md`'s spec-shaped-body bullet gains the clause "or inside a fenced code block / inline code span, which quotes content rather than authoring it". `specify/shaping-mode.md`'s authoring-constraint paragraph is narrowed the same way: a token inside backticks is permitted (it is what the two JS checkers now skip); a prose mention remains forbidden. `refine`'s Step 3.5 and the grant gate cite the rule by reference, so they need no text change; confirm with a grep and edit only if either restates the token list.
- [ ] **Tests.** `materialize-format.test.js`: a Deliverables fence quoting a line with `T-O-D-O` passes; an inline-code `` `T-O-D-O` `` passes; a bare `T-O-D-O` in the same section still fails; an unclosed fence containing the marker passes (fence runs to end of authored text); a marker after a closed fence still fails. Sibling cases in the `validateShaped` suite. The `materialize` CLI case "an unshaped record fails the gate" stays as is.
- [ ] `flow/materialize.md`'s "Materialization hard gate" sentence names the code-span exemption in the same breath as the `## Original request` one.

## Acceptance Criteria

## Technical Approach

Strip, don't special-case: removing code spans before the regex keeps `PLACEHOLDER_RE` and `PLACEHOLDER_MARKERS` untouched and the exemption identical in both checkers. Handle the unclosed-fence case by treating the run to end-of-text as code (the safer direction: a truncated fence is quoted content, not authored prose). Apply the helper *after* the `## Original request` cut, so the two exemptions compose without interaction.

## Gotchas

- An inline-code span cannot contain its own delimiter run; match backtick runs by length (`` `+ `` opening, same length closing) or a single-backtick `T-O-D-O` inside a double-backtick span is mis-cut.
- `sectionText` and the section-presence checks run on the *unstripped* body; only the placeholder scan sees the stripped text, so a section whose only content is a fenced block still counts as non-empty.
- `_shared/work-record.md`'s rule is also quoted by `capture/SKILL.md`'s born-ready branch; a grep for the token list decides whether that quote needs the clause too (AC 4's sweep).
- The exemption widens the gate; keep the "bare marker after a closed fence still fails" case so a stray `T-O-D-O` cannot hide behind an earlier code block.

## Original request

**Summary:** `shapeGate`'s placeholder scan (`\bTODO\b`) rejects a fully-shaped harness-health drift record because its authored Deliverables section quotes the CLAUDE.md bullet being replaced, and that bullet's own wording says "leave a TODO comment" — the marker is the deliverable, not a placeholder.

**Kind:** Defect

**Affected component:** `bin/lib/issues/materialize-format.js` (`shapeGate` / `PLACEHOLDER_RE`) — `/flow`'s materialization hard gate

**Repro steps:**
1. Run `/claude-tweaks:harness-health` against a project whose CLAUDE.md Philosophy section carries the pre-#621 "No implicit deferrals" bullet (the one ending "…leave a TODO comment without a corresponding record").
2. Let it file its drift record: the body's `## Deliverables` section contains two fenced blocks — **Current** (the stale bullet, verbatim) and **Proposed** (the template bullet, verbatim); both contain the words "TODO comment". All three required sections are present and non-empty; no `TBD`, no `<!-- ambiguity:` marker anywhere.
3. Dispatch it: `PIPELINE_RUN_DIR=… /claude-tweaks:flow #{n}` → `bin/materialize.js {n} --run-dir …` exits 1 with `unresolved-placeholder`.

**Expected vs. actual:**
Expected: the record passes the gate — the marker word occurs only inside fenced code that quotes the exact text the deliverable replaces, in an authored section; nothing is unresolved.
Actual: `unresolved-placeholder`, exit 1. The build had to override with a logged composer-based materialization (`materialize-format.js`'s own `composeHeader`/`composeFile`) because Settling would point at `/specify`, which cannot remove the word from a correct deliverable. #1240 (closed) and #1633 (open) exempt only the verbatim `## Original request` section, so neither covers a marker inside a fenced/inline code span in an authored section.

**Suggested remedy:** strip fenced code blocks and inline code spans from the authored text before applying `PLACEHOLDER_RE` (a quoted line of text is content, not a placeholder), keep failing on a bare marker in authored prose, and add a regression case whose Deliverables fence quotes a line containing the marker word. Harness-health drift records quote Current/Proposed text by construction, so this shape recurs for every CLAUDE.md section whose template wording mentions TODO.

**Definition:** Clear
