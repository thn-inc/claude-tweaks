# Spec: #2330 — archive-merged.js: work-twin-conflict failure reasons never escalate to residue tracking

Surface: infra

## Current State

`trackArchiveResult` in `plugin/bin/lib/reconcile/archive-merged.js` early-returns before
`trackResidue` for any `result.reason` other than `'move-failed'`. The newer failure reasons
`work-twin-conflict` and `work-twin-resolve-failed`/`work-twin-resolve-failed-partial-revert`
are silently dropped every reconcile pass -- no residue streak, no eventual issue filing.

## Deliverables

Widen `trackArchiveResult`'s reason guard so `work-twin-conflict` and
`work-twin-resolve-failed[-partial-revert]` route into the same `trackResidue(...)` call the
`move-failed` path already uses, with a `reason` value specific enough that
`escalate-residue.js`'s filed-issue title/body names the actual failure rather than reusing
"move-failed" generically.

## Acceptance Criteria

A reconcile run that repeatedly hits `work-twin-conflict` on the same run dir eventually
escalates (streak-based issue filing), the same way a repeated `no-worktree`/`no-branch`/`no-pr`
result does today. Do not conflate this with `STRUCTURALLY_STUCK_REASONS` (a different mechanism)
unless investigation shows it's actually needed there too.
