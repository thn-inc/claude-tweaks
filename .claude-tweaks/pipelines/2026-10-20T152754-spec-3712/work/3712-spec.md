# 3712: Record the root cause of the unattended merge-question stall that #2734 was filed for

Surface: infra

## Current State

**Related:** #2734, #3301, #3553, #3646, #3656, #3684, #3706, #3711

**Root cause, established at shaping time (2026-10-20) from the incident transcript.** #2734's ~7.5h stall was not a policy gap. Under an `unattended` ceiling the Review Console asked anyway, because nothing mechanical stops a console `AskUserQuestion` when `consoleAutoResolve` is granted. The evidence follows; the original transcript is due to be deleted by Claude Code's ~30-day cleanup around 2026-10-21, so this record body is now the durable copy.

- **Incident session:** `b41eb7b0-a507-4837-b6da-1f3b3564aa30`, plugin 6.128.0, 2026-09-20T18:49Z to 2026-09-21T04:53Z. Two `/flow` runs: `2026-09-20T185343-spec-2670-2681` (multi-spec) and `2026-09-20T193353-spec-2682` (single-spec).
- **The ceiling resolved `unattended` in both runs.** Both Manifesto decision-log entries read "review-auto-apply-ceiling=medium (autonomy ceiling: unattended)". The ceiling did not resolve lower than reported.
- **#2682 carried `auto:merge`** (labeled 2026-09-20T19:20:28Z, before the run claimed it at 19:34). 6.128.0's `plugin/skills/wrap-up/review-console.md` already had the `consoleAutoResolve` short-circuit, which at `unattended` merges a granted record with zero `AskUserQuestion` calls. The correct outcome was a zero-click merge.
- **The stalled question was asked by the orchestrating model, from memory.** In the #2682 run the session never invoked `/claude-tweaks:wrap-up`, never read `wrap-up/review-console.md`, and never ran `bin/console-resolve.js`. It rendered "the single-spec Review Console for `#2682`" itself and called `AskUserQuestion` (header `"Review Console"`) at 19:58:28Z. The answer came at 2026-09-21T03:22:55Z ("Approve all + merge (Recommended)").
- **The first run's console is the same failure.** In run `…spec-2670-2681` the session did read `flow/multispec-review-console.md`, which contains the same short-circuit, and still asked (header `"Review Console"`, 19:27:55Z). Neither #2670 nor #2681 carried any `auto:*` grant, so the correct outcome was a zero-click park at `pending-review` (the #1802/#1966 ungranted-member carve-out), not a question.
- **#2734 misdiagnosed it.** The session's own end-of-run finding blamed `manifesto.md`'s `merge-authorization: ask` default and filed #2734. That shipped the `pre-authorize-merge` `/flow` token (PR #3709, v6.148.0). The token is still useful for `auto:build`-only records, but it does not touch this failure. `plugin/skills/_shared/autonomy-ceiling.md`'s zero-click claim is correct as written; the defect is enforcement.
- **Enforcement today:** `plugin/hooks/hooks.json` registers `PreToolUse` only for `Bash`, `Edit`, `Write`, `NotebookEdit`, and `ExitWorktree`. `AskUserQuestion` has only a `PostToolUse` registration, which logs (`post-tool-use.js`'s `logAskUserQuestion`). Both console prompts already pin `header: "Review Console"`: `plugin/skills/wrap-up/review-console-interactive.md` (single-spec) and `plugin/skills/flow/multispec-review-console.md` (multi-spec).

**Decision (maintainer, 2026-10-20):** under an `unattended` ceiling the Review Console never asks, whether or not a human is at the keyboard. The grant decides merge versus park. A human who wants the click uses `confirm`/`hybrid` or a lower ceiling. Enforce it with a hook, not more prose: the 6.128.0 prose already said "zero `AskUserQuestion` calls", and the model read it and asked anyway.

## Gotchas

- **The header is the gate's only signal.** A model that invents a console prompt with a different header gets past it. This is accepted: the header is pinned in two skill files and the incident used it both times. AC 5's conformance test keeps the three in lockstep.
- **Never deny without a provable owned run.** `docs/hooks.md`'s never-break-a-session invariant applies: an ambiguous or foreign run, or a resolve failure, means allow. A false deny on a `supervised` console strands a human-present run with no way to answer.
- **Don't revert `pre-authorize-merge`.** #2734's token remains a legitimate per-run lever for `auto:build`-only records. This record only corrects the diagnosis.
- **`--dry-run` consoles** already never prompt (the console file's preview path), so the gate needs no `--dry-run` carve-out. Verify that against the file rather than assuming.
- **Interactive presence is deliberately ignored.** Don't add a "human is here" heuristic: the incident session was interactive and still stalled for 7.4h.
