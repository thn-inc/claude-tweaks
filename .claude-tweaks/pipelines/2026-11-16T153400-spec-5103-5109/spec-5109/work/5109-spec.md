# 5109: Consolidate the origin → gate → repo-target composition behind repoTargetOf in claim-targets.js and stale-claim-pr.js

Origin: /claude-tweaks:release v6.162.1 release-gate review (run 2026-11-05T071125-release-standalone, lens 3e)

Defer-reason: pre-existing-outside-diff

## Current State

After #4794, the origin → `gateOriginRepo` → `resolveRepoTarget` composition exists three times, each with its own fallback for an unparseable remote: `plugin/bin/claim-targets.js:54-68` (gate used only for the host; host falls back to `resolveGhHost(cwd)`, owner/repo from `gh repo view`), `plugin/bin/stale-claim-pr.js:186-202` (`target: null` → exit 3), and `plugin/bin/lib/hooks/git-exec.js` `repoTargetOf` (loose regex fallback → github.com).

`git-exec.js` already exports `repoTargetOf` as the shared helper, with a comment warning that another copy of this parse is how drift starts; neither CLI uses it. Host precedence is shared via `resolveRepoTarget`; the per-copy unparseable-remote fallback is the part that drifts. Found by the v6.162.1 release-gate whole-branch review (lens 3e, confirmed by independent tiebreak). Related: the repoTargetOf underscore-alias refusal record filed from the same review.

## Deliverables

- Make `claim-targets.js` and `stale-claim-pr.js` resolve their repo target through one shared helper (`repoTargetOf` or a successor), with a single deliberate fallback for an unparseable remote.

- Keep each CLI's existing exit-code contract for a refused or unresolvable origin.

## Acceptance Criteria

- [ ] `grep -n "gateOriginRepo(" plugin/bin/claim-targets.js plugin/bin/stale-claim-pr.js` finds no direct calls; both route through the shared helper.

- [ ] Existing claim-targets and stale-claim-pr CLI tests pass unchanged.
