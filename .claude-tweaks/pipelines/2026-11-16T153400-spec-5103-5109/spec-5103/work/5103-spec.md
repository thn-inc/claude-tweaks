# 5103: Unresolved-origin hint says `--repo [host/]owner/name` in every gated CLI

Origin: SDD ruling ratified at Review Console (#4794)

Defer-reason: genuinely-larger

## Current State

Thirteen gated CLIs print the unresolved-origin hint `could not resolve owner/repo — pass --repo owner/name` (for example `plugin/bin/release-claim.js:151` and `plugin/bin/fetch-sub-issues.js:121`), although their `--repo` accepts `host/owner/name` and, since #4794, a bare `owner/name` reaches github.com while the host-qualified form follows the origin host. A GitHub Enterprise sandbox-proxy user who re-runs with the bare form the hint names therefore reaches github.com. Changing the hint re-pins about fourteen test files outside the callers #4794 migrated, so the #4794 final review (SDD ruling, ratified at the Review Console) carried it to a backlog record instead of widening that branch.

## Deliverables

Every gated CLI that prints the unresolved-origin hint says `pass --repo [host/]owner/name` (one shared string in a helper where the CLIs already share one, such as `plugin/bin/lib/number-list-cli.js` and `plugin/bin/lib/compose-subject.js`), and the tests that pin the old text are updated to the new one in the same change.

## Acceptance Criteria

- `git grep -n -F -e "pass --repo owner/name" -- plugin/bin` returns nothing, run against a tree that still holds the old text (it matches 13 files before the change).
- Each gated CLI listed under Key Files prints a hint containing `[host/]owner/name` when its origin does not resolve, and still exits 2.
- `npm test` passes with the pinned hint text updated.

## Release Note

The unresolved-origin hint of the gated CLIs now says `--repo [host/]owner/name`, so a GitHub Enterprise user is told the host-qualified form.
