# 2553: hook event logging: complexity refusals never append wd-deny, ask-user-question is logged without the answer, contract-violation false-positives on conformant judges, duplicate commit/push events, close-without-wrapup on a clean run

Surface: infra

## Current State
The hook event log (`events.jsonl`, written by `bin/lib/hooks/*.js` and consumed by `bin/friction-events.js`, `bin/phase-timing.js`, and `reflect/full-mode.md`'s Friction lens) under-reports what actually happened during a session, in five distinct ways observed in one run:

1. `pre-tool-use.js`'s worktree gate has a "too complex to verify" refusal branch that never calls `appendEvent` — 0 of 7 denials were logged in the observed run, even though 4 of them occurred inside a worktree already recorded on the run via `record-worktree`.
2. `post-tool-use.js`'s `ask-user-question` logging captured only 1 of 2 `AskUserQuestion` stops in the run, and the one it did capture recorded `"response": null` instead of the chosen option.
3. `subagent-stop.js`'s contract-violation detector logged a `contract-violation` (`variant: lenient`) for 3 of 4 curation-judge dispatches whose first line was actually a conformant `DONE`/`DONE_WITH_CONCERNS: …` status line — a false-positive rate of 75% in the observed run.
4. The merge commit and its corresponding push were each logged twice in `events.jsonl` (no dedup on repeated breadcrumbs).
5. The ExitWorktree/close teardown path emitted a `close-without-wrapup` event for a run whose `run-state.json` already read `status: clean` and which the wrap-up flow itself was in the process of archiving — a false terminal-state signal.

Because `reflect/full-mode.md`'s Friction lens and the closure's guard-denial line both read directly from `events.jsonl`, these gaps caused the lens to file a narrower finding than the session's actual friction supported (reporting 1 of 7 real denials, 14%), and left the false contract-violation records for a future reader to triage by hand.

## Deliverables
1. `pre-tool-use.js`'s "too complex to verify" refusal branch calls `appendEvent` with a `wd-deny`/`gate-denial` record on every refusal, matching the logging already done by the gate's other deny branches.
2. `post-tool-use.js`'s `ask-user-question` event logging captures every `AskUserQuestion` stop in the session (not just some), and records the actual chosen option rather than `null`.
3. `subagent-stop.js`'s contract-violation detector parses the first non-empty line of a dispatched agent's reply against the four valid contract statuses (`DONE`, `DONE_WITH_CONCERNS`, `NEEDS_CONTEXT`, `BLOCKED`) before logging a violation, and when it does log one, names the specific clause violated.
4. Commit and push breadcrumb events dedupe on the tuple `(action, hash, dir)` so a single commit/push is never logged twice.
5. The close/teardown path checks `run-state.status !== "clean"` before emitting `close-without-wrapup`, so a run already marked clean and mid-archival does not get a false terminal-state event.
6. `reflect/full-mode.md`'s Friction lens: when `friction-events.js` returns `[]`, fall back to a grep of the resolved transcript for the deny-message signatures ("Refusing to run it", "requires an isolated worktree") so the lens still counts denials the log missed.

## Acceptance Criteria
1. Given a worktree-gate refusal on a heredoc classified "too complex to verify," `events.jsonl` gains a `wd-deny`/`gate-denial` record for that refusal — verified by triggering the refusal inside a `record-worktree`-tracked worktree and inspecting the log.
2. Given two `AskUserQuestion` stops in one session, `events.jsonl` contains two `ask-user-question` records, each with a non-null `response` field matching the option actually chosen.
3. Given a dispatched Task agent whose first reply line is exactly `DONE_WITH_CONCERNS: <reason>`, `subagent-stop.js` does NOT log a `contract-violation` for that dispatch.
4. Given a dispatched Task agent whose first reply line does not match any of the four valid statuses, `subagent-stop.js` DOES log a `contract-violation`, and the logged record names which clause (e.g. "no recognized status line") was violated.
5. Given a merge commit and its push occurring once each, `events.jsonl` contains exactly one event per `(action, hash, dir)` tuple — no duplicate pairs.
6. Given a run whose `run-state.json` already reads `status: clean` at the time ExitWorktree/close runs, no `close-without-wrapup` event is emitted for that run.
7. Given a run where `friction-events.js` returns `[]` but the resolved transcript contains at least one deny-message signature string, `reflect/full-mode.md`'s Friction lens reports that denial via the transcript-grep fallback rather than reporting zero friction.
8. A run with a genuine contract violation (first line matches none of the four statuses) and a genuine `close-without-wrapup` condition (run-state not clean at close) still logs those events — the fix narrows false positives/omissions without suppressing true ones.

## Release Note

Fixed several gaps and duplicates in hook event logging.

## Technical Approach
- `pre-tool-use.js`: locate the "too complex to verify" refusal branch and add the same `appendEvent(...)` call pattern used by the gate's other deny branches, with a `wd-deny`/`gate-denial` event type.
- `post-tool-use.js`: audit the `ask-user-question` event-emission path for why some stops aren't captured (likely a missed hook-invocation point or an early-return before logging) and why `response` isn't populated (likely reading the wrong field from the tool result); fix both.
- `subagent-stop.js`: replace or harden the contract-violation detector's line-matching logic so it correctly recognizes `DONE_WITH_CONCERNS: …`-prefixed lines (and the other three valid statuses) as conformant before flagging a violation; when it does flag one, include the specific unmatched-clause reason in the logged record.
- Commit/push breadcrumb logging: add a dedup check (in-memory or by re-reading the tail of `events.jsonl`) keyed on `(action, hash, dir)` before appending a new commit/push event.
- Close/teardown path: read `run-state.json`'s `status` field before emitting `close-without-wrapup`, and skip the emission when it already reads `clean`.
- `reflect/full-mode.md`'s Friction lens: add the transcript-grep fallback step for the deny-message signatures, gated on `friction-events.js` returning an empty array.

### Key Files
- `plugin/bin/lib/hooks/pre-tool-use.js` — complexity-refusal branch; add `appendEvent` call.
- `plugin/bin/lib/hooks/post-tool-use.js` — `ask-user-question` logging and commit/push breadcrumb logging; fix capture completeness, response field, and dedup.
- `plugin/bin/lib/hooks/subagent-stop.js` — contract-violation detector; fix first-line parsing against the four valid statuses.
- `plugin/bin/friction-events.js` — consumer of `events.jsonl`; no logic change expected, but confirm it surfaces the corrected event shapes.
- `plugin/bin/phase-timing.js` — consumer of `events.jsonl`; confirm dedup doesn't break its own event counting.
- `plugin/skills/reflect/full-mode.md` — Friction lens; add the transcript-grep fallback for the empty-array case.

## Gotchas
- The contract-violation detector fix must not become so lenient that it stops catching genuine violations (a first line that truly doesn't match any of the four statuses) — AC 8 above is the negative control.
- The `close-without-wrapup` fix must not suppress the event for a run that is genuinely closing without a wrap-up having run — only the specific "already clean and archiving" false-positive case should be suppressed.
- Commit/push dedup keyed on `(action, hash, dir)` assumes hash+dir is a reliable uniqueness key; verify this holds even for a run that legitimately re-pushes the same commit to a different remote/branch (which should NOT be deduped away if that's a real, distinct event).
- The transcript-grep fallback in the Friction lens is a screening heuristic, not a replacement for fixing the underlying logging gaps — it should be framed as a stopgap that stays useful even after the five logging fixes land, for any future logging gap not yet caught.
