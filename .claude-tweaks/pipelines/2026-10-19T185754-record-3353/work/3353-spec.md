# 3353: ledger row parsers ignore GFM's escaped pipe, so an open row can count as unrecognized

# Reflect — staged finding 4

**Category:** tangential

Origin: reflect light from #2927

Defer-reason: tangential

## Current State

`plugin/bin/lib/wrap-up/pack.js` reads open-items ledger rows with `row.split('|')` (line 339), then takes `cells[3]` as the Status. GFM tables escape a literal pipe inside a cell as `\|`, but the split does not honor the escape. An escaped pipe in the Item cell shifts every later cell, so the Status the pack reads is a fragment of the Item text.

Observed on #2927's wrap-up, 2026-10-17: ledger row 12's Item quoted `Surface: web\|mobile\|desktop`. `wrap-up-pack.js` reported `unrecognized: 1` with value `mobile\`. The row's real status was `open`.

The dangerous case is an **open** row with an escaped pipe. It counts as `unrecognized`, not `open`, so `pack.ledger.open` under-counts. The nothing-left-behind gate's open-item enforcement then misses it, and only #2080's non-blocking warning line shows anything is wrong.

`plugin/bin/lib/wrap-up/ledger-write.js`'s `flipLedgerRow` (line 106) splits the same way. It refuses a row whose cell count is not 7, so it fails loudly: an escaped-pipe row cannot be resolved through it.

## Deliverables

1. One shared ledger-row cell splitter that treats `\|` as a literal pipe inside a cell. It splits only on unescaped `|` and keeps the escape intact when serializing back.
2. Use it in `pack.js`'s ledger count and in `ledger-write.js`'s `flipLedgerRow`. Check the repo's other ledger-table readers and point any that split rows the same way at it too.
3. Tests: a row whose Item cell holds `a\|b` counts under its real status in the pack, and `flipLedgerRow` resolves it without the shape refusal. The serialized row must keep the `\|`.

## Acceptance Criteria

- An open ledger row whose Item contains `\|` is counted as `open` by `wrap-up-pack.js`, not `unrecognized`.
- `flipLedgerRow` resolves such a row, and the written row is byte-identical apart from the Status and Resolution cells.
- `npm test` passes in full.

## Release Note

Wrap-up no longer miscounts an open ledger item whose text contains an escaped pipe, so it can't slip past the nothing-left-behind check.
