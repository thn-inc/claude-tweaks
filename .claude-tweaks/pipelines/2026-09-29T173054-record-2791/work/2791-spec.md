# 2791: Support java/ruby/dotnet manifest updaters in the local-merge release engine

Origin: ledger resolve gate

## Current State

`plugin/bin/lib/release-local/manifest.js` (the local-merge release engine, #2254) declares `UNSUPPORTED = new Set(['java', 'ruby', 'dotnet'])` — a release whose stack resolves to one of these three exits 2, naming the type and pointing at the `simple` + `extra-files` config workaround instead. `go` is tag-only and already handled. release-please itself has per-language updaters for all three (Maven `pom.xml`, Gradle `build.gradle`, Ruby `version.rb`/`.gemspec`, .NET `.csproj`/`AssemblyInfo.cs`) that the local engine does not model.

## Deliverables

Three new manifest-target kinds in `plugin/bin/lib/release-local/manifest.js` (alongside the existing `json`/`toml`/`text`/`generic` kinds): a `maven`/`gradle` version-token splice for java, a `version.rb`/`.gemspec` splice for ruby, and a `.csproj`/`AssemblyInfo.cs` splice for dotnet — each wired into `resolveTargets`/`spliceVersion`/`applyVersion` the same way the existing kinds are, each with real-fixture round-trip tests under `tests/bin-lib/release-local/`.

## Acceptance Criteria

- `manifest.js`'s `UNSUPPORTED` set no longer contains `java`, `ruby`, or `dotnet`
- Each new kind has a `spliceVersion` round-trip test against a real fixture file for that ecosystem (not a hand-typed minimal string)
- `plugin/bin/release-local.js --dry-run` against a fixture repo of each stack reports the correct planned write
- Existing `UNSUPPORTED` exit-2 behavior stays intact for any stack not covered here

## Release Note

Local-merge releases now support java/ruby/dotnet manifest bumps directly, instead of requiring the `simple` + `extra-files` config workaround.
