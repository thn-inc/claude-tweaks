# 2767: Windows full-suite baseline: classify and drive down the ~350-failure environmental set (path-separator class), and make baseline adjudication mechanical

Surface: infra

Origin: ledger resolve gate (Phase 2, `ledgerRouteRemainder`) — run `2026-09-21T213441-spec-2697-2757-2758-2759`, ledger row #2

Defer-reason: pre-existing-outside-diff

## Current State

The repo has no green full-suite datapoint on this Windows box, and the failure set is large enough
that every run adjudicates against a moving baseline by hand instead of against zero.

Measured this run:

| Point | Result |
|---|---|
| base `6d0f768a4` (batch pre-flight sweep, `node tools/run-tests.js`) | 9353 tests, 9006 pass, **342 fail**, 5 skipped, across 103 test files |
| `d5343fdf7` (#2697 Common Step 5) | 9360 tests, 9012 pass, 343 fail |
| `adb11f55e` (#2757 Common Step 5) | 9423 tests, 9073 pass, 345 fail, 106 files |
| `7d8af53a8` (#2758 Common Step 5) | 9499 tests, 9144 pass, 350 fail, 5 skipped |

Prior measurement on the same box: 292 fail @ 7948 tests (2026-09-07); 242 before that. The count
tracks corpus growth, not regressions.

The failures fall into two named environmental classes, both Windows-specific and neither caused by
any spec in this run:

1. **CRLF-sensitive prose pins** — a bare-LF literal matched against a `core.autocrlf=true` working
   copy. Four confirmed instances are tracked separately in **#2763** and have their own record; this
   row is not that one.
2. **Path-separator assertions** — fixtures expecting `/` where the code produces `\\`
   (`tests/bin-lib/skill-audit/context-cost.test.js`'s 5 path assertions are the worked example;
   `hooks-git-command`, `cloud-setup-drift-check`, `verify-scope-starter`, `archive-merged` and
   others sit in the same class).

Consequence today: every `/test` step in every run must diff its failing-file set against a
hand-maintained 103-file baseline list and cite "Pre-existing — see ledger #2" rather than reading a
green suite. That is a standing tax on every build, and it is exactly the condition under which a
real regression hides (this run had one do so — see the mis-attribution recorded as `[IL-160]`).

**Related:** #2763 (the CRLF-sensitive-prose-pins class — a separate, non-overlapping record; do not duplicate its fix here)

## Deliverables

A characterization and a drive-down plan for the Windows full-suite baseline:

- Produce the current per-file failing set and bucket every file into one of: CRLF class,
  path-separator class, genuine-flake class, or unclassified. The unclassified bucket is the finding
  — "342 failures, all environmental" is an assertion nobody has actually proven file-by-file.
- Fix the path-separator class at its root (normalize the separator at the assertion boundary, or at
  the producing helper) rather than per-fixture. The CRLF class is covered by its own record (#2763); this one
  must not duplicate it.
- Replace the hand-maintained baseline list with a committed, regenerable baseline artifact the
  `/test` step can diff against mechanically, so "at baseline" is a computed answer rather than a
  reader's judgment.

## Acceptance Criteria

Every file in the current failing set is classified, with the unclassified bucket empty or its
contents individually filed.

The path-separator class passes on Windows after the fix, quoted before/after per file — no fixture-
by-fixture `.replace('\\\\', '/')` patches.

`/test`'s baseline adjudication reads a committed baseline artifact and reports "N new, M fixed" from
it, rather than a reader comparing against prose in a ledger row.

## Release Note

## Technical Approach

Three largely-sequential phases, matching the three Deliverables: (1) a classification pass over the ~103-file failing set, grouping each file's failures by root cause rather than trusting the existing "all environmental" assertion; (2) a root-fix for the path-separator class specifically — likely a shared path-normalization helper called at the point tests compare a fixture path against a produced path, rather than patching each fixture's expected-value string; (3) a committed baseline artifact (a JSON/text file listing known-failing files, checked into the repo) that `/test`'s verification step diffs the current failing set against mechanically, replacing the current hand-maintained ledger-row list. Given the pre-existing `size:high` label, a build agent should weigh decomposing this into the three phases above as separate records before starting, rather than attempting all three in one pass — see Gotchas.
