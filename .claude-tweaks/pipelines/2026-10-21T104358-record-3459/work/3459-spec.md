# 3459: Measure plan-audit headroom the way the Read rail does — marker-stripped, CRLF-normalized bytes

Origin: #3310 whole-branch review (final review Minor 5)

Defer-reason: out-of-scope

## Current State

`plugin/bin/lib/plan-audit/checks.js`'s `headroomCheck` measures each governed `.md` file with the raw `fs.statSync(abs).size`, which counts `when:` marker lines and CRLF line endings. Since #3310 it compares that raw figure to `RAIL_BYTES` (52,500 B).

The Read rail measures differently. `rail.js`'s `skillFileRailViolations` goes through `context-cost.js`'s `measureSkills`/`measureSubFiles`, which strip marker lines and normalize CRLF to LF. `plugin/skills/build/plan-audit.md` now says the rail strips only the marker lines.

Raw bytes are always greater than or equal to measured bytes, so plan-audit never misses a breach. The cost is a false positive: a marker-heavy file, or any file in a Windows CRLF checkout, sitting slightly over `RAIL_BYTES` raw gets a blocking plan-audit stop that the `rail:` tests would pass. The raw basis predates #3310; #3310 only retargeted the number.

## Deliverables

- `headroomCheck` measures per-file bytes through `context-cost.js`'s marker-stripped, CRLF-normalized measurement, the same function the rail uses. It reuses that function rather than re-implementing the stripping.
- `tests/bin-lib/plan-audit/checks.test.js` gains a fixture that is over `RAIL_BYTES` raw but under it once marker lines are stripped. That fixture reports no breach. A CRLF variant does the same.

## Acceptance Criteria

1. A governed fixture file whose raw size is `RAIL_BYTES + 100`, carrying more than 100 B of `<!-- when: … -->` marker lines, reports no `breaches` entry.
2. The same file with its marker lines removed, and its body padded so it stays over `RAIL_BYTES`, still reports a breach.
3. A CRLF copy of a file at exactly `RAIL_BYTES` LF bytes reports no breach.
4. `npm test` passes.

## Release Note

Plan audits measure a skill file's size the same way the Read-limit check does, so marker lines and Windows line endings no longer trigger a false stop.
