# 3337: verify-scope.json: map docs/journeys/** to the journey suites instead of fail-closed full

Related: refs #3225 (PR #3279)

Origin: reflect full from #3225

Defer-reason: tangential

## Current State

`.claude-tweaks/verify-scope.json` has no rule matching `docs/journeys/**`. Its rules cover `plugin/skills/**`, `plugin/**`, `tests/**`, `tools/**`, `docs/plans/*-ledger.md`, `.claude-tweaks/pipelines/**`, `docs/superpowers/plans/**` and `docs/superpowers/specs/**`, so a journey-file delta classifies as `unmatched (fail-closed)` and forces a full-suite run.

Observed on #3225 (run 2026-10-16T190603-record-3225). The only non-bookkeeping delta after the build-phase full pass was `docs/journeys/recover-from-a-dispatch-config-deny-3225.md`. Because of that one file, the first call's test phase, the second call's auto-inserted test, and review Step 1.5's re-trigger each ran the full ~11,340-test suite. That cost roughly 95s + 384s + 292s of wall clock under load, where a scoped run of the journey-scanning suites would have covered it.

## Deliverables

- Add a `docs/journeys/**` rule to `.claude-tweaks/verify-scope.json` that selects only the suites that read journey files (the journey-scanning and journey-coverage suites), instead of falling through to fail-closed full.

- If the declaration cannot express a file-subset suite for the single `npm test` check, document why in the declaration's own comment and choose the narrowest correct mapping.

## Acceptance Criteria

1. `verify.js --scope .claude-tweaks/verify-scope.json` on a delta of only `docs/journeys/*.md` no longer reports `unmatched (fail-closed)` for that path.

2. That scoped run still executes every test file that reads `docs/journeys/` (verified by reverting a journey frontmatter field and seeing the scoped run go red).

## Release Note

Pipeline re-verification after a journey-documentation-only change now runs only the tests that read journey files, instead of the whole suite.
