# 6112: Merge green learned-skills PRs at the end of every wrap-up with a drain verb

Surface: backend
Risk-flags: auth, irreversible-side-effect
**Related:** #5649, #4366, #5179, #5884

## Current State

- `plugin/bin/learned-skills-pr.js` has `capture`, `land` and `stage` verbs. `land` opens one ready learned-skills PR per run and never merges it; `plugin/skills/wrap-up/learned-skills-pr.md` ("The PR waits for a human") and `_shared/github-pr-scan.md` item 9 keep it unarmed.
- The PRs pile up and conflict (#6088): 36 in a week, median 19h open, ten `DIRTY` at once on 2026-11-22. #6088 dropped the review floor for this PR: it should merge itself once CI is green, under the `learned-skills-auto-merge` policy key (sibling sub-issue).
- This repo's `main` has no branch protection or rulesets, `allow_auto_merge` is true, and `merge-verification` resolves `merge-when-green`; `_shared/pr-first-merge.md` Step 2.5 therefore degrades a non-`BLOCKED` PR to the `wait` row (bounded 900 s watch, then an immediate `--squash` once green), never an immediate merge. CI takes about 3 minutes.
- 14 learned-skills merge commits on `main` read `(#undefined)`: a merge title read a field its `--json` call never requested.

## Deliverables

1. A `drain` verb on `plugin/bin/learned-skills-pr.js` (args: `--run`, `--integration-branch`, `--own-pr <n>` optional). It lists every open PR whose body carries `<!-- wrap-up-skills-pr -->`, and for each:
   - **green** → merges it through `_shared/pr-first-merge.md`'s Step 2.5 gate and Step 3 squash (arms `--auto` only where Step 2.5 says arming holds), with `--delete-branch`;
   - **checks pending** → for `--own-pr` only, waits within Step 2.5's bounded watch (`MERGE_GATE_WATCH_SECONDS`, 900 s); any other pending PR is left for a later drain;
   - **`DIRTY`/conflicting** → reported as `conflicting` and left open (the rebuild is a sibling sub-issue that plugs in here);
   - **red** → left open, reported; no record labels are added (the `refs` records are not this PR's to park — tidy Step 7.5's precedent for a caller with no record).
   It prints one JSON line `{merged:[…], leftOpen:[{pr, reason}], conflicting:[…]}` and follows the `gh-api-module-pattern` project skill's CLI contract (injectable runner, exit codes in the header).
   - **Seam:** `drain.js` owns listing, classification and the one merge call; `_shared/pr-first-merge.md` Step 2.5 is the source of the semantics, and a `prose-code-twin-pin` test goes red when Step 2.5's row set changes. A PR of another run has no run dir: it skips the ci-gate write and run-scoped logging and uses only the state read and the merge call; only this run's PR logs to `decisions.md`.
   - **Green** means `statusCheckRollup` is non-empty, every entry completed with conclusion SUCCESS, NEUTRAL or SKIPPED, and the PR is open and not a draft. An empty rollup is pending, never green.
   - **Per PR, oldest first:** `mergeStateStatus` is re-read right before the merge, so a sibling turned `DIRTY` by an earlier merge in the same drain is reported `conflicting`; the merge is pinned to the classified `headRefOid` (`--match-head-commit`), and a mismatch is `leftOpen` reason `head-changed`.
   - **Scope of what it touches:** only an open PR whose head branch is `learned-skills/*` in this repository (not a fork). Any other marker-carrying PR is left alone with reason `not-learned-skills-branch`. An already merged or closed PR (a concurrent drain got there first) is a no-op.
   - **`leftOpen` reasons** are the closed set `pending`, `timeout`, `red`, `head-changed`, `not-learned-skills-branch`, `no-gh`. Without `gh` the verb merges nothing and reports `no-gh`. An unset or unreadable `learned-skills-auto-merge` resolves `false`.
   The drain acts on a PR only when all three hold: its head is a same-repository branch named `learned-skills/*` (never a fork: `isCrossRepository` false), its body carries `<!-- wrap-up-skills-pr -->`, and every changed file (`gh pr view --json files`) is under `.claude/skills/`. Any other PR, marker or not, is left open and reported in `leftOpen` with the failed condition as its reason. There is no author-identity check: anyone able to push a same-repository branch already has write access, so an author check would add nothing the branch and path checks do not. Acceptance: a test pins that a marker PR from a fork, on a non-`learned-skills/*` branch, or with a file outside `.claude/skills/` is left open with that reason and never merged.

Every value is read from fields the `--json` call requested.
3. `plugin/skills/wrap-up/learned-skills-pr.md`: when `learned-skills-auto-merge` resolves `true`, run `drain` once at the end of wrap-up (after the Review Console and `record`), passing this run's PR as `--own-pr`. Replace the "Never armed" bullet with the new rule, and log each outcome to `decisions.md` per `_shared/auto-decision-log.md` with `[lever: learned-skills-auto-merge={value}]` (`AUTO` for a merge, `SKIP` for a left-open degrade). The render shows only the `--own-pr` outcome; other PRs are logged to `decisions.md` only.

## Acceptance Criteria

- Tests for `drain` with a fake gh runner: a green marker PR is merged with subject `chore: Add learned skill updates from wrap-up of #N (#P)` and a body with `Refs #N` and no `Fixes`; a pending sibling is left untouched; a pending `--own-pr` is watched and merged when it turns green; a red PR is left open with no label writes; a `DIRTY` PR is reported `conflicting`; a PR without the marker is never touched.
- A test pins that no subject contains `undefined`.
- Green is pinned: an empty `statusCheckRollup` is left open as `pending`; a head that changes between classification and merge is left open as `head-changed`; a marker PR on a head branch outside `learned-skills/*` is never touched.
- With `learned-skills-auto-merge: false`, the wrap-up procedure runs no `drain` (conformance test over `learned-skills-pr.md`).
- In an unprotected repo, a drain never merges a PR whose checks have not all completed green (test through the Step 2.5 path).
- Each new test was seen failing with its behaviour reverted.
- `npm test -- --full` passes.

## Release Note

Wrap-up now merges its learned-skill update PRs once CI passes (when `learned-skills-auto-merge` is on), so they no longer pile up waiting for a person.

## Technical Approach

Put the drain's logic in a new `plugin/bin/lib/learned-skills/drain.js` beside `land.js`, reusing `learned-skills.js`'s deps seam. Read PR state with `gh pr view --json state,mergeStateStatus,mergeable,headRefOid,statusCheckRollup,title,body,number` (request every field the subject reads). Reuse Step 2.5's existing gate code paths rather than restating them in prose; if Step 2.5 has no callable code twin, call the documented fences from the skill prose and keep `drain` to listing, classifying and the one merge call.

## Gotchas

- Do not copy `wrap-up/residue-sweep.md`'s bare `gh pr merge --auto` at creation: in an unprotected repo it can merge before CI (#5649).
- `pr-checks.js` cannot see a merge-conflicted PR (#4366); classify `DIRTY` from `mergeStateStatus`/`mergeable`, not from checks.
- A PR that turns conflicting during the bounded watch must be reported `conflicting`, not timed out (#5179's concern).
- When #5884's merge pause lands, the drain is a plugin-driven merge and must honour it.
