# 4072: verify.js --stamp-suite passes an undeclared 'stamp-suite' mode literal to newAndFixed, unpinned by the #4040 test

**Related:** #4040, #4006

Origin: /claude-tweaks:release v6.152.0 release-gate review (staged/review-18.md, run 2026-10-21T194624-release-standalone)

Defer-reason: tangential

## Current State

#4040's fix (`plugin/bin/verify.js:779`) passes `sel ? sel.mode : 'stamp-suite'` to `newAndFixed`. `'stamp-suite'` is outside `KNOWN_SCOPES` (`full`/`scoped`/`none`/`static-only`/`tool-scoped`), while the same function treats a null `sel` as `'full'` at :828 and :882. Behaviour is correct, because `pre-existing.js:58` only tests `mode !== 'full'` and yields `fixed: null` with `fixedReason: "scope mode stamp-suite did not run every suite"`, but the literal has no shared declaration.

The #4040 regression test (`tests/bin-lib/verify/cli.test.js:1521-1537`) never reads `report.json`'s `preExistingAdjudicated`, so a regression to `'full'` would claim `fixed` files for a partial chunk and still pass. Found by the v6.152.0 release-gate review (3a reproduction pair, both agents; 3f-B on the test gap) at 002884405.

## Deliverables

1. Declare the stamp-suite mode as a named constant next to the scope-mode vocabulary, and use it at :779.
2. Extend the #4040 regression test to assert `preExistingAdjudicated.fixed === null` and the stamp-suite `fixedReason`.

## Acceptance Criteria

- verify.js has no bare `'stamp-suite'` mode literal at the newAndFixed call.
- The extended test goes red when the mode is changed to `'full'`.
- `npm test` passes.
