# 5293: Merge mode cannot tear down a dispatch-parked run: teardown-run refuses a run recorded by another session

Origin: merge mode on #4811 and #4845, session of 2026-11-13

Defer-reason: genuinely-larger

## Current State

- `/claude-tweaks:wrap-up #{n} merge` (`plugin/skills/wrap-up/merge-mode.md`, Procedure step 3) tears the run down through `cleanup-procedures-execution.md` Section C. For a worktree the session does not occupy, step 5 calls `hooks.js teardown-run --run … --merged --remote-ref-only`.
- A run parked by `/claude-tweaks:dispatch` is recorded under the dispatching session. Merge mode exists to merge it from a later session, so the caller is by construction another session.
- `teardown-run` then prints `state: refused — run recorded by another session; teardown-run does not override this` (`plugin/bin/lib/hooks/teardown-run.js`) and removes nothing. `close-run` on the same run only warns (`closing run … recorded by another session`) and proceeds.
- Observed 2026-11-13 on plugin 6.166.0, merging PR #4948 (record #4811, run `2026-11-02T065743-record-4811`) and PR #4963 (record #4845): both merges landed and both claims released, but each left its worktree, local branch, remote branch and run directory in place. The owning sessions had been dead for ten days.
- The remaining route is the reconciler, which did not archive either run in that pass (`local-behind-merge`, the main checkout having diverged from origin).

## Deliverables

- A human-confirmed merge of a parked run from a later session finishes its teardown in that session: worktree, local branch, remote branch.
- The another-session refusal still protects a run whose owning session is alive.
- `merge-mode.md` and Section C say which path a later-session merge takes, so the procedure no longer ends on a refusal it does not mention.

## Acceptance Criteria

- [ ] With the owning session dead (its recorded pid not running), a merged run's teardown from another session removes the worktree, deletes the local branch and deletes the remote branch.
- [ ] With the owning session alive, the same call still refuses and removes nothing.
- [ ] A test pins both cases, and reverting the change turns the dead-owner case red.
- [ ] `merge-mode.md` names the teardown path for a run recorded by another session.

## Release Note

Merging a parked pull request from a later session now also removes its worktree and branches.

## Technical Approach

### Key Files

- `plugin/bin/lib/hooks/teardown-run.js` — the another-session refusal
- `plugin/skills/wrap-up/merge-mode.md` — Procedure step 3, which cites the teardown
- `plugin/skills/wrap-up/cleanup-procedures-execution.md` — Section C step 5, the not-occupied worktree path
