## Technical Approach

Three decisions, each settled here so the build has none left:

1. **What is load-bearing: first-match `Ruling:`.** The existing first-match-in-order rule already splits SDD's three shapes: a `parked —` line matches `parked —` first and stays `observation`; everything else carrying `Ruling:` is a decision SDD made in lieu of stopping, and the residual final-review shape has no prefix to sniff. Over-inclusion (a pre-flight ruling the human would have waved through) costs one row in a batch table. Under-inclusion is this record's bug. Rejected: sniffing `Task <N>: Ruling:` only — it misses exactly the residual final-review class the origin finding named.
2. **Which surface: an `open` row plus a staged `sdd-ruling-{N}.md`, resolved at the console.** This is `/review`'s staged-patch pattern, not the origin record's "status `open` → mandatory per-item stop" option: `ledger-format.md`'s Phase 1 Exclusion keeps an `open` row with a staged back-reference out of the fix-exhaust and the Phase 2 drill, so no new stop appears in any mode, while the row stays `open` until the console actually resolves it — a lost or unapplied staged file blocks completion loudly instead of passing as terminal. A bare `open` row with no staged file would be wrong for the reason the origin record half-named: the resolve gate's Fix anyway / Defer / Keep / Close out vocabulary has no "ratify", and Phase 1 would try to fix a decision. A `deferred`-with-staging-path row (the other reading of `ledger-format.md` line 59) was rejected because terminal statuses are final (line 61): the row could never record the ratify-or-reverse outcome, and the ledger file is meant to be the source of truth for an item's state.
3. **Approve all = ratify; Override = ratify or reverse, never skip.** Pending review's `apply` stance already means "the default is yes", and `consoleAutoResolve` at `unattended` applies it with zero clicks — consistent with SDD's own "a wrong ruling costs rework your human partner can see and undo"; every ratification is a named line in `decisions.md` plus a retained `staged/` file. Reverse at the console cannot change code (the fix wave is closed), so it files the reversal as a born-ready record through the console's own step 7, composed the way the resolve gate's `Keep` already composes one.

The staged file is a non-patch `.md`, so `staged-patch.md`'s `git apply --check` and `Invariant:` re-derivation never apply; only its `Ledger:` back-reference and write-back idea are reused. No change to `ledger-format.md`'s status enum, to `nothing-left-behind.md`, or to `/claude-tweaks:ledger`: `open`, `accepted`, and `deferred` are existing values, Add Item already takes `open`, and `finish-console`'s `ledger` array already flips a row to any terminal status with a resolution.
