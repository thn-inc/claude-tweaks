# 2344: subagent-stop.js: `contract-violation` conflates foreign-contract and non-final replies with real violations, so the Friction lens judges on a number that is ~93% noise

Surface: infra

## Current State

`bin/lib/hooks/subagent-stop.js` logs one `contract-violation` event per graded reply that fails its
three-tier status detection. `bin/friction-events.js` returns that kind unweighted, and
`reflect/full-mode.md`'s Friction lens judges a run's proportionality from the aggregate count.

One seven-spec multi-record pipeline run produced **82** `contract-violation` events (0 carrying
`variant: 'lenient'`). Classifying every event by its own recorded `firstLine`:

| Population | Count | Shape |
|---|---|---|
| Foreign status contract | 21 (26%) | `firstLine` is exactly a verdict word from a *different* declared contract — `APPROVED`, `NEEDS_FIXES`, `ADDRESSED`, `VERIFIED` — from reviewer and fix-verification dispatches whose own prompt template declares that vocabulary |
| Non-final / mid-turn narration | 55 (67%) | `"Let me finalize the review."`, `"### Spec Compliance"`, `"Working tree clean, commit created successfully."` — turns that were never the dispatch's final reply |
| Genuine contract violation | 6 (7%) | The narration-before-the-status-word shape the contract's two `WRONG:` examples target |

So the lens reported "82 contract violations" for a run whose real contract-compliance failure count
was at most 6, against 2 `ask-user-question` stops over 201 first-parent commits.

The foreign-contract population is already named in `subagent-stop.js`'s own header as **known
false-positive source #1** — "a dispatch whose own template specifies a different status contract …
is logged here even though nothing was actually violated — the detector has no way to know a
dispatch declared a different contract" — with no record tracking it and no mechanism proposed.
#750 (closed) fixed only the literal `- **Status:** WORD` bullet shape via `LENIENT_RE`; #2265's
tier-2 lenient window matches only a contract word at the **start** of a line, so neither reaches a
reply whose first token is a verdict word belonging to another contract.

The original reflect finding read the 82 as one shape (narration before the status word) and
proposed widening detection to the first five lines. That premise does not survive measurement:
widening the window would move 6 events, not 82, and #2265's first-or-last-3-line window already
covers most of that shape. The defect is population conflation, not detector tolerance.

## Deliverables

- Let a dispatcher declare that its agents answer under a different status contract, so
  `subagent-stop.js` skips grading them — keyed off state the dispatch already writes (the
  run-dir dispatch record) rather than a new prompt convention — and stop logging known
  false-positive source #1 as a violation at all.
- Where grading still applies, separate the populations **at the event**: carry
  `variant: 'foreign-contract' | 'non-final' | 'violation'` on the logged event (alongside the
  existing `'lenient'`), so the count a reader sees is not a sum of three unrelated things.
- `bin/friction-events.js` reports the genuine violation count distinctly from the other
  variants; `reflect/full-mode.md`'s Friction lens text names the genuine count as the number it
  judges aggregate volume on, and `tests/reflect-friction-lens-vocab.test.js` covers any new
  variant names.
- Remove the resolved half of known-false-positive source #1 from `subagent-stop.js`'s header
  comment, with a recorded removal condition for anything deliberately left as a shim (CLAUDE.md's
  no-indefinite-compatibility-shim rule).

## Acceptance Criteria

1. A final reply whose first line is a verdict word from a dispatcher-declared alternate contract
   logs no `contract-violation`, or logs one carrying `variant: 'foreign-contract'` — proven by a
   unit test feeding `detectStatus`/the hook a reply beginning `APPROVED` under a declared alternate
   contract, and by an orthogonal case (an unrelated third vocabulary present) that still grades.
2. Replaying this run's 82 recorded `firstLine` values through the classifier yields a genuine
   (`variant: 'violation'`) count of at most 6; the foreign-contract and non-final variants account
   for the rest.
3. `friction-events.js --run <dir>` reports the genuine count separately, and
   `reflect/full-mode.md`'s Friction lens reads that number rather than the conflated total.
4. `node --test tests/reflect-friction-lens-vocab.test.js` passes with the new variant names, and
   `npm test` passes.

## Non-Goals

- The non-final/mid-turn population's own fix — #2041 owns scoping the check to a dispatch's
  terminal reply. This record's `variant` separation makes that population *visible*; it does not
  pre-empt #2041's mechanism.
- Widening the status-word detection window further. #2265 already covers the off-position
  line-start shape, and the measurement above shows the remaining tolerance gap is 6 events.

## Technical Approach

Two independent mechanisms, per the Deliverables above:

1. **Declared-contract skip.** Identify what state a dispatch already writes to the run
   directory that names its agents' declared status vocabulary (the dispatch record
   `subagent-output-contract.md`-following skills already write per-dispatch metadata for).
   `subagent-stop.js` reads that state for the dispatch a graded reply belongs to and skips
   grading entirely when the declared contract differs from the harness's own three-tier
   vocabulary — this is a detection-time skip, not a post-hoc reclassification, so it also stops
   the event from being logged at all (cleaner than tagging it `foreign-contract` after the
   fact, per the Deliverables' own "stop logging ... as a violation at all" wording).
2. **Variant tagging for the remainder.** For replies that do get graded, extend the logged
   event shape with `variant: 'foreign-contract' | 'non-final' | 'violation'` (alongside the
   existing `'lenient'` value from #2265/#750) — this variant reflects the classification
   observed in this record's own measurement table, applied going forward. `friction-events.js`
   aggregates and reports the `'violation'` count separately from the others;
   `reflect/full-mode.md`'s Friction lens text is updated to read that field instead of the
   conflated total.

### Key Files

- `bin/lib/hooks/subagent-stop.js` — declared-contract skip logic, `variant` field on the logged
  event, header-comment update removing the resolved half of known false-positive source #1
- `bin/friction-events.js` — report the `'violation'` variant count distinctly from the others
- `reflect/full-mode.md` — Friction lens reads the genuine-violation count, not the conflated
  total
- `tests/reflect-friction-lens-vocab.test.js` — cover the new variant names

## Gotchas

- Do not conflate this record's `variant` separation with #2041's own fix (scoping the
  three-tier check to a dispatch's terminal reply only) — they are complementary, not
  overlapping: this record makes the non-final population *visible and separately counted*; it
  does not stop it from being logged as a distinct variant.
- The declared-contract skip must be keyed off state the dispatch itself already writes, not a
  new prompt-authoring convention — inventing a new declaration mechanism here would mean every
  existing dispatch template needs updating just to keep working correctly.
- When removing the resolved half of `subagent-stop.js`'s header-comment note about known
  false-positive source #1, keep whatever part (if any) still applies after this fix — don't
  delete the whole comment if only part of the false-positive source is actually resolved.
