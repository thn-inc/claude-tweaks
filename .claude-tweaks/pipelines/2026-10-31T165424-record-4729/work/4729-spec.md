# 4729: dispatch resume: name close-run when the conflicting bound run belongs to this session

Verified-as-of: 67d25419ec91f5d8909650c8bdbfb85c0d1db928

Origin: SDD ruling reversed at Review Console

Defer-reason: genuinely-larger

## Current State

SDD ruling 14 on record #4588 (staged `sdd-ruling-14.md`, build ledger row 17) deferred a residual from the targeted fix's re-review with no Defer-reason, and it was reversed at the Review Console.

The residual: `plugin/bin/dispatch-resume.js`'s bound-run scan (the loop over `listRunDirsWithState`, around line 342) treats a conflicting bound run whose `owner.sessionId` equals the current `CLAUDE_CODE_SESSION_ID` as never proven dead (`ownSession`, line 350). That is correct, because a second resume can share the session id (#965). But the scan then falls through to the generic `concurrent-resume` line: "another dispatch resume may be running; stop this one, then run /claude-tweaks:dispatch resume #N once that run ends". The scenario: a resume crashes between Step 6's bind (`record-worktree --dispatch`) and Step 6a's `close-run` in `plugin/skills/dispatch/resume.md`, and is retried in the same session. In that case no other run is live, so "once that run ends" never comes true, and the only way out is a hand-run `node {plugin-root}/bin/hooks.js close-run --run {dir}`, which the line does not name.

An owner probe cannot tell a same-session leftover from a live same-session sibling, so the line cannot pick a verdict. It can name both readings and the remedy for each, as the `unknown-owner` branch beside it already does.

## Deliverables

1. In `plugin/bin/dispatch-resume.js`'s bound-run scan, give an own-session conflicting bound run its own `concurrent-resume` line that names both readings: another resume in this session may still be running (stop it, then re-run), or a crashed earlier resume left the run open (close it with `node "{HOOKS_JS}" close-run --run "{dir}"`, then re-run `/claude-tweaks:dispatch resume #N`). Keep the reason `concurrent-resume` and never prove the run dead.

2. Add a `tests/bin-lib/dispatch/dispatch-resume-cli.test.js` case: an own-session non-terminal run bound to the worktree yields that line with the `close-run --run` command for its dir.

3. If `docs/journeys/resume-a-stalled-dispatched-build-4588.md` or `plugin/skills/dispatch/resume.md` quote the concurrent-resume line, update them.

## Acceptance Criteria

- With a non-terminal run dir whose `owner.sessionId` equals the CLI's session id and whose `worktree` is the stalled worktree, `dispatch-resume.js --issue N` refuses `concurrent-resume` with a line containing `close-run --run "{that dir}"`.

- A conflicting run owned by a different, provably live session still gets today's generic line, unchanged.

- `npm test` passes.

## Release Note

Retrying dispatch resume in the same session after a crash mid-resume now names the close-run command that clears the leftover run, instead of telling you to wait for a run that will never end.
