# 3105: writeStagedItem allocate:true race test intermittently lands two workers on the same file

Origin: CI run 38058858785 on PR #3100 (#3092) — `npm test` on ubuntu, failed once, passed on re-run with no code change

Defer-reason: tangential

## Current State

`tests/bin-lib/stage-item/write.test.js:142` spawns six Node processes that all call `writeStagedItem({ id: 'race-deviation-1', allocate: true })` against one run dir and asserts every worker lands on a distinct file. On CI run 38058858785 (head 00db92e47, ubuntu) it failed at `:169` — `every worker must land on a distinct file` — and passed on the re-run of the same commit. `plugin/bin/lib/stage-item/write.js:112-150` allocates with exclusive `wx` creates and retries on EEXIST, so a lost update should be impossible. Either the allocator has a real race the reading misses, or the test's stdout capture drops a worker's path. Cause unidentified.

## Deliverables

- Reproduce the failure (loop the test under load) and capture each worker's stdout, stderr and resulting file.
- Fix the confirmed cause, in the allocator or in the test's capture.

## Acceptance Criteria

- [ ] The race test passes 200 consecutive runs under concurrent load.
- [ ] The record of the confirmed cause names whether staged proposals could actually be lost.

## Release Note

No user-visible change, unless the cause is a real lost update in staged proposals.

## As-built deviations (build Common Step 4.5)

- **Confirmed cause (AC2):** the defect was in the test's capture, not the allocator. The test resolved each worker on `'exit'`, before the child's stdout pipe drained, so under load a worker's path read as `''` and was filtered out. **Staged proposals were never lost.** In every reproduced failure (Linux `node:20`, 14 of 300 harness iterations, and 34 of 600 in a later run), `staged/` held 6 distinct files on disk. The `wx` allocator in `plugin/bin/lib/stage-item/write.js` is correct and is unchanged.
- **Beneficial:** the test now also asserts the on-disk `staged/` count first, before the stdout capture. A future failure therefore names a lost update and a capture miss differently.
