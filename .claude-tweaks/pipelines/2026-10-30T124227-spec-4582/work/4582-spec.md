# 4582: Review Console settles nothing for a finding whose path holds characters outside [A-Za-z0-9_./-]

Origin: wrap-up leftover routing from #4563

Defer-reason: tangential

## Current State

`plugin/bin/lib/console/resolve.js` keys a finding as `{lens}|{path}:{line}` with the path class `[A-Za-z0-9_./-]+\.[A-Za-z0-9]+` — in `findingKey` and in #4563's `debateConvergedKeys`. A finding at `packages/@scope/x.ts:4`, `app/[id]/page.tsx:9`, or a path holding a space yields no key, so no tiebreak verdict, Confirmed line, or converged-positive debate ever supersedes its STAGED line: it resolves keep-staged and blocks archival until a human acks it. It fails safe (never dropped). Deferred from #4563 (ledger row 3) because widening it changes the shared key shape every #3772/#3949 route reads.

## Deliverables

Widen the path class used by `findingKey`, `lineKeys`, and `debateConvergedKeys` to accept `@`, `[`, `]`, `+` and other path-legal characters, keeping the trailing `.ext:line` anchor so sentence punctuation is never captured.

Keep `tiebreak.js`'s verdict-line regexes in step, so a verdict for such a path still parses and keys identically.

## Acceptance Criteria

A STAGED line for `packages/@scope/x.ts:4` followed by a tiebreak confirmed verdict for the same lens and location produces no Low-confidence item.

A converged-positive debate line naming `app/[id]/page.tsx:9` supersedes that finding's STAGED line.

Every existing `tests/bin-lib/console/resolve.test.js` test still passes.

## Release Note

Review findings in files whose paths contain characters such as `@` or brackets are now settled at the Review Console like any other.

### Key Files

- `plugin/bin/lib/console/resolve.js` — widen the finding-key path class
