# 3049: review: reproduction pairs anchor the same coverage gap at the test vs the code, so neither reproduces

Surface: infra

## Current State

`/claude-tweaks:review`'s Step 3 dispatches each lens as a reproduction pair at `medium` effort and above (`plugin/skills/review/step3-lens-dispatch.md:39`, 3f Test Quality included). `categoriseReproduction` (`plugin/bin/lib/coordination.js:285`, CLI `plugin/bin/review-coordination.js categorise-reproduction`) confirms a finding only when both agents report it at the same location: `sameLocation` with `LINE_TOLERANCE_REPRODUCTION` (exact path, line ±2), then a substance check. Findings with no same-location partner land `unconfirmed`.

The dispatch prompt already carries one anchoring instruction outside the byte-identical Calibration/Output block: `Path:Line` must be file-native, never bundle-relative (`step3-lens-dispatch.md:74`). It has no rule for where a coverage finding is anchored. The 3f checklist (`step3-lens-dispatch.md:205-214`) asks about missing edge-case and error-path tests and weak tests, so the same coverage gap can legitimately be anchored at the test file or at the production line.

Observed (reporter, plugin 6.136.0, `medium` effort): both 3f agents found the same gap ("production guard X is only pinned by a Spark-gated test, so CI never exercises it"). One anchored it at the test's decorator line, the other at the unguarded production line, so neither reproduced. All six 3a/3f findings landed `unconfirmed` and were confirmed only through the reviewer's direct-verification override.

## Deliverables

1. Add a coverage-finding anchor rule to `step3-lens-dispatch.md`'s dispatch-prompt instructions, next to the file-native `Path:Line` rule at `:74` and outside the byte-identical Calibration/Output-template block. A missing-or-weak-test finding is anchored at the production line the test should pin, never at the test file. A finding about a test's own defect (refactor-coupled, non-discriminating, polluting) stays anchored at the test.
2. Restate the rule as one bullet in the 3f Test Quality checklist (`step3-lens-dispatch.md:205`) so the lens agent sees it where coverage questions are asked.
3. Leave `categoriseReproduction`'s matching unchanged (see Gotchas).

## Acceptance Criteria

- `step3-lens-dispatch.md` states the coverage anchor rule in the dispatch-prompt instructions, with both halves: coverage gap → production line; test-quality defect → test line.
- The 3f checklist carries the same rule as a bullet.
- The byte-identical Calibration/Output-template block is unchanged, so any conformance test pinning it to `_shared/criteria-review-quality.md` still passes.
- `npm test` passes.

## Release Note

Make review's test-quality agents anchor coverage findings at the code under test, so two agents finding the same gap now confirm each other.

## Technical Approach

A prompt-side rule fixes the cause: the two agents disagree on where to anchor, not on what they found. The reporter's optional matcher relaxation (treat a test-file finding whose evidence names the other side's `path:line` as same-location) was considered and not adopted here. It loosens a deterministic matcher on free-text evidence, which raises the risk of confirming coincidental pairs, the failure mode `categoriseReproduction`'s #1980 substance check exists to prevent. If anchor drift still shows up in practice after this rule ships, the matcher change can be revisited with that evidence.

### Key Files

- `plugin/skills/review/step3-lens-dispatch.md` — coverage anchor rule in the dispatch-prompt instructions and the 3f checklist

## Gotchas

- Keep the rule out of the byte-identical Calibration/Output-template block (`step3-lens-dispatch.md:107` onward). That block is the canonical copy of `_shared/criteria-review-quality.md` and must stay byte-identical.
- The reporter's second unconfirmed pair (same location, different wording) is a substance-match question, not an anchor question. This rule does not address it.
- The rule must be phrased so a lens agent can apply it without seeing sibling files. Dispatched agents only see their prompt.

## What happened

At `medium` review effort, both agents of the 3f (Test Quality) reproduction pair independently found the same issue — "the production guard X is only pinned by a Spark-gated test, so CI never exercises it" — but anchored it at different `Path:Line`s: one at the gated test's decorator line in the test file, the other at the unguarded production line it should pin. `categorise-reproduction` matches on `path` exact + `line ±2`, so both entries came back `unconfirmed`, as did a second shared finding where the agents wrote different wording. All six 3a/3f findings landed `unconfirmed` and were only confirmed through the reviewer's direct-verification override.

## Expected

Two agents that found the same coverage gap should reproduce it.

## Suggested fix

In the canonical lens prompt (3f especially), state the anchor rule for coverage findings: anchor a missing-or-weak-test finding at the production line the test should pin, never at the test. Optionally let `categorise-reproduction` treat a finding pair as same-location when one side's `path` is a test file whose evidence names the other side's `path:line`.
