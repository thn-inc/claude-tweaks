# 4139: release --as anchor still requires exact HEAD == origin, unlike Step 3 after #4012

Origin: reflect hindsight from #4012

Defer-reason: tangential

## Current State

`/claude-tweaks:release` Step 3 accepts a main checkout whose only unpushed commits are run-dir archive commits (#4012). `plugin/skills/release/execute.md`'s `--as {version}` path (the Release-As override commit, execute.md:96-111) still asserts `git -C "$RUN_ROOT" rev-parse HEAD origin/{branch}` are equal and stops `failed` otherwise. A release with `--as` on a checkout carrying `[reconcile] archive run` commits therefore passes Step 3 and fails at Step 5. The Release-As commit would also push those archive commits along with it.

## Deliverables

execute.md's `--as` anchor applies the same acceptance rule as Step 3: on `{branch}`, 0 behind, tree identical to `origin/{branch}` outside `.claude-tweaks/pipelines/`.

The Release-As commit is pushed without carrying unpushed archive commits, or the stop line says why it cannot be.

## Acceptance Criteria

A `--as` release on a checkout whose only unpushed commits are `[reconcile] archive run` commits commits and pushes the Release-As override, or stops naming the archive commits and their recovery, and never stops on the bare sha inequality.

A conformance test runs the `--as` anchor against fixture repos for the accepted and stopping cases.

`npm test` passes.

## Release Note

`/claude-tweaks:release --as` no longer refuses a main checkout that only carries unpushed run-archive commits.
