# 3894: Windows regression: 1 test file(s) newly failing after a865b2ffa

Surface: infra

## Current State

The post-merge Windows check on commit a865b2ffa (merged PR #3808) reported `tests/materiality-floor-conformance.test.js` newly failing on "digest-sweep.md reads trusted comment objects with the Trusted-authors jq pasted verbatim (#3766)". The failing assertion is `promotion.includes('never reduce\nthem to bare bodies first')`.

Re-checked against current `main`, the failure is still live and reproduces on macOS under a CRLF-read simulation: exactly this one test fails, 54 pass. Root cause: the file's `read` helper (line 16) uses a raw `fs.readFileSync(path.join(REPO_ROOT, rel), 'utf8')`, and this assertion embeds a literal `\n` across a line break. A Windows `core.autocrlf=true` checkout holds that break as `\r\n`. The file's other 54 assertions carry no newline-spanning literals, which is why only this one failed.

`tests/helpers/read-skill.js` exports `readText(absPath)` (#2763), the shared EOL-normalizing read for this case.

**Related:** #3702, #3703, #3742, #3751, #3776, #3797, #3802, #3857, #3871, #3886, #3890

## Deliverables

1. `tests/materiality-floor-conformance.test.js` — the `read` helper (line 16) returns `readText(path.join(REPO_ROOT, rel))` from `./helpers/read-skill` instead of a raw `fs.readFileSync`.

## Acceptance Criteria

A one-line swap in the file's single `read` helper. All tests read through it, so the newline-spanning literal matches on any checkout with no assertion change.
