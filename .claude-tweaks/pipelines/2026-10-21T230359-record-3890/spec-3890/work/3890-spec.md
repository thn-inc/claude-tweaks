# 3890: Windows regression: 1 test file(s) newly failing after 259be0521

Surface: infra

## Current State

The post-merge Windows check on commit 259be0521 (merged PR #3833) reported `tests/routine-fleet-security-hardening.test.js` newly failing on "AC1.1: composition table has a Vertical finder row whose focus override is security-hardening", with `no "## Fleet composition table" heading`.

Re-checked against current `main`, the failure is still live and reproduces on macOS under a CRLF-read simulation: 3 of the file's 6 tests fail (AC1.1, AC1.2, and the existing-rows cron pin), 3 pass. Root cause: the file's read helper (line 10) uses a raw `fs.readFileSync(path.join(ROOT, rel), 'utf8')`. On a Windows `core.autocrlf=true` checkout, the heading lookup and the table-row parsing downstream of it never match `\r`-terminated lines. The Windows filer reported only the first failure.

`tests/helpers/read-skill.js` exports `readText(absPath)` (#2763), the shared EOL-normalizing read for exactly this case.

**Related:** #3702, #3703, #3742, #3751, #3776, #3797, #3802, #3857, #3871, #3886, #3894

## Deliverables

1. `tests/routine-fleet-security-hardening.test.js` — the read helper (line 10) returns `readText(path.join(ROOT, rel))` from `./helpers/read-skill` instead of a raw `fs.readFileSync`.

## Acceptance Criteria

1. No raw `fs.readFileSync` of a markdown file remains in `tests/routine-fleet-security-hardening.test.js`.
2. Under the CRLF-read simulation, all 6 tests in the file pass. Before the fix, 3 fail.
3. `node --test tests/routine-fleet-security-hardening.test.js` is green on Linux/macOS.
4. The next post-merge Windows check (`.github/workflows/windows-regression.yml`) no longer lists this test file.

## Release Note

Fix a Windows-only failure in the routine fleet security-hardening test caused by CRLF line endings.

## Technical Approach

A one-line swap in the file's single read helper. Every test reads through it, so all three failing tests are fixed at once with no assertion changes.

### Key Files

- `tests/routine-fleet-security-hardening.test.js` — read helper routed through `readText`
- `tests/helpers/read-skill.js` — `readText` helper reused (read-only)
