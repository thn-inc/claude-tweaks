# 2783: friction-events: an ad-hoc EnterWorktree session's guard refusals are never logged (no ad-hoc run dir minted)

Surface: infra

**Related:** #2813 — a near-identical finding (same `stampAdHocRunDir` mechanism, same symptom: `friction-events.js` returns `[]` for an ad-hoc `EnterWorktree` session with real guard denials, no run dir ever stamped) filed independently from a different session. Read both before building either — they likely share one root cause and one fix; building both separately risks duplicate or conflicting diagnosis. A human should decide whether to absorb one into the other before dispatch.

## Current State

A user-requested fix implemented in an `EnterWorktree` worktree (no `/build`/`/flow`) hit two worktree-isolation guard refusals, but `/wrap-up`'s Friction lens saw `[]` from `friction-events.js` — no `*-adhoc-standalone` run dir was ever minted, so nothing had anywhere to log to.

**Affected component:** `bin/lib/hooks/post-tool-use.js` (`stampAdHocRunDir`), read side `bin/friction-events.js`; documented in `skills/reflect/full-mode.md` "Ad-hoc-session fallback (#500, widened #1333)".

**Repro steps:**
1. In a `worktree-always` project, start a session in the main checkout and call `EnterWorktree` (name=...) at the user's request — no pipeline skill running, so no `PIPELINE_RUN_DIR`.
2. Inside the worktree, run a plain Bash command the isolation guard refuses as "cannot be shown not to be git" — e.g. `sed -n 100,150p $d/file.md` with `$d` set earlier in the same command, or `gh run view --job "$(cat /tmp/id)"`. Two such refusals occurred in this session.
3. Merge the PR, `ExitWorktree remove`, then run `/claude-tweaks:wrap-up` from the main checkout.
4. `ls .claude-tweaks/pipelines/*adhoc*` → nothing. `node bin/friction-events.js --run <wrap-up run dir>` → `[]`.

**Expected vs. actual:**
Expected: per `full-mode.md`, the first `PostToolUse` after `EnterWorktree` mints `{ts}-adhoc-standalone` with the worktree path, the guard's refusals append `wd-guard-refusal`/`gate-denial` events there, and `friction-events.js` finds that dir back (`findRunsByWorktreePath`) and unions its events.
Actual: no ad-hoc dir exists at all, so the refusals were never logged and the Friction lens reported a clean run that was not. Two things worth checking: whether `stampAdHocRunDir` fires on the harness's own `EnterWorktree` trigger (the cwd moved without a `git worktree add`), and whether this guard message ("This session is isolated in the worktree … Refusing to run it — a worktree-isolated session's git operations must target its own worktree") is among the logged event types at all. Separately, the read side keys on the recorded worktree path, which no longer resolves once `ExitWorktree remove` ran before wrap-up — the ordinary order for ad-hoc work — so even a minted dir may be unreachable by then.

## Deliverables

Diagnose and fix, per the two things worth checking above:
1. Confirm whether `stampAdHocRunDir` fires on the harness's `EnterWorktree` trigger (cwd moved without a `git worktree add`) and, if it doesn't, fix the trigger condition so it does.
2. Confirm whether the worktree-isolation guard's refusal message is among the logged event types `stampAdHocRunDir`'s companion logging actually captures — if not, add it.
3. Fix (or document as an accepted limitation) the read-side gap where `friction-events.js`'s `findRunsByWorktreePath` can no longer resolve a minted ad-hoc dir once `ExitWorktree remove` has already run before wrap-up — the ordinary sequence for ad-hoc work.

## Acceptance Criteria

- Reproducing the repro steps above (an `EnterWorktree` session with a plain-Bash guard refusal, then `ExitWorktree remove`, then `/wrap-up`) results in `friction-events.js` returning the guard-refusal event(s), not `[]`.
- If deliverable 3's read-side gap is a genuine, currently-unfixable limitation, it is documented explicitly in `skills/reflect/full-mode.md`'s Friction Lens section rather than left as silent data loss.
- `npm test` passes in full after the change.

## Release Note

Fixed friction logging so guard refusals in a manually entered worktree are recorded.

Start by reading `stampAdHocRunDir` in `bin/lib/hooks/post-tool-use.js` to confirm its actual trigger condition against the documented one (`skills/reflect/full-mode.md`'s "Ad-hoc-session fallback") — this determines whether Deliverable 1 is a real gap or the mechanism fires correctly and the loss happens elsewhere. Given #2813's independent, near-identical finding (see Related above), coordinate root-cause investigation with that record rather than re-deriving it twice — whichever record's build lands first should close out both if the root cause and fix genuinely cover both repro cases.

- `plugin/bin/friction-events.js` — the read side, including `findRunsByWorktreePath`
- `plugin/skills/reflect/full-mode.md` — the documented "Ad-hoc-session fallback" behavior this record's fix must match (or the section to update if a limitation is accepted instead)

## Gotchas

- This record and #2813 both describe the same symptom from two independent sessions — strong signal the root cause is real and reproducible, not session-specific noise. Don't diagnose in isolation from #2813's own finding.
- The `ExitWorktree remove`-before-`wrap-up` ordering (Deliverable 3) may turn out to be a structural limitation rather than a bug — if genuinely unfixable within this record's scope, document it rather than leaving AC 2 unaddressed.

## As-built notes (build Common Step 4.5 — Beneficial deviation)

Key Files named three files; the build had to reach further, by design. Fixing Deliverable 1 means an `-adhoc-standalone` run dir is now minted for nearly every session's first `EnterWorktree` (every `/flow` run included), and several consumers treated such a dir as a pipeline run: `checkTeardownGate` denied the session's own `ExitWorktree(remove)`; `collectStaleRuns` let ad-hoc dirs crowd real runs out of the stale-run banner; `resolveRun`'s fallback arms, `close-run`'s implicit `--run`, and `reap-merged.js`'s reap trail could land on one; `hasDistinctOwnedRun` downgraded the IL-131 record-worktree deny. Each now skips ad-hoc dirs (`context.js` `isAdHocRunDir`), with a regression test. `resolveRun`'s session arm prefers an older formal run over a newer ad-hoc one only when `classifyOwnership` proves it `'mine'`. Deliverable 2 was implemented as a new `PostToolUseFailure` hook (`post-tool-use-failure.js`) after a headless probe showed the harness's isolation refusal fires that event with the refusal text in `error`. Deliverable 3 was fixed (session-id union in `friction-events.js`, skipping live-worktree dirs), with the residual session-id-change and removed-sibling limitations documented in `reflect/full-mode.md`.
