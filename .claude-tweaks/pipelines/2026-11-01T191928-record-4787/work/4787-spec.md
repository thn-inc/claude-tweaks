# 4787: Stash guard: report a store that wrote nothing without a recover command

Origin: ledger resolve gate (wrap-up of #4559, ledger row 7, SDD ruling 4)

Defer-reason: genuinely-larger

## Current State

When `git stash store` writes nothing because the same commit is already at `stash@{0}`, plugin/bin/stash-guard.js now truthfully reports the entry as a `restoreFailed` outcome (error "same commit already at stash@{0} — git stash store wrote nothing"). Its stderr line, its `FAILED` decisions.md line and the `restoreFailed[].command` field still offer "recover with: {command}", which is another no-op in that state (a reproduction: stack [x, y, x], drop stash@{2}, then compare --restore). No stash content is lost; only a duplicate reflog entry is missing. The command text is also consumed verbatim by plugin/skills/build/handoff-template.md ("restore failed; recover with: {command}") and by the stash-guard stanza in plugin/skills/build/dispatch.md, whose wording is pinned by tests/dispatch-no-stash-conformance.test.js, so a CLI-only reword would leave the handoff and the stanza still telling the reader to paste it. Found by the final whole-branch review of #4559 (SDD ruling 4, ledger row 7).

## Deliverables

- [ ] In `plugin/bin/stash-guard.js`, report the nothing-written case without a recover clause: reword the error to "same commit still at stash@{0}; nothing to recover" and drop the "recover with" text from the stderr line and the `FAILED` line, deciding what `restoreFailed[].command` holds for that case (absent or null).
- [ ] Update the "restore failed; recover with" slot in `plugin/skills/build/handoff-template.md` and the stash-guard stanza in `plugin/skills/build/dispatch.md` for an entry with no command.
- [ ] Update the tests that pin the old wording (`tests/stash-guard.test.js` probe A cases and `tests/dispatch-no-stash-conformance.test.js`), each shown red by reverting its source change.

## Acceptance Criteria

- [ ] A temp-repo test for stack [x, y, x] with `stash@{2}` dropped, then `compare --restore`, asserts the stderr line and the `FAILED` line contain no "recover with" and the entry is still reported as failed.
- [ ] The handoff template and the dispatch.md stanza name the no-command case.
- [ ] `node --test tests/stash-guard.test.js tests/dispatch-no-stash-conformance.test.js` passes.

## Release Note

A stash restore that cannot change anything now says there is nothing to recover instead of printing a command that does nothing.

## Technical Approach

### Key Files

- `plugin/bin/stash-guard.js` — report the nothing-written case without a recover clause
- `plugin/skills/build/handoff-template.md` — handle an entry with no command
- `plugin/skills/build/dispatch.md` — handle an entry with no command in the stanza
- `tests/stash-guard.test.js` — update the probe A wording pins
- `tests/dispatch-no-stash-conformance.test.js` — re-pin the stanza text
