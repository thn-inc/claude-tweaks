# 3512: Make ledger rows pipe-safe — a `|` in an Item or Resolution cell breaks finish-console's step-3 flip

Origin: SDD controller final-review finding on #3401 (run 2026-10-17T190411-spec-3401)

Defer-reason: genuinely-larger

## Current State

The open-items ledger is a 5-column markdown table (`_shared/ledger-format.md`). `plugin/bin/lib/wrap-up/ledger-write.js`'s `flipLedgerRow` splits a row on `|` and throws "expected 5-column shape" when a cell's own text contains a pipe. `plugin/bin/wrap-up-engine.js finish-console` runs its ledger flips as step 3, after steps 1-2 (decision log + memory/upstream writes) have already completed, so a `|` inside an Item or Resolution cell fails the console's Approve-all mid-way and leaves a partially-flipped ledger for the operator to reconcile. Until #3401 no SDD-carried row was flipped mechanically; #3401 now appends `SDD ruling — {one-liner}` rows whose text is copied from `progress.md` `Ruling:` lines, which commonly quote regex alternations (`a|b|c`) and table fragments — so the first pipe-bearing ruling that reaches the console breaks finish-console step 3. Nothing escapes or rejects a `|` at append time today (`/claude-tweaks:ledger` Add Item, `review/step3-routing.md`'s row append, `build/dispatch.md`'s carry-forward). Found by #3401's whole-branch review (Minor, pre-existing hazard in the ledger code, surfaced by the new producer).

## Deliverables

Pick one mechanism and apply it at every ledger-row writer: escape `|` as `\|` on append (markdown-table-safe) and unescape on read in `bin/lib/wrap-up/pack.js`'s `parseLedger` and `ledger-write.js`'s `flipLedgerRow`, OR reject a pipe-bearing cell at append time with a stated substitution rule (e.g. `∣` U+2223). State the chosen rule once in `_shared/ledger-format.md`'s Format section.

`flipLedgerRow` tolerates an escaped pipe inside a cell (no longer throws on a 5-column row whose cell text carries `\|`).

`build/dispatch.md`'s carry-forward and `review/step3-routing.md`'s append cite the rule rather than restating it.

Tests: `tests/bin-lib/wrap-up/ledger-write.test.js` (or the suite that owns `flipLedgerRow`) gains a case flipping a row whose Item text carries a pipe, plus a round-trip through `parseLedger`; a `finish-console` test with such a row in the payload completes all three steps.

## Acceptance Criteria

A ledger row whose Item cell contains `a|b` (written through the chosen rule) is flipped by `wrap-up-engine.js finish-console --approve-all` without a step-3 failure, and `parseLedger` reads it back as 5 columns with the original text.

`node --test` on the owning suites passes, and the new pipe case fails against the pre-change `ledger-write.js` (prove via `git show HEAD:...` to a temp path, never `git stash`).

`npm test` passes in full.

## Release Note

A ledger item whose text contains a vertical bar no longer breaks the wrap-up Review Console's Approve-all midway.

## As-built notes (Common Step 4.5 — Beneficial deviations)

- Mechanism chosen: escape `|` as `\|`, implemented once in a new codec `plugin/bin/lib/wrap-up/ledger-cells.js` (`escapeLedgerCell` / `unescapeLedgerCell` / `splitLedgerRow` / `ledgerRowCells`) rather than inline in `pack.js` and `ledger-write.js` — one split rule for every reader and writer.
- A third code reader, the statusline's `findOpenLedger` (`plugin/bin/claude-tweaks-statusline.js`), also split rows on a raw `|`; it now uses `splitLedgerRow` so it still counts an open row whose Item carries an escaped pipe.
- `flipLedgerRow` also collapses line breaks in the Resolution it writes to one space — a raw newline split the row across lines, the same corruption class as the pipe (whole-branch review Minor 1).
- Beyond the two named prose sites, `/claude-tweaks:ledger`'s Add Item and Update Item cite the rule, `_shared/ledger-format.md` states that `finish-console`'s payload `resolution` is passed raw, and `docs/plugin-structure.md` lists the codec.
- Release Note reworded on the live record (whole-branch review Minor 4): "A ledger item whose text escapes a vertical bar as `\|` no longer breaks the wrap-up Review Console's Approve-all midway." The snapshot above keeps the original wording.
