# 3496: Route build's SDD final-review capture through write-run-artifact.js so a worktree session can write it

Origin: /flow #3044 build (run 2026-10-17T221758-record-3044) — whole-branch review follow-up

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/skills/build/dispatch.md`'s "Persist SDD's final whole-branch review before Finish (#3386)" sentence directs `/superpowers:subagent-driven-development` to write `$PIPELINE_RUN_DIR/sdd-final-review.md` directly. `$PIPELINE_RUN_DIR` is anchored at the main checkout (`_shared/pipeline-run-dir.md`), so in a worktree-isolated session the harness refuses that Edit/Write — the same refusal #3044 fixed for `sdd-dispatch-sample.txt` in the same paragraph.

#3044 added the allowlisted sanctioned writer `plugin/bin/write-run-artifact.js` (`--run <run-dir> --name <artifact> (--file <src> | --delete)`, allowlist `ARTIFACT_NAMES` in `plugin/bin/lib/run-artifact/write.js`, currently only `sdd-dispatch-sample.txt`). The #3386 sentence was left untouched as out of scope.

## Deliverables

- [ ] Add `sdd-final-review.md` to `ARTIFACT_NAMES` in `plugin/bin/lib/run-artifact/write.js` (and its unit/CLI tests).
- [ ] Rewrite the #3386 sentence in `plugin/skills/build/dispatch.md` the way #3044 rewrote the AC-forwarding sample: resolve a session-tmp scratch path with a plain `session-tmp-resolve.js` call (no eval), Write the review there, and persist it with `node "${CLAUDE_PLUGIN_ROOT}/bin/write-run-artifact.js" --run "$PIPELINE_RUN_DIR" --name sdd-final-review.md --file "{sample-path}"`.
- [ ] Update `tests/build-sdd-final-review-capture.test.js` pins to the new wording.
