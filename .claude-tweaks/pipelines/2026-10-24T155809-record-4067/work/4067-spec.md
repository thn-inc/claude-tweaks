## Current State

#3939 moved the 12 pinned wall-clock budgets from `tests/` to `perf/`, run by `npm run test:perf`. `.github/workflows/test.yml:37` runs only `npm test`, and no workflow under `.github/` invokes `test:perf`, so the budgets now run only when someone remembers to (the 3939 spec's AC2.1 is a manual idle-machine run; `docs/plugin-structure.md:73` records that as intended).

Two behaviours lost coverage in the move. The `candidates-scale-readiness` "linearity" tests in `tests/` dropped their elapsed bound, so a quadratic-backtracking regression goes slower without going red. The "waits for a held lock" behaviour of `plugin/bin/lib/model-profiles/session-failures.js:76` is asserted nowhere: `tests/bin-lib/model-profiles/session-failures.test.js` checks only read/rename order, and a mutation (`return false;` before line 76) stayed green against `perf/session-failures-lock-wait.test.js` too, because its `< 2000` bound passes a no-wait implementation.

Found by the v6.152.0 release-gate review (3c-A and 3f-A independently; 3f-B concurring with the mutation evidence) at 002884405.

## Deliverables

1. Run `npm run test:perf` automatically somewhere it cannot flake a PR: a scheduled or `workflow_dispatch` job, or a non-blocking job, reporting failures visibly.
2. Assert the session-failures lock wait behaviourally in `npm test` (e.g. a held lock released after a delay is observed as waited-on), independent of wall-clock bounds.

## Acceptance Criteria

- A workflow under `.github/workflows/` invokes `npm run test:perf` on a schedule or manual dispatch.
