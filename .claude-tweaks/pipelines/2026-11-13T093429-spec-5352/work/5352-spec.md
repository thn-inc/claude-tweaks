# 5352: Remove www. and bare github.com issue URLs from driver worker text in linear time

Origin: SDD ruling ratified at Review Console (#5269, sdd-ruling-9)

Defer-reason: genuinely-larger

## Current State

Record #5269 (PR #5285) narrowed the driver neutralizer `plugin/bin/lib/driver/events.js` `neutralize()`: a closing keyword is removed only when the token after it carries a reference marker, and references are removed to a fixed point.

SDD ruling 9 (ratified at the #5269 Review Console) returned `URL_REF` to scheme-only issue/PR URLs with a letters-only left boundary, because the `www.` and bare `github.com` URL alternatives were quadratic (200k chars about 145 s).

Consequence, as on base: `www.github.com/o/r/issues/5` and `github.com/o/r/issues/5` in worker text survive `neutralize()`, so a driver commit title, PR body or event line can still backlink an issue through those forms (their closing keyword is removed, so nothing closes). Pinned in `tests/bin-lib/driver/run.test.js` (#5269 AC2: `Closes www.github.com/o/r/issues/5 now` becomes `www.github.com/o/r/issues/5 now`).

## Deliverables

- `neutralize()` removes `www.`-prefixed and bare `github.com`-host issue and PR URL references (matching what GitHub autolinks), in linear time.
- A linearity pin for each new URL form in `perf/driver-neutralize-linearity.test.js`, covering the shapes that made the earlier alternatives quadratic (`www.` runs, `_www.` runs, `fix:www.` runs, `www.g/o/r/issues/5` chains).
- The #5269 AC2 assertions that currently expect these URLs to survive are updated to expect removal.

## Acceptance Criteria

- `neutralize('Closes www.github.com/o/r/issues/5 now')` returns `now`, and `neutralize('see github.com/o/r/pull/7')` returns `see`.
- Every case in `perf/driver-neutralize-linearity.test.js` passes its budget under `npm run test:perf`, including new cases of at least 100k characters for each added URL form.
- `node --test tests/bin-lib/driver/*.test.js` passes.

## Release Note

Driver commit titles, PR bodies and event lines no longer keep issue or PR references from worker text that GitHub would link: www. and bare github.com URLs, and owner/repo/issues/N or /pull/N paths after any host or none.

## Plan Review Clarifications

- What GitHub autolinks, probed through its GFM renderer (`POST /markdown`, `mode=gfm`, a real-repo context, 2026-11-13), settles the boundary and the host rule. The spec says: "`neutralize()` removes `www.`-prefixed and bare `github.com`-host issue and PR URL references (matching what GitHub autolinks), in linear time."
  - A `www.` URL autolinks at the start, after whitespace, or after `*`, `_`, `~` or `(`, including with a port (`www.github.com:443/…`). It renders as a plain link.
  - A bare `github.com/` host never autolinks. The reference GitHub renders there is the `owner/repo/issues/N` (or `/pull/N`) path itself, whatever precedes the owner: no host, `github.com/`, `gist.github.com/`, `example.com/`, `xhttps://github.com/`, or a `-`, `.`, `/`, `:` or `(` before the owner. Only an `_` stops it.
  - So `neutralize()` also removes that host-free path, once, after the reference passes settle. `xhttps://github.com/o/r/issues/5` therefore loses its path: #5269 pinned it as surviving, using a repo that does not exist.
