# 3947: Run a mandatory agent tiebreak on every unconfirmed and contested review finding

Surface: infra

## Overview

Second strangler-fig step: add a mandatory agent tiebreak to `/claude-tweaks:review`, in a new sub-file `plugin/skills/review/step3-tiebreak.md`, alongside the existing Direct-verification override. After every earlier review pass has run, each finding still `unconfirmed` or `contested` gets one independent Capable agent that reads the live code and answers confirmed, refuted or can't tell. Every reply goes through the deterministic resolver from the resolver sub-issue, so a confirmed finding enters normal Step 3 routing, a refuted one is dropped on quoted evidence, and a can't-tell one is routed to the digest (low) or the console / review report (medium and above). It runs at every effort tier and in every mode (`auto`, `confirm`, `hybrid`, `interactive`), dispatched or not.

This replaces the review's habit of sending every single-source and debate-inconclusive finding straight to the console's Low-confidence and Contested subsections. It also absorbs #3815: same-location, different-substance (`nearLocation`) pairs are each judged as their own finding, so the console never has to render them.

## Release Note

Added a mandatory independent tiebreak for every unconfirmed or contested review finding, so each is settled by reading the code instead of waiting for a human.

## Technical Approach

The step runs after all earlier review passes, takes the post-pass set (written to the findings artifact first, so the archive check has its denominator), and fans out one Capable agent per finding. The main thread feeds each reply to the resolver subcommand and acts on the outcome: `confirmed` enters Step 3 routing at the severity the resolver returns (the lower of the reporter's and the tiebreak's; for a contested finding the reporter's severity is the higher of the two positions'); `drop` is logged with the quoted evidence; `digest` writes a digest entry with a `Defer-reason:` stating the tiebreak could not tell (`plugin/skills/_shared/materiality-floor.md`'s digest path); `console` stages a decision item carrying the recommendation (rendered by the console sub-issue). Standalone reviews print instead of stage.

Why a new sub-file: `step3-lens-dispatch.md` sits within 3% of the Read rail and four open records also add text to it, so it receives only a pointer.
