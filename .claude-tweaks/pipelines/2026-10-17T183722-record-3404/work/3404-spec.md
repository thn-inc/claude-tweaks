# 3404: Reuse verify's TAP block parsing in the Windows regression filer

Origin: wrap-up review console from #3316 (review finding 1)

Defer-reason: genuinely-larger

## Current State

`tools/windows-regression/file-issue.js` (#3316) scans TAP output with its own `excerptFor` / `namesFile` / `slashes` helpers: it finds a failing file's `not ok` block, walks start and end boundaries (`ok N`, `# Subtest:`, YAML `...`), and collapses inspect()-doubled Windows backslashes.

`plugin/bin/lib/verify/extract.js` already owns TAP block parsing for verify (`tapBlocks`, not exported) and path normalization (`relativize`). #3316's review flagged the duplication (single-agent finding, recommended Defer): the filer needed three boundary fixes during the build (`ff32fe861`, `94c90f6b0`, `19b4b2e3d`), each re-learning a rule extract.js already encodes.

## Deliverables

- [ ] Export a block/line-classification helper from `plugin/bin/lib/verify/extract.js` (the failing block for a file, with its YAML terminator) without changing extract.js's existing outputs.
- [ ] Rebuild `excerptFor` in `tools/windows-regression/file-issue.js` on that helper, keeping the excerpt contract: open at the file's `not ok` (or a crashed file's stderr), stop at the next sibling test line, cap 12 lines.

## Acceptance Criteria

- `tests/bin-lib/verify/extract.test.js` passes unchanged, plus new tests for the exported helper.
