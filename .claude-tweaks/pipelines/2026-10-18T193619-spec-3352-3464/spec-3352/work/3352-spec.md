# 3352: statusline git status takes the index lock and races worktree git writes

# Reflect — staged finding 2

**Category:** tangential

Origin: reflect light from #2927

Defer-reason: tangential

## Current State

`plugin/bin/claude-tweaks-statusline.js`'s `renderGit` (line 204) runs `execSync('git status --porcelain -b', { cwd })` on every statusline render. It passes no `--no-optional-locks` flag and no `GIT_OPTIONAL_LOCKS=0`. A plain `git status` takes the index lock opportunistically to refresh its stat cache.

The statusline re-renders around every tool call. In a worktree-isolated session, the session's own index-writing git commands race that render and fail with `fatal: Unable to create '.../.git/worktrees/{name}/index.lock': File exists`. The colliding commands are the Bash tool's plain `git merge`, `git add` and `git commit`. The lock is gone a moment later, so the failure looks stale. That misleads an agent into deleting the lock, or into blaming `npm test`, the cause the existing guidance names.

Observed on #2927's run, 2026-10-17:
- `git merge origin/main` (the post-creation catch-up) failed 4 times in a row.
- `git commit` and several `git add` calls failed, and passed only on retry.
- The same commands run from a node `execFileSync` wrapper succeeded on the first attempt.
- `ps` showed a `git status --porcelain -b` process during the failures.

## Deliverables

1. Make `renderGit`'s status call lock-free: `git --no-optional-locks status --porcelain -b`, or `env: { ...process.env, GIT_OPTIONAL_LOCKS: '0' }`. Keep the existing branch/dirty parsing unchanged.
2. Add a test that pins the lock-free form, for example by asserting that the exec runner receives the flag or env. Follow the existing statusline test's injectable-runner seam if there is one; otherwise add the minimal seam.

## Acceptance Criteria

- The statusline's git status call never takes `.git/index.lock`: the command carries `--no-optional-locks`, or the spawn env sets `GIT_OPTIONAL_LOCKS=0`.
- The branch and dirty-dot rendering is unchanged for clean, dirty, detached and no-commits repos.
- `npm test` passes in full.

## Release Note

The statusline no longer makes your own git commands fail with an index.lock error while it refreshes.
