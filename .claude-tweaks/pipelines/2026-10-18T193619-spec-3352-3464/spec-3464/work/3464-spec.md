# 3464: Read-only git status probes may take index.lock in other sessions' worktrees

Surface: backend

**Related:** #3352, #3315, #3470

## Current State

Plain `git status` refreshes the index's stat cache and writes it back under `index.lock` as a side effect. Any `git add`/`git commit`/`git merge` in the same worktree that starts during that window fails with `Unable to create '.../index.lock': File exists`, and the lock is gone a moment later. `git status` itself never fails when the lock is held (exit 0, it just skips the write), so the *other* party is always the one that breaks. Passing the top-level `--no-optional-locks` option (or `GIT_OPTIONAL_LOCKS=0`) makes `status` compute the same answer without writing the index.

Probed on git 2.56.0 in a temp repo whose tracked files had a stale stat (mtime changed, content unchanged), comparing `.git/index` mtime + sha before and after:

| Command | Index rewritten? |
|---|---|
| `git status --porcelain` (also `--ignored`, `-b`) | yes |
| `git --no-optional-locks status --porcelain` / `GIT_OPTIONAL_LOCKS=0 git status` | no |
| `git diff --name-only HEAD` / `git diff --name-only` (working tree) | yes — **even with `--no-optional-locks`** |
| `git diff-index --name-only HEAD` | no, but reports every stat-dirty file as changed (false positives) |
| `git diff --cached ...`, `git diff A B` (commit-to-commit) | no |

`git grep -n OPTIONAL_LOCKS plugin/bin` returns nothing. The read-only `git status` call sites under `plugin/bin` (origin/main at the time of shaping):

- `plugin/bin/claude-tweaks-statusline.js:204` — `execSync('git status --porcelain -b')` in the session cwd on every render (about every 1.8s, observed as ~400ms lock bursts with a 25ms poll). This is the confirmed culprit of #3311's failures, and #3352 already owns its fix.
- `plugin/bin/lib/hooks/worktree-reap.js:220` — `status --porcelain --ignored` **inside other worktrees**, from a session hook.
- `plugin/bin/lib/residue/probes/worktrees.js:100` — `git -C {worktree} status --porcelain` across every registered worktree.
- `plugin/bin/lib/reconcile/classify.js:34` — `status --porcelain` from the background reconcile.
- `plugin/bin/lib/verify/changed-files.js:142` and `:182` — `status --porcelain -z --untracked-files=all`.
- `plugin/bin/lib/verify/report.js:23` — `status --porcelain`.
- `plugin/bin/lib/release/run.js:9` — `status --porcelain --untracked-files=no`.
- `plugin/bin/lib/routine-template-parser.js:338` — `status --porcelain -- {dir}`.
- `plugin/bin/lib/wrap-up/engine-verify.js:250` and `:306` — `status --porcelain=v1 -uall -- {paths}`.
- `plugin/bin/qa-stamp.js:78` — `status --porcelain -- . :(exclude).claude-tweaks/artifacts`.

The open question this record was filed with (claude-tweaks probe, harness, or another tool?) is answered: the statusline is a claude-tweaks probe and is confirmed; the others are the same defect in code that runs across worktrees or in the background.

## Release Note

Stop claude-tweaks' background git checks from rewriting the git index, so your own `git add` and `git commit` no longer fail intermittently with an `index.lock` error while several sessions run.

## Technical Approach

Prepend `--no-optional-locks` to each status argv rather than setting `GIT_OPTIONAL_LOCKS=0` in the spawn env. The argv form is visible to every module's existing injected-runner fakes and to a source scan. The env form would need every runner seam to forward `env` and every fake to inspect options. Several modules route status through a shared `runGit`/`git`/`tryGit` helper that also runs write commands. Put the flag in the status call's own argv, not in the helper, so write commands keep their normal locking.

The conformance scanner reads each `.js` file under `plugin/bin` and matches two shapes:

1. An array literal whose subcommand element is `'status'` (directly after `[`, or after a `'-C', <expr>,` pair).
2. A string literal starting `git ` that contains ` status`.

For each match it requires `--no-optional-locks` within that same array or string. Report the offending file:line on failure. Follow the `skill-prose-conformance-tests` and `parse-signal-discipline` skills for the "matched nothing" guard. If #3470's `-z` conformance test has landed first, reuse its file-walking helper rather than writing a second one.

For the behaviour test, set the file's mtime to a fixed past value different from the one recorded in the index. That makes the stat mismatch deterministic with no sleep, and plain `git status` then rewrites the index every time.

## Gotchas

- **Blocked by #3352.** #3352 (ready, authorized) fixes the statusline's call at the same line this conformance scan covers. Build #3352 first so the two PRs don't both edit `claude-tweaks-statusline.js` and the scan is green on arrival.
- `--no-optional-locks` is a top-level git option. After the subcommand (`git status --no-optional-locks`) it is an unknown option and git errors out. It goes before `status`, after any `-C`.
- Out of scope, deliberately: working-tree `git diff` (`plugin/bin/load-delta.js:391`, `git diff --name-only -z --no-renames --end-of-options {base}`). The probe above shows that neither `--no-optional-locks` nor `GIT_OPTIONAL_LOCKS=0` stops `git diff` from rewriting the index. The only lock-free plumbing form (`diff-index`) reports stat-dirty files as changed, which would change `load-delta`'s answer. It runs only on demand in the session's own worktree, not on a poll or across sibling worktrees, so it is not the contention this record observed.
- Out of scope: skill prose that tells the agent to run `git status`. Those runs are one-off and in the session's own cwd, not background probes.
- The test fakes listed in Key Files key on the old argv, and several will fail until updated. That is expected, and it is what makes them pin the flag. Grep `tests/` for `'status'` and `status --porcelain` before calling the sweep complete; the list above came from that grep at shaping time.
- The statusline wrapper at `~/.claude-tweaks/bin/statusline.js` resolves the newest installed plugin version at runtime, so a plugin upgrade delivers #3352's fix with no reinstall.

## Current State

During #3311's build and test phases, `git add` in this session's worktree failed with `Unable to create '.../index.lock': File exists` several times within minutes (21:12–21:23Z). Each time the lock was gone a moment later. No process of this session held it. Several sibling sessions were active.

`git status` refreshes the index and takes `index.lock` unless it runs with `GIT_OPTIONAL_LOCKS=0` (or `--no-optional-locks`). The plugin's read-only status probes set neither:
- `plugin/bin/lib/reconcile/classify.js`
- `plugin/bin/lib/residue/probes/worktrees.js`
- `plugin/bin/lib/hooks/worktree-reap.js`

`git grep -rn OPTIONAL_LOCKS plugin/bin` returns nothing. Some of these run across every registered worktree from background reconcile or session hooks.

Evidence: three `index.lock` failures in this session, worked around with a retry script (scratch `add-commit-retry.js`). Cost this session: about six retries and one workaround script.
