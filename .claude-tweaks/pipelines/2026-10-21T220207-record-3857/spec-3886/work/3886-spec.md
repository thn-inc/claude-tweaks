# 3886: Windows regression: 1 test file(s) newly failing after 32377b60a

Surface: infra

## Current State

The post-merge Windows check on commit 32377b60a (merged PR #3862) reported `tests/statusline.test.js` newly failing on "renderProject: percent-encodes spaces in the file:// link (real project dirs contain them)". The output was `file:///D:/Users/x/Code%20Workspaces/my-proj/`.

Re-checked against current `main`, this is a test-side defect and still live. `plugin/bin/claude-tweaks-statusline.js` builds the link with `pathToFileURL(dir).href`. On win32 that resolves the POSIX-style fixture path `/Users/x/Code Workspaces/my-proj` against the current drive, so `file:///D:/Users/x/…` is the correct production output there. The test at `tests/statusline.test.js:259-263` hard-codes the POSIX expectation `file:///Users/x/Code%20Workspaces/my-proj/`. Its sibling "the file:// link ends with a trailing slash" (lines 265-268) hard-codes `file:///Users/x/Code/claude-tweaks/\x07` the same way. The file already has the platform-correct idiom: the `linkedName(dir)` helper (lines 25-26) derives the expected link from `pathToFileURL(dir).href`, and the fallback test at line 256 uses it.

**Related:** #3702, #3703, #3742, #3751, #3776, #3797, #3802, #3857, #3871, #3890, #3894

## Deliverables

1. `tests/statusline.test.js` — derive the expected URL in both hard-coded tests (lines 259-263 and 265-268) from `pathToFileURL(dir).href` (directly, or via the existing `linkedName` helper), rather than from POSIX literals. Keep each test's own point explicit: the percent-encoded space (`%20`) and the trailing `/` before the OSC 8 terminator.

## Acceptance Criteria

1. Neither renderProject URL test contains a `file:///Users/...` literal. Both compute the expected link from `pathToFileURL`.
2. The percent-encoding test still asserts the link contains `Code%20Workspaces` (a space never appears raw in the URL). The trailing-slash test still asserts the URL ends with `/` immediately before `\x07`.
3. `node --test tests/statusline.test.js` is green on Linux/macOS.
4. The next post-merge Windows check (`.github/workflows/windows-regression.yml`) no longer lists this test file.

## Release Note

Fix a Windows-only failure in the statusline tests, which expected a POSIX file URL where Windows correctly adds a drive letter.

## Technical Approach

Reuse the file's own `linkedName`/`pathToFileURL` idiom for the expected value, so the test asserts the same URL construction production uses on each platform. The two semantic properties (encoding, trailing slash) stay as targeted `includes` checks on the derived value. No production change: `pathToFileURL` is already the correct, platform-aware builder.
