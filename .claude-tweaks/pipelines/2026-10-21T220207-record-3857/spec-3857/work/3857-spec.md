# 3857: Windows regression: 1 test file(s) newly failing after 8da6efddc

Surface: infra

## Current State

The post-merge Windows check on commit 8da6efddc (merged PR #3849) reported `tests/display-ci-readers-conformance.test.js` newly failing on "AC1.1: item 1 CI script maps a pending head run under a green rollup to pending". The issue body carries no error text.

The run's `verify-logs` artifact shows the real failure: the extracted item 1 script exits 1 with `Error: Cannot find module 'D:a_tempct-display-ci-item1-bZqNnPopen-prs.json'`. The backslashes of the native win32 temp path are gone. Root cause, still present on current `main`: line 209 splices the temp file path into the script with `scripts[0].replace(/\$PR_SCAN_OPEN/g, prsFile)`, and the script embeds it inside a JS string literal, where each `\` is consumed as an escape. This is the exact defect #3699 fixed for item 9's candidates path: lines 83-88's `substituteCandidates` forward-slashes the path with `toPosix` first, and `#3699 AC1.1` (line 231) pins it with a `path.win32` simulation. The item 1 test (added later by #3849) never adopted that helper.

The failure is not a CRLF one: the file passes 8/8 on macOS both normally and under a CRLF-read simulation. Production is unaffected, since the shipped script receives a forward-slashed path from `formatPrintedPath` (per the comment at lines 83-85).

**Related:** #3699, #3702, #3703, #3742, #3751, #3776, #3797, #3802, #3871, #3886, #3890, #3894

## Deliverables

1. `tests/display-ci-readers-conformance.test.js` — splice `$PR_SCAN_OPEN` (line 209) with a `toPosix`-converted path, the same way `substituteCandidates` does for `$PR_SCAN_UNARMED_CANDIDATES`. Generalize `substituteCandidates` into one substitution helper taking the placeholder name, or add a sibling; either way, no raw native path is spliced into a script literal.
2. Add an item-1 counterpart to `#3699 AC1.1`: a `path.win32`-simulated temp path spliced into the item 1 script comes out forward-slashed, with no backslash in the substituted literal.

## Acceptance Criteria

1. No `.replace(/\$PR_SCAN_…/g, …)` in `tests/display-ci-readers-conformance.test.js` splices an unconverted path. Every substitution routes through `toPosix` (directly or via the shared helper).
2. A new test asserts that splicing `path.win32.join('D:\\a\\_temp', 'ct-display-ci-x', 'open-prs.json')` into the item 1 script with `path.win32.sep` yields a literal containing `D:/a/_temp/ct-display-ci-x/open-prs.json` and no backslash. Reverting Deliverable 1 makes it fail.
3. `node --test tests/display-ci-readers-conformance.test.js` is green on Linux/macOS.
4. The next post-merge Windows check (`.github/workflows/windows-regression.yml`) no longer lists this test file.
