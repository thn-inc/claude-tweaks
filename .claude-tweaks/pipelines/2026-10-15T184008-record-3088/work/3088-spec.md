# 3088: Worktree teardown after a squash merge: the ancestry proof always fails and the remote branch is never deleted

Verified-as-of: 666d97af57cbb48a102dfe3a8aad1210c37ce5e8

Premise-check: grep -n "squash/rebase merges alike" plugin/skills/wrap-up/cleanup-procedures-execution.md

Origin: wrap-up teardown of #3074 (PR #3077), 2026-10-10

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/skills/wrap-up/cleanup-procedures-execution.md` Section C step 4 makes `git merge-base --is-ancestor HEAD origin/{integration-branch}` the primary proof before `ExitWorktree(remove, discard_changes: true)`, and claims it "holds for `--no-ff`, fast-forward, and squash/rebase merges alike" and is "strictly stronger" than SHA equality. That is false for squash and rebase merges: the integration branch gains a new commit whose parents exclude the branch commits, so the branch `HEAD` is never an ancestor and the check exits 1 every time.

Under `integration-model: pr-first` (the GitHub default) every merge goes through `pr-first-merge.md` Step 3's `gh pr merge --squash`, so the "primary proof" can never pass on the default path. The only thing that actually authorizes the discard is the `[IL-45]` content-diff fallback, which the section frames as the path for "a branch discarded without ever merging". Observed 2026-10-10 tearing down record #3074's worktree after PR #3077 squash-merged as `666d97af5`: `git merge-base --is-ancestor HEAD origin/main` exited 1, and `git diff HEAD 666d97af5` was empty.

Same teardown, second gap. For the worktree the session stands in, Section C step 4 removes it with `ExitWorktree(remove)`, which also deletes the local branch. `pr-first-merge-post-merge.md` Step 5 (remote branch delete) has no own-worktree mechanism: step 5's `teardown-run --merged` is the documented carrier, but its branch lookup (`teardown-run.js` → `run-integrity.js` `fallbackBranch`) accepts `run-state.json`'s `pr.branch` only when `branchExists` locally. With the local branch already gone it reports `remote ref: skipped — no branch recorded` and the remote ref survives. On #3074 it had to be deleted by hand with `gh api -X DELETE repos/thn-inc/claude-tweaks/git/refs/heads/worktree-record-3074`. #3023 is a different teardown defect (directory left on disk after the prune fallback).

## Deliverables

1. Section C step 4: make the merged-content proof match the merge shape. For a squash or rebase merge (always the case under pr-first), the primary proof is a clean worktree plus an empty `git diff HEAD {merge-commit}`, where `{merge-commit}` is the PR's `mergeCommit` from `gh pr view --json mergeCommit`. Keep `merge-base --is-ancestor` for `local-merge --no-ff` and fast-forward. Remove the "holds for squash/rebase" and "strictly stronger" claims.

2. Mirror the corrected rule wherever it is restated. `_shared/scratch-worktree.md` §6 is the cited source of the ancestry check; update it, or state why its scratch-worktree case differs.

3. Give the own-worktree path a remote-branch delete that survives `ExitWorktree(remove)`. Either let `teardown-run --merged` use `run-state.json`'s `pr.branch` for the remote-ref step when the local branch no longer exists (the guard against deleting the integration branch still applies), or have Section C name an explicit Step-5 call after `ExitWorktree`.

4. Tests: a `teardown-run` fixture where the recorded `pr.branch` has no local branch but `--merged` is given must attempt the remote delete. Add a prose pin so the "squash/rebase merges alike" claim cannot return.

## Acceptance Criteria

- Following Section C after a `gh pr merge --squash` reaches a passing proof without falling back to a path described as "never merged".

- Section C no longer asserts the ancestry check holds for squash or rebase merges.

- With `run-state.json` `pr.branch` set, the local branch deleted, and `--merged`, `teardown-run` issues the remote ref delete and reports it, rather than `no branch recorded`.

- `npm test` passes, with no new attributable failures against the Windows baseline.

## Release Note

Finishing a squash-merged pipeline run now proves the worktree is safe to remove on the first check and deletes the remote branch automatically, instead of failing the merge check and leaving the branch behind.
