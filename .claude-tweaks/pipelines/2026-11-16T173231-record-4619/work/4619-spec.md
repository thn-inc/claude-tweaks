# 4619: Diff tripwire

Surface: infra

## Overview

**Diff tripwire.** The intent-time risk declaration is cross-checked against what the code actually touched. Policy declares sensitive path globs per category (`risk-path-globs`, for example `migrations/**`, `src/auth/**`); the agent also classifies the diff. If the change crosses a category nobody flagged, the run **switches itself to local acceptance** and says why in the acceptance packet.

The tripwire is **monotonic**: it can add a flag, never remove one. Only the human removes a flag, and the removal is logged to the decision log (`decisions.md`). This is the design's "machinery that can loosen control" anti-goal made concrete: an automatic mechanism may only add caution.

**Contract decisions this record pins:**

- **Scope.** Runs only under `control-mode: on`; with it off nothing here is consulted.
- **Return shape.** `evaluateTripwire({ changedPaths, declaredFlags, removedFlags, globs, agentClassification })` returns `{ status: 'ok' | 'could-not-run', reason?, crossed: [{ category, via: 'glob' | 'agent', evidence }], newFlags: string[], flags: string[] }` with `flags = declaredFlags ∪ newFlags` (always a superset of `declaredFlags`). `could-not-run` adds no flag; it forces target `local` with the reason stated in the packet.
- **Inputs.** `globs` is the resolved `risk-path-globs` map. **Absent key or `{}`: the glob signal is off, only the agent classification applies, and nothing is forced** (no built-in default globs ship; they are project-specific). **Present but not a map of slug to string list: `could-not-run`.** `changedPaths` is produced by the caller from `git diff --name-status -M --no-color $(git merge-base {integration-branch} HEAD)..HEAD`, evaluated on the final tip immediately before the merge decision (after review and polish fix waves) and re-evaluated if the tip moves; renames contribute both old and new path, deletions count as touched. An empty diff yields `ok` with no crossings. A git failure yields `could-not-run`.
- **Agent classification** is `[{ category, evidence }]` with `category` in the slug set (built-ins plus policy `risk-categories`); an unknown category is ignored and logged; `evidence` is capped at 300 characters and rendered inert. It is produced by wrap-up's pre-merge step (the same step that calls `evaluateTripwire`, in `_shared/pr-first-merge.md`'s stop-before-merge branch and in the `local-merge` path); if that step did not run, the packet says "agent classification not run" and the glob signal still applies.
- **Matching.** Globs are repo-root-relative (`migrations/**` does not match `src/migrations/x.sql`; projects write `**/migrations/**` for nested). `tripwire.js` wraps the shared `merge-sensitive-paths` matcher with a normalizer (strip `./`, resolve dot segments, drop trailing slash, convert backslashes, compare case-insensitively); the shared matcher and its other consumers (`blast-radius.js`, `grant-gate.js`, express-lane) are not modified. Probe the shared matcher against the cases in AC 8 at build; if it lacks `**` semantics, the wrapper implements its own anchored glob as a pure function.
- **Flags added by the tripwire** are appended through the risk-flag record's `addRiskFlags` and also listed on a second line `Risk-flags-added-by-tripwire: {slugs}`, so a human can tell them from declared ones. The human can remove a tripwire flag as a false positive only through the same sanctioned `removeRiskFlag` path with explicit confirmation, which logs it. `plugin/bin/lib/accept/` imports only `addRiskFlags`; a source-scan conformance test fails if any module there imports or implements removal.
- **Removal history.** `removedFlags` is read by the caller from the intent-time removal log (the record comment or `decisions.md` entry the risk-flag record writes); if the log is unreadable the tripwire still fires and the packet omits the "you removed this flag" sentence.

## Non-Goals

- Not intent-time classification (separate record) and not target resolution (separate record; the tripwire feeds it a new kept flag).
- Not blocking or failing the run: crossing an unflagged category changes the acceptance target to `local`, it does not stop the build.
- Not removing flags by any path.
- Not a replacement for `merge-sensitive-paths` (an existing, separate merge-safety guard); this record reuses its matching approach for a different decision.

## Acceptance Criteria

1. A diff touching `migrations/001_add_users.sql` on a record with no declared flags, with policy glob `migrations/**` for the migrations category, yields `crossed: [{ category: 'migrations', via: 'glob' }]`, adds the flag, and the resolved target becomes `local`.
2. A diff crossing a category already declared yields no new flag and no change.
3. An agent classification naming `auth` with no glob match adds the `auth` flag (`via: 'agent'`) and forces `local`.
4. Given declared flags `[migrations]` and a diff touching nothing sensitive, `evaluateTripwire` returns `newFlags: []` and `flags` equal to the declared list (it is never reduced by the tripwire).
5. A property-style test feeds random declared-flag lists and diffs and asserts `result.flags` is a superset of `declaredFlags` every time, and that `could-not-run` leaves `flags` equal to `declaredFlags`.
6. The packet states the reason when the tripwire fired (category, path or classification evidence), and the evidence is rendered as inert text.
7. `risk-path-globs` present but malformed (a string, a map holding a non-list, a non-string glob), or a git failure producing `changedPaths`, returns `status: 'could-not-run'`, forces `local` and the packet states "tripwire could not run: {reason}". `risk-path-globs` absent or `{}` returns `ok` with the glob signal off (no forcing, no message beyond "path globs not configured"); an empty diff returns `ok` with no crossings; a rename from `migrations/a.sql` to `docs/a.sql` crosses `migrations`; a deletion of `migrations/a.sql` crosses `migrations`. A failed flag append forces `local`.
8. Path matching normalizes before comparing: a leading `./` is stripped, dot segments and a trailing slash are resolved, and the comparison is case-insensitive. With glob `migrations/**`: `./migrations/x.sql`, `app/../migrations/x.sql` and `Migrations/x.sql` are crossed; `docs/migrations-notes.md` and `src/migrations-readme.md` are not (the word in the wrong component). With glob `src/auth/**`: `src/auth/login.js` is crossed and `src/auth-utils-readme.md` is not. Scheme and percent-encoding variants do not apply to repo-relative git paths and are not tested.
9. A record whose migrations flag was removed by the human at intent time (a logged removal) and whose diff touches `migrations/**` still triggers the tripwire (target `local`), and the packet text names the earlier removal.
10. `npm test` passes.

## Release Note

Added a diff tripwire that switches a run to local acceptance when the code touches migrations, auth, public contracts or irreversible actions nobody flagged.

## Technical Approach

Pure function plus thin wiring. Inputs are paths and strings; outputs are additions only. Matching is the existing glob matcher; the agent's classification is an additional signal, never a veto. The "cannot run" case is a visible state, not a silent pass (the repo's parse-signal discipline: a could-not-parse case must be distinguishable from "nothing crossed").

## Gotchas

- Fail toward caution: any inability to evaluate (malformed globs, a failed diff, a failed flag write) forces `local` and says so, and is never reported as "no crossing found". An unset `risk-path-globs` is not an inability: it means the glob signal is off.
- The tripwire may only add. A reviewer should be able to verify monotonicity by grep: no assignment that shortens the flag list inside `plugin/bin/lib/accept/`.
- A human removing a flag at intent time is logged to `decisions.md`. Decision for this record: the tripwire still fires when the actual diff crosses that category (the removal judged the planned work; the diff is new evidence of what was built), and the packet says so in plain words ("you removed the migrations flag at intent; the diff touches migrations/001.sql, so this run is local"). Pin it with a test (AC 9) rather than leaving the choice open.
- Diff paths come from git; treat renames as touching both old and new path.
