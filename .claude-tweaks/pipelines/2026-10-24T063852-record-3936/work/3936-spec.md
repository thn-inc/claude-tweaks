# 3936: _shared/pr-run-comments.md: the Find step's gh --jq shape is refused in a worktree-isolated session

Origin: reflect full from #3845

Defer-reason: tangential

## Current State

Observed during #3845 (run 2026-10-22T033950-record-3845): `_shared/pr-run-comments.md`'s Post-or-update Find step prescribes `gh pr view {pr-number} --repo {host}/{owner}/{repo} --json comments --jq '.comments[] | select(.body | startswith("<!-- run-comment: {kind} -->")) | select(.authorAssociation == ...) | .id'`. In a worktree-isolated session (the shape every dispatched `pr-first` run is in) the harness refused it twice, as `wd-guard-refusal` / `harness-worktree-isolation` events ("runs gh with the text .comments[] | select(.body |… inside a construct too complex to verify"). The first refusal also tripped on the host-qualified `--repo github.com/...` form, whose `github` token reads as a git invocation. The skill text carries no worktree-safe form, so the executing agent rediscovers the workaround (fetch the comments JSON to a file with plain `gh pr view --json comments`, filter it with a `node -e` script) each run. `plugin/skills/_shared/scratch-worktree.md` section 7 records the pass/refuse boundary but does not list `gh --jq` filters.

## Deliverables

Give `_shared/pr-run-comments.md` Post-or-update step 1 (Find) a worktree-safe form: a plain `gh pr view {pr-number} --repo {owner}/{repo} --json comments` redirected to a scratch file, filtered by a small checked-in helper or `node` script that applies the same marker-prefix and trusted-author selection (reusing `bin/lib/issues/comment-trust.js`), keeping the current `--jq` form only as the non-isolated shortcut.

Record the refused `gh --jq` shape, and the `--repo` host-qualified token hazard, in `plugin/skills/_shared/scratch-worktree.md` section 7.

Check the other consumers that copy the same `--jq` select shape (`_shared/pr-checklist-refresh.md`, `wrap-up/verification-brief.md`) and point them at the same worktree-safe form.
