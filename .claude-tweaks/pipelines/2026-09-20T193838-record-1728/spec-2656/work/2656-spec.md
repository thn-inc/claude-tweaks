# 2656: Add a skill/CLAUDE.md bloat-audit prompt

Surface: infra

**Related:** #2644

## Current State
A social-media Reel (hook-only caption; transcribed) argues newer Claude models need less prompt scaffolding than older ones, and that a bloated CLAUDE.md/skills setup (dead rules, redundant instructions, rules written for older-model quirks) can slow the model down and cause it to ignore simple rules. It reports that Anthropic's own team cut roughly 80% of Claude Code's system prompt after a newer model shipped, rebuilding leaner rather than layering more rules on top, and recommends running an audit prompt over an existing CLAUDE.md/skills setup to find and remove dead-weight rules rather than deleting by hand. This is a direct hit on claude-tweaks' own domain, since every skill it ships is itself a prompt. The plugin already has `plugin/skills/harness-health/` (`/claude-tweaks:harness-health`), which audits skills/rules/CLAUDE.md for drift against the codebase, template, and best practice — but its existing dimension checks (see `plugin/skills/_shared/harness-health-analysis.md`) judge staleness relative to what the code does, not relative to what the current model generation actually needs; there is no dimension today that treats "a newer model shipped" as its own trigger for re-judging whether a rule is still earning its keep. `#2644` ("Audit skill-authoring guidance for Claude Fable 5.1 prompting deltas") already exists as a one-off instance of this same class of work, filed manually rather than through a repeatable check.

## Deliverables
1. A new model-version-staleness dimension added to harness-health's judged analysis (`plugin/skills/_shared/harness-health-analysis.md`) that flags rules/sections plausibly written for an older model generation's quirks (verbose scaffolding, defensive repetition, workarounds for a limitation a newer model no longer has) as candidates for consolidation or removal.
2. A proposed-diff output shape for findings from this dimension: the flagged rule/section, the reasoning for flagging it, and a suggested consolidated rewrite — never an automatic deletion, consistent with harness-health's existing "never edits code" posture.
3. A trigger tying this dimension's re-run to a new Claude model version shipping, cross-referenced with `#2644`'s existing model-version-prompting-deltas tracking so the two don't diverge into separate, uncoordinated processes for the same triggering event.

## Acceptance Criteria
- Running harness-health's model-version-staleness dimension against a sample skills directory containing at least one plausibly-outdated rule (e.g., an old defensive-repetition pattern) produces a flagged finding naming that rule and the reasoning behind the flag.
- The dimension's output is a proposed diff/consolidation description, never an automatic file edit or deletion — consistent with harness-health's existing contract.
- Running the dimension against a skills directory with no plausible staleness produces no finding for this dimension (no false positive).
- The new dimension's documentation (in `harness-health-analysis.md` or `SKILL.md`) explicitly cross-references `#2644`, noting both are triggered by the same event (a new Claude model shipping).

## Technical Approach
Extend harness-health's existing judged-dimension analysis rather than building a standalone skill, since harness-health already owns the "skills are prompts; audit them against a source of truth" responsibility and already has the target-selection, findings-file, and GitHub-issue-filing plumbing this deliverable needs. Add a new dimension check to `harness-health-analysis.md` alongside the existing drift/best-practice dimensions, scoped specifically to model-generation fit: does this rule read like a workaround for a limitation, or padding written out of caution, rather than something the current model still needs explicit instruction for. Wire the trigger so a new-model-version event (as already tracked for `#2644`) marks this dimension due for a fresh pass, rather than leaving it to the same churn/staleness rotation cadence as harness-health's other dimensions.

### Key Files
- `plugin/skills/_shared/harness-health-analysis.md` — add the new model-version-staleness dimension check alongside the existing drift/best-practice dimension checks.
- `plugin/skills/harness-health/SKILL.md` — document the new dimension in the skill's own description/workflow, and note the `#2644` cross-reference.
- `plugin/skills/harness-health/judge-procedure.md` — extend the per-target judging procedure (used by the parallel-dispatch path) to include the new dimension so dispatched agents apply it too.

## Gotchas
- Overlap risk with harness-health's existing best-practice/drift dimensions — this is a genuinely new axis (model-generation fit, not codebase/template fit), but the two could produce redundant findings on the same rule for different stated reasons; the new dimension's write-up should note how a finding here differs from an existing best-practice finding to avoid double-filing.
- The "cut ~80% of the system prompt" claim comes from an unsourced social-media Reel, not a published Anthropic decision — treat the underlying premise (newer models need less explicit scaffolding) as a hypothesis to probe carefully per rule, not a rule to apply mechanically across the board; a rule can still be load-bearing for a newer model for reasons unrelated to verbosity (e.g., project-specific conventions no model would infer on its own).
- Judging "written for an older model's quirks" requires the auditing model to reason about its own capabilities relative to a prior generation, which is inherently harder to verify than a codebase-drift check — expect this dimension's findings to need more human review before consolidation than harness-health's existing mechanical dimensions.
