# 3141: Specify headless self-report: shaping-near-duplicate-refusal

Surface: backend

**Related:** #1944, #2601, #2552, #3131, #3134, #2634, #2789

## Current State

`/claude-tweaks:specify`'s shaping mode runs `findNearDuplicates` (`plugin/bin/lib/issues/near-duplicate.js`) against the open-record snapshot before composing a body (`plugin/skills/specify/shaping-mode.md`, "Near-duplicate candidate check (#1944)"). The finder returns each candidate with a score (count of fired signals) and a `signals` list drawn from three checks: `key-files-overlap`, `title-similarity`, and `body-anchor-overlap` (any backticked span shared between the two `## Current State` sections).

The automatic stop rule is written in prose in `shaping-mode.md`: when any candidate is `ready` **and** either carries `bot:in-progress` or has an open linked PR, shaping stops, the record gets `needs:decision`, and a decision comment proposes "Absorb into #{candidate}". Any score of 1 or more qualifies, so one fired signal of any kind is enough. `plugin/skills/specify/next-mode-shape.md` applies the same rule on the headless drain path and counts the refusal in the `failed` bucket.

On 2026-10-15 this rule refused four records, none of them duplicates:

| Refused | Candidate | Signals | Subject overlap |
|---|---|---|---|
| #2601 | #2552 | body-anchor-overlap (the shared anchor was the flag `--run-dir`) | none |
| #3141 | #2552 | body-anchor-overlap | none |
| #3134 | #2634 | key-files-overlap (`plugin/skills/simplify/SKILL.md` only) + body-anchor-overlap | none |
| #3131 | #2789 | key-files-overlap + body-anchor-overlap | same call site, different failure |

Two separate weaknesses produced these:

1. **File overlap is treated as subject identity.** `key-files-overlap` and `body-anchor-overlap` say two records touch the same files or name the same symbols. That is a build-time collision concern, which `/claude-tweaks:flow`'s cross-spec conflict detection and `/claude-tweaks:dispatch`'s file-overlap grouping already handle. Only `title-similarity` speaks to the records describing the same work. `extractCurrentStateAnchors` also accepts any backticked span, so widely cited generic tokens count as identity anchors. Screening this record's own shaped body on 2026-10-15 returned 26 candidates, every one on `body-anchor-overlap` alone. The shared anchors were skill names (`/claude-tweaks:dispatch` in 11 pairs, `/claude-tweaks:flow` in 9, `/claude-tweaks:specify` in 3), label names (`bot:in-progress` in 4, `ready` in 1), and the flag `--run-dir` (1).
2. **"In-flight" rests on a projection label.** None of the three candidates had a build in flight. Each one's draft PR had finished every phase with a PASS verdict about two weeks earlier and was waiting for a merge grant. Their claims were past the 72h TTL (`DEFAULT_TTL_HOURS` in `plugin/bin/lib/issues/claims.js`), and `bot:in-progress` was leftover state. `dispatch/SKILL.md` already calls labels a "projection, not truth". The authoritative hold is a live claim blob on the `claims-registry` branch, classified by `classifyClaimBlob`.

## Deliverables

1. **A pure refusal predicate in `near-duplicate.js`.** Export `shapingRefusal(hits, stateByNumber)`, which returns the first hit that warrants refusal, or `null`. A hit warrants refusal only when all three conditions hold:
   - its `signals` include `title-similarity`;
   - the candidate is `ready`;
   - the candidate has an in-flight build, meaning `stateByNumber[n].liveClaim === true` (a claim `classifyClaimBlob` reads as `live`) or `stateByNumber[n].openLinkedPR` is set.

   `bot:in-progress` on its own is not an input. A hit that fails any condition is surfaced only, through the table and the `**Related:**` append the rule already does.
2. **Generic tokens stop counting as body anchors.** `extractCurrentStateAnchors` drops three span shapes: a flag (`--name` or `-x`, optionally followed by a value placeholder), a skill invocation (`/plugin:skill`, optionally followed by arguments), and a label name (a `family:value` span with no `/`, or one of the bare stage labels `ready`/`parked`). File paths, symbol names and section names that are not of those shapes are unaffected.
3. **`shaping-mode.md`'s stop rule calls the predicate.** Replace the prose condition with a call to `shapingRefusal`. Build `stateByNumber` from the candidates' labels, their claim blobs (`claims/issue-{n}.json` on `claims-registry`, classified by `classifyClaimBlob`), and the linked-PR query `record.js`'s `buildLinkedPRQuery`/`partitionByOpenLinkedPR` already provides. The decision comment's `**Why:**` line names the title-similarity hit and the specific in-flight evidence (live claim run id, or open PR number) instead of the fixed "open PR / `bot:in-progress`" text.
4. **`next-mode-shape.md`'s headless note matches.** Its description of what triggers the refusal uses the new condition. The failed-bucket handling stays as it is.
5. **Fixture tests in `tests/bin-lib/issues/near-duplicate.test.js`.** Cover the four refusals in the Current State table, each returning `null` from `shapingRefusal`. Add a true duplicate (title similarity, `ready`, live claim) that is refused, the same duplicate with a stale claim and only `bot:in-progress` that is not refused, and one with an open linked PR and no live claim that is refused. Add flag, skill-invocation and label-name anchors that do not fire `body-anchor-overlap`, beside a file-path anchor that still does.

## Acceptance Criteria

- `shapingRefusal` is exported from `near-duplicate.js` and returns `null` for any hit whose signals lack `title-similarity`, whatever its score.
- `shapingRefusal` returns `null` for a `ready` title-similar candidate whose only in-flight evidence is `bot:in-progress`, and returns the hit when the candidate has a live claim or an open linked PR.
- `extractCurrentStateAnchors` no longer returns flag spans (`--run-dir`), skill invocations (`/claude-tweaks:dispatch`) or label names (`bot:in-progress`, `ready`), and still returns backticked file paths (`plugin/skills/simplify/SKILL.md`) and symbol names (`classifyClaimBlob`).
- `shaping-mode.md`'s Near-duplicate candidate check names `shapingRefusal` as the refusal decision and no longer lists `bot:in-progress` as sufficient evidence of an in-flight build. Its decision-comment template's `**Why:**` line carries the signal and the evidence placeholders.
- `next-mode-shape.md`'s near-duplicate note describes the same condition.
- The fixture tests in Deliverable 5 pass. Reverting the predicate's title-similarity condition turns the four Current State fixtures red (shown by reverting before commit).
- `npm test` passes in full.

## Release Note

Stop `/specify` from refusing to shape a record just because a stalled, unrelated record touches the same files.

## Technical Approach

Move the refusal decision out of prose and into a pure function next to the finder, so the rule is testable against today's real refusals. The finder itself keeps all three signals and its scoring. The candidate table, the `**Related:**` append, and `/dispatch`'s cross-group warning all keep using them, so file overlap stays visible to a human without blocking shaping.

This deliberately drops the record's original proposal of "a linked PR updated recently". An open linked PR keeps counting as in-flight at any age. Once refusal requires title similarity, a candidate whose PR finished and is waiting for merge is a strong reason to absorb a real duplicate, because that work is already built. The stale-state problem in the evidence came only from `bot:in-progress` and expired claims, which the predicate no longer reads. That also avoids inventing a freshness threshold.

A second weakness showed up. None of the three candidates had an in-flight build. Each one's draft PR had finished build, test, review and wrap-up with a PASS verdict about two weeks earlier, and stopped at "leave-open" for lack of an `auto:merge` grant. Their claims were stale (past the 72h TTL), and `bot:in-progress` was leftover state on unmerged PRs. A `/claude-tweaks:tidy` pass released 10 such stale claims on 2026-10-15.

Proposed rule changes (two independent fixes):

1. **Refusal requires subject identity.** Key-files and body-anchor overlap are file-collision signals, which `/flow`'s cross-spec conflict detection and dispatch's file-overlap grouping already handle at build time. Refuse only when the title-similarity signal fires (or another subject-identity signal). File- or anchor-only overlap should append to `**Related:**` and let shaping proceed.
2. **"In-flight" must not rest on `bot:in-progress` alone.** That label is a projection (`dispatch/SKILL.md`: "labels are projection, not truth"). Use a live, unexpired claim in the claims registry, or a linked PR updated recently. A PR that has sat for weeks with all phases complete is "awaiting merge", which may still matter for absorption but isn't an in-flight build.
