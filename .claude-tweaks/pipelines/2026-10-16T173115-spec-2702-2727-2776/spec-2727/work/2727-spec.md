# 2727: worktree.always forces GitHub-only-write skills like backlog refine into a worktree, and post-creation catch-up manufactures the commits that make teardown expensive

Surface: infra

## Current State

`/claude-tweaks:backlog refine`'s entire write surface, in both invocation modes exercised in a session on 2026-09-20/21, is `gh issue edit`/`gh issue comment` calls against GitHub — it never writes a repo file. Under `worktree.always: true`, the skill is still required to create a full git worktree before making any writes (per `CLAUDE.md`'s worktree-always policy and `_shared/worktree-setup.md`). Worse, `_shared/worktree-setup.md`'s own mandatory "Post-creation catch-up" step then runs a `git merge origin/main` unconditionally, which (because this project's `worktree.baseRef: head` legitimately starts a fresh worktree from local HEAD, itself sometimes ahead of `origin/main`) produced real merge commits the session then had to hand-verify were safely discardable (`git merge-base --is-ancestor` checks) before `ExitWorktree` would let the worktree be removed. Two separate `/claude-tweaks:backlog refine` invocations in one session each went through this full create → catch-up-merge → hand-verify-ancestry → discard cycle for a skill that touched zero repository files.

Verified against the current codebase: `_shared/worktree-setup.md`'s Adopt-or-create section runs the origin-relative fetch+merge unconditionally on both the create and adopt branches, with no exemption for a skill whose declared write surface is GitHub-API-only; `worktree.baseRef: head` is a real, documented harness setting (`_shared/worktree-base-ref.md`) this project deliberately sets; and no existing carve-out in `plugin/bin/lib/hooks/session-start.js`'s worktree-always message or in `backlog`/`capture`/`tidy`'s own skill docs tells an agent it may skip worktree creation for this class of invocation.

## Deliverables

- Give `worktree.always` (or the `EnterWorktree` decision point skills make before creating one) a carve-out for a skill whose entire declared write surface is a forge API (GitHub issues/PRs via `gh`), not repository files — `/claude-tweaks:backlog refine`, `/claude-tweaks:capture`, and `/claude-tweaks:tidy`'s scan lanes are candidates.
- Alternatively or additionally, narrow `ExitWorktree`'s discard-confirmation guard to exclude commits already reachable from `origin/{integration-branch}` — a ride-along merge commit that only pulls in already-upstream history is not "this work" by construction, and forcing a human/agent to hand-prove that via `git merge-base --is-ancestor` before every teardown is the exact overhead this record measures.

## Acceptance Criteria

- A `/claude-tweaks:backlog refine` invocation (or another GitHub-only-write skill named above) under `worktree.always: true` either skips worktree creation entirely, or completes teardown without requiring a hand-run ancestry check to prove no unique commits exist.
- `_shared/worktree-setup.md`'s Post-creation catch-up section documents this carve-out (or its absence, if rejected) explicitly, rather than leaving every GitHub-only-write skill to independently discover the same expensive discard-guard interaction.

## Release Note

Let GitHub-only skills such as backlog refine skip the mandatory worktree and its costly teardown.

## Technical Approach

Add an explicit carve-out, stated once and cited from every affected site, distinguishing "editing repository files" (what the worktree-always requirement actually protects) from "forge-API-only writes" (`gh issue edit`/`gh issue comment`/`gh api`, no local file mutation) — the session-start hook message and `CLAUDE.md`'s policy prose currently say "before making any edits, invoke `/superpowers:using-git-worktrees`" with no such distinction, which reads as covering every write including a `gh`-only one.

1. Add the carve-out's canonical statement to `plugin/skills/_shared/worktree-setup.md`'s Adopt-or-create section — name the test plainly: a skill whose entire declared write surface for this invocation is a forge-API call needs no worktree at all, not even the adopt-or-create decision.
2. Reword `plugin/bin/lib/hooks/session-start.js`'s worktree-always message to name the distinction explicitly (e.g. "before editing repository files" rather than the current unconditional "before making any edits") so a fresh session isn't nudged toward creating a worktree for a GitHub-only-write skill by the very first message it reads.
3. Add an explicit "no worktree needed — every write here is a `gh` API call" statement to each named GitHub-only-write skill's own doc: `plugin/skills/backlog/refine-headless.md` (and its interactive sibling), `plugin/skills/capture/SKILL.md`, and `plugin/skills/tidy/scan-execution.md` (its scan-lane dispatches) — mirrors the reasoning `specify/shaping-mode.md`'s own "Parallel-safety" note already applies for `/claude-tweaks:specify`'s bare-drain form ("shaping a record writes no local files... so no worktree is required").
4. Leave `worktree-setup.md`'s Post-creation catch-up unconditional-merge behavior unchanged for any skill that *does* enter a worktree — this record's fix is about not entering one in the first place for API-only skills, not about softening the catch-up guard for skills that legitimately need isolation.

### Key Files

- `plugin/bin/lib/hooks/session-start.js` — the unconditional "before making any edits, invoke `/superpowers:using-git-worktrees`" message; needs the API-only carve-out named explicitly
- `plugin/skills/_shared/worktree-setup.md` — Adopt-or-create section; canonical home for the carve-out statement
- `plugin/skills/backlog/refine-headless.md` — cite the carve-out for `/claude-tweaks:backlog refine`'s headless posture
- `plugin/skills/capture/SKILL.md` — cite the carve-out
- `plugin/skills/tidy/scan-execution.md` — cite the carve-out for its scan-lane dispatches
- `CLAUDE.md` — the worktree-always policy paragraph; mirror the same distinction so a reader of the always-loaded file sees it too

## Gotchas

- `ExitWorktree` is a native Claude Code CLI tool, not part of this plugin's own source (it ships with the harness, alongside `EnterWorktree`) — the Deliverables' second option ("narrow ExitWorktree's discard-confirmation guard") is out of this repo's implementation scope. This record ships the first option (the carve-out) only; the Acceptance Criteria above are satisfied via that option's disjunct.
- The carve-out must be scoped to skills/invocation-shapes whose *entire* write surface for that specific invocation is a forge-API call — a skill that only sometimes edits local files (an occasional fallback path, a rare local-files-backend branch) must not get a blanket carve-out, or a single mixed invocation would skip isolation for a real local write. Verify each named skill's full write surface before adding it to the carve-out list; don't extend the list opportunistically to other skills without the same check.
- This record's own shaping pass (`/claude-tweaks:specify --source sweep`'s bare-drain form) is a live example of an agent reasoning this exact distinction out ad hoc, correctly, rather than following a stated carve-out — evidence the gap is current, not merely historical.
