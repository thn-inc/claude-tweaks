# 2702: Document one-shot literal resolution of CLAUDE_PLUGIN_ROOT/CLAUDE_CODE_SESSION_ID for worktree sessions

Surface: infra

**Related:** #2704, #2739, #2742, #2548, #2776

## Current State

**Premise correction (verified 2026-10-16 at `/claude-tweaks:flow` pre-flight, with maintainer approval — this changes the record's shape; same correction #2739, #2742, and #2548 already received).** The original report attributes the refusals to "the PreToolUse guard's command-shape verifier (`plugin/bin/lib/hooks/pre-tool-use.js`)". That is wrong: the quoted denial text ("runs sed with a value computed at runtime … cannot be shown not to be git", "inside a construct too complex to verify") appears nowhere under `plugin/bin/`. It is the Claude Code CLI harness's own worktree-session Bash guard — `docs/hooks.md` ("this is harness code, not a module in `plugin/bin/lib/hooks/`, and nothing here can alter it") and `docs/skill-authoring.md`'s "Harness-level worktree Bash guard vs. the plugin's PreToolUse gate" section both say so. A plugin PreToolUse hook can only add denials; it cannot lift or narrow the harness's own (#2548's closing ruling). The original Deliverable 1 (an exemption in `pre-tool-use.js`) is therefore unimplementable and dropped.

The friction is real, and the original Deliverable 2 is the plugin-side mitigation that remains:

- `CLAUDE_PLUGIN_ROOT` is not set in the Bash tool environment (#170), so a `${CLAUDE_PLUGIN_ROOT}`-templated snippet run verbatim either fails (`Cannot find module '/bin/…'`) or — inside a worktree session — is refused by the harness as "a value computed at runtime".
- The rule that the placeholder is **model-resolved** (substitute the absolute plugin root, derived from the Skill tool's `Base directory for this skill:` line minus the trailing `skills/{name}`) exists only in `docs/skill-authoring.md`'s "Plugin-root references" section — maintainer docs that do not ship in `plugin/` (`docs/decisions/0015-*`). A runtime agent inside a worktree session never sees it.
- Shipped `plugin/skills/_shared/worktree-setup.md`'s Post-creation catch-up already warns that the harness Bash-shape guard stays in effect for the session, and contains `${CLAUDE_PLUGIN_ROOT}` snippets itself (lines ~86, ~232, ~250), but carries no instruction to resolve the placeholder to a literal once and substitute it thereafter. `scratch-worktree.md` §7's 2026-09-14 addendum documents the general "runtime-computed variable" refusal family (`cat "$P/…"`, `sed -n … "$P/…"`) but never names `CLAUDE_PLUGIN_ROOT`/`CLAUDE_CODE_SESSION_ID` — the two variables plugin prose itself puts in front of the agent.

## Original request

worktree-always guard refuses non-git commands using CLAUDE_PLUGIN_ROOT/CLAUDE_CODE_SESSION_ID

Origin: by:feedback (self-referential session evaluation, /claude-tweaks:feedback bare invocation)

**Related:** #2704

## Current State

Under a `worktree-always` project policy, the harness's PreToolUse guard refuses a Bash command whose shape is "too complex to verify" as safe from inside a git worktree session, even when the command's only runtime-computed pieces are `${CLAUDE_PLUGIN_ROOT}` and/or `$CLAUDE_CODE_SESSION_ID` substituted into a non-git binary invocation (`sed`, `gh`, `node`). Two observed refusals in one session:

1. `sed -n '/pattern/,/pattern/p' "$CLAUDE_PLUGIN_ROOT/skills/_shared/some-file.md"` — refused: "runs sed with a value computed at runtime (the variable CLAUDE_PLUGIN_ROOT) in a plain command, so what it runs cannot be shown not to be git."
2. A multi-line shell block computing `$FIELDS` via `node -e` and passing it to `gh issue list --json "$FIELDS" --limit "$LIMIT"` — refused: "runs gh with a value computed at runtime (the variable FIELDS) inside a construct too complex to verify."

Both commands are read-only and touch no git state at all — `sed` read a plugin doc file, `gh issue list` is a read call. The guard's stated purpose (per `docs/hooks.md`) is to prevent a worktree-isolated session's git operations from silently escaping to the wrong checkout — a concern that doesn't apply to a `sed`/`gh read` invocation regardless of how its arguments were computed.

## Deliverables

- In the PreToolUse guard's command-shape verifier (`plugin/bin/lib/hooks/pre-tool-use.js` or wherever this check lives), add an exemption for a command whose leading binary is not `git` (or a known git-wrapping alias) and whose only runtime-substituted values are `${CLAUDE_PLUGIN_ROOT}`/`$CLAUDE_CODE_SESSION_ID` (both harness-controlled, non-attacker-influenced values) — these two variables specifically, not a general "any variable" relaxation, since the guard's concern is specifically about git-adjacent commands whose target repo/ref cannot be verified.
- Alternatively (or additionally), have `_shared/worktree-setup.md` and any other skill file that emits `${CLAUDE_PLUGIN_ROOT}`-templated snippets for the reader to run open with a one-shot instruction: resolve `CLAUDE_PLUGIN_ROOT` to a literal absolute path once at the start of the worktree session, and substitute it literally into every subsequent command — this avoids the guard's refusal pattern regardless of whether the guard itself changes, and matches what every one of this session's own workarounds ended up doing by hand anyway.

## Acceptance Criteria

- A `sed`/`gh`/`node`-led command that substitutes only `${CLAUDE_PLUGIN_ROOT}`/`$CLAUDE_CODE_SESSION_ID` runtime values, with no `git` invocation anywhere in the command, is not refused by the worktree guard.
- `_shared/worktree-setup.md` (or a new shared snippet it cites) documents a one-shot `CLAUDE_PLUGIN_ROOT` literal-resolution step for skills whose prose embeds `${CLAUDE_PLUGIN_ROOT}` snippets meant to be run inside a worktree session.
