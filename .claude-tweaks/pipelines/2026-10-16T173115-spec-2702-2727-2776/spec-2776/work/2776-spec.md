## Current State

That is wrong: the quoted refusal ("this command is too complex to verify that it stays inside the worktree … split it into plain, separate commands") appears nowhere under `plugin/bin/`. It is the Claude Code CLI harness's own worktree-session Bash guard — `docs/hooks.md` ("this is harness code … nothing here can alter it") and `docs/skill-authoring.md`'s "Harness-level worktree Bash guard vs. the plugin's PreToolUse gate" both say so; the report's own observation that "the same commands run unrefused from the main checkout" is consistent with a harness worktree-session guard. A plugin PreToolUse hook can only add denials; it cannot lift or narrow the harness's own (#2548). The original Deliverables 1–2 (anchored git matching, `.git/`/`.github/` allow-list in the guard) and the AC "every repro command runs unrefused" are therefore unimplementable from this repo and dropped.

## Original request

**Summary:** Inside a plugin-created linked worktree, the pre-tool-use Bash guard refuses compound commands whose text contains `git` anywhere — including `.github/` and `.git/` paths and quoted grep patterns — plus `awk` programs, `bash <script>` calls, variable-assembled commands and heredocs paired with `gh`, none of which mutate git state.

**Kind:** Defect

**Affected component:** `bin/lib/hooks/pre-tool-use.js` (worktree Bash guard), as exercised by `/claude-tweaks:flow` running inside `.claude/worktrees/<run>`

**Repro steps:**
1. Run `/claude-tweaks:flow #<n>` on any record so the pipeline creates and enters a linked worktree under `.claude/worktrees/`.
2. From that worktree, execute `grep -c "git" README.md && echo ok` through the Bash tool.
3. Also try: `tail -n 4 .git/worktrees/<wt>/claude-tweaks-verify/tests.log | head -1`, `sed -n '1,3p' .github/workflows/ci.yml && echo done`, `awk '{print $1}' somefile`, `bash ./helper.sh`, and `cat > "$TEMP/x.md" <<'EOF' … EOF` followed by `gh pr comment --body-file "$TEMP/x.md"` in the same call.

**Expected vs. actual:**
Expected: the guard refuses git *mutations* that break worktree discipline (checking out another branch, removing the current worktree, `stash pop`, …) and lets read-only and non-git commands through regardless of incidental substrings in paths or patterns.
Actual: every command above is refused with "this command is too complex to verify that it stays inside the worktree … split it into plain, separate commands". Several of them are the exact commands the plugin's own skill text prescribes (reading `{git-dir}/claude-tweaks-verify/tests.log`, `gh pr comment --body-file` with a heredoc-written file, `awk`-based log filters). The same commands run unrefused from the main checkout. Cost in one pipeline run: roughly a dozen refused calls, each redone as a small helper script or a `.g*hub` / `.g*t` glob so the literal substring never appears on the command line — a workaround the skill text does not know about, so every pipeline session rediscovers it.

**Definition:** Clear

**Plugin version:** 6.129.0

Suggested fix: anchor the match on an actual git invocation (`^\s*git\b`, or after `&&`/`;`/`|`), allow-list `.git/` and `.github/` path segments and quoted string literals, and document the guard's real rule in the flow / using-git-worktrees skill text so the workarounds stop being folklore.
