# 5999: Take the standard lane's implementer profile from the record rule and escalate once

Surface: backend
Risk-flags: public-contract

## Overview

Moves the standard lane's per-task implementer profile from a prose mapping in `/build` onto the record-rule CLI, and adds one escalation. Under `implementer-tier: record`, every per-task implementer in a build starts on the profile the record rule picks (Fast for a `size:low` record with one or two Key Files, Standard otherwise). When a task's implementer reports `BLOCKED`, or the task's first fix round fails its re-review, that task's next implementer dispatch is a fresh agent one profile up, once. Under `lane`, the default, the CLI returns today's `size:` mapping, so a build's profiles are what they are today.

Today `plugin/skills/build/dispatch.md` tells `/superpowers:subagent-driven-development` to map the materialized header's `size:` to Fast, Standard or Capable in prose, and no task changed tier after a failed round over 453 implementation tasks between 8 and 18 November 2026.

**Complexity:** Medium
**Estimated tasks:** 5

## Non-Goals

- The rule and the CLI: #5996, which adds `plugin/bin/implementer-tier.js`.

- The `batched` execution strategy: it has no per-task implementer dispatch.
- Escalating on every fix round. About half of Sonnet tasks need one; escalating each would bring Opus implementers back.
- Changing the `profile=` token, the per-task `**Role:**` markers, or Frontier's guard.

## Decisions

**Decision (plan review Q1, escalation against SDD's fix-loop schedule):** Reading A. AC5's "never escalated again" covers only this record's own escalation. After it, fix rounds 3-5 follow `/superpowers:subagent-driven-development`'s own schedule against the escalated agent, unchanged: rounds 1-3 resume the current implementer, and SDD's round-4 move to a fresh agent on a more capable model still happens, one profile above the escalated one. This record adds no instruction that overrides SDD's fix-loop rounds.

**Decision (plan review Q2, the `profile=` token and escalation):** Reading B. The `profile=` token sets every implementer dispatch in the run, so a task whose profile came from the token never escalates: escalation is off whenever `profile=` is given. AC3 holds literally ("a build invoked with `profile=standard` dispatches every task on Standard under both values"), and `dispatch.md`'s "it always wins" stays true. The Deliverable's "steps up from that profile" applies to a profile from a `**Role:**` marker only, not from the token.

## Release Note

Made each build pick its implementer model from the record's size and file count through one shared rule, and move a stuck task to the next model up once.

## Technical Approach

The rule lives in code; the prose only calls it and acts on its answer, so both lanes run one decision. Under `lane` the CLI returns exactly the mapping the prose carries today, so the move is behaviour-neutral until a project opts in. The escalation triggers are the two points SDD already reports: a `BLOCKED` status line, and a re-review verdict on the first fix round. Escalating only after a fix round fails, not on every fix round, keeps Capable for tasks that have shown they need it.
