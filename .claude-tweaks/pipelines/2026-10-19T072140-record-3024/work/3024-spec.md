# 3024: dispatch: queue-pull-script.md redirects to undeclared $DISPATCH_OPEN_PR_EXCLUDED (": No such file or directory" on every pull)

Surface: infra

## Current State

`plugin/skills/dispatch/queue-pull-script.md:294` runs `echo '[]' > "$DISPATCH_OPEN_PR_EXCLUDED"` in the open-linked-PR pass (#1224 block). That variable is not in the script's opening session-tmp `files` map (`queue-pull-script.md:17` onward), which declares every other `DISPATCH_*` path. The redirect target therefore expands to an empty string, and bash prints `: No such file or directory` on every queue pull. The script has no `set -e`/`set -u`, so execution continues. The message is noise, but it reads as a failure in every `/claude-tweaks:dispatch` run (bare drain or `#N`).

`git grep -n "DISPATCH_OPEN_PR_EXCLUDED\|open-pr-excluded" -- plugin` returns only that one line. Nothing reads the file. #1752 moved per-reason exclusion files to the unified `dispatch-exclusions.json` (`plugin/bin/lib/dispatch/exclusions.js`). The open-PR pass now records exclusions via `appendExclusion(…, { reason: 'open-pr' })` into `$DISPATCH_EXCLUSIONS`, which `dispatch/SKILL.md`'s `#N`/`#N,#M` paths read. The line at `:294` is a leftover from that migration.

## Deliverables

1. Delete `echo '[]' > "$DISPATCH_OPEN_PR_EXCLUDED"` from `queue-pull-script.md:294`.
2. Add a conformance test to `tests/bin-lib/dispatch/exclusions.test.js` asserting that every `$DISPATCH_*` variable the script references is either declared in its `files` map or assigned in the script. This guards against the same migration leftover recurring.

## Acceptance Criteria

- `queue-pull-script.md` contains no reference to `DISPATCH_OPEN_PR_EXCLUDED`.
- The new test fails on the current file, naming `DISPATCH_OPEN_PR_EXCLUDED` (verify by running it before the deletion), and passes after it.
- Existing `tests/bin-lib/dispatch/` suites, and any byte-pin or snippet-conformance test over `queue-pull-script.md`, pass. Update a byte pin only if one pins this exact fence, and name it in the PR.
- `npm test` passes in full.

## Release Note

Dispatch no longer prints a spurious "No such file or directory" error each time it pulls the queue.

A one-line deletion plus a referenced-vs-declared scan of the script. The original request's proposed diff (preserved below) is a reasonable starting point. Its declaration regex must match the `files` map's actual `KEY: 'file'` lines and any `KEY=` assignments, and the reference regex must cover both `$VAR` and `${VAR}`.
