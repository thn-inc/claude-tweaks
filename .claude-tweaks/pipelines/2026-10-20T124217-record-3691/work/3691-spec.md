# 3691: mcp-transport.md doesn't document that list_issues/issue_read return snake_case created_at/updated_at, degenerating next-ranking's oldest-first tie-break

## Current State

`skills/dispatch/mcp-transport.md` documents the GitHub MCP transport dispatch uses when `gh` is absent or GraphQL-blocked, including required workarounds for several known gaps (label truncation, no generic GraphQL passthrough, etc.). It does not document that `mcp__github__list_issues` and `mcp__github__issue_read` return issue timestamps as `created_at`/`updated_at` (snake_case), while every downstream consumer of the fetched issue list — `parseRecordFacets` and `next`-ranking's oldest-first tie-break among them — reads camelCase `createdAt`/`updatedAt`. Observed live during a `/claude-tweaks:dispatch next` firing (run `2026-10-20T022848-record-3630`, 2026-10-20): the queue-pull had to patch `dispatch-groups.json` with camelCase aliases before ranking, or the oldest-first tie-break would silently degenerate to array order with no error surfaced.

## Deliverables

- [ ] Add a documented aliasing step to `mcp-transport.md`'s queue-pull section, naming the exact snake_case to camelCase fields a caller must alias before any ranking/eligibility computation.
- [ ] Prefer a code-level fix if cheap: alias the fields once, at the MCP-fetch boundary (whichever shared adapter normalizes an MCP-fetched issue into the shape `record.js`'s `parseRecordFacets` and `grouping.js` expect), so every MCP-path consumer gets the correct shape without each call site re-deriving the aliasing by hand.
- [ ] Add a conformance test or fixture pinning the expected camelCase shape for an MCP-sourced issue object.

## Acceptance Criteria

- `mcp-transport.md` names this gap and its required workaround, in the same style as its existing #3137/#2523/#1579 gap sections.
- A test (or documented manual check) confirms an MCP-fetched issue's `createdAt`/`updatedAt` resolve correctly for `next`-ranking's oldest-first tie-break.
- `npm test` passes.

## Release Note

Dispatch's MCP transport path now gets a correct oldest-first ranking tie-break instead of a silent array-order fallback.
