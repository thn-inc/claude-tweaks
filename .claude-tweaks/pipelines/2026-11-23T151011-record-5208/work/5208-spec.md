# 5208: Arm record-less tidy housekeeping PRs — compose-subject.js refuses with no record, so the creation-time arm always fails

**Related:** #4467 (open PR #4586 edits `step-7-5-worktree-always.md` and `pr-first-merge.md` too — sequence after it or rebase), #4462

## Current State

Tidy's Step 7.5 `pr-first` branch (`plugin/skills/tidy/step-7-5-worktree-always.md`) arms a housekeeping PR at creation when `housekeeping-auto-merge: true` and `tidy-aggressiveness` is `moderate` or higher. It does this by running `_shared/pr-first-merge.md` Step 3's compose fence: `compose-subject.js {issue-list} --tag {tag} --pr {n} --out-dir …`.

A housekeeping PR (`<!-- tidy-housekeeping-pr -->`) links no record, so `{issue-list}` is empty. `parseArgs` refuses with `missing <n> argument` (`plugin/bin/lib/compose-subject.js:134`) and exits 1, and the fence stops before `gh pr merge --auto`. So the creation-time arm can never succeed. The sweep backstop (`tidy/actions-github-issues.md`'s `## Arm ready PR`) reaches the same Step 3 for the same marker flavors (`<!-- tidy-housekeeping-pr -->` and `<!-- wrap-up-residue-pr -->`), so it fails the same way.

Seen on PR #5207 (2026-11-11, `tidy --approve` on sweep run `2026-11-11T192023-sweep-standalone`). The run logged `arm-failed`, and the PR was armed by hand with a hand-written `chore:` subject. It then merged immediately because main has no required checks, which is #4467's separate concern.

## Deliverables

- `compose-subject.js` gains a record-less form for marker-stamped housekeeping PRs: `--pr {n}` with no `<n>`, gated by an explicit flag (e.g. `--housekeeping`). It emits a Conventional-Commits `chore:` subject and a body derived from the PR title, written to `--out-dir` like the record form.
- Without that flag, a call with no `<n>` still refuses with `missing <n> argument` (exit 1), so record-linked callers keep failing closed.
- `tidy/step-7-5-worktree-always.md`'s creation-time arm and `tidy/actions-github-issues.md`'s `## Arm ready PR` use the record-less form for marker-stamped PRs.
- `_shared/pr-first-merge.md` Step 3 documents the record-less invocation next to the existing fence.
- Unit tests in `tests/bin-lib/compose-subject.test.js` cover the record-less form and the kept refusal.

## Acceptance Criteria

- A tidy housekeeping PR opened under `housekeeping-auto-merge: true` with `moderate` aggressiveness logs `armed` or `merged`, never `arm-failed`.
- `compose-subject.js --housekeeping --pr {n} --out-dir {d}` exits 0 and writes a `chore:` subject and body; `compose-subject.js --pr {n}` with no `<n>` and no flag still exits 1 with `missing <n> argument`.
- `npm test` passes.

**Decision** (plan-review question 1, Reading B): AC1 is met when a housekeeping PR's creation-time arm logs `armed` or `merged`, and never `arm-failed`. On a repo where `--auto` cannot be armed, such as this repo's `main` with no required checks, Step 3 branch 1's immediate merge is a success. The same rule covers the sweep backstop and `<!-- wrap-up-residue-pr -->` PRs. Unit tests cannot observe the live arm/merge outcome, so a prose-conformance test plus the composer's exit 0 is accepted as AC1's coverage; do not stop to ask about live-outcome observability again. `plugin/skills/wrap-up/residue-sweep.md` arms through the same Step 3 and is in scope: give it the record-less form too. Every Step 3 composer fence in `_shared/pr-first-merge.md` that a marker-stamped PR reaches takes the record-less form, branch 1's degrade included. Keep `pr-first-merge.md`'s composed bundle under its byte limit by trimming within the file.
