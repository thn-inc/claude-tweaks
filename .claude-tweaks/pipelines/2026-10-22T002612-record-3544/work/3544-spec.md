# 3544: Quote session-tmp path placeholders in skill shell fences

Origin: ledger resolve gate (#3522 ledger item 13)

Defer-reason: genuinely-larger

**Related:** #3537

## Current State

Review of #3522 found that `{subject-dir}` was unquoted in its merge fences, so a space in `os.tmpdir()` (for example a Windows profile path such as `C:\Users\First Last\AppData\Local\Temp`, or a user-set TMPDIR) would split the path into separate arguments. #3522 quoted `{subject-dir}` and pinned its definition in `plugin/skills/_shared/pr-first-merge.md` Step 3 (30729d2d8), but the same failure shape remains elsewhere: session-tmp path placeholders such as `{tmp-records-file}` and `{tmp-open-only-file}` appear unquoted on shell command lines, e.g. `plugin/skills/_shared/record-queue-fetch.md` lines 67-84 (`cp "$SNAPSHOT" {tmp-records-file}`, `> {tmp-records-file}`).

A first count over `plugin/skills` finds about 35 unquoted placeholder uses on `node`/`gh`/`git`/`cat` lines across about 11 files containing `{tmp-...}` placeholders. Each one needs a judgment call: whether the placeholder holds a session-tmp path at all, whether it sits inside an existing quoted string or a `node -e` JS string literal, and whether a conformance test pins its current text.

## Deliverables

- [ ] Survey every session-tmp path placeholder in `plugin/skills/**/*.md` that appears on a shell command line and list which are unquoted.
- [ ] Quote each one that can hold a path with a space (or record why it cannot), editing the fences in place.
- [ ] Add or extend one conformance test that fails when a session-tmp path placeholder appears unquoted on a shell command line, with a go-red check on a frozen unquoted excerpt.
