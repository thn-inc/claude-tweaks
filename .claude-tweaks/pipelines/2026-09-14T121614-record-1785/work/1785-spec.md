# 1785: pre-tool-use worktree guard: refuses data-writing and read-only commands whose text contains the VCS name or a runtime-computed value

Surface: infra

## Current State

Under `worktree-always: true`, a session pinned to a linked worktree runs every Bash call through the Claude Code harness's worktree-session guard. That guard refuses commands whose text merely contains the substring `git` inside quoted data, and any command whose argument is computed at runtime (a loop variable, a glob, a `$(...)` result), with messages such as "names git in a form too complex to verify" and "runs sed with a value computed at runtime (the variable f)". Six reproduced shapes are listed in `## Original request` below; one review+wrap-up dispatch call spent five retries on them, and the workaround of rephrasing review findings to avoid the word distorts the audit trail those findings preserve.

The record as filed attributes the guard to `bin/lib/hooks/pre-tool-use.js`. That attribution is wrong: a plugin-wide grep of `plugin/bin` and `plugin/hooks` finds none of the quoted refusal strings, and `plugin/skills/_shared/scratch-worktree.md` §7 ("Shell constraint") already records this as harness behavior observed live on 2026-08-15, 2026-08-25 (#1108) and 2026-08-30 (#1651), including a `github.com` URL argument tripping the same "names git" refusal. The plugin cannot change the guard's matching; what it owns is (a) the documented constraint and its workarounds that every worktree-session procedure and dispatch prompt cites, and (b) the upstream report that asks the harness to match the VCS name only in command position and treat quoted data as data.

## Original request

pre-tool-use worktree guard: refuses data-writing and read-only commands whose text contains the VCS name or a runtime-computed value

**Summary:** Under `worktree-always`, the PreToolUse Bash guard refuses read-only and data-writing commands whose text merely contains the VCS name inside quoted data, or any runtime-computed value — false positives that survive #1108's heredoc/printf fix.

**Kind:** Defect

**Affected component:** bin/lib/hooks/pre-tool-use.js (worktree-isolated session Bash command guard)

**Repro steps:**
1. Enable `worktree-always: true` and run a session pinned to a linked worktree (a `/claude-tweaks:dispatch`-driven `/flow review,polish,wrap-up` call, for example).
2. Write a review findings JSON with `printf '%s' '[{"finding":"rollback leaves the git index staged"}]' > "$CTX/lens-3c.json"` — refused: "names git in a form too complex to verify".
3. Run `for f in docs/journeys/*.md; do sed -n '/^files:/,/^---/p' "$f"; done` — refused: "runs sed with a value computed at runtime (the variable f)".
4. Run `find <plugin-cache-dir> -maxdepth 3 -iname "*impeccable*"` — refused: "runs find with a value computed at runtime (a glob pattern)".
5. Run `gh api "repos/{owner}/{repo}/contents/claims/issue-N.json?ref=claims-registry" -q ...` inside an `if RAW=$(...)` — refused: "runs gh with the text repos/…/contents… inside a construct too complex to verify".
6. Run `sed -i 's/^- \[ \] review$/- [x] review/' "$B"` where `$B` is a scratch-file path variable — refused: "runs sed with a value computed at runtime (the variable B)".

**Expected vs. actual:**
Expected: only commands that can actually reach a repository (a `git`/`gh` invocation in command position) are gated; a `printf`/`sed`/`find` over scratch files, and JSON text that happens to contain the word, pass.
Actual: the substring match runs over the whole command string, including quoted data, and any runtime-computed argument trips the "cannot show not to be git" refusal. In one review+wrap-up call this cost five retries, and the workaround — rephrasing review findings so they do not contain the VCS name — distorts the audit trail the findings are supposed to preserve.

Suggested change: match the VCS name only in command position (start of command, or after `;`, `&&`, `||`, `|`, `$(`), treat quoted arguments and heredoc/printf bodies as data, and allow-list plain data-writing shapes (`printf … > file`, `cat > file <<EOF`). #1108 closed the heredoc/printf case for commands that name no other tool; the cases above are the remaining shapes.

**Definition:** Clear

**Plugin version:** 6.114.0
