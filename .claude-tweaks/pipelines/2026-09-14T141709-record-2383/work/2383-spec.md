# 2383: wrap-up verify: acceptance-labeling doesn't know about the Oversight-floor exemption

Origin: wrap-up of #1841
Defer-reason: tangential

## Current State

`plugin/bin/lib/wrap-up/engine-verify.js`'s `acceptance-labeling` check (registered via `registerCheck('acceptance-labeling', ...)`) unconditionally expects a resolved, non-parent-linked issue to carry `demo:pending` plus a Confirmed comment/brief, rendering `fail` when it's absent. `wrap-up/verification-brief.md`'s Oversight-floor gate (`#367`, `bin/lib/issues/oversight-floor.js`'s `exceedsOversightFloor`) legitimately skips Steps 1-4 (no `demo:pending` bootstrap, no brief) for a record whose `risk`/`size` facets don't clear the project's configured `risk-floor`/`size-floor` — e.g. a `risk:low`/`size:low` record under a run resolving `risk-floor: high`/`size-floor: high`. `engine-verify.js` has no knowledge of this exemption, so `wrap-up-engine.js verify` renders `acceptance-labeling` as `fail` and exits 3 for every such record, withholding the closure line even though the record's labeling is exactly as `verification-brief.md` intends.

Observed live during #1841's own wrap-up: the record carries `risk:low`/`size:low`, the resolved run policy set `risk-floor: high`/`size-floor: high`, `exceedsOversightFloor` correctly returned `exceeds: false`, Steps 1-4 were correctly skipped — and `verify`'s `acceptance-labeling` row then rendered `fail — #1841: missing demo:pending label`, a false negative on a check that was never supposed to run for this record.

## Deliverables

- `acceptance-labeling`'s check needs a way to know a record was Oversight-floor-exempted, so it can render `skip (oversight floor not cleared)` instead of `fail` for that record — likely by having `verification-brief.md`'s Oversight-floor gate write the outcome into `verify-expectations.json` (a new field, e.g. `oversightExempt: [n1, n2]`) the same way `memory`/`upstream` are already written there, and having `engine-verify.js` read it before checking for `demo:pending`.
- Extend `tests/bin-lib/wrap-up/engine-verify.test.js`: an issue listed in `verify-expectations.json`'s new exemption field renders `acceptance-labeling` as `skip`, never `fail`, even with no `demo:pending` label present.

## Acceptance Criteria

- A record whose Oversight-floor gate resolved `exceeds: false` (recorded in `verify-expectations.json`) renders `acceptance-labeling` as `skip`, and does not trip `verify`'s exit-3 gate on that account alone.
- A record that genuinely should carry `demo:pending` but doesn't still renders `fail` as today — the fix narrows the false-positive population, it does not loosen the check generally.
- `npm test` passes.
