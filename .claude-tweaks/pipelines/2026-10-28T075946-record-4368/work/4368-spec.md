# 4368: Read a record's Premise-check, Verified-as-of and Template lines only outside fenced blocks

**Related:** #4169, #4350

## Current State

The record metadata extractors in `plugin/bin/lib/issues/record-payload.js` (re-exported through `record.js`) — the Premise-check line regex (`PREMISE_CHECK_RE`, ~line 67, read by `extractPremiseCheck` ~line 221), `VERIFIED_AS_OF_RE` (~line 40) and `TEMPLATE_STAMP_RE` (~line 48) — run a multiline first-match regex over the whole body, fenced blocks included. #4169 made the section readers skip fences but left these alone.

`materialize.js` (~line 422) passes the extracted Premise-check command to the shell for a trusted author association. A command quoted inside a fence ahead of the record's own line, or a quoted command in a record that has none of its own, is the one that runs. The #4169 scenario — a Current State quoting another spec-shaped record — carries exactly such a line.

Probe at v6.155.1 and at the pre-#4169 tree, same result: a body with a fenced `echo QUOTED` command line followed by the record's own `echo REAL` line yields `echo QUOTED`. The #4169 plan does not record whether leaving the metadata extractors fence-blind was deliberate. Related prior finding: v6.155.0's staged review-62 (a staged finding body's command line reaching the same executor). Found by the post-release review of #4169 (review-83).

## Deliverables

- [ ] `extractPremiseCheck`, `extractVerifiedAsOf` and `extractTemplateStamp` ignore lines inside fenced blocks, using the shared fence rule (`fencedLineRanges`)

- [ ] a record whose only command line is inside a fence yields no command, so `materialize.js` runs nothing

- [ ] tests pin fenced-before-real, fenced-only and real-only bodies for all three extractors

## Acceptance Criteria

1. A body with a fenced command line before the record's own unfenced one yields the unfenced command.

2. A body whose only command line is fenced yields no command (null/empty, whichever the extractor already returns for absence).

3. The same holds for the Verified-as-of and Template lines.

4. `npm test` passes.

## Release Note

A command quoted inside a code block in a work record can no longer be picked up and run as that record's own premise check.

## Technical Approach

### Key Files

- `plugin/bin/lib/issues/record-payload.js` — metadata extractors skip fenced lines
- `tests/bin-lib/issues/record.test.js` — fenced/unfenced extractor cases
