# 3887: Dispatch retry collides with the remote branch its own failed first attempt left behind

Origin: overnight dispatch-fleet coordination session, 2026-10-21

Defer-reason: tangential

## Current State

When a dispatched attempt fails after `/build` has pushed (a plan commit, say) and its PR is closed, the remote branch `worktree-dispatch-record-{N}` stays on origin. The retry creates a fresh worktree branch with the same name from `origin/main`. `build/adopted-branch-collision-check.md` then classifies origin's tip as `foreign` and stops with `adopted-branch-collision` before any work starts. Auto mode can't silence that HARD-GATE, so the retry is spent.

Seen on 2026-10-20 and 2026-10-21:
- #3630: attempt 1's PR #3689 was closed with the branch tip at `6a9d5ff`. Attempt 2 collided, and the retry ceiling then applied `bot:blocked` and revoked `auto:build`.
- #3315: attempt 1's PR #3851 was closed with the branch at `9342f0653`, holding only the plan commit `docs/superpowers/plans/2026-10-21-windows-path-producers-3315.md`. Attempt 2 collided.
- #3488 is set up to repeat it. Attempt 1's PR #3885 closed on `failed: build`, and branch `worktree-dispatch-record-3488` sits at `04948b858` with a plan commit its failure comment says is kept "for the retry".

Each time, someone had to delete the branch by hand before the record could build. The failure comment promises the retry will use the committed plan, but the retry can never adopt that branch.

## Deliverables

- Make a retry of a record whose earlier attempt failed after pushing proceed instead of stopping on its own leftover branch. Do one of the following, and state which and why:
  - (a) On the dispatched attempt's failure path (dispatch Settle, or `two-call-gate.md`'s terminal path), delete the record's own remote branch once its PR is closed, and record any plan commit's sha in the failure comment so the retry can read it.
  - (b) In the collision check, recognize origin's branch as this record's own prior attempt (a closed PR whose head is that branch, for the same record number) and adopt or reset it instead of stopping.
- Either honor or remove the "plan committed for the retry" wording in the failure comment, so it never promises something the retry can't do.

## Acceptance Criteria

- A record whose attempt 1 fails after pushing, and whose PR is closed, is retried by the next dispatch without hitting `adopted-branch-collision`.
- A same-name branch whose PR belongs to a different record, or that has no closed dispatch PR (for example a human's branch), still stops as `foreign`.
- The failure comment's plan-for-retry claim matches what the retry actually does.
- A unit test covers the own-prior-attempt vs foreign distinction, and goes red when that distinction is removed.

## Release Note

Fix dispatched records failing on every retry because their first failed attempt left a branch behind on origin.
