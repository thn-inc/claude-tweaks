**Root cause, test-side only.** `archive-merged.js` resolves PR and issue state through `plugin/bin/lib/reconcile/pr-state.js`, which calls `execFileSync('gh', …)` and `execFile('gh', …)`. Both are bound when the module is required and have no injection point. The test file fakes `gh` by writing a `#!/bin/sh` script named `gh` (no extension) into a temp directory and putting that directory first on `PATH`. Three helpers do this: `installGhWrapper` (line 91), `installGhPrWrapper` (line 124) and `installGhIssueStateWrapper` (line 156). On win32, Node's (libuv's) command lookup appends `.com` and `.exe` to an extensionless name and never runs an extensionless file, so the stub is invisible. The runner's own `gh.exe` answers instead. The job has `GH_TOKEN` set, so that real `gh` makes an authenticated call for a fixture repository that does not exist (`acme/w`, or no remote at all), exits non-zero, and `classifyExecError` correctly reports `network-failure`. That is the excerpt's `"reason":"network-failure"`. The product classification is right: a real `gh.exe` ran and failed. This is not a Windows launch failure misread as an answer, because `gh` ships as `gh.exe` on Windows and lookup finds it. This is the same defect #3506 fixed in the two sibling files.

**The fix is reproduced by simulation, not by a Windows run.** A scratch `--require` preload swapped `child_process`'s `execFileSync`/`execFile`/`spawn`/`spawnSync` so that a bare `gh` resolves the way win32 resolves it: try `gh.com`/`gh.exe` on `PATH`, otherwise use a fake runner `gh` that prints `no git remotes found` and exits 1. ## Release Note

Fixed a reconciler test suite that failed on Windows checkouts because its fake GitHub CLI never ran there, with no change to plugin behavior.

## Technical Approach

This is a test-side fix that applies #3506's ruling to the third file with the same defect. Behavior only one platform can produce gets a per-test `skip` with a stated reason. `tests/console-execute.test.js` (#3358) and the two sibling reconcile suites already do this.

Rejected: giving `pr-state.js` an injectable runner, so the tests stop faking `gh` through `PATH`. #3506 rejected it because that would change a production module that `archive-merged.js`, `release-merged.js`, `reap-merged.js` and others depend on, for a test-only platform gap. The resolver logic is platform-neutral, and the POSIX run covers it.

Also rejected: a `gh.cmd` stub next to the extensionless one. libuv appends only `.com`/`.exe` for a bare name, so it would never be found either. A `.cmd` would also need the `cmd.exe` launch path the parity skill warns about.

Keep the skip per test, not file-wide: 97 tests install no stub and pass on Windows today.

To re-derive the stub set, a small Node script splits the file at top-level `test(` / `function` boundaries. It marks a test when its body, or any helper it calls (transitively), calls an `installGh*` helper. At shaping time that took one indirection: `fixtureOrdinaryMergedNoConsole` calls `installGhWrapper`.

For local evidence before the Windows dispatch, use the shaping-time simulation from Current State. It is a scratch `--require` preload that resolves a bare `gh` the way win32 does: `.com`/`.exe` only, otherwise a fake runner `gh` that exits 1. Run it from a scratch cwd, never from the worktree. It must give `wrapped[util.promisify.custom]` a promise form, because `pr-state.js` calls `promisify(execFile)` when it loads. Report its result as a simulation.
