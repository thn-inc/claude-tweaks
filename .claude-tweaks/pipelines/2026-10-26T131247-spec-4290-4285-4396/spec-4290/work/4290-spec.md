# 4290: Windows: chmod-based permission tests assume POSIX denial and mode bits; skipUnderRoot misses win32

Origin: #2767 class split — classification of windows-regression run 40169646104 (main 6a41ebe3a)

Defer-reason: genuinely-larger

**Related:** #2767, #4121 (this record takes its E half), #3429, #3742, #1853

## Current State

These tests simulate a permission failure with `fs.chmodSync` (`0o000`, `0o500`, `0o555`), or assert the mode bits a file was created with. On win32, Node's `chmod` only toggles the read-only attribute. It never denies a read or a directory listing, and `statSync().mode & 0o777` reads back `0o666` (438) whatever was requested. The shared guard `skipUnderRoot` (`tests/helpers/root.js`) keys on `process.getuid() === 0`, and `getuid` is undefined on win32, so it never skips there. Two files already work around this with their own constants: `tests/skill-load-report-cli.test.js:112` (`CHMOD_DENIAL_SKIP`) and `tests/bin-lib/reconcile/ledger-residue.test.js:291`. `tests/permission-sim-root-skip-conformance.test.js` requires every chmod-using file to import `root.js` and call `skipUnderRoot(` (line 36).

The two kinds in the failing set:

- **Denial simulation (13 tests).** The read, list, write or rename the test expects to fail succeeds on Windows. For example, `scope.test.js:131` reports nothing on stderr, `hooks-worktree-detect.test.js:160` gets a path back instead of `null`, and `reconcile.test.js:605` archives the "unreadable" dir.
- **Mode-bit read-back (2 tests).** `tests/install-statusline-wrapper.test.js:47` and `:108` assert `0o755`/`0o644` and get `438`.

15 tests in 9 files fail on Windows (line numbers as of 988cc584d).

## Deliverables

- Extend `tests/helpers/root.js` with a `chmodDenialSkip(reason)` that returns node:test's `{ skip }` options shape. It covers root with the caller's reason and win32 with `win32: chmod does not deny access`. Also add a `MODE_BITS_HONORED` predicate (false on win32).
- Teach `tests/permission-sim-root-skip-conformance.test.js` that `chmodDenialSkip(` satisfies the rule as well as `skipUnderRoot(`, and keep its go-red self-check.
- Decide each denial test individually. Where the module under test already takes an injectable fs or reader (for example a `deps`/`readdir` parameter), inject the throwing call so the failure branch also runs on Windows. Otherwise apply `chmodDenialSkip`. Do not add a production seam only for this. The branch is platform-neutral, so Linux CI covers it.
- For the two mode-bit tests, guard only the mode assertion with `MODE_BITS_HONORED` (the skill's mode-bit row) and keep the rest of each test running on win32.
- Migrate the two existing ad-hoc constants to the helper.
