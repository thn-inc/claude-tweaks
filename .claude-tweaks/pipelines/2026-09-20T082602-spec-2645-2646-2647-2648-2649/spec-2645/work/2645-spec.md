# 2645: browse: migrate qa-agent.md to Playwright CLI syntax (agent-browser migration, part 3a)

Surface: infra

## Overview

`plugin/agents/qa-agent.md` is the QA validation subagent's own definition — it owns a single
named `agent-browser` session and drives it through user-story steps, taking annotated screenshots
at each one. It is the heaviest single consumer of `agent-browser` CLI syntax in the plugin (26
hits: `--session`, `open`, `trace start`/`stop`, `snapshot -i -c`, `find`,
`screenshot --annotate`, `close`). This record translates every one of those command strings to
Playwright CLI syntax, per `plugin/skills/browse/playwright-cli-reference.md`'s Operation
vocabulary table, so the agent drives the new backend instead of the retired one. This is
sub-project 3a of a five-part consumer migration (`docs/superpowers/specs/2026-09-20-playwright-cli-consumer-migration-design.md`,
now absorbed into this and its four sibling records) — sub-projects 1 (spike) and 2 (reference doc
+ init detection, #2626/#2627) have already shipped.

**Complexity:** Medium
**Estimated tasks:** 4

- Retiring `agent-browser-reference.md` itself — that is sub-project 4, out of scope here.

      `playwright-cli -s=<name> open <url>`.
- [ ] Translate every `agent-browser --session <name> trace start` / `trace stop <path>` call —
      the Operation vocabulary table has no `trace` row, so resolve the actual Playwright CLI
      trace-command syntax against the bundled self-docs first (see Technical Approach), then
      apply it. `qa-agent.md`'s `<path>` arguments are placeholder text inside an agent prompt
      template, not literal file paths, so the reference doc's absolute-path caution applies here
      as an instruction to the agent reading the template — confirm the surrounding prose already
      tells the agent to always supply an absolute path when it fills in `<path>`, and correct it
      if it doesn't, rather than editing the placeholder token itself.
- [ ] Translate every `agent-browser --session <name> snapshot -i -c` call to
      `playwright-cli -s=<name> snapshot` (the interactive/context flags have no separate
      Playwright CLI equivalent — the plain `snapshot` command returns `eN` refs directly, per the
      reference doc's Ref-based element snapshot row).
- [ ] Translate every `agent-browser --session <name> find <locator> <value> <action>` call.
      Per the reference doc's caution, Playwright CLI's `find` is **read-only and text-only** — a
      call using a role/testid/css locator (not plain text) has no direct 1:1 replacement; those
      calls must be re-derived as `snapshot` (to obtain a ref) followed by a separate
      `click <ref>`/`fill <ref> "<text>"`, not translated as a bare rename. A call already using a
      plain-text locator translates directly to `find "<text>"`.
- [ ] Translate every `agent-browser --session <name> screenshot --annotate <path>` call to
      `playwright-cli -s=<name> screenshot --filename=<path>` — same placeholder-path handling as
      the trace deliverable above (confirm/correct the surrounding prose's absolute-path
      instruction to the agent, don't edit the `<path>` token itself); `--annotate` has no
      documented Playwright CLI flag equivalent, so the annotation behavior itself is dropped —
      note this explicitly in the migrated file, in whichever surrounding prose currently explains
      the annotated-screenshot behavior, rather than silently changing what the agent produces.
- [ ] Translate every `agent-browser --session <name> close` call to `playwright-cli -s=<name>
      close`.

## Release Note

Migrated the QA subagent's browser commands from agent-browser to Playwright CLI syntax.

## Technical Approach

Mechanical lookup-and-substitute against `playwright-cli-reference.md`'s Operation vocabulary
table — no new design per command, matching the same approach every sibling record in this
five-part migration uses. Two rules apply on top of the raw substitution, both stated in the
reference doc and restated here so this record is self-contained after the design doc is deleted:

- **Session flag position.** `agent-browser --session <name> <verb>` puts `--session` before the
  verb; Playwright CLI's `-s=<name>` keeps that same before-the-verb ordering
  (`playwright-cli -s=<name> <verb>`) — carry the positioning over, don't invent a new convention.
- **Absolute paths.** Every `screenshot`/`trace stop` path argument must be absolute in the
  migrated form — a file that passed a relative path under `agent-browser` needs that path
  resolved to absolute, not just the command syntax swapped.

**The `trace` gap.** `playwright-cli-reference.md`'s Operation vocabulary table has no row for
`trace start`/`trace stop` — it is not documented anywhere in the file. Per the reference doc's own
Authority section ("On any command error, or before using a command or flag this file does not
list, consult the bundled self-docs — never guess flags from memory"), check Playwright CLI's own
bundled self-documentation (`node_modules/playwright-core/lib/tools/skills/playwright-cli/
SKILL.md` plus its `references/` sub-docs) for the actual tracing command syntax before translating
any of `qa-agent.md`'s 6 trace calls. **If that path is unreadable** (this repo's own permission
settings can structurally deny `Read`/`Bash` access under `node_modules/**` — confirmed during this
decomposition's own red-team review), fall back to `npx --no-install playwright-cli --help trace`
(or the nearest subcommand-help equivalent) or Playwright CLI's own published documentation site;
only treat the gap as genuinely unresolved once both the bundled docs and one of these fallbacks
have been tried. **Before writing a new row**, grep
`playwright-cli-reference.md`'s Operation vocabulary table for an existing `trace` row first — a
sibling record in this five-part migration (parts 3b/3c/3d also hit this same gap) may have already
landed one; reuse it rather than adding a second, potentially divergent row. If a genuine
equivalent exists and no row exists yet, translate to it and add the missing row. If genuinely no
equivalent exists, note the gap explicitly in this record's own Gotchas and mark every affected call
site in `qa-agent.md` with the literal comment `<!-- playwright-cli: no equivalent found for
agent-browser trace start/stop — see issue Gotchas -->` immediately above the untranslated line,
rather than inventing syntax or silently deleting the tracing step.

The `find` translation is the one row in the table that is not a mechanical rename (see the
reference doc's caution): `agent-browser`'s `find <locator> <value> <action>` both searches *and*
acts by default, while Playwright CLI's `find "<text>"` is read-only and text-only. Read each of
`qa-agent.md`'s 26 `agent-browser` hits individually to classify: a call using a plain-text
locator translates directly; a call using a role/testid/css locator (or one that clicks/fills as
its `<action>`) must be re-derived as `snapshot` (obtain a ref) + a separate `click <ref>` or
`fill <ref> "<text>"` call, preserving the original action's effect rather than silently dropping
it or silently converting it into a text search.

`--annotate` (the flag `agent-browser`'s `screenshot --annotate <path>` calls use) has no
documented Playwright CLI equivalent in the reference doc's table — Playwright CLI's `screenshot
--filename=<path>` takes a plain screenshot with no annotation overlay. Translate the command
syntax to `--filename=<path>` and, in whatever prose in `qa-agent.md` currently explains the
annotated-screenshot step to the agent (its own step-by-step QA procedure text), update that
description to match the new unannotated behavior rather than leaving stale prose describing a
capability the migrated command no longer has.

## Gotchas

- The `trace` command gap must be resolved against the CLI's own bundled self-docs (with the
  `npx --no-install playwright-cli --help` fallback if `node_modules/` reads are permission-denied
  — confirmed to happen in this harness during this decomposition's own red-team review) before
  any of the 6 trace calls are translated — never guess a subcommand name from `agent-browser`'s
  own vocabulary onto Playwright CLI. Check `playwright-cli-reference.md` for an existing `trace`
  row before adding one — a sibling record (parts 3b/3c/3d) may resolve this same gap first. See
  Technical Approach.
- `find`'s translation is not a mechanical rename — see Technical Approach. Getting this wrong in
  either direction (leaving a role/testid/css locator untranslated, or naively renaming it to
  `find "<value>"`) either breaks the QA agent's step execution or silently changes a read action
  into a no-op search.
- `qa-agent.md` has no dedicated test file (`find tests -iname '*qa-agent*'` returns nothing) —
  `npm test`'s existing suite is the only automated gate; manual read-through of the migrated file
  against the 26 original hits is the practical verification step.
- `--annotate` has no Playwright CLI equivalent — don't silently drop the capability without
  updating the surrounding prose that describes it to the agent (see Technical Approach).
