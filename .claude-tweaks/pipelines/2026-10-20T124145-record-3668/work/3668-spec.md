# 3668: archive-run archives a closed run with no rendered console regardless of pending staged/ items

**Related:** #3297 #3249 #657 #1130 #3130

Origin: whole-branch review of #3297 (declined to judge — pre-existing, outside diff)

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/bin/hooks.js`'s `archive-run` verb (~l.1151-1158) refuses archival only on a rendered-but-unresolved console (`readConsoleState === 'unresolved'`). A terminal-status run whose `console.json` was never written (`'none'`) archives unconditionally — the inline comment reasons that terminal status means wrap-up's flow completed.

The fast-lane auto-merge short-circuit (`plugin/skills/wrap-up/auto-merge-short-circuit.md`) never writes `console.json` and surfaces staged proposals only as a non-blocking PushNotification FYI, so a fast-lane run whose `staged/` (or `spec-*/staged/`) still holds pending proposals can be archived out of the console's sight by this verb — the #657/#1130 loss reconcile's `archive-merged.js` guards against via `hasStagedItems` (#3249; #3297's `console-never-rendered-staged-pending` reason). The #3130 incident run (`.claude-tweaks/pipelines/archive/2026-10-16T155630-record-3130/`, pending `staged/reflect-1.md` and `staged/wrap-up-skill-1.md`) already sits in `archive/`.

Relatedly, reconcile's clean-status sweep (`archive-merged.js`'s `iterCleanRunDirs` loop) emits `console-never-rendered-staged-pending` for a closed run but never calls `trackStuckSkip`, so a closed-but-unarchived run in that state never escalates; the two "intentional asymmetry" comments point at each other without stating the reason.

## Deliverables

1. Make `archive-run` apply the same staged-items guard as `archive-merged.js`'s `decideArchiveCore` when `readConsoleState` is `'none'`: refuse, with an actionable message naming the pending `staged/` paths, when `hasStagedItems(runDir)` is true — reuse the existing helper (export it) rather than duplicating it.

2. Decide whether the clean-status sweep should track `console-never-rendered-staged-pending` via `trackStuckSkip`, record the reason in the clean-sweep comment, and implement with a test if adopted.

## Acceptance Criteria

- `archive-run` on a terminal run with no `console.json` and a non-dotfile under `staged/` or `spec-*/staged/` does not archive and prints a message naming the pending items; a test pins it.

- `archive-run` on a terminal run with no `console.json` and nothing pending still archives, unchanged.

- The clean-sweep tracking decision is recorded in a code comment stating its reason, and any adopted behavior has a test.

## Release Note

Cleaning up a finished run no longer hides staged proposals nobody approved when the run never showed its review console.
