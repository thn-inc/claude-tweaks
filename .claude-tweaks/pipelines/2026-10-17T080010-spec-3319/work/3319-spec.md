# 3319: PR-early polish-row omission for all-backend runs: wire it into the composer or retire the creation rule

Surface: infra

**Related:** #1712, #2877, #2997, #3120, #3263, #3278

## Current State

#1712 made the PR-early checklist's `polish` row a creation-time decision. `plugin/skills/_shared/pr-early-run-lifecycle.md` says "Omit a `polish` row only when **every** record in the run has `surface: backend`". `plugin/skills/flow/steps-and-gates.md`'s polish phase-exit paragraph and `plugin/skills/flow/multispec-pr-checklist.md`'s run-level paragraph restate the same rule. Three wording-only `#1712` tests in `tests/pr-early-run-lifecycle.test.js` (lines 186, 202, 207 on `origin/main`) pin it.

Nothing implements it. The body is composed by `plugin/bin/lib/flow/pr-body.js`'s `composePrEarlyBody` (#2997), reached through `plugin/bin/compose-pr-body.js` (#3120). Neither takes a `surface:` input, so every run's PR starts with all five rows, and `tests/bin-lib/flow/pr-body.test.js` pins that (#2877, `CANONICAL_ROWS`). Observed runs agree with the composer, not the prose. All-backend single-record runs #3028 and #2877 got the row and removed it at polish's would-be exit. All-infra bundle PR #3285 (#2719, #3267) reached merge still carrying `- [ ] polish`, which the pre-merge refresh then removed.

The creation clause also covers less than the runtime rule it predicts. It omits the row only for an explicit `surface: backend`, but polish never runs for `infra` or `terminal` either.

**Decision (2026-10-17, brainstorming on this record):** retire the creation-time clause. Every PR starts with all five rows. A run that doesn't polish removes the `polish` row through the paths that already exist and already have to exist for `no-polish`, fast-lane and runtime non-frontend detection:
- single-record: at polish's would-be exit (`pr-early-run-lifecycle.md`'s skipped-phase rule);
- multi-spec: at `_shared/pr-checklist-refresh.md`'s pre-merge refresh, once no spec in the run ran polish.

Implementing `omitPolish` in the composer was rejected. It would add a second mechanism for the same row, need `surface:` plumbing into PR-early Step 3, and still miss `infra`/`terminal`.

## Release Note

The PR checklist's `polish` row now follows one rule for every run: it always starts present, and runs that skip polish remove it, instead of documentation promising an omission the tooling never made.

## Technical Approach

This is a prose-and-test retirement with no code change. The composer already emits five rows, and the removal paths already exist. Edit the three paragraphs to describe what the composer and the phase-exit/pre-merge rules actually do. Then swap the creation-clause wording pins for one behavioral composer test plus one negative prose assertion. Follow `.claude/skills/skill-prose-conformance-tests` when writing the negative assertion: prove it can go red by running it against the current `origin/main` text first.
