# 3513: Extend sdd-ruling-* ratify/reverse to the PR-hosted and multi-spec Review Consoles

Origin: SDD controller final-review finding on #3401 (run 2026-10-17T190411-spec-3401)

Defer-reason: genuinely-larger

## Current State

#3401 (run 2026-10-17T190411-spec-3401) made a load-bearing SDD `Ruling:` line a Pending-review row (`staged/sdd-ruling-{N}.md`, `open` ledger row) with ratify/reverse semantics defined for the single-spec chat console only: `plugin/skills/wrap-up/review-console-appendix.md`'s `sdd-ruling-*` bullet (ratify = `apply` → ledger `accepted`; `reverse` → born-ready reversal record + ledger `deferred`), `review-console-interactive.md`'s Override vocabulary (`ratify {#}` / `reverse {#}`, bare `skip` refused), and `review-console.md` step 1's pointer clause. Under `integration-model: pr-first` with a live PR — the default surface — `review-console-interactive.md` routes rendering to `_shared/console-on-pr.md` and never renders "Present the console"; on the PR, the legend (`console-on-pr.md` ~line 80) and `wrap-up/console-execution.md` (~line 47) treat an unticked item as **declined**, and the chat accelerator `resolve-console --approve {ids} --decline {ids}` (`console-execution.md` ~line 99) has no reverse slot. `flow/multispec-review-console.md` step 1 (~line 138, patches only) and its Override "skip" (~line 152) have the same gap for multi-spec runs, whose per-spec builds stage `spec-{N}/staged/sdd-ruling-*.md`. Result today: a human who unticks a ruling on the PR console to reverse it gets a logged decline, no reversal record, and the row stays `open` (caught later by the nothing-left-behind gate — loud, not silent — but the decision is lost). Found by #3401's whole-branch review (Important #1); #3401's Key Files scoped the record to the chat console, so this was deferred rather than folded into its one fix wave.
