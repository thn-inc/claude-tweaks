# 4585: Review Console files every staged reference repair under Pending review — no staged prefix maps to Reference repairs

Origin: wrap-up Review Console from #4563

Defer-reason: pre-existing-outside-diff

## Current State

`plugin/bin/lib/console/resolve.js` has a `Reference repairs` section (`SECTIONS.REF`, stance approve) and routes the curation engine's `references` row to it (`ENGINE_ROW_SECTIONS`), but `engineItems` skips a staged finding whose `stagePath` names a `staged/` file ("already an item via staged/"), so that file is classified by `SECTION_MAP` — and no `SECTION_MAP` row or `CANONICAL_PREFIXES` entry maps to `SECTIONS.REF`. `plugin/skills/wrap-up/reference-sweep.md` names no staged filename either.

So every reference repair the Broken references row stages resolves `pending (unmapped-prefix)` at the console — never in Reference repairs, never auto-resolved at `unattended` — and lands as human residue that blocks a clean close. Observed in #4563's wrap-up (run 2026-10-30T061610-spec-4563): `staged/references-1.md`, a one-line dead spec-pointer repair, showed as `Pending review | references-1.md | pending | unmapped-prefix`.

## Deliverables

Give reference repairs a canonical staged prefix (e.g. `wrap-up-reference-`) mapped to `SECTIONS.REF` in `SECTION_MAP` and listed in `CANONICAL_PREFIXES`.

Name that exact filename shape in `reference-sweep.md`'s staging step, so a judge writes it.

## Acceptance Criteria

A run whose `staged/` holds `wrap-up-reference-1.md` and whose engine state names it as a staged `references` finding resolves that item in `Reference repairs` with resolution `approve` under `--policy console-auto` (a `tests/bin-lib/console/resolve.test.js` case).

`grep -n -F "wrap-up-reference-" plugin/skills/wrap-up/reference-sweep.md` returns a match.

## Release Note

Broken-reference repairs found at wrap-up now show in the Review Console's Reference repairs section instead of waiting for you as unreviewed items.

### Key Files
