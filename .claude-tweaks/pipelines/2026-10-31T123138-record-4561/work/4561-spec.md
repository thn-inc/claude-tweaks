# 4561: Unify the line-anchored section-heading rule across release-note-repair, near-duplicate and compose-record

Origin: #4367 review/wrap-up (PR #4509), ledger items 7-9; refs #4367

Defer-reason: pre-existing-outside-diff

## Current State

#4367 (PR #4509) made `findSection` in `plugin/bin/lib/issues/record-payload.js` match a record section heading only when it starts its own line, with fence tracking (`fencedLineRanges`, column-0 fences). Three other modules still keep their own heading or fence rules:

- `plugin/bin/lib/release-note-repair/apply.js:25`: `FENCE_OPEN` accepts an indented fence opener, while `findSection`'s `fencedLineRanges` is column-0 only. The repair writer and the shape gate can disagree on which lines are fenced. Every observed disagreement ends in a refused repair, not a bad write (tiebreak-confirmed, low).
- `plugin/bin/lib/issues/near-duplicate.js:121`: `extractCurrentStateAnchors` uses `CURRENT_STATE_HEADING_RE` (h2-h4) with no fence tracking, so a fenced quoted template can supply the anchors (tiebreak-confirmed, info).
- `plugin/bin/lib/compose-record/compose.js:22`: `splitSections` keeps a third line-anchored `## ` heading rule with no fence tracking.

The section-heading rule is now defined in four places.

## Deliverables

1. Route all three modules through `findSection`/`extractSection` (or one shared heading-and-fence helper exported beside it), so one rule decides what counts as a heading line and which lines are fenced.
2. Settle the fence-opener question once (column-0 only, or indented openers too) and apply it in the shared helper, so the repair writer and the shape gate agree.
3. Add tests showing each of the three callers ignores a heading inside a fenced block and agrees with `findSection` on the same body.

## Acceptance Criteria

- [ ] `release-note-repair/apply.js`, `near-duplicate.js` and `compose-record/compose.js` keep no heading or fence regex of their own; each calls the shared rule.
- [ ] For a body whose `## Release Note` / `## Current State` heading appears only inside a fenced block, every caller treats it as absent, matching `findSection`.
- [ ] `apply.js` finds the `## Original request` boundary as the first unfenced line the shared heading reader reads as `Original request`; `materialize-format.js`'s `ORIGINAL_REQUEST_RE` and the shape gate's placeholder boundary (`shapeGate`) go through the same shared rule, so no caller keeps a fence-blind heading regex.
- [ ] The existing release-note-repair, near-duplicate and compose-record suites pass unchanged, or with a documented expectation change.

## Release Note

No user-visible change: record section headings are recognized the same way everywhere.

## Decisions

Plan-review answers (2026-10-31), applied to the Acceptance Criteria above.

- **`## Original request` boundary: Reading B.** Deliverable 1 covers it. `apply.js`, `ORIGINAL_REQUEST_RE` and `shapeGate` all move to the shared heading/fence rule in this record, not a follow-up. The resulting change to the materialization shape gate is intended; document it in the PR and pin it with a test for a fenced `## Original request`.

## Build Deviations (Architecture Alignment, Beneficial)
