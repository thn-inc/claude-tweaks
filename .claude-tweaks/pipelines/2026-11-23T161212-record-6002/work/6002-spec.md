# 6002: Start an implementer at the lowest effort its record allows and raise effort before profile

Surface: backend
Risk-flags: public-contract

## Overview

Once a launch's effort can be set (#5941 for agents in a session, #5942 for driver workers), an implementer's first attempt runs at the lowest effort its record's labels allow, and a failure raises the effort one step before it raises the profile. Starting effort follows `risk:`: `risk:low` starts at `low`, `risk:medium` at `medium`, anything higher, or no risk label, at the profile's own resolved effort. A failure an effort step can plausibly fix (red tests, or a failed fix-round re-review) first raises the effort one step on the same profile (never above `high`); a failure it cannot (`BLOCKED`, `cannot-complete`), or a second failure, steps the profile up at that profile's own resolved effort. At most two escalations; past them each lane does what #5997 and #5999 do after their one escalation. Implementers only: a test or a review shows when an implementer failed, while a review that misses a finding looks like a clean review and could never trigger a retry.

The design's done-when for this half: 20 tasks started at `low` show total minutes per task, retries included, no higher than tasks started at `medium` of the same size band, and no more fix rounds per task. Starting effort follows risk, so the two groups also differ in risk; the size match narrows that confound but does not remove it, and the comparison is read as cost and quality per risk class, not as a pure effort effect.

## Decisions

**Decision (plan review Q1, start effort for a `**Role:**`-marker task):** Reading A (user decision 2026-11-23). A task whose profile comes from a per-task `**Role:**` marker starts at `startEffort({ risk, launchEffort: <the marker profile's own launchEffort> })`, never the build profile's. A Fast marker (`transcription`) therefore starts at `null`: no effort and no effort rung, so its first escalation is the profile step, as the Non-Goals require. A Capable marker (`judgment`) starts at its risk-allowed level, capped at Capable's own `launchEffort`. Reading B (marker tasks skip the start rung) was rejected: it would give marker tasks a second rule.

## Release Note

Made implementers start at a lower reasoning effort when the record's risk allows it, and raise the effort before moving to a larger model when an attempt fails.

## Technical Approach

The ladder is one pure function next to the record rule, called in process by the driver and through the CLI by the standard lane, so both lanes climb the same rungs. Effort goes first, for the failures it can fix, because an effort step stays on the same model and per-token price, while a profile step moves Standard (Sonnet) to Capable (Opus) at several times the list price; for Opus the design measured `medium` and `high` turns at about the same cost ($0.077 and $0.074). `BLOCKED` and `cannot-complete` skip the effort rung: they report a missing capability or context, which more reasoning on the same model rarely supplies, so an effort step there would only add a wasted attempt. Risk sets the start because it is the record's own statement of how much a mistake costs; size already chose the model.
