# 3040: Close the Windows-only gaps left by the v6.137.0 release review

Origin: v6.137.0 release gate review — run 2026-10-08T084748-release-standalone (staged/review-2.md, staged/review-3.md, delta review of #3039)

Defer-reason: genuinely-larger

## Current State

The v6.137.0 release gate review (run `2026-10-08T084748-release-standalone`, staged findings `review-2.md` / `review-3.md` plus the delta review of #3039) left four follow-ups. Three are Windows-only (CRLF checkouts, cmd.exe) and invisible to the Linux-only CI (`.github/workflows/test.yml` runs `ubuntu-latest`):

1. **`resolve()` mislabels probe failures.** `plugin/bin/lib/impeccable-engine/index.js` `resolve()` catches every `engine-probe` spawn failure (timeout, launch error such as EINVAL/ENOENT, non-zero exit) and returns `reason: engine-not-installed` with `fix: "<launcher> engine-probe"`. `run()` already separates `timeout` and `exec-failed`. This is what turned the #3039 Windows EINVAL bug into a wrong diagnosis. The resolver reason set (`not-installed` / `upgrade-required` / `engine-not-installed`) is documented in `plugin/skills/design-wrapper/modes/explore.md` and `impeccable-plugin.md`, so adding reasons is a contract change. Confirmed by a lens-3c reproduction pair.

2. **Vacuous doctor guard test on CRLF.** `tests/design-wrapper-doctor-no-fix.test.js:27` `fencedCodeBlocks()` requires a bare `\n` after the fence info string. On a CRLF working tree (`git ls-files --eol`: `i/lf w/crlf` for `plugin/skills/design-wrapper/modes/doctor.md`) it matches zero blocks: the sanity test goes red and the "no fenced block invokes --fix" test iterates nothing. Confirmed by a lens-3f reproduction pair.

3. **Batch-launcher escaping is unpinned on CI.** `launchSpec()` / `escapeBatchArg()` (#3039) escape each argument twice for `cmd /c` plus the launcher's `"%run%" %*` re-parse. The only test asserting escaped output is the win32-only real-process test in `tests/bin-lib/impeccable-engine/windows-launch.test.js`, skipped on Linux CI. Two lens agents showed that dropping the second caret pass, or the trailing-backslash doubling, leaves every test green. The second pass is what stops an argument like `a"&cmd&"` from closing the quote during the `%*` re-parse. Neither the fixture nor a platform-independent assertion covers that case.

4. **Release hook probe is blind on CRLF.** `plugin/bin/lib/release-preflight/pack.js` `ON_LINE_RE = /^(?:on|"on"|'on'):[ \t]*(.*)$/` never matches an `on:\r` line, because `(.*)$` cannot span the CR. On a Windows checkout every workflow therefore scans as having no trigger, and the pack reported `hook: false` for `.github/workflows/mirror-marketplace.yml` (`on: release: types: [published]`). Release Step 6 then skipped the hook verification. Verified on bytes: the line reads `6f6e3a0d` (`on:\r`), and `gatherReleasePreflight({only:["hook"]})` returns `false`.

## Deliverables

- [ ] `resolve()` returns distinct reasons for a timed-out or unlaunchable probe, carrying `err.code` in `detail`. Make it an expand-contract change: add the reasons, migrate `explore.md` / `impeccable-plugin.md` / doctor-mode tables and every consumer branching on resolver reasons, and keep `engine-not-installed` for a probe that ran and answered "no engine" (exit 127).

- [ ] `tests/design-wrapper-doctor-no-fix.test.js` fence regex accepts `\r?\n`.

- [ ] A platform-independent `launchSpec` test pins the exact escaped `/c` payload for metacharacter, embedded-quote and trailing-backslash args. The win32 real-process fixture gains an `a"&echo pwned&"`-style case whose expected argv requires the second caret pass.

- [ ] `pack.js` workflow scanning normalizes CRLF (split on `/\r?\n/` or strip `\r`), with a CRLF fixture test that would have caught `mirror-marketplace.yml`.

## Acceptance Criteria

- [ ] On Windows, a launcher that times out during `engine-probe` makes `resolve()` return a timeout reason, not `engine-not-installed`. Consumer docs list the new reasons.

- [ ] `node --test tests/design-wrapper-doctor-no-fix.test.js` passes on a CRLF checkout, and fails when a fenced block in doctor.md invokes `--fix`.

- [ ] Removing either caret pass from `escapeBatchArg` turns a test red on Linux CI.

- [ ] On a CRLF checkout of this repo, `gatherReleasePreflight({only:["hook"]})` returns `true`.
