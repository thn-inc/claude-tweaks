# 2398: flow: bare resume invocation (no PIPELINE_RUN_DIR) can mint a duplicate run over a live one

Surface: infra

## Current State

`/claude-tweaks:flow #N {step-subset}` resolves whether to adopt an existing pipeline run
directory or create a fresh one based purely on whether the `PIPELINE_RUN_DIR` env var is set
(`skills/flow/steps-and-gates.md`'s "Adopting an inherited run directory" section, cases 1-5).
When it is unset -- the common shape for a human re-invoking `/flow #N review,polish,wrap-up` by
hand, days or sessions after `/claude-tweaks:dispatch`'s first call (`build,test`) -- resolution
falls straight to case 5 (create fresh), with no check of whether the target record already has
a live claim or an open PR carrying a `claude-tweaks-run:` marker.

`steps-and-gates.md`'s own "Intentional two-call consumer" section documents the resume contract
dispatch relies on: both calls must share one run directory via `PIPELINE_RUN_DIR` passed inline
on the command line, since a dispatched agent inherits no environment. That contract assumes the
caller always knows to pass it. A human resuming manually has no way to know this is required
unless they happen to notice the record's PR body's own "Resume" line -- a convention that exists
(`_shared/pr-early-run-lifecycle.md`) but is never surfaced or enforced by `/flow` itself at the
point it would matter (before minting a second run).

Observed instance: a SessionStart hook's unrelated "unfinished pipeline run" notice happened to
name the record and its PR, which is what surfaced the correct resume command in that session --
but that hook is not guaranteed to fire in every session, and nothing in `/flow`'s own
step-argument resolution checks the target record/issue for a live claim or open PR before
defaulting to case 5. Falling through to case 5 on this shape opens a second draft PR/branch
alongside the real one instead of resuming it.

## Deliverables

- Before `/flow`'s step-argument resolution falls through to case 5 (create fresh) on a
  step-subset invocation -- no `build` in the resolved step list, and `PIPELINE_RUN_DIR` unset --
  check the named record(s) for a live claim (`_shared/issue-claims.md`'s claim-blob read) or an
  open PR whose body carries a `claude-tweaks-run:` marker.
- When either signal is found, either auto-adopt that run directory (preferred, when the signal
  unambiguously names one run) or surface a prompt naming the candidate run directory / PR and
  asking whether to resume it or proceed with a fresh run -- never silently mint a duplicate.
- When neither signal is found, proceed to case 5 exactly as today -- this check must not slow
  down or change behavior for a genuinely fresh, first-call invocation.

## Acceptance Criteria

- `/claude-tweaks:flow #N review,polish,wrap-up` (no `build` in the step list, `PIPELINE_RUN_DIR`
  unset) against a record with a live claim or an open `claude-tweaks-run:`-marked PR no longer
  mints a second run directory/draft PR -- it either resumes the existing run or asks first.
- `/claude-tweaks:flow #N {step-subset}` against a record with **no** live claim and **no**
  open marked PR behaves exactly as before this fix -- proceeds to case 5, no new prompt, no
  added latency for the common fresh-invocation case.
- The check reuses `_shared/issue-claims.md`'s existing claim-read mechanics and the PR-body
  marker convention `_shared/pr-early-run-lifecycle.md` already documents -- no new detection
  mechanism invented for this fix.
- A test exercises the specific shape this record reports: step-subset invocation, no `build`,
  `PIPELINE_RUN_DIR` unset, target record carrying a live claim or marked open PR.

## Technical Approach

Add the live-claim/open-PR check as a new gate inside `flow/steps-and-gates.md`'s adoption
resolution, positioned before case 5's creation path -- the resolution already branches on
`PIPELINE_RUN_DIR` presence and `preflight.json`'s `adoption.value.case`, so this is an additional
branch in the same decision point, not a parallel mechanism. Read the target record's claim state
per `_shared/issue-claims.md`'s "Reading claim state," and search open PRs whose
`closingIssuesReferences` name the target record for the `claude-tweaks-run:` body marker
(`_shared/pr-early-run-lifecycle.md`'s PR-open template). `flow/SKILL.md` Step 3 is the entry
point that reaches this resolution; wire the new gate there or in `steps-and-gates.md` directly,
whichever the existing case-1-through-5 branching structure makes the smaller diff.

### Key Files

  case 5's creation fallback
- `plugin/skills/flow/SKILL.md` -- Step 3, where step-argument resolution reaches this branch

- `plugin/skills/_shared/pr-early-run-lifecycle.md` -- the `claude-tweaks-run:` PR-body marker

  every step-subset invocation with `PIPELINE_RUN_DIR` unset pays this check's cost, including
  the vastly more common genuinely-fresh first-call shape.
