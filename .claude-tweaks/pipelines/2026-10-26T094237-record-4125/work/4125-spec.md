# 4125: Extract verification-brief Step 4's screenshot-route decision into a tested bin CLI

Verified-as-of: d00e3f1c601a93f4ff59eaeafbbbbcc04a5c034e

Origin: reflect hindsight from #4039

Defer-reason: tangential

## Current State

`plugin/skills/wrap-up/verification-brief.md` Step 4 decides where the demo-evidence screenshot commit lands from six inputs, entirely in prose an agent executes: `run-state.json`'s `worktree` field, the current branch name (and whether it matches `^[A-Za-z0-9._/-]+$`), `git rev-parse --show-toplevel` compared exactly against the recorded worktree, `bin/pr-merge-state.js`'s state for the run's PR, `resolvePrState`'s state for the branch, and `console.json`'s `merge.resolution`. The output is one of four routes: current branch + push, evidence PR, `no-pr` commit + push, or the unreadable-state rule.

Every defect #4039's build and review found sat in this prose decision, not in the commands it routes to: the final whole-branch review's push-to-integration-branch critical (fix 8ea9e4cd4), a missing `git add` before the pathspec commit (d7bab23b7), an unstated worktree-path comparison (cb50fdeeb), and five lens 3b/3c findings — a no-worktree run losing the current-branch route, unsafe branch names reaching `node -e`/`git push`, and unhandled failure paths (d00e3f1c6). `tests/verification-brief-evidence-routing.test.js` can only pin phrases, so a reworded rule that changes behavior passes it.

## Deliverables

1. A CLI, `plugin/bin/evidence-route.js --run {run-dir}` (run dir optional), that reads the six inputs itself and prints one JSON line: `{route: "current-branch"|"evidence-pr", branch, state, reason}` — `reason` naming which guard or state decided it. Logic in `plugin/bin/lib/wrap-up/evidence-route.js` as a pure function over the gathered inputs, so every rule is unit-testable without git or gh.

2. `verification-brief.md` Step 4 calls the CLI and routes on its `route`, replacing the prose guard, the own-branch definition, the branch-name rule, and the per-state bullets' route selection. The commands each route runs (commit, push, scratch worktree, PR create, teardown, failure handling) stay in Step 4.

3. Unit tests in `tests/bin-lib/wrap-up/evidence-route.test.js` covering each input combination the prose handles today, plus the conformance test narrowed to the CLI invocation and the per-route commands.

## Acceptance Criteria

- `evidence-route.js` returns `evidence-pr` when the current branch is the integration branch, empty, outside `^[A-Za-z0-9._/-]+$`, or not the recorded worktree's branch (exact toplevel match after dropping a trailing `/`), regardless of PR state.

- It returns `current-branch` for an open or `no-pr` run PR only when the session is on the run's own branch; with no `worktree` recorded, the current branch counts as the run's own, still under the integration/empty/name guard.

- An unreadable state (`gh-absent`, `read-failed`, any unparseable read) returns `current-branch` only for an in-run leave-open console on the run's own branch; otherwise `evidence-pr`.

- Step 4 contains no prose restatement of those rules; it invokes the CLI as its own Bash call and routes on its JSON.

- Each rule above has a unit test that fails when that rule is removed from the module.

- `npm test` passes.
