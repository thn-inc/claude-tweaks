# 4041: release: Step 5 merges without checking origin/main still equals the tip Step 3 reviewed

**Related:** #4012, #3898

Origin: /claude-tweaks:release v6.152.0 run 2026-10-24

Defer-reason: tangential

## Current State

`/claude-tweaks:release` Step 3 reviews `{base}..origin/{branch}` at the tip it fetched. Step 5 (`plugin/skills/release/execute.md`) then merges the release PR after the PR-check gate. Delta 5 there re-reads only the PR **title** to re-gate the bump part. Nothing checks whether `origin/{branch}` still equals the tip Step 3 reviewed. release-please squash-merges onto the current `main`, so every commit that lands between Step 3's fetch and the merge ships in the tag unreviewed by the release gate.

Observed 2026-10-24 during the v6.152.0 release. `main` moved d27fb609b → f65b7eab3 (5 PRs, 342 files) during Step 3's review. It moved again to 9d8132196 (8 PRs) before the merge, and again to c779e57a1 during the follow-up. The operator caught it only because the session happened to re-run `git ls-remote` before merging. One of the unreviewed deltas had broken `main` (#4016), and the next carried a high-severity `verify.js` bug that the delta review then blocked on.

## Deliverables

1. Immediately before the merge, Step 5 compares `origin/{branch}` with the tip Step 3 reviewed, recorded as a run fact at Step 3. *(As built: pr-first only. local-merge tags the reviewed local tree, and `release-local.js`'s push is ancestry-checked, so a moved origin is refused rather than shipped unreviewed. The run fact is the `at reviewed tip {tip-sha}` clause on Step 3's marker line. The fence fetches with `--quiet`, so that a fetch which moves the ref is not misread as a git error. Under `--as`, the run's own `Release-As:` commit advances the reviewed tip only when its parent is the reviewed tip.)*
2. When they differ, Step 5 does not merge. It runs a supplementary review over `{reviewed-tip}..origin/{branch}` only, with the same test gate run at the new tip, then repeats the comparison. A blocking delta verdict fires the existing `review: blocking` HARD-GATE. *(As built:*
   - *A move whose arrived commits touch only `.claude-tweaks/pipelines/` advances the reviewed tip with no review and does not count toward the bound, because run dirs never ship (Step 3's rule).*
   - *Before the pull, the branch is asserted. The pull uses `--no-autostash`, so it never touches a sibling's branch or work-in-progress in the shared main checkout.*
   - *A clean delta review re-enters the PR-check gate, not the merge.*
   - *The bump is re-gated on the higher of the PR title's part and the arrived commits' conventional-commit part. A stale, un-re-rendered title therefore cannot ship an arrived breaking change under a minor.)*
3. After a bounded number of moves (a release-policy value, default 2), the run stops `HELD` with reason `integration branch kept moving`. It names the commits that arrived and suggests holding merges, rather than chasing the tip indefinitely. *(As built: the policy key is `release-tip-moves` (integer, `min: 0`, where 0 holds on the first move). An unreadable value fails closed. The arrived-commit list is staged in `release-held.md` and also printed under Step 8's HELD line.)*

## Acceptance Criteria

- A conformance test pins execute.md's pre-merge tip comparison and its supplementary-delta branch. Reverting the prose turns it red.
- release/SKILL.md Step 3 records the reviewed tip sha in the run's decisions log, and Step 5 cites that value rather than re-deriving it.
- The bounded-moves stop renders `HELD` with the named reason and the list of arrived commits.
- `npm test` passes.

## Release Note

`/claude-tweaks:release` no longer merges a release when `main` has moved since its review; it reviews the new commits first or holds the release.
