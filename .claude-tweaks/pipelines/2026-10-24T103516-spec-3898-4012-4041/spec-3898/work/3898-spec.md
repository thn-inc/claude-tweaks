# 3898: release: a finished release's run dir stays clean and unarchived, so the next release adopts it and its staged findings have no consumer

Surface: infra

**Related:** #2870, #3977, #3979

## Current State

A finished standalone `/claude-tweaks:release` run leaves its run directory behind as `status: clean` and never archives it. Step 8 calls `hooks.js close-run --run "{run-dir}"` on a created directory (`plugin/skills/release/SKILL.md` Step 8), but nothing in the skill moves the directory to `.claude-tweaks/pipelines/archive/`.

That leftover directory causes two observed failures:

1. **The next release adopts it.** Step 0 resolves the run dir with `resolve-run-dir --spec-slug release` (no `--create`), which takes `run-dir-resolve.js`'s step-2 path: `newestMatch(pipelinesRoot, 'release')` returns the newest matching directory, rejecting it only when `archiveStatus` reports an archived counterpart. `isDeadRunDir` (#1962) excludes `interrupted` and worktree-orphaned `active` directories, but not `clean` ones. Step 0 then classifies the finished release's directory as **inherited**. In the observed run, the second release inherited the first release's `decisions.md`, its `## /review` marker, and its `review-auto-apply-ceiling` pin; the operator had to mint a fresh directory by hand and log a superseded note. Because the run reads as inherited, Step 8 also skips both its own `close-run` and its `## Next Actions`.
2. **Staged review findings have no consumer.** Step 3's whole-branch review stages every finding (ceiling `none`, so nothing auto-applies). Step 4's console reports the review verdict as a count (`console.md`'s Review row), and a non-blocking verdict, or a blocking one a human proceeds past, lets the release ship. Nothing afterwards files the staged findings as records or declines them. In the observed run, 2 confirmed medium, 8 confirmed low and 11 low-confidence findings sat in `staged/review-1.md` of a `clean`, unarchived directory until an unrelated later `/claude-tweaks:wrap-up` found them and filed them by hand.

#2870 (closed) fixed a stale, never-closed standalone directory being resolved as current. A `clean` release directory still is.

## Deliverables

1. A completed standalone release run never leaves its own run directory where a later release's Step 0 adopts it. **Decided 2026-10-24 (release-local, both halves):** (a) Step 8 archives its own **created** run directory (`hooks.js archive-run`) after `close-run`, once item 2 has disposed of every staged finding; (b) Step 0 refuses to adopt a resolved release run directory whose `run-state.json` status is terminal (`clean`/`closed`), and mints a fresh standalone directory instead, so a leftover from before this fix (or a run whose archival failed) is never inherited. *(As built: Step 0 also refuses any step-2 directory stamped `createdBy: "release-standalone"` whatever its status, because a release that stopped before Step 8 stayed `active` and was otherwise re-adopted; every exit after the mint runs Step 8's close-out; and the mint omits `--spec-slug` so it cannot re-adopt the refused directory.)* Step 0's "a prior standalone release run's directory counts" clause is rewritten to match. `run-dir-resolve.js` is **not** changed (see Technical Approach).
2. Before a release run closes, every finding Step 3 staged ends in exactly one terminal disposition: filed as a backlog record, or explicitly declined, with the disposition logged to the run's `decisions.md`. "Left in `staged/` with no consumer" is no longer a reachable end state.
3. An inherited run directory (a parent pipeline's) keeps today's behavior: release never archives or closes it.
4. Tests covering both failure modes in the Current State.

## Acceptance Criteria

- After a standalone `/claude-tweaks:release` completes (`released`, `HELD`, `PARTIAL` or `failed`), a second release invocation's Step 0 classifies its run directory as **created**, not inherited, and never resolves the first run's directory.
- A conformance test pins release/SKILL.md Step 0's terminal-status refusal (a resolved release directory whose `run-state.json` status is `clean`/`closed` is not adopted; a fresh standalone directory is minted and the run is **created**) and Step 8's archive-own-created-directory step, and reverting either prose change turns it red.
- After a release run whose Step 3 staged at least one finding, every staged review finding has a logged terminal disposition (filed as `#N`, or declined with a reason) in that run's `decisions.md` before the run closes.
- An inherited run directory is neither archived nor closed by release, and a test pins this.
- `npm test` passes.

## Release Note

Release runs no longer leave their run directory behind for the next release to reuse, and every staged review finding is filed or declined before the run closes.

## Technical Approach

Two independent fixes, one per failure mode.

**Adoption — decided: release-local** (maintainer decision 2026-10-24, issue comment 6383154978). Step 8 archives its own **created** directory after `close-run` (the `hooks.js archive-run` verb `wrap-up/cleanup-procedures-execution.md` Section B already uses), once item 2 below has disposed of every staged item; and Step 0 checks the resolved directory's `run-state.json` status itself, minting a fresh standalone directory when it is terminal. The resolver-wide alternative (`run-dir-resolve.js`'s step-2 match refusing `clean` directories for every `--spec-slug` caller) was rejected here: it edits the code #3979 is rewriting onto run-liveness right now, and it would change resolution for every caller. Do not touch `run-dir-resolve.js` in this work.

**Staged findings.** Give Step 3's staged findings a consumer before close-out, reusing an existing disposition path rather than inventing one: wrap-up's leftover routing, which files `Defer-reason:`-carrying records, is the closest precedent. A headless `--train` firing must also reach a terminal disposition without a human, so the routing must work at `autonomy: unattended`. *(As built: `release/disposition.md` reuses `review/step3-routing.md`'s Defer branch, the same `Defer-reason:` filing, with the materiality-floor digest. It inventories every staged file plus `decisions.md`-only `STAGED` lines after Step 3's marker. Approval has three cases: zero-click at `unattended` under `consoleAutoResolve`, where `release/disposition.md` is now registered as a third caller; one end-of-run `AskUserQuestion` when a human is reachable; and left-staged, logged as degraded, when headless below `unattended`.)*

### Key Files

- `plugin/skills/release/SKILL.md` — Step 0 resolution, Step 3 staging, Step 8 close-out and archival
- `plugin/skills/release/console.md` — Review row, if staged findings get a disposition surface there
- `tests/` — release-skill conformance test for the Step 0 terminal-status refusal, the Step 8 archival, and the staged-findings disposition

## Gotchas

- Step 0's inherited-vs-created verdict is computed once and never re-read from disk; any archival must happen after Step 8 has used it.
- `archive-run` refuses a non-terminal run and a rendered-but-unresolved console (#1130). The staged-findings disposition must therefore complete before archival, or archival will refuse.
- Archiving an inherited directory would break the parent pipeline's own event logging (`docs/hooks.md`'s Ownership section); only a created directory may be archived.
- `archive-run` commits only tracked `work/` and audit files (#3721). A release run dir is fully gitignored, so its archival is a plain move with no commit, and needs no sanctioned path under `worktree-always`.

The operator had to mint a fresh dir by hand and log a superseded note. In the second case, 2 confirmed medium, 8 confirmed low and 11 low-confidence findings sat in `staged/review-1.md` of a `clean`, unarchived dir.
