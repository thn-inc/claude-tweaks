# 3470: Sweep git path-list readers for -z and --end-of-options — five call sites split C-quoted output on newlines

Origin: reflect full from #3298

Defer-reason: tangential

## Current State

`plugin/bin/lib/verify/changed-files.js` reads every git path list with `-z` and `--end-of-options` (lines 138, 179, 187) and documents why: without `-z`, `core.quotepath` C-quotes any non-ASCII path (`"docs/caf\303\251.md"`), so a newline-split reader sees a path that matches nothing; without `--end-of-options`, a dash-leading ref or range is parsed as a git option.

#3298's composer repeated the newline-split pattern for `git diff --name-only` and review had to add both flags after the fact (`0e23a2f09`). Five sibling readers in the plugin still split git path output on newlines with neither flag:

- `plugin/bin/lib/merge-size-probe.js:46` — `git diff --no-renames --name-only {integration}...{head}`
- `plugin/bin/lib/wrap-up/facts.js:173` and `:176` — `git diff --name-only {base}...HEAD` and `git diff --diff-filter=RD --name-status {base}...HEAD`
- `plugin/bin/lib/wrap-up/engine-verify.js:623` — `git diff-tree --no-commit-id --name-only -r {sha}`
- `plugin/bin/lib/release-preflight/pack.js:233` — `git ls-tree --name-only {tipRef}`, `.split('\n')`
- `plugin/bin/lib/hooks/pre-tool-use.js:330` — `git diff --cached --name-status`

No `_shared` contract states the discipline, so each new reader re-derives it or misses it (`gh-api-module-pattern` covers `gh` calls, not git path reads).

## Deliverables

- [ ] Each of the five readers above passes `-z` and splits on NUL (`--name-status -z` readers parse the status/path records accordingly), and passes `--end-of-options` before any ref, range, or sha argument.
- [ ] One contract paragraph — in the `_shared` file that owns git-invocation conventions, or a new short `_shared/git-path-read.md` cited from it — states the rule: a git path-list read uses `-z` + NUL split and `--end-of-options`; `changed-files.js` and `compose-subject.js` are the reference implementations.
- [ ] A conformance test greps `plugin/bin/**/*.js` for `--name-only`/`--name-status` git argv arrays and fails on any that lacks `-z`.

## Acceptance Criteria

- A fixture repository with a path `docs/café.md` changed on the branch: `merge-size-probe.js`, `wrap-up/facts.js`'s blast-radius probe, and `pre-tool-use.js`'s staged-file read each report that path unquoted (`docs/café.md`), never `"docs/caf\303\251.md"`.
- `grep -rn -- "--name-only\|--name-status" plugin/bin --include='*.js'` lists no git argv array without `-z` on the same line, and the conformance test goes red when `-z` is removed from any one of them (revert to confirm).
- `git grep -n -- "-z" plugin/skills/_shared/` finds the contract paragraph, and it names `changed-files.js` as the reference implementation.

## Release Note

Every plugin git path-list reader now handles non-ASCII paths and dash-leading refs the same way — no silent mis-scope on a C-quoted path.
