# 3598: Close the #3047 QA-staleness follow-ups: Step 3 Routing waves, untracked files, dirty base, never-run status, wider-than-wave selection

Origin: ledger resolve gate (#3047 build ledger rows 5, 7, 8, 9, 10)

Defer-reason: tangential

## Current State

#3047 made `/claude-tweaks:review` Step 6.7 re-run the QA stories an applied fix wave touched and render a stale-QA qualifier on the QA Validation line when that re-run cannot run (`plugin/skills/review/code-mode-steps.md` Step 6.7 item 4, `plugin/skills/review/review-summary-template.md`). The build and review closed it and left five known gaps, each deferred with its origin recorded in the #3047 build ledger (`docs/plans/2026-10-19-review-qa-rerun-after-fix-wave-3047-ledger.md`, rows 5, 7, 8, 9, 10):

1. Step 3 Routing fixes land before Step 6.7, so they also make QA stale, and the qualifier wording ("the review's fix wave") reads broader than what is covered (spec Gotcha, out of scope there).
2. `git diff --name-only {WAVE_BASE}` ignores untracked new files from an uncommitted Fix-now edit.
3. A tree already dirty before the wave makes the gate count pre-wave edits as wave edits (a false re-run or staleness claim, never false freshness); suggested `WAVE_BASE=$(git stash create || git rev-parse HEAD)`.
4. The qualifier can attach to a pre-wave `Skipped`/`Not run` status, which reads self-contradictory, and item 4 does not say what to merge into when there are no pre-wave per-story results (also review single-agent finding 3, `staged/review-unconfirmed-1.md`).
5. `qa affected` selects by `verify.js --changed-files`, wider than the wave, so the re-run can include stories the wave did not touch (cost only).

## Deliverables

1. Decide and document whether Step 3 Routing fix waves re-run affected QA stories too, or narrow the qualifier wording to Step 6.7 only.
2. When there are no pre-wave per-story results, say what the QA line renders instead of a qualifier on a never-run status.
3. Close or explicitly accept gaps 2, 3 and 5 above (untracked files, dirty-before-wave base, wider-than-wave selection), each with a pinned wording in `tests/review-qa-rerun-after-fix-wave-conformance.test.js`.

## Acceptance Criteria

- `plugin/skills/review/code-mode-steps.md` states, for a Step 3 Routing fix wave, whether the affected-story re-run applies.
- `plugin/skills/review/review-summary-template.md` states what the QA line reads when the pre-wave status was Skipped or Not run.
- Each of gaps 2, 3 and 5 is either fixed or stated as accepted in the same two files, and `node --test tests/review-qa-rerun-after-fix-wave-conformance.test.js` pins the new wording.
