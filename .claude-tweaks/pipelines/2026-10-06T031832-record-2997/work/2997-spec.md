# 2997: PR-early lifecycle can open a run's PR without its template, and nothing restores it before merge

Origin: dispatch of #2980-#2984 (session 6ccd43b3), group 3 PR #2996

Defer-reason: pre-existing-outside-diff

## Current State

`_shared/pr-early-run-lifecycle.md` defines the run PR's body template: a `<!-- claude-tweaks-run: {run-id} -->` marker on the first line, a `phases-start`/`phases-end` checklist, and a `fixes-start`/`fixes-end` block carrying one `Fixes #{n}` per record. Nothing composes that template mechanically: the agent running `/flow`'s PR-early step writes the body by hand and passes it to `gh pr create`.

Observed on PR #2996 (record #2982, run `2026-10-05T071404-record-2982`, a dispatched `build,test` call): the PR was created at 2026-10-05T07:31:37Z with a freeform `## Summary` body carrying none of the three markers. GitHub's `userContentEdits` for the PR shows exactly two versions — the creation body and a later manual restore — so it was opened without the template, not overwritten afterwards.

Nothing downstream repairs it. `_shared/pr-checklist-refresh.md`'s phase-checklist update treats a missing delimiter pair as a best-effort skip (the run logged `SKIP ... body carries no phases-start/phases-end delimiter pair` twice), and its pre-merge Fixes-block rewrite replaces the fixes span only when one exists. The file calls a stale title, checklist or Fixes block "cosmetic, never a merge blocker". The run reached `pending-review` with `closingIssuesReferences` empty; the dispatching session noticed only because it happened to read that field, and restored the template by hand.

A missing block is not cosmetic, on three counts:
- `partitionByOpenLinkedPR` (`bin/lib/issues/record.js`) keys dispatch's open-linked-PR exclusion (#1224) on `closedByPullRequestsReferences` alone, so a record whose PR has no closing reference stays dispatch-eligible while that PR is open (only the claim stands in the way, until it is released).
- `_shared/github-pr-scan.md`'s unarmed-PR and stale-pending scans recognize plugin PRs only by the `RUN_MARKER` regex, so such a PR drops out of `/help` and `/tidy`.
- A merge through GitHub's UI (rather than `pr-first-merge.md`'s `compose-subject.js` path, whose commit message carries its own `Fixes` lines) does not close the record.

## Deliverables

1. A tested `plugin/bin/` CLI (or an extension of an existing one) that composes the PR-early body from the run directory — run id, phases, resume line, and one `Fixes #{n}` per target — so `_shared/pr-early-run-lifecycle.md`'s `gh pr create` step passes its output via `--body-file` instead of a hand-written body. The template's literal text moves into that module, and the prose cites it instead of restating it.

2. A repair path for a body missing the markers: when `_shared/pr-checklist-refresh.md`'s phase-checklist update or pre-merge refresh finds no run marker, no phases pair, or no fixes pair, it re-inserts the missing pieces (keeping any freeform content the body already has) instead of skipping, and logs one `AUTO` line naming what was restored.

3. Correct `pr-checklist-refresh.md`'s "a stale ... `Fixes` block is cosmetic, never a merge blocker" sentence: a missing Fixes block must be restored before the merge sequence runs (still never a new stop — restoration is mechanical).

4. A test covering a PR body with all three marker pairs absent: the repair step restores all three and preserves the freeform text.

## Acceptance Criteria

- [ ] A `/flow` run's PR-early `gh pr create` passes a body produced by the new composer, and the composed body passes `RUN_MARKER` and contains both delimiter pairs and one `Fixes #{n}` per target.

- [ ] Given a run PR whose body has no markers (the #2996 shape), the next phase-checklist update or the pre-merge refresh restores the run marker, phases block and fixes block, keeps the existing freeform text, and logs one `AUTO` line; `gh pr view --json closingIssuesReferences` then lists the run's records.

- [ ] `pr-checklist-refresh.md` no longer describes a missing `Fixes` block as cosmetic.

- [ ] `npm test` passes, including the new tests.


## Technical Approach

### Key Files

- `plugin/skills/_shared/pr-early-run-lifecycle.md` — the `gh pr create` step passes the composer's output via `--body-file`; the template's literal text moves to the module and the prose cites it.
- `plugin/skills/_shared/pr-checklist-refresh.md` — the phase-checklist update and pre-merge refresh restore missing markers instead of skipping; the "cosmetic, never a merge blocker" sentence is corrected.
- `plugin/bin/lib/flow/manifest.js` — home of the existing `composeFixesBlock` (`:218`); the body composer and the marker-repair function reuse it, here or in a sibling module under `plugin/bin/lib/flow/`.
- `plugin/bin/lib/flow/preflight.js` — already parses the `phases-start` span (`:156`); it should read the markers through the same module rather than a second literal.
- `tests/pr-early-run-lifecycle.test.js` — existing prose tests that pin the template text; update for the cite-instead-of-restate change.
- `tests/bin-lib/flow/manifest.test.js` — unit tests for the composer and for repairing a body with all three marker pairs absent.
- `docs/plugin-structure.md` — list the new CLI, if one is added, alongside the other `plugin/bin/*.js` entries.
## Release Note

Pipeline PRs now always carry the run marker, phase checklist and `Fixes` lines, and a PR opened without them is repaired before merge, so merging it closes its records.
