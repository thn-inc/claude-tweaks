# 5152: issue-branch-tracking.js: the generated track-issue-fixes workflow starts a runner on every push to every branch

Surface: infra

## Current State

`plugin/bin/lib/issue-branch-tracking.js`'s `generateWorkflowYaml()` is the single source of the workflow `/claude-tweaks:init` Step 16 writes to an adopter's `.github/workflows/track-issue-fixes.yml` (this repo's own copy is byte-identical to the generator output today — checked with a regenerate-and-diff on 2026-11-10). Verified against source:

- The trigger is `on: push: branches: ['**']`, so every push to every branch creates a run.
- Both jobs carry only a ref condition at job level (`label-fix-branch`: not the default branch; `cleanup-fix-labels`: the default branch). The "does this push reference an issue" test lives inside the job, as the step-level `if: steps.extract.outputs.issues != ''`. A job therefore always gets a hosted runner, and on a private repository every push bills at least one Actions minute to find nothing. A job whose job-level `if` is false is skipped without a runner and bills nothing.
- The plugin's own bookkeeping writes go to two fixed branches that never carry a fix: `claims-registry` (`CLAIMS_BRANCH`, `plugin/bin/lib/issues/claims.js:13`) and `health-state` (`HEALTH_STATE_BRANCH`, `plugin/bin/lib/health-core/durable-state.js:55`). Both constants are exported and are not policy-configurable. Every claim, release and health-sweep write is a `push` this workflow matches.
- `ISSUE_REF_SOURCE` is `\b(?:close[sd]?|fix(?:e[sd])?|resolve[sd]?)\s+#([0-9]+)`, built from the exported `CLOSING_KEYWORD_ALTERNATION`. Every word that alternation accepts contains one of the stems `close`, `fix`, `resolve`, and every match needs a literal `#`. The module's comments call out the case of a keyword and an issue number on different lines (`"This closes\n#123"`), which the in-job extraction handles through `jq --raw-output0` plus `grep -z`.
- GitHub's `contains()` ignores case: `actions/runner`'s `src/Sdk/Expressions/Sdk/Functions/Contains.cs` compares with `StringComparison.OrdinalIgnoreCase` (read from source on 2026-11-10).
- `/claude-tweaks:init` Step 16 (`plugin/skills/init/bootstrap/step-16-non-default-branch-issue-tracking.md`, summarised in `plugin/skills/init/SKILL.md`'s Step 16 paragraph) skips silently whenever the file already exists. An adopter who ran it once never receives a regenerated file.
- No test pins this repo's `.github/workflows/track-issue-fixes.yml` to the generator output, so a hand edit or a forgotten regeneration would go unnoticed.

The reporting project (a private repository, `pr-first`) measured 639 runs in 30 days, 637 of them executing a job, 37 finding a reference — 637 billed minutes, about 7% of its Actions usage. Those figures are the reporter's, not re-measured here.

## Deliverables

1. **Job-level prefilter.** Both jobs' job-level `if` gains a clause on `github.event.commits.*.message` that is false unless the joined commit messages contain `#` and at least one keyword stem. The stems are an exported constant (`PREFILTER_KEYWORD_STEMS`) that the emitted expression is built from, so the YAML and the module cannot drift. The existing ref conditions are kept, ANDed with the new clause, and the extraction and label steps are otherwise unchanged.
2. **A JS model of the prefilter.** Export `prefilterMatches(commitMessages)`. It models GitHub's `join(…, ' ')` followed by case-insensitive `contains`, and the tests use it to evaluate the emitted condition.
3. **Bookkeeping branches excluded at the trigger.** `on.push.branches` becomes `['**', '!claims-registry', '!health-state']`. The two names come from the imported `CLAIMS_BRANCH` and `HEALTH_STATE_BRANCH` constants, not retyped literals. Pushes to those branches then create no workflow run at all.
4. **Superset test.** A new test proves that the prefilter never drops a reference `extractIssueNumbers()` or the in-job `grep` pipeline would find (Acceptance Criteria 2–5).
5. **Adopter upgrade path.** Step 16 stops skipping silently on an existing file. It classifies the file with a new export `classifyExistingWorkflow(content)`, which returns `current`, `prior-generated` or `modified`, and acts on that result:
   - `current`: silent skip, as today.
   - `prior-generated`: the file is byte-identical, after normalising a leading byte-order mark, CRLF line endings and trailing newlines (a Windows checkout with `core.autocrlf` must not read as hand-edited), to an earlier generator output recorded in an exported list of SHA-256 digests (`PRIOR_OUTPUT_SHA256`). It is then regenerated in place and reported in one line, with no prompt. The file is fully derived, so nothing user-authored is lost; Step 14's silent regeneration of `scripts/claude-cloud-setup.sh` is the precedent.
   - `modified`: one `AskUserQuestion` offering "Keep my file (Recommended)" or "Regenerate (discards local edits)". The question names what the regeneration adds: the prefilter and the bookkeeping-branch exclusion.

   `PRIOR_OUTPUT_SHA256` holds the digest of every distinct `generateWorkflowYaml()` output in the generator file's git history since it moved under `plugin/`, computed once at build time from `git log` of `plugin/bin/lib/issue-branch-tracking.js`.
6. **Regenerate this repo's file.** `.github/workflows/track-issue-fixes.yml` is regenerated from the generator, never hand-edited, and a new test pins it byte-for-byte to `generateWorkflowYaml()` output.
7. **Prose.** Step 16's sub-file and `init/SKILL.md`'s Step 16 paragraph describe the prefilter, the excluded branches and the three-way re-run behaviour, replacing "skipped silently once the workflow file exists".

## Acceptance Criteria

1. `generateWorkflowYaml()` output's job-level `if` for both `label-fix-branch` and `cleanup-fix-labels` contains the existing ref condition AND a clause requiring `#` and at least one of `PREFILTER_KEYWORD_STEMS` in `join(github.event.commits.*.message, ' ')`. A test parses the `contains(…, '<literal>')` literals out of each emitted `if:` and asserts that they are exactly `#` plus `PREFILTER_KEYWORD_STEMS`.
2. Language test: every lowercase word of up to 10 letters that `^(?:${CLOSING_KEYWORD_ALTERNATION})$` matches (enumerated from each stem plus every suffix of up to three letters a–z, so the enumeration is exhaustive for this alternation's shape) contains at least one stem. The test also asserts the enumeration found exactly the 9 keyword forms, so a widened alternation fails the test until the stems are revisited.
3. Property test (JS side): over a seeded generated corpus of at least 5,000 commit-message arrays, `extractIssueNumbers(msgs).length > 0` implies `prefilterMatches(msgs) === true`. The corpus covers:
   - every keyword form in lower, upper, title and random case;
   - separators of space, tab, `\n`, `\r\n` and runs of them, including keyword and `#N` on different lines;
   - keyword and reference spread over two commits of one push;
   - revert commits;
   - surrounding noise text.
4. Property test (runtime side): where GNU grep is available (the existing test file's detection helper; skipped with a visible reason otherwise, and it runs in CI on ubuntu), the literal generated extraction script is run over a subset of the same corpus. A non-empty `issues` output implies `prefilterMatches` is true for that input.
5. Non-vacuity: `prefilterMatches` returns false for `['Update README']`, `['refs #12 tidy']`, `['health-state: code-health update']` and `[]`, and for a message containing a stem but no `#`.
6. The emitted trigger's `branches` list is `'**'` followed by `!claims-registry` and `!health-state`, and a test asserts that the names equal the imported `CLAIMS_BRANCH` and `HEALTH_STATE_BRANCH`.
7. `classifyExistingWorkflow()` returns `current` for `generateWorkflowYaml()` output with or without a trailing newline, `prior-generated` for this repo's pre-change `.github/workflows/track-issue-fixes.yml` content (captured as a test fixture from `main` before this change), and `modified` for that same content with one changed comment line.
8. `.github/workflows/track-issue-fixes.yml` equals `generateWorkflowYaml() + '\n'` (pinned by test).
9. Step 16's sub-file documents the three classifier outcomes and their actions, and `init/SKILL.md`'s Step 16 paragraph no longer says "skipped silently once the workflow file exists".
10. The existing `tests/issue-branch-tracking.test.js` assertions still pass unchanged, including the literal-script hard-wrap tests.

## Release Note

Stop the generated issue-tracking workflow from starting a billed runner on pushes that reference no issue, and from running at all on the plugin's bookkeeping branches. Re-run `/claude-tweaks:init` to pick up the new file.

## Technical Approach

Build the prefilter expression in `issue-branch-tracking.js` as a single string constant:

```
contains(join(github.event.commits.*.message, ' '), '#') && (contains(…, 'close') || contains(…, 'fix') || contains(…, 'resolve'))
```

Use it in both jobs' `if: >-` blocks. Generate the stems from `PREFILTER_KEYWORD_STEMS`.

Keep `prefilterMatches` deliberately simple: join with `' '`, then use `includes` on `toUpperCase()` of both sides, which approximates `OrdinalIgnoreCase`. The superset proof needs the model to be no stricter than GitHub. Upper-casing makes it at least as loose for the ASCII stems, and the Gotchas cover the one non-ASCII case-fold edge.

The test corpus generator lives in the test file with a fixed seed. Reuse the existing GNU-grep detection and literal-script runner helpers in `tests/issue-branch-tracking.test.js` rather than adding a second copy.

Compute `PRIOR_OUTPUT_SHA256` with a one-off scratch script: for each commit touching the generator, `git show {sha}:plugin/bin/lib/issue-branch-tracking.js` into a temp dir, require it, hash `generateWorkflowYaml().replace(/\n+$/, '')`, and dedupe. Commit only the resulting digest list, with a comment naming how it was derived. The scratch script stays scratch.

## Gotchas

- **Unicode case folding.** `grep -P -i` in a UTF-8 locale can treat `ſ` (U+017F) as `s`, so `cloſes #1` may match the in-job extraction. `OrdinalIgnoreCase` upper-cases `ſ` to `S`, so `contains` matches it too and the superset holds. A model that used `toLowerCase()` would not (`ſ` stays `ſ`), which is why the model upper-cases. Include `cloſes #1` in the corpus.
- **Order of branch patterns.** A `!` pattern only excludes when it comes after the positive `'**'`, so keep that order. Do not switch to `branches-ignore`: it cannot be combined with `branches` on the same event.
- **Truncated payloads.** GitHub's push payload caps `commits` at 20. The prefilter and the extraction read the same truncated array, so neither drops more than it does today.
- **Branch creation and deletion.** A new-branch push whose commits are already on the remote, or a branch deletion, has an empty `commits` array. `join` of an empty array is `''`, so the job is skipped, matching the extraction's empty result.
- Do not tighten the prefilter towards the regex (word boundaries, `\s+#`). Expressions have no regex, and every tightening step makes the superset harder to prove.
- `prior-generated` regeneration writes a CI file without a prompt. It applies only to a byte-identical earlier generator output, never to anything a human edited.
- A related cost lever for pr-first projects, CI on draft PRs, is #5153's subject. Workflow-cost reporting is #5154's.

## Original request

issue-branch-tracking.js: the generated track-issue-fixes workflow starts a runner on every push to every branch

**Summary:** The workflow `/claude-tweaks:init` Step 16 generates triggers on `push` to `'**'` and gates only its inner step on `steps.extract.outputs.issues != ''`, so every push to every branch starts a hosted runner and bills at least one minute to find there is nothing to do.

**Kind:** Defect

**Affected component:** `bin/lib/issue-branch-tracking.js` (`generateWorkflowYaml()`), init Step 16

**Repro steps:**
1. Run init Step 16 in a `pr-first` project whose repository is private (Actions minutes are billed).
2. Run pipelines for a few weeks. Every phase-exit push, and every write to the `claims-registry` and `health-state` branches, is a `push` event the workflow matches.
3. List the workflow's runs with their job durations and which runs reached the label/comment or strip-labels step.

**Expected vs. actual:**
Expected: a push whose commit messages carry no closing-keyword reference costs nothing.
Actual: in one private project over 30 days the workflow ran 639 times and executed a job 637 times; 37 of those found a reference. The mean job took 3.5 seconds and each billed a full minute, so the workflow billed 637 minutes — 7% of that repository's Actions usage and its second-largest consumer after the project's own CI.

**Suggested fix:** add a prefilter to both jobs' existing job-level `if`. A job whose `if` is false is skipped without a runner, so it bills nothing:

```yaml
if: >-
  github.ref != format('refs/heads/{0}', github.event.repository.default_branch)
  && contains(join(github.event.commits.*.message, ' '), '#')
  && (contains(join(github.event.commits.*.message, ' '), 'close')
    || contains(join(github.event.commits.*.message, ' '), 'fix')
    || contains(join(github.event.commits.*.message, ' '), 'resolve'))
```

`contains` ignores case, and the condition is strictly looser than `ISSUE_REF_SOURCE` (any match needs a `#` and one of the three stems), so it drops no reference the step would have found, including one whose keyword and number sit on different lines. Against that project's history (head commit subjects only) it would have skipped about 92% of the runs. Two further points: `branches-ignore` for the plugin's own bookkeeping branches would stop those pushes from creating a run at all, and because Step 16 is skipped once the file exists, adopters who already have the file need a way to pick up a regenerated one.

**Definition:** Clear
