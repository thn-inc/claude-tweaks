# 3490: wrap-up Section C step 5 teardown-run still archives the run directory before ephemeral-server teardown and claim release

Origin: reflect light from #3192

Defer-reason: tangential

## Current State

`plugin/skills/wrap-up/cleanup-procedures-execution.md` Section C step 5 (the "worktree this session does not occupy" path) runs `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" teardown-run --run "$RUN_DIR" --merged` with no `--remote-ref-only`, and its prose says archival there is "idempotent if Section B already archived this run". `teardown-run` archives the run directory unless `--remote-ref-only` is passed (`plugin/bin/lib/hooks/teardown-run.js` Step 2).

`wrap-up/cleanup-procedures.md`'s Ordering rule says run-directory archival (item 8) is always last, because items 4, 6 and 7 still read files under `$RUN_DIR` (ephemeral-server.txt for item 6, the materialized spec headers for item 7). Section C is item 4, so step 5's `teardown-run` archives the run directory before items 6 and 7 run — the same defect class #3088 fixed at step 5.5 and #3192 fixed at `flow/multispec-review-console.md` Shared teardown step 7, at the one remaining call site.

After #3192 every documented skill-prose caller of `teardown-run` except this one passes `--remote-ref-only`, so the flag's polarity (archive by default, opt out) is what let the same omission recur three times.
