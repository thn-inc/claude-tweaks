# 5230: Cut /claude-tweaks:dispatch over to the queue-pull CLI

Surface: backend

## Overview

This unit cuts `/claude-tweaks:dispatch` over to the queue-pull CLI built in #5227. Step 2's queue pull and Step 3's next-group ranking stop reading embedded scripts and each become one call to `plugin/bin/queue-pull.js`. The outputs, their paths and every downstream reader are unchanged. Design: `docs/superpowers/specs/2026-11-11-pipeline-driver-design.md`, section "Phase 5 — Queue selection in the driver".

The queue pull runs in every consumer project on every dispatch drain, so this is the risky step of the strangler-fig. Before the switch the record runs both paths against this repository's live queue and compares the output files; a difference blocks the cutover and is fixed in the module first. The embedded scripts stay in `queue-pull-script.md` and `next-ranking.md` in this unit, off the default path, so the cutover is reverted by one edit; their removal is the next unit's.

`plugin/skills/dispatch/SKILL.md` is 52,456 bytes against the 52,500-byte Read rail (`RAIL_BYTES` in `plugin/bin/lib/skill-audit/budgets.js`, `Math.floor(25000 * 2.1)`). The edit must leave it at or below the rail with 500 bytes of margin (at or below 52,000 bytes), because other open records also grow it; in practice that means Steps 2 and 3 get shorter.

**Complexity:** Medium
**Estimated tasks:** 7

- Editing or deleting `queue-pull-script.md` or `next-ranking.md` (the removal unit's), or sweeping every other file that cites them (also the removal unit's, except the citations named in the Deliverables below).
- `drive.js --budget` (#5229).
- Changing the report sub-files (`blocked-exclusion-report.md`, `open-pr-exclusion-report.md` and the like) beyond what the cutover forces.
- A new transport: the MCP path stays "the agent fetches, Node computes", now ending in one CLI call in `files` mode.

## Release Note

Switched `/claude-tweaks:dispatch` to select its queue with a command instead of by reading and running an embedded script.

## Technical Approach

- **Compare first.** Do the live comparison before editing `SKILL.md`. Running the scripts' bash for the comparison is the same thing the skill does today, in a scratch session id so it clobbers no real session file. The queue can move between the two runs (a claim lands, a record changes), which is why the runs are back to back and a difference is re-run once.
- **One call each.** Step 2's replacement names the CLI, its transport choice (`gh` when `gh` is available, `files` on the MCP path) and what it writes; everything after it (the exclusion reports, the selection forms) reads the same files as before. Step 3's ranking call writes `dispatch-next-pick.json` as `next-ranking.md`'s script does.
- **Rail.** Removing the "Read the script and run it verbatim" paragraphs and the citations of the script's internals shortens SKILL.md; measure after each edit, because several open records also edit it.
- **Tests.** Follow `.claude/skills/dispatch-queue-exclusion-addition`'s site list and `.claude/skills/skill-prose-conformance-tests` for what is pinned and how to prove a pin can go red: revert one pinned element and see the repointed test fail.
- **Platform.** A CLI call from skill prose is the same on every platform; nothing in the edited prose depends on bash features the script used.

## Gotchas

- Open records edit `plugin/skills/dispatch/SKILL.md` and `queue-pull-script.md` (for example #4589, which renders dispatch Task prompts from a CLI and holds `bot:in-progress` at the time of writing, and #5087, #5072 and #5071, which change queue-pull passes). A pass added to the script after #5227 merged is a parity break: re-run #5227's parity test and the live comparison after every upstream merge, and re-measure SKILL.md's bytes. After the cutover the module is authoritative; the script is kept equal to it only so the revert path stays valid.
- The embedded scripts must stay unmodified so the cutover is reversible by one edit; a stray edit to either defeats the revert path and the parity test.
- On the MCP path the agent still fetches with MCP tools and writes the raw JSON itself, because a Node subprocess cannot call MCP tools; only the compute moves into the CLI. Do not describe the MCP path as "one call" in the prose; the fetch-and-Write calls remain.
- The CLI never falls back from `gh` to `files` silently, so Step 2 must say which transport to use; a Preflight result of "`gh` absent or GraphQL-blocked" selects `files` (`mcp-transport.md`, "Preflight").
- The live comparison needs a quiet queue to be meaningful. Do not run it while a drain is claiming records; a difference caused by a claim landing in between disappears on the re-run, one that reproduces is a module defect.
- ASSUMPTION — verify at build: #5227 has merged with the CLI's transport flag and ranking mode, the pass registry and the parity test; confirm by reading `plugin/bin/queue-pull.js`'s usage text and `tests/bin-lib/dispatch/queue-pull.test.js`, and use the merged names.
