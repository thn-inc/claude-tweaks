# 5551: Make capture and feedback cite the shared needs-definition rubric

Surface: infra
Risk-flags: none

## Overview

`plugin/skills/_shared/needs-definition-judgment.md` is the shared rubric for one judgment: does a captured idea name a genuine open choice (stamp `needs:definition`) or a single clear ask? The file says "Both producers cite this file". Neither does. `capture/SKILL.md` and `feedback/SKILL.md` each restate the rubric in their own words, and the three texts have drifted: the copies lack the shared file's worked examples and its rule on incidental implementation sub-decisions, and the shared file lacks the default the copies state.

This record makes the shared file the one statement of the rubric and has both producers cite it. It is the last part of unit 1.7 of the 2026-11-15 audit simplification design, which decided to keep and cite the file rather than delete it.

**Complexity:** Low
**Estimated tasks:** 3

## Non-Goals

- Changing the rubric's test. The merged rubric is the union of what the three texts already say; where they differ only in wording, the shared file's wording wins, and the copies' "no stated preference" phrase is not carried over: the shared file's "no tradeoff decided" is the test. The producers do take on two things the shared file already states and neither copy has, the worked examples and the rule that incidental implementation sub-decisions leave an idea `clear`; that is intended, and the Release Note says so.
- `capture/SKILL.md`'s override flags, `$DEFINITION_RATIONALE` and the presentation-line format in its `### Judging Definition` section. Those are capture-specific.
- How `/claude-tweaks:specify` reads the label.
- Any other restated rubric in the two skills.

## Release Note

Capture and feedback now judge whether an idea still needs definition from one shared rubric, which also treats incidental implementation sub-decisions as clear.

## Technical Approach

Cite, do not restate (`docs/skill-authoring.md`'s rule for cross-skill contracts, and `.claude/skills/shared-contract-extraction` for wiring a consumer to an existing contract). Each producer keeps what is its own: its variable name, its rendering, its place in its flow.

The citation is an instruction to read the file, placed in the sentence that starts the judgment, so the rubric loads only on runs that reach that step. It adds 1,531 bytes to those runs. The spans replaced measure about 590 bytes in `capture/SKILL.md` (`:417-422`) and about 465 in `feedback/SKILL.md` (`:71-76`); the instruction and mapping that replace them must come in under those, which criterion 5 checks. There is no inline fallback copy by design: that duplication is what this record removes. No conformance test is added: criterion 1's grep is the check that both producers cite the file, and the shared file's own sentence "Both producers cite this file" is the invariant a later change must keep.

## Gotchas

- Keep the `### Judging Definition` heading text exactly; seven places cite it.
- `feedback/SKILL.md:364` says "Step 1's Definition judgment". Keep the word "Definition" in the Step 1 sentence so that reference still reads.
- The shared file gains the default the copies had. Without it, dropping the copies would remove the only statement of what to do when unsure.
- A skill reference inside instruction text must be fully qualified, but this is a file citation, not a skill invocation: write the path as `_shared/needs-definition-judgment.md`, the form other `_shared` citations use.
- `tests/bin-lib/skill-audit/` suites model each entry point's load closure. A new citation adds an edge from `/capture` and `/feedback` to the shared file, which joins their load closures. `git grep -n -E "capture/SKILL|feedback/SKILL" -- tests/bin-lib/skill-audit` finds only history comments in `anti-patterns.test.js`, so no closure or budget fixture there names either skill; run the full suite anyway, since a roster or budget check elsewhere may count the edge.
- `git grep -E` with `\b` silently matches nothing on the maintainer's machine. Use `-F`, `-w` or `-P`.
