# 3819: Decide whether friction events should count the subagent and worktree-gone isolation refusals

Surface: infra

Origin: ledger resolve gate (#3304 final review, I3)
**Related:** #3304, #3675, #3818, #3820, #3876, #3936

## Current State

`plugin/bin/lib/hooks/harness-refusal.js` defines `REFUSAL_FRAGMENTS` (`This session`, ` is isolated in the worktree `, `Refusing to run it`) and `HARNESS_ISOLATION_REFUSAL_RE`, which require the noun `This session`. `post-tool-use-failure.js` uses the regex to log a `wd-guard-refusal` event, and `bash-prefilter.js` uses the signature. The reflect Friction lens reads those events. `tools/upstream-drift/manifest.yml`'s `claude-code` entry asserts each fragment against the installed binary, and `tests/harness-refusal-drift-pin.test.js` keeps the two in lockstep.

Probed against the installed Claude Code 2.1.302 binary (2026-10-24), the refusal noun is chosen by one function:

```
function NI(e){return Tl()?.worktreePath===e
  ? {noun:"This session",possessive:"a worktree-isolated session's"}
  : {noun:"This agent",possessive:"a worktree-isolated agent's"}}
```

So every refusal template (`${noun} is isolated in the worktree …`) says `This agent` whenever the worktree is not the session's own, which is the case for a subagent dispatched with its own isolation worktree. Two more templates are fixed strings: `This agent is isolated in the worktree … no longer exists and the only recovery target is the parent session's shared checkout. Refusing to run there …` and a `${noun}` variant ending `Refusing to run there. Report this instead of retrying.` Neither the `This agent` noun nor `Refusing to run there` matches today's regex, so those refusals produce no `wd-guard-refusal` event.

Lens agents running inside the parent session's own worktree do say `This session` and were counted. That is how #3480's roughly 14 lens-agent refusals surfaced and led to #3675's dispatch-prompt fix. The same waste from an agent in its own isolation worktree is invisible today.

## Deliverables

- [ ] Count both: widen the matcher to the `This agent` noun and to the worktree-gone `Refusing to run there` ending, keeping the `This session` match unchanged
- [ ] Add two fields to each `wd-guard-refusal` event: `actor` (`session` or `agent`, read from the noun) and `variant` (`guard` for the command-shape and different-worktree refusals, `worktree-gone` for the two "no longer exists" templates), so the Friction lens can report the operator's own friction separately from dispatched agents' and flag lost isolation
- [ ] Update `REFUSAL_FRAGMENTS` and the `claude-code` manifest `must-match` values together (noun alternatives plus the `Refusing to run there` signature), and keep `tests/harness-refusal-drift-pin.test.js` in lockstep
- [ ] Have the reflect Friction lens break the count down by `actor` and call out any `worktree-gone` event by name

## Acceptance Criteria

- `tests/hooks-harness-refusal.test.js` logs a `wd-guard-refusal` event for each of: a `This session … Refusing to run it` refusal (`actor: session`), a `This agent … Refusing to run it` refusal (`actor: agent`), a `This agent … Refusing to run it there` different-worktree refusal, and both worktree-gone templates (`variant: worktree-gone`); and logs none for an unrelated Bash failure

## Release Note

Reflect's friction report now counts worktree-guard refusals hit by dispatched agents, not just by the main session.

## Technical Approach

The question was whether these refusals are the run operator's friction. They are the run's friction either way. A dispatched agent's refused command is a wasted turn the run pays for, and it is almost always caused by the dispatch prompt the run wrote, which is exactly the signal that produced #3675's fix. Leaving the narrow match would keep that signal for agents sharing the parent's worktree but hide it for agents in their own, an accident of how the agent was dispatched rather than a deliberate scope. The `actor` field keeps "my own friction" answerable without discarding the rest.

Build the regex from fragments as today: a noun alternation (`This session|This agent`), the isolation clause, a lazy gap, then `Refusing to run` followed by ` it` or ` there`. Derive `actor` from the matched noun, and `variant` from which signature matched: `Refusing to run there` means `worktree-gone`. (Architecture alignment, Beneficial: this replaces the original "presence of 'no longer exists'" rule. At 2.1.302 the two are equivalent, since exactly the two worktree-gone templates end `Refusing to run there`. The signature is a manifest-pinned fragment with unique anchors, whereas `no longer exists` occurs 57x in the binary and cannot be anchored.)
