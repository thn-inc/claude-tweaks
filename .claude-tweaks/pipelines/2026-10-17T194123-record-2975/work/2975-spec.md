# 2975: Micro-plan gate is unreachable for specShapedBody-composed records — no ### Key Files section

Surface: backend

**Related:** #2805

## Current State

`plugin/skills/build/micro-plan.md`'s applicability gate (#1911) requires the spec body's `### Key Files` section (under `## Technical Approach`) to parse to at most one implementation file. An absent section falls through to the full `/superpowers:writing-plans` path by design ("could not parse" is not "parsed to zero").

`specShapedBody` (`plugin/bin/lib/issues/record.js:835`) emits only `## Current State` / `## Deliverables` / `## Acceptance Criteria` (or `## Open Question`) / `## Release Note`, never `## Technical Approach` or `### Key Files`. Every agent-composed record therefore fails condition 3, so the micro-plan path is unreachable for exactly the small, born-ready records `ceremony: fast-lane` + `size: low` is meant for. The agent-composed records come from:

- `/capture`'s born-ready compose (`plugin/skills/capture/SKILL.md:296`);
- `/reflect`'s staged findings (`plugin/skills/reflect/SKILL.md:157`);
- the four health sweeps' `issue-payload.js`;
- `wrap-up/leftover-routing.md`.

Observed on #2968 (fast-lane, size:low, one implementation file `plugin/bin/lib/dream/scan.js`): the gate fell through, and build ran a full writing-plans dispatch plus plan-audit for a one-task plan.

The same missing section also blinds dispatch's cross-record file-overlap grouping for every agent-filed record. `plugin/bin/lib/issues/grouping.js`'s `extractKeyFilesSection` reads only `### Key Files`, and `grouping.js:333-337` deliberately refuses to scrape paths from prose.

## Deliverables

1. **Decision (approved in brainstorming, 2026-10-15): the producer side changes (option a).** The alternatives were a micro-plan gate fallback to backtick-quoted paths in `## Deliverables` (rejected: it widens what the gate trusts and leaves dispatch grouping blind) and materialize-time derivation (rejected: it runs after dispatch's pre-claim grouping).
2. `specShapedBody` gains an optional `keyFiles` param: an array of `{ path, change }`. When non-empty, it emits `## Technical Approach` followed by `### Key Files`, one `` - `{path}` — {change} `` bullet per entry (`plugin/skills/specify/spec-template.md`'s format), placed after `## Release Note`. When absent or empty, the output is byte-identical to today's.
3. Producers that know their target files pass `keyFiles`:
   - the four health-sweep payload composers (`plugin/bin/lib/{code,docs,harness,journey}-health/issue-payload.js`), from each finding's resolved target path;
   - `/capture`'s born-ready compose step and `wrap-up/leftover-routing.md`'s compose, via the args each already threads;
   - `/reflect`'s staged-finding compose, when the finding names its files.
4. No gate changes: `micro-plan.md` condition 3 and `grouping.js` already parse `### Key Files`.

## Acceptance Criteria

- [ ] `specShapedBody({... keyFiles: [{path:'plugin/bin/x.js', change:'…'}]})` emits `## Technical Approach` then `### Key Files` with that bullet, after `## Release Note` (`tests/bin-lib/issues/record.test.js`).
- [ ] `specShapedBody` without `keyFiles` (or with `[]`) produces output byte-identical to the current output for the existing fixtures (`record.test.js`).
- [ ] A composed body with `keyFiles` still passes `compose-record.js --check`.
- [ ] At least one health-sweep payload test asserts the finding's target path appears under `### Key Files` (e.g. `tests/bin-lib/code-health/pull-issues-v2.test.js` or the harness-health payload test).
- [ ] A record composed with exactly one implementation file in `keyFiles` satisfies `micro-plan.md`'s condition 3 (a fixture case in `tests/build-micro-plan-conformance.test.js`), and `extractKeyFilesSection` returns that file.
- [ ] `capture/SKILL.md`, `reflect/SKILL.md` and `wrap-up/leftover-routing.md` each instruct passing `keyFiles` when the composer knows the affected files.
- [ ] `npm test` passes.

## Release Note

Small agent-filed records can now take build's micro-plan fast path instead of a full planning dispatch.

## Technical Approach

Additive optional parameter on one shared composer, following the same pattern `premiseCheck`/`verifiedAsOf` used when added to `specShapedBody`. Validate entries (non-empty single-line `path`; `change` single-line, defaulting to a short phrase) and throw on malformed input as the existing params do. The health-sweep composers already hold the target path, as `finding.path` / the resolved target. The prose producers gain one sentence each, naming the param.

### Key Files

- `plugin/bin/lib/issues/record.js` — `specShapedBody` gains `keyFiles`, emitting `## Technical Approach` / `### Key Files`
- `plugin/bin/lib/code-health/issue-payload.js` — pass the finding's target path as `keyFiles`
- `plugin/bin/lib/docs-health/issue-payload.js` — same
- `plugin/bin/lib/harness-health/issue-payload.js` — same
- `plugin/bin/lib/journey-health/issue-payload.js` — same
- `plugin/skills/capture/SKILL.md` — born-ready compose step names `keyFiles`
- `plugin/skills/reflect/SKILL.md` — staged-finding compose names `keyFiles`
- `plugin/skills/wrap-up/leftover-routing.md` — compose step names `keyFiles`
- `tests/bin-lib/issues/record.test.js` — with/without `keyFiles` cases
- `tests/build-micro-plan-conformance.test.js` — single-file composed record satisfies condition 3
- `tests/bin-lib/code-health/pull-issues-v2.test.js` — target path appears under `### Key Files`

## Gotchas

- Records filed before this change keep their current bodies. No backfill: they still take the full planning path, exactly as today.
- A health-sweep finding's target can be outside the repo (harness-health memory files under `--memory-dir`). Pass only repo-relative paths into `keyFiles` and omit out-of-repo targets, or `grouping.js` would compare absolute machine-local paths across records. This pairs with #2857's repo-relative rule.
- `compose-record.js --check` accepts `## Technical Approach` today (shaped records carry it). Confirm the new section placement does not trip its section-order expectations before relying on it.
- Byte-identity for the no-`keyFiles` case matters: `tests/bin-lib/release-note-repair/fixtures.js` and several materialize tests pin composed output.
