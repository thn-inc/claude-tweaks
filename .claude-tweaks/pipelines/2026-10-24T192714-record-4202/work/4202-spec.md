# 4202: reconcile: archiving an escalated stuck dir drops its cache entry without resolving it, so the stuck-runs record never closes

**Related:** #2724, #4192, #4180 (records swallowed resolve failures; does not converge the block)

Verified-as-of: 56e7ef992848ed11636355e67485fd5e1655776a

Origin: #4192 follow-through (main-checkout reconcile pass, 2026-10-24)

Defer-reason: tangential

## Current State

- When reconcile archives a dir itself, `trackArchiveResult` (`plugin/bin/lib/reconcile/archive-merged.js:1814`) calls `recordResidueSuccess(cacheTarget, 'structurally-stuck', dir)` (#1613). That deletes the cache entry without calling `resolveResidue`, so an escalated dir's path stays in the consolidated record's stuck-paths block.
- `pruneResidueFailures` (`plugin/bin/lib/reconcile/cache.js:286`) is the only other place a gone path gets resolved. It never sees these paths, because the entry was already deleted earlier in the same pass. The comment at `archive-merged.js:2355` assumes the `recordResidueSuccess` call is enough.
- `pruneResidueFailures` also drops the entry when its best-effort resolve throws, so a failed resolve orphans the path too. A body restored from edit history can also bring back paths whose entries were already gone.
- Observed on 2026-10-24: after a real reconcile pass, #2724's block still listed 20 `record-*` paths. All were archived and none had a `structurally-stuck:` cache entry, so nothing could ever resolve them. They were removed by hand (#4192 issuecomment-6388362160). The block can never empty by itself, and `resolveStructurallyStuck` only closes the record when it does.

## Deliverables

1. On a successful archive, clear the `structurally-stuck` entry through `clearResidue` (which resolves it when escalated) instead of `recordResidueSuccess`. Use the same `RESIDUE_RESOLVED_STATUSES` handling, and keep the entry when the resolve fails; the same pass's prune retries it once and drops it afterward (keeping it across passes is #4209).
2. Make the block converge. Whenever the escalate or resolve path edits the consolidated record, drop every block path inside this checkout's own `.claude-tweaks/pipelines/` that no longer exists on disk. A path from another checkout is never judged: the record is shared by every checkout of the repo, so a path absent from this machine's disk may still be stuck elsewhere. Close the record when the block ends up empty. This also clears orphans left by earlier passes, failed prune resolves, and body restores.
3. Correct the comment at `archive-merged.js:2355` to match.

- [ ] A test where that resolve fails leaves the cache entry in place.
