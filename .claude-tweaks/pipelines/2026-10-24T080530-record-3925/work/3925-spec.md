# 3925: wrap-up-engine.js plan reads its git facts from the main checkout when run from a linked worktree

Origin: wrap-up leftover routing from #3679 (run 2026-10-21T225455-record-3679)

Defer-reason: pre-existing-outside-diff

## Current State

`bin/wrap-up-engine.js` `plan` resolves `repoRoot` through `resolveRepoRoot(process.cwd())`, which follows `git rev-parse --git-common-dir` to the MAIN checkout, and passes that as `cwd` to `gatherFacts` (`bin/lib/wrap-up/facts.js`). Every git fact (`git diff --name-only {base}...HEAD`, `--diff-filter=RD --name-status`, the heading-rename scan) then runs against the main checkout's HEAD, not the linked worktree the run builds in. The filesystem facts (`docs/journeys/`, `CLAUDE.md`, `.claude/skills/`) read the main checkout's files for the same reason.

Observed on run `2026-10-21T225455-record-3679` (PR #3918): the branch renamed and deleted nothing, yet the plan opened the `references` row with ten `R` candidates that were other runs' archived `work/*-spec.md` files, moved on `main` after the branch point. The `journeys` row printed `candidates: []` although the diff changed `docs/journeys/stage-a-patch-that-conflicts-with-an-earlier-one-3290.md` and that file's `files:` frontmatter overlaps the diff. The gate for every row is computed the same way, so `changedFiles`, `multiFileDiff` and `headingRenamed` are also main's.

#3017 introduced `resolveRepoRoot` so a shell sitting in a subdirectory of the checkout still finds `docs/journeys/`; the telemetry path rightly anchors to the main checkout (`resolveTelemetryPath`). The facts call reused the same root, which is the wrong anchor for a linked worktree.

## Deliverables

- [ ] Run `gatherFacts` against the current checkout's top level (`git rev-parse --show-toplevel`), not the common-dir root; keep `resolveTelemetryPath` anchored to the main checkout

- [ ] Keep #3017's subdirectory fix: a shell in `<checkout>/web` still resolves the checkout root, now the worktree's own

- [ ] Add a test that runs `plan` from a linked worktree whose branch differs from the main checkout's HEAD and asserts `changedFiles`, `renamedDeleted` and `journeyFiles` come from the worktree

## Acceptance Criteria

- [ ] From a linked worktree, `plan`'s `references` candidates and `journeys` candidates reflect the worktree branch's own diff against `--base`

- [ ] The test fails when `gatherFacts` is handed the common-dir root again

- [ ] `npm test` passes with no new skips

## Release Note

Wrap-up's curation plan now judges the worktree's own diff, so the references and journeys rows no longer open or close on another branch's changes.

## Technical Approach

### Key Files

- `plugin/bin/wrap-up-engine.js` — pass the checkout top level to gatherFacts
- `plugin/bin/lib/wrap-up/facts.js` — no change expected; the cwd it receives is what moves
- `tests/bin-lib/wrap-up/engine-cli.test.js` — linked-worktree fixture
