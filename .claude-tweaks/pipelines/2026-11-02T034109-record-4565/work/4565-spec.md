# 4565: tidy --approve leaves a forge-only approval run unarchivable, so its applied staged/ keeps raising the unapproved-proposals notice

Defer-reason: tangential

## Current State

`plugin/skills/tidy/approve-mode.md`'s "Archiving the run" archives the run only after Step 7.5's commit lands. `plugin/skills/tidy/step-7-5-worktree-always.md`'s first paragraph skips the worktree, the commit and the PR whenever the approved set holds no working-tree write (an all-`gh` set), and says the run dir's audit files "stay uncommitted at `$RUN_ROOT`". `hooks.js archive-run` then refuses `audit-untracked` (decisions.md, report.md and staged/ are not tracked), so the run can never archive. Its `staged/` still holds the already-applied proposals, so `session-residue.js`'s `collectApprovableStandalone` lists it at every SessionStart ("standalone run(s) finished with unapproved staged proposal(s)"), and `backlog/attention-mode.md`'s tidy row keeps reading "5 tidy proposal(s) staged awaiting approval".

Observed 2026-10-30 on `2026-10-28T172007-sweep-standalone`: `tidy --approve` applied all 7 items (3 digest absorbs into #4405/#4403/#4400, a new settle record #4560, 3 old-value-guarded `update-ref -d` orphan-ref deletions), logged each to decisions.md, closed the run, and `archive-run` refused `audit-untracked`. The same gap has been worked around by hand before. #3409, #3410, #4075 and #4470 each landed a sweep or tidy run's trail through a dedicated PR so the run could archive, so the cost recurs on every forge-only approval.

## Deliverables

1. Record per staged item that `--approve` applied it, in one representation both readers use, so `collectApprovableStandalone` and attention-mode's tidy row stop counting applied items. Examples: move applied items into `staged/applied/`, or a per-item outcome file the detectors read.
2. Give the forge-only approval path a terminal state the residue probe accepts. Either commit the run trail through the existing `pr-first` housekeeping-PR path when the approved set is forge-only, or let `archive-run` accept an untracked trail for a closed run whose every staged item is recorded applied. State in the PR which one and why.
3. Tests for both readers and for the archival outcome.

## Acceptance Criteria

- After `tidy --approve` applies every staged item of a forge-only approved set, the next SessionStart does not list that run under unapproved staged proposals, and `backlog attention`'s tidy row omits it.
- That run reaches an archived (or documented terminal) state without a manual git step.
- A run with at least one staged item still actionable (neither applied nor declined) is still listed by both readers.
- A staged item excluded at the approval prompt, or skipped as `stale — skipped` by re-verify, moves to `staged/declined/` with one `decisions.md` line; neither reader counts it, and `archive-run --local-trail` treats it as resolved.
- A staged item whose Approve rows split resolves per row outcome: at least one row applied and none failed resolves it `applied`, with its excluded or stale rows named on the same `decisions.md` line; every row excluded or stale, in any mix, moves it to `staged/declined/`; any failed row leaves it actionable in `staged/`.

## Release Note

After `/claude-tweaks:tidy --approve` applies a run's staged items, the session-start notice and `/claude-tweaks:backlog attention` stop reporting them as awaiting approval.

## Decisions

Plan-review answers (2026-10-31), applied to the Acceptance Criteria above.

- **Staged items `--approve` does not apply: Reading B.** An excluded or stale item is resolved but not applied: it moves to `staged/declined/` and is logged in `decisions.md`. Both readers skip it, and `--local-trail` can archive the run. The listing criterion narrows to items that are still actionable.
- **Staged item whose Approve rows end differently: Reading A.** One landed row with no failed row resolves the item `applied`, naming its excluded or stale rows on the same `decisions.md` line. All rows excluded or stale, in any mix, declines it. A failed row keeps it actionable for a retry. Reading B was rejected because a mixed item would return at every `--approve` with its excluded rows excluded again, the stuck-item problem this record fixes.
- **Trail ruling (2026-11-01): local by default.** Deliverable 2 takes the `archive-run --local-trail` option, not the housekeeping PR: a run's trail lands in git only when its environment disappears afterwards, and #4850 owns that case and the `.gitignore` exceptions. Keep `archive-run`'s `audit-untracked` refusal for a run without `--local-trail`, so a trail with a landing PR still waiting is never moved early.
