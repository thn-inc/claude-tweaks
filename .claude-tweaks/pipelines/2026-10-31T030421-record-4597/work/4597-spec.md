# 4597: Emit Step 4.0b's closing set from closing-links.js post-merge instead of a hand-written jq

Origin: spec #4466 review hindsight (structural debt)
Defer-reason: genuinely-larger

## Current State

`plugin/skills/_shared/pr-first-merge-post-merge.md` Step 4.0b builds `$CLOSING_SUB_ISSUES` with its own `gh pr view {pr} --json closingIssuesReferences --jq` call. The jq has a same-repo `select(...)` that copies `sameRepoNumbers` (`plugin/bin/lib/flow/closing-links.js`). A prose rule then subtracts Step 4.0's reopened, failed and pendingClose lists, and skips Step 4.0b when Step 4.0 returned none. `closing-links.js post-merge` already reads those references and computes those lists, but prints only the unwanted-closure `candidates`, not the full same-repo closing set. The #4466 review found two medium defects in the hand-written copy (cross-repo numbers, the missing no-result hold).

## Deliverables

- [ ] `closing-links.js post-merge` prints the merge's same-repo closing records minus reopened, failed and pendingClose, as one new JSON field, covered by unit tests in `tests/bin-lib/flow/`.
- [ ] Step 4.0b reads that field from Step 4.0's output instead of calling `gh pr view` itself, and skips when the field is absent.

## Acceptance Criteria

- [ ] `grep -F "closingIssuesReferences" plugin/skills/_shared/pr-first-merge-post-merge.md` no longer matches inside Step 4.0b.
- [ ] A unit test shows that a cross-repo `Fixes other/repo#N` and a reopened record are both missing from the new field.

## Release Note

Closing a below-floor parent after a merge now relies on the same tested code that settles the merge's closing links.

## Technical Approach

### Key Files

- `plugin/bin/closing-links.js` — post-merge output
- `plugin/bin/lib/flow/closing-links.js` — `sameRepoNumbers`
- `plugin/skills/_shared/pr-first-merge-post-merge.md` — Step 4.0b
