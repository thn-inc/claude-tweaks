## Deliverables

1. In each of the four files, a builder whose output is fixed, or fixed for a given set of arguments, comes from `fromTemplate` or `fromTemplateSet`, keyed by its arguments. Return shapes, directory prefixes and the commit identity stay the same.
2. A builder that cannot be a template (its content differs per test) makes its repo without a `git config` process: the identity goes in through the template it starts from, an inline `-c`, or the config file.
3. `stack-check.test.js`'s fixture repos carry `maintenance.auto = false` and `gc.auto = 0` in their own config. `gitEnv()` drops the runner's environment config on purpose, so nothing else reaches the commits made under it.
4. Repo-plus-linked-worktree sets with a fixed shape come from one `fromTemplateSet` layout. A worktree added to an arbitrary per-test repo stays a real `git worktree add`.
5. Each new template has a spawn test in `tests/helpers-git-template.test.js`: after a warm-up call the builder starts no git process.
6. The PR body reports git processes per file, before and after, with the split by subcommand.

## Architecture Alignment (build)

- Beneficial: the templated builders live in fixture modules beside the files that use them, not inside each test file: `tests/bin-lib/staged-patch/stack-check-fixtures.js`, `tests/helpers/statusline-fixtures.js`, and the existing `tests/bin-lib/reconcile/archive-merged-helpers.js`, which both archive-merged files already share. This lets the Deliverable 5 spawn tests in `tests/helpers-git-template.test.js` require them. It follows the #5769 pattern (`claims-git-cas-fixtures.js`).
- Beneficial: `mergedFeatureBranchRepo(branch)` builds one template and renames the branch in each copy with fs (loose ref plus reflog), instead of keeping one template per branch argument. The output is the same, every copy shares one feature commit, and the build pins `-c init.defaultRefFormat=files` and `merge --ff-only`, so a developer's global `merge.ff=false` or reftable default cannot break it. Packed refs throw loudly.
- Beneficial: each template build reads its git env when the call runs, never from a value captured at module load. stack-check's build calls `gitEnv()` at call time, while copies keep `FIXTURE_ENV`. Without this, a spawn test passes vacuously, because the test's `GIT_TRACE2_EVENT` never reaches the build.
