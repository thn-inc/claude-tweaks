# 3797: Windows regression: 1 test file(s) newly failing after 12c39e008

Surface: infra

## Current State

The post-merge Windows check on commit 12c39e008 (merged PR #3789) reported `tests/review-console-header-conformance.test.js` newly failing on "#3712: the deny reason's quoted section heading exists in the console file it names (single-spec)", with `plugin/skills/wrap-up/review-console.md has no "## Auto-resolution short-circuit (`consoleAutoResolve`)" heading`.

Re-checked against current `main`, the failure is still live and reproduces on macOS under a CRLF simulation (a preload that makes `fs.readFileSync` return `\r\n` text). Both the single-spec and the multi-spec variant of the #3712 test fail (6 pass / 2 fail). Root cause: line 36's `readConsole` helper reads with a raw `fs.readFileSync(..., 'utf8')`. The #3712 tests then `split('\n')` and require an exact `lines.includes('## {heading}')` match, which a CRLF line (`## …\r`) never satisfies. The heading itself is present in the file.

`tests/helpers/read-skill.js` exports `readText(absPath)` (#2763), the shared EOL-normalizing read for this case.

**Related:** #3702, #3703, #3742, #3751, #3776, #3802, #3857, #3871, #3886, #3890, #3894

## Deliverables

1. `tests/review-console-header-conformance.test.js` — `readConsole` (line 36) reads through `readText` from `./helpers/read-skill` instead of a raw `fs.readFileSync`.

## Acceptance Criteria

1. `readConsole` in `tests/review-console-header-conformance.test.js` returns `readText(...)`; no raw `fs.readFileSync` of a markdown file remains in the file.
2. Under the CRLF simulation, both #3712 tests (single-spec and multi-spec) pass. Before the fix they fail.
3. `node --test tests/review-console-header-conformance.test.js` is green on Linux/macOS.
4. The next post-merge Windows check (`.github/workflows/windows-regression.yml`) no longer lists this test file.

A one-line swap in the shared `readConsole` helper. Every test in the file reads through it, so all of them become CRLF-safe at once, and no assertion text changes.
