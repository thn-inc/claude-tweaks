# 3802: Windows regression: 1 test file(s) newly failing after 8039e9166

Surface: infra

## Current State

The post-merge Windows check on commit 8039e9166 (merged PR #3781) reported `tests/backlog-refine-flagback-divergence.test.js` newly failing on "the flag-back comparison paragraph exists in refine-closing-summary.md", with `expected a paragraph opening with "**Flag-back concurrent-grant comparison (#3324).**"`.

Re-checked against current `main`, the failure is still live and reproduces on macOS under a CRLF simulation (a preload that makes `fs.readFileSync` return `\r\n` text): 7 of the file's 9 tests fail, 2 pass. Root cause: lines 16-17 read `refine-mode.md` and `refine-closing-summary.md` with raw `fs.readFileSync(..., 'utf8')`, and line 28 splits paragraphs with `closing.split('\n\n')`. On a CRLF checkout the separator is `\r\n\r\n`, so no paragraph splits out, `PARA` is undefined, and every test reading `PARA` fails. The Windows filer reported only the first.

`tests/helpers/read-skill.js` exports `readText(absPath)` (#2763), the shared EOL-normalizing read whose header names `'\n\n'` paragraph splits as a case it makes CRLF-safe.

**Related:** #3702, #3703, #3742, #3751, #3776, #3797, #3857, #3871, #3886, #3890, #3894

## Deliverables

1. `tests/backlog-refine-flagback-divergence.test.js` — read both markdown files (lines 16-17) through `readText` from `./helpers/read-skill`.
