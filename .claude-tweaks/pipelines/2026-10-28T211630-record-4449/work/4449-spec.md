# 4449: Write gate misreads cp/mv value-taking options (-S/--suffix)

**Related:** #4303

Origin: /claude-tweaks:build of #4303 (run 2026-10-25T143627-spec-4303), SDD Task 2 parked finding

Defer-reason: tangential

## Current State

The cp/mv operand loop in `plugin/bin/lib/hooks/git-command.js` does not skip the value of a value-taking option:

- `cp a b -S .bak` resolves `/r/.bak` and misses `b`, the real destination.
- `cp --suffix -t X a` makes `explicitTargetDir` read `-t` as the target flag, so the scanner reports `/r/X`. GNU cp under bash 3.2 and 5 overwrites `r/a` and writes the backup `r/a-t`. That is a fail-open.

Both were checked against GNU cp semantics. macOS cp has no `-S`.

## Deliverables

1. Skip the value of `-S`/`--suffix` (and `--suffix=…`) and any other value-taking cp, mv or install option in the operand loop and in `explicitTargetDir`.
2. Pin both shapes.

## Acceptance Criteria

- `cp a b -S .bak` resolves `b`.
- `cp --suffix -t X a` resolves the suffix value as a suffix, not `-t` as the target flag.
- Each rule has a red-turning mutant.
- The scanner suites pass.

## Release Note

The worktree-always guard now reads cp and mv backup-suffix options correctly.
