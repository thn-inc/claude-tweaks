# 5267: drive.js: worker-authored tests run outside the sandbox with the driver's credentials

Origin: spec #5218 review (3b Security)

Defer-reason: needs-human-decision

## Current State

`plugin/bin/lib/driver/steps.js`'s test step (`deps.node(binScript('verify.js'), args, { cwd: wt, timeout: VERIFY_TIMEOUT_MS, env: deps.env })`, around line 583) runs the project's test command in the record's worktree. That tree holds the headless worker's change, and the worker can write test files and `.claude-tweaks/verify-scope.json`.

The child gets the driver's full environment, with no sandbox. The worker itself gets only an allow-listed env (`buildEnv` in `worker.js`) and a narrow Bash sandbox.

So worker-authored code runs at this step with full rights. A prompt-injected record body can make the worker write a test that reads `GH_TOKEN` or other credentials from the environment, or calls `gh` with the user's keychain auth.

`express-lane.js check` rejects an edited `verify-scope.json` only afterwards, once the code has already run. The spec's containment claim ("the narrow rights and the diff-bounds check inside `check` are what contain it") does not cover execution at the test step.

Found by #5218's review: lens 3b, both reproduction agents agreed; refs #5218.

## Deliverables

Run the driver's test step so that worker-authored code cannot reach the driver's credentials. Choose one of the following, and record the choice and why in `steps.js`'s header:

- run the test step under the same sandbox profile as the implementer;

- pass the test child an allow-listed environment, and block `gh` keychain access;

- run `check`'s protected-path bounds on the changed files before the test step.

Record what the chosen option contains, and what it still lets through, beside the code.

## Acceptance Criteria

A fake-runner test shows the test step's child process receives no `GH_TOKEN`/`GITHUB_TOKEN` (or none of the credential variables `worker.js`'s `ENV_ALLOW` excludes).

A test pins that an edited `.claude-tweaks/verify-scope.json` is either refused before any test command runs, or never read from the worker's tree.

The `steps.js` header names the residual risk the chosen option leaves.

## Release Note

The pipeline driver no longer runs worker-written test code with the user's credentials in reach.
