# 5794: Skip the node start in the direct-test-run guard hook for Bash calls it can never deny

Related: #5547 (the guard), #5754 (module split of the same file), #5755 (new deny shapes in the same classifier).

## Current State

`.claude/settings.json` registers `node "$CLAUDE_PROJECT_DIR/tools/direct-test-run-guard.js"` as a PreToolUse hook for Bash (#5547). Every Bash call in every session of this repo starts one node process for it, next to the plugin's own `hooks.js pre-tool-use` process.

Measured cost:

- 2026-11-16 18:16, load 15 to 33, ten runs: the guard on `git status --short && ls` costs 44 ms CPU and 50 ms wall; a bare `node -e 0` costs 32 ms CPU and 37 ms wall. Almost all of the cost is the node start.
- The machine runs about 100 parallel sessions, is pinned at 12 of 12 cores when more than about 20 are working, and spends 40 to 50% of CPU in the kernel on process starts (1,400 to 1,500 a second).
- Probe on 2026-11-16 at load about 245, 40 runs each, CPU from `resource.getrusage(RUSAGE_CHILDREN)`: the current registration costs 51 ms (harmless command) and 58 ms (denied command); a bare `sh -c :` costs 5.0 ms; a prototype POSIX sh prefilter sourced into the hook's own shell costs 5.8 ms on the harmless command (0.7 ms over the bare shell); the same prefilter run as `sh <file>` costs 9.9 ms, because of the second shell start.

What the guard can deny, read from `tools/direct-test-run-guard.js`:

- A typed deny needs a node program word at a program position (`readRun`: `node`, `node.exe`, or `npx … node[@v]`).
- A script-scan deny (`judgeOrThrow`, `collectScript`) needs a program that runs a script file: `node`, `sh`, `bash` or `zsh` with a script operand or a stdin file, `source` or `.`, or a program word holding a path separator.
- A program position is a segment's first word, or a word reached past leading `NAME=value` assignments, the keywords in `LEAD_KEYWORDS`, `!`, the prefix commands in `PREFIX_OPTIONS`, `xargs` or `parallel`, `find -exec`, or through `eval` text and a shell's `-c` text.
- The shared scanner's `substituteVars` (`plugin/bin/lib/hooks/git-command.js`) can build a program name from pieces (`X=de; no$X --test a b`), so the literal text `node` or `--test` in the command is not a necessary condition for a deny. The scanner cuts segments at `&&`, `||`, `;`, `|`, a lone `&`, newlines, groups and backtick spans, and its tokenizer splits words on JavaScript `\s`.

How a hook command runs: Claude Code passes it to `sh -c` on macOS and Linux and to Git Bash on Windows, or to PowerShell when Git Bash is not installed (the docs sentence quoted in `plugin/bin/hooks.sh`'s header). The current registration already needs a POSIX shell to expand `$CLAUDE_PROJECT_DIR`.

Fault probe (2026-11-16, `/bin/sh` = bash 3.2, `/bin/dash`, bash 5): a plain `. <file>` exits 2 under dash when the file is missing or has a syntax error, and exit 2 from a PreToolUse hook blocks the call. `[ -r <file> ] && command . <file>; exit 0` exits 0 with empty stdout in all three shells for a missing file, a syntax error and a CRLF file.

`.gitattributes` has no end-of-line rule for `.sh` files, so a `core.autocrlf` checkout would give a new sh file CRLF line endings.

## Deliverables

1. **A POSIX sh prefilter, `tools/direct-test-run-guard.sh`.** It runs under dash, bash 3.2 and Git Bash, and on the skip path it uses shell builtins only (no fork, no exec). It reads the payload line from stdin, takes the `tool_input.command` string (decoding the JSON escapes for a quote, a newline and a tab), splits it at every `;`, `&`, `|`, `(`, `)`, `{`, `}`, backtick and newline whether quoted or not, and skips node only when every fragment's first word is made of the characters `A-Za-z0-9_.+-` alone and is not a program word the guard reads. Every other case runs the node guard with the original stdin bytes: any other JSON escape (an escaped backslash included, so a command holding a backslash runs node), a payload shape it does not recognise, a payload over the size cap (8192 bytes), more than 256 pieces in any of its three scans (quote pieces, escape pieces, fragments), more than one line on stdin, and a shell that does not word-split.
2. **Soundness by construction.** The prefilter's skip condition is derived from the guard's program-position rules, never from a search for the text `node` or `--test`. Any first word holding a quote, `$`, `=`, `/`, a backslash, a redirection character or a non-ASCII byte runs node.
3. **Registration.** `.claude/settings.json` sources the prefilter into the hook's own shell (no second shell start), guarded so a missing or broken file cannot end the shell with status 2, then falls through to the node guard and always ends with status 0. The prefilter's body is one compound command, so a syntax fault (CRLF, conflict markers) is found before anything reads stdin and the call falls through to node with stdin intact: a broken prefilter behaves like today's registration.
4. **One source for the program words.** `tools/direct-test-run-guard.js` exports the set of words it reads at a program position, built from its own sets (`NODE_NAMES`, `SHELLS`, `LEAD_KEYWORDS`, `PREFIX_OPTIONS`, `REPEATING_LEADS`, plus `npx`, `find`, `eval`, `source`, `.`). A test pins the sh list to it.
5. **`.gitattributes`:** `tools/direct-test-run-guard.sh text eol=lf`.
6. **Tests** beside the existing ones in `tests/direct-test-run-guard.test.js`, a timing budget in `perf/`, and the doc lines that describe the hook's cost and registration (`docs/hooks.md`, `docs/plugin-structure.md`, `docs/journeys/run-several-test-files-through-the-runner-5547.md`).
7. **PR report:** CPU per hook call before and after, and a replay of recorded Bash commands (see the acceptance criteria).

## Acceptance Criteria

- AC1: Behaviour is unchanged. For the registered command string run through `sh -c` with a payload on stdin, stdout is byte-identical to the node guard's stdout for the same payload: `node --test a.test.js b.test.js` and `for f in tests/*.test.js; do node --test $f; done` are denied with the same reason text; a single-file `node --test` and `node tools/run-tests.js …` print nothing. Exit status is 0 in every case.
- AC2: Superset. A test runs every command the existing test file expects to be denied (the typed deny rows, the denied prefix rows, the replacement pins, the script-scan and by-path cases, and the win32 rows) through the prefilter and asserts each one reaches node. It iterates the existing tables, so a deny row added later is covered with no edit to the new test.
- AC3: The payload reaches node unchanged. For every case that reaches node, the bytes node reads on stdin equal the bytes the hook received, for a payload with and without a trailing newline and for a payload of more than one line.
- AC4: The skip path starts nothing. For `git status --short && ls`, the prefilter ends with status 0, empty stdout and empty stderr with no `node` and no `cat` on PATH.
- AC5: Faults never block or print. A missing prefilter file, a CRLF copy, a copy with a syntax error, a missing node, empty stdin and garbage stdin each end with status 0 and empty stdout, under `/bin/sh` and under dash where it is installed. With a broken or missing prefilter and node present, a denied command is still denied.
- AC6: The sh word list equals the guard's exported program-word set. Each rule is proven by a mutant on a scratch copy: dropping a separator from the split set, a word from the list, the first-word character check, an escape branch, or a cap turns at least one test red.
- AC7: Replay. Every Bash command recorded for this repository in the local transcript store is run through `judgeOrThrow` and through the prefilter. No command the guard denies is skipped by the prefilter. The PR reports the number of commands, the number denied, the number of throws, and the share of commands that skip node.
- AC8: Cost. The PR reports CPU per hook call before and after, for a command that cannot be denied and for one that is denied, measured with `resource.getrusage(RUSAGE_CHILDREN)` over at least ten runs, with the bare `sh -c :` cost at the same load beside them. The target is under 5 ms for the command that cannot be denied; when the bare shell start alone is at or over 5 ms at the measured load, the report says so and gives the prefilter's cost over the bare shell.
- AC9: Bounded work. A `perf/` test runs the prefilter on worst-case payloads at the size cap and at each piece cap and holds a stated time budget.
- AC10: Windows. The PR states which shell runs the hook on Windows and why the sourced sh form fits it. The `.gitattributes` line is pinned by a test. Tests that spawn `sh` run on win32 or skip with a stated reason, and a `windows-regression.yml` dispatch on the branch after the last code change shows no new failing file.
- AC11: `npm test -- --full` passes, and the docs named in Deliverables describe the new registration and its cost.
