# 3098: Claims-registry listing reads at most 1000 entries, so claims past the 1000th file are invisible

Verified-as-of: a3ddd1cb15b411e20a3e268e8953b6663d7e0c3e

Origin: /claude-tweaks:tidy 2026-10-10T130853-tidy-standalone (Step 4.7/4.8 scans)

Defer-reason: pre-existing-outside-diff

**Related:** #3137

## Current State

`plugin/bin/lib/issues/claim-store.js:168` lists claims with `gh api repos/{owner}/{repo}/contents/claims?ref=claims-registry`. GitHub's contents API returns at most 1000 entries for a directory, and `claims-registry` now holds 1333 blobs (measured 2026-10-10 via a GraphQL tree query: 1306 tombstones, 26 stale, 1 live). Every claim file sorting after the 1000th entry, roughly issue numbers 2983 and up including the live claim on #3091, is never read. Prose consumers have the same cap: `plugin/skills/_shared/github-pr-scan.md:195`, `plugin/skills/_shared/issue-claims.md:230` and `plugin/skills/tidy/scan-procedures.md:207`. Observed effect on 2026-10-10: `reconcile --checks release` did not consider the stale claims on closed #2983, #2984 and #2985, which still carry `bot:in-progress`.

## Deliverables

- [ ] `claim-store.js` lists the claims directory through the git trees API (`repos/{owner}/{repo}/git/trees/claims-registry?recursive=1`, filtered to `claims/`) or an equivalent uncapped read, keeping the existing `{name, sha}` shape.
- [ ] Every prose consumer of the contents listing (`_shared/github-pr-scan.md`, `_shared/issue-claims.md`, `tidy/scan-procedures.md`) uses the same uncapped read or calls the module's CLI.
- [ ] Truncation is detected and reported (the trees API's `truncated: true`) and never read as a complete listing.

## Acceptance Criteria

- [ ] A test with a fixture listing of more than 1000 claim entries returns every entry.
- [ ] With the change, `reconcile --checks release` considers claims for issues numbered above the old cut-off (the stale claims on closed #2983–#2985 get released, or skipped with a named reason).
- [ ] A truncated tree response surfaces as an error or a named degraded result, never as a silent partial list.

## Release Note

Claim sweeps and reconcile now see every claim in the registry, not just the first 1000.
