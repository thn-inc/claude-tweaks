# 3965: Plan and review should enumerate failure branches of a fail-closed skill-prose guard (empty, unreadable, malformed)

Origin: reflect full from #3877

Defer-reason: tangential

## Current State

#3877 added a prose guard to tidy's `## Arm ready PR` that must fail closed (hold, never arm). Its plan and acceptance criteria pinned that the rule text exists. Review then found fail-open edges that no pin named: `every record in the PR's Fixes lines carries demo:pending` is vacuously true for an empty set, a failed label, comment or `verify.json` read had no stated outcome, and the `{reason}`, `{command}` and `--run` placeholders were undefined. Fixing them took one review fix wave and six added pins. Nothing in `specify/red-team.md`, `build`'s plan checks, or `review`'s lens 3c asks a guard-shaped prose rule to enumerate empty, unreadable and malformed inputs.

## Deliverables

- `specify/red-team.md` gains a detection step for a prose guard whose job is to fail closed: the record must state the outcome for an empty input set, an unreadable source, and a malformed value, or list them as Open Questions.
- `review/step3-lens-dispatch.md` lens 3c gains one question: does an `every`/`all` quantifier in a guard rule hold over an empty set, and is a failed read a hold rather than a pass?

## Acceptance Criteria

1. A conformance test pins the new red-team detection step and the new lens 3c question, and fails when either sentence is removed.
2. The red-team step names the three input classes (empty, unreadable, malformed).
3. `npm test` passes.

## Release Note
