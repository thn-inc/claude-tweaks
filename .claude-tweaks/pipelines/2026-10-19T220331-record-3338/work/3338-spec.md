## Current State

`/claude-tweaks:feedback` (and the `by:feedback` records it files) keeps attributing the Claude Code harness's own worktree-session Bash refusals ("too complex to verify that it stays inside the worktree", "a value computed at runtime … cannot be shown not to be git", "names git in a form too complex to verify") to `plugin/bin/lib/hooks/pre-tool-use.js`. None of those strings exist anywhere under `plugin/bin/`; `docs/hooks.md` and `docs/skill-authoring.md` ("Harness-level worktree Bash guard vs. the plugin's PreToolUse gate") already say the guard is harness code the plugin cannot narrow.

Recorded instances of the same misattribution: #174, #1785, #2548, #2739, #2742, and in this run #2702 and #2776 — each needed a premise-correction reshape (two of them in this /flow run's pre-flight, costing a user decision before any build could start). `plugin/skills/feedback/` carries no check for it (grep for "harness"/"too complex to verify" finds only an unrelated transcript-judge reference).

## Deliverables

In `/claude-tweaks:feedback`'s filing path (session-evaluation and the bare/explicit report path), before naming `bin/lib/hooks/pre-tool-use.js` or any plugin hook as the affected component for a Bash refusal: grep the quoted refusal text under `plugin/bin/` (the installed build's `bin/` when filing from a consumer project). No match → attribute it to the Claude Code harness guard, and route the report as a `_shared/scratch-worktree.md` §7 addendum candidate (a documentation finding), never as a hook defect.

The plugin's own deny prefixes (`claude-tweaks: this project requires an isolated worktree…`, `claude-tweaks working-directory discipline: …`) are the positive signal for a plugin-hook attribution — cite `docs/skill-authoring.md`'s existing section rather than restating the rule.

## Acceptance Criteria

A feedback filing whose evidence quotes "too complex to verify" (or any refusal string absent from `plugin/bin/`) produces a record naming the harness guard and `_shared/scratch-worktree.md` §7, not `pre-tool-use.js`.

A conformance test pins the new attribution check in the feedback skill prose.
