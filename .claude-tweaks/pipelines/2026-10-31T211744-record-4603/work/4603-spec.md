# 4603: Move the Parent-Gate Procedure's evaluation into a tested CLI

Origin: reflect full from #4466 (multi-spec batch with #4469)
Defer-reason: tangential

## Current State

`plugin/skills/wrap-up/verification-brief-parent-gate.md` has six callers since #4466. It is still an agent-executed prose procedure. Resolve the parent, Enumerate the parent's sub-issues (`gh api …/sub_issues`), the Self-inclusion rule, Evaluate the gate, the oversight-floor check, and the below-floor close's idempotence check are each spelled out as `gh`/`jq`/`node -e` snippets for an agent to compose. Only the final state function, `parentGateState` (`plugin/bin/lib/issues/acceptance.js`), is code with unit tests.

#4466's review confirmed eight defects in those snippets:
- no `--paginate` on the sub-issue read;
- no `stateReason`, so not-planned sub-issues closed the parent `completed`;
- cross-repo closing references counted;
- a human reopen re-closed;
- the plugin's own heading comment read as absent;
- a free-text section inlined into JS source;
- a missing `parent-issue` check;
- no hold when Step 4.0 returned nothing.

All eight were fixed in prose and pinned by regex conformance tests. Those tests check the wording, not the behavior.

Integration-branch probe: `git ls-tree --name-only origin/main plugin/bin/` lists no parent-gate CLI. `git grep -n -F -e "parentGateState" origin/main -- plugin/bin` matches only `acceptance.js` and `engine-verify.js`. `plugin/bin/fetch-sub-issues.js` (paginated) exists and is not used by the procedure.

## Deliverables

- [ ] A `plugin/bin/parent-gate.js` CLI that takes a sub-issue number or a parent number plus the merge's closing set. It resolves the parent (native link or `Parent: #N`), enumerates sub-issues with state and `stateReason` through the paginated fetcher, applies the self-inclusion rule and the oversight floor, and prints one JSON verdict: `{parent, state, exceeds, closeReason, idempotence}`.
- [ ] `verification-brief-parent-gate.md` calls that CLI in place of its Resolve, Enumerate, Self-inclusion and Evaluate snippets, keeping prose only for routing the verdict.

## Acceptance Criteria

- [ ] Unit tests cover:
  - a parent with more than 30 sub-issues;
  - all sub-issues closed not-planned;
  - a cross-repo closing reference;
  - a human-reopened parent;
  - a parent without `parent-issue`.

  Each case gets the verdict the prose procedure now specifies.
- [ ] `grep -F "issues/\$PARENT_NUM/sub_issues" plugin/skills/wrap-up/verification-brief-parent-gate.md` returns nothing.

## Release Note

Closing and gating a decomposed feature's parent now runs on tested code instead of instructions an agent re-composes each run, so edge cases like long sub-issue lists and cancelled sub-issues behave the same every time.

## Architecture Alignment (build, Common Step 4.5)

Deviations from this spec as built, each classified Beneficial and kept:

1. One gate implementation. The shared core `plugin/bin/lib/issues/parent-gate.js` holds the gather and evaluate logic. The reconciler driver `plugin/bin/lib/issues/below-floor-parent-close.js` (#4599, landed after this spec) is refactored to compose it, so the CLI and the reconciler share every rule. This avoids a second Node copy of the gate.
2. The verdict is a superset of the five named fields. Besides `parentIssue` (Plan Review Decisions, Reading B), it carries `maxTier`, `riskFloor`, `needs`, `held`, `subIssues` and `skipped`. These are the values Close steps 1-3 and Step 4.0b route on, so the prose makes no second fetch.
3. A gh-absent fact source. `--facts-json <file>`, with `plugin/bin/lib/issues/mcp-parent-gate-shape.js`, carries the #4602 MCP transport (also landed after this spec) through the same evaluate path.
4. Idempotence is read only for Close-running callers. Only Step 4.0b, the tidy parent-side entry and the local-files sub-issue-side entry pass `--idempotence`, so the pre-merge entries never read comments.
5. One repo per gate. Every gate read, and the reconciler driver writes, carry `--repo {owner}/{repo}`. The bare `gh issue` writes in the prose Close/Apply fences are deferred (staged sdd-ruling-20, Defer-reason: genuinely-larger).
6. `plugin/skills/demo/entry-paths.md` enumeration gained `--paginate`, because its citation of the removed Enumerate snippet went stale.
7. A local-files fact source. `--backend local-files` carries over the `work-backend: local-files` branches the replaced prose already had (Resolve, Enumerate, Self-inclusion and Evaluate each spelled one), so that prose has a single implementation; it reads the record store through `plugin/bin/lib/issues/local-store.js` and makes no gh call.
