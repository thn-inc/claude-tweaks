# 2328: bot:parked facet not consulted by several pre-existing consumers

Surface: infra

## Current State

The `bot:parked` facet (merge-verification gate parked a record; grants stay intact —
`_shared/work-record.md`) was added, but several sites that classify or render bot state were
never updated to consult it, discovered during a pre-release whole-branch review — all confirmed
still true at this shaping pass:

- `plugin/bin/lib/issues/backlog.js`'s `classifyBuckets` (~line 208): a parked record with grants
  intact still lands in `dispatchable` (confirmed: the if/else chain checks `f.bot.inProgress`,
  `f.stage === 'parked'`, `f.notPlanned`, `f.isParentIssue` — never `f.bot.parked` — before
  falling through to the `ready && granted` → `dispatchable` branch), so `/backlog overview`
  recommends `/dispatch`-ing a record that `/dispatch` itself refuses (contrast
  `queue-pull-script.md:115`, which does filter `!i.facets.bot.parked`).
- `plugin/bin/lib/record-graph/encode.js`'s `borderStyleFor` (~line 55, confirmed): only checks
  `bot.blocked`/`bot.inProgress`, so a parked record renders identically to a healthy one in
  `/visualize`'s queue diagram.
- `plugin/bin/lib/issues/record-buckets.js`'s `isBotParked` (~line 22): exported but has zero
  callers anywhere in `plugin/bin/**` (confirmed by grep) — only skill prose
  (`tidy/step-1-records.md:164`) references it, so no JS path actually enforces the new bucket.
- `plugin/skills/backlog/attention-mode.md` (~line 69): the needs-you list filters on
  `bot:blocked` only — a merge-verification-parked record surfaces nowhere in `/backlog
  attention`.
- `plugin/skills/dispatch/SKILL.md` (lines ~47, 149, 275) and `help/context-flow.md:67`:
  queue-exclusion prose names only `bot:blocked`, though `queue-pull-script.md` itself also
  excludes `bot:parked`.

## Deliverables

- `classifyBuckets` excludes `bot.parked` records from `dispatchable` (or buckets them
  separately).
- `borderStyleFor` returns a distinct style for `bot.parked`.
- `isBotParked` gets a real JS caller, or is removed if genuinely unneeded.
- `attention-mode.md` and the dispatch/help prose name `bot:parked` alongside `bot:blocked`.

## Acceptance Criteria

- A record with `bot:parked` and intact `auto:*` grants no longer appears in `/backlog
  overview`'s `dispatchable` bucket.
- `/visualize`'s queue diagram renders a parked record with a distinct border style.
- `/backlog attention` surfaces a parked record.
- `isBotParked` (`record-buckets.js`) has at least one real JS caller after this fix, or is
  removed from the module's exports with its prose reference (`tidy/step-1-records.md:164`)
  updated to not imply a JS enforcement path that doesn't exist.
- `npm test` passes.

## Technical Approach

Five independent, narrow edits, each following an existing sibling pattern already in the
codebase:

1. `backlog.js`'s `classifyBuckets` (~line 208): add a `f.bot.parked` check to the if/else chain,
   before the `ready && granted` branches — likely its own bucket (e.g. `buckets.parked` if one
   doesn't already exist for this exact case) rather than silently folding into an existing one,
   mirroring how `f.stage === 'parked'` already gets its own `buckets.parked` line just above.
2. `encode.js`'s `borderStyleFor` (~line 55): add a `bot.parked` branch returning a distinct
   style string, following the same `if (bot.blocked) return 'blocked'` pattern already there.
3. `record-buckets.js`'s `isBotParked`: wire it into `classifyBuckets` (step 1) as the real JS
   caller — this may make it redundant with a direct `f.bot.parked` check, so decide whether to
   call the predicate function or inline the check, whichever matches this file's existing
   style for its sibling predicates (`isBotBlocked` etc.).
4. `attention-mode.md` (~line 69): extend the needs-you filter to include `bot:parked` alongside
   `bot:blocked`.
5. `dispatch/SKILL.md` (~lines 47, 149, 275) and `help/context-flow.md:67`: update
   queue-exclusion prose to name `bot:parked` alongside `bot:blocked`, matching what
   `queue-pull-script.md` already does in code.

### Key Files

- `plugin/bin/lib/issues/backlog.js` — `classifyBuckets`, exclude/bucket `bot.parked`
- `plugin/bin/lib/record-graph/encode.js` — `borderStyleFor`, distinct style for `bot.parked`
- `plugin/bin/lib/issues/record-buckets.js` — `isBotParked`, wire in a real caller or remove
- `plugin/skills/backlog/attention-mode.md` — needs-you filter, add `bot:parked`
- `plugin/skills/dispatch/SKILL.md` — queue-exclusion prose, name `bot:parked`
- `plugin/skills/help/context-flow.md` — queue-exclusion prose, name `bot:parked`
- `plugin/skills/tidy/step-1-records.md` — update if `isBotParked` usage changes

## Gotchas

- `bot:parked` records keep their `auto:*` grants intact by design (a merge-verification park is
  not a build failure, unlike `bot:blocked`) — the fix must exclude them from `dispatchable`
  without stripping or otherwise touching their grants.
- Don't conflate `bot:parked` with the pre-existing `stage === 'parked'` bucket in
  `classifyBuckets` — they're different concepts (a human-deferred backlog record vs. a
  merge-verification-parked ready record) and already have separate handling elsewhere; give
  `bot:parked` its own branch rather than merging it into the existing `parked` stage bucket.
