# 4487: Write gate walks a shell function body only where it is defined, missing a write when it is called after a cd

Origin: SDD ruling ratified at Review Console (#4481, staged/sdd-ruling-2.md)

Defer-reason: genuinely-larger

## Current State

`plugin/bin/lib/hooks/git-command.js` walks a function definition's body (`g() { … }`, `function g { … }`) once, as a group where it is defined, so a `cd` in it reaches the commands after the definition. A later call from another cwd is not re-walked: `f() { echo z > k; }; cd ../wt; f` writes `wt/k` in bash 3.2, bash 5 and zsh, while base and every #4481 revision report `r/k`. Not case-specific. #4481's SDD Task 1 ruled it deferred to its own record at Important (ledger row 15); `plugin/skills/_shared/policy-schema-coverage.md` lists it as a known gap ("a function body when the function is called later from another cwd").

**Related:** #4486, #4489

## Deliverables

Record each function name defined in a walked command with its body text, and when a later segment's command word is that name, walk the body under that segment's cwds (bounded, so a recursive or re-defined function cannot loop).

Pin `f() { echo z > k; }; cd ../wt; f` (wt/k) and a redefinition case, with bash 3.2/5 verdicts.

## Acceptance Criteria

`fileWriteTargets('f() { echo z > k; }; cd ../wt; f', '/r/x')` includes `/r/wt/k`.

Each new test fails with the change reverted; the hook suites pass; the known-gaps clause is removed from policy-schema-coverage.md.

## Release Note

The worktree write gate follows a write inside a shell function to the cwd the function is called from.

## Technical Approach

### Key Files

- `plugin/bin/lib/hooks/git-command.js` — re-walk a function body at its call site
- `tests/hooks-gate-coverage.test.js` — pin the call-site shapes
- `plugin/skills/_shared/policy-schema-coverage.md` — drop the known-gap clause
