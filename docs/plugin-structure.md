# Plugin structure and commands

Directory layout, the per-skill sub-file table, and the full command reference for the claude-tweaks plugin.

Extracted from [CLAUDE.md](../CLAUDE.md) so the always-loaded file stays lean — every dispatched subagent inherits `CLAUDE.md` in its system prompt, so bytes there are paid per agent, not per session. `CLAUDE.md`'s own `## Structure` section keeps the orientation summary and points here for the detail.

## Structure

```
plugin/.claude-plugin/plugin.json → Plugin manifest (name, version, description)
plugin/skills/{name}/SKILL.md     → Skill definition (frontmatter + body)
plugin/skills/{name}/*.md         → Sub-files lazy-loaded by the skill
plugin/skills/_shared/*.md        → Cross-skill shared content (contracts, criteria, and canonical procedures cited by skills rather than restated) — see the directory listing
plugin/skills/design-wrapper/compare-shell/ → template.html (self-contained comparison shell: grid + focus views, verdict bar, the focus view's tweak-lever panel (hue / spacing-scale / corner-radius sliders — `input` previews locally on every drag tick, only `change` posts one `tweak` event, and the preview lands on the shell's own swatch, never inside the sandboxed variant iframe), a `vd-data` JSON island + mode flag the template's own inline JS turns into `iframe.src`/`iframe.srcdoc` assignments — property assignment, not an HTML attribute, so embedded variant content needs no manual attribute-escaping) + seed-compare.mjs (`--manifest <json> --mode live|durable --out <path>`: validates the manifest, assembles identity-scope srcdoc docs by inlining a variant's skin CSS into the shared markup, refuses on a missing file/duplicate id/missing-or-unresolvable outcome, validates the durable-mode-only `tweaks: [{token, value}]` field and bakes it into `outcome.tweaks` for `decision.html` replay — live mode drops it silently and never validates it, warns past a 2 MB output). Not a lazy-loaded SKILL.md sub-file — a sibling asset directory shipping with the plugin payload (#1203). First consumer: `modes/explore.md`'s Compare/Verdict/Lock-in (#1204) via `_shared/visual-decision.md`, serving live-mode output through `plugin/bin/visual-decide.js` (#1202); tests in `tests/compare-shell-seeder.test.js` and `tests/compare-shell-tweak-lever.test.js`
plugin/agents/{name}.md           → Agent definitions (frontmatter + body)
plugin/hooks/hooks.json           → Hook definitions (SessionStart/SessionEnd/PreCompact continuity + UserPromptSubmit typed-skill ledger + PreToolUse/PostToolUse/SubagentStop enforcement + PostToolUseFailure logging, all via plugin/bin/hooks.js)
plugin/bin/hooks.js               → Hook dispatcher (one entry point for all hook events + record-worktree/close-run/teardown-run/archive-run/resolve-run-dir/record-pr/spec-status/manifest-init/delete-ledger/resolve-ledger/resolve-console/check-resume-freshness/check-staged-inventory/check-session-residue/check-pass-reentry/check-sibling-sessions/sweep-shadow/adopt-run-dir/reconcile/reconcile-background/reconcile-summary subcommands; delete-ledger --run <dir> [--ledger <path>] (#2544) gives wrap-up cleanup item 2 (ledger deletion) a verb — resolves the single active ledger via `bin/lib/wrap-up/ledger-write.js`'s resolveLedgerPath ({run-dir}/ledger.md first, else the one docs/plans ledger this branch owns — merge-base diff or untracked, shared with pack.js's ledger probe via ledger-ownership.js; 2+ owned candidates refuses to guess, naming all of them, unless --ledger disambiguates explicitly, and an uncomputable merge base refuses as unattributable) and deletes it, reporting "not found" (not a crash) when already deleted; resolve-ledger --run <dir> (#3897) is its read-only twin: prints this run's ledger (`found`/`none`/`ambiguous`/`unattributable`, then `this-run:`/`other-run:`/`unattributed:` lines) for `_shared/ledger-format.md`'s resolution rule; reconcile-background is the detached, write-only half of a SessionStart reconcile pass, and reconcile-summary prints the one-line reconcile residue summary `/claude-tweaks:flow`'s closing report renders (#644) — see docs/hooks.md's Background convergence bullet; check-session-residue (#2736) re-runs SessionStart's own unfinished-pipeline-run/unapproved-staged-proposal detection (`plugin/bin/lib/hooks/session-residue.js`, shared with session-start.js — distinct from the unrelated `bin/residue.js` close-time-residue CLI) so wrap-up's Review Console can resurface residue still unresolved by the time it renders; check-pass-reentry --run <dir> [--online] (#3553) prints consolidated-pass.js's checkPassReentry verdict JSON for flow/multispec-review-console.md's re-entry step; the fourteen that accept --run (record-worktree, record-pr, spec-status, manifest-init, close-run, teardown-run, check-resume-freshness, check-staged-inventory, check-session-residue, check-pass-reentry, archive-run, delete-ledger, resolve-ledger, resolve-console — docs/hooks.md) refuse a value not anchored under the main checkout. sweep-shadow --run <anchored-run-dir> --worktree <path> is a fifteenth, narrower case: it relocates a judge's stray staged/ writes from a worktree's shadow of the run-dir path to the anchored one (plugin/bin/lib/hooks/sweep-shadow.js; plugin/skills/wrap-up/curation-engine.md §4), and folds its own not-anchored check into the sweep's diagnostic output rather than the shared resolveRunArg rejection path, since --worktree is legitimately unanchored (a linked worktree) where the other fourteen's --run never is. adopt-run-dir --run <anchored-run-dir> --worktree <worktree-path> is a sixteenth: it requires the opposite pairing (an anchored --run AND a --worktree that must itself resolve to a genuine linked worktree of this same repo, via worktree-detect.js's repoInfo()) and, on success, copies decisions.md/report.md/staged/** into that worktree's own copy of the run-dir path (plugin/skills/tidy/step-7-5-worktree-always.md's copy-then-commit step, #2409))
plugin/bin/                       → Node executables — the statusline, hooks dispatcher, four health-sweep CLIs, and the standalone CLIs — the command reference below is their index; this line deliberately does not re-enumerate them, since a hand-maintained copy here drifted ~18 CLIs behind it
plugin/bin/lib/                   → Shared Node helpers (color, deps, coordination, issue claims + ingestion, policy, file-lock, json-store, shared-primitives, work-backend). shared-primitives.js is the canonical home for one-liner idioms otherwise retyped per module — `escapeRegExp`, `isPathContained(candidate, root, {orEqual, pathImpl})` (a thin wrapper over `path-guard`'s `isAncestorOrSelf` — root excluded unless `orEqual` — #2324/#3498, consolidated from 6 independent copies across reconcile/, hooks/, and timing/, the last same-line hand-rolled ones migrated in #3498 and the two variable-mediated `startsWith(<name bound to a sep expression>)` copies in hooks/sweep-shadow.js and timing/transcript.js in #3892), `toPosix(p, sep = path.sep)` (a repo-display path — report IDs, git-style paths, globs — with every `sep` rewritten to `/`; `sep` is a parameter so a test pins the win32 branch with `path.win32.sep` on any host, #2767; never apply it to a path later opened with fs), `GH_TIMEOUT_MS`/`GIT_TIMEOUT_MS`/`LARGE_MAX_BUFFER_BYTES` (`LARGE_MAX_BUFFER_BYTES` is a plain constant, but `GH_TIMEOUT_MS` since #2567 and `GIT_TIMEOUT_MS` since #3051 are lazily-resolved getters, not literals — `CLAUDE_TWEAKS_GH_TIMEOUT_MS` env var > the `gh-timeout-ms` policy key (bounded 1000-60000, `_shared/policy-schema.md`) > a 5000 default for the former, `CLAUDE_TWEAKS_GIT_TIMEOUT_MS` > `git-timeout-ms` (bounded 1000-120000) > a 30000 default for the latter — claims-git-cas.js's own `git` subprocess calls, which need more headroom than a `gh` call — each memoized on first read so a consumer that requires this module without ever reading it — pre-tool-use.js's hot path, which pulls it in via git-exec.js for `isPathContained` alone — never pays either policy read; import it, never retype its default at a new call site), `isTimeoutError` (the three-way timeout-kill check — `ETIMEDOUT`/`killed`/`SIGTERM` — both timeout getters and `runClassified`/`runClassifiedAsync` share), and `runClassified`/`runClassifiedAsync` (both take an optional third `{ retryOnTimeout }`, default false: when opted in, a timeout-killed `fn()` is retried exactly once at the same bound before `mapError` ever sees it — today only the three `gh`-calling reconcile modules release-merged.js, preflight.js, and pr-state.js opt in, deliberately not the `git`-calling twins, where doubling worst-case latency on the enforcement-critical worktree gate costs more); read it before re-implementing one. work-backend.js (#3554) is the one CLAUDE.md `work-backend:` reader — parseWorkBackend(text) / readWorkBackend(root), null when unconfigured, never throws; import it rather than re-adding a local regex. git-z.js (#3470) holds the NUL-stream parsers for `git … -z` path-list output — `splitNul`, `parseNameStatusZ`, `splitLogZ`, `parseNumstatZ`, `parseStatusPorcelainZ`, `parseLsTreeZ`, `unquoteCPath` — which every plugin/bin git path-list read uses per `plugin/skills/_shared/git-path-read.md` (pinned by `tests/git-path-read-conformance.test.js`); never split git path output on newlines. Multi-file modules live directly at plugin/bin/lib/{name}/ (e.g. plugin/bin/lib/issues/, plugin/bin/lib/hooks/, plugin/bin/lib/health-core/) — flat sibling directories, NOT a nested _shared/ wrapper. That convention is specific to plugin/skills/_shared/; don't assume it applies here.
plugin/bin/lib/feedback/          → file-feedback.js (argv-safe upstream feedback filing — see the file-feedback.js CLI entry below). Consumed by plugin/skills/feedback/SKILL.md
plugin/bin/lib/transcript-judge/  → watermark.js (per-consumer evaluation-watermark read/write, byte-to-line conversion for delta-scoped re-judging — a second judge run against the same transcript evaluates only the delta since the last run, or skips the dispatch altogether when `isTranscriptUnchanged` reports no growth since the watermark (#701); a `mode: "self-assessment"` watermark's byte offset is ignored by both, so the next run re-judges from the start (#2916), namespaced per consumer so two consumers judging the same transcript never share state). Consumed by plugin/skills/_shared/transcript-judge.md and its consumers (plugin/skills/feedback/session-evaluation.md; plugin/skills/reflect/SKILL.md, #857)
plugin/bin/lib/declined-learning/ → store.js (one shared, flat degrade-open cache recording `{fingerprint, declinedAt, reason, source, subject?}` for findings/insights a human explicitly declined — `subject` (#1033) is optional human-legible text behind the fingerprint, absent on any entry recorded before it existed; `listDeclined` returns full entries including `subject`, alongside the pre-#1033 `listDeclinedFingerprints` — same injectable-fs conventions as transcript-judge/watermark.js, single file rather than per-consumer since every entry carries its own `source`). Consumed by plugin/skills/_shared/upstream-feedback-batch.md and plugin/skills/feedback/session-evaluation.md (`/feedback` Step 7 declines), plugin/skills/feedback/SKILL.md Step 4 (`lookupDecline` Prior-decline annotation, #1033), and plugin/skills/reflect/full-mode.md and reflect/SKILL.md (`/wrap-up` reflect insight resolution and transcript-judge dispatch, #1033) — #849. Also fronted by plugin/bin/declined-learning.js (#2544) — a CLI wrapper so these prescribed "compute the fingerprint, then look it up"/"record the decline" steps are one command each rather than a scratch `node -e` module call
plugin/bin/lib/skill-audit/       → Corpus measurement and guards for the shipped skill payload: the Read-limit rail (`budgets.js`/`rail.js`, below — the only size limit that blocks), the per-invocation load model (`load.js`, below), transcript-measured load (`transcript-load.js`, #3309 — what real sessions loaded, read by `bin/skill-load-report.js`), Anti-Pattern row preservation, identifier loss, and the four bloat signals (the fourth, #3308, flags a file far larger than its corpus siblings: p95 at 20+ files, floored at 3× median; 3× median at 5-19). Called at runtime by harness-health's evidence pre-checks 9 and 10; its tests are what stop the payload regrowing after the v6.34-6.37 cleanup. Plus harness-cost.js (#2741): each shipped skill's declared `allowed-tools:` tool count (and each agent definition's `tools:`) measured against a fixed four-tool Read/Write/Edit/Bash baseline, together with its SKILL.md (or agent file) bytes and, for skills, distinct `_shared/*.md` citation depth — reports only, gates nothing; called at runtime by harness-health's Harness cost-efficiency check via `bin/harness-cost-report.js`. Plus option-description.js (#659): parses `AskUserQuestion` option `description` fields and flags a literal `?` — deliberation leaking into the option surface instead of stating the consequence, per docs/skill-authoring.md's Decisions bullet — exercised only by its own corpus-wide conformance test, never called at harness-health runtime. `load.js` is the per-invocation load model (#3307) — floor/closure per `SKILL.md` entry point, `loadDelta` between two trees — read by `load-delta.js`. `budgets.js` (#3306) is the single source of truth for skill-size numbers and requires nothing: the Read tool's 25,000-token and 2,000-line caps, converted to a byte rail by a calibrated bytes-per-token ratio (re-run the calibration recorded in its header when a Claude Code release changes the Read limits or the tokenizer), plus the CLI's 1,536-char per-description listing max; `rail.js` maps a plugin corpus — every shipped skill `.md`, every compose call site's composed bundle, every description — onto those limits, run by the rail tests in `context-cost.test.js` and their go-red fixtures in `budgets.test.js`. `plugin-root-reader.js` (#3461) is the one plugin-root file reader — a read returns only a regular file whose realpath lies inside the base, and a missing base or `skills/` reads as absent — shared by `load-delta.js`'s head side and `skill-load-report.js`'s closure index.
plugin/bin/lib/wrap-up/           → Five module families. (1) Deterministic git-fact readers for the wrap-up State block: reflog.js classifies `git reflog` history into report-worthy ops (rebase, reset, cherry-pick, revert, amend, merge, push), state.js reads branch/upstream/ahead-behind/pushed/linked-worktree facts (falling back to the branch's own `origin/{branch}` remote-tracking ref when `@{u}` is unset or names another branch, #1869), render.js renders the block. Consumed by plugin/bin/wrap-up-state.js so the report reads repository facts from git instead of reconstructing them from memory — the motivating failure this closes was a report claiming work had landed when it had only been committed locally. (2) The Phase 2 curation engine: registry.js is the machine half of SKILL.md's registry table (rows, gates, scopes, judges, dispositions — `tests/wrap-up-registry-pin.test.js` fails when the two drift), facts.js computes every fact-based gate from git and the filesystem, engine-plan.js builds the worklist and pre-resolves closed rows, engine-record.js validates one judgment payload per open row and appends its SCANNED + telemetry lines, engine-render.js renders the Phase 2 trace table and the Review Console's engine-fed sections behind a forbidden-vocabulary post-check. Consumed by plugin/bin/wrap-up-engine.js so row ordering, gate evaluation, and output formatting are program-owned rather than seven hand-maintained prose formats. (3) engine-verify.js — the Phase 4 closure-gate: nine deterministic checks (plans+ledger removal, design caches, run-dir archival, worktree removal, carrier commit, reference-repair scoping, acceptance labeling, memory updates, upstream feedback) replacing `execution-and-verification.md`'s old hand-run "Verify execution" checklist, read against `verify-expectations.json` (written by the Review Console) for the checks whose expected values live outside git/fs. Consumed by plugin/bin/wrap-up-engine.js's `verify` verb, which also persists the rows via verify-results.js (#3783 — writes/reads `verify.json` in the verified run dir). (4) pack.js (#1930 — gatherPack: eight concurrent read-only probes for /wrap-up Phases 3-4 — residue, state, blastRadius, pr, recordLabels, claim, ledger, unblocked — each in a {ok, value|error, durationMs} envelope; inputs resolved once from run-state.json, the materialized headers, and policy; #2887 — the ledger probe counts only docs/plans ledgers this branch owns, i.e. added or changed against the merge base or untracked, and lists inherited ones under `unattributedFiles`, never summed). Consumed by plugin/bin/wrap-up-pack.js. (5) ledger-write.js (#2544) — the write half of the pipeline ledger (pack.js's parseLedger is read-only): resolveLedgerPath finds the single active ledger file (run-dir-first, else the one docs/plans ledger this branch owns — merge-base diff or untracked, shared with pack.js's ledger probe via ledger-ownership.js — never guesses among 2+, fails closed as unattributable when ownership cannot be computed), flipLedgerRow rewrites one row's Status/Resolution cells in place, text-level, validated against ledger-format.md's closed five-terminal-status enum, and refuses a table holding duplicate row numbers (serializeLedgerTable throws rather than write back a table whose duplicate rows parseLedgerTable's Map collapsed, #3834); ledger-cells.js is the shared `\|` row codec (escapeLedgerCell / unescapeLedgerCell / splitLedgerRow / ledgerRowCells) that ledger-write.js, pack.js's parseLedger and the statusline all import. Consumed by plugin/bin/wrap-up-engine.js's `finish-console` verb and plugin/bin/hooks.js's `delete-ledger` and `resolve-ledger` subcommands (describeRunLedgers/formatLedgerReport)
plugin/bin/lib/residue/           → The wrap-up Outstanding-residue sweep: finding.js (shared finding shape + fingerprint id), scope.js (resolves the blast-radius base — merged branches, worktrees, head branch — with ran:false/reason when it can't), probes/{worktrees,branches,forge,suite,release,pipeline-runs,artifacts}.js (independent probes, each returning `{ran, reason, findings}`; the runner shape they take differs per probe — see plugin/bin/residue.js's own inline note; release reports a CHANGELOG heading as untagged only when neither the local `v*` tags nor `git ls-remote --tags origin` list it, always at `remedy: record` since tagging released history is a human call, and a failed remote read falls back to local tags with `ran: true` and a `reason` naming the fallback (#2882); pipeline-runs sweeps `.claude-tweaks/pipelines/` directly for a run whose `run-state.json` reached `status: clean` without being archived under `archive/`, at `remedy: auto` unless that run's recorded `worktree` still matches a locked entry in the `scope.worktrees` list residue.js passes in — a live sibling session still holding it downgrades the finding to `remedy: record` instead of archiving the run dir out from under that session (#1328); artifacts ages out QA evidence under `.claude-tweaks/artifacts/` on a 30-day newest-file rule, and surfaces legacy project-root `screenshots/`/`traces/` trees only when they match the pre-relocation plugin shape and `git ls-files` shows nothing tracked under them, always at `remedy: record` — never `auto`, since neither signal proves plugin ownership), render.js (the Outstanding table — a finding with no disposition renders the literal `NEEDS DISPOSITION`, never blank; an unrun probe renders `unknown` with its reason rather than silently reading as clean; a probe that ran but carries a `reason` gets a `degraded:` line under "Probes that ran on reduced input", #2882). Consumed by plugin/bin/residue.js
plugin/bin/lib/model-profiles/    → The work-profile system: profiles.js (the `Fast | Standard | Capable | Frontier` table + resolve(), merging policy overrides, run stance, CLI overrides, and session-failure avoidance in precedence order — table default, policy row, cliOverride, stance, model-ceiling, frontier gates, session-failure avoidance, with the last stage that changed the result naming `source`), policy-fragment.js (the nested `.claude-tweaks/policy.yml` model-config reader, deliberately separate from policy-schema.js's flat-only parser), session-failures.js (the session-scoped model-failure blacklist, #763: `os.tmpdir()`-keyed by `CLAUDE_CODE_SESSION_ID`, an mkdir-based lock around `recordFailure`'s read-modify-write, and `invalidateFailures` as its recovery path — #841). Consumed by plugin/bin/resolve-profile.js, the CLI wrapper dispatch sites resolve profiles through (its `record-failure`/`clear-failures` subcommands read/clear the blacklist); contract cited by `plugin/skills/_shared/subagent-dispatch-core.md` §Model Selection
plugin/bin/lib/reconcile/         → The `integration-model: pr-first` background convergence module (#405-#415): mirror-ff.js (fast-forwards the main checkout's local integration branch toward `origin/{integration}`, `--ff-only`; under `--dry-run` it reports `skipped` / `dry-run` instead of fast-forwarding), red-tip.js (inform-tier failing-CI detection on the integration branch's tip, #561), reap-merged.js (removes a merged run's worktree), release-merged.js (releases its issue claim when the merged PR closes the issue, or on issue-closed evidence), archive-merged.js (archives its run dir), archive-branches.js (archives/deletes abandoned plugin-owned local branches + ages archive/* tags), prune-remote.js (deletes remote plugin-owned branches proven merged — MERGED PR + cherry-equivalence; the family's one pushed mutation), ledger-residue.js (opens one removal PR for docs/plans/*-ledger.md residue found on origin/{integration} with no open row and no live run — tidy's orphan-ledger rule, #3812), console-execute.js (executes an answered Review-Console PR — gh-CLI-only by design, no MCP fallback), classify.js + pr-state.js (shared PR-state classification: `resolvePrState` per branch, `resolvePrStateByNumber` per PR number — widened by #2367 to also carry `mergeable`/`mergeStateStatus`, reused by `_shared/github-pr-scan.md`'s `repo-wide` item 11 pending-review staleness check rather than a third PR-state-reading code path — plus `resolvePrStatesBulk` — the chunked aliased-GraphQL screen resolving a whole branch set in ceil(N/50) all-or-nothing round trips, #1082). Both destructive branch checks read it screen-then-confirm: archive-branches and prune-remote screen the in-scope set in one bulk call, then differ on what reaches the per-branch confirm — prune-remote's provisional skip still short-circuits before any confirm call, while archive-branches' confirm also runs for a MERGED- or screen-null-screened, non-cherry-equivalent branch regardless of whether the provisional itself is destructive (`squashCandidate` routing, #2252/#2322), with the confirm's own evidence rather than the provisional having the final say (see `docs/reconcile-checks.md`'s Merged-proof and Confirm-routing symmetry sections). The two checks still differ deliberately on screen failure (prune-remote fails the whole check; archive-branches degrades to per-branch skips so its gh-independent archive-tag aging keeps running, #1083) and on the multi-PR tie-break (only prune-remote passes `preferOpen`, since its deletion is pushed and unrecoverable, #664). The #820 latency work adds five more: preflight.js (one cheap upfront GitHub-health check so a pass degrades once, fast, instead of every network-dependent check separately discovering the same outage via its own timeout), budget.js (an overall wall-clock ceiling for one pass, bounding the SUM across checks rather than any single check; `reconcile()`'s `opts.budgetMs` overrides it, and the `hooks.js reconcile` CLI passes `Infinity` for an explicit `--checks` subset so the hot-path ceiling never starves a named check such as `reap`, #3026), cache.js (one local, gitignored best-effort cache file under the MAIN checkout backing both the short-TTL "skip the whole pass" gate and the per-claim content-addressed skip), gh-pool.js (a concurrency-capped async mapper for the family's per-item `gh` calls, where a per-item failure never aborts the batch), shared-fetch.js (the one `git fetch` a pass performs, shared by mirror and prune-remote, its shape scoped to which of the two was actually requested). index.js's `reconcile()` runs the checks (mirror → red-tip → console → release → archive → archive-branches → remote-prune → ledger-residue → reap, reap last since it physically removes worktrees; an explicit `checks` subset is first expanded with its prerequisites — `expandChecks`, #3630, see docs/reconcile-checks.md) from SessionStart and dispatch's own trigger points, no session continuity required — but SessionStart runs only mirror/red-tip/console inline and defers the other six to a detached `reconcile-background` child process, surfaced one session later (see docs/hooks.md's Background convergence bullet). This list is not a full index of the directory: seven further modules (background-lock.js, escalate-residue.js, format-summary.js, issue-list-cache.js, origin-head.js, residue-summary.js, squash-provenance.js) ship beside the ones named above — docs/reconcile-checks.md documents the ones it covers, the module headers the rest. Coverage lives in tests/bin-lib/reconcile/ plus tests/reconcile.test.js, tests/console-execute.test.js, and the other top-level tests/*.test.js files the npm test glob already picks up
```
