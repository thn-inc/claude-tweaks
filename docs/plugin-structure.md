# Plugin structure and commands

Directory layout, the per-skill sub-file table, and the full command reference for the claude-tweaks plugin.

Extracted from [CLAUDE.md](../CLAUDE.md) so the always-loaded file stays lean — every dispatched subagent inherits `CLAUDE.md` in its system prompt, so bytes there are paid per agent, not per session. `CLAUDE.md`'s own `## Structure` section keeps the orientation summary and points here for the detail.

## Structure

```
plugin/.claude-plugin/plugin.json → Plugin manifest (name, version, description)
plugin/skills/{name}/SKILL.md     → Skill definition (frontmatter + body)
plugin/skills/{name}/*.md         → Sub-files lazy-loaded by the skill
plugin/skills/_shared/*.md        → Cross-skill shared content (contracts, criteria, and canonical procedures cited by skills rather than restated) — see the directory listing
plugin/skills/design-wrapper/compare-shell/ → template.html (self-contained comparison shell: grid + focus views, verdict bar, the focus view's tweak-lever panel (hue / spacing-scale / corner-radius sliders — `input` previews locally on every drag tick, only `change` posts one `tweak` event, and the preview lands on the shell's own swatch, never inside the sandboxed variant iframe), a `vd-data` JSON island + mode flag the template's own inline JS turns into `iframe.src`/`iframe.srcdoc` assignments — property assignment, not an HTML attribute, so embedded variant content needs no manual attribute-escaping) + seed-compare.mjs (`--manifest <json> --mode live|durable --out <path>`: validates the manifest, assembles identity-scope srcdoc docs by inlining a variant's skin CSS into the shared markup, refuses on a missing file/duplicate id/missing-or-unresolvable outcome, validates the durable-mode-only `tweaks: [{token, value}]` field and bakes it into `outcome.tweaks` for `decision.html` replay — live mode drops it silently and never validates it, warns past a 2 MB output). Not a lazy-loaded SKILL.md sub-file — a sibling asset directory shipping with the plugin payload (#1203). First consumer: `modes/explore.md`'s Compare/Verdict/Lock-in (#1204) via `_shared/visual-decision.md`, serving live-mode output through `plugin/bin/visual-decide.js` (#1202); tests in `tests/compare-shell-seeder.test.js` and `tests/compare-shell-tweak-lever.test.js`

plugin/hooks/hooks.json           → Hook definitions (SessionStart/SessionEnd/PreCompact continuity + PreToolUse/PostToolUse/SubagentStop enforcement, all via plugin/bin/hooks.js)

Consumed by plugin/skills/_shared/upstream-feedback-batch.md and plugin/skills/feedback/session-evaluation.md (`/feedback` Step 7 declines), plugin/skills/feedback/SKILL.md Step 4 (`lookupDecline` Prior-decline annotation, #1033), and plugin/skills/reflect/full-mode.md and reflect/SKILL.md (`/wrap-up` reflect insight resolution and transcript-judge dispatch, #1033) — #849
plugin/bin/lib/skill-audit/       → Corpus measurement and guards for the shipped skill payload: the 40 KB per-file ceiling (a warning tier since #1990 — the hard gate is composed bytes per compose call site, `overComposedCeiling`/`COMPOSED_STEP_EXCEPTIONS`), Anti-Pattern row preservation, identifier loss, and the four bloat signals. Called at runtime by harness-health's evidence pre-checks 9 and 10; its tests are what stop the payload regrowing after the v6.34-6.37 cleanup. Plus option-description.js (#659): parses `AskUserQuestion` option `description` fields and flags a literal `?` — deliberation leaking into the option surface instead of stating the consequence, per docs/skill-authoring.md's Decisions bullet — exercised only by its own corpus-wide conformance test, never called at harness-health runtime
plugin/bin/lib/wrap-up/           → Four module families. (1) Deterministic git-fact readers for the wrap-up State block: reflog.js classifies `git reflog` history into report-worthy ops (rebase, reset, cherry-pick, revert, amend, merge, push), state.js reads branch/upstream/ahead-behind/pushed/linked-worktree facts (falling back to the branch's own `origin/{branch}` remote-tracking ref when `@{u}` is unset or names another branch, #1869), render.js renders the block. Consumed by plugin/bin/wrap-up-state.js so the report reads repository facts from git instead of reconstructing them from memory — the motivating failure this closes was a report claiming work had landed when it had only been committed locally. (2) The Phase 2 curation engine: registry.js is the machine half of SKILL.md's registry table (rows, gates, scopes, judges, dispositions — `tests/wrap-up-registry-pin.test.js` fails when the two drift), facts.js computes every fact-based gate from git and the filesystem, engine-plan.js builds the worklist and pre-resolves closed rows, engine-record.js validates one judgment payload per open row and appends its SCANNED + telemetry lines, engine-render.js renders the Phase 2 trace table and the Review Console's engine-fed sections behind a forbidden-vocabulary post-check. Consumed by plugin/bin/wrap-up-engine.js so row ordering, gate evaluation, and output formatting are program-owned rather than seven hand-maintained prose formats. (3) engine-verify.js — the Phase 4 closure-gate: nine deterministic checks (plans+ledger removal, design caches, run-dir archival, worktree removal, carrier commit, reference-repair scoping, acceptance labeling, memory updates, upstream feedback) replacing `execution-and-verification.md`'s old hand-run "Verify execution" checklist, read against `verify-expectations.json` (written by the Review Console) for the checks whose expected values live outside git/fs. Consumed by plugin/bin/wrap-up-engine.js's `verify` verb. (4) pack.js (#1930 — gatherPack: eight concurrent read-only probes for /wrap-up Phases 3-4 — residue, state, blastRadius, pr, recordLabels, claim, ledger, unblocked — each in a {ok, value|error, durationMs} envelope; inputs resolved once from run-state.json, the materialized headers, and policy). Consumed by plugin/bin/wrap-up-pack.js
plugin/bin/lib/residue/           → The wrap-up Outstanding-residue sweep: finding.js (shared finding shape + fingerprint id), scope.js (resolves the blast-radius base — merged branches, worktrees, head branch — with ran:false/reason when it can't), probes/{worktrees,branches,forge,suite,release,pipeline-runs,artifacts}.js (independent probes, each returning `{ran, reason, findings}`; the runner shape they take differs per probe — see plugin/bin/residue.js's own inline note; pipeline-runs sweeps `.claude-tweaks/pipelines/` directly for a run whose `run-state.json` reached `status: clean` without being archived under `archive/`, at `remedy: auto` unless that run's recorded `worktree` still matches a locked entry in the `scope.worktrees` list residue.js passes in — a live sibling session still holding it downgrades the finding to `remedy: record` instead of archiving the run dir out from under that session (#1328); artifacts ages out QA evidence under `.claude-tweaks/artifacts/` on a 30-day newest-file rule, and surfaces legacy project-root `screenshots/`/`traces/` trees only when they match the pre-relocation plugin shape and `git ls-files` shows nothing tracked under them, always at `remedy: record` — never `auto`, since neither signal proves plugin ownership), render.js (the Outstanding table — a finding with no disposition renders the literal `NEEDS DISPOSITION`, never blank; an unrun probe renders `unknown` with its reason rather than silently reading as clean). Consumed by plugin/bin/residue.js
plugin/bin/lib/model-profiles/    → The work-profile system: profiles.js (the `Fast | Standard | Capable | Frontier` table + resolve(), merging policy overrides, run stance, CLI overrides, and session-failure avoidance in precedence order — table default, policy row, cliOverride, stance, model-ceiling, frontier gates, session-failure avoidance, with the last stage that changed the result naming `source`), policy-fragment.js (the nested `.claude-tweaks/policy.yml` model-config reader, deliberately separate from policy-schema.js's flat-only parser), session-failures.js (the session-scoped model-failure blacklist, #763: `os.tmpdir()`-keyed by `CLAUDE_CODE_SESSION_ID`, an mkdir-based lock around `recordFailure`'s read-modify-write, and `invalidateFailures` as its recovery path — #841). Consumed by plugin/bin/resolve-profile.js, the CLI wrapper dispatch sites resolve profiles through (its `record-failure`/`clear-failures` subcommands read/clear the blacklist); contract cited by `plugin/skills/_shared/subagent-dispatch-core.md` §Model Selection

Both destructive branch checks read it screen-then-confirm: archive-branches and prune-remote screen the in-scope set in one bulk call and re-read per-branch only to confirm a destructive provisional verdict, differing deliberately on screen failure (prune-remote fails the whole check; archive-branches degrades to per-branch skips so its gh-independent archive-tag aging keeps running, #1083) and on the multi-PR tie-break (only prune-remote passes `preferOpen`, since its deletion is pushed and unrecoverable, #664). The #820 latency work adds five more: preflight.js (one cheap upfront GitHub-health check so a pass degrades once, fast, instead of every network-dependent check separately discovering the same outage via its own timeout), budget.js (an overall wall-clock ceiling for one pass, bounding the SUM across checks rather than any single check), cache.js (one local, gitignored best-effort cache file under the MAIN checkout backing both the short-TTL "skip the whole pass" gate and the per-claim content-addressed skip), gh-pool.js (a concurrency-capped async mapper for the family's per-item `gh` calls, where a per-item failure never aborts the batch), shared-fetch.js (the one `git fetch` a pass performs, shared by mirror and prune-remote, its shape scoped to which of the two was actually requested). index.js's `reconcile()` runs the checks (mirror → red-tip → console → release → archive → archive-branches → remote-prune → reap, reap last since it physically removes worktrees) from SessionStart and dispatch's own trigger points, no session continuity required — but SessionStart runs only mirror/red-tip/console inline and defers the other five to a detached `reconcile-background` child process, surfaced one session later (see docs/hooks.md's Background convergence bullet). This list is not a full index of the directory: six further modules (background-lock.js, escalate-residue.js, format-summary.js, issue-list-cache.js, residue-summary.js, squash-provenance.js) ship beside the ones named above — docs/reconcile-checks.md documents the ones it covers, the module headers the rest.
