# Read a Record's Station Events From the Main Checkout

**Persona:** Maintainer of the dispatch factory floor (or any tool that reads claude-tweaks pipeline state) who needs to know where a record is in the pipeline without parsing skill prose, run directories or the driver's private event log.
**Goal:** Read one append-only file, `.claude-tweaks/station-events.jsonl` in the main checkout, and trust that every line is a transition the program code actually made, that replaying a transition never double-counts it, and that an unwritable file never changes what a claim, release, blocker check or driver run does.
**Entry point:** A terminal at the plugin checkout root, with `docs/reference/station-events.md` open for the field list.
**Success state:** Two emits of one transition leave two lines with one `eventKey`; a read-only `.claude-tweaks` directory makes the emitter drop the event with one stderr line instead of throwing; and a claim from a linked worktree lands its `session_bound` line in the main checkout's file, not the worktree's; and an append in a repo with no station-events `.gitignore` rule leaves `git status --porcelain` empty.

## Steps

### 1. Emit one transition twice and read the lines — terminal, `plugin/bin/lib/station-events/emit.js` directly
- **URL:** `node -e "const fs=require('fs'),os=require('os'),path=require('path');const {appendStationEvent,stationEventPath}=require('./plugin/bin/lib/station-events/emit');const root=fs.mkdtempSync(path.join(os.tmpdir(),'se-'));const ev={repoName:'acme/widgets',recordNumber:999,kind:'session_bound',station:'build',lane:'unknown',sessionId:'sess-1',runId:'run-a',payload:{},discriminator:'claim:t0'};appendStationEvent(ev,{mainRoot:root});appendStationEvent(ev,{mainRoot:root});console.log(fs.readFileSync(stationEventPath(root),'utf8'))"`
- **Action:** Run from the checkout root. `mainRoot` is injected so the scratch directory stands in for the main checkout; the real CLIs resolve it with `mainCheckoutRoot`. The caller supplies the stable `discriminator` (a claim's `claimedAt`, a driver step's `step@ts`); the emitter never reads the clock for it.
- **Should feel:** Boring and exact. The file is the contract, so one line per call with no decoration.
- **Should understand:** stdout prints two JSON lines with the same key set — `v`, `eventKey`, `repoName`, `recordNumber`, `kind`, `station`, `at`, `outcome`, `lane`, `sessionId`, `runId`, `payload` — the same `eventKey` on both, `at` ending in `Z`, and `outcome` `null` because only an `exited` event carries one. The duplicate is the consumer's to drop by `eventKey`: the emitter appends, it never reads the file back.
- **Red flags:** Two different `eventKey`s for the same transition (a clock or counter leaked into the key); an extra or missing field; a non-UTC `at`; a read of the existing file before the append.

### 2. Make the file unwritable and watch the event drop without a failure — terminal, same module
- **URL:** `node -e "const fs=require('fs'),os=require('os'),path=require('path');const {appendStationEvent,stationEventPath}=require('./plugin/bin/lib/station-events/emit');const root=fs.mkdtempSync(path.join(os.tmpdir(),'se-ro-'));fs.mkdirSync(path.join(root,'.claude-tweaks'));fs.chmodSync(path.join(root,'.claude-tweaks'),0o555);appendStationEvent({repoName:'acme/widgets',recordNumber:999,kind:'session_bound',station:'build',lane:'unknown',sessionId:'s',runId:'run-a',payload:{},discriminator:'claim:t0'},{mainRoot:root});console.log('survived; file exists:',fs.existsSync(stationEventPath(root)))"`
- **Action:** Run from the checkout root. The `.claude-tweaks` directory already exists but is read-only, the realistic shape of a locked-down main checkout.
- **Should feel:** Quiet. A pipeline run must never learn that its bookkeeping file was unwritable.
- **Should understand:** stderr carries exactly one line, `claude-tweaks: station event dropped: append failed: EACCES: …station-events.jsonl`, stdout prints `survived; file exists: false`, and the process exits `0`. The same holds inside `claim-targets.js`, `release-claim.js`, `resolve-blockers.js` and a driver run: stdout and exit code are byte-identical to a run with no emitter (pinned by `tests/bin-lib/station-events/failure-isolation.test.js`).
- **Red flags:** An exception or non-zero exit; more than one stderr line per dropped event; a half-written `station-events.jsonl`; the emitter turning a failed append into a changed claim or release result.

### 3. Claim a record from a linked worktree and find the event in the main checkout — terminal inside a worktree
- **URL:** `node "$PLUGIN_ROOT/bin/claim-targets.js" --run-id journey-5902 --targets 999 --steps build,test --run "$PIPELINE_RUN_DIR" --lane driver`, then `tail -n 4 "$(git rev-parse --path-format=absolute --git-common-dir)/../.claude-tweaks/station-events.jsonl"`
- **Action:** Run a real claim from a session whose cwd is a linked worktree (`.claude/worktrees/…`). `CLAUDE_CODE_SESSION_ID` is read from the environment. `--lane` is passed only by the driver; any other caller leaves the lane `unknown`.
- **Should feel:** The worktree stays clean. Nothing about the run shows up in `git status`.
- **Should understand:** The last four lines of the main checkout's file are, in order, a `session_bound` at station `build` for record 999 whose `sessionId` equals `CLAUDE_CODE_SESSION_ID`, then the claim's `bot:in-progress` pair (`exited` at `release` with outcome `passed`, `entered` at `build`), then the claim's plan: a `planned` at `build` whose payload is `{"process":"build-a-record","processVersion":1,"list":"driver","stations":[…10 stations, no "polish"…],"reasonCode":"other","reasonText":"lane driver"}` — all four with `lane` `driver` and `runId` `journey-5902`. Without `--lane`, and with no profile or lane in the run's `manifest.json`, the plan is `list` `standard` (all 11 stations) with `reasonCode` `default-list`; the `replanned` event corrects it later. Claiming 999 again in the same run writes nothing, and a `--resume-pr` re-claim writes no `planned`; the worktree has no `.claude-tweaks/station-events.jsonl` of its own. Claiming records 1, 2 and 3 in one session writes three `session_bound` lines with the same `sessionId`. On a driver run the worker's own `session_bound` supersedes the claim's for that record (`docs/reference/station-events.md`).
- **Red flags:** The file appearing under the worktree (`mainCheckoutRoot` bypassed); a `sessionId` of `null` when the variable is set; a `session_bound` written before the claim landed, or for a record whose claim was refused; a second `planned` for the same record and run; a `planned` whose `lane` differs from the claim's other lines.

### 4. Append in a project that never re-ran `/init` and find the checkout still clean — terminal, same module
- **URL:** `node -e "const fs=require('fs'),os=require('os'),path=require('path'),cp=require('child_process');const {appendStationEvent,EXCLUDE_ENTRIES}=require('./plugin/bin/lib/station-events/emit');const root=fs.mkdtempSync(path.join(os.tmpdir(),'se-git-'));cp.execFileSync('git',['init','-q',root]);appendStationEvent({repoName:'acme/widgets',recordNumber:999,kind:'session_bound',station:'build',lane:'unknown',sessionId:'s',runId:'run-a',payload:{},discriminator:'claim:t0'},{mainRoot:root});console.log('status:',JSON.stringify(cp.execFileSync('git',['-C',root,'status','--porcelain'],{encoding:'utf8'})));console.log(fs.readFileSync(path.join(root,'.git','info','exclude'),'utf8').split('\n').filter(l=>EXCLUDE_ENTRIES.includes(l)).join('\n'))"`
- **Action:** Run from the checkout root. The scratch repo has no `.gitignore` at all, the shape of a consumer project that installed the plugin after #5902 but never re-ran `/claude-tweaks:init`.
- **Should feel:** Invisible. The plugin's bookkeeping never shows up as the project's own dirt.
- **Should understand:** stdout prints `status: ""` and then the two lines `/.claude-tweaks/station-events.jsonl` and `/.claude-tweaks/station-events.jsonl.lock`: each append first lists both paths in the main checkout's `.git/info/exclude`, which is local, never committed, and shared by every linked worktree. So reconcile's mirror still reads the checkout clean and archiving does not stall at `local-behind-merge` (`archive-a-merged-run-only-after-main-catches-up-4387.md`). A second append adds nothing to the exclude file. A log already tracked in the index is outside this fix: untrack it with `git rm --cached` (`docs/reference/station-events.md`).
- **Red flags:** `?? .claude-tweaks/` in the status; the entries repeated on every append; a user's own last exclude pattern glued onto the first new entry; any change to the project's `.gitignore`; a stderr line from the exclude step.

### 5. Emit new-vocabulary outcomes and see the unknown reason kept, the edgeless send-back dropped — terminal, same module
- **URL:** `node -e "const fs=require('fs'),os=require('os'),path=require('path');const {appendStationEvent,stationEventPath}=require('./plugin/bin/lib/station-events/emit');const {REASON,ACTOR}=require('./plugin/bin/lib/station-events/stations');const root=fs.mkdtempSync(path.join(os.tmpdir(),'se-v-'));const base={repoName:'acme/widgets',recordNumber:999,station:'test',lane:'unknown',sessionId:'s',runId:'run-a',discriminator:'d1'};console.log(JSON.stringify(appendStationEvent({...base,kind:'exited',outcome:'failed',payload:{actor:ACTOR.AGENT,reasonCode:'made-up'}},{mainRoot:root})));console.log(JSON.stringify(appendStationEvent({...base,kind:'exited',outcome:'sent-back',discriminator:'d2',payload:{actor:ACTOR.AGENT,reasonCode:REASON.TEST_FAILED}},{mainRoot:root})));console.log(JSON.stringify(appendStationEvent({...base,kind:'exited',outcome:'passed',discriminator:'d3',payload:{step:'worker'}},{mainRoot:root})));console.log(fs.readFileSync(stationEventPath(root),'utf8'))"`
- **Action:** Run from the checkout root. The three events are a new-contract `failed` carrying an actor and a reason code nothing knows, a `sent-back` with no `next` station, and an actor-less `passed` as today's callers write it. Callers name actors and reason codes through `ACTOR.*` and `REASON.*` from `stations.js`, never as strings.
- **Should feel:** Forgiving about reasons, strict about edges. An unknown reason never costs the outcome; a send-back that names no station cannot draw an edge, so it goes.
- **Should understand:** stdout prints `{"written":true}`, then `{"written":false,"reason":"payload.next is not a station: undefined"}` (with the same reason on stderr as `claude-tweaks: station event dropped: …`), then `{"written":true}`, then two lines. The `failed` line's payload reads `{"actor":"agent","reasonCode":"unspecified","reasonText":"made-up"}`: the unknown code is normalized and the original kept. The `passed` line's payload is still exactly `{"step":"worker"}`. Actor-less `passed`/`failed` lines and retired outcomes (`returned`, `skipped`, `abandoned`) stay accepted unchanged until record 8/8 (#6152) retires them.
- **Red flags:** The `failed` line dropped, or written with `reasonCode: "made-up"`; a `sent-back` written with no `next`; a `reasonCode` or `actor` key added to the actor-less `passed`; a throw or non-zero exit.

### 6. Map driver step lines and read the actor and reason on each exit — terminal, `plugin/bin/lib/station-events/driver-mirror.js` directly
- **URL:** `node -e "const {stationEventsFor}=require('./plugin/bin/lib/station-events/driver-mirror');const {buildLine}=require('./plugin/bin/lib/station-events/emit');const id={repoName:'acme/widgets',runId:'run-a'};const L=(o)=>({ts:'2026-11-24T08:00:10.000Z',run:'run-a',record:999,step:'test',status:'ok',ms:4000,...o});for(const l of [L({}),L({status:'stop',detail:'red tests',verifyExit:1}),L({status:'fail',detail:'verify exited 2',verifyExit:2}),L({step:'pr',status:'stop',detail:'no changed files'})]){const e=stationEventsFor(l,id).find(x=>x.kind==='exited');console.log(JSON.stringify([e.station,e.outcome,e.payload]),!!buildLine(e))}"`
- **Action:** Run from the checkout root. The four lines are what a driver run writes to `driver-events.jsonl`: a green test step, a red-tests stop (the test step stamps `verifyExit`, verify.js's exit code), a verdict-less test run (verify.js exited 2), and a `pr` step that stopped. The mirror is what the driver's sink runs on each line before the emitter appends it.
- **Should feel:** Every exit answers "who decided, and why", even when nothing knows why.
- **Should understand:** stdout prints four lines, each ending `true` (the emitter accepts it): `["test","passed",{"step":"test","actor":"agent"}]`; `["test","failed",{"step":"test","actor":"agent","reasonCode":"test-failed"}]`; `["test","failed",{"step":"test","actor":"agent","reasonCode":"infrastructure"}]`; `["wrap-up","stopped",{"step":"pr","actor":"script","reasonCode":"unspecified","reasonText":"no changed files"}]`. Red tests are keyed on `verifyExit: 1`, never on the detail text, so a relaunch note added to the detail changes nothing. `worker`, `test` and `review` exits carry actor `agent`; `pr`, `ci` and `merge` carry `script`. A real `ci` line is always `passed`: a red CI state is data for the reviewer, not an exit (`docs/reference/station-events.md`).
- **Red flags:** An exit with no `actor`; a `reasonCode` on a `passed` exit; a red-tests stop written `stopped`; a test `fail` with no `verifyExit` written `infrastructure`; a stop with a detail but no `reasonText`.

### 7. Release a claim and grant `auto:build`, then read who did it — terminal, the main checkout's file
- **URL:** `tail -n 4 "$(git rev-parse --path-format=absolute --git-common-dir)/../.claude-tweaks/station-events.jsonl"` after a real `release-claim.js --reason merged` and a `/claude-tweaks:backlog refine` batch that adds `auto:build` (both through `apply-refine-labels.js`)
- **Action:** Read the release line and the authorize lines the two label-protocol exits wrote. Nothing in the skill prose logs these: the CLIs that make the transition write them.
- **Should feel:** Attributable. Every new-contract exit says who moved the record, and a grant says it was a person's decision.
- **Should understand:** A release whose outcome is `passed` or `failed` carries `payload.actor` `"script"` (a `failed` one also gets `reasonCode` `"unspecified"`); a release whose outcome is the retired `abandoned` or `returned` is unchanged, with no `actor`, until record 8/8 (#6152). Adding `auto:build` writes `exited` at `authorize` with `payload.actor` `"person"`, then a `decided` line at `authorize` whose payload is `{"decision":"authorize","actor":"person","via":"skill","outcomeRef":…}` (`outcomeRef` equals the exit line's `eventKey`, same discriminator; a re-authorize that also removes `bot:blocked` writes the same `decision`), then `entered` at `release`. When the exit line was not written, no `decided` line follows it. The accept verdict exits write nothing yet (`docs/reference/station-events.md`'s Coverage gaps; #6186).
- **Red flags:** An `actor` on an `abandoned` or `returned` release; a `decided` line whose `outcomeRef` matches no `exited` line in the file; a `decided` line with no preceding authorize exit; a changed stdout or exit code from either CLI.

### 8. Fix a claimed record's profile at the Manifesto and read the `replanned` line — terminal, a scratch main checkout
- **URL:** a scratch directory holding a `.git` directory and a `.claude-tweaks/station-events.jsonl` with one `planned` line (`runId` `run-a`, record 999, the standard list), then `replanRun({ runDir: '{scratch}/.claude-tweaks/pipelines/run-a', manifest: { lane: 'standard', ceremonyProfile: 'fast-lane' }, ref: 'ceremony-profile', deps: { stationEvent: (e) => appendStationEvent(e, { mainRoot: '{scratch}' }) } })` from `plugin/bin/lib/station-events/replan.js`, run twice. This is the call an `auto`-mode `/claude-tweaks:flow` Manifesto (`writeManifesto`) makes once after it writes `config.yml`.
- **Action:** Read the file's last line after each call.
- **Should feel:** Honest about a changed plan, and quiet when nothing changed: a plan is never rewritten silently, and an unchanged plan adds nothing.
- **Should understand:** The first call returns `1` and appends `["replanned","build",…,{"stations":["intake","shape","authorize","release","build","test","review","wrap-up","merge","accept"],"reasonCode":"ceremony-downgrade","cause":{"kind":"config","ref":"ceremony-profile"}}]` — the full list without `polish`, filed under `build`. The second returns `0` and adds nothing, because the latest plan line is now the replanned list. A change that only adds stations carries `reasonCode` `other` with a `reasonText` such as `ceremony profile standard`. A ceremony change made at wrap-up, by a `confirm`/`hybrid` or hand-written Manifesto, or through the express gate or the driver's adoption goes through a path that passes no sink and writes nothing (`docs/reference/station-events.md`'s Coverage gaps).
- **Red flags:** A second `replanned` for the same change; a `replanned` written by `set-config.js` at wrap-up; a `before` taken from the original claim line after a replan; a throw or changed `config.yml` when the log is unreadable.

### 9. See a hold and its release, and a blocker snapshot written only when it changed — terminal, `driver-mirror.js` and `blockers.js` directly
- **URL:** `node -e "const {stationEventsFor}=require('./plugin/bin/lib/station-events/driver-mirror');const id={repoName:'acme/widgets',runId:'run-a'};const L=(o)=>({ts:'2026-11-24T08:00:10.000Z',run:'run-a',record:999,status:'ok',ms:10,...o});for(const l of [L({step:'settle-label',stopStep:'test'}),L({step:'settle-label',stopStep:'claim'}),L({step:'settle-label',status:'fail',stopStep:'test'}),L({step:'merge-park',status:'stop',parked:true,detail:'ci-red: bot:parked applied to record 999'}),L({step:'merge-park',status:'stop',parked:false,detail:'x'})])console.log(JSON.stringify(stationEventsFor(l,id).map(e=>[e.kind,e.station,e.payload])))"`, then three `makeBlockerSnapshotSink` calls for record 999 against a scratch main checkout (`lastPayload` reading that checkout's file through `lastBlockersPayload`): the same blocker set twice with different `fetchedAt`, then a changed set.
- **Action:** Run from the checkout root. The five lines are what a driver run writes when it settles a stop (`settle-label` adds `bot:blocked`, and carries the stopped step as `stopStep`) and when the merge step parks a record (`merge-park` carries `parked`: whether `bot:parked` read back). A `/claude-tweaks:backlog refine` batch that adds or removes a hold label writes its own `held`/`released` through `apply-refine-labels.js`.
- **Should feel:** A held record says why it is waiting, and the snapshot log stops repeating itself.
- **Should understand:** stdout prints `[["held","test",{"why":"blocked"}]]` (held at the stopped step's station), `[["held","release",{"why":"blocked"}]]` (a claim-step stop: the record never entered `build`), `[]` (the label add failed, so nothing is held), `[["exited","merge",{"substep":"merge-park"}],["held","merge",{"why":"parked"}]]`, and `[["exited","merge",{"substep":"merge-park"}]]` (the label never read back). No hold line carries `actor`, and none of these carries `ref`: `ref` names only a blocking record (`#N` or `owner/repo#N`). A refine hold edit is always filed at `authorize`. The snapshot calls leave two `blockers` lines, not three: the second call matched the last line once `fetchedAt` is ignored. `resolve-blockers.js` and `preflight-records.js` both dedupe this way, reading only the file's last 64 KiB (`docs/reference/station-events.md`).
- **Red flags:** A `held` written from a failed `settle-label` or an unapplied park; a step name in `ref`; `actor` on a hold line; a hold derived by parsing `detail`; a third, unchanged `blockers` line; a throw or changed stdout from the driver or refine when the emitter fails.
