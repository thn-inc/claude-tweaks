# Select the Dispatch Queue with the queue-pull CLI

**Persona:** the maintainer of `/claude-tweaks:dispatch`'s queue, which since #5230 a program produces, not a model reading a 52 KB script. Also the pipeline driver (`drive.js`) once it calls the CLI, and the agent in a `gh`-absent cloud sandbox that has to feed it MCP-fetched files.
**Goal:** get the same `dispatch-groups.json`, `dispatch-exclusions.json` and next pick that the embedded `queue-pull-script.md` and `next-ranking.md` scripts produce, from one command with a fixed exit-code contract.
**Entry point:** `node plugin/bin/queue-pull.js --transport gh` (or `--transport files` with the agent's input files), then `node plugin/bin/queue-pull.js --rank`, under the session whose `CLAUDE_CODE_SESSION_ID` the session-scoped files belong to.
**Success state:** the session-scoped files match what the scripts would have written for the same inputs, including every exclusion entry in order, the fast-lane bundles, the near-duplicate pairs, the cross-PR overlap file, the staged Close proposals and the `AUTO`/`Warning:` lines on the script's own streams. `dispatch-next-pick.json` holds the group the ranking script would pick, or `null`. The CLI exits 0, and its stdout carries only what the script prints.

## Steps

### 1. Pull the queue through gh
- **URL:** `plugin/bin/queue-pull.js --transport gh`; `plugin/bin/lib/dispatch/queue-pull.js` (`queuePull`, `PASSES`)
- **Action:** The maintainer runs the CLI with `--transport gh`. It runs the passes in `PASSES` order, the order the script runs them: truncate (keeping `firing` entries), fetch and the queue-order cache check, `blocked`, grouping and `oversized`, the cache write-back, `not-spec-shaped`, `open-pr`, `target-missing`, `shipped`, `unlanded-blocker`/`malformed-blocker`, `neighbour-in-flight`, then the cross-PR overlap and near-duplicate passes. Every exclusion goes through `appendExclusion`.
- **Should feel:** Like running the script, minus the script. Same files, same lines, no extra stdout to read.
- **Should understand:** Parity with the scripts is the contract, defects included. A behaviour that looks wrong is reproduced on purpose and filed as its own record, never fixed in the module alone: its fix lands in the module and the script together, as #5409's removal of a later step's stale session file did (step 4). The paginated `gh` list calls get the batched timeout (`GH_BATCH_TIMEOUT_MS`), so a slow but healthy queue fetch completes as it would under the unbounded script. The target-missing pass writes each Close proposal to `target-missing-proposal-{n}.md` beside `dispatch-exclusions.json` and stages it as exactly `staged/dispatch-target-missing-{n}.md`; a proposal write that fails stages nothing for that record, and the pass moves to the next one (#5316). The proposal's `gh issue comment` line passes the comment as one single-quoted `--body` word, so a named path holding `"`, `$(…)`, a backtick, `'` or `\` reaches the comment verbatim when the Review Console runs it, and runs nothing (#5317).
- **Red flags:** An exclusion file written with anything but `appendExclusion` (earlier passes' entries and the Loop's `firing` entries vanish). A staged target-missing item whose name ends in anything but `.md` (the random-suffix name came back). A staged `gh issue comment` whose `--body` is double-quoted, or whose posted text lost part of the named path (shell syntax in the path was expanded). A queue fetch that stops the pull with exit 4 on a large, healthy queue, which means the 5 s single-call bound came back.

### 2. Pick the next group
- **URL:** `plugin/bin/queue-pull.js --rank [--priority high|medium|low]`; `plugin/bin/lib/dispatch/queue-pull.js` (`rankNext`, `rankFromFiles`)
- **Action:** The maintainer runs `--rank`. It drops every group with a member under an `oversized`, `firing` or `neighbour-in-flight` entry, takes each group's best member (priority band, then oldest `createdAt`) as its representative, applies the optional `--priority` filter, and writes the top group or `null` to `dispatch-next-pick.json`.
- **Should feel:** Silent and exact. Stdout stays empty, because the pick is a whole group of full records that must not reach an agent's context. The pick matches `next-ranking.md` expression for expression.
- **Should understand:** A missing or unreadable `dispatch-exclusions.json` reads as no exclusions, as the script reads it. An unknown `--priority` value exits 1 instead of quietly picking nothing. Omit the flag when no filter is wanted, because an empty value exits 1 too.
- **Red flags:** Anything on stdout from `--rank`. A pick that differs from the script's for snake_case `created_at` timestamps, which means the alias step was skipped.

### 3. Pull from a gh-absent sandbox
- **URL:** `plugin/bin/queue-pull.js --transport files --queue-raw … --dep-freshness … --open-numbers … --verified-open-deps … --in-flight-raw … --in-flight-claims … --foreign-states …`; `plugin/skills/dispatch/mcp-transport.md`
- **Action:** The **agent** fetches the records through MCP tools and writes each input file (each flag but `--foreign-states` defaults to its session-scoped path; `--foreign-states` has no default, so the agent passes it whenever it wrote a states file). The claims file covers the claim of every record in the in-flight pool file. It then runs the CLI with `--transport files`. The module copies the queue file into the session file before aliasing its timestamps, so the agent's own file is left as written.
- **Should feel:** Like the gh path, with the agent doing the fetching and Node doing the computing.
- **Should understand:** The documented MCP gaps are behaviour. `dispatch-crosspr-overlap.json` is `[]`, `dispatch-linked-prs.json` stays `{}`, and `open-pr`, `shipped` and `unlanded-blocker` cannot fire on this transport. A missing or malformed in-flight pool or claims file stops the pull (exit 4). A queue or dependency-freshness file that parses but is not a JSON array (a wrapper object, a string) is a failed read, never an empty list (#5307): one `Warning: {file} is not a JSON array — treated as a failed read` line, then that file's unparseable path — the queue file stops the pull, the dependency-freshness file stops a warm-cache check or, on a cold cache, leaves no cache written. A bad `--foreign-states` file (the states file the MCP path passes on the call) excludes each foreign-blocked record as `owner/name#N (state unreadable)`, with one fail-closed `ignored (...)` `Warning:` line: the follow-up lookup's own `gh`-absent Warning is not printed a second time (#5304). A lookup that fails for any other reason still prints its own Warning. Under `work-links: native` with `gh` absent, the native-blockers query keeps its documented fallback: one `Warning: … falling back to no native filtering this run` line, and the pull still dispatches (#5309). A missing or malformed `--verified-open-deps` file fails closed (#5311): every unresolved dependency counts as open, so each record it blocks is excluded as `blocked`, one `Warning: verified-open-deps file missing or malformed — every unresolved dependency treated as open (fail closed) this run` line prints when there is at least one such dependency, and no queue-order cache verdict is written. The agent writes a dependency whose `issue_read` fails into that file as open. A well-formed file that leaves out an unresolved dependency fails closed too (#5408): the dependency counts as open unless the dependency-freshness file shows its `state` closed (any case, one entry per number, or every entry for it closed), each record it blocks is excluded as `blocked`, one `Warning: verified-open-deps file omits #{N}, which the dependency-freshness file does not show closed — treated as open (fail closed) this run` line prints per such dependency, and no queue-order cache verdict is written. A dependency the agent's `issue_read` cannot read is written into the dependency-freshness file as `{"number": N, "state": "unreadable"}` (#5865): it never counts closed, each record it blocks is excluded as `blocked`, one `Warning: dependency-freshness file marks #{N}[, #{M}…] unreadable — treated as open (fail closed), queue-order cache not written this run` line names every such number (in place of the omitted-dependency line for it), and no queue-order cache is written; only a number from 1 to 2147483647 that an eligible record depends on counts. The retained script carries neither rule, because its bash fence never sees the agent's raw dependency-freshness text at the blocked pass, so until #5231 deletes the script a file that omits an open dependency, or marks one unreadable, blocks the record in the module and not in the script.
- **Red flags:** A blocked record that dispatches because the verified-open-deps file left its open blocker out, or one that stays blocked because that file left out a dependency the dependency-freshness file shows closed. `--transport gh` silently falling back to files. With `gh` absent it must exit 2 and name the files transport. A claims file covering only the queue's targets, which leaves in-flight neighbours read as not in flight. A wrapper-object queue file that ends in "no candidates" with exit 0 and no `Warning:` line. A blocked record that dispatches after its dependency's state could not be read, or a later pull that keeps holding it from the cache with no `Warning:` line.

### 4. Read a stop and recover
- **URL:** `plugin/bin/queue-pull.js` (exit codes in the header and USAGE)
- **Action:** A pull that cannot continue exits 4 and prints its stop line on stderr. That happens on a corrupt `dispatch-exclusions.json` (left as it was, and no later pass runs), an unreadable `dispatch-groups.json`, a failed queue or open-numbers fetch, or any internal throw, which prints as `queue-pull: <message>`. A fetch the script fails open on prints the script's `Warning:`/`AUTO` line for it (one per failed fetch, except where a fetch below names its own count) and the pull exits 0. A failed cache write-back never fails the pull. A failed `gh issue list --search` dependency-freshness search prints one `Warning: dependency-freshness search failed — queue-order cache not used this run` line at the cache check (the pull recomputes rather than cache-hitting) and one `Warning: dependency-freshness search failed — queue-order cache not written this run` line at the write-back (no queue-order cache is written that pull); each line is per failed search, so a pull where both fail prints both (#5310). Unreadable claims are reported once per pull (#5304): one `AUTO` line names every claim the shipped pass and the neighbour-in-flight pass could not read, with both consequences (release time unknown, no downgrade; treated as not in flight), and a pull that stops partway still prints that line once for the claims read so far. When no integration branch resolves (no `integration-branch` key and `git remote show origin` fails), the target-missing pass prints one `Warning: target-missing pass skipped — …` line and excludes nothing, and the unlanded-blocker pass prints its own skip Warning (#5305). A branch that resolves but does not name a resolvable `origin/` ref (a remote with no HEAD set, where `git remote show origin` prints `HEAD branch: (unknown)`, or a policy `integration-branch` that origin lacks) skips only the target-missing pass the same way, with the same one Warning and no exclusion; the resolved branch stays in place for the unlanded-blocker pass, which checks landing through the GitHub API (#5863). A failed linked-PR query prints one `Warning: linked-PR query failed — falling back to no open-PR or shipped-candidate exclusion this run: …` line, naming both exclusions it turns off, since the shipped pass reads its mentions from that same query (#5306). Under `work-links: native`, a failed native-blockers query fails closed (#5309): on `--transport gh` any failure, and on `--transport files` a `resolve-blockers.js` exit 3 (the spawned CLI's code, not the pull's; for example a GraphQL-blocked sandbox with `gh` present), excludes every eligible record as `blocked` with `native blockers (state unreadable)`, prints one `Warning: native dependency query failed — …` line naming the fail-closed consequence, and writes no queue-order cache verdict. The unlanded-blocker pass then has nothing to read and prints no second Warning. A failed per-dependency `gh issue view {dep}` (the live check for a dependency outside the 200-record open pull) fails closed too (#5311): the dependency counts as open, each record it blocks is excluded as `blocked`, one `Warning: gh issue view {dep} failed — dependency #{dep} treated as open (fail closed) this run` line prints per failed view, and no queue-order cache verdict is written. A `Blocked by #0` is never live-checked; the malformed-blocker pass keeps it. A failed open-PR list for the cross-PR overlap report prints one `Warning: open-PR pull failed — cross-PR overlap not checked this run` line, so an empty `dispatch-crosspr-overlap.json` on that pull does not read as "no overlap"; the report stays informational and the pull exits 0 (#5312). A failed shipped-pass `gh pr view {pr}` (the files probe, at most 5 per pull) still fails open: the record stays a weak shipped candidate and is dispatched, its PR's line in `dispatch-shipped-pr-files.jsonl` reads `files: null` (whatever the failed call printed), and one `Warning: gh pr view {pr} failed — #{record} kept as a weak shipped candidate (files unprobed) this run` line prints per affected record, right after its weak `AUTO` line — two records sharing that PR print two lines. A weak mention that predates the claim release prints none, since files cannot change its tier, and neither does one that predates the record's latest `ready`/`auto:build` labeling (#5722, from `lastShapedAt` in `dispatch-linked-prs.json`; its kept line reads `kept: merged PR #{pr} predates ready/auto:build labeling at {time} — remaining work assumed`), and a PR past the 5-probe cap was never probed (#5313). A queue record whose `labels` is not an array is excluded as `malformed-blocker` with one `Warning: #N excluded — its labels are not an array` line, the rest of the queue is judged, and that pull writes no queue-order cache (#5315). Five session files written only after their step's fallible work (`dispatch-named-targets.json`, `dispatch-shipped-probe-prs.json`, `dispatch-shipped-releases.json`, `dispatch-crosspr-overlap.json`, `dispatch-near-dup-pairs.json`) are removed at the start of every pull, so a step that throws on a re-pull in the same session leaves its file absent, never the earlier pull's copy; a removal that fails prints `queue-pull: rm-end-written: …` and the pull goes on (#5409).
- **Should feel:** Diagnosable from the exit code and one stderr line, with no guessing whether a partial run is safe to rank, and no fetch failure reported twice or not at all.
- **Should understand:** Exit 3 is reserved and never produced: every remote failure either fails open or stops with 4, exactly as the script does. Exit 1 is a malformed invocation and prints the usage.
- **Red flags:** A report or pass reading an earlier pull's copy of one of the five pull-start-removed files after a step of this pull threw. A partial `dispatch-groups.json` ranked after an exit 4. An exit 4 on a fetch the script fails open on. Two claim-read `AUTO` lines in one pull, or none on a pull whose claim reads failed. Named targets excluded as `absent at origin/` — a comparison against an empty or unresolvable branch name (`(unknown)`, #5863).

### 5. Keep the two implementations equal
- **URL:** `tests/bin-lib/dispatch/queue-pull-parity-ac1.test.js`, `queue-pull-parity-ac4.test.js`, `queue-pull-parity-ac5.test.js`, `queue-pull-parity-ac7.test.js` and `queue-pull-parity-d1.test.js` (the parity describes over `queue-pull-helpers.js`; the AC4 fault rows split by transport between ac4 and ac7, and D1 on its own); `tests/bin-lib/dispatch/queue-pull-oracle-checks.test.js` (the whole-fence oracle runs and the oracle-vs-module cross-checks); `tests/bin-lib/dispatch/queue-pull.test.js` (the module's in-process fixtures and the oracle pins); `tests/bin-lib/dispatch/queue-pull-oracle.js`; the oracle's two bash fences, `plugin/skills/dispatch/queue-pull-script.md` and `plugin/skills/dispatch/next-ranking.md`
- **Action:** A **maintainer editing either script** runs the parity suite. It runs the embedded script under PATH shims for `gh` and `git` and the module over the same canned-response table, on both transports and both cache paths, plus every fetch-failure and files-input fault. It then compares the exit status, every session file, the staged proposals, `decisions.md`, the queue-order cache blob, and the reported lines on both streams: the stop, `AUTO`, `Warning:`, cache, `express-lane:` and `resolve-policy:` lines. Other lines on either stream are not compared as text. A change to a pass lands with the matching module change in the same pull request until the removal unit lands.
- **Should feel:** Like a tripwire. A script edit without the module edit turns the suite red, naming the pair and the file that differ.
- **Should understand:** On win32, or without bash 4 or later, the parity describes skip with `no bash oracle`, and the module's in-process fixtures still run. A `queue-pull: <step>:` diagnostic from the module also fails parity when the script's stderr for the same run shows no error, so a module step that throws and carries on cannot pass as equal. The deliberate exceptions to "equal" are #5408's omitted-dependency rule and #5865's unreadable dependency-freshness entry (step 3), which exist in the module only: the parity fault rows that exercise a dependency-freshness fault run on a scenario whose verified-open-deps file lists every open dependency, so the module's extra fail-closed branch never fires in them.
- **Red flags:** A parity failure fixed by loosening `normalize` or the comparison instead of changing the module. The only permitted exception is the four Node-crash-tail lines, which are compared by their fixed prefix.
