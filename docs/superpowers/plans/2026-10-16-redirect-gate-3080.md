# Gate bare shell redirection (> / >>) under worktree-always (#3080) Implementation Plan

**Goal:** Bare shell redirection (`echo x > file`, `cmd >> file`) is resolved to a write
target by `fileWriteTargets` and reaches the full hook handler via the Bash prefilter, so
the worktree-always gate denies it from a main checkout the same way it already denies
`cp`/`tee`.

**Spec:** `.claude-tweaks/pipelines/2026-10-16T062649-record-3080/work/3080-spec.md`
(materialized from GitHub issue #3080)

---

### Task 1: Redirection-target parser in git-command.js

**Files:**
- Modify: `plugin/bin/lib/hooks/git-command.js`

- [x] Add a redirection-operator matcher and `redirectWriteTargets(t, effCwd)` that scans a
      segment's token array for `>`, `>>`, `>|`, `&>`, `&>>`, and fd-prefixed `N>`/`N>>`,
      both standalone (`cmd > file`) and glued (`cmd >file`, `2>>log`). Resolves each target
      through the existing `resolveWriteTarget` (already handles `$VAR`/backtick/unresolvable
      → no target, and `DEVNULL_LIKE`). Excludes fd duplications (`>&N`, `N>&M`) and process
      substitution (`>(...)`) from ever reaching `resolveWriteTarget`.
- [x] Call it from `fileWriteTargets`'s `forEachCommandSegment` handler unconditionally, before
      the `WRITE_SHAPES.includes(t[0])` early return — so `echo`, `printf`, `cat`, and a bare
      `> f` are all reached, not just the existing write-shape command words.
- [x] Update the header "Still NOT covered" comment on this file to drop the redirection line.
