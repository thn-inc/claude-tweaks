# wait-for.js: stop marker, blocking-wait CLI and docs (#5602, Deliverables 3-6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an agent block on a child agent's final stop, a PR's checks, a workflow run or a process, with one bounded foreground command (`plugin/bin/wait-for.js`), fed by a stop marker the `SubagentStop` hook appends.

**Architecture:** `plugin/bin/lib/wait-for/marker.js` owns both per-session temp files (the stop marker the hook appends, and the waits file holding windows and delivered stops): names, line shapes, an append-only writer and a no-follow reader. The hook appends one stop line after it has its answer, on every path, fail-safe. `plugin/bin/lib/wait-for/index.js` holds `run(argv, deps)`: argument parsing, the per-session window, the poll/sleep loop and the three targets; `plugin/bin/wait-for.js` is the thin entry with `realDeps`.

**Tech Stack:** Node 18+ CommonJS (CI Node 20), `node:test`, no dependencies.

**Spec:** `.claude-tweaks/pipelines/2026-11-16T020245-record-5602/work/5602-spec.md`

Scope keywords: wait-for.js, wait-for/marker, ct-agent-stops

## Global Constraints

- Bounds (spec Deliverable 5 + Decision of 2026-11-16, verbatim): "`--max-seconds` (default 100, at most 150) bounds one call. `--window-seconds` (default 1,200, at most 3,600) bounds a wait that spans calls, and the command keeps that window itself, per session." "the caller passes no `timeout`."
- Window (verbatim): "The first call for a target opens a window; a later call for the same target joins it. An `agents` call joins an open window when every id it lists belongs to that window; a `ci` or `pid` call joins the window of the same pull request, run or pid. A window closes when a call returns at its deadline, or when an `agents` call returns with no listed id left pending. The call after a deadline opens the next window. The nearer bound ends the call; when both pass at the same poll, `bound` is `deadline`."
- Loop (verbatim): "poll, and if nothing changed sleep in-process for the interval or the time left to the nearer bound, whichever is shorter; poll once more at the bound. The interval is one second for `agents` and `pid` and 30 seconds for `ci`."
- Output (verbatim): "one JSON line with `target`, `state`, `changed`, `elapsedSeconds`, `deadlineEpoch`, `window` (1 for a first window, one more for each window of the same target that ended at its deadline) and, at a bound, `bound` (`call` or `deadline`). `agents` adds `reported` and `pending` (lists of ids) and `stops` (the number of stop lines in the session's file, 0 when it is absent). `ci --pr` puts the classifier's state in `state`; `ci --run` puts the run's status in `state` and adds `conclusion`."

### Task 1: `marker.js` — file names, line shapes, append writer, no-follow reader

**Role:** integration
**Review risk:** high

**Files:**
- Create: `plugin/bin/lib/wait-for/marker.js`
- Test: `tests/bin-lib/wait-for/marker.test.js`

**Interfaces:**
- Consumes: `lstatType(p)` from `plugin/bin/lib/path-guard` (`{ type: 'missing'|'symlink'|'file'|'dir'|…|'unreadable', code }`).
- Produces (all exported):
  - `SESSION_ID_RE = /^[A-Za-z0-9_-]+$/`
  - `stopsPath(sessionId, { tmpDir = os.tmpdir() } = {}) -> string|null` — `path.join(tmpDir, 'ct-agent-stops-' + id + '.jsonl')`, `null` unless `sessionId` is a string matching `SESSION_ID_RE`.
  - `waitsPath(sessionId, opts) -> string|null` — same rule, `ct-agent-waits-{id}.jsonl`.
  - `formatStop({ agentId, at, blocked, pending }) -> string` — `JSON.stringify` in exactly that key order plus `'\n'`.
  - `appendStop(sessionId, stop, opts) -> boolean` and `appendWait(sessionId, record, opts) -> boolean` — `false` when the path is `null`; otherwise one `fs.writeSync` of one line to an fd opened `O_WRONLY | O_APPEND | O_CREAT | O_NOFOLLOW` (the last only where defined), mode `0o600`, then closed; `true` on success; an fs error propagates. `opts` also takes `{ constants = fs.constants }`.
  - `readStops(sessionId, opts) -> { stops: Array<{ index, agentId, at, blocked, pending }>, count }` — `index` is the 0-based line position in the file (bad lines keep their position), `count === stops.length`.
  - `readWaits(sessionId, opts) -> Array<object>` — each parsed record with an `index`.
  - `isFinalStop(stop) -> boolean` — `stop.blocked === false && stop.pending === 0`.
  - `class MarkerFileError extends Error` with `.path` and `.reason` (`'symlink'`, `'not-a-file'`, `'unreadable'`, `'replaced'`).
- Read rules (both readers): an invalid session id throws `TypeError` (the CLI validates first). `lstatType` `missing` → empty result. `symlink`, any non-`file` type, or `unreadable` → throw `MarkerFileError` before any open (a FIFO is never opened). `file` → open `O_RDONLY | O_NOFOLLOW | O_NONBLOCK` (each only where defined), `fstatSync(fd, { bigint: true })` must be `isFile()` with the same `dev`/`ino` as a fresh `lstatSync(p, { bigint: true })`, else `MarkerFileError('replaced')`; read utf8, split on `/\r?\n/`, drop the trailing empty piece. A stop line counts only when it parses and has a non-empty string `agentId`, a finite number `at`, a boolean `blocked`, and `pending` `null` or a non-negative integer; anything else is skipped. A waits line counts only when it parses and its fields match its `kind`: `open` needs a string `window`, `target` and `key`, integer `openedAt`, `deadline` and `n`, and (for target `agents`) an `ids` array of non-empty strings; `close` needs a string `window` and a `reason` of `deadline` or `done`; `delivered` needs a non-empty string `agentId` and a non-negative integer `stop`. Any other waits line (unknown `kind` included) is skipped, as a bad stop line is, so no NaN reaches Task 3's arithmetic. Test: `a waits line whose fields do not match its kind is skipped` — a `delivered` line with `stop: "x"`, an `open` line with no `deadline` and a `close` line with `reason: "other"`, then one valid `delivered` line: `readWaits` returns only the valid one.

- Parsing: the first argument is the target (`agents`, `ci`, `pid`); `--help`/`-h` anywhere returns 0 with `USAGE` on stdout before anything else. Flags are looked up with `Object.hasOwn` in a per-target table; a flag not in the target's table is an unknown flag. - Session: `--session` else `deps.env.CLAUDE_CODE_SESSION_ID`; absent → exit 2 with a stderr line naming `CLAUDE_CODE_SESSION_ID` and `--session`; not matching `SESSION_ID_RE` → exit 2. Both checked before any file or runner is touched.
- Waits records (in `ct-agent-waits-{sid}.jsonl`): `{"kind":"open","window":"<target>:<key>:<openedMs>","target","key","ids"?,"openedAt":<epoch s>,"deadline":<epoch s>,"n"}`, `{"kind":"close","window","reason":"deadline"|"done","at"}`, `{"kind":"delivered","agentId","stop":<stop index>}`. Key: `agents` the sorted, de-duplicated ids joined with `,` (and `ids` the array); `ci` `pr:<n>` or `run:<id>`; `pid` `pid:<n>`.
- Window: an open window is an `open` record with no `close` for its `window`. Join: the most recent open window of the same target whose `ids` contain every listed id (`agents`) or whose `key` is equal (`ci`, `pid`). Otherwise open one: `openedAt = Math.floor(start / 1000)`, `deadline = openedAt + windowSeconds`, `n = 1 +` the number of `close` records with reason `deadline` whose window has the same target and key. Under the spec's Decision rule this counts every such window in the session file, not only consecutive ones.
- Loop: `start = now()`; `callEnd = start + maxSeconds * 1000`; `deadlineMs = deadline * 1000`. Repeat: poll; changed → print, return 0. `t = now()`: `t >= deadlineMs` → `bound: 'deadline'`, append `close` (`deadline`), print, return 3; else `t >= callEnd` → `bound: 'call'`, print, return 3; else `await sleep(min(POLL_MS[target], min(deadlineMs, callEnd) - t))`. A `MarkerFileError` or a malformed waits file read is exit 2 with the path on stderr.
- `agents` poll: read stops and waits; `delivered[id]` = max `stop` of that id's `delivered` records (−1 when none); an id is reported when a final stop for it has `index > delivered[id]`. On change, for each reported id append `delivered` with that id's highest such index; `reported` and `pending` keep the order of `--ids`; when `pending` is empty append `close` (`done`). `state` is `'reported'` on change, `'pending'` otherwise; `stops` is `readStops(...).count`.
- Output: `JSON.stringify` of `{ target, state, changed, elapsedSeconds: Math.round((now() - start) / 1000), deadlineEpoch: deadline, window: n, bound? , ...extra }`, one line.
- `run` wraps everything in `try`/`catch`: an unexpected throw prints `wait-for.js: <message>` and returns 2.
