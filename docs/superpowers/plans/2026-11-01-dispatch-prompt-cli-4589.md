# Dispatch Prompt CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render `/dispatch`'s Task prompts (first call, second call, a handoff continuation of either, a resume's first call) with one CLI call that reads `task-prompt.md` as its only template source, block the group on a render failure, and deny at PreToolUse any main-thread dispatch `Agent`/`Task` prompt that is not byte-for-byte a rendered one.

**Architecture:** A pure lib module (`plugin/bin/lib/dispatch/task-prompt.js`) extracts the two fenced templates and the Context pack numbered list from `task-prompt.md`, substitutes a closed set of dispatcher placeholders (failing loud on any left over), and owns the prompt marker line, the digest and the prompt-size cap. A thin CLI (`plugin/bin/dispatch-prompt.js`, `run(argv, deps)` seam) resolves the values, consumes the existing `parseNextSteps` for a continuation's step list, writes the prompt to `--out` (default: a session-temp file), and appends `{sha256, call, out, …}` to the run dir's `dispatch-prompts.jsonl`. A new PreToolUse gate (`plugin/bin/lib/hooks/dispatch-prompt-gate.js`, wired into `pre-tool-use.js` for tool names `Agent` and `Task`) denies, for a main-thread call only, a marker-bearing prompt whose digest is not in that registry, and a marker-less prompt naming a run this session dispatched. Prose (`SKILL.md` Step 5, `task-prompt.md`, `continuation-call.md`, `two-call-gate.md`, `resume.md`, `express-prompt.md`'s line 3) points the dispatching session at the CLI.

**Tech Stack:** Node 18+ CommonJS, `node --test`, no dependencies.
