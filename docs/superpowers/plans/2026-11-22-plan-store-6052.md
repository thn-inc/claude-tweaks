# Plan Store (#6052) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep a reviewed plan on the hidden ref `refs/claude-tweaks/plans/{n}`, name it from the record with a `Plan:` body line, and answer "is this plan still valid?" with one CLI.

**Architecture:** Three layers, each testable alone. `plugin/bin/lib/plan-store/ref.js` holds the ref names and `git.js` the git transport primitives (one seam, real git in tests). `plugin/bin/lib/issues/plan-line.js` holds the `Plan:` line grammar and the spec hash (pure). `store.js` (write/read) and `check.js` (the ordered verdict) compose them, and `plugin/bin/plan-store.js` is the thin CLI. A plan commit is built with `git commit-tree` on a scratch `GIT_INDEX_FILE`, so no checkout moves. It is pushed with `--force-with-lease` against the remote sha observed just before, and the local ref moves only after the push succeeds.

**Tech Stack:** Node 18+ CommonJS, `child_process.execFileSync('git', …)`, `node:crypto` sha256, `node --test`.

**Spec:** `.claude-tweaks/pipelines/2026-11-22T122529-spec-6052/work/6052-spec.md`

Scope keywords: spec-sha256, PLAN_REF_PREFIX, plan-store.js, plan-line.js

## Global Constraints

- Ref: `refs/claude-tweaks/plans/{n}`. Body line, exactly: `Plan: refs/claude-tweaks/plans/{n} {plan-commit-sha} spec-sha256:{hash}`. The plan file is committed at `docs/superpowers/plans/{basename of --plan-file}`, and `read --out DIR` writes that same basename.
- Spec hash: sha256 over the `##` sections from `## Overview` through `## Planning Decisions`, in body order. With no `## Planning Decisions`, it runs through the last `##` section. Sections after `## Planning Decisions` (e.g. `## Original request`) are not covered. The hash excludes the lines `Surface:`, `Design-intent:`, `Ui-stack:`, `Visual-reference:`, `Parent:`, `Risk-flags:`, `Risk-flags-unconfirmed:`, `Risk-flags-added-by-tripwire:`, `Acceptance-target:`, `**Related:**`, `Blocked by`, the `Plan:` line and the `work-fingerprint` marker lines. Normalization: CRLF to LF, trailing whitespace stripped per line, one final newline.
- `check` verdict on stdout: `{valid, failed}`. Exit 0 when valid, 1 when not. Anything it cannot determine (a fetch error, an unresolvable base) reads `valid: false`, never valid. `failed` is one of `ref`, `hash`, `files`, `base`. A malformed `--line` exits 2 and still prints `valid: false`.
- Fetches use the explicit refspec for the one record. Under `work-backend: local-files` the ref stays local; `write` still prints the `Plan:` line, and a reader in another clone gets `failed: ref`, by design.
- Files check: the path set is the Modify and Test entries of the plan's Files sections (Check A's parse). Create entries are ignored. A path modified or deleted between the plan commit's parent and `SHA` counts as changed. A rename counts as a delete plus an add.
- Exit family (header + USAGE): **Payload-1/Invocation-2**, plus a CLI-own code. 0 success. 1 the invocation was well-formed but its inputs do not hold (unreadable file, a spec with no `## Overview`, an unresolvable `--base` on write, a ref that is missing or names another commit on read, an invalid verdict on check). 2 malformed invocation. **3 `EXIT_NO_REF`** (write only): the ref could not be created or pushed, or the lease was lost, so the caller writes no `Plan:` line.
- Commits: `{Verb} {what} — {detail}`, imperative, no conventional prefix. Every commit message ends with the line `Claude-Session: https://claude.ai/code/session_01QXpjcWGWJYNJ1zzWXuCqch`. One plain git command per Bash call: the worktree guard refuses compound git commands, `$(...)` around git and heredocs.

## Review Focus

1. **A same-tail ref on the remote:** `git ls-remote origin refs/claude-tweaks/plans/8` also prints `refs/archive/refs/claude-tweaks/plans/8` (probed on git 2.56). The lease must observe only the exact ref. Test: Task 1 `lsRemoteRef ignores a same-tail ref`.
2. **A replaced plan on the remote while a clone holds the stale local ref:** a fetch without `+` is rejected as non-fast-forward (probed), which would leave the reader on the old commit. Tests: Task 1 `fetchRef force-updates a stale local ref`, Task 4 `AC3.6 a newer plan on the remote makes an old line read failed: ref`.
3. **A fenced example heading in a spec:** a `## Planning Decisions` quoted inside a code fence in `## Technical Approach` must not end coverage early. Test: Task 2 `specHash ignores fenced headings`.
4. **A spec with no `## Overview`:** the hash must never be computed over empty text. `write` exits 1 with no line, and `check` reads `failed: hash`. Tests: Task 2 `specHash throws SPEC_NO_OVERVIEW`, Task 5 `write refuses a spec with no Overview`.
5. **A CLI run from inside a git hook (inherited `GIT_DIR`/`GIT_WORK_TREE`/`GIT_INDEX_FILE`):** the plan commit and ref must land in the target repo, never the decoy. Test: Task 3 `an inherited GIT_DIR never redirects the write`.

- [ ] **Step 3: Implement `plan-line.js`**

Header comment: the grammar, that `parsePlanLine` is the one reader of a `--line` value, that `composePlanLine` is the one composer, and the spec-hash rule from Global Constraints. Grammar: the line with `/[ \t\r]+$/` stripped must start with `Plan: ` (any other `plan:` spelling is `not-plan-line`). The remainder splits on single spaces into exactly three tokens: `parsePlanRefName(tok0)`, `/^(?:[0-9a-f]{40}|[0-9a-f]{64})$/`, then `spec-sha256:` plus `/^[0-9a-f]{64}$/`. `specHash` algorithm (the order is the decision):
