# drive.js Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `plugin/bin/drive.js #N [#M…]` takes each named record, in order, from admission to a draft PR with CI read. A program owns every step. A headless worker only writes the change.

**Architecture:** `drive.js` is a thin entry over `run(argv, deps)` in `plugin/bin/lib/driver/run.js`. `run.js` walks `STEPS`, a frozen ordered table in `plugin/bin/lib/driver/steps.js`, once per record. Between steps it owns only event emission and stop handling. `plugin/bin/lib/driver/events.js` holds the step and outcome constants, the event sink (stdout and `{run-dir}/driver-events.jsonl`) and the neutralizers for text the worker controls. Every external call goes through `deps`.

**Tech Stack:** Node 18+ CommonJS, `node:test`, `child_process.execFileSync`/`spawnSync` behind `deps` only.

**Spec:** `.claude-tweaks/pipelines/2026-11-12T104316-spec-5218/work/5218-spec.md` (record #5218). Design: `docs/superpowers/specs/2026-11-11-pipeline-driver-design.md`.

**Scope keywords:** drive.js, lib/driver/run, lib/driver/steps, lib/driver/events, driver-events.jsonl

## Global Constraints

- Node built-ins only; no new dependency. Tests: `node --test tests/bin-lib/driver/run.test.js`.
- Usage, verbatim: `drive.js #N [#M…]`.
- Exit codes are Combined-2 (`plugin/bin/link-records.js`): `0` when every named record reached a final event, whatever its outcome; `1` when the policy cannot be read at all and no further record is attempted; `2` for a malformed invocation (no record reference, a non-numeric reference) or an absent `gh` or `git`. `--help` exits 0 before any probe of `gh`, git or policy. The header comment and `USAGE` state these codes.
- Outcome words (exact): `pending-review` | `express-escalated` | `blocked` | `refused`. Event `status` (exact): `ok` | `stop` | `fail`. `stop` means a gate said no. `fail` means a call failed.
- Event line fields: `{ ts, run, record, step, status, ms, model?, usage?, denials?, detail? }`. Fields may be added later and never renamed. Final line adds `outcome, msTotal, msWithoutCi, pr, ci, costUsd, turns, denialCount, stop`, where `stop` is `{ step, class, pushed, created: { worktree, branch }, reason, detail, checkLogged }`. `class` is one of `refused` | `claim` | `pre-push` | `blocked` | `none`.
- Nothing merges. No recorded call and no source text in `steps.js` contains `gh pr merge` or `gh pr ready`.
- No step is retried, with one exception. A transient (5xx or timeout) `gh pr create` failure is retried once after 15 s. Before that retry the driver runs `gh pr list --head {branch} --state open --json number,url` and uses any open PR it finds.
- The commit is the driver's: changed files come from `git -C {wt} --no-optional-locks status --porcelain -z --untracked-files=all`, parsed with `parseStatusPorcelainZ` (`plugin/bin/lib/git-z.js`). Both paths of a rename are staged. Anything under `.claude-tweaks/pipelines/` is excluded. Staging is `git -C {wt} add -- {paths}` (a deleted path stages as a deletion), never `-A` or `.`.
- Worker text (`result.title`, `result.summary`, `detail` carrying worker text, each `denials[].tool_input`) never enters argv. It is neutralized before it reaches a commit message (`git commit -F {file}`), the PR body (summary file) or an event line.
- `check` gate on push: push only when `git -C {wt} rev-parse --verify --end-of-options HEAD` succeeds and equals `check`'s `head`, and `head` matches `/^[0-9a-f]{40}$/`.
- The integration ref is resolved once per run: the `integration-branch` policy value when non-empty, else `git symbolic-ref --quiet --short refs/remotes/origin/HEAD` with `origin/` stripped. It is never a `main` literal in shipped code.
- Quoted from `.claude/skills/gh-api-module-pattern` (SKILL.md and `cli-wrapper-contract.md`), verbatim rules that apply:
  - "Logic lives in an exported `run(argv, deps)`; every side effect goes through `deps` … tests inject fakes"
  - "The `require.main === module` guard sets `process.exitCode = run(...)`, never `process.exit`"
  - "`--help` short-circuits before any availability probe"
  - "Always an argv array, never a shell string"
  - "a literal `windowsHide: true` must be visible inside each `child_process` call's options" (no spread)
  - "Every `gh` spawn wraps its options in `ghOptions(args, …)` from `repo-resolve.js`, while keeping `timeout`, `stdio`, `maxBuffer` and `windowsHide` literal inside"
  - "For git it is `--end-of-options`, not `--`" and `gh` calls use `--` before a caller value
  - "An existence or type check goes through `path-guard`'s `lstatType`, never a bare `fs.existsSync`"
  - "A file about to be read is read directly, with `ENOENT`/`ENOTDIR` caught as absent"
  - "Every remote-contacting call is bounded with `timeout`"
  - "A value-taking flag given last reads `undefined`, so validate presence explicitly"; and "`Number('') === 0` passes `Number.isInteger`" (validate positivity)
- Quoted from `.claude/skills/headless-worker-launch` ("What the consumer owes"), verbatim: "The run loop that consumes the envelope must treat every string in `result`, `detail` when it carries the worker's own text, and `denials[].tool_input` as untrusted, and neutralize it before it reaches a command, a commit message, a comment or a log line. On POSIX the worker is detached into its own process group, so the consumer must forward termination to it. Envelope `ok` means only that conforming structured output arrived; the worker's verdict is `result.status`, which may be `cannot-complete`." Also: "Writing a schema `required` list or a field list as an array literal that starts with `'status'`" fails `tests/git-status-optional-locks.test.js`, so derive or split such lists.
- Quoted from `.claude/skills/windows-checkout-test-parity`, as the spec points to it: platform is a parameter (`deps.platform`), never read from `process.platform` inside step logic. A win32 caller passes `bin: 'claude.cmd'` to `launchWorker` (`worker.js` header: "On win32 the default `bin` of `claude` does not find an npm-installed `claude.cmd`; a win32 caller passes `bin` explicitly").
- Source-scan suites the new files must pass: `tests/windows-hide-spawn-conformance.test.js`, `tests/bin-lib/exit-code-conformance.test.js`, `tests/gh-host-seam-conformance.test.js`, `tests/git-status-optional-locks.test.js`, `tests/git-path-read-conformance.test.js`, `tests/path-guard-conformance.test.js`, `tests/path-containment-conformance.test.js`.

## Decisions this plan fixes (spec leaves to the builder or is silent)

- **Claim before mint (AC5, AC7).** `claim-targets.js` needs `--run-id` before the run directory exists. The claim step computes `runId = formatTimestamp(claimDate) + '-drive-' + n`, using `formatTimestamp` from `plugin/bin/lib/hooks/run-dir-resolve.js` so the timestamp is never hand-rolled. It claims with `--run-id runId --targets n --steps build,test` and no `--run`. The run-dir step mints in-process with the same function `hooks.js resolve-run-dir --create` calls: `resolve({ cwd: mainRoot, env: {}, specSlug: 'drive-' + n, create: true, now: claimDate })`. It then requires `path.basename(path) === runId`; a mismatch is a `claim`-class `fail`. It then writes the canonical claim-log line with `log-decision.js --run {dir} --status AUTO --section "/flow" --step "Step 2.8" --text claimLogText(n, transport)` (`claimLogText` from `plugin/bin/lib/log-decision/claim-log.js`). This keeps the order the spec states, and `express-lane.js verify` still finds the claim log.
- **#5216 not yet merged.** `admission.js` and `evaluateRecordEligibility`'s `allowAbsentCeremony` option arrive with #5216. The real modules are `require`d lazily inside `realDeps` functions only, so `--help`, a malformed invocation and every test run without #5216's code. The `express-driver*` policy keys are unknown until #5216 merges (probe: `defaultResolvePolicy(['express-driver'])` returns `{ error: 'unknown-key' }`). A key whose entry carries `error` counts as unreadable policy, which gives exit 1.
- **Worker handle (AC14 F1).** `launchWorker` returns only `Promise<envelope>`. The worker step passes a wrapping runner, `(call) => { const h = deps.runner(call); ctx.shared.activeWorker = h; return h; }`. `run.js` subscribes once through `deps.onSignal(handler)`. The handler calls `ctx.shared.activeWorker.kill('SIGTERM')` when set, then `deps.terminate(signal)`.
- **Worktree.** Created with `git -C {mainRoot} worktree add -b drive-record-{n} {mainRoot}/.claude/worktrees/drive-record-{n} origin/{ref}`, after `git -C {mainRoot} fetch origin {ref}`. The post-creation catch-up follows: `git -C {wt} fetch origin {ref}`, then `git -C {wt} merge origin/{ref}`. Stamp: `hooks.js record-worktree --run {runDir} {wt}`, whose stdout must contain `worktree recorded`. Leftover state (AC9), checked before `worktree add`: `lstatType(wt).type !== 'missing'`, or `git rev-parse --verify --quiet --end-of-options refs/heads/drive-record-{n}` exits 0, or `{mainRoot}/.claude-tweaks/pipelines` holds another entry ending `-drive-{n}` other than this `runId`. Any of these is a `fail`, class `pre-push`, detail naming the leftover, and `created` stays `{worktree:false, branch:false}`.
- **Test command.** `TEST_COMMAND = 'npm test'` (constant in `steps.js`). It is the worker's `testCommand` and the full invocation's `--cmd tests=npm test`.
- **CI wait.** `CI_WAIT_BOUND_MS = 30 * 60 * 1000`, `CI_POLL_INTERVAL_MS = 30 * 1000`. Poll `pr-checks.js --run {runDir}` while `state` is `pending` or `stale`. Still pending at the bound gives `ci: 'timeout'`. The wait is excluded from `msWithoutCi`.
- **Policy is read once per run.** The policy step caches into `ctx.shared.policy`. When the read fails it sets `ctx.shared.fatal = true`, the record ends `refused`, `run.js` attempts no further record, and the exit is 1. `run.js` reads `shared.fatal` and names no step.

## Review Focus

1. **A worker title or summary carrying `Closes #12`, `@someone`, a backtick fence or a newline.** It must not close an issue, ping anyone or break a line in the commit, the PR body or the event JSONL. Tests in Task 1 (neutralizers) and Task 4 (commit message through `-F`).
2. **A second run on a record whose first run stopped.** The worktree, branch or an earlier `*-drive-{n}` run dir already exists. The driver must refuse at the worktree step and never reuse or delete anything. Test in Task 3.
3. **SIGINT while the worker runs.** The detached worker must be signalled before the driver exits. Test in Task 4.
4. **A `check` envelope that is malformed** (no `head`, a short sha, a non-JSON stdout, `rev-parse` failing). It must never pass the push guard. Tests in Task 5.
5. **A consumer project whose integration branch is not `main`.** Every `--base`/`--integration-branch`/`origin/{ref}` must carry the resolved value. Test with `develop` in Task 3.

## Shared test harness (built in Task 1, extended by later tasks)

`tests/bin-lib/driver/run.test.js` gets a `harness(over = {})` helper returning `{ deps, calls, out, files }`. `calls` is an ordered array of `{ kind, args, cwd? }`, where `kind` ∈ `gh | git | node | worker | resolveRunDir | writeFile | appendFile`. A `script` table maps a call-matcher to a canned result. An unmatched `gh`/`git`/`node` call throws `unexpected {kind} {args}`. `files` is an in-memory map, and `deps.appendFile`/`deps.writeFile` write into it. `deps.now` is a fake clock that advances 1 ms per read. `deps.sleep` resolves at once and advances the clock by its argument. Pattern source: `tests/bin-lib/express/cli.test.js:66-103`.

  - `STEP`: frozen object mapping each name to itself in camelCase keys (`STEP.runDir === 'run-dir'`, `STEP.recordPr === 'record-pr'`, `STEP.setConfig === 'set-config'`).
  - `OUTCOMES = Object.freeze({ PENDING_REVIEW:'pending-review', EXPRESS_ESCALATED:'express-escalated', BLOCKED:'blocked', REFUSED:'refused' })`; `STOP_CLASSES = Object.freeze({ REFUSED:'refused', CLAIM:'claim', PRE_PUSH:'pre-push', BLOCKED:'blocked', NONE:'none' })`.
  - `outcomeFor(stopClass) -> outcome`: refused→refused, claim→blocked, pre-push→express-escalated, blocked→blocked, none→pending-review; anything else throws.
  - `neutralize(text) -> string`: non-string becomes `''`. CR/LF/tab runs become one space. Every backtick becomes `'`. `@` becomes `@​`. Closing keywords (`close|closes|closed|fix|fixes|fixed|resolve|resolves|resolved`, any case, whole word) are removed. Every `#\d+` and `owner/repo#\d+` is removed. Whitespace collapses; the result is trimmed.
  - `normalizeTitle(raw) -> string`: first line only, then `neutralize`, then a trailing `.` is dropped. Returns `''` when nothing is left.
  - `createEventSink({ stdout, appendFile }) -> { emit(event), bindRunDir(runDir), events() }`. `emit` writes `JSON.stringify(event) + '\n'` to stdout at once. Before `bindRunDir` it also holds the line in memory. `bindRunDir` appends every held line to `{runDir}/driver-events.jsonl`, in order, then appends each later line as it is emitted. `events()` returns the emitted objects for the current record. A sink is created per record.
