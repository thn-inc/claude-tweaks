# Verified-Open-Deps Throw Fails Closed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A throw between the start of the `verified-open-deps` step and its single write must leave the file absent, so the `blocked` pass fails closed instead of reading an empty file as "no dependency is open" — in the module and in its retained bash twin.

**Architecture:** The module's `verified-open-deps` step (gh transport only) truncates `f.verifiedOpenDeps` and then reads `dispatch-unresolved-deps.json`, which can throw; `step()` logs the throw and carries on, leaving the empty file. Replace the truncate with a removal (the step already ends with one write that creates the file and, on a failed write, removes it). The bash fence does the same truncate and then builds its loop from a `$(node -e …)` that can fail silently; give it the same shape: remove first, then create the empty file only after the unresolved list was read.

**Tech Stack:** Node 18+, `node --test`, bash fence in a skill markdown file.

**Spec:** `.claude-tweaks/pipelines/2026-11-18T072534-spec-5879-5863-5865-5830/spec-5879/work/5879-spec.md` (the worktree copy; record #5879).
