**Role:** integration
**Review risk:** high

**Files:**
- Modify: `tools/guard-refusals/transcripts.js` (export `eachLine` and `listCandidates`; no behaviour change)
- Create: `tools/wait-polls.js`
- Test: `tests/wait-polls/cli.test.js`
- Modify: `docs/plugin-structure.md` (the `tools/` row: add a `wait-polls.js (#5602 — …)` entry after the `guard-refusals/` entry)

**Interfaces:**
- Consumes: `eachLine(fsImpl, file, fn(lineBuffer, lineNo))` and `listCandidates(fsImpl, slugDir, onUnreadable) -> string[]` from `tools/guard-refusals/transcripts.js`, exported alongside `scanStore`: `module.exports = { scanStore, eachLine, listCandidates };`.
- Produces: `run({ argv, deps }) -> 0 | 2` (`deps`: `fs`, `env`, `now`, `homedir`, `log`, `err`, defaulted as in `tools/guard-refusals.js`'s `defaultDeps`), `classifyProbe(text: string) -> TargetName | null`, and `TARGETS` (the ordered target-name list), all exported from `tools/wait-polls.js`.

**Contract (decided here, documented in the CLI's header comment):**

- Usage: `node tools/wait-polls.js [--projects-dir <dir>]... [--match <slug-substring>] [--since-days <n>=30] [--until <iso>=now] [--help]`. `--projects-dir` may repeat; with none given it defaults to `$CLAUDE_CONFIG_DIR/projects`, else `~/.claude/projects` (as `guard-refusals.js`). Output is always one JSON line (no `--json` flag). Exit 0 success; exit 2 for an unknown flag, a flag with no value, a non-positive `--since-days`, an unparseable `--until`, or a `--projects-dir` that is missing, not a directory, or unreadable (stderr names the problem and prints the usage).
- Window: `[until - since-days * 86400e3, until)` over file mtimes, as `guard-refusals.js`.
- Walk: resolve each `--projects-dir` with `fs.realpathSync` and drop repeats; within each root, list slug directories (`--match` filters by substring of the slug name), resolve each slug directory with `fs.realpathSync` and drop any real path already walked; collect candidates with `listCandidates`. A file is `subagent` when its parent directory's basename is `subagents`, else `main`. Collect the candidates of every root first, then read every `main` file (across all roots) before any `subagent` file, each list sorted. `transcripts.{main,subagent}` counts the files read.
- Read errors (spec's Plan Review Clarifications): the output keeps exactly its five keys. A slug directory, candidate or file that vanishes or dangles between listing and read (`err.code === 'ENOENT'`, from `realpathSync`, `statSync`, `readdirSync` or `eachLine`) is skipped and not counted in `transcripts`. Any other read error after the up-front `--projects-dir` checks — including `listCandidates` calling its `onUnreadable` callback, which carries no error code, so pass one that records a failure — makes `run` print `wait-polls.js: cannot read <path> (<code>)` plus the usage on `err` and return 2, printing no JSON.
- Counting: a tool call is identified by its `tool_use` block `id`; the first occurrence across the whole walk counts, every later one is skipped (a fork replays its parent's history). `bashCalls` counts first-occurrence `Bash` tool_uses; a Bash call is sleep-led when its `input.command` matches `/^\s*sleep\s+\d/`; `sleepLed` counts those. Each count is split by the `main`/`subagent` kind of the file the call was first seen in. A line that is not valid JSON is skipped.
- Target classification, per counted sleep-led call, using the ordered list of every `tool_use` block in that call's own file (in-file duplicates dropped):
  1. The chained command: the command text after the first `;`, `&&`, `||` or newline that follows the leading `sleep N`. If non-empty, `classifyProbe(chained)`; a non-null result is the target.
  2. Else the probes between sleeps: the tool calls strictly between this sleep and the next sleep-led call in the file, then those strictly between the previous sleep-led call and this one, each segment used only when it holds at most `PROBE_GAP_MAX = 3` calls. A segment exists only between two sleep-led calls: the first sleep in a file has no previous segment and the last has no next one. `Agent` and `Task` calls are never probes (their prompt text would match the rules). The first call for which `classifyProbe(probeText(call))` is non-null gives the target. `probeText` is `input.command` for Bash, `input.file_path` for Read, and `name + ' ' + JSON.stringify(input)` for any other tool.
  3. Else `agent-notification` when an `Agent` or `Task` tool_use precedes the sleep in the same file.
  4. Else `other`.
- `classifyProbe(text)` — first matching rule wins, in this order:

  | Target | Matches |
  |---|---|
  | `ci` | `/\bgh\s+(pr\s+(checks\|view)\|run\s+(view\|watch\|list))\b\|pr-checks\.js\|ci-gate-record\.js/` |
  | `worktree-git` | `/\bgit\b.*\b(rev-parse HEAD\|status --porcelain\|diff HEAD)\b\|\bhash-object\b/` |
  | `suite-slot` | `/suite-slot/` |
  | `verify` | `/verify\.js\|\bnpm (run )?test\b\|node --test\|run-tests\.js/` |
  | `output-file` | `/\/tasks\/[^\s"']+\.output\b/` |
  | `dev-server` | `/\bcurl\b.*\b(localhost\|127\.0\.0\.1)\|playwright\|\blsof\b.*-i/` |
  | `background-process` | `/\bps\b\|\bkill -0\b\|\bpgrep\b\|\btail\b\|\.log\b\|^(BashOutput\|TaskOutput) /` |

  `TARGETS = ['agent-notification', 'background-process', 'output-file', 'ci', 'worktree-git', 'verify', 'dev-server', 'suite-slot', 'other']` (the spec table's order).
- Output, keys in exactly this order: `{ window: { since, until }, transcripts: { main, subagent }, bashCalls: { main, subagent }, sleepLed: { main, subagent }, targets }`, `window` values ISO strings, `targets` an object with one key per `TARGETS` entry, in that order, each `{ calls, share }` where `share` is `calls / sleep-led total * 100` rounded to one decimal (0 when there are no sleep-led calls).
