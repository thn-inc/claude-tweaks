# Getting started: skill reference

Full reference for every skill in the claude-tweaks plugin, grouped by where it sits in the lifecycle: plan phase, the automated pipeline, component skills (standalone or called by lifecycle skills), and utility skills. See the main [README.md](../README.md) for installation, the artifact-flow diagram ("How it works"), and the Work Records model.

### Plan phase

**`/claude-tweaks:init`** — One-time project bootstrap. Scans the codebase, generates a CLAUDE.md with project-specific conventions and philosophy, creates workflow directories (`specs/`, `docs/plans/`, `docs/journeys/`), sets up browser integration (agent-browser), builds a documentation registry (`docs/REGISTRY.md`) mapping docs to code areas for automatic updates, and discovers existing user journeys.

**Port isolation** — `/init` Step 6.5 offers to rewrite literal dev-server ports (in `vite.config.*`, `vue.config.*`, Compose files, and a few other common spots) to read from the environment instead, then sets the `port-services` policy key (e.g. `port-services: web,api`). From then on, every session in the project leases its own 10-port block (`~/.claude-tweaks/ports.json`, machine-wide, verified free by binding) — SessionStart writes it into `.env.local`, the statusline shows it (`:20010`), and it's released automatically when the worktree is torn down. Different worktrees of the same project never collide on ports again.

**Verify scope** — `/init` Step 6.6 runs once per project, right after port isolation: it proposes a starter `.claude-tweaks/verify-scope.json` (one suite per workspace package with a `test` script, a package other packages depend on mapped to every suite, and the pipeline's own bookkeeping paths — ledgers, run directories, plans — mapped to none) and offers to write it. `verify.js --scope` then reads that declaration, so the pipeline's re-verify sites shed the suites a change set cannot affect; anything the declaration doesn't name fails closed to the full set, which is also exactly what a project with no declaration gets. The file is project-owned and reviewed like code — the starter is create-if-absent and never overwrites an existing declaration, and `/claude-tweaks:init --update` reports drift between it and the live workspace.

**`/claude-tweaks:intake`** — Human-only gatekeeper for a mixed braindump — pasted text or `--file <path>`. Splits it into fragments, judges each against this repo, and delegates every write to the skill that already owns it: `/claude-tweaks:capture` for `file`/`absorb` verdicts, `/claude-tweaks:feedback` for `upstream`, and learning-routing's memory-write procedure for `remember`. One batch table, one `AskUserQuestion`, at most one nudge round — no `auto` mode, never invoked from `/claude-tweaks:flow`.

**`/claude-tweaks:capture`** — Brain-dump an idea into a new backlog work record (a GitHub issue carrying only `by:capture`, or a local `specs/{id}-{slug}.md` file — no stage label, per `work-backend`). Accepts free-text — no structure needed for a human idea; a supplied spec-shaped body takes the Shaped-body branch and files scored + `ready` (a deferral additionally requires `--defer-reason=`, per `_shared/deferral-gate.md`). When the idea matches an existing open record closely enough — the two-criteria bar of a shared file path or subsystem *and* an identical `type:{t}` with the same operation on it — absorb is the recommended route rather than a new record: the content is appended to that record under a dated `## Absorbed:` heading, the target's `size:` is re-judged raise-only, and no new record is filed. An agent-driven filing (`$PIPELINE_RUN_DIR` set, `--source`, or `--defer-reason=`) applies the structural half of that bar without asking; a bare `auto` invocation still defaults to `keep`. Absorb never targets a closed record, a decomposition parent, or a record carrying `bot:in-progress` — those file fresh with a `**Related:** #N` line instead. Ideas are triaged later by `/claude-tweaks:tidy`.

**`/superpowers:brainstorming`** *(Superpowers plugin)* — Generates solution approaches from a promoted backlog record or topic. Explores multiple directions, evaluates tradeoffs, and produces a Design Doc with a recommended approach.

**`/claude-tweaks:specify`** — Shapes one or more work records (a `#N` reference, or a comma-separated `#N,#M` list of them, each shaped in turn) into spec shape (adds `ready` plus risk/size scoring), or decomposes a Design Doc into agent-sized `ready` sub-issue records with clear acceptance criteria — plus a parent record, when the decomposition's Step 2.6 collapse decision keeps one (a 1-unit decomposition, and an independent 2-unit one, produce no parent). Bare `/specify` is the headless-safe drain a scheduled Routine fires — repeats the claim → framing-guard → shape-or-route → release loop over the ranked eligible backlog (`github-issues`-only), one record per iteration, until `--budget <n|all>` attempts are spent or the eligible set (re-fetched fresh each iteration) is empty — default `specify-budget` (5) — or is a cheap no-op when nothing is eligible at the start; mirrors `/claude-tweaks:dispatch`'s own bare drain end-to-end. (`next`: deprecated alias for `--budget 1`.) A record carrying `needs:definition` redirects to `/superpowers:brainstorming` instead of shaping — an undecided idea gets a real design pass before it can reach `ready`. Resolving a record's open question during shaping removes every `needs:*`-prefixed label it carries, not only `needs:definition` — a `needs:decision` label being cleared this way gets its live decision comment closed with a `**Resolved:**` line first. A reference that resolves to a decomposition parent is refused before any edit — a two-tier parent-record guard (the `parent-issue` label/facet, or a line-anchored `## Leaves` body sniff for legacy parents) stops the shape, silently-but-reportedly strips any mis-shape residue (`ready` + scoring), and points at the leaves; a sniffed legacy parent gets one repair-or-escape question interactively, while batch and headless invocations refuse without prompting. Each record carries `Surface:`/`Design-intent:`/`Ui-stack:` body metadata (not frontmatter — plain text lines at the top of the body). Detects implicit dependencies between sub-issues (and against open records) that touch the same files and links them (`Blocked by #N`, or a native sub-issue/dependency edge under `work-links: native`). Invokes `/claude-tweaks:challenge`'s `framing-check` mode inline while shaping or decomposing a record — a `solution-baked` verdict stamps a presence-only `solution:unjustified` label and writes the surfaced assumptions into the record's own `## Gotchas`. Stamps the presence-only `breaking` label — and writes a `## Breaking Change` section — when the shaped Acceptance Criteria name a contract change; `bin/compose-subject.js` turns that into the merge commit's `!` suffix and `BREAKING CHANGE:` footer at merge time. Deletes the Design Doc after absorbing it into the surviving records. Uses `/superpowers:writing-plans` to structure the execution plan.

**Polymorphic input:** `/specify` accepts a work record reference (`#N`, an issue URL, or a local record id) to shape in place, a comma-separated list of record references to shape each in turn, an inclusive range of record references to shape each in turn, a design doc path or topic name (invokes `/superpowers:brainstorming` when no doc exists yet) to decompose, or a backlog reference (title keywords) that resolves to whichever mode applies. The list form is comma-joined with no spaces — `/claude-tweaks:specify #701,#702` (`work-backend: github-issues`) or `/claude-tweaks:specify 701,702` (`work-backend: local-files`), mirroring `/claude-tweaks:flow`'s own `42,45,48` form — and is shaping mode only: every element must be a record reference, and a list containing a design-doc path or a topic is rejected with a one-line error naming the offending element before anything is shaped, while comma-containing free text stays a topic. The range form — `/claude-tweaks:specify #701-#705` or `701-705` under `work-backend: local-files` — expands to the equivalent comma-joined list before any of that form's own resolution runs, so it inherits the same rules, plus a 25-element expansion cap to guard against a typo shaping hundreds of records. When the target is (or becomes) a frontend record, `/specify` runs the Impeccable `shape` pre-step and asks a design-intent question (bold / quiet / minimal / delightful / onboarding / none) to populate the body metadata.

### Pipeline (automated by `/claude-tweaks:flow`)

**`/claude-tweaks:build`** — Implements a work record or spec end-to-end (`#N` record reference is the primary input; a spec number is the legacy alias — both materialize into the same build-time file via `plugin/skills/flow/materialize.md`). Two orthogonal choices:

| | **Current branch** | **Worktree** (default) |
|---|---|---|
| **Subagent** (default) | Fast solo work, no isolation | Isolated feature branch |
| **Batched** | Hands-on review per chunk | Full control + full isolation |

Uses `/superpowers:subagent-driven-development` and `/superpowers:executing-plans` for autonomous execution. In worktree mode, `/superpowers:using-git-worktrees` manages the isolated branch. Delegates code cleanup to `/claude-tweaks:simplify` and journey capture to `/claude-tweaks:journeys`. When a behavioral bug surfaces during verification, delegates to `/superpowers:systematic-debugging` — reproduce on command first, then fix the confirmed cause (no edit-and-pray). Updates docs matched by the documentation registry and tracks deferred items in the open items ledger.

```
/claude-tweaks:build 42                    → subagent + worktree (default)
/claude-tweaks:build 42 current-branch     → subagent + current branch (no isolation)
/claude-tweaks:build 42 batched            → human-reviewed batches + worktree
/claude-tweaks:build 42 auto               → subagent + worktree, no confirmations
```

**`/claude-tweaks:stories`** — Generates QA story YAML files by browsing your running app. Auto-detects the dev server, reads existing journey files as a skeleton, and extracts behavioral contracts from component source code (validation rules, state transitions, error paths) to generate tests that cover the full behavioral surface — not just what's visible on first render.

Stories include `source_files:` and `journey:` fields for change-aware scoping and coverage tracking. Supports auth profiles (`stories/auth.yml`), self-healing CSS selectors, and parallel orchestration across browser sessions. Auto-triggered by `/claude-tweaks:flow` when UI files changed.

**`/claude-tweaks:test`** — Mechanical "does it work?" gate. Runs types, lint, and tests from your project. In QA mode, validates story YAML files against the running app with enriched reporting — 5 finding categories (code-bug, stale-selector, ux-issue, flaky-env, story-bug), severity levels, and suggested fixes. Supports scoping by journey, tag, affected files, or retry of previous failures.

```
/claude-tweaks:test                        → standard suite (types + lint + tests)
/claude-tweaks:test qa                     → QA story validation
/claude-tweaks:test qa journey=checkout    → stories for one journey
/claude-tweaks:test all                    → full suite + QA stories
```

**`/claude-tweaks:review`** — Analytical "is it good?" gate. Gates on `/claude-tweaks:test` passing. Runs multiple review lenses in parallel — spec compliance, code quality, UX analysis. Delegates hindsight to `/claude-tweaks:reflect`, code cleanup to `/claude-tweaks:simplify`, and visual review to `/claude-tweaks:visual-review`. The architecture lens flags shallow modules and surfaces `/claude-tweaks:deepen` for a dedicated depth pass; confirmed bug fixes route through `/superpowers:systematic-debugging` (reproduce first). Detects journey regressions when changed files overlap with existing journey `files:` frontmatter. Uses `/superpowers:dispatching-parallel-agents` to fix 3+ independent issues in parallel. Every finding must be explicitly resolved — fix now, defer, or accept with reason.

| Mode | What it does |
|------|-------------|
| **code** (default) | Code review + UX analysis (when QA data available) + simplification |
| **full** (default in /flow) | Code review + visual browser review via `/visual-review` + idea generation |
| **visual** | Delegates to `/visual-review` — single page |
| **journey** | Delegates to `/visual-review` — walk a documented journey |
| **discover** | Delegates to `/visual-review` — scan and document all user journeys |

**`/claude-tweaks:wrap-up`** — Reflection and cleanup. Delegates structured reflection to `/claude-tweaks:reflect` (full mode) for knowledge capture. Routes learnings to CLAUDE.md and skill files, records significant decisions as ADRs in `docs/decisions/` when they pass the ADR gate (hard-to-reverse, surprising, a real trade-off — kept deliberately rare), captures deferred work with triggers for re-activation, resolves every open ledger item. In worktree mode, merges the feature branch via `_shared/pr-first-merge.md` (`pr-first`, the GitHub-backed default) or `/superpowers:finishing-a-development-branch` (`local-merge`) and cleans it up. Deletes plan files and the ledger — leaving a clean slate. A legacy spec file is deleted too; a record-mode build's materialized file (`{run-dir}/work/{n}-spec.md`) stays on the branch as committed audit trail instead.

**`/claude-tweaks:release`** — Drives a release: reads the preflight fact pack, runs the whole-branch review before any bump, renders one console, merges the release-please PR (pr-first) or runs `bin/release-local.js` (local-merge), verifies the tag and the publish hook landed, and comments/closes the shipped records. `--train` is the unattended tier's on-schedule form, held on a major bump or a blocking review.

### Component skills (standalone or called by lifecycle skills)

**`/claude-tweaks:challenge`** — Three-mode skill. `framing-check` is a component mode invoked only by `/claude-tweaks:specify` while it shapes or decomposes a record — it judges whether the record bakes in its own solution and renders a `FRAMING: open | solution-baked` verdict; on `solution-baked`, `/specify` stamps a presence-only `solution:unjustified` label and writes the surfaced assumptions into the record's own `## Gotchas`. `--lens=<n[,n...]>` is a human-invoked escape hatch that applies one of seven named debiasing lenses to a topic, record, or problem statement and returns the perspective in conversation — it writes no file. A bare `#N` reference is the human-invoked evidence-or-accept-risk call on a record carrying `solution:unjustified` — it reads the record's `## Gotchas` assumptions, runs a bounded in-repo evidence search per assumption, and offers supply-evidence / accept-risk / leave; either resolving choice removes the label, and accepting leaves a durable acceptance trace — a comment under `github-issues`, acceptance bullets in the record body under `local-files`.

**`/claude-tweaks:reflect`** — Structured evaluation of recent work through structured lenses. In **hindsight** mode (used by `/review` Step 4), focused on "should we change something before shipping?" In **full** mode (used by `/wrap-up` Phase 1), all five lenses — Surprises, Approach, Near-misses, Fresh start, Friction — plus tradeoff review, for broader knowledge capture. Works standalone against any recent changes.

**`/claude-tweaks:simplify`** — Code simplification via the `code-simplifier:code-simplifier` subagent. Catches unnecessary complexity from iterative development, verbose debugging patterns, and cross-file inconsistencies. Used by `/build` (Common Step 3) and `/review` (Step 5). Works standalone against any file scope.

**`/claude-tweaks:deepen`** — Architectural depth pass at the module level (where `/simplify` works at the line level). Finds shallow modules — interfaces nearly as complex as their implementation — using a leverage-based depth model (not a line ratio) and the deletion test ("would removing this concentrate complexity, or just move it?"). Presents deepening/collapse candidates ranked by leverage in a two-stage flow: candidates first, then a focused interface conversation only for the deepen candidates you pick (collapses are mechanical — they batch into a single confirm instead) — never a runaway rewrite. Declined candidates persist to `.claude-tweaks/deepen/declines.md`, so a later run re-presents them pre-marked rather than as first-seen. Classifies dependencies (pure / local stand-in / network-boundary → port + adapter) to keep the deepened module testable. Surfaced as a Next Action by `/review` (lens 3e) and `/reflect` (structural-debt lens); run it standalone every few days to catch architecture entropy. In `auto` mode it stages candidates rather than refactoring.

**`/claude-tweaks:journeys`** — Creates or updates user journey documentation (`docs/journeys/`) for recently built features. Scans existing journeys for overlap, creates new journey files with persona-specific steps and "should feel" qualifiers, and updates existing journeys when builds modify their flows. Used by `/build` (Common Step 6). Works standalone.

**`/claude-tweaks:visual-review`** — Browser-based UI inspection with structured review steps: reconnaissance, first impressions, persona-based interaction, structured analysis, and creative reimagination. Four modes: **page** (single URL), **journey** (walk a documented journey testing "should feel" expectations), **discover** (scan and document all journeys in a brownfield project), **recommendation** (browser-free — matches the diff against journey `files:` frontmatter and returns which journeys are worth walking, used by `/review` Step 6 in code-only mode). Handles its own browser detection with fallback chain. Used by `/review` (Step 6). Works standalone: `/claude-tweaks:visual-review http://localhost:3000`.

**`/claude-tweaks:visualize`** — Generates a themed, project-local visual diagram (architecture, flowchart, sequence, state, ER, timeline, swimlane, quadrant, nested, tree, org chart, layer stack, venn, pyramid, or a live `record-graph` of this project's own open work-record queue) as a self-contained HTML+SVG file, styled from the project's own `DESIGN.md` tokens (or a neutral default skin when Impeccable isn't set up). An optional D2-backed enhanced rendering path handles diagram types with a native D2 construct. Soft-hook nudges in `/journeys` Step 3.6, `/specify` Step 2.5d, and `/review` Lens 3i-diagram suggest invoking it — gated by `diagram-suggestions: enabled` in CLAUDE.md, written by `/init` Step 12. Diagrams co-locate with what they illustrate (`docs/journeys/`, `docs/plans/`) rather than a single central folder; `docs/diagrams/` is the fallback for context-free, direct invocations. `record-graph` is the one exception to that rule — it always writes `docs/diagrams/record-graph.html` by rule (never ephemeral, never co-located), takes no topic argument, and currently requires `work-backend: github-issues`. Works standalone: `/claude-tweaks:visualize`.

**`/claude-tweaks:assess-agent-autonomy`** — Content-aware trust and ceremony-depth verdicts replacing mechanical label lookups. Four modes: **grant-check** (informs `/claude-tweaks:backlog refine`'s grant-check pass recommendation and gates the same command's headless posture's own chain, reading a record's actual body content rather than just its risk/size labels), **merge-check** (replaces `/dispatch`'s Auto-merge gate — weighs diff content, review findings, and a test-exclusion-aware blast-radius summary holistically instead of a hard line-count cutoff), **failure-check** (replaces `/dispatch`'s blanket failure-revocation rule — classifies a failure as correctness/transient/ambiguous so a flaky test or infrastructure hiccup no longer permanently strips merge trust), and **ceremony-check** (informs `/specify`'s per-record ceremony depth, independent of merge trust — `/flow`'s materialize step falls back to it only for records that never went through `/specify`). Invoked inline by its callers, never directly by a human.

**`/claude-tweaks:feedback`** — Use when a learning belongs upstream in the claude-tweaks plugin rather than in the consuming project — a skill that behaves wrongly (defect) or has no opinion where it should (gap). Files it as a GitHub issue against `thomasholknielsen/claude-tweaks` after an explicit scrub and confirmation. Invoked bare, it also evaluates the session from above: a dispatched judge reads the session transcript against the maintainer-objective rubric (`plugin/skills/_shared/feedback-objectives.md`) — the first bare invocation in a session reads the whole transcript, a later one evaluates only the delta since the prior run's watermark, and one whose transcript hasn't grown at all since that watermark skips the judge dispatch entirely and reports the prior run's filings instead (`--full` ignores the watermark and forces a fresh full evaluation) — and its findings join the same batch confirmation. Human-invoked, not part of the automated pipeline.

### Utility skills

**`/claude-tweaks:flow`** — Automated pipeline: build → [stories →] test → review → polish → wrap-up in one command. **Runs hands-off by default (`auto` mode)** — the Pipeline Config Manifesto displays as a read-only FYI and the pipeline proceeds without an approval stop; the only *routine* user-facing stop is the Wrap-Up Review Console at the end. HARD-GATEs and mandatory user-input items still fire mid-run even in `auto` — the enumerated list is in `plugin/skills/_shared/auto-mode-contract.md`'s "What `auto` does NOT silence" section, and a multi-spec batch adds one more (a boundary-freshness escalation when origin moves under an in-flight run). Pass `confirm` to inspect/override the policy levers at a Manifesto gate first, `interactive` for per-skill prompts. Defaults to worktree git strategy; pass `current-branch` to commit on the current branch instead. Add `no-stories` to skip QA generation, `no-polish` to skip the polish phase entirely, `no-deepen` to skip the end-of-run depth survey. At the Pipeline Summary, flow runs `/claude-tweaks:deepen`'s read-only analysis and surfaces shallow-module candidates as a **Depth Opportunities** recommendation block — it never refactors module interfaces in a hands-off run (architecture is low-reversibility; you run `/deepen` deliberately to act). Resume from any step with `/claude-tweaks:flow 42 review`. Run multiple specs sequentially (`/claude-tweaks:flow 42,45,48`) or in parallel across terminals — each terminal gets its own isolated worktree.

**Polish phase:** After review verdict PASS on a frontend spec, `/flow` invokes `/claude-tweaks:design-wrapper polish <spec>` to dispatch Impeccable's refinement set (`polish` / `clarify` / `harden`), suggestion-driven commands (`typeset` / `layout` / `adapt` / `optimize`, dispatched when an `audit` finding's own `suggestion` field names them rather than by keyword-matching the finding's category), and intent-driven commands (`bolder` / `quieter` / `distill` / `delight`+`animate` / `onboard` per the spec's `design-intent:` frontmatter). When polish modifies code, a re-verify gate runs `/test skip-qa` (types + lint + tests, no QA) with a one-cycle cap — a re-verify failure stops the pipeline with a "Polish broke verification" failure card. Backend specs and projects without Impeccable installed skip polish cleanly.

**Craft layer:** Every dispatch that writes UI code assembles design context from two source classes, per `plugin/skills/_shared/design-craft.md` — project **decisions** (`DESIGN.md` plus Impeccable's `.impeccable/design.json` sidecar), authoritative wherever they speak, and generic craft **principles** (Emil Kowalski's design-engineering skills when installed, plus Impeccable's reference files), which govern wherever the decisions are silent. The principles layer always rides along for UI work; installing Emil's skills (`npx skills@latest add emilkowalski/skills`) is optional, and their absence degrades gracefully.

**Pipeline summary Creative Opportunities block:** Before Next Actions, `/flow` invokes `/claude-tweaks:design-wrapper survey` against the full pipeline diff and renders a Creative Opportunities table when survey returns recommendations. `/flow` handles decline detection across re-runs by comparing the previous recommendations cache to the new diff and incrementing a per-spec decline counter for un-invoked recommendations; suggestions declined twice are suppressed.

**`/claude-tweaks:help`** — Dashboard with workflow status, command reference, and context-aware recommendations. Prints the installed claude-tweaks plugin version (read from `plugin/.claude-plugin/plugin.json`, the sole source of truth). Warns about dependency conflicts between in-progress specs. Surfaces the current branch's open PR (review decision, CI checks, unresolved threads) and ranks blocked-PR work first in recommendations. The policy argument (`/claude-tweaks:help policy`) switches to a standing configuration review instead of the dashboard: it renders the levers this project has set, any invalid/unrecognized/migratable policy keys, notable defaults that current project signals argue against, and a collapsed count of advanced levers, then offers up to three validated edits to `.claude-tweaks/policy.yml` behind a single confirmation.

**`/claude-tweaks:tidy`** — Batch backlog hygiene. Scans the live work-record queue (backlog, parked, unsynced, unscored `ready`, `bot:blocked`, legacy-taxonomy, `bot:parked` records) — a record carrying any `needs:*`-prefixed label (`needs:definition`, `needs:decision`) is excluded from every headless worklist shape, surfaced instead via `/claude-tweaks:backlog attention` or its own decision comment — scans review/wrap-up history for recurring patterns across specs, audits the documentation registry, and recommends project-level fixes. Sweeps the rolling **digest** container too (Step 5.6) — the `digest`-labeled issue that collects below-materiality-floor findings the exhaust channels declined to file as records (`_shared/materiality-floor.md`): promotes a cluster of related entries into a real work record, expires stale ones, and rolls the container over at its comment cap. The container itself is exempt from staleness deletion — only this sweep ever closes it. Also audits GitHub state — stale open PRs, code-health/harness-health/journey-health/docs-health-filed issues, addressed-but-unresolved review threads — with GitHub mutations (close, resolve) executing only after batch approval. Pass `--scope=<name>[,<name>...]` to narrow a run to specific scan steps (e.g. `--scope=github` for GitHub PR/issue triage only) instead of the full sweep. A report over 40 rendered lines is not sent whole: the full report is written to `{run-dir}/report.md` and chat carries a condensed report — the Approve section in full, Yours as group heads with their batch commands, everything else collapsed to counts.

**`/claude-tweaks:demo`** — The durable acceptance gate: gives one built thing a real human verdict — approve or request changes — distinct from tests passing (`/test`) or code-quality review (`/review`). Bare `/demo` resolves this session's own unrecorded work via session-recall; `/demo #N` resolves that specific record's Verification Brief (open or closed — covers already-merged `auto:merge` work too); `/demo #N,#M` takes an explicit list one item at a time — each ref runs to its own verdict before the next begins, never a combined verdict, never a backlog sweep. It executes the brief's `### Observation plan` show-first — running Prepare commands, validating URL surfaces headlessly, then opening/running/rendering the entry point in front of you — before asking a single Approve / Request changes / Skip verdict; briefs posted before the observation-plan schema keep the older self-check flow. When a record carries no `demo:pending` label — e.g. it was built ad hoc and closed by a `Fixes #N` commit, skipping `/wrap-up`'s labeling step — `/demo` reconstructs a brief from that closing commit, and only falls back to session-recall scoped to that `#N` if no closing commit exists. A reconstruction says so in its own Confirmed section: it reports what the commit evidences, never verification nobody performed. Approve resolves a label-backed record to `demo:approved`; for a session-recall entry, Approve/Skip write nothing anywhere — the verdict just lives in the conversation. Requesting changes always files a linked follow-up backlog record, label-backed or not. Discovery of what's outstanding across the backlog is `/claude-tweaks:help`'s job (Stage 4.7), not `/demo`'s.

**`/claude-tweaks:browse`** — Browser automation via agent-browser. Defines session naming, screenshot/trace paths, and operation vocabulary used by /stories, /visual-review, and /review.

**`/claude-tweaks:research`** — Deep web research with citation-audited reports. Four runtime modes from quick (~2-5 min) to ultradeep (~20-45 min, multi-persona red-team). Delegates to Claude Code's built-in `/deep-research` Dynamic Workflow when available; falls back to a lean inline method otherwise. Reports land under `.claude-tweaks/research/`. Its `verify [brief-path|#N]` mode is the exception to "no fixed lifecycle position" — it grounds a design's assumptions against this repo, its dependencies, and the web, run before `/superpowers:brainstorming` (human-invoked, not reachable from `/flow`).

**`/claude-tweaks:ledger`** — Query and resolve the open items ledger (`docs/plans/*-ledger.md`) that tracks findings across all pipeline phases. The ledger is a file on disk — it survives context window compression so findings from one phase aren't lost before a later phase can act on them.

**`/claude-tweaks:code-health`** — Proactive, report-only repo-improvement finder. An LLM judges the repo against a criteria catalog, calling deterministic tool checks as evidence. Deterministic helpers handle scope rotation, content-hash skip (unchanged areas are skipped), fingerprinting, dedup against open GitHub issues, and issue filing. Workflow: SCOPE → CLASSIFY → JUDGE → validate-findings → file issues. A second scoping mode, `focus=<vertical>`, swaps SCOPE/CLASSIFY for a deterministic candidate generator (one vertical shipped so far: `focus=dead-code`) while JUDGE → validate-findings → file issues stay unchanged — see `plugin/skills/code-health/focus-mode.md`. Never edits code. Filed records are spec-shaped and born `ready` by construction — they skip `/specify` entirely and promote into agent-sized work with near-zero translation. Runs on a scheduled Routine for continuous coverage. Merged records close their issues through your own merge action — `Fixes #N` lines ride the merge commit or PR body; the pipeline never closes issues directly. Any records code-health files feed into `/claude-tweaks:backlog refine`'s `ready` queue, which grants `auto:build`/`auto:merge` for autonomous building; `/claude-tweaks:dispatch` then selects each authorized group and hands it to `/flow`, which claims it (via an atomic create-only write to `claims/issue-{N}.json` on the `claims-registry` branch, so concurrent consumers — a scheduled routine, a second machine, a collaborator's agent — never double-build) at its own Step 2.8 — `/flow` itself never selects records. Stale claims (crashed runs) are swept by `/tidy`. `/init` offers a GitHub issue form so human-filed issues arrive pipeline-ready. For projects that land fixes on an integration branch before the default branch, `/init` also offers a companion GitHub Actions workflow that labels and comments on the affected issues until the fix reaches default and GitHub's native close fires.

**`/claude-tweaks:backlog`** — Three modes over the open work-record backlog: `refine`, `overview`, and `attention`. Machine-granting is not a separate mode — it's `refine`'s own **headless posture** (`--source routine`, the form a scheduled Routine fires; `grant` survives only as a deprecated alias forcing that same posture regardless of `--source`). `refine` ensures every record carries the right `priority:*`/`**Related:**`/grant labels: accepts an optional `--origin <code-health|harness-health|journey-health|docs-health|capture|human>` filter narrowing the worklist, pulls ungranted `ready` records, gets a content-aware recommendation from `/claude-tweaks:assess-agent-autonomy`'s `grant-check` mode (reads the record's actual body, not just its risk/size labels — and refuses unconditionally when the record carries `needs:definition`), re-verifies spec shape before granting (a `ready` label alone never authorizes — the gate re-fetches the body), and — together with a bounded LLM synthesis pass over missing-priority records producing `priority:*` suggestions and detected `**Related:**` cross-references — renders everything as seven decision lanes (Re-authorize/Grant/Flag-back/Needs-decision/Priority/Dependency repair/Needs you), trust shown as consequence lines fetched only at `trusted`+/`--trust`, applied, in the human-present posture, after one confirm gate (a human executes the actual label write there, even when the recommendation is accepted as-is) — `refine`'s headless posture below skips that gate entirely. A record that's already scored (`risk:*`+`size:*`) and spec-shaped but still refused by `grant-check` lands in Needs-decision instead of Flag-back — it keeps `ready` and gets a structured decision comment (`## Decision needed` — proposal, rationale, a paste-ready resolving command) rather than losing `ready` on a "needs scoring" comment it doesn't actually need; Flag-back stays reserved for a record genuinely missing scoring, failing the spec-shape check, or whose `grant-check` rendered no `RECOMMEND_BUILD`/`RECOMMEND_MERGE` verdict line at all (the `no verdict rendered` reason, #1442). A record that hit its retry ceiling (`bot:blocked`) surfaces as a re-authorization candidate. `refine #N[,#M...]` is a separate, per-record resolver — human-present only, never Routine-fired — that reads exactly the named record(s)' own unresolved decision comments and `bot:blocked` state and applies a human's per-row choice (grant anyway / build it myself / keep / park with a trigger / close / re-authorize) in one batch, distinct from the whole-queue sweep above; `refine --reset-breaker` is the standalone form that clears the global merge-lane circuit breaker and exits without touching any record. `overview` is read-only: bare mode renders a funnel decision surface (mutually exclusive stage counts via `funnelBuckets`, a collapsed trust consequence line, a parked/not-planned pointer, and a parents pointer) plus a "what to build next" recommendation, per-terminal paste blocks (the batch emitter: prioritize/specify/dispatch stages with chain, overlap, and claim integrity rules), a machine-grant outlook annotation on the `specified`/`captured` stages when the repo's policy is `unattended` with `grant-origination-enabled` (phase-1 gate counts: eligible vs mechanically refused, with reasons — plus, when non-zero, a count of human-filed records excluded before the gate chain runs, since machine-grant only ever considers agent-filed `by:*` records), and a dormant-safe needs-you lane surfacing human-owed records (`needs:definition`/`solution:unjustified`) with interactive launchers, with the full `critical`/`risk-value`/`cleanup`/`trust` lens tables one explicit argument away; it also folds in `unsynced: true` local fallback records (surfacing, never fixing them — that stays `/claude-tweaks:tidy`'s job). `attention` is read-only (`work-backend: github-issues` only): unifies every open record carrying any `needs:*` label, `solution:unjustified`, or `bot:blocked` — plus every `ready` + `shaped:headless` record carrying no `auto:build` grant (#968), i.e. a spec `/specify`'s headless `next` unit shaped that no human has reviewed — into one ranked list (dispatch's own priority-band-then-age order) with a per-row recommended action, plus two non-record rows above the list (a merge-lane circuit-breaker banner, a staged-tidy-proposals pointer) — a dedicated, standalone counterpart to `overview`'s embedded needs-you lane. `refine`'s **headless posture** (`--source routine`, `work-backend: github-issues` only, Routine-fireable) is the machine-grant unit: it applies `auto:build` (+ `auto:merge-pending` when its own checks also clear merge trust) to `ready` records whose full gate chain clears — autonomy ceiling at `unattended` plus the `grant-origination-enabled` policy opt-in, class trust verdict `clean`, agent-filed `by:*` origin, `grant-check` clear, and no floor trip (`merge-sensitive-paths`, `risk:high`, the daily grant cap, and — for a `shaped:headless` record — a fixed medium provenance floor on both risk and size, #969) — with every grant and skip audited. Both keys ship off, so grant origination is inert until a human deliberately turns them on; the posture's labeling lanes (Priority/Related/Flag-back/mechanical Dependency-repair) run zero-click regardless of that opt-in or the resolved ceiling. No mode claims, builds, or dispatches anything itself.

**`/claude-tweaks:dispatch`** — The queue consumer between the gate and the executor: select → mint the group's run directory → invoke `/flow`, which claims the group (whole file-overlap group, via an atomic create-only write to `claims/issue-{N}.json` on the `claims-registry` branch — the same lock code-health's fingerprinting relies on, so concurrent consumers never double-build) at its own Step 2.8 → settle. Bare `/dispatch` is the headless-safe drain a scheduled Routine fires — repeats the select-and-dispatch loop across authorized groups, one report per group, up to a `--budget` (default 3; `--budget 1` for a single group, `--budget all` for the whole queue); `dispatch #N` selects a specific record's whole group directly; `dispatch #N,#M,...` selects exactly the named records' groups (e.g. handed off by `/claude-tweaks:backlog refine`'s Next Actions after a grant). (`next`, `--batch-size`: deprecated aliases.) A group whose members all carry `auto:merge` — either already, or via a machine-granted `auto:merge-pending` that has sat unvetoed past `grant-veto-window-hours` (default 24h; a human removing the label before then is a permanent veto) — merges without waiting for a live approval when `/claude-tweaks:assess-agent-autonomy`'s `merge-check` mode verdicts `auto-merge` for every member (weighing diff content, review findings, and blast radius holistically — not a fixed mechanical cutoff); anything less falls back to the normal wait. A failed build's effect on `auto:merge` depends on `failure-check`'s classification: `correctness`/`ambiguous` revokes it (no repeat unsupervised attempt), `transient` preserves it. After a configurable retry ceiling, all `auto:*` grants are stripped and `bot:blocked` flags for a human to re-triage. Dispatch may only downgrade or strip a grant it reads — it never originates authorization from nothing; only `/claude-tweaks:backlog refine` grants.

**`/claude-tweaks:sweep`** — One hands-off hygiene pass over the whole queue, hands-off by construction: `/claude-tweaks:tidy --source sweep` (auto mode), then `/claude-tweaks:specify --source sweep` (the bare headless drain), then `/claude-tweaks:backlog refine --source sweep` (headless posture — labeling lanes plus the grant chain, zero clicks), all three sharing one run directory and one `decisions.md`. Sweep never claims, builds, or merges — that boundary is what makes it a legal parent of a grant-writing unit (refine's headless posture) with nobody present. Closes by rendering `/claude-tweaks:backlog attention`'s ranked needs-you list directly as its own first output block, then a `## Next Actions` recommending `/claude-tweaks:tidy --approve` (when this run's tidy step staged anything — clearing an already-vetted, zero-judgment batch leads ahead of both dispatch and any needs-you pick) or otherwise `/claude-tweaks:dispatch` to drain whatever the run just authorized.

**`/claude-tweaks:pipeline-smoke-test`** — Cross-session integration test of claude-tweaks' own capture → specify → backlog → dispatch pipeline against live `git`/`gh` state, using genuinely separate `claude` CLI processes (not simulated within one conversation) so a real concurrent claim-race can actually occur. Files one throwaway, clearly-labeled test issue, deliberately fires two concurrent `/claude-tweaks:dispatch` claim attempts against it, verifies exactly one succeeded from live claim state (never from either process's own narration), then closes the issue and re-verifies every artifact's absence rather than trusting the cleanup step's exit code. Never reaches `/claude-tweaks:build` (stops at the claim step) and is human-invoked only — never part of an unattended `/flow`/`/dispatch` run.

**`/claude-tweaks:routine`** — Instantiates a skill's plugin-shipped routine template (e.g. code-health's) into a live Claude Code cloud Routine for the current project, resolving account- and project-specific values (environment, repo) that a portable template can't hardcode, then calling `RemoteTrigger` directly — no manual `/schedule` walkthrough needed. Writes a committable instantiated record to `.claude-tweaks/routines/`. Supports `create`, `update`, and `status`, plus `status --all` for a bulk drift check across every instantiated routine and `update --defaults` for non-interactive batch re-sync, plus `--dry-run` to inspect the assembled configuration before anything is created. `webhook-trigger <skill> --events <e1,e2,...> [--filter <field>=<op>:<value>[,...]]` attaches a GitHub-event trigger (author/title/body/base-branch/head-branch/labels/is-draft/is-merged, each with equals/contains/starts-with/is-one-of/is-not-one-of/matches-regex) to an already-existing routine via `create_webhook_trigger`, so the routine also fires on matching GitHub activity in addition to its schedule; `status`/`fleet status` then surface how many triggers are attached. `fleet on` provisions the whole self-maintaining posture in one deliberate action: a policy Manifesto over the autonomy/grant levers, then a staggered create-or-reconcile loop over the fleet composition table (four focus-scoped code-health finders, the generalist health sweeps, the bare `/specify` drain shaping unit, the conditional backlog-grant unit, the dispatch drain, and tidy) — idempotent on re-run. `fleet status` is a read-only aggregation of the fleet-marked routine table, the per-class trust table, and rolling-week counters (firings, findings filed, grants issued, merges, revocations) each with its source and blind spot stated inline; a supervised fleet renders no grant counters and states why. `fleet off` is pause-based shutdown that never deletes anything — it pauses every fleet-marked routine via the skill's `pause` action (a single-field `RemoteTrigger update` setting `enabled: false`); durable state (records, rotation cursors, wontfix suppressions, trust history) survives, and `resume <skill>` reverses it per routine.

**`/claude-tweaks:routine-kickoff`** — The firing-lifecycle wrapper a routine kernel invokes at fire time (best-effort `plugin/bin/hooks.js reconcile`, then the target skill). Machine-invoked only, never directly by a human.

**`/claude-tweaks:harness-health`** — Recurring health check for `.claude/skills/*.md`, `.claude/rules/*.md`, and CLAUDE.md: picks one target to audit against the codebase (or checks for a new-skill gap), judges it via the shared `_shared/harness-health-analysis.md` procedure — also used by `/init` Phase 6, `/wrap-up`'s Skills curation row, and `/wrap-up`'s CLAUDE.md & rules curation row (via `claude-md-curation.md`'s `assetType: claude-md`/`rule`) — and always files a `harness-health`-labelled GitHub issue. Never edits anything directly (skills, rules, memory, or CLAUDE.md) — report-only, matching `/code-health`. Runs on a scheduled Routine for continuous coverage, rotating through skills, rules, and CLAUDE.md via a churn/staleness cursor shared with `/init` and `/wrap-up`. Memory (`~/.claude/projects/{slug}/memory/`) is audited only via an explicit `--kind memory --memory-dir <path>` invocation — never through the Routine's automatic rotation.

**`/claude-tweaks:journey-health`** — Recurring health check for `docs/journeys/*.md`: picks one journey to audit (or the decoupled coverage scan, when due), checks it against the codebase (file-existence, self-review criteria shared with `/claude-tweaks:journeys`, journey-story coverage shared with `/claude-tweaks:review`'s `3g-cov` lens), and always files a `journey-health`-labelled GitHub issue. A separate, interactive-only deep tier (`--deep`) actually runs the journey's QA stories via `/claude-tweaks:test` (or walks it live via `/claude-tweaks:visual-review` when no stories exist yet) and judges whether a failure means the journey/story text is stale or the app genuinely regressed. Never edits journeys, stories, or code — report-only, matching `/code-health` and `/harness-health`.

**`/claude-tweaks:docs-health`** — Recurring health check for `docs/**`: picks one doc to audit, judges it against the shared `_shared/criteria-docs-diataxis.md` procedure — Diátaxis genre-drift (implied doc type vs. actual content shape), depth-mismatch (implied reading investment vs. actual word count), findability (can a reader or agent actually discover this doc), factual staleness, and dual-persona misleading-risk tagging (human engineer vs. coding agent) — and always files a `docs-health`-labelled GitHub issue. Never edits docs content — report-only, matching `/code-health` and `/harness-health`. Scoped strictly to `docs/**`, excluding `docs/superpowers/**` (ephemeral build artifacts) and never overlapping `harness-health`'s `.claude/skills/**`/`.claude/rules/**`/CLAUDE.md territory. Runs on a scheduled Routine for continuous coverage.

**`/claude-tweaks:design-wrapper`** — Wrapper for the [Impeccable](https://github.com/pbakaus/impeccable) frontend-design plugin. Modes include:

- **`test`** — invoked by `/test` for the deterministic CLI gate (`npx impeccable detect`)
- **`review`** — invoked by `/review` for LLM `critique` + `audit`, plus project-local craft critics from `critics.md` under the `design-critique` lever (Step 3.8; advisory findings; writes audit cache for `polish`)
- **`shape`** — invoked by `/specify` on frontend design docs (runs `/impeccable shape`, output appended to design doc)
- **`pre-build`** — invoked by `/build` to lazy-load Impeccable references + project design context (`docs/design/PRODUCT.md`, `DESIGN.md` from `/impeccable init`) into the implementer subagent
- **`polish`** — invoked by `/flow`'s polish phase to dispatch the refinement set (`polish` / `clarify` / `harden`) + suggestion-driven (`typeset` / `layout` / `adapt` / `optimize`, each dispatched only when an `audit` finding's own `suggestion` names it) + intent-driven (`bolder` / `quieter` / `distill` / `delight`+`animate` / `onboard` per spec's `design-intent:` frontmatter) commands. **First wrapper mode that modifies code** — `/flow` follows up with the re-verify gate.
- **`survey`** — invoked by `/visual-review` (with screenshots) and `/flow`'s pipeline summary (with the full diff). Produces ranked Creative Opportunities recommendations spanning intent-driven and manual-only commands (`colorize` / `extract` / `overdrive`). Read-only — never invokes commands. Per-spec declined-recommendation tracking suppresses noise after 2 declines; reset via `/claude-tweaks:design-wrapper reset-recommendations <spec>`.
- **`live`** — invoked by `/specify`'s shape-time variant-exploration step and `/visual-review`'s standalone Boost gate. Thin dispatcher to Impeccable's own interactive `live` command (element picker, real HTML/CSS variants, live parameter tuning, accept-to-source cleanup). Interactive-only — no auto-mode branch, by the same reasoning `live` itself has none.

The wrapper produces three independent surfacing anchors so creative commands cannot get buried: intent dispatch in polish, the Creative Opportunities block in `/visual-review`, and the Creative Opportunities block in `/flow`'s pipeline summary.

Handles 3-layer detection (kill-switch / spec frontmatter / file-extension sniff) so non-frontend specs skip cleanly. Set up by `/init` Step 11. Per-spec caches (`*-audit.json`, `*-recommendations.json`, `*-declined.json`) live in `docs/plans/` and are cleaned up by `/wrap-up`.
