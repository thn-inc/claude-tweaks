# Multi-Spec — Pre-flight Failure Ruling (#3351)

Loaded by `multi-spec.md`'s Validation step 3 — and, for a one-record run, `validation.md`'s 2.7b — before Step 2.8's claim, when the `preflight-records.js` call exits non-zero or `gh` is unavailable.

**Transport.** With `gh` present, step 3's call runs as written. With `gh` unavailable (`_shared/github-write-transport.md`'s routing), fetch each target via MCP `issue_read` (get mode), reusing step 1's already-fetched records where present. Reshape each to `gh issue view`'s `{number,title,body,labels,url}` (`materialize.md`'s `--record-json` paragraph, #1459), write the array to a session-scoped temp file (`_shared/session-tmp-root.md`), and add `--records-json {file}` to the same call. That path makes no `gh` call, so it never exits 1. If an `issue_read` fetch fails, that is a **STOP before claiming** naming the record — never write a partial file.

**Exit 0.** Proceed. Steps 4, 4a, 4b and 5 read the envelope.

**Exit 1 (`gh` transport).** Re-run the identical call once. A second exit 1 is a **STOP before claiming**, quoting stderr, which names every failing record on a record-fetch failure (a `work-links: native` GraphQL failure also exits 1, with no record named, and so does a `--blocker-landing` blocker-query failure — a `preflight-records.js: blocker landing query failed:` line, never an `undetermined` verdict; judge by the exit code and that prefixed line, as `gh`'s own stderr can precede it). Under `parallel`, the exit-1 re-run without `--waves` in `multispec-parallel-waves.md` is that one retry, never a third call. Nothing needs tearing down: this run has made no claim, worktree or run-dir write yet. Under a `/claude-tweaks:dispatch` bundle, the STOP is that bundle's failed run.

**Exit 2.** **STOP before claiming**, no retry, quoting stderr. It is an invocation bug, an unresolvable owner/repo under `native` or for a non-empty `--blocker-landing` blocker set, a `--blocker-landing` blocker number that is no valid issue number (a `Blocked by #0` line), a bad `--records-json` or `--blocker-states-json` input (missing or unparseable file, wrong shape, a requested record missing or extra), or a `--waves` cycle that step 4 would hard-fail on anyway. Under `parallel`, a `--waves` cycle is also a STOP, never a re-run without `--waves`.

**`nativeLinksUnchecked: true`.** Proceed. Ordering, the merge-state gate and (under `parallel`) the wave plan run on body-text `blocked-by` only. Once the parent run directory exists (after Step 3's Manifesto write, as `multispec-merge-gate.md` times its own entries), write one `SKIP`:
```
node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "$PIPELINE_RUN_DIR" --section "/flow" --status SKIP --step "Step 1 native dependency links (skipped)" --text "condition: gh unavailable under work-links: native, preflight-records.js --records-json reported nativeLinksUnchecked → fallback: blocked-by read from record bodies only; native-only links are invisible, so cross-record ordering, the merge-state gate and (under parallel) the wave plan ran on body-text dependencies (dispatch/mcp-transport.md, #2523)." --reversibility n/a
```

**Blocker landing.** With `gh`, the exit-0 envelope's `blockerLanding` is what `multispec-dependency-ordering.md`'s verdict table reads. Under `--records-json` there is no `gh`, so the open-blocker stop holds only if the caller supplies each out-of-run blocker's state: the first call (no states file) lists every out-of-run blocker in `blockerLanding` as `undetermined` with `via: records-json`; when none are listed, that envelope stands. Otherwise fetch each listed blocker with MCP `issue_read` (get mode), write `{ "{blocker}": {"state": …, "stateReason": …} }` with the Write tool to a session-scoped temp file (`_shared/session-tmp-root.md`), copying `state` and `stateReason` from `issue_read`, and re-run the same call with `--blocker-states-json {file}`. On that second envelope an open blocker reads `open` (hard fail), a `NOT_PLANNED`/`DUPLICATE` one `not-applicable`, and every other closed blocker `undetermined` (`via: records-json` — no compare API without `gh`), so the run proceeds and writes the per-blocker `SKIP` from `multispec-dependency-ordering.md`. A listed blocker that `issue_read` cannot fetch (deleted, transferred, or a typo'd `Blocked by #N`) is a **STOP before claiming** that names it — fail-closed: no state, no entry, so the CLI's exit 2 enforces it, and removing the edge (`multispec-dependency-ordering.md`'s escape 2) clears it. The transports differ here on purpose: on the `gh` path an unresolvable blocker reads `undetermined`/`not-found` and proceeds with a `SKIP`, but the states file cannot express not-found, so on this path it is a STOP. A states-file problem (a listed blocker missing, an unusable state) is exit 2 — a **STOP before claiming**, like every `--records-json` input problem. A blocker-query failure on the `gh` path is exit 1, never `undetermined`.

**Never** read a stopped run as "no dependencies". Never fall back to body text when the `gh` path's native call fails; that is exit 1.
