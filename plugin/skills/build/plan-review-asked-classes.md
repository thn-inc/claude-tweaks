# Common Step 1.6 — Asked-Classes Routing (#6051)

Read by `plan-review.md`'s planning-decisions pointer only when `planning-decisions` resolves `asked-classes`; under the default `ask-all` this file is never read. It applies `_shared/planning-decisions.md` to plan review. That file states the asked classes, the settled path, the doubt rule, the line forms and the asking rule; this file cites them by section name and only says where each lands in plan review's routing.

## Scope

This file applies after `plan-review.md`'s Reading the reply, to every needs-human row: the reviewer's, and every row Reading the reply promoted. Under `asked-classes`, `plan-review.md`'s `### Converged round (#4958)` does not apply and its `Settled by plan review after an answered round:` lines are not written. Every amendment line goes in a `## Planning Decisions` section of the worktree's `work/{n}-spec.md` instead of `## Plan Review Clarifications`, and wherever `plan-review.md` names that section as the trail, read `## Planning Decisions`. Everything else in `plan-review.md` (dispatch, prompt, Reading the reply, the intent-resolvable sequence, the HARD-GATE branches) applies as written.

## Routing

1. **Classify.** Classify each needs-human row against `_shared/planning-decisions.md`'s `## Asked classes` and `## Doubt rule`. Read the kept flags from the worktree spec's `Risk-flags:` line. The declared categories follow `## Doubt rule`'s control-mode rule: run `node "${CLAUDE_PLUGIN_ROOT}/bin/resolve-policy.js" --values control-mode`, and only when it prints `on`, read the extras with `node "${CLAUDE_PLUGIN_ROOT}/bin/resolve-policy.js" --values risk-categories` (reads only; plan review runs no classifier, so no record is reclassified here). When either read fails or prints nothing, the declared set is the four built-ins only. A failed or empty read logs one `SKIP` under this step's `/build` section and step with `--text-file "{text-file}"`, `{text-file}` written with the Write tool to the path `node "${CLAUDE_PLUGIN_ROOT}/bin/session-tmp-resolve.js" --value decision-text-{run-id}-planning-policy.md` prints, holding the one line `condition: {control-mode|risk-categories} read failed ({reason}) → fallback: declared categories are the four built-ins` (`_shared/auto-decision-log.md`'s Text from git or a user rule).

2. **Answered round.** A row that a recorded decision already answers (a `Decided by the user at planning:` or `Decided by the user at plan review:` line, a `**Decision**` paragraph, or a Closed rule) is settled by `_shared/planning-decisions.md`'s `## Line forms` answered-round rule, with a `Decided by the user at planning:` line quoting that decision, and is never asked again. When such a row meets step 3's condition, it also runs step 3's `risk-flags.js add` without asking, and adds its `Proof({slug}):` plan line, so an answer recorded without the flag still leaves the implementing build owing that flag's Check G proof. A failed `add` here writes no `Proof` line and asks nothing (the row stays answered); it logs one `SKIP` under this step's `/build` section and step with `--text-file "{text-file}"`, `{text-file}` written with the Write tool to the path `node "${CLAUDE_PLUGIN_ROOT}/bin/session-tmp-resolve.js" --value decision-text-{run-id}-planning-answered-flag-{k}.md` prints (`{k}` numbering this step's answered rows flagged in this reply from 1), holding the one line `condition: risk-flags.js add exited {code} ({stderr line}) on an answered row → fallback: answered row settled without the flag` (`_shared/auto-decision-log.md`'s Text from git or a user rule). Each answered-round row also gets step 4's `AUTO` line and record comment: one `AUTO` per row through the same `--text-file "{text-file}"` form, `{text-file}` holding its `Decided by the user at planning:` line (path from `node "${CLAUDE_PLUGIN_ROOT}/bin/session-tmp-resolve.js" --value decision-text-{run-id}-planning-answered-{k}.md` prints, `{k}` numbering this reply's answered rows from 1), and that line rides the same record comment.

3. **Class (b), unflagged category.** When a row plainly falls in a declared category the spec's `Risk-flags:` line does not keep, run `node "${CLAUDE_PLUGIN_ROOT}/bin/risk-flags.js" add --body-file "{worktree spec}" --add {slug} --repo-root "{worktree root}"` before the question is asked, add a `Proof({slug}):` line to the plan, and commit both with the other amendments. Add, never drop: no other `risk-flags.js` verb runs here. In a dispatched call or `parallel`-wave member, the `add` edit and its `Proof({slug}):` plan line ride in step 5's early commit, before the question comment is posted. A non-zero exit still asks the question. A failed `add` writes no `Proof` line. It logs one `SKIP` under this step's `/build` section and step with `--text-file "{text-file}"`, `{text-file}` written with the Write tool to the path `node "${CLAUDE_PLUGIN_ROOT}/bin/session-tmp-resolve.js" --value decision-text-{run-id}-planning-flag-{k}.md` prints (`{k}` numbering this step's flagged rows in this reply from 1), holding the one line `condition: risk-flags.js add exited {code} ({stderr line}) → fallback: question asked without the flag` (`_shared/auto-decision-log.md`'s Text from git or a user rule).

4. **Settled rows** (outside (a), (b) and (c)). Pick the reading by `_shared/planning-decisions.md`'s `## Settled path` and apply it through `plan-review.md`'s intent-resolvable sequence: one commit, one record comment and one re-audit, shared with every other amendment from this reply (when some rows are also asked, step 5 says which commit that is). In that sequence's step 1, the settled line stands in for the Evidence quote, and the criterion check there judges only the chosen reading, which keeps every Acceptance Criterion by construction, so a settled row never returns to needs-human. Log one `AUTO` per settled row:

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "$PIPELINE_RUN_DIR" --status AUTO \
     --section "/build" --step "Common Step 1.6 (plan review)" \
     --text-file "{text-file}" --reversibility high
   ```

   having first written `{text-file}` with the Write tool, holding the one line `Settled at planning: {finding} — chose {reading}; not {other reading}` (path from `node "${CLAUDE_PLUGIN_ROOT}/bin/session-tmp-resolve.js" --value decision-text-{run-id}-planning-settled-{k}.md`, `{k}` numbering this reply's settled rows from 1; `_shared/auto-decision-log.md`'s Text from git or a user rule). Write that same line under `## Planning Decisions`; the record comment carries that line verbatim. A settled row produces no `AskUserQuestion`, no question comment and no `failed: plan-review-needs-human`. This holds in every mode — `auto`, `confirm`, `interactive` and `hybrid` — and in a dispatched call or `parallel`-wave member: when every needs-human row settles, the build continues to Common Step 1.7.

5. **A reply with asked rows** (at least one row is asked, whether or not others settle). With a present human, the settled rows wait for the answers and join `plan-review.md`'s single post-answer amendment sequence: one commit, one comment, one re-audit, as `## Handling by class` already does for every other amendment. Only the branches that block — a dispatched call and a `parallel`-wave member — commit early, whenever they hold settled rows or step 3's flag additions: those go in one intent-resolvable commit before the HARD-GATE branch posts its question (settled rows are also logged and commented there), so a blocked call still leaves its settled lines committed. Answered-round rows (step 2) count as settled rows for this early commit: their `Decided by the user at planning:` lines and any step-2 flag edit with its `Proof` line ride it. A blocking reply whose rows are all asked still gets this commit when step 3 added a flag, holding only those flag edits and their `Proof` lines. When no settled row exists, the re-audit (`plan-audit.js … --spec`) still runs on the amended pair, and no amendment record comment is posted, because the question comment carries the flag. Every non-settled amendment row in those branches stays unapplied, as today. This replaces `plan-review.md`'s rule that a blocking call applies nothing, for settled rows and step 3's flag additions only. The question set and the question comment list only the asked rows. In those branches, the question comment for each row step 3 flagged names `{slug}` and tells the answerer to add `{slug}` to the record body's `Risk-flags:` line along with their `**Decision**` paragraph, because the resumed run re-materializes the spec from the record.

6. **Asked rows** ((a), (b) and (c)). They reach `plan-review.md`'s `### Spec gap — needs-human` HARD-GATE exactly as today, in every posture, as one question set, except that each question's options are the recommended reading first, labelled `(Recommended)`, then the other reading, then `Stop the build` (`_shared/planning-decisions.md`'s `## Asking`; the question comment lists them in the same order). An answer is recorded as `Decided by the user at planning: {finding} — chose {reading}; not {other reading}`.

7. **Standalone `/build`** (no run dir). Settled rows are listed in the handoff's `### Plan review amendments (standalone build, if any)` section, as `plan-review.md` already does for its amendments.
