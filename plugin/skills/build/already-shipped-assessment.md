## Already-shipped assessment (#2502)

Distinct from the mechanical `Premise-check:` routing above — this is a judgment call the assessment makes for every record, not something gated on a `Premise-check:` line being present. Before searching for a plan, read the spec's own Deliverables and Acceptance Criteria sections and check each item against the current codebase (the same kind of read "Check what's already implemented" below already does, just run up front, before assuming there's a plan to write or work to do). When **every** Deliverable and Acceptance Criterion is already satisfied on the base branch with **zero implementation diff required** — not "close enough," not "the intent is covered by a different approach," but the literal deliverables already present — stop here instead of proceeding to Spec Step 3 or Common Step 2:

1. **Report `OUTCOME: already-shipped`** — a fourth value alongside `build-test-ok`/`build-test-failed`/`build-test-blocked` in this call's OUTPUT FORMAT (`dispatch/task-prompt.md`'s first-call template) when running under a dispatched `/flow`. This is a clean, non-error terminal outcome, not a HARD-GATE failure — do **not** invoke Settle (`dispatch/settle-and-merge.md`) for it; Settle's failure classification, retry counting, and failure comment all assume something went wrong, and nothing did.
2. **Stage a Close proposal** for the record, reusing `plugin/bin/lib/issues/shipped-candidate.js`'s proposal shape — the same shape `dispatch/queue-pull-script.md`'s pre-dispatch shipped-candidate exclusion already stages — rather than composing a new one. Name the base-branch commit(s)/PR that already satisfy the record as the evidence.
3. **Close any draft PR the pr-early lifecycle already opened** (Spec Step 1 always runs it before this assessment, non-skippably): `gh pr close {number} --repo {owner}/{repo} --comment "Closing: this record's deliverables are already on {integration-branch} — see the staged Close proposal filed on the record."` Never leave a bookkeeping-only draft PR open for a human to find and close by hand.
4. **Release the record's claim** now (`_shared/issue-claims.md`'s release path, reason `already-shipped`) — this run is finished; there is nothing left to build, and nothing later in the pipeline needs to hold it.
5. **Do not commit a "verified already implemented, no code changes" bookkeeping doc** — that commit (and the draft PR it used to justify) is exactly the cost this assessment exists to avoid (#2502's own Current State). The materialize commit from Spec Step 1 stays as the run's only commit.

`dispatch/sequential-execution.md`'s two-call gate (`two-call-gate.md` §7) reads this outcome and skips the second `review,polish,wrap-up` call entirely — the run is done, not pending review. When even one Deliverable or Acceptance Criterion item still needs real work, however small, this is a normal build: proceed below exactly as before.
