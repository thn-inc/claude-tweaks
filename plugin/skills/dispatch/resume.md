# Dispatch — Resume (a stalled build on its own open draft PR)

The gap this mode closes (#4588): a dispatched build that stops before the test gate (a BLOCKED first call, a plan-review question, a crashed or rate-limited child) leaves a draft PR, a kept worktree and a run directory. `dispatch #N` then refuses the record — Step 2's queue drops it as `open-pr` — and `close-out` only handles a finished `pending-review` PR. `dispatch resume #N` restarts that one record on the PR it already has. It is typed by a human, never fired by a Routine, and dispatches the record alone: Steps 2-3 (queue pull, selection) do not apply.

The eligibility rule is one verdict, computed by `bin/dispatch-resume.js` (the gatherer over `bin/lib/dispatch/resume-eligibility.js`). The open-pr report line reads the same verdict (`open-pr-exclusion-report.md`), so the remedy is named only where this mode would accept the record. `{main}` below is the main checkout's root and `{root}` its `.claude-tweaks/pipelines/`. The PR is always found through the record's closing-reference connection (`closedByPullRequestsReferences`, the one the queue's exclusion reads), so any head name resolves — never from the queue's exclusion file, which has no entry for a record the label pre-filter already dropped (`bot:in-progress`). `worktreePath` derives from the PR's head (`worktree-{name}` -> `.claude/worktrees/{name}`; a head without that prefix is the name itself), and the prior run from the PR body's marker.

**Step 1 — Preflight and the run-id rule, as for `#N`.** Run `SKILL.md`'s Preflight and resolve this firing's `$RUN_ID` per Step 1, exactly as the explicit `#N` form does. Step 1's close-out runs on every exit below that follows a minted `$RUN_ID`.

**Step 2 — Gather the verdict, before anything is minted.** Run `node "${CLAUDE_PLUGIN_ROOT}/bin/dispatch-resume.js" --issue {N}`. It prints one JSON line. Exit 0 is eligible: `{eligible:true, issue, prUrl, prNumber, headRefName, priorRunId, priorRunDir, priorRunPath, archivePriorRun, closePriorRun, worktreePath, localBranchExists, context:{lastPhase, openDefects}}`. Exit 3 is a refusal, `{eligible:false, issue, reason, line, prNumbers, disposition, remedy, headRefName}` (plus `liveRun: true` when a run's owner is provably live, the prior run's or another run's bound to the stalled worktree, whatever the refusal's reason): print `line` verbatim as the whole refusal and stop, or `remedy` verbatim in its place when `disposition` is `close`, since `remedy` carries the full steps and names a fork PR that keeps the record excluded — never paraphrase it, and mint nothing. `prNumbers`, `disposition` (`resume`, `close-out` or `close`; null for `no-pr`) and `remedy` are also what `/claude-tweaks:backlog attention` renders for a human. Exit 2 (malformed argv, `gh` absent, main checkout or repo slug unresolved) and exit 4 (a read failed transiently) stop with the CLI's stderr. The refusals include (the list is not exhaustive): no open PR closes it (a plain dispatch applies); more than one open PR closes it (close the extra one; a non-draft among them reads review by hand); a PR from another record or a live sibling session (the open-pr line); a PR closing more than one record (`multi-record-pr`) or a PR from a fork or another repository (`cross-repo-pr`), each naming the PR, never `no-pr`; a non-draft PR, or a `pr-opened:` tombstone (the `close-out` remedy, `/claude-tweaks:dispatch close-out #N`; a non-draft PR is never told to close, so a foreign, multi-record or cross-repo one reads `close-out` or review-by-hand; when the marker's run dir is in neither `{root}` nor its archive, the close-out remedy reads review-by-hand instead, since close-out would stop `no run dir`); a live claim (already claimed); `bot:blocked` or no `auto:build` (`/claude-tweaks:backlog refine #N`); `bot:in-progress` without a stale claim (remove the label); a prior run whose owner is not provably dead by the owner-process probe, or whose owner is recorded on another host (refused, never read as dead); a stalled worktree with uncommitted edits (refused with every dirty path listed — resume never commits, stashes, discards or pushes them) or on a branch other than the PR head; a closed issue, an open `Blocked by` dependency, or any other `bot:*` label such as `bot:parked` (the queue's own gates, which resume would otherwise skip); a reaped worktree whose local branch differs from the PR head or is checked out elsewhere; a claim whose run id differs from the run the PR marker names (`run-mismatch`, both ids named); another non-terminal, non-ad-hoc run dir bound to the stalled worktree — `concurrent-resume` while its owner may be live, `stale-bound-run` naming `hooks.js close-run` on that dir when the owner-process probe proves it dead. Any other state the eligible list does not name is refused under the Closed rule: the line names the state and the manual remedy. The CLI's sibling-session check already excludes this session's own kept lock on the stalled worktree: it reads the prior run's `run-state.json` session id, because `ownedWorktreePaths` reads only top-level run dirs. It reads `#N` by token, then an exact match on the PR's head and worktree (`findSessionOnWorktree`), because a head may hold no record number.

**Step 3 — Archive the prior run, when `archivePriorRun` is true.** `archive-run` commits whatever the main checkout has staged, so first confirm the index is empty: `git -C {main} diff --cached --quiet`; staged changes → print that and stop before the mint. When `closePriorRun` is true, run `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" close-run --run "{priorRunPath}"` first, then `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" archive-run --run "{priorRunPath}"`, and verify `{root}/archive/{priorRunId}` now exists; if `close-run` or `archive-run` fails, or the archive dir is missing, print the failing command's output and stop before minting. A `stateless` prior dir (`priorRunDir: 'stateless'`) is not archived — `archive-run` refuses a dir with no `run-state.json` — it is logged at Step 6b and left to reconcile's orphaned-run cleanup. An `archived` or `absent` prior run needs nothing here.

**Step 4 — Mint, as for `#N`.** Mint the run directory with `resolve-run-dir --create` exactly as `SKILL.md` Step 4 runs it (`--spec-slug "record-{N}"`); call the result `$GROUP_RUN_DIR`. Only the mint runs: Step 2's CLI replaces Step 4's `check-sibling-sessions` and drain-overlap checks (the first has no own-kept-lock exclusion and would refuse this session's own resume). No claim is written here.

**Step 5 — Enter the existing worktree by path.** `EnterWorktree(path:)` on `worktreePath`. When it is missing, run `git -C {main} fetch origin {headRefName}`, then `git -C {main} worktree add {worktreePath} {headRefName}` when the CLI reported `localBranchExists: true`, or `git -C {main} worktree add -b {headRefName} {worktreePath} origin/{headRefName}` when `false`, then enter it. `localBranchExists` is meaningful only when the worktree is missing (it is always `false` when the worktree exists), and a `true` is already proven equal to the PR head and checked out nowhere else — `branch-diverged` and `branch-checked-out` refuse it before the mint otherwise. This deliberate re-entry is exempt from `sibling-session-check.md`'s Worktree-resume check: a resumed worktree is the point here, not a conflict signal, so do not `ExitWorktree` over it.

**Step 6 — Bind the run (`record-worktree --dispatch`).** As Step 5 of `SKILL.md` does: `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" record-worktree --run "$GROUP_RUN_DIR" "{worktreePath}" --dispatch`. Expect the `claude-tweaks: worktree recorded for` line.

**Step 6a — Repeat the sibling check, now bound.** Run `node "${CLAUDE_PLUGIN_ROOT}/bin/dispatch-resume.js" --issue {N} --bound-run "{new run dir}"` (the minted `$GROUP_RUN_DIR`) — never `check-sibling-sessions` alone: Step 6's binding puts `worktreePath` in `ownedWorktreePaths`, so the lock check skips it whichever live session holds its lock, and only the run-dir scan inside `--bound-run` sees a second resume bound to the same worktree. It prints `{concurrent:false}` (exit 0, go on to Step 7) or `{concurrent:true, reason:'concurrent-resume'|'live-sibling'|'stale-bound-run', line}` (exit 3; a provably live owner adds `liveRun: true`, which changes nothing here — every exit 3 stops the same way). It reads the worktree from the bound run's own stamp (what Step 6 wrote), and its sibling check reads `#N` by token, then that worktree exactly. Without a `CLAUDE_CODE_SESSION_ID`, `record-worktree` stamps no `sessionId`, so this check refuses `live-sibling` on this session's own lock (fails closed). Fail closed: exit 3, exit 2 (`--bound-run` outside the main checkout's pipelines dir) and exit 4 (the run-dir listing failed, or the bound run carries no worktree stamp) all stop the same way, in this order: print `line` verbatim (the stderr for exit 2/4); run `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" close-run --run "$GROUP_RUN_DIR"` (Step 6's binding left the new run `active`, and a leftover active dir bound to this worktree would make every later resume refuse); a failed `close-run` (on the exit-2 path it refuses the same dir, exit 1) does not end the sequence — the ExitWorktree, the log and the stop still run; `ExitWorktree(action: "keep")`; log the stop per `_shared/auto-decision-log.md`'s Degrade-trace rule — resolve a temp path with `node "${CLAUDE_PLUGIN_ROOT}/bin/session-tmp-resolve.js" DECISION_TEXT=decision-text-{run-id}-resume-stop.md`, write the one-line text `condition: {the line, or the stderr with line breaks collapsed} → fallback: nothing dispatched` there with the Write tool, then run `node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "$GROUP_RUN_DIR" --status SKIP --section "/dispatch" --step "resume Step 7 dispatch (skipped)" --reversibility n/a --text-file "{path}"` (`--text-file` because a CLI line can hold `"`, `$` or a backtick; `log-decision.js` appends to a closed run dir too); then stop without dispatching either call. This closes the window where two concurrent resumes both passed Step 2; the claim write inside call 1 stays the atomic boundary.

**Step 6b — Log a stateless prior dir.** When `priorRunDir` is `stateless` or `residue`, log one line to the new run's `decisions.md`: `node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "{new run dir}" --status AUTO --section "/dispatch" --step "resume" --reversibility n/a --text "prior run {priorRunId}: {stateless — no run-state.json, archive-run refuses it | work/-only residue}; not archived, left to reconcile's orphaned-run cleanup"`. It runs after Step 6 on purpose: `/claude-tweaks:flow` Step 3 adopts a mint whose `decisions.md` holds anything beyond claim lines as case 3 unless `run-state.json` carries `dispatched: true` with no `pr` (`bin/lib/flow/preflight.js`, #3242), and Step 6 is what writes that marker. Reconcile's `orphaned-mint` kind (`bin/lib/reconcile/archive-merged.js` `classifyRunDir`) sweeps such a dir only when it holds no `config.yml` and is over 24 h old — the human's answer leaves the dir to reconcile, and resume does not widen reconcile.

**Step 7 — Dispatch the two calls.** The normal two-call sequence with handoff continuations, via `task-prompt.md`, with `SKILL.md` Step 5's gate between the calls and terminal-path teardown (`two-call-gate.md`). On the first call only, add `RESUME_PR="{prUrl}" ` immediately before `/claude-tweaks:flow` and substitute `{resume-context}` from the CLI's `context`; never add `DISPATCH_HEADLESS=1 ` (resume is human-typed — the rule `task-prompt.md` applies to the explicit `#N` form). The PR is reused: resume writes no PR body — `pr-early-open.js` rebinds it (#4580).

**Step 8 — Settle and close out, as for `#N`.** `SKILL.md` Step 6 (Settle) and Step 1's close-out apply unchanged.

## Claim cases and invariants

- A `failed:`, `abandoned:` or `swept: stale claim` tombstone re-claims by `/claude-tweaks:flow`'s ordinary conditional write. A `'stale'` claim re-claims through `claim-targets.js --resume-pr`, which `RESUME_PR` makes `/claude-tweaks:flow` forward (`flow/claim-targets.md`). Without `RESUME_PR`, a `'stale'` claim whose marker sits on an open PR still stops in-flight.
- The prior run is the one the PR body's `claude-tweaks-run:` marker names; the claim's run id must match it.
- Resume never adds, removes or restores a grant label — a human re-grants with `/claude-tweaks:backlog refine #N`.
