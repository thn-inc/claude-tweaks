# Local Acceptance Park — `_shared/pr-first-merge.md` Step 2.9

Under control mode a record whose acceptance target resolves `local` is not merged: its PR stays open, `accept:pending` goes on it, and a human accepts it later with `/claude-tweaks:accept`. The CLI (`bin/accept-park.js`) owns every decision and write; this file orders the calls and names the outcome. Read it unless Step 2.9's `parked` exited 5 and `decide` exited 0 with `park:false`. Every result below other than that pair means never run Step 3. The reason words match `docs/driver.md`.

1. **Already parked.** For each `Fixes` record: `node "${CLAUDE_PLUGIN_ROOT}/bin/accept-park.js" parked --record {n} --run "$PIPELINE_RUN_DIR"` (omit `--run` when the caller has no run dir; the CLI then reads the repo-root policy). Exit 5 continues. Exit 0: report `pending-review` / `already-parked` (an earlier run parked it; no park this run, the run dir stays live and the claim held). Exit 6 (`unknown`, fail closed): report `pending-review` / `park-state-unknown`. Any other exit (2, 3): report `pending-review` / `supplier-failed`.
2. **Decide.** `node "${CLAUDE_PLUGIN_ROOT}/bin/accept-park.js" decide --run "$PIPELINE_RUN_DIR" --record {n}[,{m}…] --head {headRefOid} [--classification {file}]` (every `Fixes` record; omit `--run` as for `parked`; write the classification first per `_shared/tripwire-classification.md`). Exit 0 with `park:false` — run Step 3; control mode off prints `consulted:false` and nothing changes. A tripwire crossing, or a tripwire that could not run, resolves the record `local`: `park:true`, with the tripwire lines landing in the packet's Deploy status at step 3. Any non-zero exit (1 prints a fail-closed decision) — report `pending-review` / `supplier-failed`. A multi-spec series decides per record and its shared PR parks when any record parks; the other specs have already completed their own phases.
3. **Park.** `park:true`:

   ```bash
   node "${CLAUDE_PLUGIN_ROOT}/bin/accept-park.js" park --run "$PIPELINE_RUN_DIR" --record {every record whose decision parks} --claimed {every record of the run} --pr {pr} --head {headRefOid} --worktree "{path}" --worktree-mode {remove|caller}
   ```

   `park` writes `target: local`, `reason: awaiting-local-acceptance`, `park-head: {head}` and `park-base: {the PR's base oid}` into each parked record's packet Deploy status section; `/claude-tweaks:accept` counts a different PR head or base, or a missing `park-base:`, as moved. `--worktree-mode caller` when this session stands in that worktree, then `ExitWorktree` with `remove` as the last act. A non-zero `park` exit: report `pending-review` / `park-failed`. Exit 0: report `pending-review` / `awaiting-local-acceptance` with the PR URL; this run's park succeeded.
4. **The park is the run's LAST act.** `park` archives the run dir and removes the worktree, so nothing writes `$PIPELINE_RUN_DIR` after it returns: report and end. Any `steps` entry with `ok:false` in park's JSON (step 3 is refused on an unresolved console or console residue — the run then stays closed-not-archived until reconcile archives it) goes in the run's final report, never swallowed.

A parked record keeps `auto:build`; dispatch's `open-pr` queue exclusion keeps it out of the next pull. A park ends the run at `pending-review`; `/claude-tweaks:accept` re-enters it later (`accept/SKILL.md`'s `awaiting-local` row).
