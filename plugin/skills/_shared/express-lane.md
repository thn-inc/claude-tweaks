# Express lane — one agent from claim to merge

The express agent's procedure (#4025): a small, low-risk singleton record is built, runs its impacted tests, opens its PR and merges on green in one agent, outside `/flow`'s frame. `bin/express-lane.js` (`bin/lib/express/cli.js`) makes every deterministic decision; this file is the procedure around it, and its callers cite its sections by name. `{run-dir}` is the run directory itself (never its `decisions.md`); `{wt}` is the `worktree` `run-state.json` records; `{branch}` is what `git -C "{wt}" branch --show-current` prints (`run-state.json` records no branch); `{n}` is the record; `{ref}` is the integration branch per `_shared/integration-branch.md`. `$PIPELINE_RUN_DIR`, wherever a procedure this file cites reads it, is `{run-dir}`.

## Eligibility

`node "${CLAUDE_PLUGIN_ROOT}/bin/express-lane.js" gate --issue {n} --run "{run-dir}"` is the gate: a record takes the lane only when its verdict is `eligible: true`, and `reasons` names every rule it failed. The rule set lives in the CLI (`bin/lib/express/eligibility.js`) — never restate it, and never override a verdict by judgment. Run it live at routing time, every time: `--issue` fetches the record's current labels, so a verdict from an earlier queue pull never routes a record. `--run` adds the already-escalated-in-this-run rule, which keeps an escalated record from re-entering the lane; omit it only when no run dir exists yet. The lane requires `gh`: with `gh` absent the express path is never taken and the callers run the normal path, even though `gate --records-json {file}` (MCP-fetched records) can still answer.

## Procedure

One agent, inside a worktree already stamped by `record-worktree`. Every git call is `git -C "{wt}" …`.

1. **Claim** with `claim-targets.js` per `flow/claim-targets.md` (on the `/claude-tweaks:flow` entry its Step 2.8 has already claimed — go to step 2). A non-zero exit is outcome `blocked`: render that file's card for the exit and stop.
2. **Edit.** Read the record (`gh issue view {n} --json number,title,body,labels`), then edit only its `### Key Files` and test files.
3. **Commit the edit** — `git -C "{wt}" add` by explicit path (never `-A` or `.`), message `{Verb} {what} — refs #{n}` — always before any test runs, so an escalation leaves a clean tree for `/flow`'s Adopt-or-create check.
4. **Impacted tests.** Run `test/verification.md`'s scoped invocation (its Re-verify scoping: `verify.js --run "{run-dir}" --scope .claude-tweaks/verify-scope.json --integration-branch {ref}`), or its Step 2 full invocation when the project has no `.claude-tweaks/verify-scope.json`. A red run is not fixed on the lane: it writes no pass stamp, and step 5 escalates it.
5. **Check.** `node "${CLAUDE_PLUGIN_ROOT}/bin/express-lane.js" check --run "{run-dir}" --issue {n} --integration-branch {ref}` reads the runner pass stamp, then the diff bounds, both in `{wt}`, never this agent's cwd. `action: escalate` → stop with outcome `express-escalated`. `action: proceed` → keep its `head` (the sha the stamp verified) for step 6 and its `configSet` string for step 7. A non-zero exit → outcome `blocked` (Escalation's failed-call rule). The CLI logs its own entry; hand-log it only when the envelope carries `logged: false` (`_shared/auto-decision-log.md`'s CLIs that log their own entries), in the shape the CLI's own readers match:
   - proceed: `node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "{run-dir}" --status AUTO --section "/express-lane" --step "Express lane check" --text '#{n} proceed — {k} changed file(s), {implLines} implementation line(s) within bounds; runner stamp verifies HEAD {head}.'` (`{k}` is the length of the envelope's `bounds.changedFiles`, `{implLines}` its `bounds.implLines`, `{head}` its `head`);
   - escalate: write `escalated #{n} to /flow (reason: {reason}) — {detail}` (the envelope's `reason` and `detail`) with the Write tool to a session-tmp file, then `node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "{run-dir}" --status AUTO --section "/express-lane" --step "Express lane" --reversibility "high (worktree and branch kept)" --text-file "{text-file}"` — a file, because `{detail}` carries git paths and error text (`_shared/auto-decision-log.md`'s Text from git or a user).
6. **Push** — only when `git -C "{wt}" rev-parse HEAD` prints step 5's `head`; otherwise a commit landed after the check, so re-run steps 4–5 on it first. Then `git -C "{wt}" push origin {branch}`. A hook or gate denial at any step up to and including this one → escalate with reason `gate-denial` (Escalation below), outcome `express-escalated` — except a working-directory denial that repeats after the one `record-worktree` re-stamp, which is outcome `blocked`. A push the remote rejects (a non-fast-forward: an earlier attempt's branch of the same name is already on `origin`) is never forced or retried with other flags: escalate with reason `express-error`, because the lane skips `/claude-tweaks:build`, where `build/adopted-branch-collision-check.md` owns that case, and the normal path runs it.
7. **PR.** Write a one-to-two-sentence change summary with the Write tool to a session-tmp file (`_shared/session-tmp-root.md`), then `node "${CLAUDE_PLUGIN_ROOT}/bin/compose-pr-body.js" --express --run-id {run-id} --summary-file "{summary-file}" --fixes {n} --out "{body-file}"` (`{run-id}` is the run dir's basename), then `gh pr create --draft --base {ref} --head {branch} --title "{record title} (#{n})" --body-file "{body-file}"`, then `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" record-pr --run "{run-dir}" {number} {url}`, then `node "${CLAUDE_PLUGIN_ROOT}/bin/set-config.js" --run "{run-dir}" --set {configSet}` with step 5's string verbatim, plus any `merge-authorization` the caller appends. The `config.yml` that writes keeps the run dir from being swept as an orphaned mint and carries the express merge-verification and the `integration-model` pin (`_shared/integration-model.md`'s Run-scoped stability) to the merge. A `gh pr create` that fails with a transient-looking (5xx or timeout) signature is retried once after a 15-second wait (`_shared/pr-early-run-lifecycle.md`'s transient-failure row) before it counts as failed. A failed call in this step → outcome `blocked`: the branch is pushed, so it cannot escalate; the worktree, branch and run dir stay, and the report names the failed command — and, when it was `set-config.js`, that the run dir has no `config.yml`.
8. **Log** one summary entry: `node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "{run-dir}" --status AUTO --section "/express-lane" --step "Express lane" --text-file "{text-file}"`, the text — `#{n} built on the express lane: {files}; tests {scoped|full}; PR #{pr}.` — written with the Write tool first (`_shared/auto-decision-log.md`'s Text from git or a user). A non-zero exit is outcome `pending-review` with no merge: the lane never merges without its summary entry, and the PR stays in draft for a human.
9. **Merge** only when it is authorized: the record's live labels (re-read now) carry `auto:merge`, or — from `/claude-tweaks:flow` — `wrap-up/manifesto-authorized-merge.md`'s Applicability check passes for `{run-dir}`; otherwise stop with outcome `pending-review`, the PR left in draft for a human. Authorized, in order:
   - **Content judgment** — `dispatch/settle-and-merge.md`'s Auto-merge gate Content judgment for this one record: `Skill(skill: "claude-tweaks:assess-agent-autonomy", args: "merge-check #{n}")`, told the lane ran no review (review findings: none); log the verdict and confirm it through `merge-verdict.js` as that step does. Anything but a confirmed `auto-merge` → outcome `pending-review`.
   - **Acceptance labeling** — `wrap-up/verification-brief.md` from its Routing section, with `$CLOSING_SUB_ISSUES` = `{n}`.
   - **Merge** — first the forge's closing-link check, `node "${CLAUDE_PLUGIN_ROOT}/bin/closing-links.js" --run "{run-dir}" --mode pre-merge`, its result handled as `_shared/pr-checklist-refresh.md`'s "Then check the forge's closing links" says (the change summary is agent-written, so a closing phrase in it would close the record it names). Then `_shared/pr-first-merge.md` Step 2's mark-ready (the rest of its pre-merge title/description refresh does not apply: the express body has no phase checklist); Step 2.5, with merge-verification read from the run's own config overlay, never `off`; Step 3 with `{issue-list}` `{n}` and `--tag auto-merge` from `/claude-tweaks:dispatch`, or from `/claude-tweaks:flow` the tag `wrap-up/manifesto-authorized-merge.md`'s Tag selection names; on `merged`, the post-merge file (`_shared/pr-first-merge-post-merge.md`). The outcome is the one Step 3 returns.

   Express merges require CI green: no step of this procedure merges on a red or unread check state. Step 2.5's `gh`-absent degrade to `off` does not apply here — the outcome is `pending-review`. A repo with no PR CI parks every express merge: its empty check rollup reads pending, never green, so the lane needs PR CI.
10. **Report** the outcome (Outcomes below), the PR link and the run dir.

## Escalation

Escalation hands the record back to the normal path. The reasons are exactly `failing-test`, `out-of-bounds`, `gate-denial`, `express-error`; `check` escalates its own (a missing stamp, a bounds violation, no worktree recorded in `run-state.json`, an internal error). For any other — a gate denial, or an error outside `check` — write a one-line detail with the Write tool to a session-tmp file, then run `node "${CLAUDE_PLUGIN_ROOT}/bin/express-lane.js" escalate --run "{run-dir}" --issue {n} --reason {reason} --detail-file "{detail-file}"`. The CLI writes the line under `## /express-lane` — `AUTO {time} — Express lane: escalated #{n} to /flow (reason: {reason}) — {detail}. Reversibility: high (worktree and branch kept).` — so hand-write it only when `check` reports `logged: false` (Procedure step 5).

A non-zero exit from `check` or `escalate` is outcome `blocked`, never `express-escalated` and never retried: no escalation line landed, so the normal path would not know the record left the lane. Write `#{n} express-lane.js {verb} exited {code}: {stderr line}` with the Write tool to a session-tmp file, log it as the caller's rule-(a) entry (`_shared/auto-decision-log.md`) with `node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "{run-dir}" --status AUTO --section "/express-lane" --step "Express lane" --text-file "{text-file}"`, and stop.

Escalation happens only before the push: once `run-state.json` records `pr`, `escalate` and `check`'s escalating branches refuse (exit 1, nothing written), and a later failure is outcome `blocked` (step 7) or `pending-review` (step 9). On escalation, the worktree, branch, claim and run dir stay as they are — release, remove and push nothing. The normal path then runs unchanged on them: `/claude-tweaks:dispatch`'s ordinary first call, or `/claude-tweaks:flow` from Step 3 onward.

## Outcomes

`merged` | `armed` | `pending-review` | `express-escalated` | `blocked`

- `merged`, `armed`, `pending-review` — `_shared/pr-first-merge.md`'s Outcome vocabulary; `pending-review` also covers a failed summary entry at step 8, a merge step 9 is not authorized to run, an unconfirmed or `needs-human` merge-check, and a failure at step 9.
- `express-escalated` — the record left the lane before the push (Escalation above).
- `blocked` — the claim failed (step 1), a `check` or `escalate` call exited non-zero, or a step-7 call failed after the push; also a repeated working-directory denial (step 6). Nothing after it ran, and the express agent tears nothing down. From `/claude-tweaks:dispatch`, Settle releases and labels (its express call runs `dispatch/settle-and-merge.md`'s Settle before reporting), the dispatcher's `two-call-gate.md` §5 removes the local worktree only, and a pushed branch and draft PR stay open, except that Settle's failure tombstone closes a PR `run-state.json` records. From `/claude-tweaks:flow`, whatever already exists — worktree, branch, claim, run dir — stays for a human.

`node "${CLAUDE_PLUGIN_ROOT}/bin/express-lane.js" verify --run "{run-dir}" --issue {n}` checks a `merged`, `armed` or `pending-review` outcome's bookend artifacts — the claim log, an unsuperseded `check` proceed line, the recorded PR — and exits 1 listing each one `missing`. A `merged` run's post-merge reconcile can archive the run dir before the caller verifies, and a later log write can leave only a bare `decisions.md` at its old path; then it reads the `archive/{run-id}` copy, named in the envelope's `archived`.

## Post-merge sampling

A read-only review of a deterministic sample of merged express PRs, standing in for the review the lane ran without. It never edits code, never commits, never pushes. Every git call runs in the main checkout, `git -C "$RUN_ROOT" …` (`$RUN_ROOT` per `_shared/pipeline-run-dir.md`). It runs only at the end of a bare `/claude-tweaks:dispatch` drain (its Step 3 loop termination), never after an explicit `/claude-tweaks:dispatch #N` or an express merge made from `/claude-tweaks:flow`: those merges are sampled only when a bare drain later runs, and only within the 30-day lookback below — a project that merges on the lane without ever running a bare drain gets no post-merge review at all.

1. **Select** with `node "${CLAUDE_PLUGIN_ROOT}/bin/express-lane.js" samples`: its `sampled` array lists `{pr, ordinal, mergedAt, mergeSha, records}` per merged express PR that `express-review-sample-every` selects, merged within the last 30 days, and no trusted review comment covers — at most 3 per firing, oldest first (`capped: true` leaves the rest to a later firing). A selected PR still unreviewed 30 days after its merge is never sampled — the lookback bounds each firing's fetches — so name `capped: true` in the drain report, since a backlog it leaves can age out. Ordinals count every express merge ever made, so they never shift. Exit 1 (a failed fetch, or a search still at its 1000-result cap within one second) or 2 (`gh` absent) → no sweep this time: report it and do not retry; never sample from a partial list.
2. **Per sampled PR, one review.** A `mergeSha` of `null` → mint nothing; name the PR in the sweep's reply and move on. Otherwise:
   - Mint its run dir: `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" resolve-run-dir --spec-slug express-review-pr-{pr} --create`.
   - After `git -C "$RUN_ROOT" fetch origin {ref}` and `mkdir -p "{run-dir}/context"`, write the PR's change and each changed file's merged content into `{run-dir}/context/` by plain Bash redirect: `git -C "$RUN_ROOT" diff {mergeSha}^1 {mergeSha} > "{run-dir}/context/pr-{pr}.diff"`, and for each path `git -C "$RUN_ROOT" diff --name-status -z {mergeSha}^1 {mergeSha}` does not list as deleted (`D`), `git -C "$RUN_ROOT" show "{mergeSha}:{path}" > "{run-dir}/context/{path-slug}"` (`{path-slug}` is `{path}` with each `/` as `__`). The `-z` listing is NUL-split (`_shared/git-path-read.md`) and the object name is double-quoted; a path carrying a double quote, `$`, a backtick or a newline is never interpolated: skip it and name it in the review comment.
   - Derive the tier per `review/code-mode-steps.md` Step 2.5, raised to at least `medium` (every lane record is `risk:low` × `size:low`, which derives `low`: a single-read 3b/3c-only pass, thinner than the review this one stands in for), and dispatch that tier's lenses per `review/step3-lens-dispatch.md` (its dispatch contract unchanged), pointed at those copies rather than a checkout.
   - File each confirmed finding at or above its lens's floor with `/claude-tweaks:capture` (spec-shaped body, `--defer-reason` per `_shared/deferral-gate.md`), at every `autonomy` ceiling: filed findings are this sweep's documented output, exempt from approval at every tier by `_shared/auto-mode-contract.md`'s Work-record creation row. A staged proposal is no substitute — this run dir has no `config.yml`, so the reconciler's orphaned-mint sweep archives it, staged items and all, after 24 hours. Each body names its origin as `express-review of PR #{pr}`. The marker comment below is posted last, so a failed post leaves the PR to be reviewed again; before filing, one `gh issue list --state all --search "\"express-review of PR #{pr}\" in:body" --json number,body` read shows what an earlier, unfinished sweep already filed, and a finding whose `{path}:{line}` already appears in one of those bodies is cited in the comment by that record and not filed again.
   - Post the review comment only after every dispatched lens returned `DONE` or `DONE_WITH_CONCERNS` and every finding is filed: write the body — `<!-- run-comment: express-review -->` as its first line (`_shared/pr-run-comments.md`'s Comment kinds), then each finding with its filed record, or "no findings" — with the Write tool, and post it with `gh pr comment {pr} --body-file "{body-file}"`, findings or none, so the PR is never sampled again. A lens that returned `BLOCKED` or `NEEDS_CONTEXT`, a failed capture, a review that did not complete, or a failed post → no marker and no issue fallback: log `SKIP` and leave the PR for the next sweep.
   - Close the run dir once its review ends, posted or not. A posted review first logs `#{pr} reviewed: {k} finding(s), comment posted.` as an `AUTO` line (the `SKIP` call below with `--status AUTO`), so every sampling run dir carries the `decisions.md` that `close-run` needs; then `node "${CLAUDE_PLUGIN_ROOT}/bin/hooks.js" close-run --run "{run-dir}"`.

Every `SKIP` goes to that PR's sampling run dir: `node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "{run-dir}" --status SKIP --section "/express-lane" --step "Post-merge sampling" --text-file "{text-file}"`, the one-line text written with the Write tool first.
