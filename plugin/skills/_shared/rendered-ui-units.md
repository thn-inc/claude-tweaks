# Rendered-UI Units — Waiting On and Routing a Merge-Gating Read-Only Unit

Cited by `subagent-dispatch-core.md`'s Foreground Execution Discipline and its six inlined copies (each carries one exception sentence pointing here), and by `visual-review/page-mode.md`, `visual-review/discover-mode.md` and `design-wrapper/modes/review.md`. It applies wherever a dispatching agent's keep-alive bound applies (`subagent-dispatch-core.md`). The rule is its own file because the core file is composed whole into the `review-dispatch` bundle, which has no byte headroom left under the read-limit rail (#5280).

1. **What a rendered-UI unit is.** A read-only nested unit whose result feeds the rendered-UI check before merge: /claude-tweaks:review Step 6 (visual-review) and Step 6.5 (design-wrapper review), and the children each launches. Lenses, single reads and judges are not rendered-UI units: they keep the first-bound self-judge, and their late result is still ignored.
2. **The artifact directory.** The dispatcher names the child's artifact directory in its prompt as an absolute path (the child's checkout root joined with the relative path shown, since the probe can run from a different cwd than the child and a relative path would read as missing): a visual-review page or journey agent's `.claude-tweaks/artifacts/screenshots/browse/{session}/`, or `.claude-tweaks/artifacts/screenshots/browse/` for a whole visual-review unit; a whole design-wrapper review unit's `.impeccable/review/`. Design-wrapper review's Steps 3.7 and 3.8 children have no artifact directory: they only read screenshots already captured. A rendered-UI unit whose prompt names no artifact directory counts as unchanged.
3. **More windows while it changes.** At the bound, before self-judging, probe the directory read-only (`ls -lR "{artifact-dir}"` piped to `git hash-object --stdin`) against the previous probe, taken right after launch. Extend exactly as for a write-capable child's worktree, with the same wait-line log: one more 60-wait window while it changed, stopping when a whole window passes with no change or at the ceiling of 3 windows (60 minutes) per wave, naming which fired. A missing directory or a failed probe counts as no change, never retried in another form. Then self-judge it as any read-only unit.
4. **A self-judged unit is not a pass.** A self-judged rendered-UI unit never satisfies the rendered-UI check before merge. Surface it as an explicit decline, the same as a check that silently self-skipped: log it in the downgrade line (`decisions.md`, under the dispatching skill's section) as not satisfying the rendered-UI check, and state it in the review summary's Visual Review or Design Quality section.
5. **Its late result is staged, not ignored, but only while the run is active.** Read `{run-dir}/run-state.json`. With no pipeline run directory, or no `run-state.json` in it, treat the run as not active. When its `status` is anything but `active`, `console.json` exists in the run dir, or `stage-item.js` (below) exits 3 (archived or unanchored), write nothing under the run dir and name the findings in your reply instead, one line per finding, `LATE_FINDING: {severity} — {one-line finding}`, immediately before the reply's trailing `STATUS:` line (in a dispatched call whose output format is fixed too). Otherwise:
   - Write the findings to the path `node "${CLAUDE_PLUGIN_ROOT}/bin/session-tmp-resolve.js" --value rendered-late-{unit-slug}.md` prints, never under the run dir.
   - Run `node "${CLAUDE_PLUGIN_ROOT}/bin/stage-item.js" --run "{run-dir}" --id visual-review-late-1 --allocate --file "{findings-file}"`, which writes `staged/visual-review-late-{n}.md`.
   - Log it: `node "${CLAUDE_PLUGIN_ROOT}/bin/log-decision.js" --run "{run-dir}" --section "{section}" --status STAGED --step "late rendered-UI result" --reversibility high --text-file "{text-file}"`, the text file holding only `late rendered-UI result from {unit} staged to staged/{written-file}.`, where `{section}` is `/review`, `{unit}` is the child as its launch site named it (such as `visual-review page agent pricing-page-review`), `{unit-slug}` is its lowercase, hyphen-joined form, `{written-file}` is the basename of the first path stage-item printed, and `{text-file}` is a path `bin/session-tmp-resolve.js` prints, kept out of the run dir like the findings file.

   The Review Console shows it under Pending review. It never changes a verdict already reached. When the run is active, a re-woken agent stages first, then repeats its whole final reply unchanged; when it is not, a re-woken agent after its final reply repeats the whole final reply with those lines inserted before `STATUS:` (the one exception to unchanged).
