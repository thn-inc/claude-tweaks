# Frontier Exception — the one named fan-out use of the top tier

The contract for `--exception design-reader`, the single case where a Frontier resolution is valid in a parallel fan-out; `_shared/subagent-dispatch-core.md` §Model Selection names it in one row and points here. Read by `/claude-tweaks:design` (#6352) and anyone resolving with `--exception`.

**Named fan-out exception.** One exception to the singleton rule exists, named by `--exception design-reader`, for `/claude-tweaks:design`'s readers (#6352). A reader resolves its tier with `node "${CLAUDE_PLUGIN_ROOT}/bin/resolve-profile.js" frontier --exception design-reader --session-dir "{design folder}"`. It is code, not a setting — no policy key adds a second. It allows the top tier in that fan-out up to 22 resolutions per design session; the design folder is the session, and a resumed session keeps its count. Each counted resolution is a line in `{design folder}/frontier-exception-tally.log`, appended under a lock, and only top-tier resolutions count; the exception never touches `frontier-run-cap` or the run's `frontier-tally.log`, and `--run-dir` is refused beside it. An unattended call is refused (exit 1). A step-down never lowers the tier quietly: the call prints only `{"stepDown":{"reason":"…"}}` and exits 3, with the reason the first that applies of `tally`, `policy`, `stance`, `ceiling`, `limit`, `session-failure` (a missing session folder or an unreadable or unwritable tally steps down on the first reason, before the policy is read). On exit 3 the calling skill stops and asks the maintainer, and never lowers the tier itself. Exit 1 also covers an unknown exception name and a `--session-dir` inside `.claude-tweaks/pipelines/`.
