## Deferral routing

Registered by #5932 (`deferral-digest-reasons`) and #5933 (`filed-record-evidence`, `run-filed-record-cap`). `bin/deferral-route.js` reads all three through `bin/resolve-policy.js`'s resolver, from `policy.yml`. A run's `config.yml` overlays `deferral-digest-reasons` when the call passes `--run {dir}`; the other two are `policyOnly`, so a run's own config never loosens them. None is a Manifesto lever. `_shared/materiality-floor.md`'s Overrides section and Applying the floor give their places in the precedence.

| Key | Canonical home | Owner skill(s) | Default | Meaning |
|---|---|---|---|---|
| `deferral-digest-reasons` | `policy.yml` (or a run's `config.yml` via `--run`) | `bin/deferral-route.js` | `[]` | `Defer-reason:` values (`_shared/deferral-gate.md`'s vocabulary) that send an agent-raised deferral to the digest whatever its size, priority and risk; human input and a `high`/`critical` severity still file. Unset resolves `[]`. `pre-existing-outside-diff, tangential` resolves to that raw comma-separated string. `[]` is the explicit empty list: it resolves `[]` from its own source, so a run's `config.yml` holding `[]` overrides a repository list. A blank value reads as unset and falls through. An element outside the vocabulary (`not-a-reason`, `Tangential`, a trailing comma's empty entry) makes the whole value invalid: it resolves to `[]` with `invalid: true`, and `bin/deferral-route.js` prints one stderr warning naming the key and the bad element, then routes as if unset. The run-config overlay is a resolver capability: `set-config.js` writes no such key (it accepts only the Manifesto levers and run pins), and a routing site passes `--run` only inside a pipeline run, so a run's `config.yml` could overlay it there; nothing writes the key to one, so in practice the repository value applies. |
| `filed-record-evidence` | `policy.yml` | `bin/deferral-route.js` | `off` | `off` or `required`. With `required`, an agent-raised item the route would file whose `Defer-reason:` is `pre-existing-outside-diff`, `genuinely-larger` or `tangential` needs `--evidence test:{path}` (a regular file whose real path is under the working tree's git top level) or `--evidence ref:{id}` (`#{digits}` or `IL-{digits}`); without valid evidence it goes to the digest, rule `no-evidence`. The other four reasons need none. Unset resolves `off`; any other value resolves `off` with `invalid: true`, and `bin/deferral-route.js` prints one stderr warning naming the key and the value. `policyOnly`: a run's `config.yml` value is ignored. |
| `run-filed-record-cap` | `policy.yml` | `bin/deferral-route.js` | unset (no cap) | A non-negative integer. With a value and a call passing `--run {dir}`, `bin/deferral-route.js` appends one line to `{dir}/deferral-route-tally.log` for each agent-raised `file` verdict, and an item that would file once the tally holds that many lines goes to the digest, rule `run-cap`; a `high`/`critical` severity still files and is counted. `0` digests every such item. A call without `--run` is never capped. The tally is per `--run` directory: a multi-spec run's per-spec `spec-{N}/` directories keep separate tallies. Unset resolves `null` (no cap); a negative or non-integer value resolves `null` with `invalid: true` and one stderr warning. `policyOnly`. |
