## Express driver

| Key | Canonical home | Owner skill(s) | Default | Meaning |
|---|---|---|---|---|
| `express-driver` | `policy.yml` | `bin/drive.js` (#5218) | `off` | Routes records to the pipeline driver: `off`, `split` (even record numbers only — a cheap split, not an unbiased one; numbers cluster by filing batch) or `on`. Unset or malformed (`invalid: true`) gives `off`. `policyOnly`: it routes records to autonomous machinery, so a `--run` config never switches it. `split` is temporary — dropped for `on` or `off` once each arm has 20 merged records (Phase 4 parent record) |
| `express-driver-wall-clock-minutes` | `policy.yml` | `bin/drive.js` (#5218) | `30` | Minutes each driver worker launch may take, not the record: when the review step runs, a record can launch three (reviewer, implementer, fix implementer). Unset or malformed gives `30`; `0` is never unlimited (`min: 1`). `policyOnly`: ceilings bound autonomous spend, so a `--run` config never sets it |
| `express-driver-spend-ceiling-dollars` | `policy.yml` | `bin/drive.js` (#5218) | `10` | Whole dollars each driver worker launch may spend, not the record (up to three launches when the review step runs). Unset or malformed gives `10`; `0` is never unlimited (`min: 1`). `policyOnly`: it bounds autonomous spend, so a `--run` config never raises it |
| `express-driver-review` | `policy.yml` | `bin/drive.js` (#5222) | `beyond-express` | The driver's read-only reviewer step: `off`, `on`, or `beyond-express`, which reviews a record whose size label is missing or not `low`, or with more than `EXPRESS_MAX_KEY_FILES` Key Files, or one admitted widened above `risk:low` (#6018; the reviewer rule also counts a non-fast-lane ceremony, but ceremony widening is admitted only under `on`, so no real run reaches it under `beyond-express`). Under `on`, any recognised `ceremony:*` label also passes eligibility (an unrecognised spelling still refuses). Unset or malformed (`invalid: true`) gives `beyond-express`. `policyOnly`: it decides whether autonomous machinery runs, so a `--run` config never switches it |
| `express-driver-max-size` | `policy.yml` | `bin/drive.js` (#5224) | `low` | The largest size label the driver admits: `low` or `medium` (`size:high` is never admitted). Unset or malformed (`invalid: true`, e.g. `high`, `Medium`) gives `low`. `policyOnly`: it bounds what autonomous machinery may take on, so a `--run` config never widens it. A record beyond the express bounds is admitted only with the reviewer step on |
| `express-driver-max-key-files` | `policy.yml` | `bin/drive.js` (#5224) | `3` | The most Key Files a record may list for the driver to admit it; an integer of at least 1. Unset or malformed (`invalid: true`, e.g. `0`, `2.5`) gives `3`, the express limit (`EXPRESS_MAX_KEY_FILES`). `policyOnly`, for the same reason. A record beyond the express bounds is admitted only with the reviewer step on |
| `express-driver-max-lines` | `policy.yml` | `bin/drive.js` (#5224) | effective `auto-merge-max-lines` | The driver's diff-line bound; an integer of at least 1. A Shape B derived default: unset or malformed (`invalid: true`) resolves the effective `auto-merge-max-lines` value with `source: default`, the driver then passes no `--max-lines`, and `check` applies `auto-merge-max-lines`. The driver's bound applies only when the key is set and the reviewer is on for the record. `policyOnly`, for the same reason |
| `express-driver-max-risk` | `policy.yml` | `bin/drive.js` (#6018) | `low` | The highest risk label the driver admits: `low`, `medium` or `high`. Unset or malformed (`invalid: true`, e.g. `Medium`, `critical`) gives `low`. `policyOnly`, for the same reason as its siblings: it bounds what autonomous machinery may take on, so a `--run` config never widens it. A record admitted above `risk:low` is admitted only with the reviewer step on and always stops at `pending-review` for a human merge |
| `express-driver-protected-paths` | `policy.yml` | `bin/drive.js` (#6019) | `refuse` | What the driver does with a record whose Key Files touch a protected path: `refuse` (today) or `reviewer`. Under `reviewer`, a record whose protected Key Files are all merge-time families (`hooks/`, `hooks.js`, `hooks.sh`, `skills/_shared/`, `CODEOWNERS`) is admitted only with the reviewer step on, `check` reports such paths instead of refusing them, and the record always stops at `pending-review` for a human merge; build-time families (`.github/`, `.gitlab-ci.yml`, `.circleci/`, `.githooks/`, `.husky/`, `package.json`, `.claude/settings*.json`, `.mcp.json`, and `.claude-tweaks/policy.yml` and `.claude-tweaks/verify-scope.json`, which `check` and `verify.js` read from the PR's own worktree) refuse under both values. Unset or malformed (`invalid: true`, e.g. `Reviewer`, `on`) gives `refuse`. `policyOnly`, for the same reason as its siblings: a `--run` config never loosens it |
| `protected-paths` | `policy.yml` | `bin/drive.js`, `bin/express-lane.js` (#6020) | the shipped list (`SHIPPED_PROTECTED_PATHS`) | Which paths the express lane refuses to merge unattended, as comma-separated path globs matched as `merge-sensitive-paths` globs are: root-anchored and case-sensitive over the canonical posix path with no leading `./`, so `package.json` protects only the root file, `**/package.json` protects every depth, and a trailing `/**` also matches the bare directory. A set list replaces the shipped list, removals included, and `[]` protects nothing; removing an entry lets the express lane merge a change to that path on green with no human. Unset or malformed keeps the shipped list, never an empty one: the resolver returns `{ value: [], source: 'default' }` unset, the raw comma string set, `[]` for `[]`, and `{ value: [], source: 'default', invalid: true }` malformed (an empty entry, whitespace, a quote, bracket, brace, `?` or backslash, so the YAML-flow `["infra/**"]` is malformed; a `#` directly after a non-space character is malformed too, since the line parser would cut the value there, while a `#` after a space is a comment). A glob with a leading `/` or `./` is valid but matches nothing. Always read from the main checkout's `policy.yml`, so a record's branch cannot change its own list. A list that omits `.claude-tweaks/policy.yml` or `.claude-tweaks/verify-scope.json` lets a branch loosen the other values `check` and `verify.js` read from its own worktree (`merge-sensitive-paths`, `auto-merge-max-lines`, the verify scope). `resolve-policy.js` run inside a worktree shows that checkout's value, not the main checkout's value the gates use. The driver reviewer's evidence-path guard always keeps the shipped list as well, and under `express-driver-protected-paths: reviewer` a path is never build-time on account of being project-added. `policyOnly`: a `--run` config never shrinks it. Refused from the factory layer; Phase 11 will let a factory set a floor |
