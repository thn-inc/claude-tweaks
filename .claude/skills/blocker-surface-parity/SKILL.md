# Blocker surface parity

## Overview

Many surfaces read a record's blockers, and each must reach the same verdict, or one reports a record ready while another excludes it. #4553, #4792 and #4793 each had to land one blocker rule across all of them, and #4793's final review still found two surfaces short. `docs/journeys/block-a-record-on-another-repositorys-issue-4793.md` walks the surfaces as a user sees them; this skill is the change-side roster.

## Rules

1. **One predicate decides.** Every surface calls `foreignBlockerBlocks` / `openBlockerRefs` rather than restating the rule: only an exact CLOSED releases; open and unreadable both hold (fail closed).
2. **Name it the same everywhere.** A foreign blocker reads `owner/name#N`, or `owner/name#N (state unreadable)` with one `Warning:` line naming the cause. No surface reads a qualified ref as this repository's bare number. A failed whole native query is named `native blockers (state unreadable)` (#5309): the dispatch queue pull excludes every eligible record with it, fail closed; no other surface emits it yet, so a surface that adds a native-query failure path uses this same string. A same-repository `Blocked by #N` whose state cannot be read stays bare `#N` in the exclusion detail, fail closed, with one `Warning:` line naming the cause and no queue-order cache write (the dispatch queue pull's #5311 and #5865 paths); a surface that adds this failure path uses the same shape.
3. **Make the new input a required argument.** `filterCandidates` and `partitionByOpenBodyBlockers` throw `TypeError` without a foreign `Map` (`new Map()` for none), so a caller that never learned the rule fails loudly instead of reading every foreign blocker as absent.
4. **State the freshness signal cannot see means a cache miss.** A foreign issue closing changes nothing in this repository, so `cacheUsable` misses while any `auto:build` body declares a qualified line or a persisted exclusion names a foreign blocker. A change to which records a blocker rule excludes bumps `BLOCKER_RULES`, the stamp `composeOrderBlob` writes and `cacheUsable` requires, so a blob an older release wrote misses once (an older build ignores the field, so the bump is expand-contract safe).
5. **Cover both `work-links` modes and both transports** on every row of the table, or say in the row's prose which one the surface does not support and what it prints instead.
6. **A new landing verdict lands on every landing surface.** A verdict beside `unlanded` (`hollow`, #6142: the closing merge carried no implementation) is named by the unlanded-blocker pass and its report line, the /flow 2.7b stop card and failure card, and the dispatch Settle and queue-pull notes that list the stopping verdicts. Derive the list with `git grep -n -l -w unlanded -- plugin tests` and add a conformance assertion per surface.

7. **The symbolic blocker is held by every reader and keeps `ready` off on every path that sets it.** #6353's `Blocked by: {part} (left for owner/name)` line has no `#N`, so `DEP_RE`, `CROSS_REPO_DEP_RE` and `plan-line.js` cannot parse it (#6374 added `blocker-lines.js` as the one parser). Every surface above holds a record carrying it (the dispatch queue pull and resume, the /flow pre-flight and the materialize header, the backlog funnel and grant pre-pass, and wrap-up's newly-unblocked report) and names it `{part} (left for owner/name)`, the same string everywhere. Separately, every path that adds `ready` runs `readyGate`: the code paths through `recordPayload` (which withholds `ready` and returns `readyWithheld`) and `readyRestorable`, the prose paths through `node "${CLAUDE_PLUGIN_ROOT}/bin/ready-gate.js" <body-file>` (exit 0 may add `ready`, 1 must not, 2 stops). The line names no issue and no resolvable state, so `ready` stays off until a later run rewrites it to `owner/name#N`. `symbolicBlockers` reads the line over the whole body, `## Original request` included (fences and code spans stripped), because shaping carries a sub-issue's original body there, line and all. A path that verifies its write expects what the gate decided (`shaping-mode-readback.md`, `planning-hold.js`'s `readBack`), and bare drain excludes `shaped:headless` so a shape the gate stopped is not repeated on every firing. List the paths with `git grep -n -l -e "add-label ready" -e "label ready" -e readyRestorable -e "ready: true" -e LABELS.READY -e "stage: 'ready'" -- plugin`, not from memory, and classify each hit as gated by a `ready-gate.js` call, covered by `recordPayload`, gated in code, or not a ready path; `tests/ready-gate-callers-conformance.test.js` pins the prose calls, and its `READY_PATH_ROSTER` reads the terms out of this grep line and fails on any file the grep finds that the roster does not classify, so a new hit gets its classification there as well as here. Classified so far: `bin/lib/console/bundle.js` (`composeBundle` reads each member's symbolic refs and withholds `ready` itself) is gated in code; the Review Console's creates from a staged `Labels:` header are covered because the staging step writes `payload.labels` there (`wrap-up/leftover-routing.md`'s staging fence, `_shared/ledger-format.md`'s Keep row, which stages the same way); `review/step3-routing.md`'s Defer and `capture/SKILL.md`'s shaped branch are covered because each creates with every label in `payload.labels` (capture: the labels `compose-record.js` prints, in place of a typed `by:capture`); `reflect/full-mode.md`'s Defer passes `parked: true`, never `ready`, so it is not a ready path; `ambiguity-resolve.js`, `record-payload.js` and `resolve-ambiguity.js` define or report the gate, `link.js`'s `already: true`, `build-authority.js`, `record-vocabulary.js` and `stations.js` read or name the label, and every `gh issue list --label ready` and `--remove-label ready` call reads or clears it, so none is a ready path; the five `*-health/issue-payload.js` files (ci-audit, code-health, docs-health, harness-health, journey-health) pass `ready: true` to `recordPayload`, covered below. Covered means the call site applies the payload's printed `labels` (`compose-record.js`'s output or the payload object's `.labels`): a call that writes `--label ready` as a literal is never covered, whatever builds its body. The four health-sweep filings (`code-health/filing.md`, `docs-health/SKILL.md`, `harness-health/filing.md`, `journey-health/SKILL.md`) are covered: each builds its payload through `recordPayload` (`*-health/issue-payload.js`) and creates the issue with every label in `payload.labels` (ci-health's idiom), never a typed `--label ready`, so the withhold decides. Their free-text evidence lands unfenced in the body, so a symbolic line there is reachable (`tests/bin-lib/code-health/issue-payload.test.js` runs it). `tests/health-sweep-filing-labels-conformance.test.js` fails a typed `ready`, `risk:`, `size:` or `by:` label returning to any of the four, and the removal of the `payload.labels` application.

## Common Operations

Derive the current reader list instead of trusting the table:

```bash
git grep -n -l -E "openBlockerRefs|foreignBlockerBlocks|partitionByOpenBodyBlockers|bodyForeignBlockers|openNativeBlockerRefs|symbolicBlocker" -- plugin tests
```

## Anti-Patterns

| Pattern | Why it fails here |
|---|---|
| Landing the rule in the dispatch queue pull only | Backlog's funnel counts the record dispatchable and wrap-up reports it newly unblocked while dispatch excludes it (journey step 3's red flags) |
| An optional foreign argument that defaults to empty | Every caller that never passes it reads all foreign blockers as absent and releases the record, with no error |
| A placeholder blocker line without `#N` on a `ready` record | The line names no issue and no resolvable state (#6353 final review); keep `ready` off until a later run writes the `owner/name#N` form, by running `readyGate` on every path that adds it |
| Re-checking a cached verdict only on `updatedAt` | The foreign issue closes without touching any local record, so the stale exclusion replays until something unrelated changes (#4793 final review) |
