# Git calls on the seam

Lazy-loaded from `SKILL.md`'s "Git calls on the seam" section. The injectable-runner rules there (argv arrays, loud-throw fakes, record inside the runner and assert after) apply to `git` unchanged; these are the `git`-only rules.

- **A read-only `git status` passes `--no-optional-locks` before `status`, after any `-C <path>`** (`['-C', wt, '--no-optional-locks', 'status', '--porcelain']`). A plain `status` rewrites the index under `index.lock`, so a sibling session's `git add`/`commit` in that worktree fails meanwhile. `tests/git-status-optional-locks.test.js` fails the full suite on an argv array or a `git … status` command string without it (#3464).
- **An argv array stops shell injection, not flag injection.** A caller-supplied value that begins with `-` is still read as an *option* by the command itself, so any such value needs an end-of-options separator ahead of it. For `git` the separator is **`--end-of-options`, not `--`**: `--` switches `rev-parse --verify` and `merge-base` into pathspec mode and silently changes what they resolve — verified empirically before the fix landed, after `--` was tried first (#888 review lens 3b). `plugin/bin/lib/blast-radius-cli.js` is the shipped instance, on both of its revision-resolving calls. Pin the separator with a fake-runner test that asserts the exact argv array for a value like `-evil` (`tests/bin-lib/blast-radius-cli.test.js`), not just that the call succeeded. **`--end-of-options` alone never resolves a revision — it needs `--verify` alongside it.** A bare `git rev-parse --end-of-options <rev>` (no `--verify`) doesn't error and doesn't resolve either: it echoes `--end-of-options` back as a literal output line ahead of the resolved value, because plain `rev-parse` is in multi-arg parse-and-print mode, not single-revision mode. `plugin/bin/lib/docs-health/commit-ref.js`'s `classifyOne` (#2866) hit this directly — its first cut of peeling an annotated tag to the commit it points at used `rev-parse --end-of-options <sha>^{commit}` without `--verify` and failed with `error: unknown option \`end-of-options'`; adding `--verify` fixed it. Always pair the two.
- **A `^{ref}` exclusion token goes after `--end-of-options` and before `--`, and a walk it can empty owes a count of the range without it.** After `--end-of-options` git still reads a `^`-prefixed token as a revision, and a dash-leading ref fails as `bad revision '^-x'` rather than parsing as a flag. After `--` the same token is a pathspec, and `rev-list --count` silently prints 0 (both probed on git 2.56). An exclusion can also swallow the whole range, and an empty walk then reads as "nothing to judge". `plugin/bin/lib/flow/artifact-overwrite-check.js` (#4845) walks `--end-of-options {base}..{head} ^{integrationRef} -- …`. On an empty walk it runs `rev-list --count` over the range with and without the exclusion, and throws when only the exclusion emptied it. A range empty both ways stays clean. `tests/bin-lib/flow/artifact-overwrite-check.test.js` pins the argv and both empty cases. It is `parse-signal-discipline`'s "did not run" versus "found nothing" split, applied to a git range.
- **A `git` path-list read also needs `-z`.** An argv that asks git for a path list (`--name-only` / `--name-status`, `ls-files`, `ls-tree`, `--numstat`, `status --porcelain`) passes `-z` and splits on NUL via `plugin/bin/lib/git-z.js`, besides `--end-of-options` before any ref. A read that never turns git's output into a path (an emptiness test, an exit code, display) carries the same-line `// git-path-read: not a path list (<reason>)` marker instead — see `plugin/skills/_shared/git-path-read.md`.
- **Pick the git root by what the module reads: `--show-toplevel` for working-tree facts, the `--git-common-dir` parent only for state that must outlive a worktree.** From a linked worktree the common-dir parent is the MAIN checkout, so a `git diff {base}...HEAD`, a `docs/` scan or a frontmatter read run against it sees the main checkout's HEAD and tree and comes back empty without erroring. `plugin/bin/wrap-up-engine.js` keeps both on purpose (#3431): `resolveFactsRoot` (`--show-toplevel`) feeds `gatherFacts` and `buildJourneyFrontmatter`, while `resolveRepoRoot` (common-dir) anchors the telemetry TSV, archived-run lookups and `policy.yml`. A regression test for a root fix needs a fixture that differs between the two roots at every call site that takes the root: the first #3431 test left `buildJourneyFrontmatter` on the wrong root and stayed green because the journey file was identical in both checkouts.
- **A module that parses git's output pins that output's format against the user's and the repo's git config.** A parser written against git's defaults misreads the output under another config, and nothing fails. `diff.noprefix` and `diff.mnemonicPrefix` change the `a/`/`b/` header prefixes. `color.ui=always` and an external diff driver rewrite the text. `core.quotePath`, on by default, prints a non-ASCII path quoted and escaped, so `café.txt` no longer matches its own name. For a path list, pass `-z`, which prints every path verbatim (`plugin/bin/lib/verify/changed-files.js`). For patch text, pass every flag explicitly, as `plugin/bin/lib/review-context/build.js` does (#3020): `-c core.quotePath=false diff --no-color --no-ext-diff --src-prefix=a/ --dst-prefix=b/`. Its first version passed none of them, and an added non-ASCII file over the size cap kept its whole diff chunk. Pin the flags two ways: real-git tests that set the config in the fixture repo, and an exact-argv assertion for the flags no fixture test exercises (`tests/bin-lib/review-context/build.test.js`).
- **A module that switches git's config off through the environment also scrubs the config the environment carries.** `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1` stop the user's and system config files, but environment-carried config still applies: `GIT_CONFIG_PARAMETERS` (what a parent `git -c key=value` exports to its children) and `GIT_CONFIG_COUNT` with `GIT_CONFIG_KEY_n`/`GIT_CONFIG_VALUE_n`. Two more inherited variables change what the call reads or prints: `GIT_COMMON_DIR` points it at another repository, as `GIT_DIR` does, and `GIT_DIFF_OPTS` sets the context length of every diff it emits. `plugin/bin/lib/staged-patch/stack-check.js`'s exported `gitEnv` deletes all of them (#3997). Before that it deleted only `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE`, so `core.autocrlf=true` injected through `GIT_CONFIG_COUNT` made 11 re-derive tests fail on an LF checkout, and review then found `GIT_COMMON_DIR` and `GIT_DIFF_OPTS` still passing through. A new module that isolates git this way imports `gitEnv` rather than building its own env object. `tests/bin-lib/staged-patch/stack-check.test.js` pins the deletes, including a `GIT_CONFIG_KEY_10` positive and a `GIT_CONFIG_KEY_X` lookalike that must survive. A caller that must keep the user's config (a `git commit` needs the identity it carries) and only needs the repo pinned uses `plugin/bin/lib/hooks/git-exec.js`'s `repoPinnedEnv()` instead: it drops only `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and `GIT_COMMON_DIR`, passed as `runGit`'s `env` option. `plugin/bin/lib/reconcile/archive-merged.js` wraps `runGit` with it once, because an inherited `GIT_DIR` overrides `git -C <root>` and lands the archival commit on a linked worktree's branch (#4178). A module that builds commits on a scratch `GIT_INDEX_FILE` (`read-tree`, `apply --cached`, `write-tree`, `commit-tree`) layers the index onto `repoPinnedEnv()`, never onto `process.env`: `{ ...process.env, GIT_INDEX_FILE: scratch }` replaces only the index and keeps an inherited `GIT_DIR`. #5290's review found `plugin/bin/lib/learned-skills/learned-skills.js`'s runner passing `process.env` on every call, its temp-index commits included. Its `gitEnv(extra)` is the shape to copy, `{ ...repoPinnedEnv(), GIT_LITERAL_PATHSPECS: '1', ...extra }`, where the literal-pathspec flag makes a caller-named path such as `*` or `:(top)x` name that one file. `plugin/bin/lib/reconcile/ledger-residue.js`'s residue commit still spreads `process.env` under its `-C <root>`, so do not copy it.
- **Every git call in a module that changes a repository (a `mv`, an `add`, a commit) runs under `repoPinnedEnv()`, including when the module takes an injected `env`.** Neither `git -C <worktree>` nor a `cwd` pins the repository: an inherited `GIT_DIR`, `GIT_WORK_TREE` or `GIT_INDEX_FILE`, which a git hook exports to its children, overrides both, so the change and its commit land in another repo. `plugin/bin/lib/run-header-archive.js`'s `archiveRunHeader` (#3976) first shipped its pre-merge `git mv` and commit without the pin, and code review caught it. Its fix is the shape to copy when the caller injects an env: one local wrapper every call goes through, `const g = (args, opts = {}) => git(args, worktree, { env: repoPinnedEnv(env), ...opts })`, where `repoPinnedEnv(env)` filters the env it is given (with no argument it filters `process.env`). The per-call `opts` spread lands after the pin, so no call site passes its own `env`. Prove the pin with a decoy repo: set `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE` to a second fixture repo in the env the test passes, run the write, and assert that the real repo changed and the decoy's HEAD did not (`tests/run-header-archive.test.js`, "an inherited GIT_DIR, GIT_WORK_TREE or GIT_INDEX_FILE never redirects the move to another repo (#4178)").
- **A fetch or push that serves a state branch (a branch that stores data, not code) leaves the user's clone as it found it.** Fetch into a per-call scratch ref with `--no-tags` (a fetch that stores into a ref otherwise follows tags into the clone) and `--no-write-fetch-head` (FETCH_HEAD is one shared pointer a concurrent fetch can overwrite; git 2.29+), and name the source in full, `refs/heads/{branch}:{scratch}`, since a bare branch name can resolve to a same-named tag and return the wrong tip as the write lease. Push the branch with `--no-verify`: it carries no code, so a consumer's pre-push suite must not run for it. `plugin/bin/lib/release-state/store.js`'s `readStateGit` and `plugin/bin/lib/release-state/marker.js`'s `createLocalHistory` are the instances (#5883). Create a new state branch through the two shared legs rather than a copy: `bootstrapClaimsBranchGit` in `plugin/bin/lib/issues/claims-git-cas.js` takes `branch`, `fetchFlags`, `pushFlags` and `scratchRefPrefix`, and `createBranchContentsApi(ghApi, slug, branch)` in `plugin/bin/lib/issues/claim-store.js` is the contents-API leg (`ensureReleaseStateBranch` calls both). `readClaimBlobGit` in `claims-git-cas.js` still fetches the bare `claims-registry` name with neither flag, so do not copy it.
- **A hidden non-branch ref that is itself the store (`refs/claude-tweaks/plans/{n}`) differs from a state branch in four places.** (1) `git ls-remote <remote> <ref>` matches by tail, so it also lists `refs/archive/<ref>`: keep only the line whose name equals the ref exactly (`lsRemoteRef` in `plugin/bin/lib/plan-store/git.js`; `tests/bin-lib/plan-store/transport.test.js`, "lsRemoteRef ignores a same-tail ref"). (2) `ls-remote` and `fetch` take the remote before any ref, where there is no `--end-of-options` slot, so a dash-leading remote is refused before git runs (`badRemote`). (3) When the local ref is the store, fetch straight into it with a forced one-ref refspec, `+{ref}:{ref}` (a replaced plan is not a fast-forward of the stale local ref), still with `--no-tags --no-write-fetch-head`, and compare the ref to the expected commit after the fetch (`fetchRef`, and `readPlan` in `plugin/bin/lib/plan-store/store.js`); the scratch-ref rule above is for a branch whose local copy is not the store. (4) A write pushes under `--force-with-lease={ref}:{sha ls-remote saw}`, never the local ref's value, which can lag a writer in another clone (an empty sha is `SKILL.md`'s create-only form), and moves the local ref only after the push, as `update-ref <ref> <new> <prior>` with an empty `<prior>` meaning it must still be absent: a failed push leaves both sides as they were, and a concurrent local writer makes the move fail instead of being overwritten (`writePlan`; `tests/bin-lib/plan-store/store.test.js`'s "two racing writers: the loser exits no-ref and the winner's ref stands" pins the exact push argv).
