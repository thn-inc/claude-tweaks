# Hook event in-process tests

`docs/hooks.md`'s "In-process entry" section owns the contract: the context the event tail builds (`{ input, runDir, runState, ownedRun, cwd, env, homeDir, spawn }`), `realDeps`, and the reads that stay on the real process. `docs/journeys/run-a-hook-event-in-process-from-a-test-5377.md` walks through reading a red test. This skill is the procedure for a change on the event path. A verb is not an event: a verb test goes through `runCli` (`hooks-js-verb-registration`), and any other CLI follows `gh-api-module-pattern`'s `cli-wrapper-contract.md`.

## Rules

1. **Call the event through `runHookCli`, never `runCli` or `spawnCli`.** `runHookCli(['pre-tool-use'], { input: JSON.stringify(payload), cwd, env: hookEnv({ PIPELINE_RUN_DIR: runDir }) })` from `tests/helpers/hook-event.js`. It collects the event's JSON from `deps.stdoutSync`, which `runCli` neither fakes nor guards, and runs the call inside the env tripwire. `cwd` and `env` are required, and `env` is the whole environment the event sees. Build it with that file's `hookEnv`, which adds `CT_HOOKS_TEST_MODE: '1'` over `tests/helpers/git-fixtures.js`'s `hookEnv`. A `session-start` call passes `deps: { spawn: fakeSpawn }`, or `runCli` fails it on the real spawn.
2. **Who calls a helper decides how it takes `env`.** A function only hook events reach takes `env` with no default and throws `TypeError` without it: `ctxLib.assertEnvObject` (`plugin/bin/lib/hooks/context.js`) in the hook modules, an inline check of the same shape in `plugin/bin/lib/ports/ensure.js`, `plugin/bin/lib/superpowers-version.js` and `plugin/bin/lib/reconcile/background-spawn.js`. A helper that a verb or another CLI also calls takes an optional `env` whose default is the inherited environment, and a call without it builds exactly the options it built before: spread `env ? { env } : {}`, never set `env: undefined`. Every call from an event module passes `env`. Grep the function's callers across `plugin/bin` before choosing: a required `env` on a shared helper breaks every verb caller. `spawnBackgroundIfStale` is the one named exception, required although the `reconcile` verb also calls it.
3. **Inventory the live reads by running the tests, not by grepping.** Convert the tests first, run them, and fix each `hook event read process.env: <KEY>@<frame>` the tripwire reports at the `plugin/bin` frame it names. A grep of the event module misses reads in the helpers it reaches: #5377's implementers missed them in three tasks, and each surfaced only when a converted test ran. A `*` key is a child started without an `env` option. Run a new event test once under `npx -y node@20 --test` as well: CI runs Node 20, which can report a `*` read the local Node does not.
4. **Check an "untestable" or "must stay a real process" claim before accepting it.** A test kept on `spawnCli` because an event or a verb ignores the injected env names a missing thread-through, not a reason. `record-worktree`'s `patchWithOwnerBlock` and `writeRunState`, and session-start's `collectStaleRuns` → `checkRunIntegrity` git children, were each fixed by passing `deps.env`, and their tests moved in-process. Keep a real process only where the process is the subject, with a `// real process: <reason>` comment.
5. **Probe the tripwire's blind spots yourself.** It cannot see a native `os.tmpdir()` or `os.homedir()` call, a `process.cwd()` read, a `process.env` reference captured before it armed, or a read after the call resolved. Point `TMPDIR` (`TEMP` on Windows) and `HOME` in the passed env at directories in the test's fixture and assert where each file landed; `runCli`'s leak guard reports `os.homedir()` under an injected `HOME`, but nothing reports a temp-directory read. `plugin/bin/lib/hooks/repo-info-cache.js`'s `storePath` stays on `os.homedir()`; tests isolate that store with `CT_HOOKS_REPO_INFO_STORE`. The factory policy file (#6006) is isolated with `CT_FACTORY_POLICY_FILE`: `tools/run-tests.js` points it at a missing file and `tests/helpers/tmp-dir.js` sets it when unset. An absolute value wins over an injected `homeDir`, so a test that writes a factory file under an injected home must delete the variable from a copied `process.env`, or that file is silently never read.
6. **Prove the thread-through, not just the argument.** A call site that passes `env` to a helper that drops it before its git child still leaks. Run the call with a clean passed env while the real `process.env.GIT_DIR` names no repository (`withBrokenGitDir` in `tests/helpers/process-env.js`), plus a control call without `env` that goes the other way.
7. **Keep both guards green by fixing, never by widening.** `tests/hooks-event-env-conformance.test.js` scans each module in `EVENT_MODULES` for `process.env` and `process.cwd()` (Scan A) and for a `repoInfo(`, `runGit(`, `writeRunState(`, `resolveIntegrationBranch(` or `preferRemoteTrackingRef(` call that does not name `env` in its own parentheses (Scan B), with a floor per call name per module: raise the floor when you add a call. `tests/hooks-event-process-ceiling.test.js` caps the converted files at `CEILING` (20) `spawnCli(HOOKS` call sites and refuses a raw spawn of `hooks.js` or a `spawnCli(` inside a loop body. Add a newly converted file to its `CONVERTED` list.

## Anti-patterns

| Pattern | Why it fails |
|---|---|
| `tripwire: false`, or a new `TRIPWIRE_ALLOWED` key, to reach green | The reported read is the defect the test found; the allowlist holds two keys, each with its reason |
| A `process.env` default on a function only hook events call | An event test that forgets `env` passes on the inherited environment instead of throwing, the silent fallback the required form closes |
| A required `env` on a helper verbs also call | Every verb caller that passes no `env` now throws |
| A hand-built context without `env` (or, for `session-start`, `homeDir`) passed to a module's `run` | `requireEnv` throws `hook context has no env`; add the key at the test file's shared context builder |
| A `git` or `gh` stub on the real `PATH` instead of the passed env's | The event never sees it; on Windows find the key without spelling it (`Path`) |
| An in-process `reconcile` assertion on a check outside the fast set with a pr-first fixture | Those checks still read `process.env` (`docs/hooks.md`, #5606); use a no-remote fixture |
| Lowering a Scan floor, or raising `CEILING`, without removing a call | The floor is what catches the next silent matcher drop, and the ceiling is the record's acceptance number |
