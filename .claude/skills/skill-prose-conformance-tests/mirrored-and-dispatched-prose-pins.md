# Mirrored and dispatched prose pins — skill-prose-conformance-tests

Lazy-loaded from `SKILL.md` (this skill's directory). Read this file when the prose under test is a deliberate copy of canonical text in another file, or is inlined verbatim into a Task-tool agent's prompt — a dispatch-facing distillation is often both.

## Pin a deliberately mirrored copy to its canonical text with a vocabulary-only normalizer

Some shipped prose exists twice on purpose. `plugin/skills/harness-health/judge-procedure.md` is a dispatch-facing distillation of `_shared/harness-health-analysis.md`: it is inlined verbatim into Task prompts, which cannot follow a pointer, and its header says "When that fragment changes, update this file in the same edit". Only prose enforces that obligation. When a change adds a paragraph to both copies, pin the two equal. Slice the same structurally-bounded region out of each file, rewrite only the enumerated tokens that legitimately differ, and `assert.strictEqual` the results. `tests/harness-health-runaway-section.test.js` (#2684) is the instance. Its `norm` helper rewrites `"{target.path}"`/`<target-path>` to `<path>` and ``(`claude-md`|CLAUDE.md) only,`` to `(<kind> only,`, and nothing else. An equality between two live files cannot pass vacuously the way a `doesNotMatch` against an unrelated control can, so it needs no frozen go-red excerpt. The normalizer is the part that needs care. One that strips whole lines or collapses a wider pattern than the known differences makes unequal copies compare equal. When the region carries an executable snippet, extract and run it from **both** copies (the same suite runs `snippet(JUDGE)` in one test and `snippet(ANALYSIS)` in another), because the equality pin alone never proves either copy runs.

## Pin a clean-room-dispatched sub-file's self-containment, not just its content

A sub-file inlined verbatim into a Task-tool agent's prompt (`review/step3-lens-dispatch.md`'s per-lens prompt, `docs-health/judge-procedure.md`'s dispatch body) reaches that agent with none of its sibling files — a clean-room session sees exactly the bytes handed to it, nothing it can follow a pointer from. Pinning the content alone (a token sweep, a byte-pin) proves the prose says the right thing; it doesn't prove the agent can actually resolve every reference inside it. Two separate checks are needed, and both recur: `tests/bin-lib/harness-health/skill-md.test.js` and `tests/bin-lib/docs-health/skill-md.test.js` each (1) assert the inlinable body is a strict, non-empty subset of the whole file (the meta lead above the dispatch boundary is never sent to the agent), and (2) sweep that same body for a closed list of forbidden self-references — `SKILL.md`, `_shared/`, `Step {N}`, `above`/`below`, and the file's own name — any of which is unresolvable to an agent that received only this body. A third, narrower check — fenced-code-block balance (`split('\n').filter(/^\s*\`\`\`/)`, assert an even count) — guards against the inlining itself corrupting the prompt mid-fence. Two live instances of this same three-part pattern (self-contained-subset, forbidden-reference sweep, fence-balance) existed before either file documented it as a reusable shape; write the next one the same way rather than re-deriving the forbidden-reference list from scratch.
