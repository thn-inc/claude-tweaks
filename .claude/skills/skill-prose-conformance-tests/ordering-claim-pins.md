## An ordering claim's control must carry both markers — in the wrong order

`tests/verification-skip-before-execute.test.js` (#2527) and `tests/design-variant-exploration-availability-order.test.js` (#2540) both pin "section X comes before section Y" with plain `indexOf` position comparisons over the live file. That is the right instrument when the property is *which comes first* rather than whether a literal is present — but it carries a blind spot the presence, count, and adjacency rules in `SKILL.md` do not cover. A `requireOrder`-style helper asserts each marker exists (`assert.notStrictEqual(idx, -1)`) and only then that positions increase, so **the existence half carries the entire go-red proof whenever a marker is new in the same change**.

#2540 is the worked example: all three of its ordering tests pin markers that do not exist at the base ref — `## Availability (checked before any option is presented)` in `design-wrapper/modes/explore.md`, and `**Policy gate.**` / `**Availability pre-check.**` in `specify/design-pre-steps.md` (confirm with `git show {base}:{file} | grep -c -F '{marker}'` — all zero). Every one of them goes red at base on the *missing marker*, and the `idx > last` comparison the suite exists for was never exercised. This is not a vacuous pin — the comparison does catch the regression it guards, a later edit moving the section back below the offers — it is an **unexercised** one: nothing shows the helper's ordering arithmetic works at all, and a `requireOrder` that compared the wrong variable, or reset `last` each iteration, would be exactly as green.

Build the control by **permutation, not deletion**: take the live text, splice the later block above the earlier one, and assert the same helper *throws* on the permuted string — one `assert.throws` per ordered pair, in the same suite. Where the two sections have clean boundaries, the blank-line paragraph split from `SKILL.md`'s "Doctor by structural boundary" yields the permutation directly, and the exact-count guard there applies unchanged. A frozen pre-change excerpt is the wrong control here for the same reason it is wrong for a new adjacency window (`SKILL.md`'s `doesNotMatch` blind spot): at base one marker is simply absent, so the failure is attributable to absence rather than to order. This is also why the `grep -c -F` recipe in `advanced-proof-patterns.md`'s "Proving discrimination without editing the tree" does not settle an ordering pin — it is presence-shaped, and "one marker missing at base" is precisely the reading that proves nothing.

Match the permuted throw to the helper's ordering message, and prove the existence half with a separate deletion control matched to its own message. A splice that drops a marker by accident throws `marker missing`, which a bare `assert.throws` accepts, so the ordering comparison again goes unexercised (the message-matching rule from `SKILL.md`'s "New prose has no pre-change bytes"). `tests/pre-review-catchup-conformance.test.js` (#4304) pairs `assert.throws(() => requireOrder(swapped, …), /must come after/)` with `assert.throws(() => requireOrder(absent, …), /marker missing/)`, each preceded by an `assert.notEqual` on the doctored text.
