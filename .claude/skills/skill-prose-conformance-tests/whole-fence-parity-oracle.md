# Running a whole embedded fence as a parity oracle

Lazy-loaded from `SKILL.md` (this skill's directory). Read it when a Node port of a skill's bash fence must match the fence's behaviour, and the test runs the fence itself, whole, as the oracle. The worked instance is #5227's queue pull: `tests/bin-lib/dispatch/queue-pull-oracle.js` (`withEscapeGuard`, `runPair`, `REPORTED_LINE`, `TAIL_LINES`, `assertParity`), `queue-pull-fixtures.js` (`shimTable`) and `queue-pull-clock-stub.js`. The cutover and removal units of a strangler-fig port repeat the pattern.

Executable-snippet pins (`executable-snippet-pins.md`) run one snippet and check its output. An oracle runs a whole fence against a port on shared fixtures, and every difference between the two runs is a finding. The fence can reach the real repository, so the harness owes more than a snippet pin does.

1. **Extract the fence by its first line, and skip with a named reason.** Anchor the extraction on the fence's first line, not a line span, so an edit above it cannot shift the slice. When bash 4 or later is missing (win32, stock macOS bash 3.2), skip with a reason the test output names (`no bash oracle`), and keep the port's in-process fixtures running.
2. **Pin the environment explicitly.** Spawn with an explicit env, not the inherited one: pin cwd, `OLDPWD`, `PWD` and `HOME` to the sandbox, unset `CDPATH`, and set `GIT_CEILING_DIRECTORIES` above the sandbox. Pass through only what the run needs (`NODE_OPTIONS`, a `CT_TRACE_*` prefix). #5227's fuzzed `cd -` read the inherited `OLDPWD` (bash 5) and committed on the real branch before this was pinned.
3. **Pin the git identity through env, never `-c user.*`.** CI exports `GIT_AUTHOR_*` and `GIT_COMMITTER_*`, and they beat `git -c user.name=…`, so a test that sets the identity with `-c` passes locally and goes red in CI (#5227's escape-guard test at 9ab42903a, fixed at 7f8db65b1).
4. **Shim `gh` and `git` on PATH from one canned table.** Fence and port answer from the same table of `{argv, stdout, stderr?, status?}` entries, so a difference is a behaviour difference, not a fixture difference. The `git` shim refuses any `-C` path or cwd outside the sandbox. The shims are `sh` scripts generated from the table, so an exact, effect-free `gh` entry is answered without a Node start.
5. **Wrap every pair in an escape guard.** Before and after each run, compare HEAD, the symbolic ref, the sandbox-authored refs, the index, and tracked status of the real checkout. Fail the test when anything moved. Compare tracked status deliberately: a concurrent tracked edit trips it, which is the point.
6. **Share deterministic seams.** The oracle's `mktemp` shim and the port's temp-name seam read one counter file, so both sides name files identically. A frozen-clock preload stubs `Date` on both sides.
7. **Compare what the acceptance criterion names, and guard the rest.** Compare the exit status, the files each side writes, and the reported line kinds the criterion names (`AUTO`, `Warning:`). A comparison built only from what the reference prints hides everything extra the port prints. Add a guard that fails when the port prints a step diagnostic where the reference's stderr shows no error (`assertParity`'s `queue-pull:` check, added in #5227's review fix wave 566b73843).

**Cost to plan for.** Before #5366, one full run of #5227's suite took 470 s and started at least 8,539 Node processes, most of them shim starts, one per `gh` or `git` call. Since #5366 the shims are `sh` scripts, and what still starts Node is the Node CLIs each side runs (the fence's own and the port's) and every `gh` call the `sh` shim hands to its Node fallback: graphql queries, entries with an effect, and misses. Size the fixture matrix with that in mind, and expect the runner to need a heavy tier for files like this.
